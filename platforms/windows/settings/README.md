# Windows WinUI 3 设置

`MSIME.Settings.vcxproj` 是 Windows 设置窗口的原生宿主（安装后为 `msime-client-settings.exe`）。它使用 Windows App SDK 的 WinUI 3 控件，参考 macOS 原生设置的分组与密度绘制：带返回按钮与当前页标题的内容工具栏、224 DIP 宽的侧栏和单一设置搜索、每组一张 10 DIP 圆角卡片。组内使用细分隔线、13 DIP 标签和 11 DIP 说明，移除重复行图标和开关状态文字，窄行把控件排到标签下方。页面边距为 22 DIP，强调色与候选窗统一为品牌绿，浅深色随主题切换。它不启动 Tauri 作为设置界面，也不拥有 TSF 或输入会话。

## 页面

侧栏的 16 个页面分成 6 组，依次是打字（输入方案、输入习惯、按键、词库）、外观（主题、候选窗口、悬浮工具栏）、更多输入方式（屏幕键盘与手写、语音输入）、工具（剪贴板、打字统计、插件、AI 辅助）、账号（账号与同步）、支持（维护与诊断、关于），每组以组名开头。分组与顺序和共享设置界面的桌面侧栏一致，即 `settingsNavGroups`（`packages/ui/src/settings/settings-page-registry.ts`）去掉 `desktopMergedPages` 并进「关于」的「帮助与反馈」，定义在 `SettingsNavigation.h`，由 `tests/ui/settings_navigation.cpp` 核对，并对照共享路由词表检查；组名和页名在 `main.cpp` 中。手写设置只有一个打开面板的按钮，与共享设置界面的 `handwritingOnScreenKeyboardPage` 一样并进屏幕键盘页，那一页在提供手写的版本里叫「屏幕键盘与手写」，在不提供手写的版本（日文、越南文、藏文）里仍叫「屏幕键盘」、不画手写那一组；`handwriting` 路由打开这一页，不提供手写的版本打开默认页。

- 全部 16 个页面都在本窗口中原生绘制，没有交给共享应用的设置页。
- 账号与同步不跳共享应用：「账号与同步」页照共享账号页（`packages/ui/src/account/account-page.tsx`）的桌面那一支画出来，Windows 上没有 App 图标、「我的设计」和「关于」一组。没登录时是登录卡片：「使用 Google 登录」（服务端开着 Google 时；等待浏览器时按钮写「正在等待浏览器完成 Google 登录…」，下面是「取消 Google 登录」）、「邮箱登录」「手机号登录」；两个恢复动作只在出问题时出现，与共享页相同：没有可用的登录方式（读失败或一个都没开）时给「刷新登录方式」，读不出本机登录状态（`status` 失败）时给「清除失效登录状态」；选了邮箱或手机号后是号码输入框、「获取验证码」（发出后 60 秒内显示「N 秒后可重新发送」）、6 位验证码和「登录」（过期时写「验证码已过期，请重新获取」）、「取消」。登录后是资料卡片（头像、昵称和邮箱），点开「编辑资料」对话框：点头像用系统打开对话框选 1 MiB 以内的 PNG 或 JPEG 更换、「移除头像」（只对上传的头像）、社区昵称（首尾空白去掉、最多 64 个字符、不含控制字符）、账号 ID（点按复制，显示「已复制」）、邮箱、登录方式和加入日期，「保存修改」保存昵称；然后是「设置同步」卡片（刷新云端设置、上传本机设置、下载并应用云端设置，后两个先确认，只同步各平台共有的输入设置，应用后本窗口重读设置）、「云端」一组（云剪贴板，面板仍由 `MSIME.exe` 显示；云词库的入口只在「词库」页）、「我的内容」一组（我发布的 / 收藏的词库和回复模板，在本页打开社区词库与回复模板，见下）和「账号」一组（退出登录、退出所有设备、注销账号，后两个先确认）。所有操作经 `msime_client_account`，用共享应用和输入法读的同一份会话文件 `%LOCALAPPDATA%\<本版本的用户目录>\account\account-session.json`，旧版本放在 `%LOCALAPPDATA%\<本版本的 Tauri identifier>` 的会话第一次用到时搬过来；Google 登录由 Rust 监听回环端口并用系统浏览器打开授权页，离开页面或关闭窗口时结束等待。除读状态和取消 Google 登录外都在工作线程上进行，每次进入页面重新读状态。头像经 `avatar` 取成 data: 地址在本窗口解码，不加载远程图片。文案、昵称校验、错误码的说法、验证码和日期规则在 `AccountPageModel.h`，由 `tests/ui/account_page_model.cpp` 核对。 登录后在「设置同步」之后是「绑定 QQ 群助手」（共享页的 `qq-link-card.tsx`）：8 位绑定码（去掉空白和连字符后正好 8 位数字才能点「绑定」，回车也能绑定）、已有绑定的「绑定于 时间」和「解绑」，经 `msime_client_account` 的 `qq_links`、`qq_link_redeem`、`qq_link_delete`，绑定失败的说法在 `AccountPageModel.h` 的 `qq_link_message`。
- 本窗口没有单独的社区页：社区皮肤是本窗口「主题」页的「社区皮肤」标签，社区插件是「插件」页的「社区插件」标签（见下），`community` 路由打开本窗口的「主题」页。社区的词库与回复模板也不跳共享应用：账号页「我的内容」的四行在「账号与同步」页里换上共享应用在 Windows 上的社区页（`packages/ui/src/community/community-resources.tsx` 的 `CommunityHomePage`，没有皮肤画廊时只有「词库」「回复模板」两个分类），停在那一行的分类和范围上（我发布的是「我的作品」，收藏的是「收藏」），顶上的「账号与同步」回到本页，离开本页时卸下。图库有搜索、「全部 / 收藏 / 我的作品」、卡片和「加载更多」；详情里词库是词条预览、「导入这版词库到本机」（按词条类型分组，以标准格式经 `msime_client_settings_dictionary` 导入本机词库，与共享应用的 `dictionary_request` 相同；Windows 没有命名词库）和「导入这版词库到云端」，回复模板是提示词预览（桌面没有「高情商回复」键盘，不能添加到键盘）；之后是收藏、评分、举报，作者「编辑并发布新版本」和「下架作品」。「发布作品」对话框照 `ResourceEditor`：名称、说明、权利确认（新版本不要），回复模板的提示词（最多 2000 字），词库的词条表单（类型、编码、词语、权重，最多 128 条，不能重复）。社区操作经 `msime_client_community`，都在工作线程上；文案和规则在 `CommunityPageModel.h`，由 `tests/ui/community_page_model.cpp` 核对。社区是作品库，不是设置。AI 对话是 AI 辅助的子页，Windows 的设置应用不提供它（宿主没有 `chat`，共享页因此不显示「AI 对话」一组），`chat` 路由打开「AI 辅助」。
- 帮助与反馈并进「关于」：与共享桌面侧栏一样没有单独的「帮助与反馈」页，`help`、`feedback` 路由（托盘和工具栏菜单的「使用帮助」「问题反馈」）打开「关于」，「关于」在「版本与更新」之后、「许可与隐私」之前画帮助、问题报告和反馈渠道（`build_feedback_sections`，对应共享页的 `FeedbackSections`）。本窗口没有子页，共享页「帮助」子页的内容直接画在「关于」里，所以这一页比共享页长：它是共享「帮助」页（`packages/ui/src/settings/help-settings-page.tsx`）在 Windows 上的内容，文案取 `settings/platform-copy.ts` 的 Windows 分支，「完整文档」用默认浏览器打开 https://msime.app/docs/。
- 反馈不跳共享应用：「关于」页照共享页（`packages/ui/src/settings/pages/feedback-page.tsx` 的 `FeedbackSections`）画「提交可复现的问题」和「反馈与交流」。选反馈类型、写描述（最多 4000 字），「复制报告」把「### 类型 / ### 描述 / ### 环境」格式的报告放进剪贴板，「在 GitHub 提交」用默认浏览器打开 `https://github.com/metasequoiaime/msime/issues/new?title=…&body=…`，正文截到 4000 个字符；附上的信息是版本号、系统版本（`RtlGetVersion`）和当前输入方案。渠道是 GitHub Issues、QQ 交流群（复制群号 829919142）和 Telegram 群组（https://t.me/msimegroup）。报告格式和地址编码在 `FeedbackReport.h`，由 `tests/ui/feedback_report.cpp` 核对。
- 屏幕键盘设置不跳共享应用：「屏幕键盘与手写」页照共享页（`packages/ui/src/settings/pages/screen-keyboard-page.tsx` 和 `touch-keyboard-geometry-section.tsx`）在 Windows 上的内容画四组，提供手写的版本在「工具栏」和「外观」之间多一组「手写识别板」（打开手写面板的一行，面板仍由 `MSIME.exe` 显示）。「屏幕键盘」组是打开面板的一行（面板本身仍由 `MSIME.exe` 显示）和键盘预览：预览照 `ScreenKeyboardPreview` 的桌面布局画在 1100 单位宽的画布上、最宽缩到 760，配色取 `msime_client_theme_catalog` 的 `keyboard` 调色板（跟随系统和没有调色板的主题用共享预览的系统键盘色），明暗跟随颜色模式（各界面一律跟随，不读 `screen_keyboard_theme`），自定义主题带键盘设计时按设计画键形、材质、描边、渐变、底纹和照片；在预览上左右拖动调键距、上下拖动调行距，规则与共享页的 `useTouchKeyboardGeometryDrag` 相同。「尺寸」组是键盘高度（`touch_keyboard_height_adjustment`，-12 到 48）、按键间距（`touch_key_spacing_tenths`，30 到 60）、行间距（`touch_row_spacing_tenths`，40 到 100）和「恢复默认」，后者的说明和确认文案只提这一页看得到的高度、间距和顶部语音入口（与共享页的 `touchKeyboardResetSubjects` 相同），确认后从文档里删掉这三项和 `touch_voice_shortcut`、`touch_toolbar`。Windows 有触屏的二合一设备，高度和两种间距都留着，macOS 没有触屏，去掉了间距；它的键盘窗口高度固定，高度也不显示。「工具栏」组只有「顶部语音入口」（Windows 不是 `touch_toolbar_components` 的宿主）；「外观」组的「屏幕键盘外观」说明屏幕键盘跟随「主题」页的颜色模式和主题，「前往」落到「主题」页的「颜色模式」一行。手机才有的「布局」「手势」和触屏反馈不画。
- 在线翻译服务不跳共享应用：「标点与翻译」页「候选词翻译」组的「翻译服务」照共享页（`translation-service-selector-section.tsx`、`use-translation-settings.ts`）列出关闭、腾讯云机器翻译、小牛翻译（NiuTrans）、自定义 DeepLX 兼容服务和水杉账号，候选词翻译关着时不可选；选一种只打开它、关掉另外两种，选水杉账号时写 `translation_account`，否则去掉这一项。选腾讯云、小牛翻译或自定义服务时下面多一组它的设置（SecretId、SecretKey、地域；App ID、API Key；翻译 Endpoint、API Key），密钥框带「显示」「隐藏」按钮，文案、提示和警告与共享页相同。输入时就地更新提示，不重建页面；偏好库接受的值才写入（停下后保存），不接受的值输入框标红、不写入。每组的「测试配置」在工作线程上调用 `msime_client_test_api_credential`（与 Tauri 的 `test_api_credential` 同一个 `credential::test_service`），结果只在配置没改时显示。自定义地址的提示由 `msime_client_translation_endpoint_issue` 按 WHATWG 网址规则给出；其余规则在 `TranslationServiceSettings.h`，由 `tests/ui/translation_service_settings.cpp` 核对。
- 剪贴板不跳共享应用：「剪贴板」页（`tools` 路由）照共享页（`packages/ui/src/settings/pages/tools-page.tsx` 和 `clipboard-history-section.tsx`）在 Windows 上的内容画三组。「剪贴板」组是「剪贴板历史」开关（`clipboard_history`，从开到关时再清空已存的历史）、「从系统剪贴板同步」和有历史时的「清空历史」，后者点两次才清空（第二次按钮是「确认清空」）。历史开着时多一组「历史记录」：每条一行，文字单行显示、悬停看全文，下面是「已固定 · 」和本地时间（没有时间的旧记录写「旧记录」），右侧保留「重新复制」，「更多操作」菜单提供「发到云剪贴板」「固定 / 取消固定」「删除」，避免窄窗口的按钮挤掉正文。历史文件与共享应用相同（偏好目录下的 `clipboard_history.json`），读、同步、清空、固定和删除都在工作线程上经 `msime_client_desktop_clipboard_history`；同步读系统剪贴板用与 Tauri 外壳相同的 `clipboard_history::windows_clipboard_text`，带密码管理器隐私标记的内容不记录。「重新复制」用 WinRT 剪贴板放回系统剪贴板，再像共享应用的 `copy_text` 一样经 `msime_client_capture_clipboard_history` 记进历史。「发到云剪贴板」经 `msime_client_account_cloud_clipboard` 使用共享应用登录时写在 `%LOCALAPPDATA%\<本版本的用户目录>\account` 的会话：每次进入页面查一次账号和服务端开关，未登录、服务端关着或服务不可用时按钮不可用并在组里说明，超过 4000 个 UTF-16 单元的记录不发送。「云剪贴板」组只有打开云剪贴板面板的一行，面板仍由 `MSIME.exe` 显示。
- 打字统计不跳共享应用：「打字统计」页（`typing-statistics` 路由）照共享页（`packages/ui/src/settings/typing-statistics.tsx`）在 Windows 上的桌面版画出来：统计关着时的「输入统计已关闭」和「启用输入统计」，概览六格（今日输入、累计输入或选中那天、今日活跃、今日速度、平均速度、连续天数，随可用宽度排成两列或三列）和两行概况，标签「按键」「趋势」「类型」「模式」「方案」「候选」。「趋势」是近 30 天的每日柱形（点按选中一天，「返回整个时间范围」取消，选中时概览和其他标签只算那一天）、有分时记录时的「今日时段」（与前几天平均对比）、「速度趋势」折线、近 53 周的「日历热力图」和最近 30 个记录日的「按日明细」；「按键」是 ANSI 键盘（记到屏幕键盘专有的键时是手机 26 键，按过九宫格再加九宫格）上的按键热力图、其他键和最常按的五个键；「类型」「模式」是环形图加图例，「方案」是单色排行，「候选」是首选命中率和第 1 到第 10 条以后的分布。下面是「记录打字统计」开关、「自动清理」（永久保留、最近 30/90/180/365 天）、「刷新统计」「打开数据目录」「清空统计」（确认后清空）和隐私说明；开着却没有数据时说明原因。统计经 `msime_client_typing_statistics` 读写状态目录下的 `typing-statistics.json`（与输入法和共享应用同一份），请求带 `status:true`，回答里有统计文件是否写过和最后写入时间，与 Tauri 的 `load_typing_statistics` 同一个 `TypingStatisticsStore::status`。读写都在工作线程上；页面开着时每 5 秒和窗口重新激活时重读一次，没有变化就不重画。派生数字、文案和按键布局在 `TypingStatisticsModel.h`，由 `tests/ui/typing_statistics_model.cpp` 核对；图表用 WinUI 的形状画。 「记录打字统计」下面是「上传到云端」（共享页的 `typing-statistics-upload.tsx`）：经 `msime_client_account` 的 `typing_upload_status`、`typing_upload_set`、`typing_upload`（与账号页同一份会话，平台 `windows`，日期是本地日期），没登录时不能打开、已经打开的在退出登录后仍能关掉；打开时立刻上传最近 7 天的每日计数，关闭时删除云端副本，失败时的说法与共享页相同（`TypingStatisticsModel.h` 的 `upload_error_message`）。设置窗口打开和每次进入本页各补传一次，离上次不到十分钟时 Rust 不发请求。打开了上传时，「输入统计已关闭」和页底的隐私说明改写「只保存在本机」那一句。

社区皮肤与社区插件不跳共享应用。「主题」页和「插件」页顶上各有一对来源标签，与共享外壳（`packages/ui/src/index.tsx`）在桌面上的一样：「我的皮肤」「我的插件」是本页的设置，「社区皮肤」「社区插件」换成社区图库；停在哪一边跨页面保留，图库随页面挂上和卸下，每次挂上从第一页读起，搜索选中「社区皮肤」「社区插件」时打开图库。「社区皮肤」照 `community/community-candidate-skins.tsx`：搜索框（最多 128 个字）、「全部 / 我的作品」、「发布我的皮肤」、八个分类筛选（第一页读失败时分类退回上一次成功的），卡片是预览图、名字、分类 · 作者（自己的写「我的作品」，另标「私有」「已下架」）、下载量和评分、素材授权，「加载更多」。点卡片在原处打开详情：「← 社区」、预览图、标题和「我的作品」或「私有」「已下架」标记、说明、授权行、下载与评分、「一键安装」（先扫本机皮肤目录，同名时先问「替换安装」；安装后说「已安装到外部皮肤」，「去启用」回到「我的皮肤」，「我的皮肤」下次显示时重扫目录）、作者的「公开 / 设为私有」和「修改分类」、别人作品的 1–5 星评分和「举报」（六个固定原因和最多 1000 字的补充说明），作者公开作品的「下架这款皮肤」（先确认）。图库挂上和装好皮肤后与账号的皮肤库同步一次（`candidate-skin-sync.tsx`），下载或删除了本机皮肤时「我的皮肤」重扫。预览图经 `candidate_skin_preview` 取成 data: 地址在本窗口解码，每款读一次，卡片和详情共用，读到后就地换上，不重画整页。「发布候选窗口皮肤」对话框（`candidate-skin-publish-dialog.tsx`）从图库的「发布我的皮肤」或「我的皮肤」里每张皮肤卡片的「发布到社区」打开：选本机皮肤、「公开（所有人可下载）/ 仅自己可见」、打包检查（不上传）的文件数和大小、授权行、皮肤名称（最多 32 个字，默认取包的名字）、设计说明（最多 280 个字）、权利确认、分类和上传须知，主按钮是「公开发布」或「保存到我的皮肤库」；公开发布缺素材授权时改成三选一（CC BY 4.0、CC0 1.0、其他，其他最多 120 个 UTF-8 字节）和「使用此授权并继续」，写进 `skin.toml` 后重新检查；没有预览图时可「生成预览图」：在工作线程上用 Direct2D 按 `skin-preview-render.ts` 的版式（皮肤支持浅色时画浅色，装饰带、圆角卡片、背景图、拼音和五个候选，每 dip 两像素，PNG 超过 256 KiB 时改用质量 0.85 的 JPEG）画一张写进皮肤文件夹；其余打包问题只说明并给「打开目录」。从卡片发布的结果写在皮肤卡片下面，从图库发布的写在图库里并从第一页重读。「社区插件」照 `community/community-plugins.tsx`：搜索、「全部插件 / 我的作品」、「发布我的插件」、八种类型筛选，卡片是名字、类型 · 作者、说明和下载评分，整页都是本机装不了的类型时宿主跳过，最多再读五页；详情是标题、插件 id · 授权 · 大小、下载评分、「一键安装」（同 kind 同 id 的包已装时先问「替换安装」，装好后「我的插件」回来时重读目录）、评分、举报和作者的「下架这个插件」。「发布插件」对话框列出本机非内置的插件，打包检查后填上建议的名称和说明，显示版本、授权、文件数和大小（上限 8 MB）、名称、说明、权利确认和上传须知，主按钮「公开发布」。发布 id 是随机的 UUID，改了皮肤、公开范围、分类、名称或说明就换一个，失败重试时沿用。出错说明按 `community-helpers.ts` 的 `candidateSkinMessage` 和 `communityPluginMessage`，未登录时后面跟「去登录」，打开「账号与同步」页。所有社区操作经 `msime_client_community`，用「账号与同步」页同一份账号会话，皮肤根目录是数据目录下的 `skins`，插件根目录是数据目录下的 `plugins`，都在工作线程上。规则和文案在 `CommunityPageModel.h`，由 `tests/ui/community_page_model.cpp` 核对。

自定义主题与外部皮肤不跳共享应用：「主题」页照共享页（`packages/ui/src/settings/pages/skin-page.tsx`）在 Windows 上的内容画出来。页首说明之后，内置主题卡片后面是每款外部皮肤包一张卡片（`skin/external-skins.tsx` 的 `ExternalSkinCard`）：标题带卡片画的明暗和「使用中」，说明（包的描述或「基于 某主题」，不支持当前排列方式或明暗时说明它支持什么）、槽位说明、id · 版本 · 作者，开关和 `system` 底的包才有的「预览浅色 / 预览深色」（只改卡片，当前明暗变了以后作废），以及横排、竖排两个缩小的候选窗口，配色是 `msime_client_resolve_theme` 给「只由这款包组成、画在它 base 之上的自定义主题」的那一份，带包的圆角、最小宽度、背景图（按 cover / contain / stretch 和不透明度，按圆角裁切）和装饰图。打开开关按 `applyCandidateSkin` 把包放进它 base 所属的槽位（`custom_theme.candidate_skin` 或 `candidate_skin_dark`，`system` 底的两个都放）并把底改成包的 base、选上自定义主题；关掉按 `removeCandidateSkin` 取下，取下最后一款时底回到 `system`。自定义主题用着目录里的包时选中的是那张包卡片，「自定义」卡片代表不带皮肤包的自定义主题，点它会清掉两个槽位；它的配色按不带皮肤包和皮肤目录的请求解析。卡片下面写两种明暗各用哪款皮肤。「更多皮肤」组的「外部皮肤」一行照 `ExternalSkinDirectoryRow`：说明、扫描状态、皮肤目录，「打开目录」（在工作线程上建出数据目录下的 `skins` 再用资源管理器打开，与 Tauri 的 `open_skin_directory` 相同）、「刷新皮肤」，打不开、读不到时的说明和「已忽略 N 个无效皮肤目录」列表。目录由 `msime_client_skin_catalog` 扫描，图片经 `msime_client_skin_resource` 读取，都在工作线程上；第一次进入页面和「刷新皮肤」总会更新卡片并重读图片，再次进入页面和窗口重新获得焦点时自动重扫，结果没变就不重画。「外观」组是颜色模式和「候选窗口主题」：设置窗口、工具栏、菜单和各面板一律跟随颜色模式（`surface_themes_follow`），只有候选窗口还能单独设明暗。「自定义主题」组是一个默认收起的「自定义配色」折叠区（共享页的 `MoreOptions title`），搜索落到「自定义主题」或某个取色器时展开，里面是五个候选颜色取色器（`candidate-colors-section.tsx`：表面色、文字、强调、选中、悬停；编号色和边框色跟随主题，Server 的 `candidate_theme_values` 也不读存下的值），色块打开 WinUI 的 `ColorPicker`，没设时显示候选窗口当前明暗下的默认色；选颜色写 `custom_theme.candidate_colors.<槽>`，按 `updateCandidateColor` 同时选上自定义主题，原来不是自定义主题时把当时的主题留作底并清掉两个槽位；「跟随主题」把这一项写成 null。拖动时随时写入并刷新顶部预览，停下后保存。规则在 `ThemeSkinModel.h`，由 `tests/ui/theme_skin_model.cpp` 核对。卡片不画悬浮工具栏的预览（那要按包的 CSS 画），与内置主题卡片一致；每张卡片还有「发布到社区」，见上文的社区皮肤。

「候选窗口」页照共享设置的一列布局（`appearance-page.tsx`）：预览之后是「布局与字体」组，主流程只有排列方式、每页数量、候选字体（及按需出现的主字体）和字号，其余各行收进同一个「更多选项」折叠区，顺序是显示水杉 logo、跟随光标、英文字体、预编辑字号、整体大小、不透明度、圆角、候选窗口预编辑、行内预编辑（「双拼预编辑」在「输入方案」页的双拼详情里）；搜索落到折叠区里的行时把它展开。「游戏」组管游戏里候选窗能不能出现，是功能开关，放在折叠区之后照常展开。字体各行照搬共享页在 Windows 上的样子（`CandidateFontPresetRow` 与 `CandidateFontControls`），不跳共享应用：「候选字体」预设（默认、宋体、黑体、楷体、圆体，Windows 没有自带圆体，该项禁用，末尾是「自定义…」）同时写 `candidate_font_family` 和有序的 `candidate_fallback_fonts`；选「自定义…」只亮出「主字体」框、不改字体，字体不是任何预设时打开页面就是「自定义…」和字体框，选回预设时字体框收起；「主字体」在 Windows 上同时排到回退列表最前；「英文字体」写 `candidate_english_font`，未设置时显示 Segoe UI。原来单独的「系统字体列表」一行并进了第一个可见的字体框：读取状态写在那一行下面，「刷新」按钮（读屏名「刷新字体列表」）在输入框旁边；主字体框收起时由「更多选项」里的英文字体框带着。预设、主字体框何时出现和字体名的规则在 `CandidateFontPresets.h`，由 `tests/ui/candidate_font_presets.cpp` 核对。字体列表由 `msime_client_list_font_families` 读取（与 Tauri 的 `list_font_families` 同一份 `system_fonts` 目录），第一次点开字体输入框时在工作线程上读，读取状态在原处更新，不重建页面，输入框不会丢掉焦点。下拉按用户区域设置不分大小写地筛选（`LCMapStringEx`）。名字不合法（空、超过 128 个 UTF-8 字节或含控制字符）时不写入，输入框标红，框下显示「名称不能为空、不能含控制字符或超过 128 个 UTF-8 字节。」，读屏从输入框的帮助文本读到同一句。

「输入」页的辅助码方案下拉框和共享设置的 `HelpcodeSettingsGroup`（`packages/ui/src/settings/pages/helpcode-page.tsx`）规则相同，辅助码插件也在这里选，不跳共享应用。选项依次是内置方案、资源目录 `helpcodes/custom` 里的自定义码表（`custom/<文件名>`，由 `msime_client_helpcode_schemas` 读宿主选项的 `resources`，名字是「中文名 (英文名)」）和已安装的辅助码表插件（「插件名（插件）」，取自 `msime_client_plugins` 的 `catalog` 中种类为 `helpcode` 的包）。选插件只写 `plugins.helpcode_pack_quanpin` / `helpcode_pack_shuangpin`，输入引擎用它替换内置方案；选内置或自定义方案时同时清空插件。已选的插件不在了显示为「id（插件，未找到）」，资源目录读不到时已选的自定义码表也留在列表里。自定义码表只读一次，插件每次进入「输入」页重读，都在工作线程上读。本版本提供全拼或双拼之一就显示这一组，两族都列出（共享页的 `editionUsesHelpcode`）；「在候选窗口中显示…辅助码」不随开关变灰；Windows 不是 Shift 输入辅助码的宿主（`helpcode_shift_entry` 为 false），所以没有共享页那段 Shift 说明。

选用五笔时，「输入方案」页的「当前方案选项」提供「五笔快捷选词」（`wubi_candidate_selection`，默认关闭）：开启后默认用 `;` / `'` 选择当前页第 2、3 候选，候选不足时仍输入标点。两个候选键可改为不同的英文标点，按「保存选词键」一起保存；共享偏好库校验标点、重复与翻页/以词定字冲突，拒绝时恢复已保存设置并提示。关闭后保留自定义键位；「按键」页的通用「二三候选」是另一项设置。

选用五笔时，「输入方案」页在方案选项后面有「五笔查码」组，与共享设置的 `WubiCodeLookupSection`（`packages/ui/src/settings/wubi-code-lookup-section.tsx`）相同：输入或粘贴汉字（最多 1000 个字符）后「查码」，经 `msime_client_settings_dictionary` 发只读的词库请求 `wubi_codes`，在工作线程上查；结果表列出整段文字作为一个词和每个不同汉字的 86、98 五笔编码（简码在前，码表里没有时写 —），当前选用的码表标「（当前）」，字太多时说明只列出了前多少个。

`--route=settings:<id>` 指定打开的页面，可以是共享路由的设置分类 id（`appearance`、`dictionary`、`about` 等，映射见 `route_aliases`），也可以是本窗口的页面 id；其他值打开默认的「输入」页。

## 页面与导航

窗口参照 macOS 原生设置：侧栏只保留一个设置项搜索，正文工具栏显示当前页面；各页标题附一行用途说明。「输入方案」逐项选择输入方式，专属选项和辅助码随当前方案变化；「输入习惯」集中混输、输出、快捷模式、纠错和调频；「按键」集中选词、翻页与快捷键。原有路由 id 不变，搜索结果按新归属打开页面。

实时预览位于「皮肤」「候选窗口」页的独立预览区域，横向候选可滚动。示例文字可按空格分成候选，短列表循环填满一页；清空恢复默认示例。预览明暗可单独切换，也可跟随保存的设置；示例和预览明暗在离开再回到页面后保留，仅保存在当前窗口。

## 外观与主题预览

窗口以 macOS 的紧凑分组布局为依据，强调色固定为浅色 `#2C7A4B`、深色 `#5FBF84`（与候选窗口原生调色板相同），不跟随 Windows 的个性化强调色。窗口的明暗跟随颜色模式，不读 `settings_theme`。

「主题」「候选窗口」「输入」「标点与翻译」页的候选窗口预览和「自定义」主题卡片不自己配色：它们用与 Server 相同的请求（全局主题、去掉键盘设计和编号色、边框色的 `custom_theme`、候选窗口自己的明暗与排列方式、数据目录下的 `skins`）调用 `msime_client_resolve_theme`，再用 `src/candidate/CandidatePalette.h` 合成调色板，并按 `CandidateWindow.cpp` 的规则绘制选中行、序号、选中条和翻译，所以自定义主题的 `candidate_colors` 与皮肤包会反映在预览里。「自定义」卡片和共享页一样只画不带皮肤包的自定义主题，请求里去掉两个皮肤槽位和皮肤目录；皮肤包卡片的配色见上文。其余主题卡片使用 `msime_client_theme_catalog` 给出的预览色。

## 默认输入法提示

每页标题上方的橙色提示条对应设计稿的 deskStrip：水杉输入法不在当前用户的键盘列表中时显示「去添加」，已添加但不是默认输入法时显示「设为默认」。状态通过 `input.dll` 的 `EnumEnabledLayoutOrTip` 读取（无头文件和导入库，运行时加载），按钮分别调用 `InstallLayoutOrTip` 和 `SetDefaultLayoutOrTip`；添加失败时打开「语言和区域」。`input.dll` 无法回答时不显示提示条。窗口重新获得焦点时重新检查。

## 保存

设置窗口通过 `msime_client_load_preferences` 和 `msime_client_save_preferences` 读取、校验并以 compare-and-swap 方式保存共享偏好。每个控件改动后立即保存，滑块停止拖动后保存；保存被拒绝（其他窗口已更新或与其他设置冲突）时重新读取并在页面顶部说明。窗口重新获得焦点时重新读取，以反映托盘、共享应用或同步带来的变化。数据目录必须与 Server 的状态根相同：Server 启动它时注入 `MSIME_CLIENT_STATE_DIR`，直接用这个目录；从开始菜单直接启动时没有这个变量，就按 Server 的方式自己解析，先用 `common/StateDirectory.h` 的 `resolve_state_directory()`（本版本的数据目录环境变量、安装器在 HKLM 记下的 `DataDir`、`%LOCALAPPDATA%\<本版本的状态目录>`），那里的 `runtime-options.json` 写了绝对路径的 `preferences_directory` 时再改用它，与 `server_main.cpp` 的 `production_preview_document` 和 Tauri 外壳的 `windows_server_preferences_directory` 一致。以前开始菜单启动直接回落到 `%LOCALAPPDATA%\MSIME-Client`，而默认安装的 Server 用的是安装器的 `DataDir`（`%LOCALAPPDATA%\metasequoiaime-full`），这个窗口里改的开关（包括 `/`、`@` 和 K 模式、辅助码）就都写进了 Server 不读的文件。顺序在 `SettingsStateDirectory.h`，由 `tests/ui/settings_state_directory.cpp` 核对。

控件按偏好的点分路径读写文档，路径可以任意深（`plugins.key_sound.enabled`、`custom_theme.candidate_colors.surface`）。写入时缺的中间层从随包默认值里同一路径的对象复制而来，默认值里也没有才是空对象，因为存储只整体接受一个嵌套对象；删除一项时不补中间层，读取随之回落到默认值。`ai_assistant.tokens` 这类以来源为键的表，表项的键里可能有点，所以单独给出、原样作为最后一段。列表有两种写法：顺序没有意义的列表排序并去重后写入，顺序由用户决定的列表原样写入。路径规则在 `PreferencePath.h`，与 JSON 实现无关，由 `tests/ui/preference_path.cpp` 用一棵假的树核对。

「候选窗口」页「游戏」组的两张程序列表（`game_compatibility.overlay_processes`、`excluded_processes`）在写入前先按偏好库的规则规范化和校验（`GameProcessList.h`）：去掉首尾空白、ASCII 字母转小写，要求以 `.exe` 结尾、不超过 64 个字符、不带路径和 `\ / : * ? " < > |` 及控制字符，两张表之间不重复、合计不超过 32 条。不合法时在列表下方说明具体原因，不写入文档：保存被拒时窗口只能给出上面那句笼统的说明，用户看不出是哪一项出了问题。这组设置只由 TSF DLL 在每次激活时读取，对已打开的游戏要切换一次输入法才生效，取舍见 [决策笔记](../../../.agents/notes/implemented/feature/2026-10-08-windows-game-candidate-overlay.md)。

## 设置文件、数据目录与许可声明

「维护与诊断」页的「设置文件」组导出和导入设置。「导出…」用系统的保存对话框选位置，`msime_client_export_settings` 读出已保存的偏好并换算成设置文件（`app.msime.client.preferences`，规则在 `crates/client-core/src/settings_document.rs`），再先写临时文件后改名写到所选位置。「导入…」用打开对话框选文件，读入（上限 1 MiB）后交给 `msime_client_import_settings`：它保留本机的语音、AI 辅助和翻译服务配置与密钥、诊断日志、使用统计和剪贴板历史开关（所以也不会清空已存的剪贴板历史），文件里的方案本版本不提供时保留本机的方案，然后按本窗口读到的修订号比较并交换写回。导入成功或被拒都会重新读取设置；错误码换成说明的规则在 `SettingsDocumentFile.h`，由 `tests/ui/settings_document_file.cpp` 核对。

同一页的「数据目录」行显示状态根并可在资源管理器中打开。移到其他磁盘要重新运行完整安装包：数据目录登记在 HKLM 的 `DataDir`，改它要管理员权限，安装器的「选择数据位置」一步已经负责复制、切换和删除旧目录，本窗口只说明这条路径。

「关于」页的产品名按版本取（`MSIME_EDITION_DISPLAY_NAME`），「许可与隐私」组的「第三方组件许可」用关联程序打开安装目录下的 `THIRD_PARTY_NOTICES.txt`（本窗口所在 `server` 目录的上一级，与安装器的 `DestDir` 一致）。取舍见 [决策笔记](../../../.agents/notes/implemented/feature/2026-10-10-windows-settings-file-and-local-data-parity.md)。

## 检查更新

「关于」页的「检查更新」在本窗口中完成，不再打开共享应用：工作线程调用 `msime_client_update_check`（`crates/client-services/src/update_check.rs`，与共享设置页、鸿蒙走同一份 Rust 逻辑），请求带 `platform: windows`、本版本 id 和当前版本，结果写在该行下方：「已是最新版本」「暂无可用发行版」「检查失败，请稍后重试」，或「发现新版本 vX」加未签名提示与安装包的 SHA256，按钮随之变成「前往下载」，打开该版本在 GitHub 上的发布页。只接受本仓库的 tag 页地址。当前版本是编译期宏 `MSIME_WINDOWS_VERSION`：`Build-Client.ps1` 用 `/p:MsimeVersion=<TargetVersion>` 传入，开发构建取 `platforms/windows/version.txt`，与 Server 上报的版本相同。

## 连接 AI 助手

「维护与诊断」页的「连接 AI 助手」即共享设置页的同名区块：通过 `msime_client_mcp_status` 和 `msime_client_mcp_install` 显示与 `msime-client-settings.exe` 同目录的 `msime-mcp.exe`、可复制的 MCP 配置，并把它写入 Claude Desktop 或 Cursor 的配置文件。服务器指向的运行时选项取自 Server 注入的 `MSIME_CLIENT_HOST_OPTIONS`，直接启动时取 Server 状态目录（`resolve_state_directory()`，不是 `preferences_directory`）下的 `runtime-options.json`，也就是 Server 启动时读的那一份；两者都没有时说明输入法尚未初始化，不提供配置。写入逻辑与 Tauri 外壳共用 host-api 的 `mcp_clients`。

## 与共享应用的分工

Windows 的表情、手写、屏幕键盘和语音输入面板以及云词库、云剪贴板两个云端面板由同目录的共享 Tauri 应用 `MSIME.exe` 提供；它们是输入工具，不是设置，本窗口不再打开共享应用的任何设置页（`SettingsNavigation.h` 的 `shell_links` 只剩这几个面板，由 `tests/ui/settings_navigation.cpp` 核对）。本窗口通过 `src/system/ShellLauncher.cpp`（与托盘相同的启动器）启动它，数据目录和运行时选项都已知时一并传入，保证两边读写同一份设置。Server 将设置路由发送给 `msime-client-settings.exe`，将面板路由发送给 `MSIME.exe`。

## 构建

在 Visual Studio 开发者命令行中构建：

```powershell
msbuild MSIME.Settings.vcxproj /p:Configuration=RelWithDebInfo /p:Platform=x64 `
  /p:HostApiLibrary=C:\path\to\msime_host_api.dll.lib
```

Windows App SDK 版本由 `WindowsAppSDKVersion` 属性控制，默认值与项目文件固定，发布构建使用 self-contained unpackaged 模式。项目没有 XAML 编译器：应用自己实现 `IXamlMetadataProvider` 并转交给 WinUI 控件库的元数据提供者，界面全部在 `main.cpp` 中用代码构建。


## 界面验收

`CI (platforms)` 的 `Windows native settings` 编译并链接本工程与真实 host-api DLL，再运行 `tests/tools/settings_ui.ps1`。脚本使从真实 host-api DLL 取得完整默认偏好，用独立合成状态，通过 UI Automation 访问全部 16 页，在浅色、深色及 800／1000 宽窗口下保存截图，产物为 `windows-native-settings-screenshots`。本机也可对构建好的宿主运行：

```powershell
powershell -NoProfile -File platforms/windows/tests/tools/settings_ui.ps1 `
  -Program target/windows-full/x64/settings/msime-client-settings.exe `
  -OutputDirectory target/windows-full/x64/settings-screenshots
```

脚本不注册输入法，不修改现有用户偏好；页面运行验收仍不能替代 TSF 在真实编辑器里的输入验证。

「候选窗口 → 游戏」另有 CS2 / Dota 2 原生候选兼容按钮：默认关闭，启用后系统登记名称变为「拼音输入法」，关闭恢复当前 edition 的产品名。它需要 UAC 授权和重启游戏，作用于本 edition 的两份 TSF profile，并由注册流程在升级时保留、卸载时清除。它不写共享偏好；失败恢复原名称，详见[决策笔记](../../../.agents/notes/implemented/feature/2026-10-16-windows-source2-profile-and-local-online.md)。
