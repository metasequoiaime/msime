# Windows WinUI 3 设置

Win7 兼容设置是独立的 Win32 产品范围，只展示本机核心设置；账号、AI、云剪贴板、社区内容和 AI 助手页面不在 Win7 导航或路由中。本文其余章节描述现代 Windows 原生设置和仍由 Win7 共用的业务契约，不能据此推断这些服务页在 Win7 可用。

`MSIME.Settings.vcxproj` 是 Windows 设置窗口的原生宿主（安装后为 `msime-client-settings.exe`）。它使用 Windows App SDK 的 WinUI 3 控件，参考 macOS 原生设置的分组与密度绘制：标题栏里只写当前页名（15 DIP 粗体、正文色，与 macOS 的页面工具栏一样没有跨页面的历史返回按钮），正文不再画页面大标题，顶部是 macOS 的页首引导（`packages/ui/src/settings/settings-mascot-intro.tsx` 的 `SettingsMascotIntro`）：左边一句 13 DIP 的次要色说明，右边一张 80 DIP 的水杉娘插画，窗口矮于 700 DIP 时插画缩到 56 DIP，「关于」页没有这一行；260 DIP 宽的侧栏和单一设置搜索；每组一张带 1 DIP 描边的 10 DIP 圆角卡片。数值取自 macOS 的平台 token（`packages/ui/src/theme/platform-tokens.ts` 的 `groupTitle`、`group`、`groupsGap`）：组名 14 DIP 半粗体、左右缩进 8 DIP、与卡片相隔 8 DIP，组与组相隔 24 DIP；组内每行左右 16、上下 10 DIP 内边距，有说明的行至少 56 DIP 高、没有说明的行至少 44 DIP，14 DIP 标签和 12 DIP 说明，行间 1 DIP 分隔线贯穿卡片整宽，移除重复行图标和开关状态文字，窄行把控件排到标签下方。卡片里不是行的内容（说明文字、表单、子卡片）左右缩进 16 DIP，说明和子卡片上下各留 10 DIP。打开网页或别的设置页的行照共享页的 `LinkRow`：整行是一个按钮，悬停铺中性底色，行尾是灰色的「↗」（窗口外）或「›」（本窗口的另一页），没有单独的「查看」「前往」按钮，「关于」页的「其他平台下载」「历史版本」「隐私政策」「开源许可协议」「第三方组件许可」和问题报告下的「诊断日志」是这种行。「更多选项」一类折叠区照共享页的 `MoreOptions`：标题行与普通行同高、没有边框，标题右边一个灰色「›」，展开时转 90°（系统关掉动画效果时直接转过去），展开后各行带分隔线；标题行的 ItemStatus 是「已展开」或「已收起」。正文边距上 24、左右 48、下 44 DIP（macOS 的 `contentColumn`），正文窄于 640 DIP（窗口拉到 800 宽）时左右退到 32 DIP，因为这个窗口的侧栏不像 macOS 那样在窄窗口时收起。强调色与候选窗统一为品牌绿，浅深色随主题切换。它不启动 Tauri 作为设置界面，也不拥有 TSF 或输入会话。

## 页面

侧栏与 macOS 设置一样平铺 16 个页面，不显示组名，依次是输入、词库、快捷键、标点与翻译、语音输入、屏幕键盘（提供手写的版本叫「键盘与手写」）、主题、候选窗口、悬浮工具栏、剪贴板、AI、插件、打字统计、账号与同步、维护与诊断、关于。顺序和共享设置界面的桌面侧栏一致，即 `settingsNavGroups`（`packages/ui/src/settings/settings-page-registry.ts`）去掉 `desktopMergedPages` 并进「关于」的「帮助与反馈」，定义在 `SettingsNavigation.h`（每页仍记着它在 `settingsNavGroups` 里的组，组只决定顺序），由 `tests/ui/settings_navigation.cpp` 核对，并对照共享路由词表检查；页名在 `main.cpp` 中。导航项照 macOS 侧栏：底色块高 36 DIP、相隔 2 DIP、8 DIP 圆角，14 DIP 文字和 15 DIP 图标；图标是 macOS 侧栏那一套产品图标（`packages/ui/src/assets/*.svg`，见 `app-resources.ts` 的 `settingsIcons`），转成 PathIcon 的路径数据放在 `SettingsNavIcons.h`，前景是正文色、不透明度 0.9，不再用 Segoe Fluent Icons 字形；选中、悬停和按下都只铺一层中性底色（浅色 rgba(0,0,0,.06)、深色 rgba(255,255,255,.1)），文字和图标仍是正文色。标题栏左侧的品牌行是 24 DIP 图标加 15 DIP 半粗体产品名，左缘与导航项的图标列对齐。页首引导的说明逐字取自共享 UI 的 `introductions` 与 `tabIntroductions`，连同插画场景放在 `SettingsMascotIntro.h`：「语音输入」「键盘与手写」「剪贴板」在共享 UI 里按标签各有一句，这三页都显示当前页内标签的那句，切标签时跟着换；「语音输入」的「服务配置」子视图（`page_tabs_` 里的标签 id 是 `service`）没有自己的一句，仍显示「识别与输入」那句，与共享页相同。插画是 `packages/ui/src/assets/mascot/*.webp` 转成的 PNG（`assets/mascot/`），作为 RCDATA 110–119 打进 `Settings.rc`，不依赖系统的 WebP 解码器；图源换了要重新转，`scripts/test-windows-settings-art.py` 核对两边的场景、资源号顺序和侧栏图标的图源。手写设置与共享设置界面的 `handwritingOnScreenKeyboardPage` 一样并进屏幕键盘页，那一页在提供手写的版本里叫「键盘与手写」，分「键盘」「手写」两个页内标签，在不提供手写的版本（日文、越南文、藏文）里仍叫「屏幕键盘」、没有标签也不画手写那一组；`handwriting` 路由打开这一页的「手写」标签，不提供手写的版本打开默认页。

- 全部 16 个页面都在本窗口中原生绘制，没有交给共享应用的设置页。

登录」）、「邮箱登录」「手机号登录」，一种都没有时是一句居中的说明（读到了但没有开、正在重读、读失败三种说法）；两个恢复动作是卡片底部居中的灰色小链接，只在出问题时出现，与共享页相同：没有可用的登录方式（读失败或一个都没开）时给「刷新登录方式」，读不出本机登录状态（`status` 失败）时给「清除失效登录状态」；选了邮箱或手机号后标题换成「邮箱登录」或「手机号登录」、说明换成「我们会发送一个 6 - 现代 Windows 的本窗口没有单独的社区页：社区皮肤是本窗口「主题」页的「社区皮肤」标签，社区插件是「插件」页的「社区插件」标签（见下），`community` 路由打开本窗口的「主题」页。社区的词库与回复模板也不跳共享应用：账号页「我的内容」的四行在「账号与同步」页里换上共享应用在 Windows 上的社区页（`packages/ui/src/community/community-resources.tsx` 的 `CommunityHomePage`，没有皮肤画廊时只有「词库」「回复模板」两个分类），停在那一行的分类和范围上（我发布的是「我的作品」，收藏的是「收藏」），顶上的「账号与同步」回到本页，离开本页时卸下。图库有搜索、「全部 / 收藏 / 我的作品」、卡片和「加载更多」；详情里词库是词条预览、「导入这版词库到本机」（按词条类型分组，以标准格式经 `msime_client_settings_dictionary` 导入本机词库，与共享应用的 `dictionary_request` 相同；Windows 没有命名词库）和「导入这版词库到云端」，回复模板是提示词预览（桌面没有「高情商回复」键盘，不能添加到键盘）；之后是收藏、评分、举报，作者「编辑并发布新版本」和「下架作品」。「发布作品」对话框照 `ResourceEditor`：名称、说明、权利确认（新版本不要），回复模板的提示词（最多 2000 字），词库的词条表单（类型、编码、词语、权重，最多 128 条，不能重复）。社区操作经 `msime_client_community`，都在工作线程上；文案和规则在 `CommunityPageModel.h`，由 `tests/ui/community_page_model.cpp` 核对。社区是作品库，不是设置。AI 对话是 AI 辅助的子页，Windows 的设置应用不提供它（宿主没有 `chat`，共享页因此不显示「AI 对话」一组），`chat` 路由打开「AI 辅助」。
- 帮助与反馈并进「关于」：与共享桌面侧栏一样没有单独的「帮助与反馈」页，它是「关于」页的「帮助与反馈」标签（`build_feedback_sections`，对应共享页的 `FeedbackSections`）。`feedback` 路由（托盘和工具栏菜单的「问题反馈」）打开「关于」的这个标签，`help` 路由（「使用帮助」）再在那里打开帮助视图。标签里先是「帮助」一行（「安装、切换输入法与常见问题」，行尾「›」），点它在原处换成帮助视图，对应 macOS 设置的「帮助」子页（`packages/ui/src/settings/help-settings-page.tsx` 的 macOS 分支）：顶上「关于」回到标签页（焦点落回「帮助」那一行），然后是页名「帮助」、「开始输入」「候选词释义」「遇到问题」三张术语卡片（左边 170 DIP 的按键或术语，右边的说明，第一行下面一条分隔线）和「更多 / 打开官网」一行（默认浏览器打开 https://msime.app/docs/）。卡片的问法和版式照 macOS，内容写 Windows 的：Win+Space（「默认是…输入法」按本版本的默认方案写，五笔、日语、越南语、藏文各版不是全拼）、Shift、数字键、翻页键、Ctrl+Shift+Space 和 Alt+Shift+H；「候选词释义」讲离线词库优先、在线服务（「标点与翻译」页的「翻译服务」）、两种语言，以及释义列快捷键（`GlossColumnPolicy.h`）：macOS 的 Option / Control 加数字在 Windows 上是 Alt / Ctrl 加数字（Alt 是目标语言，Ctrl 是第二种语言），Tab / Shift+Tab 在高亮候选有释义时换列、没有释义时照常翻页；「遇到问题」里输入法不在列表里时去 Windows「设置 › 时间和语言 › 语言和区域」添加，候选旁没有释义时先看「显示英文释义」或「候选词翻译」开着没有。从别的页回到「关于」时帮助视图关上；搜索落到卡片上时直接打开它。

「悬浮工具栏」页照共享页（`packages/ui/src/settings/pages/floating-toolbar-page.tsx`）在 Windows 上的样子：页首是无标题组里的预览（共享页的 `SettingsPreviewBlock`：12 DIP 次要色的「预览」小字，下面是与主题卡片预览面同样底色的一块，工具栏靠左，太宽时横向滚动），然后是「显示」组（「在桌面显示悬浮工具栏」）、「按钮」组（「勾选要显示在悬浮工具栏上的按钮」，各按钮的复选框（不提供手写的版本没有「手写识别板」）按工具栏上的顺序排成纵向一列，14 DIP 字）和「尺寸」组（「工具栏大小」，末尾是跳到「主题」页「颜色模式」的跳转行「颜色与明暗」）。预览按原生工具栏的度量（`ToolbarLayout.h`）和 `toolbar_palette` 画当前设置的按钮、大小和 logo，按钮状态是默认输入状态；下面不再写尺寸和状态那一行，画出来的 DIP 尺寸只写在「预览」小字的读屏帮助文本里（自动化 ID `toolbar-preview-label`，读屏名「悬浮工具栏预览」），界面验收靠它确认调整按钮后预览跟着变。

`canvas` 包的卡片与社区「生成预览图」共用静态离屏绘制：支持明暗面板、九宫格、内容与外留白、拼音行距以及前后层自由挂件，只展示包声明支持的排列。图片与真实候选窗共用解码器，GIF 首帧保留逻辑画布和帧偏移；面板解不出来时用安全配色。预览不播放动画，也不代替真实候选窗的焦点、定位、材质或缩放验收。

「候选窗口」页照共享设置的桌面版（`appearance-page.tsx`）分四个页内标签（`candidateTabs`，自动化前缀 `candidate-tab`）：「布局」「字体与大小」「窗口样式」「预编辑」，每个标签里一组，组名与标签同名；标签条和标签内容之间是一张无标题卡片里的预览（见下文的实时预览）。「布局」是候选项排列方式、每页候选项数量、显示水杉 logo 和跟随光标；「字体与大小」是候选字体（及按需出现的主字体）、字号、英文字体和整体大小；「窗口样式」是不透明度和圆角大小；「预编辑」是预编辑字号、候选窗口预编辑和行内预编辑（「双拼预编辑」在「输入」页「输入方案」标签的双拼详情里）。搜索落到某一行时切到它所在的标签。每页候选项数量照共享页的 `CandidatePageSizeSection` 是 3–9 的带刻度滑块、没有说明，存着的值不在这个范围里时把范围放宽到它而不改写（`offeredCandidatePageSizes`，Windows 的上限是 9）；字号和预编辑字号是 12–32 的下拉框、没有说明；整体大小和不透明度的说明随数值变化（「N%，字号与窗口尺寸一起缩放」「N%，文字和焦点高亮保持不透明」），拖动时就地更新；圆角大小旁边是「跟随皮肤」按钮，跟随时它是按下的、说明是「跟随皮肤；设置后覆盖皮肤自带的圆角」，拖动滑块后说明变成「Npt，覆盖皮肤自带的圆角」、按钮抬起，再点它清掉覆盖值。这三个滑块旁不画数值，数值只写在说明里：共享页这几行只传 `valueText`、不传 `displayValue`，`valueText` 只是读屏用的 `aria-valuetext`，不画出来。「游戏」组管游戏里候选窗能不能出现，是 Windows 独有的功能开关而不是外观，不属于哪个标签，画在标签内容下面、一直显示，搜索结果的位置也不带标签名。字体各行照搬共享页在 Windows 上的样子（`CandidateFontPresetRow` 与 `CandidateFontControls`），不跳共享应用：「候选字体」预设（默认、宋体、黑体、楷体、圆体，Windows 没有自带圆体，该项禁用，末尾是「自定义…」）照共享页的 `SegmentedRow` 画成六段的分段控件，不退成下拉框，同时写 `candidate_font_family` 和有序的 `candidate_fallback_fonts`；选「自定义…」只亮出「主字体」框、不改字体，字体不是任何预设时打开页面就是「自定义…」和字体框，选回预设时字体框收起；「主字体」在 Windows 上同时排到回退列表最前；「英文字体」写 `candidate_english_font`，未设置时显示 Segoe UI。原来单独的「系统字体列表」一行并进了第一个可见的字体框：读取状态写在那一行下面，「刷新」按钮（读屏名「刷新字体列表」）在输入框旁边；主字体框收起时由同一组里的英文字体框带着。预设、主字体框何时出现和字体名的规则在 `CandidateFontPresets.h`，由 `tests/ui/candidate_font_presets.cpp` 核对。字体列表由 `msime_client_list_font_families` 读取（与 Tauri 的 `list_font_families` 同一份 `system_fonts` 目录），第一次点开字体输入框时在工作线程上读，读取状态在原处更新，不重建页面，输入框不会丢掉焦点。下拉按用户区域设置不分大小写地筛选（`LCMapStringEx`）。名字不合法（空、超过 128 个 UTF-8 字节或含控制字符）时不写入，输入框标红，框下显示「名称不能为空、不能含控制字符或超过 128 个 UTF-8 字节。」，读屏从输入框的帮助文本读到同一句。

「输入」页「高级选项」标签的「辅助码」组排在模糊音之后、调频之前，辅助码方案下拉框和共享设置的 `HelpcodeSettingsGroup`（`packages/ui/src/settings/pages/helpcode-page.tsx`）规则相同，辅助码插件也在这里选，不跳共享应用。选项依次是内置方案、资源目录 `helpcodes/custom` 里的自定义码表（`custom/<文件名>`，由 `msime_client_helpcode_schemas` 读宿主选项的 `resources`，名字是「中文名 (英文名)」）和已安装的辅助码表插件（「插件名（插件）」，取自 `msime_client_plugins` 的 `catalog` 中种类为 `helpcode` 的包）。选插件只写 `plugins.helpcode_pack_quanpin` / `helpcode_pack_shuangpin`，输入引擎用它替换内置方案；选内置或自定义方案时同时清空插件。已选的插件不在了显示为「id（插件，未找到）」，资源目录读不到时已选的自定义码表也留在列表里。自定义码表只读一次，插件每次进入「输入」页重读，都在工作线程上读。本版本提供全拼或双拼之一就显示这一组，不看当前方案（共享页的 `editionUsesHelpcode`）；与共享页的桌面形态一样，主流程是当前方案那一族的「X辅助码」「X辅助码方案」「在候选窗口中显示X辅助码」三行（双拼方案是双拼，其他方案是全拼），另一族的三行收在组末的「更多选项」里；「在候选窗口中显示…辅助码」不随开关变灰；Windows 不是 Shift 输入辅助码的宿主（`helpcode_shift_entry` 为 false），所以没有共享页那段 Shift 说明。

选用五笔时，「输入」页「输入方案」标签的「方案」组提供「五笔快捷选词」（`wubi_candidate_selection`，默认关闭）：开启后默认用 `;` / `'` 选择当前页第 2、3 候选，候选不足时仍输入标点。两个候选键可改为不同的英文标点，按「保存选词键」一起保存。输入时与共享页一样就地校验（`InputSettingsModel.h`）：不是两个不同的单个英文标点时，「自定义选词键」的说明换成「请输入两个不同的单个英文标点。」，保存按钮变灰；保存时共享偏好库再校验标点、重复与翻页/以词定字冲突，拒绝时恢复已保存设置并提示。关闭后保留自定义键位。通用的二三候选（`second_third_candidate`）是另一项偏好，与 macOS 一样不在设置窗口里。

选用五笔时，「输入」页「输入方案」标签在方案组后面有「五笔查码」组，与共享设置的 `WubiCodeLookupSection`（`packages/ui/src/settings/wubi-code-lookup-section.tsx`）相同：输入或粘贴汉字（最多 1000 个字符）后「查码」，经 `msime_client_settings_dictionary` 发只读的词库请求 `wubi_codes`，在工作线程上查；结果表列出整段文字作为一个词和每个不同汉字的 86、98 五笔编码（简码在前，码表里没有时写 —），当前选用的码表标「（当前）」，字太多时说明只列出了前多少个。

`--route=settings:<id>` 指定打开的页面，可以是共享路由的设置分类 id（`appearance`、`dictionary`、`about` 等，映射见 `route_aliases`），也可以是本窗口的页面 id；其他值打开默认的「输入」页。

## 页面与导航

窗口参照 macOS 原生设置：侧栏只保留一个设置项搜索，正文工具栏显示当前页面。打字一组的三页照共享设置的桌面分支分页内标签。「输入」（`pages/input-page.tsx`、`input-tabs.ts`）是六个：「输入方案」是「方案」组（「输入语言」下拉：中文、日文、韩文、越南文、藏文，只列本版本有的，只剩一项时不画；当前是中文方案时下面是三列「中文方案」卡片单选，选中的卡片是强调色描边加淡强调色底；再往下是当前方案的选项行，日语、韩语、粤拼、注音、笔画、藏文各一行说明；双拼方案文档里已是自定义双拼（比如从 macOS 同步来）时下拉框列一项灰的「自定义双拼」）和选用五笔时的「五笔查码」；「中英模式」是「中英文」组，「默认中英文」「中英文状态」是下拉框；「选词与翻页」是以词定字（「关闭 / [ / ] / - / =」分段，被翻页占用的键组那段按不下去）、退格回退和翻页方式；「候选与联想」开头是云候选，「云候选来源」之后按来源、请求方法和响应格式出现各行，按「保存云候选服务」整份交给 Rust 校验；「输出设置」是「中文输出」（简体 / 繁体分段，说明随选项和方案变）、中英文之间加空格和全角输入；「高级选项」依次是快捷模式、逐个模式（「更多选项」里每个模式一行带说明的开关，总开关关着时 Shift+字母进入的各行变灰，另有「@ 地名」）、模糊音（「启用模糊音」打开后才有分四个小标题的规则和「重置模糊音配置」，重置先确认）、辅助码和拼音方案调频。「快捷键」（`shortcuts-settings-section.tsx`）分「按键设置」（页首说明、「输入模式切换」组和组末只读的「Ctrl+Space（由 Windows 管理）」）和「按键速查」（只读键帽：至少 120 宽、圆角 5，翻页那几组按当前生效的列出，Tab 和 PageUp / PageDown 固定算开，多组时排到标题下方、按自身宽度靠左排，放不下时折行，最后是 Ctrl+Shift+Win+K 打开屏幕键盘）。「标点与翻译」（`expression-tabs.ts`）分「标点设置」「候选释义」「翻译服务」。macOS 设置里没有的「二三候选」「自动纠错」和「恢复默认快捷键」不在窗口里，偏好和输入行为不变。列表和文案在 `InputSettingsModel.h`，由 `tests/ui/input_settings_model.cpp` 核对。原有路由 id 不变，搜索结果按新归属打开页面和标签。

侧栏搜索照 macOS（`settings-style.ts` 的 `sidebarSearch`，`use-settings-shell-navigation.tsx` 的结果列表）。搜索框 32 DIP 高、圆角 8、没有描边，底色浅色 rgba(0,0,0,.055)、深色 rgba(255,255,255,.07)，左边是 15 DIP 的次要色放大镜，占位文字「搜索」，聚焦时一圈 2 DIP 的强调色边框；它是普通的 `TextBox`（自动化 ID `settings-search`，读屏名「搜索设置」），不再有下拉建议。输入后侧栏的页面列表整个换成结果列表（`settings-search-results`，放在导航视图的 PaneCustomContent 里，页面列表的各项在查询期间收起）：先是名字匹配的页面（也认共享设置 UI 的注册名，「屏幕键盘」找得到「键盘与手写」，「AI 辅助」「AI 助手」找得到 AI 页），再是标题匹配的设置行；说明文字不参与匹配，条数不设上限，同一位置的同名行只列一次。每条是 13 DIP 的标题，设置行下面是 12 DIP、60% 不透明度的位置「页 › 标签 › 分组」，没有标签或分组时省掉那一段；高亮的那条铺 15% 的强调色（ItemStatus「已选择」），悬停 10%。查询按 trim 后不分大小写匹配；查不到时写「没有匹配的设置」。上下键移动高亮、回车打开，Esc 清空查询，输入法组字期间不接管这几个键。打开一条结果时先清空查询、换回页面列表：页面结果只切到那一页；设置行切到所在的页和标签，展开所在的折叠区，滚到那一行，是控件时把键盘焦点交给它。换明暗重建外壳时保留查询和结果。

页内顶部标签照共享设置 UI 的 `useSettingsTabs`（桌面的 `candidateTabs` 样式），`main.cpp` 里是 `page_tab_bar` 加 `in_tab`，后续要分标签的页面都用它，不要再各自拼一个分段控件：标签条铺满正文宽度、各段等宽，段至少 36 DIP 高、14 DIP 正文色的字，底色照 macOS 的 `--p-seg-bg`（浅色 rgba(0,0,0,.055)、深色 rgba(255,255,255,.08)）、没有描边，选中浮起与紧凑分段控件相同（`segmented_control` 的 `full_width`），段数不受三段的限制；与页首引导、下面的第一组各相隔 24 DIP。一次只画选中标签的那几组；选中哪个标签按页面 id 记在窗口里（`page_tabs_`），跨页面保留、不写偏好，没选过时是第一个。切标签时整页重画，页首引导换成这个标签的说明和插画。建搜索索引时每个标签的内容都画，每个条目记下所在的标签；选中搜索结果时先切到那个标签再画页面（折叠区仍由 `fold_holds_focus` 展开）。打开某个标签的路由在构造窗口时写进 `page_tabs_`（`mcp` 打开 AI 页的「连接助手」，`handwriting` 打开「键盘与手写」的「手写」，`vocabulary` 打开「词库」的「管理词库」并进入背单词子页）。标签按钮的自动化 ID 是 `<前缀>-<标签 id>`，选中的那个 ItemStatus 是「已选择」。现在用它的是「输入」（`input-tab`）、「快捷键」（`shortcuts-tab`）、「标点与翻译」（`expression-tab`）、「语音输入」（`voice-tab`）、「键盘与手写」（`osk-tab`）、「候选窗口」（`candidate-tab`）、「剪贴板」（`clip-tab`）、AI（`ai-settings`）、「词库」（`lexicon-tab`，标签条不铺满，见上）和「关于」（`about-tab`，没有页首引导，标签条顶上不留与引导相隔的那一段）十页；「输入」有六个标签，最窄的窗口里放不下一行字的段把字折成两行，同一排的段一起变高。行内的小分段（发声方式、效果样式等）和打字统计、社区图库的标签仍是紧凑样式。

实时预览位于「候选窗口」页的独立预览区域（「主题」页不画它，也没有页头的「界面预览」开关，卡片本身就是预览），横向候选可滚动；「候选窗口」页把它放在标签条下面的一张无标题卡片里，照共享页 `groupPreview` 左右留 24、上 20、下 30 DIP。预览顶上是共享页 `AppearanceCandidatePreview` 的说明「预览：固定样例随当前设置草稿变化，不代表实际输入候选。」（12 DIP 次要色，与预览面相隔 18 DIP）。默认样例与共享页的 `previewSamples` 相同：首行是水杉 logo（随「显示水杉 logo」）、拼音 ni'mf 和光标，候选是你们、你、尼、妮、泥、逆、拟、腻、拧；方案是全拼或双拼、这一族的辅助码打开且「在候选窗口中显示」时，候选后面带上辅助码（如「你们(rR)」）。拼音隐藏时首行只剩 logo，logo 也关掉时首行不画。示例文字框、预览明暗下拉和页头的「界面预览」开关、「编辑主题」按钮是 Windows 自己的比较工具，macOS 没有，有意保留：示例文字可按空格分成候选，短列表循环填满一页（不带辅助码）；清空恢复默认示例。预览明暗可单独切换，也可跟随保存的设置；示例和预览明暗在离开再回到页面后保留，仅保存在当前窗口。选着自定义主题、预览明暗那个槽位里的皮肤包在目录里、能在这种明暗下画并支持当前排列方式时（照共享页 `ExternalAppearancePreview`），预览除了包经 `msime_client_resolve_theme` 解析出来的配色，还照候选窗画包的圆角（用户设了圆角时用用户的）、最小宽度、背景图（按卡片内圈圆角裁切，透明度乘上窗口不透明度）和装饰图（卡片上方留出随整体大小缩放的装饰带，图的底边压进卡片顶边一个内边距，按清单的对齐方式摆放）；画布皮肤只画配色。为此「候选窗口」页和「主题」页一样，进入时和窗口重新获得焦点时重扫皮肤目录（只在自定义主题设了皮肤包时），扫描落地、图片解码完成或失败时只重画预览，不重画整页。

## 外观与主题预览

窗口以 macOS 的紧凑分组布局为依据，强调色固定为浅色 `#2C7A4B`、深色 `#5FBF84`（与候选窗口原生调色板相同），不跟随 Windows 的个性化强调色。深色的强调色只用于开关、复选框、滑块这类不带文字的填充；底上是白字的填充（主按钮、默认输入法提示条的按钮、账号头像、社区资源图块）在深浅两种外观里都用 `#2C7A4B`，与共享页的 `--accent-strong` 相同，保证白字可读。配色取 macOS 设置外壳的值：侧栏（窗口底色）浅色 `#E8E8EA`、深色 `#2E2E30`，右侧一条 1 DIP 边线（浅色 rgba(0,0,0,.08)、深色 rgba(0,0,0,.5)）；正文浅色 `#F2F2F4`、深色 `#1F1F21`，标题栏里正文上方那一列也是正文色，底部一条细线；分组卡片浅色白底、深色 `#29292B`（正文上叠 4.5% 白），描边浅色 rgba(0,0,0,.06)、深色 rgba(255,255,255,.07)。窗口的明暗跟随颜色模式，不读 `settings_theme`。

「候选窗口」「输入」「标点与翻译」页的候选窗口预览和「主题」页的「自定义」主题卡片不自己配色：它们用与 Server 相同的请求（全局主题、去掉键盘设计和编号色、边框色的 `custom_theme`、候选窗口自己的明暗与排列方式、数据目录下的 `skins`）调用 `msime_client_resolve_theme`，再用 `src/candidate/CandidatePalette.h` 合成调色板，并按 `CandidateWindow.cpp` 的规则绘制选中行、序号和选中条（共享页的样例不带翻译，预览也不画），所以自定义主题的 `candidate_colors` 与皮肤包会反映在预览里。内置主题卡片也走这条路，按卡片画的明暗解析；「自定义」卡片和共享页一样只画不带皮肤包的自定义主题，请求里去掉两个皮肤槽位和皮肤目录；皮肤包卡片的配色见上文。

## 默认输入法提示

每页标题上方的橙色提示条对应设计稿的 deskStrip：水杉输入法不在当前用户的键盘列表中时显示「去添加」，已添加但不是默认输入法时显示「设为默认」。状态通过 `input.dll` 的 `EnumEnabledLayoutOrTip` 读取（无头文件和导入库，运行时加载），按钮分别调用 `InstallLayoutOrTip` 和 `SetDefaultLayoutOrTip`；添加失败时打开「语言和区域」。`input.dll` 无法回答时不显示提示条。窗口重新获得焦点时重新检查。

## 保存

设置窗口通过 `msime_client_load_preferences` 和 `msime_client_save_preferences` 读取、校验并以 compare-and-swap 方式保存共享偏好。每个控件改动后立即保存，滑块停止拖动后保存；保存被拒绝（其他窗口已更新或与其他设置冲突）时重新读取并在页面顶部说明。窗口重新获得焦点时重新读取，以反映托盘、共享应用或同步带来的变化。数据目录必须与 Server 的状态根相同：Server 启动它时注入 `MSIME_CLIENT_STATE_DIR`，直接用这个目录；从开始菜单直接启动时没有这个变量，就按 Server 的方式自己解析，先用 `common/StateDirectory.h` 的 `resolve_state_directory()`（本版本的数据目录环境变量、安装器在 HKLM 记下的 `DataDir`、`%LOCALAPPDATA%\<本版本的状态目录>`），那里的 `runtime-options.json` 写了绝对路径的 `preferences_directory` 时再改用它，与 `server_main.cpp` 的 `production_preview_document` 和 Tauri 外壳的 `windows_server_preferences_directory` 一致。以前开始菜单启动直接回落到 `%LOCALAPPDATA%\MSIME-Client`，而默认安装的 Server 用的是安装器的 `DataDir`（`%LOCALAPPDATA%\metasequoiaime-full`），这个窗口里改的开关（包括 `/`、`@` 和 K 模式、辅助码）就都写进了 Server 不读的文件。顺序在 `SettingsStateDirectory.h`，由 `tests/ui/settings_state_directory.cpp` 核对。

控件按偏好的点分路径读写文档，路径可以任意深（`plugins.key_sound.enabled`、`custom_theme.candidate_colors.surface`）。写入时缺的中间层从随包默认值里同一路径的对象复制而来，默认值里也没有才是空对象，因为存储只整体接受一个嵌套对象；删除一项时不补中间层，读取随之回落到默认值。`ai_assistant.tokens` 这类以来源为键的表，表项的键里可能有点，所以单独给出、原样作为最后一段。列表有两种写法：顺序没有意义的列表排序并去重后写入，顺序由用户决定的列表原样写入。路径规则在 `PreferencePath.h`，与 JSON 实现无关，由 `tests/ui/preference_path.cpp` 用一棵假的树核对。

「候选窗口」页「游戏」组的两张程序列表（`game_compatibility.overlay_processes`、`excluded_processes`）在写入前先按偏好库的规则规范化和校验（`GameProcessList.h`）：去掉首尾空白、ASCII 字母转小写，要求以 `.exe` 结尾、不超过 64 个字符、不带路径和 `\ / : * ? " < > |` 及控制字符，两张表之间不重复、合计不超过 32 条。不合法时在列表下方说明具体原因，不写入文档：保存被拒时窗口只能给出上面那句笼统的说明，用户看不出是哪一项出了问题。这组设置只由 TSF DLL 在每次激活时读取，对已打开的游戏要切换一次输入法才生效，取舍见 [决策笔记](../../../.agents/notes/implemented/feature/2026-10-08-windows-game-candidate-overlay.md)。

## 维护与诊断、设置文件与许可声明

「维护与诊断」页照共享页（`packages/ui/src/settings/pages/developer-page.tsx`）在 Windows 上的样子依次画四组：「输入法服务」是一句「请求受监督的输入法服务重新启动。」和「立即重启输入法服务」一行，「重启」与共享应用的 `restart_input_method` 走同一条路，往本版本 Server 的 Aux 管道（`FANY_IME_AUX_NAMED_PIPE`）写 UTF-16LE 的 `RestartServer`，Server 只收本用户完整桌面进程发来的这条消息，以重启退出码结束后由看门狗重新拉起；结果写在页面顶上（「已发送重启请求。」或「重启输入法服务失败，请稍后重试。」）。「诊断日志」是「Server 端日志」开关、「日志文件」一行（「打开日志目录」打开数据目录下的 `logs`，还没写过日志时打开数据目录本身）和「TSF 端日志」开关，标题和说明与共享页的 Windows 一支逐字相同。「数据目录」见下。最后是 Windows 独有的「设置文件」组，导出和导入设置。macOS 的「卸载」一组不画，Windows 从系统的「应用」设置卸载。

「设置文件」组：「导出…」用系统的保存对话框选位置，`msime_client_export_settings` 读出已保存的偏好并换算成设置文件（`app.msime.client.preferences`，规则在 `crates/client-core/src/settings_document.rs`），再先写临时文件后改名写到所选位置。「导入…」用打开对话框选文件，读入（上限 1 MiB）后交给 `msime_client_import_settings`：它保留本机的语音、AI 辅助和翻译服务配置与密钥、诊断日志、使用统计和剪贴板历史开关（所以也不会清空已存的剪贴板历史），文件里的方案本版本不提供时保留本机的方案，然后按本窗口读到的修订号比较并交换写回。导入成功或被拒都会重新读取设置；错误码换成说明的规则在 `SettingsDocumentFile.h`，由 `tests/ui/settings_document_file.cpp` 核对。

同一页的「数据目录」组照共享页的 `DataDirectorySection`：组注说明哪些数据放在这里以及怎样搬走，「当前目录」一行用 Consolas 显示状态根，「打开」在资源管理器中打开它。共享页在 macOS 和 Linux 上有「选择位置…」，这里没有：数据目录登记在 HKLM 的 `DataDir`，改它要管理员权限，安装器的「选择数据位置」一步已经负责复制、切换和删除旧目录，所以组注写的是重新运行完整安装包这条路径。

「关于」页照共享页（`packages/ui/src/settings/pages/about-page.tsx`，标签取 `about-tabs.ts`）分「版本更新」「帮助与反馈」「系统信息」「许可与隐私」四个页内标签，一次只画一个，打开时是「版本更新」。「版本更新」是品牌卡（`AboutHeroSection`：62 DIP、圆角 16 的浅底标志块里 48 DIP 的产品图标，「Metasequoia IME」小字、22 DIP 半粗体的产品名、「为现代 Windows 桌面体验打造的开放中文输入法。」，右边 112 DIP 的 welcome 插画）和「版本与更新」组（「当前版本」、「其他平台下载」「历史版本」，见下文「检查更新」）。「系统信息」逐项列出应用版本（非完整版带版本名，有发布日期时带上）、系统（Windows 加 `RtlGetVersion` 的版本号）、处理器架构（本程序编译成的，写法同 Rust 的 `std::env::consts::ARCH`）和输入方案，报不出的项省略；最后一行「复制系统信息」把「水杉 IME 系统信息」加每项一行「名称：值」放进剪贴板，按钮显示「已复制」1.6 秒。各项和文本格式在 `AboutPageModel.h`，由 `tests/ui/about_page_model.cpp` 核对。「许可与隐私」依次是「开源许可协议」（↗）、「许可与版权」（「水杉 IME 以 GPL-3.0 发布；第三方组件许可随应用资源提供。」，行尾「© 2026 Metasequoia IME」）、「第三方组件许可」（↗）、「隐私政策」（↗）、「匿名使用统计」开关（「不含输入内容、候选和剪贴板；关闭后不再发送。」）和「发送哪些内容」：共享页这一行进「发送哪些内容」子页，这里是同一位置的折叠区，展开后是同样的「发送什么」「每条包含」「不包含」「其他」四组。

「关于」页的产品名按版本取（`MSIME_EDITION_DISPLAY_NAME`），「许可与隐私」的「第三方组件许可」用关联程序打开安装目录下的 `THIRD_PARTY_NOTICES.txt`（本窗口所在 `server` 目录的上一级，与安装器的 `DestDir` 一致）。取舍见 [决策笔记](../../../.agents/notes/implemented/feature/2026-10-10-windows-settings-file-and-local-data-parity.md)。

## 检查更新

「关于」页「版本更新」标签的「当前版本」一行照共享页：说明是版本号，行尾「检查更新」（检查中写「正在检查…」）。检查在本窗口中完成，不再打开共享应用：工作线程调用 `msime_client_update_check`（`crates/client-services/src/update_check.rs`，与共享设置页、鸿蒙走同一份 Rust 逻辑），请求带 `platform: windows`、本版本 id 和当前版本，结果写在版本号下面：「已是最新版本」（下面再加 64 DIP 的 updated 插画）「暂无可用发行版」「检查失败，请稍后重试」或「发现新版本 vX」。发现新版本时这一行下面单列结果块（共享页的 `updateResult`）：「水杉 IME vX 已发布。」、未签名时的红字警告、有摘要时「下载后请核对 SHA256：」和「核对命令：」（`Get-FileHash`，都用 Consolas），然后是「国内镜像下载」（`https://dl.msime.app/gh/` 加该版本安装包在 GitHub 上的下载地址，照共享页的 `mirrorDownloadUrl`；回答里没有合形状的安装包名时不画）和「前往下载」（官网下载页）。只接受本仓库的 tag 页地址；安装包名和摘要照共享页先查形状，不合的当作没有。结果块各项的拼法在 `AboutPageModel.h`。当前版本是编译期宏 `MSIME_WINDOWS_VERSION`：`Build-Client.ps1` 用 `/p:MsimeVersion=<TargetVersion>` 传入，开发构建取 `platforms/windows/version.txt`，与 Server 上报的版本相同。版本号后面附发布日期（`v0.2.1（2026-10-19 发布）`），来自编译期宏 `MSIME_WINDOWS_RELEASE_DATE`：工程依次取环境变量 `MSIME_RELEASE_DATE`、`platforms/windows/release-date.txt` 和 git 当前提交的日期，都没有时只显示版本号；检查更新和反馈报告仍只带版本号。

## 连接 AI 助手

「AI」页「连接助手」标签里的「连接 AI 助手」即共享设置页的同名区块（`packages/ui/src/settings/mcp-connect.tsx` 的 `McpConnectSection`）：通过 `msime_client_mcp_status` 和 `msime_client_mcp_install` 显示与 `msime-client-settings.exe` 同目录的 `msime-mcp.exe`，并把它写入 Claude Desktop 或 Cursor 的配置文件。说明之后是一排紧凑的「AI 助手」标签（自动化 ID `mcp-tab-<标签>`，打开时是 Claude Code）：Claude Code、Codex（安装命令和「之前添加过的」移除命令，各配「复制命令」「复制移除命令」）、命令行（不注册 MCP、在终端里直接调用工具的说明，配「复制说明」）、找到服务器程序时每个可写入的助手一个（「写入 <配置文件>（已连接），重新启动 X 后生效。」，按钮是「写入 X」，已连接且权限一致时不可按；权限和现有条目不同或条目指向 Nix store 里以前那一版时给提示并改成「更新 X」，写入期间写「正在写入…」）、其他（加上权限的 MCP 配置，配「复制配置」），标签多于正文宽度时整排横向滚动。命令和配置按种类着色（程序、参数、字符串、占位符、键，颜色取共享页的 `--syntax-*`，等宽 12 DIP，命令折行、配置横向滚动），复制后按钮显示「已复制」1.6 秒再复原，复制失败时顶上说一句。下面是写入结果和两个权限开关「允许修改设置」（`--allow-write`）、「允许读取词库」（`--allow-dictionary-read`）：命令、配置和一键写入都带上开着的权限（写入时作为 `flags` 交给 `msime_client_mcp_install`）；已连接的助手标签上开关先显示它现有条目的权限，改了之后在写入前一直保留；带权限写入前先弹「允许 X 中的助手使用这些权限？」确认框，主按钮「允许并写入」，已有另一个同名条目时再问要不要替换。开关的选择存在当前用户本版本的注册表键（`MSIME_EDITION_REGISTRY_KEY`）的 `McpFlags` 值里，与共享页的 localStorage 一样只属于这台电脑，没存过时两项都开。最后是信任提示和「服务器程序 <路径>」。命令里的服务器名是本版本登记的名字（full 是 msime）。命令、配置、授权说明和提示的文字在 `McpConnect.h`，由 `tests/ui/mcp_connect.cpp` 核对。服务器指向的运行时选项取自 Server 注入的 `MSIME_CLIENT_HOST_OPTIONS`，直接启动时取 Server 状态目录（`resolve_state_directory()`，不是 `preferences_directory`）下的 `runtime-options.json`，也就是 Server 启动时读的那一份；两者都没有时说明输入法尚未初始化，不提供配置。写入逻辑与 Tauri 外壳共用 host-api 的 `mcp_clients`。

## 与共享应用的分工

Windows 的表情、手写、屏幕键盘、语音输入和背单词面板以及云词库、云剪贴板两个云端面板由同目录的共享 Tauri 应用 `MSIME.exe` 提供；它们是输入工具，不是设置，本窗口不再打开共享应用的任何设置页（`SettingsNavigation.h` 的 `shell_links` 只剩这几个面板，由 `tests/ui/settings_navigation.cpp` 核对）。本窗口通过 `src/system/ShellLauncher.cpp`（与托盘相同的启动器）启动它，数据目录和运行时选项都已知时一并传入，保证两边读写同一份设置。Server 将设置路由发送给 `msime-client-settings.exe`，将面板路由发送给 `MSIME.exe`。

## 构建

在 Visual Studio 开发者命令行中构建：

```powershell
msbuild MSIME.Settings.vcxproj /p:Configuration=RelWithDebInfo /p:Platform=x64 `
  /p:HostApiLibrary=C:\path\to\msime_host_api.dll.lib
```

Windows App SDK 版本由 `WindowsAppSDKVersion` 属性控制，默认值与项目文件固定，发布构建使用 self-contained unpackaged 模式。项目没有 XAML 编译器：应用自己实现 `IXamlMetadataProvider` 并转交给 WinUI 控件库的元数据提供者，界面全部在 `main.cpp` 中用代码构建。


## 界面验收

`CI (platforms)` 的 `Windows native settings` 编译并链接本工程与真实 host-api DLL，再运行 `tests/tools/settings_ui.ps1`。脚本使从真实 host-api DLL 取得完整默认偏好，用独立合成状态，通过 UI Automation 访问全部 16 页，在浅色、深色及 800／1000 宽窗口下保存截图（「输入」「快捷键」「标点与翻译」的其余标签也逐个切过去截图，并确认「输入」页不再出现「二三候选」「自动纠错」），并核对侧栏搜索：结果替换页面列表、页面结果在前、设置行的位置写成「页 › 标签 › 分组」、查不到时的「没有匹配的设置」、Esc 换回页面列表，以及回车打开的结果切到所在标签、展开折叠区（「键盘与手写」的「打开手写识别板」，「输入」页「高级选项」里的「@ 地名」）；「关于」的四个标签和帮助视图、「维护与诊断」的四组也逐一核对（不点「重启」和各个复制按钮）；最后经 `MSIME_CLIENT_HOST_OPTIONS` 给一份合成运行时选项再开一次窗口，核对连接助手的助手标签、权限开关和「复制命令」点后显示「已复制」再复原（会改写系统剪贴板）；产物为 `windows-native-settings-screenshots`。本机也可对构建好的宿主运行：

```powershell
powershell -NoProfile -File platforms/windows/tests/tools/settings_ui.ps1 `
  -Program target/windows-full/x64/settings/msime-client-settings.exe `
  -OutputDirectory target/windows-full/x64/settings-screenshots
```

脚本不注册输入法，不修改现有用户偏好；页面运行验收仍不能替代 TSF 在真实编辑器里的输入验证。

## 缩放与滚轮验收

`app.manifest` 经 MSBuild 合并进最终可执行文件，声明 PerMonitorV2 与 PerMonitor 回退；保留 Windows App SDK 注入的 WinRT 激活清单。默认 SDK 使用 1.7.9（`1.7.260224002`），包含 1.7.5 对关闭「悬停时滚动非活动窗口」后丢失滚轮输入的修复。

`tests/tools/settings_ui.ps1` 直接查询真实窗口的 DPI 上下文，并分别在两种滚轮路由下发送鼠标滚轮，读取正文滚动位置是否改变；测试恢复原系统设置和指针位置。`-InputOnly` 可只跑这一部分。运行需要交互式 Windows 桌面；SSH 的非交互窗口站不能代替它。
