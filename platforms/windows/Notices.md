# Third-party notice collection

Win7 安装包另在 `server/fonts/` 随字体分发 Google Noto Emoji 的完整 OFL-1.1 许可证与固定来源记录，见 [`assets/fonts/README.md`](assets/fonts/README.md)。字体不安装到系统，仅供候选窗口与表情面板的进程私有排版使用。

`Collect-Notices.ps1` produces `target/windows-notices/THIRD_PARTY_NOTICES.txt` from notices committed in this repository, supplied dependency-prefix copyright files, and optional supplemental documents. Packaging selects that generated file by default when present; explicit `NoticesDirectory` remains authoritative.

```powershell
.\platforms\windows\Collect-Notices.ps1 -DependencyPrefixes C:\deps\x64,C:\deps\x86 -SupplementalNotices C:\release\rust-frontend-notices.txt
```

The Rust crates statically linked into the host DLL (the input engine `msime-engine` with its dependencies, and the microphone and resampling crates `cpal` and `rubato` among the others), the MCP server and the settings binary, and the npm packages bundled into the settings frontend, are not in any dependency prefix. `platforms/linux/collect-notices.py` collects them from the resolved graphs; run it on Windows so Cargo resolves the Windows graph, after `Build-Client.ps1` has installed `node_modules`, and pass both outputs as supplemental notices. `.github/workflows/release-windows.yml` does exactly this:

```powershell
python -X utf8 platforms\linux\collect-notices.py cargo C:\release\rust-crates-NOTICES.txt msime-host-api msime-engine msime-mcp-server msime-desktop:tauri/custom-protocol
python -X utf8 platforms\linux\collect-notices.py npm C:\release\frontend-npm-NOTICES.txt apps\desktop
```

The on-device speech runtime that `Build-Client.ps1` stages beside the Server (`sherpa-onnx-c-api.dll`, Apache-2.0; `onnxruntime.dll` and `onnxruntime_providers_shared.dll`, MIT) is pinned by `resources/voice-runtime.lock.json`, and its upstream archive carries no license files. `Collect-Notices.ps1` therefore always adds the committed texts: `shared/voice/third_party/sherpa-onnx/LICENSE` under a header naming the locked sherpa-onnx version, and the ONNX Runtime license and third-party notices pinned in `platforms/linux/data/licenses/` (the Windows DLLs report the same ONNX Runtime release). `installer/Prepare-PackageFiles.ps1` refuses to package the runtime with a notice file that does not name both sherpa-onnx and ONNX Runtime, so a notice collection older than the runtime has to be regenerated.

The repository notices are read from where the data and code they cover are committed: `resources/licenses/msime-engine-dictionary-NOTICE.md` for the dictionary data and `resources/licenses/Zinnia-LICENSE.txt` for the recognizer the host library ports from zinnia (the copies the Linux and macOS packages ship as well), `resources/licenses/Administrative-divisions-of-China-WTFPL.txt` for the place names `@` mode offers, `resources/licenses/libhangul-hanja-BSD-3-Clause.txt` for the Korean Hanja table compiled into the host library, `resources/licenses/kfcd-chaizi-CC-BY-3.0.txt` for the component reverse lookup table of 拆字反查 (C mode) compiled into the host library, adapted from kfcd/chaizi (CC BY 3.0, whose attribution and list of changes travel with it), `resources/licenses/rime-wanxiang-CC-BY-4.0.txt` for the group codes and code points of the symbol mode (S mode) table compiled into the host library, from wanxiang_symbols.yaml of amzxyz/rime-wanxiang v18.0.16 @ 7ab73ee0c7f80190004233e70f954833df64c80e (CC BY 4.0, whose attribution, licence address and list of changes travel with it; the Chinese group names and their order are this project's own), `resources/licenses/Unicode-License-V3.txt` for the Unihan readings, ranks and traditional variants in that table, `resources/licenses/rime-cantonese-CC-BY-4.0.txt` and `resources/licenses/libchewing-data-LGPL-2.1.txt` for the data of the host library's Cantonese and Zhuyin schemes, which comes from rime-cantonese and libchewing-data (the notices travel with every engine build; a package that carries `msime-cantonese.db` or `msime-zhuyin.db` in `server_exe/language-dictionaries` also ships the licence text beside it, which `Prepare-PackageFiles.ps1` refuses to leave out), `resources/licenses/rime-stroke-LGPL-3.0.txt` for the stroke orders of the host library's Stroke scheme, which come from rime-stroke and whose main table carries the CNS11643 attribution (the notice travels with every engine build, like the two above), `resources/licenses/vi-MIT.txt` for the vi crate behind the host library's Vietnamese scheme, `resources/licenses/ewts-MIT.txt` for the ewts crate behind the host library's Tibetan scheme, `resources/helpcodes/ENGINE-NOTICE.md` and `resources/helpcodes/NOTICE.md` for the helpcode tables, `platforms/windows/third_party/miniaudio/LICENSE` for the Server's capture and cue sound library, `platforms/windows/settings/assets/feedback/NOTICE.md` for the GitHub, Telegram and QQ icons the settings window draws beside the feedback channels on its about page, the OpenCC license compiled into the host library, and `plugins/script/LICENSE` and `plugins/phrase_table/LICENSE` for the official plugin packs `Prepare-PackageFiles.ps1` stages into `server_exe/plugin-packs` (the uuid script plugin and the latex-symbols phrase table: this project's own work, MIT rather than GPL-3.0, each pack also carrying the text as `LICENSE.txt`). The installer carries neither the handwriting model nor the settled-rerank model: the settings app downloads them on demand, and the handwriting model's LGPL-2.1 licence (`HandwritingModel-LICENSE.txt`) is pinned beside the model in `resources/handwriting-model.lock.json`, so it is downloaded and installed together with the model rather than collected here. zinnia's licence stays in the collection, because the recognizer ported from it is compiled into the host library whether or not a model is present. `-Edition` (default `full`) names the edition whose installer the notices go into and must have a Windows section in `shared/contracts/editions.json`; `release-windows.yml` passes each matrix edition. Each dependency prefix must provide at least one nonempty `share/<package>/copyright`; all such files are collected in sorted order with their SHA-256 and relative provenance. Supplemental files also carry hashes. Absolute local paths are not included. All inputs are read before an existing generated bundle is replaced, so missing inputs preserve prior output.

This is a collection tool, not a completeness or redistribution approval check. It does not infer which ports/crates/npm packages were linked, fetch licenses, collect nested third-party archive licenses automatically, or grant permissions missing from upstream. The helpcode notices explicitly record unresolved redistribution permissions, and their original text is retained. Supply and review the nested archive, Rust/frontend, model and distribution-specific material; retain the separate bundled Japanese model notice and application LICENSE. Missing records must not be papered over with a claim that the whole bundle has one license. Generated output is a release artifact, not a source-tree edit.

Win7 的组合表情使用 HarfBuzz Core 静态排版；来源和版本由 `compat/vcpkg.json` 与 `settings/win7/vcpkg.json` 的基线固定。构建只启用核心字体整形，不引入 FreeType、ICU 或平台字体后端。`Collect-Notices.ps1` 必须收集对应依赖前缀的 `share/harfbuzz/copyright`，许可证随完整安装包分发。
