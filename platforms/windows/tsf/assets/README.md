# TSF icon provenance

Apart from the exceptions below, these ICO files are from `windows/image` in MSIME-Windows, remote default branch `develop`, fixed commit `04a8df56f86312474a069f4335a1b58da7afaa9e`.

They are the original assets referenced by that version's TSF resource script, not generated replacements. They retain the upstream repository's GPL-3.0 license; see the repository LICENSE. No neighboring working-tree files were copied. The DLL embeds the main, Chinese/English/Japanese/Korean/Caps Lock and per-scheme light/dark, character-width and punctuation mode icons through `IME/MetasequoiaIME.rc`.

`kr-light.ico` and `kr-dark.ico`, the Korean mode icons, are the first exception: upstream has no Korean mode, so they were drawn for this repository and carry its license. Each is the syllable 한 built from straight strokes and one ring on a 64-unit grid with 4-unit strokes, rasterized without any font at the same ten sizes as the Japanese icon (16 to 48 in steps of 4, and 64), black for light themes and white for dark ones, stored as 32-bit BMP entries like the files above.

The scheme icons `shuangpin`, `wubi`, `cantonese`, `zhuyin`, `vietnamese`, `tibetan` and `stroke` (each `-light.ico` and `-dark.ico`) are also drawn for this repository and carry its license. They show 双, 五, 粤, 注, 越, 藏 and 笔, one character filling the tile like the macOS input-mode icons. `platforms/windows/scripts/render_tsf_mode_icons.swift` generates all fourteen files from the outlines of Source Han Sans SC Regular 2.005 (SIL Open Font License 1.1, from `09_SourceHanSansSC.zip` of the adobe-fonts/source-han-sans `2.005R` release; the script checks the OTF's SHA-256), scaled by each glyph's ink box as `platforms/macos/scripts/render_menu_icon.swift` does, at the same ten sizes as the Korean icons and with an AND mask like the upstream files. They do not use PingFang SC like the macOS menu icons: that font is licensed to Apple systems only, so images of its glyphs cannot ship in the Windows installer. Rerun the script on macOS with the font file after changing a character or the weight; its output is byte-for-byte reproducible.
