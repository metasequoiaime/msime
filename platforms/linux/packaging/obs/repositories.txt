# OBS 上要构建的发行版，一行一个 OBS 发行版列表（/distributions）里的 reponame。publish.sh 运行时按名字查出它对应的 OBS 项目、仓库和架构写进项目配置，OBS 改了底层路径也不用改这里；列表里查不到的名字打印出来跳过。
# 名字后面可以跟两种可选的列，顺序不限。不含 = 的那一列是逗号分隔的 PROJECT/REPOSITORY，替换发行版列表给的那条路径；形如 rebuild=MODE 的一列写成 OBS 仓库的 rebuild 属性（MODE 取 transitive、direct 或 local，不写就是 OBS 默认的 transitive，依赖包更新时重建），其他属性名或取值 publish.sh 报错退出。替换路径的例子：Ubuntu 的 universe 只有发行时的包，Ubuntu 24.04 要的 cargo-1.91、rustc-1.91 在 universe 的更新（universe-update）里；更新过的 universe 开发包又要求 main 的更新（update）里同版本的运行库。OBS 不会顺着这两个更新仓库的路径把 universe 与基础源带进来（libfcitx5core-dev 只在 universe 里），所以四条按先更新、后发行时的顺序全部列出。

# Arch 与 Omarchy：OBS 的发行版列表里 Arch:Extra 与 Arch:Community 同名为 Arch，按名字只会取到后一个（Community 已并入 Extra，不再更新），所以显式指定 Arch:Extra；它的路径里带着 Arch:Core。构建用 msime-bin 的 PKGBUILD 重新打包发布的 .rpm。rebuild=local 让它只在提交新版本时构建：msime-bin 的内容就是发布的 .rpm，依赖包更新后重建出的包没有实际变化，但版本仍是 VERSION-1（pkgrel 固定为 1），每次 makepkg 写进的构建时间又让文件内容变了，压缩后的大小也会跟着变，于是同一个文件名在镜像上先后有两份不同的包，镜像或本地缓存还是旧的那份时，pacman 按新数据库记录的大小下载会报 Maximum file size exceeded（#10515）。
