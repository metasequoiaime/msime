# windows-server-smoke passes. Five things stood between it and a run, each
# measured rather than guessed, in the order they were removed:
#   - the Wine prefix was created at image build time without a display, which
#     leaves WIC unregistered, so every Direct2D factory failed;
#   - Wine reports windows created on a PER_MONITOR_AWARE_V2 thread as v1, so
#     the window-level DPI assertion is accepted at v1 only when ntdll exports
#     wine_get_version, and still requires v2 on Windows;
#   - DirectComposition is a stub, so DeviceResources falls back to a layered
#     window, which is what the Windows source uses for these surfaces;
#   - first_candidate_point measured rows against the window's width and sent a
#     card coordinate as a client one, so its clicks landed outside the row;
#   - WM_LBUTTONUP released capture before reading the press, and ReleaseCapture
#     delivers WM_CAPTURECHANGED, which is the path that clears it;
#   - EnsureFactories treated WIC as mandatory, so a surface drawing only text
#     could not draw at all on a thread without COM initialised.
#
# The last two are product defects, not environment limits.
