# Agent Note: 门禁临时文件失败时立即停止并限定清理范围

Status: implemented

## Problem

接入模型性能优化时系统盘耗尽，`verify-local.sh` 的 `mktemp` 失败却继续运行；`collected` 为空时，退出清理里的 `"$collected".*` 变成 `.*`，删除当前 worktree 的 `.git` 等隐藏普通文件。最初失败日志保留；工作树改动已从本任务副本恢复，不涉及其他会话数据。

## Decision

先初始化空路径与退出清理，再申请临时文件；任一次申请失败立即非零退出，让已成功创建的文件仍由清理负责。收集器非空时才展开它自己的后缀，其他临时路径各自检查非空。继续用原有单个退出 trap 持有构建锁与契约检查目录，不引入另一套生命周期。

## Existing decisions

已检索 `mktemp`、临时文件失败与清理；现有 Windows 门禁可移植性和 Linux Cargo 缓存笔记分别管理测试入口与构建缓存，没有持有本项失败处理，没有完全吸收或需废弃的笔记。

## Alternatives considered

- 全局 `set -e`：能使部分命令失败提前退出，但会改变整份门禁收集失败并统一报告的约定，明确检查两处申请即可。
- 只检查收集器非空：避免误删，但仍会在没有有效日志路径时运行后续阶段，必须同时在申请失败时停止。

## Verification

合成临时沙箱抽取真实启动与清理代码，注入第一或第二次 `mktemp` 失败：退出非零，不运行后续检查，不删除 `.git`、`.gitignore` 与普通哨兵，成功申请的文件已清理。成功时清理收集器后缀但保留无关文件；显式空收集器也不能展开工作区隐藏文件。旧版四项中三项真实失败，新版四项全通过；独立只读审查无阻断或重要问题。脚本稳定后的完整 quick 退出 0，包含自动发现并运行这四项回归；完整范围与环境恢复见[本次模型接入记录](../testing/2026-10-17-runtime-terminal-prefix-view.md)。

## Consequences

只修复这两处申请与对应退出清理，不把其它临时文件分配和目录创建宣称为全面审计。测试中的失败注入仅在合成沙箱执行，原始项目目录不承受故障清理。
