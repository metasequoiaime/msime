# Agent Note: 在用户真机上自动打字前隔离学习、同步与外发

Status: implemented

## Problem

2026-10-29 在用户自己的 Pixel 3 XL 上跑九键测速：脚本用 monkey 逐键输入整句，按空格上屏首选。当时「记忆新词」、云同步（登录的是用户本人的账号）和「用水杉账号翻译候选」都开着。约一千次上屏被学进了用户的词库，其中四到六成是错的首选，学到的整句作为用户的词随云同步上了云端；打字时高亮的候选也被发去服务端翻译。0.6.0 的 Android 界面没有清除学习记录的入口，云端唯一的删除入口会连设置、常用语一起删，事后无法只清掉测试留下的数据。仓库里没有任何地方提醒，在用户真机上自动打字之前要先隔离这些开关。

## Decision

把隔离写成真机测试的流程规则，放在 `.agents/skills/launch-platform-host/SKILL.md` 的「在别人的真机上自动打字」一节（#10244）：打字之前关掉记忆新词、云同步和用水杉账号翻译候选，记录原值，用 `trap … EXIT INT TERM` 在结束或中断时按原值恢复并冷启动复核；先停设备端的输入注入再动设置；记录写明持有者；云同步先关后开，遇到合并对话框交给用户；云候选、AI 候选、AI 辅助翻译、第三方候选翻译和 WebDAV 词库同步一并记录、关闭、恢复；能用测试账号就用测试账号；不往用户数据里写东西，也不自己删用户的词。同一节附三端的位置与偏好键表。

AI 辅助翻译各端的开关不同，规则按代码写明：桌面与 HarmonyOS 走 host-api 的 `selected_translation_services`（`crates/host-api/src/ffi/providers.rs`），看 `translation_ai`、不看 `ai_assistant.enabled`；Android（`CandidateTranslationPolicy.route`）与 iOS（`TranslationProviderPreference`）在没选别的翻译服务时按 `ai_assistant.enabled` 走 AI 翻译、不看 `translation_ai`。隔离时两项都关。

## Alternatives considered

- **只在测量脚本里做隔离，不写进技能**：最强的理由是脚本本身就是执行者，写在脚本里就一定会执行。没有采用：下一次可能是另一个会话、另一套脚本、另一个平台，规则只在一套脚本里就等于没有；技能是每次真机测试都会读的地方，脚本只是它的一种实现。
- **只要求用测试账号或专用设备**：最强的理由是彻底，用户数据根本不在场。没有采用为唯一要求：真机延迟和输入法行为常常只能在用户手头那台设备上复现，借用时仍需要隔离；所以写成「能用测试账号就用」，同时给出借用用户设备时必须做的隔离步骤。
- **测完再清理用户数据**：最强的理由是不用改测试流程。没有采用：清理入口不一定存在（0.6.0 就没有），清理往往连用户自己的真实数据一起删，而且学到的内容已经随云同步传到了其他设备。

## Consequences

- **收益**：真机自动打字不再把测试文本写进用户的词库和云端，也不把测试内容发到翻译服务；隔离被中断时有恢复路径。
- **代价**：每次真机测试前后多出几分钟的开关操作（Pixel 3 XL 上记录并关闭约 5 分钟，恢复约 3 分钟）；测量时的配置和用户日常配置不完全一样，报告里需要说明。
- **没有解决的**：2026-10-29 已经学进用户手机和云端的测试数据还在，要等 Android 加上清除学习记录的入口后再清理。
