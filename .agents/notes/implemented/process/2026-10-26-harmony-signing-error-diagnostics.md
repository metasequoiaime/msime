# Agent Note: 鸿蒙发布签名错误保留脱敏诊断

Status: implemented

## Problem

`platforms/harmony/sign-release.py` 调用 `hap-sign-tool.jar` 或应用市场打包工具失败时，只报告 Java 的退出码，丢弃了标准错误输出。签名工作流因此只能显示“执行失败（退出码 1）”，无法区分 HAP 格式、证书参数和工具链问题。2026-10-25 的 HarmonyOS 0.2.1 发布任务就因此只能确认失败发生在签名阶段，无法从日志判断具体原因。

## Decision

`run` 在子进程失败时把标准输出和标准错误作为诊断附在 `ValueError` 后面。错误文本先移除签名密码环境变量的值，再移除命令参数的原文；日志保留工具返回的其他诊断，但不暴露密码、路径参数或测试命令里的合成秘密。两个输出流都为空时继续只报告退出码。

签名、验签和市场打包调用传入中文阶段名，避免多个 Java 调用在日志里都只显示 `java`。签名块丢失的根因与回归证据见[签名前压缩](2026-10-26-harmony-compress-before-signing.md)。

## Alternatives considered

- **继续只报告退出码**：改动最小，也不会有任何日志泄露风险；但发布失败无法定位，维护者只能盲目修改并重跑完整的 HarmonyOS 构建，因此不采用。
- **在工作流 shell 中额外打印完整 Java 命令**：最容易临时排查；签名密码作为命令参数传给工具，完整命令会把凭据写入 CI 日志，因此不采用。
- **原样转发标准错误**：能保留最多的工具信息；工具可能回显命令参数，且测试已证明子进程可以把敏感参数写到 stderr，因此不采用。

## Consequences

签名失败的 CI 日志现在能直接显示鸿蒙工具的非敏感错误，减少一次完整构建的排查成本。命令参数本身会从诊断中删除，某些包含路径或参数值的上下文会变少；需要时仍可通过工具固定的错误文本和退出码判断失败类别。现有签名验证逻辑、输出文件和成功路径不变。

验证包括 `python3 -m py_compile platforms/harmony/sign-release.py`、14 项 `scripts/test-harmony-release-signing.py` 和 `git diff --check`；另用合成子进程确认普通诊断会保留、合成秘密不会出现在异常文本中。完整 HarmonyOS 构建留给 CI，开发机磁盘空间不足以安全启动全量构建。
