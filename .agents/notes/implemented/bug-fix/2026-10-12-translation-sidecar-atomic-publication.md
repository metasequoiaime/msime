# Agent Note: 翻译词条副本完整写入后发布

Status: implemented

## Problem

`crates/engine/src/host/options.rs` 在会话建立时把用户或资源里的翻译词条复制到词库目录。旧写法先截断目标文件，再写入并同步。另一输入进程可能同时打开这个副本，因此会读到空文件或半写入内容；中途失败还会破坏旧副本。

## Decision

目标路径保持普通文件和单链接校验。新内容写进目标目录中的独立临时文件，同步后再替换目标。已打开旧文件的读者继续读完整旧内容，新读者读完整新内容。临时文件由 `tempfile` 管理，正常失败时自动清理。

## Alternatives considered

- 原地写入并加进程间锁：能保持现有 inode，但每个读取方也必须遵守同一把锁，跨引擎和宿主改动大，且崩溃时仍可能留下半文件。
- 沿用原地写入：实现最简单，但不能保证并发读者获得完整内容。

## Verification

- 回归测试先观察到旧句柄读出新内容而失败，修改后通过。macOS 引擎全量测试 1828 通过、13 忽略；格式检查和 `msime-engine` clippy 通过。
- Android 专用模拟器上翻译副本相关的 7 个可运行测试通过。硬链接用例的夹具无法在 Android SELinux 下创建，按仓库设备测试规则跳过。设备全量引擎测试另有 1803 通过、13 忽略，3 个依赖仓库路径下辅助码表的测试因测试二进制未带这些文件而失败。
- `pnpm run verify-notes` 通过。原开发基线上的 `scripts/verify-local.sh --quick` 报告 `quick check passed`；更新至后续 `develop` 后，门禁因新合入的 `pack-tool` 和 `host-api` 独立编译缺口失败，翻译副本相关 8 个测试在更新后的基线上仍通过。

## Consequences

并发读者不再读取到写入中的目标 inode；成功发布前旧副本保持完整。磁盘上会短暂存在一个隐藏的同目录临时文件；进程被强制终止时该文件可能残留。目标路径的链接校验仍在发布前执行；并发替换目标目录项的安全边界与原实现相同。
