# Agent Note: 全拼辅助码保留原首选顺序

Status: implemented

## Problem

#11414 为双拼辅助码加入原首选退避时复用了共享的候选重排函数。全拼也调用这一路径，所以全拼输入辅助码后，如果原首选和另一个候选都命中同一码，原首选会被移到命中组末尾。自然码表同时包含简繁字形时，用户可能因此看到繁体候选被顶到第一位，触发 #11575 的 macOS 报告。

## Decision

双拼继续使用[辅助码命中时原首选退避](../feature/2026-11-13-shuangpin-helpcode-first-candidate-demotion.md)规则。全拼使用独立的稳定路径：一码辅助码按首码、末码优先级重排但保留原首选在同组中的位置；两码辅助码只筛选完整命中项，保持基础词库顺序。这样全拼辅助码仍能缩小和重排候选，已有的简繁输出偏好也继续只决定宿主显示转换，不被辅助码路径间接改变。

## Alternatives considered

- **让全拼也沿用双拼的首选退避**：改动最少，但全拼的一码辅助码通常是直接选字提示，跨入双拼专门约定的“辅助码表示排除首选”语义会改变现有全拼候选顺序，因此不采用。
- **在 macOS 候选窗里把繁体字再换回简体**：可以遮住首选顺序回归，但会让宿主显示与 Engine 候选身份、上屏文本不一致，也会误伤用户明确选择的繁体字形，因此不采用。
- **删除自然码表中的繁体字条目**：能避免这类首选变化，但会破坏辅助码表对繁体字的可达性，且影响所有平台，因此不采用。

## Consequences

全拼辅助码恢复到 #11414 之前的相对顺序，双拼的用户要求保持不变。共享层增加两个明确表达“保留原顺序”的入口，调用方按方案选择规则；代价是候选辅助码的排序策略不再由一个函数覆盖两种方案，需要通过方案级回归测试守住边界。

## Verification

新增全拼一码、两码在多候选命中时的顺序回归；保留既有双拼退避测试。将在远端运行 `cargo fmt --all -- --check`、`cargo test --locked -p msime-engine`、`cargo clippy --locked -p msime-engine --all-targets -- -D warnings` 及仓库 quick 门禁。没有 macOS 真机或报告者编辑器环境时，PR 验证段记录该缺口，不把它当作代码推进前置条件。
