# Agent Note: 鸿蒙键盘显示期间同步设置偏好

Status: implemented

## Problem

鸿蒙设置应用和键盘扩展通过共享沙箱清单交换偏好。键盘原先只在获得焦点时导入设置端清单并比较修订号；键盘已经显示时，设置页保存的布局、方案或外观只能等下一次聚焦才进入键盘。组字期间还必须避免重建会话打断输入，现有的共享镜像顺序契约见[鸿蒙键盘先导入设置偏好再发布快照](./2026-11-02-harmony-preferences-mirror-order.md)。

## Decision

键盘显示期间启动轻量偏好轮询器，每 500 毫秒只读取设置端的 `manifest.json` 并比较偏好内容指纹。指纹变化后复用现有 `SharedStateSync.keyboardSync` 导入，不复制新的状态通道。轮询发现组字或本地模式正在进行时保留待处理指纹，等空闲后再导入并调用已有的 `reloadChangedPreferences` 重建会话。轮询在键盘隐藏、会话停止或没有共享目录时停止。

导入失败时不推进轮询状态，下一轮继续重试。设置端只改变修订号而没有改变偏好内容时，指纹保持不变，不重建会话。冲突仍由 `SharedStateMirrorPolicy.pending` 的双方清单和 `changedMs` 规则决定。

## Alternatives considered

- **继续只在下次获得焦点时导入**：实现零改动，但报告的设置延迟仍然存在，用户无法在键盘保持显示时看到布局和外观更新。
- **设置应用通过额外进程通信主动通知键盘**：通知可以更快，但基础访问模式的输入法扩展不适合依赖新的 IPC 通道，也会引入一套与共享清单并行的生命周期和失败重试规则。
- **轮询完整偏好文件或每次都重建会话**：能够发现变化，但会把跨进程文件读取和重建成本放到每个轮询周期；这里只读很小的清单，且仅在指纹变化后复用已有导入和重建路径。

## Consequences

- 设置页保存后，键盘在显示且空闲时最多约 500 毫秒开始应用新偏好，不需要重新聚焦输入框。
- 组字和本地模式期间不会重建会话，完成后由下一轮轮询继续处理。
- 键盘显示期间增加一次小清单读取周期；隐藏键盘和无共享沙箱时不保留计时器。
- 未改变签名、镜像目录格式、偏好内容格式或现有冲突裁决规则。

## Verification

- `preference-sync-poller.test.ts` 覆盖清单指纹、500 毫秒调度、不可轮询时不执行读取以及停止后的生命周期。
- `SharedStateMirrorPolicy.pending` 继续负责导入失败保留待处理状态；ArkTS 测试和 HAP 构建仍需在 PR 门禁及签名 HarmonyOS 真机上完成。
