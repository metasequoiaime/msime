# Agent Note: Android 访客剪贴板补读状态隔离

Status: implemented

## Problem

访客模式和主模式已经使用不同的历史目录，但剪贴板补读去重只在输入法进程的共享偏好里保存一个全局身份。用户在主模式复制或补读一条内容后切换访客模式，打开访客剪贴板时会把相同的系统剪贴板身份误判成“已经处理过”，因此访客历史为空；切回主模式又共享同一个去重状态。报告者在 Android 11、0.7.4 复现了“需要再次复制文本才能出现”。

## Decision

新增 `ClipboardCaptureState`，按 `ClipboardModePolicy.Mode.MAIN` 和 `VISITOR` 使用两个固定的 SharedPreferences 键保存最近补读身份。主模式首次读取时兼容旧版的 `handled_clip` 键，避免升级后把已清理的系统剪贴板重新补读。`MSIMEInputService` 的剪贴板补读在判断和写回身份时都带当前模式；复制监听仍照旧每次记录，历史目录、容量、隐私和敏感剪贴板规则不变。这样同一系统剪贴板身份可以分别首次进入主模式和访客模式，但同一模式内清空或删除后仍不会在打开面板时被补读回来。

## Alternatives considered

- **切换模式时清空全局身份**：能让访客第一次补读成功，但回到主模式后同一身份又会被重复补读，破坏主模式的清空和删除语义。
- **切换模式时立刻把当前剪贴板写入新目录**：会在用户尚未打开面板时产生历史，也绕过现有隐私、敏感内容和补读触发规则，因此不采用。
- **把身份写进两份历史文件**：会把去重元数据混入用户可备份的历史格式，增加迁移和兼容负担；两个固定偏好键足以表达两个模式的状态。

## Consequences

- 主模式和访客模式各自记住最近补读身份；切换后打开剪贴板能看到当前系统剪贴板，而不需要再次复制。
- 同一模式内的补读去重行为保持不变，主模式删除或清空不会被访客模式的状态干扰。
- 新增的 JVM 冒烟只使用合成身份和内存 SharedPreferences 替身；尚未在报告者 Android 11 真机或模拟器中验收切换、打开面板及两种统计数字。

- `platforms/android/check-host.sh`、完整 quick 和 API 30 真机验收待运行；本次改动涉及 Android 剪贴板持久状态，合并前必须完成 Android 设备验证。
