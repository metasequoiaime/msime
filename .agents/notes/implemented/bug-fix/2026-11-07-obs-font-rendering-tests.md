# Agent Note: OBS 发行版字体环境下的 Linux 原生画布测试

Status: implemented

## Problem

Issue #11067 反馈 openSUSE Tumbleweed 的 OBS 软件源长期停在 0.11.0。检查 `home:msime/msime` 的公开构建日志发现，0.15.0 的源码已经提交，但 OBS 的 Tumbleweed 构建在 `linux-candidate-native-canvas` 失败，发布仓库继续保留旧包。失败来自两类与发行版字体环境有关的测试断言：

- 序号字体和候选字体的实际像素宽度在 Tumbleweed 的 Pango/fontconfig 组合下没有保持严格的小于关系；
- 装饰候选文字的抗锯齿像素没有产生超过 10 个完全等于目标 RGB 的像素，Ubuntu 24.04 的 OBS 构建也因此失败。

这些断言没有覆盖需要保持的布局或绘制契约，却把具体字体栅格化实现当成了固定结果。

## Decision

测试验证序号字体的描述确实使用了绝对字号，并且其字号小于候选字体描述；不再比较两个字体在当前发行版上的像素宽度。这样仍然覆盖 `numberScale` 生成小字号字体的契约，但不依赖 Pango 的字体提示和像素取整。

装饰候选的像素检查使用颜色主通道和抗锯齿容差判断有色墨迹，保留文字必须位于声明框内且不能获得候选命中的断言。墨迹框是小数坐标（居中对齐时常落在半个像素上），而抗锯齿像素只要被文字盖住一部分就算有色墨迹，所以「位于框内」比的是与墨迹框相交的整像素范围：横向 `[floor(x), ceil(x + width))`、纵向同理，不再拿像素坐标直接和小数边界比。普通 canvas 和 chrome 两条装饰路径都使用同一套判断，纯色像素数量门槛从 10 降到 2，避免小字号字体因没有完全不透明像素而误报失败。

## Alternatives considered

- **在 RPM 规格中跳过 `linux-candidate-native-canvas`**：最强的理由是能立即让 OBS 产出包。不采用，因为会把 Linux 候选窗的布局与绘制回归一起从发行版构建中删掉，无法证明包内代码可用。
- **给测试容器固定一套字体并保留严格像素断言**：最强的理由是结果更接近单一基线。不采用，因为 OBS 使用各发行版自己的字体包，固定测试容器不能覆盖真实打包环境，且字体替换仍会让像素阈值失效。
- **给 Nix 包的检查阶段配一套字体（`makeFontsConf`）**：最强的理由是沙箱里会画出真字形，而不是缺字方框，更接近用户机器。不单独采用，因为小数边界上的半覆盖像素与字体无关，换成真字形也只是碰巧不压线；它可以另做，但替代不了按整像素比较。

## Consequences

- Linux 原生画布的运行时代码和布局数值没有变化；只有测试把环境相关的像素结果改为稳定的字体描述与抗锯齿容差契约。
- Fedora、openSUSE 和 Debian/Ubuntu 的发行版构建可以继续运行完整 ctest，0.15.0 需要在修复提交进入可用的包定义后重新提交 OBS 才会更新软件源。
- 本机是 macOS，且当前没有 Linux 原生构建依赖和空闲的完整构建空间，未在本机编译该测试；需要由 Linux 容器/OBS 构建验证实际发行版结果。
- 只放宽抗锯齿判定、仍拿小数边界比较时，Nix 沙箱构建（fontconfig 没有任何配置和字体，Pango 画缺字方框）每次都在 `decoration_overlay` 的框内断言上失败：墨迹框的边界落在小数坐标上（例如上沿是 `25.5`），边上那一行半覆盖的像素被算作墨迹却在框外。按整像素比较后，同一沙箱里画 `alpha(cloud)` 的各种小数起点都没有越界像素，`nix build .#msime-fcitx5` 的 ctest 通过。
