# Agent Note: iOS 候选文字宽度与横向栈隔离

Status: implemented

## Problem

#10883 中干净 develop 的长组字用例停在候选更新后的 `layoutIfNeeded()`，首次进程外采样显示 `UIButton.updateConstraints` 与 `NSISEngine` 求解持续占用主线程，进程 footprint 约 2.3 GiB。现场候选宽度已有内容计算约束，横向栈仍为多行文字按钮生成带 1/9 系数的宽度消歧约束。外置诊断仅停用这组自动约束后，保留原输入、释义、学习和断言的五类延迟用例各运行五次，25 次全部通过。此对照定位到候选宽度求解，不证明所有历史布局异常同源。

## Decision

用普通 `UIView` 包住候选按钮，横向栈排列容器，按钮继续沿用原有固有宽度、释义测量、最小触控尺寸和混合滑行上限。隐藏时断开按钮与容器的右边界，再同时隐藏两者，让栈可以将容器设为零宽而不压缩按钮自己的内容约束。显示时恢复边界；按钮、动作、候选身份和配置继续复用。间距从横向栈显式传给半行宽度计算，避免增加包装层后读不到皮肤间距。

生产代码只用公开 UIKit API，不提交诊断探针，不匹配或停用系统私有约束。不改变引擎、默认值或原测试前置。以原长组字失败作为红灯证据，随后重放相关候选回归及完整套件。

## Alternatives considered

- 直接停用系统宽度消歧约束：对照实验效果明确、改动少，但需要匹配私有标识并在系统每次更新后干预，只用于诊断，不作产品实现。
- 将可见候选固定宽度改成 required：可以压过系统软约束，但会改变无释义候选和混合滑行上限的优先级关系；隐藏前后还需翻转优先级，不采用。
- 手工排列整个候选条：已有九键拼音侧栏先例，可完全去掉横向栈；但要另行维护滚动内容宽度、文字固有尺寸和上限规则。先采用保留现有宽度规则的包装边界，实际行为回归失败时再重审。

## Verification

- 第一轮七项宽度、符号、英文上限及皮肤间距回归通过；新增压力测试使用实际 UIKit 控件反复更新宽度、显隐和内容尺寸。补充全部隐藏后恢复与触摸命中后在完整套件已执行部分通过；恢复全部产品实现并撤回临时取证后，最终定向 12 项、0 失败，32.4 秒完成。
- `bash scripts/verify-local.sh --quick`、`pnpm run verify-notes` 与 `git diff --check` 通过；不相关平台按 quick 范围跳过。实际候选画面保留改前改后原图；同一合成输入两图逐字节相同，图床直链均下载回本机逐字节校验。最终 quick 再次完整通过。

完整套件暴露 `CandidateCanvasTests/testRealControllerStripKeepsCandidatesInsideThePanelAtTheDefaultSize`：内容 guide 高 34pt，候选及外层内容行高 35.67pt，首选下沿 39.67pt 超过允许的 38.5pt。还原基线控制器与宽度规则、保留同环境及原断言后，独立运行得到相同尺寸和失败；额外一次根布局或挂到窗口也未消除。原候选「你」可见，不是命中隐藏项。诊断只用公开 API，已撤回临时输出，不以放宽断言、改变默认值或猜测修复消除该红灯。草稿 PR 在此项定位和最终完整检查完成前不合并。

## Consequences

包装层阻断横向栈对多行文字按钮生成宽度消歧约束，同时保留现有内容测量和动作复用；代价是每个候选多一个轻量容器及一条显隐边界约束。包装层改变视图父级；测试和半行宽度规则需要按能力查找滚动视口，不能再把固定父级层数当契约。此处不消除其他键盘控件的布局或生命周期风险。
