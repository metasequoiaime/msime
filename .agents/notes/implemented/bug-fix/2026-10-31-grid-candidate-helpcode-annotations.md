# Agent Note: 补齐 grid 候选辅助码注释

Status: implemented

## Problem

开启候选辅助码显示后，9／14／18 键中的部分词组仍没有辅码标注。例如码表包含“仓”和“颉”时，词典直接提供的“仓颉”不显示辅助码，由两个单字生成的同词候选却能显示。

原因是 grid 快照只复制纠错注释，绕过普通拼音的辅助码注释计算；host 假定词典候选已经附带注释，只为 `Generated` 来源补码。注释在到达 UI 前已经缺失，候选本身和码表没有丢失。

## Decision

将普通拼音的辅助码注释计算提取为 `InputSession::candidate_helpcode_annotations`，由普通拼音和 grid 快照共用。grid 按当前码表和快照方案生成注释，直接读取核心快照的调用方也能获得结果。

沿用既有辅助码开关、显示开关和大小写格式；英文词典、日文混输及多语言来源继续排除，隐藏辅助码或缺少字码时回退到纠错注释。本地模式注释和韩语训音保留原分支，不参与这段共用计算。

## Alternatives considered

- 在 host 为所有空注释补码：改动较少，但会扩大现有来源范围，也无法覆盖直接读取核心快照的调用方，因此在核心快照组装时补齐。
- 在 UI 侧取码：可以局部补上显示，但会重复码表选择、格式及来源判断，各宿主容易产生差异，因此继续由引擎提供注释。

## Verification

合成词库回归覆盖全拼／双拼的 26／9／14／18 键、词典与生成候选、辅助码及显示开关、缺末字码，并同时核对核心快照和 host 输出。显示开关不改变候选顺序；相关注释与辅助码回归通过，不将其等同于各平台编辑器验收。

## Consequences

词典候选与生成候选按同一规则显示辅助码；缺码时仍允许没有辅码注释。grid 快照增加逐候选取码计算，不增加 SQL 查询，也不改变候选生成、排序或辅助码筛选。只增加内部共用方法，不新增公开接口。
