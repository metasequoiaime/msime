# Agent Note: AI 设置请求绑定外部配置代次

Status: implemented

## Problem

`useAiAssistant` 仅在内部编辑和宿主替换时失效请求。重载、重置和偏好通知直接替换 `ai` 属性后，旧模型列表仍能自动选择首个模型并覆盖新草稿，旧润色结果或错误仍可显示；旧互斥还阻止新配置立即测试。宿主凭据能力变化和实际 AI 凭据保存、清除也没有进入请求归属。

## Decision

现有 `useAsyncGeneration(client)` 继续处理宿主生命周期。配置 effect 用仓库已有 `deepEqual` 比较上一份 AI 配置、宿主凭据能力和 AI 凭据操作代次，只有语义变化才推进请求代次、推进两种操作的独立序号、释放互斥并清除润色反馈。每次实际配置变化都推进代次，因此 A→B→A 不会复活旧操作；普通保存回执返回的同值副本不取消请求，也不清空有效结果。

`useProviderCredentials` 发布独立的 `aiCredentialGeneration` 及同步的 `aiCredentialGenerationRef`，在凭据客户端变更及当前 AI 凭据保存、清除成功时推进，经 `SettingsPage` 传入 AI hook。成功回执同步推进 ref，不等待状态提交；每个 AI 操作捕获开始时的凭据代次，完成、异常和忙碌状态写回都读取当前 ref 校验。数值 state 仍驱动下一轮配置 effect 清理反馈，不能用该 effect 作为旧请求失效的起点：React 批处理提交前，旧请求可能已经返回。密钥轮换可以返回相同的端点和模型元数据，不能靠状态值比较识别；腾讯和语音凭据保存不推进此代次。宿主 `ai_provider_credentials` 仅是能力位，不能替代真实凭据操作代次。

模型列表与状态仅在客户端、端点、服务商、当前来源令牌、宿主凭据能力或 AI 凭据操作代次变化时清除。自动选择模型会替换 `ai`，但不改变模型目录来源，需要保留刚获取的列表和成功反馈。

## Alternatives considered

- **把失效 effect 改成 layout effect**：能缩短 DOM 提交后的窗口，改动很小；但成功回执与旧请求可以在 React 提交前先后完成，layout effect 仍然来不及。同步代次直接守住成功回执边界。

- **只依赖 `ai` 对象身份**：最省代码，也能识别配置切换；但自动保存会返回同值副本，导致正常请求被误取消。
- **完成时只比较捕获的配置值**：只拦截与最终配置不同的结果，改动较少；但 A→B→A 会重新接受旧操作，也无法及时释放忙碌状态。
- **配置变动时一并清除所有模型列表**：状态重置简单；但获取列表后的自动选模也会改变配置，立即抹掉成功结果。
- **只通过内部 `updateAi` 失效**：内部编辑已经有完整守卫；但外部快照直接更新草稿，调用方不能可靠地把每种重载入口转换成内部编辑。

## Verification

CI 运行 `38689785228` 在 3504 项中有 1 项失败：Linux AI 凭据保存成功后，旧模型列表把当前模型覆盖成 `stale-model`。原代码本地全量 3504 项通过，但同一批 React 更新中先完成凭据操作、再返回旧模型列表的两个合成用例稳定失败，证实不能依赖 effect 时序。回归覆盖保存／清除后的模型及润色成功／失败反馈，并以失败的 AI 保存、成功的腾讯凭据操作验证有效 AI 请求继续完成。修复后 Node `24.21.0` 下全量 616 个文件、3514 项测试通过；相关 46 项定向测试、lint、两端设置 shell 类型检查、桌面前端构建、笔记及 diff 检查通过。本地 quick 通过，包含 149 项宿主测试、391 项 x86 源文件语法检查、Windows x64 交叉构建及共享宿主检查；未把这些检查称为原生窗口验收。

最初 8 项隔离回归在旧实现失败，正常自动选模的控制用例通过。复审新增的同值配置副本、真实保存回执及 Linux 凭据保存/清除用例先在不完整实现上失败；补齐后，模型获取、润色、凭据操作和新回归共 24 项通过。测试仅使用合成配置、令牌和文本，不访问真实 AI 服务。

## Consequences

凭据初始读取与成功操作回执的发布顺序由[凭据状态代次](2026-10-15-provider-credential-initial-status.md)单独管理，不使用 AI 请求代次替代。

底层 AI 请求仍会完成，代次仅丢弃失效的 UI 写回。配置按 JSON 结构语义比较，不依赖属性顺序；无关设置保存和同值 AI 回执不受影响。凭据代次仅在本页可见的成功操作和客户端生命周期变化时推进，不表示对外部进程直接修改凭据文件的持续监控。新增的是共享 hook 内部参数，不修改宿主或网络协议。
