# Agent Note: macOS 候选释义等待页的控制器归属

Status: implemented

## Problem

#9397 报告不同 macOS 应用显示的候选释义不同。同一设置下跨应用应保持释义可用，这个诉求合理；公开材料不能确定实际翻译来源，不能把它直接归为词典覆盖或账号服务问题。源码调查发现独立的跨控制器缺陷：输入框各自持有控制器，Swift 后端却共用一个正在发送的请求和一个等待页；旧控制器的迟到取消会无条件删除新控制器已经放入的等待页。

基线 `bcdab74501` 的实际发送、取消方法通过 Foundation 原生夹具运行，合成控制器 A 发送后由 B 接管，A 再取消，断言 B 的等待页仍存在时失败。夹具提取生产方法，只替换输入法外壳和账号后端，不读取用户配置，也不访问账号网络。

系统翻译同样跨控制器共用后端等待页。离线词典的异步完成会重新请求系统翻译；焦点已经交给新输入框、旧输入框尚未收到失焦回调时，旧控制器仍能覆盖新页。基线 `e2dbbd6c24` 的实际 `fetchOnDeviceGlosses:targets:` 在相同交接夹具中失败于“旧词典回调不能替换当前控制器的系统翻译等待页”。当前页的请求去重又会阻止它立即重新提交，因而不能只依赖显示结果的代次检查。

## Decision

宿主在主线程用弱引用记录最近实际提交账号请求的控制器。当前焦点控制器有权取消尚未交接的旧等待页，以保留关闭翻译、切换服务或离开输入框的意图；非焦点控制器仅能取消仍属于自己的等待页。非焦点计时器不能向后端提交请求，避免旧页在交接后重新覆盖当前页。取消前先释放归属，避免同步回调中接管的新请求被旧取消的收尾覆盖。

系统翻译在实际发送入口使用同一个焦点检查，拒绝失焦控制器迟到的词典回调；重新取得焦点后仍能正常提交。系统翻译没有宿主取消共享等待页的接口，因此无需再增加一个所有者引用。检查放在唯一发送入口，所有调用路径都受保护。

正在发送的请求仍按现有后端规则完成并填充缓存；不修改显示视图代次、词典查找、翻译偏好或公开桥接接口。不据此声明已复现报告人的应用与服务组合。方法级回归同时接入通用契约发现和 macOS CI 的原生构建矩阵，避免 Linux 契约作业的环境跳过成为唯一的 CI 结果。

## Alternatives considered

- 只允许最后提交者取消，能以最少状态挡住迟到取消，但当前焦点退出账号翻译时将无法清理旧控制器尚未交接的等待页；该合成原生断言真实失败。采用焦点退出权限与提交者归属并存，并拒绝失焦后的发送。
- 给 Swift 请求和取消接口都增加所有者参数，可以由后端直接验证归属。但当前账号候选入口仅由这个原生控制器调用，扩展桥接契约增加迁移范围；先在现有唯一入口维护弱引用。
- 只在收到系统翻译结果时核对当前页，可以避免显示旧结果，也无需约束请求入口；但后端当前等待页在这之前已经被替换，当前控制器的请求去重不会补回丢失的工作，因此在发送前核对焦点。

## Verification

基线实际方法首先失败于“迟到的旧控制器不能取消新控制器的等待页”。修复后八项原生回归通过：迟到取消、无请求旁观者、当前所有者取消、同控制器换页、取消回调中接管、新所有者取消、当前焦点退出清理旧页、失焦计时器拒绝发送。方法与弱引用声明取自实际控制器源码，使用合成后端与 Foundation，经 Clang 的 `-Wall -Wextra -Werror -UNDEBUG` 编译运行，不复制被测决策逻辑。

系统翻译补充四项实际方法回归：焦点控制器完整提交词页与目标语言、旧控制器不能覆盖当前页、无焦点时不能提交、重新取得焦点后正常提交。修复前实际触发旧页覆盖断言，修复后默认 Python 与系统 `/usr/bin/python3` 均通过全部十二项；后端替身只接收并解析实际 JSON，不重写焦点判断，也不访问系统翻译模型或网络。该脚本沿用已有通用契约与 macOS CI 接线。

系统翻译补充验证的 run `20261024-181854` 完整 quick 退出 0：完整契约、Rust workspace、macOS 全部原生构建目标与共享 Apple 桥接通过，其余平台按实际改动范围跳过。随后实际运行 `shortcut-translations`（5.93 秒）和 `shortcut-vim-mode`（2.47 秒），两项均通过；本次不把初始账号修复的完整 `shortcut` 基线对照记为新树结果。最新笔记校验在本机执行，远端缺少 Node 的跳过不作为通过证据。

macOS CI 新步骤使用系统 `/usr/bin/python3`，该解释器实际运行八项回归通过；新增 workflow 接线通过 `actionlint`。该接线在远端运行开始后补充，本机单独验证，不将旧运行的 workflow 范围跳过写成接线已受检。`MSIME_CHECK_JOBS=2 bash scripts/run-checks.sh` 完整通过，`pnpm run verify-notes` 的树、格式、归档三项校验通过。完整 `InputController.mm` 与既有 `ShortcutTest.mm` 均通过 Clang 的 C++17、ARC、`-Wall -Wextra -Werror` 语法检查。远端 run `20261024-102847` 的完整 quick 退出 0，契约、Rust workspace、全部 macOS 原生目标及共享 Apple 桥接构建通过；非 macOS 阶段按范围跳过，远端缺 Node 的笔记检查在本机执行。

## Consequences

不再由旧输入框取消或替换新输入框的账号等待页，也不由旧词典回调替换系统翻译等待页，同时保留当前焦点退出账号翻译时的清理能力。账号队列使用一个主线程弱引用，系统翻译复用焦点检查；不改变桥接 ABI、正在发送请求的缓存规则或候选视图代次。源码方法提取回归依赖方法声明与结束格式，重构时需同步；它不创建系统输入法客户端。若候选翻译入口新增原生控制器之外的调用方，须重访该归属边界并将所有者传到后端，避免绕过宿主检查。

本机磁盘低于新建构建树的 50 GiB 门槛，完整宿主验证在远端进行。系统翻译补充验证启动前远端构建卷约有 64 GiB，复用已结束的 #9190 构建缓存：先检查整个旧镜像的进程与打开文件，再只克隆产物并重定位 CMake 缓存路径，不复制其源码。11,385 份受控文件双端 SHA-256 一致，当前镜像重建自己的 Rust 库及原生目标；补充验证说明单独检查。当前仅证明账号与系统翻译各自的共享队列缺陷；原报告的应用与服务组合仍待现场复验，不能断言全部跨应用差异已解决。
