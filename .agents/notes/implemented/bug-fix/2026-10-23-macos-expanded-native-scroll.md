# Agent Note: macOS 展开候选使用虚拟化原生滚动视图

Status: implemented

## Problem

[自定义像素滚动修复](./2026-10-20-macos-expanded-candidate-smooth-scroll.md)纠正了方向、跨行跳动和裁剪，但每个像素事件仍重新测量、重建可见按钮。原生滚动需要保留可见行虚拟化、主题和选词契约，并为停在首尾后重新开始的手势提供一致的边缘反馈。

## Decision

固定首行和皮肤外框，候选区域使用透明的 `NSScrollView` 与普通非翻转文档视图。AppKit 接收精确滚动及惯性事件，负责像素位置和边界；竖向明确使用 `NSScrollElasticityAllowed`，横向关闭弹性，保留自动隐藏的原生覆盖式竖向滚动条，不让候选浮窗本身位移或取得键盘焦点。已经停在首尾后重新开始的手势仍交给 AppKit，不按 `hasPreviousPage` 或 `hasNextPage` 拦截；虚拟行定位保持在合法内容范围，但不把原生裁剪视口拉回边界，避免打断回弹。

完整重排时计算各行几何和累计高度，让滚动视图知道完整内容尺寸；仅为视口覆盖的行创建按钮。行内滚动只移动原生裁剪视口，跨行时删除离开视口的按钮、创建进入视口的按钮，其余按钮复用。普通滚轮保留旧的按行语义，键盘、带代次选词、主题、读屏和动画继续走既有控制器。

普通滚轮也使用原生视口的累计行高和实际像素上限，不能用首次展开的可见行数判断是否到底。向前移动到下一行起点并限制在实际底部；反向先清掉当前行的像素余量，再进入前一行。没有位移的边界事件不修改控制器状态；发生位移后保留固定视口高度和手动位置，仅在高亮移出实际可见范围时将其夹回。这样非等高末行仍可继续滚动，停在底部再滚普通滚轮、随后重画也不会跳回旧高亮行。

实际可见行范围只用于滚轮边界与高亮夹紧，不覆盖键盘的 `_expandedVisibleRows` 翻页预算。一个特别高的末行可以独占整个视口，但这不代表之后的 PageUp 只能退一行；键盘接管仍沿用该布局原有的整页步长，再重新定位高亮。回归从非等高末行切回普通滚轮后按 PageUp，核对返回原有的目标行。

固定高度只属于同一次布局，不跨字号、偏好、皮肤包替换、明暗几何或选中条变化复用。上述入口清零原生方案的 `_expandedViewportHeight`，下一次绘制重新测量；普通候选页也清掉旧预算。保留上游 #9280 的失效时序，而不引回自定义滚动的待处理 delta 或第二份视口高度。缩放回归从手动原生视口开始，将字号改为 `150%`，检查候选区域随之增高，之后的精确滚动继续固定新高度。

展开网格采用类似 `SharedSizeGroup` 的全列表共享列：同一列取所有行的自然宽度最大值，再按屏幕可用宽度收窄超长列，短列保留自然宽度。所有行按共享列宽重新测量文本，列内折行而不把一页候选拆成多个不对齐的子行；短末行不均分剩余宽度。首行、后续行和滚动后才出现的行共用列边界，普通未展开候选的逐页排版不变。现有原生滚动笔记吸收这一几何契约，不另建重复笔记；普通候选的[自适应宽度上限](../feature/2026-10-22-candidate-single-line-adaptive-cap.md)仍只约束原有逐页布局。

候选区域右侧固定预留 AppKit 常规覆盖式滚动条宽度（向上取整）再加 `4 × candidateScale` 点间隔，滚动条仍覆盖原生视口，但不覆盖候选按钮。宽度分配与屏幕上限先扣这段留白，卡片再将其加回；首行、收起按钮和普通候选窗不挪进滚动区。即使滚动条暂时隐藏也保留留白，避免显示时列宽或窗口跳动；不只增加文字内边距，因为候选背景和鼠标命中区域也不应压到滚动条下。

Canvas 内容边距适配同时调整展开视口及文档宽度。视口已经平移 `padding.left - inset`，其宽度只增加 `padding.right - inset`，右边界因而贴合最终卡片（扣除独立收起按钮列）；不能再叠加左右边距的总差，否则会重复计算左边平移。文档宽度跟随实际裁剪视口，候选列位置及预留滚动条间隔不变。右边距为零或小于基础 inset 时仍保留完整原生滚动条，不让卡片裁掉它，也不引入横向滚动。

采用原生视口替代自定义事件距离累计，保留前述修复的坐标、短末页高度和选词契约。首次展开测量全部行而不是只测量可见行；窗口宽度取所有行的最大宽度，避免滚动时不断改变外框。虚拟化限制的是按钮数量，不宣称消除了全列表测量成本；超长候选列表的进一步优化需要几何缓存或估算策略。

## Verification

`shortcut-expanded-scroll` 使用正确映射 CoreGraphics 手势阶段的像素事件，等待 AppKit 异步滚动完成，再核对方向、两点跨行连续性、非等高行、结束事件、短末页及键盘和普通滚轮接管。行内滚动必须保留同一外框、滚动视图和按钮，不增加光标位置查询；跨行保留重叠按钮。二百条合成候选的按钮数量小于候选总数，原生裁剪视口定位后重画也保留手动滚动位置。

普通滚轮回归额外覆盖：精确滚动到底后的无效向下事件与再次重画、末行折行特别高时的向下接管、逐行到达真实底部及反向离开底部；全过程核对固定窗口高度与重画后的像素位置。

Canvas 夹具组合右边距 `0/2/21`、左边距 `0/23`、独立收起按钮开关、`100%/150%` 缩放、横竖布局和明暗主题；强制显示原生滚动条，核对其完整边界、候选间隔、文档与裁剪视口等宽及无横向滚动。卡片受 `NSWindow` 物理像素取整影响，边界断言只允许一个物理像素误差。`candidate-factory-layout` 单独覆盖展开共享列的首列左下外圆角和末列左下内圆角，普通候选的末行圆角与动画路径断言仍保留。

原生视口的坐标转换和逻辑布局分开验证：文档内首候选的 X、Canvas 视口的 X、候选视口顶部与收起按钮的间距仍要求 `0.01` 点精度；跨过 `NSClipView` 转换后的候选左缘、底缘及卷轴顶部关系只允许一个 backing 像素误差。普通未展开布局仍要求 `0.01` 点，不把原生滚动的容差扩散到原有路径。失败日志记录缩放、主题、布局、候选及 viewport/clip/document 矩形，不靠继续扩大容差排查。

PR 的 macOS arm64 CI 在 `candidate-row-layout` 左缘及 `candidate-factory-expand-toggle` 顶部关系断言失败，但没有输出偏差值；本机 macOS 26.7.1 / Xcode 27 的 Debug、Release 均不能复现原断言。加入严格逻辑几何与物理像素坐标两层检查后，CI 的左缘和卷轴检查均通过，继续暴露 Canvas 无首行时与卡片高度比较的顶部断言。与窗口卡片边界比较的坐标同样只允许一个物理像素，预编辑与视口本身的逻辑间距仍要求 `0.01` 点精度；超出一个物理像素的偏差必须按新增日志继续定位，不能继续扩大容差。

回弹回归检查竖向 `Allowed`、横向 `None`，以及停在底部后新手势仍进入原生滚动入口、原生裁剪视口确实越过底部、虚拟行定位不越界、外框高度不变。手势结束后只等待 AppKit 将视口弹回合法范围，不用程序定位伪造复位。合成事件覆盖越界和复位，但不证明真实触摸板手感，维护者仍需要分别测试连续滚到底和停稳后再向下滑。

原生宿主构建、`shortcut`、`shortcut-expanded-scroll`、`candidate-row-layout`、`candidate-factory-layout`、`candidate-expanded-grid`、`bundle-contents`、`session-smoke`、`text-client`、`desktop-input-session`、`input-source-registration`、`backend-library-load` 十一项 CTest 和 `pnpm run verify-notes` 是这组改动的本地验证范围。输入会话测试曾出现一次响应计数断言失败，单独复跑通过，不把它记作首次全绿。完整设置应用与输入法安装时另核验签名和核心 UUID；合成事件与安装核验不等于真实触摸板惯性验收。

## Alternatives considered

- **保留自定义像素视口**：已有经过验证的最小修复，首屏只测量可见行，回退成本最低。不选它：每个像素事件重建按钮，原生视口可复用重叠按钮并将滚动与弹性边界交给 AppKit。
- **原生滚动视图一次创建全部按钮**：实现直接，AppKit 自动管理全部内容。不选它：候选数量可以很大，完整视图树会增加展开延迟和常驻内存；`NSScrollView` 不妨碍自行虚拟化按钮，不能把“不自带虚拟化”误写成“无法虚拟化”。
- **关闭全部弹性**：候选内容始终贴着边缘，不出现回弹留白。不选它：关闭竖向弹性会使停在末尾后继续向下滑没有回弹，与原生边缘反馈不一致。

## Consequences

同一行内滚动不重建候选外框、测量布局或替换按钮，跨行只更新进入和离开的行。普通滚轮和键盘保留原有语义；当前视图和候选代次检查阻止过期按钮选词。安装前保留设置应用和输入法备份，不修改用户偏好或私有词库。

共享列让第二、第三行与首行逐列对齐，代价是全文测量后还需要按列实宽重测行高，首次展开更耗时；位于不同列的最长词可能让网格比任何单独一页更宽，最终仍受屏幕可用宽度约束。仅参照第一行宽度虽能省测量，但会裁切后续更长候选；逐行独立排版更紧凑，但无法保证列对齐，因此两者都不采用。回归覆盖不可见行决定列宽、前三行逐列位置与宽度、短末行及滚动前后宽度稳定。

首次测量所有行可能增加展开延迟和几何内存；滚动条留白使短候选卡片稍宽，接近屏宽时会减少列可用宽度并可能增加折行。竖向 `Allowed` 在全部候选都可见时也允许拖出留白，松手由 AppKit 复位。嵌套裁剪容器改变坐标层级，第三方皮肤的圆角、悬停和选中动画仍需实测。异步候选代次重载继续使用旧的定位策略，可能中断滚动；本次不改选词或重载契约。

隐藏测试面板没有 WindowServer 窗口和真实手势跟踪，直接调用 `scrollWheel:` 的合成惯性事件不能证明 AppKit 惯性位移；真实编辑器中的慢速拖动、快速惯性、反向滚动和首尾边界手感仍属于维护者的实机验收。
