# Agent Note: Android 整句候选设置避免误解

Status: implemented

## Problem

Android「表达 → 智能」里的「整句联想」实际控制的是输入多音节拼音时的整句候选：标准使用词库词网格，增强再用神经模型重排。用户按单个汉字测试，或把它理解成上屏后推荐下一个词时，看不到预期结果，会把正常的能力边界当成设置失效。

## Decision

设置项统一称为「整句候选」，副标题明确触发条件、标准与增强的差别，并说明下一词推荐属于独立的「上屏后联想」开关（见[上屏后联想](../feature/2026-10-24-post-commit-prediction.md)）。Android 搜索关键词同时保留旧称「整句联想」，加入新称和「神经模型重排」，使旧入口与新文案都能被设置页搜索命中。偏好键和值不变，运行时行为不变。

## Alternatives considered

- **把设置改成上屏后推荐下一个词**：这正是 #9433 反馈希望得到的行为，但需要新增跨上屏的预测状态和候选交互，超出本次文案修正范围；本 PR 仅澄清已有设置，下一词推荐由独立的上屏后联想决定承接。
- **只改标题，不改说明和搜索词**：改动更小，但仍不能说明单字测试为何看不到整句候选，旧的无障碍搜索入口也可能找不到，不能完整消除误解。

## Consequences

用户能从标题和说明直接知道整句候选的触发条件与两个级别的差别；已有偏好、引擎逻辑和存储格式保持兼容。整句候选本身不承担下一词推荐；独立的[上屏后联想](../feature/2026-10-24-post-commit-prediction.md)提供这一能力，保留本篇关于原设置含义和兼容性的决定。

## Verification

通过 Android Java 宿主编译与静态检查、笔记门禁和差异空白检查；未改 Android 文件读写、目录遍历、权限或资源文件，不需要设备文件系统验收。
