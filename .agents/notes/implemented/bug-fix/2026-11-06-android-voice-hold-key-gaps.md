# Agent Note: Android 长按语音锁定后的操作键留出键距和行距

Status: implemented

## Problem

#10966：Android 0.6.0 长按空格说话再锁定后，聆听面板下方的操作区（取消 / 符 ！ ， 其他 / 🔒 已锁定 发送）键帽横竖连成一片，最左、最右两列还顶到屏幕边缘。「其他」弹出的换行、空格、删除三个键也一样贴在一起。

原因在 `ImeVoiceEntry.buildHoldActions()` 和 `toggleEditPopup()`：三行和弹层里的键位都用 `new LinearLayout.LayoutParams(0, h, weight)`，没有外边距，容器也没有内边距；`holdButton()` 又把键帽内边距清零。普通键区的键距、行距是 `ImeStyler.applyKeyboardGeometry` 给键位加的外边距，这个面板在 #10327 / #10373 里自己建行，没有经过那一步，也没有自己补上。点按入口的聆听面板（说完了 / 取消）写了固定的 12 dp、16 dp、10 dp，所以没有这个问题。

长按语音只在 Android 上有；iOS 和 HarmonyOS 只有点按面板，那个面板本来就有间隙，不需要三端同步。

同一问题的另一份修复 #10982 先合进了 develop：它在 `buildHoldActions` 末尾对操作区调用 `applyKeyboardGeometry`、按 `ImeStyler.keyAreaEdgePadding()` 补边距，按钮高度扣掉行距。它留下三处没处理：「其他」编辑弹层的三个键仍然相接（那份 PR 明确说不在范围内）；空位不带外边距、控制行按 1:3:1 直接分，🔓 和「发送」与上一行的「符」「其他」错开约 2.4 dp；面板没盖住功能行时仍会在已有内边距的键区里再补一次边距。本笔记的做法在合并 develop 时取代了那段实现，沿用它新增的 `keyAreaEdgePadding()`。

## Decision

- **间距跟用户的键区设置走。** 新增 `holdKeyParams(width, slotHeight, weight)`：键位四周各留半个键距（`halfHoldKeyGap()`，与键区一样经 `KeyboardSpacingPolicy.layoutKeySpacing` 取当前键面的键距，注音大千键面会收窄）和半个行距（`touchRowSpacingTenths`），相邻键帽之间正好一个键距，上下两行之间一个行距，与它盖住的键区取同一组值。`slotHeight` 是含行距的整格高度，键帽高度扣掉上下两个半行距。
- **左右边距与键区一致。** 操作区容器用键区同一个 `ImeStyler.keyAreaEdgePadding()`（`DESIGN_PADDING_HORIZONTAL_DP - 半个键距`）补左右内边距，最外侧键帽距屏幕边缘 6 dp。只在面板盖住了功能行、搬到键区外面时补：没有可见功能行时面板仍挂在键区（`keyRows`）里，键区本身已经有这份内边距，再补一次最外侧键帽会离屏幕边缘约 9 dp。
- **空位也带外边距。** 取消行两侧和标点行中间的空位用同一份参数，同一行每格扣掉的外边距一样多，按权重分到的列宽才和上下行一致。
- **最下一行与上一行同列。** 「松开发送」先拿两个键距的宽度，剩下的再按 1:3:1 分。这样 🔓、「发送」和「符」「其他」一样宽，「松开发送」正好占中间三列加两个键距；只给三键加外边距的话，🔓 的右沿会比「符」偏出约 4/5 个半键距（默认设置约 2.4 dp）。
- **控制行整格高度不变。** 仍取被覆盖的原功能行高度，键帽在这一格里上下各让半个行距，和原功能行的键帽同一位置，按住原空格的手指照样落在「松开发送」上。新增的上方两行行距由 weight=1 的 `VoiceListeningView` 让出，面板总高度不变。取消行、标点行的键帽保持 44 dp（#10982 把整行压在 44 dp 里，键帽只剩约 37 dp）：这两行是锁定后要点按、上滑的键，键帽不该因为加了行距变矮，多出的约 14 dp 从聆听区里出。
- **编辑弹层按含间距的格子算宽高。** 每格 56 dp 加一个键距，高 44 dp 加一个行距，定位仍按弹层宽高贴在「其他」上方右对齐。
- **命中判定不动。** `VoiceHoldPolicy` 只认取消和锁定按钮的实际范围，其余位置松手发送；键帽之间的空隙落进发送分支，与「松开发送」的语义一致；`moveHold` 的高亮按实际按钮范围算，空隙里不高亮。

## Alternatives considered

- **在行上设 `SHOW_DIVIDER_MIDDLE` 的透明分隔线**（回复面板的做法）：只在格与格之间加空隙。不用的原因是取消行、标点行、控制行的格数不同，分隔线数目不同会让上下行的列边缘错开，而且两侧边缘还要另外处理。
- **把整块操作区交给 `ImeStyler.applyKeyboardGeometry(View)`**（#10982 的做法）：它按 `followsKeySpacing` 给键帽加外边距。不用的原因是它跳过空位，同一行的列宽就和上下行对不齐；还有，它不管键位高度，控制行的键帽高度、空位、列对齐和弹层尺寸都还得另外算，结果依赖一个看不见的遍历顺序；面板不在 `keyRows` 下，改设置时那一遍也不会再走到它。
- **写死 dp 值**（点按面板的做法）：改了键距、行距的用户看到的面板会和键区不一样。

## Consequences

- 收益：锁定后的操作区和弹层与普通键区一样有键距、行距，不顶屏幕边缘，跟着用户的键距、行距设置变。
- 代价：键帽比原来窄一个键距、矮一个行距。面板在长按时建一次，期间改键距设置不会重排，这和改之前一样（之前根本没有间距）。

## Testing

- `VoiceHoldDeviceChecks.assertHoldKeyGaps`：在真实输入法窗口里锁定后，量「符」与「！」、「，」与「其他」、🔓 与「已锁定」、「已锁定」与「发送」之间的横向空隙，取消行与标点行、标点行与控制行之间的纵向空隙，以及最外侧两键与键盘窗口边缘的空隙，都必须大于 0；🔓 与「符」右沿、「发送」与「其他」左沿相差不超过 1 px。弹层里换行、空格、删除两两之间也要有空隙。改之前的代码上这些键帽首尾相接，第一条断言就失败。
- `platforms/android/check-host.sh` 钉住接线：键位经 `holdKeyParams` 取键距和行距，操作区不再直接 new 不带外边距的键位参数。把 `ImeVoiceEntry.java` 换回 develop 的版本，这一段报错退出；换回改后的版本通过。
- `voice-lifecycle.sh hold` 先删掉设备上上一轮的截图（专项在截图之前失败时不会拉回旧面板），再把锁定后的面板截图拉回 `target/android/voice-hold-panel-api<N>.png`，Android device 作业不论成败都上传为产物，PR 的改后截图取自这里。
