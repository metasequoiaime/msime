# Agent Note: Android 外语轮换与日语九键布局修正

Status: implemented

## Problem

#7751 暴露了中英键轮换的两个回归：输入法设置里移除的外语仍会被轮换，因为键盘把所有已安装方案当成可见方案；日语九键的语言键仍在左列，而其他 Android 键盘已把语言键放到回车左边。英语切到外语时还会先渲染一次中文键盘，再渲染目标方案，出现闪烁。

## Decision

用户可通过[语言键与数字键交换](../feature/2026-10-14-android-language-number-key-swap.md)选择左侧语言键；本篇的默认位置与轮换修复保持不变。

中英键轮换的 `visibleSchemes` 只从用户启用且资源已就绪的方案计算；设置页的「添加语言」仍可展示未启用方案，但它们不会出现在键盘轮换环。日语九键把语言键从左侧模式列移到右侧空格和回车之间，与新的手机底行位置保持一致。

从英文直输切到其他方案时，保存期间保留英文模式；保存成功后在同一个主线程回调里退出英文并应用目标方案，只让最终键盘进入下一帧。若目标方案已经是当前方案，直接退出英文并渲染；保存失败则仍保留原来的英文键盘。

## Alternatives considered

- **保留所有已安装方案参与轮换。** 最强理由是用户刚安装的语言无需再写启用列表；但这会让用户在设置中移除的外语继续出现，直接违背 #7751 的预期，因此采用启用列表过滤。
- **日语九键继续保留独立左列。** 最强理由是它原本没有底栏，左列空间充足；但用户会在中文、韩语等键盘上看到右侧语言键，切到日语后突然跳到左侧，位置记忆不连贯，因此把它放到右侧列。
- **先渲染中文，再异步切到外语。** 实现简单且能复用现有 `toggleInputLanguage`；但两个不同布局连续出现就是报告中的闪烁，因此增加不渲染中间状态的路径。

## Consequences

移除外语后中英键不再跳入该语言；日语九键的语言键与其他手机键盘靠近回车，且英文到外语只显示一次最终布局。方案切换仍需异步保存，保存期间的重复点击仍被忽略。`visibleSchemes` 的语义与 [Android 中英键可选轮换已添加的其他语言键盘](../feature/2026-10-10-android-language-key-cycle.md) 保持一致；日语九键位置的旧排除说明由本笔记取代。
