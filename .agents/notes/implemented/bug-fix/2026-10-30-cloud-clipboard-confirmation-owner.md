# Agent Note: 云剪贴板确认框保持客户端归属

Status: implemented

## Problem

共享云剪贴板面板在更换 `CloudClipboardPanelClient` 时会清空列表、设备状态和加载标记，但保留了待确认的关闭、重置或移除设备操作。面板完成新客户端的刷新后，旧客户端打开的确认框仍然可见；确认动作使用当前 hook 的客户端，可能把旧账号的破坏性意图带到新客户端。

## Decision

待确认的云剪贴板操作必须与打开它的客户端绑定。`useCloudClipboardPanel` 在 `[client]` 生命周期 effect 中清空 `confirmation`，新客户端加载后用户必须重新发起并确认关闭、重置或移除。草稿、搜索词和其他非破坏性输入仍按原契约保留。

## Historical audit

已检索云剪贴板面板状态、客户端契约、端到端加密、设备批准和确认相关的活跃笔记。[云剪贴板面板状态独立复用](../../implemented/simplification/2026-10-19-cloud-clipboard-panel-state.md)持有 hook 的状态边界，本篇只补充客户端切换时确认归属；[云剪贴板端到端加密](../feature/2026-10-11-cloud-clipboard-e2e.md)持有重置与移除协议，本篇不改变协议或服务端行为。没有其他笔记实现同一确认生命周期。

## Alternatives considered

- **给面板按客户端加 React `key`**：可以整体重建并清除所有状态，但会同时丢掉允许保留的草稿和搜索，且要求每个调用方维护客户端身份；在已有生命周期 effect 中只清除破坏性确认可以保持现有输入状态契约。
- **在每个确认动作中再次比较客户端**：可以阻止旧回调，但确认框仍会向用户展示旧意图，且客户端替换后没有必要保留待确认操作；在归属变化时清除状态更直接。

## Verification

新增三项受控回归分别覆盖关闭、重置和移除确认。旧实现三项均失败，修复后确认框在新客户端列表加载完成后均为空，且新客户端没有收到任何旧破坏性操作请求；既有云剪贴板 hook 测试继续通过。测试使用合成条目、设备和客户端，不执行真实账号或云端操作。

## Consequences

客户端切换会丢弃尚未确认的破坏性操作，用户需要在新客户端重新确认；草稿、搜索和列表刷新语义不变。修复只影响共享 React 面板状态，不改变云剪贴板协议、密钥、服务端数据或原生宿主接口。
