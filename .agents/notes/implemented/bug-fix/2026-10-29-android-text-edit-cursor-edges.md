# Agent Note: Android 方向键不越过文档首尾，同一输入框重启连接不关文本编辑面板

Status: implemented

## Problem

#10141（#10138 是同一个问题，已按重复关闭）：Android 0.6.0 上，在「文本编辑」面板切到触控板后上下左右各滑一下，面板会自己关掉、回到主键盘。Via 浏览器里 GitHub 新建 issue 页的标题框、Firefox 地址栏、下载工具的地址栏和链接输入框都 100% 复现；MacroDroid 里只有一个输入框的页面一切正常。

两处原因叠在一起：

- 触控板、面板方向键和空格拖动都靠向编辑器发 DPAD 移光标，发之前不看光标是否已在文档首尾。编辑器处理不了的方向键会被系统当作焦点导航：原生输入框在光标已在 0 或末尾时 `Selection.moveUp` / `moveLeft` 等返回 false，`ViewRootImpl` 把焦点交给相邻的可聚焦控件；WebView、GeckoView 同样可能借此换焦点或对同一输入框 `restartInput`。网页表单和浏览器地址栏旁边总有别的可聚焦元素，MacroDroid 那页没有，所以只有前者出事。
- `onStartInput` 对任何连接开始都调用 `ImeTextEditPanel.editorChanged`，第一句就是 `close()`；`stop()` 也经 `closeToolbarPanels` 再关一遍。同一输入框的 `restartInput` 和换了输入框一视同仁，面板都被收起。报告者第二份诊断包里，测试那段时间有约十条连续的 `ime_start`、中间没有 `ime_finish`，正是 `restarting=true` 的重启。

## Decision

### 不往外发越界的方向键

`TextCursorEdgePolicy.plan` 决定一批方向键里实际发几个，触控板（`ImeTextEditPanel.moveTrackpad`）、面板的 ←↑↓→（`perform`）和空格拖动（`ImeBottomRow.moveEditorCursor`，主空格、分离式键盘右半边的空格和底栏移光标条都经它）共用 `ImeTextEditPanel.cursorPlan` 这一个入口。被扣掉的步不发键、不震动，触控板手势照常继续。

- 每批发键前只读一次、只读要走的那一侧（`getTextBeforeCursor` / `getTextAfterCursor`，至少 256、至多 1024 个字符）。不在批内逐键回读：编辑器处理 IME 发来的按键是先排进自己主线程队列的（`ViewRootImpl.dispatchKeyFromIme`），紧跟着发出的同步回读会先于这个键被处理，读到的还是旧文字。
- 横向最多走「那一侧的字素数」步；字素用 `BreakIterator.getCharacterInstance`，代理对、组合附加符只算一步。纵向最多走 `max(1, 那一侧的换行数)` 步：软换行只会让真实行数更多，按换行数不会多走；同一行里只发一下（光标先到行首或文档开头）。斜向同一侧时，纵向只按横向走剩下的文字算。
- 选区：不在选择模式时有选区的第一下只把选区收起，横向在开头也照发这一下。纵向在边界一侧没有文字时，只有另一侧还有文字才发这一下：原生 `Selection.moveUp` / `moveDown` 只在整段选中时收起选区后返回 false，只选了开头或末尾一部分时返回 true。选区的锚点和活动端取面板从 `onUpdateSelection` 记下的值；这份回报是异步的，上一批刚把选区收起、回报还没到时它会过时，所以收起那一下正好要越过边界（横向请求比剩下的字素多，或纵向那一侧已没有文字）时，先用 `getSelectedText` 确认编辑器此刻还有选区，没有就不算收起。
- 选择模式下活动端朝锚点收缩时，先走完选区里的字，再走锚点外侧的文字（`getTextBeforeCursor` / `getTextAfterCursor` 读到的正是锚点外侧），到文档边界为止。选区里的字按 UTF-16 长度算，不另读选中的文字；纵向不知道选区里有几行，只数锚点外侧的换行，至少一步。哪一端是活动端只能从 `onUpdateSelection` 的回报看：原生 TextView 原样报锚点和活动端，报来 start > end 时活动端一定在左端；Chromium WebView 的回报来自 Blink 的 `PlainTextRange`，总是 start <= end，方向丢了。所以报来 start < end 时两个方向都按「活动端可能正朝锚点收缩」取上限：从末尾向左选出的选区在 WebView 里报成 (2,5)，往右收缩时要走的是选区里的字，若按「活动端在右端、外侧已没有文字」算就会把收缩的键全部拦掉，选区缩不回去。取上限的代价是方向不确定时在边界上可能多发几下 Shift+方向键：编辑器自己消化（原生 `Selection.extendLeft` / `extendRight` 恒返回 true，Blink 不开空间导航时同样吞掉），`ViewRootImpl.performFocusNavigation` 只认不带修饰键的方向键，带 Shift 的不会变成焦点导航。密码框开头一侧按报来的 selectionEnd 截断，它要么是活动端、要么是方向丢失时的右端，同样是上限。
- 照原样发、不拦的情况：`TYPE_NULL` 编辑器（Termux 一类终端要原样收到方向键，也不读）；回读返回 null 的编辑器；两侧都读出空串、又不能经 `getExtractedText` 确认全文为空的编辑器——不维护文字、自己处理方向键的远程终端和远程桌面多用 `BaseInputConnection` 的默认实现，它不提供抽取文字。能确认全文为空的真输入框（网页表单里还没填的标题框正是报告者的场景）照常拦，哪个方向都不发。
- 密码框沿用触控板笔记的零读取约束，不读文字、不读选中的文字、也不问是否为空，只凭报来的选区拦开头一侧：活动端（不在选择模式时是选区起点）为 0 时左、上不发，否则横向最多走那么多步、纵向一步；纵向收起选区那一下在开头一侧无从确认另一侧，不发；末尾一侧不知道文档长度，照原样发；选区未知（-1，不报选区的编辑器）时也照原样发。

### 同一输入框重启连接时留着面板

`onStartInput` 在 `restarting`、包名、fieldId、输入类型、imeOptions 都没变（`MSIMEInputService.sameEditor`，与留着引擎会话的判断同一份），并且新连接的初始选区就是编辑器最近报来的选区（`ImeTextEditPanel.reportedSelection`，两端都已知才算）时，改调 `ImeTextEditPanel.editorRestarted`，`stop()` 也带上 `keepTextEdit` 跳过关面板，其他工具栏面板照关。`editorRestarted` 只作废旧连接上在途的选词回读和自身选区记录（`selectionVersion.reset`），把放大镜重新绑到新连接；选择模式、方向键连发、正在进行的触控板拖动和按住工具临时打开的触控板都留着——`TextTrackpadGesture.retarget` 和 `TextTrackpadHold.retarget` 让它们改认新连接，余量不丢，旧连接随即失效。换了输入框、不是重启或选区对不上，仍按原来的 `editorChanged` 关面板、取消手势；保留组字的那条重启路径按同一个判断选。

只比包名、fieldId、输入类型和 imeOptions 分不出同一个 WebView 或 Compose 视图里的两个输入框：`fieldId` 是宿主 View 的 id，网页里焦点从一个 `<input type=text>` 换到相邻的另一个，同样以 `restarting=true` 的 `restartInput` 到达，输入类型和 imeOptions 也一样。不加选区这一条，面板会连同选择模式、方向键连发和进行中的手势一起带到另一个输入框，剪切、删除落在那里。这一条判断和面板的生命周期接线在 `platforms/android/check-host.sh` 里用 rg 钉住。

这收窄了[文本编辑触控板](../feature/2026-10-23-android-text-edit-trackpad.md)里「输入连接重建时取消旧手势」的规则：同一输入框的重建不再取消，换输入框照旧。

## Alternatives considered

- **每发一个键都回读一次再决定下一个**：最直接，单键时也最准确。但同步回读会先于刚发出的键被编辑器处理，一批里第二个键看到的仍是旧光标，从 1 往左发两个键照样越界；斜向批次的纵向回读也一样过期。改成每批读一次、按读到的文字截断步数。
- **只靠 `onUpdateSelection` 报来的偏移判断，不回读**：零跨进程读取，主线程不会被慢编辑器卡住。但回报是异步的，快速拖动时落后好几步，开头一侧拦不准；末尾一侧不知道文档长度，根本拦不了；纵向更不知道还剩几行。只在不能读的密码框里用它兜开头一侧。
- **同一输入框重启时面板留着，但选择模式、连发和手势一律复位**：不用分辨是不是同一个输入框，带到别的输入框也无害。但 WebView 拖动中途重启同一个输入框时拖动就断了，要抬手重来；选区对得上已经能分开绝大多数情况，剩下的碰撞见「已知上限」。
- **只做面板兜底（第二处），不拦方向键**：改动小，同一输入框重启的场景都能保住面板。但原生输入框把焦点交给相邻控件属于换了输入框，面板照样关；多出来的键还会把焦点挪走，用户回头找不到光标。两处一起改，拦键治本，留面板兜底。
- **放大触控区域、减少滑到边界的机会**：维护者明确不做，也治不了边界本身。

## Consequences

- **收益**：光标到了首尾继续滑、继续按方向键或继续空格拖动都只是停在边界，焦点不再跳到相邻控件，面板不再被关；WebView 在拖动中途对同一输入框重启连接时，面板和手势都接着走。
- **代价**：每批方向键多一次主线程上的同步回读（只读一侧，最多 1024 字符）；只在快到边界时才多一两次：收起选区那一下要越过边界时读一次选中的文字（整段选中的长文档会把全文读回来），纵向收起时读另一侧一个字符，两侧都为空时问一次 `getExtractedText`。编辑器卡住时这一批会跟着等。原来面板的放大镜回读放在后台队列，这里必须和发键在同一线程、同一顺序，不能挪走。
- **已知上限**：一段很长的软换行段落里，快速纵向拖动一批多步时只走一步（下一批接着走）。从右到左段落里 ← 在逻辑上是向后走，开头一侧为空时会被拦下，阿拉伯语、希伯来语用户遇到时要重访。编辑器主线程很忙、上一批的键还没处理完时，这一批的回读可能落后一批，仍可能多发一键。两侧读出空串、不提供抽取文字、却又不自己处理方向键的编辑器，空文档里不拦，焦点照旧可能被交出去。选择模式收缩时选区里有代理对或组合附加符，一批很长、正好走到文档边界时仍可能多发几下；报来的选区看不出方向（WebView 的 start <= end）时，按可能收缩的上限算，活动端其实在外侧时同样会在边界多发几下（带 Shift 的方向键不触发焦点导航，不受影响）；纵向收缩一个多行选区时每批可能只走一步。同一输入框重启的判断依赖 `onUpdateSelection` 回报：拖动中回报落后于重启时选区对不上，面板照旧被关（回到修复前的行为）；反过来，同一个 WebView 里两个输入框的光标恰好在同一个偏移（最常见是两个都空着、都在 0）时仍会被当成同一个输入框，面板和选择模式会留到另一个输入框上。
- **重访信号**：真机上仍有「滑到头面板消失」的报告，先看 `input_events.ndjson` 里是否还有成串的 `ime_start`，再看那个编辑器的回读是否返回 null 或空串。

## Verification

- `TextCursorEdgePolicySmoke` 用合成文字覆盖开头、末尾、横向按字素截断、纵向按换行截断、斜向同一侧共用文字、收起选区（含部分选中时上下键收起、回报过时时按 `getSelectedText` 算）、选择模式双向与收缩越过锚点到边界为止、WebView 不带方向的选区回报仍能收缩、`TYPE_NULL` 与确认不了的空文档原样发、确认为空的输入框不发、回读失败原样发，以及密码框零读取。
- `platforms/android/check-host.sh` 用 rg 钉住 `onStartInput` 的同一输入框判断（含选区一条）、两条路径的 `editorRestarted` / `editorChanged` 分支，以及 `stop` 只因 `keepTextEdit` 跳过关面板、更多工具照关。
- `TextTrackpadGestureSmoke`、`TextTrackpadHoldSmoke` 覆盖改认新连接后手势接着走、余量不丢、旧连接失效、无关连接不接管。
- 以上随 `platforms/android/check-host.sh` 的 JVM 冒烟一起跑。设备上的相邻输入框夹具和真机抽查未做，见 PR 的「未验证」。
