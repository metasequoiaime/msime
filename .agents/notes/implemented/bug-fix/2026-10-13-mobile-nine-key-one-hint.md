# Agent Note: 手机九键保留符号入口的数字 1

Status: implemented

「第一格短按打开符号面板」和「iOS 和鸿蒙底行的 0」两条已被 [九键底行改为 符 起头，1 键把常用标点放进候选条](../feature/2026-10-15-nine-key-symbol-key-and-quick-marks.md) 取代：1 键现在把常用标点放进候选条，面板从底行最左边的 符 打开，0 只留在数字层的底行。数字提示、长按与字号的决定仍成立。

## Problem

Android、iOS 和 HarmonyOS 的拼音九键把第一格画成「@#」，却只给 2–9 加数字提示和长按菜单。用户看不到 1，也不能像其他八格一样长按输入它。iOS 和鸿蒙底行的 0 使用字母字号，中/英使用功能字号，键帽虽齐，文字比例不一致。

## Decision

- 三端拼音九键字母层九格都显示长按可输入的数字。第一格显示 1，短按仍打开符号面板；Android 组字时短按仍分词。数字 1 只经字面输入路径，不交给拼音引擎。
- 长按第一格只提供 1，其余八格继续提供数字和小写字母。数字层不重复显示提示，也不弹长按菜单，切回字母层恢复提示和菜单。
- iOS 数字层取消为角标预留的上边距，让数字标题回到键帽中心。iOS 和鸿蒙底行 0 与相邻中/英使用相同功能字号与字重。Android 的 0 位于网格右列，继续与网格数字等大，不挪到中/英旁边。
- 鸿蒙的 2in1 网格第一格仍是分词，不增加数字提示或长按菜单。

## Alternatives considered

- 直接把第一格改成大号 1：数字更醒目，但会让符号入口消失，且把点按 1 送入不接受它的拼音引擎。保留符号键面，补回数字提示和字面长按。
- 只在数字页提供 1：实现最少，但用户选择九键后仍会看到字母层缺一个数字，且 1 比 2–9 多一次切层。

## Consequences

- 用户在字母页能看到完整的 1–9，1 与其他数字使用相同的长按路径。第一格长按由无动作变成菜单，短按符号或分词功能保留。
- 底行字号调整不改变键帽大小或点击区域。平台各自保留原有 0 的位置。

## Verification

- Android `check-host.sh` 的 230 项 JVM 冒烟及设备测试源编译通过，原生 APK 构建通过。`smoke.sh emulator-5566 --core` 在 API 28 通过；`NineKeyEnglishDeviceSmoke` 在 API 35 通过，真实编辑器结果依次为合成文本 `ok`、长按后的 `ok1`、数字页输入后的 `ok11`，回切后仍能长按第一格。API 28 的专项驱动无法观察完整候选状态，因此专项验收使用 API 35，不把旧版驱动失败算成通过。
- iOS `NineKeyKeyboardTests` 的 90 项测试通过，覆盖数字提示、长按选项、数字层禁用长按及回切恢复、短按 1 打开符号面板；真机签名构建并安装到 iPhone 17，键盘区域截图确认底行 0 与中使用一致字形。
- HarmonyOS `tests/run.sh` 通过，补测符号入口的 1 提示和长按选项；原生库与 `hvigorw assembleHap --no-daemon` 构建通过。没有连接鸿蒙设备，未做真机输入验收。

- `pnpm run verify-notes`、`git diff --check` 和本地 quick 门禁通过。首次 quick 在磁盘写满时失败，清理本任务的可重建产物后重跑通过。
