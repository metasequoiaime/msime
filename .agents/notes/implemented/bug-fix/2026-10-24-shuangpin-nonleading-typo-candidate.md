# Agent Note: 双拼非首选整句纠错候选保留

Status: implemented

## Problem

小鹤双拼输入 `mwgfxi` 时，纠错边可以把它解释为「没关系」，但生产词库中的字面整句「没根系」频率更高。纠错解码只取首条路径，并要求纠错句分数高于字面句，导致纠错候选在进入候选合并前就被丢弃。原有小型夹具没有模拟这种词频关系，因此回归测试未覆盖真实失败形状。

## Decision

双拼整句纠错使用独立的解码策略：在纠错轮次把末列 n-best 至少扩展到 64 条，从结果中选择第一条实际使用纠错边且不同于字面整句的路径，即使它的分数低于字面整句，也作为候选返回。候选合并仍把纠错整句排在普通整句之后，不让它抢首选。全拼继续沿用原规则，只接受分数胜过字面整句的纠错路径。

纠错路径只由当前输入产生的纠错边标记，候选仍携带原始输入和 `corrected_from`，因此宿主的选择、上屏和学习路径不变。

## Alternatives considered

- 提高纠错边权重或降低纠错惩罚，可以让「没关系」重新成为首条路径；这会改变纠错排序和全拼行为，且无法保证高频字面句不在其他输入中错误让位，因此不采用。
- 让所有输入方案都保留非首选纠错句，改动范围更小；全拼当前的分数门槛是既有质量约束，放宽它会把低置信纠错带入全拼候选，故只在双拼调用点启用策略。
- 只把 `nbest` 从默认值小幅提高，仍要求取第一条路径；当字面路径高频时纠错路径仍可能不是首条，不能解决实际失败，故改为在 n-best 中寻找第一条纠错路径。

## Verification

新增完整词网格夹具：字面路径「没根系」权重远高于纠错词「关系」，输入 `mwgfxi` 时断言「没关系」出现在首选之后并保留 `corrected_from`。同时保留全拼原有胜过字面路径的测试。`cargo test -p msime-engine --lib --locked` 通过（2568 项通过、56 项既有忽略），双拼定向测试 65 项通过，Host API 真实引擎偏好测试通过，Clippy、格式、差异检查和笔记门禁通过。Android 模拟器验收尚未执行：本机仅剩约 20–21 GiB，且已有其他 Android smoke 进程占用共享缓存，低于仓库规定的 50 GiB 构建安全线；不能用旧 APK 代替本次代码的安装验收。

## Consequences

双拼用户在字面整句更高频时仍能看到可选的纠错整句，纠错候选不会抢走普通整句的首位。双拼纠错轮次最多保留 64 条末列路径，可能增加少量纠错查询开销；全拼路径、默认值、词库格式和宿主协议不变。

## 历史笔记检索

检索了自动纠错弱位置、双拼纠错键规划、词网格路径和句子候选合并相关笔记。已有笔记分别约束纠错边的规划、路径所有权和候选合并顺序，没有一篇持有“非首选双拼纠错句是否保留”的决定，因此本篇新增并与这些既有约束并行。
