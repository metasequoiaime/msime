# Agent Note: 全拼简拼保留双字母声母与单字母拆法

Status: implemented

## Problem

#8763 的 `zhg`、`zhsh`、`chsh` 需要把 `zh/ch/sh` 作为一个简拼单位；`shdx`、`zhrmghg` 又需要把同样的两字母拆成两个简拼单位。现有全拼切分优先保留双字母声母，词库查询却仅在双拼中把它当声母，既漏掉整体匹配，也漏掉拆开后的候选。

## Decision

共享引擎的简拼过滤接受全拼中的 `zh/ch/sh` 单位，严格匹配同一声母。全拼查询遇到这些不完整单位时，同时查询有限条拆成单字母的替代切分；完整音节与已有完整全拼候选保持优先。手动分隔符保留用户给定边界，不自动拆开双字母单位。候选的匹配键记录实际消耗的原文字母，标准读音继续用于学习。

替代查询留在全拼词典，不修改通用规范化和双拼切分，不重建词库，不增加跨平台偏好字段。每个前缀最多 32 条替代切分，并优先保留全拆路径；单独一个双字母声母的短前缀仍只查询单字，避免关闭纠错时把错误拼写的开头扩展成词组。

## Alternatives considered

新增三档偏好能让用户单独选择新行为，但需要所有原生设置界面、持久化和同步协议共同扩展；当前缺失的是已有简拼查询没有覆盖的歧义，限定在不完整声母上补充候选即可保留完整全拼优先级。

直接修改通用切分能让预编辑串反映另一种读法，但通用切分还参与词条规范化、双拼与学习；强制选择其中一种拆法也无法同时满足 `zhsh` 与 `shdx`。替代查询保留两种合法解释。

## Verification

新增回归在原实现上复现 `zhrmghg` 只能返回 `zh` 开头单字。合成词库覆盖 issue 的七组简拼、手动边界、混合声母单位、完整全拼优先和最多 32 条替代路径；包含 64 个双字母声母的输入仍保留全拆路径。双拼的平翘舌严格区分继续由既有回归约束。

会话回归覆盖整段选择、保留尾部 `ni` 和光标前缀选择，检查匹配码消耗的原文字母数，以及非首选词按完整标准读音写入调频日志。默认首选沿用既有不写调频日志的规则。

初次完整 golden 揭示单声母短前缀扩展会让关闭纠错的 `shnaghao` 出现「上好」；修复保留单声母前缀的原行为，golden 文件不改写。直接调用全拼引擎的夹具也要像实际编排层一样在关闭纠错时重做字面切分，不能把纠错切分预先作为显式读音传入。

远端运行 `20261020-182132` 通过全部 2,371 项引擎单测（49 项按原有约定忽略）、31 项 golden 检查和全目标 clippy（`-D warnings`），随后完成 Host API 构建。

真实随包词库经 macOS Host API 的 C ABI 通过十二组输入与实际选择上屏：`zhrmghg`、`shdx`、`zhg`、`zhsh`、`chsh`、`zh'g`、`nh`、`wsm`、`zhongguo`、`zhi`、`chi`、`shi`，每次选择后预编辑均清空。`shdx → 上海大学` 位于第 3 项，`zhsh → 知识` 位于第 19 项；`nh → 你好` 仍位于第 10 项，反映本次没有调整词频。

最终 quick 运行 `20261020-182423` 通过，覆盖 Windows 可移植策略、仓库契约、Rust workspace、Android 目标与 Java 宿主、WebAssembly、Linux 设置壳、Linux 原生 93 项、macOS 宿主和 Apple bridge。Windows 本机／MinGW、pipe 与 HarmonyOS HAP 因工具链或 staged 输入缺失明确跳过，不将这些项算作设备验收。本机磁盘低于 50 GB，所有编译在远端完成。

## Consequences

全拼同时支持 `zhg → 中国`、`zhsh → 知识` 和 `shdx → 上海大学`，候选保留准确的输入消费范围与学习读音。代价是不完整声母的冷查询会增加有限条词库访问；替代行复用既有路径缓存，不改变完整音节的查询和排序。当前不新增三档偏好，也不修改词库权重；常用词继续通过既有调频规则学习。共享引擎与 C ABI 验证不等于系统输入法界面验收。
