# Agent Note: macOS 输入源缓存清理绑定祖先目录句柄

Status: implemented

## Problem

输入源刷新会清理系统缓存目录中的旧条目。清理逻辑已经把最终缓存目录打开成句柄，再用 `unlinkat` 删除条目，但最终目录此前仍通过路径型 `open` 打开。祖先目录在检查通过后若被替换成符号链接，路径解析会跟随这个祖先，把删除操作导向外部目录。

## Decision

缓存目录统一通过共享的 `open_private_directory` 逐级打开。该入口对每个祖先组件使用不跟随符号链接的句柄操作，并保留受信任系统别名的既有策略；目录枚举和删除继续使用已打开的句柄。

## Alternatives considered

- 继续使用最终组件上的 `O_NOFOLLOW`：只能保护缓存目录最后一级，无法阻止祖先目录替换后的路径重定向。
- 只增加一次 `canonicalize` 或再次检查路径：检查和打开之间仍有竞态，不能把删除绑定到检查时看到的目录。
- 为缓存清理单独实现一套目录遍历：会复制共享存储安全策略，后续容易与其它私有目录访问分叉。

## Consequences

祖先目录被并发替换时，清理会安全失败而不会删除外部目录中的文件；正常缓存清理行为保持不变。实现复用共享目录句柄逻辑，避免新增平台专用路径遍历代码。
