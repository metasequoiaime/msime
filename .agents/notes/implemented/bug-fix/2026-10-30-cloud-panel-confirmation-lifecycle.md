# Agent Note: 云面板切换客户端时关闭旧确认

Status: implemented

## Problem

云词条、完整目录、云候选、云词库文件和快照应用面板都通过 `useConfirm` 渲染页内确认框。客户端替换时各面板会清空结果并使异步操作代次失效，但 `useConfirm` 的待确认请求仍留在原组件实例中。用户切换到新客户端后，旧账号或旧词条的确认框因此继续显示；回答虽然会被代次守卫拦截，确认入口仍被旧意图占用。

## Decision

`useConfirm` 提供稳定的 `dismiss`，以取消当前待确认请求并让等待中的 Promise 得到 `false`。所有带客户端生命周期 effect 的云面板在失效当前操作代次时同时调用 `dismiss`，因此客户端替换会先关闭旧确认，再清理面板数据；组件卸载仍由 `useConfirm` 自己的清理逻辑负责。当前客户端的确认、取消、焦点恢复和代次守卫保持不变。

## Alternatives considered

- 只保留确认回答后的 `isCurrent` 检查：能阻止旧宿主执行写操作，但旧确认框仍显示在新面板上，用户仍可能看到过期账号或词条意图，也会占用确认入口，因此不足以修复生命周期问题。
- 在每个面板外层按客户端强制卸载确认组件：可以间接清除状态，但会重置整个面板并扩大生命周期变化；让确认 hook 暴露明确的取消动作，调用方只清理过期确认，边界更小。
- 只在云词条和完整目录面板接入取消：这两个面板最先暴露问题，但云候选、文件和快照应用面板具有相同的客户端替换与确认边界；统一接入可以避免同一缺陷在相邻云面板复现。

## Consequences

客户端替换时所有云面板的旧确认框立即消失，等待中的确认动作以取消结果结束，旧宿主不会收到后续修改请求。新增的 `dismiss` 扩大了 `useConfirm` 的小型公共 hook 接口，调用方必须在自身生命周期失效时主动使用它；已有确认框的键盘焦点、按钮行为和卸载清理不变。测试使用合成客户端和词条，不覆盖真实账号或原生宿主验收。

## Verification

新增回归在旧实现上验证为失败：客户端替换后旧删除、下载和目录确认仍可见。修复后云词条、完整目录、云候选、文件面板、快照应用及共享确认框相关测试共 47 项通过，覆盖旧确认清理、当前确认回答、旧异步结果隔离和 `dismiss` 的取消结算。
