# Agent Note: macOS 残留损坏输入法仍显示首次安装入口

Status: implemented

## Problem

#9821 反馈首次安装时没有「立即安装」按钮且找不到输入法。启动检查把输入法安装目录中已经存在但结构损坏的 bundle 当成“已有安装路径”，因此不打开首次安装窗口；用户只能进入维护页，无法从首次安装入口重新复制有效 bundle。

## Decision

首次安装窗口判定使用与启动刷新相同的 bundle 校验：目标路径不存在时显示；目标是普通目录但 `validate_bundle` 失败时也显示。符号链接、权限或其他无法安全确认的路径仍不自动显示首次安装入口，交给维护页的修复流程处理。这样只把确定为损坏的产品 bundle 交给现有「立即安装」事务，不改变正常安装、系统目录选择或版本比较。

## Alternatives considered

- **保持现状，只在维护页提供修复**：实现最小，但报告者已经无法找到输入法，首次安装窗口与维护页的入口语义不一致，不能解决反馈。
- **遇到任何已存在路径都显示首次安装窗口**：入口更积极，但符号链接或未知文件可能使安装按钮进入不可安全覆盖的路径，因此不放宽到非目录和符号链接。

## Consequences

损坏 bundle 会回到首次安装窗口，用户可以按原有范围选择和安装流程修复它；完整 bundle、其他产品 bundle、符号链接和不可读路径的行为保持不变。首次安装判定新增了一个纯本地结构校验，不会读取用户输入或修改系统状态。

## Verification

新增 Rust 单测覆盖资源目录有效、目标目录存在但 bundle 不完整时仍返回首次安装待处理。由于当前工作区缺少仓库规定的 `target/macos/EngineResources`，本机无法完成 `msime-desktop` 的完整构建测试；提交前仍运行 `git diff --check` 和 `pnpm run verify-notes`，CI 负责 macOS 原生构建。
