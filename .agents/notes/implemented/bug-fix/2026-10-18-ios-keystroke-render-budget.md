# Agent Note: iOS 连续输入按键路径的主线程预算

Status: implemented

## Problem

iOS 键盘连续输入时，普通字母键也会重复重写整套字母键配置、重复刷新九键拼音条，并在候选栏已经位于起点时再次设置滚动位置。这些操作都在主线程的按键回调中执行，输入引擎本身很快，但 UIKit 的布局和配置更新会积累成卡顿和漏帧。

## Decision

按键路径只在对应状态真正变化时更新 UI：

- 缓存字母键面的输入状态，候选内容变化不再重写 26 个键；
- 缓存九键/十四键拼音条的词列表和摆放位置，连续输入没有拼音条变化时不再逐个写按钮配置；
- 候选横向滚动位置只有不在起点时才归零；
- 计算 iPad 分离键盘前先判断设备、方向和开关，手机与竖屏不读取本地模式状态。

缓存键只覆盖绘制所依赖的状态；方案、语言模式、大小写、辅助码提示、滑动符号开关、本地模式和拼音条内容发生变化时仍会完整刷新。

## Alternatives considered

- **只调低延迟测试阈值或关闭候选释义**：不能减少真实设备上的 UIKit 主线程工作，也会掩盖用户仍能看到的卡顿，因此不采用。
- **把整个候选栏渲染移到后台线程**：UIKit 视图和配置必须在主线程更新，后台绘制还会引入代次和竞态；本次先减少可安全跳过的重复主线程更新。

## Consequences

连续输入复用不变的键面和拼音条配置，减少布局请求与候选滚动视图的无效更新；方案切换、大小写变化和候选内容变化仍按原路径重绘。延迟测试继续覆盖全拼、九键和高候选量输入，模拟器安装验证仍只能代表模拟器运行层级，不能替代真机输入法验收。
