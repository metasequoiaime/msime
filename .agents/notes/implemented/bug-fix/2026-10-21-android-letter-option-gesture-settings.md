# Agent Note: Android 字母选项支持滑动选择并遵守符号设置

Status: implemented

## Problem

#8985：中文 26 键上滑弹出字母选项后，原按键没有把后续移动和抬起传给弹窗，只能松手再点一次；右上角符号按 ASCII 字面提交，中文标点、组字转换、引号交替和成对补全没有生效。上滑分支又排在设置方向判断之前，连关闭「滑动输入符号」也无法停用。#9256 继续发现候选栏已经显示时，滑动输入符号仍会抢走这次触摸，打断候选选择。

## Decision

长按保留小写、大写、角标三项及松手后再点选的方式。打开字母选项之后，同一次手势的后续移动根据屏幕坐标命中实际按钮，显示选中态；进入过选项后，松手只触发当前命中的选项一次，取消或移出后松手则关闭。尚未进入选项的长按仍保留弹窗，轻微抖动也不会把它关闭，兼容点选与无障碍操作。弹窗仍不取编辑器焦点；九键、14 键、英文 O 和上标弹窗保留原行为。

通用弹窗按列容器中的多排行容器排版；中文拖选在打开时按显示顺序收集实际按钮，命中、选中态和抬起提交统一使用这份按钮列表，不将行容器强转成按钮。弹窗关闭时同时清空列表，避免下一次手势引用旧视图。英文长按设备夹具复用已有测试包编辑器入口，不能用产品包上下文构造测试 Activity 的组件名。

滑动开关同时控制直接输入与打开选项：设置方向直接输入角标，中文状态的反方向打开选项；关闭时两种滑动都停用，长按不受影响。默认下滑符号、上滑选项不变，设置为上滑符号时两者对调。设置页说明这层关系。

设置页选择方向后立即更新行尾标签，方向与滑动总开关的保存均在成功和失败时重载页面，使标签及方向行的可用状态跟随持久化结果。只给这两个关联控件补充刷新，不改变其他页面的通用保存回调。

符号选项的键面复用 `LetterHintTable.face`，选择与直接滑出角标共用同一份提交入口；适用的中文标点走 `punctuation`，继续由 Engine 结束组字、交替引号和补全成对标点。字母与原本不能走 Engine 的角标继续沿用字面提交，不复制中文符号表。

候选栏显示时，26 键符号滑动只保留普通按键路径。候选可见状态由输入法的候选视图和中文方案共同判断，英文建议仍保留原来的角标手势；`SwipeHintPolicy.enabled` 集中表达开关与候选态门控。

## Alternatives considered

- **恢复通用弹窗的单行结构**：能让原来的第一层按钮索引继续工作，但会撤掉英文变体的多行排版和窄屏适配；中文拖选改为跟踪实际按钮，保留通用弹窗结构。
- **用弹窗接管整段触摸分发**：可沿用系统 PopupWindow 的点击和焦点，但当前手势已经属于输入法窗口；弹窗抢焦点会影响编辑器，并不能自然接到旧窗口正在处理的 DOWN。保留原键事件，由屏幕坐标命中弹窗按钮。
- **上滑始终打开选项，只修符号输出**：最大程度保留新加的固定上滑行为，但继续违背现有方向与关闭设置；不能满足用户修改手势行为的要求。
- **中文选项直接写中文标点字面**：无需调用 Engine，但组字会走字面收尾，且绕过引号交替、成对补全；必须复用已有标点入口。
- **让通用 `saveLocalSetting` 成功后统一重载**：可一次更新所有依赖当前设置的行，但也会让各页的普通开关和滑块在每次保存后重建，扩大页面状态变化。本次只给方向与总开关显式传入刷新回调。

## Consequences

弹窗会被屏幕边缘裁切，命中必须取布局后的真实屏幕位置，不能按锚点猜坐标。用户可以在一次按压中完成选择，代价是服务要维护一次手势的锚点、选中项和弹窗引用。当前手势仍由原键持有，取消、失去窗口和弹窗关闭时必须清掉跟踪状态，避免旧输入框收到选择。其他复用弹窗的键不能自动获得字母拖选行为。
