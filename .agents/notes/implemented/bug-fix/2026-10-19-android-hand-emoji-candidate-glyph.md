# Agent Note: Android 手势候选缺字形时使用局部图像

Status: implemented

## Problem

#8801 在 Android 11（vivo）报告「左手、右手」候选为空。词库的两组键分别包含 U+1FAF1、U+1FAF2 和 U+1FAF7、U+1FAF8，不能只补前两个。API 28 的系统字体实测缺少前两个字符；候选由共享引擎管理，宿主不能过滤空白行后改变序号。未修改的安装产品运行新设备回归，失败于「手势 span 数量错误」。

## Decision

沿用 `CandidateSymbolLabel` 的候选主文字绘制入口，为四个手势及五种肤色提供 `ReplacementSpan`。系统 `Paint.hasGlyph` 支持整串时沿用系统字体，否则画随 APK 分发的 128×128 Noto Emoji 图像；按当前文字字号和基线排版，不改原始 Unicode、候选序号、释义或上屏文本。相邻 ZWJ 序列不拆开覆盖，避免把握手组合改画成两个单手。显式文本变体 U+FE0E 保持文本字体语义。

图像从 googlefonts/noto-emoji 固定提交 `e20cbc2bbec1926686be9f9bee7d1d2cfa1fea0e` 的 `2D/svg/` 转成 PNG。该子目录明确标示 Apache 2.0，避开仓库根目录字体 OFL 与 README 图像许可链接不一致的问题。来源、输入与输出 SHA-256、完整 Apache 许可及版权通知随源码保存，许可与通知也打入 APK。仅缺字时解码，缓存上限为 24 个图像，不下载完整字体。

## Alternatives considered

- **随包提供完整 emoji 字体**：可覆盖所有较新表情及复杂组合；但包体和字体加载成本大于本问题的四种手势，先限定修复范围。新缺字问题普遍出现时应重访统一字体方案。
- **换成旧版左右指手**：旧系统已有字形，无需资产；但手势含义不同，改变用户选中的字符，不能静默替换。
- **手动画轮廓**：不引入第三方资产；但四种手势与肤色需重新设计和维护，已有授权明确的标准图像更容易核对方向和颜色。

## Verification

未修改的安装产品在 API 28 的新增设备专项失败于「手势 span 数量错误」。修复后用 `arm64-v8a` 原生发布 APK 在 API 28、35 各跑 `HandEmojiCandidateDeviceSmoke` 和 `HeavyEqualsCandidateDeviceSmoke`，四项通过。API 28 缺失全部 24 个手势字形，API 35 缺失 0 个，分别覆盖图像兜底和原生字体路径。专项检查三种字号、深浅背景、原始码位、前缀与释义、肤色和变体边界、ZWJ 保护及绘制宽度。

`check-host.sh` 通过 247 项 JVM 冒烟和 188 份设备源码编译；资产契约核对全部 24 张 PNG 的集合、尺寸、来源和输出哈希、两种 APK 的通知打包路径。安装包在本机重新签名后安装，两台设备的已安装 APK SHA-256 均与本次构建一致，不将此前误用 x86_64 包的安装失败计为通过。远程显式选择 Python 3.14 的 quick 通过（`20261019-193953`），Rust 工作区、Android 目标、Android 宿主、Linux 设置壳和 Apple bridge 编译通过；不在改动范围或缺工具的阶段按日志跳过，笔记由本机补验。


后续验证脚本修正后，显式 Python 3.14 的 quick 再次通过（`20261019-200749`）。API 35 整套 UI 冒烟通过七种数字布局及此前全部键盘套件，文本编辑专项修正单行夹具与旧返回键面后独立通过，随后光标候选、实体键盘译文和 AI 候选占位专项通过；五笔查码的设置页导航用例失败。API 28 核心 UI 冒烟在固定合成全拼配置后，通过安装、准备、打字、手势字形、候选皮肤/画布、剪贴板导出、十万辅助码、74 词导入、拖选和七种数字布局，随后聊天页返回导航用例失败。两端均不记为整套通过；这些导航失败尚未归因于本次字形修复。

## Consequences

缺字形不再使四种手势候选显示空白，支持字形的系统继续使用本机字体。绘制只在本输入法候选里有效，无法补外部编辑器字体；复杂握手 ZWJ 不在这批局部资产范围。图像缓存与许可材料需要随未来资产更新一起维护。未在 vivo 真机验收，模拟器通过不能替代该设备现场确认。
