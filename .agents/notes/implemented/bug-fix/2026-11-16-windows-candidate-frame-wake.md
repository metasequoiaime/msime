# Agent Note: 新候选帧交给桌面线程时立即请求绘制

Status: implemented

## Problem

维护者报告 Windows 7 输入拼音后感觉等了数百毫秒。Win7 SP1 x64 的已安装 0.6.0 在真实记事本中，普通候选显示约 50～125 毫秒；已安装引擎 DLL 的 564 次逐键调用中，基础排序的 character + view 中位数约 0.25 毫秒、增强排序约 0.55 毫秒，最大 13.8 毫秒。正常节奏尚未复现每字数百毫秒，整句瞬间注入会形成数百毫秒积压，不能把两者混为同一根因。

`DesktopCandidates::State::run` 每轮最多等待 16 毫秒才读取新快照。拿到快照并调用 `Surface::publish` 后，只有协调线程是被显式叫醒时才叫醒桌面线程；普通按键仍等桌面线程下一轮最长 16 毫秒的消息等待。这是已经拿到新数据之后的一次额外等待。

## Decision

`Surface::publish` 发布了属于该桌面的新 `render_serial` 时，设置该桌面已有的自动复位事件。第一次收到有效帧、恢复路由或争用之后重新取得帧也请求一次绘制；重复的同一帧和非目标桌面不因此请求。协调线程维持原有轮询，不在输入队列或焦点锁内增加通知，不改变按键协议、模型、默认值、选词屏障或窗口的动画定时。

## Alternatives considered

- **每个按键发布后唤醒协调线程。** 能一并减少两级轮询，实测慢速候选更新中位数从约 58 毫秒降到 40～45 毫秒；但两轮连打的改善不稳定，Server CPU 用时从 500 增至 797 毫秒、交换顺序后从 1141 增至 1594 毫秒。CPU 包含后台工作，不能把差值全归因于通知，但不足以支持采用；这个实验未进入产品。本方案只通知已经收到新帧的目标桌面。
- **提高系统计时精度。** 可以缩短轮询粒度，但前一轮 Win7 实测 timeBeginPeriod(1) 未改善候选延迟，也会影响系统唤醒频率，因此不采用。
- **关闭增强排序。** 降低了引擎计算量，但没有消除候选显示等待，且改变用户选词体验，不作为本次修复。

## Verification

Win7 SP1 x64 虚拟机、32 位系统记事本、注册的 TSF 输入法，复用已安装 0.6.0 的 Rust DLL；原版与修改版都用相同的 MinGW Release 配置构建原生 Server。按原版 A → 修改版 A → 修改版 B → 原版 B 的顺序测试，每轮启动新的 Server 和记事本。测试关闭学习与在线候选，使用合成文本，结束后恢复原版二进制并校验 SHA-256，同时读回确认原设置。

| --- | --- | --- | --- |
| 原版 A | 57.7 / 80.7 | 70.7 / 33.4 | 718.8 / 78.1 |
| 修改版 A | 39.6 / 81.2 | 40.9 / 44.4 | 750.0 / 78.1 |
| 修改版 B | 41.8 / 69.1 | 35.5 / 46.9 | 859.4 / 125.0 |
| 原版 B | 58.2 / 75.6 | 57.2 / 68.4 | 812.5 / 31.3 |

逐键间隔 200 ms，每轮排除第一组预热后计入 33 个字母键。QMP 注入物理键并抓取真实帧缓冲，慢速每约 15 ms、连打每约 7 ms 取样，按候选窗连续背景区域定位后比较像素；不把编辑框的闪烁光标算进候选更新。连打数字是最后一键到候选最后变化的时间，不代表完整汉字上屏。CPU 是首个测量按键到最后一个空格之间约 15 秒的累计用时差，包含 Server 后台工作，Win7 计数以约 15.625 ms 的粒度变化。

`windows-desktop-candidates` 在 Win7 上通过同一焦点租约的连续候选更新、桌面隔离、读锁争用保帧、失焦隐藏、无效客户端和退出清理；非输入桌面不自动绘制，新增连续更新用例在收到对应帧回执前持续请求绘制，不改变既有测试的前置条件。`windows-candidate-render-request` 原生运行通过。新原生 Server 与这两个测试均完成 x64 MinGW 构建。

## Consequences

普通逐键候选更新的中位数在两次对照中稳定减少约 16～18 ms；40 ms 间隔连打也连续两次改善，80 ms 间隔和最长延迟仍有重叠，不承诺所有慢样本都变快。两组整体 Server CPU 比各自原版多约 31～47 ms，摊到约 15 秒输入窗口是约 0.2～0.3 个百分点的单核时间；候选线程也有额外用时且计数较粗，不声称零开销。采用这个局部唤醒，用小额调度成本减少已经拿到新帧之后的等待。

自动复位事件合并重复请求，窗口读到的是最新不可变快照；如果焦点随后改变，原有租约校验仍然拒绝过时帧。只减少第二级等待，不能保证消除引擎计算、编辑器阻塞或第一次初始化造成的延迟，也没有在正常节奏下复现报告中的每字数百毫秒。
