# Agent Note: macOS 候选行按窗口内边距计算圆角

Status: implemented

## Problem

#7761 的首选圆角取整个卡片圆角，悬停行却取固定行圆角。用户设最大圆角和最小内边距时首选成为胶囊而悬停行仍是小圆角，共享预览只按固定行圆角绘制。

## Decision

取消首尾高亮行的特殊圆角。用户明确设置窗口圆角时，选中与悬停圆角都使用窗口圆角减去有效内边距，最低为零；有效内边距至少为 2pt，并随整体大小缩放（这个下限已由[内边距低于 2pt](2026-10-15-macos-candidate-padding-below-2pt.md)改为边框宽度，行圆角改在缩放之后推导）。共享 macOS 预览使用相同公式和最小内边距，其他平台保持原来的几何。原生预览的绘制与高度测量读取实际内边距，不再写死 6pt。

本决定部分取代[宿主预览 token](2026-10-11-macos-candidate-preview-native-tokens.md)中首尾高亮的已知差异，其配色与平台边界仍保留。检索命中的九键、剪贴板、脚本行及词库笔记只提到预览或候选行，不决定此处几何，不修改。

## Alternatives considered

只删除首尾规则能消除选中与悬停的不一致，但大窗口圆角和小内边距仍会配固定 6pt 内圆角，不能形成协调的内外轮廓，因此同步推导用户自定义行圆角。

## Consequences

自定义大圆角让所有候选行更圆。未设自定义圆角的皮肤继续采用原有行 token，不重新解释皮肤几何。原生 token 测试覆盖最小与最大圆角、内边距和缩放；实际控制器测试检查选中与悬停按钮，共享预览测试核对 macOS 公式，原生预览测试检查内边距影响高度。
