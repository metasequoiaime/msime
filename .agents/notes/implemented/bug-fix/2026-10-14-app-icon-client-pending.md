# Agent Note: 图标客户端更换时清理旧切换标记

Status: implemented

## Problem

`AppIconSettingsCard` 用 `pending` 标记正在切换的图标，并据此禁用所有选择。图标客户端更换时，共享操作层解除忙碌、作废旧结果，卡片重新加载图标状态，却保留旧 `pending`。旧请求的 `finally` 因代次失效不会清理它，导致新客户端加载完后仍显示「更换中」，所有图标按钮一直禁用。

## Decision

`AppIconSettingsCard` 独立在 `packages/ui/src/account/app-icon-settings-card.tsx`，账号页各入口复用它。卡片的图标信息、切换标记、错误提示、初始化与切换动作由内部 `useAppIconSettings(client)` 管理，展示只绑定它返回的 `info`、`pending`、`error` 和 `choose`。hook 继续复用 `useAccountAction` 的忙碌、挂载与客户端代次守卫，不扩大公共包导出。

在 hook 的客户端初始化 effect 中把 `pending` 清为 `null`，与图标信息及错误提示一起交给新客户端重新建立。旧请求结果和收尾仍使用代次保护，不能覆盖新客户端已经开始的切换。`set` 报错后继续重读 `info`，仅当系统记录的图标与目标一致时视为成功；重读失败或记录不符时显示固定失败提示。客户端、文案、按钮可用性和系统图标接口的调用时机保持原语义。

## Alternatives considered

按客户端给整个卡片更换 key，可强制丢弃全部局部状态。但这需要改变卡片所在父组件的挂载约定，重新建立整个区域及焦点；现有初始化 effect 已持有这些客户端状态，增加清理即可。

让旧请求的 `finally` 无条件清理 `pending`，能在旧请求结束后恢复按钮。但旧请求可能一直未完成，恢复时机不受新客户端控制，也可能清掉已经开始的新切换，不能采用。

只把整张卡片搬到另一个文件，能直接缩短账号页。但状态、异步守卫与 JSX 仍混在一起，因此卡片与内部状态 hook 分开，沿用已有账号操作层，不新增通用图标操作框架。

## Consequences

这里重置的是共享 React 卡片的客户端状态，原生系统对图标的实际应用结果继续由 `info` 和 `set` 接口提供。异步失败后读取系统状态的既有逻辑继续保留。

新客户端加载后可以继续选择，不再依赖旧请求的结束时机。切换标记多了一条客户端初始化时的清理路径；请求结束时仍只能清理自己所属的代次。

账号页不再持有图标卡片的展示细节和异步生命周期。增加两个内部模块以明确状态与展示的边界；`AppIconClient` 和 `AppIconInfo` 仍由现有账号模型定义，原生宿主的图标实现与设置页归属不变。

## Verification

`app-icon-client-generation.test.tsx` 使用真实 `AccountPage` 的图标卡片和可控接口结果。普通及 StrictMode 中，在旧切换未完成时更换客户端并继续选择；StrictMode 中再覆盖旧结果迟到成功和失败，确认新切换仍禁用、显示「更换中」且没有旧错误，新结果完成后恢复选择。

旧切换标记问题的四条回归在修复前全部失败：新客户端读完状态，图标按钮仍禁用。组件抽取前后，账号页、图标代次、共享操作及图标复用回归四个文件共 92 项通过。补充用例覆盖首次读取失败及客户端替换、切换返回不匹配、切换与重读均失败后的重试，以及旧客户端重读的迟到成功和失败。抽取边界检查在旧账号页上因缺少独立卡片接入而失败，迁移后通过。使用固定图标标识和合成接口结果，验证层级为共享 React/jsdom。

前端类型检查与生产构建、改动文件 lint 和格式检查、`pnpm run verify-notes`、`git diff --check` 和 `bash scripts/verify-local.sh --quick` 通过。
