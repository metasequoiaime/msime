# Agent Note: 图标客户端更换时清理旧切换标记

Status: implemented

## Problem

`AppIconSettingsCard` 用 `pending` 标记正在切换的图标，并据此禁用所有选择。图标客户端更换时，共享操作层解除忙碌、作废旧结果，卡片重新加载图标状态，却保留旧 `pending`。旧请求的 `finally` 因代次失效不会清理它，导致新客户端加载完后仍显示「更换中」，所有图标按钮一直禁用。

## Decision

在卡片现有的客户端初始化 effect 中把 `pending` 清为 `null`，与图标信息及错误提示一起交给新客户端重新建立。旧请求结果和收尾仍使用代次保护，不能覆盖新客户端已经开始的切换。

## Alternatives considered

按客户端给整个卡片更换 key，可强制丢弃全部局部状态。但这需要改变卡片所在父组件的挂载约定，重新建立整个区域及焦点；现有初始化 effect 已持有这些客户端状态，增加清理即可。

让旧请求的 `finally` 无条件清理 `pending`，能在旧请求结束后恢复按钮。但旧请求可能一直未完成，恢复时机不受新客户端控制，也可能清掉已经开始的新切换，不能采用。

## Consequences

这里重置的是共享 React 卡片的客户端状态，原生系统对图标的实际应用结果继续由 `info` 和 `set` 接口提供。异步失败后读取系统状态的既有逻辑继续保留。

新客户端加载后可以继续选择，不再依赖旧请求的结束时机。切换标记多了一条客户端初始化时的清理路径；请求结束时仍只能清理自己所属的代次。

## Verification

`app-icon-client-generation.test.tsx` 使用真实 `AccountPage` 的图标卡片和可控接口结果。普通及 StrictMode 中，在旧切换未完成时更换客户端并继续选择；StrictMode 中再覆盖旧结果迟到成功和失败，确认新切换仍禁用、显示「更换中」且没有旧错误，新结果完成后恢复选择。

旧实现四条全部失败：新客户端读完状态，图标按钮仍禁用。修复后四条通过；与已有账号页、共享操作及图标复用回归一起运行，四个文件共 77 项通过。使用固定图标标识和合成接口结果，验证层级为共享 React/jsdom。

前端类型检查与生产构建、改动文件 lint 和格式检查、`pnpm run verify-notes`、`git diff --check` 和 `bash scripts/verify-local.sh --quick` 通过。
