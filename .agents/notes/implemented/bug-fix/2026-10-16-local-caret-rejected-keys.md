# Agent Note: 快捷模式在光标处拒绝按键时先提交原文

Status: implemented

## Problem

#8043 已要求普通快捷模式不接受的字符先提交所见原文，再交还当前键。末尾输入遵守这条规则，光标在组字内部时却先进入 `insert_at_caret`，拒绝后只返回未处理且保留组字。真实运行时回归中，`U0041` 移到开头后按 `g` 没有提交原文；`Eab` 同样移到开头后按字符 `1`，runtime 将拒绝的数字解释为候选选择，消费了原应交还应用的键。

## Decision

普通快捷模式的光标拒绝路径复用既有 `commit_raw`，返回提交原文且 `handled = false`。合法字符、相邻撇号的专门处理、临时英文、临时日文、网址与专用英文各自的拒绝规则保留。将 `commit_raw` 的可见范围扩到 session 的兄弟模块，复用清空状态和提交上下文的既有实现。

## Historical note audit

- [末尾快捷模式拒绝键](../../implemented/bug-fix/2026-10-15-local-mode-rejected-key-passthrough.md)持有原文提交和透传规则，部分重叠，扩展到光标入口。
- [日期时间光标字母](../../implemented/bug-fix/2026-10-16-date-time-caret-letters.md)的合法字符规则保留；本决定取代其“拒绝后不改组合”的部分。
- [表达式光标单位](../../implemented/bug-fix/2026-10-16-expression-caret-unit-letter.md)与[翻译命令光标分词](../../implemented/bug-fix/2026-10-16-command-caret-separator.md)继续持有语法及长度上限，本篇取代其字符拒绝后保留组字的后置行为。
- 专用英文光标拒绝消费键的规则、光标代次和候选身份均不变；相关笔记不需要接管本决定。

## Alternatives considered

- **继续保留组字，只透传拒绝键。** 保留编辑机会，已有日期时间、表达式和翻译光标测试也这样断言；但 runtime 继续把未处理数字当选词键，两层语义不一致。普通快捷模式也已有提交原文后透传的统一规则，光标位置不应改变拒绝键的去向。
- **在 runtime 按本地模式禁止数字回退。** 能阻止误选候选，改动集中在宿主编排；但直接调用 Session 的其他宿主仍得到不一致的末尾与光标结果，且 runtime 必须再次复制引擎的拒绝策略。

## Verification

- 新增引擎回归在旧代码中因 `U0041` 没有提交失败；真实 runtime 回归也确认 Unicode 缺提交，以及 `Eab` 拒绝数字后错误消费按键。修复后两项回归通过。
- 全引擎首轮暴露的八项光标拒绝控制仍断言旧组字保留；按新规则验证原文提交和退出，并在测试合法插入或候选选择前重新建立组字。合法字符、容量限制和候选结果断言继续保留。
- 两次默认并行全测在九键 `dominated_projection_matches_frozen_refresh_across_grids_and_locks` 的分配预算断言失败，状态与容量对照未报错；该项三次独立运行通过，完整串行引擎为 2223 通过、37 忽略。逐字换回修复前的四个源码文件，以同命令运行基线也通过；这不能证明失败原已存在。字典查询批次按 20 ms 重开读事务可能受调度影响，尚未证实根因；后续单独调查，不放宽预算或新增已知失败。
- 修复后的最终默认并行完整测试通过：引擎 2223、golden 31、runtime 307，另有 37 个引擎忽略项；Clippy `-D warnings`、格式、笔记校验和本地 quick 通过。独立只读审查未发现实现问题，并要求公开保留上述偶发失败的验证缺口。最终通过不能证明偶发问题已解决。

## Consequences

普通快捷模式不再因光标位置改变拒绝键的提交与透传语义，runtime 也不会把该数字解释为候选选择。代价是日期时间、表达式、命令等模式在光标处遇到非法字符后结束当前组字，失去原来的继续编辑机会；需要重新进入模式。容量和接受字符集没有扩大。

接受判断之后的通用相邻撇号去重继续保留；表达式因已有单位分隔符而明确拒绝第二个撇号时，采用与末尾相同的提交并退出规则。临时模式、网址、专用英文、普通方案和显式标点入口各自维持原规则。自动化使用合成词库和真实共享会话，不代替系统编辑器验收。


## Allocation investigation follow-up

[九键分配隔离](../testing/2026-10-17-nine-key-allocation-isolation.md)通过受控 `close_cached_journals` 在两臂之间推进全局 generation，使预算稳定失败为 `144>136`；均匀暂停和单侧查询暂停没有支持上文 20 ms 事务续期的假设。该机制足以导致预算失败，但没有捕获上文两次历史失败的精确时序。两个原预算测试以单目标子进程隔离其他测试的全局失效，原断言保留。
