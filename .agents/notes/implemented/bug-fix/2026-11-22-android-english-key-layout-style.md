# Agent Note: Android 英文模式沿用中文 26 键布局样式

Status: implemented

## Problem

Android 26 键按键布局样式原本只在中文模式读取 `touch_twenty_six_key_style`。中文输入方案切到英文模式后，`TouchKeyStyle.Styles.forLayout` 把底行强制回退为标准样式。报告者在 Android 0.8.3 上确认，标准、逗号句号、长空格和表情键四种设置在中文模式生效，在英文模式不生效。

## Decision

`TouchKeyStyle.Styles.forLayout` 对标准 26 键按输入方案判断是否属于中文方案，并在中文方案的英文模式中继续读取 26 键样式。韩文、日文、越南语、藏文等独立语言仍使用标准底行，14/18 键和九键继续读取各自样式。英文模式只改变键面文字和输入行为，不再改变用户选择的 26 键底行布局。

回归测试覆盖中文方案英文模式读取表情键和长空格样式，同时保留其他语言回退标准底行的断言。既有的[触屏按键布局样式笔记](../feature/2026-10-27-touch-key-layout-styles.md)曾规定英文 26 键始终为标准底行，这次依据报告者在真实版本中的复测结果翻转该边界，保留原笔记作为历史决定记录并在此说明新的范围。

## Alternatives considered

- 保持英文模式标准底行，只补充文档说明：实现成本最低，但无法满足报告者确认的四种设置在英文模式失效的问题。
- 让所有 26 键语言都读取 `touch_twenty_six_key_style`：会把中文 26 键的设置扩展到韩文、日文和其他独立语言，改变未报告键面的既有行为，因此不采用。

## Consequences

英文模式切换时，中文方案的 26 键底行会继续保持用户选定的样式，表情键、长空格和标点键的布局与中文模式一致，英文键面只替换标点文字。独立语言键盘不受影响。长空格样式在中英文切换时继续保留工具栏行，键盘高度不会因样式查询改变而跳动。

验证使用 Android JVM `TouchKeyStyleSmoke` 和 Android 12 实机。实机在中文方案选择表情键后切到英文模式，改前旧包显示标准的「符」与「123」底行，改后包显示表情键底行。没有修改默认样式或共享偏好字段。
