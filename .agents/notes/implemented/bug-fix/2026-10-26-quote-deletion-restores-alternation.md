# Agent Note: 删除刚输入的成对引号后恢复交替方向

Status: implemented

## Problem

引擎的中文双引号和单引号使用独立的开闭交替状态。Windows 成对标点宿主在上屏开引号时还会插入闭引号并把光标放在两者之间。用户误按引号后按退格删除它时，文档里的字符消失了，但引擎仍保留下一枚为闭引号的状态；随后重新输入 `"`，就会得到相反方向的引号。Windows 空闲退格原本直接交给应用，Server 不会看到这次编辑。

## Decision

`PunctuationPolicy` 记录最近一次交替引号按键。普通标点、实际字符输入和光标等编辑动作都会结束撤销窗口；空闲 `Backspace` 在没有中间输入时撤销最近一次引号的状态翻转。组字中的退格仍只编辑组字，不触碰这项记录。

Windows TSF 在没有组字时仍把 `MSIME_BACKSPACE` 命令送给 Server，但保持未处理结果，让文档删除继续由宿主完成。成对标点被右半边跨过时，TSF 用现有的 `MSIME_CANCEL` 空闲命令清掉撤销窗口，避免删除已经跨过的闭半边时误撤销开半边。这样 Server 只同步状态，不代替应用修改文本；其他宿主已经会把空闲退格送进同一会话命令路径。

## Alternatives considered

- **每次退格都强制把双引号设为开引号**。最强理由是实现简单。没有采用：用户可能先输入开引号和正文，再退格正文，下一枚引号本来应当闭合，强制重置会破坏正常交替。
- **只在 Windows 宿主维护引号方向**。最强理由是不改共享引擎。没有采用：引擎仍会在无成对补全、其他 Windows 编辑器或其他宿主路径中保留错误状态，平台之间的标点行为会继续分叉。
- **新增独立 IPC 事件通知“删除了引号”**。最强理由是事件语义明确。没有采用：当前空闲退格命令已经是现有跨宿主会话入口，只需让 Windows 不再绕过它，避免扩展 Windows IPC 契约和旧版本协商。

## Consequences

收益：误删最近输入的引号后，下一次同键会恢复原来的开闭方向；中间输入冒号、字母或移动光标后不会撤销更早的引号，正常成对输入保持不变。Windows 需要为每次空闲退格增加一次本地 Server 命令调用，但命令仍不吞掉退格，也不读取或保存文档内容。

验证：`crates/engine/src/punctuation.rs` 覆盖策略层撤销窗口；`crates/engine/src/session/tests.rs` 覆盖空闲退格、冒号隔断和未处理结果；Windows 成对标点 wiring 测试检查空闲退格调用 `MSIME_BACKSPACE`。已运行引擎定向测试与 Rust 格式检查。
