# Agent Note: 鸿蒙键盘先导入设置偏好再发布快照

Status: implemented

## Problem

鸿蒙设置应用和键盘扩展各有一份偏好，经共享沙箱镜像交换。键盘获得焦点时原来先发布自己上次会话的偏好，再导入设置应用的快照。键盘自己的旧清单因此带着更晚的 `changedMs`，设置应用刚保存的值会被 `SharedStateMirrorPolicy.pending` 判断为较早而跳过；用户看到设置已保存，第一次打开键盘却又回到旧值。

## Decision

`SharedStateSync.keyboardSync` 先导入设置应用的镜像，再在完整体验模式下排空已确认的个人词库并发布键盘当前快照。导入前仍使用双方已有清单判断冲突：键盘确实在上次发布之后改过的偏好保留，设置应用较新的改动进入键盘；导入后的偏好由后续修订号比较触发会话重建。

## Alternatives considered

- **继续先发布，再提高设置应用的 `changedMs`** — 最强的理由是保持已有调用顺序。否掉：发布时无法区分键盘真正的新改动和上次会话留下的旧副本，单独调时间会把真实冲突也掩盖掉。
- **在导入时无条件覆盖键盘偏好** — 最强的理由是能保证设置应用的修改立即生效。否掉：键盘在失焦期间保存的真实修改会被静默丢掉，违背共享镜像按变化时间解决冲突的契约。

## Consequences

- 设置应用刚保存的偏好会在键盘第一次获得焦点时先进入键盘，不再被旧快照遮住。
- 键盘自己较新的偏好仍可按已有双方清单和 `changedMs` 规则保留；发布动作改为在导入后进行，减少一轮错误的旧快照传播。
- `keyboardSync` 的发布顺序成为跨进程同步契约，测试脚本钉住导入调用必须位于键盘发布之前。
