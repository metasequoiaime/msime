# Agent Note: Android 按键音效缓存绑定来源目录

Status: implemented

## Problem

`ImeKeyFeedback` 原先只按 `plugins.key_sound.pack` 的 ID 判断缓存是否可复用。运行时切换偏好目录会改变 `preferencesDirectory`，同一音效包 ID 可能由新目录提供不同样本，但旧 `SoundPool` 仍会被保留；加载期间播放路径也只比较 ID，因此会继续播放旧会话的音效。

## Decision

按键音效缓存身份同时包含包 ID 和解析请求使用的状态目录。`PackSounds` 保存来源目录，偏好刷新时计算当前来源；只有包 ID 与来源都相同才复用或播放。刷新快路径也比较来源，不能仅凭偏好对象和本地设置对象相同就跳过。

每次加载持有独立请求身份，切换包、切换来源或服务销毁时作废旧身份。这样先选 A、开始加载 B、再选回已缓存 A 时，迟到的 B 不会替换 A；即使 A→B→A 的最后一次重新发起加载，最早一次 A 也不能冒充新的 A 请求。旧结果在回调里释放自己的 `SoundPool`，不改当前缓存和加载状态。

## Alternatives considered

- 只在输入会话切换时清空 `SoundPool`：可以避免复用旧样本，但会让同一目录的会话无谓地重新加载，而且仍需处理切换期间迟到的回调。
- 只比较音效包 ID 的文件修改时间：状态目录不同或两个包同时使用相同时间戳时仍可能误认，不能表达请求实际解析的来源。

## Consequences

切换到不同偏好目录时，加载完成前按键音回落到系统音效；新包加载后再使用 `SoundPool`。同一目录和包 ID 的会话继续复用现有缓存。纯 JVM 策略冒烟覆盖同包同目录、换目录、换包、缺失状态和缺失来源。`scripts/test-android-key-sound-lifecycle.py` 编译并执行完整 `ImeKeyFeedback` 产品源码，只替换 Android 音频、调度与界面依赖：验证仅换目录且复用同一偏好对象、保留缓存的 A→B→A、重新请求的 A→B→A、同来源复用及销毁期间迟到回调的释放。该测试分别在快路径漏比目录和旧请求只比包 ID／目录时复现失败；策略测试本身不能证明宿主调用点正确。
