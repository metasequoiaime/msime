# Agent Note: Android 角标不能挤掉主字母区域

Status: implemented

## Problem

Android 0.8.0、0.8.1 在 vivo X300 上三排主字母消失，角标、图标与底行正常，切换内置皮肤仍复现。0.8.1 的[显式居中修复](2026-11-17-android-vivo-keycap-gravity.md)未解决此问题，原笔记把尚未验证的厂商 gravity 推测写成根因，这个结论撤回。

使用 0.8.1 正式发布包的 Java、资源与原生库，在 API 28 模拟器设置 1080×2400、560 dpi、字体缩放 1.45、全拼 26 键，复现三排字母全空、角标与底行正常。`KeyHintButton` 给角标增加的右边距没有检查剩余区域是否容得下主字母，窄屏下主标签宽度归零。主字母走 `TextView` 排版裁切，角标单独绘制，所以只有主标签消失。

真实工厂先设 14sp、开启角标、再设 22sp；Android 自动字号开启后忽略 `setTextSize`，恢复字号也会回到旧的 14sp。原键面测试反过来先设 22sp 再开提示，只断言还有主文字像素，无法证明完整显示，也漏掉真实创建顺序。

历史检索：[九键双拼收简键面](../feature/2026-10-13-android-shuangpin-compact-keyfaces.md)与[平板分离键区](2026-10-26-android-tablet-split-width.md)部分重叠，继续保留底部提示、宽键横向错开与同组字号一致的约束；居中笔记保留独立对齐约束并互链纠正根因。

## Decision

角标横向留白必须仍容得下整组主字母的最大宽度，否则恢复基础左右边距、使用上下分区。计算上方留白时扣除主字形在排版行里的固有空白，避免重复预留导致紧凑键帽字号过小。首次测量前先按可用宽高和同组字体度量应用可容纳的字号上界，再交给框架自动字号，零尺寸探测不永久侵占主标签区域。

`KeyHintButton.setTextSize` 在提示已开启时更新未缩放字号，再重算提示区域；关闭最后一个提示时清空缓存并通过父类恢复后来指定的字号，不递归进入提示计算。

设备回归按真实工厂顺序构造 `ShuangpinHintButton`，覆盖 24/28/34/62dp 宽、40/52/84dp 高、1/1.45/2 倍字体，先探测零宽度再重测，检查排版宽度非零、整行字形不超宽、主字母可辨认且有实际像素，以及关闭角标恢复 22sp。原有低键高、双拼底部提示、九键、统一字号与基线断言继续执行，不修改原测试前置条件。

## Alternatives considered

- 仅显式设置 `Gravity.CENTER`：能统一 OEM 默认对齐，但正式包复现与用户反馈都证明对齐无法恢复已归零的文字区域；保留对齐约束，不再把它解释成根因。
- 始终向右增加角标内边距：低键高下有利于横向避让，但窄键会失去主字母区域，因此只有确实放得下整组字母时才使用。
- 改为自绘主字母：能绕开系统排版，但会额外复制文字状态、字体与无障碍行为。当前问题能通过可验证的区域预算修正，继续使用原生 `TextView`。

## Consequences

窄屏、大字体和显示缩放不再让角标占光主字母区域；宽键、紧凑键帽和提示开关仍遵循原来的同组字体契约。窄键可能采用上下错开，主字母位置和受限字号会随实际区域调整。不改变皮肤颜色、用户出厂设置、按键输入或无障碍标签。

- 与[键面由模板与键组排版](../architecture/2026-11-18-android-key-face-groups.md)部分取代关系：26/14/18 键字母层的字母键改由键组排版、由键自己绘制，不再走本篇的内边距与自动字号规则；分词键、句号、常用标点、九键数字键和文本编辑面板的角标键仍走本篇的规则。
