# Agent Note: 词库集合容纳三万行导入

Status: implemented

## Problem

#8643 的公开脱敏附件有 33555 行，第三列数值范围 0–7622。现有集合容量 20000 会截断，前一轮批量事务的三万词测量因此只能写入两万词。容量是已确认的独立缺口；权重分布不能据此归因为超大值，吞吐目标仍需另外测量。

## Decision

单集合条数上限扩为 50000，覆盖报告规模且保留明确边界；文本输入 16 MiB、单集合文件 48 MiB、outbox 96 MiB 和最多 32 个集合的限制不变。个人词库活动队列仍为 128 项，不扩大引擎维护锁的一批持有时间。备份恢复的 `MAX_QUEUED_WORDS` 是单次提交的分块限制，继续为 20000，不把它与集合容量混为一谈。

回归使用 33555 条合成 Rime 词，在禁用集合中导入后重新加载，核对计数、尾部身份及未截断；不提交或在日志打印附件词条。现有容量边界回归继续核对满集合拒绝新增、重复不占容量及超限导入报告。

## Historical audit

- [有界批量事务](../../implemented/bug-fix/2026-10-18-personal-dictionary-batches.md)部分重叠：它显式保留两万容量，本篇只补这个缺口；事务、回执和权重保护继续成立。
- [导入后立即应用](../../implemented/bug-fix/2026-10-17-android-import-apply-before-success.md)部分重叠：继续保留两秒预算和空闲推进，不因容量增加阻塞输入启动。
- [本地备份](../../implemented/feature/2026-10-08-android-local-backup.md)无关：恢复分块继续保持原大小。
- 其余精确上限检索命中为引擎候选缓冲与测试夹具，无关。

## Alternatives considered

- **自动拆成多个集合**：单文件及老版本容量不变；但会把一个导入变成多个独立启停/删除对象，集合重名和失败回滚也需新语义。
- **取消条数限制只按字节限制**：更灵活；但条目身份、队列索引及全量集合读取的内存成本也必须有界。
- **扩大至十万或更多**：能接受更大词库；但当前实现每轮刷新还会读取全部集合，先覆盖已知报告规模，避免以更大常量掩盖大集合开销。

## Verification

宿主 services 单测 1198 项通过、1 项忽略；host-api 的 8 MiB 细胞词库容量回归通过，断言使用共享集合上限而非旧的 20000。两包全部 targets 的严格 Clippy 通过。

API 28、35 专用 AVD 均在默认 shell 身份下运行 client-base/core/providers/services 整套单测，分别为 36、419、224、1151 项通过；硬链接等平台不支持用例沿用既有跳过规则。33555 条合成 Rime 导入、重载尾部和 50000 容量边界在设备执行通过。顺带修正[图库夹具定位](../testing/2026-10-19-candidate-skin-gallery-fixtures.md)，13 项真实图库测试在两设备执行通过，没有扩大跳过范围。

API 28、35 均安装含本次原生库的 arm64 APK，从 `DictionaryCollectionsStore.importFile` 导入 33555 行合成 Rime 词，报告未截断且无失败；经 JNI 重新加载集合，再核对磁盘计数及末行的编码、内容和权重。原有 74 词全部应用、第六词进入九键候选、活跃会话的繁忙队列保留及关闭后的重试仍通过。普通容量阶段验证完整导入及落盘重载；显式传入 `measure_capacity=true` 时继续同步到全部写入，并核对 SQLite 总数。两 API 的显式完整写入测量分别为 48522 / 48471 ms、233 轮、最慢同步 415 / 441 ms，均实际应用 33555 词。这是同机并行运行的模拟器、空合成主库与原生 release APK 测量（构建日志确认 Rust `release` 优化），不代表真实手机，也未达到每秒万行。

macOS 调试构建、空合成主库加索引、33555 词实际全部导入并写入引擎的显式测量：263 轮、70266 ms，最慢同步 129 ms。10 秒进程采样的大量调用落在集合 `read_state` 和 `write_outbox`，证明仍有全量集合/待发文件的重复工作；这是调试构建及副盘上的单次测量，不能外推为手机或发布版吞吐，也没有达到每秒万行。首次测量的 `collections_io` 来自远端系统盘耗尽，未产生吞吐结果；改用副盘的测试临时目录后才完成上述测量。

最终源码 quick（`20261019-205242`）和格式检查通过：Rust 工作区、Android/WebAssembly 目标、Java 宿主、Linux 设置壳与原生 90 项、macOS 原生编译和 Apple bridge 均通过。Windows 本机可运行 169 项通过；MinGW/pipe 与 HarmonyOS 原生打包因缺工具或暂存环境跳过，不计通过。笔记在本机另行验证。

## Consequences

集合全量读取的时间和内存上限增大；旧版本仍会拒绝超过其两万上限的集合，降级前需导出并拆分。这一容量修复不宣称达到每秒万行，也不代替权重排序验证，PR 使用 `Refs #8643`。
