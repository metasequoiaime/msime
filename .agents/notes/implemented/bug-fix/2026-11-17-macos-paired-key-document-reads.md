# Agent Note: macOS 普通字母不为成对标点查询文档

Status: implemented

## Problem

#11517 报告 macOS 全拼输入偶发卡顿、候选延迟及输入顺序交换。调查中确认一个独立的同步调用开销：已经补进文档的右标点尚未跨过时，普通字母也先调用 `MSIMETextClientFollowingCharacter`，向应用查询选区和后一个字。这两次往返不能让普通字母跨过右标点。合成原生客户端探针测得单个普通字母新增两次文档读取，未证明它是报告中顺序交换的原因。

## Decision

直接跨过字面右标点的分支先用本机 tracker 栈顶判断这个键是否可能跨过，匹配后才读取应用文档。跨过之前仍核对真实文档字符，不缓存选区或文档内容；普通字母继续原样交给会话。经过中文标点、样式或全角转换的按键仍走原有转换与跨过分支。

行为回归在真实控制器和合成客户端中连续发送 100 个普通字母：文档读取计数不增加，会话字符调用增加 100；随后沿用原有右标点跨过、组字、全角及失败断言。只减少确定无用的调用，不把这个切片说成完整解决 #11517。

## Historical audit

- [标点字形样式](../../implemented/feature/2026-10-13-punctuation-mark-styles.md)：部分重叠，持有标点映射与跨过规则；本次保留这些规则，只提前筛选字面跨过分支。
- [大括号固定直角括号](../../implemented/feature/2026-10-29-brace-keys-fixed-corner-brackets.md)：部分重叠，保留专用英文、全角和中文直角括号的分流。
- [macOS 上屏重入保护](../../implemented/bug-fix/2026-10-23-macos-reentrant-text-client-commit.md)：部分重叠，减少同步调用机会，但不改变重入代次或排队策略，也不据此宣称输入顺序交换已修复。

## Alternatives considered

- 缓存光标后的字符：能够进一步减少查询，但应用、鼠标或其他输入源可以改变文档，缓存会让跨过判断失效，不能拿旧文档决定新写入。
- 只要 tracker 不空就继续读取：当前实现能及时观察文档变化，但普通字母无论读回什么都不能跨过，真正的右标点到达时仍会重新核对文档，没有必要为普通字母付出同步往返。

## Verification

- 同源 Rust host（启用 `onnx-rerank`）与 CMake 原生目标构建通过；`shortcut`、`shortcut-nested-commit`、`shortcut-english-punctuation`、`text-client`、`text-client-reentrancy`、`paired-punctuation` 六项 CTest 通过（43.53 秒），包含新增的 100 字母回归及原有标点跨过断言。
- 控制构建只将产品的筛选条件换回旧条件，保留同一组 100 次输入和计数判断；为避免断言崩溃，夹具将同一判断改为失败退出。结果文档读取 200 次、会话收字母 100 次、退出 1；修复后正式回归断言文档读取增加 0 次、会话收字母 100 次。证明减少查询，没有修改输入、默认设置或旧回归前置。
- 只运行替身与原生单测，没有启动系统输入法、安装或操作设备。

## Consequences

本切片只证明减少跨进程查询，不量化报告者应用中的延迟，也没有复现报告中的 `ab` 变成 `ba`。不修改现有设置默认值，不增加设置入口。
