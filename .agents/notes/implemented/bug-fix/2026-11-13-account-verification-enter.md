# Agent Note: 验证码登录支持回车提交

Status: implemented

## Problem

桌面账号页和触屏登录面板的验证码输入框虽然只接受 6 位数字，但按下 Enter 不会触发登录。用户输入错误验证码后也需要重新操作鼠标，无法在当前登录面板里快速重试。

## Decision

验证码输入框在收到非输入法组字状态的 Enter 时，只有验证码完整、挑战未过期且当前操作未忙时才提交登录；提交会阻止浏览器默认行为，避免重复触发。输入法仍处于组字状态（`isComposingKeyEvent`）时保留事件，不提交，避免拦截输入法确认键。桌面页和 HarmonyOS 触屏面板复用同一控件，因此两处行为一致。

登录失败不清除挑战或验证码输入状态，继续沿用现有错误处理，让用户可以修改验证码后再次按 Enter 或点击登录。

## Alternatives considered

- **把控件改成原生 `<form>` 并依赖默认提交。** 语义更标准，但共享按钮组件固定渲染 `type="button"`，还需要改变请求验证码按钮和两个宿主布局的提交边界，容易把发送验证码误当成登录提交，因此不采用。
- **在账号页和登录面板各自监听键盘事件。** 能快速覆盖两个界面，但会复制组字判断和有效性条件，后续两端容易产生差异，因此不采用。

## Consequences

验证码登录可用键盘直接提交，完整验证码、过期和忙状态仍由现有禁用条件与共享 hook 校验；组字确认键不会被抢走。新增回归测试覆盖普通 Enter 会提交、IME 组字 Enter 不提交。
