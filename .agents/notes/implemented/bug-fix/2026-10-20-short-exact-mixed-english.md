# Agent Note: 短英文完整匹配保留可选候选

Status: implemented

## Problem

#8938 报告中文模式下缺少常见短英文。桌面固定 `mixed_input.minimum_prefix = 5`，共享混排入口在查词前就跳过不足五个字母的所有英文，因此完整单词也不可选择。原门槛用于防止短英文抢占中文简拼首位，不能靠全局调低来修。

## Decision

26 键的全拼、双拼混排在达到配置门槛时保留补全和首选规则。低于门槛、至少两个小写 ASCII 字母的输入，只查询字典中的完整匹配，取最高权重的一个显示形式，放入既有英文优先座位；有中文候选时不得因音节拆不开而领先。不做短前缀补全，不改变开关、宿主门槛和词频尺度。

## Historical audit

检索 `minimum_prefix`、短英文、中英混输和英文首选。部分修订[英文领先规则](../../implemented/feature/2026-10-12-mixed-english-leads-unsegmentable-input.md)：其五字符领先门槛、完整音节判定与个人固定位置继续保留，只让短词作为候选出现。九键的空列表英文回退与本次 26 键混排入口独立；字典英文纠错与大小写候选不变。

## Alternatives considered

- **把默认门槛降到两个字母**：直接恢复短词，但同时放开补全和领先，常见简拼会被缩写抢占首位，与原决策防范的问题相同。
- **用短前缀查询后丢弃补全**：可以少加一个查询方法，但索引范围里所有长词仍需排序，常见两字母前缀的开销不必要；完整键查找更小也更明确。

## Verification

合成词库回归在旧实现上稳定失败，修复后全拼和双拼的短完整词可选、中文保持首位，短前缀和单字母不新增补全，关闭开关后不混入。重复查询、选择完整提交和长词既有领先均覆盖。

英文初始化现在可能发生在短词查询；既有「不分配无用表情路径」回归先初始化英文库，再独立测量混排阶段，零分配阈值保持原值。

`english_minimum_prefix` 的 golden 只在 `ni` 步新增第二位的完整 `Ni`，不混入 `Ninja`、`Nimbus`；后续达到门槛的 `nin` 补全保持原样。其余 299 项脚本场景未改。

2371 项引擎单测、31 项 golden 基准及全目标 clippy 通过，49 项手动性能测试按原规则忽略。固定真实词库经 Host API 对照使用独立的合成 `home`、`cat`、`bus`、`cd`：旧版均无英文，新版均保持中文首选、短英文随后；各重复两次完整提交，无诊断。共享设置页 TypeScript 检查及生产构建通过。

提交前 quick `20261020-202108` 以 0 退出，耗时 15 分 55 秒：共享 Rust、Android 目标与 Java、WASM、HarmonyOS 设置页、Linux 设置壳、Linux 原生 93 项及 macOS 宿主和 Apple 桥接编译通过。Windows 原生与交叉工具链、pipe 工程及 HarmonyOS HAP 依赖未配置，按现有规则跳过。本机格式、笔记与差异检查通过；构建在远端编译机完成。

## Consequences

短词候选会改变第一页的非首选位置；一个完整拼写有多种显示时只提供权重最高的一种。增加的查询复用现有只读 SQLite 连接与索引，不改变文件路径、打开方式、权限或存储格式。设备界面验收与共享接口验证分别报告。
