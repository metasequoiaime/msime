# Agent Note: 全拼纠错候选按原始按键推进

Status: implemented

## Problem

全拼候选的 `pinyin` 是纠正后的读音，长度可能与用户键入的字母不同。提交时只按该读音长度推进组字，键入重复字母的整句即使有完整纠错候选，上屏后也会残留尾字母。候选回答全部按键的判断、进入改字的判断和实际提交各走同一组字完成条件，因此不能只修提交后的残留。

## Decision

全拼纠错候选用 `corrected_from` 的长度表示已回答的原始字母数；普通候选仍用去掉分隔符的 `pinyin` 长度。候选完整性判断和部分组字推进共用这一规则。提交专用的候选副本保留 `corrected_from`；改字提交保留原候选的纠错来源，让改好的整句消费原始按键。双拼、原生五笔以及日语和韩语继续使用各自已有的完成与推进规则。

## Alternatives considered

- **只在提交后清空尾字母**：改动局部，但候选会先被错误地判为未回答全部按键，改字入口和上屏路径仍不一致。
- **按纠正后拼音长度统一切原文**：保持旧路径简单，但插入或删除字母的纠错会继续留下尾字母或多消费输入。
- **把所有候选的 `corrected_from` 当成显示元数据丢掉**：普通候选少一次可选克隆，但纠错候选的原始消费长度随之丢失；字段筛选的原有决定见[候选提交跳过无用行元数据](../testing/2026-10-10-selection-row-metadata-borrow.md)。

## Verification

合成词库中重复输入一个字母，分别直接选择纠错整句，以及进入改字后提交。两条回归都检查候选完整性或改字入口、上屏文本和清空的组字文本；旧实现在两条路径留下尾字母。完整 engine 测试、golden 基准、Clippy、笔记校验和本地 quick 门禁作为提交前检查。

## Consequences

纠错候选上屏时按实际键入字母数推进，候选完整性和改字入口与提交结果一致。纠错候选的提交副本多复制一个来源字段；普通候选该字段为空，不产生字符串分配。这里没有扩大纠错搜索或放宽纠错阈值。
