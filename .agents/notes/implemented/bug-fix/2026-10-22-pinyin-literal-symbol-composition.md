# Agent Note: 拼音组字中的特殊符号保留原文候选

Status: implemented

## Problem

#9101 要求输入 `C#`、`Something#` 时，特殊符号与此前内容继续处于组字状态，仅提供当前原文一个候选，由用户空格、回车或选词确认。当前普通拼音拒绝这些符号，runtime 随即结束组字并走标点路径；这会提前提交内容。

## Decision

普通全拼、双拼已有组字时接收 `# $ % &`，存在这些符号后整串只提供原文候选，不继续把小写片段转换中文。以引擎原文作为唯一状态来源，复用现有字面候选的消费、删除和学习隔离；不新增宿主或 wire 枚举。发布可接受的 `spelling_symbols`，让宿主与 runtime 的字符、中文标点和 ASCII 标点路径均可继续组字。

首个大写若已进入快捷模式，尚未输入模式内容时遇到这些符号，同样退回普通字面组字，不把入口字母先提交。已有快捷模式内容保留原语义。逗号、句号继续结束组字；`@` 的现有邮箱入口与补全优先保留，已向用户询问该取舍，当前按保留既有补全继续。

## Historical audit

- [大写字面片段](../../implemented/bug-fix/2026-10-19-uppercase-literal-pinyin-boundaries.md)部分重叠：沿用原文范围、合成候选身份与学习隔离；特殊符号使整段转为字面文本，不按小写片段查询。
- [邮箱与网址补全](../../implemented/feature/2026-10-15-engine-email-url-completions.md)部分重叠：邮箱 `@` 与网址触发符号已有独立产品语义，不用全部 ASCII 标点的宽泛规则覆盖它。
- [快捷模式拒绝键](../../implemented/bug-fix/2026-10-15-local-mode-rejected-key-passthrough.md)部分重叠：只有空大写入口加特殊符号回到字面组字，已输入内容时仍按原文结束和拒绝键规则。

## Alternatives considered

- **宿主截住 `#` 并维护一段临时文字**：局部改动即可改变 macOS 体验；但候选选择、光标编辑和学习身份会与共享引擎分离，其余宿主也要复制状态机。
- **把所有非字母都接进拼音**：分类简单；但逗号、句号需要结束组字，数字选词、双拼分号、邮箱网址与快捷模式都已有独立语义。
- **只让符号留在组字，继续查询符号前的小写拼音**：复用现有分段字面候选；但 issue 明确要求符号进入后只提供原文一个候选。

## Verification

旧实现的共享 runtime 输入 `C#` 返回 `handled = true`、`commit = "C#"` 且组字为空；引擎独立红例同样复现提前提交。修复后共享引擎完整单测 2435 项通过、50 项既有忽略，golden 31 项通过；runtime 359 项通过。真实词库目录未指定，不把对应真实词库评测的内部跳过计作验收。

回归覆盖全拼、双拼的字符及两种标点入口、四个符号、空快捷入口、唯一原文候选、确认上屏、删除符号后恢复中文、内部光标编辑、逗号句号、邮箱网址和已有快捷内容边界。普通 `Something` 用例关闭符号模式的 `S` 入口；已启用且已有内容的模式继续拥有自己的接受和拒绝规则。合成数据不进入中文学习，旧异步中文回包不恢复候选。

ASCII 标点路由原先仅让本地模式或非码表方案继续拼写，普通拼音即使发布 `#` 也会提前结束；现在已有组字且引擎发布该符号时继续交给字符入口，普通拼音的 `/ @ . :` 保留既有 ASCII 标点规则。

macOS 的 `text-client` 使用真实 `MSIMEClientSession`、C ABI 和引擎，经合成文本客户验证两方案、四符号、字符与标点入口、空格与回车共 32 组组合：输入后不提交、只有原文候选、标记文字和光标正确，确认后上屏并清空组字。半角、全角、再半角的空闲人民币符号及组字内 `$` 场景通过；原生全集 167 项全部通过。这是原生会话与文本客户接口验证，尚未安装到系统输入源或在真实编辑器验收。

`host-api` 的货币测试按同一契约检查三条输入路由：空闲时随字宽输出 `¥` / `￥`，已有拼音时保持唯一的 `nihao$` 原文候选，确认后才转为半角或全角上屏；ASCII 标点与 Caps Lock 不提前结束已有组字。两项货币测试通过。算式模式的独立符号预期包含新增的 `#$&`，选择统计测试由此完整执行并通过：生成的算式结果不计数，随后普通候选的第二位选择仍计一次。测试不再要求恢复特殊符号加入前的行为。

格式、两 crate 的全部 targets 严格 Clippy、`pnpm run verify-notes`、`git diff --check` 与最终 quick（`20261022-061810`）通过。quick 实际完成 Rust 工作区、Android/Wasm 目标、Android Java 宿主、Linux 设置壳及原生 108 项测试和 full/wubi 安装暂存检查、macOS 宿主与共享 Apple bridge；Windows 可移植测试 176 项通过、2 项因宿主差异排除、64 项需要 Windows。Windows 完整交叉编译和 HarmonyOS 真打包缺工具环境而跳过，macOS Tauri 设置壳缺 staged bundle 而未检查，不计作验证通过。新增原生测试首轮配置缺少必需字段而失败，补齐合成配置后通过；之前被中止的 quick 不计作门禁通过。

本地与远端受测源码的差异 SHA-256 一致，提交前只补充验证记录；没有修改黄金基准或失败债务清单。

## Consequences

特殊符号进入后保持一行原文，用户可继续编辑或明确确认，删除最后一个符号即可恢复中文解码。代价是含这些符号的文字不参与中文学习或在线拼音查询；已有拼音后输入 `$` 现在继续字面组字，空闲时仍输出人民币符号。`spelling_symbols` 在既有邮箱入口后追加四个符号，多一次小字符串扩容；两处精确分配预算同步增加一，辅助码注释仍不重复构造。首个大写快捷入口仅在没有正文且模式自身不接受该符号时退回普通字面输入，已有 Unicode、算式和符号模式内容继续走原路径。
