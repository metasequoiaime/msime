# Agent Note: 崩溃队列与发送绑定持续授权代次

Status: implemented

## Problem

只有[共享偏好持久代次](2026-10-28-persisted-reporting-consent.md)与观察器换身份，仍不能阻止撤回后旧进程晚写的原生记录进入新队列。发送线程也可能已经取出旧队列，关闭重开之后继续发送旧快照。MetricKit 的历史授权不能只由当前布尔值证明。

## Decision

遥测状态保存本机当前代次，崩溃记录头保存捕获时的代次。激活新代次在队列锁内清理旧事件、会话与记录，保留匿名安装 ID。绑定代次的存储每次取得锁后核对持久状态，不能让旧发送收尾覆盖新队列或退避状态。补录只认当前代次，旧代次和没有可证明归属的旧记录不进入队列，成功持久化后才清理原件。撤回清理移除当前代次，保证旧绑定立即失效且不额外创建安装身份；状态保留 `consent_required`，即使尚无安装 ID 也记住该目录已经接入持久授权，防止漏接的旧入口在清理后重新启用无代次队列。授权代次仅在本机使用，事件的构建元数据、设置导出与诊断配置快照均不上传它；脱敏快照移除该字段而不改变原偏好。诊断包识别有效的版本化原生头，剥离本机归属后使用下一行真正的故障摘要；无效头拒绝导出，NDJSON 与原始崩溃文件共用该规则。

偏好锁先于队列锁。Host API 的授权准备、开始与系统诊断补录在同一偏好锁内验证代次并做本地操作；普通崩溃回调沿用预备记录头，不读偏好。每条网络发送前重新核对授权，释放偏好锁后才发请求。已经交给网络的请求无法撤回，但阻塞请求之后不得继续发送旧快照，撤回本身不能等网络。

iOS 观察器使用持久代次与起点，临时读失败仅解除武装，同代次恢复可复用身份，代次变化必须丢弃旧身份。MetricKit 按批次起点与当前代次认领，不能由旧 UserDefaults 历史扩大授权。所有入口仍保留默认上报值和现有独立采集的会话语义。

共用 `CaptureOnly` 观察器也使用共享持久授权。Windows 看门狗与准备程序、Linux 原生和 Python 辅助入口、macOS 语音 helper 的正常准备按 `preferences_directory` 与 `consent_epoch` 原子核验，不再把缓存布尔值交给 begin。即使两次观察之间关闭重开，也重新准备头与队列；旧进程晚写由绑定同代次的收集器拒绝。临时不可读只解除武装，保存快照以便同代次恢复；明确关闭丢弃快照，并在共享偏好锁内条件清理，不能删除已经重开的新队列。首次确保授权会在既有偏好目录持久化文档，不抢先创建准备程序尚未建立的状态目录；原来的默认值不变。同目录的输入会话宿主、桌面设置发送端与 MCP 同时迁入这一协议，不能让绑定辅助采集器与未绑定主宿主混用。

MCP 与桌面设置/面板也直接使用共享 Rust 偏好与队列 API，不绕过一层 JSON FFI。MCP 沿用实际配置目录和嵌入配置中尚未持久化的明确关闭，不能因默认值而重新开启。两者保存实际授权代次与捕获快照；两次观察之间关闭重开也换身份，读取失败只停采，同代次恢复沿用身份，明确关闭在偏好锁内条件清理。MCP 只落盘，不创建输入会话、不发送网络。桌面端在同一偏好锁内验证代次并准备当前队列，每条发送前再次核对，网络期间不持锁；Linux 设置补收 Fcitx5 时使用同一授权，旧工作线程不得激活过时代次。桌面发送间隔保持三十分钟，同代次读失败恢复不提前触发新发送，换代重新计时。

共用 `Telemetry` 输入会话包装器为 Windows Server、IBus、Fcitx5 与 Win7 设置/面板读取实际持久偏好，准备、发送和旧原生记录补收绑定同一代次。显式布尔参数仅保留无偏好目录调用方的兼容协议；产品提供偏好目录后不再相信迟到回调的布尔值。独立 `ConsentObserver` 每 500 ms 在正常路径核对，网络请求不持本地生命周期锁；真实 begin 返回与同代次暂停恢复之后、重新武装之前再次读取持久授权，迟到的准备不能恢复已撤回或换代的旧头；坏配置只停采，同代次恢复复用会话，关闭重开换身份。旧网络请求的关闭响应不直接停采，而是重新读取当前持久授权；已停止的配置不能由网络收尾重新开始。观察器析构先通知并等待自己的线程，再结束本次会话，不等待网络。Fcitx5 的启动任务与停止操作另用一把生命周期锁串行，停止后迟到的启动不得重新 begin；插件原有工作跟踪器仍等待全部脱离任务后才允许卸载。macOS 输入法与现代 Windows 原生设置在本轮共同授权补修中迁入，Android 与 HarmonyOS 仍单独跟踪。

公开隐私说明同步列出本机代次的存储、不上传、旧记录首次迁入时的丢弃、在途请求无法撤回，以及 iOS、三种桌面输入宿主、桌面设置与面板、MCP 和共用辅助采集器已接入、Android 与 HarmonyOS 宿主仍待接入的边界；iOS 信号帧说明改为实际保存的模块相对偏移与 UUID。

正常路径的授权适配下沉到 `client-services::telemetry`，C ABI、Tauri 与 MCP 共用 `with_consent_epoch`、条件清理和逐条核验发送器。Host API 的 macOS、Windows 与 Linux 请求收到真实 `preferences_directory` 且没有显式代次时，先确保当前持久同意再原子绑定；显式旧代次仍拒绝，不自动追认为新授权。Windows Server 不再传缓存布尔值，使用自身真实状态目录；MCP 在已有持久修订时以真实偏好为准；首次保存前仍保留旧运行配置中显式关闭的兼容语义，不生成授权，也不凭内联快照清除已绑定队列。已经绑定过的目录拒绝无绑定的准备、输入会话开始、收集、发送、无条件清理与按最后标记结束，作为后续漏接保护；按已知 UUID 结束本进程会话仍保留，故障现场仍允许旧快照晚写，由绑定收集器过滤。

原生桌面授权观察不等待网络：macOS 使用串行本地观察队列与独立发送队列，Windows 设置使用可停止的生命周期观察线程，Fcitx5 插件使用可停止的 `ConsentObserver`，启动与停止由独立生命周期锁串行，不添加卸载后仍运行的 detached 观察线程。共用输入宿主在本地刷新时比较持久代次，同为 true 的偏好发布也不能跳过；读失败暂停且保留同代次身份。Tauri 沿用既有偏好观察器，MCP 沿用可停止观察线程，两者均按真实偏好目录与代次恢复或替换预备头。自动兼容适配只用于三种桌面平台，不把 Android 与 HarmonyOS 的尚未迁移生命周期隐式绑定；回归保留它们既有的无代次准备和清理。不修改任何平台的出厂默认。

Linux 两条设备外子进程夹具也按真实来源收集：配置重定向后传入重定向的偏好目录；在线 provider 启动器使用 XDG 配置目录时，收集器使用同一个目录，而不是测试准备文档的另一份副本。复制偏好文档不能证明两个目录后续生成的持久授权相同。

IBus 启动投递夹具也必须提供真实共享授权：原夹具只写内联空偏好、没有 `preferences_directory`，宿主迁入持久授权后正确停采，Debian 与 Fedora 均停在「排队事件未发送」；不能恢复无绑定入口来让测试通过。夹具明确开启独立共享偏好，由真实宿主首次启动生成代次，重启不覆盖偏好文件。恢复正例先运行真实宿主并触发 SIGSEGV，再在同一目录以 `--recovered` 启动，核对真实会话关联、同日仅一条 active、构建元数据与本机代次不上传；正文和脱敏路径使用合成值。原先手写无代次记录的场景改为拒收负例，不能让本次开启追认旧故障；跨版本故障归属仍由共享层专项覆盖。不修改产品出厂默认值。

共用输入宿主的关闭夹具也必须区分停采和清理完成：正常路径先解除故障处理器武装，再清理磁盘队列；夹具的状态读取不取得生命周期锁，不能把 `armed: false` 当成清理已完成。阻塞发送的关闭回归在原有十秒期限内等待停采与 active 事件清空两个条件，随后仍保留原来的队列断言；坏配置只停采的用例不要求清理。Linux 完整门禁实际暴露了这个窗口，受控状态序列可重现原等待过早返回，修后等第二次读取才结束；没有延长超时、删断言或修改产品的停采顺序。

## Alternatives considered

- **每个 epoch 单独一个遥测目录**：天然隔离旧进程晚写，但匿名安装 ID 与退避状态会随目录重建，且撤回后旧进程仍能重建废弃目录；共享队列已有安全清理和锁，直接绑定代次保持原语义。
- **只在观察器换会话 UUID**：最小改动，但旧原生文件和已取出的发送快照仍可混入新的授权。
- **只拒绝无绑定入口而不迁移宿主**：能立即封住旧记录与旧发送绕过，但合法主宿主也会全部停止上报。共同目录必须先完整迁移，再用拒绝保护后续漏接，不能用保护替代接入。
- **发送期间持偏好锁**：可以把授权检查与整个请求完全串行化，但撤回、键盘收起和其他设置保存都可能等待十秒网络超时，不能采用。

## Consequences

收益是采集身份、磁盘队列、系统补录与逐条发送共享同一持续授权边界。代价是新协议首次激活时丢弃无法证明属于当前授权的旧待发报告，正常路径增加本地核对与锁操作，临时读失败会保守停止采集和发送。匿名安装 ID 保持，授权代次不上传，其他尚未接入该可选协议的平台行为保持兼容。

已经交给网络的单条请求无法撤销；在检查和实际发送之间发生的撤回属于在途请求边界，不承诺撤回已抵达后台的数据。运行中的旧版本不维护新协议，不能用本次实现保证降级后的持续授权。故障现场仍只能使用预备快照，不能等偏好锁或读盘补查授权。六平台设备故障到后台精确符号化、iOS 实际致命故障与 MetricKit 系统回调继续由全平台提案跟踪。
