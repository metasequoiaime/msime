# Agent Note: Android 拼写二次编辑不再改变输入法窗口高度

Status: implemented

## Problem

Android 点击全拼读音进入二次编辑时，`ImeCompositionEditor` 原来作为 `candidateRegion` 的纵向子项加入。编辑器从 `GONE` 切换为 `VISIBLE`，会改变候选区的测量高度，系统随之重新调整输入法窗口，表现为键盘瞬间抬起再回落；点击「完成」隐藏编辑器时也会触发同样的窗口变化。这个问题在九宫格全拼上由 #11194 报告，其他网格布局的相同问题另由 #11195 跟进。

## Decision

`ImeCompositionEditor` 作为 `keyboardSurface` 的覆盖层创建，使用 `FrameLayout.LayoutParams` 的包裹高度，不再参与 `candidateRegion` 的纵向测量。候选区布局完成后，覆盖层的顶边对齐候选区顶部；它显示或隐藏只改变覆盖层自身的可见性，不改变键盘主体和输入法窗口的边界。其他后加入的功能面板仍可按现有顺序覆盖它，编辑器的无障碍描述和光标编辑行为保持不变。

## Alternatives considered

- 把编辑器从 `GONE` 改成 `INVISIBLE`：可以避免反复测量，但普通键盘会永久预留编辑行高度，改变现有布局并留下无用空白，因此不采用。
- 继续把编辑器放在 `candidateRegion` 中、只调整窗口高度动画：依赖系统窗口过渡时序，无法保证点击「完成」时不出现短暂消失，也不能消除候选区高度变化的根因，因此不采用。

## Consequences

编辑器打开和关闭时键盘窗口边界保持稳定，九宫格和其他可编辑拼写布局共用同一覆盖层机制。覆盖层需要在候选区布局变化后重新设置顶边，且其触摸层级位于键盘主体之上；功能面板按创建顺序仍能覆盖编辑器。设备测试增加了窗口边界稳定性断言，能捕获窗口短暂消失或高度变化。

## Verification

实现后运行笔记校验、差异格式检查、Android 本地门禁，以及 API 28 设备测试；涉及键盘界面的改动还需按仓库要求运行 API 35 设备 smoke。验证命令和结果写入对应 PR。
