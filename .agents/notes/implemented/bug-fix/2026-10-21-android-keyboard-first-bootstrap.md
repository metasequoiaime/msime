# Agent Note: Android 输入法入口完成首次词库准备

Status: implemented

## Problem

#9117 报告 Android 17 的 0.4.2 拼音版在中文模式直接输入字母。固定发布包在 API 37 的独立设备中，先启动设置应用并等准备完成时能够组字并提交「你好」；清除专用测试包的数据后，仅从系统启用输入法、不启动设置应用时，键盘持续提示共享运行时未就绪，并直接输入字母。首次准备只由 `HomeActivity`、`OnboardingActivity` 等设置入口触发，输入法服务没有准备配置的路径。此条件是已确认的一条缺陷路径，不等于已证明原报告者的每次故障都由它引起。

## Decision

仅在需要引擎的编辑器中发现运行配置尚不存在时，既有启动工作线程调用幂等的 `Bootstrap.prepare`，继续使用跨进程 `bootstrap.lock`。准备完成后回到主线程，在同一个输入框重新读取配置、应用模式与偏好，再排原有会话创建；沿用 `pendingEngineStartup` 与启动代次，换编辑器或结束输入后丢弃旧回调，收起再显示时仍能恢复。已有但损坏或不可信的配置保持失败，不用重建掩盖错误。准备不阻塞输入线程，不重放准备期间已经直出的字母。

## Alternatives considered

- 每次输入法进程启动都准备全部资源：入口简单、能够提早开始；但已安装设备也要额外取得准备锁并做可选资源检查。只有缺少运行配置且当前字段需要引擎时才触发。
- 缺少配置时要求先打开设置应用：无需改动服务的异步生命周期；但系统本来允许从系统设置直接启用已安装键盘，不能让这个输入法入口永久停在字母直出。

## Verification

固定发布 APK 的无设置应用启动回归在同一编辑器等待 60 秒后失败；先启动设置应用完成准备后，同一发布包的相同回归通过。修复后的原生拼音瘦包在独立 API 37 Google APIs arm64 AVD 上，从缺少配置的首次键盘入口完成准备，两轮 `nihao` 均有真实组字标记，提交后标记消失，文本为「你好你好」。首次键盘显示后收起重开的专项也通过。

同一拼音包在 API 28 与 API 35 的首次键盘入口及收起重开专项均通过。两台设备上的 `client-base`、`client-core`、`client-providers` 和 `client-services` 测试各通过 1965 条，15 条忽略、7 条过滤；另有四个独立子进程测试通过。API 28 的 `smoke.sh --core` 完整通过。API 35 按原脚本分批覆盖默认冒烟的全部断言，末尾剪贴板保存生命周期套件通过；没有跳过剩余入口，也不将结果表述为一次完整脚本连续通过。首次及重跑曾出现长拼音夹具、隐藏视图组字与键高失败，固定修复包清理专用产品数据后或单项复跑通过，固定基线的相关单项也通过；这些波动的首次原因仍未确定，保留原失败记录。

十四键旧回归把无障碍描述当成读音文字，在固定基线包与修复包上同样失败。门禁顺带修正为同时限定「编辑拼写」动作描述和可见读音，保留原有组码隐藏、侧栏、锁定、分词、窄屏和真实提交断言；修正后 API 28 与 API 35 的完整十四键套件通过。此修改只更新设备选择器，不改变产品行为。最终设备源编译、quick、笔记校验与差异检查通过。

曾尝试在收起前强制观察“方案按钮仍未就绪”，但那次未观察到该状态，故不作为产品失败或已覆盖准备中取消的证据。收起重开专项只承诺视图生命周期验收；过期启动的代次规则继续由既有 `InputViewRefreshPolicy` 回归保护。Java/JNI 宿主检查、quick 与本地笔记校验均通过。

## Consequences

首次只从系统启用键盘的用户不再依赖先打开设置应用；准备只在缺少配置的引擎字段触发，不给每次正常输入增加资源刷新。准备任务无法强行中断正在运行的原生事务，但只有当前编辑器的回调能够创建会话。准备期间输入仍按原逻辑直接写入，不自动删除或重放已有文本。已有配置损坏仍报告失败，不自动覆盖。

这条模拟器复现条件不能当成 Pixel 6a 原始现场已完整验收，因此 PR 使用 `Refs #9117`，不自动关闭原 issue。APK 为本地开发签名，仅用于专用设备验证，不是更新用户正式安装的发布产物。
