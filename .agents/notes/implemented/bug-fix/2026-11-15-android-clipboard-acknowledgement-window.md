# Agent Note: 剪贴板插入确认层使用独立附属窗口

Status: implemented

## Problem

#11196 的旧系统回退把居中卡片加到输入法根视图，再将卡片并入父窗口触摸区域。API 28 专用模拟器以报告中的 1080×2376、480 dpi、字号 1.25002 复现：打开提示时同一输入法窗口的无障碍边界从 `Rect(0, 1415 - 1080, 2232)` 变为 `Rect(0, 959 - 1080, 2232)`，原设备断言失败。Android 9 的无障碍边界由可触摸区域包围矩形计算，把卡片加进去无法同时保持父窗口边界和按钮可点击。

本篇取代[多选闪烁修复](2026-11-10-android-clipboard-multi-selection-flash.md)中旧系统使用根视图覆盖层的决定，保留原第五条选择行为、插入上限与真实设备断言。与普通操作结果 Toast、空语音顶部提示及共享设置无关。

## Decision

所有 Android 版本的插入上限确认卡片均使用 `TYPE_APPLICATION_ATTACHED_DIALOG`，绑定键盘窗口令牌，以 `FLAG_NOT_FOCUSABLE`、`FLAG_NOT_TOUCH_MODAL` 和 `SOFT_INPUT_ADJUST_NOTHING` 保持编辑器焦点及父窗口布局。API 30 之前另设 `FLAG_LAYOUT_NO_LIMITS`，让卡片可在屏幕中央布局；不扩展父输入法窗口的触摸区域。

确认、提示替换和输入法生命周期结束时移除附属窗口。沿用现有防截屏标志、无障碍文本、右下角确认按钮及选择状态，不增加常驻占位或新的设置。

## Alternatives considered

- 保留旧覆盖层并补触摸区域：改动最少，已能让确认按钮收到点击；但 API 28 的实际回归证明它扩展父窗口无障碍边界，不能继续采用。
- 把卡片放回键区内部：不需要跨窗口，也能维持窗口大小；但旧系统验收要求屏幕居中，键区内居中不满足这个行为，因此使用独立附属窗口。

## Consequences

输入法父窗口的触摸区域和边界保持原值，提示自身仍可真实点击，关闭后保留五条选择、编辑器焦点和空内容。旧系统也复用现代系统的提示生命周期，删除仅服务旧覆盖层的字段和触摸区域补丁。

原 API 28 回归在修复前失败，独立窗口方案通过同一套断言，未改变采样频率、目标窗口身份或边界要求；最终代码的 API 28/35、完整 quick 及报告者 Android 11 真机仍分别记录，其他版本通过不能代替报告者环境。
