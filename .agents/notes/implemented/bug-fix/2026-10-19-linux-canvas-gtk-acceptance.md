# Agent Note: Fcitx5 皮肤资源热更新后刷新真实候选窗口

Status: implemented

## Problem

Fcitx5 的静态 canvas 面板已有九宫格像素单测和真实 classicui 配置测试，但前者只检查生成的 PNG，后者没有显示候选窗口。真实 GTK 编辑器验收发现，组合期间损坏皮肤图片后，`theme.conf` 已切回安全配色和原生卡片，屏幕仍显示旧贴图，直到下一次按键才更新。仅重载 classicui 配置不会请求当前 InputPanel 重绘。

## Decision

`applyCandidatePanelTheme` 返回主题是否成功套用或退出覆盖；未变输入、尚未到重试时间、第三方主题所有权和写入失败都不要求重绘。`FcitxState::syncCandidatePanelTheme` 在返回成功变化后先请求 InputPanel 更新，让资源检查触发的图片变化立即进入真实窗口，不修改组合、候选身份或编辑器焦点。不变的轮询仍保留廉价缓存路径。

原生 GTK／Wayland 验收还复现了客户端面板的重载竞态：`fcitx5-gtk` 用 GLib 文件监视器异步读取主题，立即发出的 InputPanel 更新可能先画旧主题；文件监视器之后虽已重载资源，却不主动请求 popup 重绘。对声明 `ClientSideInputPanel` 的上下文，在主题变化后保留一次不早于 250ms 的后续刷新，由现有偏好轮询消费；不新增常驻动画循环，也不反复写主题或解码。不保存候选快照，刷新只读取当前 InputPanel，失焦／关闭时取消，新换肤替换未消费的刷新。这是给异步文件重载留出下一轮事件处理的有界补偿，不是客户端重载完成的协议确认。

在已有的隔离 D-Bus／Xvfb 验收中注册横排、竖排两个真实 GTK 编辑器用例。共享 Host API 准备已校验词库与合成偏好，本次构建的插件加载九色 PNG 和清单。实际按键唤起候选后读取 X11 根窗口像素，验证浅色、深色、损坏后的原生回退、修复后的贴图恢复。切换和资源变更期间不再发送按键，最后检查编辑器焦点仍在、空格提交合成词且面板消失。临时文件、显示服务和 daemon 随用例清理，不操作用户桌面或已安装输入法。

Wayland 用同一个合成皮肤夹具，运行独立无头 Sway，关闭 Xwayland，以虚拟键盘输入并用 `grim` 读取合成器实际输出。GTK 客户端与编辑器同进程，XDG 配置、资源目录必须在 Python 导入 GTK 之前固定，防止 GLib 缓存其他目录；同时预建空的 `fcitx5/conf` 父目录，让监视器能观察首次生成的配置文件，主题文件和内容仍由真实插件写出。平铺窗口中的输入框保留自然高度，避免把 popup 锚点拉到屏幕底部。容器 root 只负责构建与收集截图，合成器和输入会话由普通用户运行。定位用例移动输入框后发送正常的编辑按键，让 GTK 上报新光标矩形，再断言实际 popup 像素跟随；它不证明只改控件 margin、尚未上报光标时也会移动。

## Historical audit

- [静态九宫格面板](../feature/2026-10-19-linux-fcitx-canvas-panel.md)部分重叠：保留产品映射与像素单测，本篇修复其资源热更新时的窗口重绘，并增加真实窗口证据。
- [IBus 兼容前端验收](../testing/2026-10-15-fcitx5-ibus-frontend-acceptance.md)部分重叠：复用隔离环境和 GTK 输入思路，不替换其前端协议验收。
- [候选渲染边界](../architecture/2026-10-13-cross-platform-candidate-rendering-boundaries.md)仍有效：窗口由 Fcitx5 classicui 拥有，测试不另开模拟候选窗口代替产品。
- 其他 canvas 笔记分别归属共享资源、其他平台或静态图片几何，不改变本次的刷新决定；原有主题所有权、字体与轮询缓存决定继续有效。

## Alternatives considered

- **仅给现有配置测试补更多断言**：不需要显示服务，执行快；但缺陷恰好发生在配置已经正确之后，保留第一层测试并增加窗口像素验收。
- **每次资源轮询都刷新面板**：不需要额外返回值即可覆盖缺陷，但每个有焦点的上下文每 250ms 都会检查主题，输入没有变化时不应重复请求重绘。
- **仅在主题写入后立即重绘**：对独立 classicui 路径简单且足够，但 GTK 客户端用文件监视器异步重载，会先处理 InputPanel 消息再换图。保留即时刷新，并只为客户端补一次下一轮刷新；不采用持续轮询重画。
- **重启插件来刷新主题**：可以重新加载全部资源，但会清空当前组合，不能作为普通换肤与资源修复的实现或验收手段。
- **目测人工截图**：能覆盖更多桌面环境和真实字体，但不适合作为重复回归检查；保留实机验收缺口，加入合成像素断言。

## Verification

修复前，真实窗口保留旧 canvas 像素，而生成的配置已显示 `Image=shape-*` 和安全配色；修复后，同一编辑器中依次通过浅色、深色、坏图回退、修复恢复、焦点保持及空格提交 `你好`，不依赖中途按键或重启插件。原生配置测试同时断言首次套用需要刷新、不变输入不需要刷新。

最初 PNG 切片的共享库重新构建后，九项验收全部通过：三项真实 classicui 主题测试、智能 ABC、真实 daemon 前端、原有 GTK 编辑器、新增横排／竖排 canvas 像素用例与 GTK IBus 兼容前端。横排和竖排各保留明暗、损坏、修复四个阶段的实际窗口截图；生成图片不提交。

提交前 `bash scripts/verify-local.sh --quick` 在独立远端镜像通过：Linux 原生 92 项、全拼与五笔构建及安装隔离、Linux 设置壳、Rust workspace、Android Rust／Java、WebAssembly、macOS 原生宿主和共享 Apple bridge 均通过；Windows 本机可运行 171 项通过（最新 run `20261020-013823`，5 分 38 秒，完整日志保留在本地验收产物中）。完整 Windows 交叉构建与 HarmonyOS 真打包因工具链或工程准备不全而跳过，不计通过。本机笔记校验、Python／Shell 语法、Fcitx5 源码契约与差异检查通过。

扩展验收中的 `fcitx5-native-context` 和 `fcitx5-native-ai` 在共享的快捷模式断言 `Disabled expression mode must pass through` 失败。对照使用同一套当前构建的共享库与固定资源，将插件和测试源码恢复为未修改的 `e3a4af9681810b16c89ec058d47101a7f52f325b`，两项仍在同处失败；它们属于既有基线问题，不在本次重绘修复中改写快捷模式行为或增加已知失败豁免。

追加的原生几何、主题、X11 与 Wayland 验收 16 项全部执行通过，无跳过；PNG／GIF／WebP 横竖排均覆盖明暗切换、坏图回退、资源修复、焦点与 `你好` 上屏，Wayland 还覆盖正常输入后的光标跟随。54 张实际输出截图保存在验收产物中，抽样目测确认九宫格与中文可读。修复前的同一 Wayland 夹具在深色切换或图片修复后停留于旧样式，修复后通过，没有通过中途按键替代换肤／修复的等待断言。

## Consequences

资源变更不再等待下一次按键才反映到候选窗口。新增测试依赖验收镜像已有的 GTK、Python D-Bus/GI、Xvfb 与 xdotool，沿用现有已验证资源及 Xvfb／xdotool 的注册门槛；普通原生构建门禁仍可独立运行。像素统计使用合成纯色边框，避免把字体抗锯齿差异当作皮肤失败。

原先证据只覆盖隔离的 X11／GTK／classicui 路径；本次扩展到独立无头 Sway 的 GTK 原生 Wayland 客户端面板。Xvfb 不包含桌面合成器和真实显示缩放；本次镜像补充中文字体，无头 Sway 的字形与定位证据仍不能代替发行版桌面和真实显示缩放验收。PNG／GIF／WebP 的静态面板验收见[共享图片解码](../feature/2026-10-20-linux-canvas-image-formats.md)。合成器原生 input-method popup、GNOME Shell、kimpanel、动画与自由挂件仍需各自实现与验收，不能据此宣布全平台兼容完成。

X11 canvas 的窗口所有权由[原生 X11 画布](../architecture/2026-10-20-linux-native-canvas-x11.md)部分取代：有效 canvas 包、X11 输入上下文和水杉持有的 classicui 主题使用原生候选窗，挂件与独立行距由该路径绘制；其余上下文继续使用本篇的桌面面板路径。静态图片不代表接通动画，Wayland 与其他 UI 的缺口仍保留。
