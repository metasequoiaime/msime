# Agent Note: Android 隐藏引擎启动期间的状态行

Status: implemented

## Problem

#8473：Android 首次进入编辑器时，引擎会话在后台异步创建，但键盘把内部状态「共享运行时准备中」写进候选头。候选头在空闲状态下本来应隐藏；这条文案让它短暂占据一行，九键首帧因此比会话建好后的键盘更高，随后又回弹。引擎启动任务本身的代数和队列边界由[过期启动任务](2026-10-14-android-stale-engine-startup.md)与[取消启动恢复](2026-10-14-android-resume-cancelled-engine-startup.md)维护，本次只处理其用户可见状态。

## Decision

`EngineStartupStatusPolicy` 把引擎启动和隐私重建期间的状态行文案固定为空。`MSIMEInputService` 仍保留 `engineStartupPending()`、代数检查和失败回退；只有真正的直接输入或启动失败才设置状态行。这样后台启动不改变候选头可见性与键盘高度，启动成功后也不需要再从「准备中」切换到空字符串。

## Alternatives considered

- **继续显示「共享运行时准备中」，只把候选头固定为占位高度**：能避免高度回弹，但用户仍会看到输入法内部实现细节，且所有空闲键盘都要永久承担这段额外高度。
- **把启动提示改成 Toast**：不会改变键盘高度，但每次切换输入框都可能打断用户，不能满足后台准备且用户无感的目标。
- **只删除 `message` 赋值，不抽出策略**：改动最小，但首帧直接输入和隐私重建容易在后续改动中重新混用，缺少可独立验证的状态契约。

## Consequences

后台创建会话、个人词库同步和实时偏好读取继续按原有线程与代数运行；九键和其它布局在会话未就绪时不再因启动文案临时显示候选头。密码框、数字框等直接输入场景仍显示「直接输入」，真正失败仍显示「共享运行时未就绪：仅直接输入」。新增 JVM 冒烟和 `check-host.sh` 守住启动状态不得回到可见行。

## Verification

`EngineStartupStatusPolicySmoke` 覆盖引擎启动、直接输入和会话重建三种状态；`check-host.sh` 还检查服务源码不存在直接写入「共享运行时准备中」。设备验收需在 API 28/35 AVD 上运行 Android smoke，确认首帧键盘高度与会话建好后保持一致。
