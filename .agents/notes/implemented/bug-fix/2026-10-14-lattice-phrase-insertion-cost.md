# Agent Note: 多字词插入代价进入共享词网格解码

Status: implemented

## Problem

#7583 的新样例继续出现长句拆词后同音词抢先。共享 `edge_log_prob` 对多字词使用 `ln(weight) + length_bonus * syllables`，没有每词代价；把一个词拆成两个多字词会额外赚一次正的词频分。给缺少的词组补上正常权重不能消除这种偏差。

## Decision

把九键已经使用的每多字词一份 `PHRASE_LENGTH_BONUS` 代价移到共享 `edge_log_prob`：多字词分为 `ln(weight) + phrase_length_bonus * (syllables - 1)`。单字原有的语料归一不变。九键 `comparable_weight` 只再扣音节奖励，避免重复扣除；同一路径的理论最终分与原九键公式相同，但搜索保留的路径可以改善。全拼与双拼也在搜索时使用每词代价。保留默认奖励 20、搜索预算、个人模型及神经模型混合权重，不增设配置。

## Historical audit

[九键切分种子](../../implemented/feature/2026-10-10-nine-key-sentence-seeds.md)已经确认缺少每词代价会鼓励拆碎，但把代价放在九键跨切分排序中。本试验尝试把同一约束前移到共享解码；种子和搜索预算继续保持。此前[扩大路径试验](../../rejected/bug-fix/2026-10-14-lattice-rerank-path-coverage.md)因为回退被否，本次不扩大路径。

## Alternatives considered

- 所有词统一减 `ln(unigram_z)`：对应近似概率归一化，形式更规整；但单字和多字词的权重来自不同尺度，而且会翻转已有九键的校准，优先检验现有插入代价能否复用。
- 只把新词条权重升高：对单个短输入可能有效，但竞争分由多段词频乘积决定，需要过大的权重才能在长句中争首选，且会污染其他上下文。

## Verification

合成网格中，完整词权重 100、两段同音词权重 50,000 与 20,000；旧实现因为两段词频的正分相加而优先错误读法，新实现优先完整词。九键回归验证每词代价不能重复扣除。双拼回归同时检查完整词条去重和整句备选。

完整 engine/runtime 测试通过：2,005 个 engine 单测、31 个 golden 测试（含 300 个脚本场景）、274 个 runtime 单测，15 个既有 ignored 不变。15 个 golden 场景只更新 Generated 权重；其中重复音节的同分路径由 `好 / 好好` 变为 `好好 / 好`，个人二元、三元分词记录随之更新，其余候选文字、上屏与失败诊断保持原断言。

## Consequences

收益是所有拼音词网格统一按每词代价保留路径，减少拆碎取词频的偏差；代价是候选集合、束搜索路径、九键种子及同分分词可能变化，个人模型记录仍按实际选择的分词写入。词条补充需要词库 PR 合入并发布、客户端消费新锁后才进入产品，本次不发布。不得只凭一个样例正确就替换评分。

相关：自然对数的消费者契约继续遵守[神经重排单位](2026-10-14-neural-lattice-score-units.md)，不改模型权重。

自动全拼跨音节边界的后续[跨度重切分试验](../../rejected/bug-fix/2026-10-14-quanpin-lattice-span-resegmentation.md)已否决：预留原读音路径虽恢复候选覆盖，仍有一条原正确首选退至第 69 位，总体首选数没有提高。共享每词代价及本篇已实施的修复继续保留。
