# Agent Note: Android 本地语音明确区分模型选用与运行库准备

Status: implemented

## Problem

#9144 的截图里快速整句模型已经导入并显示「使用中」，键盘却提示缺少语音识别组件。服务页同样提示缺少运行库：模型安装本身没有失败，两个模型文件不包含独立的语音运行库。运行库与模型同列在很长的模型组里，「从文件导入」还位于全部模型之后，用户容易把选用当成全部准备完成。

## Decision

模型页先显示独立的「本地识别准备」组，说明模型与运行库都不可缺，列出当前选用的模型与运行库状态；缺运行库时同时提供下载和直接从文件导入。模型行统一用「已选用」表达选择，不冒充运行状态。键盘缺运行库的提示指向同一个模型页，明确可下载或导入。

## Alternatives considered

- 自动在模型导入后下载运行库：减少操作，但离线导入正是为网络不通提供的途径，不能把完成导入解释为允许额外联网下载。保留已有的选择本地服务或开启离线识别时请求下载的行为，新增同屏可见的手动下载与导入入口。
- 把运行库重新内置：无需准备第二项，但增加每个安装包的体积，推翻已有按需资源决定；本问题来自准备状态和入口不清楚，沿用原安装器即可。

## Consequences

- 模型页首先展示两项准备状态，运行库直接导入入口不再埋在模型列表末尾；已准备的运行库不显示重复导入入口。
- 下载仍经已有服务处理流量确认、取消与校验；导入仍经系统文档选择器与共享安装器，不增加自动联网或绕过校验的路径。
- 准备组额外占用模型页高度；模型列表需要继续向下滚动，代价换来缺项与安装入口先可见。
- 原生设备用例接入已有 `VoiceProviderCatalogDeviceSmoke`，保持清单的 100 项 instrumentation 上限；用合成状态覆盖模型与运行库各自缺失、都缺失和都齐备，打开真实导入说明再取消；不保存偏好、不安装模型、不录音或联网。它验证界面准备流程，不能证明报告人 vivo 真机的识别质量。
