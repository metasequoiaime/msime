# Agent Note: iOS 词库版本轮询离开主线程

Status: implemented

## Problem

真机 Time Profiler 在键盘没有按键查询时采到一段连续约 64ms 的主线程工作：两秒维护定时器读取完全访问权限，随后 `DictionarySnapshotWorker.tick` 同步调用 `localDictionaryStateVersion`，进入 `HostOptions.into_engine_options` 的语言词库路径解析和文件元数据检查。版本每十秒重查、键盘出现时强制重查，逐键回调计时没有覆盖它。用户确认关闭九键按压动画后依然非常卡。

## Decision

普通版本轮询先在主线程复制已准备选项，再在独立后台任务调用无会话句柄的版本接口；不占用负责按键的固定引擎线程。结果回主线程发布版本和认领请求，后台准备仍沿用原来的快照租约。取消后不发布迟到结果。实际激活仍只在后续空闲 tick 进行，后台版本读取完成不得直接激活快照；激活前维持已有版本核对。

维护定时器只在没有组字、本地模式和待交付数字、并且最后一次按下已过去 300ms 时运行；同一轮维护只读一次完全访问权限，避免在连续输入或首键快照尚未回主线程时插入同步维护。

## Related decisions

[按键线程归属](../../implemented/bug-fix/2026-10-19-ios-nine-key-owned-thread.md)部分重叠：它约束有会话句柄的 C ABI，版本接口不含会话句柄；[收起时释放租约](../../implemented/bug-fix/2026-10-14-ios-snapshot-worker-lock-release.md)部分重叠，立即释放契约继续保持；[按压反馈](../../implemented/bug-fix/2026-10-19-ios-nine-key-immediate-press-feedback.md)处理不同路径，不能视为用户卡顿已解决。没有完全吸收或需要否决的旧提案。同一个维护定时器里剩下的个人词库和快照队列读取后来也移出了主线程，见[维护定时器的文件读取](2026-10-22-ios-idle-maintenance-off-main.md)。

## Alternatives considered

- **把版本读取送进按键线程**：能消掉主线程直接的文件操作，但版本检查会排在下一次按键查询之前，仍让候选滞后；版本接口不依赖会话线程，因此另用后台任务。
- **取消版本轮询**：能彻底消除这部分开销，但云端预览失去本地版本更新，恢复前冲突检查也不能因此省略，保留原协议。

## Verification

真机 Release 的 11 项定向回归通过，包含阻塞版本读取时主线程继续执行、重复 tick 不重入、收起后迟到版本不写队列、后台读取期间输入继续组字、账号不符取消请求、完整准备与激活，以及原异步输入顺序和候选代次。最终正常 Release 产品（App 和扩展 build `2026101902`）严格签名验证和真机覆盖安装通过，二进制不含临时触摸探针。最终包三轮 12 组合成拼音、117 次数字点按全部通过，交替空格和候选上屏，断言只有汉字、没有残留组字；这仍只是功能验收，不作卡顿改善的证据。临时 runner 对 `44`、`4646`、`64426` 的三组不交叠注入，预编辑均与慢速基线一致，随后通过候选/空格完成汉字提交。当时标称的 70ms 间隔、25ms 按住没有校准；后续普通按钮触摸校准说明请求间隔不能当作实际间隔，见[触摸校准记录](2026-10-19-ios-nine-key-immediate-press-feedback.md)。这只能保留为合成输入的功能检查，不能证明 70ms 连打、双指交叠或触摸到画面的延迟达标。

Time Profiler 的直接进程附加不可用，改用短暂全局采样后仅保留扩展栈并删除原始全局采样。基线 64 个连续 1ms CPU 样本均在主线程维护定时器，37 个样本进入版本读取，32 个进入选项验证和语言词库路径解析。修复后的两次采样均提前断开，没有扩展样本；不能据此宣称真机帧延迟降低。后台线程执行和取消行为由可阻塞读取的真机回归验证，用户手感仍需实测反馈。

## Consequences

异步结果可能在账号、输入状态或键盘可见性改变后到达。认领前重新检查账号，取消后丢弃结果，激活仍由新的空闲 tick 触发。本改动只消除已确认的维护阻塞，不证明全部触摸手感达标。
