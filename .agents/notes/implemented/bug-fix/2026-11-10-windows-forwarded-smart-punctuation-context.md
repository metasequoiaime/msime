# Agent Note: Windows 转发按键保留智能标点前文

Status: implemented

## Problem

Windows 浏览器等 TSF 宿主有时不给输入法可读的光标前文；输入法把未吃掉的数字或字母交回应用后，若 `wch` 也为空，下一次输入 `,`、`.` 或 `:` 就无法判断它是在 ASCII 数字或字母之后，设置中的「数字后直出」和「字母后直出」会退回中文标点。这个问题与 Linux IBus 无 surrounding text 的已修复路径相同，Windows 还要覆盖延迟键屏障和键盘布局字符缺失的 TSF 路径。

## Decision

Windows TSF 的智能标点影子只记录确认的 ASCII 字母和数字。转发键带有 `wch` 时使用它；宿主没有字符值时，从标准字母键、数字键和数字小键盘的虚拟键码恢复可确定的 ASCII 字符。其它转发字符、被输入法吃掉的键和编辑键继续清除影子。编辑器能回读前文时仍优先使用编辑器文本，影子只作为读不回前文时的回退。

## Alternatives considered

- **继续依赖 TSF 文档前文**：不采用。浏览器、终端和代理文本存储并不保证提供 surrounding text，设置在这些宿主里会永久失效。
- **把所有未吃掉的字符都记入影子**：不采用。标点、快捷键或布局产生的非 ASCII 字符会让影子脱离文档，后续标点可能错误地走 ASCII 路径；只保留能确认的 ASCII 字母和数字。
- **把所有虚拟键码都转换成字符**：不采用。键盘布局、修饰键和输入法状态会使一般虚拟键码的字符含义不确定；只恢复字母、数字和数字小键盘这几类稳定映射。

## Consequences

- 无法回读前文的 Windows 宿主在转发 ASCII 数字或字母后仍能按对应设置输出 ASCII 智能标点。
- 标点、编辑键和其它非 ASCII 转发键会使旧上下文失效，不会把过期的数字或字母带到下一次标点。
- 新的纯策略测试覆盖带字符值、缺字符值、数字小键盘和非 ASCII 输入；Windows 实机浏览器复验仍需在报告者环境完成。
