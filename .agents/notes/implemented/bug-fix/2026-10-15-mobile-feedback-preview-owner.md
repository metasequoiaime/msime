# Agent Note: 按键振动预览错误绑定当前操作

Status: implemented

## Problem

`useMobileKeyboardFeedback` 的加载和保存使用 `useAsyncActionRunner` 隔离宿主代次，振动预览却只检查是否挂载。切换宿主、复用旧宿主对象、关闭再启用移动模式后，旧预览失败仍会向当前 `onError` 发布错误。连续预览或发起保存时会清空错误，但较早的预览拒绝后又能覆盖较新操作的反馈。

## Decision

预览捕获现有 runner 暴露的 `generation`，并记录本地预览请求序号；只有组件仍挂载、宿主代次和请求序号都一致时才报告失败。新预览和已接受的保存都会递增该序号，使旧预览不再改变当前错误。宿主切换和移动模式切换沿用 runner 的代次生命周期，不另建 effect。

预览继续允许重叠，不占用加载和保存的运行锁；它不会阻止用户保存强度或关闭振动。

## Alternatives considered

- **把预览也放进加载/保存共用的 `run`**：统一管理错误和互斥，代码更少；但长时间不返回的试听会阻止保存，改变了现有非阻塞预览行为。
- **只检查客户端对象或当前挂载状态**：可以处理普通卸载或单次宿主切换，但同一对象重新启用、移动模式切换和同宿主的重叠预览仍会接受旧错误。
- **只比较宿主代次**：足以隔离客户端生命周期，但连续预览以及保存已发布新反馈时，旧预览仍属于同代次，需要本地操作序号。

## Verification

合成延迟用例在旧实现下 7 项失败，当前预览失败的控制用例通过；修复后连同已有移动反馈保存、卸载测试和公共 runner 测试共 27 项全部通过。桌面构建、格式、lint、笔记门禁和本地 quick 作为提交门禁。

## Consequences

底层已经发出的振动不会被取消，守卫只控制 React 错误反馈。保存与预览共享错误出口，因此新保存使先前预览的错误失效；后续新预览仍能报告自己的错误。
