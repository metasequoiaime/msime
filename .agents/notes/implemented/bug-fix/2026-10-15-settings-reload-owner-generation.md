# Agent Note: 设置重载隔离宿主代次

Status: implemented

## Problem

设置页切换宿主时会清空旧快照并启动新宿主加载，但手动刷新或移动端回前台触发的 `reload` 仍能等待旧宿主的 `load`。旧请求返回后会写回新页的状态；旧请求占用的 `reloadInFlightRef` 还会让新宿主的刷新被错误合并到旧请求。

同一宿主的首次加载与重载还有另一种交错：请求读取 revision 1 后，偏好通知已经送来 revision 2，迟到的读取仍会无条件采纳 revision 1，覆盖通知里的新偏好。加载代次不能区分同一次请求期间的通知更新。

## Decision

每次 `reload` 在开始时记录 `useAsyncGeneration(client)` 的当前代次，并递增独立的加载代次，使同一宿主尚未结束的首次加载也失效。加载成功、失败和 `finally` 只在两种代次仍匹配时更新状态。切换宿主的清理 effect 同时清除旧的 `reloadInFlightRef`，让新宿主建立自己的刷新互斥；旧操作的 `finally` 不会清理新操作的引用。

首次加载与重载在成功采纳快照前都比较当前 `snapshotRef` 的 revision。当前版本较新时保留它及草稿，读取仍正常清理加载状态。相同版本继续沿用显式重载重置草稿的既有语义，新的宿主由既有重置 effect 清空 refs，因此其较小 revision 也能被采纳。

## Alternatives considered

- **只在 `reload` 返回后比较 `clientRef.current`**：能阻止旧结果写入，但不能阻止旧的刷新 Promise 占住新宿主的互斥，也不能覆盖组件内部代次变化或同一宿主首次加载的迟到结果。
- **取消底层 `load`**：设置宿主接口没有统一的取消协议，强行增加会扩大所有平台的契约；代次守卫可以安全丢弃迟到结果。
- **让宿主切换等待旧刷新完成**：会使新宿主页面继续显示加载中的旧状态，并把无关的慢请求延长到新宿主，违背切换时立即隔离状态的既有约定。
- **让首次加载与回前台重载共用一个请求**：可以减少重复 I/O；但首次读取可能开始于后台期间的修改之前，恢复前台需要一次新读取，因此保留独立重载并用 revision 守住结果顺序。

## Verification

新增合成延迟宿主测试，覆盖旧重载成功、失败、晚于新加载返回、首次加载与重载交错，以及旧重载不阻止新重载和不解除新互斥；先在修复前观察到旧快照覆盖新状态和新重载未启动，修复后 5 项全部通过。相关设置持久化测试与桌面类型检查作为 PR 门禁运行。

偏好通知与读取交错的两个回归用例在旧实现均失败（revision 2 被退回 revision 1），修复后与加载归属和保存测试一同通过。共享 UI 验证不替代原生宿主装机验收。

## Consequences

宿主切换期间旧 `reload` 仍会完成底层调用，但其结果、错误和忙碌状态都被丢弃；同一宿主被刷新时，尚未完成的首次加载也只完成底层调用，不再覆盖刷新结果。新宿主可以立即加载和刷新。加载归属与保存归属各自维护；保存端后续的客户端复用边界见[设置保存隔离宿主代次并保留卸载续写](2026-10-15-settings-save-owner-generation.md)。
