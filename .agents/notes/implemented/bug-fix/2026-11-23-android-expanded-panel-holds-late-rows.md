# Agent Note: Android 展开面板开着时晚到的候选等收起或刷新

Status: implemented

## Problem

[#11816](https://github.com/metasequoiaime/msime/issues/11816) 要求晚到的结果不挪动已显示的候选。展开面板（普通网格和九键三栏）开着时，停顿重排和云/AI 候选照常换代。[展开面板跟随异步刷新](2026-11-14-android-expanded-async-refresh.md)让面板换成新一代，网格回到顶部，用户正在看的位置跟着跳走。

## Decision

面板开着时，会换代的晚到结果先留在宿主，不交给共享内核，面板绑着的代次因此不变：

- **停顿重排**：`PauseRerankController` 不起跑、不接续，停在原处，面板收起时接着做。它只换顺序、不添新词，用户要找的词还在面板里。
- **云/AI 候选**：`CandidateHoldGate` 留住在线结果，提示（`ImeCandidatePanelCue`）浮在面板上方，带来源标记和「新候选 · 刷新」，不占格子的位置。点提示时在等的候选马上用上，面板换成新一代并回到顶部；之后再到的照常等。收起面板也会用上。停顿重排不跟着刷新放行，收起时再做。
- **不换代的装饰照常就地更新**：释义、读音、译文。
- **面板开着不轮询**：收起和刷新由宿主调 `release()`/`resume()`。每次 `render` 发现面板已收起都会放行，所以收起键、选词、打字等各条路径都不会漏掉。
- **按着候选的规则不变**：照旧每帧再看一次。

在线结果交给主线程后，在线 worker 不再等它用完，也去掉了原来 2 秒的等待上限：

- 用完云候选，AI 那一步按用过之后的查询再排回 worker；
- AI 是否解决、签名释放等收尾移到这条链的末尾；
- 留得再久也不占住 worker，也不会过时丢掉回答。

## Existing notes audit

- [展开面板跟随异步刷新](2026-11-14-android-expanded-async-refresh.md)部分被取代，双方互链。被取代的是它「完全停止面板打开期间的重排和在线候选会隐藏本已启用的候选能力」这一条：在线候选现在不藏，等着时有提示，点一下就用上；重排只换顺序，留到收起不藏任何词。保留的是同步完整快照、旧格子按旧身份拒绝选择、换代时网格回到顶部，用在刷新和收起之后。
- [过期候选回调](2026-10-14-android-stale-candidate-callbacks.md)：身份围栏不变。
- [异步停顿重排](2026-10-21-async-settled-rerank.md)：任务有效性不变。停在原处的一步在打字、换会话时随 `cancel()` 作废。

## Alternatives considered

- **云/AI 候选先交给共享内核、面板留旧快照**：面板里的格子会指向过期的代次，点了选不中，不能采用。等统一的候选绑定按文字找回同一个词之后可以再看。
- **提示做成收起键上的小点**：更安静，但点它就收起面板，不能就地刷新，也容易看漏。
- **只去掉 2 秒上限、照旧等**：面板开着多久，在线 worker 就被占住多久，下一段组字的请求排在它后面，所以改成不等。

已知限制：

- 云候选还留着时 AI 请求不发，因为它要用过云候选之后的查询。AI 候选要等刷新或收起之后才到。
- 云候选可能和已有的词重复（共享内核在用的时候去重），提示只说候选到了，不说和面板里的不同。

## Verification

- `CandidateHoldGateSmoke`：面板开着时云/AI 候选等着、不轮询、按先后报来源；刷新时放行，之后再到的照常等；已放弃的不执行也不提示。
- `PauseRerankControllerSmoke`：面板开着时不起跑、两片之间停下、收起后接续；取消后停下的那一步作废。
- `CandidatePanelCueSmoke`：来源顺序和读屏文字。
- `CandidatePanelRefreshDeviceChecks`：在真实会话里经在线入口确认等待中面板不换代、提示露出；点提示刷新和收起面板两条路径都用上结果，旧格子仍拒绝选择。

## Consequences

刷新是用户自己的动作，所以面板换代并回到顶部；收起之后，留着的结果立刻换上候选条。读屏念「有新的云候选，点按刷新候选面板」。
