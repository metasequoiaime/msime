# Agent Note: 空快捷入口的拒绝大写回到普通组字

Status: implemented

## Problem

#8774：`Shift+U` 进入 Unicode 模式后，`Shift+V` 不属于十六进制字符。现有通用拒绝分支提交 `U` 并透传 `V`，两枚连续大写不能继续留在候选框编辑。

## Decision

全拼、双拼的快捷模式只有一个大写入口字母时，如果下一枚大写字母不被模式接受，将两枚字母一起移入普通组字，消费当前键但不提交。已有模式内容、合法模式字符、小写拒绝字符、符号入口和其他方案继续遵循原来的拒绝提交规则。

不改变快捷模式默认值，不把合法的 `U0041`、`U+FFFF` 解释为英文，也不在宿主维护第二份原文。转移后继续使用共享引擎的大小写原文、退格和原样提交路径。大写字母是否参与中文候选属于 #8773 的独立修复。

## Historical note audit

- [快捷模式拒绝键](../../implemented/bug-fix/2026-10-15-local-mode-rejected-key-passthrough.md)部分重叠：本篇只取代空入口拒绝大写的情况，已经输入模式内容后的规则保留。
- [光标拒绝键](../../implemented/bug-fix/2026-10-16-local-caret-rejected-keys.md)持有光标内部编辑；入口字母之后的末尾转移不改变该路径。
- [Shift 入口总开关](../../implemented/feature/2026-10-11-shift-letter-entry-switch.md)持有默认值及触屏菜单约束，本篇不改变它们。该笔记曾否决连续大写退出，因为宿主需重放且会提前上屏；现在普通拼音能接收大写，两枚字母能留在共享组字中，因此不需要宿主重放。
- [大写开始组字](../../implemented/bug-fix/2026-10-14-uppercase-pinyin-start.md)持有未启用入口的接受规则，本篇补齐已进入空模式的拒绝边界。

## Alternatives considered

- **保持拒绝时提交原文**：所有模式统一，避免吞键；但 `UV` 没有丢字仍然被拆成两次输入，不符合连续编辑的要求。
- **默认关闭快捷入口**：大写英文行为最一致；但改变既有用户习惯，并牵涉使用同一入口的触屏菜单，超出本缺陷的必要范围。
- **所有连续大写都退出模式**：`MBTI` 等缩写更容易输入；但合法的 Unicode 十六进制大写也会被抢走。本片仅在模式明确拒绝字符时转移。

## Verification

旧实现下新回归在全拼 `UV` 稳定失败；修复后全拼、双拼中的空 Unicode、日期时间、快捷短语和表达式拒绝大写保留两字母组字，原样提交不丢字。真实共享运行时回归覆盖 `UV`、`UI`、`KA`、`TA` 的无提前上屏、退格和原样提交。已有模式内容与小写拒绝继续保留旧回归；合法 Unicode 的既有场景不变。

整合 `dfecd5e440`（包含 #8776）后重跑：引擎 2351 通过、49 忽略，运行时 324 通过，golden 31 通过（300 个合成场景）；严格 all-targets clippy、格式、笔记和差异检查通过。指定旧真实词库未就绪，真实词库回放跳过；没有在系统输入法 UI 中验收。

远程 macOS 镜像的最终 quick（`20261019-182839`）退出 0，覆盖 Rust workspace、Android、Wasm、Java 宿主、Linux 共享壳与原生宿主（90 项测试）、macOS 原生和共享 Apple 桥接编译。缺少 Node、HarmonyOS 暂存依赖及 MinGW 的阶段明确跳过；笔记在本机单独通过验证。

macOS 的 `local-mode-preferences` 原生回归改为核对未启用或缺少可选资源的入口大写留在普通组字，并在应用下一份偏好前明确取消这段组字；总开关关闭时仍透传大写。修正旧断言后专项通过，最终 quick（`20261019-205219`）退出 0，Linux 设置壳及原生 90 项实际执行通过；笔记在本机通过校验。这是原生测试宿主验证，不是系统编辑器现场验收。

## Consequences

空模式遇到拒绝大写不再立即提交；后续候选由普通组字决定。大写的中文联想问题需 #8773 解决，不能把原文完整保留等同于候选语义修复。
