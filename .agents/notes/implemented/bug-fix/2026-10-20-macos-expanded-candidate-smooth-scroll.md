# Agent Note: macOS 展开候选网格保留触控板像素滚动

Status: implemented

## Problem

#8852：macOS 展开候选网格把触控板的连续滚动距离折算成整行，候选卡片在上下滚动时跳动，无法跟随原生输入法的像素级滚动手感。现有实现仍需只绘制可见行，不能因为平滑滚动把全部候选按钮一次性建出来。

## Decision

展开网格接收候选面板传来的原始 `scrollingDeltaY`，在宿主保存当前虚拟窗口首行与首行内的像素偏移。滚轮事件只移动视口，跨过完整行时推进虚拟窗口首行；重画时额外绘制被偏移露出的下一行并由内容视图裁切。非精确鼠标滚轮仍按整行移动，键盘方向键和翻页键仍按整行移动并清除像素偏移，普通候选窗继续使用原有的整页滚轮分页。

## Alternatives considered

- **继续把触控板距离折算成整行**：最强的理由是改动最小且保持现有测试契约。不选它：这正是 issue 报告的跳动来源，无法提供 macOS 原生输入法的连续滚动。
- **改用 `NSScrollView` 承载完整候选列表**：最强的理由是 AppKit 自带像素滚动和裁切。不选它：候选按钮、皮肤、焦点高亮和代次重载都已经由输入控制器管理，改成滚动视图会引入另一套视图生命周期并失去现有的大列表虚拟化边界。
- **滚动时重建全部候选按钮**：最强的理由是实现简单，偏移只交给坐标布局。不选它：`all_candidates` 可以很大，完整建树会放大触控板每帧重画的开销，也违背展开网格现有的可见行虚拟化。

## Verification

- 精确触控板事件的连续 delta 在行内移动候选视口，不立即跳整行。
- 跨行后仍只保留可见窗口及必要的相邻行，首尾边界不越界。
- 键盘上下、PageUp/PageDown 和普通候选分页行为保持原契约。
- macOS 原生测试覆盖像素偏移、虚拟窗口边界和键盘清零偏移。

## Consequences

触控板滚动时卡片随像素距离连续移动，跨行后仍只绘制可见窗口和一个必要的尾行；行高会因折行和释义变化而不同，偏移归一化依据实际行几何，内容视图裁切偏移后露出的按钮，避免按钮越过卡片边界。普通鼠标滚轮和键盘导航保留按行语义，普通候选窗的分页契约不变。

## 后续修正（#9233）

#9233 暴露出原实现仍按当前虚拟窗口的自然行高重算卡片高度：滚到包含不同字形或换行内容的行时，卡片高度和候选锚点会随每一帧变化。展开会话现在固定首次布局的视口高度，像素偏移只移动候选内容并继续由内容视图裁切；这样保留了原有的可见行虚拟化，同时避免滚动过程中窗口尺寸跳动。回归测试在首屏之外放入更高的合成候选，并断言跨行滚动前后面板高度不变。

## 布局重建时的视口（#9280）

固定的是同一次布局内的滚动高度。回到普通候选页、修改偏好、重装同名皮肤或明暗切换导致皮肤几何或选中条改变时，清掉旧视口，让下一次展开绘制按新字号和皮肤重新测量。否则 100% 布局的固定高度会带进 150% 布局，造成底部留白错误和候选裁剪；不能通过放宽留白断言掩盖它。

本地原生测试先复现 `candidate-row-layout` 的底部留白失败；新增 `shortcut` 回归在展开期间把字号由 100% 调为 150%，旧实现的候选区域高度没有跟着放大而失败。修复后两项原生 CTest 均通过，既保持换字号后的新高度，也保持后续像素滚动高度稳定。

最终源码的完整本地 quick 通过；`candidate-row-layout` 通过，`shortcut` 在降低并发后复跑通过（89.66 秒）。首轮 quick 中的 Swift 与 PowerShell 超时、首轮 `shortcut` 的翻译定时测试失败均没有计为通过，最终证据来自复跑结果。
