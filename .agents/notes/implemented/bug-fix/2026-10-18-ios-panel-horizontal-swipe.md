# Agent Note: iOS 键盘面板横向滑动统一接管

Status: implemented

## Problem

iOS 键盘的功能菜单和输入方式面板把分页交给 `UIScrollView`，但图块本身是 `UIButton` 或 `UIControl`，部分还带长按手势。从图块上开始的快速横划会被子控件先消费，导致 logo 菜单和输入方式面板看起来完全滑不动。表情面板只有分类按钮，内容网格没有横划切换分类的入口。

## Decision

`KeyboardPagedGridView` 在分页滚动视图内增加单指横向手势，关闭滚动视图自带的 pan，由外层手势按拖动距离直接更新 `contentOffset`，结束时吸附到最近整页。手势只在横向速度大于纵向速度时开始，开始后取消图块的点按或长按，因此从任意图块区域都能翻页，既有程序翻页和无障碍翻页继续使用同一套 `scrollToPage`。

`KeyboardEmojiPickerView` 在表情网格上增加单指横向手势。横向距离达到 48pt 且明显大于纵向距离时切换一个相邻分类，首尾不循环；纵向拖动仍由 `UICollectionView` 处理，搜索状态和多指触摸不切换分类。

## Alternatives considered

- 只把分页网格的 `delaysContentTouches` 改回 UIKit 默认值：改动小，但不能保证带长按手势的图块和不同 iOS 版本的触摸竞争都交给滚动视图，也不能为表情内容区增加分类横划。
- 继续依赖 `UIScrollView.isPagingEnabled`：系统分页动画完整，但它无法控制图块子控件何时取消自己的触摸，正是当前故障的触发边界。
- 给每个表情按钮分别安装横划手势：空白网格区域无法滑动，还要逐个协调按钮点击与网格纵向滚动，因此改为在网格容器统一接管。

## Consequences

功能菜单、输入方式、皮肤等复用分页网格的面板都能从图块和空白区域横向翻页，结束时仍保持整页偏移。表情面板可以在内容区左右切换分类，横划不会误插入表情；代价是分页网格放弃系统自带的连续减速效果，改由自己的横向手势和整页吸附完成，表情分类切换仍是离散的一类一步。

分页网格的自定义横划手势已撤回，翻页改回系统分页，见 [iOS 分页面板改回系统分页](2026-10-23-ios-paged-grid-system-paging.md)；表情面板的分类横划不变。

## Verification

新增实现会通过 iOS 键盘单测、模拟器构建，并在原生键盘宿主上检查三类面板的手势配置和现有分页回归。
