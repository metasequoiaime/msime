# Agent Note: 词库更新轮询等待当前请求

Status: implemented

## Problem

`useDictionaryUpdates` 每两秒启动状态读取并推进请求代次。状态读取如果总是慢于两秒，每个回答都会被下一个 tick 作废，版本一直无法显示。配置开关、手动检查和回退也共用代次：执行超过两秒时，成功状态与错误同样被轮询吞掉。

## Decision

轮询只在当前代次没有在途请求时启动。首次查询、配置、检查和回退都记录自己的代次，成功与失败在 `finally` 中释放自己的占位。手动动作仍可接管旧查询，旧完成既不能发布状态，也不能释放新的在途占位。入口变化和卸载仍由 `useAsyncGeneration(request)` 使旧请求失效；新入口可立即读取，不必等待旧入口。两秒订阅的固定相位保持。

## Existing notes audit

- [全平台词库独立更新](../feature/2026-10-18-dictionary-auto-update.md)部分重叠。其中轮询和手动操作统一采用最新请求优先的策略由本篇修正；后台更新、下载与安装规则不变，两篇互链。
- [云词库快照轮询等待在途状态读取](2026-10-21-cloud-snapshot-poll-single-request.md)部分重叠，属于不同 Hook；沿用等待在途读取和旧完成只释放自身的规则。
- [共享间隔订阅](../simplification/2026-10-15-shared-interval-hook.md)部分重叠，订阅机制和相位不变。
- 原生平台、账号存储与词库安装的其他命中无关；没有完全吸收的笔记或需要否决的旧提案。

## Alternatives considered

延长轮询间隔只改常量，正常反馈却更慢，而且宿主仍可能慢于新间隔，无法保证回答可见。保留并发查询但接受所有回答可以避免饥饿，却会倒序覆盖状态并持续增加宿主负载。完成后重新计两秒能自然串行，但改变现有订阅相位，因此保留固定 tick 并跳过在途请求。

## Verification

真实 `DictionaryUpdates` 的八项新增回归在旧实现失败，覆盖六秒读取、配置、检查及回退的成功和失败。修复后同时验证完成后恢复原相位轮询、旧读取不覆盖手动结果、旧入口或旧请求完成不释放当前占位、入口切换和卸载清理。测试只用合成状态和可控 Promise，不联网或改用户词库。相关五文件共 33 项通过；桌面与鸿蒙共享界面类型检查和生产构建、改动文件 lint 与格式检查、笔记校验及差异检查通过。静态复核确认 Windows 原生词库更新页已用 `dictionary_update_busy_` 阻止同类重叠查询。

`bash scripts/verify-local.sh --quick` 通过，包括仓库契约、Rust workspace、Android target 与共享 Apple bridge 编译。Linux 设置外壳因缺少 Docker、Windows 原生构建因缺少 MinGW 跳过；其他原生宿主按改动范围跳过。

## Consequences

慢响应可以发布结果，轮询不会累积相同查询。永久不结束的宿主调用仍会占用该代次，底层超时由宿主负责，重新打开页面或更换入口会开始新生命周期；已有状态下手动动作仍可发起。验证属于共享 React/jsdom 层，不代替原生宿主真实下载、安装和回退验收。
