# Agent Note: Windows 输入期间使用后台配置快照

Status: implemented

## Problem

#8341 报告 Windows 10 在磁盘扫描和开机期间候选消失、输入卡顿及文字回退。源码确认 TSF 的按键快捷键判断重复同步加载偏好，焦点恢复还读取运行配置并探测词库文件；500 毫秒窗口定时器也直接读取偏好。非阻塞文件锁不等于文件读取不会等待磁盘。尚未在报告者的 Windows 10 机器复现全部现象。

## Decision

每个 TSF DLL 进程保留不可变配置快照。首次激活同步准备一次，游戏候选策略紧接着消费这份已发布快照，避免把同一份偏好再次从磁盘读入；后续激活才重新读取最新排除规则。此后按键、焦点和窗口定时器只读取内存。500 毫秒定时器提交至多一个后台刷新，慢读期间保留最后成功的偏好、运行配置和词库可用性。后台只读配置，不持有 COM、TIP 或引擎句柄；引擎仍在所属线程调用既有 `update_preferences`，保留修订号和组字延迟规则。

线程池回调持有 DLL 加载引用，返回时交给 `FreeLibraryWhenCallbackReturns`；停用和卸载不等待磁盘线程。可信配置文件读取沿用原有校验及大小限制。

[游戏候选策略](../feature/2026-10-08-windows-game-candidate-overlay.md)仍在每次激活时同步读取最新排除规则：停用期间没有轮询，缓存可能过时，而 Server 已锁存的 UILess 不能在刷新后直接改判。游戏策略与协议保持不变，这个激活入口是明确保留的同步读取。[macOS 焦点监视](./2026-10-14-macos-key-focus-preference-monitoring.md)仅有机制重叠，不改变其实现。其余检索命中归属不同平台或功能，不修改。

## Alternatives considered

- 全异步冷启动：能去除首次配置读盘，但游戏 UILess 策略必须在向 Server 激活之前确定；直接使用默认值会忽略用户排除规则，延迟激活需要另外设计按键与焦点协议。本次保留激活时的同步读取，明确不宣称修复全部开机问题。
- 延长 GUI 定时器周期或只用 try-load：改动小，能减少读取次数或锁等待，但一次慢磁盘读取仍会冻结宿主线程。
- 常驻 watcher 线程：可以复用既有文件监视类，但析构 join 会重新让界面线程等待阻塞中的磁盘读取；线程池任务与 DLL 引用更符合 TSF 的卸载边界。

## Verification

- 确定性回归让后台读取停住，另一线程仍完成一万次快照访问；请求不堆积，失败、空响应和调度失败保留旧值，恢复后发布新值。
- 生产按键与焦点访问器不再打开偏好、运行配置或词库文件；窗口定时器只提交后台任务和应用内存快照。
- x64 Windows 原生产品与全部原生测试交叉构建通过；宿主上的缓存阻塞回归、焦点测试及四个生产接线检查通过。
- 最终代码的 44 项 TSF 测试在 Wine 中全部通过，包括实际线程池刷新、忙碌保留、停用后新增游戏排除规则和 DLL 类工厂。
- `bash scripts/verify-local.sh --quick`、`pnpm run verify-notes` 和 `git diff --check` 通过。quick 同时执行 i686 源码检查、共享 Rust 与 Android 检查、Linux 88 项测试、macOS 原生编译和双架构管道构建；这些是构建清单改动触发的门禁，不代表 Windows 10 实机验收。

## Consequences

除首次配置准备外，激活时的游戏规则读取、引擎创建仍可能等待磁盘；首次激活不再重复读取刚发布的配置快照，停用期间新增的规则仍在后续激活重新读取。词库查询与 Server 其他 I/O 也不在本次覆盖面。输入期间的配置生效最多延迟一个刷新周期及实际 I/O 耗时；停用期间不轮询，恢复后再刷新；失败期间继续使用旧设置。Wine 与单测不能证明 Windows 10 机械硬盘或游戏现场已经恢复。
