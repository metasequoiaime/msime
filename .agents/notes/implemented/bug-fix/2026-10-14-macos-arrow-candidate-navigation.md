# Agent Note: macOS 拼音光标与候选方向键分工

Status: implemented

## Problem

#7770 中，↓ 展开候选与上下选择候选共用按键，而左右键只改字，打开展开功能后普通候选缺少自然的选择入口。展开后接近末页时，窗口为了填满行数向前回滚，当前高亮行也不在第一行。

## Decision

> 「首选」与 → 在光标未到末尾时的分工已由[方向键按候选窗朝向和首选分工](2026-10-21-left-right-by-orientation-and-first-candidate.md)收紧：首选指全部候选的第一个，不在首选时左右键只移动候选，竖排时左右键只编辑光标。

全拼、双拼的普通候选开启方向键选择时，← 在首选上编辑拼音，其余位置选择上一个候选；→ 在拼音光标未到末尾时编辑拼音，在末尾选择下一个候选。↓ 沿用展开入口，展开后按行导航。候选列表、其它方案和关闭方向键选择时保持既有路由。修饰键不走这条规则。

展开窗口保持当前高亮行位于第一行，末尾减少显示行数；向上导航仍能看到之前的行。规则属于宿主，不复制引擎组词算法。

历史检索：本决定部分取代[整句改字](../../implemented/feature/2026-10-10-sentence-conversion-edit.md)的 macOS 普通候选路由与[展开候选](../../implemented/feature/2026-10-12-macos-expanded-candidate-grid.md)的末页补满策略；其它平台和网格选择身份契约保留，双方互链。

## Alternatives considered

继续上下选择、左右编辑有跨平台一致的优点，但开启 ↓ 展开后失去一个直接选择方向，无法满足报告中先编辑再选择的连续操作。

通过重复翻页把当前页变成网格第零页可以保留填满窗口，但改变引擎分页和候选代次，且复制的数据已有全部候选；因此只调整显示窗口。

## Verification

原生测试覆盖全拼与双拼的首选左移、非首选选择、光标中间右移、末尾右选、偏好关闭及候选列表路由；网格从末页展开时首行就是原高亮行，接着上下按行移动。

## Consequences

macOS 普通候选与其它平台的按键分工不同；网格末尾不再为了填满而显示前几行，窗口高度可以减少。
