# Agent Note: 移动端移除易误触的拼写铅笔入口

Status: implemented

## Problem

Android 候选栏顶部和 iOS 候选栏最前面的 SF Symbol `pencil` 是拼写编辑入口。它们占据一块独立的触摸区域，快速连续输入时容易被误点；iOS 26 键和九键在拼写写进输入框后还会为了这支笔保留空白区域。此前的拼写编辑设计把笔当作移动端的主要入口，见 [iOS 拼写编辑条](../feature/2026-11-02-ios-spelling-editor-bar.md) 和 [手机键盘读音命中区](../bug-fix/2026-11-02-mobile-preedit-tap-target.md)。

## Decision

Android 与 iOS 都移除候选栏最前面的拼写铅笔及其专用的空白命中区。26 键和九键的行内拼写不再通过空白区域打开编辑条；Android 只有在读音文字确实可见时才保留读音行的编辑入口，iOS 没有可见读音时直接收起 `preeditButton`，并将其标记为静态文字。14/18 键的可见读音仍可点按编辑，已有编辑条、光标移动和完成操作保持不变。

这次决定覆盖旧笔图标决定中「常驻笔图标入口」的交互选择，但不删除可见读音上的拼写编辑能力，也不改变 `touch_spelling_editor` 的默认值或共享偏好契约。Android 的开关仍控制可见读音入口和编辑条；关闭后不显示入口、不预留空行。鸿蒙没有本次涉及的铅笔实现，保持现状。

## Alternatives considered

- **只缩小图标或触摸区域**：改动更小，但误触的独立命中区仍存在，不能解决快速输入时的根因，因此不采用。
- **默认关闭拼写编辑**：能隐藏入口，但会改变已有用户的编辑能力和默认手感，也会把可见读音上的有效入口一并关掉，因此不采用。
- **删除所有移动端拼写编辑**：最彻底，但 14/18 键的可见读音仍有明确编辑需求；保留该入口能兼顾可达性与误触风险。

## Verification

- iOS 真机签名构建通过，`MSIMEApp` 已安装到 iPhone XR（iOS 18.7.11）。
- iPhone XR 真机 `MSIMEKeyboardTests/CompositionCaretTests/testInlineSpellingDoesNotExposeAnEditorPen` 通过，1 项、0 失败；断言无铅笔图像、无空白按钮命中区。
- iOS 的九键行内拼写回归也断言编辑条保持收起、候选栏不保留铅笔或空白入口；候选行布局回归断言第一个候选从顶行左侧开始。
- Android 的 `check-host.sh` 通过，包含 `SpellingEditorPolicySmoke` 和设备测试源码编译；已有 API 28/35 专项结果覆盖开关、入口和空行的基线行为，但本次移除图标没有在专用 AVD 上重新运行。本机连接的 Pixel 3 XL 不是仓库认可的专用 AVD，未用它冒充 Android 设备验收。

## Consequences

用户在 26 键和九键快速输入时不会再被候选栏最前面的笔或空白入口误触。14/18 键仍可通过可见读音编辑拼写。代价是 26 键和九键不能从候选栏空白处打开编辑条；需要编辑时应先把光标移入可见读音，或使用仍保留的其他编辑路径。旧笔图标笔记仍记录当时统一编辑条的背景，本篇记录后续收窄入口的决定。
