# Agent Note: macOS 首次激活先恢复语音与工具栏设置

Status: implemented

## Problem

macOS 冷启动时先同步读取共享输入设置，工具栏组件与语音服务仍等待后台偏好重载。首次激活后马上失焦会作废后台读取，常驻工具栏留下默认组件，语音总开关也可能停在旧缓存。当前报告发生时没有保留状态转换日志，因此这条可复现路径不能作为历史现场全部时序的证明。

只把首次读到的文档保存到下次激活还不够：首个按键接管焦点时工具栏可能尚未创建；没有客户端的控制器也收不到后台重载，手里的旧文档会在另一个控制器应用新设置后把全局语音缓存和共享工具栏改回去。测试若预先塞入工具栏，或只让同一控制器收到新文档，就会漏掉这两条路径。

## Decision

`applySharedInputPreferencesBeforeFirstUse` 返回本次同步读取的完整文档，不把它存进控制器。`activateServer:` 和 `handleKeyEvent:client:` 仅在同一次调用中把它交给 `applyInitialHostPreferencesFromSnapshot:`。系统模式报告若已提前读过输入设置，首次取得客户端时再读当前文档，只补宿主设置，不重放输入设置，保留系统随后选中的方案。首次读取失败后不标记宿主设置已应用，后续激活或焦点接管继续重试。

`applySharedToolbarPreferences` 在应用合法设置前取得共享工具栏，首个修饰键也不会把组件和尺寸发给 nil。它直接应用已收到的设置，不另存一份待激活快照；同一控制器的重载、另一个控制器的激活以及没有修订号的本机通知都不会留下可供旧控制器回放的文档。

首个 `KeyDown` 来自新客户端时，`handleEvent:` 不再按旧的本机缓存提前唤醒工具栏；等 `handleKeyEvent:client:` 完成焦点接管与共享设置恢复后，才按更新后的开关请求显示。焦点接管在恢复设置后无条件调用 `activateForDelegate:visible:`，把所有权交给当前控制器，再按开关显示或隐藏；否则旧控制器正常失焦后仍持有可见工具栏，新控制器的隐藏请求会被所有者检查拒绝，关闭开关也就切断了后续唤醒与交接。已经持有焦点的客户端继续沿用原来的按键唤醒路径。诊断日志也使用运行参数解析出的偏好目录，不能等会话创建或后台监视补上 `_preferencesDirectory` 才生效。

保留首次后台读取的完整应用：同步初始化完成后，会话仍可能从旧运行参数恢复英文联网候选开关，后台读取必须同时更新引擎与宿主运行态。只按同步读取的修订号跳过宿主应用，会把候选开关或日志配置留在错误状态。原有后台读取的客户端、会话、代次检查与引擎修订号门禁不变；成功更新后，后续未变更的轮询仍会跳过。

## Verification

`shortcut-startup-voice` 使用隔离的合成偏好与相反的原生语音缓存，暂停自动轮询，直接执行生产控制器的激活或按键路径。新增用例在修前分别失败：首个修饰键的 `microphone=0 runtime_enabled=1`；模式报告后，另一控制器应用关闭设置，旧控制器激活仍输出 `expected=0 microphone=1 runtime_enabled=1`。补充的运行态回归在修前也分别失败：首次 `KeyDown` 对已关闭的工具栏请求显示一次；新控制器启用诊断日志后仍是关闭状态；会话恢复旧运行参数后，后台读取未把英文联网候选开关纠正为文档值。

修后二十四种组合通过：首次激活、系统先报告韩语再激活、没有预设工具栏的首个修饰键、首次读取失败后重试、同一控制器收到新文档、另一个控制器更新后再激活、另一个控制器更新后由按键接管焦点、首次后台读取纠正旧运行态、首个 `KeyDown` 尊重工具栏关闭设置，未创建会话时启用诊断日志，以及旧所有者失焦后的工具栏关闭、开启交接，分别覆盖语音明确开启与关闭。运行态用例用替身会话提供相反的初始参数，执行真实控制器的 `prepareSession` 和后台完成路径，同时断言引擎更新一次、会话参数与宿主开关一起回到文档值。

所有权用例让 A、B 共用同一个外观对象，执行 A 的真实激活与失焦路径，再更新共享文档，让 B 不经激活直接收到首个 `KeyDown`。修前关闭场景输出 `new_owner=0 visible=1 expected_visible=0` 并失败；修后断言所有者是 B、实际可见性符合开关，后台读取完成后仍保持一致。开启场景还经工具栏的麦克风 action 确认请求交给 B；面板入口由计数替身接收，不打开语音面板或录音。

`shortcut` 全量控制器用例、`shortcut-startup-voice`、`shortcut-toggle-hotkeys`、`floating-toolbar-panel`、`shared-voice-preferences`、`voice-wave-overlay` 与 `preference-load-state` 共七项 CTest 通过。

语音入口使用实际 `toggleVoiceInput:`，合成模型路径保证在权限申请与音频采集之前报告缺模型错误。独立的 `voice-wave-overlay` 验证聆听面板与波形状态，不采集麦克风；首个按键路径的改前、改后原生视图截图保留在本机验证产物中。

## Alternatives considered

- 跨回调保留首次文档：模式报告已经读过时可省一次读取，但控制器没有客户端就收不到新文档，旧快照会回退全局语音与工具栏状态。文档只在本次激活或焦点接管里传递，不跨回调保存。
- 维护按目录共享的全局修订号和最新文档：能比较不同控制器手里文档的新旧，但还要处理没有修订号的本机通知与配置目录切换。缩短文档生命周期即可消除本次新增的回放路径，不引入另一套全局缓存。
- 每次首次激活都重新读整份文档并重放输入设置：能避开旧快照，但重复本次刚完成的同步读取，也可能盖掉系统刚选中的方案。复用同次调用里读到的文档；只有更早的模式报告已经读取输入设置时，才为宿主设置补读当前文档。
- 按同步读取的修订号跳过首次后台宿主应用：能省一次组件刷新，但会话创建还会恢复运行参数，后台读取必须重新完成运行态应用；不同控制器也共用原生缓存和工具栏，单个控制器的标记不足以证明全局状态没有变化。因此保留这次完整应用，后续未变更的轮询交给原有修订号门禁。
- 靠提前唤醒交接工具栏：复用既有入口即可切换所有者，但会先按旧的开启状态请求显示；如果只在开关开启时交接，关闭时又无法隐藏旧所有者的常驻工具栏。用独立的激活接口同时交接并应用可见性，保留先读设置再显示的顺序。
- 缩短后台轮询或失焦后仍应用：实现简单，但首次呈现仍会使用默认值，过时回调还可能改动新客户端。保留读取代次保护，补齐同步初始化。

## Consequences

语音总开关、服务、工具栏组件与主题在首次激活或按键接管焦点时生效，失焦不再留下等待后台回调的默认工具栏。控制器只多保存一个布尔值；模式报告提前读取过文档时，首次取得客户端多读一次当前文档，不增加后续逐键读取，不改变默认值、不提前写文件、不申请录音权限。

改变仅涉及 macOS 原生宿主。本次按用户要求不跑完整跨平台检查；本机聚焦测试使用同源、未开启可选 ONNX 重排后端的 arm64 Rust 库，未重新装机。历史现场没有足够日志，还不能排除其他导致语音不出现的路径。
