# Agent Note: iOS 数字侧栏保留大触控区与固定符号入口

Status: implemented

## Problem

iOS 数字九宫格左栏将四则运算与 `#+=` 五项均分到三排数字键的高度，键盘较矮时每项过小。数字页同时隐藏底行的「符」，用户只能先进入扩展符号页再打开分类面板。底行独立按比例分宽，使「九键」和空格的边界与上方网格错开。

## Decision

数字左栏底部固定一个「符」键，直接打开既有分类符号面板；上方放可滚动的四则运算与 `#+=`。每项及「符」键都与一排数字键等高，运算符列表显示滚动指示，保留全部原有动作。高度跟随右列删除键及当前行距；左右子树都加入 `nineKeyContainer` 后才激活等高约束，避免没有共同祖先时触发 UIKit 异常。字母页侧栏和其他平台不变。

数字页底行使用上方五列的宽度：「九键」对齐左栏，0、空格、中/英分别对齐 7、8、9，换行对齐右栏。0 保持至少一个数字键宽度；隐藏中/英时 0 合并前两格，空格对齐 9。系统要求底行额外显示地球键时保留原比例布局，避免把新增按钮硬塞入五列。跨行约束只在数字页启用，切回字母页恢复既有大空格。

本项部分取代[移动端默认数字九宫格](../../implemented/feature/2026-10-15-mobile-default-number-pad.md)中的 iOS 五项同时显示，并补充[九键符号入口](../../implemented/feature/2026-10-15-nine-key-symbol-key-and-quick-marks.md)中数字页没有「符」键的限制。两篇其余输入与统计约定保留。检索命中的空格光标、快捷符号偏好仅决定手势和标点内容，与本次几何无关。

## Alternatives considered

- 在底行恢复「符」：与字母页位置一致，但会占用 0 的宽度。将入口固定在侧栏，让底行对应上方五列。
- 左栏只留加减和「符」：三项全部可见，布局最简单；乘除与 `#+=` 的既有快捷入口会消失，因此保留可滚动列表。
- 保留独立比例分宽：0 可以占据更大的中央区域，但底行键边界无法对齐上方网格。无额外地球键时采用网格宽度，0 与其他数字键等宽，隐藏中/英时再扩展。

## Verification

- 最终模拟器测试包编译通过；iOS 18.4 上运行 `NineKeyKeyboardTests`、`KeyboardFormFactorTests`、`FourteenKeyKeyboardTests` 共 143 项，142 项通过、1 项因测试包没有笔画词库跳过、0 失败。覆盖底行五列边界、隐藏中/英时 0 合并两格、字母页恢复、手机和平板、自定义行距、运算符滚动及符号面板往返。初轮回归捕获的约束激活顺序错误已修正；此前重跑遇到的 CoreSimulator 宿主启动阻塞在专用新模拟器上解除。
- 修改后的系统编辑器 UI 测试源通过 `swiftc -typecheck`，本轮没有系统编辑器交互验收结果。
- 包含底行对齐的最终原生 App 与扩展完整 Release 构建通过，`codesign --verify --deep --strict` 通过，已覆盖安装到 iPhone 17 并成功启动宿主。用户确认过此前侧栏修正版的数字键盘正常显示且左下方「符」按钮可见；最终对齐包尚无用户界面确认。符号面板点击、滚动输入与连续算式仍没有本轮真机自动化结果。
- 本地 quick 初轮因磁盘不足失败；清理本任务缓存后重跑通过。底行对齐调整后再次运行 quick 通过，覆盖 Linux 桌面容器检查、Windows 交叉链接及共享 Apple 桥；`pnpm run verify-notes` 与 `git diff --check` 通过。

## Consequences

乘除和扩展符号需要滚动一次，换取更大的触控区。模拟器 UIKit 几何验证不能代替用户手机上的实际输入手感。
