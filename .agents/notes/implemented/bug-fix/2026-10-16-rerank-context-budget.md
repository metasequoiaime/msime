# Agent Note: 重排上下文只为实际比较候选留空间

Status: implemented

## Problem

`rerank_pick` 会扫描整张候选列表来找最长回答行，但上游 `Reranker::best_where` 最多只比较前九条回答当前按键的候选。九键候选列表常常在比较集合之后还有更长的整句；这些行不会参与评分，却会把上下文窗口再截短，令上游前缀缓存因无关长度变化而失效。

## Decision

重排上下文的最长候选只从实际比较集合取值：按候选顺序过滤 `answers_key`，最多扫描九条，再把这个长度交给 `rerank_context`。模型比较集合、候选顺序、静态证据分支和评分接口保持不变；超过九条的候选仍由原有 `best_where` 规则忽略。

## Existing decisions

本片复用 [运行时重排上下文窗口](../../implemented/testing/2026-10-15-lattice-return-budget.md) 所记录的窗口边界和上游九条比较上限；[静态重排评分缓冲](../../implemented/testing/2026-10-15-rerank-static-score-buffer.md) 继续持有静态证据路径的九条栈缓冲。本片只收紧窗口长度的输入，不改变模型评分或候选预算。

## Alternatives considered

- **继续为整张候选列表留空间**：实现最简单，但会让不参与评分的长行改变上下文前缀，破坏跨按键缓存复用。
- **把候选列表截成九条后再传给模型**：能避免无关扫描，但会改变现有 `best_where` 的输入契约和回退路径；本片不改变调用方候选视图。
- **增加按上下文长度的独立缓存**：可能进一步减少重排，但需要保存更多候选身份和失效规则，超出当前局部切片。

## Consequences

实际比较集合的最长行仍能完整占用模型窗口；比较集合之后出现或消失的长候选不再让前缀缓存无谓失效。新增一个无分配的线性扫描和辅助函数，扫描上限从候选总数收紧为九条；候选结果、模型分数和资源格式均不变。该切片需要以固定九键集合复测端到端延迟，不能仅凭单元测试宣称已经达到 16 ms 预算。

## Verification

新增回归测试覆盖九条短候选后跟一条长候选时最长值仍为短候选；完整 `msime-engine` 测试、Clippy、格式、笔记校验和九键重排延迟将在提交前运行。
