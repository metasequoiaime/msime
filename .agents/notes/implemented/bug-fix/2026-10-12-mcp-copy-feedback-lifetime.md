# Agent Note: MCP 复制提示复用公共临时状态

Status: implemented

## Problem

`McpConnectSection` 每次复制成功都创建一个独立的 1600 毫秒定时器。同一个按钮再次复制时，旧定时器仍能清除该按钮的新提示；卸载页面也没有取消计时器。账号页、系统信息和反馈页已有公共的提示计时逻辑，但 MCP 页没有接入。

## Decision

MCP 页复用 `useTemporaryFlag(1600)` 管理提示是否显示、成功后重新计时和卸载清理。页面仅保留最后成功复制的按钮标识，只有临时状态为真且标识匹配时显示「已复制」。复制成功后的挂载和客户端代次校验仍在调用公共 hook 之前执行，旧客户端结果不会启动提示。

## Alternatives considered

在 MCP 页增加定时器引用并在重复复制和卸载时清除，改动局限于单个页面，也能修复问题。但这会再实现一次公共 hook 已提供的生命周期逻辑，其他消费者已统一到 `useTemporaryFlag`，因此直接复用。

把公共 hook 扩展为携带任意值的临时状态，可以把按钮标识和计时一起管理。但已有调用方只需要布尔状态；MCP 页额外保留一个按钮标识即可接入，无需扩大公共接口和迁移所有调用点。

## Consequences

同一命令和不同命令的连续复制都从最后一次成功开始计时，卸载会取消待执行的提示计时器。页面保存的按钮标识可能在提示消失后继续存在，因此渲染必须同时检查公共状态和按钮标识。复制内容、权限参数、客户端代次检查和失败处理维持原有职责；这里没有把剪贴板操作迁入公共 hook。

## Verification

`apps/desktop/tests/settings/mcp-copy-feedback.test.tsx` 用合成命令操作实际组件，覆盖重复复制的 1000+600+1000 毫秒边界、另一按钮替换提示、卸载计时器清理、旧客户端完成后的忽略行为。旧实现前两项失败，第三项通过；现有 MCP 用例继续覆盖命令、配置和连接流程。验证为 jsdom 和构建检查，不代表原生设备验收。
