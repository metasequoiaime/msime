# Agent Note: macOS 方案的入口和「中」都不在列表里时选唯一的中文入口

Status: implemented

## Problem

Issue #11963：设置里的方案是全拼，系统输入法列表里只加了「水杉双拼」和「水杉英文」。在水杉里用 Shift 从英文切回中文，控制器要把菜单栏选回方案自己的入口 `.Hans`。`MSIMESelectSystemInputMode`（`platforms/macos/src/input/InputModeIdentifiers.h`）发现系统不提供它，直接返回、不发出任何选择，输入菜单和系统菜单栏图标停在「英」上，而按键已经按全拼打中文。

这是 [只加了一个水杉中文入口时以设置里的方案为准](2026-11-27-macos-saved-scheme-beats-only-listed-entry.md)（#11911）留下的显示问题：那次保住了方案，但明确没去改选别的入口。菜单栏显示「英」、实际打中文，用户会以为中英切换失效了，比显示「双」打全拼更误导。

## Decision

`MSIMESelectSystemInputMode` 的回退多一级。原来的规则不变：方案自己的入口（双、五、日 等）系统不提供时退到「中」。现在「中」也不在列表里时，再退到 `MSIMEOnlyAvailableChineseInputMode` 给出的入口：本 bundle 的中文入口（中、双、五、粤、注、笔）里系统列表中唯一可选的那一个。上面的例子里就是「双」，菜单栏从「英」切到「双」，方案仍是全拼。

- 只在恰好一个中文入口可选时回退。列表里有不止一个（例如「双」和「五」），不替用户在它们之间挑，照旧不选；一个都没有时也不选。
- 「英」不参与回退：英文模式要选的就是「英」，选不了时什么都不选，与原来一样。
- 「日」「한」「越」「藏」是换语言的入口，不算中文入口，不会被选来代替全拼。
- 模式正是系统刚报告的 `current` 时照旧不动（报告过的入口按定义是可选的）。

这次选择带回的报告不会改方案，有两层保证：

1. 控制器发出选择前把 `current` 设成「双」，不论回执是在 `selectInputMode:` 调用栈里同步送回，还是之后异步送回，它都只是重复 `current`，`MSIMEAdoptReportedInputMode` 不采纳，也不再触发同步。
2. 即使它被当成新报告处理，`MSIMEReportIsOnlyChineseEntryIn` 认出它是唯一可选的中文入口、而存的方案自己的入口不在列表里，也不改方案。

`MSIMEReportIsOnlyChineseEntryIn` 改为复用 `MSIMEOnlyAvailableChineseInputMode` 判断「报告的是唯一可选的中文入口」，两处对「中文入口」的列表只写一次，判断结果不变。

菜单栏状态项（`InputModeStatusItem`）不受影响：它一直显示控制器算出的模式（全拼是「中」），不看系统最终选了哪个入口。

## Alternatives considered

- 维持原状，只靠设置页「菜单栏入口」提示添加「水杉全拼」：改动最小，#11911 当时选的就是这条，理由是改选一个和方案不符的入口要再推一遍回执的处理。现在回执的处理已经推过（见上面两层保证），而停在「英」上的误导比入口名不符更严重，所以不再保留这条。设置页的提示仍在，用户加了「水杉全拼」之后菜单栏就回到「中」。
- 有多个中文入口时也回退，按固定顺序挑第一个：能让菜单栏在更多配置下不停在「英」。不选它，是因为在「双」和「五」之间挑哪个是用户的选择，替他挑一个和方案无关的入口，日后切进来系统报告这个入口时（`left` 未知、列表里有多个中文入口），`MSIMEReportIsOnlyChineseEntryIn` 不保护，方案会被改成它。只有唯一入口时这条路是安全的。
- 回退到「英」以外的任意可选水杉入口（包括「日」）：同样能离开「英」。不选它，「日」是换语言，显示它比显示「英」更不符合实际在打的中文。

## Consequences

收益：只加了一个水杉中文入口、设置里选了别的方案的人，从英文切回中文后菜单栏显示这个入口（例如「双」），不再停在「英」上；方案和 `MSIMEClientInputScheme` 不变。列表里有方案自己的入口或「中」时行为不变。

代价：菜单栏显示的入口名仍与方案不符（显示「双」、打全拼），直到用户把方案自己的入口加进列表，这一点设置页会常驻提示。回退时按中文入口逐个查一次 TIS，只在方案自己的入口和「中」都不可选时发生。

没有在真机上验证：控制器和选择逻辑由单元测试覆盖，系统菜单栏图标的实际显示依赖真实的输入源列表和图形会话。

## Testing

`platforms/macos/tests/input/InputModeIdentifiersTest.mm`：`MSIMEOnlyAvailableChineseInputMode` 在只有「双」「英」「日」时给出「双」、可用性为空时给出 nil；从「英」选「中」时选出「双」、回执不被采纳、再次同步不再请求；五笔方案在「五」和「中」都不在时同样落到「双」；列表里有「日」时日文方案照旧选「日」；「双」「五」都在时不选；「中」在列表里时照旧选「中」。

`platforms/macos/tests/input/ShortcutTest.mm` 的 `TestOnlyListedShuangpinKeepsSavedScheme` 在真实控制器上模拟只加了「双」「英」的列表：`setEnglishInputMode:YES` 选「英」，`setEnglishInputMode:NO` 选「双」，方案仍是全拼、本地偏好也是全拼，随后送来的「双」报告不改方案、不再触发选择；客户端在调用栈里同步回报时结果相同；把「中」加进列表后切回中文选的是「中」。
