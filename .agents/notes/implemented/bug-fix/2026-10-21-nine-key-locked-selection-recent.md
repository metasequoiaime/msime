# Agent Note: 九键锁定拼音后的选择保留到未锁定数字输入

Status: implemented

## Problem

#9041 的九键录屏显示，先在侧栏选择读法，再确认该读法的首候选，下次重新输入数字仍恢复另一读法的高频候选。`select` 仅在非首位选择时记录最近候选，记录还绑定 `nine-key:<digits>:<locked>`，未锁定时不会读取。

## Decision

显式选择读法后，确认覆盖全部剩余数字的普通词库候选时，把它记录到未锁定的 `nine-key:<digits>:` 第 1 槽，包括读法内的首候选。仍按原规则记录锁定上下文内的非首位、未固定候选。未锁定上下文已经固定的同一候选不改位置，避免选定读法时覆盖另一上下文的手动槽位。后一次选择其它候选仍可以替换第 1 槽。

默认结束组字、学习关闭、分段选择、简拼和非词库来源均不产生新增记录。数字串取选择时的完整编码，锁定补齐的音节因此作用于补齐后的数字，不追溯更短的键入前缀。使用已有固定位置表，不修改存储格式和主词库权重。

## Alternatives considered

- **只放宽首候选判断**：代码少，也能记住锁定状态，但下一次未锁定输入仍读不到，不满足录屏中的重复输入路径。
- **取消上下文的锁定部分**：读写自然共享，但不同显式读法的固定位置可能互相干扰。只额外记到未锁定上下文，保留读法过滤及原手动管理边界。
- **改全局词频或单字个人模型**：复用已有学习流程，但会连带改变其它键盘及读法的排序；上下文第 1 槽直接表达这次九键选择。
- **只给两字以上的词固定第 1 位（打字流评测之后试的 pinwords）。** 锁读法后确认的单字正是 #9041 录屏里的路径，它会把这里修好的行为收回，并且有一格评测变差，没有采用，见 [最近选择只给多字词](../../rejected/feature/2026-10-29-nine-key-recent-pin-words-only.md)。

## Verification

合成词库回归在旧实现上确认锁定首候选选择无法进入下一次未锁定候选首位；修复后首位和非首位选择均通过。另覆盖连续替换、锁定上下文的已有首位记录、手动槽位、读法隔离、学习关闭、默认结束组字及分段选择。完整引擎测试、Clippy 和 quick 门禁已通过。Android API 28、35 均完整运行 client-base、client-core、client-providers、client-services 单测，并各通过 163 项九键引擎回归；硬链接用例沿设备 runner 的既有规则跳过。

`NineKeyPanelDeviceSmoke` 的真实软键盘验收使用合成输入交替选择 `mi`、`ni`、`mi`，确认读法内的首候选上屏，重建输入连接后在未锁定候选条的第 1 位读到相同词。`-e recent-learning true` 只跑此路径，默认完整面板验收也包含它。调频设置为关闭，避免全局权重变化掩盖上下文记录缺失。

## Consequences

每次锁定后的显式完整选择最多增加一次日志写入和一次固定位置查询；写入失败仍上屏并返回既有位置诊断。已有第 1 槽不能区分手动和自动，本次沿用原先“后选替换首位”的规则，其它槽位不改。
