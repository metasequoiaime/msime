# Agent Note: Android 快速删除守住组字边界

Status: implemented

## Problem

#9893：组字时上滑删除键，松手路径先取消当前拼音，再调用编辑器光标前全文清空，把此前已提交的文字一并删除。删除键按下时还会先执行一次普通退格；短拼音可能因此在长按计时前消失，连删随后进入已提交正文。

## Decision

按下删除键之前记住这次按压是否已有引擎组字；连删中若发现组字也锁住同一边界。按压碰过组字时，普通退格和长按只处理组字；组字已被删空或取消后，不继续连删编辑器正文。上滑待命松手只取消仍存在的组字，不调用光标前全文清空。没有组字的上滑继续按[原快速删除规则](../feature/2026-10-08-android-backspace-quick-delete.md)处理正文；下滑撤回、普通退格和取消手势沿用各自规则。

## Alternatives considered

- 只在上滑松手时检查当前是否组字：改动少，但按下即退格或长按可能先把短拼音清空，松手时已无法区分本次按压原本针对组字还是正文。
- 把所有上滑都改成只清组字：能彻底避免误删正文，但废除用户已经依赖的光标前全文清空能力。

## Consequences

删除键的一次按压不会从组字跨进已提交正文，短拼音在按下时已经被删空也不例外。代价是组字时启动的长按不会顺带继续删除正文；用户如需清空正文，要松开后再上滑一次。没有组字时的快速删除和撤回保留。

合成编辑器设备用例覆盖「清风」后未上屏 `nihao` 的立即上滑和长按后上滑，也覆盖取消后空格上屏与普通退格。JVM 策略用例守住按压起点与松手状态不同的边界。真实触摸和 `InputConnection` 的执行结果需在 Android 模拟器验收。
