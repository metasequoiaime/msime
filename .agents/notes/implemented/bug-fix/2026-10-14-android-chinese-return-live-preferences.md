# Agent Note: Android 返回中文只记忆实时方案

Status: implemented

## Problem

#7826 的录屏从中文九键进入日语九键，使用一会后返回中文变成全拼 26 键。`onStartInput` 每次先应用 `runtime-options.json` 的出厂偏好副本，再异步读取实时偏好；原先两条路径都调用 `rememberChineseScheme`。副本的中文 26 键覆盖进程内最近的中文入口，随后实时日语不会再更新这份记忆。API 28/35 的修复前设备回归复现了这条路径，API 35 明确捕获返回目标为 26 键。

## Decision

只在实时偏好被接受时更新最近中文入口；启动副本仍能准备会话，但不能作为用户实际选择的证据。`reloadPreferences` 接受的实时中文选择照常更新记忆。真实输入法设备回归从中文九键或 14 键进入英文、日语九键，输入并确认日文后换焦点，每种中文入口重复三次，检查返回目标、实际键面和落盘的入口及布局。

设备套件恢复原有偏好、本机设置、输入模式和默认输入法。专用 AVD 可能保留瘦包的资源目录，因此仅在日文文件缺失时临时复制当前完整 APK 自带的三份日文资源，结束后移除测试补入的文件；已有资源不覆盖。API 28/35 的回归均需带日语资源的完整原生宿主。

## Related notes audit

[中英键轮换](../../implemented/feature/2026-10-10-android-language-key-cycle.md)持有最近中文入口和进程重启回退的决定，保留并互链。本篇只修补副本污染这份记忆的实现。[外语轮换修正](../../implemented/bug-fix/2026-10-14-android-language-switch.md)涉及启用列表和中间帧，保持原语义。剪贴板和皮肤的副本过滤涉及别的状态，不合并。

## Alternatives considered

- 持久化最近中文入口：可覆盖进程被系统杀掉后的返回，且能区分同一引擎的九键和 26 键；但不能阻止仍在运行的服务接受旧副本为最近选择，录屏也未证明发生进程重启，先修复已观察到的来源错误。
- 完全跳过启动副本的方案应用：可以连第一帧都保留原方案；但启动引擎和缺少实时偏好时的回退仍依赖副本，本次只收窄最近中文记忆的更新条件。

## Verification

API 28 修复前在日语换焦点后的中文返回目标处失败，API 35 修复前明确捕获 `Quanpin26` 返回目标。修复后 API 28/35 均完成中文九键及 14 键各三次完整路径，返回目标、真实键面、保存状态与恢复阶段全部通过。完整包采用当前基线重建的 arm64 JNI，核对剥离调试信息后的 JNI 与包内字节一致，十二份词库资源符合当前锁；Gradle 原生宿主构建、签名和 16 KB 对齐核验通过。本地 quick、Android 宿主 Java/JNI 门禁和笔记门禁通过。未验证原 Xiaomi Android 16 真机。

## Consequences

用户在日语中换输入框后仍回到最近的中文入口，启动副本不能再把它改成出厂全拼 26 键。默认关闭轮换、已启用语言的轮换顺序以及用户真实修改中文入口的语义不变。首次运行和进程重启没有中文记忆时仍采用原有引擎方案回退，不扩大存储契约。设备套件必须独占专用 AVD，临时日语资源和恢复操作使每次运行多一次资源复制。
