# Agent Note: 全局语音核心会话按录音轮次释放词库租约

Status: implemented

## Problem

独立录音器的核心句柄跨轮保留，而每个 Host API 会话都持有共享词库租约。录音器与进程同寿命，且不在输入控制器的 quiesce 遍历范围内，因此一次录音后，设置中的词库维护仍拿不到独占锁。

## Decision

核心句柄只属于一轮录音及其最终交付。失败、取消和交付完成先撤销令牌、结束设备与请求，再关闭并清空句柄；交付还在等待时保留本轮。socket 控制方法不依赖核心句柄，排队 stop/cancel 保留原对象及独立的进程内唯一传输租约，不能使用重建后可能重复的核心 generation。

开始录音前与创建句柄后都检查同一份词库 quiesce 租约。活动轮次订阅现有版本隔离维护通知，并以一秒检查兜底；维护出现时取消并释放句柄。空闲时没有会话，也没有维护定时器。原先跨轮持有核心的选择由本篇取代，[独立采集](../architecture/2026-11-03-global-voice-capture-before-imk-delivery.md)的其他提供商及交付决定不变。

## Alternatives considered

- 跨轮保留句柄、只在维护通知时关闭，可以减少建会话成本；但通知遗漏或空闲维护也需要额外常驻状态和检查。每轮释放使空闲时不阻塞维护成为直接不变量，通知与检查只服务活动录音。

## Consequences

每轮重建核心有额外初始化成本，未测量为真实录音延迟。聚焦回归以临时词库和真实文件锁验证录音时互斥、完成与失败后可维护、维护期间不启动、活动维护通知与定时兜底、待交付保持租约，以及连续 socket 轮次隔离。不打开实际麦克风，不修改用户词库或偏好。
