# Agent Note: AI 服务配置按依赖顺序展示

Status: implemented

## Problem

自定义服务的接口地址是 Token 和模型目录的前提，却藏在更多选项里。空地址导致凭据禁用，原因显示在 Token 下方，用户必须跳过凭据和模型再找地址。提示词的长说明与大输入框同时展开，遮住连接测试。

## Decision

服务配置始终按服务商、接口地址、凭据、模型、获取模型列表排列。有效性只更新地址说明与依赖控件的禁用状态，不搬动地址输入框，不因输入变有效而收起内容。自定义提示词单独折叠，保留当前槽位及全量替换、JSON 输出约束，缩短说明和初始高度。

这部分取代[设置页裁剪](../../implemented/simplification/2026-10-16-macos-tools-support-settings-prune.md)中把接口地址和模型目录一起藏入更多选项的决定；当前槽位、桌面测试和候选数量边界继续适用。

## 历史检索

设置页裁剪与本篇部分重叠并互链；AI 凭据编辑器、模型选择状态和 endpoint 安全策略继续各自负责保存、安全和编辑状态，不在本篇翻转。检索命中的原生 Windows、iOS 与 Android 决策不属于这份共享页面布局。

## Alternatives considered

- 仅自定义服务显示地址：预设服务更短，但改成代理或预设地址无效时，凭据仍依赖折叠内的前提。统一顺序让用户先确认凭据送往哪里。
- 地址无效时自动提到上面：正常状态最紧凑，但输入从无效变有效会搬动输入节点并丢失焦点。

## Consequences

基础配置无需展开，错误原因紧贴地址；有效性变化保留同一个输入节点，Token 与模型目录继续受 origin 校验保护。预设服务多占地址与目录两行，换来明确的配置与凭据目标。不改变 URL 策略、凭据按 origin 绑定或服务商切换保留自定义值的逻辑。

提示词默认收起；说明保留留空回退、全量替换和 JSON 候选要求，当前槽位及其他槽位不被重置。

## Verification

44 项定向测试通过，覆盖预设与自定义地址的可访问性、配置顺序、连续地址输入的焦点、Token/模型目录禁用状态、当前提示词槽位和菜单内部滚动。类型检查、生产构建、定向 lint、格式检查、`verify-notes` 与本地 quick 门禁通过；quick 的 Linux 原生宿主 90 项测试通过，缺少工具链的 Windows 原生完整构建和鸿蒙 ArkTS 工程编译按脚本跳过。

合成浏览器验收覆盖空值、合法与非法 URL、模型获取、Token 按服务地址保留、预设往返切换、提示词槽位，以及 1000×780 浅色和 800×600 深色布局。没有页面异常或横向溢出。

macOS 设置应用已重新打包安装并通过严格签名校验；实际窗口确认基础配置直接可见、提示词单独展开和服务商菜单可用。原生输入法 bundle 沿用已安装版本，真实服务凭据不做修改或网络测试。菜单的滚动边界归属见[服务商图标菜单](../feature/2026-10-19-ai-provider-icons.md)。
