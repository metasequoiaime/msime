# Agent Note: 双拼纯声母串参与整句组词

Status: implemented

## Problem

#11766：小鹤双拼输入 `m't't'q'z'm'y`（7 个声母、没有任何完整音节）时，候选只剩 `mtt` 前缀组的三字词（慢吞吞、煤炭厅、木酮糖……），整句「明天天气怎么样」根本不存在。旧 C++ 引擎有一条 Google 整句解码路径能出这条整句；Rust 移植去掉了它，整句改由双拼词网格组。

#11564 让带有完整音节的混输串走进词网格，但笔记里明确保留了「纯声母整串的既有行为」：`has_mixed_initials` 要求至少一个完整音节当锚点，否则仍调用只认完整音节的 `query_lattice_span`，纯声母串一条词边都建不出来。

## Decision

双拼整句准入不再要求完整音节锚点：输入至少两段、每段是完整音节或严格声母（`is_prefix` 且 `extract_initial_token` 等于整段）、且至少一段不是完整音节时，就走 `query_lattice_span_with_mixed_initials`。纯声母串因此与「完整音节 + 声母」的混输串共用同一条词网格路径；完整音节串不受影响，仍走精确的 `query_lattice_span_with_trailing_initial`。

不变的部分：声母严格匹配（`z` 不配 `zh`、`c` 不配 `ch`、`s` 不配 `sh`）；完整音节只配规范化后的同一音节；词边携带词库完整读音和相同音节数；按键消费沿用混输路径；整句开关（`sentence_association.word_lattice`）关掉时纯声母串没有整句候选；单键和短前缀的缩写直查仍排在整句之前；句中辅助码约束（`generate_constrained_sentences`）与整句共用同一份准入。

跨度查询仍逐段按 `jp` 索引扫描，每段只匹配首字母相同的完整音节，不枚举声母对应完整音节的笛卡尔积；纯声母串的查询量与同音节数的完整音节输入同量级。

## Alternatives considered

- 另开一条「所有段都是声母」的准入函数，`has_mixed_initials` 原样不动：两处判断会把「完整音节 + 声母」和「纯声母」的边界各写一遍，之后改准入要同步两处；合并成一条谓词后，整句、约束整句和前缀回退自动共享同一个边界。
- 复用全拼的不完整跨度查询（`quanpin` 的单字母匹配与末段前缀补全）：单字母会跨平翘舌匹配（`z` 配 `zh`、`c` 配 `ch`、`s` 配 `sh`），末段前缀补全还会扩大已经定出的音节，与双拼音节语义不符；#11564 已否掉同一个方案。
- 恢复 C++ 的 Google 整句解码器：需要额外模型和词表，而 Rust 侧整句已由词网格承担；纯声母串缺的只是准入，不是新的解码器。
- 只在候选列表前插入整句、跳过词网格：排序、学习与按键消费都要另写一套，而且句中辅助码无法参与约束。

## Verification

合成词库（明天、天气、怎么样三行）的回归 `pure_initial_string_decodes_the_whole_sentence`：`mttqzmy`、自动分段的 `m't't'q'z'm'y`、含一个完整音节的 `mttqizmy` 三种输入的首选都是「明天天气怎么样」，带整句标记、完整读音和 7 个汉字；同一用例在原实现上首选是「明天」（只有两字前缀）。既有混输、末尾声母、五种内置方案、辅助码、缓存与整句开关用例保持通过；`cargo test -p msime-engine --lib` 全量通过。

未验证：Windows TSF 宿主上的实际候选窗口排序与按键消费（本机没有 Windows 主机）；真实发行词库上的首选排序只按合成词库验证行为，没有用 `MSIME_EVAL_RESOURCES` 的发布词库跑评测。

## Consequences

纯声母串能拼出整句，首选回到旧版位置，前缀组三字词退到后面。整句开关打开时，纯声母输入（包括常见的两键缩写）每条会多出与完整音节输入同量级的跨度扫描；开关关闭时行为不变。排序仍由词网格的 n 元和词频打分决定，本修复不保证每一串纯声母上的首选都符合用户意图。
