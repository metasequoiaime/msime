# Agent Note: 符号面板的成对符号不分在两行

Status: implemented

## Problem

维护者在 iOS 键盘的符号面板「常用」里看到「（」排在一行的最后一格、「）」排到下一行开头，指出成对的括号不能换行。

三端的符号面板都是每行五格，而写死的列表是按每行十个写的，成对符号落在奇数位置时就会拆开。按改动前的列表数：「中文」拆开了（）、〈〉、＜＞，「英文」拆开了 < >，iOS 和鸿蒙「常用」的默认 30 个拆开了（）。iOS 和 Android 的「常用」前面接的是点过的符号，Engine 目录和符号集插件的顺序来自数据，这几类列表的顺序都不固定，单靠调整写死的列表挡不住。

## Decision

两层同时做：

- **排版规则（三端相同）**：排到一行最后一格的符号是成对符号的前半个、后半个又紧跟在它后面时，这一格留空，两半一起排到下一行。成对与否用面板点前半个时补后半个的同一张表（Android `PairedPunctuationPolicy.SYMBOL_PAIRS`，iOS `NineKeySidebar.pairedSymbols`，鸿蒙 `PairedPunctuationPolicy` 的 `LITERAL_PAIRS`），不另立一张。
  - Android：`SymbolPanelModel.breaksBeforePair` 判定，`SymbolPanelView.appendRows` 在放不下长条目要换行的同一处换行并补空格。
  - iOS：`KeyboardSymbolPanelView.rows(_:)` 分行，`show` 按它画。
  - 鸿蒙：`SymbolPanelPolicy.cells` 给出带空格的格子序列，`""` 是只占位、不画键的一格。
- **写死的列表重排，本身不留空格**：每行五格，成对的括号和引号两两占左边四格，最右一格放单个符号；单个符号和成对符号各自的先后顺序不变。「中文」的 79 个符号一个不少，「英文」把 `/` 挪到 `<` 前面，iOS 与鸿蒙的「常用」默认 30 个把 `～`、`￥` 各前移一格。三端的「中文」「英文」逐项相同，iOS 与鸿蒙的「常用」默认内容逐项相同。

ASCII 的 `<` `>` 不在配对表里（`<` 多作小于号），排版规则管不到它们，只靠「英文」列表的顺序避开。

### Android 目录分页按实际排版续排

Android 的 Engine 目录分页加载，下一页到达时要从上一页最后那一行的开头重排。原来按「已显示条数 ÷ 列数」推算这一行从第几个条目、第几个子视图开始，这只在每个条目恰好占一格时成立：成对符号留出的空格会让推算错位，跨列的长条目本来就让它不准。现在 `appendRows` 每开一行就记下这一行的起始条目、起始子视图和行号，分页从记下的位置续排；偏旁分组的下一行也改用 `appendRows` 的返回值，不再按条数推算。

## Alternatives considered

- **只重排写死的列表，不加排版规则。** 改动最小，写死的分类看起来都对；但 iOS、Android 的「常用」把点过的符号接在前面，位置随使用记录变化，截图里的问题正好就出在这里，Engine 目录和插件的顺序也不归这里管。
- **只加排版规则，不动列表。** 所有列表都不再拆开成对符号；但「中文」会留下 4 个空格，满屏的符号中间缺一格，看起来像漏了一个符号。
- **前半个落在行尾时与下一个单个符号对调，而不是留空。** 不留空格；但会改变用户点过的符号在「常用」里的先后，目录里的顺序也不再是数据给的顺序，而且后面紧跟的可能还是一对，要连环调整。

## Consequences

- 收益：任何分类、任何使用记录下，成对符号的两半都在同一行，长按前半个只输入半个、点一下输入整对的位置一目了然；写死的分类仍是满格。Android 目录分页的续排位置由实际排版给出，不再受跨列条目影响。
- 代价：「中文」的顺序变了，单个符号被分散到各行最右一格，用过旧顺序的人要重新找一下；「常用」或目录里遇到行尾的前半个时会多出一个空格。三端各有一份列表和一份排版函数，改顺序时要三处一起改，测试只分别核对各自不留空格，三端逐项一致还没有自动检查。

## Verification

- Android：按 `check-host.sh` 的源码集合在本机 `javac --release 17 -Xlint:all -Werror` 编译通过，317 个 JVM 冒烟全部通过；`SymbolPanelModelSmoke` 断言每个写死的分类不留空格、「中文」仍是 79 个，以及行尾前半个换行、放得下的一对不动、前半个后面不是它的后半个时不动。
- 鸿蒙：`platforms/harmony/tests/run.sh` 通过；`SymbolPanelPolicy` 组断言同样的情形。把 `cells` 里留空的那一句改掉后该组失败，确认断言拦得住回归。
- iOS：`swiftc -parse` 通过；`testSymbolPanelKeepsPairedSymbolsOnOneRow` 断言写死分类每行满五格、行尾前半个换行、「常用」接上点过的符号后没有一行以前半个结尾。XCTest 需要模拟器，交给 CI 的 iOS Simulator。
- 三端「中文」「英文」与 iOS、鸿蒙「常用」逐项相同、五列下不留空格，用一次性脚本比对过。
- 未在真机或模拟器上看过面板。
