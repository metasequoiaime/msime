# Agent Note: Android 9 预览前固定输入法窗口边界

Status: implemented

## Problem

API 28 的设备 CI 在全文预览打开后丢失编辑器焦点。独立探针在运行 `39981119651` 记录到 `View.layout` 经 `clearFocusInternal` 清除焦点，窗口焦点仍在；等待夹具就绪、清除无障碍缓存、用原屏幕坐标计算最终 insets 都不能消除该失败。

Android 9 的 `ViewRootImpl` 只在首次添加或可见性改变时将内部 insets 标记为待定；已显示窗口单纯扩高时，系统先用原来的相对 insets 布局后方应用。停靠小窗口的顶部 inset 为零，扩到全屏后这一旧值会短暂把应用压到零高，后续正确的 insets 不能恢复已丢失的输入框焦点。

检索审计：[浮动键盘](../../implemented/feature/2026-10-08-android-floating-keyboard.md)与本片部分重叠，其中一直铺满窗口的方案此前因停靠布局风险被否；本片仅翻转 API 28 的窗口实现，其余系统沿用原决定。[全文预览](../../implemented/feature/2026-10-20-android-clipboard-card-preview.md)与本片部分重叠，保留非焦点子窗口、触摸穿透、底部键区及清理契约。[设备 CI 回归](../../implemented/bug-fix/2026-10-22-android-device-ci-regressions.md)继续持有测试探针、模型槽位和夹具就绪契约。

## Decision

API 28 从输入法窗口首次显示起就使用透明的全高父窗口，停靠键区包裹内容并贴底；预览打开、关闭时不再改变已显示父窗口的高度。正常停靠仍通过键区上沿提供应用避让，通过键区矩形提供触摸区域，浮动键盘及跟随光标模式继续让应用不避让。

停靠背景只绘制键区所在的底部横带，保留平板居中键区两侧原有的背景色；上方保持透明。预览期间继续固定原键区高度与屏幕上沿。窗口全高与浮动表面是两个独立状态，浮动切换仍须重新应用表面宽度、高度及定位。

## Alternatives considered

- **扩窗后再修正 insets**：改动较小，最终应用避让也正确；但真实 CI 的调用链证明布局过程中已经清除了焦点，最终坐标无法补救。
- **先发布未来窗口所需的 insets，再扩窗**：不必保持全高窗口；但发布时仍处于小窗口坐标系，会先让应用临时扩大，再缩回，不能保持编辑器几何稳定。
- **所有系统都使用全高窗口**：统一布局路径；但当前证据只确认 Android 9 的过渡问题，扩大到其他系统会重复原浮动键盘笔记记录的风险，因此仅处理 API 28。

## Testing

- 必须在 API 28 从真实输入框启动键盘并检查普通与密码框切换、全文预览、卡片横滑及 AI 设置；预览前后核对实际焦点、窗口焦点、编辑器和卡片边界。
- 最终原生 APK 在本机 API 35 arm64 依次通过 `DeviceSmoke`、常用语提示、完整 `ClipboardSegmentDragDeviceSmoke` 和 `AiEndpointCheckDeviceSmoke`。完整 CI 的 API 28、35 x86_64 设备任务继续覆盖不同架构的布局时序。
- 平板停靠的背景横带与浮动状态分离，不把应用上方涂成键盘背景，不扩展触摸区域。

## Consequences

固定父窗口高度消除预览开关引起的扩窗过渡，保留停靠避让和透明区域触摸穿透。代价是 API 28 的停靠表面从父窗口定高改为内容包裹，并维护只绘制底部横带的背景；面板测量及背景绘制需要设备验收，不能把编译通过当成几何与触摸验证。
