# Agent Note: 鸿蒙读音行提供真正的拼写编辑菜单

Status: implemented

## Problem

#10689 真机复审发现，原实现只把弱化读音改成带光标的文字，仍需退格重打或知道空格拖动手势。#10591 明确要求 Android 编辑条或 iOS 的三项编辑菜单，只有光标显示不满足入口的行为。硬件 Home/End 有候选时另有候选首尾语义，不能直接复用。

## Decision

读音行打开原生菜单，与 iOS 一致提供「光标移到开头」「光标移到末尾」「删除光标后的字母」。无效动作保留并禁用；菜单留在键盘窗口内，点外面关闭。菜单分发经独立策略和 ArkUI 适配器，宿主仅接线；开头与末尾调用引擎的组字命令，不经过候选翻页。组字结束或方案不允许编辑时关闭菜单，点击动作时再次检查能否编辑。

读音行的触摸范围向下覆盖原有间距，不改行高，不覆盖候选；本地模式只有触发符、尚无拼写内容时不接触摸。14/18 键留在候选栏的读音及锁光标方案沿用原来的不可编辑规则。

这部分取代[原读音行决策](../feature/2026-11-02-harmony-pronunciation-row-edit.md)中「只展开、不提供菜单」的选择；弱化提示、2in1 边界、网格方案显示规则继续成立。

## Historical audit

- [手机读音行点按范围](2026-11-02-mobile-preedit-tap-target.md)：部分重叠，沿用整段宽度和间距命中，不改 Android/iOS。
- [按组码对齐光标](2026-11-05-caret-alignment-by-grid-keypad.md)：无冲突，鸿蒙网格方案继续不开放这个入口。

## Alternatives considered

- 保留只画光标的实现：改动最少，而且空格拖动已经能移动光标；但不能替代 issue 要求的可发现入口。
- 仿 Android 增加放大编辑条：直接点字母定位更方便；需要额外处理布局、选区和关闭周期。本次选用 issue 已允许的 iOS 菜单，复用原生菜单语义及现有引擎命令。

## Consequences

触屏可以明确跳到拼写开头或末尾并向后删除，候选和组字编辑语义保持分离。菜单会暂时覆盖键盘的一部分，关闭后恢复按键；不新增偏好、默认值或协议。

行为测试覆盖三项可用状态、动作分发、空组字和本地模式标题（21 + 9 条断言）。实际 ArkTS 完整包编译、签名覆盖安装成功；鸿蒙真机已验证菜单的禁用状态、开头跳转、向后删除首字母、补回字母、末尾跳转、读音行下方间距点开、点外部关闭和候选上屏。完整 quick 通过。首轮门禁指出 `Array.from` 在 ArkTS 的字符拆分差异，已改用统一 `TextPolicy.characters` 后复跑通过。截图保留在验收目录并随 PR 附上；网格方案和 2in1 仍由策略测试覆盖，不把普通 26 键实测写成这些场景的真机验收。
