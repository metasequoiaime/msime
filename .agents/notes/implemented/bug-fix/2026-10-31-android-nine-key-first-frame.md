# Agent Note: Android 九键首帧不被旧 26 键视图覆盖

Status: implemented

## Problem

Android 键盘切换到水杉时，`runtime-options.json` 里的启动缓存可能先创建出 26 键 `view`，实时偏好中的九键设置随后才到达。宿主虽然已经持久化了上次确认的触屏布局，但 `displayedTouchLayout` 会在实时偏好尚未应用时立即采信这份旧视图并把 26 键写回提示，于是九键用户在第一次弹出或切换输入法时短暂看到 26 键。诊断包能确认报告者的实时配置是 `nine_key`，但不包含首帧布局事件，因此修复边界必须由生命周期和视图状态保证。

## Decision

`MSIMEInputService.displayedTouchLayout` 通过 `TouchLayoutHintPolicy` 选择首帧键面。没有引擎视图时继续使用已记住的布局；实时偏好已经应用、引擎返回非标准网格、本地模式或非全拼/双拼方案时，以引擎视图为准。实时偏好到达前，全拼和双拼的标准 26 键启动缓存不能覆盖已记住的九键提示；标准键面仍可在偏好应用后由真实视图更新并持久化。专用英文模式始终使用标准 26 键。

策略保持只读视图判断与持久化分离：未确认的全拼/双拼标准视图不会写回 `touch_layout`，避免把启动缓存污染成新的 26 键提示。14 键、18 键、九键双拼以及其他方案的非标准或有上下文视图仍会立即记忆真实布局。

## Alternatives considered

- **只继续依赖现有的单个布局提示**：提示在视图为空时有效，但会被实时偏好到达前的启动缓存覆盖，不能解释报告者的重复复现，因此不采用。
- **在首帧前同步阻塞读取完整偏好**：可以避免旧视图，但会把文件读取和词库准备延迟放到输入法主线程，增加键盘弹出卡顿；本次只修正视图信任边界，不改变会话启动时序。
- **让所有未就绪视图都服从提示**：会把本地模式、其他语言以及 14/18 键的真实上下文误判成中文九键；因此只对全拼/双拼的标准启动视图使用提示。

## Consequences

键盘切换时，已确认的九键不会被启动缓存的 26 键短暂覆盖；无历史提示时仍按标准 26 键安全回退。实时偏好到达后，真实引擎视图恢复最高优先级，布局切换、英文模式、本地模式、14/18 键和其他语言不会被旧提示锁住。新增的纯逻辑冒烟测试固定了这些优先级边界；真实 Android 编辑器验收仍由设备门禁完成。
