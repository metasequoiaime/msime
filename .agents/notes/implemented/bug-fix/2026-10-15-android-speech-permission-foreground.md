# Agent Note: Android 语音权限拒绝后等待前台恢复再重试

Status: implemented

## Problem

小米设备在 Android 0.4.1 上仍返回错误码 9，截图显示水杉输入法的麦克风权限已经允许。旧提示和[键区语音笔记](../../implemented/bug-fix/2026-10-08-android-platform-voice-in-keyboard.md)把水杉有运行时权限推导成「缺权限的只能是识别服务应用」，没有覆盖 AppOps 和前台录音状态，无法据此定位这台设备的拒绝来源。

[AOSP RecognitionService](https://android.googlesource.com/platform/frameworks/base/+/ad87e5684837ac2dea585428a723e631273fdd40/core/java/android/speech/RecognitionService.java) 先调用服务的 `onStartListening`，随后才检查录音权限交付；服务可能先发送 `onReadyForSpeech`，再被框架用错误码 9 结束。现有键区入口把 ready 当成不必再重试的证据，跳过前台窗口。窗口本身又在 `onCreate` 或授权回调里立即开始录音，没有等待 `onResume`。

## Decision

HTTP 整句上传进入键盘及必要窗口的自动结果回传由[语音自动上屏](2026-10-21-android-voice-auto-insert.md)补充；本篇的系统识别和权限恢复约束继续适用。

权限拒绝无论是否 ready 都只转交前台窗口一次；主动结束后不重试。客户端错误与服务断开仍只在 ready 前重试，网络和没有听到声音不扩大重试范围。

识别窗口用待启动标志和恢复标志等待 `onResume` 后启动。授权回调只在已恢复时消费请求，否则交给下一次恢复；消费后清除标志，避免恢复重复启动。等待期间主动停止或取消会撤销待启动请求并结束窗口，恢复和后续授权不能重新开始录音。该窗口的系统、本地与上传识别统一遵守前台录音时机。

系统识别器创建、绑定或启动时同步抛出的 `SecurityException` 按错误码 9 处理，其他运行时启动异常按客户端错误处理；先清除并释放失败的识别器，再结束请求，避免清理阶段再次调用失败实例。旧系统直接绑定权限受限服务就能触发这个同步拒绝，不能仅依赖异步 `onError`。

错误码 9 只提示「录音权限被拒绝」，保留错误码和本地模型、豆包的替代路径，不再查包名并断言缺权限的是某个应用。替代识别仍需要水杉录音权限，不能绕过系统的全局麦克风禁用；本次不自动切换服务商。

## Alternatives considered

- **保留点名服务应用，并提供跳转应用权限设置**：用户可以直接找到应用，确实缺运行时权限时最方便；但截图不能证明服务一侧缺权限，AppOps 或前台状态被拒时继续让用户开权限会误导，所以先修复重试边界和时机。
- **权限失败后改用 `ACTION_RECOGNIZE_SPEECH` 的外部识别界面**：可由服务应用自己持有录音界面，避开部分调用方状态限制；但设备可能只提供服务而不提供界面，当前也没有证据表明小米必须走这条路径，因此不扩展外部界面和结果交接生命周期。
- **延迟固定几百毫秒再录音**：改动更小；但延迟不能证明 Activity 已恢复，授权弹窗、锁屏或系统调度都可能超过延迟，使用生命周期信号更明确。

## Verification

`bash platforms/android/check-host.sh` 通过 231 个 JVM 冒烟；覆盖 ready 后权限失败仍重试、主动结束不重试、其他错误不扩大重试和两行提示边界。原生宿主 `assembleFullRelease` 构建通过；本次 Java 改动复用已暂存的 JNI 库和资源，不声称重建了 Rust 原生库。

`bash platforms/android/tests/device/voice-lifecycle.sh emulator-5566` 与 `emulator-5580` 在 API 28、35 上通过。用例在真实 Activity 创建时断言识别器尚未创建，恢复后断言已创建；合成服务先发 ready 再报错误码 9，并通过广播确认确实执行了这组回调，最后检查请求结束。另验证恢复前停止不会启动识别器，并清除活动请求；API 28 额外选择绑定权限受限的服务，验证同步拒绝不会崩溃或留下活动请求。旧实现的设备安装包会触发「Recognizer started before resume」断言。

Android 11 及以前由调用应用直接绑定服务，测试提供用录音权限保护的独立入口；新版本由系统代理绑定使用 `BIND_SPEECH_RECOGNITION_SERVICE` 的入口。两个合成入口默认禁用，启停由测试包自己的 UID 执行，避免依赖 shell 改组件状态的特权；测试结束后再次禁用并恢复默认服务和宿主、测试包原有的麦克风授权布尔状态，清理失败仍继续其他恢复步骤并报告失败。API 28 在测试前撤销两包授权，运行后核对两包仍未授权、默认服务未改变，再还原验证前状态。合成服务不访问麦克风或网络。

`pnpm run verify-notes`、`git diff --check` 与 `bash scripts/verify-local.sh --quick` 通过。

## Consequences

权限链晚于 ready 被拒时不再丢掉前台重试；窗口等待恢复再录音，重复恢复不会重新消费已经启动的请求。权限提示保留错误码并移除无法证明的服务应用归因，仍需系统允许水杉和识别服务录音。

该决定部分取代旧键区语音笔记的权限归因与重试边界，其余键区聆听、音量和结果交接继续成立。代价是恢复之前不开始录音，前台重试仍可能遭遇服务本身的策略拒绝。

本机只有 AOSP 模拟器，没有报告中的小米真机。修复覆盖代码中确认存在的重试遗漏和启动时机；不能据此宣称解决小米系统语音引擎自身的所有权限策略。真机仍失败时需要机型、系统版本和服务权限状态继续定位。
