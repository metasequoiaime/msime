# Agent Note: 快捷模式不接受的字符保留原文并交还宿主

Status: implemented

## Problem

#8043：Unicode、日期时间、快捷短语等模式把不接受的字符标记为已处理，既不进入预编辑，也不上屏或交还应用。`Shift+U` 后输入 `I` 只剩 `U`，造成输入丢失。参考实现的 `local_unicode_edges` 黄金场景保留了同样的吞键行为。

## Decision

只修改 `InputSession::handle_local_character` 的通用拒绝分支：复用原样提交路径保留当前可见预编辑及入口字母、清空组字与上下文，再以 `handled = false` 交还当前按键。模式支持的字符继续拼写。临时英文、临时日文和网址对不在字符集内的键有独立拒绝分支，保留现有语义；标点路由和数字选词不改。共享引擎负责判定，宿主按现有先提交结果、再处理未消费按键的协议工作。

本篇与 [Shift 入口开关](../../implemented/feature/2026-10-11-shift-letter-entry-switch.md)及[拆字模式](../../implemented/feature/2026-10-13-builtin-chaizi-mode.md)部分相关，但不改变模式入口或接受字符集。#8035 管理连续大写和临时模式回车入口字母，独立交付，不把它的改动复制进本分支。

## Alternatives considered

- **把拒绝字符追加进模式原文**：用户不会丢字，也保留继续编辑的机会；但模式既不识别这些键，就不应继续占用按键，退出并透传更符合 issue 明确要求。
- **只返回 `unhandled`**：改动最小，临时模式已有这种规则；但其他本地模式的原文仍留在组字中，下一次输入和应用中的光标顺序继续受旧模式干扰。
- **逐宿主重放字符**：可按原生事件精确透传；但共享结果已经支持提交文本同时不消费当前键，另加重放会引入多端重复输入风险。

## Verification

引擎回归在旧实现上以 `U rejected i` 失败，修复后通过。引擎单元测试 2113 项（既有忽略 20 项）、runtime 288 项和黄金测试 31 项通过，其中完整脚本回放覆盖 300 个场景。未提供真实词库目录，不把真实词库基准的跳过视为完成验证。

回归覆盖 10 种入口、大小写拒绝、原文前缀及合法拼写控制、模式长度上限、临时语言拒绝时保留状态。真实引擎的 runtime 回归覆盖 `U+i/I`、`K+A`、`T+A`、表情模式数字、字符路由标点，以及原有中文标点路由；已有提交文本不再被后续标点回退丢弃。7 个黄金场景只更新拒绝按键及随后空组字取消／退格的期望，其余步骤保留原断言；场景注释和黄金说明记录与固定参考的差异。

`cargo clippy -p msime-engine -p msime-input-runtime --all-targets -- -D warnings`、`cargo fmt --all --check`、`pnpm run verify-notes`、`git diff --check` 和本地 quick 门禁通过。quick 包含 Android 目标与 Java 宿主检查、Wasm、Windows x64 原生链接及共享壳交叉检查、macOS 宿主和共享 Apple 桥接编译；Linux 容器检查因 Docker 不可用而跳过，HarmonyOS 因构建依赖未暂存而跳过。这些编译结果不替代真实编辑器的系统入口验收。

## Consequences

光标入口由[光标拒绝键的提交与透传](2026-10-16-local-caret-rejected-keys.md)补齐；本篇继续持有末尾拒绝语义与临时模式例外。

包括网址在内的模式达到长度上限时同样进入通用拒绝分支，因此提交已保留的原文并透传后续键，避免超过上限的键被静默丢弃。原样提交不选择候选，也不把拒绝字符学进词库。
