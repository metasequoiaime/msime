# Agent Note: 桌面数据树复制绑定目录句柄

Status: implemented

## Problem

桌面设置迁移会递归复制用户数据树。旧实现把每一级源和目标都重新解析为路径；迁移过程中目标父目录被替换时，复制可能跟随新的路径指向。目录树还需要拒绝符号链接和特殊文件，并保留原有权限。macOS 的目录枚举会返回 `.` 与 `..`，句柄递归若把它们当作普通子项会在目标上重复创建当前目录并失败。

## Decision

Unix 平台的复制从一次打开并校验过的源、目标父目录句柄开始。每一级目录使用 `openat`、`mkdirat` 和 `O_NOFOLLOW`，文件使用相同父目录句柄创建并写入；源条目通过 `fstat` 限制为普通文件或目录，目录和文件权限通过 `fchmod` 保留。递归枚举显式跳过 `.` 与 `..`，并继续使用调用方的跳过谓词。非 Unix 平台保留原有路径实现。

## Alternatives considered

- 继续在递归中拼接路径并在每次操作前重新检查父目录：实现改动较小，但检查与使用之间仍有竞态，不能保证复制写入最初选定的目标目录。
- 先把整棵树读入内存再一次性写入：可以减少部分路径交错，但会放大内存占用，也无法替代目标父目录句柄绑定。
- 只为顶层复制打开句柄、内部继续使用路径：能覆盖最外层替换，却仍允许嵌套目录在复制期间被重定向，因此不满足递归数据树的边界要求。

## Consequences

复制操作在 Unix 上不再跟随被替换的目标父目录，且不会复制符号链接、FIFO 等特殊条目；目录树和权限复制行为由单元测试覆盖。实现依赖 `rustix` 的 Unix 文件描述符 API，代码比路径实现更长；macOS 的 `Dir` 枚举返回的点目录必须显式过滤。非 Unix 平台仍使用原有实现，保持现有平台兼容范围。
