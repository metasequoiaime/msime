# Agent Note: iOS 九键拼音侧栏隔离排列约束

Status: implemented

## Problem

[按键渲染预算](2026-10-18-ios-keystroke-render-budget.md)已经避免整套九键网格约束随拼音侧栏显隐重建，但侧栏自身仍由竖向 `UIStackView` 排列复用按钮。真实扩展分段测量中，每句首键的拼音更新与后续布局集中出现长耗时；文档代理同步调用和 `KeyboardKeyButton.layoutSubviews` 自身不是这段耗时的主要来源。

## Decision

九键侧栏用固定宽度的 `KeyboardSpellingScrollView` 直接竖排按钮，按按钮固有高度和原有 6 pt 间距设置 `frame` 与 `contentSize`。按钮按位置复用，列表变化时重排，视图宽度变化时重新适配；隐藏按钮不占滚动范围。十四键横向拼音条保留原来的 `UIStackView`。拼音按钮配置在本地组合完后只赋值一次，避免连续重写背景配置。

该决定只改变侧栏内部的排列方式，不替代[会话拥有线程](2026-10-19-ios-nine-key-owned-thread.md)的后台查询、快照代次和输入顺序契约。

## Alternatives considered

- 只合并按钮配置：改动小，真机试验确实降低局部更新耗时，但后续布局和整体长帧没有稳定改善，不能单独作为卡顿解决方案。
- 保留竖向 `UIStackView`：UIKit 自动处理固有高度和滚动范围，维护成本低；同包对照显示完整候选方案降低句首更新、后续布局和整键主线程耗时，因此采用隔离后的排列方式。

## Consequences

减少侧栏按钮变化牵动的排列约束，保留原有按钮动作、读屏标识、文字样式与滚动行为。代价是宿主自己维护滚动范围和宽度变化，回归同时检查隐藏按钮不留空白、重新显示及变宽后的可点按区域。候选栏和十四键横排仍使用各自原来的布局方式。

## Verification

iPhone 17 / iOS 27.0.1，同一 Release 包中的 A/B/B/A 对照，每轮 279 个合成数字，目标间隔 40 ms，不等待上一键完成；四轮都启用后台九键查询、释义和 9 个候选。A 是原侧栏，B 同时采用手动排列和一次配置赋值。底层原生库从分支基线 `3ca43cb9be` 重编，不混用上一阶段的旧接口产物。

温度状态相同的前三轮中，拼音更新 P95 从 5.05 ms 降到 1.65 / 1.91 ms；主线程和候选完成布局也一起降低。末轮升温，单列其数据，不把四轮都称作正常温度。所有轮次均完成 279 个数字，B 两轮最多积压 2 / 1 键。四轮帧间隔 P95 都为 16.67 ms，B 两轮的最大帧间隔较小，但仍有约 40 ms 的最大帧间隔，不能宣称完全消除卡顿。

这些时间包含主线程按键动作、快照绘制及显式同步布局，不含物理触摸传递和像素显示。自动化仅在合成脚本完成后读取一次结果，避免输入期间反复查询无障碍树。更早的配置写入单独试验和手动排列单独试验处于热状态 2、轮次漂移明显，不与本表跨包比较，也不据此给单项优化分摊收益。性能数据留在忽略的 `target/ios/ninekey-spelling-final-cold-abba.json`；临时探针和保亮改动不进入生产源码。

模拟器上 28 项相关回归通过，覆盖拼音侧栏显隐、按钮复用、展开候选里的拼音选择、数字侧栏、十四键与候选字号；新增滚动范围测试检查长列表、隐藏后恢复和宽度变化。

正常 Release 真机系统键盘的重复输入用例通过：三轮 12 句、117 个数字，交替空格和候选提交，仅留下汉字且没有残留组字。该用例等待界面空闲，只验证功能链路，不当作快速输入性能结果。

新增真机侧栏用例另做三轮 `64426`：每轮点选 `ni` 拼音、提交候选，检查侧栏恢复后的可点按区域、提交后的隐藏与纯汉字上屏，全部通过。正常包签名校验通过，扩展二进制不含临时探针符号。本地 quick 门禁通过。
