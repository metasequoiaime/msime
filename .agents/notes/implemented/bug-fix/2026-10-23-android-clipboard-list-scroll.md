# Agent Note: 剪贴板卡片把纵向手势交给列表

Status: implemented

## Problem

#9341：长文本卡片内部滚动抢走纵向手势，用户只能从卡片之间的空隙拖动列表。#9029 已提供长按打开的全文浮层，卡片内部继续滚动不再是阅读长文本的唯一入口。

检索 `ClipboardPreviewButton`、卡片内滚动和 #9029，命中[卡片与全文预览](../../implemented/feature/2026-10-20-android-clipboard-card-preview.md)，与本片部分重叠。本片翻转卡片内滚动的决定，原文保留当时取舍；全文浮层、窗口裁剪和生命周期约束继续成立。[左滑删除](../../implemented/feature/2026-10-09-android-clipboard-swipe-delete.md)继续持有横滑规则，不改其阈值和动画。

## Decision

删除卡片专属的纵向滚动控件，恢复三行省略的普通键帽。纵向滑动统一交给外层列表，全文只在长按后的浮层滚动；保留本机卡片点按插入、长按管理和左滑删除，云端卡片使用同一个固定摘要工厂，长按复用只读全文浮层，保留查看原文的入口。完整文本仍保留在视图文本和原动作闭包中，省略只影响绘制。普通按钮显式关闭自动大写，保留原文显示，避免失去原控件构造器里的这项设置。

## Alternatives considered

- 保留卡片内部滚动，调高阈值或改成双指：长文仍可就地阅读，但普通纵向拖动仍有两种含义，且既有浮层已经提供完整阅读入口，增加手势学习成本没有必要。
- 只停用触摸滚动，保留卡片的无障碍滚动：读屏仍可直接翻阅全文，但控件继续维护完整长文布局和独立滚动状态；统一使用现成浮层能同时删除这套状态。

## Consequences

纵向手势只对应列表滚动，卡片不再维护独立滚动状态和无障碍翻页，删除专属控件后也减少一套触摸分流。点按和长按继续由普通键帽处理，左滑仍交给既有监听；正文绘制省略不改变原始记录或插入动作。

上方可用空间不足 96dp 时原浮层不显示，取消卡片内部滚动后也没有该备用阅读入口，仍可使用既有编辑操作查看全文；不在本片扩大浮层或改变窗口策略。云端卡片新增同一个只读浮层的长按入口，没有本机管理操作。

## Verification

- 旧 APK 的 API 28 固定卡片专项确定失败：长卡片仍提供独立滚动动作。
- 修复后 API 28/35 的 `ClipboardSegmentDragDeviceSmoke -e fixed-cards-only true` 通过：20 条多行合成记录从卡片正文起手拖动，外层列表确实移动并可向回滚动，卡片没有独立滚动动作，编辑器和历史保持不变。混合大小写的合成正文同时防止普通按钮自动大写。
- `check-host.sh` 的 256 项 JVM 冒烟、215 个设备源码与 JNI/Java 契约通过；完整原生库、原生发布宿主 APK、开发签名与 16 KiB 对齐构建通过。
- API 28/35 完整 `ClipboardSegmentDragDeviceSmoke` 通过：全文浮层实际像素、滚动及生命周期，固定卡片、列表滚动、左滑和分词拖选均明确报告成功。最终远端 `scripts/verify-local.sh --quick`（`20261023-052500`）通过，额外覆盖 Rust、Android、WebAssembly、Linux 设置壳与原生宿主（111 项）、macOS 和共享 Apple 桥。笔记与 diff 检查通过。

[手动分类与返回顶部](../../implemented/feature/2026-10-23-android-clipboard-categories.md)复用外层列表滚动；返回顶部只改变列表偏移，不恢复卡片内部滚动，也不写历史。
