# Agent Note: 双拼模糊候选按实际覆盖与词库调频排序

Status: implemented

## Problem

#8949 的双拼候选在同一会话内似乎记住选择，重建会话后又退回。实际词库 C ABI 在 `nihc` 开启 `n-l` 时复现：选择「拟好」后，它在当前会话成为首位，重建会话后「利好」又排在前面。调频已写入词库，但普通候选的匹配码是 `nihc`，模糊候选是 `ni'hc`；合并按字符串字节数排序，把格式化分隔符也当成输入覆盖，模糊行因此固定压过普通行。仅排除分隔符又会让普通组固定压过模糊组，学过的模糊词仍无法凭持久词频提升。当前会话的上下文重排暂时掩盖了排序错误。

## Decision

双拼合并按除去分隔符后的实际按键数排序，保留微软方案的分号等有效编码。同一覆盖范围内，普通与模糊词库行按权重稳定合并；只移动词库行所占的槽位，生成整句的分数不参与词频比较，位置也不受权重合并影响。同权重保持到达顺序。未发现权重逆序时不创建排序容器；需要合并时移动整行，不复制候选字符串。

同一覆盖范围内没有字面词库整词时，让模糊词库整词先于生成的替补整句，保留已有 golden 的整词让位约束；有字面整词时保留整句原有槽位。单辅助码在权重合并后重新施加匹配顺序，再稳定按覆盖分桶，避免调频越过辅助码匹配优先级。双辅助码继续过滤不匹配行。调频持久文件格式与写入流程保持。

## Alternatives considered

- 只排除分隔符，改动最小且能修复精确输入 `nihc` 的示例；但反向输入 `lihc` 时，学过的模糊候选仍被普通组挡住，因此不能完整解决跨会话学习失效。
- 所有候选统一按权重排序，代码更短；生成整句分数与词库词频不在同一量纲，会改变整句插入和长覆盖优先级，因此只合并同覆盖的词库槽位。

## Verification

基线回归运行 `20261020-190653` 失败，重建会话后已学习候选仍退回。会话回归使用独立合成词库，分别从 `nihc` 与 `lihc` 学习原非首选「拟好」，检查标准读音 `ni'hao` 的调频日志，并重建会话核对无分隔符和手动分隔符两种拼写。候选排序回归约束高分整句保留槽位、高频短前缀仍在长覆盖之后；旧编码重标测试按词频顺序检查模糊标记与消耗编码。

## 单字问题 #8944 的复核

远端默认分支固定为 `f194735294`，已有本篇的排序修复。固定随包词库经 Host API 对五种内置双拼的三组合成单字输入验证，关闭规则时目标模糊字均不存在，开启后均可选择且正确消耗两键；高频模糊字进入首屏。此次不重复修改运行时排序，单独补充 #8944 的宿主回归。

`crates/host-api/src/tests/fuzzy_single.rs` 使用每种读法 24 个合成精确字和一个高权重模糊字，页大小为三。五种内置方案乘三组平翘舌规则再乘双向输入，共 30 组，检查组字中开启规则延迟到取消后生效、冷/热查询的首屏及匹配编码、按候选代次选择正确上屏、关闭规则后不复用旧缓存，以及未选择的规则不能生效。保留默认辅助码开关，不以关闭产品默认功能换取通过。

运行 `20261020-221418` 的新增回归通过。仅将共享双拼引擎文件回退为 #8969 之前的固定提交 `b00e86a496` 后，同一回归在首屏断言失败：三个可见槽均为低权重精确字，目标模糊字被留在后页。对照后恢复当前文件，核对内容并刷新时间戳强制重编，避免镜像同步还原旧时间戳后复用回退产物。

最终运行 `20261020-222108` 通过（14 分 38 秒）：911 项宿主单测、20 项集成测试、全目标 clippy（`-D warnings`）、笔记校验与 quick；5 项按既有条件忽略。quick 中 Rust 工作区、Android 目标与 Java、WASM、Linux 设置壳与原生 94 项、macOS 宿主及 Apple bridge 通过；Windows/MinGW、pipe-only 和 HarmonyOS HAP 因环境前置缺失明确跳过。测试临时目录使用编译卷上的短路径，避免 macOS Unix socket 路径上限。此项验证共享宿主 ABI，不等同 Fcitx5 桌面输入验收。

## Consequences

分隔符不再制造额外覆盖，持久词频能跨普通与模糊查询生效；启用模糊音时高权重模糊词也能排在精确词前，同权重仍保持精确行先到。词库与调频文件格式保持。出现逆序的覆盖桶需要两个临时容器和稳定排序；无逆序的桶不创建这两个容器。验收覆盖共享引擎和 C ABI，Fcitx5 桌面实际输入须单独核验。
