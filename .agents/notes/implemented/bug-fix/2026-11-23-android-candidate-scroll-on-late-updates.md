# Agent Note: 安卓候选条在晚到的换代后保持用户滚到的位置

Status: implemented

## Problem

候选条和竖排候选在每次换代时都回到开头：`ImeCandidateStrip.render` 只要代次变了（放出尾部除外）就 `scrollTo(0, 0)`，`resetCandidateScrollIfViewChanged` 按会话、代次、页码判断，代次一变也排一次回到开头。这条规则本来是为翻页和打字设的，但换代的不只是用户的输入：

- 停顿重排每一片都推进代次，候选没变也推进（[安卓候选按住时不换代](2026-11-22-android-candidate-update-timing.md)）；
- 云候选、AI 候选到达时推进代次；
- 候选条滚到放出来的末尾、引擎放出暂扣的尾部时推进代次。候选条自己的「建回原来的数量、不回到开头」会被随后那次 `resetCandidateScrollIfViewChanged` 排的回到开头抵掉（读代码推出，模拟器上没有触发到）。

用户把候选条往后滑、正在找词时，这些晚到的换代把它拉回开头。模拟器（API 35，「增强」延后到停顿，把停顿起跑临时推到 1.5 s，让滑动先发生）上：候选条滑到约 1360 px 后，一次没有改变候选的停顿重排（`moved=false`）把它拉回开头，2/2 次。展开面板里同样的换代让网格回到顶部，那是 [展开候选跟随异步刷新](2026-11-14-android-expanded-async-refresh.md) 有意保留的，不在这次范围内。

## Decision

换代分两种：用户的输入（打字、退格、翻页、选拼音、换会话，以及其他没标记的换代）回到开头；晚到的换代（停顿重排、在线候选、放出暂扣的尾部）保持用户眼前的位置。

- **晚到的路径打标记。** 停顿重排的发布、`applyOnlineResult` 换上在线结果、`followCandidateGeneration` 跟到放出尾部的新一代，这三处在换上新视图前调 `markCandidatesLate`，`CandidateScrollAnchor.markLate` 记下那一代。没标记的换代一律当作输入，所以漏标一处只会退回原来「回到开头」的行为，不会把该回开头的列表留在中间。
- **`CandidateScrollAnchor` 取代 `CandidateScrollPolicy`。** 它记着上次定位的会话、代次和页码：同一代重画（释义、读音）不动；标记过的、同会话同页的晚到一代保持位置；其余回到开头。换页、换会话时即使是晚到的结果也回到开头。
- **候选条让眼前第一个候选留在原处。** 晚到的换代之前，候选条记下眼前第一个按钮是第几个、离可视区左边多远（这时上一代的按钮还挂着）；新一代建回原来的按钮数后，按文字加来源（`CandidateScrollAnchor.follow`）在新列表里找回它，在下一次绘制前把它滚回原来的位置，中间那一帧不画。候选没变时位置不变；云候选插在前面时跟着挪一格；它不在新列表里了就回到开头。
- **竖排候选保持滚动距离。** 晚到的换代在竖排里少见，这次只保持像素位置，不按候选对齐。
- **停顿重排的发布也让义项页跟过去。** 在线结果早就调 `imeTranslationSenses.followOnlineRefresh`，停顿重排漏了，开着的义项页会被一次重排关掉；现在两条路一样。

## Alternatives considered

- **在用户输入的路径上打标记（`apply()` 记一个输入序号），其余换代都保持位置。** 规则看起来更直接，但服务里换视图的地方有十几处（英文模式、全角、标点、焦点、偏好重读等），哪些算输入要一处处判断；漏标一处就会让新的列表停在中间，比回到开头更难看出问题。反过来只标三条晚到的路径，漏标的后果是旧行为。
- **只保持像素位置，不按候选对齐。** 实现最小，没变的停顿重排也够用；但云候选插在前面、或模型在用户滑动之后才换序时，同一个位置上会换成别的词，用户以为自己看的那个词还在原处。按候选对齐只多一次查找和一次绘制前的滚动。
- **按组字文字判断要不要回到开头（`editing_text` 没变就保持）。** 不用打标记，但上屏后的联想列表组字文字都是空的，连续选联想时新列表会停在旧位置；选拼音、辅助码筛选也可能不改组字文字却换了整张列表。
- **滑动、惯性滚动期间也像按住候选那样暂停换代。** 能挡住滑动中途的换代，但滑完停下来看的时候照样会被拉回开头，而那正是用户在找词的时候；保持位置对两种情况都有效。
- **展开面板开着时暂停停顿重排和在线候选。** [展开候选跟随异步刷新](2026-11-14-android-expanded-async-refresh.md) 已经考虑过并否掉（会藏起用户开着的候选能力）；这次不改面板，另行讨论。

## Consequences

- 用户滑开候选条之后，停顿重排、云候选、AI 候选和放出尾部都不再把它拉回开头；打字、翻页、选拼音照旧回到开头。
- 晚到的换代要建回之前建过的按钮数（与放出尾部时相同），滑得很远时这一次重画多建一些按钮。
- 展开面板和九键面板的行为不变：异步刷新照旧跟到新的一代、网格回到顶部。
- 竖排候选只保持滚动距离，插在前面的在线候选会让眼前的行往下挪一行。
- 验证：`CandidateScrollAnchorSmoke`（取代 `CandidateScrollPolicySmoke`：同代重画、翻页、输入换代、晚到换代、换页换会话、清空，以及按文字加来源找回眼前的候选）；模拟器（API 35，同样把停顿起跑临时推后）上滑开候选条后等停顿重排落下，位置保持。云候选到达走同一条换代路径，模拟器上没有账号，没有实际跑到。
