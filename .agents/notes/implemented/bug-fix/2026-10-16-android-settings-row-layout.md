# Agent Note: Android 设置行说明与当前值布局

Status: implemented

## Problem

Android 设置页的长说明与行尾当前值共用一行时会互相挤压，尤其是“引号样式”的说明和“弯引号”值；九键滑动距离的阈值说明也缺少稳定的副标题位置。

#9009 的手写识别等待时间使用固定 46dp 数值标签，大字体下连三位毫秒数也会从左边裁掉。

## Decision

`GroupCard` 为需要较长说明的导航行提供 `stackValue` 选项，把当前值放到标题和说明下面；普通导航行和值行继续使用行尾布局。滑块提供可选副标题，并把九键滑动距离的解释放在滑块标题下方。这样说明可换行，当前值仍保留可见且不压缩右侧箭头。

滑块数值标签在建行时用当前字体测量所有合法步长的标签，预留其中最大的宽度，至少保留原来的 46dp。数值变化只更新文字，不改变标签宽度，避免拖动时滑块横向移动。

## Alternatives considered

- **继续把值固定在行尾**：实现改动最小，但长说明会和当前值争夺横向空间，窄屏上容易截断或重叠，因此不采用。
- **缩短或删除说明**：能避免布局冲突，但会丢失设置项的触发条件和误触影响，无法解决 issue 要求的可理解性，因此不采用。
- **把数值标签固定加宽**：改动简单，但不同字体缩放和单位需要的宽度不同，不能保证完整显示，因此按实际字体测量。
- **数值标签直接按内容自适应宽度**：始终容纳当前值，但从三位数变成四位数时会推动滑块的位置，影响连续拖动，因此预先保留所有取值需要的最大宽度。

## Consequences

设置行在说明较长时会变高，用户能同时读到完整说明和当前值；只有显式启用 `stackValue` 的导航行改变布局，现有短说明行保持原样。`KeyboardGestureDescriptionSmoke` 覆盖九键滑动距离副标题和引号样式纵向值布局，`check-host.sh` 已通过 235 个 JVM smoke 与 123 个设备套件源码检查。

数值标签随字体缩放扩宽，会减少左侧标题的横向空间，窄屏或大字体下标题可能换行。取值范围、步长和保存协议不变。#9009 的新布局尚待原生 APK 大字体验收。
