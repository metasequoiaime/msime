# Agent Note: macOS 为缺失的内置辅助码表提供随包回退

Status: implemented

## Problem

#8931 的全拼辅助码开关和注释显示均已打开，`juH` 仍没有筛选或注释。仅含下载词库的合成资源目录可复现；同一配置补齐 `helpcodes` 后，首选为「炬 (HJ)」。辅助码不属于在线词库锁，旧目录和下载的新代次可能没有这些随包资源；词库代次不变时刷新配置不会补表。

## Decision

macOS 输入法 bundle 自带七份内置码表，并通过仅在当前会话中添加的 `helpcode_fallback_resources` 指定只读回退资源根目录。Engine 仅在主资源中的内置表确实不存在时使用该目录；已有空表、不可读表、自定义表与插件表保持既有语义。会话切换方案时继续使用同一回退目录，不重写用户配置或词库目录。旧宿主不传该可选键，行为不变。

## Alternatives considered

复制随包表到每份下载资源可以复用已有资源路径，Linux 的安装脚本采用此法；但 macOS 还需覆盖旧目录、升级和在线更新，并且输入法会向可能只读的资源目录写入。只读回退无需修改这些目录。将内置表编进 Engine 可消除路径问题，但会改变所有缺表宿主和测试夹具的现有行为；这里由宿主显式选择回退。

## Verification

合成词库覆盖缺表回退、注释与筛选、已有表优先、空表/目录/链接不回退、自定义表不回退，以及相对回退路径忽略。Host API 回归覆盖偏好切换和插件表优先级；移除宿主表后重新装载内置表也继续使用回退。

远端 macOS arm64 上，完整 Engine 单测 2368 项通过，49 项按既有配置忽略；31 项 golden 基准通过。Host API 辅助码专项 8 项与相关 crate 的全目标 clippy（`-D warnings`）通过。macOS 原生输入法和 `shortcut-test` 构建成功，`shortcut` 通过，原生 bundle 的七份表与源码资源逐字节一致。

Android API 28 和 35 上，75 项 Engine 辅助码测试通过（两项读取 checkout 绝对路径的整表测试留在主机），四个 client 核心库完整设备套件均通过。新辅助码回退的文件读取在两个 API 级别都实际执行。

在包含 #8912 的 `714dfeb7d6` 基线上，最终 `bash scripts/verify-local.sh --quick` 通过，包含 Linux 原生 93 项测试。重新运行 macOS `shortcut` 通过。最终 C ABI 加载真实词库和实际 bundle 资源：合成配置无回退时 `juH` 首选「句」、注释为空；有回退时首选「炬」、注释为 `(HJ)`。

## Consequences

旧宿主不传回退根目录，保留原行为。新 macOS 宿主在内存文档里注入可选键，准备配置的序列化输出仍省略它，避免旧版输入法读取不认识的持久化键。输入法独立 bundle 多带七份码表，沿用已经随包的三份来源声明。

缺表时只读随包副本，不改写用户词库或配置；已有表（包括显式空表）、自定义表和插件表的优先级不变。合成目录的复现证实缺表会产生报告症状，未直接检查报告者配置；本次没有替换维护者本机安装，也没有完成该用户环境的系统输入验收。
