# Agent Note: Android 临时大写结束后返回中文

Status: implemented

## Problem

#8787：中文双拼空闲时点 Shift 会调用永久中英切换；一次性大写用完或再次关闭 Shift 后，键盘仍是英文，而且该状态写入中英模式记忆。

## Decision

由中文空闲 Shift 发起的英文状态属于当前会话的临时大写。一次性大写字母提交后或手动关闭大写时恢复中文；350 ms 内双击仍锁定大写，锁定结束后恢复中文。临时切换不写入中英模式记忆。会话停止时丢弃临时状态，明确点击中英键沿用永久切换。英文起始、中文辅助码与其他语言的大小写语义不变。

历史审计：[双击 Shift](../../implemented/bug-fix/2026-10-08-shift-double-tap-caps-lock.md)持有双击时间窗，本篇补充中文返回边界；[就地更新键面](../../implemented/bug-fix/2026-10-11-android-shift-relabel-in-place.md)仍适用；[全拼分词键](../../implemented/feature/2026-10-15-quanpin-touch-separator.md)不受影响。没有完全吸收或过时的提案。

## Alternatives considered

不切英文、直接给引擎发送大写能避免额外宿主状态；但中文空闲的大写还承担本地模式入口，直接复用会把用户要写的英文字母变成模式快捷键。临时大写继续复用英文直输路径。

## Verification

设备回归初版只设置原生会话为首道双拼，宿主仍是默认全拼，因此首次 Shift 实际执行分词动作，该失败不计入红绿证据。夹具现在同时设置宿主方案与原生会话。使用相同夹具，在当前 `origin/develop` 基线构建的 API 35 原生 APK 上，失败点为「一次性大写后恢复宿主中文模式」；修复版在 API 28、35 均通过，包含实际大写提交、原生会话恢复、后续双拼候选、慢速取消、快速双击锁定及关闭、永久英文保持、实体字母输入、主动中英切换、停止会话和模式记忆写入次数。

原生 APK 编译、签名、ABI 与 16 KB 对齐通过，本地 quick 门禁通过（Android 宿主 Java、设备套件源文件编译，以及 Rust 工作区、Android 目标和 Apple bridge）；独立宿主检查的 247 项 JVM 冒烟通过。其他平台构建按改动范围跳过，不计通过。笔记校验与差异检查通过。API 35 的 `QuanpinSeparatorDeviceSmoke` 经真实系统编辑器验证空闲分词无输出、连续三轮「西安」组字上屏、英文 Shift、切回中文恢复分词和密码框保留 Shift。

## Consequences

临时大写结束后恢复中文，不再改变中英模式记忆；代价是宿主额外维护一个随会话清除的临时所有权状态。临时英文与永久英文共用渲染和原生会话接口，在实际写完字母后才切回。辅助码、全拼分词键与其他语言保留各自入口。模拟器验证不代表 Redmi 真机验收。
