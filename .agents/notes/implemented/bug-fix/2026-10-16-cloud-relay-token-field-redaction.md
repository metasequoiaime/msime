# Agent Note: 共享中继设置不回显已保存令牌

Status: implemented

## Problem

共享设置页的自建云剪贴板中继字段把偏好里的 `cloud_clipboard_relay.token` 直接作为受控输入值。输入框虽然默认使用密码类型，但「显示」按钮、浏览器自动填充或调试工具都能把已经保存的令牌重新显示出来；Android 原生页已经遵守打开时留空的令牌字段契约。用户只修改中继地址时也不应该被迫把旧令牌重新暴露或复制出来。

## Decision

共享中继设置页只把用户本次输入的令牌放进输入框。已有令牌用空输入表示「沿用」，修改地址后保存时由公共 `useCloudClipboardRelay` 把旧令牌带回保存请求；用户输入新令牌时则使用新值。没有已保存令牌时，空输入仍然按原规则报错。这样与 Android 原生设置页保持一致，同时保留只改地址的操作。

`useCloudClipboardRelay` 完整持有模式、地址与本次令牌草稿、校验结果、保存条件和两个显式写入动作；`CloudClipboardRelaySection` 只绑定控件和展示提示。包入口同时公开 hook、状态与选项、控件与 props，以及现有的纯校验、来源判断和偏好写回函数，旧路径继续兼容。已保存令牌只参与 hook 内部的保存组装，返回状态仅含 `hasSavedToken`，不新增一份可回显的旧令牌。

保存动作自身检查当前模式、校验、变更和禁用条件，改回账号也检查模式、已配置与禁用条件；单独复用状态层时不能绕过按钮的写入约束。模式切换和输入只改草稿，地址或已保存令牌在外部变化时重置模式与草稿，同值配置对象或展示回调重建则保留未保存输入。

## Alternatives considered

- **继续把已保存令牌填入密码框，只依赖 `type=password` 遮挡**：实现最小，但点击「显示」即可暴露已有凭据，也和 Android 页的现有契约不一致。
- **修改地址时强制重新填写令牌**：能避免在页面状态中保留旧令牌，但会让只改地址的正常操作失败，且不符合共享设置里「留空保留」的凭据语义。
- **只去掉“显示”按钮**：能降低一次显式暴露，但受控输入值仍然包含令牌，自动填充、调试工具和 DOM 读取仍可见。
- **把表单状态继续留在组件，只公开控件**：代码改动较少，但其他展示不能独立复用留空沿用、外部配置重置与显式保存规则。公共 hook 承接整条状态契约，控件和其他调用方使用同一个实现。

## Consequences

已保存令牌不再回填到共享页面的输入框；地址单独修改时仍能保存，令牌不会改变。用户若要轮换令牌，直接输入新令牌即可；改回水杉账号仍通过现有账号选项清除整组中继配置。设置表单新增的占位提示只说明留空含义，不把令牌写进界面文本。

回归测试覆盖已保存令牌输入框为空、只改地址时保存按钮可用，以及保存请求保留旧令牌；原有中继地址、令牌、路由和清除设置测试继续运行。公共 hook 独立测试覆盖首次配置、规范化、令牌轮换与保存回填、非法新令牌、显式切回账号、禁用写入、外部配置变化和 StrictMode 下同值配置与回调重建。

表单不引入新的凭据持久化或中继协议，仍由现有宿主保存配置并走共享 Rust 校验。代价是新增公共状态 API；保存仍是受控回调，只有调用方回填配置后才清空本次令牌输入。
