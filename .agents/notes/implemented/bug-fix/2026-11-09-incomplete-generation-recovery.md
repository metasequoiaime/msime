# Agent Note: 回收旧版本留下的半成品词库代次

Status: implemented

## Problem

#11130 的 Windows 重装现场在用户选择删除数据后仍留下了只含 `msime-bigram.bin`、`msime-trigram.bin` 的代次目录，没有 `.ready`。当前引擎已经把新准备过程改成独有的 `.incoming` 目录并在最后原子改名，但遇到这个旧版本直接写出的最终名字目录时，改名会因目标非空失败，之后每次启动都报告运行资源准备失败。

已有笔记 [2026-10-26-stale-generation-staging.md](2026-10-26-stale-generation-staging.md) 当时明确保留了“最终名字但没有 `.ready`”这一遗留状态；本次决定把这个遗留状态的可恢复子集补上。

## Decision

准备代次时，在检查 `.ready` 之后识别旧格式的最终名字半成品：目录必须是普通目录、至少有一个文件、所有条目都必须是已知的代次文件（主词库、英文词库或 n-gram 表），且不能含 `.ready` 或未知文件。满足条件时整体删除该目录，再用当前独有的 `.incoming` 流程重新准备；目录中出现未知文件时保留原目录并继续报告不完整，避免把用户文件误当作引擎产物删除。

当前流程不会在最终名字目录中写入半成品：它先在 `.incoming` 中完成复制、回放、索引和 `.ready`，所以这个回收只针对旧版本或异常退出遗留的已知文件集合。新测试同时覆盖了可回收的 n-gram 半成品和含未知文件的拒绝路径。

## Alternatives considered

- **继续拒绝所有没有 `.ready` 的目录**：最保守，但会让 #11130 的残留代次永久阻塞重装，用户只能手动删除目录。
- **无条件删除整个目录**：能恢复更多历史现场，但会把目录里的未知文件一起删除，无法证明它们不是用户资料，因此不采用。
- **按目录年龄等待一小时再回收**：能降低与旧进程并发的风险，但重装后的新安装仍会在这段时间内不可用；当前新流程不会写最终名字半成品，已知文件集合足以收窄回收范围，因此不采用。

## Consequences

- 旧版本留下的已知词库半成品可以在下一次启动时自动恢复，Windows 卸载后重装不再因残留 n-gram 文件卡住。
- 含未知条目的目录继续保留并报告不完整，仍需要人工清理，避免扩大删除范围。
- 回收只覆盖运行时生成文件，不会改变用户词库日志、配置或其它状态文件。
- 需要在 Windows 重装现场用包含该修复的版本复验 #11130；本机 Linux 只能验证共享引擎的回归测试。
