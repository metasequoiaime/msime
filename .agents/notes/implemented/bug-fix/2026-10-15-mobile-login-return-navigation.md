# Agent Note: 移动端离开账号页清理登录返回目标

Status: implemented

## Problem

移动端设置页从嵌套页面打开账号登录时，会保存登录完成后的返回页。账号页仍显示底部标签栏，用户可以在登录过程中切到其他标签；页面卸载后，旧的返回页仍保留。再次进入账号页并完成登录时，旧回调无条件调用 `history.back()`，历史栈已经多了其他标签页记录，结果回到错误的页面。

## Decision

待返回页只在账号页仍是当前页面时有效。统一导航选择离开 `account` 时清除它；系统返回手势经 `popstate` 恢复到其他页面时也清除它。重新进入账号页不会继续使用已经卸载的登录表单的返回回调。

## Alternatives considered

- 记录打开登录时的历史长度，并在完成时用 `history.go` 跳过中间标签记录：可以保留跨标签的登录回调，但要假设期间的所有历史变化都属于本设置页，外部页面或宿主导航会使步数失去意义；账号表单离开后本来也会卸载，因此不保留这条异步流程。
- 在完成登录时把当前历史记录改成返回页：能避免一次错误的后退，但会留下重复或过时的标签记录，系统返回手势仍可能回到已离开的账号页。

## Consequences

账号登录页离开后，旧登录完成回调不会再把用户带到错误历史位置；重新进入账号页按新的登录流程处理。直接在账号页完成登录的原有返回逻辑不变。系统返回和底部标签切换遵守同一条清理规则。

## Verification

新增设置导航回归用例，旧实现稳定复现“账号 → 首页 → 账号 → 完成登录”后仍使用旧返回目标，以及系统返回离开账号页后保留旧目标；修复后两种路径都清除目标，完成回调不再导航。相关 Vitest 用例通过。
