# Agent Note: Android 反馈草稿跨标签保留

Status: implemented

## Problem

#9888：`HomeActivity` 切换底部标签时清空详情页回退栈；`FeedbackPage` 的描述、类型、诊断开关和截图只存在于即将销毁的 Fragment 字段。再次打开反馈页会得到一份空表单。旋转重建 Activity 时也会丢失这些字段。

## Decision

反馈表单由 Activity 作用域的 `ViewModel` 持有。切换标签后重新打开和旋转重建都读取同一份内存状态；提交成功时先保留当前页面的确认状态，离开后清除整份表单。提交任务继续绑定反馈页视图，离开页面时按既有生命周期规则取消；保留的草稿不会把旧请求视为成功。

草稿只在当前应用进程内存中存在，不写入偏好文件、数据库或系统保存状态。进程结束后草稿不可恢复。键盘弹出时的提交入口仍使用详情页的滚动容器和现有输入法避让规则，通过设备用例检查能滚动到按钮。

既有[反馈页视图生命周期](2026-10-11-android-feedback-view-lifecycle.md)决定离开页面时取消提交，[输入法弹出时隐藏主页导航](2026-10-26-android-home-tabs-hide-with-ime.md)决定键盘出现后的底栏位置；本篇只改变表单状态的归属，不改这两项规则。

## Alternatives considered

- **把草稿写进持久存储**：能跨进程重启恢复，但描述和截图可能包含私人资料，需要另定保存期限、清理入口和加密边界；本次只要求普通页面切换和旋转。
- **切标签时保留反馈 Fragment**：可少改表单字段，但会改变整个宿主统一清空详情页回退栈的导航规则，返回层级也会变得不一致。

## Consequences

同一进程内重新进入反馈页仍可继续编辑。应用进程被系统终止或用户强制结束后草稿消失，这一边界不作为持久化承诺。提交成功后新打开的表单恢复初始类型、诊断开关、描述和截图。设备测试只输入合成文字，不发起反馈提交。

## Verification

`bash platforms/android/check-host.sh` 通过：279 个 JVM 冒烟、245 个设备套件源码编译及宿主契约检查；`python3 scripts/test-android-feedback-view-lifecycle.py`、`pnpm run verify-notes`、`git diff --check` 和 `bash scripts/verify-local.sh --quick` 通过。原生 APK 用 JDK 21 构建并完成签名、JNI 导出与 16 KB 对齐校验。

API 28 原生设备的 50 组合成输入全部通过。第一版设备断言只调用 `ACTION_SHOW_ON_SCREEN` 要求提交按钮自动滚入可见区：输入法覆盖在仍占全屏的滚动视图上时，该辅助功能动作没有滚动，测试在此超时。随后在同一原生页面实际向上滑动，画面显示完整提交按钮位于输入法上方。设备用例改用同样的触摸滚动，并检查按钮与输入法窗口的边界。

第二版设备断言已通过触摸滚动和输入法边界，却在点“我的”时按旧套件的 `RadioButton` 类名寻找节点而超时。API 28 实际节点是 `tab_account` 的 `FrameLayout`，无障碍描述为“我的”；设备用例按这一稳定描述进入，并把入口、重开和草稿恢复分阶段断言。

第三版确认“我的”Tab 已成功打开，但“帮助与反馈”行仍在账号页首屏之外；对该行调用 `ACTION_SHOW_ON_SCREEN` 同样不触发滚动。设备用例改为在 `account_scroll` 上做真实触摸上滑，确认行实际可见后再点；增加仅运行新增导航流程的 instrumentation 参数用于快速定位，完整 50 组合成输入仍是默认回归。

最终 `navigation-only` 快速设备专项和默认完整反馈专项均通过：真实触摸上滑后提交按钮完整位于输入法上方，切“我的”后重开反馈页仍保留合成描述；全过程没有点击提交或发送请求。`smoke.sh emulator-5566 --core --feedback` 在此前置核心用例均通过后，曾因旧断言在反馈专项退出；最终复验直接运行已安装产品上的反馈 instrumentation，没有重跑反馈之后的无关核心项目。
