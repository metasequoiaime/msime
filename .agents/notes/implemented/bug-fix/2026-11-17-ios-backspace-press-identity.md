# Agent Note: iOS 删除按压身份贯穿滑出与松手

Status: implemented

## Problem

#11525 报告快速点按多删、长按反应慢。删除键原先共用计时器和 `didRepeatBackspace`，没有有效按压身份；`touchDragExit` 清掉已连删标记，滑回后 `touchUpInside` 又按短按删除一字。取消后的松手、旧按键的迟到松手也没有守卫。这个确定的事件序列缺陷不能直接证明报告中的所有快速连点都由同一路径引起。

## Decision

独立的 `BackspacePressState` 持有按键身份、能否继续连删及是否已经连删。滑出只停止计时并保留长按身份；短按滑回仍单删，长按滑回松手不再追加。松手只消费一次，取消立即结束身份，另一按键的迟到松手或滑出不能影响当前按压。计时回调另外核对实际 `Timer` 身份，旧计时器不能为新按压删字。

`KeyboardKeyButton.accessibilityActivate` 为删除键提供独立的一次性激活，记录一次按键并执行一次删除；不把读屏或开关控制的激活冒充没有按下的触摸松手，禁用键不执行。其他按键继续调用 UIKit 原有激活。

`touchUpInside` 的 target 同时接收 `UIEvent?`：真实触摸有事件，必须匹配有效按压；`sendActions(for:)` 等程序化激活没有触摸事件，可以独立执行一次并计数、终止旧计时器。程序化激活已经有对应按压时仍按正常松手消费，不把已连删的按压变回短按。这样保留原有手写删除键的程序化激活契约，同时拒绝取消后迟到的真实触摸松手；不修改既有手写回归的前置或断言。

长按首次等待由 0.4 秒缩为 0.3 秒，重复间隔仍为 0.075 秒，满足 issue 要求的更快长按响应；没有修改任何偏好默认值。手写笔迹删完即停、拼音按音节删到组字结束即停、九键取消组字以及韩语等书写型组字继续逐键删除的规则保持。

## Existing notes audit

[按下即反馈](2026-11-03-ios-key-feedback-on-press.md)部分重叠：保留按下发声、松手不重复反馈的契约，本次只补删除动作的按压身份和独立读屏入口，不翻转该决定。检索活跃笔记没有其他 iOS 删除按压身份的归属；Android 快速删除与上滑清空记录不属于本次范围。

## Alternatives considered

- 只在 `touchDragExit` 不清 `didRepeatBackspace`：能以最少代码避免长按滑回时多删，但仍没有按键身份，旧按键松手和旧计时器回调可以影响新按压。
- 所有删除都改为按下立即执行：首次动作最快，但组字只剩一个字母时会在长按阈值之前消失，后续连删可能进入已提交正文，还会改变滑出取消短按的行为。本次保留松手单删，只缩短长按等待。

## Consequences

按压与计时有效性有可执行的行为约束，取消和交错按键不再凭全局布尔值推断。代价是多一份很小的按压状态；该状态不持有按键，不延长键盘视图的生命期。短按和长按之间的 0.3 秒判定仍是固定交互参数，不新增设置项。

行为回归编译真实状态类型，覆盖快速点按、重复松手、长按、滑出滑回、交错按键、取消和组字停止边界。原生宿主接线的验证结果与未执行项写入 PR；本轮不操作真机或模拟器、不安装、不发 issue 评论。没有视觉布局、样式或设置界面改动，截图为无。
