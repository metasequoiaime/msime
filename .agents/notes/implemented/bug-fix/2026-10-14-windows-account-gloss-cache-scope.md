# Agent Note: Windows 账号候选释义缓存按账号隔离

Status: implemented

## Problem

Windows 候选释义 worker 的账号缓存键只有 provider、目标语言和候选词。设置应用换到另一个账号后，新的请求会先读到旧账号留下的释义；账号服务返回的 `user_id` 已经随令牌响应提供，但原实现丢弃了它。

## Decision

账号令牌解析为令牌和 `user_id`，每次账号释义请求先确定当前账号，再用带账号作用域的键读取、写入正面和否定缓存。匿名账号使用稳定的匿名作用域；不同认证账号始终使用不同作用域。

## Consequences

账号切换不会复用另一账号的候选释义，也不会让否定缓存阻止新账号重新查询。账号令牌仍只在内存中用于请求头，缓存键只包含不敏感的账号标识。

## Alternatives considered

- **清空整个 worker 缓存**：需要可靠地监听账号文件变化，而且会丢掉当前账号仍可复用的结果；按账号作用域建键可以在切换后立即隔离并保留旧结果。
- **把访问令牌放进缓存键**：令牌会轮换，导致同一账号频繁失去缓存，也会把凭据带入内存索引；使用服务返回的账号标识更稳定。

## Verification

新增 Windows 账号释义策略冒烟断言，确认不同账号作用域分离且空标识映射到匿名作用域；另跑编译后的策略可执行文件。提交前还运行 Windows host 检查、`git diff --check` 和 `pnpm run verify-notes`。
