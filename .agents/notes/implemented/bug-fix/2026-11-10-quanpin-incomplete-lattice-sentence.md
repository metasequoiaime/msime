# Agent Note: 全拼不完整音节参与长句词网格

Status: implemented

## Problem

Issue #11171 中，长串全拼在中间使用单字母声母缩写时，普通候选仍能逐段出现，但整句词网格拒绝不完整音节，因而不会生成跨越这些段的完整候选句。现有跨度查询也只接受完整音节；解码层的同一门槛使得即使查询得到词条，整句仍然为空。

## Decision

词网格把每个输入段接受为完整音节或合法拼音前缀。完整跨度继续走原来的精确查询，以保持分配预算和精确键语义；含合法前缀的跨度改用全拼混合简拼查询，让词库行携带自己的完整规范读音。词网格解码和全拼整句合并入口使用同一合法性规则，并且只在至少有两个不完整段、同时仍有完整段可锚定的长串上开启整句合并，避免一个普通的末尾未完成音节改变既有候选排序。空段和不属于拼音前缀的字符串仍拒绝。普通单路径查询不改变其原有行为。

跨度缓存对完整段保留旧查询路径，只有不完整段进入新查询，避免完整输入增加额外分配。词条行的规范读音仍由数据库返回，候选的输入拼音字段继续保留用户实际键入的缩写。

## Alternatives considered

- 只在候选合并层把缩写扩成一个整句：最小改动，但词网格的跨度边仍不存在，无法让中间缩写和完整词条共同参与束搜索，因此不能覆盖 issue 的长句场景。
- 先枚举所有完整拼音切分，再为每条切分单独建图：可以表达更多边界，但会重复查询和解码，且复活了既有全拼重切分方案被否决的复杂度与预算风险；本次只复用已有混合简拼扫描。

## Consequences

合法的中间声母缩写现在可以与前后完整音节组成整句候选，真实词库中的 `mu'qian'yu'dao'de'w't's` 可生成“目前遇到的问题是”。完整拼音路径的查询和分配预算保持不变；不合法段仍不会产生整句。issue 截图中的 `dang'q'y'd'w't's` 还涉及缺少音节的具体输入，当前实现只保证输入段数量和合法前缀语义，不承诺自动插入未键入的音节。

验证覆盖合成词库的跨度查询、合法缩写整句解码、非法段拒绝、全量 `msime-engine` 单测，以及 quick 门禁。Linux 原生宿主容器检查因本机没有 Docker 未运行；远端 quick 门禁在修正临时工作区的 `target` 路径后通过。
