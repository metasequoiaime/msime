# Agent Note: Android 数字九宫格固定符号与返回入口的位置

Status: implemented

## Problem

#9113 从拼音九键的 `符 | 123` 切到数字层后，底行变成 `九键 | 符`。用户按原数字入口的位置想返回拼音，实际打开了符号面板。截图要求交换数字层左下角这两个键。

## Decision

数字层沿用字母层的动作顺序，不再交换数字层独有的前两键：`符 | 九键/原方案 |（地球）| 0 | 中/英 | 回车`。`123` 和返回键是同一个层切换动作，宽度一致，两个键面保持横向位置；`符` 也固定在同一位置。0 与右列空格继续沿用现有布局。

既有语言与数字键交换设置仍交换这两个动作，符号入口不参与交换；借用同一数字九宫格的中文方案和直接数字输入框一起使用该排列，不按入口另造布局。

### 既有笔记审计

- [底行中间的数字 0](../../implemented/feature/2026-10-16-android-nine-key-numeric-bottom-row.md)部分被取代：只翻转数字层前两键的顺序，保留唯一 0、空格手势和控件归属。
- [默认数字九宫格](../../implemented/feature/2026-10-15-mobile-default-number-pad.md)部分重叠：Android 借用页同步改排列，方案返回标题、数字统计及其他平台决定保留。
- [九键符号入口](../../implemented/feature/2026-10-15-nine-key-symbol-key-and-quick-marks.md)、[语言数字键交换](../../implemented/feature/2026-10-14-android-language-number-key-swap.md)、[直接数字输入框](../../implemented/feature/2026-10-17-android-direct-number-keypad.md)沿用既有动作与入口判定，无新增设置。
- 检索命中的数字侧栏、数字顺序设置移除、十四键、组码与候选笔记不决定这两个底行入口的位置，不作变更。

## Alternatives considered

保留现有排列能让数字层的返回键位于最左边，符合一般返回动作的习惯；但同一个键在往返时换位置，正是报告中的误触原因，因此统一采用字母层已有的排列。

## Verification

既有 JVM 底行用例覆盖有无地球键及语言数字交换时的顺序、宽度和唯一 0；设备用例比较切换前后符号入口和层键的实际横向位置，并验收数字、空格、小数点、符号面板和两次返回。

## Consequences

数字层与拼音层保持入口位置一致，用户按原数字入口可以返回九键，符号面板入口固定在左侧。习惯现有数字层顺序的用户会遇到一次位置变化。改动只影响 Android 的共享数字底行。
