# Agent Note: iOS 完整候选列表不因显示条数上限拒绝展开

Status: implemented

## Problem

#8782 报告切换方案后极低概率无法展开候选，按钮仍有反馈。当前 `CandidatePanelSnapshot.decode` 对完整快照硬性要求 `candidates.count <= 4096`，但共享运行时的完整列表不限制为 4096 行。当前固定词库的 `tbl_1_y` 有 4490 行、4343 个不同词值，静态数据表明存在越界的可能，但尚未以当前引擎实际输出验证这批行数。这个边界是独立可复现的失败条件，还不能据此认定原报告的全部低概率路径都已解释。

网格目前为每个候选创建一个 `UIButton` 并保留到关闭；只删除条数限制会把大列表的按钮和排版开销带入键盘扩展，不能只修解码而忽略设备内存。

## Decision

完整快照来自同进程的 Host API，解码不再把离线释义请求的 4096 行边界当作引擎列表上限。逐行的文字长度、代次、索引范围和去重校验继续生效。

网格保留全部候选及布局几何，改由 `UICollectionView` 管理可见按钮、滚动、菜单和无障碍生命周期。测量复用单个按钮，避免为了计算全列表几何保留全列表的 UIKit 控件；布局按纵向有序的行二分查询可见范围。显示序号、长按菜单与选择仍映射同一份完整快照和全局候选索引。普通网格与九键三栏共用这一路径。

系统入口回归由 `KeyboardExtensionEditorUITests.testCandidatePanelAfterHostSchemeChanges` 覆盖：独立的 `MSIMEKeyboardTestHost` 在 `--system-keyboard-editor` 启动参数下显示普通 `UITextField`，只接受系统键盘输入，不在进程内构造产品键盘控制器。带着未完成组字把编辑器留在后台，通过产品宿主「设置 → 输入 → 普通话」保存双拼、全拼、九键、十四键，连续三轮切回同一个编辑器。每次先检查扩展当前方案，再输入合成单音节，检查候选展开、可触摸、收起、再次展开，以及选词向编辑器追加完整汉字并结束组字。它覆盖应用切换、宿主写入与扩展重载的进程边界，不能由测试宿主内直接改偏好或终止编辑器代替；系统键盘不可达而跳过时不计验收通过。独立编辑器只由测试启动参数启用，正常单测宿主保持空白页面。

## Historical audit

- `CandidatePanelSnapshot`、完整候选与 4096 行的活跃笔记检索没有找到同一决定。离线释义的请求体和条数预算是另一条契约，继续保留。
- [Android 候选网格分批创建](../../implemented/bug-fix/2026-10-09-android-candidate-grid-batches.md)部分重叠于控件数量和布局开销；本篇只改变 iOS，不复制 Android 的原生实现。
- [完整候选 release 代次](../../implemented/bug-fix/2026-10-11-full-list-generation-release-build.md)约束展开后换代，继续保留，不通过截断、重编号或放宽身份检查绕开。

## Alternatives considered

- **只提高 4096 常量**：改动最少，能覆盖当前词库的单字母列表；但下一份更大的词库仍会失败，也会一次创建更多按钮。
- **只保留前 4096 行**：维持既有预算，能让面板出现；但尾部词条永久不可达，与完整列表及全局选择身份的语义不符。
- **手动回收 UIScrollView 内的按钮**：能保留现有视图层级，滚动窗口的实现也较小；但需要自行处理长按菜单、无障碍焦点及交互中的视图保留。采用 `UICollectionView`，以自定义几何布局保留变列宽、跨列、注释行高和皮肤画布规则，让系统维护单元格生命周期。
- **只在原生测试宿主循环切换方案**：更快、更容易在 CI 重放候选解码与虚拟化；但没有经过宿主 App 保存设置、系统切换编辑器和扩展重载的原报告入口，因此保留单测并另加系统键盘界面用例。
- **在产品 App 的试用框中重开编辑器**：可以复用已有入口、不额外安装测试应用；但不能保留另一应用的编辑器进程重放后台切换。复用现有独立单测宿主增加普通输入框，并明确记录安装前置，不借用设备上的备忘录或浏览器及其私人内容。

## Verification

新增 4097 与 10000 行合成快照保留尾部身份的回归，在未改生产解码器时失败，修改后通过。iOS 27 arm64 原生测试宿主运行 `CandidatePanelSelectionTests`、`CandidateFontSizeTests`、`KeyboardSkinTests`、`CandidateMarkerTests`、`CandidateTranslationTests` 及共享 `CandidatePanelSnapshotTests`：键盘 76 项执行，1 项因固定词库没有离线释义跳过，其余通过；共享 3 项通过。

一万行网格在普通布局与九键三栏检查常驻候选按钮少于 200 个、滚动至末尾并选择全局位置 9999、窗口旋转、原位换代保持偏移、注释更新及缩短列表后的动作复用。现有 AI 占位、释义、字体和皮肤布局回归继续通过。复用后旧测试使用集合视图的共同坐标系，并滚动到目标行再检查可见按钮，不要求离屏控件常驻。

CI 还发现普通全拼的展开/收起回归在重新展开后直接遍历按钮，没有执行布局；虚拟化只为有效视口创建按钮。测试现在先执行 `layoutIfNeeded`，再查找可见的 `panelCandidate-1` 并验证选词完成组字。补跑该回归、候选选择与完整快照：键盘 4 项、共享 3 项通过，不要求同步创建离屏控件。

显式选择远程 Python 3.14 的 quick（`20261019-193953`）通过。补测后的最终 quick（`20261019-204141`）通过；其前一轮因远端系统盘耗尽、Docker 连接中断失败，不计通过。最终轮 Linux 设置壳编译实际通过；Linux 原生因改动范围跳过，原实现的 Linux 原生检查已在首轮通过；本机笔记与差异检查通过。XcodeGen 重生成后工程文件无差异；测试使用原生测试宿主和真实 UIKit 集合视图，不将其计为系统键盘现场验收。

新增跨应用专项的真机 Rust 静态库与锁定资源构建通过；本机 `MSIMEClientUITests` 的 Release 真机 `build-for-testing` 通过，产品 App、独立编辑器与 UI 测试 runner 均通过严格签名校验。XcodeGen 的规范工程只新增 scheme 对独立编辑器的构建项，不提交 CocoaPods 临时注入的工程内容。最终 quick（`20261020-045949`）、笔记与差异检查通过。配对真机仍要求解锁，尚未执行新增用例；编译与签名结果不计为三轮系统键盘验收，更不据此认定极低概率原报告已解决。

## Consequences

完整快照不会因 4096 行的显示限制拒绝展开；按钮数受视口限制，尾部身份与菜单选择保留。全列表测量与几何仍为线性工作，视图回收不等于消除首帧成本。滚动中的菜单与无障碍生命周期由系统单元格管理。

尚未完成真实系统键盘中各方案反复切换的现场验收；原报告没有可重放输入，不能把这一可复现边界修复说成已覆盖所有生命周期原因，PR 使用 `Refs #8782`。
