# Agent Note: Android 剪贴板超过插入上限时不再触发键盘闪烁

Status: implemented

## Problem

#11196 报告 Android 剪贴板多选达到第 5 条时键盘瞬间关闭并恢复。原实现把「一次最多插入 4 项」作为选中时的 `notice()`，提示写入候选区诊断行，诊断行的显隐改变输入法窗口测量高度；同时第 5 条及之后仍创建空的序号角标。插入上限的既有决定是只给前四条画 ①–④，导出和删除仍允许选择到 20 条，见[剪贴板多选按序号插入](../feature/2026-10-31-clipboard-multi-insert.md)。

## Decision

旧系统的确认层归属已由[独立附属窗口](2026-11-15-android-clipboard-acknowledgement-window.md)取代；本篇的第五条选择、角标与插入上限规则继续适用。

多选点击只更新选择状态，不在顶行或诊断行显示插入上限提示。选中超过 4 条时继续保留选择、高亮、导出和删除，卡片只给前四条画序号角标；「插入」按钮保持可点，点击后在输入法窗口的独立确认层显示「一次最多插入 4 项，导出和删除不受影响」和「知道了」，不改变键盘主体测量，也不退出多选。1–4 条仍按点选顺序退出多选并一次插入。

提示层在 Android 11 及以后使用不取焦点的输入法附属窗口并居中，Android 9/10 回退到根视图的 `FrameLayout` 覆盖层：Android 9 原有父窗口已经全高，卡片仍在屏幕中央；Android 10 沿用键盘区域内居中；两条路径都不加入纵向键盘布局。关闭输入法或按「知道了」都会移除提示层。

## Alternatives considered

- 保留选中第 5 条时的诊断行提示：改动最小，但诊断行属于候选区纵向布局，正是输入法窗口闪烁的直接原因，不能解决问题。
- 继续把「插入」置灰：可以阻止无效提交，但用户无法看到明确的上限说明，也不符合超过 4 条仍可导出和删除、点「插入」后再提示的交互要求。
- 使用 Activity 的 `AlertDialog`：系统对话框可能抢走编辑器焦点或收起输入法，且输入法服务没有稳定的 Activity 窗口令牌，因此沿用输入法附属窗口/表面覆盖层。

## Consequences

第 5 条选择不再触发候选区重测量，键盘窗口边界保持稳定；超过 4 条的选择仍可用于删除和导出，插入操作的限制在用户明确点击时才反馈。附属窗口需要随输入法生命周期清理，API 28 的回退覆盖层在原透明全高窗口中显示，卡片单独参与触摸区域，直到用户确认。

## Verification

`ClipboardSelectionPolicySmoke` 覆盖前四条角标、第五条无角标、20 条选择上限和插入上限；Android host Java 编译与设备剪贴板多选 smoke 需在 API 28/35 模拟器上运行。报告者的 Android 11 真机应复验选择第五条、点击「插入」和点击「知道了」三个路径。

定向入口 `smoke.sh --clipboard-selection` 只在主输入通过后运行五条合成记录的多选回归；完整 nightly 同样覆盖，发布短套件不增加这项。测试把专用模拟器设为报告中的 1080×2376、480 dpi、字号 1.25002，结束时恢复原配置；在选第 5 条、点插入和关闭确认层期间每 20 ms 采样输入法窗口身份与边界，验证选择总数、导出/删除可用、编辑器焦点及内容不变，并在回到 4 条后验证按选择顺序插入。API 28 及 API 30 以上另检查提示位于屏幕中央；API 29 沿用键盘区域内居中。保留四条、五条、弹窗和关闭后四幅合成截图。新增设备断言目前待实际运行，不以 JVM 或普通 PR 冒烟替代。

设备 APK 的 instrumentation 已达 Android 的 100 个入口上限，多选回归复用 `ClipboardSegmentDragDeviceSmoke -e selection-only true`，主体放在独立的 `ClipboardSelectionDeviceChecks`；不新增清单入口。

首轮 API 28 定向设备运行 `42811170859` 已通过选择第五条及打开提示的连续窗口断言，但点击「知道了」后返回普通键盘。源码确认 API 28 的根视图本来就是透明全高，`onComputeInsets` 却只把底部键区作为可触摸区域；居中的确认按钮在区域外，真实点击穿透到编辑器，造成输入焦点切换及面板重置。把确认卡片矩形并入触摸区域，不改变窗口大小、应用让出的高度或键盘布局，原有实际点按与选择保留断言不变，并要求 API 28 同样屏幕居中。

首轮截图收集使用 `run-as`，产品 APK 不可调试，产物实际是50字节错误文本。截图改写应用外部专用目录并用 adb pull 收集；未取得的新图不作为已验证视觉证据。

API 35 首轮定向运行 `42811170859` 已成功，包含第五条选择、确认层开关和四条顺序插入；API 28 的触摸区域修正另行复验。针对报告者 Android 11 增加 API 30 定向运行时，`42815349978` 在 SDK 安装脚本仅接受 28/35 的检查处退出，未执行产品测试。安装器补接受 30，并以合成 SDK 验证实际请求 API 30 镜像、损坏下载重试和已有完整镜像复用；默认发布和 nightly 矩阵不变。旧实现负对照同步此安装支持，使用同一套产品断言取得改前画面，不为了拍图关闭失败断言。
