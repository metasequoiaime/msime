# Agent Note: Android 26 键标准底行的逗号不再画误导的句号角标

Status: implemented

## Problem

[手机底行保留逗号并以长按输入句号](../feature/2026-10-16-comma-key-secondary-period.md)让 Android 逗号键右上角画长按句号的角标，那时底行没有句号键，角标是句号唯一可见的入口。[手机 26 键标准底行在空格左边放句号](../feature/2026-11-12-twenty-six-key-period-beside-space.md)之后，标准底行空格左边有了独立句号键，逗号长按输入句号保留，角标也照旧画着：同一行出现两个「。」。

这个角标还在暗示一个不存在的手势（#11823）。同一位置的角标在字母键上表示沿「滑动输入符号」的方向滑一下输入它（`KeyHintButton` 的角标就是按这个含义写的），而标准底行的逗号没有滑动手势（`commaSwipesPeriod` 只在长空格样式成立），只有长按输入句号：照字母键习惯上滑，手指滑出键帽什么都不输入，没滑出就是普通逗号。

## Decision

Android 26 键一族（`KeyboardActionRow.usesCommaSecondaryPeriod`）的逗号只在这一行没有句号键时画句号角标，由 `KeyboardActionRow.commaShowsPeriodHint` 判定：直接看该样式的底行里有没有 `PERIOD` 一格，不另列样式。

- 标准底行（中文、英文，以及韩文、日文罗马字等 26 键）不画；逗号长按仍输入句号，读屏说明「长按输入句号」不变。数字框、密码框退回的标准行同样不画。
- 长空格、表情键样式没有句号键，照旧画：逗号是那里输入句号的唯一入口。
- 「逗号句号」样式的逗号本来就不画（长按是常用标点菜单），不变。
- 英文网址框里逗号主位是 `.`、角标是 `,`（[网址框句点键](../feature/2026-10-27-android-url-period-key.md)），那是这一行唯一的逗号，不变。
- 只改 Android。iOS 与 HarmonyOS 的同一角标不在这次范围内，是否跟进由维护者决定。

## Alternatives considered

- **给标准底行的逗号也加上滑动输入句号，让角标名副其实。** 角标和行为一致，也与 #7835 当初「长按或上滑」的要求更接近。不采用：标准底行已有句号键，再加一个滑出句号的手势只是第二条重复入口，还要处理和点按、长按的冲突；去掉角标更直接。
- **角标跟「显示字母键角标」走。** 能让不想要它的人关掉，默认值也不变。不采用：那个开关只管字母键，扩到逗号会改变它的含义；而且默认仍画着误导的角标。
- **连长按一起改成常用标点菜单，与「逗号句号」样式一致。** 两种有句号键的底行行为统一。不采用：老用户已经习惯长按逗号出句号，去掉角标只是少画一个重复的提示，不需要连手感一起改。
- **三端一起改。** 与 #11325 的做法一致。这次只做 Android，iOS 和 HarmonyOS 维持现状，等维护者决定。

## Consequences

- 标准底行的逗号键面只剩居中的「，」，与「逗号句号」样式的逗号一样；同一行不再有两个「。」，键面也不再暗示滑动。
- 「表情键」样式的逗号同样画着角标、只能长按，没有改：那一行没有句号键，角标是句号唯一的可见入口；它的角标与手势仍不一致，是否给它加滑动另行决定。
- 代价：标准底行上长按逗号出句号变成看不见的捷径，只靠读屏说明和老用户的习惯；有独立句号键，新用户不需要它。
- Android 与 iOS、HarmonyOS 在这一处键面上不同，直到两端跟进。

## Verification

JVM 冒烟 `KeyboardActionRowSmoke` 逐个核对 26 键与韩文 26 键的每种底行样式：角标与「这一行没有句号键」一致（只有长空格和表情键画），14/18 键、注音、九键、笔画和手写一律不画；`check-host.sh` 372 项冒烟通过。API 35 模拟器（x86_64 包）：`smoke.sh --pr` 与 `LetterHintPunctuationDeviceSmoke`（标准底行长按逗号只出一个句号）通过；截图核对标准底行逗号无角标、长空格样式仍有。没有在真机上看，API 28 没有跑。
