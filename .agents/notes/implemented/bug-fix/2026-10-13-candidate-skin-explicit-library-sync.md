# Agent Note: 单款皮肤安装与手动整库同步分开

Status: implemented

## Problem

候选窗口皮肤的一键安装只下载一个发布包，但共享社区页挂载、安装成功和设置组件启动都会隐式运行整库双向同步。同步会下载账号云端库中尚未落地的所有个人皮肤，也会上传本机包；用户选择单款皮肤或浏览社区时无法预期这些操作。

## Decision

共享候选皮肤图库提供「同步我的皮肤库」按钮，说明下载云端个人皮肤、上传本机皮肤和同步已记录的删除。只有点击才运行整库同步，并展示进度、结果和失败。取消页面挂载、单款安装后的同步和设置组件启动后台同步。单款安装保留来源记录及目录更新通知；核心同步算法和显式宿主命令保持现有语义。

## 历史笔记审计

- [Windows 原生社区页](../../implemented/feature/2026-10-11-windows-settings-community-tabs.md) 部分重叠：它记录了原生 WinUI 的自动同步；本次仅收窄共享图库和设置组件启动入口，Windows 原生页不在本次验收范围内。
- [社区页 C 接口](../../implemented/architecture/2026-10-11-windows-settings-community-host-api.md) 部分重叠：接口语义不变，启动自动同步的事实由本篇接管。
- 同步目录句柄、状态锁、删除安全笔记与触发时机无关；现有持锁和安装来源契约保持不变。

## Alternatives considered

- 仅取消安装后的同步：改动最小，但打开页面和启动组件仍然能拉取整个云端库，无法保证用户操作范围。
- 修改核心同步算法，使其永不下载未安装的云端包：能从底层限制下载，但会破坏用户明确请求的跨设备整库恢复。保留算法，改为明确的手动入口。

## Verification

- 相关社区、同步生命周期及皮肤目录刷新测试：4 文件、58 项通过。覆盖浏览和筛选不自动同步、普通及替换安装只调用选中的发布 ID、明确点击才同步、忙时重复点击、失败重试、暂停结果、本机变化刷新，以及旧账号的成功或失败不污染新账号。
- 共享 UI 类型检查、构建、本次改动文件 lint 与格式检查、Rust 格式检查、`cargo clippy -p msime-desktop --all-targets --locked`、笔记门禁、`git diff --check` 和本地 quick 门禁通过。全仓格式检查命中 `develop` 已有的 `local-modes-section.test.tsx` 格式问题，本次未改该文件。
- macOS 设置组件编译、打包、安装及 `codesign --verify --deep --strict` 通过。经原生宿主生产启动入口打开设置，确认社区页显示手动同步按钮；仅启动和浏览不会改变皮肤目录数量或同步状态文件。单款安装及整库同步使用合成客户端测试，本机未对真实账号发起同步。安装保留已合并的四标签修复，已启用输入模式仍仅中文。

## Consequences

关闭自动同步后跨设备皮肤库不再即时恢复，用户需要主动点击同步。已安装包保持原样，不清理用户既有皮肤。
