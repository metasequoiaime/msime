# Agent Note: 数字行开启时数字与符号页保留第五排

Status: implemented

## Problem

#8210 中开启数字行的字母页有五排，切到数字或扩展符号页只有四排，可直接点选的字符减少。Android 的本地数字行与 iPad 全宽完整按键都存在这个落差。

## Decision

源字母布局会显示数字行时，数字和符号页保留相同高度的补充行。Android 继续使用数字行开关、26 键或韩文布局和 480dp 窗口高度门槛；iOS 继续使用 iPad 全宽完整按键开关。真正的九键、14 键、笔画、手写、假名、注音及窄屏不增加行。

借用的中文数字九宫格增加括号、百分号、货币与上标键；常规 123 页增加 `[ ] { } # % ^ * + =`；扩展符号页增加 1–0。已有数字页不重复数字凑行。补充键复用所在层的输入、样式和分体规则，数字九宫格不分体。补充行与源字母数字行使用相同高度分摊，切页不挤压按键。

## Alternatives considered

- 保持四排并放大按键能减少表与视图，却没有增加可点选字符，不能解决报告的问题。
- 重复一排数字最易复用，但常规数字页已有数字，浪费新增键位，改用该页原来没有的符号。
- 所有布局统一加行能统一页数，但真正九键和窄屏的源字母页本来只有四排，没有额外高度可保留。

## Verification

Android 宿主检查、原生 arm64 安装包与笔记门禁通过。API 28 核心套件全部通过；新增用例实际通过切换字母、数字、扩展符号页时的高度、补充键输入、关闭开关与横屏边界。iOS 原生控制器回归覆盖 iPad 第五排、中文与英文切层、手机及原九键排除。完整 `scripts/verify-local.sh --quick` 通过。API 35 新增用例及默认设备套件分段通过；Xcode 27 / iOS 27 模拟器中的原生控制器测试共 22 项、0 失败（20 项形态测试和 2 项切层与键面测试）。

API 28 原核心套件在笔画布局因瘦包缺可下载词库而回落全拼；用于重跑的语言包六个文件均对照仓库锁核验长度和 SHA-256，只暂存到专用 AVD，未声称验证下载。新增用例沿用了原脚本的 `InputStream.readAllBytes`，它在 [Android API 33](https://developer.android.com/reference/java/io/InputStream#readAllBytes()) 才提供；改用缓冲读取后，API 28 横屏检查与清理正常完成。

API 35 默认套件前段使用瘦包，在直接读取随包日文词库的用例停下；构建包含锁定语言词库的完整验收 APK 后，从该用例继续，剩余 28 项及剪贴板生命周期全部通过。前后段的日志分别保留，不把缺资源的首轮算作一次全套成功。iOS 测试使用原生键盘测试宿主中的真实控制器布局，不等同于系统键盘向外部编辑器输入的端到端验收；本轮没有安装用户真机。

## Consequences

数字九宫格的补充行复用网格字面提交，普通符号页复用原符号路由，避免数字选候选语义混入。Android 分开记录字母数字行与符号补充行，设置、旋转和标点改变会使相应布局缓存失效。iOS 的高度、分体与间距遍历均包含新行。

增加一排可直接点选字符，切层保持源字母页高度；代价是两个宿主各维护一张十键补充表，需同步键面。关闭数字行、窄屏与源网格布局仍使用原行数。
