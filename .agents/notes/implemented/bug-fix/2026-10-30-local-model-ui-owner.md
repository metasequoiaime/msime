# Agent Note: 本地语音模型操作绑定客户端代次

Status: implemented

## Problem

`LocalModelManager` 已用客户端代次隔离进度订阅，但列表、安装、导入和删除只比较客户端对象。A→B→A 后旧操作重新被当作当前操作：迟到的列表与错误覆盖新状态，旧安装或导入调用选用回调，旧 `finally` 清除新操作的忙标记并再次刷新。删除确认返回之前切换客户端或卸载组件，旧流程仍会调用宿主删除模型。

## Decision

复用已有 `useAsyncGeneration(client)`，在操作开始时捕获代次；确认返回后、发起宿主操作前、成功与失败回写以及 `finally` 刷新均校验挂载状态、客户端对象与捕获代次。已经提交给宿主的操作正常结束，但过期结果不再更新当前界面。

列表刷新另有单调请求序号，同一客户端内并行安装产生的旧快照也不能覆盖较新的列表。

## Alternatives considered

- 仅比较客户端对象，改动最少且能隔离 A→B；但无法区分返回同一 A 对象后的新生命周期，现有进度订阅已经证明这里需要代次。
- 取消所有旧下载或导入，可以减少后台工作；但切换页面归属并不等于用户取消安装，组件也无法回滚已经发出的删除。本次只限制过期 UI 流程继续提交与回写。
- 每个动作另建通用请求管理器可以集中代码，但这里已持有客户端代次，列表序号和局部守卫足以表达边界。

## Verification

新增 13 条真实组件回归在旧实现全部失败，分别观察到旧列表回写、过期路径被选用、旧失败清除新忙标记、旧删除确认调用宿主，以及并行安装后旧刷新回退最新列表。修复后新增回归与现有本地模型组件、挂载复用测试共 3 个文件、41 项全部通过。测试用受控 Promise 安排完成顺序，数据全部为合成值；未增加产品测试入口。

桌面与 Harmony 前端类型检查及生产构建、定向 lint、格式检查、笔记校验、`git diff --check` 和仓库 contracts 通过（缺少工具或平台环境的检查明确跳过）。本机内置盘本轮约 43–47 GiB，低于仓库新建完整构建树的门槛，尚未启动新的 Rust quick 构建。没有原生设置窗口或设备验收，不能将组件测试称为装机验证。

## Consequences

客户端替换、复用及卸载后，旧操作不能继续删除模型，也不能选用旧路径、回写消息或清空新操作。列表增加请求序号以拒绝同一客户端内的旧快照。已经提交给宿主的安装与删除正常结束，不因界面归属变化而取消或回滚。

不修改 Rust 模型文件读写、安装锁、宿主协议或默认值。代价是每次异步操作都要保存客户端代次，所有后续交互继续遵守这一守卫。
