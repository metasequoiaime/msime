# Agent Note: Android 自动数字行离开触发应用即复位

Status: implemented

## Problem

#10878：在 26 键里进过一次验证码或密码框后，字母上方自动多出的数字行再也收不起来，到别的应用也一直在，只能强制结束输入法进程。

[密码框与 SSH 工具临时展开 Android 数字行](../../implemented/feature/2026-10-21-issue-8972-automatic-number-row.md) 照搬 GBoard，把自动数字行保留到系统切换输入法：普通输入框和收起键盘都不清除。多数人只装一个输入法、从不切换，于是这一行等于在进过密码框后永久打开。它不写共享偏好，设置页的「顶部数字行」开关仍显示为关，用户把开关打开再关掉也收不起来，因为实际值是「手动开启或自动开启」，关掉的只是手动那一半。

## Decision

`AutomaticNumberRow` 记下最近一次触发它的应用包名（`EditorInfo.packageName`）。之后进入不触发的输入框时：

- 包名与触发应用相同，保留。同一应用里从密码框到用户名框、ConnectBot 和 JuiceSSH 的各个输入框（它们本来按包名逐个重新触发）都还有数字行。
- 包名不同，或触发时、进入时没有包名（无法判断是不是同一应用），复位。复位后回到触发应用的普通输入框也不再出现，再进密码框或终端会重新开启。

另外，共享偏好 `touch_number_row` 重读时从开变成关，也一并复位（`AutomaticNumberRow.manualChanged`，在 `MSIMEInputService` 写 `numberRowEnabled` 的两处调用）。这是同一应用里留下的自动数字行唯一的手动出口。系统切换输入法时照旧复位，切回来时按当前输入框重新判断。

状态仍只在内存里，不写偏好、不落盘，包名不进日志。

## 历史决策审计

- [密码框与 SSH 工具临时展开 Android 数字行](../../implemented/feature/2026-10-21-issue-8972-automatic-number-row.md) 部分被取代：触发条件、不写偏好、监听系统输入法、切回时重新判断仍然成立；「保留到切换输入法」收窄为「保留到离开触发应用、关掉开关或切换输入法」。那篇已加指向本篇的链接。
- [Android 数字行](../../implemented/feature/2026-10-09-android-number-row-and-split-duplicates.md)、[触屏按键布局样式与顶部数字行](../../implemented/feature/2026-10-27-touch-key-layout-styles.md) 无关：手动开关的存储、画法范围与高度限制不变。

## Alternatives considered

- **只按当前输入框实时开关**：最简单，离开密码框就消失，也正是 #10878 提交者说的「验证码场景不更变布局」。但 #8972 要的正是离开密码框后继续可用（例如输完密码再在同一页填数字），同一应用里的保留还有用处，不采用。
- **保留旧语义，只在用户关掉「顶部数字行」时复位**：改动最小，但开关默认就是关，用户得先打开再关掉才收得起来，没人想得到；不在同一应用里的情况本来就不该留着，所以只作为同一应用里的补充出口。
- **收起键盘（`onFinishInputView`）时复位**：同一应用里换输入框常常先收起再弹出，这样等于按输入框实时开关，与第一条相同，不采用。

## Consequences

收益是自动数字行不会再跨应用常驻，用户在同一应用里也能经开关收起它。代价是 #8972 里「保留到切换输入法」的承诺收窄了：在 A 应用的密码框之后切去 B 应用的普通输入框，数字行会消失，回到 A 也不会自动回来（要再进一次密码框）。与 GBoard 的行为因此不再一致。同一应用里的验证码页之后继续在同一应用聊天，这一行仍会留着，直到关开关、换应用或切换输入法。

JVM 冒烟 `AutomaticNumberRowSmoke` 覆盖同应用保留、换应用复位、没有包名时复位、最近一次触发的应用持有保留、终端按包名重新触发、开关从开到关复位。设备用例 `AutomaticNumberRowDeviceSmoke` 仍只验同一测试应用里的保留和切换输入法复位；跨应用复位和关开关复位没有设备用例，要靠 CI 之外在真机上补测。
