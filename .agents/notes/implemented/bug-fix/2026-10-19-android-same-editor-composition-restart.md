# Agent Note: Android 同编辑器重启连接时核对并保留拼音组字

Status: implemented

## Problem

#8771 报告聊天框首个双拼字母不出候选，重复字母后才出现。`onStartInput` 无条件销毁引擎，即使 `restarting` 为真，编辑器仍有刚写入的组字。合成 `RestartingEditorActivity` 每次文字改变后重启连接；API 28 原产品输入首字母后，连接创建数增加，候选随即消失，新增专项失败。此证据没有证明 B 站实际使用相同回调。

## Decision

只在已有活动全拼或双拼组字、当前文档仍在、包名/字段/inputType/imeOptions 都相同、编辑器初始折叠光标与 `SelectionEchoTracker` 记下的组字尾部及长度精确匹配时读取新连接的组字后缀。后缀必须与当前显示的组字完全相同；随后用 `setComposingRegion` 重新标记已确认的区间，成功才保留原引擎和桥接状态。不重新写文字，不复制引擎组词规则。未知位置、不可读后缀、改写、清空、字段切换或拒绝标记均走既有重建路径。其他方案及不在编辑器内显示组字的布局保持原生命周期。

API 35 设备回调证明仅在 `onStartInput` 保留仍然不够：编辑器可以先报告折叠光标不动、组字标记变为 `-1/-1`，原 `onUpdateSelection` 已在重启前清空引擎。API 28 还可能在第一次选区回报里就已经丢失标记，不能要求先收到一次正常组字区回声。此时旧连接可能已断开，直接尝试重标记也会失败。只有位置仍精确匹配完整组字尾部的原地标记丢失才延后最多 100 ms；紧随的 `onStartInput` 取消该回报并核对新连接。没有重启就按原取消规则处理，新选区回报会取代它，结束输入立即撤销；新按键、命令与候选选择先处理待定回报，避免向失去标记的区间追加第二份拼音。不延后真正光标移动、清空或改写。

[Android InputConnection 契约](https://developer.android.com/reference/android/view/inputmethod/InputConnection)允许文本读取失败，`setComposingRegion` 只改标记不改文字。读取不进入密码框，不输出文本或异常原文。

## Historical audit

- [过期引擎启动](../../implemented/bug-fix/2026-10-14-android-stale-engine-startup.md)部分重叠：异步启动围栏继续生效，只避免已确认相同组字的无效销毁。
- [连接失败恢复](../../implemented/bug-fix/2026-10-15-android-input-connection-recovery.md)部分重叠：保留有限次故障恢复，不把 `restarting` 当故障。
- [数字层默认值](../../implemented/feature/2026-10-15-mobile-default-number-pad.md)部分重叠：数字层的同编辑器重启规则继续独立成立。

## Alternatives considered

- **所有 restarting 都保留引擎**：实现最小，但应用可能已清空或改写文字，会把旧组字带入新位置。
- **只比较光标或后缀**：读取最少，但相同位置可能已有不同文字，仅相同后缀又无法排除移动；必须同时核对并重建标记。
- **从原文重放引擎**：能重建候选，但丢掉已选片段、候选身份和上下文，并在宿主复制恢复状态机。

## Verification

API 28、35 的原生 APK 均通过合成编辑器专项：全拼及首道双拼首字母候选保留、后续字母继续组字、空格只替换一次；外部清空、同位置改写、移动光标和换字段不复活旧组字。另有不触发重启、只结束标记的反例：等待 500 ms 后新输入的 a 独立转换，前面的 n 保留为字面文字，避免把无限保留误当修复。原版在 API 28 的首字母候选断言失败。

两 API 的数字层同编辑器重启、延迟批量组字专项均通过；位置跟踪 JVM 回归覆盖未知位置、非折叠选区、错位、长度不符、结束标记及失效状态。最终 Java 宿主门禁和 quick 通过（远端 20261019-202354），测试 APK 使用 javac 严格编译并在设备执行；笔记与差异检查通过。没有输出输入文本或异常原文。

## Consequences

后缀读取是可能失败或耗时的跨进程调用，仅在身份和位置严格匹配的活动拼音组字重启路径执行。无重启的原地标记丢失最多延后 100 ms，新的输入动作会提前结算。应用有意结束组字但保留完全相同文字和光标时会恢复标记，这是连续输入选择的语义。真实 B 站及 Android 16 未验收，PR 使用 `Refs #8771`。
