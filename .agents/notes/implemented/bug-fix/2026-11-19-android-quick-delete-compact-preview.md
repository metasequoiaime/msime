# Agent Note: Android 顶部删除键保留紧凑快速删除提示

Status: implemented

## Problem

#11578 让九键空闲状态不再预留读音行，第一排删除键因此上移到键盘覆盖层顶部附近。原快速删除策略要求删除键上方至少放下 28 dp 提示框，并保留两段移动距离，九键在这个位置会直接判定不可用。API 35 nightly 的 `QuickDeletePreviewDeviceSmoke` 因此在九键静止长按时看不到提示。

## Decision

`BackspaceSwipePolicy` 在空间充足时继续使用原来的 40 dp 提示框和 8 dp 第二段移动距离。顶部空间只够窄条时改用 16 dp 紧凑提示框，待命线放在删除键上沿上方 12 dp，仍先越过显示线再越过 4 dp 的待命距离。连紧凑框也放不下时才保持原来的普通连删行为。

快速删除的清空范围、撤回、组字边界、短按和隐藏工具栏下的安全条件不变。紧凑框只改变提示层的几何和可用性，不改变松手前的删除动作。

## Alternatives considered

- **继续禁用顶部删除键的快速删除**：最强的理由是保持旧的安全边界。放弃它，因为键盘布局变化后九键常态触发了报告中的缺失提示，用户无法使用已有功能。
- **把提示框画到键盘旁边或覆盖删除键**：最强的理由是能保留原框大小。放弃它，因为旁边没有稳定空位，覆盖按压键会干扰当前手势和邻键点击。
- **让顶部空间不足时直接进入待命**：最强的理由是无需新增几何分支。放弃它，因为手指刚离开键帽就会清空正文而没有可见确认。

## Consequences

- 九键等删除键靠近覆盖层顶部的布局仍会显示可见的快速删除提示，并要求第二段上移后才清空。
- 空间充足的 26 键和其他布局保持原提示尺寸与触摸距离。
- JVM 回归覆盖无法显示、紧凑框显示与待命、普通框显示三种边界。真实 API 35 nightly 仍需在合并后的 scheduled run 中复核。
