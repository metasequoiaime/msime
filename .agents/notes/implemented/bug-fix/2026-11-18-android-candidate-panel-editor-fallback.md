# Agent Note: Android 候选部分上屏后保留剩余组字

Status: implemented

## Problem

[#11565](https://github.com/metasequoiaime/msime/issues/11565) 报告淘宝和抖音商城输入句子时，展开候选后每选一个字候选区域就收起，下一字必须再次下拉。Android 宿主的候选选择会在同一批次先上屏已选字、再写入剩余拼音；部分 WebView/Compose 编辑器接受前一步却拒绝后一步，宿主把这种部分成功误判为整次输入失败，导致候选视图收尾并关闭面板。

## Decision

`EditorBridge` 记录最近一次批量写入是否已经成功提交正文、随后明确拒绝了非空组字。Android 宿主只在这两个条件同时满足、且本次响应确实包含上屏文字和剩余组字时，把当前编辑器切换到既有的键盘内组字状态：保留共享引擎的下一代视图和候选面板，拼音不再写入不兼容的编辑器，后续候选选择继续只提交确定文字。提交成功后清除该抑制状态，离开输入框仍按原生命周期处理。

这条回退由编辑器实际返回的拒写触发，不按输入类型、应用包名或“搜索框”猜测兼容性；能正常接受组字的 QQ 等编辑器继续走原来的行内路径。它补在既有的 [Android 应用组字豁免](../../implemented/bug-fix/2026-10-22-android-app-composition-exclusion.md)之后：精确包名例外仍覆盖逐键触发搜索的编辑器，本 issue 覆盖只在候选部分上屏时才暴露拒写的编辑器。

## Alternatives considered

- **继续把部分拒写当作输入失败**：能保持最保守的编辑器契约，但会丢掉已经成功上屏的候选和剩余引擎组字，正是 #11565 的候选面板收起。
- **把淘宝、抖音或所有搜索框加入包名白名单**：可以绕开报告中的应用，却依赖应用身份和字段用途，不能覆盖同类 WebView/Compose 编辑器，也会重复已有精确包名例外的维护成本。
- **先把剩余拼音写入再检测并清除**：编辑器可能已经触发搜索或文本变更，且清除会破坏候选选择的原子性，因此不采用。

## Verification

`EditorSmoke` 使用只接受 `commit`、拒绝非空 `compose` 的合成编辑器，验证部分成功可被识别、纯组字拒写不会误报为部分上屏。Android JVM/宿主 quick 门禁和 API 28/35 设备回归需在 PR 分支上继续执行；真实淘宝、抖音和报告者设备未验收，保留在 PR 验证缺口中。

## Consequences

不兼容编辑器第一次部分选词后会把剩余拼音留在键盘内，输入框只收到已确定文字，候选面板可连续使用；正常编辑器行为不变。这个状态只存在当前输入会话，应用离开或候选结束后恢复既有生命周期。若编辑器在提交文字后以异常方式返回成功但静默丢弃组字，仍由已有的组字读回校验处理。
