# Agent Note: 发布并锁定候选词条修复后的词库

Status: implemented

## Problem

`msime-dictionary` 的 #76 已补齐 #7583 反馈的缺失词条，但客户端锁文件仍指向 `dict-v2.0.14`。只合并词库源数据并不会改变已下载或新安装客户端使用的词库，修复因此无法生效。

## Decision

客户端统一改锁 `dict-v2.0.24`，并把锁中的 `source_commit` 更新为该发布实际使用的 `msime` 构建提交。主锁、语言词库锁、组件锁和版本派生锁保持由 `resources/desktop-dictionary.lock.json` 生成关系；同步更新各语言文档中的发布版本说明。新发布的 SHA-256 和大小直接取 GitHub Release 资产元数据，避免手工下载二进制后再复制摘要。

## Alternatives considered

- **只更新 `msime-dictionary` 源数据，不改客户端锁。** 最省改动，但客户端仍下载旧词库，#7583 的缺词修复对用户不可见，因此不采用。
- **只更新 `desktop-dictionary.lock.json`。** 能改变 full 版本，但组件版、语言版和派生锁会继续指向旧资源，且生成关系被破坏，因此不采用。
- **把新词条复制进 msime 仓库的本地资源。** 能绕过发布锁，但会复制词库构建产物并形成两份来源，后续发布容易漂移，因此不采用。

## Consequences

新安装和下一次资源刷新会下载包含 #76 词条的 `dict-v2.0.24`；所有资源锁仍由同一主锁派生，校验摘要与发布资产一致。锁版本更新也会使整句模型和词库的来源提交一起前进，依赖真实词库的评测需要在新锁上重新运行；本次只验证锁生成、资产摘要和仓库门禁，不把旧评测数字宣称为新词库结果。

锁之后改到 `dict-v2.0.39`，并在新锁上重跑了评测基线，理由与前后数字见[跟上设备实际在用的词库](2026-10-27-dictionary-lock-latest.md)。
