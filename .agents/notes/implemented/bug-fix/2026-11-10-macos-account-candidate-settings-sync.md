# Agent Note: macOS 账号同步候选窗口设置

Status: implemented

## Problem

#11081 的 macOS 共享账号页可以同步输入偏好，却不会同步候选窗口的主题、布局和外观设置。旧的 `platform.macos.*` 快照只覆盖回退窗口的一小部分字段，正常的共享设置同步路径不会读它；用户在两台 macOS 设备上登录同一账号后，候选窗口仍需重新配置。候选皮肤包和插件包本体也不能只靠设置值凭空出现在另一台设备上。

## Decision

macOS 的设置同步在 `client-services` 里导出并应用候选窗口运行时实际读取的全部可同步偏好，继续使用 `platform.macos.*` 命名空间，以免覆盖其他平台的同名设置。范围包括候选窗口主题、全局主题、自定义主题底色和浅色/深色候选皮肤槽位、候选布局与数量规则、页数与候选显示开关、字体和字重、预编辑与翻译字号、整体缩放、不透明度、圆角、窗口与候选项内边距、候选项间距、按内容收紧、字体回退列表和候选颜色。

可选数值用 `-1` 表示跟随皮肤或清除本地覆盖；可选字符串用空串表示清除；字体回退列表编码为受服务端长度限制的 JSON 字符串。应用端逐键复用 `Preferences::validate`，越界或无法识别的单项进入 `skipped`，不会让其他设置失效。候选皮肤包本体仍由皮肤库单独下载，缺包时保留设置值并由宿主按现有逻辑回退。

服务端字段表同时收录这些键并保留整数范围和字符串长度限制，客户端在上传时仍只提交服务端 schema 已知的字段；旧版原生快照字段继续兼容读取。

## Alternatives considered

- **只同步报告者提到的垂直内边距和圆角**：改动更小，但主题、字体、布局和其他候选窗口选项仍会在设备间漂移，不能满足“尽可能将设置全部同步”。因此改为覆盖 macOS 候选窗口实际可修改且运行时读取的整组字段。
- **复用旧 SwiftUI 回退窗口的快照映射**：可以少写一套字段，但它遗漏共享设置页新增的布局、字体、颜色和展开选项，而且回退窗口按架构约定冻结。共享 Rust 映射独立读取 `Preferences`，保留旧键只作为兼容输入。
- **把候选窗口设置放进共用 `input.*` 键**：会让 Android、鸿蒙、iOS 和 Windows 上传或应用它们没有控件的默认值，覆盖其他设备的选择。macOS 专属键保留在 `platform.macos.*`。

## Consequences

两台 macOS 设备经共享账号页应用设置后，候选窗口的外观和布局可一致；缺少皮肤包时仍安全回退，不会下载未验证的资源。服务端 schema 变大，旧客户端会忽略新增键，客户端升级后可读取已有账号文档。思考强度、切换热键、凭据、自动学习记录和词库内容仍不通过这条设置映射同步；词库使用已有的 WebDAV/云词库同步入口。

## Verification

客户端设置同步回归覆盖全部 macOS 候选字段的导出、应用、清除覆盖和非法值逐键跳过；服务端验证覆盖新增字段的类型、范围和长度，OpenAPI 与字段表由生成脚本核对。提交前运行 Rust 相关测试、后端 Go 检查、`cargo fmt`、`pnpm run verify-notes` 和 `git diff --check`。
