# Agent Note: Android 十八键去除侧栏，三端铺平第二排

Status: implemented

## Problem

Android 十八键沿用了十四键的左侧符号栏和第二排半键缩进。真机上这会在字母区左侧形成一条连续的高底轨，`A` 与 `L` 同时向内缩，三排字母看起来像拼在两个不同网格里。十八键本身已有第三排「符」键，不需要再占一列放空闲符号。

## Decision

十八键字母层不再创建左侧符号栏，三排从同一左右边界铺开；第二排的六个键按整行宽度分配，因此 `A` 与首排 `Q` 左对齐，`L` 与首排 `P` 右对齐。第二排的几何按移动端一致的要求同时改到 iOS（去掉 `layoutMargins` 半键缩进）和鸿蒙（去掉两侧 0.5 份占位），三端设置页与皮肤预览按同一规则画十八键，避免预览和真机分叉。左侧符号栏只有 Android 有过，不涉及另外两端。

Android 十八键的拼音选择挂到读音行、读音右边，与 iOS、鸿蒙的 14/18 键拼音条同一位置：读音和选择条各占半行，没有拼音可选时选择条收起。十八键组字时引擎同时给出拼音和候选，选择条必须和候选行分开，候选在整个组字过程中都能直接点。十四键继续保留左侧拼音栏和原有几何。

这项决定部分取代[Android 十八键全拼入口](../feature/2026-10-24-android-eighteen-key-quanpin.md)和[Android 十八键双拼](../feature/2026-10-24-android-eighteen-key-shuangpin.md)中“复用十四键侧栏、第二排居中”的布局描述，以及 [iOS 十八键](../feature/2026-10-25-ios-eighteen-key.md) 中第二排两侧留半键边距的几何；组码、候选、长按和底行行为不变。

## Alternatives considered

- 保留侧栏，只把底轨收进三行范围：能修正上下边界，但侧栏仍让十八键多出一列，无法解决截图中的整体拥挤和 `A/L` 缩进。
- 保留侧栏并把第二排铺满：可以让 `A/L` 对齐，但左侧连续底轨和三排不属于同一网格的问题仍在。
- 只在空闲时隐藏侧栏：组字前后键位会横向移动，拼音选择出现时还会改变触摸区域；因此十八键始终不创建侧栏。
- 拼音选择叠在候选行上（注音九键的做法）：注音的选择条只在候选列表关着时出现，候选行本来是空的；十八键组字时拼音和候选同时存在，叠上去会盖住候选文字并吞掉候选的点按。把候选藏起来又让用户在选拼音前没法直接选词。
- 在字母区上方另加一条拼音行：不挡候选，但键盘常驻多出一行高度，空闲时也要留着这条空白才不让键位跳动；读音行本来就在，放进去不增加高度，也与 iOS、鸿蒙一致。

## Consequences

三端十八键字母区的三排边界一致，第二排键宽会因只有六个键而比首排宽，触摸区域随可用宽度完整铺开。Android 十八键的拼音条在读音行里，按键与「漢」同字号、不画键帽，读音长时截尾让出半行。符号入口统一由第三排的「符」键提供；十八键不再显示左侧 `，/。/?`。十四键和九键的侧栏行为不变。设备几何断言改为检查第二排左右边界与首排对齐，不再要求三排字母键等宽或第二排居中。

## Verification

- Android JVM smoke 与真机 APK 需要在本次布局改动后重新运行。`EighteenKeyQuanpinDeviceChecks` 在拼音条显示时检查它与候选「你好」不重叠，并用 `input tap` 按候选在屏幕上的中心坐标点它，确认真实触摸能上屏。
- iOS `EighteenKeyKeyboardTests` 检查第二排六键等宽、`A`/`L` 与 `Q`/`P` 对齐；鸿蒙键面需要在真机或模拟器上看一次第二排。
- 真机截图必须同时包含完整十八键三排、底行和工具栏，确认没有左侧符号栏且 `A/L` 与首排边界对齐。
