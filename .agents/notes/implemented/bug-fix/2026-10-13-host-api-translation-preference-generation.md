# Agent Note: 释义偏好变化撤销旧代次回包

Status: implemented

## Problem

`translation_query` 读取最新请求的翻译设置，但 `apply_translations` 只检查候选 `generation`。组字期间关闭候选翻译后，关闭前的异步释义仍能写回候选栏；关闭再打开或切换目标语言时，同代次旧服务的译文也可能落在新配置下。已显示的旧语言释义同样会一直留着。

## Decision

Host API 比较最新请求的偏好与新快照中影响释义查询的字段：候选翻译和离线英文释义开关、读音开关、目标语言、账号选择及三个自有翻译服务配置。组字期间这些字段变化时，运行时清空当前释义并推进候选代次，随后发布新偏好。旧代次回包由现有 `apply_translations` 代次检查拒绝；新查询使用新代次。组字文本和本地候选保留，相同偏好的重复同步不推进代次。

Linux 的 IBus 与 Fcitx5 宿主同步把读音开关列入翻译请求重置条件。读音开关会改变 `translation_query` 的字段；只让共享层换代而不撤销宿主正在处理的请求，会让旧任务占住宿主的加载状态，延后新设置的释义查询。

## Alternatives considered

- 只在回包时检查当前开关：能挡住关闭期间的结果，却无法识别重新打开后的旧请求或目标语言切换前的译文。
- 给释义查询和应用接口增加独立请求令牌：能保持候选代次不变，但所有原生宿主的 C ABI 桥接、回包协议和去重逻辑都要同步迁移。现有代次已承担旧回包校验，因此沿用它。
- 每次偏好更新都推进代次：实现短，但主题、皮肤等无关偏好也会使候选身份失效。

## Consequences

切换释义相关设置会立刻移除旧译文，并让旧候选 ID 失效；宿主需要使用偏好更新返回的新 `view`。候选文本与组字过程不重置。即使当前释义为空，相关设置变化也推进代次，保证关闭再打开期间的旧回包不能复用；只有实际清掉释义时才推进展示事件计数器。

## Verification

使用合成释义的 Host API 回归先证明关闭后的旧回包被接受；修复后覆盖关闭再打开、目标语言切换和已显示释义清理。`msime-input-runtime` 236 项、`msime-host-api` 589 项通过，另有 1 项原有忽略；两 crate 的 Clippy 通过。Fcitx5 原生回归先证明只切换读音时宿主没有重置翻译请求，补齐 Linux 两个宿主的重置条件后通过。
