# Agent Note: Windows 待确认回复期间暂停候选重排

Status: implemented

## Problem

Windows 宿主在输入停止 150 毫秒后会调用 `rerank_settled`。如果上一按键的回复还没有确认送达，候选窗仍可能展示旧代次；重排推进 Engine 代次后，随后送达的数字选词会按旧代次校验并被拒绝，表现为候选反复变化且无法上屏。释义页也复用 Engine 列表的代次，底层列表在释义页打开时不能被重排。

## Decision

`FocusedSession::rerank_settled` 保留 develop 已实施的异步评分协议：回复合成器存在待确认回复时返回 pending，既不启动也不轮询评分；回复确认后继续异步处理。本次补齐释义页处于打开状态时暂停底层评分，页面关闭后恢复。回归保留异步评分、旧组字和焦点过期的全部原断言，另通过真实多义释义页与 fake C ABI 计数验证页面送达后仍不启动或轮询评分、Esc 关闭后恢复。

## Alternatives considered

- **候选窗可见时一律禁止重排**：能更宽地避开代次变化，但会放弃静止输入后的排序更新，改变已有候选体验；本次证据只要求保护回复确认窗口和释义页，因此不扩大范围。
- **在数字选词处重试旧代次**：需要跨候选窗、回复合成器和 Engine 增加旧视图恢复或重放协议，可能把已经过期的选择重新应用；宿主已有待回复闸门，直接延后重排更符合现有时序。

## Consequences

待确认回复或释义页期间不会发生 settled rerank，候选代次保持稳定，数字选词可以继续按送达时的视图校验。输入真正空闲后仍会执行原有重排；如果用户一直保持释义页或回复未确认，排序更新会推迟到这些状态结束。设备和真实编辑器验收的实际覆盖在 PR 验证段单独记录。MSVC 将原有 C ABI 夹具中的直接抛异常视为 C4297 错误，因此同步旧入口误用时改为输出固定错误并立即 `abort`，保留原本的强失败约束，不放宽 `/WX`。
