# Agent Note: Windows 待确认回复期间暂停候选重排

Status: implemented

## Problem

Windows 宿主在输入停止 150 毫秒后会调用 `rerank_settled`。如果上一按键的回复还没有确认送达，候选窗仍可能展示旧代次；重排推进 Engine 代次后，随后送达的数字选词会按旧代次校验并被拒绝，表现为候选反复变化且无法上屏。释义页也复用 Engine 列表的代次，底层列表在释义页打开时不能被重排。

## Decision

`FocusedSession::rerank_settled` 在回复合成器存在待确认回复，或释义页处于打开状态时直接跳过，不推进 Engine。没有待确认回复和释义页时保持原有的 settled rerank 行为。回归测试通过 fake C ABI 计数确认这两个时序：待确认回复期间不调用核心，回复确认后允许调用核心。

## Alternatives considered

- **候选窗可见时一律禁止重排**：能更宽地避开代次变化，但会放弃静止输入后的排序更新，改变已有候选体验；本次证据只要求保护回复确认窗口和释义页，因此不扩大范围。
- **在数字选词处重试旧代次**：需要跨候选窗、回复合成器和 Engine 增加旧视图恢复或重放协议，可能把已经过期的选择重新应用；宿主已有待回复闸门，直接延后重排更符合现有时序。

## Consequences

待确认回复或释义页期间不会发生 settled rerank，候选代次保持稳定，数字选词可以继续按送达时的视图校验。输入真正空闲后仍会执行原有重排；如果用户一直保持释义页或回复未确认，排序更新会推迟到这些状态结束。设备和真实编辑器验收未在本轮运行，需在 PR 验证段明确记录。
