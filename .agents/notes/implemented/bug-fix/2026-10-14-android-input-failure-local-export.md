# Agent Note: 输入与语音失败类别进入本地诊断包

Status: implemented

## Problem

#7837 的输入失败分类只写 logcat，用户导出的诊断 ZIP 没有这些原因。#7806/#7809 的两份附件各保留 5,000 条输入事件和性能记录，崩溃记录都是零；只有按键、选词、退格、结束及候选耗时，不能把输入连接失败归因到编辑器，也不能凭空崩溃记录排除系统终止。事件已截断，不能当作完整故障历史。

Android 0.4.1 的语音失败同样没有进入标准诊断包。导出时的本地模型配置只能描述当时设置，不能证明故障请求实际选择了哪个引擎，更不能用空的 crash 记录排除已捕获的代码异常。

## Decision

在既有日志与隐私开关允许时，停止输入会话之前写入四种固定本地事件：`input_failure_runtime_rejected`、`input_failure_invalid_response`、`input_failure_editor_rejected`、`input_failure_jni_link`。复用时间戳与枚举，不增加自由文本、异常说明、堆栈、输入、路径或应用身份。共享诊断包保留这些事件；Android 上传读取和最终编码都只允许原有十种云端事件。该实现已在 `MSIMEInputService.fail` 中接入，旧失败停止与直接输入回退保持不变。

服务端实际默认分支 `main` 的固定提交 `87b3300e6f5e35b25098a9f7dd60c4d364ae117e` 中，`internal/account/diagnostics.go` 仍只认可十种事件，未知 kind 会拒绝整份请求。因此本次明确支持本地 ZIP，上传不携带新事件，不假设未发布的服务端变更已上线。失败恢复行为与用户日志默认开关保持原样。

语音输入同样使用固定的本地事件记录实际引擎、本地模型检查、运行库检查、录音器打开、原生识别启动及录音阶段，并区分模型、运行库缺失、录音、系统识别权限和意外异常等失败。恢复性失败不会进入 crash，也不写异常消息、堆栈、路径、模型名、令牌、识别文本或音频；异常只映射为有限类别。旧包没有这些事件，不能据此断言没有触发过语音，也不能排除代码缺陷。

键盘发起的前台语音窗口通过 `ResultReceiver` 把固定整数事件回传键盘，仍由键盘的既有写入器落盘。接收端只接受语音枚举，并同时检查启动时与收到事件时的日志及隐私开关；键盘停止轮询偏好后仍重读落盘开关，取不到私有目录时跳过诊断。前台窗口本身不打开同一日志文件，避免跨进程读改写丢行。设置页独立发起的语音请求没有这个接收器，本片不声称覆盖该入口。它与[系统识别前台重试](2026-10-15-android-speech-permission-foreground.md)的行为修复互补，不建立原设备根因结论。

## Alternatives considered

- 同时扩展服务端事件枚举：上传可直接定位，但需要另一仓库的发布和客户端兼容顺序，未部署前会导致上传失败，本片先交付手动 ZIP 证据。
- 把恢复性故障写成 crash：现有运输已支持异常类型，但会把可恢复输入故障误报为崩溃，丢失事件时间线语义，不采用。
- 只保留 logcat：无需调整格式，但用户已提供的标准诊断附件仍无法携带原因，不能补齐这里的缺口。
- 每个进程各自打开同一个事件文件：接入直接且不依赖键盘存活，但现有写入器按整文件替换，两个进程会互相覆盖；改为键盘拥有的接收器，沿用单写入者和隐私判断。

## Verification

API 28、35 安装当前原生 APK 后，`DiagnosticsBundleDeviceSmoke` 调用真实本地识别器拒绝不存在的合成模型，核对模型检查与失败类别依次进入本地写入器、JNI 和 ZIP；同包的上传编码仍只含原十种事件，合成私人标记被拒绝。`VoiceDiagnosticsPrivacyDeviceSmoke` 在隔离服务对象上验证启动和接收两端的日志开关、隐私模式、密码框、不做个性化学习，以及非语音和越界事件的拒绝；保持旧内存快照时，落盘隐私开关仍生效。两套设备检查均通过。

两版模拟器的 `voice-lifecycle.sh` 验证前台窗口通过 Parcel/Binder 回传引擎与权限失败两个固定整数、不带负载；API 28 还覆盖同步启动拒绝，恢复前停止不会产生识别事件。Rust 诊断测试 12 项、232 项 Android JVM 冒烟、原生库编译与 ELF 校验、原生 APK 构建、相关 clippy、`cargo fmt --check`、`git diff --check` 、`pnpm run verify-notes` 和最终完整重跑的 `bash scripts/verify-local.sh --quick` 通过。编译契约允许清理作用域内新增的固定阶段记录，同时继续要求录音器和原生会话清理。

## Consequences

日志未开启或隐私模式禁止记录时仍不会记录；本次不能恢复旧附件的缺失原因，也不能证明原设备根因。云端仍没有这些失败类别，本地诊断包的事件白名单需要与上传白名单明确区分。
