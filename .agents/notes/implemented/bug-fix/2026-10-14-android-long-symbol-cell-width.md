# Agent Note: Android 长符号条目按文字宽度跨列

Status: implemented

## Problem

#7795 的网络符号格把邮箱后缀和单个符号一样放在五列等宽格里，缩小字号后仍省略域名末尾，用户无法区分同一服务的不同后缀。#8063 还报告切换输入法后首次打开常用符号为空、重新打开才恢复：同一网格在布局完成回调里重建按键，新按键没有测量尺寸。

## Decision

固定符号与常用分类保留五列基础网格，超过四个码位的条目至少跨两列，并按实际字形宽度与可用列宽增加跨度。整行放不下时换行，不拆分或缩写上屏值；布局宽度变化时在网格测量阶段重排这些固定条目，并在同一轮重新测量新增按键。不能在 `OnLayoutChangeListener` 中替换子视图：#8063 的首次常用面板会留下未测量的按键，直到重新打开才可见。颜文字仍为两列；本次补充让 Engine 符号目录也复用同一套跨列规则，避免长符号在目录分页中被固定压缩到单格。

## Historical audit

[邮箱后缀](../feature/2026-10-09-android-email-suffixes.md)部分重叠：复用后缀表、字号与上屏规则，替代固定单格省略的宽度策略。符号目录分页的缓存与分代规则不变，只改变目录网格中每项的列跨度。[常用符号记录](../feature/2026-10-08-android-symbol-panel-recents.md)部分重叠：保留存储与打开分类规则，只修复首次测量，不通过清除记录或重复打开面板绕过空白。[成对符号不分在两行](2026-10-31-symbol-panel-pairs-on-one-row.md)部分重叠：跨列规则不变，目录分页续排的起点改由 `appendRows` 记下的实际行起点给出。

## Alternatives considered

- 网络分类全部改成两列，长后缀宽度够用，实现简单；但网址片段与单个符号都占大格，增加不必要的滚动，常用分类也无法复用这条规则。
- 继续缩小字号，保留五列紧凑布局；字面已为 11sp，继续缩小降低辨认能力，仍不能保证不同域名的末尾可见。
- 目录继续固定等宽；这样实现简单，但长符号仍会被单格省略，与按字宽排满一行的目标不符。

- 布局结束后用 `post` 延迟重排：可以让新按键参加下一次测量，但引入额外一帧和回调代次管理；直接在测量阶段完成重排，不需要延迟任务。

## Consequences

网络、常用分类和 Engine 目录的长条目有足够宽度显示完整文本，单个短符号仍保持基础列宽。跨列增加行数，但保持项目顺序；目录分页仍按页缓存，只在网格中重排当前已显示内容。极端字号或窄到整行也放不下的窗口仍以单行省略兜底。宽度改变会多一次网格测量，首轮和调整宽度时才触发；目录分页没有新增延迟回调。
