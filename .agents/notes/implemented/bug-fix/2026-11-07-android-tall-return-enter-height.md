# Agent Note: Android 右侧大回车按两行分配高度

Status: implemented

## Problem

Android API 35 发布设备验收在九键 `tall_return` 字母层测到回车高 175px、重输高 136px，未达到两倍高，因而阻断 Android 0.7.0 正式发布。右列回车容器沿用了单行 `bottomRow` 高度角色；高度遍历把它固定成一行，覆盖了右列按权重跨两行的布局。

## Decision

右侧大回车的容器不再使用单行 `bottomRow` 角色。`ImeLayoutRows.addTallReturnKey` 让回车按钮继续填满自己的两行容器：右列上部（删除、重输）权重为 2、回车为 2，九键双拼与拼音九键相同（它曾是四行网格、需要回车权重补偿，见[九键双拼回到三行网格](2026-11-12-android-nine-key-shuangpin-three-rows.md)）；左列和中列的实际单行底格仍保留 `bottomRow` 角色。这样高度调整统一由整块四行外框分配，回车不会被单行高度遍历覆盖。

## Alternatives considered

- 给回车容器增加一个新的“两行底行”高度角色：能显式表达跨度，但会把只用于布局分配的跨行容器带进全树高度规则，后续还要处理两行调整量和行距的重复计算；本次没有新增角色。
- 只放宽设备断言：可以让发布继续，但会把实际的一行回车当成两行，破坏右侧大回车的可达区域；不采用。

## Consequences

- 右侧大回车在九键拼音、九键双拼、笔画及数字层都按两行高度绘制，回车下半段仍可点击。
- 右列布局不再把跨行回车误当成可调高度的单行底栏，九键双拼的删除、重输与回车同样按 1+1+2 行分配；左列和中列的底行高度逻辑不变。
- 发布前必须重新跑 Android API 28、API 35 设备验收；API 35 的 `TallReturnDeviceChecks` 是该修复的直接回归。
