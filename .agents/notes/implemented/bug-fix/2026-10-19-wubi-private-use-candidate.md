# Agent Note: 过滤五笔词库中的私用区候选

Status: implemented

## Problem

五笔原始码表中的 `kunt` 词条值为 Unicode 私用区字符 `U+E820`。构建器此前只过滤基本区以外的 CJK 字符，没有过滤私用区字符，因此该值进入发布词库。Windows 默认候选字体没有 `U+E820` 的字形，候选栏会显示缺字问号；用户仍能看到一个看似有效的第三候选，但无法辨认或可靠使用它。

## Decision

五笔 86 和五笔 98 在词库构建阶段过滤所有 Unicode 私用区字符，同时继续过滤基本区以外的 CJK 字符。过滤只作用于五笔输入源和生成的五笔补充表，不改变通用码表解析器或快速短语表，因为私用区文本在其他输入源中可能是有意使用的自定义内容。过滤行计入构建器已有的跳过或过滤统计，并用回归测试覆盖主表、Fcitx 补充表和生成补充表。

## Alternatives considered

- 在 Windows 候选栏里为缺字字符换字体或替换成占位符：这只能掩盖一个宿主的显示问题，无法为没有标准语义和字形的私用区码点提供可读文本，还会让候选选择索引与词库内容产生额外契约。
- 只删除已发现的 `U+E820` 和 `U+E821`：改动更小，但同一批来源仍可能包含其他私用区码点，未来更新词库时会再次出现同类缺字候选。
- 保留私用区候选并依赖用户安装自定义字体：私用区的含义由字体约定决定，发布词库无法保证用户安装相同字体；内置词库应提供跨平台可辨认的候选。

## Consequences

候选列表不再展示没有通用字形的五笔私用区条目，Windows 缺字问号问题得到修复，五笔 86、98 和生成补充表的行为保持一致。依赖特定私用区字体和词库约定的用户将失去这些内置候选；这类内容应通过明确的自定义词库与对应字体单独提供。构建统计会把过滤的五笔行计入过滤或跳过数量，便于发现上游码表再次引入异常值。
