# Agent Note: 词库导入报告保留行号最早的失败

Status: implemented

## Problem

词库导入先解析整份文件，再把引擎拒绝的词条并入同一份失败报告。解析阶段会先占用最多五个展示名额；即使引擎拒绝的是更早的行，`record_rejected` 也会在名额已满时直接停止。结果可能展示第 2 至第 6 行，却漏掉第 1 行，违背“展示最早失败”的含义，让用户先去检查较晚的行。

## Decision

`record_rejected` 逐条将引擎拒绝的行并入解析失败，按原文件行号排序，并始终只保留最早五条。`failed` 仍计入全部失败，报告结构与上限不变。新增回归用例覆盖“第 1 行被引擎拒绝、后五行解析失败”的次序。

## Alternatives considered

先收集所有失败、最后统一排序截断，可以简化合并过程，也容易得到正确顺序；但这会让展示用列表随输入行数增长。现有报告只需要五条，逐条排序并截断让内存保持有界，每次排序最多涉及六条。

## Consequences

桌面和移动端复用这份报告时，都能看到文件中最早的失败行。每个引擎拒绝项增加一次至多六条记录的排序；单次导入的解析行数有上限，这项开销有界。失败总数和 JSON 字段不变。
