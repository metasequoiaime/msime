# Agent Note: 外链重试成功后清除旧错误

Status: implemented

## Problem

设置页的 `useExternalUrl` 在宿主或浏览器打开链接失败时写入「无法打开外部链接，请稍后重试。」，但下一次重试成功只完成打开动作，不会清掉错误状态。设置页顶部因此继续显示已经过期的失败提示，用户无法从页面判断重试是否成功。

## Decision

每次 `openExternalUrl` 开始时先调用现有的 `setError("")` 清除旧错误；随后继续执行原有的 HTTPS 校验、宿主调用和失败提示。清除动作放在 `try` 外，使设置状态回调本身的异常不被误判为外链失败，也保持原有异常处理范围不变。

## Historical audit

- [浏览器隔离新标签页的 null 返回值](2026-10-14-browser-link-null-result.md)持有 `window.open` 的返回值契约，本篇只处理错误状态生命周期，保留其浏览器行为。
- [反馈页接住宿主操作失败](2026-10-21-feedback-host-action-errors.md)处理反馈 hook 自己的错误和重试状态；本篇修复共享外链包装器的通用旧错误残留，不改变反馈报告的独立错误文案。
- 未发现其他活跃笔记持有 `useExternalUrl` 重试清错的决定。

## Alternatives considered

- 在每个设置页按钮成功后分别清错：能修复已知入口，但容易遗漏 Markdown、账号和新增页面，也会让页面重复了解外链状态管理；因此不采用。
- 只在失败前清错：会让同一次失败显示相同错误，不能清掉旧提示；因此不采用。
- 让 `useExternalUrl` 在成功后再清错：成功路径仍需清错，但非法 URL 和宿主同步异常的状态时序更难统一；在调用开始时清错可表示一次新的尝试已经开始，并保留失败路径的最终文案。

## Consequences

失败后重试成功会立即移除旧提示；新的失败仍会写入相同错误。调用方不需要新增接口或逐页改动。代价是用户点击一次新的非法链接时，旧错误会先被清空，随后再次显示错误，这是一次新的尝试对应的正常状态变化。

## Verification

回归测试先在未修改的实现上失败，原因是第二次成功调用没有写入空错误；加入 `setError("")` 后 `use-external-url.test.ts` 的 7 项测试全部通过。测试覆盖浏览器回退、原生宿主、非法 URL、同步浏览器异常、宿主拒绝和失败后成功重试。
