# Agent Note: Android 空语音提示放在手机屏幕顶部

Status: implemented

## Problem

#11113 要求没有听到声音时把提示移到手机屏幕顶部中央，并让工具栏继续显示原图标、保持原高度。诊断行参与候选区布局，会使工具栏短暂变矮；原草稿只把提示挪到键盘表面的顶边，仍占据工具栏所在位置，目标没有实现。

## Decision

复用现有 `ImeOperationNotice` 的屏幕顶部窗口与 Android 11 之前的自定义 Toast。语音空结果使用独立实例、窗口标题和无障碍描述，并沿用四秒自动关闭及无障碍建议时长。开始新识别、结束输入、收起窗口、配置改变、重建键盘和销毁服务都会取消旧提示。

空回包、空识别结果、去掉标点后为空，以及系统识别超时或无匹配走此提示；权限、网络、服务配置等错误保留既有路径。结果交付的空结果标记只决定提示去向，不得因补充用户提示而丢失原有的 `VOICE_EMPTY` 诊断事件。

设备专项通过真实工具栏启动系统识别，合成识别服务只回传固定的超时、无匹配、空回包，不访问麦克风或网络。每种结果必须显示屏幕顶部提示，输入法窗口、字母键和工具栏范围保持不变，编辑器保持焦点，自动消失后继续采样半秒；截图只包含合成编辑器。API 28/35 使用 `--voice-empty`，保留安装、真实主输入及工作流的 Rust 设备单测、崩溃专项。

## Related notes audit

[旧键盘浮层方案](../../rejected/bug-fix/2026-11-10-android-voice-empty-hint-overlay.md)已否决，保留其少增窗口和复用键盘生命周期的理由，但它不符合目标位置。与常用语操作提示的独立窗口兼容路径部分重叠，直接复用现有实现，没有新增另一种产品浮层。

## Alternatives considered

- 键盘顶边覆盖层的实现较少，生命周期也自然绑定键盘；但它覆盖工具栏，且位置与 issue 要求不同，因此不用。
- 继续使用诊断行能沿用所有错误处理，但该行参与布局，无法保持工具栏高度。
- 所有语音错误一起挪动可以简化分支，但会扩大到权限和网络错误的阅读路径，本次保持这些错误原有行为。

## Consequences

空结果提示不占键盘布局、也不取编辑焦点。旧 Android 使用系统管理的 Toast 时长，现代系统使用输入法附属窗口；两条路径都必须在设备上验证出现、消失及窗口稳定性。API 28/35 的最终专项 `42796151250` 已验证出现、消失、焦点与窗口稳定性；审查跟进新基线后保持 PR 为 draft，直到当前提交的本地门禁与设备检查完成。


### 聆听开始时的窗口高度

`42791924790` 的 API 28 在超时空结果场景中，开始真实工具栏识别后即触发窗口边界断言。`ImeVoiceEntry.show` 把聆听面板高度强行取为当前键区与 180 dp 九键兜底值的较大者，却只用当前键区高度作为负外边距；26 键的三行字母区低于兜底值时，多出来的高度会撑大窗口。已测量的键区现在直接使用自身高度，只有尚未测量时才沿用原来的兜底高度。原键行仍为 INVISIBLE 并占位，面板移除后恢复原键行；不改默认键高，也不放宽从启动到空结果消失的窗口稳定断言。新诊断在失败时记录前后矩形并保存合成编辑器现场。此修正在 API 28/35 的最终专项 `42796151250` 均通过，未放宽原窗口稳定断言。
