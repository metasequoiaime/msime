# Agent Note: 异步停顿重排按组字与配置共同失效

Status: implemented

## Problem

macOS 的停顿计时器和按键入口共用主线程，桌面整句模型同步评分会阻塞后续空格等按键。把模型放到后台后，仅检查候选代次仍不足以保证结果有效：评分期间关闭再开启开关、替换或移除模型，都可能让旧评分发布，甚至重新装回已移除的模型。评分期间用户还可能移动高亮，开始评分时记下的高亮已不是发布时的选择。

## Decision

`Runtime::begin_settled_rerank` 把停顿模型和候选副本移入拥有型请求，快速按键模型留在会话中；后台只评分，不访问会话。会话线程经 `apply_settled_rerank` 或 `discard_settled_rerank` 收回结果。C ABI 每会话只保留一个任务，macOS 在输入停顿后启动并按帧轮询，会话销毁时放弃任务。

结果同时绑定候选代次、开关身份和模型身份。开关值真正改变时更新独立身份，重复应用同值不失效；替换模型或显式移除模型时总是更新模型身份。身份由仍持有引用的 `Arc<()>` 表示，避免配置来回切换后旧结果重新有效。发布必须同时满足三者匹配且开关开启；归还模型只要求模型身份匹配，因此关闭开关可以保留模型供重新开启，而替换或移除后绝不恢复旧模型。

配置失效不推进候选代次，避免用户仍看到的候选身份突然不可选。实际顺序改变时才沿用既有代次推进规则。高亮在发布前按候选文本和码快照，再在重排后恢复，保留评分期间用户已移动到的选词。

## Existing decisions

已检索停顿评分、后台任务、插件排列和候选代次相关笔记。[落定座位比较缓冲](../testing/2026-10-17-runtime-settled-order-scratch.md)只约定比较向量复用，与后台所有权部分重叠，继续保留其缓冲约定；双拼纠错排序资格相关笔记决定哪些候选可评分，与本项任务生命周期无关。不替代原有排序资格或插件席位规则。

## Alternatives considered

- **继续同步评分**：所有权和有效性最简单，但主线程仍会阻塞后续按键，无法解决输入停顿后的响应延迟。
- **配置变化时推进候选代次**：可以复用已有失效判断，但可见候选顺序未变，旧的候选选择身份也会失效；分开记录配置身份保留选择契约。
- **只比较最终开关值或模型是否存在**：额外状态最少，但关闭后重开以及替换后移除都无法区分旧任务，不能保证旧结果失效。

## Verification

新增合成候选与模型回归覆盖同步/异步一致、线程转移、按键失效、取消归还、静态证据、开关关闭及关闭重开、同值配置、模型替换与移除的发布/丢弃路径，以及评分期间移动高亮。远端 arm64 Mac 的完整运行时测试 347 项、C ABI `settled` 8 项、引擎排序 21 项（另 1 项忽略）及三个 crate 的严格 Clippy 通过。完整 `--quick` 通过，包含 Android/WASM 编译、Android JVM 门禁、Linux 原生 108 项、macOS 宿主和共享 Apple bridge 编译；macOS `shortcut`、`shortcut-translations` 两项真实原生测试通过。未配置 Windows 交叉工具链及 HarmonyOS 打包环境，对应阶段明确跳过，不算验证通过。

## Consequences

按键不再等待停顿模型，后台任务只持有模型与候选副本，且不会把旧配置结果发布到会话。代价是每个异步任务复制候选数据、创建工作线程并由宿主轮询；销毁会话不等待正在运行的前向计算，任务完成后自行释放。共享 ABI 提供异步能力，本 PR 只把 macOS 宿主切换到该路径，其他平台仍沿用原入口。

后台作业的就绪态将评分放入 `Box`，取出时转移同一个分配，避免增加配置与模型身份后把注册表的空闲枚举扩大到 216 字节；申请发生在后台评分完成时，按键线程不额外分配。候选导航推进代次时旧评分失效，模型归还后新一轮评分保留导航后的高亮。
