# Agent Note: 异步停顿重排按组字与配置共同失效

Status: implemented

## Problem

macOS 的停顿计时器和按键入口共用主线程，Windows Server 的停顿任务和按键共用输入队列并持有焦点锁，桌面整句模型同步评分都会阻塞随后到来的空格等按键。等待输入停顿 150 ms 只推迟开始时间，不能保证计算期间用户不会继续输入。把模型放到后台后，仅检查候选代次仍不足以保证结果有效：评分期间关闭再开启开关、替换或移除模型，都可能让旧评分发布，甚至重新装回已移除的模型。评分期间用户还可能移动高亮，开始评分时记下的高亮已不是发布时的选择。

## Decision

`Runtime::begin_settled_rerank` 把停顿模型和候选副本移入拥有型请求，快速按键模型留在会话中；后台只评分，不访问会话。会话线程经 `apply_settled_rerank` 或 `discard_settled_rerank` 收回结果。C ABI 每会话只保留一个任务，macOS 在输入停顿后启动并按帧轮询，Windows Server 经既有服务 tick 在输入队列上启动或收取，会话销毁时放弃任务。

Windows 的停顿租约和时钟只在输入队列读写，控制线程最多排入一个推进任务，不能直接读写输入回调的状态，也不能等后台评分。回复尚未送达时延后推进；结果已过期时只收回模型，下一轮再为当前组字启动。评分令牌绑定启动时的焦点 epoch，失焦后重新激活不能接纳旧评分；失焦且不再激活的会话保留至多一个结果，随会话销毁释放。模型开关、逐键 15 ms 校准预算和用户出厂设置保持原值。

结果同时绑定候选代次、开关身份和模型身份。开关值真正改变时更新独立身份，重复应用同值不失效；替换模型或显式移除模型时总是更新模型身份。身份由仍持有引用的 `Arc<()>` 表示，避免配置来回切换后旧结果重新有效。发布必须同时满足三者匹配且开关开启；归还模型只要求模型身份匹配，因此关闭开关可以保留模型供重新开启，而替换或移除后绝不恢复旧模型。

配置失效不推进候选代次，避免用户仍看到的候选身份突然不可选。实际顺序改变时才沿用既有代次推进规则。高亮在发布前按候选文本和码快照，再在重排后恢复，保留评分期间用户已移动到的选词。

## Existing decisions

已检索停顿评分、后台任务、插件排列和候选代次相关笔记。[落定座位比较缓冲](../testing/2026-10-17-runtime-settled-order-scratch.md)只约定比较向量复用，与后台所有权部分重叠，继续保留其缓冲约定；双拼纠错排序资格相关笔记决定哪些候选可评分，与本项任务生命周期无关。不替代原有排序资格或插件席位规则。

## Alternatives considered

- **继续同步评分**：所有权和有效性最简单，但主线程仍会阻塞后续按键，无法解决输入停顿后的响应延迟。
- **配置变化时推进候选代次**：可以复用已有失效判断，但可见候选顺序未变，旧的候选选择身份也会失效；分开记录配置身份保留选择契约。
- **只比较最终开关值或模型是否存在**：额外状态最少，但关闭后重开以及替换后移除都无法区分旧任务，不能保证旧结果失效。

## Verification

Windows 7 SP1 x64 虚拟机上，已安装的 0.6.0 full 宿主 DLL 配合锁文件固定的桌面模型，单次同步重排为 190～446 ms；普通逐键「增强」的 p95 约 12 ms，受限 CPU 下校准超过 15 ms 后会按既有规则停用。真实 32 位记事本通过 `SendInput` 输入合成拼音，停顿 300 ms 后按空格，长句开启桌面神经联想为 171.799 ms，关闭为 30.723 ms。此证据确认桌面模型的队列阻塞，不证明报告者的设备已开启该开关，也不把虚拟机当作物理老机器。

`windows-lifecycle-call-order` 的停顿回归控制评分何时完成：评分未完成仍可派发并确认下一个键，旧组字结果不发布，焦点 epoch 改变后只归还模型，待送达回复期间不启动或收取评分。

修复前后 Server 以同一基点 `3cc609b825f7423eee05ca202ac4dabbb8561be5`、同一 MinGW GCC 14-posix Release 参数构建，保留 Win7 已安装的 0.6.0 full TSF 与宿主 DLL，仅替换 Server。桌面模型一直开启，按旧版、修复版、修复版、旧版顺序在真实 32 位记事本输入，每轮 15 次，逐键间隔 40 ms，停顿 300 ms 后按空格。每版 30 次上屏：旧版中位数 70.479 ms、p95 382.464 ms、最高 382.637 ms；修复版中位数 24.503 ms、p95 60.791 ms、最高 71.455 ms。全部 60 次均完整上屏且随后 500 ms 保持稳定，四轮分别核实该 Server 进程的桌面模型挂载日志。生命周期回归在 Win7 上实际运行通过；原程序哈希、偏好与资源包已恢复。此验收不是重新打包安装，也未覆盖报告者的物理机器。

测速构建的两组参数都保留基线 `TrayMenuWindow.cpp` 中已初始化 `std::optional` 的 GCC 14 `maybe-uninitialized` 警告，仅临时取消这一项警告的错误级别；仓库编译选项和提交门禁不改。curl 8.14.1 按既有锁定源码在同一工具链重编，避免复用另一版 MinGW 静态库的 CRT 符号。

同一个 Win7 已安装 DLL 的异步探针覆盖 15 次组字，其中 9 次确实有在途评分：启动不超过 0.51 ms，评分尚未完成时完成组字的调用为 0.06～0.18 ms，收取时旧评分均返回 `current: false`；模型归还后下一轮仍可启动。这是 ABI 层的耗时，不是修复后真实编辑器的端到端延迟。

共享 ABI 最初接入 macOS 时，合成候选与模型回归覆盖同步/异步一致、线程转移、按键失效、取消归还、静态证据、开关关闭及关闭重开、同值配置、模型替换与移除的发布/丢弃路径，以及评分期间移动高亮。远端 arm64 Mac 的完整运行时测试 347 项、C ABI `settled` 8 项、引擎排序 21 项（另 1 项忽略）及三个 crate 的严格 Clippy 通过。完整 `--quick` 通过，包含 Android/WASM 编译、Android JVM 门禁、Linux 原生 108 项、macOS 宿主和共享 Apple bridge 编译；macOS `shortcut`、`shortcut-translations` 两项真实原生测试通过。当时未配置 Windows 交叉工具链及 HarmonyOS 打包环境，对应阶段明确跳过，不算验证通过。

## Consequences

macOS 与 Windows Server 的按键不再等待停顿模型，后台任务只持有模型与候选副本，且不会把旧配置结果发布到会话。代价是每个异步任务复制候选数据、创建工作线程并由宿主轮询；销毁会话不等待正在运行的前向计算，任务完成后自行释放。Windows Server 继续使用 100 ms 服务 tick，评分完成后的候选更新可能等到下一轮，但其间按键照常处理。Windows 旧版 UI-less 本地候选兼容分支的 `HostOnlineCandidateSync` 仍调用同步入口，此次针对已复现的 Server 队列，不改变那条独立的 TIP 同步协议。

后台作业的就绪态将评分放入 `Box`，取出时转移同一个分配，避免增加配置与模型身份后把注册表的空闲枚举扩大到 216 字节；申请发生在后台评分完成时，按键线程不额外分配。候选导航推进代次时旧评分失效，模型归还后新一轮评分保留导航后的高亮。
