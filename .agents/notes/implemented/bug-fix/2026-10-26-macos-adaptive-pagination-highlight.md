# Agent Note: macOS 自适应候选翻页保留当前行

Status: implemented

## Problem

macOS 横排候选数量自适应时，翻页会重新取得完整候选快照并按宽度重排。完整快照不一定携带当前普通候选视图的高亮标记；宿主把找不到高亮当成索引 0，重画后候选窗就回到第一页。#9753 报告了输入 `liangzhe` 后翻页反复回第一页的现象。

## Decision

自适应重排优先从刷新后的普通 `view` 读取高亮候选的全局 `id.index`，再在完整快照中定位同一候选；只有普通 `view` 不能提供可用身份时，才回退到完整快照的 `highlighted` 标记。这样保留当前页不改变完整候选快照、候选排序和共享 runtime 分页协议。

回归测试使用合成会话模拟完整快照没有高亮标记、普通视图高亮在第二页的情况，确保重画后的自适应页仍为第二页。

## Alternatives considered

- 继续只信任完整快照的 `highlighted`：实现最小，但在快照缺少标记时必然回到第一页，不能覆盖报告的失效路径。
- 直接保存 `_adaptivePage`：只能保存旧行号；候选扩展或重排后行边界可能变化，且不能确认当前高亮候选仍然存在，因此不如用候选身份恢复。

## Consequences

自适应候选重画多一次候选身份匹配，但不增加新的状态字段，也不改变固定分页、候选选择或其他平台行为。普通视图和完整快照都无法提供有效高亮时仍按原有快照标记工作，无法恢复时保持第一页这一安全回退。


## Verification

回归测试直接验证当前视图身份能映射到完整快照的第 6 项，不再把行为断言绑定到 CI 字体和窗口宽度产生的行数。
