# Agent Note: Fcitx5 字号单位按实际运行版本选择

Status: implemented

## Problem

#9087 的候选序号偏大暴露了跨版本部署缺口。宿主按开发库的编译版本决定 `Font` 用像素还是磅，但官方 Debian／归档包使用 bookworm 的 5.0.21 开发库，部署到 Arch 等新版 Fcitx5 后仍可能写像素。5.1.18 起 classicui 把序号字号按磅解析，会放大序号。报告人的具体包来源尚未确认。

## Decision

使用长期稳定的 `fcitx::Instance::version()`，在每个宿主构造时按运行版本选择单位；5.1.18 起用磅，更早版本保留像素。版本解析不依赖平台库，读取前三段非负数字，格式未知时保留旧的像素行为。删除只有字号单位使用的 CMake 编译宏，其他功能的编译版本门禁保留。

默认字体不接管、旧像素描述匹配时迁移、缩放后转换以及写入失败重试均继续保留。IBus 的像素策略不受影响。

## Related decisions

检索 `CandidateFontUnit`、字号单位、字体同步及候选字号后，[字号缩放](2026-10-14-linux-candidate-font-scale.md)与[字体写入重试](2026-10-13-linux-candidate-font-sync-retry.md)属于部分重叠，保留其原规则；没有完全重复或需要废弃的笔记。两篇既有笔记均链接本篇，不改变其原有决定。

## Alternatives considered

- **所有版本一律写磅**：不必解析版本，而且新版序号自然正确。但旧版 X11 的字体 DPI 规则不同，会改变原有像素大小。
- **只升级打包镜像**：新包编译在新库上便会选磅。但抬高了最低运行库要求，也不能正确适配反向部署或自行构建的包。
- **保留编译版本判断**：没有额外运行期逻辑。但动态链接兼容允许新旧开发库与运行库组合，它不能表达真正绘制候选的版本。

## Verification

`fcitx5-candidate-font-pixels-horizontal`／`vertical` 复用隔离 GTK 编辑器，在真实 classicui 窗口测量首个序号，与固定 96 DPI 的 Pango 绝对像素参考比较。它覆盖 20／32 像素字号、150% 整体缩放、偏好热更新、焦点保持和空格上屏，并核对 daemon 实际加载的 core 与 classicui 都来自指定运行库目录。测试取最大连续高亮区，排除同色页眉和圆角外底色；浅色字形与包含抗锯齿边缘的参考墨迹宽高最多相差 2 像素。

插件由实际 5.0.21 开发库编译，分别在实际 5.0.21 和 5.1.23 core／classicui 上通过上述两项验收。5.1.23 从上游提交 `27cca6e0239938b2d53937061d0980c087856b22` 构建，yoga 子模块固定为 `042f5013152eb81c1552dec945b88f7b95ca350f`。仅撤回运行版本选单位的生产接线，在 5.1.23 上横排与竖排都出现 20 像素设置下序号实际高 16 像素、参考高 12 像素的失败；恢复修复并强制重编插件后通过。切换对照时强制重编，避免同步源码保留旧时间戳而复用错误对象。默认验收容器只代表其实际安装版本，替换版本入口的单测不算新运行库验收。

像素验收补充后的远端完整 quick 门禁通过，包含 Linux 原生宿主 108 项 CTest、full／wubi 构建安装、日文配置、Linux 设置壳与 macOS 原生宿主编译。缺少 MinGW 的 Windows 原生交叉构建与未准备 HAP 输入的鸿蒙 ArkTS 工程编译按脚本跳过。Python 语法、笔记三条校验及 diff 检查通过。报告中的 v0.13.0 发布提交不包含运行版本修复，但安装来源仍未知；这些结果不代表报告人的 Arch／niri Wayland 现场验收。

真实 Fcitx5 宿主的版本入口经测试链接器替换，注入 5.0.21、5.1.17、5.1.18 和 5.1.23。在固定 bookworm 的 5.0.21 开发库中编译，旧实现的跨版本回归失败；修复后真实宿主与字体策略两项 CTest 通过。纯策略检查覆盖版本边界、无效输入、后缀与未来主版本，既有字体迁移／缩放／写入重试继续通过。远端完整 `bash scripts/verify-local.sh --quick` 通过；固定容器中的 Linux 原生宿主 108/108 项 CTest 通过，full／wubi 构建安装与日文配置检查通过。此轮最终门禁自行构建本工作区的 Rust 库，不依赖定向回归时只读借用的同基线库。本机 `pnpm run verify-notes` 与 `git diff --check` 通过。

## Consequences

旧开发库构建的兼容包在新运行库上也会写正确单位，不必抬高包的最低依赖。代价是宿主构造时多一次版本查询与三段整数解析；焦点与逐键热路径不重复查询。

运行库版本与 classicui 通常来自同一安装；自行混装不同版本的 core 与 classicui 不在此版本入口能辨识的范围内。不能把此回归代替报告人实际安装包和候选画面的验收。
