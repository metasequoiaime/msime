# Agent Note: iOS 九键与候选栏立即反馈

Status: implemented

## Problem

用户在所有输入框的九键连续汉字输入中都感觉按键和候选粘手。当前九键按下及松手各用 60 ms 缩放、遮罩动画，25 ms 的短点按在按下动画结束前已经开始恢复；仅测量输入动作到 `render` 耗时不能验证按压反馈是否仍在继续。

## Decision

九键网格的按压反馈直接应用当前高亮状态，取消这九个按钮的过渡时间。保留按下的缩放和遮罩样式、抬指输入、取消触摸及长按语义。候选词块也关闭按压过渡，按住时立即应用原有的 0.6 不透明度，松手立即恢复；候选网格的展开箭头直接切换方向，不再播放 0.2 秒旋转。`KeyboardKeyButton.animatesPressFeedback` 默认为真，在九键网格和候选词块创建时关闭；零时长路径同时取消变换与遮罩的图层动画，不在外层禁用动画的事务中重新启用动画。其他按键的反馈、候选皮肤自带的帧动画和候选查询与上屏语义保持不变。

本改动只消除代码设定的按压过渡，不把它解释为候选查询或触摸传递变快。真机 A/B/B/A 的按压呈现图层复原对照仍未完成，不能把本地无残留动画检查视为真机手感验收。CADisplayLink 观测也只能说明图层动画状态，不能证明像素已经显示。

## Historical audit

[主线程绘制预算](../../implemented/bug-fix/2026-10-18-ios-keystroke-render-budget.md)、[九键会话线程](../../implemented/bug-fix/2026-10-19-ios-nine-key-owned-thread.md)及[拼音侧栏](../../implemented/bug-fix/2026-10-19-ios-spelling-sidebar-layout.md)持有查询与布局的决定，本篇只处理按压动画，部分重叠且不翻转原决定。[离窗动画清理](../../implemented/simplification/2026-10-13-ios-keyboard-window-animation-cleanup.md)处理工具栏生命周期，与九键动画时长无关；[移动反馈契约](../../implemented/simplification/2026-10-15-mobile-feedback-contracts.md)处理共享设置类型，与本次运行时反馈无关。没有被吸收或过时的提案。

## Alternatives considered

- **合并积压的中间快照**：能在主线程落后时减少重复绘制。早期四轮各 117 个数字的合成输入未触发合并，当时曾撤回试验；后续触摸校准证实标称间隔不等于实际间隔，因此不能据此排除真实连打收益。当前仅合并已排队的中间帧，不增加等待窗口；交叠触摸批次存在注入数量异常，不能作为优化证据。
- **只缩短按下、保留松手动画**：保留平滑恢复，但抬指之后仍有恢复过程，不能满足反馈直接跟随触摸的目标。
- **所有按钮取消动画**：实现集中，但会改变工具栏等与九键和候选栏无关的手感，因此限定在九键网格、候选词块与候选展开箭头。
- **候选富文本统一用 Foundation 构建后再桥接**：能减少 Swift 富文本在测宽、追加行之间的转换。临时模拟器基准用四组合成词、单行释义和同一按钮，交替构建两条路径各 400 次，去掉预热后各 379 个样本；构建均值只从 0.05ms 变为 0.04ms，按钮配置加布局均值均为 0.06ms。独立按钮未接入真实扩展窗口，不能代表真机词块成本；现有证据不足以支持改写生产富文本路径，撤回临时基准和试验。

## Consequences

消除九键在主线程收到松手之后仍继续恢复缩放和遮罩的固定过渡，候选词块也不再延迟恢复不透明度，展开箭头直接显示当前状态；代价是这些控件失去平滑过渡。输入动作仍发生在原来的抬指路径，不提前提交或改写长按。引擎查询、候选渲染与系统触摸传递仍有耗时，尚无证据证明用户报告的全部粘手已消失；需要完成真机对照并让用户复验。

## Verification

2026-10-30 候选栏取消过渡：两份改动的 Swift 源文件语法检查、Mac Studio 上的 arm64 模拟器 `MSIMEKeyboardExtension` Debug 构建、`scripts/verify-local.sh --quick`、本机 `pnpm run verify-notes` 和 `git diff --check` 通过。扩展构建复用已有 Rust 模拟器静态库；本轮未在实体设备或真实编辑器中验收动画观感。

模拟器 `MSIMEKeyboardTests/NineKeyKeyboardTests` 共 116 项：115 通过、1 跳过、0 失败。新增回归对九个真实网格按钮连续按下/松手，检查变换和遮罩没有残留动画、尺寸位置保持、空格键仍保留原时序。最终源文件调整后，新增回归和既有中断清理回归另跑 2 项通过。`bash scripts/verify-local.sh --quick` 与 `npm run verify-notes` 通过。

早期真机四轮各 117 键的合成短按未见合并收益，但实际间隔未校准，不能据此排除真实连打收益；交叠触摸的实际收到数量异常，同样不能作为性能证据。按压反馈的真机对照被系统键盘注册和应用切换打断，尚未产生有效新数据。临时探针、测试专用入口、保亮改动与工程噪音从源文件移除；正常 Release 编译、严格签名校验和真机安装通过，扩展二进制确认不含 `TouchLatencyProbe`。

本轮继续对真机连续输入做了单次触摸校准：百度和水杉在同一试用框中切换成功；水杉的五次九键触摸均产生组字快照，百度扩展拒绝了这套私有 XCTest 注入，不能作为公平的速度基线。水杉的异步九键回调原先每个数字都立即触发完整 `render`，连续输入会把候选栏重绘排在主线程队列中。本次把没有 `commitText` 的中间快照合并到下一次主线程机会，只保留最新一帧；空格、回车、删除及焦点边界先排空查询和合并帧，含上屏文本的快照仍按顺序立即交付。这样只减少中间绘制，不改变 Engine 查询、抬指输入或提交顺序。 中间帧等待主线程绘制期间仍计为输入中；任一控制命令产生更新快照时清除旧中间帧，防止切换语言、选择候选后的状态被旧帧覆盖。现有首键边界回归在未清理旧帧时复现 `mode` 失败，修复后通过。合并仅覆盖排队结果，不能保证正常手指输入时每次都发生合并，也没有采用额外 8 ms 等待窗口。

用户报告系统键盘消失后自行将它重新添加；本轮自动恢复没有成功，不能将恢复归功于安装或自动化。随后对 PR #8790 对应的无探针 Release 直接验收，`testNineKeyRepeatedChineseInputOnDevice` 三轮、12 组合成拼音、117 次数字点按通过，交替空格和候选提交，断言仅有汉字、没有残留组字。此结果只覆盖该安装包的功能链路，不覆盖后来合入的候选画布，也不证明快速输入手感达标。

临时 UI 测试曾以标称每 70 ms 一次的原生触摸事件对照逐键输入。25 ms 短按在三个短序列中与基线一致，但当时没有校准实际触摸间隔，不能据此证明 70 ms 连打的手感或延迟。后续在同一真机的普通 `UIButton` 中记录 `UITouch.timestamp`：标称 150 ms 和 70 ms 间隔、25 ms 按住的两组事件，实际相邻按下仅隔约 25～34 ms，上一次抬起与下一次按下几乎相接。事件记录中的 offset 不能直接视为实际触摸时间，先前的数据仅保留为合成输入数量检查。90 ms 按住造成的交叠序列出现丢失、重复和次序异常。对没有任何输入法逻辑或手势的普通 `UIButton` 做独立对照，同样两次跨按钮触摸也出现一次动作、重复按下；开启多点触摸仍未消除跨按钮异常。尝试复用手指路径后，连不交叠的基线也失真。因此这些交叠脚本不能作为产品漏触或性能优化的证据，不据此修改生产触摸语义。

后续设备验收使用 Xcode 手册记载的 `UseDestinationArtifacts` 和目标 bundle identifier，复用设备上的产品安装；只更新独立 UI 测试运行器。直接启动目标时缺少本地产物路径会失败，先启动现有 App，再由测试激活它可完成输入验收。安装完成、系统列表存在、扩展加载和汉字上屏分别核对，任一项都不能替代其它项。所有临时测试及本机工程改动均撤回；失败诊断中的屏幕截图不进入仓库或公开报告。

用户在恢复键盘后确认正常 Release 仍然「超级卡」，按压动画改动不能记为整体卡顿已解决。后续真机采样确认维护定时器存在按键路径之外的主线程阻塞，修复和验证边界见[词库版本后台轮询](2026-10-19-ios-snapshot-version-background-poll.md)。

百度与水杉对照使用同一真机、同一编辑器，分别确认九键模式。普通 XCTest 点按会等待空闲；并发画面采样在公共 `press` 期间也会停顿约一秒，不能把请求起止时间或端点截图解释为按下、抬起到画面更新的延迟。百度组字保留在键盘内，水杉组字还会更新宿主的标记文本，因此宿主组字回调次数也不能直接横比。汉字上屏才是可比的共同终点，应同时用宿主校准按钮的实际触摸时间戳核对整段输入时长。试验中出现残留组字、未得到完整汉字以及前台检查跳过的样本，尚不满足这一验收条件，不能用于断言水杉漏按、两者延迟差异或整体手感达标。临时宿主的 `UITextField.setMarkedText` 覆写没有覆盖系统实际写入路径：标记文本已经变化时，覆写计数仍可为零；记录编辑变化需使用 `editingChanged` 等真实宿主通知，并与最终内容核对。按键高亮、候选呈现和真实手指连打仍需单独验证。

## Asynchronous verification boundary

新增 `testAsyncNineKeyBurstCosts` 显式启用产品扩展使用的异步路径。分别以 0、40、70ms 的内部按钮回调间隔运行，每档三轮 117 个数字，共 351 键、36 段；逐键记录入队耗时、调度迟到，并等待全部后台数字与待绘制帧完成后，分别报告整段和末键到查询加布局完成的耗时。模拟器 40/70ms 两档末键到完成 p95 分别为 14.99/15.71ms，逐键入队 p95 均为 0.17ms；0ms 突发末键到完成 p95 为 145.39ms，包含整段积压。这些数值没有包含系统触摸和真实文档代理，不能证明真机手感。旧的同步短词结果不包含异步交付；仅等回车第一次变为「确认」也不足以证明最后一键已画出。该用例检查提交后下一轮主线程不能恢复旧组字，不把整段突发输入时间当作单键延迟。

修改前的安装包由真机独立运行器通过 `nineKey2…9`、`returnKey` 等无障碍标识执行 5 轮 `64426` 和确认，候选出现与功能链路通过。最新修复的 Release 编译、严格签名验证、真机覆盖安装与启动完成。新包首轮点按遇到 `{-1, -1}` 的无效命中后中止，随后画面确认当前是百度九键，不能将这轮当作产品漏键证据。通过系统切换列表回到水杉、每键先检查 `exists && hittable` 后，五轮 `64426→确认` 全部通过，每轮上屏两个汉字且没有残留组字。另用公开的 `tap(withNumberOfTaps:numberOfTouches:)` 在同一个6键上执行 4、8、4、8 次连续短按，24 个数字全部进入组字，并分别提交 2、4、2、4 个汉字；请求总耗时包含 XCTest 等待，不当作单键延迟。早期该用例因预编辑控件隐藏及输入框点按移动插入点而中止；最终从文档差分核对插入文本，既保留原文，也适配非末尾光标。普通 XCTest 等待空闲，耗时受测试框架影响，不能用于评价快速连续打字。私有触摸与坐标对照用例不再执行。真机 Time Profiler 按扩展 PID 定向附加返回无法找到进程，没有新的扩展栈，不据此声称真机性能已改善。

候选释义的 `canFillGloss` 将系统完全访问检查改为按需求值：内置英语和已安装的离线语言不读取权限；关闭在线释义或未配置服务时也不读取。只有网络释义才检查当前权限，不缓存权限结果，避免权限变更后沿用旧授权；网络访问边界不变。回归用计数器检查九个候选的离线分支不触发权限查询，以及在线分支仍尊重允许和拒绝。此修改减少已确认的冗余调用，不把调用次数下降当作实测手感提升。

本轮定向模拟器回归 28 项通过、1 项因固定词库缺少离线释义而跳过；扩展到三个节奏后的异步用例另行通过。`verify-local.sh --quick`、`pnpm run verify-notes` 和 `git diff --check` 通过。公平的百度与水杉真机快速输入对照仍未完成。

临时 Release 计时构建在真实扩展的 `UITouch.timestamp`、按钮回调、异步交付、重绘和布局处仅记录阶段名称及数字，数据写入专用临时缓存。公开多次点按在同一6键上的实际按下间隔为 50～59ms；一轮包含 5 次跨键慢速输入和 24 次同键短点按，29 次按下、抬起、按钮回调和查询交付的数量吻合。第一批重绘 p95/max 为 17.776/24.462ms，第二批分阶段观测为 11.791/17.865ms；两批没有产品改动，差异不能记作优化收益。第二批 270 次词块更新累计约 192ms，占候选栏更新约 220ms 中的大部分，释义取值累计约 7.7ms。显示回调的间隔只能反映主线程调度，不能证明像素实际呈现。

同一诊断构建按候选代次交替使用字体缓存与原构造路径：127 次缓存查找合计 0.1374ms，143 次原构造合计 0.9294ms；总节省不足 1ms，不能解释词块更新的主要开销，因此撤回字体缓存试验。临时采样代码和编译开关均从最终源码移除。

用户随后在同一真机手打，反馈「已打，这次顺畅」。按自动点按结束后的 78.36 秒无触摸间隔划分样本，手动区间约 41.49 秒，包含停顿、36 次九键区域触摸和 18 次字符回调；区域计数包括删除等控制键，两者数量不应直接比较为漏键。手动区间查询交付 p95/max 为 19.970/19.970ms，重绘 p95/max 为 12.230/26.690ms；按下送达 p95/max 仍有 116.207/126.740ms，抬起送达为 37.847/39.553ms。阶段统计不等于触摸到像素延迟，也不能据此给字体缓存或某项修复单独归因。该反馈只确认这一次手打顺畅，不代表持续使用、全部输入框或与百度的速度对照已经验收。记录只含阶段与数字，不保存输入内容。

将手动区间按下记录的触摸时间戳与按钮收到时间对齐，五次超过 50ms 的差值为 82.77～126.74ms；每个区间仍有 5～8 次显示回调，回调最大间隔 18.47～21.57ms，四段没有重绘，一段只有一次 2.88ms 重绘。这五次按下紧接着抬起，没有字符处理回调，因此不能认定它们属于数字键，更不能直接判为查询或候选绘制阻塞。既有采样只按 `nineKey` 前缀筛选，未保留键角色、触摸身份或窗口事件接收时间，尚不能区分控制键、手势延后与系统投递；不据此调整生产触摸语义。

撤除探针后的普通 Release 构建、严格签名验证及真机覆盖安装通过，扩展不含 `NineKeyTimingRecorder`、`TouchLatencyProbe` 或计时缓存路径。独立运行器对该包再跑一轮 `64426→确认`，上屏两个汉字且没有残留组字；这次只复核功能，普通版的用户手打稳定性尚未单独复验。恢复普通包后，限定在 App Group 的 `Library/Caches` 单层列表确认专用临时计时目录已不存在，没有清理其他缓存。

## Autonomous device stress follow-up

用户要求由代理继续测量。本轮先在普通 Release 验证跨键输入及 4／8／4／8 次同键短点按，24 个数字全部进入组字并提交汉字。随后在真实键盘扩展安装临时计时构建，通过无障碍标识启动固定合成输入：每批六组长短句、三轮、279 个数字，按 40／70／20／40ms 的绝对时刻调度四批，共 1116 个数字、72 段。动作调用实际按钮的 `primaryActionTriggered`，保留真实会话线程、候选 UI 和宿主文档代理，但这些动作不是物理触摸。查询全部交付后显式布局，再提交整段，等待旧回调以检查组字是否回弹；调度迟到单列，不把设定间隔冒充实际投递间隔。

同一安装包运行两轮，每轮四批全部查询交付、全部整段结束，没有超时或旧组字恢复；共 2232 个数字及 144 段。每轮之后另用公开 XCTest 连点 24 次数字键、4 次删除键，两轮共 48 次数字触摸、8 次删除。数字全部进入组字，四次删除各删四个刚由合成测试生成的汉字。计时按 `grid` 和 `control` 分组，未记录键值、文档或候选内容。
