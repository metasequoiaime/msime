# Agent Note: Android 叹号键提供数字与上下角标快捷手势

Status: implemented

## Problem

Android 叹号键需要支持从同一键位快速输入 `0` 和常用的上标 `⁰`、下标 `₀`。九键主键面与 123 / `#+=` 符号页分别创建叹号键，只在符号页接入手势会漏掉九键主键面（#9052），用户按说明操作右侧叹号仍没有这些功能。实现必须覆盖两处和全角叹号，且不能改变轻点叹号的既有行为。

## Decision

`SuperscriptShortcutPolicy` 集中定义叹号键的适用面、上滑阈值复用规则、普通数字输出和长按选项顺序。`ImeLetterRows.bindSuperscriptShortcut` 只为匹配的叹号键绑定手势，符号页和 `ImeLayoutRows` 创建的九键主键面共用这一个入口：轻点继续走原有点击处理，上滑在取消长按后提交普通 `0`，长按打开现有九键长按弹窗并列出 `⁰`、`₀`。`ImeLayoutRows` 把九键长按弹窗的绘制与提交生命周期抽成通用短文本选项路径，避免新增一套弹窗状态。这个固定快捷手势独立于字母键角标和九键数字滑动方向的偏好。拼音九键字母层的 ！ 后来改成跟「九键滑动输入数字」的方向走，见 [拼音九键 ！ 滑出 0 的方向跟「九键滑动输入数字」](../feature/2026-11-01-nine-key-exclamation-zero-follows-swipe-direction.md)；123 / `#+=` 符号页仍是固定上滑。

全角和半角叹号都启用相同策略；其他标点不获得这个快捷手势。设备 smoke 以产品包为目标，在其私有目录暂存合成九键偏好并在结束后恢复；九键主键面覆盖轻点叹号、真实上滑普通数字和真实长按选上标、下标，再回归原有符号页完整输入链路。

## Alternatives considered

- **为所有标点键增加数字或角标手势**：覆盖面更大，但会把未请求的隐含动作带到问号、引号等键上，增加误触和后续兼容负担；本次只收窄到叹号键。
- **新建独立的角标对话框**：可以自由排版，但要重复弹窗定位、触摸反馈、取消和提交状态；复用九键长按弹窗能保持现有交互和生命周期一致。
- **把上滑动作放到通用按键控件**：会让所有按键都承担特殊判定，难以保证普通点击和长按的优先级；在生成键位时仅绑定目标叹号，影响面可审计。
- **在九键创建处复制一套手势监听**：入口近，便于单独调整九键；但两处的取消长按、普通点击和上滑阈值会各自演进。复用同一个绑定方法，让键面的差别只限于原有轻点提交路径。

## Consequences

用户可以轻点输入叹号、上滑输入普通 `0`，或长按选择 `⁰` / `₀`。策略类和设备验收源码随 Android 设备测试清单与 manifest 一起编译。动作依赖现有触摸事件和九键长按菜单；系统输入法或无障碍层若吞掉触摸事件，仍由宿主平台行为决定。

## Verification

- #9052 在 API 28 模拟器上先运行新增回归，旧 APK 明确失败于九键主键面没有长按入口。修复 APK 的同一套 `SuperscriptShortcutDeviceSmoke` 通过：九键轻点仍输入叹号，上滑输入普通 `0`，真实长按选择上标和下标，再回归 123 / `#+=` 符号页的三种快捷输入。
- `check-host.sh` 通过 250 项 JVM 冒烟与 196 个设备测试源文件编译，原生 APK 构建、笔记门禁与 `git diff --check` 通过。
- 最初的符号页实现在 API 35 完整设备 smoke 中通过；#9052 新增的九键路径本轮只在 API 28 专项验收。API 28 完整 smoke 仍有既有的 `limited composition typing` 状态问题，不以本次专项通过代替完整套件结果。
