# Agent Note: Android 123 页叹号键提供数字与上下角标快捷手势

Status: implemented

## Problem

Android 123 / `#+=` 符号页的叹号键只有普通字符输入，用户无法像其他数字快捷键一样从同一键位快速输入 `0`，也不能直接输入常用的上标 `⁰` 和下标 `₀`。实现还必须同时覆盖全角叹号，且不能改变轻点叹号的既有行为。

## Decision

`SuperscriptShortcutPolicy` 集中定义叹号键的适用面、上滑阈值复用规则、普通数字输出和长按选项顺序。`ImeLetterRows` 只为匹配的叹号键绑定手势：轻点继续走原有点击处理，上滑在取消长按后提交普通 `0`，长按打开现有九键长按弹窗并列出 `⁰`、`₀`。`ImeLayoutRows` 把九键长按弹窗的绘制与提交生命周期抽成通用短文本选项路径，避免新增一套弹窗状态。

全角和半角叹号都启用相同策略；其他标点不获得这个快捷手势。设备 smoke 通过无障碍描述定位叹号键，覆盖长按上标、上滑普通数字和长按下标的完整输入链路。

## Alternatives considered

- **为所有标点键增加数字或角标手势**：覆盖面更大，但会把未请求的隐含动作带到问号、引号等键上，增加误触和后续兼容负担；本次只收窄到叹号键。
- **新建独立的角标对话框**：可以自由排版，但要重复弹窗定位、触摸反馈、取消和提交状态；复用九键长按弹窗能保持现有交互和生命周期一致。
- **把上滑动作放到通用按键控件**：会让所有按键都承担特殊判定，难以保证普通点击和长按的优先级；在生成键位时仅绑定目标叹号，影响面可审计。

## Consequences

用户可以轻点输入叹号、上滑输入普通 `0`，或长按选择 `⁰` / `₀`。新增策略类和设备验收源码需要加入 Android 设备测试清单与 manifest，构建时会一并编译。动作依赖现有触摸事件和九键长按菜单；系统输入法或无障碍层若吞掉触摸事件，仍由宿主平台行为决定。JVM smoke、Android API 检查、APK 构建和 API 35 设备全套 smoke（含新增场景）均已通过；API 28 的完整 smoke 仍受既有模拟器 `limited composition typing` 状态问题影响，未宣称通过。
