# Agent Note: Windows 语音取消令牌生命周期

Status: implemented

## Problem

Windows 语音会话把每次批量识别任务的取消令牌放入 `request_cancellations_`，取消时遍历它们以中止所有仍在运行的请求。任务完成后令牌没有从向量移除，长期反复录音会保留每个 `shared_ptr` 控制块，造成无界增长。

## Decision

在加入新令牌和发起取消前，删除 `use_count() == 1` 的令牌。向量自身是唯一持有者时，识别任务及其 `future` 已经释放；仍被任务持有的令牌继续保留并接受取消。取消令牌仍由共享指针拥有，保证正在运行的识别任务跨越会话对象的控制路径安全完成。

## Alternatives considered

- 每个识别任务完成后主动回调会话对象移除令牌：可更快释放，但需要让后台任务再次访问会话锁和生命周期，增加析构竞态。
- 只保留最新一个令牌：不能覆盖流式识别和批量收尾任务短暂并存时的全部取消请求。

## Consequences

完成的任务令牌会在下一次录音或取消操作前清理，长期运行的服务器不会按录音次数积累控制块；活动任务仍可被一次取消操作全部中止。清理依赖 `future` 和任务闭包释放后令牌只剩向量持有，因此不会误删活动请求。

测试通过 `voice_request_cancellations` 验证仅删除向量独占的完成令牌，并保留仍有任务持有的活动令牌。
