# Agent Note: 悬浮工具栏读不到模式时画上一帧，而不是只剩一块白

Status: implemented

## Problem

用户报告：悬浮工具栏「经常变成一块白的，什么字都没有」。

`FloatingToolbarWindow::paint` 把背景、阴影和圆角**无条件**画在前面，而 logo、分隔线和全部按钮都在这个条件里：

```cpp
const auto value = reader_();
if (value && shown_ && same(value->lease, shown_->lease)) { ... 画内容 ... }
```

三个条件任一不成立——`reader_()` 这一帧读不到模式（输入队列正忙）、还没有画过任何一帧、或读到的租约不是画面上那一份——这一帧就只剩下那块白底圆角条。它取决于绘制那一刻能不能拿到状态，所以时有时无，「经常」而不是必然。

同一个函数末尾对读屏树早就有兜底：「这次没读到模式（输入队列正忙）或租约不是画面上那个时按钮没有重画，读屏的树也留着上一棵」。绘制这一侧漏了同样的处理。

## Decision

读不到这一帧的状态时，用上一帧已经画过的那份（`shown_`）画：

```cpp
const ModePresentation *source =
    (value && shown_ && same(value->lease, shown_->lease)) ? &*value
    : shown_ ? &*shown_ : nullptr;
if (source) { ... }
```

`shown_` 正是上一次 `update` 时画面采用的那份状态，拿它重画得到的就是用户上一刻看到的工具栏。只有连它都没有（窗口还没画过任何一帧）才退回什么都不画——那时窗口也还没显示。

工具栏上只有三个状态来自这一帧（中英、全半角、中文标点），其余按钮与模式无关，所以沿用上一帧不会显示出错误的模式：这三项要么是最新的，要么是上一刻真实显示过的。

## Alternatives considered

- **读不到状态就不画整个窗口（跳过这一帧，保留上一帧的像素）** — 合成窗口的内容会留在屏幕上，看起来也没问题。否决：这一帧已经 `Clear` 并画了背景，要「什么都不画」得提前到 `BeginDraw` 之前判断；而且阴影、皮肤图和圆角本来就该随窗口尺寸重画，把它们也跳过会在尺寸变化那一帧留下旧形状。
- **读不到状态时画问号图标** — 已有先例：`states` 里的 `std::nullopt` 就是「Server 没报这个模式」时显示问号。否决：那表示「这个模式未知」，而这里是「整份状态这一帧没读到」，把每个按钮都变成问号比沿用上一帧更误导。
- **让 `reader_()` 阻塞到读出状态为止** — 根上消除空值。否决：它在绘制路径上，阻塞会把输入队列的繁忙直接变成界面卡顿。

## Consequences

- **收益**：任何一帧读不到状态时，工具栏显示的是上一刻的按钮，而不是一块空白。
- **代价**：模式刚变而这一帧没读到时，按钮会晚一帧更新。模式变化本来就会触发 `update` 重画，所以这一帧之后立刻就对上了。
- **重访信号**：如果以后 `ModePresentation` 增加了「不能沿用上一帧」的字段（例如与具体输入位置绑定的内容），这里要重新判断哪些可以沿用。

## Verification

改动后构建装机。这一缺陷由绘制时刻能否读到状态决定，没有稳定的复现步骤，所以**没有**做出「修复前必现、修复后不现」的对照；只能说明代码路径上不再存在「只画背景不画内容」的分支。日常使用中是否还会出现空白条，要靠实际使用观察。
