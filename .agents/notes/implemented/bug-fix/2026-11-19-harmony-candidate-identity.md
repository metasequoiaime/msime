# Agent Note: 鸿蒙候选操作使用引擎身份

Status: implemented

## Problem

候选条会过滤等待中的云候选；分页后的可见位置既不是完整列表的座位，也不一定是当前页中的原始位置。鸿蒙宿主却把页内位置作为引擎候选序号提交，翻页后数字键和点击选词被拒，候选管理及以词定字也有同样的身份错位风险。

## Decision

候选条按可见位置找到该行引擎返回的 `CandidateId`，选词、以词定字和候选管理带上该行的会话、代次与完整列表序号。展开列表保存每一行自己的身份，不从过滤后的显示位置重建；会话不匹配或序号无效时不向引擎提交。展开可能释放引擎暂扣的尾部并改变代次，收起时重新取得当前视图，以免候选条保留过期身份。读取当前页的文字和来源仍使用页内位置。

## Alternatives considered

- **用页码乘每页大小计算序号**：实现简单，但过滤、动态分页及引擎重排会让显示位置和完整列表座位失去固定关系；引擎已经提供可验证的行身份。
- **仅修改普通选词**：修复当前主要症状，但管理操作和以词定字使用同一协议，也会作用于错误的座位，因此一并按同一身份处理。

## Consequences

合成适配器执行实际会话方法，覆盖过滤后的第二页选择、候选管理、以词定字、展开列表与收起刷新；策略测试覆盖错误会话与越界。测试替换了系统和引擎接口，不等于设备验收。共享引擎的完整列表代次机制另见 [完整列表代次修复](2026-10-11-full-list-generation-release-build.md)。
