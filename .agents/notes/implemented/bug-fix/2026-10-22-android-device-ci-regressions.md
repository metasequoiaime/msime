# Agent Note: Android 设备验收回归修复

Status: implemented

## Problem

`origin/develop` 的 Android 设备 CI 在 API 28 和 API 35 同时失败。API 28 的剪贴板全文预览把长文本拆成多个无障碍文本节点，设备冒烟却要求一个节点承载完整正文；API 35 的 AI 设置冒烟仍把共享服务目录数量写死为旧的 13 项，而共享目录已经增加到 15 项。

## Decision

剪贴板预览验收改为检查预览滚动区域已经出现，并检查包含首行文本的非长按节点；这样仍验证全文预览已经渲染，同时兼容旧 Android 将长文本拆分成多个 `TextView` 的无障碍树。AI 目录断言改为核对现有服务 ID 都在共享目录中，允许共享目录继续增加服务；同时保留损坏响应、重复 ID 和字段类型的严格解析检查。

## Alternatives considered

- **让产品把全文复制到一个无障碍节点**：这样可以保留原断言，但会为测试便利改变 Android 旧版本的无障碍呈现，增加无意义的 UI 约束，因此不采用。
- **只把目录数量改成 15**：可以立即跟上当前目录，但下一次增加服务仍会重复制造同一回归，因此不采用。

## Consequences

设备冒烟不再依赖旧 Android 将多行正文合并到单个节点，API 28 的真实预览行为可以通过同一套验收。AI 目录新增服务时不需要修改设备冒烟；现有服务 ID 缺失时仍会失败。严格解析和重复项检查继续阻止不完整或损坏的目录进入设置页。
