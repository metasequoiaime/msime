# Agent Note: Android 设备验收回归修复

Status: implemented

## Problem

`origin/develop` 的 Android 设备 CI 在 API 28 和 API 35 同时失败。API 28 的剪贴板全文预览把长文本拆成多个无障碍文本节点，设备冒烟却要求一个节点承载完整正文；API 35 的 AI 设置冒烟仍把共享服务目录数量写死为旧的 13 项，而共享目录已经增加到 15 项。

修正上述断言后，运行 `39951385119` 又暴露后续断言失配：API 28 在浮层遮挡编辑器时，仍通过仅匹配可见节点的查询验证输入焦点；AI 原生页用例则仍要求切换服务商后沿用上一家的模型，没有跟上各服务商独立记忆接口地址和模型的契约。

## Decision

剪贴板预览验收改为检查预览滚动区域已经出现，并检查包含首行文本的非长按节点；这样仍验证全文预览已经渲染，同时兼容旧 Android 将长文本拆分成多个 `TextView` 的无障碍树。AI 目录断言改为核对现有服务 ID 都在共享目录中，允许共享目录继续增加服务；同时保留损坏响应、重复 ID 和字段类型的严格解析检查。

浮层打开期间通过测试 APK 的 `EditorProbeProvider`，在合成编辑器主线程读取输入框焦点、窗口焦点和屏幕边界；切换输入框也调用合成编辑器的真实 `requestFocus`。API 28 在运行 `39959012910` 中无法通过包含不可见节点的 `awaitAny` 取得焦点节点，运行 `39962910197` 的 `UiAutomation.findFocus(FOCUS_INPUT)` 也返回空。探针因此独立于无障碍可见性，区分真实焦点丢失与观测接口不可用；编辑器与键盘卡片是否移动的断言全部保留。实际触摸目标及浮层渲染、滚动、关闭后的状态继续按可见节点核对。

探针只打入测试 APK，要求合成编辑器通过 `msime_test_editor_probe` 显式启用，并验证调用方为同签名的被测宿主；只允许普通、密码两个合成输入框，输出仅含焦点布尔值和坐标，不返回文字。活动销毁时清除弱引用，Binder 请求在主线程有界执行，避免读取跨线程视图状态或保留旧活动。

AI 原生页夹具清空 `endpoints`、`models`，避免之前套件留下的服务商槽位干扰初始默认值。界面用例先填写 OpenAI 自定义模型，再切到 DeepSeek 检查其预设，最后切回 OpenAI 检查自定义模型恢复；延迟模型目录返回的用例也要求保留目标服务商恢复的模型，而非回环服务的旧模型。凭据隔离及过期响应不能覆盖当前设置的检查继续保留。

卡片纵向拖动已经交给外层列表，后续横滑删除必须先把原卡片滚入可见区，等待边界稳定并重新读取坐标；复用纵向滚动前的边界会点到其他控件。运行 `39959012910` 的 API 35 在这一后续阶段失败，横滑回归因此也遵循重新定位的规则。

`DeviceSmoke.await`、`awaitAny` 每轮观察前调用 `dropStaleNodes`，让 API 34 以上清掉无障碍缓存，API 33 以下继续使用 `find` 既有的 `refresh`。稳定边界测量也通过这个入口读取实时节点；连续两次缓存边界相同不能证明视图已经停止移动，旧焦点也不能代表点按后的输入框状态。失败阶段附带合成卡片的边界，便于区分测量与手势处理问题，不记录正文。

合成编辑器通过节点 `extras` 在所有支持的 API 上公开最后一轮输入法显示请求已结束的代次状态；`DeviceSmoke.tap` 点按这些合成输入框后，等待实际焦点与就绪状态，再开始输入。它复用[实体候选栏验收已有的就绪契约](../../implemented/feature/2026-10-11-android-hardware-caret-candidates.md)，保留 API 30 以上的 `stateDescription` 供原套件读取；普通触摸输入不能与夹具剩余的显示请求交错。

全文预览扩展窗口前同时保存键区的屏幕上沿。预览期间的应用避让边界用该屏幕坐标减去当前窗口原点计算，不读取尚在重新布局的键区上沿。窗口扩展和子视图布局可能分两拍完成，过渡的窗口内坐标为零时不能让应用也临时缩成零高。Android 9 的布局会清除零尺寸视图的焦点，恢复尺寸不会自动恢复该输入框；运行 `39981119651` 进一步确认系统在最终 insets 回传前已用旧值压缩编辑器，仅保存屏幕边界不足以解决。API 28 的父窗口从首次显示起固定全高，决定与证据由[Android 9 窗口 insets 修复](2026-10-24-android-api28-ime-window-insets.md)持有；本文继续持有探针与测试就绪契约。

常用语提示套件的编辑器入口通过真实点按后核对最终焦点；已经聚焦的节点可能拒绝重复 `ACTION_FOCUS`，不能把该返回值直接判成失焦。

就绪等待使用点按目标自身的包名和描述，不能复用固定主测试包的 `field()`：首帧夹具单独安装在 `app.msime.android.firstframe`，同一合成控件需要在该包中等待焦点与显示请求结束。运行 `39981119651` 的 API 35 在主路径通过后于首帧入口暴露了该包名隔离要求。本机 API 35 用原测试 APK 重现该失败，按实际目标包等待后通过五轮冷启动九键首帧与底行检查。

夜间构建 `40164019651` 又暴露两类问题。一是 #9658 把键盘页的「剪贴板」、语音页的「模型」分页并进「工具栏」「服务」后，剪贴板导出用例仍点「剪贴板」，本地语音准备检查仍点「模型」；剪贴板一组排在键盘工具栏之后，用例点「工具栏」后把页面主体最高的可滚动列表向下滚到「导出文件夹」可见。「服务」分页的识别服务列表里也有一项叫「本地模型」，排在「本地识别准备」之上，检查「准备入口在模型列表之前」时取页面上最后一个「本地模型」文字，即模型列表的分组标题。二是 API 28 的延迟组字用例：前一个以产品为目标的套件结束时 `:ime` 被强停，这个用例到超时都没有再起输入法进程，而 `BatchEditorActivity` 只在 `onCreate` 里请求过一次显示；它现在采用与 `EditorActivity` 相同的连续显示请求和 `msime-test-ime-requests-settled` 就绪信号。本机 arm64 的 API 28 模拟器复现不出这一条，修正只能由 CI 的 x86_64 运行确认。

## Alternatives considered

- **让产品把全文复制到一个无障碍节点**：这样可以保留原断言，但会为测试便利改变 Android 旧版本的无障碍呈现，增加无意义的 UI 约束，因此不采用。
- **只把目录数量改成 15**：可以立即跟上当前目录，但下一次增加服务仍会重复制造同一回归，因此不采用。
- **为了读取编辑器先关闭浮层**：可以重新获得可见节点，但无法验证浮层打开期间的焦点和布局不变量，因此保持浮层打开，读取编辑器自身状态。
- **只用系统输入焦点查询**：不增加测试进程协议，接口也直接表达待验证的不变量；但 API 28 在真实 CI 中仍返回空节点，不能据此判断产品丢失焦点，因此使用合成编辑器自身的状态探针。
- **恢复跨服务商共用模型的旧产品行为**：可以满足旧断言，但会破坏已经落地的独立槽位契约，因此修正设备测试并补足切回恢复的验证。
- **继续按键区当前窗口内位置计算应用避让**：直接复用布局结果，不增加几何状态；但窗口扩展与子视图重排不是原子完成，过渡位置不能代表原编辑器需要保留的空间，因此保存扩展前的屏幕上沿。
- **只靠无障碍事件使缓存失效**：避免每轮重新读取窗口树，轮询较便宜；但已出现连续读到旧边界和旧焦点的现象，等待状态本身必须重新观察，而不能假定事件已经同步缓存。

## Consequences

设备冒烟不再依赖旧 Android 将多行正文合并到单个节点，API 28 的真实预览行为可以通过同一套验收。AI 目录新增服务时不需要修改设备冒烟；现有服务 ID 缺失时仍会失败。严格解析和重复项检查继续阻止不完整或损坏的目录进入设置页。

焦点探针区分浮层遮挡与真实失焦，预览的应用避让边界跨布局过渡保持稳定；AI 界面验收覆盖独立槽位的恢复及异步目录隔离。编译门禁无法证明无障碍窗口行为，仍需在 API 28、35 的模拟器运行相关套件。

等待每轮重取 API 34 以上的窗口树会增加跨进程查询，点按合成输入框也要等待夹具已经排定的显示请求结束；这些代价换取当前状态与稳定输入边界，不靠重试已经失败的输入或延长断言时限。

## Verification

- 当前源码构建的原生宿主在本机 API 28 arm64 模拟器上通过完整 `ClipboardSegmentDragDeviceSmoke` 和 `AiEndpointCheckDeviceSmoke`；探针验证了浮层打开期间的真实输入框焦点、窗口焦点及边界。
- 同一 arm64 镜像上的旧无障碍查询也能通过，CI x86_64 镜像的空节点现象仍以对应 CI 运行记录为准，不能把本机通过等同于 CI 覆盖。
- 使用未授权的 shell 身份调用探针时得到 `SecurityException`；探针不返回输入文字。
- API 35 arm64 的完整剪贴板专项在普通、双倍动画时长下通过，动画倍率在专项结束后恢复；AI 设置专项也通过。
- 运行 `39969900930` 的 API 28 探针读到输入框焦点为假、窗口焦点为真，因此不能再把该失败只归因于无障碍遮挡；探针通过有界的焦点丢失调用链辅助定位触发路径，不读取文字。
- 固定应用避让边界后的原生 APK 在本机 API 28、35 arm64 的完整剪贴板专项通过，远端原生构建与 quick 门禁 `20261024-000600` 通过。
- 本机按核心冒烟顺序运行时，修正后的常用语提示、剪贴板和 AI 设置通过；之后因该本机构建未捆绑笔画词库，在数字键盘专项中正常回退为拼音，不能将其记为完整核心冒烟通过。CI 构建显式要求锁定的语言词库。
- 运行 `39976219582` 在 API 28 的限长组字、API 35 的常用语初始化阶段失败，尚未进入全文预览；这些触摸入口此前没有等待夹具最后一轮显示请求结束，API 35 的等待也未每轮清除焦点缓存。
- 统一就绪状态与实时轮询后，本机 API 28、35 arm64 依次通过基础输入、常用语提示、完整剪贴板和 AI 设置四组专项；基础输入包括限长组字，常用语专项包含重新打开编辑器及焦点保持。
- 远端 quick `20261024-003042` 的未改动 Windows 就绪脚本发生子进程超时；同一脚本单独通过，随后完整 quick `20261024-003810` 通过，没有改变该项测试或时限。
