# Agent Note: Android 符号面板只给全角标点按墨迹居中

Status: implemented

## Problem

符号面板的「英文」分类里，减号 `-` 和下划线 `_` 都停在格子的垂直中线上，肉眼只能靠形状区分；`.` 与 `·` 也有同样的问题。用户报告下划线应当偏下。

根因是 #7718 起 `SymbolPanelView.appendRows` 对每个单码位符号都套了 `CenteredGlyphSpan`：它按字形实际墨迹把符号放到格子中间，原本是为了让全角 `，` `。` 不再贴着格子下沿、`“` `”` 不再贴着上沿。全角标点的墨迹只占字身一角，按墨迹居中是对的；其余字形的高低本身是设计的一部分，逐个把墨迹拉回中线就会抹掉这个差别。

用户追问「要显示在下方的符号是否都会存在类似问题」后，把随包的 `msime-others.db`（2026-10-28 的 `target/preview-resources` 副本，2323 个符号）逐类查了一遍：受影响的不止 ASCII。目录里还有 `‗` 低位线（箭头）、`₀`–`₉`/`₊₋₌₍₎`/`ₐₑₓₔₒ` 下标和 `⁰`–`⁹`/`⁺⁻⁼⁽⁾ⁿⁱ` 上标（数学）、`‚„` 低位引号与 `‛‟` 高位引号（标点）、`¨¯´¸ºª`（标点）、`⏝⏟⏡⎵` 下括号与 `⏜⏞⏠⎴` 上括号、`⌄⌣` 与 `⌃⌢`（标点）、`▁▄` 与 `▔▀`（形状）、`⁎` 低星号、`‥` 两点前导等。它们都按墨迹居中，上下标会变成同一个位置的小字，上下括号会变成同样的弧线，`‗` 会像一条中线。

## Decision

单个符号要不要按墨迹居中，由无 Android 依赖的 `SymbolPanelModel.centersGlyphInk` 判断，判据是**只给全角/CJK 标点居中**：CJK 符号区（U+3000–303F）、CJK 兼容形式（U+FE30–FE4F）、全角形式（U+FF00–FFEF），加上中文分类在用的弯引号（U+2018/2019/201C/201D）、破折号、省略号和间隔号。区段里高低本身有含义的码位排除：`〝〞〟`（U+301D–301F）、`﹉﹊﹋﹌﹍﹎﹏`（U+FE49–FE4F）、全角下划线 `＿`（U+FF3F）和全角长音符 `￣`（U+FFE3）。

其余字形全部交回字体基线：半角 ASCII、字母和数字（含全角数字、罗马数字、半角假名）、上下标、prime、高低引号、声调符号、上下括号、上下线、块元素等都保持字体原本的高低。多字条目和颜文字不居中。

这样 `_` 落回基线以下、`-` 留在中段；目录里的 `₀` 与 `⁰`、`‚` 与 `‛`、`⏝` 与 `⏞`、`▁` 与 `▔` 也各自保持上下关系。中文分类里 `，` `。` `、` `：` `；` `！` `？` `“”‘’` 仍然是按墨迹居中，`°` `℃` `★` `→` 等回到字体基线。

## Alternatives considered

- **只给 `_` 开例外，其余单码位符号继续按墨迹居中**：改动最小，不会移动任何其他符号。不采用：目录里的上下标、高低引号、上下括号、低位线和块元素是同一类问题，例外名单会随着报告继续变长；按「全角/CJK 标点才居中」划一条字形边界能一次覆盖这一类。
- **符号面板整体不再按墨迹居中，与 iOS 一样交给字体基线**：最接近系统键盘和 iOS 的排版，代码也最少。不采用：全角 `，` `。` 会重新贴到格子左下角，正是 #7718 修掉的问题；中文分类还是没有使用记录时默认打开的分类。
- **按分类决定（「中文」居中、「英文」不居中）**：语义直白。不采用：Engine 目录的「标点」「数学」等分类同时含全角和半角符号，「常用」更是混在一起，按分类判断还得再猜每个符号属于哪种字形，逐字判断更稳定。
- **用字体墨迹的水平偏移自动判断（偏左的角标才居中）**：不写码位表，将来目录新增字符也能自动适配。不采用：判断依赖具体字体的字身与墨迹，同一符号在不同厂商字体上会得到不同结果，纯 JVM 冒烟也测不到；符号面板只用系统字体，但这条规则会随系统字体版本漂移，码位判据更可控。

## Consequences

- 收益：`-` 与 `_`、`.` 与 `·` 在面板里重新可分；目录里的上下标、高低引号、上下括号、低位线也各自保持上下关系；「英文」分类的 `,` `.` `;` `:` `'` `"` `~` `` ` `` 等回到字体设计的上下位置，字母、数字在同一格里也不再因墨迹高度不同而基线漂移。
- 代价：「英文」分类里原本被拉到中线的半角标点会回到偏上或偏下的位置；中文分类的 `°` `℃` `★` `→` 等非标点符号也会回到字体基线，垂直位置与 #7718 之后略有不同。这是有意的排版取舍，不是回退。
- 全角中文标点、弯引号、省略号、破折号和间隔号的绘制与原来完全一致。

## Verification

- `SymbolPanelModelSmoke` 新增三组断言：半角 ASCII 与目录里一整组靠高低表达含义的符号（上下标、prime、高低引号、声调、上下括号、上下线、块元素）保持基线；全角/CJK 标点继续按墨迹居中；多字条目、颜文字和空值不居中。用仓库内的纯 Java 依赖单独编译 `SymbolPanelModel` 及其测试后运行通过（`SymbolPanelModelSmoke: PASS`）。
- 符号目录的受影响字符来自 `target/preview-resources/.../msime-others.db` 的 `symbol_catalog` 表，按 Unicode 名称和上下位置逐条筛出；该库是随包资源的本地副本，不在仓库里。
- `SymbolPanelLayoutDeviceSmoke` 在「中文」断言 `，` 仍带墨迹居中、`°` 不带，在「英文」断言 `-`、`_`、`,` 不带居中跨度，防止这条分界被改回去。
- 本机是 Windows，没有 Android SDK 和模拟器：`check-host.sh`、设备套件编译和真机观感都没有跑。合并前需要按仓库 Android 验收流程补跑 `check-host.sh` 和模拟器上的符号面板设备套件，并实际打开「英文」「数学」「标点」分类确认关键符号的上下位置。
