# Agent Note: macOS 闲置输入会话限制与资源耗尽恢复

Status: implemented

## Problem

IMK 为多个输入客户端保留控制器，失焦后控制器仍持有 Rust 会话及词库文件、目录和锁句柄，没有数量上限。macOS 的 launchd 默认打开文件软上限为 256；隔离运行已安装的原生宿主，在此上限下连续创建、输入合成五笔码并失焦，保留 36 个会话后下一次创建返回 `dictionary access unavailable`；释放旧会话后，同一进程创建成功。资源耗尽还可能让运行时配置文件无法打开，两个错误都表现为中文模式直接输出英文字母。现场旧进程已重启，无法追溯它当时的句柄数，因此复现证明的是这条缺陷路径，不宣称已经取得现场的完整根因证据。

## Decision

原生宿主最多保留四个已经失焦的词库会话，活动客户端不参与回收。回收复用词库维护时的清理路径，保存专用英文状态，在下次使用时重建；全半角和标点的宿主状态继续由原有同步恢复。创建失败时，如果确实释放了闲置会话，重新读取配置并重试一次；没有可释放资源或仍然失败时保留既有按键直通。诊断只记录固定错误类别，不写原始错误、路径、输入或凭据。

会话创建及有界重试失败后，原生宿主在主队列异步显示非模态、不能成为键盘焦点的恢复面板。每个进程只保留一个面板，自动提醒间隔至少 60 秒；排队期间恢复、失焦、进入安全输入或切到英文模式时不显示，已经恢复或失焦的提示立即收起。用户选择「稍后」不改变输入模式，故障期间仍可从输入法菜单手动进入恢复。

「重试」只回收闲置会话并重建当前失败的会话。「重启输入法」沿用原有独立注册助手路径；面板先说明会结束其他窗口中未完成的输入，菜单入口只打开该面板，明确点击面板按钮后才执行。助手未能启动时保留当前进程、恢复按钮并显示失败说明，启动成功后才退出旧进程。按钮在等待期间禁用，等待状态由进程持有，跨控制器也不会重复启动。所有文案是固定的用户说明，不展示底层错误、输入或私人路径。

## Alternatives considered

- 每次失焦立即销毁会话可完全避免积累，但会让两个常用应用之间的切换也反复重建；保留少量闲置会话兼顾复用与资源上限。
- 提高进程文件上限能延后故障，却让闲置会话继续无限累积，不能替代生命周期约束。
- 自动重启输入法可以恢复输入，但会打断其他客户端并掩盖未释放的资源，不采用。
- 复用中英切换 HUD 可以沿用现有位置和样式，但它会在 0.6 秒后自动消失、鼠标穿透且没有操作入口，不能承担持续故障的恢复提示。
- 模态错误对话框容易被注意到，但模态循环和键盘焦点会干扰 IMK 服务其他客户端，因此使用不激活应用的面板。

## Verification

隔离的已安装原生宿主在 256 个文件句柄软上限下保留 36 个五笔会话后创建失败，释放后同进程恢复。修复后的 `shortcut-test --session-recovery` 使用合成 SQLite 词库和真实 Rust 会话，在同样的软上限下连续创建、输入、失焦并保留 64 个原生控制器，闲置会话始终不超过四个，活动会话仍保留 `wq` 组字，五笔候选持续可用。专项还覆盖回收后专用英文恢复、创建失败后成功、配置首次读取失败后恢复、持续失败至多两次尝试，以及未知错误的隐私过滤。专项通过，本机完整 `shortcut-test` 和 `dictionary-quiesce-controller-test` 通过；后者验证活动组字在维护时上屏、维护租约内拒绝重建、租约结束后恢复会话与专用英文。

资源上限修复的 `bash scripts/verify-local.sh --quick` 完整通过，覆盖契约检查、Rust workspace、全部 macOS 原生目标与 Apple bridge 编译；非 macOS 平台阶段按改动范围跳过。本机 `pnpm run verify-notes` 与 `git diff --check` 通过。首轮门禁中的 Windows 设置页就绪测试曾在 40 秒后超时，独立复跑通过；首轮原生编译因构建盘空间不足而主动停止，迁移已有缓存后完整重跑门禁通过。

恢复提示的专项覆盖异步显示、不能成为键盘或主窗口、显示前后键盘窗口不变、进程级提醒间隔、菜单恢复入口及恢复后的移除；还覆盖重试持续失败与真实 Rust 会话恢复、菜单重复选择不启动助手、跨控制器禁止重复重启、助手失败不退出与成功后退出。排队后恢复、失焦、英文模式和安全输入均不显示过时提示；安全输入开启后收起已有提示，过时控制器不能操作当前面板。重启测试用可控助手回调与退出计数验证，不重启本机已安装的输入法。

恢复提示补齐后，本机再次运行 `shortcut-test --session-recovery`、完整 `shortcut-test`、`pnpm run verify-notes` 和 `git diff --check` 均通过；远端 macOS 编译机的最终 `bash scripts/verify-local.sh --quick` 通过，覆盖契约检查、Rust workspace、全部 macOS 原生目标与 Apple bridge。桌面检查工具无法识别隔离测试进程，故上述原生组件验证不计作完整安装和真实编辑器验收。

## Consequences

闲置会话的文件和目录句柄数量受到约束，创建失败时可以在同一进程恢复。超过四个常用客户端后，再次切回被回收的客户端需要重新打开词库；若实测切换延迟不可接受，再评估缓存上限与会话间资源共享，不能直接恢复无上限保留。四个仅限制闲置会话，活动客户端数不受限制，其他模块耗尽资源时仍可能创建失败。

回收复用维护路径取消异步服务并显式关闭会话，仅回收已没有活动客户端的控制器。维护租约存在时不开新会话，不通过重试绕过维护。固定日志类别可以用于后续现场取证；恢复面板只在主线程管理窗口和弱引用委托，过时按钮不会操作新的输入客户端。当前验证没有更新本机安装，也没有用修复后的完整安装包在真实编辑器验收。
