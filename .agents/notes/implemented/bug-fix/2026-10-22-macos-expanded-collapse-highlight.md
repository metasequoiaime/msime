# Agent Note: macOS 收起展开候选时保留当前高亮

Status: implemented

## Problem

metasequoiaime/msime#9206：普通候选高亮第三项，展开后左移到第一项，再按 ↑ 收起，会恢复第三项。网格只移动 `_expandedCursor`，引擎高亮没有同步。

## Decision

收起时以网格当前候选的全局 ID 为目标，先验证会话与代次，再复用引擎的上一页、下一页、上一个和下一个候选命令同步高亮，只应用最后一个回复。不提交候选，也不重写候选身份；跨页导航先按页走，再在目标页定位，避免逐项遍历整个列表。目标已经高亮时不发命令；过期网格只收起；命令失败记诊断事件，并显示最后成功的状态。

本决定部分取代[展开候选网格](../feature/2026-10-12-macos-expanded-candidate-grid.md)中「收起后恢复引擎原高亮」的规则。展开期间的本地导航、重载和选择身份校验保持不变；↑、Esc、鼠标按钮和接着输入时的收起共用同一入口。

## Alternatives considered

- 新增按全局 ID 设置高亮的 C ABI 可以一次定位任意候选，但需要贯穿运行时、Host API 与 Apple 桥；现有导航命令已具备分页和高亮语义，本修复不扩大接口。
- 只改普通候选的绘制高亮最小，但接着按空格仍会提交引擎保留的旧候选，显示和实际选择不一致，因此同步引擎状态。

## Consequences

收起会执行必要的导航命令并更新候选代次；跨页距离决定调用次数，但展开期间不增加引擎调用。既有 `shortcut` 原生控制器测试覆盖第三项到第一项的原复现、重新展开、Esc 跨页收起、鼠标收起与短末页。新增断言在旧实现上失败，修复后与 `candidate-expanded-grid` 一起通过；这是原生替身测试，不是已安装输入法中的手工验收。
