# Agent Note: macOS 语音重采样的满幅峰值不取消录音

Status: implemented

## Problem

用户按住右 Option 后出现录音再立即退出。运行中宿主记录显示捕获已经开始，随后在实体松手前报告 capture 类别失败；现有元数据不能区分具体 PCM 错误，不据此断言实际麦克风失败的完整根因。

独立的合成复现确认一个可触发同类错误的缺陷：输入全部为有限且处于 `[-1, 1]` 的 44.1 或 48 kHz 浮点信号，经过 `AVAudioConverter` 转为 16 kHz 后，滤波瞬态仍可能超过满幅。`MSIMEVoicePCMBuffer` 把任何大于 1 的输出当作格式错误，清除已采集数据；流式调用随后报告捕获失败，结束录音。低电平常量测试碰不到此路径。相同缓冲层也服务局部录音、豆包流式和 HTTP 整段录音。

## Decision

在共享的原生 PCM 缓冲层把重采样后有限的输出限制在 `[-1, 1]`，继续保留和交付本轮录音。不扩大输入格式范围、不重启录音、不重试识别，也不改变各提供商预算。非有限值、转换器错误、录音中更换格式以及结束／取消后的旧数据仍走原有失败或隔离规则。

合成回归覆盖 16、44.1、48、96 kHz 的正负满幅邻近信号与多块连续转换，并通过 `VoiceInputService` 的真实流式 PCM 入口检查：不产生失败回调、不提前停止、输出保持有限且有界、停止时交付的总帧数正确。测试替换实际采集入口，不开启麦克风，不读取真实音频或用户偏好。

## Alternatives considered

- **保留严格的满幅检查并取消。** 能尽早拦截异常数据，但满幅之外的有限转换输出并不一定是损坏输入；合成的合法输入也可触发，因此不能以它取消整段录音。非有限值继续拒绝。
- **让提供商各自处理越界浮点样本。** 本地流已经在转 PCM16 时限制满幅，但共享缓冲在它之前就失败，其他批量提供商也需要有界输出。统一在转换后的公共边界处理，避免各入口行为不同。

## Consequences

正常的高电平输入和重采样瞬态不再导致整段录音被丢弃；超过满幅的峰值会被削限，其他采样保持原值。批量采样上限、流式释放、幂等完成与取消隔离保持既有规则。

与[全局语音](../feature/2026-11-02-macos-global-voice.md)及其首帧硬件恢复部分重叠：本篇只记录 PCM 转换策略，不取代硬件重配置恢复或全局手势的决定。排查未录制或读取真实语音；合成回归通过不能证明用户当前麦克风的每一次退出都由该峰值路径引起，安装后仍需实体按住与波形响应复验。
