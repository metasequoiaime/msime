# Agent Note: 移动端统计页统一系统认证规则

Status: implemented

## Problem

Android 已按维护者要求实现「有系统认证就认证，没配置就直接打开」，iOS 和 HarmonyOS 仍在进入统计页时直接加载，三端行为不一致。维护者随后要求在「我的」页自行开关，原先三端都没有此入口。

## Decision

三端「我的 → 通用」增加「统计页身份验证」。关闭时跳过系统凭据检查与认证，直接进入；开启时按下述凭据规则处理。开关默认开启，保留既有 Android 行为。Android 用私有 SharedPreferences，iOS 用 App 私有 UserDefaults，HarmonyOS 用原生 preferences 保存；选择只属于这台设备，不进入账号同步、键盘共享偏好或统计文档。保存失败保留原选择。

iOS 使用 `LocalAuthentication.deviceOwnerAuthentication`，支持生物认证和系统密码，仅明确的 `passcodeNotSet` 免认证。HarmonyOS 使用系统 `userAuth` 的 PIN 配置检查和系统认证窗口，仅明确的 `NOT_ENROLLED` 免认证；查询失败、锁定、取消和认证失败均保留重试入口。

认证门放在统计内容挂载之前，未通过时不加载统计、不挂载上传控件。离开页面或应用退到后台撤销授权，丢弃旧认证回调；系统认证窗口短暂抢走焦点不导致重复弹窗。授权只存在于本次页面会话，不持久化。iOS 认证门位于统计 NavigationStack 外，推入按日明细不触发离页锁定，系统失焦只隐藏内容而不销毁导航栈。共享 React 页面通过宿主可选能力接入，仅 HarmonyOS 提供，桌面设置不受影响。

检索审计：[Android 无凭据放行](2026-10-25-android-statistics-auth-availability.md)与本篇部分重叠，本篇扩展相同规则到其他移动宿主；[原 Android 认证](../feature/2026-10-25-android-statistics-auth.md)仍负责 Android 接线；剪贴板认证与本次统计页一致性无关。

## Alternatives considered

- 完全移除三端认证：访问路径最短，但不符合维护者最后明确的「有认证就用认证」，因此保留系统认证。
- 所有系统认证错误均视为无凭据：覆盖设备差异容易，但会将已配置凭据的设备故障、取消或锁定当成免认证，因此只认系统明确的未配置状态。

## Consequences

三端开启开关且配置凭据时先认证，无凭据时直接加载；取消保留重试入口，回到前台不会循环弹窗。后台返回和重新进入重新检查配置，过期回调不能解锁新会话；鸿蒙同时监听原生前台通知，避免依赖 ArkWeb 一定发出可见性事件。共享桌面统计保持现状，统计记录、上传开关和默认值不改变。

前端认证回归覆盖读取前拦截、取消重试、后台撤销、原生恢复、过期回调、开发模式重复挂载和更换宿主；Swift 回归通过注入系统上下文检查无密码、故障、锁定、取消、失败重试、后台和过期回调。系统认证窗口引起的短暂失焦与真正后台分开处理。鸿蒙每次使用系统安全随机源生成 16 字节挑战；真机曾在空挑战处返回 `InitChallenge fail:401`，因此不使用空数组。

开关回归覆盖宿主持久化、重新挂载读取、保存与读取失败；Swift 覆盖认证途中关闭、旧回调、重新开启和关闭时不创建系统上下文。iOS UI 回归由「我的」关闭开关后重启，验证四分段与明细导航。新模拟器的系统认证可用性查询返回可用但认证未完成，因此不能把这条 UI 路径作为无凭据放行的验证；无凭据规则由真实状态机注入系统错误覆盖。

验证包括统计相关前端测试、HarmonyOS 逻辑测试、原生编译、quick 和笔记门禁；Android 0.6.0 在 Pixel 真机验证开关切换、重启持久化和无锁屏凭据直接进入；API 28 专用模拟器覆盖同样流程。HarmonyOS 真机验证关闭后直接读取、重启后保持关闭、重新开启要求系统认证，以及取消后保留重试入口。未输入或修改用户的系统密码，凭据成功支路不宣称已完成真机验收。鸿蒙沿用未改动的 Rust/NAPI 编译产物检查 ArkTS 与 HAP，iOS 原生工程编译通过；iOS 27.0 与 26.5 模拟器均在系统启动或迁移阶段停滞，本轮未完成 UI 回归，不记为通过。不能用 TypeScript 测试代替原生编译或模拟器验收。
