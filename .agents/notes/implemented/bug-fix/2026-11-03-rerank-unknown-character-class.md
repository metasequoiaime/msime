# Agent Note: 字表外的字按未知字类的大小扣分

Status: implemented

## Problem

2026-11-03 在 Mac 上做 220 段的完整验收，一条消息开头的「饭别做太多」上屏成「𫔍别做太多」，「别什么都瞒着我」上屏成「癟什么都瞒着我」。

这两个字都不在 ONNX 模型 1.2 万字的字表里，`Vocabulary::encode` 把它们编成同一个未知字。模型给未知字的，是「随便哪个生僻字」这一整类的总概率。拿这个总概率和一个具体的常用字（「饭」「别」）比，并不公平；生僻字在开头这种上文很少的位置尤其占便宜。

## Decision

`OnnxScorer::log_probabilities` 算出逐字平均之后，每个字表外的字（`Vocabulary::unknown`）扣 ln(`UNKNOWN_CLASS_SIZE`)，再按候选字数摊开。`UNKNOWN_CLASS_SIZE` 取 2 万：

- CJK 统一汉字和扩展 A 大约 2.7 万字，扩展 B 以后更多；
- 减去字表里的 1.2 万。

这样就把一类的总概率摊回到一个字上。字表里的字一点不变，自测那一页全是字表里的字，结论也不变。

## Alternatives considered

- **含未知字的候选不交给模型比较，或者直接给最低分。** 实现更简单。但用户真要打的生僻字（人名、地名）就再也不会被模型提上来，只剩词频说话。按类大小扣分，仍然留给它们靠上下文和词频胜出的余地。
- **按每个字在语料里的频率算各自的概率。** 更准，但要在运行时带一份字频表。按类平均已经修好了验收里的这两例。

## Consequences

- **收益**：生僻字不再借未知字的总概率，压过常用字。
- **代价**：字表外的字（某些人名用字）比以前更难被模型提上来，要靠词典首选和词频。
- **效果**：`convert_eval`，6x256 配 32 条，六个集合合计改对 2、改错 0（「别什么都瞒着我」「歪歪坐在软垫里」）；只用引擎的那一组不受影响。

## Verification

- `crates/onnx-rerank/tests/golden.rs` 的 `an_unknown_character_pays_for_standing_in_for_a_whole_class`：两个不同的未知字分数相同。
- 与参考运行时逐位对照的那几条测试不变，说明字表里的字没有受影响。
