# Agent Note: 鸿蒙云面板覆盖设置页显示

Status: implemented

## Problem

真机从「我的」点击「云剪贴板」后画面仍停在原处。`HarmonySettings` 将 `CloudClipboardPanel` 追加在占满视口的 `SettingsPage` 后面，`native-panel` 只有宽度和最小高度，没有定位。面板实际在设置页下方，用户看不到启用开关。云词库及其子页使用同一处挂载方式。

## Decision

鸿蒙宿主把已打开的云面板放进固定于当前 WebView 视口的可滚动图层。设置页继续挂载以保留页面、滚动和未保存草稿，图层显示期间对设置子树设 `inert`，阻止焦点和触摸落到背后的页面。图层以 `dialog` 和 `aria-modal` 声明当前云剪贴板或云词库操作，关闭仍由面板现有按钮完成。

不修改共享桌面面板的定位：桌面由独立原生窗口承载，同一个组件在鸿蒙是设置窗口上的覆盖页。端到端加密、设备批准、开关请求和密钥存储保持既有业务流程。

检索活跃笔记中的鸿蒙、云剪贴板和面板：[云剪贴板端到端加密](../feature/2026-10-11-cloud-clipboard-e2e.md) 持有批准与重置协议，本次仅修宿主展示；[鸿蒙账号 Rust 目录模式](../architecture/2026-10-17-harmony-account-rust-directory-mode.md) 持有桥接和会话，不改请求契约；[剪贴板历史状态](../simplification/2026-10-17-clipboard-history-state.md) 属于本机历史，与本次无关。

## Alternatives considered

将定位加到共享的 `native-panel` 可统一生效，但会改变桌面独立窗口的布局约束，因此由鸿蒙宿主提供覆盖图层。

卸载设置页并用云面板替换，能保证只有一页，但关闭后会丢失设置页的本地状态和未保存草稿，因此保留原子树。

## Consequences

云面板在当前视口内显示，内容超出时可滚动，关闭后回到原页面。鸿蒙云词库共用同一展示修复。模态图层增加宿主内一层布局，不绕过等待其他设备允许的限制，也不触发清空或重置。
