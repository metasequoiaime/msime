# Agent Note: 移动端数字九宫格的返回键和符号入口留在字母层那一格

Status: implemented

## Problem

#9113：Android 拼音九键字母层底行是 `符 | 123`，切到数字层后变成 `九键 | 符`。用户按原数字入口的位置想返回拼音，实际打开了符号面板。

#10061：Android 的 #9113 修复让所有借用同一数字九宫格的键面都用拼音九键的 `符 | 返回` 次序。全拼 26 键、各家双拼 26 键的字母层底行却是 `123 | 符`，进数字层后 `返回` 落在原来 `符` 那一格，`符` 落在原来 `123` 那一格，凭肌肉记忆按返回会打开符号面板，与 #9113 是同一类误触。14 键、18 键和手写的字母层同样以 `123` 打头，进数字层后返回键也被挤到第二格。

iOS 和 HarmonyOS 的借用数字页本来就把返回键放在第一格，没有 #10061 的问题；但两端拼音九键的数字层底行是 `九键 | 0 …` / `九键 | 空格 | 0 …`，没有底行 `符`，字母层 `符` 那一格在数字层变成切换键，#9113 的错位在这两端一直存在。

## Decision

三端共用一条规则：往返字母层和数字层时，数字层的返回键留在字母层 `123` 那一格，两层都有的 `符` 也留在同一格，宽度不变。次序由进入数字九宫格之前的键面决定，不由数字九宫格本身决定。

### Android

`KeyboardActionRow.numberPadEntries(sourceLayout, globe, swapLanguageNumber, style)` 给出数字九宫格的底行，`ImeBottomRow.updateActionRow` 在画数字九宫格时传入当前键面（`drawnTouchLayout`）。底行签名里已有键面，从不同入口进同一个数字页时会重排。

- 字母层底行以 `123` 打头的键面（`numberPadLayerFirst`：26 键一族、韩文、14 键、18 键、手写、大千注音）：`返回 |（地球）| 符 | 0 | 中/英 | 回车`，与 26 键字母层 `123 |（地球）| 符` 同次序。14 键、18 键和手写的字母层底行没有 `符`，数字层的 `符` 排在返回键和地球键之后。
- 字母层底行以 `符` 打头的键面（拼音九键、九键双拼、笔画）：`符 | 九键/笔 |（地球）| 0 | 中/英 | 回车`，即 #9113 的排列。注音九键、日文假名网格的 `123` 在自己的键块里，字母层没有底行，沿用这一排列。
- 各键宽度与九键数字层相同，只换次序；0 接替空格的份额，原空格键在右列。
- 「交换语言键与数字键」在排好的次序上对调返回键和中/英，`符` 不参与交换。右侧大回车外框自带底行，这时 `numberPadEntries` 返回空表。
- `numberPadLayerFirst` 直接读来源键面的字母层底行第一个键，新键面加入时只要它的字母层底行定下来，数字层次序就跟着定下来，不另维护一张键面列表。

### iOS

拼音九键、九键双拼和笔画的数字层（不是右侧大回车时）底行按 `TouchBottomRowLayout.nineKeyDigits` 排：`符 1.05 | 九键 1.25 |（🌐 1）| 0 | 空格 1.05 | 中/英 1.05 | 回车 1.6`。0 和空格合起来占字母层空格（九键双拼再加它字母层的 0）那一份，整行总份额与字母层相同；隐藏中/英时它的份额并进 0。底行带 `符` 时符号栏里的 `numberPadSymbolPanelKey` 隐藏，运算符占满符号栏；这条判断按「数字层底行里有没有 `符`」做，右侧大回车的数字层同样由它隐藏栏里的 `符`。

数字层比字母层多一个键、多一道键距，`符` 和切换键的边界与字母层相差不到一个键距，键的中心仍落在字母层同一个键上。

从 26 键、14 键、18 键、手写借来的数字九宫格不变：`返回 | 0 | 空格 | 中/英 | 回车` 对齐上方各列，返回键在它们 `123` 那一格，`符` 在符号栏第三排。

### HarmonyOS

`NineKeyLayout.actionRow(digitLayer, english, style, nineKeyDigits)` 的 `nineKeyDigits` 为真时（`KeyboardView.nineKeyActions`：数字层，且键面是拼音九键 / 九键双拼或笔画），数字层底行是 `符 1.05 | 九键 1.25 | 空格 3.15 | 0 1.05 | 中/英 1.05 | 回车 1.6`，0 的一份从空格里让出，整行份额与字母层相同（9.15）。英文九键的数字层同样带 `符`，它的字母层也以 `符 | 123` 打头。

借来的数字九宫格不变：`返回 1.25 | 空格 4.2 | 0 1.05 | 中/英 | 回车`，底行没有 `符`。`tallReturnRow` 仍按借用页那一行（5 个键、9.15 份）换算右侧大回车中列的宽度。

### 三端仍不同的地方

规则只管返回键和 `符` 的位置。0 与空格的排法三端各自沿用：Android 的 0 接替空格、空格在右列；iOS 是 `0 | 空格`；HarmonyOS 是 `空格 | 0`。借用页上 iOS 的 `符` 在符号栏，HarmonyOS 没有 `符`，Android 在底行。这几处来自各端已有的布局决定，不在本篇范围。

## Alternatives considered

- **数字层返回键一律放最左边**：返回放在第一格符合一般「返回」键的习惯，三端借用页也是这样。不采用：拼音九键字母层第一格是 `符`，往返时同一个位置一会儿是 `符` 一会儿是返回，正是 #9113 的误触。
- **所有入口共用拼音九键的 `符 | 返回`（原 #9113 的做法）**：数字页只有一种底行，实现最简单。不采用：26 键一族、14/18 键和手写的 `123` 在第一格，进数字层后返回键挪到第二格，就是 #10061 报告的误触。
- **把拼音九键字母层改成 `123 | 符`，三端数字层都以返回键打头**：数字层次序不必看入口。不采用：会改动三端所有拼音九键用户已经熟悉的字母层底行和右侧大回车外框，影响面远大于数字层。
- **让用户自己排 `符 / 123 / 中` 三个键的次序（#10061 报告人的设想）**：每个人都能排成自己顺手的样子。本篇不做：要在三端设置页加排序面板、在共享偏好加字段、迁移 Android 本机的「交换语言键与数字键」，还要和各键面的底行样式组合；先用固定规则消除误触，简单的开关另行处理（#10056）。
- **iOS 九键数字层继续对齐上方五列，`符` 留在符号栏**（[iOS 数字侧栏](2026-10-18-ios-number-sidebar-touch-targets.md)的做法）：0、空格、中/英和数字列上下对齐。不采用：数字层底行第一格是切换键，与字母层 `符 | 123` 错位，三端也不一致；借来的数字九宫格仍保留这种对齐。

## Consequences

收益：三端往返字母层和数字层时，返回键和 `符` 都不换位置，26 键一族不再按到符号面板；iOS 和 HarmonyOS 的拼音九键数字层多了一个直接打开符号面板的底行 `符`。

代价：习惯 Android 借用页 `符 | 返回` 的用户，以及习惯 iOS、HarmonyOS 九键数字层 `九键 | …` 的用户，会遇到一次位置变化。iOS 九键一族数字层的 0 和空格不再对齐上方数字列，0 比一个数字键宽；HarmonyOS 九键一族数字层的空格从 4.2 份让到 3.15 份。Android 与 iOS、HarmonyOS 的数字页在 0、空格和借用页的 `符` 上仍各不相同。

## Verification

#9113 原修复：`KeyboardActionRowSmoke` 覆盖有无地球键、语言数字交换时九键数字层的次序、宽度和唯一 0；`NineKeyNumericLayoutDeviceSmoke` 在 API 28 和 35 专用模拟器上比较切换前后 `符` 和层键的实际横向位置，并验收数字、空格、小数点、符号面板和两次往返。

本篇：

- Android：`KeyboardActionRowSmoke.numberPadFollowsTheSourceRow` 对 26 键、韩文、14 键、18 键、手写、大千注音逐一断言数字层第一格与字母层第一格是同一个键（含交换语言数字键）、26 键的 `符` 同一格、地球键位置、唯一 0、各键宽度与九键数字层相同，拼音九键、笔画、注音九键保持 #9113 的排列，右侧大回车返回空表。`NumberPadDeviceSmoke` 在全拼、小鹤双拼、14 键、拼音九键、笔画进数字页时比较返回键与字母层 `123`、`符` 与字母层 `符` 的实际横向位置，本篇没有在模拟器或真机上运行它。
- iOS：`KeyLayoutStyleTests` 钉住 `nineKeyDigits` 的份额、与字母层同宽同位的前两键和整行总份额，并用真 `KeyboardViewController` 按各九键样式、显示和隐藏中/英量数字层底行；`NineKeyKeyboardTests` 比较 `符`、切换键在两层的横向位置。
- HarmonyOS：`keyboard-logic.test.ts` 钉住九键一族数字层的键序、份额和与字母层相同的前两键。
