# Agent Note: macOS 设置页提供可用的手写试写入口

Status: implemented

## Problem

macOS 手写设置页只有入口说明，却显示恢复全部偏好的按钮。宿主已有独立识别和复制命令，设置页没有使用它们；直接加打开按钮又会把没有原生输入会话的面板显示为可以上屏。

## Decision

设置页提供打开手写板的操作和书写预览，说明设置中可识别并复制，直接上屏从目标应用的输入法工具栏或菜单进入。面板用宿主只读能力查询决定是否提供输入：macOS 需要对应启动路由、窗口、未使用的候选输入会话及空闲生命周期；未知或查询失败只提供复制。实际提交仍由原生会话验证，不用界面查询替代原有守卫。手写页不显示全局偏好恢复按钮；HarmonyOS 笔迹设置在宿主自己的设置文件里，原有全局恢复也不作用于它。

## 历史笔记审计

- [Windows 手写页](../../implemented/feature/2026-10-11-windows-settings-handwriting-row.md) 部分重叠：复用共享手写板的识别和复制操作，Windows 原生设置不改。
- [macOS 面板发送测试](../../implemented/testing/2026-10-13-macos-panel-test-complete-send.md) 无关：它修正测试发送端短写，本次不改协议或发送路径。
- [屏幕键盘发送指引](../../implemented/bug-fix/2026-10-13-macos-screen-keyboard-delivery-guidance.md) 部分重叠：保持错误指引；同一反馈中发现的键盘标题栏宽度和字号修正不改发送契约。

## Alternatives considered

- 保留说明而不提供入口：能避免无会话上屏失败，但浪费了已有的识别和复制能力，设置页仍是没有操作的空页。
- 设置页打开面板后捕获上次活动应用并注入文字：操作直观，但设置窗口不拥有原生 IMK 会话，上次目标也可能已变。复用受验证的原生入口，设置中只识别并复制。

## Verification

macOS 上 9 个 UI 测试文件、62 项测试通过，覆盖能力拒绝或查询失败时仍识别并复制、合法原生会话输入、旧客户端回答隔离及其他桌面平台沿用原能力。Rust 原生能力测试通过，覆盖路由、窗口、会话类型、无会话及忙状态。类型检查与界面构建、改动文件的 lint 和格式检查、Rust fmt 和 clippy、笔记检查、diff 检查及 `verify-local.sh --quick` 通过。

已安装到本机，通过原生宿主的生产启动入口验收共享设置与面板。窗口 AX 几何确认键盘布局按钮为 52×28px，与第一排按键不重叠；手写页有打开入口、没有全局重置，实际面板有画布和复制操作，没有无会话的输入操作。浮动 NSPanel 的窗口截图工具不可用，因此这里的本机证据是 AX 控件与几何检查；识别和复制行为由合成客户端测试覆盖，未向用户编辑器注入文字。安装组件的 deep strict 签名校验通过，原生输入法启用模式仍仅有 `.Hans`。

## Consequences

旧宿主没有能力查询时，macOS 的直接输入入口隐藏，复制仍可使用。改动不删除现有原生提交接口。
