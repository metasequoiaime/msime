# Agent Note: macOS 自适应候选空测量不再压缩候选栏

Status: implemented

## Problem

macOS 横向候选数量设为「自动适应」时，临时出现候选文字为空或极窄的测量结果会让共享列宽回落到 1pt。候选栏仍保留卡片和选中状态，但候选按钮被压成空胶囊，输入小鹤双拼 `UE` 时可见；候选随后变化时宽度又恢复，造成用户看到空白或被裁切的候选内容。

## Decision

自适应候选测量沿用普通候选页的内容区最低宽度。候选行的自适应无序号宽度下限取行框本身的 chrome 宽度（序号栏、间距和左右内边距之外的固定部分），皮肤另有更大最小项宽时取两者较大值。共享列仍按自然宽度排布，只有空测量行使用这个下限；正常候选的收紧和最大宽度规则不变。

同时保留共享列卡片的 20pt 总宽度下限，防止共享列覆盖普通候选页的卡片保护。下限只影响空或极窄测量，不改变有效候选的列宽、分页、候选身份和上屏路径。

## Alternatives considered

- **恢复历史最大宽度**：会让自动适应失去按内容收紧的行为，不能处理本次空测量导致的按钮压缩，因此不采用。
- **过滤空文字候选**：会改变引擎候选的序号与身份映射，且空文字候选可能是运行时保留的原样输入行，因此不采用。

## Verification

候选行布局回归新增空测量候选：渲染自动适应候选页后，卡片宽度至少为 20pt，按钮宽度至少为 1pt。运行 `git diff --check`；完整 macOS 原生构建和真机编辑器验收交由 PR 的 macOS CI 与维护者按仓库验证段执行。

## Consequences

有效候选的自适应收紧、最大宽度、分页和展开列宽保持不变；只有空或极窄测量结果会使用内容区下限。仓库当前磁盘空间不足以启动新的完整 macOS 构建，因此原生测试和真实编辑器验收留给 PR 的 macOS job 与维护者复验。
