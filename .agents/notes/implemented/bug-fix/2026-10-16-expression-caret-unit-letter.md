# Agent Note: V 模式光标插入接受单位字母

Status: implemented

## Problem

`V` 表达式模式在末尾输入数字后的单位字母和单位分隔撇号时，会把它们作为单位继续解析；光标编辑时，`insert_at_caret` 只接受 `spelling_symbols` 中的数字和运算符，拒绝同一条输入路径本来会接受的单位字母与撇号。例如 `V3g` 在 `g` 前插入 `k` 不能改成 `V3kg`，`V3jinkg` 在单位后也不能插入分隔撇号。

## Decision

表达式模式把“光标之前已经出现数字后接受单位小写字母”和“单位字母后接受唯一分隔撇号”的判断提取为共享谓词，末尾输入和光标插入都调用它。其余字符仍按原有 `spelling_symbols` 规则处理，长度限制和单位解析逻辑不变。

## Alternatives considered

- **在光标分支单独接受所有小写字母。** 这样能覆盖单位编辑，但也会让数字前的普通字母进入表达式，改变入口和原文回退规则；按光标前缀复用末尾路径的数字前置条件更窄且一致。
- **让宿主在光标处自行重写单位。** 宿主不应复制表达式解析和预编辑重建，跨平台实现会再次分叉；共享会话已经拥有正确的规则，因此在引擎内复用谓词。

## Verification

新增真实 `Session` 回归：输入 `V3g`、将光标放到 `g` 前、插入 `k`，确认按键被处理、预编辑变为 `V3kg`、光标与候选正确且退格可以恢复；不同长度的单位后都能从字符或标点入口插入撇号并选择换算结果；数字前插入字母、重复撇号和满长度插入仍被拒绝。两项新增插入回归在原实现下均因 `handled` 为假失败，同一谓词仍服务末尾输入的现有单位测试。修复后的完整引擎 2210 项单测和 31 项 golden 通过，35 项按既有配置忽略；Clippy、格式、笔记和差异检查通过，独立审查无阻断。完整 quick 复跑通过，覆盖共享 Rust、Android/wasm、Android Java、macOS 原生宿主和 Apple bridge；Linux 缺 Docker、Windows 缺 MinGW、HarmonyOS 缺完整环境的构建按规则跳过。首次 macOS 链接阶段失败，独立重建与完整 quick 复跑通过，未把该次失败计为验证成功。未进行系统输入框 UI 或真机验收。

## Consequences

本篇原先保留的“光标拒绝字符后组字不变”由[光标拒绝键的提交与透传](2026-10-16-local-caret-rejected-keys.md)部分取代；以下合法插入语法、字符集和容量边界继续成立，拒绝后的提交与退出遵循新规则。

单位字母和分隔撇号可以在表达式光标编辑中被插入，末尾和光标两条路径不会再分叉。数字前的普通字母、运算符、重复撇号、长度上限及单位换算均保持原有行为。与[带符号数值的 V 模式规则](2026-10-16-signed-unit-conversion.md)相邻但独立：该笔记约束数值前缀，本笔记约束光标编辑入口。
