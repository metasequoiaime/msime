# Agent Note: Android 剪贴板详情顶栏与触摸命中

Status: implemented

## Problem

剪贴板记录详情仍显示顶部「返回」按钮和「记录详情」标题，固定顶栏占用正文高度。标题所在的空白触摸区域没有可点击子视图，事件会继续落到键盘下层，导致用户点详情顶部时输入候选字。

## Decision

详情态隐藏剪贴板顶栏，并把滚动正文的顶边从 32dp 调整为 0，使记录从面板顶部开始显示。返回能力保留在详情正文底部的「返回」按钮。剪贴板面板根容器设置为可点击，让没有子控件处理的空白点按由剪贴板窗口消费，不再传给下层键区；列表态仍恢复 32dp 顶栏。

设备冒烟覆盖详情态没有顶栏控件、正文顶边归零以及旧顶栏位置的点按由面板消费；现有从列表和全文预览返回的路径保持不变。真实输入法的 `ClipboardSegmentDragDeviceSmoke` 原来等待已移除的「记录详情」标题，现改为等底部返回入口并断言标题不存在，在真实输入法面板顶部注入一次点按、断言合成编辑器仍为空，继续按原默认设置检查时间、返回全文预览、插入、编辑与历史不被意外改写。只更新已明确删除的标题契约，不改变测试输入、开关或滚动前置条件。

## Alternatives considered

- 只把标题设为不可点击：可以阻止标题自身的部分事件，但固定顶栏仍占空间，标题周围的空白仍可能穿透，因此没有采用。
- 保留顶栏返回键、只拦截顶栏触摸：能规避候选字，但没有满足 issue 要求的删去返回键和标题、释放正文空间，因此没有采用。

## Consequences

详情页可多显示一行正文，顶部空白点按不会输入候选；返回入口集中到底部操作行，读屏用户仍有明确的返回描述。剪贴板根容器会消费面板内没有子控件处理的点按，这是面板作为键盘窗口的预期边界；列表态的顶栏、滚动和返回路径不变。
