# Agent Note: AI 皮肤取消后隔离旧生成请求

Status: implemented

## Problem

AI 皮肤抽卡的取消操作只通知生成服务。服务端取消与结果返回存在竞态；结果先到时，页面仍会显示用户已取消的皮肤。取消后立刻重新抽取时，旧请求的收尾回调还可能清掉新请求的加载状态。

## Decision

点击取消时立即清空当前请求 ID，并恢复抽卡操作。生成结果、错误和收尾回调只在其 ID 仍属于当前请求时更新页面；进度回调继续按请求 ID 筛选。取消通知异步发送，页面状态不等待服务端确认。React 抽卡的状态归属与公共 runner 代次见 [AI 抽卡状态](../../implemented/simplification/2026-10-17-ai-skin-generation-state.md)，它同时隔离服务会话更换后的旧请求。

## Alternatives considered

等待 `client.cancel` 完成后再解锁抽卡可以减少同时在途的请求，但取消调用不能保证先于生成结果完成，也会让用户等待服务端响应，无法单独解决迟到结果覆盖页面的问题。

## Consequences

取消后可以立即重新抽取；旧请求即使随后成功或失败，也不能覆盖新请求的结果或加载状态。代价是前后两次请求可能短时间同时在途，服务端取消仍需独立完成。回归测试覆盖取消后旧结果抵达以及重抽期间旧请求收尾的顺序。
