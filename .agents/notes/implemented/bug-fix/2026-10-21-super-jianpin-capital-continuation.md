# Agent Note: 超级简拼空入口遇到大写转回普通组字

Status: implemented

## Problem

#9098 的 `JIT` 仍出现中文候选：`J` 先进入超级简拼，`I`、`T` 被该模式接受并折成小写。普通全拼、双拼已有的大写字面规则只处理未进入本地模式的组字，因此没有覆盖此入口。

## Decision

全拼、双拼中，超级简拼只有入口 `J` 时，后续大写按既有空入口拒绝大写路径转回普通组字，两枚字母保留、不提前上屏；后续候选和编辑复用大写字面规则。`J` 后接小写仍使用超级简拼；已输入模式内容后的接受规则保持原状。Unicode 的合法十六进制大写不受影响。

- [Shift 入口总开关](../../implemented/feature/2026-10-11-shift-letter-entry-switch.md)保留默认值、开关和触屏入口约束。

## Alternatives considered

- **关闭超级简拼或整个 Shift 入口默认值**：所有大写英文都更容易输入；但会改变已有用户和触屏菜单，且未解决入口接受大写的根因。
- **所有模式遇到第二枚大写都退出**：规则统一，也能覆盖其他缩写；但会抢走 `UF` 等合法 Unicode 输入，因此只调整会查询中文的超级简拼空入口。
- **只把英文候选提到首位**：完整英文词可能符合预期；未知缩写仍会查询中文，不能保证 `JIT` 的字面含义。

## Verification

未修改生产代码时，新引擎回归在全拼 `JI` 断言失败：仍处于 `SuperJianpin`，证明大写没有进入字面路径。修复后的共享运行时定向回归通过，覆盖全拼、双拼 `JIT`、`JSON` 的无提前上屏、首候选选择及退格、原样提交。

首轮完整引擎库测试 2386 通过、49 忽略；golden 只有 `local_super_jianpin_queries` 与新规则有意不同，旧断言要求 `JNH` 出「你好」等中文。只更新该步骤的原文候选、模式与分词边界，并在场景和参考文档注明 #9098；其余 299 个场景继续保留原断言。完整重跑通过：引擎库 2386 通过、49 既有忽略，运行时 330 通过，golden 31 通过（300 个合成场景）；真实词库 golden 未配置，不计实际回放。两 crate 的全部 targets 严格 clippy、格式检查通过。

远端 macOS 的最终 quick（`20261021-145355`，18 分 41 秒）退出 0：Rust 工作区、Android 目标、WebAssembly、Android Java 宿主、Linux 设置壳与原生宿主（108 项测试）、macOS 原生宿主和共享 Apple 桥接层编译均通过；Windows 可在本机运行的 162 项通过。完整 Windows 交叉构建因缺少 MinGW 跳过，HarmonyOS 真打包因依赖未就绪跳过，不计通过。笔记与差异检查在本机通过，生产代码、回归和 golden 文件与远端已验证副本逐文件 SHA-256 一致。

## Consequences

`JIT`、`JNH` 等缩写从第二枚大写起回到普通组字，不再用其字母查询超级简拼。`J` 后接小写、已有模式内容后的接受规则和 Unicode 合法大写保持原路径。原来使用 `J` 后立即输入大写简拼的用户需改用小写。尚未在系统输入法 UI 中验收，运行时回归不代表装机验证。
