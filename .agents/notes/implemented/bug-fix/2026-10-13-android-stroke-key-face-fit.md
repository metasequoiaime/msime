# Agent Note: Android 笔画键面只保留符号

Status: implemented

## Problem

笔画键使用 26sp 主符号和半字号名称。API 35 模拟器上六个名称都在键帽底边被裁切：小字仍占用基础画笔的行高。用户要求收简键面，笔画符号不需要再附「横、竖、撇、点、折、通配」文字。左栏的整条背景也与中间、右侧独立键帽不一致。

历史检索：[九键标签适配](2026-10-13-android-nine-key-label-fit.md)和[九键符号栏](../feature/2026-10-08-android-nine-key-number-pad.md)部分重叠，分别互链；大千注音键高笔记处理四行几何，与本次笔画键面无关。其余笔画查询缓冲笔记无关。

## Decision

`StrokeKeyboardLayout.face` 只返回笔画符号，名称继续通过 `accessibilityLabel` 提供给读屏。主符号上限从 26sp 调为 22sp，在 14–22sp 间按键帽宽高适配单行文字，继续遵守键盘字体缩放上限。笔画左栏采用独立键帽，一屏三项，与三行网格对齐；显式自定义符号仍可滚动。左右侧栏使用相同宽度权重，重输字号与九键一致，句点键面跟随中文标点设置。

## Alternatives considered

- **保留符号与名称两行，单独缩小第二行的行高**：能保留每种笔画的明确名称，也能修复文字被裁切；但键面仍重复说明，用户希望只保留符号。一行即可，名称留给读屏。
- **保留两行，只缩小主符号**：改动最少；但牺牲笔画辨识度，系统大字体与矮键高仍更容易裁切。

## Consequences

键面减少为一个笔画符号，主符号略小，窄屏、大字体和较矮键高继续由自动字号适配。键盘总高和输入映射不变；视觉界面不再显示笔画名称，读屏仍能辨识各键用途。其他布局的两行提示排版不受影响。

## Verification

键面与无障碍描述由已有 `StrokeKeyboardLayoutSmoke` 检查。原生 APK 构建、资源 lint 与签名验证，以及 quick、笔记检查和差异检查覆盖本次改动。API 35 专用模拟器使用仓库内 Windows 笔画合成词库夹具检查键面；笔画输入、重输、选择「一」上屏与删除沿用已有按键映射。最终单符号键面的正常字号、2 倍字号及最低 75% 键高截图用于检查裁切，设备测试后恢复原偏好并移除夹具。
