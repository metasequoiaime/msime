# Agent Note: IBus 按需激活使用可认领的组件总线名

Status: implemented

## Problem

#8907 在 GNOME 选择水杉输入法时超时。隔离的真实 IBus 1.5.27 中，只加载安装组件 XML、由 daemon 首次选择引擎会超时，宿主已经运行后第二次选择立即成功。现有验收主动启动宿主，再使用动态注册的引擎，因此没有覆盖首次按需激活。XML 的组件名 `msime-linux` 不是有效的 D-Bus 服务名，宿主也从不认领组件名；动态 `RegisterComponent` 不能完成正在等待原始静态组件的首次选择。

## Decision

组件 XML 与宿主使用同一个按产品版本生成的 `<tauri_identifier>.IBus` 名称。宿主在工厂准备完成后认领它，使 daemon 把工厂关联到原来的静态组件；认领失败时退出，避免把没有取得名字的重复宿主继续作为可用引擎。保留动态注册，兼容直接运行与崩溃恢复的现有路径。引擎名保持原样，已有 GNOME 输入源配置不需要迁移。

版本契约检查分别校验 XML 的组件总线名与引擎名，不再要求它们同名；原有引擎身份、包名、用户配置目录等升级兼容约束继续保留。

## Alternatives considered

延长 GNOME 的超时能容忍慢启动，但此处宿主已完成动态注册，静态组件仍没有工厂，等待时间不能修复关联。让安装脚本预启动宿主可以绕开首次选择，但会让可用性依赖外部启动时序，仍然遗漏 IBus 的正常按需启动契约。

## Verification

真实 daemon 回归从安装产物的组件 XML 首次选择引擎，不预启动宿主。旧实现首次选择超时，修复后首次和重复选择均成功；使用已验证词库输入合成 `nihao` 并提交「你好」。Linux 原生构建和现有 93 项测试通过，新 daemon 测试在没有运行时依赖的构建镜像中明确跳过，随后在包含真实 IBus 的隔离验收镜像中通过。六个产品版本的脚本与数据渲染检查通过。

安装产物上的既有真实 daemon 验收继续通过，包括 SIGSEGV、SIGKILL 后自动重启并恢复输入、维护停止不重启，以及 daemon 退出后结束监督进程。

以上两组验收分别在 IBus 1.5.27 与上游 `1.5.34` 标签源码上通过。后者固定提交 `1f7af28437afd62a6d145bfc81035e698a37411d`，源码归档 SHA-256 为 `a358b14c98f5cc63462a342724913f4f0f8c62f5d02b4321cddfdc52cd81ff24`；沿用上游源码自报的 `1.5.34-rc2`，不改写版本字符串。

五笔版安装产物在同一现代 IBus 中也通过首次与重复激活，组件名的按版本渲染与宿主的宏保持一致。

最终提交前 quick `20261020-175905` 全程通过（9 分 34 秒），包含版本契约、Linux 原生门禁、macOS 宿主、共享 Apple 桥接、Android Java、Rust workspace 与目标编译检查；缺少工具链的 Windows 原生与 HarmonyOS 打包阶段按脚本明确跳过。

## Consequences

按需激活不再依赖外部预启动或第二次选择。宿主多进行一次同步总线名认领；总线名按版本隔离，后缀 `.IBus` 与设置应用的标识区分。此处复现定位在静态工厂关联，未在报告者的 Arch/GNOME 51.1 系统直接验收。
