# Agent Note: Fcitx5 上屏后丢弃旧的标点前文

Status: implemented

## Problem

#8942 报告双拼空格上屏后的第一个逗号为英文、删除重输才成为中文。Fcitx5 的上屏操作异步发给客户端，宿主却继续把提交前的有效 surrounding text 当作当前文档；旧光标前的 ASCII 字母盖过本会话刚提交的中文影子，智能标点因而错误保留英文逗号。真实 Fcitx5 输入上下文回归 `20261020-194319` 复现：旧前文为合成 `A`，`nihc` 空格正确上屏「你好」，下一次逗号未按中文提交。

组字时逗号无反应还有独立原因：`navigation.comma_period` 默认开启，逗号作为上一页键。此项有明确导航偏好，不在本次前文时效修复中更改默认值；关闭此项时，组字中的逗号沿用已有标点提交路径。

## Decision

Fcitx5 宿主在发送非空提交之前使旧 surrounding text 失效，等待客户端重新发布文档；期间智能标点使用本会话由输入法自己提交的末尾影子。失效发生在 `commitString` 之前，因此同步前端在提交回调内发布的新文档保持有效。新空文档、新选择或新光标仍以客户端状态为准，不改为影子全局优先。

旧影子回归在提交后发布空文档，才检查文档起点优先级。提交前发布空文档只能描述旧光标，不能用来断言一次提交后的状态。其他影子隐私、焦点和直通按键的失效纪律保持。

## Alternatives considered

- 始终让标记为有效的文档优先，可以避免影子盖过客户端的真实光标与选择；但提交前发布的文档不是提交后的状态，原有有效标记必须失效。
- 根据旧文档自行插入提交文字，可以继续提供完整前后文；无法可靠预测提交过滤、客户端改写或异步选择变化，因此不伪造文档快照，只保留输入法已确认的末尾影子。
- 修改影子为全局优先，能绕过过时前文；却会忽略客户端后来发布的新光标、空文档和选择，故只收窄提交前快照的有效期。

## Verification

定向原生回归在修复前失败，失败点为「中文上屏后不能沿用提交前的 ASCII 前文」。测试使用真实 Fcitx5 输入上下文与 Host API，覆盖双拼组字、空格提交、真实释放事件、随后输入逗号；另覆盖 ASCII 提交后的智能标点、提交后发布的新空文档、同步提交回调内的新文档，以及逗号导航开关两种行为。测试独立注册，避免完整 native-context 中已有的无关表达式断言先失败而掩盖它。

最终实现 `20261020-194533` 以 0 退出，真实 Fcitx5 前文时序与导航定向回归全部通过；本机笔记校验和差异检查通过。

提交前 quick `20261020-194732` 以 0 退出，Linux 原生测试 93/93，通过 Rust、Android 目标、WASM、Android Java、macOS 宿主与 Apple 桥接层构建。Windows 交叉工具链及 HarmonyOS 原生依赖未配置，对应阶段按现有规则跳过，由 PR CI 覆盖。

## Consequences

中文上屏后不再误读提交前的英文字母；输入法刚提交 ASCII 时仍能通过影子保留英文标点。等待客户端刷新期间，其他依赖完整前后文的功能也不能使用旧光标，可能暂时采用无前文路径。这比把过时位置当作当前文档更保守。不修改文件格式、Host API、默认逗号翻页偏好或 IBus 宿主。本 PR 只修复 #8942 的上屏后标点部分，以 `Refs` 关联。
