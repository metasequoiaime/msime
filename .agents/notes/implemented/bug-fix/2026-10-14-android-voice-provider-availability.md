# Agent Note: Android 语音设置显示系统识别服务可用性

Status: implemented

## Problem

Android 语音设置页把没有云端凭据的配置显示为「暂用系统识别」，但此前只依据共享配置解析结果，没有检查设备是否注册了 `RecognitionService`。没有系统识别服务的设备因此在设置页看起来已经有可用路径，按键后才得到失败提示；这与 #7335 报告的「打开设置后仍无法使用」相符，也让用户错过本地模型或豆包这两个替代路径。

## Decision

设置页读取 `VoiceRecognitionActivity.available(context)`，把系统识别服务是否可用作为页面状态的一部分。`VoiceProviderPolicy.status` 增加带可用性参数的重载：系统服务缺失时明确提示「没有可用的系统识别服务，可改用本地模型或豆包」；云端服务缺少凭据且系统服务也不可用时，不再声称会暂用系统识别。保留无参数重载的原有语义，其他宿主和 JVM 调用不受影响。

`SpeechRecognizer.isRecognitionAvailable` 在厂商系统抛出运行时异常或链接错误时按不可用处理，避免设置页因查询失败而崩溃或显示错误的可用状态。

## Alternatives considered

- **只保留键盘启动时的错误提示**：改动最少，但用户必须先离开设置页、触发一次失败才能知道系统没有识别服务，不能解释为何「打开相关设置」仍无效。
- **没有系统服务时自动切换到云端或本地模型**：能隐藏错误，但会在用户不知情时改变音频处理路径；本地模型还可能没有下载，云端服务也可能没有凭据，因此继续由用户选择替代服务。
- **让设置页直接启动系统语音服务设置**：不同厂商的设置入口不稳定，且不能解决系统没有服务的设备；先在当前服务行给出准确状态，沿用已有的本地模型和豆包入口。

## Consequences

- 无系统识别服务的用户在按键前就能看到明确原因和可行替代路径。
- 有系统识别服务的设备保持原有提示和行为；云端服务配置完整时仍不显示多余提示。
- 页面额外查询一次系统能力；查询异常被视为不可用，避免把异常传播到设置渲染线程。

## Verification

`VoiceProviderPolicySmoke` 覆盖系统服务可用、不可用以及云端凭据缺失时的三种文案；`bash platforms/android/check-host.sh` 负责编译宿主并运行该 JVM 冒烟，同时验证 Android 清单与宿主契约。
