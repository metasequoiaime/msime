# Agent Note: macOS Caps Lock 轻点等待实体状态

Status: implemented

## Problem

Issue #10845 报告在最新 macOS nightly、内置键盘和 Apple 外接键盘上启用 Caps Lock 轻点切换后，轻点不能切换输入模式。现有代码在首个 `flagsChanged` 事件没有实体按住位、HID 也尚未返回结果时直接放弃布防；这会把状态读取竞态表现成“每次都回到系统键盘/没有切换”。相关功能的原始设计见 [2026-10-11-caps-lock-language-switch](../feature/2026-10-11-caps-lock-language-switch.md)。

## Decision

首个事件缺少实体按住位时仍然布防，并启动或重试 HID 监听；在 HID 结果到达前，定时器只负责识别超过阈值的长按，不把未知状态当成已经松手。后续的 `flagsChanged` 松键事件到达后再完成轻点判定。已有的实体按住状态、长按、撤回大写锁定失败和失焦重置路径保持不变。

## Alternatives considered

1. 继续等到实体状态已知才布防：这是原实现，会复现 #10845。
2. 首个未知状态立即按松手处理：会把实体状态回调延迟误判为轻点，并破坏长按。
3. 只等待固定时长而不读取松键事件：会给轻点增加不必要延迟，且无法区分真实长按。

## Consequences

首个 Caps Lock 事件与 HID 状态回调竞态时，输入法可以保留待定轻点并在实际松键事件到达后切换；待定期间的状态事件由输入法消费，避免未确认的锁定状态继续传给应用。若系统既不提供 HID 状态也不发送松键事件，待定状态会在长按阈值后按长按处理；不会改变任何出厂默认值。

## Verification

新增合成回归覆盖：首个事件没有实体按住位时继续布防、定时器不提前切换、后续松键事件完成轻点，以及无松键通知时的轮询路径。由于本机剩余磁盘不足以启动新的 Xcode 构建，未在本地编译 macOS 宿主；需要 CI 以及报告者在 macOS 27.2 的内置键盘和 Apple 外接键盘上复验。
