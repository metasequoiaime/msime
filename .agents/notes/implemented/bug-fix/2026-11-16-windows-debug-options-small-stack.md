# Agent Note: Windows 调试宿主配置解析适配系统编辑器的小栈

Status: implemented

## Problem

Windows 真实编辑器验收中，512 KiB 主线程栈的系统记事本加载同源调试版宿主库后，在 `HostOptions` / `Preferences` 的 serde 反序列化路径退出。仅优化宿主 ABI 后，独立的配置解析拒绝路径已通过，但原版记事本仍在 `ProviderRegistry::new` 的 `___chkstk_ms` 退出：配置之后的引擎会话构造同样用尽了主线程栈。改前与改后原生 TIP 均复现；WER 记录分别落在 serde 访问者与 `___chkstk_ms`。不能把找不到编辑器窗口当成焦点问题，也不能通过扩大系统编辑器的栈或删减完整偏好绕过。

## Decision

先在子进程内以完整出厂偏好和 256 KiB ABI 可用栈重现，为系统与 TSF 调用链保留原 512 KiB 栈的一半。独立 Windows 对照已经确认：同一库、同一完整配置，2048 / 512 KiB 空线程返回正常，256 KiB 以 `0xC00000FD` 退出；不能把空线程的全部 512 KiB 都算给配置解析。`msime-host-api` 的 dev profile 保留本轮同步进来的三级优化，`msime-engine` 开启一级优化，让宿主 ABI 的泛型反序列化与引擎会话构造避免未优化的大量栈临时值；宿主门面的 `Session.inner` 用 `Box` 持有核心会话，后续 runtime 和宿主注册表构造不再层层搬移整个大对象；保持调试断言、溢出检查、发布配置、设置默认值与宿主线程模型。

## Alternatives considered

- 在专用大栈线程创建会话，最强理由是能明确预留足够栈。不选：宿主会话注册表具有线程归属，把创建移到临时工作线程会改变既有契约；只转移反序列化也给每次配置解析增加线程与等待。
- 仅提高优化级别，最强理由是不改变对象存储布局。实测宿主与引擎一级、二级优化仍不能让完整会话通过 256 KiB 回归；只优化宿主并单独装箱核心会话也不足。优化消除临时值与缩小宿主会话对象需要一起验证，不能以解析拒绝路径代替。
- 只换 release 库，最强理由是发布构建本来就优化。不选：仓库也用 dev 构建进行本机安装，不能留下同一开发构建在系统编辑器启动即崩溃的问题。

## Consequences

macOS 上真实 C ABI 的完整偏好与非法 edition 小栈回归通过；仅撤掉包级优化后，同一 256 KiB 测试因栈溢出失败（退出 101，子进程 SIGABRT），恢复后退出 0。Windows 原库独立对照在 256 KiB 退出 `0xC00000FD`，2048 / 512 KiB 空线程正常。Windows native settings 的实际构建步骤运行这个集成测试，不能只编译。

回归同时使用完整出厂偏好在 256 KiB 的同一线程里成功创建并销毁真实会话，所有路径指向临时合成目录，不访问个人词库。此前只覆盖 API 版本拒绝路径的回归漏掉了引擎构造；扩展回归后，仅优化宿主 ABI 的版本在 macOS 子进程里再次栈溢出（退出 101，SIGABRT），与 Windows 原版记事本的第二次转储相互印证。宿主与引擎一级优化、核心会话装箱组合后，同一完整回归退出 0。随后同步 PR 上已提交的宿主三级优化，最终级别的组合按同一回归复验通过。完整 Host API 套件在测试进程句柄上限 4096、两条测试线程下通过 13 组、1212 项，6 项原有忽略；默认高并发运行先后耗尽文件句柄和线程资源，日文混输测试还出现后台模型尚未就绪的时序失败，不改测试输入、默认值或断言来绕过。

每个宿主会话新增一次堆分配，销毁仍在原线程按字段顺序释放核心会话；按键路径不新增分配。宿主门面的公开方法与线程约束保持原样。

这两个包的 dev 编译可能变慢，局部变量的调试体验可能受优化影响；调试断言、溢出检查、发布配置、默认值与线程归属不变。最终同源 Windows 库和未改栈大小的系统记事本仍须实测，完成前不记作真实编辑器通过。原始 dump 和日志只在本地保留，公开材料不包含私人配置或路径。
