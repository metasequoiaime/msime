# Agent Note: iOS 设置深链接隔离导航栈代次

Status: implemented

「手机设置视图持有创建时的根栈标识」与「保留现有按深链接重建设置栈的行为」已被 [iOS 设置栈不再靠换栈回到根页面](2026-10-30-ios-settings-stack-no-identity-swap.md) 取代：iOS 18 上换掉推入过页面的设置栈后新栈不再推入页面，手机深链接改为先弹回根页面再推入。路由器只保存请求、栈内选中页归视图所有的决定仍成立。

## Problem

在试用键盘二级页打开 `msime://settings/input` 后，应用只显示设置首页。系统直接打开链接的对照用例同样失败，因此不是扩展未能启动宿主。设置根栈重建时，把一次性路由请求直接用作 `navigationDestination(item:)` 绑定，导航初始化或退出时的回写会清空请求。

## Decision

手机设置视图持有创建时的根栈标识及栈内选中页；路由器只保存待消费的请求。当前栈挂载或收到请求时消费它，导航目的地与设置行只绑定栈内选中页，导航初始化与旧栈退出的回写均不影响新请求。保留现有按深链接重建设置栈的行为，不增加固定延时，不重建其他标签。

检索审计：[二级对话页](../../implemented/feature/2026-10-16-mobile-chat-secondary-page.md)持有标签栈与重选规则，部分重叠；[扩展启动宿主](../../implemented/bug-fix/2026-10-13-ios-keyboard-app-launch.md)持有 URL 打开能力，部分重叠，本次不改扩展调用；平板场景恢复笔记只处理侧栏选中项，与手机绑定回写无关。

## Alternatives considered

- 给共享绑定增加代次判断可以阻止旧栈回写，改动最少；实际扩展回归仍只到首页，新的导航绑定初始化也可能清空请求，因此让导航状态与一次性请求各有归属。

- 延迟设置目的地可避开旧栈清理，但依赖机器速度和转场时序，不能建立状态归属。
- 把全部设置导航改成统一显式路径能集中管理状态，但会扩大页面与平板导航契约的改动，先隔离既有绑定生命周期。

## Verification

- ad-hoc 签名的 iPhone 17 / iOS 27.0 模拟器中，新增试用页系统直接深链接用例先失败，修复后通过；保留更深设置页面时的跨标签深链接与标签重选回首页也通过，三项共 49.701 秒。
- 扩展中的添加语言入口独立通过，实际进入输入设置，44.771 秒。
- 真机 USB 转发当前找不到目标设备，尚未安装本修复，不能将模拟器结果写成真机验收。

## Consequences

导航栈自己保存当前页面，路由器只保留尚未被当前代次消费的请求，避免退出与初始化覆盖链接。正常返回不会再次消费旧请求，其他标签保留原栈。真机验证仍需恢复 iphone-use 连接。
