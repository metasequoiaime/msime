# Agent Note: macOS 切换输入源前保留原始字母

Status: implemented

## Problem

macOS 用户在水杉中文输入法中已经输入一段字母、随后用系统输入源菜单切到 ABC 或其他输入法时，输入源监视器会先清理水杉的运行状态。旧路径没有在这次交接前结束组字，正在编辑的字母可能随旧会话一起丢失；修饰键轻点和输入法内部模式切换虽然已有 `MSIME_COMMIT_RAW` 规则，却没有覆盖系统输入源切换。

## Decision

输入源监视器确认当前输入源已经离开水杉后，在重置共享模式状态和隐藏工具栏之前调用输入控制器活动入口。入口只针对当前获得焦点的控制器、活动客户端、有效会话和非空 `editing_text` 发出 `MSIME_COMMIT_RAW`，并通过现有 `apply:` 将原始字母交给编辑器；没有满足条件或核心命令失败时保留原有清理路径。入口只在主线程调用，提交成功后 `editing_text` 为空，重复的切源通知不会重复上屏。

系统输入源切换不是输入法内部的按键事件，因此不伪造 `MSIME_KEY_POINTER`，也不调用会提交高亮候选的 `MSIME_FINISH_COMPOSITION`。这样切到其他输入法时保留的是用户实际输入的字母，而不是候选区当前高亮的中文。

回归测试在合成的焦点控制器、会话和文本客户端上触发活动入口，确认只调用一次 `MSIME_COMMIT_RAW`、原始字母进入客户端且组字清空；输入源监视器原有的外部模式识别测试继续覆盖通知过滤和主线程调度。

## Alternatives considered

- 在 `deactivateServer:` 中统一改用 `MSIME_COMMIT_RAW`：它覆盖 IMK 的焦点回调，但输入源监视器会先清理状态，且普通焦点离开仍有既定的 `MSIME_FINISH_ON_FOCUS_LOSS` 候选提交语义，混改会改变编辑器切窗口行为。
- 继续使用 `MSIME_FINISH_COMPOSITION`：实现简单，但会把高亮候选中文提交到文档，正好复现 issue 报告的错误结果。
- 由输入源监视器直接持有控制器实例：会扩大监视器和 IMK 控制器的生命周期耦合；改用现有的焦点控制器活动入口，保持监视器只负责判断“已切出”这一事实。

## Consequences

切换到其他 macOS 输入源时，未完成的拼音、双拼或其他方案的原始编辑字母会在切换完成前写入原编辑器，避免因运行状态清理而丢失。没有组字的切源行为、普通失焦的候选提交、内部修饰键切换和模式重置规则保持不变。

本次只完成合成控制器回归和 macOS 定向构建验证；尚未在报告者的 macOS 版本、已安装水杉输入源和真实编辑器中完成实体输入源切换验收。
