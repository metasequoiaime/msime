# Agent Note: 换上用聊天上文训练的按键模型，句首单字按「字 + 逗号」比

Status: implemented

## Problem

聊天时，输入法看到的上文是同一个人前面发出的几条消息，中间隔着换行。按键重排模型 `rerank-v1` 训练时只见过「同一轮里前面的话」当上文，所以在 Mac 自动打字验收里，上文是「妈」时它仍把「你和爸」打成「喝吧」，前一条消息打错了「他」，后面几条会跟着把「他」打成「她」。9B 老师在 2.0 选错的 55 句聊天里能选对 39 句，说明这是模型判断的问题，可以靠蒸馏解决。

换上新模型后又露出一个旧问题：会话开头单打 `ma` 时，模型在「马」「码」「妈」「麻」这些单字里挑。它给每个字的分是「下一个字是它」的概率，消息开头常见的「马上……」「麻烦你……」也算在里面，而用户单打 `ma` 再按空格，要的是一个单独成词的字。旧模型在这里只是险胜（「妈」领先 0.12 到 2.01），新模型 7 次里有 3 次挑了「麻」或「马」（领先 0.09 到 0.44）。

## Decision

- **两档模型换成 chinese-ime-lm 的 `rerank-v2`**（`resources/rerank-model.lock.json`）。v2 结构、算子、`vocab.json` 都和 v1 相同，只换了权重。它从 v1 接着训，训练数据是 DeepSeek 为 chinese-ime-lm 写的 1,352 段单人连发聊天，每条消息以同一段里前面的消息为上文，由 9B 老师打分；训完和 v1 做权重插值（8x448 取新权重七成，6x256 取五成），把 ctx-v1 守在 90% 以上。语料里多了合成聊天，署名一并更新：图的元数据、`model.json`、`resources/licenses/rerank-model-Apache-2.0.txt`、各平台的 THIRD_PARTY_NOTICES，以及 `docs/third-party.md`；`scripts/test-model-notices.py` 逐字核对这些地方。
- **句首单字按「字 + 逗号」比**：`ordering::opening_particle_pick` 把每个候选单字后面接上 `OPENING_PAUSE`（全角逗号）再交给打分器，比的是「这个字单独说完、停一下」的概率。拼接用栈上的缓冲区，不分配堆内存。只有句首、首选是句尾语气词这一种情况会走到这里，别处的打分方式不变。

## Alternatives considered

- **要求模型领先一定差距才换掉词典顺序的第一个单字。** 这个方案已经写完、测过，然后撤回了。它的出发点是：模型差距很小时，相信词频。但锁定词库里 `ma` 的单字顺序是 马（279,925）> 码 > 妈（110,515），词典第一个是「马」，加了门槛反而让「妈」再也赢不了。真机验收里会话开头的 7 次「妈」有 3 次变成了「马」。
- **接换行而不是逗号。** 离线用真机上同样的上文重放，6x256 接换行也是 7 次全对，但 8x448 只对 2 次；接逗号时 6x256 新旧都是 7 次全对，8x448 对 6 次。所以选逗号。
- **只换模型，句首不动。** 真机验收 220 句的总数照样比旧模型多，但会话开头的「妈」从全对掉到 7 次错 3 次。这正是 [一句话开头不出句尾语气词](../feature/2026-11-03-sentence-start-particles.md) 要守住的情形，不能接受。

## Consequences

- **收益**：Mac 上用真实输入法自动打 220 句聊天（develop 7b3d59dad2 加本分支，开纠错，6x256 整句池 32 条），第一次按空格就对的从 187 句（85.0%，c70b16174f 加 v1）到 192 句（87.3%）。改对 7 句：「打车」「排期」「思思」×2、「人手」，两处「给他」（之前打成「给她」）；会话开头的「妈」7 次全对。离线在 MSIME 引擎里测 330 段带上文的单人聊天：8x448 从 80.6% 到 83.3%（多对 11、少对 2，p = 0.02），6x256 从 83.3% 到 85.5%（多对 9、少对 2，p = 0.07）。
- **代价**：ctx-v1 有上文的准确率在发布文件上 8x448 从 91.9% 到 91.4%，6x256 从 90.4% 到 90.1%，仍在 90% 的底线以上；sentences 四套里 6x256 少对 11 句（p = 0.13，不显著）。验收里还有两句变错了（「时间不急」「王总同意分两期了」），但前两轮完整跑新模型时这两句都对，离线新旧模型都错，判断是不稳定，不是退步。
- **延迟不变**：结构没变。`rerank_latency` 在 M4 Pro 上逐键成对测量，6x256 整句池 32 条时，带模型的 p95 是 3.29–3.37 ms 对 3.33 ms。
- **Hugging Face 的两个仓库仍是 v1**，许可文件只写 GitHub Release；`scripts/test-model-notices.py` 里这一项的 `hugging_face` 为空，等 Hugging Face 也换成 v2 再加回来。
- **验收方法**：真机验收要在 develop 版的包上做，并且先确认装的是哪个版本。2026-11-04 第一次验收是把新模型放进了已安装的正式版 0.57.0，引擎比 develop 旧，「下周私商闲」「要上西安」这类切分错误被误当成了模型的问题。
