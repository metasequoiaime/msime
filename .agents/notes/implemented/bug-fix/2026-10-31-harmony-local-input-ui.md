# Agent Note: 鸿蒙手机和平板隐藏快捷模式入口

Status: implemented

## Problem

鸿蒙手机和平板的共享设置页和触屏键盘仍显示快捷模式入口。V、T 等实体键盘快捷模式不适合手机触屏，功能面板里的「本地输入」及其下一级模式列表也会让触屏界面出现不应提供的入口。

## Decision

仅按鸿蒙设备形态隐藏界面入口：共享设置页在 `mobile_settings` 为真时不渲染「快捷模式」组，功能面板在手机和平板上不列「本地输入」磁贴；2in1 继续保留设置和实体键盘相关能力。共享偏好字段、模式定义和引擎路由不删除，避免清理已有配置并保持 2in1 行为。

「日期时间混入候选」（`date_time_inline`）和「日期格式入口」（`date_time_menu`）虽然列在 `local-mode-options.ts` 里，管的却是普通全拼打字的候选，缺键读作开，引擎在每个平台都照用。手机和平板上这两个开关不随「快捷模式」组隐藏，改由 `LocalModesSection` 的 `only` 只列这两行，放进「日期时间候选」组。

插件契约跟着入口收窄：`SettingsFormFactorCapabilities` 的 `pluginTriggers` 只在 2in1 上为真。手机和平板进不了 K 和 / 模式，插件页因此按 `touchPluginKinds` 不列短语表和指令表，「新建插件」也不给这两类，@ 名单不显示，社区插件只列符号集、单词本、按键音效包和辅助码表。否则这些表的详情会把人指向已经不存在的「输入 → 快捷模式」和「本地输入」。

## Alternatives considered

- 删除或清空 `local_modes` 偏好：会破坏已有配置，也会把实体键盘能力和 UI 隐藏混在一起，因此不采用。
- 仅把磁贴置灰：用户仍会看到不适用的入口，不能满足手机和平板不出现快捷模式 UI 的要求。

## Consequences

鸿蒙手机和平板的输入设置不再出现「快捷模式」，只保留「日期时间候选」两个开关；功能面板也不再出现「本地输入」及其子面板；插件页不再列短语表、指令表和 @ 名单，已装的这两类表计入列表末尾「用不到」的数目。2in1 的快捷模式设置、插件页和实体键盘能力保持不变。代价是手机接实体键盘时，已在别处打开的 / 和 @ 模式在设置里没有开关可关，引擎路由本身不变。未安装前端依赖，Vitest 与 Harmony 类型检查无法在本机启动；已完成差异检查和 Harmony 测试脚本的静态门禁检查。
