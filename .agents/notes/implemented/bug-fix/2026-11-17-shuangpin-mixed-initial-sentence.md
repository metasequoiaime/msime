# Agent Note: 双拼句中声母参与整句组词

Status: implemented

## Problem

#11555：双拼和简拼混输时，普通词条查询接受句中的声母，整句生成却只允许完整音节或末尾一个声母。多个词组成的长串无法跨过句中的声母建词格，首选退回较短前缀。合成词库中，六音节输入 `nihcckegsj` 原先只返回两字前缀“你好”。

## Decision

双拼整句允许完整音节与严格声母混合，至少保留一个完整音节作为锚点；纯声母整串的既有行为保持。普通整句与句中辅助码约束使用同一跨度查询。完整跨度和仅末尾声母的跨度复用原来的精确/有限枚举查询；句中声母跨度按 `jp` 扫描并逐段过滤，沿用混合简拼的扫描预算和词格的结果条数上限。约束查询保留原有不预截断的规则，先筛辅助码再束搜索。

声母必须完全相同，单键 `c/z/s` 不匹配 `ch/zh/sh`。完整音节只匹配规范化后的同一音节，`ke` 不变成 `ken`，零声母完整音节 `a` 不变成 `ai`。词边始终携带词库完整读音和相同音节数；生成候选携带实际输入按键，选择后消耗对应按键并学习完整读音。混输之后追加一个无法补全的末音节时，完整混输前缀仍保留自己的消费范围。

不改贪心两键优先切分，不枚举新的按键切分，不把混输当纠错，不更改任何设置或默认值。测试使用合成输入和词库，不复制报告者原文。

## Related decisions

- [双拼末尾声母参与整句补全](../feature/2026-10-24-shuangpin-trailing-initial-sentence.md)：部分取代。保留末尾补全、严格声母、完整读音、按键消费和前缀回退；句中声母原先明确不开放的范围由本 issue 扩展。
- [全拼不完整音节参与长句词网格](2026-11-10-quanpin-incomplete-lattice-sentence.md)：部分重叠。复用词格解码，但双拼不用全拼的宽松单字母匹配或末段前缀补全，保持双拼音节语义。
- [双拼末尾后置超级简拼](../feature/2026-11-05-shuangpin-postfix-super-jianpin.md)：无关。混输是普通双拼组字，不进入 J 模式。

## Alternatives considered

- 复用全拼不完整跨度查询：代码最少，但全拼的单字母声母可以匹配平翘舌伙伴，且末段前缀补全会扩大双拼已经定出的完整音节，因此改为严格双拼查询。
- 枚举所有声母对应的完整音节再逐个解码：可沿用精确 SQL，但多处声母的笛卡尔积会重复建图。按已有 `jp` 索引查询每个跨度，所有匹配读音在同一个词格竞争。

## Verification

新增合成回归在原实现上三项全部失败，首选只有“你好”。行为测试覆盖未分隔输入、手动分隔、末尾声母、五种内置双拼、冷/热缓存、整句开关、句中辅助码、严格平翘舌、完整音节、ü 别名、零声母、跨度上限和溢出桶音节数。共享会话测试覆盖实际按键消费和完整读音学习。

既有 `incomplete_tail_keeps_generated_prefix_and_its_input_span` 中“句首声母不生成整句”的断言属于被本次扩展的旧准入边界，应改为同一输入能生成完整候选；其余前缀、未完成输入和关闭词格的前置条件与断言保留。没有设备、模拟器或系统编辑器验收。

## Consequences

混输长串能跨越句中声母组成整句，前缀仍能单独选择。新跨度只在句中声母存在时查询，不增加完整输入的查询或分配。扫描预算仍可能限制低频匹配覆盖，且贪心切分有歧义的串仍按现有边界解释；本修复不保证任意输入的首选符合用户意图。
