# Agent Note: 表情锚定行的首页占位上限

Status: implemented

## Problem

混排表情已经会跟在它描绘的候选词后面，但每个读法最多取 48 行，所有关键词相同的表情会一起插在同一个汉字后面。输入 `you` 或 `好` 时，这些表情可能连续跨过第一页，把后面的常用汉字推到第二页。旧规则满足了“表情跟着词”的要求，却没有限制同一锚点的占位数量。

## Decision

在 `crates/engine/src/ime/queries.rs` 的 `anchor_expressive_rows` 中，每个候选词对每一类表达候选（emoji、颜文字）只在原位置保留一行。相同锚点的其余行不丢弃，而是按查询顺序进入列表末尾，并继续受既有的 `MIXED_RESULT_LIMIT`（每类三行）限制。不同候选词仍各自可以保留一行，表情仍紧跟它描绘的词；因此首页优先展示不同汉字，长尾仍可访问少量其他表情。

这个上限是引擎共享规则，macOS 的 #11334 和其他使用同一混排路径的平台得到相同候选顺序；没有改变任何平台默认开关或词库数据。

## Alternatives considered

- **继续保留同一锚点的所有行**：最能保持 2026-10-08 的旧行为，但无法阻止一个常用字后的表情连续占满首页，直接复现报告问题。
- **把所有表情统一放到候选列表末尾**：能保证汉字不被挤走，但会破坏“表情紧跟它描绘的词”的既有能力，也会让用户难以找到对应表情，因此不采用。
- **每个锚点只保留一行并丢弃其余行**：首页最干净，但会无故减少可选表情；保留少量尾部行能兼顾可达性和候选密度。

## Consequences

- 同一个汉字后不会再连续出现多行同类表情，后续汉字更可能留在第一页。
- 多个汉字各自仍可带一行 emoji 和一行颜文字；同一类的额外行移到末尾，最多三行。
- 规则依赖已有的 `MIXED_RESULT_LIMIT` 和固定数组，不增加堆分配，也不改变资源格式、设置字段或宿主接口。
