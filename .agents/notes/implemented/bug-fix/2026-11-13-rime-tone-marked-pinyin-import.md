# Agent Note: Rime 带调拼音词库导入

Status: implemented

## Problem

#11379 的 Rime `dict.yaml` 附件具有合法的 YAML 文件头与三列 TSV 词条，但编码使用带调拼音并以空格分音节。现有导入器只接受 ASCII 小写字母，因此拼音和快捷短语两种目标都报没有可用行；快捷短语还会拒绝音节间的空格。合成词典的三个正向回归在旧实现均得到 `NoUsableRows`。

核对上游实际默认分支 `wanxiang` 的固定提交 [`b0c0986eec2231fea9cc306a11697592e6fd4794`](https://github.com/amzxyz/rime-wanxiang-data/tree/b0c0986eec2231fea9cc306a11697592e6fd4794)，带调全拼是该词库的既有格式。本次只兼容编码，不引入上游数据、脚本或资源。

## Decision

共享 `client-services::dictionary::import` 在 Rime 格式且目标为拼音或快捷短语时，将拼音预组字符的声调去掉、字母转小写，`ü` 及其四声写成 `v`。拼音保留空格与单引号，交给已有 Host API 按词长和合法音节规范化；快捷短语移除这些音节分隔，得到它现有校验接受的连续字母编码。词条、权重和原文件行号不变。

转换只认可拼音字符，不过滤未知字符；数字、标点、汉字与表情仍由原有编码校验拒绝。标准 TSV、Windows TSV、五笔、英文与粤语的规则不变。编码长度与短语长度继续由原来的边界检查负责，不放宽字母表或上限。没有新增设置或修改默认值，各宿主复用共享导入入口。

## Alternatives considered

直接放宽编码字母表，改动最少，能让解析器接受带调词条；但引擎、个人词库和同步接口使用无调 ASCII 编码，词条会在下游被拒绝或无法匹配。转换放在共享导入解析器中，所有调用者得到既有存储契约接受的编码。

只修拼音导入可以保留快捷短语编码的完全原样语义；但报告者也使用快捷短语导入，带音节分隔的拼音无法成为快捷短语编码。仅在明确选了 Rime 格式时收拢空格和单引号，其他格式的严格检查不变。

## Consequences

带调 Rime 词库无需手动转写即可导入，词频和失败行定位仍然可用。代价是水杉不区分声调；去调后同音同词条沿用既有去重与导入规则。本次不支持任意 Rime schema 转写、辅助码、非默认列序或组合附加符形式的拼音，不自动下载或内置报告者附件。

验证覆盖共享解析器、集合到个人词库队列、设置请求跨 1000 行批次和真实引擎的条目校验。Windows 11 原生文件选择与报告者完整附件导入仍需单独验收，单测不替代真实宿主验证。
