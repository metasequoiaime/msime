# Agent Note: 复制设备信息后优先显示剪贴板预览

Status: implemented

## Problem

#9189 中，键盘内复制设备信息后虽然已经写入剪贴板，但成功提示占用了候选栏，用户要等提示消失才能看到「最近复制」预览。复制入口刚关闭工具面板，预览本来就是用户下一步最可能使用的反馈。

## Decision

复制成功后先让现有的最近复制逻辑读取并显示设备信息。剪贴板历史与建议开关允许预览时直接重绘键盘，不再显示会遮住预览的成功诊断提示；这些条件关闭或系统拒绝读取剪贴板时仍保留「已复制设备信息」提示。失败路径继续显示错误提示。

本决定取代[键盘设备信息复制反馈](../feature/2026-10-17-device-info-copy.md)中成功时也总是显示诊断胶囊的部分；保留该篇的菜单关闭、图标、复制用途说明与白名单。[设备信息白名单](../feature/2026-10-08-android-device-info-copy.md)与本次部分重叠，继续拥有字段和隐私边界；[功能菜单顺序](2026-10-13-android-function-menu-order.md)负责入口位置，继续保留。没有完全吸收或过时提案。

## Alternatives considered

- **继续显示成功诊断提示**：实现不变，也能告诉用户复制成功；但它隐藏了已经存在的剪贴板预览，用户必须等待提示超时。
- **增加一个新的设备信息预览控件**：可以精确控制布局；但会复制最近复制的剪贴板读取、过期和隐私规则，造成两个预览来源漂移。

## Consequences

复制成功且剪贴板预览可用时，键盘立即显示统一的剪贴板预览；关闭剪贴板历史或建议开关时仍有成功提示。设备信息字段、剪贴板隐私门控和失败反馈不变。真实 Android 设备回归需要同时确认剪贴板文本正确、预览立即出现以及编辑器内容未改变。

## Verification

设备专项 `CopyDeviceInfoDeviceSmoke` 隔离设置并分别检查预览开启与关闭：开启时一旦出现会遮挡预览的成功诊断就直接失败，不能等待提示过期后才算通过；关闭时必须显示成功提示。它仍检查合成设备信息白名单、编辑器保留「你好」并能继续输入。清单改为以产品包为目标，允许保存并恢复隔离偏好，编辑器由 shell 显式启动；没有新增 instrumentation。最终源码的原生 APK 与测试 APK 在 API 28、API 35 的专用模拟器上均通过此专项。API 35 另做同夹具的旧实现对照：仅撤回复制成功后的预览优先逻辑，断言在“成功提示遮挡预览”处失败；恢复修复后通过。该对照使用变基前的源码，最终两平台专项使用同步到 `ac7f157a85` 的源码。

API 28 的旧坐标把“宣传”误认作复制入口；夹具固定浮动键盘、文本编辑工具栏入口关闭后，按可见菜单的第二页第二行第三列点击复制。预览开启时顶部替换工具栏，返回键盘的断言检查可见字母键，不再等待此时应当隐藏的旧工具栏。测试开始前先写合成剪贴板哨兵，再输入以按产品规则收起旧预览，防止它遮住更多菜单。

完整设备冒烟仍有缺口：API 35 在前置 `DeviceSmoke` 的隐藏键盘组字检查处失败；API 28 整套运行曾在修正前的复制坐标处停止。专项通过不等于完整设备套件通过。

在远端镜像运行 `bash scripts/verify-local.sh --quick`（任务 `20261022-104627`），结果为 `quick check passed`、退出码 0：Android Java/JNI、Rust workspace、Android 与 WASM target、Linux 设置壳、Linux 原生 109 项、macOS 原生宿主和共享 Apple bridge 检查通过。HarmonyOS HAP 与 Windows MinGW 因缺少环境跳过。已核对生产 Java 和测试清单与被测源码逐字节一致；测试 Java 只修正了关于剪贴板读取 UID 的中文注释。
