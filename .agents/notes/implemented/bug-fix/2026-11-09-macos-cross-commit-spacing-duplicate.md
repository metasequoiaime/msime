# Agent Note: macOS 跨次上屏英文重复

Status: implemented

## Problem

开启 macOS 跨次上屏自动加空格后，部分 IMK 客户端在提交英文原文后仍短暂报告旧的 `marked text`。宿主随后按提交范围插入带前导空格的文本，客户端可能把这次替换当成第二次上屏，中文后输入 `mcp` 回车会出现 `mcpmcp`。

## Decision

跨次格式化继续沿用[提交后校验方案](../feature/2026-10-24-cross-commit-spacing-post-commit.md)的提交后绝对范围替换，但在替换前读取可选的 `markedRange`。只要客户端仍报告非空标记，就放弃本次可选格式化，保留已经安全落地的原文；待后续提交确认标记已清除后再按正常路径处理。读取不到 `markedRange` 的客户端保持原有行为，未知上下文仍按既有策略跳过。

回归测试模拟提交后保留标记的客户端，确认文档只保留一次英文文本，并保留原标记状态；现有可读客户端的跨次空格测试继续验证中文与英文之间的格式化。

## Alternatives considered

- 在提交前同步读取文档并把空格拼入原始 `commit`：可以避免一次替换，但会改变既有的提交时序，重新引入同步查询期间下一键越过上屏文字的竞态，因此不采用。
- 无条件关闭 ASCII 提交的跨次格式化：能绕开重复，但会丢掉跨次空格的正常能力；本次只收窄仍处于 marked 状态的异常客户端。

## Consequences

仍报告旧标记的客户端本次提交可能没有自动空格，但不会重复插入英文；实现只依赖 macOS 客户端已有的可选上下文接口，不读取或记录用户文本。正常清除标记的客户端行为不变。
