# Agent Note: 词书导入只切换选择并保留最新限额

Status: implemented

## Problem

导入先读取进度以确认文档可读，再解析词表和写入词书，最后用先前快照里的每日新词数和会话上限构造完整设置。另一个窗口在此期间保存的限额会被覆盖。合成并发复现用词书锁暂停导入，等导入已打开锁文件后把限额改成 `7/11`，放行导入后得到旧值 `20/200`。

## Decision

进度存储提供只选择词书的受锁读改写：在同一把进度锁内读取最新文档，只改 `settings.wordbook`，再原子写回。导入保留写词书前的进度预检，但预检快照不再参与最后的设置写入。学习记录、每日计数、每日限额、会话上限、默认值和宿主请求格式保持。

### 既有笔记审计

- [原子清空进度](../../implemented/bug-fix/2026-10-12-vocabulary-reset-settings-atomic.md)：部分重叠，同样要求在存储锁内保留最新设置；它处理清空，本篇处理导入后的选择，不翻转其决定。
- [删除后的选择](../../implemented/bug-fix/2026-10-12-vocabulary-remove-selection-atomic.md)：部分重叠，删除仍只在锁内清理被删除书的选择。
- [导入请求上限](../../implemented/bug-fix/2026-10-29-vocabulary-import-envelope.md)：导入大小的独立契约，保持。
- 活跃 proposed/rejected 笔记没有同一导入限额覆盖决定。

## Alternatives considered

- **写回前再读一次设置。** 改动更少，也能缩短竞态窗口；但第二次读取与写入之间仍能插入其他窗口的保存，必须把读取和修改放到存储同一把锁内。
- **不自动选择新词书。** 可以完全去掉导入后的设置写入；但会改变现有导入完成即开始复习新词书的行为，没有必要为解决限额覆盖而改变它。

## Verification

合成并发复现先在旧实现得到 `20/200`，修复后同一路径的返回值与独立重新读取均为 `7/11`，选中刚导入的新词书。等待条件是导入线程已打开被外部持有的词书锁，不用固定休眠猜测执行进度。存储回归覆盖最新限额、卡片和每日计数保留，以及无效词书 id 和损坏文档不落盘；两个新增测试先因缺少选择接口编译失败，修复后整个 `vocabulary::` 的 108 项通过，严格 Clippy 通过。其他本地门禁和 Android 实际设备结果见 PR；文件写入行为需在模拟器实际验证后合并。

## Consequences

另一窗口保存的限额不再被导入前的快照覆盖，所有宿主共用此修复。导入仍跨词书库和进度两个存储，本次不扩展崩溃恢复或导入与删除的事务边界。新选择仍按最后完成的导入生效，只保证不会用旧快照覆盖其他设置；代价是进度层增加一个只改选择的窄接口。
