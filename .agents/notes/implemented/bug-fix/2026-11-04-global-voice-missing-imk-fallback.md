# Agent Note: 全局语音缺少 IMK 客户端时回退系统按键

Status: implemented

## Problem

实装 build `58000000000003` 的真实按住录音能产生最终结果，但 Codex 在 ABC 下临时切到水杉后始终没有聚焦 IMK 控制器。生命周期日志连续两轮停在 `waiting gate=2`，三秒后到 `delivery target unavailable`。用户在同一编辑器改用既有「系统按键」策略后确认文字直接上屏，定位到会话交付而非麦克风或识别。原错误提示建议换输入框，会把缺少 IMK 客户端误说成输入框不支持。

## Decision

用户明确选择自动回退。全局语音的默认 `tsf` 路径仍优先使用 IMK；现有三秒预算结束且没有聚焦 IMK 控制器时，仅尝试一次既有 `sendinput` 通道。没有可选输入源或切源请求失败时同样处理。已有控制器但组字准备未完成或忙碌时不绕过它；用户明确选择 `sendinput`／`ctrl_v` 的路径和既有回退保持不变。

回退与显式系统按键复用同一提交实现，使用交付时的前台应用和当前会话令牌，保留简繁转换、统计、取消、手动切源优先及临时来源恢复。不写剪贴板，不恢复 AX 字段检查或 Copy 窗口，不新增偏好或翻转默认值；局部录音不改变。系统事件权限不可用时使用既有失败释放路径，错误不再要求用户换输入框。

## 旧笔记审计

[按当前输入客户端交付](../simplification/2026-11-04-global-voice-current-client-delivery.md)保留当前客户端语义及移除目的地／Copy 的决定；本篇取代其中「缺少 IMK 客户端就仅报错」的边界。[先录音后 IMK 交付](../architecture/2026-11-03-global-voice-capture-before-imk-delivery.md)保留独立录音、提供商和会话租约；本篇取代其全局默认会话失败不自动改用系统按键的妥协。其他键盘音效、皮肤和平台设置笔记中的按键或回退不属于本次范围。

## Alternatives considered

- 让用户一直选择「系统按键」：既有实现已在真实 Codex 通过，改动最少；但默认全局路径仍会在同一环境静默丢失识别结果，用户明确选择自动回退。
- 延长 IMK 等待：能覆盖单纯慢激活，但原有等待已经两次完整超时，没有证据延时能产生客户端；保留原三秒预算。
- 默认使用剪贴板粘贴：覆盖编辑器较广，但会修改剪贴板；本机已有不使用剪贴板的系统按键成功证据，不采用。

## 验证边界

隔离回归先复现没有客户端的结果被丢弃，再覆盖 IMK 成功不回退、无客户端回退一次、系统事件不可用、现有组字准备、取消、手动切源及显式提交方式。测试只使用合成文本和提交替身，不读取用户音频或识别内容。用户对既有系统按键的成功复验不代替新增自动回退分支的实装验收。

## 本地验证记录

新增缺客户端回退回归在旧实现失败，修补后通过。20 项聚焦套件首轮 19 项通过；完整 `shortcut` 套件首轮在未改动的 `InputController` 偏好读取回调释放路径触发 AppKit 的非主线程关窗断言（`MSIMEInputSessionRecoveryPanel`，与已移除的全局 Copy 面板不同），单次确认重跑通过；保留首轮日志与崩溃栈，不据此豁免任何托管失败。测试前后真实偏好文件哈希相同。

## Consequences

系统事件成功投递仍不等于编辑器确认接受；保留既有最佳努力语义，不增加重复投递、最近结果或恢复面板。真实自动回退的编辑器上屏需在完整更新后单独复验。
