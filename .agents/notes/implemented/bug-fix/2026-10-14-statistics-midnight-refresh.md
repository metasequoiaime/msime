# Agent Note: 统计页刷新时推进本地日期

Status: implemented

## Problem

共享统计页按数据签名跳过重复状态更新，跨午夜且没有新输入时不会重画「今日」指标。桌面趋势用空依赖缓存，手机趋势只依赖统计日期表，即使手动刷新触发渲染，也可能继续显示昨天的范围。

## Decision

页面通过 `use-typing-statistics-state.ts` 保存本地今天的日期状态（见[读取状态边界](../simplification/2026-10-23-typing-statistics-state.md)）。现有可见性轮询、窗口激活和手动操作刷新这个状态，同一天保留原对象；桌面和手机趋势缓存同时依赖日期键。数据签名仍只决定统计数据是否更新，日期推进单独触发渲染。

## Alternatives considered

删除趋势缓存并在每次读取后无条件保存统计，可以用最少的状态修正范围，但每五秒都要重画整页，破坏已有的重复数据抑制；保留签名并明确记录日期更容易维护。

另设午夜定时器可以恰在午夜更新，但后台定时器会被延迟，时区和系统时钟也可能改变。现有刷新入口已经处理回到前台和定期更新，复用它不需要第二套调度生命周期。

## Verification

相关 52 项测试、UI 类型检查与生产构建、lint、格式检查、笔记校验及本地 quick 门禁通过。六项固定本地时钟用例覆盖桌面和手机的跨午夜轮询、窗口激活以及新记录手动刷新。旧实现五项失败、一项通过：手机手动加载新数据原先可以刷新范围，桌面即使有新数据也保留旧日期缓存。

## Consequences

页面跨日后「今日」指标及趋势同步推进。同一天的数据签名与日期对象都不变时不重复渲染，另增加一个日期状态。可见页以现有五秒轮询推进日期；后台页在恢复可见时推进，不保证后台午夜立刻渲染。日期仍是用户本地日期。

## Related decisions

按统计刷新、摘要轮询、午夜、跨日和日期变化检索活跃笔记。[日期跨度笔记](2026-10-14-statistics-calendar-span.md)约束夏令时下的日历算术，与本次的页面刷新生命周期无关；Windows 原生统计笔记描述独立原生实现，也归为无关；当前决定只作用于共享 React 页面。共享页的摘要已有按本地日期重新请求的规则，本次沿用该刷新时机。[React useMemo 文档](https://react.dev/reference/react/useMemo)明确缓存由依赖变化失效。
