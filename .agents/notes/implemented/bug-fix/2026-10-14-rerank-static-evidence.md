# Agent Note: 独立句子排序保留词网格的静态证据

Status: implemented

## Problem

#7583 的字母位置图试验补到合法候选后，独立模型仍会选新增错误读法。词网格的自然对数分写在 `WordItem.weight`，但宿主快照只保留文本、来源、是否回答完整按键等信息，独立模型只收到逐字概率，已有频率、分词与切分先验在此丢失。不能靠排除合法的不同字数读法绕过问题。

## Decision

独立排序通过 `OrderRowSource::static_evidence` 保留词网格证据。`WordItem::static_evidence` 仅接受标记为整句联想的 `Generated` 与 `NeuralKeyboard` 行，从现有整数权重扣除规范读音的音节奖励，携带自然对数总分的整数毫 nat 与 Unicode 字数。字典词频、在线行及其他来源没有同一单位，证据为空；外部 View、JSON 和 C ABI 不增加字段。

原生 `EngineSnapshot` 携带与候选同步排列的证据，所有旋转、整句降位、在线排序和候选变换沿用同一排列。网页从相同 `WordItem` 提取证据，调用同一个 `rerank_pick`，不在宿主复制评分。

继续沿用前九条回答完整按键的比较集合、可信字典首选豁免、方案和纠错权限，不按字数排除候选。比较集合内每行证据有效时，将静态总分除以实际字数，与模型逐字概率等权混合；相同分保持原序。任一行缺分、字数为零或证据数组长度不匹配时，整次调用退回既有 `best_where`，不对部分行猜分。没有挂模型或用户关闭模型时不运行混合。

用户截图中桌面神经联想关闭，本篇分别报告纯静态路径；模型试验收益不能替代该设置下的正确行为。

## Trial evidence

基线 `bd121bd8d9` 的离线模型决策与 runtime 1,477 条逐例一致，等权逐字混合的正确首选从 857 到 989，改对 177 条、改错 45 条。原始纯静态首选也是 857，但其与模型的预测有 705 条不同，所以混合并非简单沿用其中一个。

旧字母图复装后的纯静态首选 844（改对 1、改错 14），模型首选 854（4/7），等权混合只有 962（相对基线模型 173/68）。因此再次撤回字母图，保留已有固定音节图，实现并验证静态证据传递；这不是 #7583 关闭神经选项时的整体修复。

## Alternatives considered

- 把模型直接改成总概率或只比较同字数：实现简单，但违反固定上游的完整按键比较语义，合法的不同音节数读法仍应比较，不采用。
- 再扩大路径和输出数量：覆盖容易改善，但已有试验表明会挤掉原正确候选且增加时延，先解决证据传递问题。

关闭两个句子模型的 1,477 条输出逐例完全相同，首选正确数均为 857；模型关闭时本改动没有质量收益。

质量参考文件保留原结果，因此完整 `verify-local.sh` 的精确质量基线比较会报告此次排序变化；本次采用独立二进制的逐例配对审核，不以改参考消掉改错和 top-5 下降。上述遗留单测、真实资源 golden、网页对照及键面预算缺口也没有新增失败豁免。

## Consequences

收益是独立模型不再丢弃已计算的切分、词频和分词证据，覆盖和搜索预算保持。代价是九条以内的额外评分元数据和混合计算、部分首选改错及前五覆盖下降；静态启发式分并非已校准的完整语言概率，等权不能据此推广到所有设置或未来模型。

用户截图中关闭神经联想的静态切分、词库补充、未覆盖读法仍待处理，本改动不关闭 #7583。字母图的再次配对依然没有收益，源码和新增图测试不保留。词库补充仍在独立词库 PR 中，未发布资源不作为产品已消费的内容。
