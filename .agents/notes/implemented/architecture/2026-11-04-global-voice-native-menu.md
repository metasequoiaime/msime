# Agent Note: 跨输入法语音范围使用原生输入法菜单

Status: implemented

## Problem

全局语音功能需要可达的显式启用入口，但[原生迁移规则](../../proposed/architecture/2026-11-03-all-native-ui.md)冻结了 React 新设置，旧 AppKit 设置窗口也冻结为回退。把新控件从 React 搬进回退窗口仍违反归属边界；只删除控件会让新用户无法从界面启用本功能。

## Decision

按用户 2026-11-04 选择的第二项方案，本 PR 提议一项窄范围例外：只在已有原生输入法菜单中增加「语音快捷键范围」子菜单，两个选项为「仅水杉输入法」与「任意输入法」。不扩展 React 或旧 AppKit 设置窗口，不创建新设置应用或面板。现有快捷键编辑仍走原入口，范围菜单在选择水杉输入法时可达，启用后其他输入法继续使用原有快捷键。

这项例外仍需上游维护者接受；用户选择不等于上游已经批准。PR 保持 draft，正文明确提出例外及其边界，不将原生设置迁移标为完成。

菜单读取共享 Rust 经 Host API 返回的偏好快照，默认值和持久化规则仍归 Rust。所有文件读取、CAS 与写入在进程内共用的串行工作队列执行，保存期间或尚无有效快照时禁用菜单；文件锁等待不能卡住输入法主线程。复用宿主已接受的快照预热菜单，后台刷新不清空已验证的勾选；菜单返回时就携带可用状态，不依赖 IMK 的远程副本收到后续本地修改。系统 action 先按 `kIMKCommandMenuItemName` 解包，兼容直接 AppKit 调用；跨进程菜单项仅携带目录字符串，可变状态与弱引用留在宿主内。选项只更新 `voice_input.hotkey_global`；保存冲突时重读最新快照再尝试一次，不覆盖其他语音字段或整个过期文档。异步读写回调以启动时的缓存快照为基线，文档重置后的较小修订也可刷新未变化的缓存，迟到回调不能覆盖其间已接受的新快照。保存成功、刷新确认较小修订或文档失效后推进进程级范围读取代次，宿主轮询携带开始时的代次，重置前的高修订读取也不能在新保存之后重新预热旧范围。读取失败禁用该菜单，保存失败显示提示，不以本机缓存冒充保存成功。旧原生语音窗口的导出不再拥有范围字段，避免迟到的提供商保存把菜单的新值改回去。

## Alternatives considered

- **删除 React 入口并等待原生迁移。** 最符合冻结政策，且已有配置继续生效。但新用户没有图形启用入口；用户明确选择当前可用的原生控制，而非延后入口。
- **在旧 AppKit 设置页新增下拉框。** 与原 React 布局最接近，也可复用旧窗口。但这会扩展明确冻结的回退界面，且菜单入口已足以表达二选一范围，因此不采用。
- **立即迁移完整 macOS 设置应用。** 能形成统一原生界面，但远超一项语音功能的范围，也涉及更新与安装链连续性，不并入本 PR。

## Consequences

用户从系统输入法菜单更改范围，显示为原生子菜单与勾选态，外观与 React 下拉不同。现有快捷键编辑和录音波形不变；在其他输入法中想更改范围时，需先切回水杉。范围的缺省关闭行为不变，已有已启用值保留。

聚焦回归覆盖菜单标签及状态、原生 action 到共享偏好的真实读写、并发修订重读、文档重置后的保存回显、迟到保存不覆盖新缓存、失败不改值，以及旧窗口不再回写范围；文件读写仅使用测试自建临时目录，不注册后台项、不申请权限、不录音。全平台本地检查和重新安装按既有用户要求不运行。原生菜单的可达性与视觉记录不等于真实录音、系统权限迁移或登录启动验收。
