# Agent Note: 鸿蒙独立沙箱共享只读上报授权

Status: implemented

## Problem

API 12 起设置应用和键盘各有私有偏好。普通镜像经 `savePreferences` 导入时保留接收方的授权代次，两次导入之间关闭再开启不能撤销旧捕获。基础访问模式对共享目录只读，而普通偏好读取需要创建锁文件，不能把键盘直接切到共享偏好目录。隐私政策又是独立于统计开关的前置授权，撤回政策也必须使旧上报身份失效。

## Decision

设置应用在共享沙箱的独立目录发布小型授权记录；本沙箱源偏好与政策决定仍是唯一输入。授权记录把源偏好代次与政策身份映射为一轮随机持续授权，只在两个授权均有效时开放。关闭重开、源代次改变或政策身份改变后产生新代次；暂时读取源偏好失败发布暂停状态，同源恢复复用身份，不把错误当撤回或删除队列。

发布方创建稳定锁文件，独占锁内原子替换记录；接收方以只读描述符取得非阻塞共享锁，不创建文件。采集和队列本地操作在共享读锁内核对，发送只在每条请求之前短暂读锁，联网期间释放。锁顺序固定为源偏好、共享授权、各进程私有遥测队列；任何路径不能反过来取得源偏好锁。设置保存与政策决定同步发布，活跃 App/键盘另有不依赖网络完成的观察器。拿不到共享沙箱时键盘不报告；设置应用保留本沙箱报告能力。

授权记录只留本机，不进入偏好镜像、设置同步、诊断包或事件。共享授权不改变其他功能使用的私有状态目录和默认值；App 与键盘仍各自持有队列。

## 当前实现与验证

共享存储与 Host API 已实现：接收方只读现有稳定锁文件，锁忙或源暂停保持错误；发布方把源偏好与政策身份映射为独立授权。已经观察过的偏好文件消失时暂停，首次还未同意政策的空目录不误记成“配置消失”。Android 与其他宿主的旧偏好来源保持可用。

本机九项核心回归、十二项 Host API 遥测回归及两个 crate 全 target 严格 Clippy 通过。回归覆盖真实只读目录、缺失/忙锁/损坏、符号链接拒绝、源与政策关闭重开、首次拒绝后同意、源文件损坏或消失后恢复、暂停期间政策换代、旧现场晚写、来源混用拒绝和网络阻塞期间撤回。

App 与键盘已接入共享权威记录，另有不等待网络请求的每秒观察器；App 无共享目录时在私有目录发布同一协议，键盘保持拒绝。读取错误与明确关闭分开，清理只由 Rust 条件接口执行；停止取消定时器和监听，迟到启动按 generation 与代次拒绝。键盘向 App 回写偏好时保留 App 的统计开关，普通镜像不复制授权元数据，指纹忽略本沙箱代次差异。此 ownership 避免键盘陈旧完整偏好重新打开用户刚关闭的统计，不改变其他设置的镜像能力或默认值。

完整 `platforms/harmony/tests/run.sh` 与实际适配器十一组生命周期回归通过。先 `ohpm install` 再 `hvigorw assembleHap --no-daemon`，最终真实 HAP 编译打包成功（7.326 秒）；ArkTS 子集、隐私门禁及原子文件契约通过。HAP 复用缓存原生库，只证明 ArkTS 类型和打包，设备文件锁、新 NAPI 的运行、同源原生包和真实系统回调均未验收。原进程捕获身份及精确构建归属也未由本次授权协议解决。

## Alternatives considered

- **直接把共享偏好目录交给键盘的 PreferencesStore**：现有代次协议全部可复用，但基础访问模式不能创建偏好锁，且读取可能初始化默认偏好，不适合只读授权来源。
- **导入镜像时复制源代次到本地偏好**：可保持原有私有队列，但网络发送期间仍要依赖下一次焦点导入才能看到撤回，也改变普通设置导入不得伪造授权身份的约束。
- **在 ArkTS 中检查一个布尔文件**：不需要新增 Rust 存储，但 Rust 批量发送必须逐条核对，单次 ArkTS 门禁无法覆盖请求之间的撤回和关闭再开启。

## Consequences

收益是两个沙箱共享同一轮持续授权，关闭重开不能被镜像延迟隐藏；Rust 在每条发送前核对，网络不阻塞撤回。代价是每秒读取小型本机文件和文件锁，无法取得共享目录时键盘保守不上报；App 导入键盘偏好时统计开关明确由 App 拥有。

存储介质拒绝写入时无法承诺另一沙箱立即得知撤回；发布失败记录固定错误并停止本进程使用旧许可，不能把失败误当明确关闭清队列。共享文件读写仍需 Android API 28/35 的真实应用 UID 验证，鸿蒙还需同源原生包、真机共享沙箱和系统回调验收。系统延迟诊断仍须结合原进程捕获身份，不能仅凭当前代次与报告时间证明原构建。
