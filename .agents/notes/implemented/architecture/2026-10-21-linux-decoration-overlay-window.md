# Agent Note: X11 装饰候选词进入原生候选窗口

Status: implemented

## Problem

Linux 以前只把 `canvas` 包交给原生窗口，传统装饰图由 `classicui` 的静态主题绘制。`candidate_overlay_*` 需要在高亮和分页时更新图内文字，静态主题没有按候选绘制文字的入口。

## Decision

在已有真实 X11 输入上下文、焦点、`classicui` 所有权围栏内，为成功解码装饰图且具有有效装饰词声明的包绘制图内文字。窗口是否接管由[默认原生候选窗](2026-10-21-linux-x11-native-candidate-default.md)统一决定：非 canvas 包继续使用其 chrome 结构，不因为打开图内文字切回旧 canvas 排版。关闭声明或坏图只撤下文字，候选窗口保留现有回退；不扩大 Wayland、IBus、GNOME Shell 或第三方 UI 的所有权。

共享扫描器继续拥有 TOML、颜色、尺寸和路径规则。原生层复核规范化的 JSON 类型与范围，复用共享 `DecorationCandidate` 的取词、缩字与对齐计算，并用 Pango 实测完整单行。图按声明框 contain 且受面板宽度约束；文字仍以声明框同侧、底边定位，最小字号后不裁字。字形 ink 外伸与逻辑矩形共同扩展窗口，随后由既有工作区与 8192 像素预算决定能否显示，不能沿用自由挂件的 500 DIP 留白夹限裁掉长词。

MCP 输出 schema、制皮 prompt 和创建工具的说明同步描述 Linux X11 的有限原生入口，移除「Linux 都没有画布」「只有 macOS 播放装饰动画」的过时判断。资源声明、帧播放能力、待机变换和设备验收分别说明，不能让 AI 代理把可读取的元数据当成完整设备支持。

普通候选在既有简繁转换时保留独立原文与来源标注，不从混有纠错、注释和训音的普通显示行拆词。占位行和非引擎菜单项没有装饰词；序号只数当前页真实候选，索引 0 严格使用当前高亮。图片和文字不加入 ShapeInput，不增加候选身份或选择回调。装饰图复用既有有界动画解码、资源戳、单调时钟和隐藏停播生命周期，菜单不画装饰图或文字。无显式配色的 `system` 包从既有 Linux 明暗原生 token 补齐颜色，不丢弃皮肤身份；辅助行缺省跟随原生次要文字色，避免深色背景上继续使用浅色模式的深灰字。

资源缓存只记录加载前的输入戳。真实 GTK 坏图验收发现，切暗色加载期间替换图片时，原先收尾再取戳会把新坏图记成已加载，之后每拍都跳过，旧窗口永久残留。现在在解码前收集完整资源依赖，每个路径与清单只记录本次调用首次读到的戳，下一拍能够识别加载期间的变化并清理。新增依赖也进入同一份快照，保持首次加载后不重复刷新的既有约束。简单保留最初输入虽能避免漏更新，但首次发现资源时会额外刷新一次，既有门禁拒绝，因此没有采用。

宿主目录在包含有效装饰词包时也发布绝对 UTF-8 根目录，供非 canvas 的 `system` 包通过完整包 API 读取装饰词声明；普通静态包仍不新增目录。配色目录保持严格的 snake_case 宿主条目，不能直接塞入 camelCase 的 UI 包。GTK 合成夹具从完整包转换装饰图尺寸、路径和对齐，确保验收包含真实装饰带，而不是因缺少元数据退回普通面板。坏图要求撤下装饰带与文字并缩回默认原生卡片，关闭声明只撤文字；两者都保留未上屏和正常深色背景的检查，不再沿用默认原生窗接入前的「必须没有原生窗口」断言。

## 与默认原生候选窗整合

canvas 继续使用声明框的 Windows 版式，非 canvas 使用 chrome 顶带。两条路径复用规范声明、Pango 选词与缩字；主题明确声明的槽位与 canvas 缺省补色分开，chrome 先铺系统色后只覆盖显式槽位，避免回退色覆盖 Adwaita 的选中背景；chrome 的声明尺寸、字号、最大宽度与偏移随候选缩放，文字跟随图片的同一待机变换。完整单行和字形外伸扩大窗口时，绘制与所有命中矩形一起平移，避免点击落到旧位置。

展开网格保留普通当前页的独立装饰快照与高亮，不能把可见网格行或网格游标误当成页内索引。资源戳仍在解码前收集，保留新默认窗口的样式、logo 和背景戳。MCP 的本地 64 图与社区 37 图、图片工具栏协议与装饰词说明同时保留；共享设置页同时绘制 canvas 挂件及装饰词组。

## Alternatives considered

逐次高亮把文字烘焙进 PNG 最容易沿用 `classicui`，但会在逐键路径产生图片编码、文件写入和主题重载，也无法可靠维持动画与生命周期，因此使用已有内存窗口。

让所有传统图片包进入原生窗口能统一入口，但会扩大第三方主题、发行版和普通静态皮肤的行为变化；原方案只接管动态装饰词包。此后默认入口由[默认原生候选窗](2026-10-21-linux-x11-native-candidate-default.md)独立接管，本篇只增加图内文字，不再另设入口。

## Verification

整合新增 chrome 真实像素、完整文字外伸后命中平移、普通页与网格快照隔离、无高亮与坏图清理回归。两组 Cairo/Pango 测试翻译单元的严格 C++20 语法检查已通过；Linux 容器中完整 `candidate_native_canvas.cpp` 用例已运行通过，包含新增 chrome 装饰像素、边界和快照回归。该专项复用已有 Host API 静态库的图片解码，未代替当前分支完整原生构建、GTK 专项、quick 和 Android 设备验收。macOS 的 Pango 在既有 CJK 字体像素断言失败，不计入全套通过。

新增 Cairo/Pango 用例覆盖类型、真实高亮、页内序号、占位过滤、独立标注、九种对齐像素、最小字号的长词和字形外伸、菜单与图片失效清理。新增独立 Xvfb、D-Bus、GTK 编辑器的横竖排与 1／2 倍缩放验收入口，检查无配色 system 包、高亮、分页、对齐、明暗、坏图、关闭声明和候选上屏。原生构建与专项通过；四种组合各连续运行三次（合计十二次）通过，资源加载与替换交错不再残留旧窗口。截图复核发现全屏深色像素计数会误中浅色文字，已改成只检查原生面板底部空白内边距；严格深色像素、辅助行次要色修复后的最终四组合与 Cairo/Pango 专项五项全部通过，已下载并实际查看浅色横排及深色二倍竖排截图。既有画布回归选择十八项，十六个可执行用例逐项通过（其中 GIF 初轮因下述焦点握手失败，修正后专项通过）；两个 Wayland 用例因容器前置条件跳过，不计通过。另修正验收的焦点握手：保存等待成功时的同一份 D-Bus 上下文快照，避免第二次查询恰逢连接切换而抛出 `StopIteration`；焦点和上下文身份断言保持。

完整解码前快照方案的最终复测中，`fcitx5-candidate-theme-canvas`、四种真实 GTK 装饰词组合与 Cairo/Pango 共六项全部通过；既有 GTK／原生画布专项再运行十七项，十五项可执行用例全部通过，两项 Wayland 因前置条件跳过。此次结果同时保留了不变资源不重写主题的断言和加载期间坏图替换后的清理验收。最终 `verify-local.sh --quick` 通过，包含 Linux 原生九十四项门禁、Linux 设置壳及其他已配置平台的编译。

同步修正 MCP 说明后，`msime-mcp-server` 的九十四项单测、十二项 stdio 集成测试、`cargo fmt --all --check` 和 `cargo clippy --locked -p msime-mcp-server --all-targets -- -D warnings` 均通过；既有说明契约测试现在要求明确真实 X11、焦点、classicui 所有权及 Wayland／IBus／第三方 UI 回退。

## Consequences

X11 可以显示传统装饰图内的当前页候选词；其余 Linux 桌面入口仍只消费可表达的静态子集。新增资源类型时，必须同时补齐解码前的依赖收集，避免缓存重新漏掉加载期间的替换；同一资源不重复刷新由既有 `fcitx5-candidate-theme-canvas` 门禁约束。本篇不代表 Wayland 动态图内文字、完整 Windows 材质或六平台全部兼容已经完成。来源固定为 `msime-windows@0978b5c28b2a1806e7ef3acdbc3a1c87e4784823`，GPL 来源与重写范围记在第三方清单。
