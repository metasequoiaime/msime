# Agent Note: 全局语音先录音、后取得 IMK 提交目标

Status: implemented

## Problem

真实 Right Option 手势已被接受，输入源也已选到水杉，但 `MSIMEFocusedController` 持续为空，录音从未开始。辅助功能权限、当前安装路径和 Launch Services 注册均已核对。这证明「系统接受切源」不保证得到 IMK 客户端，尚不能确定系统内部为何遗漏激活。继续延长等待不能让麦克风启动获得独立保证。

## Decision

全局会话直接使用既有 `VoiceInputService` 和各识别提供商，不依赖 IMK 控制器，也不在按住修饰键期间切源。物理松手、识别完成后才取得 IMK 客户端并提交。保留原有 `tsf`、`sendinput`、`ctrl_v` 选择；不自动改成剪贴板。提交继续绑定原进程、辅助功能元素和会话令牌，目标改变或有界等待失败时只提供显式复制。仅恢复本轮临时选择的输入源，用户手动切源优先。

## 旧笔记审计

[跨输入法语音快捷键](../../implemented/feature/2026-11-02-macos-global-voice.md)部分重叠：其按键、权限、提供商和目标安全边界继续成立；本篇取代「先等 IMK 激活再录音」这一决定，保留原篇及其理由。其他输入源恢复笔记不涉及独立录音会话，不吸收。

## Alternatives considered

- 继续等待 IMK 可最大限度复用原控制器；但真实尝试已经在源到达后持续缺少客户，失败点先于音频，增加固定延迟没有完成条件。
- 通过辅助功能直接写文本能省去切源，但真实 Codex 文本框不允许设置 `AXValue` 或 `AXSelectedText`，不能覆盖本次使用环境。
- 默认改为模拟粘贴容易覆盖更多编辑器，但会改变用户提交策略及剪贴板内容；只保留用户已明确选择的策略。

## 验证边界

独立会话覆盖本地模型、豆包、HTTPS、系统语音与外部 socket 通道；首帧之前不宣称开始录音；松手之前不切源；迟到权限和旧回调不补开麦克风；失焦、取消和手动切源不会误提交或抢回输入源。各提供商共用 `MSIMEVoiceQuery` 的偏好映射。原有简繁输出、显式提交策略和打字统计的授权边界继续生效。聚焦原生回归使用合成音频、文本、权限和提交目标，前后核对已安装偏好文件的哈希，不把这些回归称为真实麦克风或 IMK 验收。

## Consequences

独立会话增加提供商生命周期编排，取消、早到最终结果、链式权限授权、超时和结果交接有专门回归。音频与模型仍复用既有实现。输入法激活失败不再阻止开麦克风，但默认 IMK 交付仍可能在特定编辑器失败；三秒上限后提供显式复制，不改变用户的提交方式。真实 Right Option、实际说话和编辑器最终上屏仍需在安装后分别验收，不能由合成测试代替；不运行用户明确跳过的全平台本地检查，不创建新的构建树。
