# Agent Note: Android 键面由模板与键组排版

Status: implemented

## Problem

Android 键盘上每个键印的内容（主标签、右上角角标、底部双拼提示、九键数字、空格上的方案名和麦克风）分散在 `KeyHintButton`、`NineKeyDigitButton`、`TextEditHintButton`、`KeyboardIconKey`、`SpaceKeyFace` 等类里，各有一套字号、偏移和避让规则；主标签靠 TextView 的内边距和自动字号给提示让位。结果是：

- 同一种角色各处不一致：右上角提示离右边 5 dp 或 12 dp，有的随紧凑键高缩放、有的不缩放，透明度 255 或 204；主标签与角标相碰时的避让规则有四种。
- 同一排的键各算各的字号：只有 26 个字母在 `KeyHintWidthPolicy` 里统一过上界，其余键各自自动缩放。
- 提示一变就重新布局：角标参与主标签排版，换角标要改内边距和字号。18 键小鹤双拼开着网格辅助码时，分词键的「辅」随组字出现、消失，每次开始组字和上屏都重新测量整排（[14/18 键尺寸与卡顿](../bug-fix/2026-11-17-android-grid-key-metrics.md)之后仍有，API 35 模拟器上这两下的测量与布局约 20–26 ms，26 键 1–3 ms）。
- 加新的提示位置就要再写一个类。

## Decision

键面由**模板**描述、由**键组**统一排版、由键自己绘制。父视图给每个键的尺寸（键格）不变，键面不参与布局。

### 位置、模板与键组

- **位置**（`KeyFaceSlot`）：`MAIN` 主标签、`TOP_RIGHT` 右上角、`BOTTOM` 底部。空着的位置没有开销。
- **模板**（`KeyFaceTemplate`，取值在 `KeyFaceTemplates`）：一类键用哪些位置；每个位置的首选字号按键格高度的比例（设计字号所在的键高是默认的 52 dp，不是设计稿里的 46 dp：按 46 dp 算时默认键盘上的字整体大了约一成）、上下限（sp）、离键边的距离（按自身字号的倍数）、不透明度；主标签离两侧的边距、与提示墨迹的最小间距；两个字母的键面两字之间的间距；主标签按大写字母高还是按整个墨迹竖直居中；居中放不下时依次尝试的退让方式（保持居中、左移、上下分区、缩小主标签，顺序由模板定，缩小有上限），都不行就不画右上角提示。
- **键组**（`KeyFaceGroup`）：一组看起来应当一致的键共用一个模板和**内容域**（`KeyFaceDomain`）。内容域是按当前设置**可能**出现的全部文字，不只是此刻画着的。键组按组里最小的键格算一份参数（`KeyFaceParams`），每个位置按带这个位置的最小键格算，组里每个键用同一份：字号、基线、偏移和退让方式全组相同。
- **计算**（`KeyFaceSolver`）：纯函数。首选字号随键高变化，和上下限一样跟随键盘的字体缩放（封顶 1.15 倍），收到放得下：最宽的文字不超过键宽减边距，墨迹高度不超过主标签区。底部提示在下方占一条；主标签小于最小字号时先放弃底部提示。右上角提示与主标签按墨迹框判断碰不碰，不按字体行高。

### 键与键组的契约

- 建键行时 `ImeKeyFaces` 清空上一副键盘的组；字母键建出来时放进对应的组（`KeyboardPressButton.setFaceGroup`），声明可能用到的提示位置。`ImeKeyFaces` 只读服务里的设置、把键放进组；哪些文字可能出现在字母键上由 `LetterKeyFaceDomains` 按传进来的设置列出，不读服务。
- 键在 `onSizeChanged`、`onVisibilityAggregated`、`onAttachedToWindow`/`onDetachedFromWindow` 时把键格报给组；隐藏、离开窗口的键报 0，不算进最小键格。组的结果变了就通知组里每个键重画（`KeyFaceGroup.Member#faceParamsChanged`）。键面不影响尺寸，所以只会引起重画，不会引起重新布局。
- 键换上内容域里没有的文字时（双拼提示随方案画上、键面随大小写换），由键补进内容域（`KeyFaceGroup.include`），组重量一次。皮肤字体、字体缩放、角标开关或引号样式变了，`ImeKeyFaces.refresh` 在下一次渲染时换掉内容域（`KeyFaceGroup.replace`），组里每个键此刻的文字并进新的内容域，不重建键行。
- 内容域在第一次需要时按基准字号量一遍，之后键格变了只做按比例的换算；同样的最小键格直接查表。

### 绘制

- 放进键组的键由 `KeyFaceRenderer` 画：`onMeasure` 直接用父视图给的精确尺寸，不按文字量；`onDraw` 只画，不量字、不分配对象，位置在参数、文字或尺寸变了之后才重新算。
- 主标签按排版宽度水平居中。竖直方向：字母键的模板按基线以上的墨迹（大写字母高）居中，Q、分号这类基线以下的尾巴往下挂，全组共用一条基线，算字号时上下都为尾巴留出位置；按整个内容域墨迹居中会让没有尾巴的字母整体偏高（14 键 `OP` 在 API 28 上偏上 4 px，超出居中检查的容差）。两个字母的键面分开画，中间按模板的间距。右上角提示按文字框定位，与原来的角标同一个位置：排版宽度的右端离右边、字体上行线（ascent）离上边各按模板的距离（字母键 10 sp 时 5 dp、3 dp）；底部提示水平居中。
- 键仍是 `Button`：`setText` 的文字照旧是节点文字（读屏、按键统计、按键气泡），只是不再由 TextView 排版和绘制。颜色照旧来自皮肤（主标签用文字色，角标用 `hint()`，双拼提示用 `accent()`），主标签用皮肤的字体（等宽皮肤为等宽字体），提示用系统默认字体，不加皮肤字段。
- 键面按键格坐标画（`KeyboardPressButton.beginFaceDraw` 抵消 TextView 的滚动）。键组里的键不走 TextView 的测量，TextView 留着的文字排版可能还是按旧宽度排的，它在每次绘制前（`onPreDraw`）仍按那份排版把内容滚开，画布随之平移：九键右列的「重输」在模拟器上因此偏右约 26 px。
- 键组里的键换节点文字不重新布局（`KeyboardPressButton.setText` 期间的 `requestLayout` 换成重画），放进键组时关掉 TextView 的自动字号。TextView 在绘制前会补建自己的排版，之后每次 `setText` 都按它重排、跑一遍自动字号，文字高度一变就请求整个键盘重新布局；键面不按文字量尺寸，这些都是白做。
- 没放进键组的键照原来的方式排版和绘制。
- **按自己的墨迹居中**（`KeyFaceTemplate.Glyphs`，全组共用基线的例外；`every` 为假时只有登记的文字这样画，其余的照常共用基线，框对称于它们的墨迹中线，位置不变）：符号栏这类键的文字墨迹位置各不相同，全角「，」「。」只占字身左下角一小块，和 ？、…… 共用一条基线时会贴底、显得很小。模板可以要求每个键把自己的墨迹中点放在主标签区中点上，并为墨迹很小的标点登记放大倍数（「，」「。」「、」1.3 倍，原来由 `CenteredGlyphSpan` 做）。字号仍是全组一个：内容域按每段放大后的墨迹量出一个以基线为中线的框（最宽的墨迹宽、最高的墨迹高），求解器照常用它判断放不放得下、碰不碰提示，每个键居中后的墨迹都落在这个框里。只用于标点和声调这类键；字母和汉字仍共用一条基线。

### 键帽轮廓

- 皮肤的键形（圆角、胶囊、卵石、票根）只占键格的一部分：胶囊两头是半径为键高一半的半圆（比键高窄时按 Skia 的规则缩成键宽的一半，成了上下两头圆的跑道形），卵石的右上角按键宽和键高的比例收进去，票根两侧中间有缺口，凸起材质的键帽面比键格矮 3 dp。按矩形键格摆的角标在胶囊和卵石上会压到轮廓外。
- `KeyOutline` 是键帽轮廓的唯一描述：键形按路径操作给出（`trace`），`KeyboardSkinKeyDrawable` 把它接到 `Path` 画键帽，键面把同一串操作展平成多边形，按像素行算出能落墨的左右范围（`KeyOutline.Spans`，扣掉边框加 1 dp 的边距，按键格尺寸缓存）。一副键盘一个轮廓，放在 `KeyFaceEnvironment` 里；皮肤换了，`ImeKeyFaces.refresh` 换掉组的环境。
- 主标签的宽度扣掉轮廓在它那几行收进来的部分；按退让方式摆好以后实际占的行还出轮廓就再缩小。右上角提示在轮廓收进去的地方沿对角线（向左下各挪同样多）挪进键帽：组里按带它的最小和最大键格里挪得多的那个判断与主标签碰不碰（卵石的大键收得多），每个键画的时候按自己的尺寸算（提示离轮廓的距离各键一致，提示字号全组一致）；哪里都放不下就不画，与放不下时隐藏提示的退让一致。底部提示离开凸起键帽的厚度，整条（最宽的文字）要落在键帽里：窄而高的胶囊下端是个半圆，先往上挪（最多键高的四分之一），还不行再缩小，主标签按挪过的位置让出底部那一条。
- 回车还没放进键组，自己画的「换行」角标用同一个轮廓挪进键帽（`ImeStyler` 配键帽时把轮廓给 `KeyboardIconKey`）。

### 现在放进键组的键

- 26 键（及同一套字母行的其他语言）字母层的字母键和微软双拼的 `;`：模板 `LETTERS`，位置主标签、右上角、底部。碰上角标时先保持居中、最多缩小 15%，再左移，最后才排到角标下方：全组只能用同一种退让，按组里最窄的键定，单字母窄键左移不开；排到角标下方让一排字母整体下沉（字体放大 1.3 倍时在 API 28 截图上很明显），所以放在最后。
- 14/18 键的字母键：模板 `GRID_LETTERS`，两个字母的键面中间隔 0.15 个字号，位置主标签、右上角。
- 键区里的功能键：26 键一族的 ⇧、⌫，14/18 键第三排的分词键（符／分词，右上角「辅」）和 ⌫，九键、笔画、注音九键右列的 ⌫ 和重输。模板 `FUNCTIONS`，位置主标签、右上角，内容域由 `FunctionKeyFaceDomains` 列出。主标签是图标或一两个字：汉字按整个墨迹居中，和同一排按大写字母高居中的字母落在同一条中线上；文字设计 15 sp，另外不大过同一副键盘的字母组（`KeyFaceGroup.capMainAt`：字母组的参数变了功能键组跟着重算，除此之外两组各按自己的键格算）；图标（`KeyFaceTemplate.IconSpec`）设计 22 dp，随键高变化、夹在 16–26 dp 之间，不跟字体缩放，不超过键格短边。画图标时主标签位置是空的，`⇧`、`⌫` 这样的节点文字不进内容域。⇧、⌫ 是常驻的键，会挪到 123 层和底行：`ImeKeyFaces` 每次建键行先把功能键拿出组，放回键区时再放进新组。

- 26 键一族的其他文字：韩文字母一组（`KOREAN`，与字母同字号，内容域含两套辅音元音，按双辅音只重画）；大千一组（`DACHEN`，注音符号共用基线，声调键按自己的墨迹居中、放大 1.8 倍，见 `Glyphs` 的「只登记的文字」用法）；日文罗马字的 ー 自己一组、以字母组为上限（全角的 ー 放进字母组会让窄键上的每个字母都按它缩小）；微软双拼的 `;` 在字母组；注音的 #+= 共享符号行在 #+= 层其余几排的组。
- #+= 层的字符键：第一排（模板 `LAYER_TOP_ROW`，设计 20 sp）和其余几排含第五排补充行（`LAYER_CHARACTERS`，设计 18 sp）各一组，只有主标签，全排共用一条基线（按内容域的整个墨迹居中，下划线、引号仍在各自的高度上）。内容域由建这一层时放进来的键自己的文字组成，这一层的表变了（中英文标点、长空格、底行顺序）整层重建、组跟着换掉。这一层自带底行的功能键（123、返回、符号、中英文标点、表情、逗号）放进功能键组。
- 九键、笔画和数字九宫格左侧的符号栏：模板 `SIDE_SYMBOLS`，按每个符号自己的墨迹居中（见上），内容域是建栏时的表（`SideColumnKeyFaceDomains`，表改了整栏重建）。设计 18 sp 所在的格高是三行键高分成五格，格子变矮时按比例缩小（最小 12 sp），更高时不超过 18 sp，与原来的固定字号一致。大回车外框接在末尾的 ！ 右上角的 0 是这一组的右上角提示。数字九宫格左列的 #+=、#+= 符号层和日语九键的 ⌫ 放进功能键组；功能键文字最小 9 sp，与底行功能键相同。拼音九键侧栏的拼音列不放进键组：它是一列候选，每一项各自缩小放进窄栏（#5591），全组一个字号会让每项都按最长的拼音缩小。
- 数字行（26 键一族和 14/18 键字母上方的 1–0）：模板 `NUMBER_ROW`，设计 20 sp，没有提示，按大写字母高居中；自己一个组，与字母键互不影响。
- 九键：拼音九键字母层的九格和右列的 ！（模板 `NINE_LETTERS`，字母组设计 18 sp，右上角是长按输入的数字），数字九宫格的 1–9、右列小数点和 ！、九键双拼的数字键（模板 `NINE_DIGITS`，设计 22 sp，九键双拼底部是表里的简短声韵提示），以及数字九宫格和九键双拼底行的 0。内容域由 `NineKeyFaceDomains` 列出。右上角的数字与字母键角标同字号、文字框离上边一样远，离右边按 1.2 个字号（10 sp 时 12 dp），与原来的九键数字同一个位置（模板的提示位置可以单独设离右边的距离，`SlotSpec.insetXEm`）。九键的键用 `sans-serif-medium`（等宽皮肤用等宽字体），与样式通道一致。底行的 0 是常驻的键：建键行时拿出组，渲染底行时放回当前的组，已经在组里时什么也不做。功能键组以九键字母组为上限。

其余带提示的键（句号、常用标点、拼音列、底行的其他键、笔画与注音九键、文本编辑面板的角标键）仍走原来的内边距与字号规则，见[角标不能挤掉主字母区域](../bug-fix/2026-11-17-android-key-hint-main-label-width.md)。右侧大回车外框里的回车经底行的 `placeKey` 放置，与底行回车同一个键、同一套文字，随底行一起迁入。

## Alternatives considered

- **保留 TextView 排版，只把内边距和字号改由键组算出后再设回 TextView** — 改动最小，`getTextSize()` 等现有检查不用动；但主标签仍由 TextView 排版，提示变了还是要改内边距、引起重新布局，两套排版规则（TextView 的行高与我们的墨迹框）对不齐，正是现在偏位和卡顿的来源，所以放弃。
- **把键改成不继承 TextView 的 `View`，自建读屏节点** — 最干净；但工厂、字段和键位标识里有大约 450 处按 `Button` 引用键，设备验收按「按键 …」描述和节点文字找键，一次改动面太大。保留 `Button` 作为外壳，绘制由我们接管。
- **Jetpack Compose 画键盘** — 能声明式地描述键面；但输入法进程的打字热路径要加载一套新的运行时，安装包变大，设备验收和读屏节点都建立在 View 上，不合适。
- **逐键各自适配（现状）** — 每个键按自己的文字和宽度收字号；同一排的键字号各不相同，提示一变就要重排，放弃。
- **每种键形一套模板** — 让胶囊、卵石的模板把角标放得更靠里；但收进去多少取决于键的尺寸（胶囊按键高或键宽的一半，卵石按键宽和键高的比例，圆角按皮肤的半径），固定的距离在宽键或窄键上不是多就是少，模板也要按键形成倍增加。轮廓作为与键格尺寸、字体缩放并列的输入，模板仍只按键的种类分。
- **轮廓按键形写解析公式** — 精确、算得快；但那是键帽形状的第二份写法，与画键帽的路径会各改各的（`packages/ui` 的 `keyboardKeyPath` 与 Android 的胶囊、圆角已经不一致）。改用同一串路径操作，新键形只加路径。

- **符号栏的标点保留 `CenteredGlyphSpan`，或全栏共用一条基线** — 前者让符号栏留在键组外，字号不随格高变、与同一副键盘的其他键各算各的；后者让「，」「。」贴在格子底部。按每个键自己的墨迹居中只放开居中方式，字号仍全组一个。

## Consequences

- **收益**：同一组的键字号、基线和退让方式一致；换提示只重画，不再重新布局；新增提示位置只是模板里多一个位置。排版规则是纯函数，JVM 冒烟用固定数值的假字体就能检查，不依赖设备字体。
- **代价与已知上限**：字号和位置按新规则重新算，不追求与之前逐像素一致，外观有可见变化；屏幕很窄时（如 320 dp）九键字母组按最宽的 WXYZ 放进键内、不碰数字，比原来小约两成。胶囊、卵石键帽上角标挪进了键帽，圆形小键（窄屏上的回车、九键 123）放不下时不画角标。内容域只增不减：一组键用过的文字在重建键行之前一直保留位置（关掉双拼提示后，底部那一条要到下次重建键行才收回）。两套键面代码在迁移期间并存，其余键迁入键组后删除旧的内边距与自动字号逻辑。
