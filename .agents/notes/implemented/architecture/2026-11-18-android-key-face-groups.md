# Agent Note: Android 键面由模板与键组排版

Status: implemented

## Problem

Android 键盘上每个键印的内容（主标签、右上角角标、底部双拼提示、九键数字、空格上的方案名和麦克风）分散在 `KeyHintButton`、`NineKeyDigitButton`、`TextEditHintButton`、`KeyboardIconKey`、`SpaceKeyFace` 等类里，各有一套字号、偏移和避让规则；主标签靠 TextView 的内边距和自动字号给提示让位。结果是：

- 同一种角色各处不一致：右上角提示离右边 5 dp 或 12 dp，有的随紧凑键高缩放、有的不缩放，透明度 255 或 204；主标签与角标相碰时的避让规则有四种。
- 同一排的键各算各的字号：只有 26 个字母在 `KeyHintWidthPolicy` 里统一过上界，其余键各自自动缩放。
- 提示一变就重新布局：角标参与主标签排版，换角标要改内边距和字号。18 键小鹤双拼开着网格辅助码时，分词键的「辅」随组字出现、消失，每次开始组字和上屏都重新测量整排（[14/18 键尺寸与卡顿](../bug-fix/2026-11-17-android-grid-key-metrics.md)之后仍有，API 35 模拟器上这两下的测量与布局约 20–26 ms，26 键 1–3 ms）。
- 加新的提示位置就要再写一个类。

## Decision

键面由**模板**描述、由**键组**统一排版、由键自己绘制。父视图给每个键的尺寸（键格）不变，键面不参与布局。

### 位置、模板与键组

- **位置**（`KeyFaceSlot`）：`MAIN` 主标签、`TOP_RIGHT` 右上角、`BOTTOM` 底部。空着的位置没有开销。
- **模板**（`KeyFaceTemplate`，取值在 `KeyFaceTemplates`）：一类键用哪些位置；每个位置的首选字号按键格高度的比例（设计字号所在的键高是默认的 52 dp，不是设计稿里的 46 dp：按 46 dp 算时默认键盘上的字整体大了约一成）、上下限（sp）、离键边的距离（按自身字号的倍数）、不透明度；主标签离两侧的边距、与提示墨迹的最小间距；两个字母的键面两字之间的间距；主标签按大写字母高还是按整个墨迹竖直居中；居中放不下时依次尝试的退让方式（保持居中、左移、上下分区、缩小主标签，顺序由模板定，缩小有上限），都不行就不画右上角提示。
- **键组**（`KeyFaceGroup`）：一组看起来应当一致的键共用一个模板和**内容域**（`KeyFaceDomain`）。内容域是按当前设置**可能**出现的全部文字，不只是此刻画着的。键组按组里最小的键格算一份参数（`KeyFaceParams`），每个位置按带这个位置的最小键格算，组里每个键用同一份：字号、基线、偏移和退让方式全组相同。
- **计算**（`KeyFaceSolver`）：纯函数。首选字号随键高变化，和上下限一样跟随键盘的字体缩放（封顶 1.15 倍），收到放得下：最宽的文字不超过键宽减边距，墨迹高度不超过主标签区。底部提示在下方占一条；主标签小于最小字号时先放弃底部提示。右上角提示与主标签按墨迹框判断碰不碰，不按字体行高。

### 键与键组的契约

- 建键行时 `ImeKeyFaces` 清空上一副键盘的组；字母键建出来时放进对应的组（`KeyboardPressButton.setFaceGroup`），声明可能用到的提示位置。`ImeKeyFaces` 只读服务里的设置、把键放进组；哪些文字可能出现在字母键上由 `LetterKeyFaceDomains` 按传进来的设置列出，不读服务。
- 键在 `onSizeChanged`、`onVisibilityAggregated`、`onAttachedToWindow`/`onDetachedFromWindow` 时把键格报给组；隐藏、离开窗口的键报 0，不算进最小键格。组的结果变了就通知组里每个键重画（`KeyFaceGroup.Member#faceParamsChanged`）。键面不影响尺寸，所以只会引起重画，不会引起重新布局。
- 键换上内容域里没有的文字时（双拼提示随方案画上、键面随大小写换），由键补进内容域（`KeyFaceGroup.include`），组重量一次。皮肤字体、字体缩放、角标开关或引号样式变了，`ImeKeyFaces.refresh` 在下一次渲染时换掉内容域（`KeyFaceGroup.replace`），组里每个键此刻的文字并进新的内容域，不重建键行。
- 内容域在第一次需要时按基准字号量一遍，之后键格变了只做按比例的换算；同样的最小键格直接查表。

### 绘制

- 放进键组的键由 `KeyFaceRenderer` 画：`onMeasure` 直接用父视图给的精确尺寸，不按文字量；`onDraw` 只画，不量字、不分配对象，位置在参数、文字或尺寸变了之后才重新算。
- 主标签按排版宽度水平居中。竖直方向：字母键的模板按基线以上的墨迹（大写字母高）居中，Q、分号这类基线以下的尾巴往下挂，全组共用一条基线，算字号时上下都为尾巴留出位置；按整个内容域墨迹居中会让没有尾巴的字母整体偏高（14 键 `OP` 在 API 28 上偏上 4 px，超出居中检查的容差）。两个字母的键面分开画，中间按模板的间距。右上角提示按自己的墨迹右沿贴边、按内容域墨迹的上沿对齐；底部提示水平居中。
- 键仍是 `Button`：`setText` 的文字照旧是节点文字（读屏、按键统计、按键气泡），只是不再由 TextView 排版和绘制。颜色照旧来自皮肤（主标签用文字色，角标用 `hint()`，双拼提示用 `accent()`），主标签用皮肤的字体（等宽皮肤为等宽字体），提示用系统默认字体，不加皮肤字段。
- 没放进键组的键照原来的方式排版和绘制。

### 现在放进键组的键

- 26 键（及同一套字母行的其他语言）字母层的字母键和微软双拼的 `;`：模板 `LETTERS`，位置主标签、右上角、底部。碰上角标时先保持居中、最多缩小 15%，再左移，最后才排到角标下方：全组只能用同一种退让，按组里最窄的键定，单字母窄键左移不开；排到角标下方让一排字母整体下沉（字体放大 1.3 倍时在 API 28 截图上很明显），所以放在最后。
- 14/18 键的字母键：模板 `GRID_LETTERS`，两个字母的键面中间隔 0.15 个字号，位置主标签、右上角。

其余带提示的键（14/18 键分词键、句号、常用标点、九键数字键、文本编辑面板的角标键）仍走 `KeyHintButton` 原来的内边距与字号规则，见[角标不能挤掉主字母区域](../bug-fix/2026-11-17-android-key-hint-main-label-width.md)。

## Alternatives considered

- **保留 TextView 排版，只把内边距和字号改由键组算出后再设回 TextView** — 改动最小，`getTextSize()` 等现有检查不用动；但主标签仍由 TextView 排版，提示变了还是要改内边距、引起重新布局，两套排版规则（TextView 的行高与我们的墨迹框）对不齐，正是现在偏位和卡顿的来源，所以放弃。
- **把键改成不继承 TextView 的 `View`，自建读屏节点** — 最干净；但工厂、字段和键位标识里有大约 450 处按 `Button` 引用键，设备验收按「按键 …」描述和节点文字找键，一次改动面太大。保留 `Button` 作为外壳，绘制由我们接管。
- **Jetpack Compose 画键盘** — 能声明式地描述键面；但输入法进程的打字热路径要加载一套新的运行时，安装包变大，设备验收和读屏节点都建立在 View 上，不合适。
- **逐键各自适配（现状）** — 每个键按自己的文字和宽度收字号；同一排的键字号各不相同，提示一变就要重排，放弃。

## Consequences

- **收益**：同一组的键字号、基线和退让方式一致；换提示只重画，不再重新布局；新增提示位置只是模板里多一个位置。排版规则是纯函数，JVM 冒烟用固定数值的假字体就能检查，不依赖设备字体。
- **代价与已知上限**：字号和位置按新规则重新算，不追求与之前逐像素一致，外观有可见变化。内容域只增不减：一组键用过的文字在重建键行之前一直保留位置（关掉双拼提示后，底部那一条要到下次重建键行才收回）。两套键面代码在迁移期间并存，其余键迁入键组后删除旧的内边距与自动字号逻辑。

## Verification

- JVM：`platforms/android/tests/keyboard/KeyFaceSolverSmoke.java` 用固定数值的假字体检查字号随键高变化和上下限、字体缩放、按最宽的字收字号、底部提示占一条和放不下时先放弃、按大写字母高居中、缩小上限，以及 28×15 种键格加有无底部提示下主标签不出键格、不压住提示；`KeyFaceTemplatesSmoke.java` 检查默认 52 dp 键上是设计字号（字母 22、角标 10、双拼提示 9 sp）、字体缩放、上下限和退让顺序；`LetterKeyFaceDomainsSmoke.java` 检查 26/14/18 键的内容域随角标开关和引号样式变化；`KeyFaceGroupSmoke.java` 检查全组按最小键格、提示按带它的最小键格、最小键格不变时不重算不通知、隐藏和拿下来的键不算、同样的最小键格查表、内容域增长与整体替换。`check-host.sh` 全部通过。
- Gradle：六个版本的 `compile*ReleaseJavaWithJavac` 与 `lintFullRelease` 通过。第一版内容域用了 `Stream.toList`（API 34 起才有，D8 不补），API 28 上输入法一建键行就崩；lint 的 NewApi 检查会拦下，已改成普通循环。
- 设备（模拟器 API 28、API 35）：`smoke.sh --key-faces`（含新增的 `KeyFaceGroupChecks`：同组参数一致、主标签与提示墨迹不相碰不出键格、换提示不请求布局）、`FourteenKeyDeviceSmoke -e grid_metrics true`（14/18 键字母同字号、截图上墨迹居中），以及 14/18 键、字母角标与手势、英文长按与滑动、微软双拼与按下点、数字行、键盘高度、中文 Shift 共 15 个字母键套件全部通过。
- 性能：API 35 模拟器上与改前的构建（develop `38126259cb`）交替各跑两轮，每次点按的测量与布局中位数：18 键小鹤双拼开着网格辅助码和字母角标，上屏由 18–29 ms 降到 4–5 ms（分词键的「辅」仍会引起整排重新布局，但字母键不再按文字量尺寸），开始组字 13–21 ms 对 13–14 ms；26 键打字、建键盘、弹出键盘与改前持平；绘制每次点按 0.2–2 ms，不变或更低。
- 外观：两个模拟器上 26/14/18 键全拼、26/18 键小鹤双拼在字体缩放 1.0 与 1.3 下改前改后截图对比：字号与原来相近，字母由原来偏下改为居中，大字体下不再挤到角标下方。
