# Agent Note: Android 面板之上的层和停靠窗口的透明高度

Status: implemented

## Problem

按键气泡（连同上滑提示）画在 `keyboardSurface` 里的覆盖层上，面板上沿以外的部分被裁掉：API 29+ 停靠时窗口按内容包裹高度，窗口上沿就是面板上沿，顶排键的气泡只露出下半截；浮动键盘的圆角面板同样裁掉它。长按选项是自己的 PopupWindow，却被夹回键盘根视图里，顶排键放不下就向下挪，盖住工具栏或候选行；英文 e、o、i、u 有三行选项，连同按着的键和顶排其他键一起盖住。API 28 的停靠窗口从首次显示起就是全高（[Android 9 窗口 insets](../bug-fix/2026-10-24-android-api28-ime-window-insets.md)），那里的长按选项本来就浮在键上方，各系统不一致。

另外，「什么画在面板上面、谁盖住谁」没有一处写下来：气泡、滑行轨迹、按下的抬起效果共用一个覆盖层，长按选项、放大镜各是一个弹窗，以后的读音条也要画在面板之上（#11865）。

## Decision

**层是一份有名字、有先后的列表**，`keyboard/OverlayLayer`，从下到上：

| 层 | 窗口 | 现在放什么 |
|---|---|---|
| `PANEL` | 输入法窗口 | `keyboardSurface` |
| `READING_STRIP` | 输入法窗口 | 还没有用到，占住位置 |
| `KEY_PREVIEW` | 输入法窗口 | 按键气泡（上滑提示只换气泡上的字） |
| `LONG_PRESS` | 子窗口（PopupWindow） | 长按选项 |
| `MAGNIFIER` | 子窗口（PopupWindow） | 文本编辑面板的放大镜 |

- 规则：一层只能放在不低于它下面各层的窗口里，否则下面那层所在的窗口会盖住它（`OverlayLayer.ordered()`，`OverlayLayerSmoke` 钉住）。不用数字 z 值。
- 同在输入法窗口里的层由 `core/ImeOverlayHost` 管：每层是 `keyboardRoot` 里排在面板之后的一个铺满的空 FrameLayout，按列表顺序插入，第一次用到时才加，换了输入视图后重新加；不可点，不进无障碍树。层和按键在同一个窗口里，同一帧画出。
- 层的 Z 比面板的投影高：浮动键盘和平板居中时面板有 `ImeOverlayHost.PANEL_ELEVATION_DP`（10 dp）的投影，同一父视图里 Z 高的子视图后画，层不抬高就会被面板盖住。层都用 11 dp，彼此之间仍按子视图顺序；层没有背景，不投影。改面板的投影高度 must 经过这个常量。
- 子窗口总在输入法窗口之上，两个子窗口层不会同时出现。

**停靠在 API 29+ 时窗口在面板上方多留 80 dp 的透明高度**（`PanelGeometry.HEADROOM_DP`）：

- 条件是 `MSIMEInputService.headroomWindow()`：停靠在 29+、不在编辑预览和「键盘调整」里，也就是 `applyFloatingLayout` 不铺满窗口的那些时候。API 28、浮动键盘、跟随光标的候选栏的窗口本来就是全高，不再多留。
- 80 dp：气泡连上下阴影边距 78 dp，整个放得下，与顶排键离面板上沿多远无关；最大字号的读音条（预编辑字号 32、系统字体放大到封顶的 1.15 倍）约 33 dp。`PanelGeometrySmoke` 检查两者都装得下。
- `ImePanelLayout.applyHeadroom` 把它写成面板的上外边距，`ImeStyler.applyKeyboardSurfaceGeometry` 套布局参数时调用；按内容包裹高度的根视图和窗口随之加高。整个停靠期间高度不变，不在显示中改窗口大小。
- `onComputeInsets` 在这时把应用的内容区和可见区上沿放在面板上沿，可触摸区域沿用系统默认的「可见区上沿以下」。应用让出的高度、可点的范围（面板这一横条整宽）都和没有这段时一样，点上面那段落到应用。
- 底色和 API 28、「键盘调整」时一样只画面板那一横条，上方透明。

**气泡放进 `KEY_PREVIEW`**：位置和左右夹边仍按面板里的覆盖层算，再平移到这一层，所以气泡照旧不伸出面板左右两侧（平板居中的键盘也一样），只有上沿不再被截。滑行轨迹和按下的抬起效果仍画在面板里的覆盖层上。

**长按选项只停在屏幕可用区的上沿**：`keyboard/KeyOptionsPlacement.top` 给出弹窗上沿：键上方隔 6 dp，不高过可用区上沿（可见显示区上沿，和全屏窗口收到的系统栏、刘海让位里较低的那个），不低到弹窗底边伸出键盘下沿。API 29 及以下子窗口被输入法父窗口裁剪，伸出窗口上沿的部分画不出来，所以那里上沿还不高过输入法窗口的上沿（`KeyOptionsPlacement.limit`）；API 30 起只受屏幕可用区限制。英文字母、上标和九键按住的选项都经 `ImeLayoutRows.showChoiceOptions`。选中方式不变：松手后点选由弹窗接收；按住拖选时手势从键上开始，整个手势都在键盘窗口里，按屏幕坐标命中选项，与可触摸区域无关。三行的选项（约 124 dp）比透明高度高：API 30 起伸出输入法窗口上沿照样完整显示；API 29 停在窗口上沿，盖住顶排键上沿约 11 px（420 dpi），按着的键和选项都看得见；API 28 的窗口本来就是全高。

## 与已有决定的关系

- [浮动键盘](../feature/2026-10-08-android-floating-keyboard.md) 的备选里否掉了「一直让窗口铺满、停靠时也用 `onComputeInsets` 算高度」，理由是停靠布局建立在包裹高度之上，风险落在所有用户身上。这里部分推翻它：API 29+ 停靠时窗口不再等于面板，`onComputeInsets` 也接管了停靠时的应用边界。但窗口仍按内容包裹高度，只是多出固定的一段，不铺满；平板居中外框和表情面板依赖的包裹测量不变。两篇并存。
- [Android 9 窗口 insets](../bug-fix/2026-10-24-android-api28-ime-window-insets.md) 的教训（已显示的窗口扩高时系统先用旧 insets）在这里照样遵守：透明高度从首次显示起固定，停靠期间不改窗口大小。只画面板横条的底色沿用它的做法。
- [英文字母长按变体](../feature/2026-10-21-android-english-letter-options.md) 里「夹进键盘边界」的纵向那一半由本篇取代，横向不变。

## Alternatives considered

- **常驻的预览子窗口铺到屏幕上沿，气泡画在里面。** 最强的理由是完全不碰输入法窗口和 insets，停靠布局一点不变。原型在模拟器 API 35 上多出 28 MiB 的缓冲区，进程掉帧从约 2% 升到约 16%：每次按键两个窗口都要出帧。不用。
- **子窗口只盖面板上沿一带，只画会被裁掉的气泡。** 内存降到 +5.1 MiB，掉帧仍约 11%；而且子窗口要么接住框内全部触摸，要么全不接，以后的读音条要可点，旁边又要落到应用，只有输入法窗口有可触摸区域，子窗口做不到。不用。
- **停靠时窗口一直铺满**（浮动键盘的做法）。路径统一，但这正是浮动键盘笔记否掉的方案，平板居中外框和表情面板的测量都要重新验证。多留固定的一段就够，不用。
- **透明高度取 92 dp，三行长按选项也放进输入法窗口。** 这样 API 29 上三行选项也不必停在窗口上沿；但只有三行选项、只在 API 29 需要它，却让所有 29+ 的停靠窗口再高 12 dp（约 0.45 MiB），以后选项再多一行又不够。API 30 起子窗口能画到窗口之外。取 80，API 29 及以下停在窗口上沿。
- **按数字 z 值（elevation / translationZ）排层。** 写起来最省事，但值散在各处，新加一层要翻遍全部才能知道放在哪，也表达不了「这一层必须在子窗口里」。用列表加规则。
- **滑行轨迹和按下的抬起效果一起搬上来。** 轨迹手指滑出面板时也会被截；但它们和气泡共用覆盖层的坐标，搬动要另外验证，这次只修气泡，留在原处。

## Consequences

- **收益**：顶排键的气泡和上滑提示完整显示，停靠、浮动、API 28 一致；长按选项浮在键上方，不再盖住按着的键，各系统一致；面板之上画什么有一份列表和一条可检查的规则，以后的读音条照列表接入。
- **代价**：
  - API 29+ 停靠时输入法窗口高 80 dp（420 dpi 下 210 px），缓冲区多约 1.5 MiB；API 28 不变。
  - 停靠时的应用边界改由 `onComputeInsets` 给出，所有 29+ 停靠用户都走这条路径。窗口改写依赖系统 `input_method.xml` 的结构，厂商改过这层布局时可能表现不同（浮动键盘笔记已记下同一风险）。
  - 新增写面板几何的地方仍须经过 `ImePanelLayout`；`applyHeadroom` 由 `ImeStyler` 在套布局参数时调用，改 `applyKeyboardSurfaceGeometry` 时 must 保留这一步。
  - 长按选项的上沿不再受键盘约束，需要窗口高度以外的空间；在可用区很矮（分屏、小窗）时停在可用区上沿，可能盖住按着的键，和原来压回键区时一样。API 29 的三行选项停在窗口上沿，略压住顶排键的上沿。
  - 层的 Z 依赖面板的投影高度，两者 must 经 `ImeOverlayHost.PANEL_ELEVATION_DP` 一起改；第一版漏了这一点，浮动键盘和平板居中时气泡被面板盖住，模拟器上才发现。
- **验证**：
  - `OverlayLayerSmoke`、`PanelGeometrySmoke`（透明高度装得下气泡和最大读音条）、`KeyOptionsPlacementSmoke`（含 API 29 停在窗口上沿），由 `check-host.sh` 运行。
  - 模拟器 API 35、29、28（1080×2400，420 dpi），改前改后的构建交替跑同一套脚本：
    - 面板上沿（窗口上沿加内容区 inset）三个级别改前改后都是 1570，可触摸区域相同；在面板上方 40 px 点应用的输入框，焦点移过去；收起再显示、横屏（面板上沿 376）、按住键时旋转、表情面板、单手、分离（手机横屏）都和改前相同。API 29+ 停靠窗口上沿 1570 → 1360，API 28 不变。
    - 顶排 Q、P 的气泡三个级别都从被截掉变成完整，第二排不变；API 35 上浮动键盘和平板尺寸（1600×2560，280 dpi）的气泡也从被截掉变成完整。
    - 英文 e 的三行选项改前压在按着的键上，松手就输入了选项（ê）；改后 API 35 上沿 1328、API 29 停在 1360、API 28 1328，松手后点选和按住拖选都输入了所选的字。中文 q 一行选项从 1570 到 1528。
    - API 35 打字 30 秒、改前改后各 3 轮：输入法窗口掉帧 1.39 / 1.39 / 1.39 % 对 2.36 / 2.08 / 1.67 %，p50、p90 相同（约 20 ms、26 ms）。模拟器用 CPU 渲染，多一个百分点左右，要真机才能判断。
  - 真机（Android 17，1080×2400，450 dpi，手势导航）：透明高度 225 px，点在这段里的应用链接照常响应；顶排气泡完整；一行和三行选项浮在面板之上，三行的伸出窗口上沿也完整，按住拖选、松手后点选都输入了所选的字；打字时输入法窗口 2310 帧里 2 帧超时（0.09 %），p50 6 ms、p90 10 ms。没有同一基线的对照构建。
  - 没覆盖：浮动和平板尺寸下的长按选项、从浮动面板直接点「停靠键盘」切回（经设置切回已查），TalkBack 在透明那段上的表现，API 29 的真机。
