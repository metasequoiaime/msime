# Agent Note: 连续多语言路径复用现有词库查询

Status: implemented

## Problem

#8921 的[路径内核](2026-10-24-multilingual-path-kernel.md)只接收词条，并不识别原始输入。公开词库原型即使找到完整路径，也把原例中文片段选成「在日问世」。跨语言结构成本不能代替中文句子的词网格和 n 元排序；逐键查询全部子串还会重复读取已经确认的范围。完整产品仍归[统一输入提案](../../proposed/feature/2026-10-24-unified-language-composition.md)，本篇仅记录词库适配接口。

## Decision

`engine::multilingual::DictionaryComposer` 只打开调用方显式选择的中英日提供者，少于两种语言不打开提供者。它复用中文 `conversion_rows`、英文 `query_exact` 和日文精确读音查询；中文边最多七音节，日文必须有精确词条、至少三拍、最佳路径没有未知假名。未知尾部不拼原文，缺模型不下载资源。

适配器持有独立的中文、英文和日文查询状态，不借用活动组字的请求、缓存、纠错或上下文。中文 n 元表及日文模型仍由原有进程缓存共享。相邻中文边合成片段后，交给现有 `convert_pinned` 词网格重排；语言和原始输入范围不变。

连续输入的日文提供者只领取已经就绪的共享模型，不获取全局加载锁或同步校验模型。后台未就绪时仍查询中英，未命中不记成永久失败；就绪状态改变时丢弃跨度及同串答案，让未改变的编码也能重新得到日文路径。旧日文整段混输同样只在模型就绪后查询，避免两个功能并用时由旧路径先等待加载锁。独立日文方案仍沿用原有同步提供者语义。

追加只查询新结尾的跨度；删除和中间编辑保留共同前缀内完整结束的边，同串复用答案。词库修订后调用方必须 `clear()`，模型或语言集合变化时重建。本接口没有监听文件或读取偏好。

小写 ASCII 输入最多 96 字节，每次输入变化最多查询 4096 个原始跨度，图最多 4096 条边，单个提供者词面最多 256 字节。任一预算超限都清掉输入、图和答案并返回 `None`。超过词面上限的完整单语言词条不能静默丢弃，否则较短混合路径会失去其单语言对照，错误成为候选。空词面作为无效边忽略。

`Conversion::chinese_complete` 保留完整中文解释的存在性，后续候选层必须落实用户确认的「中文优先，混合结果作为备选」。本切片没有 Session、来源值、偏好、简繁、学习或产品设置入口。

## Alternatives considered

- 借用活动提供者能省去中文、英文读取连接，但子串查询会干扰活动请求状态和缓存，因此使用独立实例，接受额外连接开销。
- 逐键重新枚举全部子串实现简单，删除和中间编辑天然一致，但会重复查不变跨度，因此按共同前缀保留边，并显式约定词库修订失效。
- 直接连接各条中文边保留结构路径的原始输出，查询更少，但原例中文会变成「在日问世」，因此将合并中文片段交还现有词网格重排。
- 首次查询同步读取日文模型可立即返回完整三语候选，但公开资源对照已发现约 1.4 秒的 debug 冷准备；后台预热与查询竞争仍会等同一加载锁。因此连续输入暂缺日文时保留中英候选，后台准备完成后再参与。
- 丢弃超长词面后继续搜索能提高召回并保留正常短边，但会擦掉完整单语言证据、错误生成混合候选，因此预算失败必须放弃整次转换。

## Verification

合成真实 SQLite 词库及日文模型覆盖三语言两次切换、原始范围、中文重排、完整中文歧义、未选语言、缺模型、追加/删除/中间编辑、词库修订及输入/词面限制。独立审查发现超长完整英文词条被静默丢弃后，先增加回归并在 Windows 实测 20 通过、1 失败；传播预算失败后 21 项内核及适配器测试通过。独立复审关闭该阻断。

公开词库固定 `msime-dictionary` 提交 `128a332cabc5fa42b1cf5f827033ad5697ff528b`，按资源锁逐一校验拼音、英文、bigram、trigram 和日文模型的大小及 SHA-256；使用独立合成状态目录。24 个样例全部比较整串转换与逐字追加的最终结果一致。19 个单语言对照不增加混合行，5 个混合样例完整覆盖，其中 2 个保留 `chinese_complete=true`。原例输出为 `hello在中文是你好在日文是おはよう`，仅证明这组公开样例，不能外推语言识别准确率。

Windows debug 构建首次整串转换为 1450.459 毫秒，构造为 39.996 毫秒；其后 247 次逐字追加调用的 p50/p95/max 为 0.260/2.066/3.723 毫秒。首次调用包含尚未准备的资源开销，不能用后续数据掩盖它，也不能视为 release 或设备延迟承诺。现有日文提供者有后台预热接口，后续会话整合仍需验证首次加载和按键线程的关系。

独立冷启动对照中，中英两语言首轮/同进程再次构造后的整串转换为 36.971/36.195 毫秒，中英日为 1463.356/44.330 毫秒；结合日文提供者首次查询才加载进程共享模型的实现，将约 1.4 秒额外开销定位到首次日文准备。此对照和上面的追加探针都是 Windows debug 研究数据。

同源 Windows 最终门禁通过 21 项 Cargo 测试、引擎全部 target 的 `clippy -D warnings`、workspace 格式检查、真实 Host API 构建、正规 CMake 配置和完整 quick；前后八份源码及既有笔记散列一致。quick 实际构建 TSF、Server 和全部原生目标，运行 131 项可移植检查，2 项按宿主差异排除，116 项交原生构建；pipe-only 通过。缺前端依赖、移动 SDK、Apple 宿主、Docker 的阶段如实跳过，既有链接器诊断未压制。

Android API 35 的专用 `emulator-5590` 使用同一提交构建的 `aarch64-linux-android` 引擎测试程序，部署前后 SHA-256 一致，21 项内核与适配器测试通过，耗时 4.54 秒。这是 `adb shell` UID 下的模型与 SQLite 读取验证，未安装 APK，也不是应用沙箱或 IME 入口验收。

冷加载回归在后台模型加载暂停时先复现按键 `Timeout`；只领取就绪模型后，中英候选及时返回，模型就绪后同一输入重新获得日文。复审补充的真实 Session 双开日文混输回归同样先红后绿。最终 34 项多语言专项通过，既有日文相关测试 184 通过、13 项按原配置忽略、0 失败；这些是合成词库和本机引擎证据，不代表设备耗时承诺。

### 并行测试的模型生命周期

日文候选行为夹具显式取得并返回共享模型的强引用，调用者以具名变量持有到断言结束。仅等待后台预热结束不能保证缓存仍在：其他并行用例的宿主清缓存可在预热结束和首个候选查询之间释放仅由进程缓存持有的模型，非阻塞查询此时合法返回尚未就绪。持有模型后，即使缓存清理降为弱引用，后续查询仍可取得同一模型。缺模型仍返回 `None`，方案开关、辅助码、候选与学习断言保留。

预热专项直接构造真实 Session 并等待后台状态，不经过显式读模型的行为夹具，继续证明会话本身会预热。后台加载暂停时按键不阻塞的两项屏障回归不改。CI 在 `japanese_rows_carry_no_helpcode` 失败，本机修前完整引擎的 16 线程执行重现相同失败；修后同一 16 线程完整引擎套件 2604 项通过、0 失败、56 项按原定义忽略（190.69 秒），引擎全部 target 的严格 clippy 退出 0。不改变产品缓存或输入线程行为。

## Consequences

中文自然度复用现有模型，提供者与活动组字状态隔离，完整范围可交给后续简繁和学习契约。代价是选用统一输入时额外持有读取连接，首次资源准备仍需解决。4096 跨度预算按每次输入变化计：一次全新输入超过 90 字节可能耗尽预算，逐字追加则可能到达 96 字节；超限只影响新增混合候选，调用方仍须保留原候选和编码。

Host API 已按共享偏好和资源门控调用此接口，六宿主逐段输出接线见[运行时笔记](2026-10-24-multilingual-runtime-output.md)。Android 应用 UID 的资源读取验收、真实 TIP/编辑器和其他平台原生入口验收仍须单列证据。#8921 继续开放，未来部分实现的 PR 使用 `Refs #8921`。
