# Agent Note: 鸿蒙日文与五笔直接读取一份共享资源

Status: implemented

## Problem

[#11034](https://github.com/metasequoiaime/msime/issues/11034) 要求按需资源只有一份。原实现虽然从 HAP 移除了日文和五笔，却把设置应用的资源包依次复制到共享目录和键盘私有目录，完整资源最多保存三份。

既有笔记中，[按需资源](../feature/2026-11-06-harmony-on-demand-resources.md) 的打包和下载规则继续使用，资源包镜像部分由本篇取代；[共享状态沙箱](2026-10-09-harmony-ime-shared-sandbox.md) 仍负责可写状态，两者部分重叠并互链。[全平台瘦包](../feature/2026-11-07-all-platform-package-slimming.md) 规定其他平台的资源边界，不需要改变。

## Decision

日文、五笔的不可变资源放在 `<共享目录>/msime/dictionary-resources/resource-packs/<id>`。设置应用独占安装和卸载，继续用 Rust 编译期锁文件核对文件名、大小和摘要，再原子发布完整目录；键盘在基础访问和完整体验模式下都直接只读该目录。它们从 `SETTINGS_ENTRIES` 中移除，不再经过目录指纹、发布和导入。

`HostOptions.dictionary_resource_root` 只在内存里注入，指定这两类资源包所在的根目录。它不改变偏好、用户词库、词库更新、缓存、学习和统计的目录，也不改变其他模型和资源包的解析。未提供此字段的宿主保持既有行为；不是绝对路径时忽略它，符号链接仍由共享资源读取边界拒绝。共享路径明确指定但包缺席时，不回读键盘遗留副本；下次聚焦重新解析安装或卸载后的路径。五笔的个人工作词库仍是各会话派生的可写数据，本篇消除的是不可变下载包的重复复制。

设置应用从原私有资源包和旧共享镜像收编旧文件，NAPI 经既有通用请求工作线程调用 `resource_pack_adopt`。Rust 在同一文件系统内改名、按锁校验并原子发布，不复制；失败放回源文件。目标完整发布后才清理旧目录，重复打开不重新收编。键盘仅在共享包已发布后清理自己的旧包，不写共享目录。显式卸载同时清理设置应用的旧私有目录和旧发布目录，防止下一轮迁移恢复它。

共享沙箱不可用时，保留各宿主原来的私有资源路径；不把偏好目录整体迁入共享沙箱，也不新增 WebView 或设置入口。资源列表合并私有目录的其他资源与共享目录的日文、五笔，其他资源包仍在原处安装、查询和卸载。

## Alternatives considered

- **继续镜像已发布目录。** 最强的理由是复用成熟同步流程、键盘所有文件都在可写沙箱，升级兼容成本低。但它恰好违反同一份资源的要求，目录指纹只能避免重复聚焦时复制，无法消除首次安装的两份副本。
- **把整个状态目录改成共享目录。** 能去掉全部同步代码，却会让基础访问模式的键盘无法创建偏好锁、个人词库、缓存和统计文件；共享状态笔记已记录这些约束。本次只拆不可变资源，保留可写状态的边界。
- **用符号链接指向共享资源。** 接线少，但共享资源校验明确拒绝非系统符号链接；为此放松校验会破坏路径信任边界，直接传入真实资源根目录更小、更明确。

## Consequences

新安装与成功迁移后的日文、五笔下载包各保留一份；安装/卸载不再扫描和复制大目录。升级收编要在后台完整哈希旧文件，首次打开设置页可能等待这一步；跨文件系统或校验失败时保留旧文件，让用户仍可重新下载到共享目录。无法取得共享沙箱的开发签名仍没有跨沙箱共享能力，此限制不伪装成已解决。

## Verification

行为测试覆盖无复制收编、先发布再清理、失败保留来源、第二来源回退、重复打开、卸载后不恢复、键盘只清理私有目录和资源镜像条目移除。Host API 回归覆盖共享路径与私有状态分离、缺席/不完整包不回读旧副本、下次聚焦读取安装和卸载、只读目录不创建锁或缓存及符号链接拒绝。验证结果随 PR 更新；本任务按维护者要求不安排设备验收，不把未执行的验证记作通过。
