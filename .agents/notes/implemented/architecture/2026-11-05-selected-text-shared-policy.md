# Agent Note: 候选选中文字色的写入与触屏规则归共享层

Status: implemented

## Problem

#10803 的新增 Android 取色器在 `CandidateSelectedTextPolicy.change` 判断何时切自定义主题、保留原主题作底和清两皮肤槽；Android 与鸿蒙又分别判断触屏候选条何时使用选中文字色。既有功能笔记曾以 C ABI 成本为由延后统一，但仓库要求新设置的业务规则和校验先进共享 Rust，宿主只适配界面。这项延后没有专项授权，且两端规则以后可能走样。

## Decision

`client-core::preferences` 的新模块计算候选选中文字色的纯补丁：设色时按原规则切自定义、保留底和清皮肤槽；清除只移除这一项。Host API 仅做长度、JSON 类型适配，Android 在既有 `KeyboardSheets.save` 读到的最新文档上应用补丁，再走原 CAS 保存。通用保存接口不增加隐式主题副作用。

`client-services::skin::theme::ResolvedTheme` 新增可选 `touch_selected_text`，只有自定义主题中合法的显式 RGB 取色器才输出。Android 和鸿蒙消费已有主题解析响应，不再从偏好重建此规则。缺字段继续使用原键盘配色，不改变出厂值、缺字段读法、其他取色器或其他候选文字。

## Alternatives considered

- **保留宿主各自实现。** 规则短、已有行为测试，不增加接口。没有采用：违反新规则由共享 Rust 持有的仓库边界，新增设置的实现不能以已有重复为继续复制的理由。
- **让通用保存自动切主题。** 所有宿主保存一个字段便自动获得同一结果。没有采用：保存完整快照原本只校验和 CAS，悄悄添加副作用会改变导入、同步和既有编辑器的语义。
- **为触屏颜色再增加一个独立 C ABI。** 返回值极小且用途明确。没有采用：两端已经取得 `resolve_theme` 响应，可选字段即可承载已计算的值，避免额外跨边界调用。

## Consequences

规则集中到共享层，Android 和鸿蒙只消费补丁与主题解析结果，新增设置不再复制主题切换、生效条件。代价是新增一个有界 C ABI 及一个可选 JSON 字段；旧宿主忽略可选字段，原有请求和默认值不变。

共享行为回归覆盖全部全局主题的选色/清除、原主题作底、双皮肤槽清理、非法色拒绝，以及非自定义、缺色、非法色不输出触屏取色器。C ABI 覆盖请求类型、长度、UTF-8、未知字段及空指针。测试先在缺少共享字段、空补丁实现上失败，再在实现后通过。

Android 保留候选文字、背景、强调色、纠错色和显示标签断言，把主题判定/写入断言迁到 Rust。新增 JVM 回归验证共享解析值经过应用主题叠加后仍到达候选外观；它先暴露 `withAppTheme` 丢失新字段，再补齐复制。鸿蒙测试改为真实解析共享响应，缺字段/空值/非法值仍回键盘配色。新增规则不修改其他取色器、缺字段读法、通用偏好保存或 CAS。

设备和截图覆盖仍依原 PR 记录，JVM、Rust 和鸿蒙逻辑测试不冒充设备验收。
