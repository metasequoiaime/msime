# Agent Note: 用有界词条图保留连续输入的语言边界

Status: implemented

## Problem

#8921 的同一组字需要跨越中英日词条。现有整段英文和日文查询不提供串内路径，贪心最长前缀也可能把可转换的尾部堵死。中文词频、英文权重和日文成本不能直接相加。完整功能仍在[统一输入提案](../../proposed/feature/2026-10-24-unified-language-composition.md)中，本篇只约定共享引擎的路径内核，不代表提供者、偏好或宿主入口已经接通。

## Decision

`engine::multilingual` 接受提供者已确认的 `Lexeme`：原始输入的 UTF-8 字节范围、语言、词面和同读音名次。它不读取词库、配置或用户数据，不把未知尾部作为原文拼接，不产生部分覆盖结果。调用方显式传入语言集合；未选语言、无效范围、非字符边界、零长度和空词面不参与搜索。

每个输入位置保留已用语言集合和末尾语言的路径。只有完整覆盖输入且至少涉及两种语言的路径可返回；相邻同语言词条合成 `Segment`，保留完整输入范围和语言，后续简繁转换与学习可据此维持边界。

混合路径先比较词条数，再比较切换数与同读音名次之和；完全相同的分数按语言、词面和范围固定比较，不依赖提供者枚举顺序。完整单语言路径用更少词条回答输入时，不返回拼凑的混合候选。同数时保留混合备选。`Conversion::chinese_complete` 表示所选语言和有效词条中存在完整中文路径；用户明确要求中文优先，后续候选整合必须据此把中文留在前面，不能因为混合路径更短就抢占首位。

每次解码最多接受 96 个输入字节和 4096 个词条。词条上限包含无效词条，超限直接返回 `None`，调用方保留既有候选。所有词条至少消耗一个字节，路径深度最多 96，每个输入位置最多 24 个状态；这些上限约束结构搜索，不代表词库查询已满足按键延迟预算。

扩展边时先计算三项结构成本，严格差于目标已有路径时直接跳过，避免为注定被丢弃的边复制前缀。相同成本仍走原来的固定字典序比较，路径选择规则不变。96 字节、4096 词条的合成密集图在独立优化构建下交替测量三组各 100 次，各批次的单次平均耗时取中位数，预过滤前为 18.294 毫秒，预过滤后为 1.779 毫秒。这不是 300 次调用的延迟分布中位数；数据只用于探索内核开销，不包含提供者、宿主，也不是设备延迟承诺。

## Existing note audit

- [统一输入提案](../../proposed/feature/2026-10-24-unified-language-composition.md)：部分落地。内核契约归本篇，提供者、偏好、候选来源、逐段简繁与宿主验收继续归提案，不将整篇提前标成已实现。
- [日文整段混输](../feature/2026-10-12-mixed-japanese-candidates.md)：部分重叠。保留其语言门槛、资源门控和跨语言分数不可比的依据，本模块不更改已有选项。
- 其余词网格和语言命中属于单语言句子、拼音纠错或手动切换方案，不是重复的跨语言路径内核。

## Alternatives considered

- 只找最优混合路径，能最大限度召回跨语言结果；没有采用，因为锁定公开词库的 19 条单语言对照中有 14 条被拆成混合碎片，`women` 变成我men，`hello` 变成hell哦。完整单语言路径必须参与结构比较。
- 单语言不差时一律删除混合路径，能进一步压低噪音；没有采用，因为用户选择中文优先、混合结果作备选。同样词条数的混合解释可以保留，排序使用明确的中文路径证据。
- 每个位置只取最长词，计算和状态都少；没有采用，因为最长前缀可能走进死路，丢掉本可完整转换的短前缀路径。
- 直接相加三种提供者的原始分数，能立即复用现有排序；没有采用，因为分值的单位和方向不同。内核只消费同读音名次，词面自然度仍归各语言提供者。

## Consequences

内核与平台和词库查询解耦，可独立验证完整覆盖、语言子集、UTF-8 范围、非贪心回溯、枚举稳定性和预算边界。256 个确定性合成小图在八种语言子集与正反两种枚举顺序下，对照不裁剪状态的穷举路径；它检验搜索正确性，不能代替真实语言准确率。

固定基点 `bad4a893a3bb943a977e30475b167709a85cfbd7` 的初轮同源 Windows 验证通过：13 项 `multilingual::` Cargo 单测、引擎全部 target 的 `clippy -D warnings`、工作区格式检查和完整 quick。初轮 quick 包含 Rust 工作区检查、131 项可移植测试和 pipe-only 编译；Windows 完整原生构建目录尚未配置，TSF/Server 完整构建因此跳过。

成本预过滤增量在核心提交 `450dae9b59cdc4b4fe22b4cc94c5119f11c785ea` 上再次通过相同的 13 项 Cargo 单测、严格 clippy、格式检查和完整 quick。此轮先构建真实 Host API，再按正规依赖配置 `target/windows-full/x64`；quick 实际完成 TSF/Server 与全部原生目标编译，前后源文件散列一致。Host API 链接器保留一项标准输出诊断，未压制告警。缺少前端依赖、移动 SDK、Apple 宿主和 Docker 的阶段按环境跳过，不能据此宣称这些平台已验收，也未运行真实 TIP/编辑器验收。独立源码复审没有发现当前纯内核及成本预过滤范围内的阻断问题。

公开词库探索中的单语言对照改善，不等于 issue 已完成：纯路径内核不处理示例中文片段的「在日问世」词面问题，后续[词库适配器](2026-10-24-multilingual-dictionary-adapter.md)复用现有中文词网格重排。本模块不添加产品设置或候选来源；接入前仍需资源门控、逐段简繁与学习保护、共享和原生设置、完整 quick 及平台验收。
