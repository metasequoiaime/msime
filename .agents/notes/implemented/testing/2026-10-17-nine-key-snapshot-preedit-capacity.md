# Agent Note: 九键快照预编辑缓冲一次预留容量

Status: implemented

## Problem

`NineKeySession::snapshot` 原先用 `locked.join("'")` 只按已锁定读音创建预编辑字符串，然后在仍有未锁定数字时追加尾部数字、切分和分隔符。尾部超出初始容量时会在每次快照中扩容；九键首字母快照场景已有严格分配预算，能稳定暴露这次额外申请。

## Decision

快照先无分配地计算锁定读音和分隔符的字节长度，再把剩余数字、切分分隔符以及锁定与未锁定部分之间的分隔符计入一次 `String::with_capacity`。随后按 `locked` 原顺序直接写入读音，保持空读音、分隔符、首字母替换偏移和预编辑文本完全不变。

## Existing decisions

已检索九键快照、锁定前缀长度、首字母替换和预编辑缓冲笔记。`2026-10-17-nine-key-snapshot-prefix-offset.md` 负责复用锁定前缀长度，`2026-10-17-nine-key-snapshot-initial-char.md` 负责首字母替换字符的栈缓冲；本片只负责快照预编辑字符串的初始容量，三者边界互不替代。没有发现相同的未落地提案。

## Alternatives considered

- 保留 `join`，只在追加前调用 `reserve`：可以保留现有写法，但仍需先计算完整容量并保留一次可变扩容入口；直接构造使容量契约和写入顺序在同一处可见。
- 继续让 `String` 按需扩容：实现最短，但每次锁定前缀加未锁定数字的快照都会重复支付尾部扩容。
- 复用会话级预编辑字符串：能进一步减少快照分配，但 `SessionSnapshot` 必须拥有独立文本，跨快照复用会改变所有权边界并增加清空与借用状态。

## Verification

旧实现的首字母场景分配为 3 次；把回归门槛降为不超过 2 次后，旧实现先失败，新实现通过。九键单测、引擎全量测试与 golden、`cargo fmt`、`cargo clippy -- -D warnings`、`git diff --check`、`pnpm run verify-notes` 及仓库 quick 门禁作为提交前验证。

## Consequences

九键快照仍返回独立拥有的预编辑文本，文本内容、容量之外的快照字段、候选顺序和首字母显示规则不变。热快照少一次预编辑字符串扩容；每次快照多一次长度扫描和一次手写追加，且为非活动会话可能预留少量额外容量。收益仅针对可增长的快照预编辑缓冲，不外推为整个九键输入延迟目标已达成。
