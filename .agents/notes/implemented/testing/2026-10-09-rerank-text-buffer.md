# Agent Note: 候选重排文本引用使用栈缓冲

Status: implemented

## Problem

`ordering::rerank_pick` 每次调用模型前都会把候选行的文本引用复制到临时 `Vec`。即使首行已令模型拒绝重排，入口也先扫描最长候选、裁剪上文并收集全表引用。候选页通常不超过 128 行，这个容器只用于把借用的文本传给 `Reranker::best_where`，并不承载结果所有权。

## Decision

先按固定上游 `6ce2cbb` 的 `comparable` 规则排除不回答当前按键的首行及仍受信任的词典首行，拒绝路径不扫描最长候选、不裁剪上文、不投影文本，也不调用模型。全拼词典首行仍检查整表纠错标记后才确认豁免，包括末尾不参与评分的纠错行；双拼继续忽略纠错行的领先权限。

需要一般模型回退的候选行不超过 128 条时，用栈上引用数组收集文本并把切片传给重排器；更大的列表继续使用原有 `Vec` 回退，避免无界调用固定扩大栈帧。重排器收到的文本顺序和行元数据判断保持不变。

## Alternatives considered

继续把拒绝决定留给 `best_where`：契约只维护在上游一处，最容易随依赖更新；但本地静态证据分支已经需要同样的首行门控，入口也已持有相同元数据。提前返回这两个确定条件能省去后续全部准备工作，回归测试同时固定纠错权限与下次模型评分行为；升级上游时需一起核对这些条件。

始终使用栈上数组可以完全移除这次临时堆分配，但会为异常的大候选列表增加固定栈占用，并要求截断输入。按候选页上限切分两条路径能保留大列表的原有复杂度和完整输入。

只减少 `Vec` 的预留容量仍会为常见短列表建立堆缓冲，不能消除重排热路径的临时分配。

## Verification

拒绝路径新增完整入口分配与行读取预算。旧实现两行词典首选读取 10 次行数据，超过首行加纠错扫描的 3 次预算；129 行的词典首选和双拼纠错首行均申请一次 2064 字节文本向量，实现后拒绝路径均为零申请。测试覆盖 2、128、129、1024 行、全拼与双拼及词典、AI、目录和不完整首行。另以末尾纠错回归固定全拼词典豁免撤销，并比较跳过长上下文的拒绝调用后，下次评分的结果、分配次数与申请字节与未跳过调用的模型一致。

新增两行候选文本引用的分配预算测试；旧实现分配 1 次，栈缓冲实现为 0 次。排序模块测试、完整 `msime-engine` 测试、golden、doc tests、Clippy、格式检查、笔记校验和 quick 门禁覆盖接入路径。

## Consequences

拒绝重排的大列表少一次全表引用向量申请（129 行 2064 字节，1024 行 16384 字节，按 64 位计算）；除全拼词典首行所需的纠错扫描外，拒绝路径只读取首行。有效评分的计算量和模型资源不变，不据此声称端到端 16 ms 达标。128 条以内的普通重排每次在栈上占用约 2 KiB（64 位），换取短候选页不再创建文本引用向量；超过边界的列表继续使用堆向量并保持原有行为。

[神经评分栈缓冲](2026-10-14-neural-rerank-score-buffers.md)将最多12条的评分中间存储移到栈上，并只对已评分前缀应用排列；本篇决定继续保留。

[静态证据输入缓冲](2026-10-15-rerank-static-score-buffer.md)直接借用最多九条有效候选的文本，静态评分成功时跳过本篇的完整文本投影；一般模型回退仍遵循本篇的短列表栈缓冲和大列表堆缓冲决定。
