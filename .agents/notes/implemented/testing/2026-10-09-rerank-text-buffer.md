# Agent Note: 候选重排文本引用使用栈缓冲

Status: implemented

## Problem

`ordering::rerank_pick` 每次调用模型前都会把候选行的文本引用复制到临时 `Vec`。候选页通常不超过 128 行，这个容器只用于把借用的文本传给 `Reranker::best_where`，并不承载结果所有权。

## Decision

需要一般模型回退的候选行不超过 128 条时，用栈上引用数组收集文本并把切片传给重排器；更大的列表继续使用原有 `Vec` 回退，避免无界调用固定扩大栈帧。重排器收到的文本顺序和行元数据判断保持不变。

## Alternatives considered

始终使用栈上数组可以完全移除这次临时堆分配，但会为异常的大候选列表增加固定栈占用，并要求截断输入。按候选页上限切分两条路径能保留大列表的原有复杂度和完整输入。

只减少 `Vec` 的预留容量仍会为常见短列表建立堆缓冲，不能消除重排热路径的临时分配。

## Verification

新增两行候选文本引用的分配预算测试；旧实现分配 1 次，栈缓冲实现为 0 次。排序模块测试、完整 `msime-engine` 测试、golden、doc tests、Clippy、格式检查、笔记校验和 quick 门禁覆盖接入路径。

## Consequences

128 条以内的重排每次在栈上占用约 1 KiB，换取短候选页不再创建文本引用向量；超过边界的列表继续使用堆向量并保持原有行为。

[神经评分栈缓冲](2026-10-14-neural-rerank-score-buffers.md)将最多12条的评分中间存储移到栈上，并只对已评分前缀应用排列；本篇决定继续保留。

[静态证据输入缓冲](2026-10-15-rerank-static-score-buffer.md)直接借用最多九条有效候选的文本，静态评分成功时跳过本篇的完整文本投影；一般模型回退仍遵循本篇的短列表栈缓冲和大列表堆缓冲决定。
