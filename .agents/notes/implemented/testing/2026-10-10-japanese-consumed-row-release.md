# Agent Note: 日文矩阵提前释放已消费行

Status: implemented

## Problem

矩阵按递增起点扩展读音，每行完成精确跨度和未知回退后已没有读者，却把临时取出的整行放回 rows，保留节点向量和所有句子前缀文本到查询结束。长输入同时保留全部历史前缀，累计文本长度随输入长度二次增长；最终候选并不借用这些行。

## Decision

只取消起点循环末尾的整行恢复，让局部 previous_row 在本轮最后一次读取后析构。未来跨度仅写 `end > start`，末行只在全部扩展之后取出，不恢复历史行不影响排序、同分、连接成本、未知回退和输出。仍使用既有 Vec 行，不引入环形表、共享文本、unsafe 或缓存。Rust 的[析构规则](https://doc.rust-lang.org/std/ops/trait.Drop.html)保证拥有字段随局部值一起释放。

## 既有笔记审计

[节点提前筛选](../../implemented/testing/2026-10-09-japanese-pruned-node-text.md) 部分重叠，继续约束八项增量稳定排名；[末行文本转移](../../implemented/testing/2026-10-09-japanese-final-text-move.md)继续约束最终拥有文本；[精确词条流式](../../implemented/testing/2026-10-09-japanese-exact-lemma-stream.md)继续约束词库借用、排名与限额。三篇互链且保留历史验证。本片只改变已消费节点的释放时机。[固定八槽行](../../rejected/testing/2026-10-09-japanese-inline-matrix-rows.md)仍被否决，不改行布局。句子输出容器复用、待定键与词条结果消费属于别层，无关且保留。活跃笔记检索行释放、历史行、previous_row 与峰值内存，没有相同决定。

## Alternatives considered

- 保留历史行直到函数结束：所有权最直接且代码已稳定；历史行没有后续读者，却占用所有句子前缀存储。
- 滚动十六行或复用行向量：还能减少最初为所有行预留的节点容器；需要模运算、槽位代次和跨跨度写入边界，本片先缩短已拥有值的生命周期，不改变索引机制。
- 把节点文本改为共享路径链：可避免每轮完整句子复制；需要改变节点表示、最终物化和同分保留边界，此片保持拥有字符串。

## Consequences

已消费行在其最后一次读取之后释放，节点文本不再累计到查询末尾。长未知文本的在用请求字节峰值由二次累计前缀降到行容器、边界和相邻文本的线性上界；密集节点仍受八项限额约束，结果、排序、连接成本、去重与总分配保持。初始所有 Vec 行和未来十六个跨度节点仍占内存，本片没有滚动行或共享路径链，没有新增生产缓存或公开 API。

代价是把析构从函数末尾分摊到每个起点。计量和三轮 release 在当前环境都只提供逻辑内存收益，OS RSS 和延迟风险仍需分别看待，不能宣称所有输入更快。若稳定隔离环境复现长 Unicode 的延迟回退，下一步比较仅清空历史节点文本但保留 Vec 容器到查询结束的策略，或再考察滚动行；本片不靠选择最好一轮掩盖回退。冻结正文与堆计量只在 cfg(test) 中维护，增加测试维护成本，不改变生产分配器。
