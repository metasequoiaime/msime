# Agent Note: 日文预测词条流式写入输出

Status: implemented

## Problem

完整日文读音查询需要先显示句子转换结果，再显示读音前缀预测。`JapaneseProvider::query_into` 先把预测词条借用视图收集到临时 `Vec`，等待句子搜索结束后再逐行写入候选。这个向量只在同一次查询中消费，热查询因此保留一份不需要长期存在的结果容器。

待定字母查询对每种假名前缀也收集一个词条视图向量，再立即消费到已有候选行。共享拼接键已避免逐后缀重建字符串，但命中的各前缀仍分别申请结果容器；两词条合成 `kak` 热查询为 21 次分配，其中两次属于这类容器。

待定读音矩阵还将 `continuing_lemma_views` 收集为视图向量，再立即写入句子输出。这一容器也仅消费一次，命中查询另分配一次；两词条合成 `kak` 在句子结果容器已复用的基线上，矩阵和 provider 分别为 16 与 18 次分配。

只有待定字母、完整读音为空的矩阵分支也为每个命中假名前缀收集词条视图向量，再立即写入输出；即使只要一个候选，它也会先构造该前缀的全部 24 条视图。三词条合成 `k` 的充分预热 provider 查询因此保留两份临时结果容器，分配为 5 次。

## Decision

`JapaneseDictionary` 提供只消费一次的 `for_each_prefix_lemma_view` 内部入口。它调用原来的泛型 `prefix_lemmas_with`，访问闭包返回 `()`，因此结果类型是无需元素存储的 `Vec<()>`；不复制前缀短索引、下界扫描和成本排名逻辑。零大小元素不分配存储是 [Rust 标准库的 Vec 保证](https://doc.rust-lang.org/std/vec/struct.Vec.html#guarantees)。完整读音分支先运行句子搜索，再通过该入口把预测词条直接写入 `Rows`；待定读音分支按原假名顺序把每个前缀的词条直接写入 `Rows`，然后执行句子搜索。不满足完整读音预测长度的查询保持原条件，候选顺序和去重规则保持不变。

继续补全提供同类 `for_each_continuing_lemma_view`，调用原泛型 `prefix_lemmas_continuing_with` 并返回零大小 `()`。矩阵在最佳句子和待定精确补全之后、其余末行之前按原成本排名逐项写入 `Output`；继续补全限额仍为 48，即使最终输出已满仍执行原查询与消费判定，保持各路径的分配边界。原视图向量入口生产已无调用，收为仅测试的查询对照。

空读音矩阵分支同样复用 `for_each_prefix_lemma_view`，各假名前缀仍按原顺序查询 24 条，并按文本去重。当前前缀回调结束后检查最终页是否已满，再决定是否查询下一个前缀；零限额仍在查询前返回。页满后同一前缀已排名的剩余视图继续执行不物化文本的接纳判定，原循环也会在消费前构造全部这些视图。`prefix_lemma_views` 生产已无调用，收为仅测试的旧查询对照。

这些入口只暴露 crate 内部借用视图，闭包调用期间词库保持借用，最终候选仍由 provider 拥有，句子结果仍由矩阵输出持有。它不改变词库映射、预加载、模型生命周期或前缀筛选的边界。

## Alternatives considered

- **继续收集 `Vec<JapaneseLemmaRef>`** — 代码路径直接且能一次计算预测长度，但向量只服务当前查询，并为每个完整读音保留一份临时容器。
- **把预测词条缓存到 provider 字段** — 可以复用容量，但视图生命周期绑定词库而 provider 同时持有词库，形成自引用存储边界，且缓存会把单次查询状态带入跨查询状态。
- **让句子搜索接收预测输出回调** — 能省掉一个入口，但会把句子排序和 provider 候选编排耦合在一起；当前实现只让词库结果构造支持流式消费，保留两层职责。

## Consequences

- **收益**：空读音分支每个实际执行的非空前缀查询省一份视图向量，三词条合成 `k` 的 provider 热查询 5→3；零限额或未命中没有这项差值。完整日文预测查询直接把借用词条写入已有候选行，充分预热的合成查询分配从 15 次降为 14 次；待定查询每个命中前缀省一份视图向量，合成 `kak` 从 21 次降为 19 次；在精确流式合入前、句子容器已复用的基线上，继续补全使矩阵 16→15、provider 18→17；精确流式合入后的父基线上，本片为矩阵 14→13、provider 16→15。词条顺序和结果内容不变。
- **代价与已知上限**：完整读音候选缓冲按 16 条预测的上限预留空间，原实现按预测实际长度预留，因此少量或未命中预测可能保留更多行槽位；实际容量仍按 `Vec` 的增长规则决定。前缀和继续补全仍需临时排名存储，查询键与排名 ID 在回调消费期间仍由原泛型调用持有，句子搜索和最终候选仍按原路径拥有输出；空读音页满后仍会访问本前缀 24 条限额内的剩余视图；若后续隔离计时显示这项访问有显著回退，再考虑有停止语义的消费入口并重新验证排名与页满边界。这些入口只减少前缀与继续补全的视图结果向量，不代表完整日文查询零分配，也不据此宣称整段查询延迟改善。
