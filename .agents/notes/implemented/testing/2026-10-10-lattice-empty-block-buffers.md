# Agent Note: 词网格空句子输出块延后分配

Status: implemented

## Problem

词网格已解码出句子，但已有候选可以覆盖所有句子。线性与哈希去重分支仍提前为 `Generated` 输出块预留 `paths.len()` 个槽位；神经重排两条分支即使没有任何可添加行，也预留两个槽位。这些空块随后直接丢弃。

## Decision

输出块从 `Vec::new()` 开始，在首条确实可以添加的句子写入前，沿用原来的 `Vec::with_capacity(paths.len())` 或 `Vec::with_capacity(2)`。只改变空块分配；非空块的容量提示、候选字段、顺序、插入位置与重排重复规则保持一致。哈希集合与 64 条分流边界保持原样。

## 历史审计

[合并短列表去重](../../implemented/testing/2026-10-08-lattice-merge-dedup.md) 部分重叠，持有线性与哈希分流决定，本篇只约束输出块的分配时机，两篇互链。[终点路径去重](../../implemented/testing/2026-10-07-lattice-sentence-dedup.md) 作用于解码器终点而非输出块，无关并保留。检索 `lattice`、`句子合并`、`generated_block_linear` 与 `reranked_block_linear` 的其余活跃笔记属于跨度查词、纠错计划或九键排序，无相同决定。

## Alternatives considered

- 直接使用 `Vec::new()` 后不断 `push`，代码更少，但非空块首次扩容策略与旧容量提示不同，可能增加分配和返回存储。
- 先扫描是否全重复再保留旧收集器，可以避免空块分配，但非空输入重复做去重查询；首条保留行触发原容量预留只需一遍扫描。

## Verification

冻结 `4666d90faf5f13e40cde0a6152595b321d4bc785` 的合并入口及输出块逻辑作为对照，仅改名称、可见性并移除原注释。五项回归在旧实现上因空块容量或多一次分配而失败，改动后通过。生成块矩阵覆盖 0、1、2、5、64、65、128 条路径与批内重复；重排矩阵覆盖无键盘、空键盘、反向排名、两种重复策略与是否包含字面最优行。非空块全字段、容量和分配次数与对照一致。

真实合并入口使用完整拼音 `a'ba` 与 `a'ba'ca`、合成词条和占位候选，跨过 64 条线性/哈希边界，包含 `emit = 0/1`、实际运行的合成神经重排及非空纠错返回。准备和全局表初始化在计量前热身；普通两音节全重复合并分配 50→49，带合成神经模型和纠错边的三音节全重复合并 161→160。整个入口的逻辑请求字节峰值在这些场景中没有下降，解码器先前的峰值更大。

## Consequences

全部句子重复或重排选项不允许输出时，输出块零分配；非空块保留原容量提示，代价是首条保留行前的条件判断。哈希桶和解码器的其它分配仍然存在。线程局部计数与请求字节不等于 RSS 或延迟；本片只证明对应空块每次少一次分配，不把收益泛化到所有按键。冻结对照是测试维护成本，生产后续若修改合并语义，应有意识调整回归约束而不追着生产代码改旧对照。
