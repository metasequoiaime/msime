# Agent Note: IBus 监督器测试按等待请求验证退避

Status: implemented

## Problem

全拼路径页压缩的普通 push 门禁中，`linux-ibus-launcher-supervisor` 观察到三次宿主启动间隔为 2.052、4.060、10.636 秒，最后一次超过测试为 8 秒退避预留的 1.5 秒上界。间隔还包含进程创建、解释器启动和系统调度，不能据此认定监督器请求了错误等待。测试另有依赖固定短等待的信号就绪判断，以及升级、停止的墙钟上界。

## Decision

只在测试夹具的 `PATH` 中提供受控 `date` 与 `sleep`。短命宿主场景的时间固定，普通等待记录秒数与已启动宿主次数后立即结束，真实启动器仍决定退出码、退避翻倍、升级与重启参数。停止退避场景让等待进程一直阻塞到收到信号，测试观察就绪和信号记录；未终止等待会超时，不能靠很快跑完退避蒙混通过。宿主信号处理器就绪后再发布状态，测试按状态等待。

首轮最后一个宿主启动前故意延迟 2 秒，保留本次调度迟到的回归场景。正常与升级场景精确核对等待请求及对应的启动次数；升级时多一次等待也会失败。停止场景的等待不自行结束，因此遗漏信号转发会卡住而被超时检出。生产启动器和公开配置不增加测试开关。

## Historical audit

检索活跃 proposed、implemented、rejected 的监督器文件名、崩溃守护、IBus 退避与启动器，没有既有时钟隔离决定。[IBus 按需激活](../../implemented/bug-fix/2026-10-20-linux-ibus-demand-activation.md)持有静态组件总线名与真实 daemon 验收；[Windows 本地门禁](../../implemented/testing/2026-10-14-windows-local-gate-portability.md)持有平台兼容和独立临时目录，两者均不持有本测试的计时策略。其余皮肤、WebKit 与图标笔记无关，没有完全吸收项或过时提案。

本次问题由[全拼路径页压缩](2026-10-23-quanpin-path-page-compaction.md)的门禁暴露，部分重叠；那篇继续持有产品表示和原性能证据，本篇只持有监督器测试的时钟与生命周期策略。

## References

Python 官方 [sleep 文档](https://docs.python.org/3/library/time.html#time.sleep)明确允许调度使等待任意延后；[CPython 的时间测试](https://github.com/python/cpython/blob/main/Lib/test/test_time.py)也没有为一般 sleep 设调度时延上界。夹具复用本文件的条件轮询与临时目录，不增加依赖。

## Alternatives considered

- 放宽墙钟上界：改动最小，能容纳这次负载，但调度延迟没有固定最大值，会留下同类失败。
- 只删除上界：保留真实等待和最小等待检查，容易审查，但升级跳过等待和停止打断等待仍依赖调度时长，整组还要真正等完多轮退避。
- 给生产脚本增加测试时钟环境变量：注入直接，但会为测试扩大产品配置面；命令边界已可在夹具隔离。

## Verification

迟到 2 秒的场景先在旧断言下失败，三个间隔为 2.023、4.039、10.038 秒。受控时钟下完整脚本通过，用时 4.17 秒，保留 2、4、8 秒翻倍、升级保留退避、停止码、配置和宿主失效、三种停止信号与退避中断覆盖。将最小退避改成 3 秒、在升级分支插入等待，分别触发精确请求序列断言；删除对等待进程的停止转发则触发超时，夹具清理进程组，三个错误变体均被检出。

红、绿、错误变体与完整门禁记录封存在[验证目录](../../../../docs/measurements/2026-10-24-ibus-supervisor-controlled-clock/README.md)，与路径页原有性能证据分别保存。

修正后的完整本地 quick 用时 1738.943 秒，退出 0。Windows 本机原生逻辑 176 项通过；契约、1751 篇笔记与 4 项归档封印、Rust workspace、Android target 与 Java、两种 WASM、Linux 桌面壳和原生宿主、macOS 原生宿主与 Apple 桥接层通过。Linux 的 111 项注册测试中 110 项通过、按需激活因缺少真实 daemon 依赖沿用原规则跳过；监督器用时 4.18 秒，主题提示用时 8.22 秒。Windows 完整构建和 HarmonyOS 真工程因缺少环境跳过，没有设备装机验收。

## Consequences

这组测试验证监督器的等待决策和进程生命周期，不再测操作系统 `sleep` 实现的计时精度。用可观察的等待请求取代真实退避，使整组不必等满 2、4、8 秒等多轮退避；代价是在私有 `PATH` 中维护两个命令夹具。逻辑时钟固定只适用于本组短命宿主，不覆盖健康运行 30 秒后的退避重置。真实 IBus 框架的装机与崩溃恢复验收仍由原有平台验收承担，不能以本夹具声称完成设备验收。测试失败时清理自己启动的进程组，避免受控阻塞进程残留。
