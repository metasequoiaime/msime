# Agent Note: 自动纠错候选标记延迟折叠原始输入

Status: implemented

## Problem

`mark_autocorrect_candidates` 在每次候选查询中都会先调用 `fold_reading(raw)` 创建折叠后的原始输入，即使候选列表没有任何行需要写入 `corrected_from`。普通输入和没有匹配纠错行的查询因此承担了一次无用的字符串分配。

## Decision

候选标记先完成已有的切分比较，只在找到第一个需要标记的候选时通过 `get_or_insert_with` 创建折叠后的原始输入；后续匹配行继续复用这一个字符串的克隆。所有纠错判定、已有标记保留和字段内容保持原有行为。

## Alternatives considered

- 保留无条件折叠：实现最简单，但每次没有匹配候选时都会付出一次分配，和热路径的实际需求不符。
- 为每个候选单独折叠原始输入：会重复分配，无法复用同一次标记操作的结果。
- 改变 `corrected_from` 的所有权或公开接口：可以进一步减少克隆，但会扩大候选数据契约的改动范围，当前切片没有必要。

## Verification

新增分配计数测试，证明没有匹配候选时标记路径不分配；既有纠错标记测试覆盖匹配、无差异切分、别名改写和保留已有标记的行为。实现后运行相关 `msime-engine` 测试、完整引擎测试、Clippy、Rustfmt、差异检查、笔记检查和 quick 门禁。

## Consequences

没有匹配候选时省去一次折叠字符串分配；有匹配候选时仍只创建一次折叠字符串，并为每个被标记行复制到其公开字段。代码增加了一个延迟初始化状态，但不改变候选排序、标记条件或缓存内容。
