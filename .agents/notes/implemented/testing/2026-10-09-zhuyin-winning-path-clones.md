# Agent Note: 注音转换只复制能改善路径的缓存词条

Status: implemented

## Problem

注音转换在比较路径分数之前，先复制区间命中的读音键和词条文本。二十音节、每种区间长度都有词条的合成热缓存转换查询 210 个区间，实测分配 421 次，其中 380 次来自随后败选的字符串副本。

## Decision

转换器提供内部筛选入口，把当前终点的分数比较作为词频谓词传给查询方。编辑器在缓存词条的借用期间先应用歧义权重下限，再检查路径是否严格改善，只有改善时才复制词条。公开 `convert` 接口仍接受原来的拥有词条回调，通过适配器复用同一转换过程。

查询结果区分缺失、败选和拥有词条。败选不能进入单音节兜底，否则负词频词条被丢弃后可能用零权重的读音改变最佳路径。每个原有区间仍查询一次，查询错误照常传播；不因为已知长度分数会败选而提前跳过查询。

## Alternatives considered

把整个缓存预热后再交给只读转换器能直接返回借用，但会为冷热交错的按键转换增加一轮描述构造和缓存查询。把词条改成共享所有权可以廉价保留候选，但会增加冷缓存对象分配和热路径引用计数，并改变结果类型。词频谓词沿已有缓存回调传递即可减少败选复制，同时保留转换结果和公开接口。

只在最终回溯时复制词条能进一步减少中间胜选副本，但需要再查询胜选区间或把词条借用跨缓存插入保存，扩大查询时序与生命周期契约。本切片在原有单次查询顺序内筛选，保留路径拥有字符串的边界。

## Consequences

合成密集命中转换的分配从 421 次降到 41 次：首次改善二十个终点的词条仍各复制两个字符串，结果向量仍分配一次。冷查询的缓存插入、缺失单音节兜底、钉住词条及中间胜选路径仍可能分配；这里不声称真实打字延迟同比下降。

内部查询入口增加词频谓词和三种结果状态，改善词条的分数在写入路径时仍按原规则核对。长度优先、饱和词频相加、同分保留先到路径、跨 pin 禁止和超过组合上限的动态路径表都保持不变。

## Verification

`warmed_dense_conversion_only_clones_improving_paths` 在旧实现实测 421 次分配并违反 41 次预算，优化后通过。删除合成夹具的词条表后仍能重算，证明测量走热缓存。额外用例覆盖缓存败选与缺失的区分、负词频、同分与饱和分数以及败选区间的查询错误传播；注音单测、引擎单测、golden、Clippy、格式、笔记和 quick 门禁验证本切片。
