# Agent Note: 运行时接入单次前向的前馈缓冲复用

Status: implemented

## Problem

主项目固定 `328e348374`、上游固定 `cc1d3dd` 的九键二十秒采样中，`linear` 与 `dot_i8` 仍是主要热点，申请和释放也出现在实际调用树。九键 16 ms 预算仍未达到；采样扰动后的成绩不能用于预算验收。上游已验证单次前向内跨层复用前馈缓冲，需要固定正式合并提交接入并检查主项目结果。

## Decision

接入已合并的上游 [PR #62](https://github.com/metasequoiaime/chinese-ime-lm/pull/62)，两个 crate 清单、主锁文件与 fuzz 锁文件统一固定 `6ce2cbb5b76e189a1ef6ff11eaa0435bfd9983a0`。仅复用一次 `run_prefix` 或非空 `run_tail_states` 内的归一化、隐藏层与投影存储，不跨调用持有，不改变数值运算顺序、公开 API、权重或缓存寿命。

## Existing decisions

已检索活跃笔记中的前馈、`feed_forward`、前向工作区与前向缓冲。[最终 KV 直接构造](../../implemented/testing/2026-10-16-runtime-rerank-packed-kv.md)只决定 KV 存储，[投影行遍历](../../implemented/testing/2026-10-16-runtime-project-row-stream.md)只决定完整词表投影，[共享归一化](../../implemented/bug-fix/2026-10-15-runtime-rerank-normalization-reuse.md)约束状态投影寿命；三者部分相关且保留。上游不持有跨轮前向工作区的决定不翻转。没有完全吸收的笔记或过时提案。

## Upstream verification

上游[固定提交笔记及全部整表](https://github.com/metasequoiaime/chinese-ime-lm/blob/6ce2cbb5b76e189a1ef6ff11eaa0435bfd9983a0/.agents/notes/implemented/testing/2026-10-16-feed-forward-scratch.md)保留全部红绿和测量证据。完整六层前馈链的 12 种形状各 40 对，计入输入复制、构造和析构，量化 192 宽单行新/旧中位比 0.9848，其余 0.9837–1.0020，全部预设门禁通过且没有并行构建。Float/Quantized 边界几何与真实模型前缀、尾部 KV、隐藏状态、完整分布逐位一致；Rust 1.97.1 / 1.75.0 各 35 单测、15 模型文件测试和 doc tests，以及全目标 Clippy、fmt 与独立审查通过。

上游合并时，完整模型多次旧/新整表尝试都遇到其他会话构建，全部作为受干扰观察保留；当时无构建重叠的完整模型整表对照尚未完成。主项目在全部门禁和九键四轮测量结束后补齐无构建重叠的旧/新整表，见下节。没有证明稳定整体收益，本片收益依据仅为无干扰的完整六层配对预算和数值回归。主项目端到端延迟需独立记录，不能换算成九键 16 ms 达标。

## Alternatives considered

- 主项目复制实现：便于直接调优，但会使模型实现和数值契约分叉，继续由上游持有。
- 跨按键持有完整前向工作区：可复用更多申请，但会增加缓存状态及持有内存；本片只接入单次同步调用内的局部缓冲。
- 直接依赖上游分支：可以更早接入，但无法固定审查和验证对应来源，继续使用合并提交。

## Main verification

主项目基线 `46c818e253`，上游固定 `6ce2cbb5`。以 `env -u MSIME_EVAL_RESOURCES` 避免把只含评测资源的目录当作完整测试资源，`MSIME_NEURAL_MODEL_DIR` 指向固定真实模型：`cargo test -p msime-engine -p msime-input-runtime --locked --no-fail-fast --quiet` 通过 2166 个引擎单测、31 个 golden、294 个运行时单测及 doc tests，33 个既有忽略项。全目标 Clippy `-D warnings`、全仓 Rustfmt、release `convert_eval` / `rerank_latency`、笔记和差异检查通过。

全拼 60 例、九键 81 例的 `convert_eval` JSON 用 Python 载入后与上一片 `328e348374` 的报告整体相等，全部分组、失败样本及来源桶保持；全拼 top1/MRR 为 0.833/0.842，九键为 0.617/0.640。两者加载同一实际模型，没有 settled 模型；未更新质量基线。

本地 `env -u MSIME_EVAL_RESOURCES CARGO_BUILD_JOBS=4 MSIME_BUILD_JOBS=4 bash scripts/verify-local.sh --quick` 通过：Rust 工作区、Android/WASM 目标、Android Java 宿主、macOS 原生宿主和共享 Apple bridge 均构建。Docker、MinGW 与 HarmonyOS 完整构建前置缺失的阶段明确跳过；没有平台 GUI 或 Android 设备验收。本片没有改变文件读写、权限或 Android 资源。

独立只读接入审查确认四处 pin 一致、无额外依赖变化；其指出的完整模型受干扰说明已补入本笔记，没有把未完成项记为通过。审查者没有运行构建或计时。

## Runtime latency

本任务全部构建、测试、quick 与质量评测终态后，固定模型、九键 81 例及 release 二进制，按旧、新、新、旧串行运行。每轮每臂 1791 键、丢弃 5 个预热 case，16 ms 预算不变。每秒监测四轮均未观察到并行构建；每轮退出 1 均已核对是 p95 超出预算，而非运行错误，二进制哈希测前测后保持。

旧臂来自 `328e348374` 主工作区，SHA-256 `b783a77d9a92f345e3a1c62a46f7291d754906f5adf29738cb37d767aef38c38`；新臂来自 `46c818e253` 加本片 pin，SHA-256 `99a36eec8a0a8acca8e1e7d89e377c86d371522fa9fd6c7e2c57a2b37eb095c0`。两份主项目基线之间的 engine、input-runtime、工作区清单、锁文件和评测集无其他差异。

| 旧 1 | 3.65 / 7.06 | 6.71 / 17.79 | 3.06 / 12.08 | 31.12 | 131 |
| 新 1 | 3.93 / 7.77 | 6.97 / 17.93 | 3.04 / 12.01 | 31.52 | 147 |

新版两轮模型臂略慢，纯引擎臂也更慢；配对增量均值 3.04/3.07 ms 落在旧版 2.92–3.06 ms 附近。本组没有证明端到端提速，也不能单凭纯引擎同步变慢就排除回退；保留全部尖峰，不挑样本。局部收益依据仍是无干扰的完整六层配对门禁。九键 16 ms 预算未达到，目标继续 active。

## Full model recheck

固定相同模型 SHA-256 `86ac529510cb3b4968a5e6ade83ec8080f5b34a0a681e75c362accbbd387d1c1`、九键 81 例，直接运行上游 release `bench`，每形状 40 次。旧版干净 `cc1d3dd` 二进制 SHA-256 `3c80574a2edf519a6c7ab32b524f54bfc775ddc9f2a4ed02a12087b2c5f48219`，保存后在同一规定构建目录构建已合并的 `6ce2cbb5`，新版 SHA-256 `02f1630064e4c58e8f1f85d7143f8a56b3808e8bb8ab779f721a0054cde47980`，与上游最初 worktree 的新版二进制相同。构建终态后旧、新串行，两个进程都退出 0；每秒监测各轮并行构建观察数均为 0。

十五字决策列没有样本，0 值无效；逐句十五字行也不能解释成真实十五字决策。以下保留所有表与尖峰，各一轮仅作观察，不能证明稳定整体收益，更不能换算成九键 16 ms 达标。

## Consequences

单次前向内减少重复申请，完整六层量化 192 单行主形状配对约少 1.5% 耗时。局部配对收益不能换算成九键端到端收益。5N 个 f32 容量跨下一层 attention 存活，不能宣称完整前向峰值内存下降。模型和候选缓存寿命必须保持。
