# Agent Note: 光标入口复用编辑文字长度判断

Status: implemented

## Problem

会话在字符输入、退格和网址触发判断中，需要判断显式光标是否位于编辑文字内部或末尾。入口仍通过 `editing_text()` 构造完整字符串再取长度；进入实际光标编辑后，编辑函数还会再次构造同一文字。普通拼音的编辑文字长度已经可以直接从会话状态读取。

## Decision

将这三处长度判断改用 `editing_text_len()`，保留光标越界截断和末尾网址触发语义，同时让光标输入路径只构造实际编辑所需的一份文字。

## Alternatives considered

- **继续完整构造编辑文字**：代码简单，但在每次光标输入前做一次无用字符串分配。
- **缓存完整编辑文字**：可以覆盖更多调用，但需要在引擎刷新、方案切换和本地模式变化时维护失效，扩大状态边界。

## Consequences

- 普通拼音在中间光标输入的分配次数不超过 283。
- 现有光标、退格、网址触发、越界光标和各方案编辑行为测试继续通过。
- 格式、Clippy、笔记门禁与本地 quick 门禁通过。
- `editing_text_len()` 与 `editing_text()` 对每个本地模式和输入方案保持相同的字节长度语义；越界光标仍按编辑文字长度判断。
