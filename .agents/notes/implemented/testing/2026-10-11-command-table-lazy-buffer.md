# Agent Note: 宿主命令表延后缓冲

Status: implemented

## Problem

`crates/engine/src/local/command.rs` 的 `usable_command_table` 在验证宿主命令表前预留结果 `Vec`，长表还会预留触发词去重 `HashSet`。输入全部无效时，这两个容器都不会产生有效结果却仍会分配。

## Decision

短表的结果容器从空 `Vec` 开始，首条有效命令加入前按原输入上限预留。长表的结果容器和触发词集合都延后预留；遇到首个合法触发词时仍先建立去重状态，以保留无效模板占用触发词的既有语义，首条可输出命令再申请结果容量。过滤、去重、启用顺序、截断和有效结果容量保持不变。

## Alternatives considered

- 保留过滤前的两个预留：命中路径少一次判断，但全无效宿主表会承担不会使用的存储。
- 先验证模板再写触发词集合：可以进一步少量分配，但会改变无效模板阻止后续同触发词命令的现有行为。
- 按每条有效命令自然增长：可降低稀疏表容量，但会引入扩容并改变有效结果容量提示。

## Verification

新增全无效长命令表的零分配回归；旧实现产生 2 次分配，修复后为 0。随后运行命令模块、引擎全量、Golden、Clippy、格式、差异检查、笔记校验和 `bash scripts/verify-local.sh --quick`。

## Consequences

全无效宿主命令表不再申请结果或去重缓冲；合法触发词仍按原规则参与去重，首次有效命令继续按输入上限准备结果容量。
