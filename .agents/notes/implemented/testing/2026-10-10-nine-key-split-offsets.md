# Agent Note: 九键切分偏移使用固定栈数组

Status: implemented

## Problem

九键每次刷新都会把用户输入的绝对切分位置减去已锁定长度，并收集到临时 `Vec<usize>`。切分数量受 32 个数字的输入上限约束，但逐键刷新仍为这组有界偏移分配堆缓冲。

## Decision

按 `DIGIT_LIMIT` 在栈上准备固定偏移数组，直接填入相对切分位置并把有效前缀传给读法路径。切分位置的排序、边界和查询结果保持原样。

## Alternatives considered

- **继续 `collect` 到 `Vec`**：逻辑简短，但每次带切分刷新都产生临时堆分配。
- **在会话中增加可复用的 `Vec` 字段**：可以复用堆容量，但增加状态字段并让临时查询缓冲跨刷新保留。
- **使用无上限的动态数组**：无法利用九键数字输入的既有 32 位上限。

## Verification

新增刷新分配回归：合成词库中相同数字输入的无切分刷新作为基线，带一个切分的旧路径产生 152 次分配并超过 151 的预算；固定数组路径通过预算并保持少于无切分基线。相关九键测试、Engine 全量测试、Clippy、Rustfmt、差异检查、笔记检查和 quick 门禁覆盖提交。

## Consequences

带切分的九键逐键刷新不再为相对边界建立临时 `Vec`，其余词典查询和候选排序仍按原路径执行。
