# Agent Note: 九键神经重排缓存命中借用候选行

Status: implemented

## Problem

九键神经重排每次刷新都会收集最多 12 条词网格整句。缓存命中时，当前实现仍复制每条候选的词面和静态权重构造签名，再把缓存里的排名字符串复制到新的临时 `Vec`；命中只需要比较当前候选行并读取已有排名，重复拥有这些数据会增加按键线程的堆申请。缓存未命中和没有模型时仍需要维持原有路径。

## Decision

缓存匹配按上下文、候选数量、词面和 `comparable_weight` 逐项借用比较，不创建签名。命中时直接借用缓存条目的排名切片；未命中时才拥有签名、构造 `SentencePath` 并把模型结果直接移入缓存。模型调用、候选顺序、去重、词网格开关和无模型时移除整句行的行为保持不变。

## Alternatives considered

- 为候选签名建立跨刷新哈希：可以把比较变成整数键，但要维护哈希碰撞处理和失效规则；当前最多 12 条逐项比较无需新状态。
- 只去掉签名复制：仍会在命中时复制缓存排名到临时向量，保留另一项堆成本，因此同时借用排名切片。
- 提高缓存容量：只能增加命中率和常驻内存，不能减少命中时已经发生的复制。

## Verification

缓存命中匹配测试在分配计数器中为零；九键相关测试 131 项通过，engine release 测试 2136 项、golden 31 项通过，input-runtime release 测试 288 项通过；Clippy 全目标和 fmt 通过。固定资源九键无采样配对测量模型臂 p95 为 20.13 ms，基线同机测量为 22.05 ms，但这两次运行受主机调度影响，不能把差值归因于本项；十六毫秒门禁仍失败。

## Consequences

逐项比较会读取候选词面，缓存条目保存的签名仍需拥有字符串；候选数量最多 12 条，比较成本有界。缓存排名切片借用期间不能修改缓存向量，代码保持字段借用范围清晰。签名比较同时检查上下文、长度、词面和静态权重，避免错误复用排名。没有修改模型文件、文件读写、目录遍历或 Android 资源，因此没有设备验收结论。
