# Agent Note: 拼音切分批次键去重的小列表路径

Status: implemented

## Problem

`query_exact_segmentations_keyed_flat` 在批量查询前用 `HashSet` 和重复索引数组去重切分键。模糊查询的路径预算有限，但这个数据库接口也允许更大的批次。

## Decision

切分键不超过 16 条时，直接按键扫描已保留项并原地压缩；更大的批次继续使用哈希表回退。只比较键字符串，保留首次出现以及后续按表分组顺序。

## Alternatives considered

线性扫描无需哈希及临时状态，对很短的批次有优势；实测 64 条全唯一键反而从约 2.0 µs 升至 4.5 µs，因此放弃 64 条阈值，采用 16 条。大批次保留哈希表，避免平方复杂度；只缩小哈希表仍会保留集合和临时索引分配。

## Verification

新增 16 条切分键的零临时分配测试，以及 0、1、15、16、17、64、128 条输入在边界两侧的首次保留和容量测试；既有批量 SQL、重复切分和跨表排序测试继续覆盖查询行为。

独立优化构建的合成基准排除输入构造，9 轮各 1024 批次取中位数：9 条全唯一键约 294 ns → 91 ns，16 条约 501 ns → 285 ns；原哈希路径各分配 1 次，线性路径 0 次。这是辅助函数的本机测量，不代表完整查询延迟。旧笔记分别覆盖行值、候选词和终点句子去重，与本次切分键批次没有相同归属。

## Consequences

16 条以内的去重时间复杂度为平方级，但模糊路径和常用批次都处于受控范围；大批次继续走哈希表路径。
