# Agent Note: 词网格直接借用两组出边

Status: implemented

## Problem

固定 `30643d802c5c5d079f0047cc92f327c09a0783d0` 的 `decode_graph` 在每列把主图与附加图的边引用复制进 `Vec<&Edge>`，之后只读。跨列复用仍至少需要一次分配和逐列指针写入，不可达列也复制。已有九键采样确认解码是大热点，本项只处理其临时存储，不将采样延迟当无采样成绩。

## Decision

每列借用主图与附加图的两个切片，以可克隆的标准 `Chain<slice::Iter, slice::Iter>` 按主图在前的顺序遍历。每个评分行和假设从相同初始迭代器开始；评分行仍按两切片总长度预留。保持前词行索引、备忘访问、评分算术、搜索顺序、剪枝、平局、回溯与返回容量。

## Historical audit

按 outgoing、出边、向量、借用及临时缓冲检索活跃笔记。[二元行复用](../../implemented/testing/2026-10-11-lattice-bigram-lazy-reserve.md)部分重叠，继续负责评分行生命周期。[列容量](../../implemented/testing/2026-10-15-lattice-column-capacity.md)部分重叠，继续负责假设列容量，其主图/附加图链式遍历是同仓库参考。没有另一条出边向量借用决定。[前缀散列实验](../../rejected/testing/2026-10-15-lattice-bigram-prefix.md)负责键构造且保持拒绝，不恢复候选。

标准库 [Chain 文档](https://doc.rust-lang.org/std/iter/struct.Chain.html)确认两个迭代器按序串联，底层可克隆时 Chain 也可克隆。不引入依赖或自制迭代器。

## Alternatives considered

- 保留指针向量：内层遍历连续指针数组，无须重复判断切片边界，原路径已验证；但仍分配和逐列复制，且多一次间接读取。须以配对计时约束借用入口的边界成本。
- 每次重新构造带 flat_map 的附加图迭代器：可复用原表达式，但内层保留额外 Option/flat_map 状态。每列先借用两个切片更直接。
- 无附加图才借用：普通路径直接切片遍历，但保留两种流程和临时容器；先验证同一借用入口是否符合预算。

## Verification contract

原实现先在临时出边分配预算上失败，再要求非空单列图至少省一次分配。复用 `decode_prefix_legacy_tests.rs` 的固定旧正文（与当前生产入口相同），比较完整字段、评分位模式、备忘、返回容量与分配请求，覆盖表、冷热备忘、三元/个人模型、附加图、不可达列及空列。每形状 release 配对四十对交替先后，最快批次校准至少 50 ms，中位新旧比严格小于 1.05；至多完整重复一次，不拼接两轮局部成绩。固定资源质量及无采样九键延迟另验。相关完整测试、Clippy、fmt、notes、quick 和 pre-push 通过后独立提交、推送、开 PR 并合并。

## Consequences

链式迭代有切片边界状态，编译器对短图与密集图的优化可能不同，不能因分配减少便断言更快。借用不跨解码，不改文件访问、权限、模型或格式。九键 16 ms 仍未通过，不降低搜索与质量预算。

## Initial verification

旧实现的分配预算真实失败：宽度 1 新旧均为 11 次申请、299 字节峰值、123 字节返回存储，未达到至少省一次的要求。借用后宽度 1/4/8/32/65 均精确省一次，峰值分别 299→267、788→756、1373→1309、4652→4396、6238→5718 字节，返回存储不变；这是 Rust 逻辑请求，不是 RSS。debug 聚焦两项通过，覆盖主图起点清空但后续仍有边的不可达形状，附加图可以重新接通。

机械核对共享固定旧解码正文与 `30643d802c` 一致。首次完整 release 测试只有两条旧回溯分配等式失败，实际节省都比旧预算多一次。`decode_return_tests.rs` 现明确核对原回溯节省加本次出边缓冲的一次申请，保持精确等式；不把它放宽成不等式。生产逻辑未因调整测试改变。

设置固定资源为 `MSIME_NEURAL_MODEL_DIR`、移除 `MSIME_EVAL_RESOURCES` 后重跑两 crate 完整 release：引擎 2129、golden 31、runtime 288 项通过，失败 0、忽略 26。历史日文资源要求按原测试处理，不修改其期望。release 单测仍使用项目的线程局部计数分配器，配对结果需结合使用正常分配器的端到端程序解释。
