# Agent Note: 日文行生命周期的短批次配对计时

Status: implemented

## Problem

[已消费行释放](../../implemented/testing/2026-10-10-japanese-consumed-row-release.md)降低长未知输入的逻辑堆峰值，但三轮长批次计时有方向反复和明显回退。分别取旧新批次中位数再相除，可能把随时间变化的负载混入差异；仅待定键控制也有大幅波动，仍不能据此排除延迟风险。

## Decision

`cfg(test)` 的 `row_lifetime_tests` 冻结 `4c867d6be89579e603938797b18ba2369a2ffbfb` 搜索完整正文，用同一个 `#[inline(never)]` 核心和运行时策略隔离行生命周期。完成全部精确跨度和未知回退之后，`Retain` 恢复整行，`Drop` 释放整行，`Clear` 清空全部 `Node`/`String` 后恢复空 `Row`、保留 `Vec` 容器。第四个 `Production` 策略调用当前生产冷查询入口，所有路径通过共同的不可内联包装。三轮历史数据中的生产为已消费行整行释放，没有显示清空策略的有效优势；当前生产由[矩阵滚动行](2026-10-10-japanese-rolling-rows.md)限制物理行并复用空容器，并由[滚动字节边界](2026-10-10-japanese-rolling-boundaries.md)限制局部字节位置存储，仍立即释放已消费文本，三种共同核心保持冻结。

每个输入和限额在计时之外预热并核对完整结果、总分配、返回在用请求字节和峰值。四策略全部 24 种排列各执行十次，每种策略在每个位置出现六次、每对策略的先后各十二次，每遍轮换排列的起始偏移。每组四份耗时对应相同迭代数，共 240 组；六对比值逐组计算后取 p10、中位数和 p90，包括 `Clear/Drop`、`Production/Drop` 和 `Production/Clear`，不拿独立中位数相除。分位数是本次样本分布，不是置信区间。

短输入每批 32～64 次，32 字符每批 2～4 次，128 字符四次、512 字符一次，仅待定键 256 次，空与所有 limit0 统一 2048 次。参数和结果用 [`black_box`](https://doc.rust-lang.org/std/hint/fn.black_box.html)，输出在计时区间内销毁。样本向量提前分配，统计与打印均在区间外；另报告每种策略批次绝对耗时分位数和 256 个空计时区间。基准默认忽略，不设 CI 时间阈值。

第四对照仍在 `cfg(test)` 二进制中，既有 `CountingAllocator` 即使关闭统计仍在 `alloc/dealloc` 访问 TLS。它能显示共同核心分支与代码布局造成的差异，不能消除测试分配器对析构时机的影响，也不能代表非测试生产构建的实际延迟。共同核心冻结搜索正文，但继续调用当前 `Row`、`Output` 与词库方法；后续改动这些共享方法时仍需检查隔离边界。

## 既有笔记审计

已检索活跃笔记的行释放、历史行、配对、短批次、微批次与 row lifetime。已消费行释放部分重叠，互链且保留原三轮证据；固定八槽行仍被否决，不重启该方案；精确及 continuing 流式词条、末行文本转移和输出容器复用约束保持，无同类配对计时决定，其余命中属于其它模块且无关。本片只增加实验，不改旧冻结对照的搜索正文。

## 内存与结果

三策略都先恢复整行的占位实现使两项真实红测试失败：生产峰值 1062 对实验 `Drop` 的 1362、32 字符 limit1 的 11916 对 14024。实现三种生命周期后，全部完整候选、成本、次序、分配次数、返回存储相等；计量最低 signed 差值全部为零。覆盖稀疏与密集、负成本、平局、连接成本、重复词面、十六字符跨度、Unicode、待定别名和 limit0/1/2/8/16/32；长输入严格守住 `Drop`、`Clear` 比 `Retain` 峰值低的断言。三种策略依然进行相同数量的分配，只有存储释放时机不同。

## Alternatives considered

- 延用十个长批次交替：采样开销小，已有可执行对照；单批几十至几百毫秒，旧新不同时刻的负载变化会混入独立中位数，不用于本次生命周期归因。
- 线程 CPU 时钟：能排除被抢占的等待，但需要新增仅测试的平台代码和 unsafe；本片使用标准 [`Instant`](https://doc.rust-lang.org/std/time/struct.Instant.html)、短配对及顺序均衡，保留墙钟和控制路径的限制，单调性不保证匀速。
- 为每个策略复制独立优化核心：更接近各自最终代码，却混入代码布局和编译器优化差异；共同核心隔离生命周期，真实生产第四对照暴露共同核心和包装成本。
- 将生产改为 `Clear`：未知 512 字符仅比 `Drop` 多保留 4088 字节，内存成本不高；三轮没有有效计时优势，维持较少存储的 `Drop`。
- 因内存收益直接认定没有延迟回退：已有确定峰值下降，但不能解释重复回退；保持内存优化同时补证据，不把本次没有重现当作旧风险已经完全排除。

## Verification

正文逐字核对固定基线通过，唯一正文差异为 `previous_row` 的可变性和行生命周期结尾；冷 `Output` 构造与原冷入口相同。新增三个普通测试通过，一个本地基准默认忽略。组合后的完整引擎 1498 项、golden 31 项和 Clippy 全部通过，8 项本地基准默认忽略。独立设计及实现审查确认所有权、排列均衡与计量边界，提出直接 `Clear/Drop` 输出后已补齐六对配对比值。

完整 quick 门禁退出 0 并报告 `quick check passed`：共享 Rust、Android 目标与 Java、Linux 桌面共享层、Linux 原生宿主 73 项测试与五笔版构建检查、macOS 原生宿主和 Apple bridge 通过；Windows 本机 102 项测试、HarmonyOS 设置页打包检查通过。Windows 交叉与 pipe-only、WASM、HarmonyOS 原生 ArkTS 因工具链或前置资源缺失明确跳过，未做设备验收。Rustfmt、差异和 357 篇笔记校验通过。

分支包含最新 `2f2aafa02` 的宿主 API 与移动端已合并改动，引擎源码与本片固定来源保持一致。组合后的完整 quick 再次退出 0，覆盖面和明确跳过项与上述首轮相同；没有重复采集未变化的引擎基准。

## Consequences

行生命周期有可复现的短批次共同核心实验，旧长批次的回退证据继续保留。结果和存储边界严格约束实验可比性，三轮支持保留当前 `Drop` 策略；本片没有改变生产算法、缓存、行布局或公开接口。

代价是新增仅测试冻结正文和配对基准的维护成本。`black_box` 是尽力而为的优化屏障；`Instant` 包含 OS 调度与频率变化，均衡和短批次不能保证环境隔离。测试分配器、布局与外部负载仍是限制，真实发布构建的延迟风险尚未完全排除，不能宣称所有输入更快或旧回退均为噪声。

[矩阵滚动行](2026-10-10-japanese-rolling-rows.md)让第四个生产对照另包含容器复用：三种实验策略的次数仍严格相等，生产加回非零限额下 `字符数减16` 正部的独立行容器分量和实测旧边界容器分量后与它们相等，返回在用字节仍相等，生产峰值不高于 `Drop`；长未知输入严格低于 `Drop`。ignored 输出标注生产含滚动行与边界并分别打印四策略次数，以上三轮历史数字不归因于后续滚动存储。
