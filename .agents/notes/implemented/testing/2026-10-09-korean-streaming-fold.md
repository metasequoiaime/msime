# Agent Note: 韩文折叠直接写入复用输出

Status: implemented

## Problem

韩文 `compose_into` 和 `KoreanScheme::handle_key` 在每次刷新或按键时调用 `fold`，先分配完整 `Vec<Syllable>`。按键提交又经 `split_finished` 生成临时字符串，再复制到已有的 `committed`。音节内部已经使用固定槽，但已有输出缓冲仍不能消除这些临时分配。

## Decision

现有状态转移由一次扫描的回调路径承载：每个已完成音节立即交给调用方，扫描结束返回最后一个仍可修改的音节。`compose_into` 直接渲染全部音节；新增只在引擎内部使用的追加接口把已完成音节写入 `committed`，并借用原按键切片返回开放音节的起点。原文仍是状态来源，不新增可漂移的持久自动机状态。

韩文模块是引擎内部模块；旧 `fold` 和 `split_finished` 在迁移逐键调用后失去生产调用，因此一起删除。分拆测试通过测试内的薄封装调用追加接口，继续验证完成文本和开放按键的既有行为；不为不存在的对外 API 保留物化结果或第二条路径。

## 历史笔记审计

[音节固定槽](../../implemented/testing/2026-10-08-korean-syllable-fixed-slots.md) 部分重叠：它约束元音与尾辅音的固定上限，本改动沿用这些槽，补充外层结果物化的成本与追加输出边界。两篇互链；固定槽笔记同步描述当前流式使用方式，并保留原先固定槽分配证据。其余韩文命中涉及候选提交、功能出口或候选刷新入口，与本决定无关。

## Alternatives considered

- **复用会话内的音节向量与临时字符串**：改动较小且热路径可零分配，但每个会话多持有完整中间状态，且合成接口需传递额外缓冲；渲染仅需当前音节和目标字符串，逐个发出完成音节更直接。
- **栈上保存短向量，长输入回退堆分配**：日常按键短输入可消除分配，但宿主恢复可以送入任意长度拼写，需要新增短长分支或容器依赖。流式扫描同样支持长输入并使用恒定的中间状态。
- **保留拥有型分拆接口与物化向量**：能保留旧内部接口的精确完成字符串容量，但调用者已经全部迁移，韩文模块并非公开 API。这条路径会成为死代码；直接删除，并通过追加接口检验原分拆行为。

## Consequences

音节中间状态使用恒定空间，不为逐键提交和请求刷新收集完整音节向量。追加接口仅在发出首个完成音节时按输入字节数的三倍预留上界，避免长恢复拼写反复扩容；没有完成音节时保留原提交且不预留。这个上界可能多于最终文本的精确长度，目标容量满足上界时热路径无需分配。不再存在生产音节向量；已无调用的内部拥有型分拆接口及其向量容量测试一起删除，完成文本与开放按键的语义测试保留。

完成音节只能在状态机原先的三个发出分支交给调用方，扫描末尾仍开放的音节作为返回值；尾辅音后接元音时最后一个辅音以原 `moved_at` 进入下一音节。方案依据返回切片的前缀长度删除已完成按键，与此前尚未取走的提交内容无关。回调借用与追加接口增加一处内部边界，但合成与提交共享一套转移规则，无需维护第二份自动机。

## Verification

旧实现的五项预算分别实测：热合成 1 次临时分配、冷合成 2 次分配、复用尾辅音迁移 2 次、八次热请求刷新 8 次、合成按键序列 39 次。初次修复后这五项预算全部通过，冷合成只分配返回字符串，其余测量零分配。直接追加接口另外覆盖既有提交前缀、空/全非布局输入、UTF-8 跳过字节、复合尾辅音拆分、128 次长拼写、原输入切片指针和冷完成文本一次预留。11172 个音节 round trip 同时覆盖新接口不会提前提交单个开放音节；全量引擎与门禁结果以本切片 PR 的最终验证记录为准。
