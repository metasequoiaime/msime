# Agent Note: 注音候选行缓冲复用

Status: implemented

## Problem

注音候选列表每次重查询都会把列表项重新构造成新的 `WordItem` 向量，之前的候选行和字符串容量随旧向量释放。列表保持打开时重复刷新会产生不必要的行内分配。

## Decision

重查询注音列表时取出已有的引擎候选向量，逐字段写回候选行并按列表长度截断或补齐；注音列表项的固定来源、方案和元数据由复制函数统一重置。首次生成和列表内容变化仍按需扩展。

## Alternatives considered

继续调用 `zhuyin_rows` 会为每一行构造新的 `WordItem` 和字符串；只保留外层向量容量仍无法复用行内字符串。把注音列表改成借用引擎行会跨越编辑器和会话的所有权边界。

## Verification

新增行复制零分配测试，以及打开注音列表后的重查询分配上限测试；完整引擎测试、Clippy、格式检查、笔记检查和 quick 门禁覆盖提交。

## Consequences

注音列表连续刷新可以保留现有候选行存储，减少候选列表打开期间的按键级分配，同时保持列表内容和方案元数据不变。
