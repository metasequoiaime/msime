# Agent Note: 混排表情查询借用前缀

Status: implemented

## Problem

普通表情查询已经使用 `QueryPrefixes` 借用小写输入，但 emoji 和颜文字混排路径仍把小写前缀复制成 `Vec<String>`。全拼混排按键因此为最多一个查询前缀保留了多余的列表和字符串存储。

## Decision

混排路径使用 `Cow<str>` 保留全小写输入的借用形式，只在大小写需要折叠时创建副本；把 `read_readings` 和 `query_readings` 改为接受可重复遍历的借用前缀迭代器。双拼仍按原顺序查询原始和归一化前缀，数据库回退查询继续复用同一组前缀。

## Alternatives considered

继续创建单元素 `Vec<String>` 会保留每次混排查询的临时列表分配；把双拼前缀强行放进固定拥有数组会复制不需要的字符串。让读取函数接受借用迭代器可以覆盖全拼和双拼，同时不改变九键已有的拥有型读法列表。

## Verification

混排 emoji、颜文字、双拼多前缀、目录缺失回退和查询上限测试继续通过；引擎相关测试、Clippy、Rustfmt 和差异检查覆盖实现。

## Consequences

全拼混排不再为前缀列表创建额外堆分配，大小写输入和双拼归一化仍按原规则拥有必要的文本；读法顺序、去重、权重和目录关键词保持不变。
