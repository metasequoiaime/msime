# Agent Note: 网址退回组字复用剩余文本

Status: implemented

## Problem

网址模式删除进入触发键后，会话把剩余文本分别复制到 `pending_sequence` 和 `pending_sequence_with_cases`，随后立即消费这两份字段。引擎写回接口本身接受借用字符串；常见全拼 `www.` 退回路径因此多两次中间分配。

## Decision

清空组字后直接借用剩余文本调用 `replace_active_raw_input`，按原顺序使在线请求失效并更新混合候选。`reset_composition` 已清空光标和待处理字段，直接写回与原来立即消费待处理字段的状态相同。保留完整原字符串，继续检测五笔码长截断并在必要时恢复网址模式。新增分配回归测试把全拼 `www.` 退回的预算限制为不超过 33 次，旧实现为 35 次。

## Alternatives considered

- **继续使用待处理字段**：复用已有编排入口且更新顺序集中，但这条同步路径立即消费字段，不需要为暂存而复制两份文本。
- **只把原字符串移入一个待处理字段**：改动局部且能少一次复制，但五笔截断后还需要原字符串恢复完整网址，必须增加方案分支或改变消费接口。

## Consequences

全拼网址触发键退回组字少两次堆分配，编辑文本和候选结果保持不变；五笔普通和混拼网址的截断恢复逻辑保持原路径。在线请求失效和混合候选刷新仍由会话负责，公开接口与待处理编辑流程保持不变。代价是回退入口直接承担这三步更新，后续修改组字写回流程时需要同时核对它与 `apply_pending_sequence` 的顺序。
