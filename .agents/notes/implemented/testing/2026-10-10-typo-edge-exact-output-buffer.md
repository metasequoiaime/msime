# Agent Note: 纠错边输出缓冲按实际行数预留

Status: implemented

## Problem

`lookup_planned_edges` 已经把纠错查词结果延迟到首次非空页才建立输出向量，但首次命中仍按 `planned.len() * TYPO_ROWS_PER_KEY` 预留。纠错规划最多有 96 个键，稀疏命中一两行时，返回结果只使用很小的一部分容量。

## Decision

查完并填充纠错缓存后，先统计计划键缓存中的实际行数，再按这个总数一次性建立 `Vec<TypoEdge>`。没有任何行时仍保持零容量；有行时容量正好覆盖需要克隆的边，不把计划键上限或每键行数乘进稀疏结果。查询顺序、缓存淘汰、字段克隆、罚分和边顺序保持不变。

## Alternatives considered

- 保留首个非空键的原容量提示：密集结果少一次扩容，但稀疏结果会长期持有最多 384 个边槽，不能解决这次热点。
- 依赖 `push` / `extend` 自然扩容：可以避免上限预留，但需要多次扩容，且容量会受分配器增长策略影响；缓存已经给出每个键的实际行数，先统计后一次分配更直接。
- 在每个键写入前逐步 `reserve_exact`：不需要第二次缓存扫描，但多个稀疏键会产生重复扩容和更多分配。

## Verification

新增稀疏首命中测试，断言 96 键规划只返回一条边且容量为 1；原有纠错边测试改为断言容量等于实际边数，并继续比较冻结实现的字段、顺序、罚分、缓存内容和空结果边界。覆盖全热空结果、真实数据库部分命中、缓存容量与淘汰、冷查询以及长输入守卫。

## Consequences

稀疏纠错查询释放未使用的输出槽，冷查询的返回存储和峰值下降；密集结果仍只分配一次，容量不超过实际边数。统计缓存行会多做一次只读查找，最多 96 个键，代价固定且不产生临时堆对象。容量属于内部实现细节，候选行为和纠错语义不变。

历史上的[纠错边收集缓冲按需预留](2026-10-10-typo-edge-lazy-buffers.md)记录了先延迟到首个非空页的阶段；本决定进一步替换其非空容量提示，保留该阶段的空结果和未命中缓冲优化。
