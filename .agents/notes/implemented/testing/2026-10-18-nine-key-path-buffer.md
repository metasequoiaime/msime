# Agent Note: 九键切分路径输出缓冲

Status: implemented

## Problem

九键会话每次刷新都会调用 `SpellingTable::split_paths`，重新创建最终路径页、路径容器和每条路径的音节字符串。候选与读音列表已经复用容器，但切分路径在相邻刷新之间仍反复申请相同容量，热刷新因此保留了可避免的分配。

## Decision

`SpellingTable` 向已有路径输出缓冲写入。输出路径数量变化时保留仍使用的 `Vec<String>` 槽位，截掉多余路径；覆盖每条路径时清空字符串并写入文本，只有新增槽位才创建字符串。空输出缓冲沿用原来的消费式 `collect`，保持冷查询的分配次数与容量；非空缓冲原地覆写。中间搜索仍每次完整重算，后续搜索页存储由会话工作区复用。九键会话从字段中取出该缓冲供一次刷新使用，完成候选构造后放回，保持路径排序、截断和字符串内容不变。

## Historical audit

已检索 `split_paths`、路径页、路径容器与路径链。现有[路径链](2026-10-16-nine-key-path-chain.md)负责中间页后继索引，[路径页延后预留](2026-10-11-nine-key-path-lazy-buffer.md)负责死路零页分配，[种子尾段](2026-10-17-nine-key-seed-tail-materialization.md)负责最终采用条数；这些决定继续有效，与本片最终输出复用部分重叠，互链保留。没有完全吸收的笔记或过时提案。

## Alternatives considered

- 继续每次返回新的 `Vec<Path>`：实现最简单，但热刷新无法复用路径容器和字符串存储。
- 只复用最外层 `Vec<Path>`：可以减少路径页扩容，但每条音节字符串仍会重复分配，不能覆盖主要热路径成本。
- 把路径缓存放进全局表：会让会话之间共享可变工作区，增加同步和生命周期复杂度，也无法复用每个会话自身的路径容量。

## Consequences

路径顺序、切分边界和输出上限保持不变；连续刷新可复用路径及字符串容量，减少热路径分配。刷新临时借出缓冲并在完成候选构造后归还，多余槽位被截掉，不进入候选结果。路径缓冲使会话保留上次输出的拥有字符串，代价是延长这些有界存储的存活期；空闲会话不会新增路径申请。首字母过滤、种子追加和单音节补充仍沿用原来的处理。

后续[种子组合在复制前检查重复](2026-10-18-nine-key-seed-dedup.md)保留尾段切分与普通路径输出规则，只消除重复组合的前缀复制和空尾段外层向量。

后续[搜索页工作区](2026-10-18-nine-key-path-scratch.md)在活动组字期间复用中间页容器，每次逆序覆写节点；冷输出继续消费根页，已有输出时保留根页，排序和死路不新增页申请的规则保持不变。
