# Agent Note: 九键英文前缀页直接追加

Status: implemented

## Problem

固定 `3a706bd021661aadcfcdf0cc477e28282c7928d8`，最新九键诊断仍有英文行解码分配。`english_candidates` 对每个前缀取得独立 `Vec<WordItem>`，逐行搬到总结果后释放临时页。字段有最终消费者，这个临时容器没有；每个非空成功页多申请一次候选存储。

## Decision

分组英文查询直接追加到总结果。普通英文仍用相同的可复用行解码；为解码增加目标起点和首次预留容量，NULL 跳过、值转换、失败丢弃整页及 LIMIT 行数均不变。追加失败只回滚本页，先前前缀不丢；若此前没有存储则恢复零容量。SQL、前缀展开、去重、稳定排序及最终五条上限不变，不增加缓存、unsafe、依赖或文件系统操作。

## Historical audit

[九键英文空页](../../implemented/testing/2026-10-10-nine-key-english-lazy-buffer.md)继续约束最终容量；[完整码先筛选](../../implemented/bug-fix/2026-10-21-keypad-english-filter-before-limit.md)继续持有 SQL 与前缀限额；[专用英文复用](../../implemented/testing/2026-10-17-dedicated-english-candidate-buffer.md)继续持有普通前缀行覆写。三者部分重叠，保持原决定。检索 `query_keypad_prefix`、英文候选页追加和九键英文缓冲，未发现同一追加决定；英文前缀展开及数字借用处理查询键，属于相邻但不同成本，不吸收。

本仓库的[全拼热前缀追加](../../implemented/testing/2026-10-16-quanpin-prefix-row-stream.md)是拥有字段直接进入最终容器的参考。标准库 [Vec](https://doc.rust-lang.org/std/vec/struct.Vec.html) 的 `truncate` 保留容量，`reserve_exact` 按当前长度计算额外空间；本轮固定 Rust 1.97.1，不采用新 API。重复检查、架构、官方契约、既有实现与无消费者根因均已核对，满足 confidence-check 的实现条件。

## Alternatives considered

- **跨前缀复用临时页**：可复用外层容量，但行被搬走后字符串仍不能复用，还多一次逐页搬运；直接追加省去整个临时容器。
- **在 SQLite 行借用期间筛掉最终排名败选行**：能少建更多字段，但需要保留所有已见展示文本以守住首条同文行胜出，跨步进借用及排序边界更复杂，本片保留现有候选集合。
- **缓存整个英文结果**：相同输入可跳过查询，但引入词典失效和长期存储。本片只消除没有消费者的页容器，不改变查询生命周期。

## Verification

旧入口有效红测为两个非空页共 56 次申请，未满足减少两次的要求；直接追加后为 54 次，内容及最终容量相同。另按 0/3/9/27 个非空成功前缀页验证逐页恰少一次申请。两种分组键盘、专用/混输/无中文回退、锁定及冷/热共 448 次完整英文入口对照相同。另以已校验的发布英文词库显式执行忽略项，对八个公开合成英文输入的各前缀做 168 次冷热对照，全部字段、顺序与容量相同。

四项词库专项覆盖 NULL、非法 UTF-8、整数/实数展示、重复展示、平局、零/负权重、限额、普通英文覆写、prepare/步进失败和已有前页；部分步进失败及缺列错误均只回滚本页，零容量得以恢复。完整冻结英文入口、分组查询与行解码均与固定基线机械核对一致，仅忽略注释、空白和私有方法重命名。第一次测试夹具引用了私有模块而编译失败，修正为本地合成夹具；这次编译错误不当作有效红测。

完整引擎 2487 项、golden 31 项、运行时 362 项通过，引擎 54 项沿用忽略；新增发布词库专项后，最终严格 Clippy、格式检查及完整 quick 均通过。release、质量和 quick 的最终结果保存在[证据目录](../../../../docs/measurements/2026-10-23-nine-key-english-page-append/README.md)。

单次完整 ABBA 四臂模型 p95 为 20.35/20.25/22.74/20.36 ms，均超过原 16 ms 门槛。后两臂观察到外部编译，整组不用于推断收益或代码回退，不筛选前两臂，也不重试找绿。全部均值、长尾、最大值及退出码保存在证据目录。

## Consequences

首个前缀部分解码后失败，总结果必须恢复原来的零容量；后续失败不能清空先前页。普通英文从零起点覆写，分组英文从尾部追加，两者须保持独立错误边界。失败可能在 prepare、query 或 next 发生，不能只测没有连接。没有设备宿主或文件读写变化；局部节省不证明净耗时收益。

成功页不再申请、搬运和释放临时候选向量，最终候选字段仍独立拥有。首个前缀部分写入后失败时会短暂预留完整聚合容量，随后回滚到零；旧路径此时只预留单页。这一错误路径的瞬时容量代价受原 320 行上限约束，成功路径消除了同时持有临时页的峰值。不引入长期存储或新的查询结果缓存。默认九键 16 ms 目标仍未达成，不以确定性申请差额声称净耗时收益。

[分组英文查询复用 SQLite 程序](2026-10-23-keypad-glob-statement-reuse.md) 消除同一 SQL 因字符组模式绑定触发的无效重新规划；本篇的追加、容量和错误边界继续保持。
