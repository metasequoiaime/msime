# Agent Note: 候选规范读音校验借用音节

Status: implemented

## Problem

`normalize_canonical_pinyin_for_word` 先用 `split_segments` 复制音节到向量，只读检查段数和完整性后又原样拼回。候选选择与学习调用这条路径，临时向量和每段字符串均不需要拥有存储。

## Decision

空输入先返回空串，直接统计撇号段数并调用既有 `count_han_chars`，计数匹配后才借用分段做原有完整性检查，成功时只复制最终原串。不改变空段拒绝、字符计数、多音节完整切分、别名拼写和返回所有权。

## 既有笔记审计

[学习句子长度计数](2026-10-08-learning-sentence-segment-count.md)部分重叠于只读分段计数，但不负责规范读音校验；[句子学习借用候选行](2026-10-09-sentence-row-borrow.md)部分重叠于校验的调用方，不改变其所有权契约。两篇互链保留。九键规范读音缓冲与选择、九键简拼写入约束、拼音聚合空页和词网格键规划分别属于行复用、词库写入或查询规划，没有同一校验决定；活跃树没有完全吸收的笔记或过时提案。

## Alternatives considered

- 使用 `Vec<&str>`：保留直观的段数和逐段检查，但仍为只读校验分配向量。
- 直接使用单音节集合并仅计汉字：与函数名称和旧注释一致，但当前完整性检查允许一段包含多个可完整切分音节，`count_han_chars` 实际按 UTF-8 字符计数，会收紧既有行为。
- 返回借用串：能省去最终输出复制，但调用方需要在候选列表修改后保存独立结果，会改变返回契约。

## Verification

冻结 `6af0b0a780b23c5fd8f1fe1a25ca88720f152504` 的完整旧函数，正文机械核对逐字一致。双段预算真实红测试两侧都是 4 次分配，改后为 4→1 次。4 项新增测试覆盖空段、计数不匹配、Unicode 字符与组合字符、单段多音节、原始别名拼写、1025 段、63/64/65 字节动态规划边界及短路顺序，返回内容和容量与冻结实现一致，释放输入后结果仍独立可读。既有全拼和双拼候选选择各校验两次双段读音，分配预算分别从 23 降至 17、32 降至 26，提交和状态断言保持。

冷计量只借用输入，区间外初始化全局音节表，区间内创建并释放临时对象，只返回输出。当前 arm64 debug 双段有效输入为 4→1 次分配、Rust 逻辑请求峰值 59→6 字节、返回存储两侧均为 6 字节；计数不匹配、空段、非法尾段和 Unicode 拼音为 3→0 次分配、返回存储零；66 字节单段有效输入为 4→2 次分配、峰值 1698→1608 字节、返回存储两侧均为 66 字节。空输入零分配不变；所有最低 signed 差值均为零。长单段仍保留既有动态规划堆回退。

## Consequences

校验不再复制临时音节和向量，成功返回仍独立拥有原始拼写，计数先于完整性检查的短路顺序保持。计数和校验仍分别遍历输入，尚未测发布构建时间或真实宿主延迟，不声明物理堆或 RSS 收益。

依据 [str::split 官方契约](https://doc.rust-lang.org/std/primitive.str.html#method.split)借用分段，非空输入的 split 与原 join 互逆。核对固定 Rust 1.97.1 的本地标准库：join 以合并字节数创建 Vec，str::to_owned 复制原字节；容量通过固定工具链对照测试验证，公共文档不被解释为永久精确容量保证。
