# Agent Note: 候选规范读音校验借用音节

Status: implemented

## Problem

`normalize_canonical_pinyin_for_word` 先用 `split_segments` 复制音节到向量，只读检查段数和完整性后又原样拼回。候选选择与学习调用这条路径，临时向量和每段字符串均不需要拥有存储。`update_creating_word_progress` 的选中读音副本仅参与拼接，最终校验副本仅用于判断 `can_store`，两处只读用途也不需要拥有校验结果。

## Decision

空输入先返回空串，直接统计撇号段数并调用既有 `count_han_chars`，计数匹配后才借用分段做原有完整性检查，成功时只复制最终原串。完整性逻辑由私有谓词复用，拥有型规范化接口仍在校验通过时返回独立字符串。造词进度在原顺序校验选中读音，拼接时借用 `SelectionTransition` 的原始读音；完成后用同一谓词判断 `can_store`。不改变空段拒绝、字符计数、多音节完整切分、别名拼写、五笔提前返回和进度字段的独立所有权。

## 既有笔记审计

[学习句子长度计数](2026-10-08-learning-sentence-segment-count.md)部分重叠于只读分段计数，但不负责规范读音校验；[句子学习借用候选行](2026-10-09-sentence-row-borrow.md)部分重叠于校验的调用方，不改变其所有权契约。两篇互链保留。九键规范读音缓冲与选择、九键简拼写入约束、拼音聚合空页和词网格键规划分别属于行复用、词库写入或查询规划，没有同一校验决定；活跃树没有完全吸收的笔记或过时提案。

## Alternatives considered

- 使用 `Vec<&str>`：保留直观的段数和逐段检查，但仍为只读校验分配向量。
- 直接使用单音节集合并仅计汉字：与函数名称和旧注释一致，但当前完整性检查允许一段包含多个可完整切分音节，`count_han_chars` 实际按 UTF-8 字符计数，会收紧既有行为。
- 将拥有型规范化接口改为返回借用串：能省去所有成功校验的输出复制，但学习调用方需要在候选列表修改后保存独立结果，会改变返回契约。私有谓词让只读调用省去输出副本，拥有型调用继续复制。
- 仅把最终 `can_store` 校验换成谓词：改动最少，但选中读音仍先复制再拼接；借用原始字段复用校验结论可以同时去掉这份临时结果。

## Consequences

校验不再复制临时音节和向量，只读造词进度不创建校验结果字符串，拥有型规范化接口仍独立拥有原始拼写。造词进度的三个字符串仍独立拥有，计数先于完整性检查、选中读音先于缺口判断和完成状态控制最终校验的顺序保持。计数和校验仍分别遍历输入，尚未测发布构建时间或真实宿主延迟，不声明物理堆或 RSS 收益。

依据 [str::split 官方契约](https://doc.rust-lang.org/std/primitive.str.html#method.split)借用分段，非空输入的 split 与原 join 互逆。核对固定 Rust 1.97.1 的本地标准库：join 以合并字节数创建 Vec，str::to_owned 复制原字节；容量通过固定工具链对照测试验证，公共文档不被解释为永久精确容量保证。
