# Agent Note: 九键英文前缀只物化最终层

Status: implemented

## Problem

`letter_prefixes` 为九键英文候选展开数字前缀时，逐层把每一层的 `Vec<String>` 交给下一次 `flat_map`。达到预算或遇到无效键时，已经生成的中间层会被立即丢弃；即使最终结果只需要一层，这些中间字符串也会在九键英文刷新热路径中产生额外分配。

## Decision

先按每个数字键的字母数量计算预算内的最终深度和笛卡尔积大小。预算内的输入再用一个可变前缀递归深度优先生成最终字符串：追加一个字母，完成后回退该字符，叶节点克隆到一次性按最终数量预留的结果向量。空输入、无字母键、零预算和超预算截断继续返回原有结果；组合顺序、字符串容量和 `FourteenKey` 的复用保持不变。

## Historical audit

已检索九键英文前缀、空页预留、输入数字借用和简拼编码物化笔记。[九键英文候选借用已输入数字](2026-10-16-nine-key-english-digits-borrow.md)只移除 `digits` 的临时副本，[英文前缀空页延后候选存储预留](2026-10-10-english-empty-prefix-storage.md)只约束词库结果容量；被否决的[简拼编码只物化最终页](../../rejected/testing/2026-10-16-nine-key-initials-final-codes.md)针对另一套 `initials_codes` 算法和墙钟回退，本片只改变英文 `letter_prefixes` 的中间结果生命周期。

## Alternatives considered

- **继续逐层构造**：逻辑直观且每一层可独立复用，但会为随后被覆盖或因预算而拒绝的中间字符串付出分配。
- **从上一条结果迭代进位生成字符串**：可以避免递归，但需要维护每个键的进位状态和字符串替换边界，增加代码状态而不改变最终页契约。
- **只预检预算、保留原展开**：能够更早拒绝超预算输入，却仍会为有效输入的所有中间层分配；不能解决有效英文查询的主要浪费。

## Verification

新增分配回归在旧实现的固定输入 `64426`、预算 `64` 上产生 `48` 次分配并超过 `30` 次阈值；最终层生成实现通过同一阈值。九键相关测试 218 项通过；完整 `msime-engine` 库测试 2284 项通过、0 失败、40 项既有忽略。`cargo fmt --all -- --check`、`git diff --check` 和 `cargo clippy -p msime-engine --all-targets -- -D warnings` 通过。

## Consequences

英文前缀展开只保留预算内最终页及最终字符串，超预算和无效输入会在分配前结束；组合顺序和调用方拥有型结果不变。递归深度等于预算内输入深度，当前调用使用数字键码，仍受原有预算限制；这项局部分配收益不能单独推导九键端到端延迟预算已经达标。

完整组码与查询限额的先后顺序由[分组键盘英文先过滤再限额](../bug-fix/2026-10-21-keypad-english-filter-before-limit.md)约束，保留本篇的预算与分配边界。
