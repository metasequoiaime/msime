# Agent Note: Windows 原生画布像素检查等待真实绘制

Status: implemented

## Problem

Windows 原生设置冒烟在搜索合成画布后只固定等待 700 毫秒，就按 UI Automation 元素边界读取屏幕像素。最近一次 CI 中，元素已经出现在 UIA 树里，但屏幕合成仍是白黑占位图；脚本先保存了未完成的局部截图并失败，而稍后保留的完整失败窗口已经显示了正确的浅色画布。这个门禁把“元素存在”误当成“像素已经提交”。

## Decision

`Assert-CanvasPreview` 在每个横排或竖排画布上轮询屏幕截图，直到合成皮肤的模式特有像素至少出现 8 个，最多等待 15 秒；只有达到这个条件才保存截图并继续。UIA 元素仍负责提供边界，像素条件负责确认真实绘制完成。

## Alternatives considered

- 把固定延时从 700 毫秒提高到更大的常数，改动最小，但无法覆盖 runner 负载波动，也会在快机器上白等。
- 只等待 UIA 元素的可见状态，语义简单，但本次失败已经证明 UIA 可见不代表屏幕合成完成。

## Consequences

像素冒烟对 WinUI/DWM 合成时序有了明确的完成条件，避免把占位帧误报为产品回归；正常情况下仍在首帧出现后立即通过，最坏等待时间增加到 15 秒。测试仍依赖交互式桌面和真实屏幕捕获，不能替代产品逻辑测试。

## Testing

在 CI 失败产物中确认 `failure.png` 的最终窗口已显示画布，而失败时保存的局部画布图仍为占位像素；对照前一个同代码成功 run，确认失败发生在固定 700 毫秒读取窗口，而非 Windows 设置构建或 PR 的 Linux 代码。
