# Agent Note: 词网格入列时复用原堆选择

Status: implemented

## Problem

固定 `d9cd6400651af727c572af4d670eba1f953eb54f`、资源代次 `7356c4a452d8ba15475c0e57f134fccf7b7cbe267440461541c74d09b11b6ffe` 和模型 pin `0f19789abbad5aa887e3b27088bf168acf6e9098`，九键神经配置 81 条的临时计数有 43063 次解码、255918 个非末列，剪枝前合计 174550417 条入列假设。当前先完整写入列向量，再按原 libc++ 堆选择保留最多 beam 条。大量将被淘汰的 Hyp 写入并长期占着整列容量。

同一调查中，没有出边的列为零，故不实施空列跳过；避免以不出现的合成形状替代真实目标。临时计数只输出数量且已撤回，不作为延迟成绩。

## Decision

只对预扫描确认会超过束宽的非末列按原到达顺序执行相同堆选择。先按原样收集 beam 条；第 beam+1 条到来时调用已有 `make_heap`，按原比较与 `sift_down` 处理新条目。列状态带 `streamed` 布尔值，堆完成后执行已有 `sort_heap` 并截断；未溢出的列保持原到达顺序，零束宽不进入流式路径。

容量仍先算原前向到达上界；流式非末列取 `beam+1`，未溢出非末列保持原容量。末列由后续[最终预算流式选择](2026-10-17-lattice-terminal-stream.md)覆盖，保持原最终排序和返回容量。`BeamColumn` 增加固定布尔字段，测试把它造成的列头字节计入允许开销。保持每条边评分、备忘访问和展开顺序，不提前省略任何评分或改变束宽。仅把原剪枝的堆选择分散到各次入列，排序和浮点计算步骤保持。

## Historical audit

按堆、增量、有界、在线剪枝和 partial_sort 检索活跃笔记，没有相同方案。[列容量](../../implemented/testing/2026-10-15-lattice-column-capacity.md)部分重叠，继续负责前向到达上界；[假设布局](../../implemented/testing/2026-10-15-lattice-hyp-layout.md)部分重叠，保持 Hyp 字段；[出边借用](../../implemented/testing/2026-10-15-lattice-outgoing-borrow.md)继续借用两切片。[行索引实验](../../rejected/testing/2026-10-15-lattice-row-entry.md)仍被拒绝，本项复用其固定 b50aeb2f05 参考，机械核对它与当前生产正文相同，避免多复制一份完整解码。

源码直接复用同仓库 cxx_sort 的 make_heap、sift_down 和 sort_heap。[LLVM 21 partial_sort](https://github.com/llvm/llvm-project/blob/release/21.x/libcxx/include/__algorithm/partial_sort.h)确认先建前缀堆、逐条比较替换与下沉、最后堆排序；[Vec 文档](https://doc.rust-lang.org/std/vec/struct.Vec.html)约束容量足够时 push 不扩容。没有新依赖或 unsafe。

## Alternatives considered

- 使用 BinaryHeap 或逐次 push_heap：有现成实现，但初始堆的建立次序会改变平局置换，不能保持当前参考输出。
- 对末列也做流式选择：可以减少更多存储，但末列还有不同预算、最终不稳定排序与返回容量契约，初次实现暂缓；后续由[末列最终预算](2026-10-17-lattice-terminal-stream.md)单独覆盖并验证。
- 每列增加堆状态字段或独立位图：状态更直观，但增加所有图的列头大小或额外分配；现有丢弃尾部可用一条标记区分是否已经开始堆选择。

## Verification

先让密图 Hyp 峰值预算在生产基线上失败。排序原语对照原部分排序的每个保留元素及比较轨迹，覆盖大量同分、升降序、NaN/无穷、零及大束宽。完整解码与固定旧参考比较字段、顺序、分数位、备忘、返回容量和分配，覆盖表/三元/个人/附加图、空图、不可达、冷/热状态及各束宽。配对 release 每形状中位新旧比 <1.05；真实固定资源完整质量 JSON 相同，并独立测九键十六毫秒门禁。完整相关测试、Clippy、fmt、notes、quick 与 pre-push 后单独提交推送 PR 并直接合并。

## Consequences

必须在首次溢出才建堆，不能把未溢出列排序；标记只能由匹配的 finish 解释，不得交给旧 keep_beam 再建堆。前驱列完成排序后才能保存下游索引。入列时多一层分支，短图可能退化，须完整计时；内存下降不代表真实按键延迟达标。

## First timing and generated code

首轮完整 release 配对 36 形状耗时 232.76 秒，有表非空多列几何均值 `0.991546`，但无表的 32/32 无附加图与 4/8 有附加图分别为 `1.063954`、`1.086003`，超出 1.05 门槛，不能接入。正常程序的 nm 未找到独立 push_partial/finish_partial 符号，反汇编确认已内联；旧/新 decode_graph 的局部栈分配都是 0x270，加寄存器保存 0xa0，不是每次调用一个新函数。新循环在已满束时仍走零宽、未满、刚满三次判断。第二版本把已满束处理置前，冷初始化留到后面；此调整必须重新完整验证，不从两轮选有利形状拼接。


## 实验证据

在固定 `d9cd6400651af727c572af4d670eba1f953eb54f` 上，候选的完整路径、分数位、备忘和返回存储回归覆盖 4 个种子、4 个列数、4 个宽度、5 组束宽/结果预算、32 组选项和冷热两次运行；等价性通过。`cxx_sort` 流式原语测试覆盖 0..260 长度、同分、升降序、非总浮点比较和比较轨迹。完整 release 测试：引擎 2135、golden 31、runtime 288，失败 0、忽略 28；两 crate 全 targets Clippy 通过。

本轮最终生产入口配对计时 36 形状耗时 228.45 秒，所有中位比 `<1.05`。密集 12/32、32/32 形状中位比约 `0.865`；有表和热备忘密集形状约 `0.85–0.90`；小列和零表形状接近 1.0，未用第二轮局部计时替换最终轮数据。峰值内存回归在 12 列从 430171 降至约 99500 字节，32 列从 1253032 降至约 129800 字节；列头固定元数据按测试单独计入。

固定资源完整全拼 141 条、九键 81 条，在默认和神经配置下四份质量 JSON 与基线逐字段相同。无采样九键延迟按旧/新/新/旧测量，每臂 1791 键、5 条预热；模型臂 p95 为 `21.17 / 21.25 / 21.13 / 21.23 ms`，均未达到 16 ms，不能宣称目标完成。结果显示整体端到端收益不稳定，局部解码内存和密图计时收益仍是本项采用依据，不把 p95 差异全归因于本项。

另有一次真实九键计数：43063 次解码、255918 个非末列均无空出边，因此没有实施空列跳过；剪枝前约 174550417 条入列假设，支持优先处理密集入列存储。
