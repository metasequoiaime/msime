# Agent Note: 候选合并的小列表去重路径

Status: implemented

## Problem

替代切分合并已经按权重排序，但小规模候选页仍为每次去重建立 `HashSet`，并创建记录每行是否保留的临时 `Vec`。这些临时状态只服务于一次合并。

## Decision

合并行数不超过 64 时，直接扫描已保留词并原地压缩；更大的合并继续使用哈希表和保留标记数组。线性路径保留排序后的首次出现、原有容量和大列表的复杂度边界。

## Alternatives considered

把所有合并都改成线性扫描会让公开词典结果很大时出现平方级退化；只缩小哈希表容量仍会保留临时堆分配，不能解决候选页路径的开销。

## Verification

新增 36 行替代候选的分配预算测试，确认去重零分配并保留 18 个词；既有替代切分升位、排序和重复词测试继续覆盖行为。

## Consequences

64 行以内的去重时间复杂度为平方级，但候选页规模受控；大合并继续走哈希表路径。
