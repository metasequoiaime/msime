# Agent Note: 语言词典查询结果延后预留

Status: implemented

## Problem

`LanguageDictionary::lookup`、`lookup_completions` 和 `lookup_pattern` 在执行 SQLite 查询前按 `limit` 创建结果向量。没有匹配行、`limit` 为零、补全上界无效或首行读取失败时，结果为空却仍保留整页容量。粤拼、注音和笔画的候选刷新都会经过这些入口或它们的复用版本，空查询是正常输入路径。

## Decision

三个拥有型查询入口从空 `Vec` 开始。对应的 `*_into` 读取循环在首条行已经成功转换后、写入前，且结果没有已有存储时，按原 `query_capacity(limit)` 精确预留；复用缓冲、SQL 限制、行字段转换、排序和顺序保持不变。空结果、零限额、无效补全上界和首行读取错误不再申请查询结果存储；正常命中继续保留原容量提示。

## Alternatives considered

- 继续在查询前预留：命中路径少一次容量判断，但所有空页都为不会返回的行分配空间。
- 按每条结果自然增长：空页同样可以零容量，但命中页失去既有 `limit` 容量契约，可能增加扩容次数。
- 查询后按实际行数重建：需要额外扫描或改变复用缓冲的所有权，不能保留已有字符串存储。

## Verification

新增回归断言覆盖精确未命中、补全未命中和通配查询未命中；旧实现实际返回容量 10，测试先失败，修复后为空容量。已有命中断言继续要求 `limit` 容量，并保留复用查询的行内容与字符串容量行为。语言词典模块测试 15 项通过；提交前运行引擎全量单测、golden、Clippy、Rustfmt、差异检查、笔记校验和 `bash scripts/verify-local.sh --quick`。

## Consequences

空语言词典查询省去结果向量的固定预留；首条有效行仍按原上限一次准备存储。复用 `*_into` 缓冲不会丢弃已有容量。计量只涵盖 Rust 结果容器，不代表 SQLite 内部或系统 RSS，也不把空结果分配减少直接等同于端到端延迟下降。
