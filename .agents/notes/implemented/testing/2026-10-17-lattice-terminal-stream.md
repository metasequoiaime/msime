# Agent Note: 词网格末列按最终预算流式保留假设

Status: implemented

## Problem

固定 `833f43b2c1344b8ac8923187f3a2016c0b5cddb1` 与模型 `6acc7839572fb7df221a8e4910467c9dedd72fb8`，九键 release 十二秒采样中 `decode_graph` 有 413 个栈顶样本，模型 `linear_into`/`dot_i8` 为 1124/672。采样同时观察到其它构建，仅定位热点，不作为延迟结论。完整九键两臂加五个预热例的临时计数为 88680 次解码；末列累计容量上界 84972950 槽，按各次 `max(beam, nbest)+1` 截断上界合计 2925146 槽。计数只含合成评测，无真实输入；临时插桩已撤回。当前末列在全部展开结束后才执行 `keep_beam`，无后续列需要回溯它的被淘汰假设。

## Decision

复用既有 `push_partial`/`finish_partial`，将末列的选择预算设为 `max(beam, nbest)`，非末列仍为 `beam`。列头保留原 `streamed` 布尔值；只在预扫描容量超过预算加一且预算非零时启用。入口按 `nbest > beam` 选择两份常量泛型实例，常见的相同预算实例在编译期移除逐边动态预算读取及列初始化的终点判断；宽末列实例在末列使用最终预算。末列先完成相同堆排序，再进行原最终不稳定排序、唯一预算回溯和三元重排。所有边评分、浮点步骤、备忘访问、到达顺序、平局、返回容量与拥有关系保持。

## Historical audit

已检索末列、流式、`decode_graph`、`Hyp` 与束搜索。与[非末列流式选择](../../implemented/testing/2026-10-15-lattice-streamed-beam.md)部分重叠：该篇明确暂缓末列，本篇接管末列并保留非末列决定。与[可达列容量](../../implemented/testing/2026-10-15-lattice-column-capacity.md)及[回溯物化](../../implemented/testing/2026-10-16-lattice-trace-materialization.md)部分重叠，分别保留容量上界与输出构造契约。二元前词散列和矩阵分派已有负结果，不重试。没有完全吸收或过时提案。

实现参考为本仓库 `cxx_sort` 的流式原语；已核对 [LLVM 21 partial_sort](https://github.com/llvm/llvm-project/blob/release/21.x/libcxx/include/__algorithm/partial_sort.h) 的建堆、替换与排序顺序及 [Vec](https://doc.rust-lang.org/std/vec/struct.Vec.html) 的容量契约。不新增依赖、unsafe、IO 或平台接口。

## Alternatives considered

- 继续完整收集末列：代码最直接，末列预算不同也不需列状态变化，但每次展开为马上淘汰的假设保留大量存储。
- 只以 `beam` 流式截断末列：可以复用相同常量，但 `nbest > beam` 时会丢失合法输出，不采用。
- 每列保存动态预算：可在同大小列头里统一所有目标列，但首轮实测同时违反单项和整体收益门槛；生成代码还增加热分支重载，因此恢复布尔标志并对常见预算作静态实例化。
- 新增末列专用堆：容易隔离，却重复平局敏感的选择算法；现有原语已经逐项验证比较轨迹，复用它更易维护。

## Verification

内存预算先在旧生产路径真实失败。冻结完整 `decode_graph` 为独立参考，逐项检查路径字段、分数位、顺序、返回容量、备忘与分配次数；覆盖空图、不可达、主/附加图、表/个人/三元、冷热、零束宽和 `nbest > beam`。密图临时请求峰值降低超过两成，列头大小不增加。普通系统分配器 release 48 形状，同进程每形状 21 对交替先后，最快批次校准至少 50 ms，每形状新旧中位比 <1.05，有表多列总体几何均值 <1.0；三轮完整结果如下，不挑选重测。默认真实资源全拼与九键质量 JSON 字节一致，正式二进制九键 ABBA 仍保留 16 ms 预算，四轮均超限；局部优化通过不能当成端到端目标完成。

## Consequences

末列需要 `max(beam, nbest)` 而非普通束宽；必须只完成一次堆排序，不能再次建堆改变平局顺序。零预算保留原路径；极大预算加一必须饱和处理。两份泛型实例会增加代码体积，入口分支成本须纳入完整计时。容量上界减少不等于实际写入同量减少，也不能证明九键 16 ms 已达标。

## Third code generation

第三版只把列初始化中的预算与终点条件同时依赖 `WIDE_TERMINAL`。入口在 `nbest > beam` 时才选择宽实例，普通实例的 `max(beam, nbest)` 必然等于 `beam`；评分、到达顺序与最终预算不变。三项针对性测试通过，零值、非有限值、平局及极大预算结果与冻结旧版相同，三形状峰值仍为 1960、20179、50240 字节。
