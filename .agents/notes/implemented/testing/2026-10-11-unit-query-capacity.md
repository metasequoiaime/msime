# Agent Note: 单位换算按结果上界预留容量

Status: implemented

## Problem

`query_units` 无论源单位和目标模式，都按整页 `RESULT_LIMIT` 预留结果字符串。质量、面积和温度等查询最多只能生成少量目标行，额外容量会随每次单位候选查询申请。

## Decision

根据是否指定目标和源单位的量纲，计算可生成的最大行数；显式目标预留三行，默认目标按同量纲的默认单位数预留，并继续受 `RESULT_LIMIT` 限制。结果行、去重、文本长度过滤和失败语义保持不变。

## Alternatives considered

- 继续按整页预留：实现最简单，但大多数单位查询保留未使用容量。
- 完全不预留：空结果最省，但有效查询会失去一次性容量提示。
- 为每个转换逐行扩容：容量最精确，但会增加有效查询的扩容次数。

## Verification

新增质量、温度和长度查询的容量回归，相关单位换算测试全部通过；提交前还会运行引擎全量测试、Clippy、格式、差异检查、笔记校验和 quick 门禁。

## Consequences

单位查询的结果缓冲按实际模式上界分配：质量 `2jin` 为 3 行、温度 `100c` 为 2 行、长度 `1m` 为 7 行；超过上界时仍由 `Vec` 正常增长，候选内容和顺序不变。

带符号数值的解析边界见[单位换算符号规则](../bug-fix/2026-10-16-signed-unit-conversion.md)，本篇的分配约束继续适用。
