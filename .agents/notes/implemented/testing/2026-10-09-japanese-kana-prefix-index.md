# Agent Note: 日文待定罗马字借用固定假名前缀索引

Status: implemented

## Problem

`kana_for_romaji_prefix` 每次查询都复制并规范化待定文本、扫描固定拼法表、创建和排序去重假名列表。provider 与 matrix 可在同一次候选查询里重复这些工作，而结果只取决于固定表。

## Decision

按现有 `ROMAJI_LOOKUP` 的 `LazyLock` 模式建立非空 ASCII 拼法前缀到排序去重假名列表的不可变索引。键借用固定表字节，值保存假名指针。新内部视图入口返回静态切片，调用者不复制列表；旧拥有型函数正文仅在测试里保留作独立 oracle。查询以表中最长拼法的编译期长度作为栈缓冲上限，按字节 ASCII 小写化；空和超长输入直接返回空切片。

不存储用户文本或词库，不引入锁接口、依赖或 unsafe。索引首次访问构建一次；静态内存常驻进程，必须测量冷构建分配、耗时、键数和指针容量，不能把暖查询零分配推广到冷路径。

## 既有笔记审计

[小写借用](../../implemented/testing/2026-10-08-japanese-romaji-borrow-lowercase.md) 部分重叠，继续约束转换的规范化和拥有型输出，互链。[拼法边界](../../implemented/bug-fix/2026-10-08-japanese-romaji-spellings-and-kana-slot.md) 部分重叠，继续保留全部别名，不能从反向表推导前缀，互链。词条借用和空排名笔记的短前缀缓存属于词库 ID，不是本片固定拼法索引，保留无关；caret 前缀借用与 continuing 查询键缓冲是独立算法，保留无关。检索活跃笔记中的 `kana_for_romaji_prefix`、`ROMAJI_TABLE`、前缀索引、假名前缀和前缀缓存，没有同一决定。

## Alternatives considered

- 保留逐次扫描：没有常驻内存和冷初始化，代码简单；重复扫描、排序和分配位于按键热路径。
- 复用 `normalized_romaji` 的 Cow：复用已有规范化，常见小写可借用；大写仍分配，短固定键可以直接使用栈字节缓冲。
- 反向假名表：已有排序结构可复用；一个假名有多种拼法，反查首选拼法会丢弃合法别名。

## Verification

旧实现真实红测试：`k` 暖前缀查询分配 4 次，预算为 0；合成词库 `kak` provider 查询分配 45 次，预算为 37。新实现分别为 0 和 37，provider 完整字段和候选顺序保持。全部固定表前缀的所有 ASCII 大小写组合、合法前缀加非法尾部、Unicode、空与长输入与旧正文逐项对照一致；包含 `sh`、`xtu`、`zya`、`dya` 和 `-`。索引键集合恰好是表中全部非空前缀，切片严格排序去重，输入临时字符串释放后引用仍有效，跨线程调用共用同一存储。

matrix 的 32 seed 完整输出 oracle 保留旧拥有型查询，不同步改为索引。完整引擎 1474 项通过、两个本地计时测试默认忽略；golden 31 项通过。独立设计和最终代码审查无遗留问题。Clippy、Rustfmt、差异检查和 349 篇笔记校验通过。`bash scripts/verify-local.sh --quick` 退出 0 并报告 `quick check passed`：共享 Rust、Android 目标与宿主 Java、Linux 共享桌面层、Linux 原生宿主 73 项测试、macOS 原生宿主和 Apple bridge 构建通过；WASM、HarmonyOS ArkTS 和 Windows MinGW 阶段按工具链缺失明确跳过。

本机 release 单独进程：首次索引查询约 196.958 µs、259 次分配；223 个键，HashMap capacity 224，假名指针总长度 401、实际 capacity 1040，值缓冲 16640 bytes。此数不包含 HashMap 桶、控制字节和分配器额外开销，不声称整个索引仅占 16.6 KB。

release 十批交替顺序，每批 100000 次的中位批次：`k` 86.533→1.450 ms，`sh` 73.329→1.579 ms，`K` 84.221→1.437 ms，`SH` 73.609→1.564 ms，`?` 59.717→1.200 ms，`あ` 35.604→1.336 ms，超长输入 9.427→0.099 ms，空输入 0.192→0.099 ms。暖路径分配分别为 4/3/4/3/1/1/1/0→全部 0。计时使用 black_box、交替测量顺序、旧扫描独立对照，不设置 CI 时间阈值，不能当成实际打字延迟保证。

## Consequences

静态索引首次访问承担一次构建成本，并常驻进程内存。固定表仅 223 个前缀，本机暖路径的扫描排序分配成本明显下降，接受小规模固定内存换取热查询借用。空与超长输入在访问 LazyLock 之前直接返回，不触发初始化；其他首次短查询即使未命中也可能触发初始化，暖零分配不能推广到冷路径。

索引只保存固定表字节和假名，不保存用户文本、词库或会话状态。表键必须是 ASCII 小写，测试守住该不变量；最大键长从表编译期计算。原拥有型函数只供测试对照，生产 provider 和 matrix 直接借用静态切片，不扩大 crate 外部 API。
