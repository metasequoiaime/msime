# Agent Note: 双拼辅助码检测借用无分隔符输入

Status: implemented

## Problem

逐键双拼查询会检查是否进入双字辅助码模式。旧实现无论输入是否含手动分隔符，都复制原始输入和带大小写输入以删除 `'`；无分隔符时这两份字符串只是为了读取长度和检查模式，属于重复临时分配。`active_helpcode_query` 的单辅助码候选分支也先删除分隔符复制整串输入，连 `n`、`ni` 这类立即排除的普通输入都因此多一次分配。

## Decision

检测带大小写输入时，仅在确实含 `'` 时建立无分隔符副本，否则直接借用原字符串；原始输入只需计算去分隔符后的有效字节数，不再建立副本。带分隔符的判断和双拼完整音节校验保持原有顺序。

`active_helpcode_query` 在双辅助码分支未命中后，用同样的 `Cow<str>` 策略为单辅助码分支提供输入：无分隔符时借用，确有分隔符时仍建立去分隔符副本。保留双辅助码优先、带大小写输入为空时回退原始输入、单辅助码的大写末字偏好和带分隔符的排除边界；返回的查询字段仍拥有其字符串。

查询入口的独立判空也[直接扫描原始字节](2026-10-15-shuangpin-query-empty-check.md)，避免在进入本篇的检测路径前创建一次无用副本。

双辅助码的[大写标志先于基码分段检查](2026-10-15-shuangpin-full-helpcode-fast-reject.md)，进一步排除无效模式；这里的输入借用与含分隔符回退保持独立。

## Alternatives considered

- **继续复制两份字符串**：实现最简单，但每次双拼按键都会承担不必要的输入复制。
- **让调用方传入已规范化输入**：可以避免重复工作，但会扩大检测函数契约，且其他调用方仍需自行处理分隔符。
- **统一改成返回所有权字符串**：无法为无分隔符路径提供借用结果，仍会保留分配。

## Verification

单辅助码查询候选分支的回归先在旧实现上捕获 1 次分配，借用后 `n`、`ni` 及空大小写字段回退均为 0 次。用四张内置方案、17 种输入、大小写字段保留/回退和辅助码开关共 272 组状态，对照冻结的旧式拥有型输入流程，逐字段检查查询基码、切分和辅助码；覆盖大小写单码、双码优先、手动及连续及末尾分隔符和微软双拼分号。原有双辅助码检测分配预算仍为 2 次。

引擎单元测试 2097 项通过、19 项忽略，golden 31 项通过；Clippy、Rustfmt、差异检查、笔记检查与本地 quick 门禁通过。quick 包含 Linux 原生宿主 87 项测试、macOS 原生宿主及 Apple bridge 构建，不代表设备验收。

## Consequences

双辅助码检测不再为无分隔符输入建立完整副本，单辅助码查询候选分支也直接借用；后者在非空且不含手动分隔符时少一次输入复制分配。含分隔符时保留原有副本与边界判断。真正返回的查询字段仍按原接口分配，不新增缓存、常驻状态或公开接口，也不承诺完整查询零分配或端到端延迟收益。
