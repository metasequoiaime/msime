# Agent Note: 横向候选验收在滑过目标后回找

Status: implemented

## Problem

#10356 跟踪 develop `0e2824c8a2` 的 API 28 设备失败。共享单测全部通过，唯一设备失败是连续候选专项寻找第 70 项时已滚到偏移 181289、创建 1873 项，随后在列表尾部停止。夹具始终按调用者给出的方向滑动，不核对已建目标是否落在身后，因此一次越过目标就再也不能回找。

## Decision

目标存在时按其屏幕边界在视口外的那条边决定下一次手势的方向和距离；系统裁剪离屏节点会得到 `left=0, right=-1308` 这样的负宽度矩形，不能要求宽度为正才回找。目标尚未建立时才沿原方向推动追加。保留真实 DOWN/MOVE/UP、候选顺序、首末往返、真实点击上屏和停滞失败断言。单声母增加确定性的越过目标再回找，使用旧固定方向实现做失败对照。

- 候选即时呈现与各平台几何笔记无关，不改决定。

## Alternatives considered

- 增加滑动次数或延长超时：有助于慢设备，但已到末尾时继续向前不会到达身后的第 70 项。
- 使用无障碍滚动到目标或直接修改偏移：定位简单，但会绕过真实触摸与追加链路，不能代替候选条验收。

## Verification

API 28 旧固定方向实现加入 90→70 确定性回找后，复现 CI 同样的 1873 项、目标 70 和偏移 181289 的失败。首轮修正版要求正宽度，API 35 仍失败；几何诊断确认已刷新的第 70 项边界为 `Rect(0,1544,-1308,1613)`，宽度为负但右边仍能指出目标位于左侧。诊断轮在取得该证据后主动终止，不算通过。

修正后 API 35 完整连续条专项通过：120 项末项往返、70→90→70、反向回首项、再次到目标并真实点击上屏，候选顺序断言保留。API 28 在通用整机结束后串行运行同一专项，也完整通过（`target/android/strip-overshoot-final28.log`）；两版均验证真实触摸上屏。远端 `bash scripts/verify-local.sh --quick` 退出 0；本机另跑 `pnpm run verify-notes`。GitHub x86_64 原失败环境以新 head 的 CI 为准。

设备产品 APK 复用固定 `4d661fcb96` 的包：该提交只有 OCR 与本分支不同，候选条、键盘、核心与 JNI、Rust、共享代码及资源无差异；测试 APK 从本分支重编。未复制未提交源码，也不把此专项当作 OCR 验收。

## Consequences

夹具能够从越过的目标回找，不再把负宽度裁剪矩形误当无效位置。真实 DOWN/MOVE/UP、停滞断言与 220 轮上限保持，没有增加重试或修改生产候选条。仍需刷新节点并核对序号，窗口重建后继续重取节点；新 head 的 GitHub x86_64 CI 尚须收取结果。
