# Agent Note: 全拼查询槽按需投影解析缓存

Status: implemented

## Problem

`insert_online_words` 只读取 `SeriesResolution::cache_key`，`expand_initial_candidates` 只读取规范切分来构造不带纠错前缀的键。热缓存却先克隆整个解析结果，包括完整纠错音节及两档替代切分，随后把这些副本全部丢弃。

常规 `query_exact` 的系列候选槽已经热命中时也有同样的完整复制；命中只需本次标记状态和槽键，纠错数组的拥有值没有消费者。

系列热命中前还会构造规范化音节列表；完整解析和候选槽均已命中时，这份列表也没有消费者。延迟构造必须保留数据库版本变化时先取音节、再清切分缓存的原顺序，否则失效重建会重新切分并增加冷副本。

在线回写和首字母展开虽已投影热解析，仍在投影前构造完整音节；它们的投影结果只含槽键，热解析时没有后续音节消费者。

完整查询写入系列候选缓存时总会复制槽键。只有至少两音节的原读法或纠错读法需要把原键登记为个人模型计分键，其余原键没有第二个消费者，随后被丢弃。

## Decision

私有解析方法接收即时投影回调。热命中把缓存结果包装为借用的 `Cow<SeriesResolution>`；冷未命中仍按原逻辑计算、克隆缓存副本，并把原拥有值交给回调。在线回写只取得缓存键，冷值直接转移该字符串，热值只克隆这一字段；首字母展开从规范切分构造原来的无纠错前缀键。

完整查询写入系列槽时，原音节或纠错音节至少两项的结果保留先克隆键插缓存、再把原键登记个人计分集合的顺序；其余结果直接把原槽键交给缓存。这里的分支条件继续按原音节数量，不能改成结果是否非空、是否含整句或音节是否完整。`series_slot_key` 按最终字节数构造，原键与原来的克隆拥有相同容量，转移不会额外保留过量预留。结果向量的缓存副本和调用方拥有值仍按原规则分别保存。

借用只持续回调，不跨过后续词典可变调用。缓存结构、完整键碰撞核对、FIFO 年龄、失效范围及冷缓存容量保持原样。

常规 `query_exact` 先投影拥有的标记切分、两档替代标记和完整槽键。热解析借用在即时回调内结束，不复制完整结果；冷解析保留原拥有结果。随后仍按原顺序检查个人模型和数据库版本、读取候选槽。只有需要继续读词典时才从解析缓存取得独立拥有结果，冷路径直接复用已保留的结果；系列槽失效后的热路径用投影已核对的哈希索引取得解析副本，不重复输入哈希、完整键校验或纠错搜索。投影和副本读取之间，个人模型失效只删系列槽，数据库重置明确保留解析备忘；期间没有解析缓存的插入、淘汰或其它可变访问，因此索引仍指向刚才核对的条目。

解析缓存核心接收冷构造闭包。在线回写和首字母展开只在解析未命中或完整键冲突时构造音节，热投影不填充尚未存在的切分备忘；这两个写槽方法没有后续音节消费者。保留已有音节参数的旧签名委托仅供冻结旧查询测试，拥有型旧解析入口也直接走该委托，避免测试对照随产品惰性构造改变语义。常规查询用本次局部 `Option<Vec<String>>` 保留首次构造的音节：解析冷或完整键冲突时构造一次并复用；解析热但系列未命中时才补取；两层都命中时完全不构造。这按 [Rust `Option::get_or_insert_with` 的惰性契约](https://doc.rust-lang.org/std/option/enum.Option.html#method.get_or_insert_with)执行，没有新缓存或公开接口。

数据库变化时必须在 `reset_cache` 前补取重建音节，复用原切分备忘并保留原副本成本；个人模型失效只清系列槽，后续按需取得音节。分字段的切分函数保留自动切分冷值先克隆入备忘、再规范化返回值的顺序，显式切分仍走原拆分和别名规则。纯热命中有意不填充尚不存在且本次未消费的切分备忘；其余缓存格式、FIFO 读取不刷新年龄和冷插入容量规则保持原样。

投影核心按字段拆分为私有函数，允许回调同时借用重排上下文，无需先复制上下文或移动缓存。系列缓存未命中后的主切分直接借用局部拥有解析的 `segmentation`，交给主读法查询和替代切分合并。候选标记状态和最终候选仍独立拥有，借用不逃逸即时回调或本次查询。

主标记字符串的独立所有权继续保留；[主切分标记缓冲](2026-10-17-quanpin-marking-buffer.md)在同步投影内复用其已有容量，不再逐次复制后替换。本文历史计数仍为各切片当时的测量。

内层 `query_series` 的前缀中间键由[系列前缀借用](2026-10-14-quanpin-series-prefix-borrow.md)处理，本篇保留外层主切分拥有值、解析投影和版本失效顺序。

## Alternatives considered

- 用 `Arc<SeriesResolution>` 替换缓存拥有值：热命中可以共享全部字段；不选，因为会增加冷路径分配和引用计数，还需重新判断直接保存计算结果的多余容量。现有两个回写调用只需要键，借用投影足够。
- 回写调用各自增加缓存快查：改动局部；不选，因为会复制完整键核对和冷解析逻辑，或让冷未命中重复哈希和查找。
- 回调只接收 `&SeriesResolution`：接口简单；不选，因为常规候选查询仍要独立拥有结果，冷路径将多克隆一份；区分拥有和借用可以转移原结果及在线键。
- 把主切分字符串移出局部解析：也能省去复制；不选，因为其余查询仍引用完整解析及纠错字段，局部只读借用就能覆盖主读法和替代合并，无需引入部分移动。
- 在投影里先检查系列槽，未命中立即克隆完整解析：能少一次未命中时的解析备忘查找；不选，因为会给每次热命中增加一次系列槽查找，并把个人模型/数据库失效前后的两次判断耦合起来。当前热命中直接结束，未命中按原次序处理失效再取得拥有值。
- 始终先构造音节，再检查解析和候选缓存：顺序简单，天然保留失效前的切分副本；不选，因为两层热命中时仍有完整且无人消费的音节向量。仅在解析冷、候选未命中或版本变化时构造可保留这些实际消费者。
- 把所有未命中的音节构造统一放到 `reset_cache` 之后：实现最短；不选，因为数据库变化会先清掉可复用的切分备忘，导致自动切分重新计算、再次保存冷副本。版本变化测试同时锁定分配相等和重建后切分备忘仍空。
- 将自动切分缓存音节借用到查询结束：能直接省去缓存命中的副本；不选，因为别名规范化可能修改返回音节，版本失效又会清空缓存。延迟构造覆盖无人消费的整份列表，不让借用穿过可变失效调用。
- 所有系列重建统一转移原槽键、提前另存可选个人计分键：能只写一次缓存插入；不选，因为只有未登记路径缺少第二个消费者，登记路径本来就需要两份键。保留该路径的原副本去向和先插缓存再登记顺序，只在未登记分支转移更直接。

## Consequences

[活动词典保留已预热 n 元表](2026-10-14-active-dictionary-ngram-tables.md)消除词典查询对共享表缓存驻留的依赖；本篇关闭词网格隔离各项预算的覆盖边界仍保留。

热回写和系列热命中省去不需要的完整纠错结果副本，继续读词典的查询和冷缓存克隆仍然存在。即时回调不增加缓存状态、引用计数、公开接口或依赖。只有热解析而候选槽未命中或失效时，按已核对哈希索引多读取一次解析备忘；不重复输入哈希或完整键校验，申请次数保持原样。配对计时覆盖这一控制路径，但本机波动不足以判定稳定的时间成本。

两层热命中省去音节构造及未消费的自动切分备忘填充；系列未命中仍取得独立音节，冷解析保留本次音节供后续查询复用。每次延迟取得音节增加局部 `Option` 判断，冷构造闭包不重复执行。补取音节只修改切分备忘，不触碰已核对的解析条目；数据库重置前取音节的顺序不能移动到重置后。先前热查询未填充备忘时，后续首次未命中会承担切分冷成本；序列对照证明累计分配不增加，单次未命中分配不保证与已在前次热查询付过成本的旧状态相同。

在线回写和首字母展开也省去热解析时无人消费的音节，解析冷及完整键冲突仍按原顺序构造和保存切分备忘。它们热写槽后若备忘仍空，后续真正消费音节的查询会承担该次冷构造成本；这里的预算是写槽单次收益，不把尚未支付的冷构造成本算作整段交互收益。

在线回写须保留 `C:` 纠错前缀，首字母展开继续按旧契约去掉它；不能把两个查询槽规则合成一个。继续读词典的查询必须取得拥有解析，缓存借用不得逃逸回调；冷缓存仍使用原克隆副本，不能用投影顺手转移过量预留容量。候选槽在版本检查后才可返回，不能因为投影时看过缓存而跳过失效检查。

不登记个人计分键的系列未命中少一次槽字符串分配；登记路径和系列热返回保持原成本。系列插入与登记仍按原顺序，FIFO 读不刷新年龄，个人模型变化只删除登记过的槽；不引入缓存状态、公开接口或依赖。
