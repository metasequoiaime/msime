# Agent Note: 拼音切分批次直接归并表键

Status: implemented

## Problem

`query_exact_segmentations_keyed_flat` 先把每个切分的 `(table, key)` 收集到临时 `Vec`，去重后再移动到按表分组的 `BTreeMap`。常见批次不超过 16 条，向量只承担一次过渡存储，切分键最终仍要进入按表分组的容器。

## Decision

切分批次不超过 16 条时，直接把有效键插入 `BTreeMap`，在对应表的键列表中线性检查重复项；更大的批次继续使用原有向量和哈希去重回退，避免无界批次退化为平方复杂度。表的排序、键的首次出现顺序和 SQL 分组保持不变。

## Alternatives considered

所有批次都直接线性归并可以去掉过渡向量，但大批次会重复扫描已有键，放大查询规划成本。只缩小过渡 `Vec` 仍会为短批次分配临时容量，不能消除这一路径的堆状态。

使用固定数组保存拥有型 `String` 会给批次引入额外容量边界，且仍需把字符串逐项移动到 `BTreeMap`；按 16 条边界分两条路径更直接。

## Verification

新增小批次表键归并的分配预算测试。旧路径在两条同表切分上产生 8 次分配，直接归并后不超过 7 次；既有 16 条边界两侧的键去重、跨表分组和查询结果测试继续通过。

## Consequences

短批次少一次临时过渡存储分配，代价是最多 16 条键的有界线性重复检查；大批次仍保留哈希去重和原有复杂度边界。

固定单跨度的[规范化查询键规划](2026-10-10-pinyin-lattice-span-key-plan.md)直接使用单键批量 SQL，省去该入口的单项表分组；本篇多切分批次的归并与大批次回退不变。
