# Agent Note: 九键候选规范读音复用行内字符串

Status: implemented

## Problem

九键刷新候选时，无论候选是否已有完整规范读音，都会复制一份 `canonical_pinyin`（或 `pinyin`），随后用新的数字串替换 `pinyin`。候选行原有的字符串容量因此不能复用，常见的短数字输入每次刷新都会为候选规范化产生额外分配。

## Decision

规范读音非空时直接移动候选行已有的 `canonical_pinyin`；为空时只复制一次原始 `pinyin` 作为规范读音。更新候选的显示拼音时清空并写入数字串，保留原 `pinyin` 的容量。候选过滤、模糊匹配、规范读音和排序结果保持不变。

## Alternatives considered

继续复制两个字符串实现最简单，但每次刷新都会丢弃可以复用的 `pinyin` 容量。把候选字段改成共享字符串会扩大 `WordItem` 的所有权契约，超出单次刷新优化的范围。

## Consequences

九键候选刷新在候选已有容量时少一次或多次字符串分配；规范读音为空的候选仍需为独立的规范键复制一次内容。新增分配预算测试覆盖短数字输入并验证刷新分配下降。

## Verification

目标测试先在旧实现上观察到 150 次分配并失败，复用后通过 149 次以内的预算；后续运行九键相关测试、Engine 全量测试、golden、Clippy、Rustfmt、笔记校验、差异检查和 quick 门禁。
