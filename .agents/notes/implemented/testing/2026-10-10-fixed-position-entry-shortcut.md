# Agent Note: 固定位置入口复用日志存在性

Status: implemented

## Problem

普通候选刷新在没有个人日志、也没有在线候选时仍会构造位置上下文并进入固定位置处理，产生临时分配。日志存在时，会话入口和底层固定位置函数还会重复检查同一个文件。

## Decision

会话候选入口先检查日志和在线候选；两者都不需要固定位置时直接返回。日志存在性结果传给固定位置实现，避免同一轮刷新再次访问文件系统；其他调用方继续使用原有包装函数，行为保持不变。

## Alternatives considered

只在固定位置函数内部提前返回仍会保留会话入口构造上下文的开销；每个调用点单独缓存状态会导致日志创建后的失效同步；移除固定位置处理会破坏已保存位置和在线候选槽位。

## Verification

旧实现的普通候选固定位置刷新产生 13 次分配，新实现为 0 次。固定位置单元测试、混排方案位置测试、个人日志路径测试、完整引擎测试、Clippy、Rustfmt、笔记检查和 quick 门禁覆盖提交。

## Consequences

没有个人日志的普通输入跳过位置上下文和临时缓冲；有日志或在线候选时继续执行原有固定位置和动态候选排序。
