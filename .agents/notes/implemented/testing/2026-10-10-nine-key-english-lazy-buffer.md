# Agent Note: 九键英文空结果延后缓冲

Status: implemented

## Problem

九键英文查询按候选前缀数乘单前缀上限预留 `words`，但数字可能没有任何英文词条，或所有数据库行会被九键数字匹配过滤。空结果仍占用理论页容量。

## Decision

英文词条结果向量改为空创建，首次收到完整组码查询匹配的词条才按原理论上限 `reserve_exact`。候选预留时机不改变排序和去重；完整码过滤现由词库查询在限额前执行。

## Alternatives considered

- 查询前按前缀上限预留：命中路径少一次容量判断，但无匹配数字会分配无用空间。
- 逐词自然扩容：空结果同样无分配，但命中页会改变原容量提示和扩容次数。

## Verification

新增无匹配数字 `999999` 以及“查询到词但全部被数字匹配过滤”的回归测试，断言结果为空且容量为 0；旧实现实际容量为 320，测试先失败，延后预留后通过。另验证命中路径仍保留原理论容量。九键模块 134 项测试通过。

## Consequences

英文九键空结果不再预留前缀理论上限；首次有效结果仍一次预留原上限，输出内容和排序保持一致。

完整组码与查询限额的先后顺序由[分组键盘英文先过滤再限额](../bug-fix/2026-10-21-keypad-english-filter-before-limit.md)约束，保留本篇的预算与分配边界。

[九键英文前缀页直接追加](2026-10-23-nine-key-english-page-append.md) 消除分组查询的临时候选页；本篇原有的查询、复用及容量契约继续保留。
