# Agent Note: 拼音精确键批次去重的小批次路径

Status: implemented

## Problem

`query_exact_keys_per_key` 原来总按输入键数创建 `HashSet`，但短批次只需检查此前的键。查询还在去重前调用 `split_segments`，重复键也会创建音节向量并复制非空音节文本；查询本身虽然去重，临时拆分仍按原输入次数发生。

## Decision

输入不超过 64 个键时，按输入顺序线性扫描此前的键；更大的批次继续使用 `HashSet`，避免无界输入退化成平方复杂度。先执行 `query_key_is_new`，仅对首次出现的键进入完整键规划；拥有型拆分由后续[借用键规划](../../implemented/testing/2026-10-10-pinyin-borrowed-key-plan.md)消除。原实现已在完整拼音验证前记录新键，调整只提前同一个检查，非法键与空键的去重状态不变。重复键仍只保留第一次出现，完整拼音过滤、查询规划、SQL、每键行数上限及结果字段/顺序/容量保持不变。

## Alternatives considered

所有批次都改成线性扫描可以消除哈希表分配，但大输入会退化成平方级；只缩小哈希表仍保留短批次分配。保留先拆分再去重能保持原执行顺序，但重复键的拆分结果从不参与查询。把通用分段接口改为借用切片能进一步减少唯一键分配，但会扩展共享接口。去重切片只提前现有检查，后续借用规划通过私有辅助函数缩小改动范围，保留通用分段与表名接口。

## Verification

既有小批次零临时分配与 64/65 键去重边界测试保留。新增 `dictionary/pinyin/dedup_before_split_tests.rs`，冻结远端基线 `41bb27db0e6473b09fdda3e383782c00e07fc530` 的完整按键查询正文，两侧均使用已合并的底层、聚合和结果表延后预留，仅比较重复拆分。红测试在旧生产上实际失败：96 个重复单音节键两侧各分配 196 次，少 190 次的预算失败。提前去重后 7 项新测试通过，覆盖 1/64/65/96/129 键、单/双/五音节、非法与空段/空键、命中/未命中/缺表、跨表与等权/负权/大权重、零限额/关闭连接、单音节无界限额、真实 SQLite 首步溢出及 129 个唯一键。映射按键比较，逐键行字段、顺序与容量严格相等；唯一批次总分配次数相等。

完整冷边界先在区间外初始化不可变音节表与线程级随机状态，数据库打开、缓存、规划、查询及显式析构均在区间内，仅返回结果并借用外部路径/键。PR #6591 验证时 arm64 debug 的 96 重复键：单音节未命中 219→29 次、命中 224→34 次；双音节未命中 318→33 次、命中 324→39 次。每个重复单音节省 2 次、双音节省 3 次，空键不省拆分。峰值分别为 2810、9122、3469、9990 字节，两侧相等；返回存储分别为 0、6405、0、6413 字节，两侧相等且最低差值均为零。[空结果表预留](../../implemented/testing/2026-10-10-pinyin-empty-key-map-storage.md)的旧冻结对照保留，仅在次数断言里独立加入重复拆分收益，不重复归因于结果表。独立新进程冷测试通过；完整引擎 1544 项单测通过（13 项忽略）、golden 31 项通过，Clippy `--all-targets -- -D warnings`、格式、差异和 364 篇笔记检查通过。独立审查核对冻结正文、去重状态、字段/顺序/容量、旧测试次数补偿和冷测量边界，无阻断。完整 quick 通过共享 Rust、Android target/Java 宿主、Linux 外壳和原生宿主（73 项测试）、macOS 原生宿主与 Apple bridge；Windows 本机 102 项通过。完整 Windows 交叉构建、wasm 与 HarmonyOS 真打包因工具链/资源缺失跳过。

## Consequences

64 个键以内的去重为平方级，但该路径的输入有界；更大的输入继续使用借用键的哈希表，默认随机哈希器不变。`TYPO_KEY_BUDGET` 为 96，不能把全部纠错批次称为线性路径；纠错 `plan_keys` 与滑行 `rank_by_dictionary` 都已主动去重，以上重复输入计量只适用于数据库入口收到重复批次，不代表每次真实纠错或滑行都有该收益。去重切片当时保留唯一键拆分，后续借用规划另处理其存储；以上去重计量的峰值/返回存储没有改善。当前旧冻结对照另在次数断言计入首次键拆分节省，保留历史正文；未做发布构建计时或真实宿主延迟、SQLite C 堆或 RSS 测量。

当前按键分组的键副本由[借用输入键分组](2026-10-10-pinyin-borrowed-key-groups.md)消除；本篇冻结查询正文与历史测量保留，次数预算在计量区间外独立补偿首次合法多音节键的克隆节省。

当前结果槽通过[复用已有结果键](2026-10-10-pinyin-result-key-reuse.md)消除重复行的键副本；本篇冻结正文与历史测量保留，热次数预算在区间外独立补偿该聚合收益，既有冷场景每键至多一行而无需追加补偿。
