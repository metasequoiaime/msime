# Agent Note: 拼音精确键批次去重的小批次路径

Status: implemented

## Problem

`query_exact_keys_per_key` 每次都按输入键数创建 `HashSet`，但纠错边收集一次最多提交 96 个键；短批次只需要检查此前出现过的键，却仍会产生临时哈希表分配。

## Decision

输入不超过 64 个键时，按输入顺序线性扫描此前的键；更大的批次继续使用 `HashSet`，避免无界输入退化成平方复杂度。重复键仍只保留第一次出现，完整拼音过滤、每键行数上限和结果顺序保持不变。

## Alternatives considered

所有批次都改成线性扫描会让较大的纠错批次出现平方级查找；只缩小哈希表仍保留短批次的临时堆分配。

## Verification

新增小批次零临时分配测试，以及 64/65 条边界的去重结果测试。调用方 `TYPO_KEY_BUDGET` 为 96，线性路径因此覆盖常见纠错批次；完整引擎测试、Clippy、格式检查、笔记检查和 quick 门禁覆盖提交。

## Consequences

64 个键以内的去重为平方级，但该路径的输入有界；更大的输入继续使用哈希表。
