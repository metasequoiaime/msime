# Agent Note: 词网格约束过滤复用终点计数缓冲

Status: implemented

## Problem

`decode_constrained_sentences` 在按起始音节列过滤词网格边时，每一列都重新创建 `vec![0; syllables.len() + 1]`。计数只在当前调用的过滤循环内使用，长度固定，旧向量在下一列马上丢弃；长输入会为同一轮约束查询重复申请相同大小的堆缓冲。

## Decision

在整个过滤循环外建立一个与音节数相同的 `Vec<usize>`，每列开始把已有元素清零后复用。保留按终点计数和 `span_limit` 的筛选顺序，不改变图边、解码或公开函数契约。

## Alternatives considered

- **继续每列创建计数向量**：代码最直接，但重复申请和释放固定长度的工作缓冲，约束查询的列数越多浪费越大。
- **使用固定大小栈数组**：可以避免堆分配，但输入音节数没有适合的编译期上限，额外的截断规则会改变现有函数对长句的处理边界。
- **把计数放进图边或调用方状态**：能复用更久，但会扩大图边所有权或公开调用契约；计数只服务本次过滤，没有必要延长生命周期。

## Verification

- 分配回归先在旧实现上以 `21` 次申请超过 `6` 次上限而失败；复用计数缓冲后为 `6` 次并通过。
- 约束过滤行为测试覆盖按终点的 `span_limit` 和接受谓词，结果保持为 `甲乙`；空输入保持零分配且不查询词库。
- 词网格解码 62 项定向测试通过；完整引擎单测 2281 项通过、40 项既有忽略，Golden 31 项和 input-runtime 318 项通过；Clippy、格式、差异检查和 `pnpm run verify-notes` 已通过，本地 quick 门禁在提交前完成。

## Consequences

每次约束过滤只为终点计数申请一次缓冲，后续起始列只清零已有元素；在 16 个音节的空图回归中从 21 次申请降到 6 次。复用缓冲必须在每列过滤前完整清零，否则前一列的终点计数会错误限制后续列。输入图和公开解码结果仍由原有路径拥有，未引入新的生命周期边界。
