# Agent Note: 词网格合并短列表去重

Status: implemented

## Problem

词网格合并每次都按现有候选和解码路径创建 `HashSet<&str>`。默认解码路径很少，短列表只需要检查已有候选和刚生成的句子，却仍会分配临时哈希桶；自定义查询又可能返回更大的候选列表。

## Decision

现有候选与解码路径合计不超过 64 条时，线性扫描候选和当前输出块；超过边界继续使用借用键的 `HashSet`。无重排和神经重排都走同一边界策略，保留重复句子的首次出现、`show_next_on_duplicate` 语义和插入顺序。

输出块的分配时机由[空句子输出块延后分配](2026-10-10-lattice-empty-block-buffers.md)进一步约束，线性/哈希边界与本篇决定保持一致。

## Alternatives considered

所有合并都改成线性扫描会让无界词典候选在大列表上退化为平方复杂度。始终创建 `HashSet` 保持查找复杂度，却无法消除默认短列表的临时分配。按实际合并规模分流能覆盖两种调用形态。

## Verification

新增线性句子去重的零临时分配测试；完整引擎单元测试（1158 项）、Clippy、Rustfmt、差异检查和 quick 门禁覆盖实现。

## Consequences

默认短句子合并不再为去重分配哈希桶，代价是最多 64 条输入上的有界线性比较；大候选列表仍保持哈希查找复杂度。
