# Agent Note: 在线提供方过滤后延后结果缓冲

Status: implemented

## Problem

`UnixSocketProvider::query_candidates` 在解析响应后按响应条数创建候选结果 `Vec`。当前查询可能关闭云端或 AI 来源，响应会在来源校验阶段全部被过滤；这时查询返回空结果，却仍为最多 11 个未使用的候选槽位保留容量。

## Decision

结果向量从空容器开始，首条候选通过来源和配额校验、即将写入时才按原响应条数一次预留。空过滤结果保持零容量；有效响应继续保留原有的单次容量提示、去重顺序和来源配额。[在线候选已有词去重](2026-10-08-online-batch-existing-dedup.md)笔记处理的是运行时缓存批次的去重哈希表，本篇只处理 Unix socket 响应结果容器，两者存储层不同。

## Alternatives considered

- 查询前继续按响应条数预留：有效批次少一个分支，但每次来源关闭或无可用候选的响应都承担固定结果容量。
- 按每个通过候选自然增长：空批次同样零容量，但有效响应可能多次扩容，失去已有的一次性预留。
- 先筛选响应再单独计算唯一候选数：需要额外暂存或重复扫描，增加 provider 热路径工作；首条通过校验时已经足以保留原上限。

## Verification

新增真实 Unix socket 回归测试，返回被当前查询禁用的云端来源，确认结果为空且容量为零；旧实现按预期以容量 1 失败，修复后通过。既有在线 provider 去重、配额、控制字符和 worker 测试覆盖行为保持不变。

## Consequences

来源过滤掉整批响应时不再申请候选结果存储；至少一条候选命中时仍按响应上限一次预留。响应解析本身的 `replies` 存储、网络超时和来源配额语义不变。
