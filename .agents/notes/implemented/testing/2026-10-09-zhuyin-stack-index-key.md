# Agent Note: 注音九键索引查询使用栈键

Status: implemented

## Problem

注音九键每次按声调结束音节都会调用 `NineKeyIndex::readings`，原先该函数先分配一个 `String` 拼接数字和调号，再查找已经建立的索引。命中和未命中查询都重复分配临时键。

## Decision

使用 `MAX_DIGITS` 加一个 Unicode 字符最大 UTF-8 长度的栈缓冲拼接键，再借用字符串查找现有映射。构造索引时只接受不超过数字上限的音节，调号从末尾单个字符拆出，所以超过栈键容量的查询必定未命中。保留数字参数的 UTF-8 检查和拼接键的原有语义。

## Alternatives considered

给索引增加可变字符串缓冲会要求改变共享只读查询接口。把映射键改为数字和声调二元组会改变建索引和查询的表示，并限制原来允许的键拆分。固定栈键即可消除查询分配，不改变索引所有权与 `Arc` 返回值。

## Consequences

五种声调的三数字查询和未命中查询不再分配临时键。返回值仍共享原来的读音组，非法 UTF-8、空键和超长参数保持未命中；非标准但等价的键拆分仍命中同一组。

## Verification

旧实现在五次命中加一次未命中查询中分配六次，零分配回归预算失败。测试覆盖所有声调、最大数字长度、返回读音内容、共享对象身份、等价键拆分以及非法与超长参数。注音单测、引擎全量单测、golden、Clippy、Rustfmt、笔记校验、差异检查和 quick 门禁覆盖本切片。
