# Agent Note: Windows 设置滚轮的真实输入回归与定向消息对照

Status: implemented

## Problem

#9161 报告 WinUI 设置页在卡片内可以滚动、卡片间隙不能滚动，报告中的测量使用窗口定向输入。源码中背景为空并不能单独证明真实滚轮存在同样问题；为未经复现的根因修改宿主，会把假设写成维护契约。

## Decision

`settings_ui.ps1` 在浅深色、1000/800 两种宽度的快捷键页调用 `settings_wheel.ps1`，以独立合成配置和真实 WinUI 宿主验证滚轮。先通过 `SendInput` 检查卡片内部的阳性对照，再检查实际卡片间隙、组前留白、左右和上下内边距、上下边界及展开的下拉框。每组 14 项断言，合计 56 项；快捷键页只有一个组，因此卡片间隙改在输入高级页的「快捷模式」和「逐个模式」之间测量。

UI Automation 只设置滚动起点、查询坐标并读取动画稳定后的百分比。被测滚动使用系统鼠标输入流，不能用 UIA 的 Scroll 操作代替。临时把窗口高度设为 600 DIP，结束时恢复滚动起点、窗口尺寸和指针位置，不修改系统滚轮选项。轨迹写入各主题/宽度的 JSON 并随原有界面截图上传。

滚动判定以物理像素为单位：根据 UIA 视口高度 `H` 与 `VerticalViewSize` 百分比 `V` 计算范围 `H × (100/V − 1)`，再将滚动百分比差换算为像素。起点、边界及弹出层允许最多一个栅格像素的差异，阳性对照必须沿预期方向移动超过一个物理像素。仍使用原生 `SendInput`，不改生产宿主。JSON 同时保存原百分比、视口高度、可视比例、滚动范围与像素位移。单位依据见微软的 [UIA 屏幕坐标](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-screenscaling)和 [VerticalViewSize 定义](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.scrollpattern.scrollpatterninformation.verticalviewsize)。

首次浅色 1000 宽度的回归另外记录 `WM_MOUSEWHEEL` 定向消息诊断，分别向顶层窗口和指针下的子窗口投递，比较卡片与间隙。目标必须属于本次合成窗口，发送有超时。定向消息绕过系统的输入路由，记录结果不计为真实滚轮通过或失败，也不要求产品处理任意发往顶层 HWND 的消息。

## 历史检索与验证

- 未改生产实现的提交 `8a173390bf`，Windows CI [run 39602562674](https://github.com/metasequoiaime/msime/actions/runs/39602562674) 中 56 项原生滚轮断言、既有 16 页界面验收全部通过。卡片间隙的向下滚动百分比为 0 → 16.9102（1000 宽）及 0 → 16.7702（800 宽），向上均返回 0，明暗主题一致。这没有复现报告，更不能证明任何背景补丁有效。
- [透明背景提案](../../rejected/bug-fix/2026-10-21-windows-settings-wheel-hit-test.md)记录当时最强的原因推断及拒绝落地的证据；本次仅加入回归和输入路径对照，不修改生产宿主。
- [WinUI 模板陷阱](../bug-fix/2026-10-17-windows-settings-winui-template-traps.md)持有其他模板问题，与本次输入路径实验无重叠。
- PR #9083 处理 SDK 的系统滚轮路由问题。本回归不修改 SDK，不复制其他工作区的未提交内容。
- Win7 完整验收的同源现代包在 Windows 11 23H2 上触发旧边界阈值：两轮分别为顶部 `0 → 0.0818875%`、底部 `100 → 99.9060824%`。未改断言的第三轮额外测量得到视口 543 物理像素、可视比例 66.7076167%、滚动范围 271 像素，顶部 `0 → 0.1384816%` 对应 0.375285 像素，正常滚轮约 81 像素。旧的固定 `0.01%` 在该页面仅为 0.0271 像素，因此会将亚像素读数变化记为失败。这里记录的是实测误差，不推断所有控件均有同样舍入。完整像素指标复跑 `040-fixed-modern-settings-pixels-undisturbed` 的 56 项真实滚轮断言、64 次页面渲染及其余原有交互全部通过，边界最大绝对位移 0.457215 像素，弹出层均为零。详细结果随[产品验收](../feature/2026-10-24-windows7-product-build.md)记录，原失败日志保留。
- 两轮 quick 及笔记门禁通过；新增诊断经 Windows PowerShell 5.1 解析、C# 输入桥编译通过。非交互 SSH 不能作为界面验收。

## Alternatives considered

- 直接给页面和视口加透明背景：两处改动即可让空白面板可命中，且微软有明确的通用说明；当前生产代码的真实滚轮回归已经通过，缺少失败对照，因此拒绝把它当作本例修复。
- 直接放宽固定百分比：改动最少，但相同阈值随内容长度代表不同距离，长页面可能掩盖真实移动；采用物理像素阈值，同时提高阳性断言要求。
- 用 UIA Scroll 模拟滚轮：定位稳定、无须鼠标；它绕过被测的命中检测与系统输入路由，无法证明滚轮有效，因此只用 UIA 复位和读取。
- 要求定向消息与系统输入流完全等价：便于复用自动化工具；消息接收 HWND 和焦点路由可能不同，等价断言会把工具路径当作产品契约，因此保留独立诊断。

## Consequences

收益是设置页已有可重复的真实滚轮回归，并能对照定向输入的差异；代价是界面套件增加原生输入和等待动画的耗时，需要交互桌面运行。

Windows CI 使用的系统环境不等同于报告中的 Windows 11 25H2；实体鼠标是否复现、报告当时的目标 HWND 与输入路径仍待核对。本 PR 使用 `Refs #9161`，不关闭 issue，也不宣称问题已修复。
