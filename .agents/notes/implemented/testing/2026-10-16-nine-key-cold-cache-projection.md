# Agent Note: 九键冷页借用投影后移交完整缓存

Status: implemented

## Problem

固定 `a0560876cf289af1e455571d58075d0efddb648b`、模型 pin `6ce2cbb5` 的九键二十秒采样仍出现大量申请、析构与 `WordItem` 深复制。`linear_into`/`dot_i8` 栈顶分别 1644/958 次；申请与释放的前两个入口分别 704/708 次。系列冷页先完整复制进缓存，再由九键筛掉补全等拒绝行，已实施的热页投影没有覆盖它。采样运行的模型 p95 48.92 ms 受到采样及系统负载影响，不能作为正常延迟成绩。

## Decision

筛选入口借用冷页：回调先同步借用完整局部页，只复制通过的行，随后原页移入同一 FIFO 槽。普通拥有查询保留原有冷页转移路径；模糊合并保留完整拥有结果后筛选。保持全部字段、顺序、标记、个人计分登记、槽键、失效和 FIFO 年龄。冷页投影现在先于入缓存；普通转移回调只取拥有结果，筛选回调同步借用局部页，不能重入借用字典。允许有拒绝行的冷页输出字段容量缩至内容长度，投影后对原页执行 `shrink_to_fit`，再移入缓存；全保留时完整副本入缓存、原页交输出，不增加缩容申请；普通冷页与模糊路径仍按原方式复制。

## Historical audit

[热页筛选](../../implemented/testing/2026-10-16-nine-key-filter-before-clone.md)部分重叠，本片扩展其冷页路径并明确翻转冷页容量完全相等的限制；两篇互链。[系列前缀流式追加](../../implemented/testing/2026-10-16-quanpin-prefix-row-stream.md)只管内部组装，[原始行投影](../../implemented/testing/2026-10-14-quanpin-row-cache-projection.md)只管 DictRow；均保留。矩阵行分派与批处理已有负结果，不重做。没有完全吸收或过时提案。

## Alternatives considered

- 所有查询一律借用冷页：实现更短，但普通查询本来可以返回原拥有页，无需改其容量与复制路径。
- 在完整缓存前过滤：能连缓存也缩小，但会让后续其它筛选读到缺行的答案，不能保持缓存独立性。
- 不缩减原页容量：省一次重分配，未缩容原型也观察到局部收益；组装夹具却使 129 行缓存多持有 17272 字节，放弃该版本并在投影后缩减外层容量。
- 全链共享字符串：能减少更多副本，但改变缓存、快照和学习的所有权边界，本片只同步借用。

## Verification

真实 SQLite 冷查询红测试在 1 行全拒绝时旧路径 49 次申请，新预算加拒绝行副本后为 52，证明旧路径多复制三个字段；实现后严格预算通过。已有热页预算不变。广域测试覆盖冷/热、全留/半留/全拒绝、清缓存、模糊、标记与输出修改后的独立性；只对无模糊冷页允许容量缩减，热页与模糊页保持严格相等。固定旧完整九键刷新对照仍检查全部字段与容量。

首次局部矩阵在 debug 测试分配器下每形状 40 对交替运行，32 行全拒绝/半留中位比 0.781043/0.880982，128 行全拒绝/半留为 0.610480/0.797062，全留 0.977732；小形状全部低于 1.05。这是带测试分配器的探索，不是预定普通分配器 release 门禁。

## Consequences

缓存接管完整未筛选页，输出只复制通过行；输出字段容量与旧路径可能不同。外层容量缩减可能增加一次重分配；普通冷页以外的分支不放宽原申请预算。最终质量 JSON 与旧版整体相等。下列未缩容探索与最终版本分开记录；不能把局部收益当成整体达到 16 ms。

## Retained capacity

普通冷页容量允许缩减，热页及模糊页保持原严格相等。单音节与双音节的合成 SQLite 页覆盖 1/4/32/128 行和全拒绝/半留/全留；分别计算返回 Vec 与当前完整系列槽的容量，包括所有字符串和 sentence_words。最初未缩容原型的所有初次形状旧/新持有字节相等；128 行全拒绝时单音节缓存 20242 字节、缓存加返回向量 37650 字节，双音节分别 21266/38674 字节。这里只是该页逻辑请求容量，不包括分配器元数据、SQLite C 分配、其它缓存或 RSS，不能推断任意真实页无持有量增长。

追加真实短前缀组后，全部测试形状的返回页加槽容量总和仍相等，但存储位置不同：双音节 128 条完整行再追加 1 条短前缀，缓存由 21418 增至 38690 字节（+17272），全拒绝总和都为 56234 字节，全保留总和都为 60108 字节。返回页消费后，缓存的增量继续存活至 FIFO 驱逐；128 个同形状槽相当于约 2.11 MiB 额外容量。这暴露了未缩容原型的持有内存代价；旧实验只要求夹具缓存不超过旧值两倍、页与槽总和保持，该宽松门禁没有保留到最终版。默认 FIFO 仍为 128 槽，未扩大缓存寿命或槽数。

缓存增量实验后，首个缩容版本在投影后缩减外层 Vec：129 行组装缓存回到 21418 字节，旧/新总持有容量在全拒绝时为 56234/38962 字节，全保留为 60108/42836 字节，各少 17272 字节。原型没有缩容时的数值保留作为放弃理由；最终测试要求返回页与槽总和不增加、槽容量不增加，并只在有拒绝行且真实富余容量缩减时允许一次重分配。全保留修正后不再采用该分支的容量下降数字，恢复旧页与副本的持有容量。该结论仍限于测试矩阵，不声称所有字段的未用容量都会消失。
