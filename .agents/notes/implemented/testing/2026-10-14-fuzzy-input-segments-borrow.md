# Agent Note: 模糊查询输入音节借用

Status: implemented

## Problem

`fuzzy_candidates` 已延迟拥有每个前缀的读法，但进入循环前仍用 `split_segments` 分配音节向量并复制每个非空段。beam 只读输入音节，最终路径由 `fuzzy_syllables` 独立拥有；输入副本没有所有权消费者。

## Decision

`fuzzy_segmentations` 位于私有 `pinyin` 模块，没有从 crate 导出。该内部入口接收 `AsRef<str>` 切片，拥有型与借用型输入共用原 beam 正文；字典按原段数预留 `Vec<&str>`，读取原样撇号分段，不复制音节。保留向量与前缀切片，避免每条路径过滤时重新扫描输入分隔符。原路径排除使用逐项文本比较，并核对全部长度；路径展开和输出容量策略不变。

## Existing decisions

已检索活跃笔记的模糊路径、前缀和 `fuzzy_segmentations`。[模糊前缀延迟拥有](2026-10-14-quanpin-fuzzy-typed-prefix-borrow.md)曾明确将输入音节借用留给独立决定，本篇部分重叠并互链。[beam 复用父路径](2026-10-09-fuzzy-path-reuse.md)继续拥有父路径转移、单变体容器与字符串转移，完全保留。[行投影](2026-10-14-quanpin-row-cache-projection.md)及[行索引借用](2026-10-11-fuzzy-row-cache-key-borrow.md)属于查询后缓存策略，保持。拼音聚合页和切分键去重属于 SQL 层，与本次输入存储无关；没有完全吸收或过时提案。现有 `PinyinDatabase::batch_rows<K: AsRef<str>>` 是同仓库的拥有/借用切片参考。

beam 的变体列表由[借用变体视图](2026-10-14-fuzzy-variant-views.md)处理；本篇继续持有输入音节借用。冻结 beam 的展开依赖转接固定旧展开，次数预算在计量外独立补偿后续的变体存储节省。

没有真实分叉的 beam 由[延后拥有原切分](2026-10-14-fuzzy-beam-lazy-start.md)进一步省去完整原路径；本篇继续持有输入音节借用，冻结预算在计量外补偿必空路径，非空输出容量保持。

## Alternatives considered

- 所有前缀都直接从字符串迭代：能消除输入向量；未采用，因为原路径过滤需要重放输入，每条输出路径都额外扫描分隔符，前缀循环也重复拆分。借用切片保留原索引遍历。
- 保留 `&[String]` 包装并另设借用入口：保持具体函数类型，已有调用方无须适配；未采用，因为该函数位于私有模块，未从 crate 导出，包装在生产里没有消费者并触发 Clippy 的死代码门禁。内部入口直接泛化只需为一个无类型空切片测试标注 `&[String]`，没有对外接口变化。
- 栈上保存固定数量音节：短输入还能省向量；未采用，因为本入口没有固定输入上限，需要额外溢出状态与回退，先消除音节所有权副本。

## Consequences

空输入无段，而非空输入中的空段必须保留；不能以 `zip` 前缀相等误删路径。输出仍拥有全部字段。收益只归于 Rust 临时存储，不声称 CPU、RSS 或设备延迟。

标准库的 [Iterator::eq](https://doc.rust-lang.org/std/iter/trait.Iterator.html#method.eq) 核对逐项内容与整体长度；没有 crate 对外接口变更、状态、依赖或 unsafe。保留一份借用音节向量；省去音节字符串申请，并把每段向量槽从 `String` 缩小为 `&str`。
