# Agent Note: 模糊拼音伙伴引用栈缓冲

Status: implemented

## Problem

`pinyin::fuzzy::with_partners` 为初声或韵母收集少量字符串引用时不需要临时 `Vec`。这些引用只在当前 `fuzzy_syllables` 调用期间使用，初声最多 6 个伙伴，韵母最多 5 个伙伴。原音节已经作为结果首行，伙伴列表首项组合仍会重复构造它并在去重时丢弃；其他组合也可能不是合法音节，先创建字符串再检查会产生无用分配。

## Decision

使用按伙伴表长度加一的 const 泛型数组保存引用，并返回有效元素数量。`fuzzy_syllables` 只把有效切片用于笛卡尔积，跳过两个首项组成的原音节组合，结果字符串仍由原有结果向量拥有。数组容量由实际规则表确定，不引入运行时输入上限；原音节继续在结果首位。

其余组合在 `MAX_SYLLABLE_LENGTH` 字节的栈缓冲中拼接，借用 `intact_piece` 返回的静态音节检查合法性与重复，只为最终保留的结果调用 `to_owned()`。六字节边界来自完整音节表，已有测试核对表中最长音节与常量一致；超过边界的组合通过 `get_mut` 安全跳过。无效输入与规则关闭时仍走原有早返回。

最终变体规划由[借用变体视图](2026-10-14-fuzzy-variant-views.md)接管；本篇保留伙伴表引用、合法性验证与去重规则，实际输出路径才拥有字符串。

## Alternatives considered

继续返回 `Vec` 并只减少预留容量仍会为每次模糊展开创建堆状态，不能消除短路径的临时分配。

使用固定的单一最大数组会让不相关的规则表承担更大的栈帧；按表长度生成数组能保持边界与数据定义一致。

构造全部组合后统一去重可以保持循环简单，但原音节组合已确定存在于首行，提前跳过它不改变结果，又能避免必然被丢弃的字符串分配。

使用 `String` 拼接声母与韵母能直接调用 `is_intact`，也不需要固定大小的临时缓冲；但合法音节本来就有共享的长度上限和字节查询入口，复用它们可以在创建结果字符串之前过滤无效组合，避免每次展开产生无法返回给调用者的堆状态。

## Verification

伙伴引用分配预算测试验证栈数组路径为 0 次临时分配。原音节组合回归测试覆盖初声与韵母同时扩展（6 次降为 5 次）、无初声（4 次降为 3 次）和规则无变体（3 次降为 2 次），并逐项核对输出顺序。双音节 beam 结合[路径与变体所有权复用](2026-10-09-fuzzy-path-reuse.md)后为 32 次分配。模糊拼音测试、引擎全量单测、31 项 golden、doc tests、Clippy、Rustfmt、笔记检查和 quick 门禁覆盖行为与接入路径。

无效组合回归测试在旧实现上确认 `lian` 分配 7 次、目标 5 次，`chua` 的单规则展开分配 3 次、目标 2 次。新增预算覆盖 `lian`、`fo` 与最长音节 `chuang` 的具体输出，并遍历全部 421 个音节的规则关闭、11 个单规则和全部规则共 5,473 种组合；每次展开的分配数必须恰好等于返回字符串数加一个结果向量。

## Consequences

模糊拼音短路径不再为初声和韵母引用建立堆向量，完整音节扩展也不再重复构造原音节或无效变体。结果顺序、去重和完整音节判断保持不变；每次调用在栈上保留两个很小的引用数组与六字节缓冲。返回值继续拥有字符串，不把内部静态引用暴露给调用者。
