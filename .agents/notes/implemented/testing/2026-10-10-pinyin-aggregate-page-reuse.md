# Agent Note: 精确拼音聚合复用首个结果页

Status: implemented

## Problem

`query_exact_segmentations_keyed_flat` 在首个非空页返回后，按原始切分数乘 `limit` 预留另一份行缓冲。输入切分可能重复或无效，也可能落在同一张表；这些条目都不能代表结果页数。`query_lattice_span` 在上游直接键构造后已绕过切分聚合，但仍把唯一表的页存储搬到第二个同容量容器。底层支持 `usize::MAX` 无界查询，聚合层却仍申请最大容量并触发溢出。

## Decision

精确切分聚合的首个非空页直接成为结果容器；直接跨度入口将唯一 `batch_rows` 页接管并保留原稳定排序。后续满页按剩余有效表数乘上限预留，短页只补实际行数缺口；乘积或最终字节容量不可表示时退回实际页行数。结果仍在所有表查询结束后稳定按权重排序。表、键的遍历顺序、每表 SQL 上限、字段、同值行保留与所有权保持一致。单表路径省去一次独立聚合分配；无界上限不再作为初始容量使用。

## 历史审计

[聚合空页延后预留](../../implemented/testing/2026-10-10-pinyin-empty-aggregate-storage.md) 持有旧预留决定；本篇翻转非空页保持旧容量的取舍，互链保留其空页约束和冷测量理由。[长词续接按页预留](../../implemented/testing/2026-10-10-pinyin-longer-rows-reserve.md) 部分重叠，借用满页/短页策略但不修改其实现。[切分批次表键归并](../../implemented/testing/2026-10-09-pinyin-table-key-buffer.md) 与[切分键去重](../../implemented/testing/2026-10-08-pinyin-segmentation-key-dedup.md) 约束规划阶段，仍有效并不改动。[直接跨度键规划](2026-10-10-pinyin-lattice-span-key-plan.md) 在同步时合入，部分重叠于单表缓冲，本片保留其全部借用键规划，只翻转保留非空聚合缓冲的决定，并将其非空分配预算精确增加一次节省。检索精确聚合、乘积与稀疏页，模糊路径复用笔记属于输入生成层，无关。

## Alternatives considered

- 只对无界上限取消预留：修复溢出，但普通单表词网格仍分配第二个缓冲，重复切分仍放大有限容量。
- 所有页直接自然增长：代码更少且无乘积风险，但密集多表路径增加扩容和容量余量。按后续满页预留能保持密集预算，短页仅按实际缺口增长。
- 所有页先收集再按总行数分配：最终容量精确，但所有页缓冲和总结果缓冲同时存活，密集峰值更高，并多分配页容器。
- 先做 SQL 计数：容量可精确规划，但多一次数据库查询，计数与读取之间的变化也需要额外快照约束。

## Verification

合成 SQLite 数据库覆盖精确批次和词网格跨度的 `usize::MAX` 查询；旧生产两者真实触发 `capacity overflow`，新实现返回完整行。冻结同步后 `2e79b2040406b4bfa4ee1eba21d99943be788261` 的完整聚合与直接跨度入口对照；精确聚合正文与同步前基线相同。单个非空页少一次分配，重复/无效切分不再放大输出容量；跨表、同权、同值、负/大权重、空页和密集页的字段与顺序保持一致。密集多表保留原分配预算，短页增长的额外次数由实际表数限制。新增 9 项测试通过，覆盖密集 32/128 行页、连续五张短页、同表多键共享上限和真实词网格合并。同步后完整引擎 `cargo test -p msime-engine --lib` 1604 项通过、13 项忽略，golden 31 项通过，`cargo clippy -p msime-engine --all-targets -- -D warnings`、格式、差异和 391 篇笔记检查通过。冻结聚合与跨度正文和固定基线机械对照一致。独立只读审查核对追加提示、布局边界、字段与顺序、测量归因及历史笔记，无阻断；同步后重新验证直接跨度入口，无界命中和真实合并均通过。

## Consequences

短页连续超过已有容量时会增加扩容与复制，属于减少无依据预留的明确代价。底层页仍按自身有限上限预留；本篇不宣称一行页返回一槽容量，也不扩大到 `rows` 或按键分组容器。请求字节不等于 RSS，未作延迟结论。

当前 arm64 debug，65 个重复切分、单表一行、limit128 的冷查询分配 168→167，Rust 逻辑请求峰值 474268→8456 字节，返回存储 465937→7185 字节，两侧最低 signed 差值均为零。数据库打开、查询及显式析构在测量区间内，外部键/路径只借用，完整音节全局表在区间外预热。真实 SQLite 两音节词网格合并三次非空查库，结果及纠错返回相等，分配 62→59。上游直接键构造已经先把共同基线从75降到62，本片只计页接管的三次分配。密集三表 32/128 行分配次数与旧实现相等；五张一行短页、limit2 的聚合容量 10→5，但分配多两次。

按 [Vec::reserve_exact 官方契约](https://doc.rust-lang.org/std/vec/struct.Vec.html#method.reserve_exact)，参数是相对当前长度的追加行数，不能把容量缺口当作参数；此实现先比较剩余容量，再申请整个追加提示。满页提示用 `checked_mul`、`checked_add` 和 `isize::MAX / size_of::<DictRow>()` 限定布局，无法表示时按实际页长度扩容；无法实际容纳所有真实行的内存耗尽仍按标准容器契约处理。未做真实设备或发布构建延迟测量。
