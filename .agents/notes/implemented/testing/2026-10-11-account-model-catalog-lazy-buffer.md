# Agent Note: 账户模型目录校验延后缓冲

Status: implemented

## 问题

`valid_model_catalog` 先按模型上限创建 `Vec`，再把所有输入复制进去并创建去重集合。空目录或首条模型就无效时，这两块存储都没有必要。

## 决策

直接遍历输入，用一个 `HashSet` 同时完成数量、格式、默认模型存在性和重复检查。默认模型或首条输入无效时立即返回；首条有效模型出现后才按原上限为去重集合预留容量。

## 验证

新增回归测试确认首条无效模型后不会继续消耗输入迭代器；账户单元测试、Clippy、格式检查和 notes 校验通过。`verify-local.sh --quick` 已完成 Rust、Android、契约和 Linux 桌面 shell 阶段；Linux 原生宿主的既有 `fcitx5-native-test --theme-priority` 在容器中无超时挂起，随后为释放构建进程而终止了剩余 macOS 构建阶段。

## 备选方案

- 保留临时 `Vec`：实现简单，但空目录和无效目录会先复制输入并按上限分配。
- 只使用自然增长的去重集合：空路径同样没有分配，但有效目录可能多次扩容；本实现保留原上限提示。

## 后果

空目录和无效目录不再复制模型 ID，也不会按模型上限创建临时向量；有效目录仍保留去重集合的容量提示，校验结果和上限不变。
