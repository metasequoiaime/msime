# Agent Note: 粤拼分段结果延后预留

Status: implemented

## Problem

`cantonese::syllable::segment_with` 在开始搜索前固定为最多 `MAX_SEGMENTATIONS` 条结果申请容量。不可读输入、死路回溯或硬边界导致没有完整分段时，结果向量为空却仍保留 16 个槽位；粤拼候选刷新会频繁经过这条路径。

## Decision

结果向量从空容器开始。递归首次抵达输入末尾、准备写入完整分段时，再按原 `MAX_SEGMENTATIONS` 一次 `reserve_exact`。分段顺序、最大条数、死路标记、前缀处理和返回内容保持不变；无结果查询保持零容量，命中查询继续保留原容量提示。

## Alternatives considered

- 继续在搜索前预留：命中路径少一次条件判断，但每个未命中粤拼输入都会申请固定结果页。
- 按每条分段自然增长：空页可以零容量，但达到多路径上限时会增加扩容次数并改变原容量提示。
- 先计算可达分段数再预留：需要重复遍历搜索图，增加无结果输入的工作，不能保留当前回溯流程。

## Verification

新增回归断言覆盖不可读回溯输入的返回容量。旧实现运行该测试失败，实际容量为 16；延后预留实现通过。随后会运行粤拼分段测试、引擎库测试、golden、Clippy、格式、差异和笔记校验。

## Consequences

无完整粤拼分段的查询不再为结果页申请固定槽位；有结果时仍按原最大分段数准备存储。容量只描述结果向量，不代表递归路径、死路表或进程 RSS。
