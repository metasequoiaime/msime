# Agent Note: 九键锁定切分状态使用栈数组

Status: implemented

## Problem

九键选择读法时，会把已经被新锁定音节覆盖的切分位置与其余位置分别收集到两个临时 `Vec<usize>`。切分数量受 `DIGIT_LIMIT` 约束，但这条用户选择路径仍会为一次有界状态分配额外堆缓冲。

## Decision

撤销记录改为保存 `DIGIT_LIMIT` 大小的栈数组和有效数量；选择读法时原地 `retain` 未被覆盖的切分位置，并把被覆盖的位置写入栈数组。撤销时只恢复数组的有效前缀，切分顺序、去重和锁定行为保持不变。

## Alternatives considered

- **继续使用 `partition`**：实现简单，但每次带切分选择都会为保留和丢弃结果建立临时向量。
- **仅改用 `retain` 并继续用 `Vec` 保存撤销切分**：可以复用保留向量，但丢弃位置仍需要一次堆分配。
- **在会话中复用动态撤销缓冲**：能减少分配，但会扩大状态生命周期，且九键已有固定数字上限，栈数组更直接。

## Verification

新增分配回归测试：同一九键选择在带切分路径和无切分基线之间比较分配次数；旧实现为 `316` 对 `315`，新实现降为不多于基线（`315` 对 `315`）。九键相关测试 76 项通过；随后运行 Engine 全量单测、golden、Clippy、Rustfmt、差异检查、笔记检查和 quick 门禁。

## Consequences

九键选择读法不再为切分撤销状态建立临时堆向量，撤销记录的每项固定增加有限的栈内存；候选刷新、锁定恢复和用户可见顺序保持原行为。
