# Agent Note: 九键大批次候选缓存排序键

Status: implemented

## Problem

固定 `1e12fd8466`、模型 pin `cc1d3dd` 的二十秒九键采样中，`rank_key`、`is_initials_row` 和字符扫描在排序路径反复出现，栈顶样本分别为 136、96、250；`linear` 仍是最大模型热点（2140），通用行分派已有负结果。`rank_candidates` 的稳定 `sort_by_key` 会在比较中多次扫描相同候选的读音，用于简拼、补全及整句权重校准。采样受观察干扰，不作为无采样延迟成绩。

## Decision

超过 32 条的候选使用稳定 `sort_by_cached_key`，每条只计算一次原 `RankKey`；32 条以内保留原排序，避免为常见短列表引入缓存键数组。排序键、同分到达顺序、同词去重、简拼交错、个人调频和 128 条截断保持。缓存只存在于一次排序，不增加跨轮状态或来源字段。

[读音段数按字节计数](2026-10-17-nine-key-syllable-byte-count.md)继续减少每次求键的扫描成本，保留本篇的32条门槛、缓存范围与后处理契约。

## Historical audit

已按 rank_candidates、rank_key、排序键、cached key 检索活跃笔记。[二元行前缀负结果](../../rejected/testing/2026-10-15-lattice-bigram-prefix.md)部分相关，其中明确把缓存九键排序键留作后续方向，不翻转其二元评分决定；[候选缓冲复用](../../implemented/testing/2026-10-10-nine-key-candidate-buffer-reuse.md)、[leading 表延迟预留](../../implemented/testing/2026-10-10-nine-key-leading-map-storage.md)只管理外层容器，不管理排序键计算。简拼、跨路径权重、个人调频仍由各自笔记持有，没有完全吸收或过时提案。

[Rust 官方接口](https://doc.rust-lang.org/std/primitive.slice.html#method.sort_by_cached_key)规定稳定顺序且每元素最多求一次键；同仓库 `expressive_candidates` 已使用该接口。键只由整数与 bool 组成，保持全序，不引入浮点比较。短列表阈值 32 是事先选择的边界，性能矩阵必须包含 32/33 两侧。

## Alternatives considered

- 所有长度都缓存：实现最短，能减少短列表解析，但会为原本可直接排序的少量行额外分配缓存数组。
- 在 push_ranked 时永久携带键：可连首次计算也复用，但须同步筛选、候选向量和参数变化，增加跨函数生命周期契约；本片只消除同一次稳定排序中的重复扫描。
- 只替换 is_initials_row 的扫描：改动较小，但仍在每次比较重复执行同一判断，且不覆盖补全和权重校准。

## Measurement protocol

debug 专用计数先在旧代码证明大批次求键超过每条一次的预算，新版满足；计数不进入 release。固定旧完整 rank_candidates，比较全部 WordItem 字段、稳定同分、同词优胜、简拼交错、个人调频、空列表及 32/33/64/128/512/2048 条，覆盖九键、十四键和九键双拼。完整流水线配对 release 每形状 40 对、交替先后，计时包括输入复制和结果析构，批次校准至少 10 ms；大批次（至少 64 条）中位新旧比小于 0.98，其余小于 1.05，全部形状收集后统一判断，不挑样本；零与一条仅覆盖行为，不以纳秒计时判断。局部配对只证明该排名流程的收益，逐键延迟单独测量。

## Consequences

缓存键数组增加一次局部堆状态，收益可能被简拼交错和去重成本稀释；稳定语义相同仍须验证保留重复词的全部字段。64 条以上混合候选完整排名的局部配对耗时约减少 48%–58%，同分列表约减少 5%–6%；短列表保持原分配次数。局部排序收益不能替代十六毫秒逐键预算。

## Ranking verification

固定旧完整排名函数的 debug 红测试中，128 条候选求键 1966 次，超过每行一次的预算；接入缓存后该测试通过，计数仅在 debug 单测编译。长度 0/1/8/32 的实际分配次数与旧实现相等。新旧完整 `WordItem` 对照覆盖九键、十四键、Migala2 九键双拼和两项排序参数、重复词与同分稳定性。

混合来源矩阵之外，另用 64 条统一覆盖的词典行（48 音节、16 简拼）核实交错确实改变原始稳定排序，个人计数确实让指定最低权重简拼前移，再比较调频前后全部字段。该样本覆盖九键、十四键、`prefer_exact` 和 `initials_lead` 的组合，避免测试因同覆盖组没有两类行而空走分支。debug 共 4 项通过，1 项性能测试手动运行。

所有计时均在 release 构建终态后独占执行，没有同时运行构建或采样。下表为完整排名新旧逐对耗时中位比，全部 14 种形状通过预定预算，没有删除样本或调整阈值。

## Model regression

固定句子模型 SHA-256 `86ac529510cb3b4968a5e6ade83ec8080f5b34a0a681e75c362accbbd387d1c1`，用 `MSIME_NEURAL_MODEL_DIR` 指向已验证模型目录，运行 `cargo test -p msime-engine -p msime-input-runtime --locked --no-fail-fast --quiet`：2160 个引擎单测、31 个 golden、294 个 runtime 单测通过，30 项保持忽略（含本篇手动配对测试）。全目标 Clippy `-D warnings` 和 Rustfmt 通过。

全拼 60 例和九键 81 例分别生成 `convert_eval --report` JSON，与固定 `1e12fd8466` 报告载入后整体 `==`，全部字段一致（含来源分桶、分组与失败样例）。全拼 top1/MRR 为 0.833/0.842，九键为 0.617/0.640；top1 来源 database/generated 分别为 3/57、7/74，命中金标来源分别为 2/49、7/55。质量基线未修改。

本地 `verify-local.sh --quick` 通过：包含 Rust 工作区、Android/WASM 目标、Android Java 宿主、macOS 原生宿主和共享 Apple bridge 编译，以及本机可执行的 151 项 Windows 原生测试。Docker、MinGW、HarmonyOS 完整构建前置缺失的阶段明确跳过；没有平台 GUI 验收。独立审查指出混合来源样本没有实际触发交错和调频，补充统一覆盖样本后复查无阻塞问题。
