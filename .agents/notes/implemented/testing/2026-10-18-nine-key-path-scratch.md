# Agent Note: 九键路径搜索页复用会话工作区

Status: implemented

## Problem

九键路径输出已经复用，但中间搜索每次刷新仍重新建立后缀页及每页容器。两个排序算法替换的[尝试](../../rejected/testing/2026-10-18-nine-key-path-sort.md)没有通过预算，不能靠减少排序申请宣称改善；本片保留排序与所有评分规则，只复用热刷新中同样大小的页存储。

## Decision

会话持有借用静态拼写表音节的路径工作区。搜索从后向前覆写：终止页先清空并写入终止节点，每个偏移取出自身旧容器、清空、按原顺序构造、原稳定排序与截断后放回。读取后继时，它已经在本次调用中完成覆写。输出非空时，根页以复制轻量节点的迭代器物化已有路径输出，不消费页容器。输出为空时先释放旧根页容量，再按原路径建立并消费根页，让 `collect` 沿用原有分配复用和容量；首次转入热态可能再申请一次根页，之后继续复用。公开无工作区调用使用一次性局部工作区。

停止组字或切到纯字母路径时释放工作区页缓冲，仅在活动拼音组字期间保留；不增加输入位数限制，缩短输入时释放超过当前长度的页。静态拼写表的借用与已有先验相同，无unsafe或全局可变状态。

## Historical audit

[路径链](../../implemented/testing/2026-10-16-nine-key-path-chain.md)定义中间页后继和稳定排序，本片保留其算法；[路径输出复用](../../implemented/testing/2026-10-18-nine-key-path-buffer.md)只复用最终拥有字符串，本片扩展到它上游的工作页。旧的[延迟预留](../../implemented/testing/2026-10-11-nine-key-path-lazy-buffer.md)继续保证死路不额外申请页。没有翻转已采用的排序选择，无完全吸收的笔记。

## Alternatives considered

- 每次刷新重新申请所有页：所有权最局部，组字后不保留搜索容量，但热按键之间反复申请和释放相同容量。
- 复用搜索结果而不重算：同一数字串可直接跳过计算，但频度、显式切分和输出上限会影响路径，缓存失效契约更复杂；本片只复用存储并每次完整重算。
- 改排序算法消除暂存：可以减少更多短命分配，但此前完整矩阵未通过，保留失败笔记，不能将其混入缓冲复用。

## Consequences

活动组字期间保留随当前输入增长的搜索容器，代价是页容量存活期延长，组字结束时释放；每次调用仍完整重新计算，不缓存旧评分或路径。稳定排序自身的暂存申请继续存在。局部分配与切分计时不能证明完整引擎、模型重排或设备端16 ms预算达标。
