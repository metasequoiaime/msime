# Agent Note: 模糊 beam 延后拥有原切分

Status: implemented

## Problem

变体规划已零分配，但 `fuzzy_segmentations` 先建立拥有型原路径。规则开启而全部音节只有原值时，逐项复制及路径扩容后在末尾过滤整条原路径；32 个 `guo` 仍申请37次，结果为空。`limit=1` 只保留首位原组合，也不会返回路径。

## Decision

首次真正分叉前只遍历借用规划，不建立原路径。首次分叉时按原 `push` 顺序补回前缀再进入既有 beam；之后的单变体容器、父路径复用、容量、顺序与上限保持。`limit<=1` 直接返回无容量空向量。全部单变体也自然返回无容量空向量，不预扫描或重复展开音节。

## Existing decisions

已检索活跃笔记的模糊路径、原切分、单变体与延迟拥有。[父路径复用](2026-10-09-fuzzy-path-reuse.md)部分重叠，首个分叉以后继续复用父路径/单变体层，只翻转初始化必有一个拥有路径的决定。[变体视图](2026-10-14-fuzzy-variant-views.md)部分重叠，保留零分配展开，空输出容量降至零；实际输出容量保持。[输入音节](2026-10-14-fuzzy-input-segments-borrow.md)、读法前缀和行缓存的借用/投影属于独立存储层，冻结比较在计量外补偿本次省去的必空 beam。九键切分与自动纠错来源无关，没有完全吸收或过时提案。

## Alternatives considered

- 先扫描所有音节，确认没有变体后早退：易于实现，空结果可零分配；未采用，因为有分叉时重复做前缀规则展开。
- 首次分叉时按前缀长度一次预留：可省前缀扩容；未采用，因为本片只延后拥有，实际分叉保留已有路径容量与成本，独立验证收益范围。
- 原路径仍创建，最后只过滤：过程一直有至少一条路径，容易验证；未采用，因为无输出时这些拥有值无消费者，借用规划足以检测分叉。

## Verification

两项新专项在旧生产上真实失败：完整音节测试的 `a`、规则1、上限1实际3次，目标0；前缀测试的 `zan`、规则1、上限1实际4次，目标0。修复后两项通过。独立复核完整冻结 beam 匹配 `f355dc4d8dfdc3ca20e4365ddf99975255bd87ba`，仅改名/移除注释；共用的展开正文未改。

421个完整音节加8个空/非法/Unicode/长输入 × 13规则 × 4上限共22308组；8种前缀长度（0/1/3/4/5/8/17/40）× 3种原样前缀 × 4种分叉后缀 × 3规则 × 10上限共2880组，各测拥有/借用输入并清空拥有输入确认输出独立。预热不可变音节表在计量外；必空结果零分配、零容量；实际分叉的完整输出、顺序、每层向量与字符串容量和分配成本与冻结实现相同。测试包含前后单变体、空段、Unicode、部分父路径截断和 `usize::MAX`。

既有完整拥有 beam 与完整字典查询的冻结正文保持。补偿只在计量外按冻结展开判定必空，测量冻结 beam 全成本作为可省部分；实际分叉继续使用前篇的精确规划公式，不调用生产规划，没有循环依赖或嵌套计量。末父路径部分采用的见证额外要求结果非空，避免被必空节省误满足。540组冷/行页热/整条热完整查询及外部失效回归继续覆盖共享前缀预算、所有候选/缓存字段和返回值所有权。

## Consequences

首次分叉前没有拥有路径，补回前缀必须使用原样全部音节并按原 push 顺序构造，不能过滤空段或用一次预留改变实际路径容量。上限1的早退依赖展开始终原值在首位。仅主张 Rust 分配节省，不推断设备延迟、CPU 或 RSS。

沿用标准库 [Vec](https://doc.rust-lang.org/std/vec/struct.Vec.html) 的零容量空值及本仓库原 beam 复用规则；无依赖、unsafe、持久状态或 crate 对外 API 变化。原切分完整过滤仍在有路径的循环末尾进行。
