# Agent Note: @ 列表短表去重

Status: implemented

## Problem

`usable_mentions` 的主机列表通常很短，但每次仍按输入长度创建临时 `HashSet`。这为常见的 `@` 列表增加了不必要的哈希桶分配。

## Decision

列表不超过 64 行时，在线性扫描此前有效文本；更大的列表继续使用借用文本的 `HashSet`。文本或键无效的历史行不会占用触发词位置，保持原有验证顺序和首条文本语义。

## Alternatives considered

始终线性扫描会让大型导入列表退化为平方级；始终使用哈希表则无法消除短列表的临时状态。按 64 行分流覆盖常见面板列表，并保留大列表的哈希复杂度。

## Verification

新增短列表零临时分配测试、无效历史行语义测试和大列表回退测试；完整引擎测试、Clippy、Rustfmt、差异检查、笔记检查和 quick 门禁覆盖实现。

## Consequences

64 行以内的 `@` 列表不再创建临时哈希表；超过边界的列表继续按既有验证、首条去重和 1000 行上限运行。
