# Agent Note: 注音转换查询复用缓存描述缓冲

Status: implemented

## Problem

`cached_best` 每次查询前都分配描述键，即使命中已有词条或已有缺失结果。二十音节转换遍历的 210 个区间在热缓存上仍产生 210 次分配。

## Decision

词条映射与描述字符串放进同一个内部缓存对象。描述写入保留容量的字符串，命中时借用查找；未命中且词库查询成功后，只为映射复制独立键。回调在缓存借用期间消费词条，使命中只查找一次，不需要为返回借用与后续插入提前查询两次。

## Alternatives considered

`contains_key` 后返回 `get` 的借用能保持原来返回引用的接口，但会给每个命中增加一次哈希查找。共享所有权也能返回无需复制的词条，但会增加首次缓存的对象分配和热路径的引用计数。回调保持现有缓存所有权，并让调用方只在转换确实需要拥有词条时克隆。

把查询缓冲转移给映射能省去未命中时的键复制，但会丢掉查询缓冲容量，下一次命中需要重新分配；短键也可能长期占用从较长描述继承的大容量。仅在未命中时复制独立键，保留缓冲容量更适合冷热查询交错的转换过程。

## Consequences

热缓存与描述容量预热后，二十音节的 210 次查询不分配临时描述。首次查询、缓存缺失、查询错误和键格式保持原有语义；单读音词频捷径仍直接借用读音。描述缓冲首次建立或增长时仍可能分配，未命中时还需要为映射分配独立键并复制内容。缓存对象在组合清空时保留缓冲容量，直到方案销毁。

## Verification

旧实现的二十音节、210 次热查询在分配预算测试中实测 210 次分配并失败。测试覆盖单读音与多读音组合、词条内容与共享字符串身份、缓存缺失、重复查询错误及组合清空后失效；删除夹具的词条表后仍能读取缓存命中与缓存缺失。注音单测、引擎单测、golden、Clippy、格式、笔记与 quick 门禁用于覆盖本切片。
