# Agent Note: 长词续接首个满页复用结果存储

Status: implemented

## Problem

`query_longer_phrases` 为每个音节长度查询创建页面缓冲。首个页面填满请求上限时，旧实现仍另建聚合 `Vec`，把页面行搬过去后释放页面存储；一次长词续接查询因此多分配并复制一份相同的 `DictRow` 槽位。

## Decision

首个非空且已填满请求上限的页面直接接管聚合结果 `Vec`，后续页面继续使用现有的按页容量规划和追加路径。稀疏首页面仍按实际行数建立聚合容量，避免把查询上限的未使用槽位保留下来；排序、按值去重和最终截断保持不变。

## Alternatives considered

- 对所有首个非空页面直接接管：会让稀疏页面保留 `rows` 查询上限容量，退化现有的稀疏容量优化。
- 对页面调用 `shrink_to_fit` 后再接管：需要重新分配或复制，无法稳定节省首个页面的聚合分配。
- 先预扫描每个页面的行数：会重复查询或遍历数据库，增加空页和命中页的工作。

## Verification

新增满页长词续接分配预算测试；旧实现分配次数多一次，修复后首个满页直接复用且容量保持请求上限。长词聚合相关 9 项测试全部通过。

## Consequences

首个满页查询少一次结果缓冲分配和 `DictRow` 搬移；稀疏页面仍保持按实际行数增长的容量边界，后续页面的排序、去重和上限语义不变。
