# Agent Note: macOS 面板输入测试完整发送帧

Status: implemented

## Problem

`DesktopInputSessionTest.mm` 只调用一次 `send()` 发送帧头和正文，并忽略返回的字节数。流式套接字允许短写；测试如果提前关闭写端，服务端收到的是不完整帧，测试却会把无响应归咎于输入会话。一次 macOS arm64 CI 的大帧用例确实收到零字节响应，重跑通过；现有日志不足以证明那次失败由短写造成。

## Decision

测试发送端循环调用 `send()`，直到每段字节完整发送；被 `EINTR` 中断时重试。预期会调用处理器的有效请求必须确认帧头和正文均发送成功。无效或未授权请求允许服务端提前关闭连接，测试仍按原有拒绝行为判断响应。

## Alternatives considered

- 只断言单次 `send()` 的返回值等于请求长度：能更明确地暴露短写，但在合法短写时仍会让测试偶发失败，无法测试完整帧的产品行为。
- 增加等待或放宽响应超时：可能掩盖发送不完整的问题，不能保证服务端真正收到测试指定的字节。

## Consequences

有效请求的断言建立在完整帧已发送的前提上；连接提前关闭时会在发送步骤给出更准确的失败位置。测试保持原有帧内容和服务端预期，不改变产品协议。利用带发送超时的小缓冲 Unix 套接字，本机验证了 12000 字节的单次 `send()` 可以只返回 1024 字节；这证明原测试假设不成立，但不将上次 CI 失败归因于同一原因。
