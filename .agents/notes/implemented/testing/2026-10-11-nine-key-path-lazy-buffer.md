# Agent Note: 九键路径页缓冲延后预留

Status: implemented

## Problem

`SpellingTable::split_paths` 在每个数字偏移都按 `PATH_LIMIT` 创建路径页。完全不可读的输入不会写入任何路径，却仍会为每个偏移申请并释放一块固定容量的临时存储；输入越长，空查询产生的分配次数越多。

## Decision

每个偏移的路径页从空 `Vec` 开始。首条可行路径加入前，再按原来的 `PATH_LIMIT` 执行 `reserve_exact`；有路径时继续保留原容量提示、排序和截断行为，无路径时不申请路径页。

## Alternatives considered

- 查询每个偏移前继续预留整页：可少一次首行判断，但死路输入会为每个偏移承担固定分配。
- 按每条路径自然增长：空页成本最低，但密集页会重复扩容并失去原有路径上限提示。
- 只延后最终路径返回页：无法消除中间偏移页在死路输入上的逐项分配。

## Verification

新增 32 位完全不可读数字的分配回归；旧实现产生 34 次分配，修复后不超过 2 次。九键模块 108 项测试通过；提交前还会运行引擎库、golden、Clippy、格式、差异检查、笔记校验和 `bash scripts/verify-local.sh --quick`。

## Consequences

没有可行音节的九键路径偏移不再申请 `PATH_LIMIT` 条路径存储；有路径时首条路径仍按原上限准备容量，路径顺序、每偏移上限和最终结果保持不变。分配计数只覆盖 Rust 路径容器，不代表字典索引或系统内存占用。
