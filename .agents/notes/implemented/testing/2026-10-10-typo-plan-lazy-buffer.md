# Agent Note: 纠错键规划缓冲按需预留

Status: implemented

## Problem

`plan_keys` 每次先申请 `TYPO_KEY_BUDGET` 个 `PlannedKey` 槽，即使最终没有匹配变体，仍返回一块没有元素的预留存储。真实调用会跳过不足三个音节与关闭纠错的情况，但合法三音节输入只启用换位纠错时也可能没有任何规划键。短输入和关闭类型仍作为内部边界验证。纠错收集的两个缓冲已按需预留，这块独立的空规划存储仍重复申请。

## Decision

规划向量从 `Vec::new` 开始，在第一个去重后的键写入前沿用 `Vec::with_capacity(TYPO_KEY_BUDGET)`。空计划容量为零；非空计划保留原容量提示、弱位置优先顺序、稳定变体排序、个人折扣、首次去重和预算截断。只延后这一块存储，不提前跳过其他规划工作。

## Historical audit

[变体缓冲复用](2026-10-08-typo-plan-variant-buffer.md)、[已有键去重](2026-10-08-typo-key-planning-dedup.md) 同处 `plan_keys`，但分别处理临时变体和键检查，与本次输出向量预留无关。[收集缓冲按需预留](2026-10-10-typo-edge-lazy-buffers.md) 处理其调用方的未命中键与输出边，两侧冻结规划对照都不执行该收集步骤，避免重复归因。[beam 延迟分配](2026-10-09-autocorrect-lazy-beams.md) 是不同对象上的预留模式参考。历史检索没有本次输出缓冲已有的决策归属，无需修改这些旧笔记。

## Alternatives considered

- 保留立即预留：省去首次插入判断，非空路径直接使用缓冲；空计划仍申请 96 个无用槽。
- 让 `push` 自然增长：空计划不分配，但有计划时多次扩容并改变原容量策略。
- 为短输入和关闭类型增加提前返回：可以连同变体与弱位置工作一起跳过，但只覆盖可预测的空计划，且扩大本片行为路径；先延后输出预留，统一覆盖所有空计划。

## Consequences

空计划不再申请输出预算缓冲，非空保留原 96 槽容量提示；弱位置、变体稳定排序、键去重、个人折扣及预算截断不变。首次插入多一个空向量判断，没有真实按键耗时或宿主延迟证据。Rust 请求字节不代表 SQLite C 堆、分配器暂存和 RSS，原有弱位置、变体与查表开销保持原样。
