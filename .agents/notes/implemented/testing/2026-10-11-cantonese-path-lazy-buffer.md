# Agent Note: 粤拼分段路径工作缓冲延后预留

Status: implemented

## Problem

粤拼 `segment_with` 和 `first_segmentation` 在开始递归前按输入字节长度创建路径工作向量。不可读输入的递归从未压入路径，却仍为整段输入申请存储；候选刷新中的长前缀探测会遇到这类输入。

## Decision

两条分段入口的路径工作向量从空容器开始。统一的 `push_path` 在首次压入分段时才按输入长度执行 `reserve_exact`，后续回溯继续复用同一容量；递归顺序、死路缓存、结果上限和路径内容保持不变。

## Alternatives considered

- 继续在入口按输入长度预留：成功路径少一次条件判断，但不可读输入为不会使用的路径槽位付出成本。
- 每次压入自然增长：失败路径仍可零分配，但成功的深路径会多次扩容，失去原容量提示。
- 只在 `walk` 而不在 `walk_first` 延后：首选分段仍会为失败搜索申请工作缓冲，不能覆盖两个生产入口。

## Verification

新增 200 字节不可读输入的分配回归。旧实现分配 2 次（死路表和路径工作缓冲），测试先失败；新实现分配 1 次，仅保留死路表。粤拼分段测试 13 项通过；提交前还会运行引擎库、golden、Clippy、格式、差异和笔记校验。

## Consequences

无可行粤拼路径的查询不再分配路径工作存储；有路径时首次压入仍一次保留原输入长度，递归回溯不增加扩容。分配计数只覆盖 Rust 堆，不代表死路表、字典查询或端到端延迟。
