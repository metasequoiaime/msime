# Agent Note: 固定候选位置空结果延后容量预留

Status: implemented

## Problem

`fixed_rows` 每次读取固定候选位置时都按 `FIXED_SLOT_COUNT` 预留五个槽位。已存在日志但当前上下文没有固定候选时，查询返回空列表，却仍申请整页结果存储。

## Decision

结果从空 `Vec` 开始，首条成功读取的固定行出现时才按 `FIXED_SLOT_COUNT` 精确预留；空结果和首步读取失败保持零容量，有固定行时继续复用原来的五槽容量。

## Alternatives considered

- 继续固定预留五槽：命中路径简单，但空上下文每次候选刷新都会申请无用存储。
- 完全取消预留：空结果更省，但固定候选较多时会引入多次扩容。
- 按每条行逐步增长：容量更细，但失去固定位置最多五行这一已知上界。

## Verification

新增空固定位置容量回归；固定位置模块 8 项测试通过。提交前还会运行引擎全量测试、Clippy、Rustfmt、差异检查、笔记校验和 quick 门禁。

## Consequences

无固定行的上下文不再申请五槽结果缓冲；首个有效固定行仍一次预留完整固定槽位，固定行排序、缺失行补查和动态候选归位行为保持不变。
