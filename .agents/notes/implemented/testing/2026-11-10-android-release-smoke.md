# Agent Note: Android 发布冒烟与穷举回归分层

Status: implemented

## Problem

维护者要求缩短过重的 Android 冒烟。0.7.3 发布运行 `42760805312` 中，API 35 输入验收从 05:37 到 07:05，约 88 分钟；其中数字键盘遍历所有方案约 398 秒，随机数字键盘约 247 秒。此前只缩短 PR 和 develop 的矩阵，发布仍串行重复执行整套交互回归。

## Decision

新增 `smoke.sh --release`，Release Android 显式使用 API 28/35 的发布矩阵。共享 workflow 的四个 Rust crate 设备单测、崩溃专项、安装与首次资源准备不变，`publish` 仍依赖整个 `device` 成功。无参数完整套件与 API 28 `--core` 保持不变，nightly 继续执行穷举回归。

发布复用风险套件的真实主输入、辅助码与词库导入、词书、会话存储、剪贴板导出和保存生命周期，再覆盖候选绘制、批量组字、数字层重启、组字恢复、设备信息复制、候选皮肤包、设置搜索定位与禁止截图窗口。系统主题切换沿用原来的 API 35 覆盖边界。各输入方案的数字键盘穷举、完整设置和手势组合留给 nightly；改动触及这些行为时仍需在对应 PR 做定向设备验收。

本次发布已经失败的设备信息复制与主题恢复仍在发布门禁里，不能靠套件收窄消除失败。设备信息更新白名单以匹配 #11109 已批准的构建时间，继续严格检查未知字段；主题测试保持原有颜色断言和默认设置，修正按键选择器的候选排除规则：同文字的原始拼写候选也会暴露为按钮，不能只按文字与控件类型找字母键。

共享设备 workflow 提供手动入口，可以指定矩阵直接复验设备链路，不必重新构建六个发行 APK。矩阵仍通过相同设备 job 和失败汇总执行。主题故障提供 `--theme` 定向入口，仍先验证主输入，不改变正式发布的主题门禁。主题断言失败时在恢复偏好、离开合成编辑器之前保存现场截图，并记录按键位置与表情面板是否可见，用设备证据区分遮挡和产品配色错误；诊断不改变原断言或默认设置。运行 `42780626008` 的失败位置为 `Rect(0, 1564 - 105, 1633)`，`emojiVisible=false`，实际取到候选栏按钮区域的背景色，排除了此前的表情遮挡推测。设备回归构造同文字的候选和键帽节点，要求候选不匹配，并保留大小写键面与数字层字母按钮的匹配。截图采集成功后还必须列入日志产物白名单，否则 runner 退出时会丢失现场。

本决定只改变发布选用的套件，与[推送按风险分层](2026-11-07-android-device-matrix-by-risk.md)部分重叠；保留原笔记负责 PR/develop 的选择规则。

## Alternatives considered

- 保留全部套件，仅并行分片：能缩短墙钟时间，但会增加模拟器启动与重复构建的总消耗，没有满足减负要求。
- 让发布直接使用 `--pr`：只验证短的界面入口，缺少最低 API 的资源和存储验证，也会漏掉本次已知失败，因此不用。
- 缩短每次点击的固定等待：可能减少遍历耗时，但会改变所有测试的同步时序；当前没有设备证据支持统一降低，暂不采用。

## Consequences

发布不再等完整的交互组合回归，资源权限、存储、输入、隐私以及已知失败仍阻止发布。代价是未被选入的组合缺陷最迟由 nightly 发现，涉及对应行为的 PR 必须定向验收。实测运行 `42774771490`：API 28 输入步骤 9 分 59 秒并通过；API 35 输入步骤 11 分 18 秒，在主题恢复断言失败。这是输入步骤耗时，不含构建和独立设备单测，不代表发布已通过。

假 adb 的脚本行为测试记录到顶层 instrumentation 数量从 API 28 的 47 降为 13、API 35 的 105 降为 14（不包括辅助脚本内部调用，不能换算成耗时比例）。该测试在 API 28/35 验证选中的套件和存储脚本确实执行，注入设备信息与主题双失败时要求非零退出并汇总两项；原完整回归的测试继续运行。


### 2026-11-10 主题复验的新证据

`42787579493` 的 API 28 发布冒烟成功，API 35 仍在缺槽回退的候选颜色断言失败。新增描述显示失败对象实际是「候选 1：你」，不是 N 键。失败截图确认拼写编辑面板覆盖在候选栏上，`fff1e6cc` 来自覆盖层；此前将这一颜色失败归因为同名 N 候选并不充分，字母选择器的排除规则本身仍由独立节点回归验证。

继续保留全部颜色断言及原点击顺序，在合成编辑器里记录拼写编辑面板首次出现的阶段、选区位置和截图。不记录文字；不自动关闭覆盖层，也不把意外覆盖当作通过。还需确定它由测试重新点击已有编辑器触发，还是输入/配置变化的异步选区回声触发，确认前不合并、不发布。

手动 `--theme` 专项与键面专项一样，只重复安装、资源准备、真实主输入及目标场景，跳过已通过且未涉及改动的 Rust 设备单测和崩溃专项。这个例外只匹配精确的专项参数，发布 `--release`、nightly 与普通风险路径仍执行这些门禁；专项通过也不能代替发布双 API 验收。


`42798262906` 的事件序列排除了误点：缺槽回退阶段点击目标与点击事件均为「字母 N」，随后合成编辑器选区从 7:7 到 8:8，首次出现拼写编辑面板；此前重聚焦时没有覆盖层。宿主仅在显式编辑入口或未识别的选区回报中打开该面板，而该序列没有编辑入口点击，因此本次属于普通输入回报被当作组字光标编辑。

修正选择接管的边界：校验完整组字和实际文字之后，若换算目标等于引擎当前 `caret_position`，把它当作已同步的组字位置，不移动也不打开编辑面板。实际移到组字中间或从中间回到末尾仍走原编辑路径，显式铅笔入口也保持；没有关功能或改默认值。主题设备用例额外断言字母键不能打开拼写编辑面板，原设置、点击顺序与颜色断言保留。AOSP Android 15 的 `resetStateForNewConfiguration` 会用当前 `EditorInfo` 重启输入，这为旧基准失配提供了可能来源；尚未记录到宿主待确认队列，不能把该来源写成已证实的根因。修正是否完整仍由相同主题用例和组字编辑回归决定，未通过前保持草稿。

### #11313 的完整 nightly 设备回归

API 35 专用 AVD 复现了三项失败：组字提交后的高度增加、热更新测试等不到页码、14 键关闭符号滑动后等不到首个汉字候选。它们分别处理，不归为统一的候选等待波动。

- 高度用例保留原输入、默认编辑能力和窗口高度阈值，修复隐藏状态仍参与测高的产品问题，见[移除拼写铅笔](../bug-fix/2026-11-10-mobile-remove-spelling-pens.md)。
- `PreferencesDeviceSmoke` 保留原默认拼写位置的完整热更新、组字保留、标点、坏文件保护和恢复路径，再用 `touch_spelling_position=candidate_bar` 跑同一套行为，在可见读音行上验证 5→2 的页数关系。旧页码前置条件随[移除空入口行](../feature/2026-11-10-android-spelling-editor-switch.md)失效：该决定明确让页码随空读音行隐藏，连续候选条又不按引擎页大小裁剪。不能为了测试恢复空行，也不能删掉页大小验证。
- `GridLetterSymbolDeviceChecks` 继续使用同一个 C/V 键和同一方向，不换成能出候选的输入。关闭滑动时先记录普通点按的组字读音，再清空并真实纵滑，要求读音一致、拼音选择可达、无字母弹窗且没有上屏文字；退格必须确实撤销组字。单组 C/V 在当前引擎可以只有拼音选择而没有汉字候选，「必须有候选 1」不再作为是否输入成功的判断。

这次不修改发布与 nightly 的套件选择、等待超时、产品默认值或候选排序。放宽候选等待和更换输入虽然能更快消除红灯，却无法分辨手势被吞掉和有效组字无候选，因此不采用。

验证：API 35 的三项失败均在修改前复现，修复后拼写编辑、两种拼写位置的完整热更新、14/18 键角标符号专项全部通过。API 28 的主输入和拼写编辑专项也通过。这里的定向通过不代表整条 nightly 已恢复：iOS 上传依赖与 macOS 产物服务故障仍由 #11313 跟踪，完整 nightly 必须按正常调度得到成功结果。
