# Agent Note: 拼音大小写还原直接比较编码字节并复用输出

Status: implemented

## Problem

全拼、双拼和会话共用 `apply_segmentation_cases`。为判断切分编码能否沿用原始输入的大小写，它先建立两份去分隔符字符串，再为原始输入创建 ASCII 小写副本。比较后这些字符串全部丢弃，返回文本却还要独立分配；匹配与不匹配的常见 ASCII 输入均承担三份临时字符串。即使去掉这些比较副本，调用方仍先获取拥有型结果，再复制到已经有容量的请求字段；全拼追加辅助码时还会为临时结果扩容。

## Decision

用两条字节迭代器跳过 ASCII 撇号，仅对原始输入流做 ASCII 小写折叠，再逐字节比较。保留空输入、比较失败时的原切分返回，以及成功后原有大小写回填循环。原拥有型入口没有对外导出，三个生产调用统一迁移到内部写入接口；拥有型包装仅放在测试模块用于检查空缓冲路径。内部写入接口 `apply_segmentation_cases_into` 清空并复用调用方字符串，全拼请求、双拼请求和双拼辅助码重切分直接写入 `raw_segmentation`，后缀也追加到同一存储。切分编码本身不额外转小写，维持原先单侧折叠的准入条件。

## 历史决策审计

- [辅助码检测借用输入](2026-10-09-shuangpin-helpcode-detection-cow.md) 无直接重叠：管理模式检测中的输入存储，本篇管理大小写回填的编码比较和输出存储。
- [双拼模糊候选重标](2026-10-15-shuangpin-fuzzy-relabel-borrow.md) 无直接重叠：管理候选编码的写回容量，不涉及大小写回填。
- [光标前缀查询复用请求存储](2026-10-09-caret-prefix-request-reuse.md) 部分重叠：管理请求的生命周期，本篇消除写入该请求字段前的大小写还原副本；继续复用其已有字段，不引入新的请求缓存。
- 其余检索命中的日文/越南语大小写转换、日文查询流式输出及辅助码模式/缓冲笔记均与本函数契约无关。

## Alternatives considered

- 保留拥有型结果再 `clone_from` 到请求字段，改动范围最小且已有容量能在最终字段复用；临时结果仍每次分配，全拼还会为追加辅助码后缀扩容，不能消除这部分成本。
- 借用无分隔符原文，仅在有分隔符或大写时建立副本，便于复用既有字符串 API；切分编码通常含分隔符，有效原文也常含大写，仍保留中间存储。
- 对两边做不区分 ASCII 大小写比较，表达简洁；原逻辑只折叠原始输入一侧，切分编码自身含大写时可能改变是否进入回填，不能放宽这一条件。

## Verification

旧实现的常见 ASCII 输入回归以 4 次分配失败，优化后匹配、不匹配和微软分号输入均只分配拥有型结果的 1 次，纯分隔符仍为 1 次，任一输入为空时均为 0 次。用 7 种字符组成长度 0 到 3 的 400 个输入，加 8 个多音节边界和 2 个长输入，共 410×410＝168100 组，与冻结的旧实现逐结果对照；覆盖单侧大小写折叠、前导/连续/末尾分隔符、不匹配、Unicode 字节和 128 音节长输入。相同输入对也逐一验证内部写入接口的结果，预热足够容量后 168100 组均零分配、指针不变，并在每次调用前加入旧内容，覆盖清空和覆盖语义。

3 项调用方回归先在旧实现上因预算超额失败，优化后复用原字段指针、整个请求与预热结果相等：双拼请求 12→11、全拼辅助码请求 18→16、双拼辅助码重切分 11→10。

## Consequences

比较阶段不创建规范化存储，遇到不匹配可提前结束；生产调用直接写入已有缓冲，拥有型包装仅用于空缓冲测试。只折叠原始输入一侧的 ASCII 大小写，只跳过 ASCII 撇号，保留回填循环的已有字节语义；全拼与双拼使用同一实现。复用的是请求原本持有的字段容量，不增加缓存失效状态；内部写入接口对空输入和比较失败必须覆盖旧内容。缓冲不足时仍会扩容，不承诺整个请求或快照零分配，也不推断端到端延迟收益。
