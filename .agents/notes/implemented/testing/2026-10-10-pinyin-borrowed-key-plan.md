# Agent Note: 拼音完整键规划借用音节切片

Status: implemented

## Problem

`query_exact_keys_per_key` 对每个去重后完整键调用 `split_segments`，创建音节向量并复制每段文本，实际只需校验完整音节、取得段数和首字母。纠错与滑行调用方已有去重，但唯一键仍承担这些临时分配。

## Decision

私有规划函数以撇号分隔的借用切片校验 `intact_pinyin_set`，统计完整音节数，调用现有 `quanpin_table` 生成表名并返回段数。保留空键/空段/非法音节过滤、七音节与溢出表规则、去重边界、SQL、每键限额、结果字段/顺序/容量。公开分段与表名构建接口保持。

## 既有笔记审计

活跃笔记检索按键查询、表名与借用分段，无同一规划实现。[精确键去重](../../implemented/testing/2026-10-08-pinyin-exact-key-dedup.md)部分重叠于跳过重复拆分，但仍保留唯一键拆分，本片保留并互链；[空结果表预留](../../implemented/testing/2026-10-10-pinyin-empty-key-map-storage.md)约束结果表存储，与本片临时音节无关，旧冻结对照单独计入新增收益；[拼音最少切分缓冲](../../implemented/testing/2026-10-09-pinyin-min-cut-buffer.md)处理不带显式音节界的切分规划，不替代数据库完整键校验。

## Alternatives considered

继续复用拥有型拆分可避免新增私有辅助函数，但保留无用复制。把通用分段函数改为借用返回可以复用到更多调用方，但改变共享接口和真正需要拥有音节的调用方。此入口直接读取原键切片，表名继续调用既有格式规则，不另写命名契约。

## Verification

真实红测试在旧生产上失败：三个不同双音节键两侧各分配 25 次，少 9 次的预算失败。新增 `dictionary/pinyin/borrowed_key_plan_tests.rs` 的 8 项测试通过，冻结远端基线 `a6bbd05e10d4a9841e60cd8476ebc10e7d5c711f` 的完整旧查询正文，仅接收者转接、中文注释及格式变化，机械核对一致。覆盖全部完整音节、空段/非法键、1/64/65/96/129 键、七/八音节与 1025 音节长键、跨表/等权/负权/大权重、1026 行单键密集页、保护检查、单音节无界限额及真实 SQLite 首步溢出。逐键比较完整字段、行顺序、结果表及每键行向量容量。借用规划只有合法表名自身的一次分配，非法键不分配；重复输入只计首次键的拆分。

冷计量在区间外初始化不可变音节表与线程级随机状态；数据库打开、PRAGMA 与 SQL 缓存、规划、查询及显式析构均在区间内，仅返回结果并借用外部路径/键。arm64 debug：96 唯一单音节键分配 503→311 次，逻辑请求峰值 2636→2606 字节；96 唯一双音节键 519→231 次，峰值两侧均 13779 字节；单音节命中 33→31 次、峰值 862→836 字节，双音节命中 38→35 次、峰值两侧均 1730 字节。四个非法唯一键 31→22 次、峰值两侧均 712 字节。返回存储分别为 0、6413、329、337、0 字节，两侧相同，最低差值均为零。两侧已经先去重和延后结果表预留，不重复计入前两片收益。

两份既有空结果表/去重的冻结查询正文逐字保留，次数断言在区间外独立计量本次新增拆分节省：空表旧基线按全部原输入键计，去重旧基线另按首次键计；关闭连接与零限额不额外补偿。独立新进程冷测试通过，完整引擎 1552 项单测通过（13 项忽略）、golden 31 项通过，Clippy `--all-targets -- -D warnings`、格式、差异与笔记校验通过；独立审查核对同一完整音节集合、空段/Unicode 与别名过滤、七/八/长键规则、冻结正文、旧次数补偿及冷边界，无阻断。完整 quick 通过共享 Rust、Android target/Java 宿主、Linux 外壳和原生宿主（73 项测试）、macOS 原生宿主与 Apple bridge；Windows 本机 102 项通过。完整 Windows 交叉构建、wasm 与 HarmonyOS 真打包因工具链/资源缺失跳过。

## Consequences

唯一键不再拥有临时音节向量或字符串，非法键可在首个非法音节返回；有效段数及首字母仍通过 `quanpin_table` 使用共享表名规则，空键和前后/连续撇号不变成合法键。表名、分表键列表、结果表和命中行仍按原策略拥有存储；多音节批次峰值由其它存储决定，不保证峰值或延迟改善。借用拆分使用 [Rust `str::split` 的切片迭代](https://doc.rust-lang.org/std/primitive.str.html#method.split)，不新增共享接口、依赖或不安全代码。冷边界只计 Rust 逻辑请求，未测 SQLite C 堆、RSS、发布构建计时或真实宿主延迟。

同步到包含长词续接按页预留的 `3023448f46340b1178a525619bf51882b6f27d3e` 后，按键查询正文与 Cargo 配置不变；组合状态完整引擎 1553 项通过（13 项忽略）、golden 31 项通过，Clippy 再次通过。
