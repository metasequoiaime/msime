# Agent Note: 候选排列只遍历每条循环一次

Status: implemented

## Problem

`ordering::apply_order` 为每个起点重新遍历整条循环寻找最小下标。将第二条整句读法移动到候选末尾的合法排列 `[0, 2, …, n-1, 1]` 有一条长循环，检查成本为 `(n-1)^2 + 1`，同一排列还应用到 runtime 多个平行数组、网页候选和神经路径。固定基线 `9d12d8b7b7a16ff5711f595e459e82bae107beea` 的独立优化构建复现 8,192 行排列一次约 88 ms；该时间仅描述本机微基准。

## Decision

记录已访问座位，每条循环只交换一次，维持新座位到旧座位映射、原地移动和泛型 API。128 行以内用栈上布尔数组，大列表用一次布尔缓冲分配；恒等排列先返回，不增加分配。排列仍由内部调用方保证合法，不改无效排列的契约。

检索活跃笔记中 `apply_order`、原地排列、置换、visited 与候选排列：[神经路径原地重排](../../implemented/testing/2026-10-08-neural-paths-inplace.md)决定部分重叠，保留路径不复制的理由并互链；整句改字与 Windows 设置页笔记仅涉及排列呈现，无关。没有同类过时提案。

## Alternatives considered

- 保持原实现：无辅助存储、所有长度零分配，但长循环重复扫描产生平方成本。
- 只在扫描遇到更小下标时提前停止：无需分配，但按升序组成的长循环仍为平方成本。
- 复制整张结果列表：线性但要求元素可复制并复制候选文本；访问标记保留原地所有权移动。

## Verification

长循环计时用例与生产函数从源文件机械提取，单独以 `rustc -O --test` 构建，避免红灯依赖全仓编译。固定基线处理相同 32,768 总行数时，128 行列表中位数 5,642,750 ns，8,192 行列表 353,036,666 ns，超出 16 倍预算而真实失败；修复后分别为 175,625 和 172,208 ns，通过。用例默认忽略，避免计时噪声进入 CI。默认用例枚举长度 0 至 7 的全部排列，另覆盖 0、1、127、128、129、256、8,192 行的长循环、不可克隆元素、输入缓冲指针与分配预算，以及大恒等排列零分配。引擎全量 1,832 项与 golden 31 项通过，14 项计时默认忽略。runtime 228 项、网页引擎与其集成测试通过，三个相关 crate 的全目标 Clippy、Rustfmt、笔记和差异检查通过；仓库内的 ignored 长循环用例显式运行通过。完整 quick 连续三次因系统盘耗尽失败，尽管逐阶段清理本片产物，Linux 原生与 macOS 最终门禁仍未完整通过；合并前必须在空间持续足够的环境补跑，macOS 保留 Release 全目标配置和 149 项 CTest 注册，不把交叉编译记作设备验收。

## Consequences

每条循环只遍历一次，时间为线性，保持原地移动和所有权，不克隆候选字符串。增加 128 字节栈访问标记缓冲；超过 128 行的非恒等排列新增一次长度为候选数的布尔缓冲分配，平行数组各调用会各分配一次。恒等排列和短列表仍零分配，神经路径现有零分配回归保持。

另以机械提取的固定基线和新函数做七轮交替配对微基准，每轮处理相同总行数并取单次操作中位数。整句次选降位形状 128 行为 24,063→434 ns，1,024 行为 2,452,557→3,437 ns，8,192 行为 101,401,302→28,135 ns；同轮还测 8、20、129 行，以及恒等和逆序排列，未观察到这些用例回退。主机有其它任务，小数值易受噪声影响；本地微基准只测整数切片排列，不能推断完整按键路径或真实设备输入延迟。以后若调用方复用访问缓冲，可继续减少大列表多次辅助分配。
