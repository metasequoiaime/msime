# Agent Note: 双拼直接辅助码路径复用编码值

Status: implemented

## Problem

直接辅助码路径搜索在每个递归节点把两个 ASCII 编码字节转换成新的 `String`，再把它复制到当前路径的每个分支。路径只需保存固定长度编码，字符串副本在路径生成和分支选择后没有独立的生命周期需求。

## Decision

`DirectSpelling` 将编码从拥有型 `String` 改为两个字节的 `[u8; 2]`。递归校验仍使用小写 ASCII 编码的临时 `str` 视图；路径分支复制固定大小数组，不再复制编码字符串。查询阶段按路径长度一次预留并将字节写入纯双拼键。路径数量上限、分支顺序、大小写归一化、读法校验和辅助码候选结果保持不变。

## Historical audit

已检索 `direct_helpcode_paths`、`DirectSpelling`、直接辅助码会话测试及双拼路径和帮助码缓冲笔记。相邻的[直接辅助码字符借用](2026-10-17-shuangpin-direct-helpcode-character-borrow.md)只处理候选词字符匹配，不持有路径编码；单辅助码分类缓冲只覆盖重排状态。没有发现重复实现或需要吸收的决定。

## Alternatives considered

- **继续保存每个编码的 `String`**：实现简单，但每个递归节点都要申请并在分支复制时再次申请。
- **保存输入切片范围**：可避免编码副本，但大小写归一化后的查询键仍需逐段转换，且路径跨越输入边界时要额外维护切片生命周期；两个字节值更直接。
- **让路径借用一个共享编码表**：会增加路径状态和索引查找，固定两字节值已经能表达完整编码，不需要共享存储。

## Consequences

直接辅助码路径生成保留路径本身和结果向量的必要申请，去掉每个编码单元的短字符串申请。输出纯双拼键仍按原顺序、大小写和容量规则构造；`DirectSpelling` 是内部类型，没有公开接口或持久化格式变化。
