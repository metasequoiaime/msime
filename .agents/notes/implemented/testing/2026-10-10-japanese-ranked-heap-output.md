# Agent Note: 日文排名堆直接消费已保存的排序键

Status: implemented

## Problem

普通排名与 continuing 堆项为 `((cost, id), id)`，重复保存 ID。排名完成后只保留 ID，再对每次排序比较读取词库成本，放弃了堆中已有的不可变成本。所有生产成本来自模型的固定字节，没有排序期间的更新。

## Decision

两处堆只保存 `(cost, id)`，仍按同一总序筛选，保持首次实际命中才分配、限额、重复 ID 和扫描次序。最终使用 `into_vec`、对保存键 `sort_unstable`、映射 ID；continuing 直接构造结果，不另收 ID 向量。成本来自模型不可变字节，排序不再重新解码。`into_sorted_vec` 留在仅测试的完整备选核心中，两轮初选在 30 个非控制情况中各有 28 个支持缓存键不稳定排序，生产选择后者。完整空与零限额分支、短前缀缓存、查询键、词条视图生命周期及文件操作保持。

## Alternatives considered

- 保留重复 ID 并重新解码成本：原实现已经验证，排序对象小；有可明确计量的重复存储和读取，成本在堆中已经可用。
- `into_sorted_vec`：标准库原地堆排序直接利用当前堆，无新排序键和依赖；比较次数和分支可能不如小数组的不稳定排序，需计时。
- `into_vec` 后排序保存键：维持原 `sort_unstable` 算法家族且避免重新解码；未利用已有堆序，仍需比较两种完整查询。
- 常驻排名缓存或自定义 unsafe 迭代器：可进一步省临时堆；引入跨查询状态或生命周期风险，本次只使用标准拥有容器。

## Verification

固定 `29c26963f397ac39a701352ec8ebfdcd20f3678b` 的普通排名、continuing、exact 和 prefix 四份完整正文，只改测试名称、可见性和格式，逐正文核对。真实红测试三项失败：两条输入 limit2 的成本调用为 4 而要求 2，limit1 峰值 12 未下降，continuing 流式峰值也未下降。修复后要求成本每条扫描输入只读取一次、非空排名峰值严格下降；空与零限额不读取输入或成本。完整字段、重复项与借用生命周期对照冻结查询、独立全量排序 oracle 和堆排序备选，覆盖负成本、平局、i32/u32 极值、倒序和 16 种打乱、限额超过输入、64 缓存边界、Unicode 与未命中。

## Alternatives considered

- 保留重复 ID 并重新解码成本：原实现已经验证，排序对象小；有可明确计量的重复存储和读取，成本在堆中已经可用。

## Consequences

缓存成本键减少排名存储和重复成本读取，大部分已测常用限额支持采用；同时接受已测 limit1 和宽前缀约 1%～2% 中位回退，完整结果、次数与字节门禁不放松。若后续隔离环境或原生宿主完整查询确认小限额、宽前缀显著回退，重访按限额优化；不能以本片内存收益推断全面加速。

一次正式轮前后系统负载均值为 97.29/65.76/59.51，外部任务未隔离；计数器即使关闭也访问 TLS。测试覆盖完整词库查询，但没有原生设备按键或完整 provider 延迟证据。时间不设 CI 阈值，也不归因控制路径的噪声。保持 continuing 历史重叠 suffix 的重复项，例如 `[1, 2, 2, 3]`，不顺带 dedup。集合转换的容量复用依赖实测工具链，不承诺所有标准库版本同一分配实现。没有新增状态、依赖、unsafe、公开接口或模型格式。
