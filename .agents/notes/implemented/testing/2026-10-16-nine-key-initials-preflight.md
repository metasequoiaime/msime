# Agent Note: 简拼完整预算在分配前检查

Status: implemented

## Problem

`initials_codes` 逐层分配前缀后才发现完整展开超过原限额。例如固定 `4007628d74` 的 `999999` 在返回 `None` 前申请1391次。非法尾部也会丢弃已完成的全部前缀。

## Decision

将原有合法首字母计数、饱和乘积和限额检查移动到完整展开前，确认通过后执行原来的 `flat_map` 正文。拒绝路径零分配；成功路径保持原字符串、顺序、字符串容量、页容量和申请次数。空输入不进入预检循环，仍在零限额时返回单空串。不增加长度限制，不改搜索预算或候选质量。

## Existing decisions

检索 `initials_codes`、简拼编码和预检相关活跃笔记：[原简拼能力](../../implemented/feature/2026-10-08-nine-key-initials.md)及[十四键](../../implemented/feature/2026-10-10-fourteen-key.md)部分相关，保留其输入语义；[直接最终页实验](../../rejected/testing/2026-10-16-nine-key-initials-final-codes.md)失败，保留实验理由和数据。[组码前缀](../../implemented/testing/2026-10-16-nine-key-code-prefix.md)及[缓存排名](../../implemented/testing/2026-10-16-nine-key-cached-rank.md)是不同调用层的优化，无替代关系。没有完全吸收或过时提案。

参考同仓库展开正文和 [Rust saturating_mul](https://doc.rust-lang.org/std/primitive.usize.html#method.saturating_mul) 契约，不引入依赖。

## Alternatives considered

- 只生成最终页：可显著减少成功路径申请，原型还保持了全部有序文本；但正常分配器局部墙钟计时显示部分有效双拼输入回退，两版均放弃，见互链实验记录。
- 保留逐层检查：控制流最少且已验证，但超预算及非法尾仍需创建上千个无用前缀。将同样检查前置能独立解决该浪费。

## Verification

冻结旧正文对照五种键盘全部一至三键组合及限额边界，拒绝零分配，成功页和字符串容量、申请数完全不变。额外覆盖非ASCII尾和4096位单选择串。正常分配器线程CPU的37形状局部配对矩阵中位比均低于1.05；原墙钟矩阵仍未通过，结果及限制见下文。完整测试2192项引擎单测、31项golden、294项runtime通过，34项忽略（33项原有及新增手动计时）；两crate全targets Clippy `-D warnings`、fmt通过。使用固定真实模型 `MSIME_NEURAL_MODEL_DIR`，不将评测专用目录当作完整 `MSIME_EVAL_RESOURCES`。

## Consequences

成功路径将检查集中到分配前，线程CPU中位比低于1.05，原墙钟矩阵未通过；拒绝收益不能证明端到端16ms达标。

## Measurement environment

预检版第一轮墙钟完整37形状没有通过1.05门槛：九键 `99999` 为1.199744、米旮旯2 `2` 为1.201134及 `29` 为1.239488、米旮旯3 `2` 为1.156147、辜氏2空输入为1.420762。该轮170次环境采样中168次有并行编译，最多29个；例如辜氏2 `2222` 的p10/p90为0.641688/6.815668，空输入也出现明显噪声，不能将该轮作为稳定 CPU 或延迟成绩。

保持全部形状、31对和1.05门槛，补测线程 CPU 时间以排除线程未获调度的时段；macOS SDK `_time.h` 定义 `CLOCK_THREAD_CPUTIME_ID=16`，独立临时程序通过 `clock_gettime_nsec_np` 读线程 CPU 时间。生产和仓库测试不引入 FFI 或 unsafe。墙钟失败保留，线程 CPU 结果仅说明局部执行成本，真实 runtime 延迟另外按墙钟报告。
