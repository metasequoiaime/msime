# Agent Note: 注音转换路径表使用栈缓冲

Status: implemented

## Problem

注音每次重新转换组合都会通过 `vec![None; count + 1]` 分配临时路径表，即使组合为空也会分配。生产组合的音节数量已由 `MAX_SYLLABLES` 限制为二十个。

## Decision

使用可容纳组合上限加一个起点的栈数组，转换过程只借用实际长度的切片。直接调用转换器且音节数超过组合上限时仍使用原有动态表。排序、词频比较、钉住词条和返回向量的容量保持不变。

## Alternatives considered

把路径表长期存到编辑器中可以复用堆容量，但会把转换器的临时状态带进编辑器，并扩大函数接口。固定上限下的栈缓冲即可消除常规转换的路径表分配，且不用增加依赖或改变回调契约。

## Consequences

正常长度的转换少一次临时堆分配，空组合转换不再分配。栈上保留二十一个路径槽；超长直接调用仍分配动态表并保持原有输出。

## Verification

旧实现在完整钉住的二十音节组合上分配四次，收紧为三次的回归预算失败。优化后的预算只允许返回向量和钉住词条的两个字符串，并验证空组合零分配。额外测试覆盖超过二十音节的转换，注音单测、引擎全量单测、golden、Clippy、Rustfmt、笔记校验、差异检查和 quick 门禁覆盖本切片。
