# Agent Note: 全拼系列前缀键借用规范切分

Status: implemented

## Problem

`query_series` 每次都把完整音节重新拼成拥有型字符串，再逐次截断为前缀。完整查询的主读法、纠错读法和高成本读法通常已经把同样的规范切分作为参数传入，这个中间字符串只用于本次只读查询。

## Decision

用即时借用的 `Cow<str>` 核对参数是否恰好等于音节按撇号拼接的结果。逐段消费字符串前缀及分隔符，不创建临时列表或键；完全相同时借用参数，不同时仍按原规则拼接拥有值。核对不依赖音节内没有撇号、ASCII 或非空的假设。

前缀循环只缩短字符串视图，仍按原最后一个撇号截断，保留空段、Unicode 和嵌入分隔符的旧行为。拥有型回退存储留在本次调用，借用不跨可变词典状态或缓存；冷缓存键和最终候选继续分别拥有。整句合并继续读取原参数作为 typed 值，稀疏回退的单独拼接保持原样。

## Existing decisions

按 `query_series`、`partial_segmentation`、`truncate_last_segment` 和前缀键检索活跃树，没有同一系列前缀借用决定。[解析缓存投影](2026-10-14-quanpin-resolution-cache-projection.md)部分重叠，继续持有外层主切分拥有值和失效边界，本篇只处理内层再次拼接。其余光标前缀、混输前缀、模糊行缓存键属于不同入口，无关并保留；[精确读法首位](../bug-fix/2026-10-12-exact-reading-keeps-first-seat-over-longer-phrase.md)独立持有排序规则，本篇保持相同前缀字节，不改该决定。

## Alternatives considered

- 无条件借用切分参数：代码更短，常规规范主读法已经满足；不选，因为空参数、别名、重复分隔符或调用方提供的其它切分仍须按音节构造旧键。
- 保留一次拼接后原地截断：所有输入自然等价，已有实现也只拼一次；不选，因为参数完全相同时仍有无人消费的字符串申请与复制。
- 按音节长度累计计算前缀边界：可以不逐次找最后一个撇号；不选，因为原截断规则对含嵌入撇号的内部音节与逐个剥离完整音节并不相同，不能借性能改动改变旧规则。

## Verification

- 固定 `0ded5ef2d213ea733a6f96885d21210424c71050` 的完整 `query_exact` / `query_series`，只改名、转接冻结系列方法与去注释。生产修复前三个测试均因目标少一次申请而失败，候选对照相同；修复后三个专项测试通过。规范非空输入每次恰好少一次中间键申请；不匹配参数和空键保留原成本。
- 16 组直接系列输入 × 冷/热路径 × 词网格开/关，共 64 组；15 组完整查询 × 冷查询/解析热且系列清空/系列热 × 词网格开/关，共 90 组。涵盖普通、自动切分、手动切分、首字母、别名、真正纠错与高成本读法、空段、嵌入撇号、Unicode、空键和非法键；断言确实出现同次多个系列调用与高成本读法。外部词典写入后对照重建，并保护精确读法首位及首页溢出的更长候选顺序。候选内容、顺序、容量、缓存中的拥有结果和修改/reset/drop 后的独立性均逐项对照。
- 精确申请计数关闭词网格，避免进程共享 n 元表并发淘汰造成额外 `PathBuf` 申请；开启词网格时仍对照完整行为与容量。静态切分/纠错表在测量外初始化；结果容量比较用相同冷热状态，不把冷结果与热缓存克隆作比较。
- 首次全量仅两个会话的绝对预算因收益而失败：末尾输入 `131→130`，光标处输入 `204→202`。临时恢复本次 `query_series` 的旧拼接/截断，两个原预算均通过；恢复修复后按实际收益收紧，不改忽略按键、移动光标等热控制预算。

## Consequences

[活动词典保留已预热 n 元表](2026-10-14-active-dictionary-ngram-tables.md)消除词典查询对共享表缓存驻留的依赖；本篇关闭词网格隔离前缀预算的覆盖边界仍保留。

借用前增加一遍按音节的完整内容核对，不承诺 CPU 或真实宿主延迟收益。不得把用于整句显示的原参数换成规范键，不能把本次借用写入长期缓存；字符边界必须来自合法字符串分隔符。

[热前缀直接追加](2026-10-16-quanpin-prefix-row-stream.md)后来消除另一层临时候选页。为继续单独验证本篇键拼接预算，旧键对照只同步较短前缀追加；旧拼接与截断保持，本篇历史测量不反写。新追加方案由它自己的完整旧系列冻结对照独立验证。
