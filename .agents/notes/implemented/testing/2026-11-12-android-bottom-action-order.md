# Agent Note: Android 左下底栏语义顺序回归

Status: implemented

## Problem

#11001 报告全拼 26 键从字母层切到数字层后，左下角的数字入口、符号入口和语言入口会改变语义位置。现有键位策略已经让数字层的返回键沿用字母层 `123` 的位置，但设备冒烟只检查数字键与语言键的左右关系，没有直接钉住 `123/返回` 与 `符` 的相邻顺序。

## Decision

Android 继续沿用现有默认布局：全拼 26 键字母层按 `123 | 符` 排列，数字层按 `返回 | 符` 排列；开启本机「交换语言键与数字键」后，两个层分别按 `中/英 | 符` 与 `中/英 | 符` 排列，交换只改变数字入口和语言入口的语义位置，不移动符号入口。设备冒烟在默认、交换、英文切换和数字层往返中读取真实无障碍节点边界，验证第一键始终位于符号入口左侧。

## Alternatives considered

直接调整 Android 底栏构建逻辑可以改变顺序，但会重复已经落地的 `KeyboardActionRow` 语义映射，并可能影响其它键面；本 issue 的实现已存在，因此只补缺失的设备行为断言。

## Verification

`LanguageNumberKeySwapDeviceSmoke` 覆盖全拼 26 键默认与交换状态，包含切换英文、进入数字九宫格、返回字母层以及恢复设置。设备 job 在 API 35 上运行；本机设备受磁盘空间限制时，PR 保留设备 job 结果，不伪造本地真机验收。

## Consequences

回归测试明确记录了 #11001 的用户可见语义顺序，后续重排底栏时会在真实无障碍树上失败；没有改变已有默认值、设置字段或其它键面的布局。
