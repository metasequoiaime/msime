# Agent Note: 插件回包缓冲按容量申请边界验证

Status: implemented

## Problem

`repeated_command_queries_reuse_the_output_rows_buffer` 用一次完整插件查询的总分配次数守护回包行容器复用。共享候选字符串合入后，固定基点 `3fc3fab9b4` 的生产入口仍复用容器，但总计数为 49，旧预算为 46。该断言同时耦合了候选构造、注释与视图发布，不能直接区分行容器是否重新分配。

## Decision

在真实 Runtime 的测试提供者外包一层探针，只统计向回包缓冲申请一行容量的 `reserve(1)`。首次调用必须分配一次，后续两次重新查询必须零分配，并继续检查调用次数、候选及注释。探针委托原有提供者写行，不改变产品代码或候选字符串表示。用临时恢复每次新建回包缓冲的变异验证该测试能发现目标退化。

检索结果：[回包行缓冲笔记](2026-10-15-plugin-command-row-buffer.md)持有生产复用决定，本篇只接管分配测试的计数边界；[共享候选字符串](../architecture/2026-10-23-shared-candidate-strings.md)说明新建非空字段的 Arc 分配代价，不改它的表示决定；[注释缓冲](2026-10-15-plugin-annotation-buffer.md)独立守护注释构造，部分相关，保留原专项。

## Alternatives considered

- **把全查询预算改成 49**：改动最小，也能保留整体分配变化的报警，但无法说明新增分配是否来自行容器，后续其他合法的内部表示调整仍会触发无关失败。
- **只断言容量或指针相同**：能发现丢弃缓冲的常见写法，但没有直接测量目标容量申请是否发生；探针可用一次冷调用及两次热调用同时校验计数器与复用。

## Verification

生产实现的冷调用计数为 1，两次热调用均为 0；临时在生产入口清空容量的变异使热调用计数变成 1 并失败，验证后已撤销该变异。插件指令 13 项回归与 clippy 通过。固定基点的全量 Runtime 为 364 通过、两项旧分页契约失败，由独立短页测试 PR 同步，不混入本切片。格式和笔记校验通过。临时叠加独立短页切片的已提交测试后，全量 Runtime 366 项通过；测试结束核对临时文件未被并发修改，恢复本分支原文件。Windows runner 的完整 `bash scripts/verify-local.sh --quick` 退出 1，与独立短页切片一致，仍有宿主可移植测试、POSIX/换行契约、`client-core` 测试缺字段及 pipe-only 既有警告错误。缺少目标环境的 macOS、Linux、Android 构建按脚本跳过，不作为通过。本机约 10 GiB，远端复用现有标准 Rust 缓存；没有在本机新增构建树。

## Consequences

本测试只守护行容器的重复申请，无法替代其他候选及注释路径的分配专项，也不宣称查询总分配减少或端到端延迟改善。
