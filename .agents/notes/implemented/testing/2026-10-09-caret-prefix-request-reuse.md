# Agent Note: 光标前缀查询复用请求存储

Status: implemented

## Problem

全拼和双拼的光标前缀查询每次都先创建临时 `Scheme`，再从它生成新的 `QueryRequest`。分页扩展同一个前缀时，这些方案和请求的短命字符串会重复分配，输入内容本身没有变化。

## Decision

`ImeSession` 持有一个只供光标前缀查询使用的 `scratch_request`。全拼和双拼从原文直接写入这个请求，并在查询结束后把请求存回；只有其他方案才继续创建临时 `Scheme` 走原有回退路径。光标前缀扩展在构造请求时直接借用当前请求的带大小写原文，保持查询键和显示大小写一致。

## Alternatives considered

- **每次继续创建临时 `Scheme` 和 `QueryRequest`**：实现边界最简单，但分页或光标移动会为同一前缀重复分配。
- **让全拼、双拼也复用当前正在编辑的 `Scheme`**：会修改实时组字状态，查询期间不能安全地与当前候选刷新并行使用。
- **把请求缓冲放在调用方并长期缓存前缀结果**：需要额外处理方案切换、开关变化和词库失效，缓存生命周期比一次查询更难保证正确。

## Verification

光标前缀扩展的分配次数从 360 降到 356；`session::tests::` 的 186 个测试、golden 的 31 个测试、`cargo clippy -p msime-engine --all-targets --locked -- -D warnings`、格式检查、差异检查和 quick 门禁覆盖本次改动。

## Consequences

常见全拼和双拼光标前缀查询不再创建临时方案，请求字段容量可在分页之间复用；其他方案保留原有实现和行为。请求缓冲属于会话状态，查询闭包必须在返回前完成对它的使用，不能把引用泄漏到下一次操作。
