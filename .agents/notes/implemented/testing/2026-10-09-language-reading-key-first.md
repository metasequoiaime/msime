# Agent Note: 多结果读音查询首行移动连接键

Status: implemented

## Problem

单读音位置的 `lookup_readings` 多结果路径为每一行克隆连接键，包括第一行；原始键在构造结果后没有继续被使用。

## Decision

先把原始键移动到第一行，再从第一行的键为后续结果创建副本。新增合成 SQLite 测试，确认三行结果少一次分配，并验证返回结果保持一致。

## Alternatives considered

- 为结果键引入共享 `Arc<str>`：会扩大返回类型影响面，并给每行增加共享指针管理成本。
- 使用 `remove(0)` 取第一行：会移动剩余条目，查询结果较多时增加不必要的线性搬移。

## Consequences

多结果单读音查询减少一次键字符串分配；结果顺序、键内容和空结果及单结果路径保持不变。
