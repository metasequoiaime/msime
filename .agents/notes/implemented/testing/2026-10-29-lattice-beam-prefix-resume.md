# Agent Note: 整句束搜索从共用前缀的旧图接着解

Status: implemented

## Problem

九键每按一个数字，要对二三十条切分各解一次整句词网格。按 Pixel 那次的按键序列（`nks` + 聊天子句），平均每键 22.8 次解码、每次 6.6 个音节（测量用探针计数，未入库）。[整句解码缓存](../bug-fix/2026-10-22-sentence-decode-cache.md)只挡住音节串完全相同的重复，那篇已经指出剩下的大头是「只比解过的音节串多一个音节」，当时把增量解码留到以后。用同一份探针按前缀统计：每次解码的列里有 85% 与更早某张图的非末列前缀相同。本机采样里 `decode_graph` 及其下的二元评分约占九键刷新的三成。

## Decision

`lattice::decode` 新增 `BeamPrefixCache`，`QuanpinDictionary` 持有一份（`beam_prefixes`），整句解码没命中 `sentence_decode_cache` 时经 `decode_lattice` / `decode_lattice_borrowed` 的 `resume` 参数传给 `decode_graph_resuming`：

- **存**：每张不带纠错附加边的图解完，把列 0..n（不含末列）剪枝后的假设按原顺序存下，图边记成它在起点列里的下标。最多留 `BEAM_PREFIX_CAPACITY`（32）张，同一串音节只留最新一份，满了丢最早的。
- **取**：新图从缓存里找共用前缀最长、而且这个前缀在两张图里都不是末列的存档（`m < n_old`、`m < n_new`），打分参数要相同（束宽、跨度上限、最长词组、各项权重按位比较，二元表和个人模型按地址，个人模型另比调用方给的版本号，搭配打分只比有没有）。下标所指的边在新图里必须存在、终点要等于假设所在的列，否则当没命中。
- **接着解**：列 0..=m 照搬存档；先按原来的先后，把列 0..m 里终点越过 m 的边补展开一遍（这些列已是终态，不再剪枝），再从第 m 列照常往后解。

为什么逐位相同：列 k 的假设只来自终点为 k 的边，这些边的起点、音节和查到的词库行都在前 k 个音节之内；非末列的打分只看前驱假设和这条边（句末语气词加分、搭配的句尾项只在终点是末列时才算）。图边在列内按终点升序排，终点不越过 m 的边在两张图里是同一批跨度查出的同一批行，下标相同。往终点越过 m 的列推假设的先后与从头解完全一样（起点列升序、列内假设升序、边升序），所以 `push_partial` 的堆选择、平分时谁留下也一样。`BigramMemo` 只是查表的备忘，跳过的那部分查询不影响它返回的值。

失效（must）：`beam_prefixes` 在 `sentence_decode_cache` 清空的每一处一起清空（`set_sentence_alternatives`、`clear_row_caches`、纠错资料换代）；个人模型按存档里的版本号核对。以后新增影响解码的状态，要和整句解码缓存一样在这里接上清空或进比较。

纠错整句（带附加边的第二遍解码）和不经 `QuanpinDictionary` 的调用方（双拼的 `merge_lattice_candidates` 等）不变。

## Alternatives considered

- **按列缓存原始二元评分行**：[已否决](../../rejected/testing/2026-10-23-lattice-column-score-cache.md)，只省评分、不省展开，未过门槛。本篇整列跳过展开，评分也跟着省掉。
- **统一数字图一次解完所有切分**：[原型已否决](../../rejected/testing/2026-10-23-nine-key-unified-lattice-trial.md)，改变了候选；本篇不改任何候选。
- **存下所有前缀长度各自的状态**：每张图要存 n 份，内存翻 n 倍；而列 0..=m 本身就是任何更短前缀的状态，存一份全列就够。
- **把存档挂在 `sentence_decode_cache` 的条目上**：那份缓存有 512 条，每条都带全列假设会占到几 MB；单独一份 32 条的缓存够盖住上一键的图。

## Consequences

收益（本机 M4 Pro，测量用的 `ninekey_arms` 经 C ABI 每键调 `msime_client_character` 和 `msime_client_candidate_range(0, 48)`；与[上一个提交](2026-10-29-nine-key-covered-digit-pinyin.md)的二进制 ABBA 各两次、每次 3 轮计时，21210 个数字键样本）：

| | 平均 | p50 | p95 | p99 |
|---|---|---|---|---|
| 上一个提交 | 4.140 ms | 3.797 ms | 8.564 ms | 11.226 ms |
| 本改动 | 3.598 ms | 3.398 ms | 7.238 ms | 10.027 ms |
| 比值 | 0.869 | 0.895 | 0.845 | |

一行数字第 13 位以后比值 0.824（p50 0.791）；前 6 位 1.009，图短、能接的列少，存档本身的开销露了出来。

输出不变：`convert_eval` 九键与 14 键六组、全键盘 sentences / harvested / neutral / words / particles 和 particles 的九键、14 键两组，`--report` 与 `--dump`（每条用例的全部候选），以及 `typing_sim` 九键和全键盘两组的 `--report` 与 `--dump`，都与 develop 逐字节相同（行内时间行的文字是墙钟，按位置和来源比较）。

测试（`lattice/decode_prefix_resume_tests.rs`）：随机词表、随机按键游走（多一个音节、换末音节、删末音节、整串换掉），束宽 1/4/8/32、末列宽于束宽与否、二元表、三元表、个人模型、备忘、搭配打分 32 种组合下，接着解与从头解的句子、读音、词和分数逐位相同，并确认接上过前缀；打分参数或个人模型版本不同时不接；存档下标对不上新图时不接。把补展开少走一条边的变异会被第一项测出来。

代价：每次解码多存一份全列假设（每个假设 32 字节，32 张图、每列至多束宽 32 个，长串约 1 MB 封顶），多一次音节串复制；新图要线性扫一遍 32 张存档比前缀。短输入上这部分开销与省下的相当。
