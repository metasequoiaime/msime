# Agent Note: 九键在复制前拒绝已被更优同词行覆盖的候选

Status: implemented

## Problem

固定 `92058b68c2eda173906abb9ace0723836fc661eb`，九键正式按键阶段的二十秒采样仍有 `WordItem::clone`（122 个栈顶样本）、析构（194）和 `push_ranked`（135）。预热完成后才启动采样，没有把词库准备算成热点；采样期间存在其他会话构建，结果只用于定位，不能当延迟验收。`query_filtered` 借用系列页时仅筛读法，先克隆整行，再由 `push_ranked` 丢弃已经有更优同词行的结果。不同切分大量共用较短前缀，这些副本没有消费者。

## Decision

词典筛选回调接收只读完整 `WordItem` 和系列热页标志；标志只在失效检查后实际命中系列槽时为真。普通九键与 14 键的非模糊系列热页保留读法约束，再用当前 `leading` 中已接受的同词排序键检查；只拒绝其键不优于已有行的结果。预投影的排序使用将来的数字覆盖长度和规范读法，与最终拥有行共用相同算法。模糊查询已拥有完整结果，不提前做排名判断；九键双拼的覆盖核对要生成临时编码，保留原单次核对路径，避免对改善行多分配编码。冷页保持原读法筛选，不提前拒绝排名：全保留时仍移交原页，避免幸存生成行及容器容量收紧或缓存持有量改变。整个页筛选期间不更新 `leading`，页内同词仍由原 `push_ranked` 处理；后续可能改善的行继续保留。保留模糊合并先去重、系列缓存的完整内容、FIFO、失效、个人计分、输出所有权、顺序与容量。

## Historical audit

[读法筛选后复制](../../implemented/testing/2026-10-16-nine-key-filter-before-clone.md)及[冷页借用投影](../../implemented/testing/2026-10-16-nine-key-cold-cache-projection.md)部分重叠，继续持有完整缓存与冷页容量规则；本片增加排名拒绝条件。[排序表延迟预留](../../implemented/testing/2026-10-10-nine-key-leading-map-storage.md)继续持有 `leading` 的容量策略；[缓存排名键](../../implemented/testing/2026-10-16-nine-key-cached-rank.md)继续管理最终排序。二元前词散列、矩阵行分派及 attention 缓冲已有负结果，不重复。没有完全吸收或过时提案。

复用本仓库 `push_ranked` 的支配判定及 `query_filtered` 的借用筛选范式。标准库 [HashMap::get](https://doc.rust-lang.org/std/collections/struct.HashMap.html#method.get) 与 [Vec::retain](https://doc.rust-lang.org/std/vec/struct.Vec.html#method.retain)确认借用查找和稳定过滤的契约。不新增依赖、IO、宿主或公开接口。

## Alternatives considered

- 改为共享候选字段：可消除更多深复制，但跨越会话、缓存失效、学习和独立修改边界，本片不需要。
- 在回调内更新领先表：能够连同页重复也提前拒绝，但筛选尚未完成，未保留的行不能阻止后来的行；也会复制词面并引入另一套接纳流程。
- 冷页也提前拒绝排名：能覆盖更多页面，但会把原来全保留的冷页改走克隆投影；三音节两词边夹具使外层容量从 4 变成 3，生成词序也有富余容量。最终仅热页提前排名，不放宽冷页容量契约。
- 保留复制后排名：代码最短，无额外预查；本次须用精确分配红绿与完整刷新对照证明新增预查的价值，不能仅凭采样宣称提速。

## Verification scope

在旧生产刷新上新增分配预算先失败。冻结当前完整刷新作为独立对照，覆盖九键、14 键、九键双拼、冷热、锁定、切分、声母、模糊、同词相同及改善排名；检查所有字段、候选顺序与容量。预投影键对照实际构造后的旧排序键，包含空规范读法、所有相关来源与生成分归一化。质量 JSON 与正式旧二进制整体相同；完整测试、Clippy、fmt、notes、quick 和独立审查后交付。

## Consequences

新增哈希预查会增加非重复行的成本；页内不维护临时最佳表，不能消除同页重复。排名依赖数字覆盖长度而非原全拼字节长度，规范键回退也必须与拥有路径一致。`corrected_from` 的事后标记不影响原排名键。保持 16 ms 预算，不据确定性分配减少推断整体已达标。

## Paired timing protocol

在首次计时前固定：普通系统分配器的 release 完整刷新，三网格 × 模糊开关 × 0/32 条额外合成前缀共 12 形状；旧批次校准至少 50 ms、每形状 40 对交替先后。普通九键及 14 键无模糊的 32 行形状要求新旧中位比 <0.98，其余 <1.05。冻结当前完整旧刷新，最终字段与容量对照先通过；计时仅运行 ignored benchmark，不在移除计数分配器的二进制中运行申请断言。监测并记录其他会话构建，完整记录失败，不重测找绿。随后正式旧新二进制的九键 ABBA 保持 16 ms 预算；受干扰的观察不用于宣称整体提速或达标。


## Verification

真实完整热刷新预算在旧生产路径先失败：1772→1772；修复后为 1772→734，精确少 1038 次申请（约 58.6%）。冻结 `92058b68` 的完整刷新只改名、测试可见性、注释与格式，机械对照通过；预投影键另与冻结的原 `rank_key`、生成权重及简拼判定对照，覆盖三网格、来源、空规范键、异常读法、数字覆盖与标记组合。跨网格冷热、锁定、分隔、声母、模糊和同词改善矩阵对照字段、顺序及容量。

首个未收窄原型在九键双拼模糊形状多出两次编码申请，现仅普通九键/14 键的非模糊热页提前排名。冷页容量回归也先失败（外层 3 对原 4，夹具生成行两词却预留三槽），随后用实际命中标志隔离冷页后通过；标志测试还覆盖外部写失效、reset 和模糊路径。原补全筛选测试的差值因叠加本片收益从 9 变成 87，旧测试改为对照本片冻结前版本，仍精确检验原三条补全各省三个字段，不放宽其预算。

完整测试通过：引擎 2212、golden 31、运行时 294；36 个既有或手动计时忽略项。全目标 Clippy `-D warnings` 通过。全拼 60 例和九键 81 例正式旧新 `convert_eval` 完整 JSON 相同，不更新质量基线。独立只读审查指出并复核上述冷页修正后，无阻断问题。
