# Agent Note: 五笔反查显示候选的身份校验快速路径

Status: implemented

## Problem

五笔方案的宿主快照需要给显示候选追加反查编码。引擎已经在原始候选刷新时按候选保存编码，但显示列表还会经过混输、固定位置、个人重排、前缀筛选和本地行插入。直接把显示下标当成原始候选下标会把别的候选编码附到当前行；旧的按词查找语义正确，却会为每个显示行线性扫描原始候选。首版快速路径只比较词面，遇到同词面但 `pinyin`、来源或规范读音不同的行时，仍可能错误复用同座缓存码。

## Decision

显示行与原始行在同一位置时，只有 `word`、`source`、`pinyin` 和 `canonical_pinyin` 全部相同且对应编码非空，才直接读取该位置的缓存编码；身份变化时按同一完整身份扫描已有编码缓存，不重新查询五笔词库。保留按词入口供明确的按词查询使用。快速路径只减少安全可证明的同序扫描，不把显示索引当成原始索引。

## Alternatives considered

- **直接按显示下标读取原始编码**：实现最小，但显示候选经过重排、混输插入和过滤后不再与原始顺序同构，会产生错误注释。
- **每次快照建立词面哈希表**：能把任意显示顺序变成近似常数查找，但会为每次快照新增哈希表分配，且需要明确重复词的首项语义；在常见同序路径上不如有界快速路径直接。
- **让所有显示候选携带原始身份**：语义最完整，但要把身份扩展到本地候选、插件行和多组平行数组，跨越引擎与宿主快照契约，改动面超出本切片。
- **只继续比较词面**：能覆盖大多数同序行，但同词面候选的其它身份字段仍可能不同，无法证明座位缓存属于当前显示行。

## Verification

- 同序原始候选直接复用已有编码，不执行线性按词扫描。
- 混输、固定位置、个人重排、前缀候选、单字过滤和重复词均与旧按词入口产生完全相同的注释。
- 越界、长度不一致或词面不一致时不误用别的行编码。
- 五笔反查宿主测试 5 项通过；新增同词面不同候选身份的回归先在旧入口上按预期失败，修复后通过。Engine release 单元测试 2137 项通过、28 项忽略，golden 31 项通过；Engine 全 targets Clippy（`-D warnings`）、`cargo fmt --all -- --check`、`pnpm run verify-notes` 和 `bash scripts/verify-local.sh --quick` 均通过。Quick 门禁报告 Linux 原生宿主 87/87、Windows 主机 149 项通过（2 项主机差异排除），其余平台阶段按环境规则执行或跳过。

## Consequences

快速路径只在完整身份和边界都匹配时生效；错位、越界、重复词或身份字段变化时扫描已有缓存，因此显示候选的重排和插入不会改变编码语义。代价是同序路径仍要比较四个身份字段，错位路径保留线性扫描，但两条路径都不重新访问五笔数据库。
