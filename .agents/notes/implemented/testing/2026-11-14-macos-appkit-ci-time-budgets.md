# Agent Note: macOS AppKit 验收的分项时间预算

Status: implemented

## Problem

#11429 的 macOS 15 Intel 运行 `43528445237` 中，235 项原生测试仅 `skin-preview` 在 20.36 秒被 CTest 终止；拆出的六个主题矩阵均通过。韩语输入源 UI 已完成添加，连同退出系统设置共用 62.607 秒，超过 XCTest 默认的 60 秒，测试体虽然显示通过，`xcodebuild` 仍因超时失败。后续 TIS 复核与真实韩语输入因此没有执行。

[韩语布局验收笔记](../feature/2026-10-23-korean-romaja-layout.md)曾按主题拆分预览矩阵并维持每项 20 秒，删除 UI 调试输出后也维持了整体 60 秒。本次日志表明两处总预算仍无足够余量。CI 的预览采样产物只有 `sample timeout`，没有可用调用栈，不能据此认定产品死锁或宣称已找到性能根因。

## Decision

仅 `skin-preview` 主入口显式使用 60 秒预算；六个独立主题矩阵继续沿用原 20 秒。主入口除自定义主题矩阵，还执行字体、设置持久化、几何和图片像素检查，保留全部组合与断言，不扩大其他原生测试预算。

韩语输入源 UI 的默认与最高执行预算改为 90、120 秒，覆盖系统设置启动、系统 UI 交互和退出；各控件既有的 2–10 秒等待、添加流程断言、随后 TIS 状态核对与真实 IMK 输入断言保持。仍限一次性 CI Mac，不在维护者桌面修改输入源。

## Alternatives considered

- 继续依赖重跑：不改变任何时间约束，但已完成的添加流程仍会被总时间误判，后续真实输入继续被阻断，不采用。
- 取消超时：不会误判慢机器，但可能无限等待，丢失 CI 故障边界，不采用。
- 继续拆预览主入口：可以定位最慢分组并保持 20 秒，但当前没有可用 Intel 栈，主入口包含串行状态和持久化断言；先保留完整行为，避免为缩时改变夹具状态。

## Verification

- 原始 Intel CI 日志确认六个主题矩阵通过、主入口 20.36 秒超时，韩语流程在添加成功后以 62.607 秒完成；采样超时，不作为根因证据。
- 复用既有 arm64 原生产物执行预览主入口，退出 0，实测 8.84 秒。该结果仅说明本机无同样阻塞，不能替代 Intel CI。
- 本分支重新构建 `skin-preview-test`，七项 CTest 全部通过，总耗时 19.04 秒；脚本语法检查及完整 quick 门禁通过（含 macOS 原生编译、共享 Apple 桥、Windows x86_64／i686 管道交叉编译）。发往 develop 的普通 PR 默认只跑 arm64，但本改动触及 `run-korean-system-ci.sh`，`Decide installed Korean acceptance` 会设置 `installed_korean=true` 并让 Intel 矩阵实际构建、测试和执行系统韩语输入。开 PR 后核对该条件确实生效，保持 draft 直到 Intel 实际成功，不重复触发同一套手动运行。

## Consequences

已完成的系统设置交互有额外时间余量，预览主入口在慢 Intel runner 上仍有明确的失败边界。代价是这两项真正卡死时较晚报告；没有掩盖断言失败或自动重试。预算调整不证明预览的性能根因，后续若 60 秒仍超时，应补足采样并定位，不能继续盲目增加预算。
