# Agent Note: 日文待定候选循环复用拼接读音键

Status: implemented

## Problem

provider 的待定前缀词条查询和 matrix 的待定精确词条查询都为每种假名构造一份完整读音键。`k` 对应九种假名，两层在一次候选请求中构造十八份临时拼接字符串；它们只用于查询，不成为最终输出。

## Decision

两处循环各使用一份局部 `String`。只有假名列表非空才按公共读音与最长假名字节数预留容量并写入公共读音；每次截断到完整公共读音末尾，再追加当前假名。列表为空不分配，单假名直接取其长度。查询继续调用原 exact/prefix 方法和完整字符串比较，不改变成本、限额、遍历顺序、去重或最终候选拥有文本。

provider 和 matrix 的键缓冲各自保留在调用点，避免为了借出几行拼接键引入 lending iterator 或新的回调接口。provider 的词条结果通过[前缀词条流式访问](2026-10-09-japanese-prediction-stream.md)直接消费，不改变拼接键机制。旧 provider 查询正文冻结在测试模块以对照完整字段；旧 matrix reference_search 保持逐假名拼接，不随生产缓冲改动。

## 既有笔记审计

[continuing 查询键](../../implemented/testing/2026-10-09-japanese-continuing-query-buffer.md) 部分重叠，本片复用同一局部缓冲思路但针对外层 prefix/exact 查询，互链，保留 decoder 实现和原验证。[词条借用](../../implemented/testing/2026-10-09-japanese-lemma-borrow.md) 保留视图只绑定词库的生命周期，部分重叠，互链。[固定假名前缀索引](../../implemented/testing/2026-10-09-japanese-kana-prefix-index.md) 保留全部拼法和排序去重列表，部分重叠，互链。[两段比较被否决](../../rejected/testing/2026-10-09-japanese-continuing-key-borrow.md) 保留回退证据，本片继续完整键比较。其余拼法边界和小写规范化属于不同转换层，保留；caret、注音、拼音、九键的命中属于其他算法，保留无关。检索活跃笔记中的 join_reading、join_text、查询键、拼接读音与假名前缀，未发现外层两处循环的单缓冲决定。

## Alternatives considered

- 保留逐假名拼接：局部代码最短且无需扫描最长长度；每个后缀都分配一份相同公共读音副本。
- 两段借用比较：可以消除全部查询键分配；此前 decoder 的 release 对照出现回退，本片保持完整字符串二分与扫描。
- provider 常驻缓冲：充分预热后这层键可零分配；matrix 仍需局部存储，先消除同一次查询内的重复构造，不增加保存用户读音的长期状态。

## Verification

旧实现红测试中，合成两词条 `kak` matrix 为 24 次分配，provider 为 37 次；缓冲实现为 16 和 21 次，分别减少八次与十六次。完整矩阵输出对照保持旧逐假名拼接的 batch oracle；新冻结当前基线的完整 matrix 正文专用于本片分配与计时对照，排除历史剪枝等优化。provider 冻结旧正文且调用当前生产 matrix，仅隔离 provider 外层键变化；两份冻结正文由独立审查逐项核对与 `f37203c77` 一致。

长 UTF-8 读音、短长假名交替、别名、空假名列表、只有待定字母、Unicode 待定文本、负成本、平局、限额和不同长度编辑的完整输出与旧流程一致。matrix 进入待定精确补全循环且列表非空时，查询键分配分量严格等于假名数减一，否则为零；provider 预热后的查询键分量在相同条件下也按假名数减一计算，并另统计词条视图向量分量。动态候选插入、脏行字段复用与完整候选字段保持。合成词库读音按字节排序，并明确断言两侧 provider 的模型必须加载成功，防止两侧共同降级为无词库时自证。

provider 对照仍使用冻结原正文；生产词条回调消费后，其差值同时包含本篇的查询键减少量与[实际命中前缀的视图向量减少量](2026-10-09-japanese-prediction-stream.md)，分别计算再求和。原本只隔离拼接键的历史计时数字保留，当前 ignored provider 计时覆盖整个待定前缀查询差值。

## Consequences

每处循环只保留一份完整查询键，减少同一次查询内重复分配与公共读音复制，不增加保存用户读音的常驻状态。键在循环完成后释放，词条视图只绑定词库，最终候选仍拥有文本。代价是多假名时扫描最长长度及每轮截断和追加；单假名保留一次键分配但不扫描最长长度，空列表不创建键。

`truncate` 的边界必须是已写入完整公共读音的末尾，容量必须覆盖最长假名。两处键缓冲各自局部，decoder 的 continuing 缓冲、原完整字符串比较、所有查询限额、顺序和候选去重保持。`join_reading` 仅保留测试以支撑冻结旧流程，matrix 的 `join_text` 仍负责节点文本构造。

[固定八槽行实验](../../rejected/testing/2026-10-09-japanese-inline-matrix-rows.md) 因 release 未显示稳定收益且出现查询回退被否决；生产 Vec 行及本篇历史验证保持。实验仅保留在 `cfg(test)` 中，不能把减少分配视为查询加速。

冻结 provider 对照现另包含[句子结果容器复用](2026-10-09-japanese-sentence-output-buffer.md) 的分配差值；在合成有词库夹具中，除裸 `-` 外的查询恰好再省一次容器分配，分别统计后求和。历史拼接键计时不归因于此后新增的容器优化。

矩阵冻结对照现另包含[继续补全视图流式消费](2026-10-09-japanese-prediction-stream.md) 的结果向量分量。读音非空、限额非零且待定继续补全命中时恰好再少一次分配；拼接键继续用 `33a5a3f46` 与 `f37203c77` 隔离，视图分量另对照固定 `961f0514a` 的精确流式查询，最终页已满也沿原流程查询。空读音分支的前缀视图流式消费也按最终页满之前实际命中的前缀数另核算；它与非空读音的继续补全分量互斥，冻结查询正文保持。ignored 矩阵计时已更名为整体待定读音查询，历史拼接键计时仍只对应当时的实现。

[精确词条流式消费](2026-10-09-japanese-exact-lemma-stream.md) 进一步减少 matrix 精确视图结果容器。本篇历史计时与 24→16 分配仅反映当时的键复用；当前 pending 键差由冻结 `33a5a3f46` 单缓冲 Vec 查询与 `f37203c77` 逐假名拼接查询隔离，生产分配另外要求不超过单缓冲对照。当前 `benchmark_matrix_pending_queries` 对照固定历史正文，包含精确与继续补全流式收益，不再能独立归因于键复用。

[矩阵滚动行](2026-10-10-japanese-rolling-rows.md)另减少非空、非零限额查询的行缓冲次数。当前生产与固定精确流式对照的次数断言分别加回继续补全视图、空读音前缀视图和 `字符数减16` 正部的行容器分量；拼接键的两份冻结查询正文不改，历史计时不归因于滚动存储。

[滚动字节边界](2026-10-10-japanese-rolling-boundaries.md)再减少非空、非零限额查询的完整位置 Vec。生产与固定精确流式对照另加回实测边界 alloc/realloc 分量，与行缓冲、继续补全和空读音前缀视图分量分别核算；冻结查询与历史键复用证据保持。
