# Agent Note: 五笔查码去重字符复用栈工作区

Status: implemented

## Problem

五笔查码入口把输入文本里第一次出现的汉字收集到 `Vec<char>`，最多只会保留 64 个字符。设置页粘贴文本时，这个向量只是去重和截断工作区，随后还会把每个字符转换成最终的 `WubiTextCodes`；短查询也会为工作区单独申请堆存储。

动手前检索了活跃笔记中的五笔查码、反查和候选编码路径。已有的[五笔反查显示候选身份校验快速路径](2026-10-15-wubi-reverse-code-fast-path.md)只处理宿主快照中的候选编码读取，不涉及设置页查码的字符去重工作区；没有重复实现或待吸收的同机制笔记。

## Decision

`lookup_codes` 使用固定的 `[char; MAX_LOOKUP_CHARACTERS]` 保存去重字符，并由 `distinct_han_characters` 返回已填长度和截断标记。扫描仍按输入顺序线性去重，超过 64 个不同汉字时在发现第 65 个后停止；最终的 `characters` 结果从有效长度切片收集，保留精确结果容量并按原顺序拥有 `WubiTextCodes`，公开返回类型、数据库访问和整段词查码不变。

## Alternatives considered

- **继续使用 `Vec<char>`**：代码最短，但每次查码都为最多 64 个仅供扫描的字符申请堆存储，短文本也承担这次临时分配。
- **使用 `HashSet<char>` 去重**：平均查找更快，但需要哈希表分配；输入上限很小，线性扫描更简单且保持首次出现顺序。
- **用 `Option<char>` 数组再 `flatten()` 收集输出**：能明确标记未填槽位，但丢失迭代器的精确长度；33 条结果的容量回归测试实测会保留 64 槽，抵消工作区优化。有效长度切片保留原有精确预留行为。

## Verification

- 合成去重扫描测试确认 `你你好` 得到 `你、好`，且扫描本身分配次数为 0。
- 64 个字符上限测试确认保留前 64 个并标记截断，顺序不变。
- 空输入、非汉字、扩展区汉字、重复字符及 1/4/5/33/63/64/65/80 个不同汉字与冻结的原 `Vec` 扫描对照，结果和截断标记一致；非空扫描均减少临时分配。
- 33 条结果的容量回归先以 64 对 33 失败，改用有效长度切片后通过。
- `wubi::lookup::tests` 的 9 项测试通过；引擎全量单测 2090 passed、19 ignored，golden 31 passed；Clippy、Rustfmt、差异检查、笔记门禁和 quick 门禁均通过。quick 包含 Linux 原生宿主 87 项测试及 macOS/Apple bridge 构建，缺少前置的 Windows 交叉编译和 HarmonyOS ArkTS 阶段按脚本跳过。本次不改文件读写逻辑，未做设备验收。

## Consequences

短文本查码不再为去重字符工作区申请堆存储，每次查询使用 256 字节字符栈数组；最终字符结果、词组查码、缺失数据库和缺失表的行为保持不变。该优化只覆盖字符扫描，不减少每个字符的 SQL 查询和最终结果字符串存储，也不把设置页查码的分配收益外推为整个平台输入延迟。
