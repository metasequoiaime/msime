# Agent Note: 日文待定补全在查询内复用拼接键

Status: implemented

## Problem

`prefix_lemmas_continuing_with` 为每个非空后缀创建完整查询键。三个非空后缀命中为五次分配，其中三次是拼接键；三个后缀未命中仍分配三次。所有键共享同一前缀且只在当前查询内读取。

## Decision

查询内创建空 `String`，首个非空后缀才按前缀与最长后缀的总字节数预留容量并写入公共前缀。单后缀直接使用当前后缀长度，多个后缀才扫描最长长度。每次非空后缀先截断到前缀末尾，再追加当前后缀；只分配一次并不扩容，空后缀原分支完全保留。完整键仍使用原二分下界与 `starts_with`，没有自定义比较器或常驻缓存。

后缀顺序、重叠与重复后缀的重复排名 ID、平局、负成本、限额、首次命中排名容量和最终排序保持，词条视图仍只借用词库。空前缀、无后缀及零限额仍直接返回；全空后缀无需查询键分配。

[两段借用查询](../../rejected/testing/2026-10-09-japanese-continuing-key-borrow.md) 因 release 计时回退已否决，保留比较器开销的防坑证据，互链。[词条借用](../../implemented/testing/2026-10-09-japanese-lemma-borrow.md) 与[空排名存储](../../implemented/testing/2026-10-09-japanese-empty-ranking.md) 部分重叠，继续约束视图生命周期和延迟排名分配，互链并更新当前事实、保留历史验证。[末行文本转移](../../implemented/testing/2026-10-09-japanese-final-text-move.md) 和其他日文转换笔记属于其他层，保留。活跃笔记检索 continuing、suffix、lower_bound、后缀和拼接读音，其他算法的命中均无关，没有另一套查询内单缓冲决定。

## Alternatives considered

- 两段借用比较：完全消除键分配和拼接，所有结果对照正确；release 小结果和未命中计时出现回退，否决。
- 让缓冲自动增长：少一次最长后缀扫描，代码更短；后到更长后缀会重新分配，最长容量只在首次非空后缀时计算一次。
- provider 常驻缓存键：跨查询也可零分配；查询方法当前是词库不可变借用，增加共享状态与锁会改变生命周期和并发边界，查询内缓冲足以消除重复后缀分配。

## Verification

旧实现真实红中多后缀未命中为三次、预算一次；三后缀命中五次、预算三次。单后缀预算保持原值，全空后缀零键分配。多长度后缀先短后长与反向均只一份键存储；Unicode、长前缀、空值、负成本、平局、重复 ID 和限额的完整输出与固定旧拼接查询一致。固定基线的旧拼接查询正文和独立二分搜索经过代码审查逐项核对，普通下界和旧测试辅助函数仍保持。日文 83 项、完整引擎 1470 项、golden 31 项、Clippy、Rustfmt、差异与 347 篇笔记检查通过。一个本地计时测试默认忽略，已单独运行 release。独立设计和最终代码审查无遗留问题；单后缀容量快路径加入后完整引擎、golden 和 Clippy 已再次通过。

完整 quick 门禁退出为 0 并报告 `quick check passed`：共享 Rust、Android 目标与宿主 Java、Linux 共享桌面层、Linux 原生宿主 73 项测试及五笔版构建与安装检查、macOS 原生宿主和 Apple bridge 构建通过；Windows 本机测试 102 项通过。Windows 交叉构建、WASM 和 HarmonyOS 原生 ArkTS 因工具链或前置条件缺失由脚本明确跳过，没有设备验收。

release 十批交替顺序、每批 1000 次、中位批次：16 条合成词库多后缀命中 2.410→2.295 ms、未命中 0.361→0.341 ms；1024 条多后缀命中 48.528→47.098 ms、未命中 0.831→0.805 ms。单后缀未命中分别为 0.080→0.084 ms、0.193→0.204 ms，每查询约增加 4–11 ns；单后缀命中 1.512→1.517 ms、24.832→27.990 ms，重复测量的同一大词库路径此前也出现 20.881→20.327 ms 和 130.911→78.629 ms，受本机负载影响大，不能当作延迟保证。

计时测试使用 black_box、交替测量顺序和独立旧查询对照，只作本地忽略测试，无 CI 时间阈值。单后缀无需扫描最长长度；多后缀稳定减少键分配，单后缀保留一份键但承担缓冲分支开销。

## Consequences

`truncate(prefix.len())` 的边界必须始终是已经写入的完整前缀，不能清空后再依赖原长度。最长后缀容量只在实际遇到非空后缀时计算，全空后缀不分配。单个非空后缀仍需一份键存储，不声称所有查询零分配或实际打字延迟同比下降。

多个非空后缀共用一份键缓冲，减少重复分配和公共前缀复制。代价是首次非空后缀时额外扫描后缀长度，以及每次截断和追加；缓冲只活在当前调用中，没有锁、共享状态或新接口。
