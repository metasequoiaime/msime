# Agent Note: 简拼小页使用固定栈缓冲

Status: implemented

## Problem

`query_jianpin_codes_per_table` 在无命中时仍预留最多 128 个聚合槽；命中时每张表又生成独立 `Vec<DictRow>`，随后搬入聚合结果。九宫格普通查询上限为 64，个人排序扫描每表上限为 512，稀疏扫描的临时页按 512 槽预留。两个公开入口共用这一层。

## Decision

共享 SQLite 读取循环增加私有 `visit_rows` 回调；现有 `rows` 使用同一读取循环并保留原容量提示。简拼每张表先用固定 64 槽 `Option<DictRow>` 栈页接收，超过 64 行才转入按原 `query_capacity(table_limit)` 预留的堆页；无界提示从 128 槽接续增长。首次非空页才按 `table_limit.min(128)` 预留聚合容器，再用精确长度迭代器整页追加，保持旧聚合扩容。保留查询规划、每表 SQL 上限、稳定权重排序、最高权重同值去重、公开全局截断与结果所有权。

## 既有笔记审计

[底层空页预留](../../implemented/testing/2026-10-10-pinyin-empty-row-storage.md)持有共享循环的空页和错误语义，部分重叠；现有 `rows` 的行为与预算保持不变。[聚合空页](../../implemented/testing/2026-10-10-pinyin-empty-aggregate-storage.md)与[精确聚合首个页复用](../../implemented/testing/2026-10-10-pinyin-aggregate-page-reuse.md)处理另外两个入口，部分重叠但保留其独立容量策略。[九宫格个人排序](../../implemented/feature/2026-10-09-nine-key-initials-personal-ranking.md)与[简拼候选](../../implemented/feature/2026-10-08-nine-key-initials.md)约束查库上限与排序，不改变这些决定。检索活跃树的简拼聚合、直接行追加与上述函数，无相同决定或过时提案。

## Alternatives considered

- 延后原聚合预留：空结果无需分配且保持非空预算，但每个命中表仍分配临时页再搬移。
- 接管第一张非空页：单页少一次分配且不需提取共享循环；512 上限的一行页会把返回容量从 128 放大到 512，后续表仍有临时页。
- 将每表页提示统一压到 128 再接管：改善稀疏容量，但改变密集和不均匀页的扩容预算。
- 直接逐行追加到聚合结果：省掉所有临时页，却使真实 SQLite 单页 257 行/limit512 的返回容量 257→512，额外保留 14280 字节；分配数仍为 547。半满页不能只按满页证据验收。
- 模拟首次 `Vec` 扩容公式：可能省一次大页聚合扩容，但依赖标准库实现细节；保留原提示后整页追加，更容易守住既有预算。

## Verification

固定 `b3934a95ee5b550f6c503d9841ea76aea65ddb00` 的两个完整公开入口作为对照，两侧共用当前 `rows`；其容量提示和行转换行为保持原样，另由已有底层冻结测试覆盖。旧生产上的 8 项测试中有 5 项按预期失败，覆盖空结果预留、首步错误、稀疏临时页、密集临时页和冷区间存储。直接逐行追加的试验另在真实 SQLite 单页 257 行/limit512 上失败，容量 257→512；最终改用固定栈页。

最终 9 项针对测试通过，覆盖两个入口的非法/重复码、缺表、首步真实错误、NULL/blob/数值转换、负/大权重、稳定等权排序、值去重、每表和全局截断，以及释放输入和数据库后的结果所有权。密集四表在 limit64 下分配 544→540、容量均为 256；limit128 和 limit512 下次数分别保持 1057 和 4132，容量分别保持 512 和 2048。真实 SQLite 129/200/257/383 行、200→257→1、四表各 257 行及其他不均匀页的容量、次数和堆峰值不增加；四表 257 行的容量均为 1028，Rust 请求峰值均为 140593 字节。新增矩阵进一步覆盖 limit64、limit512 和 usize::MAX。

完整冷区间包含打开数据库、查询与显式析构，只返回结果并借用外部 fixture/path/input；进程级不可变音节表在计量前预热。limit512 单行命中分配 32→31、Rust 请求峰值 37086→8414 字节，结果保留字节同为 7183；有效 miss 分配 29→28、峰值 8399→1231 字节，结果保留存储 7168→0。两侧最低 signed 差值均为零。热计量只比较分配次数。

同步远端 `develop` 到 `ff171709de62b0485ec261cd464318081c68a4b8` 后，完整引擎 1676 项通过、13 项忽略，golden 31 项通过。

## Consequences

普通 64 行简拼与不超过 64 行的个人排序扫描省去每张命中表的临时堆页，全部表为空时聚合容器不分配。超过 64 行的页继续使用原堆容量提示，最终按页长整批追加，守住不均匀多表的返回容量；这些密集页没有临时页分配次数收益。共享 `rows` 的空页、正提示与无界增长行为不变。

固定 64 槽行载荷在当前 arm64 上约为 3.5 KiB，数组初始化、`Option` 搬移与 `into_iter` 临时量也有成本；该数值不是实测总栈帧增量。没有引入依赖或 unsafe，没有重复查询计数，没有末尾 shrink 掩盖扩容。Rust 计量不含 SQLite C 堆或 System 内部暂存，不等于 RSS；本片没有发布构建计时或原生宿主输入延迟证据，不能把分配收益推断为延迟改善。[Vec::reserve_exact 官方契约](https://doc.rust-lang.org/std/vec/struct.Vec.html#method.reserve_exact)只保证至少所需容量，测试记录的是固定工具链和当前平台上的逻辑请求存储。
