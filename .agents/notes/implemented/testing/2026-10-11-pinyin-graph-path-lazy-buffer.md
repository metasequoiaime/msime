# Agent Note: 拼音图遍历路径缓冲延后预留

Status: implemented

## Problem

`enumerate_complete_segmentations` 已经延后结果页容量，但递归遍历的 `current` 路径仍在进入搜索前按输入长度申请缓冲。没有任何可达边的图不会压入路径，却仍为这块工作存储分配空间。

## Decision

遍历路径从空容器开始。递归首次准备压入边时，再按图的输入长度执行 `reserve_exact`；有路径时继续复用原容量，无路径时保持零分配。结果顺序、路径上限、结果页容量和边遍历顺序不变。

## Alternatives considered

- 继续在遍历入口预留：成功路径少一次判断，但所有无路径输入都申请工作缓冲。
- 按每条边自然增长：失败路径可零分配，但深路径会重复扩容并改变原容量提示。
- 只延后结果页而保留路径页：仍为无路径图保留一块输入长度大小的临时存储，不能消除完整空查询成本。

## Verification

新增不可读 256 字节图的分配回归。旧实现测试先失败并产生 1 次工作缓冲分配；修复后分配为 0。拼音图测试 8 项通过；提交前还会运行引擎库、golden、Clippy、格式、差异和笔记校验。

## Consequences

无可达拼音图不再申请遍历路径存储；有路径时首次压入保留原输入长度容量。分配计数只覆盖 Rust 路径工作向量，不代表图边数组或端到端延迟。
