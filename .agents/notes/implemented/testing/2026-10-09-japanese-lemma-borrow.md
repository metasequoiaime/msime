# Agent Note: 日文内部词条查询借用已验证的词库文本

Status: implemented

## Problem

日文矩阵搜索与 provider 每次查询都把词库中的读音和词面复制成拥有字符串，随后只读取字段或再写入最终候选。单假名矩阵搜索真实红测试分配 17 次，其中同一词条被查询两次、共复制四个临时字符串。

## Decision

新增 crate 内部词条视图，读音与词面借用 `JapaneseDictionary` 已验证的只读文本，数值字段按值保留。三种查询共用原筛选、短前缀缓存和成本排序，通过私有泛型映射函数选择拥有型或借用型结果。`japanese` 是私有模块，旧 `JapaneseLemma` 及三个拥有型查询只保留在 `#[cfg(test)]` 中作原行为和分配对照；生产 matrix 和 provider 全部使用借用视图，外部 API 不变，不增加中间 ID 向量。

视图的生命周期只绑定词库，不能绑定查询临时字符串。映射和预加载字节都继续由词库持有；最终候选、句子节点与测试对照的拥有型查询结果仍自行拥有文本。不修改文件读取、映射、UTF-8 校验、模型替换协议与连接成本，也不改变重叠 suffix 的现有筛选结果。

## 既有笔记审计

[provider 转换缓冲](../../implemented/testing/2026-10-09-japanese-provider-conversion-buffer.md) 部分重叠，本篇消除词条中间复制，原篇继续约束转换和无词库热预算，两篇互链。[罗马字拼法与假名位置](../../implemented/bug-fix/2026-10-08-japanese-romaji-spellings-and-kana-slot.md) 保留候选顺序约束，与本篇存储决定无关。其他日文请求和临时会话行笔记分别负责转换与最终行，无关且保留。对 proposed、implemented、rejected 检索 `JapaneseDictionary`、`prefix_lemmas`、词条借用，未发现同一决定。

## Alternatives considered

- 在词库加载时缓存全部拥有词条：查询能直接借用缓存，但 128 万词条会把只读映射的文本复制到常驻堆，破坏按需驻留的内存取舍。
- 让原查询直接改成借用类型：代码最少，但失去旧拥有结果的字段与冷分配对照；旧入口仅保留于测试，生产使用视图入口。
- 先通过旧查询取得拥有结果再转视图：可复用接口，但复制已经发生，无法解决分配根因。
- 分别实现两套筛选：避免泛型映射，但成本、限额、短前缀缓存和 continuing 行为容易漂移；只让结果构造参数化。

## Verification

单假名矩阵搜索与充分预热的有词库 provider 查询在真实红测试中均分配 17 次，借用后均为 13 次，完整结果一致。日文 63 项测试通过。完整引擎 1450 项、golden 31 项和 Clippy 通过；Clippy 暴露的旧拥有型查询生产无调用问题已通过仅保留测试路径解决，未添加 `allow(dead_code)`。独立设计、代码审查与范围修正审查没有遗留问题。最终日文测试、Rustfmt、差异和 337 篇笔记检查通过。完整 quick 门禁退出为 0 并报告 `quick check passed`：共享 Rust、Android 目标与宿主 Java、Linux 桌面共享层及原生宿主 73 项测试、macOS 原生宿主和 Apple bridge 构建通过；Windows、WASM、HarmonyOS 的缺失工具链或前置阶段按脚本明确跳过，未做设备验收。

内部三种查询与测试对照的拥有结果逐字段一致，指针均位于词库字节内；每条非空合成词条恰好少两个字符串分配。70 条合成词库覆盖成本平局、限额 0/1/2/24/64/65/70/100：短前缀缓存只分配一份视图向量，扫描查询分配两次，continuing 另按非空 suffix 分配查询字符串，测试对照结果只额外承担原来的两个字符串分配。空、缺失、空及重叠 suffix 的原结果不变，临时查询释放后视图仍可用。映射替换与预加载替换/卸载后，旧词库句柄的视图和指针保持有效。

[未命中排名存储](2026-10-09-japanese-empty-ranking.md) 进一步取消空查询的排名堆分配；本篇的命中预算和文本生命周期约束继续有效。

[矩阵节点提前筛选](2026-10-09-japanese-pruned-node-text.md) 进一步避免败选句子节点文本的构造；仍保留本篇的借用词条生命周期和最终候选拥有文本边界。

## Consequences

内部查询每条词条避免复制读音和词面，没有新增中间 ID 向量。旧拥有型查询退出生产，只用于测试，不扩大 crate 外接口。新增三个内部视图入口和三个私有泛型结果映射函数，使内部接口稍多，但只有一套筛选、缓存和排序规则。生命周期由借用检查器绑定词库，调用方不会把视图保存到词库之外；没有新增缓存、unsafe 或文件操作。

查询向量、ID 排序、continuing 查询字符串和句子节点仍会分配，本篇只消除词条文本复制，不声称整个词库搜索零分配。模型校验、加载、替换与候选排序没有变化，内部重叠 suffix 仍保留现有重复结果供最终候选去重。
