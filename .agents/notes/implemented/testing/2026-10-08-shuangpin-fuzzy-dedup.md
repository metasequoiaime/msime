# Agent Note: 双拼模糊候选去重的小列表路径

Status: implemented

## Problem

双拼引擎合并全拼模糊候选时，会为精确结果与模糊结果创建临时 `HashSet` 和重复索引列表。模糊查询的常见候选批次较短，却仍承担一次哈希状态分配。

## Decision

精确与模糊候选总量不超过 64 条时，按词面线性扫描精确结果并直接追加唯一模糊行；超过边界时继续使用借用词面的 `HashSet` 和重复索引回退。模糊结果仍在合并后按拼音覆盖长度稳定排序，首次出现顺序保持不变。

## Alternatives considered

所有批次都使用线性扫描会让模糊候选扩展时出现平方级比较；始终保留哈希路径则无法消除短模糊查询的临时集合。按 64 条边界分流，让常见小批次避免分配，同时保留大批次复杂度。

## Verification

新增短批次零临时分配测试和大批次首次出现顺序测试；完整引擎单元测试（1165 项）、Clippy、Rustfmt、差异检查、笔记检查和 quick 门禁覆盖实现。

## Consequences

64 条以内的双拼模糊候选合并不再创建临时哈希集合或重复索引；较大的批次继续使用哈希去重。
