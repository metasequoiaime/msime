# Agent Note: 拼音最短切分 DP 栈缓冲

Status: implemented

## Problem

`cut_one_piece_min_segments` 的短拼音只使用很小的动态规划表，不需要为每次调用建立临时堆向量。完整性检查 `is_complete_pinyin_input` 又只判断切分结果是否为空，却把每条音节复制为字符串并建立结果向量；候选过滤、在线查询和组字流程都承担这笔开销。

## Decision

长度不超过 64 字节时使用栈上的 65 项 DP 表；更长输入继续使用按字节长度分配的堆向量，不限制公开函数处理长输入。

`with_minimum_cut` 和 `with_minimum_cut_best` 统一管理栈表、堆回退和原有最少音节算法，再把已填好的表借给一次性回调。公开切分函数在回调中按首音节终点构造原有结果；完整性检查只读取首位置是否有路径，不创建音节字符串或结果向量。这延续引擎 `ordering::with_row_texts` 的栈缓冲加回调模式，表借用只覆盖本次调用，回调使用 Rust 的 [FnOnce](https://doc.rust-lang.org/std/ops/trait.FnOnce.html)，首位置用 [Option::is_some](https://doc.rust-lang.org/std/option/enum.Option.html#method.is_some) 判断。

空输入以及任何空撇号分段仍返回不完整。检查只接受完整音节，不能改用前缀或修正别名；例如 `jv` 是合法完整音节，`sahng` 和 `zhonguo` 的修正路径不算完整输入。多字节字符继续由原有字节查询拒绝，切分的最少音节和短首音节优先级都保持同一套实现。

## Alternatives considered

- **始终使用固定表**：可统一栈路径，但会把输入长度限制在 64 字节，改变长输入行为；因此保留堆回退。
- **始终使用堆向量**：管理简单，但短路径仍为临时表分配。
- **完整切分后判断结果为空**：直接复用公开结果接口，却为布尔答案复制所有音节并建立结果容器。
- **另写可达性布尔 DP**：表更小，也无需比较最少音节数，但会维护第二套字节边界和音节合法性规则；共享已有表可以直接保留切分与完整性检查的一致性。
- **长期缓存最近一次完整性结果**：重复输入能避免 DP，但需增加输入、方案与生命周期失效状态；本次仅去掉不会被调用方使用的结果分配。

## Verification

两项分配预算在旧实现上按预期失败，优化后分段测试 20 项全部通过。音节表预热后的 `ni` 从 2 次分配降到 0 次，`nihao` 和 `linian` 从 3 次降到 0 次，`xi'an` 从 4 次降到 0 次；64 字节的重复 `ni` 从 33 次降到 0 次，66 字节输入从 35 次降到 1 次。64 个短撇号分段构成的 191 字节输入从 128 次降到 0 次，说明边界按单段计算；长不可切分和多字节输入仍只分配一张堆表。

回归覆盖空段、非法尾部、修正别名、最少切分才能识别的完整输入、64 字节边界和长输入回退。全部 421 个合法音节分别组合 11 类合成后缀，共 4,631 个输入，对照原有完整切分结果。公开最少切分的 `nihao` 仍保持 3 次结果分配。实际会话选词的两项精确预算随本次收益收紧：全拼从 31 次降到 23 次，双拼从 40 次降到 32 次，提交内容保持原有结果。

引擎全量串行单元测试 1423 项、golden 31 项、doc tests、零警告 Clippy、Rustfmt、笔记和差异检查通过。九键整次刷新分配比较在并行构建负载下出现一次波动，单独运行与完整串行运行均通过，原断言保持不变；该刷新包含按 20ms 重开数据库快照的计时路径。

`bash scripts/verify-local.sh --quick` 通过，覆盖仓库契约与笔记检查、workspace 编译、102 项本机可运行的 Windows 原生测试、Android target 与 Java、Linux 桌面检查和原生 73 项 CTest、五笔版安装及库依赖隔离、日文版登记、macOS 原生宿主与 Apple bridge 构建。Android 共享桌面库仍报告 11 条警告；macOS 共享桌面包未构建，Wasm 工具链、MinGW、HarmonyOS 真打包输入及设置页依赖缺失，相应阶段跳过。未进行设备或系统输入法框架验收。

## Consequences

常见短拼音最短切分不再为 DP 表申请堆内存，完整性检查也不再构造切分结果；长输入每段保留一次 DP 表分配。完整性检查仍执行原有最少音节 DP，复杂度和 64 字节栈边界不变；公开切分结果继续拥有字符串，没有新增公开接口、缓存状态或依赖。
