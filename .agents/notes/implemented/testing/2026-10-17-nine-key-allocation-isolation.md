# Agent Note: 九键精确分配对照隔离进程级缓存失效

Status: implemented

## Problem

九键完整刷新矩阵在并行全测中偶发出现分配预算失败，独立和串行运行通过。计数器虽使用线程局部状态，其他测试的 `close_cached_journals` 仍会推进进程级 `CACHE_GENERATION` 与 `STORE_GENERATION`；被测线程下一次查询须重开日志、重载个人模型，使旧新两臂不再处于相同缓存条件。

在热刷新两臂之间受控调用该生产失效入口，当前基线稳定失败为 `NineKey/ni/0/0/false: 144>136`，候选、快照和容量对照通过。这证明此机制足以使预算失败，不倒推声称捕获了前两次历史失败的精确时序。均匀进程暂停以及单侧查询暂停未复现预算失败；20 ms 事务续期不是本篇已证实的原因。

本轮读法筛选矩阵在依赖接入全测又以 `FourteenKey/ni'men'hao/1/1/true: 436>216` 失败（其余 2234 个引擎测试通过）；独立运行通过。该矩阵及它的热刷新精确预算仍在原测试进程，尚未使用既有隔离。对原矩阵热轮两臂之间受控调用 `close_cached_databases`，稳定触发 `NineKey/ni/0/0/false: 129>118`，候选和容量对照先通过。该证据证明相同机制足以破坏这组预算，也不声称捕获全测失败的精确时序。

## Decision

四个九键读法筛选与支配筛选预算测试各自在同一测试可执行文件的单目标子进程运行完整原测试体。隔离器在父级 `nine_key::isolated_test` 注册一次，四个入口共用它。保留原测试名、夹具、冷热两轮、全部状态与容量比较、精确少 1038 次、读法热刷新精确少 9 次及每格不增加分配的断言。父进程同时要求子进程成功和完整测试体返回后的目标完成标记，避免 `--exact` 错误地筛成零测试仍成功。递归标识仅通过子进程环境设置，测试专用辅助函数不进入生产 API。

## Alternatives considered

- **按 generation 快照重试整个形状。** 可继续留在测试进程，且仓库日志连接测试已有同代重试；但必须暴露测试观测入口、重建两臂以保留冷热形状，还要维护重试上限。本片使用进程隔离直接消除共享失效源。
- **给预算和全部关闭入口加全局读写锁。** 可以保留单进程并行；但所有失效调用都必须参与，测量体自身可能关闭缓存，扩大锁顺序和死锁审计范围。
- **冻结时钟。** 能排除事务续期的运行时长差异，但受控暂停未支持该假设，且无法阻止真实全局 generation 变化。

## Consequences

四个预算测试各启动一个测试子进程，增加相应启动成本。隔离只处理其他测试的进程级失效，不改变被测体内部的真实失效、定时事务、生产缓存关闭或文件访问规则，也不据此宣称历史偶发失败的全部原因已穷尽。
