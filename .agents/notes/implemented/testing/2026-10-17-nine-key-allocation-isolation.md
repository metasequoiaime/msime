# Agent Note: 九键精确分配对照隔离进程级缓存失效

Status: implemented

## Problem

九键完整刷新矩阵在并行全测中偶发出现分配预算失败，独立和串行运行通过。计数器虽使用线程局部状态，其他测试的 `close_cached_journals` 仍会推进进程级 `CACHE_GENERATION` 与 `STORE_GENERATION`；被测线程下一次查询须重开日志、重载个人模型，使旧新两臂不再处于相同缓存条件。

在热刷新两臂之间受控调用该生产失效入口，当前基线稳定失败为 `NineKey/ni/0/0/false: 144>136`，候选、快照和容量对照通过。这证明此机制足以使预算失败，不倒推声称捕获了前两次历史失败的精确时序。均匀进程暂停以及单侧查询暂停未复现预算失败；20 ms 事务续期不是本篇已证实的原因。

## Decision

两个九键支配筛选预算测试各自在同一测试可执行文件的单目标子进程运行完整原测试体。保留原测试名、夹具、冷热两轮、全部状态与容量比较、精确少 1038 次及每格不增加分配的断言。父进程同时要求子进程成功和完整测试体返回后的目标完成标记，避免 `--exact` 错误地筛成零测试仍成功。递归标识仅通过子进程环境设置，测试专用辅助函数不进入生产 API。

- [活动 n 元表](../../implemented/testing/2026-10-14-active-dictionary-ngram-tables.md)修复共享表淘汰导致生产重载，是另一种共享状态机制，不替代其活动句柄决定。其余日文隔离笔记针对查询与词典所有权，与本篇无关。无完全吸收或过时提案。

## Alternatives considered

- **按 generation 快照重试整个形状。** 可继续留在测试进程，且仓库日志连接测试已有同代重试；但必须暴露测试观测入口、重建两臂以保留冷热形状，还要维护重试上限。本片使用进程隔离直接消除共享失效源。
- **给预算和全部关闭入口加全局读写锁。** 可以保留单进程并行；但所有失效调用都必须参与，测量体自身可能关闭缓存，扩大锁顺序和死锁审计范围。
- **冻结时钟。** 能排除事务续期的运行时长差异，但受控暂停未支持该假设，且无法阻止真实全局 generation 变化。

## Verification

- 受控失效注入在隔离后的测试体内仍以 `144>136` 失败，父测试收到原断言，Cargo 退出 101；诊断注入逐字撤销。撤销注入后的聚焦测试为 6 通过、1 忽略，两个完整原测试通过。
- 零目标和子进程断言失败的永久控制测试均通过，只有成功退出且完整目标完成才算通过。
- `cargo test -p msime-engine --locked` 默认并行运行通过：引擎 2226、golden 31，失败 0、忽略 37；格式、笔记校验与 `git diff --check` 通过。独立只读实施审查未发现阻断或重要问题，确认原测试体逐字保留。全目标 Clippy `-D warnings` 与本地 quick 均退出 0。quick 覆盖仓库契约、Rust workspace、Android/WASM、Android Java、macOS 原生宿主及共享 Apple bridge；Windows 可移植测试 155 通过，2 项宿主差异排除、66 项需 Windows。Linux Docker、完整 Windows 交叉、HarmonyOS 真工程与 pipe-only 缺前置而跳过；这些结果不构成设备验收。

## Consequences

新增两个测试子进程及启动成本。隔离只处理其他测试的进程级失效，不改变被测体内部的真实失效、定时事务、生产缓存关闭或文件访问规则，也不据此宣称历史偶发失败的全部原因已穷尽。
