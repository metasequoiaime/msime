# Agent Note: 自动纠错习惯查询借用音节键

Status: implemented

## Problem

自动纠错规划为每个候选变体读取个人接受次数。个人资料把计数存成 `(String, String)` 的扁平键，`accepted` 为了查询每次都复制两个音节字符串；没有对应计数时也会发生分配。这条路径按输入位置和变体数量重复执行，放大了每次纠错查询的分配成本。

## Decision

把内存中的接受次数索引改成“输入音节到目标音节到次数”的嵌套 `HashMap`。加载和写入仍使用同一个 SQLite 表与相同的计数上限，查询先借用输入音节再借用目标音节，不创建临时字符串。公开的 `accepted` 结果、计数饱和和表裁剪行为保持不变。

## Alternatives considered

- 继续使用扁平 `(String, String)` 键：结构简单，但标准库 `HashMap` 无法用两个 `&str` 直接查询，热路径必然复制键。
- 每次查询线性扫描所有计数：可以避免临时键，但会把每个变体查询变成与个人资料大小相关的扫描，输入越长越慢。
- 拼接成单个字符串键：能减少一次复制，但仍需为组合键建立临时字符串；嵌套索引可以完全借用两个查询片段。

## Verification

新增分配计数测试，覆盖命中和未命中的 `accepted` 查询，确认两次查询共零次分配；个人资料现有的批量写入、计数饱和、表容量、外部写入刷新和旧日志兼容测试继续通过。实现后运行完整 `msime-engine` 测试、Clippy、格式与差异检查、笔记检查和 quick 门禁。

## Consequences

自动纠错规划读取个人习惯时不再为查询键分配字符串，命中和未命中都只做两级哈希查找。内存索引增加了一层外层哈希表和每个输入音节的内层表，加载时的结构开销略有增加；这是把成本从每次按键查询移到资料加载和写入路径的有界交换。
