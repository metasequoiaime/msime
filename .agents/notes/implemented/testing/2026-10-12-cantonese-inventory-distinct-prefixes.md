# Agent Note: 粤拼库存只复制新前缀

Status: implemented

## Problem

`Inventory::new` 在粤拼方案激活时遍历全部音节，把每个真前缀先复制成 `String` 再插入集合。多个音节共享前缀时，已登记的前缀仍反复申请、释放字符串，并重新执行更短前缀的查询。

## Decision

从最长真前缀倒序处理，先以借用切片检查集合，只为缺失前缀复制字符串。遇到已有前缀立即停止：库存中每个前缀的所有更短真前缀都已登记，这个不变量由完整处理此前音节保持。构造期间另用 256 字节的布尔数组记录已登记的单字节前缀，首字节未见时直接插入整条前缀链，避免无共享库存为每个新前缀多查一次哈希表。数组只在构造时位于栈上，不进入库存字段；只有长度大于一的音节登记其首字节。音节集合与最长音节长度的更新保留，空库存、空音节和音节同时作为更长音节前缀的情况不变。

现有粤拼笔记覆盖分段搜索、候选缓冲和提交路径；本决定仅涉及方案激活时的库存构建，无重叠的库存前缀决定需要取代。

## Alternatives considered

- 保持先复制再插入：每个前缀只查一次集合，但重复项仍产生堆分配。
- 从短前缀开始逐项检查：避免重复字符串，但完整遍历已有前缀链；倒序利用闭包不变量提前停止。
- 改成 trie 或借用集合：能共享字符或文本存储，但改变库存布局、拥有关系和查询方式；现有集合足以消除重复前缀分配。

## Verification

26 个合成音节共享三个前缀的构造分配测试在固定基线 `80e2c414736fabfcf517b652b8933461e8d7c066` 上因 84 次分配超出 10 次预算失败；最终实现为 8 次。用例覆盖空库存、空音节、重复音节、不同输入顺序、嵌套前缀、单字母音节先出现和分段行为。引擎全量 1,830 项与 golden 31 项通过，13 项计时用例按原设置忽略；Clippy、格式、笔记、差异和本地 quick 门禁通过。quick 在 Linux 固定容器内构建原生宿主并运行 81 项测试，构建 Linux 桌面外壳、Android Java 宿主、WASM 与共享 Apple bridge；macOS 在规定的 `target/macos-isolated` 中用 Release 配置构建全部目标，149 项 CTest 仍注册，本轮只编译而未在本机运行。Windows 原生交叉构建与 HarmonyOS 真打包因工具链或资源未就绪跳过，不作为设备验收。首次 quick 因系统盘空间耗尽中断，清理本片已完成阶段的产物后完整重跑通过。

## Consequences

共享前缀不再反复复制，已有前缀链只查到最长已知项。初版仅倒序查集合，在无共享的两字母音节用例中构造时间回退约 31%，因此增加首字节标记。最终配对计时取七轮各 20,000 次构造的中位数，两端构造器正文机械提取自固定基线与最终源文件，包含相同的音节字符串复制和销毁：共享用例 4,006→2,389 ns，无共享用例 3,605→3,422 ns，已有 22 音节库存切片 5,282→3,541 ns。主机同时有其它任务，数字仅描述本地微基准，不作为跨机器门禁，也不直接证明整体激活延迟或系统 RSS 改善。首字节数组增加 256 字节构造栈空间；共享首字节但未见的较长前缀仍有额外借用查询。短前缀闭包不变量依赖库存集合只由当前构造器建立；以后引入增量更新或单独删除前缀时必须重新审视提前停止。
