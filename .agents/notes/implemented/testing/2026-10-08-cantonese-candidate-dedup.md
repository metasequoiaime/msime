# Agent Note: 粤语候选去重的小列表路径

Status: implemented

## Problem

`CantoneseScheme::candidates` 会把每个 span 的候选合并后，用 `HashSet` 和重复索引 `Vec` 去重。单个词典查询限制为 200 条，常见短输入的合并列表只需要检查少量候选，却仍会产生临时堆分配。

## Decision

候选总数不超过 64 条时，按 `(text, syllables)` 对已保留行做线性扫描并原地压缩；更大的列表继续使用哈希表和重复索引回退，避免长输入退化为平方复杂度。首次出现顺序和同一文本跨 span 可重复选择的语义保持不变。

## Alternatives considered

所有候选都改成线性扫描会让多 span 长输入的去重复杂度平方增长；只减少哈希表容量仍保留短输入的临时分配。

## Verification

新增短候选零临时分配测试，并覆盖 64 条边界以上的哈希回退。合成基准比较 4、16、32、64、96、128、200、512、1024 条候选，分别测量全唯一和两次重复输入；64 条以内线性路径最快或相当，96 条及以上哈希路径明显更快。粤语 scheme 测试、完整引擎测试、Clippy、格式检查、笔记检查和 quick 门禁覆盖提交。

## Consequences

64 条以内的去重是平方级，但列表规模受控；更长列表继续使用哈希表路径。
