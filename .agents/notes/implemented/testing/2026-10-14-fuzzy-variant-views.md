# Agent Note: 模糊 beam 变体借用规划

Status: implemented

## Problem

模糊 beam 每个音节都先建立 `Vec<String>` 变体列表。已有末父路径转移消除了再次复制，却仍要为列表申请向量；截断只采用部分变体时，未采用的拥有字符串也白白分配。合法替代音节的 `intact_piece` 已返回静态引用，原音节可以借用调用方。

## Decision

按 `(INITIAL_PAIRS.len()+1)*(FINAL_PAIRS.len()+1)` 的规则组合上界，在栈上保存原音节与合法变体引用，保留原顺序、合法性和去重。beam 只为实际采用的分支 `to_owned`，父路径与单变体层容器仍复用；不再需要可变拥有变体及末父路径判断。最终路径与字典候选继续拥有字符串，原输入可释放。内部展开未从 crate 导出，不保留只供测试的拥有型包装。

## Existing decisions

检索模糊变体、路径、伙伴引用与 `fuzzy_syllables`。[伙伴栈缓冲](2026-10-09-fuzzy-partner-buffer.md)部分重叠，保留伙伴表、合法性与静态引用规则，改变最终规划的拥有时机。[父路径复用](2026-10-09-fuzzy-path-reuse.md)部分重叠，仍复用父路径/单变体层，只取代拥有变体的末父路径转移机制，互链保留原理由。输入音节借用、前缀拥有与缓存投影是独立存储层，保持其行为，冻结 beam 对照单独补偿本次节省。自动纠错变体规划是另一套候选来源，与本次模糊规则无关；没有完全吸收或过时提案。

必空 beam 的原路径存储由[延后拥有原切分](2026-10-14-fuzzy-beam-lazy-start.md)处理；本篇继续持有零分配变体规划。必空输出容量改为零，实际分叉仍保留原输出容量与成本；冻结存储节省在计量外补偿后续省去的必空路径。

## Alternatives considered

- 重用动态变体向量：复用后可少申请列表，但需跨音节保存容量，仍为最终未采用的变体拥有字符串；本入口已有静态引用及有限规则表，可直接规划引用。
- 在最后一个父路径转移字符串：此前能省末次复制，且简单；本次直接消除拥有列表，实际输出才复制，末次转移不再需要。
- 固定使用六个引用槽：当前音节最大变体数小且栈更小；不采用，因为容量应由规则表结构证明，不把当前音节库存的偶然最大值当契约。

## Verification

固定 `e9861e5ae4cf498d291bc25fd9128cb9fe158f20` 的完整拥有展开及 beam，只改名、转接冻结入口并移除注释。两项专项在旧生产上真实失败：`a/0` 规划实际2次分配，目标0次；空音节单步 beam 的精确节省断言左侧4、右侧3，即新计数3加目标节省1，与旧计数3相比，未达到省1次的目标。修复后两项通过，独立复核冻结正文与运行专项无阻断。

区间外显式预热不可变音节表。421完整音节加8个非法/空/Unicode/长输入 × 13规则共5577组，逐项对照冻结展开的顺序与内容，真实规划全部零分配。13组输入 × 3规则 × 10上限共390组，核对完整 beam 内容、向量和每个字符串容量，并比较拥有/借用输入成本。节省按冻结变体数独立推导：每轮省一个列表，末父路径采用数为 `(capacity-1)%variant_count+1`，尾部未采用的非空变体各省一次。明确覆盖部分父路径截断、40单变体音节、空段、Unicode、零上限和 `usize::MAX`。

既有输入音节借用测试保留完整冻结查询/beam，拥有展开依赖转接本篇固定的旧展开，正文保持不变；预算在计量外按旧路径数推进共享前缀预算，另补偿本篇 beam 存储节省。原先两个输入段副本的节省继续单独计入，整条外层命中及规则关闭仍为零。既有展开测试直接核对真实借用规划与零分配，没有测试专用的生产拥有包装。

已有绝对预算收紧：双音节 `zan/fa` 完整beam为32→30；单父路径limit1为8→4，limit4为11→10；截断双音节limit5为26→23；32个单变体音节为69→37。完整 `zong'guo` 行页热查询为31→28，恰好省处理的三轮变体列表。

完整 `cargo test -p msime-engine` 通过2031项单测（16项忽略）、31项 golden；`cargo clippy -p msime-engine --all-targets -- -D warnings` 通过。

## Consequences

引用数组上界必须跟规则表一致；只返回静态变体与输入借用，不借用六字节拼接缓冲。输出容量保持原 beam 策略，节省结论不扩展到 CPU、设备延迟或 RSS。

当前数组最多42个引用槽，增加固定、短期的栈空间，不进入缓存或持久状态；规则表改变时容量随之推导。沿用标准库[固定数组](https://doc.rust-lang.org/std/primitive.array.html)及既有静态音节查询，不增加依赖、unsafe 或 crate 对外接口。只主张已测的分配节省。
