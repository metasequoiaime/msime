# Agent Note: 双拼前缀候选去重的小列表路径

Status: implemented

## Problem

双拼前缀查询会先收集多个前缀组的候选，再用 `HashSet<&str>` 和重复索引列表去重。常见短前缀批次候选很少，却仍会为临时哈希状态和索引列表分配堆内存。

## Decision

候选总量（已有候选与所有前缀组候选之和）不超过 64 条时，按候选词面线性扫描并直接追加唯一项；超过边界时继续使用借用词键的 `HashSet` 和重复索引回退，避免较大批次退化为平方复杂度。首次出现顺序、组顺序和已有候选优先级保持不变。

## Alternatives considered

所有批次都改用线性扫描会让词典返回的大候选列表出现平方级比较；始终保留 `HashSet` 则无法消除短前缀查询的临时哈希分配。按 64 条边界分流覆盖常见短输入，同时保留大批次的近似常数时间查找。

## Verification

新增短批次零临时分配测试，并覆盖重复候选的首次保留顺序；双拼字典相关测试、完整引擎单元测试（1160 项）、Clippy、Rustfmt、差异检查、笔记检查和 quick 门禁覆盖实现。

## Consequences

64 条以内的前缀合并不再创建临时哈希集合或重复索引；更大的候选批次继续使用哈希去重，避免无界结果退化。
