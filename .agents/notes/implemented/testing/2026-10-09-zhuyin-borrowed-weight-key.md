# Agent Note: 注音单读音词频查询借用缓存键

Status: implemented

## Problem

注音九键刷新读音列表已经复用字符串并借用词条，但每条读音取词频前仍通过 `describe` 创建临时缓存键。三条热缓存读音的刷新仍有三次分配。

## Decision

增加只读取词频的内部查询入口。仅当查询包含一个位置且该位置只有一个读音时，直接用现有读音借用查找缓存；命中和已缓存缺失都直接返回。未命中、多读音和多位置查询仍复用 `cached_best` 的组合键、词库查询和错误处理。

## Alternatives considered

另建词频缓存会重复维护词条缓存的失效规则。为返回借用词条的入口增加预查询会额外查找缓存；词频是可复制整数，直接读取现有缓存即可避免热路径的字符串分配。

## Consequences

短读音列表的热缓存刷新从三次分配降至零次。排名缺失读音仍使用 `i64::MIN`，歧义权重下限缺失仍使用零；组合键和转换输出接口保持不变。首次查询仍可能分配，多读音及多位置查询不走单读音捷径。

## Verification

把原有读音刷新分配预算收紧到零后，旧实现因三次分配失败。新增回归测试验证首次词频查询、零分配缓存命中与已缓存缺失，以及多读音和多位置查询错误不会误用单读音缓存。注音单测、引擎全量单测、golden、Clippy、Rustfmt、笔记校验、差异检查和 quick 门禁覆盖本切片。
