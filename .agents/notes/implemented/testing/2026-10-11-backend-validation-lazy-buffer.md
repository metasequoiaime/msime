# Agent Note: 后端批量词典校验延后输出缓冲

Status: implemented

## Problem

`validate_dictionary_batch` 在检查第一条词条前就按输入批次长度为输出 `Vec<Value>` 预留容量。批次的第一条词条无效时，函数立即返回错误，剩余输出槽位完全不会使用；50 条合成批次的峰值堆用量为 2345 字节，单条同样无效请求为 777 字节。

## Decision

从空 `Vec` 开始，只有一条词条完整通过 `validate_dictionary` 后才按原批次长度 `reserve_exact`，然后追加已验证值。错误语义、首条失败规则和有效批次的一次性容量预留保持不变。

## Alternatives considered

- **继续在循环前预留**：有效批次路径简单，但首条失败时保留整批未使用的结果槽位。
- **每条结果自然增长**：空错误路径不分配，但有效批次会失去一次性预留并可能多次扩容。
- **先验证再单独计算容量**：需要重复遍历或额外暂存验证结果，增加实现和堆工作；首条成功时已足以安全建立原有容量提示。

## Verification

新增 50 条合成批次、首条无效的峰值堆用量回归；基线 2345 字节对比单条 777 字节先失败，修复后峰值相等。相关后端测试、引擎全量测试、Golden、Clippy、Rustfmt、差异检查、笔记校验和 quick 门禁覆盖提交。

## Consequences

无效批次不会为未生成的输出条目申请容量；有效批次在第一条成功结果后仍一次准备输入上限，保持原有热路径扩容行为。错误返回路径只改变未使用的结果缓冲，不改变协议响应。
