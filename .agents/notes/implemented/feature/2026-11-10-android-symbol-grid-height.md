# Agent Note: Android 符号网格按可见高度分配行高

Status: implemented

## Problem

Android 符号面板固定使用 40 dp 的网格格高。顶部返回栏和底部分类栏占去面板高度后，键盘高度较小时只能看到不到三行，用户必须滚动才能看到同一组符号的后续行。

## Decision

符号网格根据 `ScrollView` 的实际可见高度计算能容纳的整数行数。以 40 dp 格高和现有 3 dp 上下间距为最小行尺寸，能放下多行时把剩余高度均分给这些行；可见区域连一行最小尺寸也放不下时仍使用 40 dp，让 `ScrollView` 继续提供滚动。每次面板测量高度变化都更新已有网格格子的布局参数，因此折叠屏内外屏或键盘高度变化不需要重建分类和异步目录状态。

只调整网格行高，不移除顶部返回栏，也不改变底部分类栏和偏旁连续滚动的结构。偏旁页保留原有固定格高，避免每个笔画分组因可见高度被拉伸而改变连续定位。

## Alternatives considered

- **移除顶部返回栏，把返回并入底部分类栏**：能释放更多高度，但会改变近期的面板结构和装饰，需要独立的产品决定；本 issue 的明确收益可以由行高分配取得，因此不在本次范围内。
- **始终把每个格子拉伸到整个可见区域**：会让短分类或目录分页的行高随内容数量变化，长目录滚动时视觉不稳定；本次只按当前可见区域能容纳的整数行数均分。

## Consequences

符号页在常见键盘高度下会显示更多完整行，仍保留最小 40 dp 触控目标和矮键盘下的滚动能力。高度重新测量时会修改现有格子的布局参数，增加一次轻量布局工作；偏旁页和标题、提示行的尺寸与定位保持不变。JVM 冒烟覆盖行数与最小格高计算，设备冒烟在不同面板高度下检查真实网格格子尺寸。面板高度与 40 dp 最小格高都按设备密度换算为像素后再比较；Pixel 3 XL 的 560 dpi 对应最小 140 像素，旧测试把它与 40 像素比较会误报。修正只统一测试单位，不改变最小触控目标、产品布局或输入前提。
