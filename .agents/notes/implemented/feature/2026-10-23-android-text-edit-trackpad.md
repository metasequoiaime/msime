# Agent Note: Android 文本编辑触控板与光标文字放大镜

Status: implemented

## Problem

#9260 要求在远程终端、脚本和普通编辑器中，通过键盘上的触控板上下左右移动光标，并把现有编辑操作放在同一面板，拖动时显示光标附近文字的放大镜。报告者提供的设置截图还包含水平和垂直灵敏度、按住工具临时打开、双击选词和三击选行、逐步震动、轨迹及放大镜开关。只给现有方向键添加滑动事件不能覆盖这份需求。

现有 `ImeTextEditPanel` 已拥有方向键、选择模式、首尾跳转、删除，以及右列可滚动的全选、复制、剪切、粘贴、数字键盘、空格和换行七项操作。它通过 `InputConnection` 向真正的编辑器发送 DPAD 和修饰键，不能把本地重画的一份文档当作实际编辑器。

## 历史检索

已检索活跃笔记和 Android 源码中的 `9260`、触控板、放大镜、`trackpad`、`Magnifier`：没有同一功能的实现。既有[文本编辑面板](../../implemented/feature/2026-10-08-android-text-edit-panel.md)持有编辑动作与选区修饰键的规则，本实现沿用其编辑通道增加交互入口，不替换复制、剪切或密码框的限制。GitHub 当前没有对应 #9260 的实现 PR，issue 已分配给 `houko`；独立分支为 `feat/issue-9260-text-trackpad`。

## Decision

- 在现有文本编辑面板增加方向键和触控板的显式切换。触控区域与原有编辑动作共存，保留上述七项右列操作、选择模式、首尾跳转和删除；新装仍从原方向键面板进入，用户主动切换后记住选择。工具栏和功能面板复用现有文本编辑入口，按住临时打开的行为由独立开关控制，松手恢复之前的面板状态。
- 单指拖动按相对距离移动，横向按字符、纵向按编辑器排版的行；小于一步的余量在同一手势内累计，反向先抵消余量，结束后清零。默认水平 12 dp、垂直 28 dp，可分别设置为 4–48 dp 和 8–96 dp。继续复用现有 DPAD、Shift 的按下和松开路径，避免在宿主侧猜测换行位置或破坏远程终端的按键协议。
- 选择模式与面板共用一个状态。长按后拖动临时延伸选区，松手只解除临时模式、保留编辑器选区；双击选词、三击选行由独立开关控制。文字边界使用平台分词能力，并核对输入连接、返回片段的偏移和最新选区；编辑器不提供足够上下文时给出明确反馈，不把一个局部片段误当成全文。
- 震动、轨迹和放大镜分别可关。震动遵守系统与现有键盘反馈设置；轨迹只在活动触摸期间保留。双击选择、震动、轨迹和放大镜的功能开关默认开启，但只有用户打开触控板后才参与交互。水平、垂直灵敏度的默认值和合法范围由共享 Rust `client-core` 定义，原生 Java 页面只负责呈现与持久化桥接；设置不加入账号同步白名单。
- 放大镜使用编辑器经 `InputConnection` 返回的有限光标上下文重画文字、选区和插入点，不截取其他应用的屏幕。优先跟随 `CursorAnchorInfo` 的插入点，经矩阵换成屏幕坐标；没有位置、位置不可见或被键盘遮挡时放在键盘上方。密码输入框直接绘制掩码，不读取明文；长选区不整段跨 Binder 读取。上下文读取放在单一后台队列，连续移动合并请求，并用输入连接身份和代次丢弃迟到结果。
- 宿主已有物理键盘候选栏的光标位置订阅。触控板放大镜复用 `synchronizeCursorUpdates` 的统一订阅入口，将两个消费者的需求合并；某一方结束不能发出取消订阅而破坏另一方。`onUpdateCursorAnchorInfo` 先分发给当前有效消费者，再执行其各自判断，不让物理键盘专属条件挡住软件键盘放大镜。
- 放大镜先结合屏幕可见区域与窗口 Insets 选择位置，避开系统栏和刘海，再转为 `PopupWindow` 所需的父窗口坐标。沿用现有剪贴板预览的 `getLocationOnScreen` / `getLocationInWindow` 转换，兼容 API 28，不依赖 API 29 才公开的绝对坐标开关。停靠的输入法窗口局部 Insets 可以完全不含顶部系统栏；不能只看它来裁定屏幕安全顶边。
- API 28 的子窗口画面仍会被停靠输入法父窗口裁剪，`setClippingEnabled(false)` 不能跨出父窗口。放大镜在旧系统活动时复用剪贴板全文预览的透明父窗口扩展，键区保留原高度、应用仍只为键区让位。两种预览分别持有扩展状态，合并后才决定父窗口大小；一方结束不能撤回另一方的窗口。预览等父窗口完成布局后再计算坐标，隐藏时取消尚未执行的显示。
- 切换输入框、输入连接重建、隐藏键盘、关闭面板、失去窗口和多指状态转换均取消旧手势、停止重复动作并清除预览。轨迹和上下文不写日志、偏好或测试快照，测试只使用合成文档。

## Alternatives considered

- 单独新增一个没有编辑按钮的大面积触控板：移动区域更大，也容易复用上游的默认布局；但报告者明确要求把七项编辑操作一起保留，因此选择在现有面板中切换主要移动区，保留操作列。
- 只发送四方向按键，暂不提供放大镜和选区：可以最早覆盖远程终端的基础移动，也不需要读取上下文；但它遗漏显式需求，不能作为本 issue 的完整交付。
- 直接使用 Android `Magnifier` 放大宿主输入框：能复现原字体和真实像素；但该 API 需要调用进程持有附着窗口的源 `View`，输入法没有其他应用编辑器的 `View`，因此使用编辑器返回的文本绘制独立预览，不新增截图或无障碍服务权限。
- 为所有移动直接计算 `setSelection`：横向位置容易测试，也不依赖编辑器处理 DPAD；但视觉行由编辑器排版决定，且远程终端可能只接收按键。继续使用既有按键通道，只有明确需要的选词或选行操作在片段与绝对偏移均可靠时设置选区。

## Testing

- 共享偏好两项测试通过，覆盖旧文档默认值、选项往返、非法范围及真正的 `restore_defaults`；同步排除测试与 FFI 默认值/范围测试分别通过。三个相关 Rust crate 的全目标 clippy（`-D warnings`）和格式检查通过。
- JVM 回归覆盖二维余量、反向抵消、多指取消、短按与长按、双击与三击、文字边界和异步回读合并。密码与有界读取、临时入口、末词末行回归均先失败再修正通过；Android host 共 262 项 JVM 冒烟通过，生产和设备 Java 以 `-Xlint:all -Werror` 编译通过。
- 原生 APK 已用 JDK 21 构建并签名；ELF ABI、16 KB LOAD 对齐、依赖和 JNI 导出检查通过，APK 为 131,309,954 字节，低于 135 MB 门槛。完整 quick 门禁通过，包含 Linux 宿主 111 项测试、macOS 原生编译及共享 Apple 桥构建。屏幕可见区域补强、API 28 父窗口扩展、排版等待及设备夹具最终版本再次通过完整 quick 门禁，包含上述 Linux、macOS 和 Apple 桥阶段。
- API 35 已通过安装产品后的完整触控板专项：独立 EditText 与 WebView 的横纵移动和反向、Shift 与长按选区、多指取消、双击选词、三击选行、末词末行、七项快捷操作、模式服务重启持久化、按住工具恢复原面板、密码读取计数不增加、原生六开关与两滑块的边界/默认值/持久化，以及独立按键接收宿主的准确 DPAD/Shift 事件。后者是无网络的按键协议验收，不代表已验收真实远程终端客户端。
- 真实截图暴露的两项位置问题均有失败证据：原先放大镜画在键盘内部，键盘上方仅变化 96 个光标像素；坐标转换后该回归及完整 API 35 专项通过。随后状态栏回归测得 3,122 个状态栏像素被覆盖，已加入系统栏与刘海边界，最新 API 35 的普通与密码框位置、状态栏截图回归通过。密码框曾复现局部 Insets 安全顶边仅 11 px、屏幕可见区域顶边为 128 px，导致 4,618 个状态栏像素被覆盖；结合可见区域后该回归通过，掩码截图读取计数为零。截图等待实际像素变化，避免把长按公告早于异步回读/绘制完成的时序误判为没有放大镜。
- API 35 最终扩展专项完整通过：引擎初始化前的密码框预览、真正拒绝位置更新后的键盘上方回退、6,500 字符长选区的有界预览、密码掩码和零读取，以及真实 `uinput` 键盘接入时打开与关闭放大镜均不破坏原订阅。已保存并查看各场景的合成截图。API 28 首轮在密码框稳定复现父窗口外零像素显示，补齐旧系统窗口扩展后完整触控板专项通过；已查看首个密码框预览截图，掩码位于键盘上方、读取计数为零，键区和编辑器位置正常。API 28 现有 `ClipboardSegmentDragDeviceSmoke` 完整专项也通过，覆盖全文预览及窗口恢复、固定卡片、列表滚动、跨行拖选与预览操作。测试编辑器同时覆盖 API 21 的单参数和 API 33 的双参数 `requestCursorUpdates`，否则新版框架会绕过拒绝位置或订阅计数的夹具。API 28 父窗口扩展与排版等待修复后的最新 APK 和测试包再次通过 API 35 完整触控板专项，包括上述各场景和真实物理订阅共存。旧版普通设备专项没有可接入的 `uinput` 能力，物理订阅共存的设备证据限定为 API 35，不宣称跨版本覆盖。

设备专项的普通拖动连续异步注入，再由实际编辑器选区断言收尾。同步等待每个 `MotionEvent` 在模拟器繁忙时会将相邻 MOVE 拉开数秒，已实际捕获普通横拖触发「拖动延伸选区」公告的失败证据；这改变了被测手势本身，不能通过调长产品长按阈值或重复运行掩盖。显式长按仍等待产品公告和实际预览像素，双击、三击用固定事件时间表达快速连点；设备失败记录测到两次松手相隔 427 ms，超出双击阈值，不能让 Binder 注入耗时改变被测手势。临时生命周期日志确认面板直到测试清理触发 `onFinishInputView` 才关闭，诊断代码已全部撤去。

专用 API 35 模拟器曾出现渲染线程阻塞导致的 ANR，主线程在 `HardwareRenderer.setStopped` 等待，渲染线程停在 GPU 或 Surface 提交。改用 host GPU 后取得上述完整运行。最新专用设备改为实际 540×1200、210 dpi、2 核、30 Hz，降低渲染负担。另一次合成编辑器启动 ANR 的主线程停在系统 VSync 查询，尚未进入触控板；该失败证据与手势注入失败分别保存；只调整本任务的模拟器，没有停止其他会话的设备或构建。

## Consequences

[固定网格与七键排序](2026-10-24-android-text-edit-layout.md)接管后续布局：触控板嵌入中央移动区，两侧与底部编辑动作保持同屏；本篇的手势、模式持久化及取消生命周期继续适用。

完整方案保留输入法现有编辑通道，让不支持文本回读的编辑器仍可接受方向移动；放大镜和基于文本的选择能力则明确受编辑器公开接口约束。代价是增加面板模式、触摸状态、原生设置以及一个有界异步上下文读取生命周期，需要同时验收软件键盘与物理键盘候选栏。

本方案不引入第三方依赖，不复制上游源码；若后续确需引入依赖或代码，另按许可证、来源固定提交和仓库依赖规则处理。

## 验证缺口

真机手感和真实远程终端客户端尚未验收。`InputConnection` 的回读可能阻塞或返回过期片段，异步队列、连接身份及代次核对是当前实现的不变量；光标订阅需要与现有候选栏共用所有权，不能独立取消别人的订阅。
