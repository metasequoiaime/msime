# Agent Note: 鸿蒙手机读音行进入拼写编辑

Status: implemented

## Problem

HarmonyOS 手机键盘把拼写写进输入框时，候选栏读音行只显示占位，不接收触摸。用户只能退格重打，无法像 Android 一样直接点读音修改刚输入的拼写。

## Decision

菜单入口部分由[真机复审后的三项编辑菜单](../bug-fix/2026-11-06-harmony-reading-menu-actions.md)取代；以下保留原先只展开显示的选择与理由，弱化提示和平台边界仍然适用。

手机候选栏的读音行在组字仍存在、拼写确实写入输入框、且方案允许移动组字光标时接收点击。拼写写在输入框里时读音行原本不画拼写（`InlinePreeditPolicy.hidesStripReading`），一行空白看不出能点，所以可点开时这一行用半透明的次要色画出拼写作为提示，接在短语已选定部分的后面。点击后只切换候选栏的显示状态，把已有的引擎拼写和光标照常画出来；后续编辑仍由现有 `KeyboardSession` 命令和引擎处理。组字结束、输入框不再接受行内组字或换成锁定光标的方案时自动收起这个显示状态。

判定（能否点开、画什么、提示文字、何时收起）放在 `keyboard/candidate/ReadingRowEditPolicy.ts`，由 `platforms/harmony/tests/reading-row-edit.test.ts` 覆盖；`KeyboardView.ets` 只保留接线，遵守 AGENTS.md 不往巨型文件里加功能的规则。

桌面候选窗继续使用原来的预编辑显示规则。韩语、注音、越南语和藏文等锁定组字光标的方案不接触摸，候选条里的拼音选择项仍由自己的点击处理。

## Alternatives considered

- **为鸿蒙另做一套编辑弹窗或菜单**：可以完全复刻移动端某一平台的界面，但需要新增 ArkUI 浮层、焦点和关闭生命周期，且会重复现有引擎光标编辑能力；本次只需要补上入口，因此不采用。
- **可点开时让读音行空着占位、不画任何东西**：这是最初的做法。没有 canvas 的皮肤上这一行本来就占位，空白看不出能点；有 canvas 的皮肤上空着的读音行原本不占位（`Visibility.None`），为了一个看不见的触摸目标让它占位，等于每次行内组字都凭空多出一条空白行、挤压 canvas 内容，因此改为画出弱化的拼写，读音行只在有东西显示时占位，与 `stripCanvasContentHeight` 的原有约定一致。
- **让整条候选栏都响应点击**：触摸范围更大，但会吞掉候选、拼音选择和其他控件的点击；不符合“不能吞掉候选栏其他控件”的边界，因此只把点击接在读音行自身。

## Consequences

可编辑的手机行内组字期间，读音行画出半透明的拼写提示；有 canvas 的皮肤上读音行因此在这期间占位，和拼写写不进输入框时一样。点按后可看到光标并继续使用现有退格、左右移动和输入键修改拼写；候选选择和锁定光标方案行为不变。2in1 候选窗口仍按「候选窗口预编辑」画组字。该改动没有改变偏好、引擎协议或落盘格式。

验证方面，`bash platforms/harmony/tests/run.sh` 通过（含新增的 `reading-row-edit.test.ts`），`git diff --check` 通过。完整 ArkTS 编译、携带原生库和词库的 HAP、设备上的触摸验收和改前改后对比图仍需在具备设备的环境中完成。
