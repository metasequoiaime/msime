# Agent Note: 鸿蒙手机读音行进入拼写编辑

Status: implemented

## Problem

HarmonyOS 手机键盘把拼写写进输入框时，候选栏读音行只显示占位，不接收触摸。用户只能退格重打，无法像 Android 一样直接点读音修改刚输入的拼写。

## Decision

手机候选栏的读音行在组字仍存在、拼写确实写入输入框、且方案允许移动组字光标时接收点击。点击后只切换候选栏的显示状态，把已有的引擎拼写和光标画出来；后续编辑仍由现有 `KeyboardSession` 命令和引擎处理。组字结束或输入框不再接受行内组字时自动收起这个显示状态。

桌面候选窗继续使用原来的预编辑显示规则。韩语、注音、越南语和藏文等锁定组字光标的方案不接触摸，候选条里的拼音选择项仍由自己的点击处理。

## Alternatives considered

- **为鸿蒙另做一套编辑弹窗或菜单**：可以完全复刻移动端某一平台的界面，但需要新增 ArkUI 浮层、焦点和关闭生命周期，且会重复现有引擎光标编辑能力；本次只需要补上入口，因此不采用。
- **让整条候选栏都响应点击**：触摸范围更大，但会吞掉候选、拼音选择和其他控件的点击；不符合“不能吞掉候选栏其他控件”的边界，因此只把点击接在读音行自身。

## Consequences

读音行现在在可编辑手机组字期间保持可见，点按后可看到光标并继续使用现有退格、左右移动和输入键修改拼写；候选选择和锁定光标方案行为不变。该改动没有改变偏好、引擎协议或落盘格式。

验证方面，已运行 `git diff --check`。鸿蒙测试入口 `bash platforms/harmony/tests/run.sh` 因新 worktree 没有安装仓库根目录的 TypeScript 编译器而退出，完整 ArkTS 编译和设备验收仍需在具备依赖与设备的环境中完成。
