# Agent Note: Android 剪贴板卡片滚动与全文浮动预览

Status: implemented

## Problem

#8657：剪贴板卡片把长文本截成三行，相似记录只能插入编辑器后再辨认。卡片同时支持点按插入、长按管理和左滑删除，内部纵向预览必须与这些手势及外层列表滚动协调。

#9029：三行卡片适合辨认记录，阅读长文仍然局促。长按需要提供延伸至键盘上方的全文浮层、纵向滚动条和独立关闭按钮，同时保留下方原有操作行。

#9343：阅读全文后还要关闭浮层才能插入或编辑，阅读与后续动作脱节。浮层需要直接交付原有动作。

## Decision

卡片保留三行的高度上限，布局完整文本并在卡片内纵向滚动，不把完整文本展开成一个占满列表的条目。超出可见区域的卡片在按下时保留手势，超过系统移动阈值后按方向分流：横向仍交给既有左滑删除，纵向能继续滚动时取消按压并滚动正文；从边界向外拖动交还列表。一次纵向预览手势锁定到松手，防止途中变成粘贴或删除。短卡片继续由外层列表处理纵向移动。

完整文字和元信息使用既有文本及样式，点击仍插入原始记录。滚动不写历史、不改变置顶或时间戳。读屏提供向前、向后滚动动作。复用卡片工厂的本机与云端记录都可预览。

本机卡片的长按同时展开既有管理操作行和 `ClipboardTextPreview`。操作行重建会移除旧卡片，因此浮层使用稳定的 `keyboardRoot` 取得窗口令牌。正文使用原始全文，`ScrollView` 限制可见高度并常显纵向滚动条，底部独立操作行始终可见。本机记录提供「插入」「修改」「关闭」：前两项先撤销浮层、清正文并恢复临时窗口，再通过记录所属面板的回调复用原始全文插入和应用内编辑页；关闭只清理预览。只读调用不传动作，不显示本机管理按钮。浮层按屏幕可见区域限宽、限高，下沿停在键盘上方，给卡片和管理操作保留触摸空间。云端卡片没有本机管理长按入口，继续沿用卡片内预览。

预览期间复用宿主已有的全屏透明输入法窗口机制，将窗口、系统 `inputArea` 与根视图临时铺满；停靠键区保留打开前的像素高度和底部位置，内容、可见区域的 insets 仍只让应用为这块键区让出空间，根窗口触摸区域也只包含键区。这样 API 28 的子窗口画面裁剪边界包含了上方空间。布局完成后才用稳定根视图创建非焦点 `PopupWindow`，正文窗口独立处理触摸，外点关闭并让该次触摸继续到达原应用或操作行。不申请系统悬浮窗权限，也不改变浮动键盘或跟随光标候选栏的设置。

渲染新的历史列表、关闭面板、收起键盘、切换编辑器、重建或移除键盘视图时撤销浮层和待布局回调，清掉正文，恢复原来的窗口尺寸及键区布局，避免窗口或旧文本跨输入框存活。

检索审计：[左滑删除](../../implemented/feature/2026-10-09-android-clipboard-swipe-delete.md)与本篇部分重叠，横滑阈值、两步删除和独立动画器的决定继续成立；[分词拖选](../../implemented/feature/2026-10-08-android-clipboard-segmentation.md)仅作用于分词页，不改变；[历史分页](../../implemented/feature/2026-10-19-clipboard-history-pagination.md)控制列表加载，不改变。

#9343 的操作直接复用原插入和编辑路径，不在预览内添加输入框或复制剪贴板文本；编辑仍通过安装级条目令牌打开原生应用页面，保留返回原编辑器的行为。回调捕获原记录，不读取经过省略或滚动后的视图文字。

## Alternatives considered

- **点击打开全文对话框**：滚动容器现成，也不会争抢列表手势；但原点击直接粘贴需要改成二次操作，且不符合在卡片内浏览的需求。
- **把所有长条目展开到完整高度**：列表只保留一种滚动，手势最简单；但一条长记录就会挤走其他记录，失去比较相似条目的便利。
- **长按打开可取焦点的全文对话框**：系统负责滚动和返回键，窗口管理较简单；但剪贴板菜单已经在 Via 等 WebView 宿主上因抢走编辑器焦点而收起键盘，全文预览不能重新引入这个问题。
- **保持父窗口大小，仅使用非焦点 `PopupWindow` 或普通子窗口**：改动局部，前者自带外点关闭和生命周期，后者可在旧系统公开声明屏幕布局；但 API 28 上两者仍继承父输入法窗口的画面裁剪，无障碍边界与触摸都正确，键区上方却没有画面。设备截图和像素对比揭示了这个差异，需要先给父窗口提供足够的绘制空间。
- **使用独立的 `TYPE_INPUT_METHOD_DIALOG` 窗口**：不依附键区子窗口的边界；但系统限制普通输入法创建这种窗口，Android 9 的窗口权限检查要求内部系统权限，不能作为产品的通用入口。

## Consequences

长文本在固定卡片内可浏览，不会写入编辑器或修改历史；短文本仍保持点击插入，长按和左滑删除继续由既有路径处理。内部与外层滚动按手势开始时的可滚方向划分，滚到边界后需要抬手再拖动列表。

全文阅读获得更大的空间和持续可见的操作入口；本机插入和修改与关闭共用固定高度操作行，正文仍可独立滚动。动作以原记录回调交付，不在浮层复制存储或编辑逻辑。代价是宿主需要维护临时全屏窗口、键区固定高度、insets 与浮层的共同生命周期。可用上方空间不足 96dp 时只展开原操作行，避免横屏或极小分屏中画出没有正文空间的浮层；需要在这些窗口形态下阅读时仍可使用卡片内滚动。浮层的外点关闭会把应用区还给原应用，预览不拦截用户原有操作。

## Verification

`ClipboardSegmentDragDeviceSmoke` 在 API 28、35 的原生宿主上使用 80 行合成记录通过验收：真实长按、键区上方的实际像素变化、编辑器与卡片边界不移动、正文无截断、触摸与无障碍滚动到末尾、关闭不改编辑器或历史、外点一次触发管理操作，以及收起键盘和切换密码框时清理浮层；随后继续通过卡片内部滚动、左滑删除、管理长按和分词拖选。仅改子窗口时，新增的像素回归在 API 28 失败；扩大透明父窗口后通过，设备截图也能看到预览与滚动条。

`platforms/android/check-host.sh` 覆盖宿主契约、250 项 JVM 冒烟及 196 个设备测试源编译；原生 APK 与 `scripts/verify-local.sh --quick` 的运行结果随 PR 记录。`ClipboardEditDeviceSmoke` 的清理先停掉被测键盘再恢复系统剪贴板，避免恢复动作被历史监听误录、干扰后续元信息核验。未以模拟器结果代替真机验收。


#9343：旧 APK 在 `ClipboardSegmentDragDeviceSmoke -e preview-actions-only true` 查找新增插入动作时确定失败。修复后 API 28/35 的专项及默认完整套件均通过，覆盖 80 行合成原文完整插入、修改进入原生编辑页、保存后返回空白原输入框、再次插入修改结果，以及固定时间戳和置顶状态不丢失；同时回归全文浮层实际像素、滚动、关闭、外点操作、窗口清理、卡片内滚动、左滑和分词拖选。两平台截图均核对底部三按钮可见。

多行插入专项用 `msime_test_multiline` 显式启用既有多行编辑器；普通单行夹具会在无障碍显示中把换行转为空格，不能用它核对换行原文。256 项 JVM 冒烟、215 个设备源码、JNI/Java 契约、完整原生库和原生发布宿主 APK 构建、开发签名与 16 KiB 对齐通过；最终远端 `scripts/verify-local.sh --quick`（`20261023-053834`）、笔记与 diff 检查通过。
