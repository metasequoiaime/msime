# Agent Note: Android 剪贴板卡片内滚动预览

Status: implemented

## Problem

#8657：剪贴板卡片把长文本截成三行，相似记录只能插入编辑器后再辨认。卡片同时支持点按插入、长按管理和左滑删除，内部纵向预览必须与这些手势及外层列表滚动协调。

## Decision

卡片保留三行的高度上限，布局完整文本并在卡片内纵向滚动，不把完整文本展开成一个占满列表的条目。超出可见区域的卡片在按下时保留手势，超过系统移动阈值后按方向分流：横向仍交给既有左滑删除，纵向能继续滚动时取消按压并滚动正文；从边界向外拖动交还列表。一次纵向预览手势锁定到松手，防止途中变成粘贴或删除。短卡片继续由外层列表处理纵向移动。

完整文字和元信息使用既有文本及样式，点击仍插入原始记录。滚动不写历史、不改变置顶或时间戳。读屏提供向前、向后滚动动作。复用卡片工厂的本机与云端记录都可预览。

检索审计：[左滑删除](../../implemented/feature/2026-10-09-android-clipboard-swipe-delete.md)与本篇部分重叠，横滑阈值、两步删除和独立动画器的决定继续成立；[分词拖选](../../implemented/feature/2026-10-08-android-clipboard-segmentation.md)仅作用于分词页，不改变；[历史分页](../../implemented/feature/2026-10-19-clipboard-history-pagination.md)控制列表加载，不改变。

## Alternatives considered

- **点击打开全文对话框**：滚动容器现成，也不会争抢列表手势；但原点击直接粘贴需要改成二次操作，且不符合在卡片内浏览的需求。
- **把所有长条目展开到完整高度**：列表只保留一种滚动，手势最简单；但一条长记录就会挤走其他记录，失去比较相似条目的便利。

## Consequences

长文本在固定卡片内可浏览，不会写入编辑器或修改历史；短文本仍保持点击插入，长按和左滑删除继续由既有路径处理。内部与外层滚动按手势开始时的可滚方向划分，滚到边界后需要抬手再拖动列表。

## Verification
