# Agent Note: 安卓英文键盘 X/C 角标使用英文常用符号

Status: implemented

## Problem

安卓 26 键字母角标的 `X` 和 `C` 在英文键盘下仍显示省略号 `…` 和中文顿号 `、`。这两个字符属于中文标点习惯：英文输入需要更常用的下划线 `_` 和反引号 `` ` ``。同一张角标表也服务中文键盘，不能顺手改变中文模式的键面或实际提交字符。语言模式与中文标点开关独立，中文模式关闭中文标点时也必须保留原角标。

## Decision

`LetterHintTable` 的基础表保留 `x → …`、`c → 、`，按独立的英文模式参数将这两键替换为 `_` 和反引号。`face()` 在选取语言对应的角标之后才应用中文标点键面。键面、滑动预览、中文选项与最终 `commitLetterHint` 都使用宿主当前的 `dedicatedEnglish`；英文长按字符菜单明确读取英文角标。中文模式无论开关中文标点，都显示并实际提交原来的 `…` 和 `、`；其他模式也不扩大变更范围。下划线和反引号仍按字面上屏。

回归测试同时验证完整 26 键映射、X/C 大小写的双模式实际提交值、中文标点开关两种状态的键面、上滑和下滑输出、英文长按选项，以及标点路由边界。新增的中文实际提交断言在修复前失败：中文键面显示省略号和顿号，但无模式的全局表返回了英文符号。

## Alternatives considered

- **只改英文模式的视图层，不改角标表**：可以避免改共享表，但会让长按、滑动、无障碍描述和键面提示使用不同来源，容易再次漂移，因此没有采用。
- **把中文 X/C 也改成新的 ASCII 符号**：实现更简单，但会改变现有中文键盘的输入手感，超出 issue 的英文范围，因此没有采用。

## Consequences

英文键盘的 X/C 角标与建议的常用符号一致，中文键盘保持原有省略号和顿号的显示与实际输出。Android 主机检查新增的回归断言；没有改变符号层的独立按键布局。

验证：修改后的 `LetterHintTableSmoke` 先复现中文实际提交值回归；修复后 `bash platforms/android/check-host.sh` 通过 281 个 JVM 冒烟并编译 245 个设备套件源文件，三个相关套件也经 `javac --release 17 -Xlint:all -Werror` 独立编译运行通过。`scripts/verify-local.sh --quick` 的 Rust workspace、Android target 和 Java 阶段通过；公共 Windows runner 契约由 #9986 处理，Apple bridge 初始配置失败来自本次验证误传主工作区的 `MSIME_APPLE_BRIDGE_BUILD`，导致 CMake 源码根目录不匹配；已核对主缓存的两份翻译单元、依赖头和 CMake 配置与本分支逐字节相同，已有主缓存的定点构建退出 0。真实设备的 X/C 触摸验收尚未执行，JVM 结果不替代设备验收。
