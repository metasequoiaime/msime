# Agent Note: 提高移动端剪贴板单条字节上限

Status: implemented

## Problem

#11133 反馈 Android 复制 ADB 命令和 AI 结果时，超过 40,000 UTF-8 字节的单条文本无法保存到剪贴板历史。现行上限由共享 Rust 剪贴板存储执行，Android、iOS 和 HarmonyOS 使用同一份移动端校验；只改 Android 文案或宿主入口会让写入前后的边界不一致。

## Decision

把共享移动端单条文本的 UTF-8 字节上限从 40,000 提高到 100,000，字符数上限仍保持 10,000 个扩展字素簇，控制字符规则和条目数上限不变。同步更新 HarmonyOS 的策略镜像、Android 文档和共享存储的边界测试；共享历史文件的有界读取仍按单条上限的最坏 JSON 转义大小计算。

100,000 是可读、可解释的十进制上限，能容纳常见的长命令、日志和 AI 回复，同时保留对异常大文本的有界保护。只提高字节上限不会改变普通中文文本的 10,000 字符上限；复杂 emoji 和组合序列仍同时受字节和字素边界约束。

## Alternatives considered

- **只修改 Android 宿主**：共享 `push_mobile`、`replace` 和 host-api 的校验仍会拒绝新上限，无法真正保存，且会制造 Android 与其他移动端的契约分叉，因此不采用。
- **同时取消 10,000 字符上限**：会把这次针对字节上限的请求扩大成字符容量和存储占用的重新设计，超出 issue 已授权范围，因此保留字符上限。
- **把上限改成无界或直接放开文件读取**：会失去剪贴板历史对损坏文件、JSON 膨胀和内存分配的有界保护，因此不采用。

## Consequences

符合字符数规则的移动端剪贴板条目现在最多可保存 100,000 UTF-8 字节；既有 40,000 字节以内的条目行为不变。共享历史文件理论上限随单条上限提高，HarmonyOS 的文件读取上限同步提高到 640 MiB，仍由固定的有界读取保护；移动端三端的策略和持久化校验保持一致。

## Verification

- Rust 单测覆盖 100,000 字节边界和超出一个组合字素簇的拒绝路径。
- HarmonyOS 逻辑测试覆盖同一字节边界；Android host Java 与共享 Rust 的 quick 门禁覆盖共享常量消费者。
- Android API 28 设备验收需在本分支 APK 上补跑剪贴板保存和读取路径；本次改动没有界面布局变化。
