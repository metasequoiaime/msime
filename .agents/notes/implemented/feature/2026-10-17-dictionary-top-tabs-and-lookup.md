# Agent Note: 词库页顶部标签与词条查询

Status: implemented

## Problem

桌面词库页把本地查询、编辑、导入导出、云词库和学习数据连续堆在同一页，查询入口埋在长列表中。原查询接口只接受个人词库的五种类型，日语、粤语、注音、笔画和韩语汉字表不在下拉中；多数类型空查询也只列个人词条，不能浏览基础词库。

## Decision

桌面共享词库页使用三个窗口级顶部标签：「查找词库」「管理词库」和「云端词库」。「查找词库」标签进入时先显示当前类型的全部词条，输入词条文字或编码前缀后再按查询筛选，并支持分页；用户新增词条可编辑和删除，基础词条不显示写入操作；管理词库标签承载导入导出、社区词库、词库信息、背单词和学习数据；「云端词库」标签嵌入原有云词库面板，并在同一设置窗口内切换完整目录、候选排序、导入导出和应用到本机子页。查询框输入后经过 280ms 防抖实时筛选，不设搜索按钮；类型或条件变化后旧响应立即失效，结果在宿主筛选后分页。手机继续使用平台自己的词库列表与详情布局，不显示桌面标签。没有本地词库（`client.dictionary`）也没有页内云词库的桌面宿主只剩「管理词库」一项，这时同样不画标签栏，直接展示管理内容。

## 查询范围与契约

桌面宿主提供只读 `browse`，类型覆盖拼音、86/98 五笔、英文、快捷短语、日语、粤语、注音、笔画和韩语汉字表。个人编辑、导入导出与云同步仍只接受个人类型，语言资源不扩展个人日志协议。个人类型后来多了粤语（只在本机，云同步不收），`browse` 的 `cantonese` 仍指发布的粤语词库，查询下拉里资源词库的选项值带 `resource:` 前缀，与同名的个人粤语词库分开，见[粤语个人词条](2026-11-02-cantonese-personal-words.md)。旧宿主未提供 `browse` 时继续使用 `list`；`list` 的个人分页与导出语义保持兼容。

日语直接复用引擎校验过的 MSJPDT1 映射，在文件顺序中按假名读音前缀（兼容片假名）或词条文字筛选并分页；日语浏览在筛选与分页前排除词面只有空白、标点、符号或独立长音、迭代记号的模型行，含字母、数字、汉字或假名的正常词条保留，混合词内的符号也保留；此规则只影响词库浏览，不修改模型文件与输入转换候选。同读音同词条的不同词性模型行保留；页面按固定列显示读音与词条，不展示模型内部成本。粤语、注音、笔画复用引擎只读 SQLite 入口，韩语汉字表复用内嵌表，不复制词库到页面、不通过输入会话搜候选。缺失资源返回 `available: false`，页面提示去「输入」设置下载，区别于零匹配结果。越南语和藏语是规则转换，没有独立词库。

嵌入云词库的容器按设置内容区宽度布局，搜索与管理按钮分成两行，输入后经过 280ms 防抖。共享面板原有的 `100vw` 和视口最小高度只适用于独立窗口，嵌入时明确覆盖，不能用裁切掩盖溢出。设置窗口的云词库请求复用已有的[共享账号回退](../bug-fix/2026-10-18-macos-cloud-dictionary-account-fallback.md)，不依赖仅独立面板启动时提供的 socket 或原生会话。完整快照复用 host-api 的队列、维护锁和账号校验；macOS 设置页通过文件选择与宿主 `save_export` 导入导出，独立原生面板的文件对话框协议保持原样。加载失败与空词库分别显示，错误码转换成登录或网络说明，不展示 provider。

内嵌查询工具栏的输入框和下拉框保持 36px 等高，下拉框明确清零纵向内边距。面板通用样式的上下各 7px 内边距适用于自动高度控件，与固定高度叠加时，Linux WebKitGTK 会裁切所选词库名称的下半部分（#8646）；macOS WebKit 会忽略原生下拉的这组内边距，Chromium 也未呈现同样裁切，因此不能只在这两者上验收。这里沿用原生下拉的文字垂直对齐，不通过缩小字号或替换控件解决。

操作成功提示与错误只在查询条件变化或下一次操作开始时清理，不能由迟到的防抖查询启动时清理。首次查询延迟 280ms，用户可能在它执行前完成导出、清除学习数据或得到词条保存失败；这时自动查询仍更新列表，但保留已完成操作的结果提示。显式刷新和分页仍清理旧读取错误，保证读取恢复后不残留失败提示。清除学习数据成功时推进词条读取代次，并清掉清除期间已经发布的读取错误；宿主同步通知或防抖在清除期间发出的查询，不能在成功后重新显示旧词条、失败记录或读取错误。清除失败不作废当前查询，之后新发起的查询也照常生效。

查询入口同时校验发起它的查询上下文（类型和搜索条件）是否仍属于当前页面。保存、删除、导入、失败重试和移除失败记录的实际写入仍使用操作开始时的参数；回执迟到时改用当前类型、搜索条件和页码刷新，不能再用旧闭包发起刷新。仅过滤旧响应不够：旧回执新发起的请求会取得最新请求代次，反而使正确列表失效。查询条件不变时，操作完成后的正常分页刷新继续执行。当前页码记录该查询最近发出的请求，切换条件时重置为零；不能直接沿用尚未返回的新首页所保留的旧列表页码。

## 操作结果与标签

词库操作的结果按「用户在哪里看」放置。等待键盘同步数、快照错误和同步失败记录是词库本身的状态，由导入、保存等操作之后重新读取的列表带回；桌面把它们和导入、导出、保存、删除的结果（`phraseError`、`phraseNotice`）一起画在标签下、面板之上，在哪个标签上都看得到，失败记录的重试和移除按钮只有这一份。「清除全部学习数据」的按钮在「管理词库」页末，结果画在页顶时用户滚到页末点完什么也看不到，所以它的成功提示和错误单独存放（`learnedDataNotice`、`learnedDataError`），桌面画在「学习数据」组里、按钮下面。手机直列，所有提示仍画在本地词库管理组里，位置不变。

操作结果只属于产生它的标签：桌面切换标签（包括账号页把外壳切到「云端词库」、默认标签晚到时自动落到「查找词库」）时清掉 `phraseError`、`phraseNotice` 和学习数据的结果，例如「查找词库」里的读取失败不会留在「管理词库」的导入导出上面；等待同步数和失败记录是状态而不是某次操作的结果，切换标签时保留。新操作开始和查询条件变化时同样清掉两处结果，页面上只留最近一次操作的提示。已经发出、在切换标签之后才完成的导入或导出，结果画在用户当时所在的标签上。

`useSettingsTabs` 的非受控选择在用户点过标签之前记为空，始终跟随当前的第一个标签：宿主能力晚到、默认标签后出现时落到默认标签上，用户点过之后一直尊重这次选择。词库页的标签状态由外壳持有（默认 `lookup`），本地词库晚到时同样回到「查找词库」。

## Historical audit

[macOS 账号回退](../bug-fix/2026-10-18-macos-cloud-dictionary-account-fallback.md)保留账号与快照协议；其中设置页隐藏独立面板入口的规则由本篇的页内云词库标签接管，未提供页内客户端时仍隐藏 macOS 旧入口。现有的[输入、标点与翻译顶部功能标签](../../implemented/feature/2026-10-13-desktop-input-expression-voice-tabs.md)规定桌面共享设置页复用 `useSettingsTabs`，并保持手机直列；本改动沿用该边界。现有的[正常候选设置入口标签](../../implemented/bug-fix/2026-10-13-macos-primary-settings-tabs.md)只约束共享桌面页面的标签交互和挂载方式，与词库的数据请求契约无冲突。

## Alternatives considered

- **前端收到一页后过滤符号**：改动集中在列表组件，但前几页仍会被符号占满，页码和 `has_more` 也会误导用户。过滤放在引擎的只读浏览迭代器、`skip` 和 `take` 之前，让所有宿主共用正确的分页；输入转换读取模型的路径保持原样。

- **继续把查询留在单页顶部**：改动最小，但导入、云端和学习数据仍会把查询结果推到很下面，不能解决用户找不到查询入口的问题。
- **新建独立的词库路由**：可以完全隔离查询和管理，但会增加导航页、路由与手机投影的契约；现有的词库宿主接口和移动端布局也不需要第二个页面，因此不采用。

- **只让导出、清除和保存测试等待首次查询结束**：不改产品逻辑，测试更容易稳定。但真实用户也能在 280ms 防抖结束前完成操作，成功提示或保存错误仍会被自动清掉；改为在查询条件变化时清理提示，并保留迟到查询的列表刷新。只删除查询入口的错误清理也会让显式刷新成功后残留旧读取错误，因此仅自动查询保留已有错误。

- **把语言类型加进个人词库枚举**：能复用原有列表状态，但也会让不支持的编辑、导入与云同步类型进入个人协议。浏览类型单独建模，只在只读资源列表使用。


- **清除学习数据的结果继续和其他提示共用一处，画在页顶**：只需一份提示状态，#8579 先这样做，让结果至少不被藏进另一个标签。但「学习数据」组固定在「管理词库」页末，用户滚到底点完按钮，结果出现在视野之外；按值比对提示文字来判断来源又脆弱，因此由词库管理状态把这一项操作的结果单独存放。

- **切换标签时保留结果，按产生它的标签分别显示**：切回原标签还能看到旧结果，但每条提示都要记录来源标签，迟到的异步结果还要决定归属；用户已经离开那个标签，旧结果的价值很低，因此切换时直接清掉。

- **在 `useSettingsTabs` 里统一规定少于两个标签时不画标签栏**：能一并处理其他页面，但桌面皮肤页没有社区皮肤服务时也只剩一个「本地皮肤」标签，统一规则会同时改变那一页的界面和既有测试，超出本次修复的范围；词库页在调用处按标签数决定是否启用标签。

- **操作期间禁用类型和搜索框**：可以避免用户在写入期间切换条件，但把阅读和搜索也绑定到写入延迟；查询和操作还共用忙碌状态，单靠控件禁用不能保证所有异步入口。查询入口按上下文将旧刷新转到当前条件，保留用户切换查询的能力。

- **查询上下文变化后直接跳过操作回执的刷新**：能阻止旧条件覆盖列表，但新查询可能在写入提交前已经返回空结果；跳过刷新会让刚保存的匹配词或已移除的失败记录一直保留提交前状态。因此回执仍刷新列表，参数取当前查询及当前页码。

## Verification

清除学习数据的并发读取回归通过真实 `HOST_USER_WORDS_CHANGED_EVENT` 发起查询，用合成状态分别控制清除与读取的完成顺序。旧实现三项失败：迟到成功重新显示旧词条，迟到失败覆盖清除状态，先到的读取错误在清除成功后残留。回归还检查清除后的分页、等待同步数、失败记录、快照错误保持已清空，后续通知可以重新加载新词条；清除失败时当前查询仍然发布，清除失败提示保留。此次只改共享页面的回执归属，不修改存储清除或宿主通知协议。相关词库管理、标签反馈和代次套件共六文件 41 项通过，桌面与鸿蒙共享界面的类型检查、生产构建、改动文件 lint 与格式检查、笔记及差异校验通过；未以原生宿主窗口复现该慢回执时序。

可控回执回归先完成新类型或新搜索的防抖查询，再释放旧操作；保存、删除、导入、失败重试和移除失败记录均不能覆盖当前列表，随后新操作仍能正常刷新。六项回归在旧实现上均因旧词条覆盖新结果而失败。另两项回归覆盖写入提交前新搜索先返回空列表、旧查询在第二页而新搜索首页还在等待，确保回执刷新后能显示刚提交的匹配词，并保持新查询从第一页开始。

实时查询回归先等待宿主收到当前条件，再检查返回行，避免把初始列表里的同名词条误当成防抖查询的结果。管理页已提供独立的类型选择框，回归检查查询与管理标签之间的类型同步及实际导出请求，不依赖已经移除的旧说明文案。

Linux WebKitGTK 2.50.6、GTK 3 与 Noto CJK 字体下，合成页面挂载实际 `CloudDictionaryTab` 和设置页容器，修复前截图复现词库名称的下半部分裁切。仅在页面临时清零纵向内边距即恢复完整文字，固定高度和字号不变；正式样式下，拼音与快捷短语在 100% 缩放、98 五笔与快捷短语在 125% 缩放时均显示完整，控件仍为 36px、14px 字号。macOS Chromium 和 WebKit 的对应组件也保持完整显示。这是共享组件的真实 WebKitGTK 渲染验证，不等同于从 IBus/Fcitx5 系统入口启动设置页。

可控计时回归先完成导出、学习数据清除或被拒绝的词条保存，再推进首次查询的 280ms 防抖，确认成功提示与保存错误保留；继续改变查询条件时提示清空。三项在对应旧实现上均失败；另有回归确认首次读取失败后显式刷新成功会清除旧错误。新增设置回归覆盖顶部标签的初始选择、标签切换后的内容可见性，以及实时查询发送中文条件；云词库入口回归覆盖桌面账号页切换到词库页的云词库标签，移动端仍调用原生面板。资源浏览回归还覆盖纯符号过滤后的首末页、查询零匹配、长音与迭代记号混合词保留，以及符号仍能作为输入转换候选；新增过滤用例在旧实现上失败。资源浏览回归覆盖日语读音、片假名与文字检索、数据库文字与编码检索、字面通配符、分页、缺失资源和不写入原文件；界面回归覆盖完整下拉、默认列出、只读操作、防抖和旧响应失效。前端构建、类型检查和真实 macOS 设置窗口验收覆盖可见界面。


标签内结果回归在桌面宿主上先切到「管理词库」再导入、导出或清除学习数据，按用户可见的方式断言：清除学习数据的成功提示与错误在「学习数据」组内且全页只有一份；导入后带回的等待同步数、快照错误和失败记录在「管理词库」上可见，重试与移除按钮全页（含隐藏标签）只有一份；「查找词库」的读取错误切到「管理词库」后不再显示，导出提示切到「查找词库」再切回也不再出现；没有本地词库的宿主不画标签栏、云词库入口直接可见，本地词库晚到后落到「查找词库」；`useSettingsTabs` 的回归覆盖默认标签晚到时跟随、用户已选时保持。逐项还原产品改动时对应用例都会失败；只有「本地词库晚到后落到查找词库」在还原 `useSettingsTabs` 时仍通过，因为词库页的标签状态由外壳持有，它在还原单标签规则时失败。

## Consequences

桌面默认进入「查找词库」，个人类型查询结果会明确显示内置来源，资源词库统一提示只读，管理操作需要切换到「管理词库」，账号页的云词库入口切换到「云端词库」标签而不再另开设置窗口。词库操作的结果出现在用户操作的位置，切换标签即清掉；代价是切回原标签时看不到之前的结果，需要的话重新操作一次。标签选择是窗口状态，不写入用户偏好；云词库目录等子页仍保持在同一设置窗口内，避免跨窗口丢失登录会话和异步请求上下文。
