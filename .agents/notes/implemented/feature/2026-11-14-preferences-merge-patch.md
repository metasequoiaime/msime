# Agent Note: 偏好配置局部补丁事务

Status: implemented

## Problem

#10988 要求脚本能校验并写入局部偏好。现有 `PreferencesStore::save` 接受完整结构，调用方需要先读整份配置并补齐字段，容易把拼错的键静默留在文件中。偏好又允许较新版本的未知字段回写，不能为严格校验新补丁而破坏旧文档的兼容性。

## Decision

`PreferencesStore::apply_patch(expected_revision, patch)` 接受 JSON 对象，持有现有偏好锁完成读取、修订号比较、递归合并、反序列化校验与原子保存。对象递归合并，`null` 删除成员后按既有反序列化规则校验，数组整体替换；必填字段删除后仍无效，不能借补丁绕开原有约束。

补丁不能引入未知键，也不能改变或删除磁盘上已有的未知键。未涉及的未来数组元素继续保留；明确替换数组时丢弃旧数组的未来元素，同时拒绝补丁新带入的未知元素。只移除未来元素、已知偏好相同时仍写盘并增加修订号。普通空补丁和无变化补丁保持修订号及文件不变。并发使用同一修订号的两个补丁只有一个成功，另一个返回 `Conflict`。

实现与行为回归分别放在 `preferences/patch.rs`、`preferences/patch_tests.rs`，主文件只接入模块、错误类型及既有保存流程的强制写回标志。共享完整保存继续负责同意元数据、迁移标记、校验与落盘，不复制另一套保存规则。本切片只提供存储 API，CLI、Schema、MCP 与宿主接入不在其中，关联 issue 使用 `Refs`。

## Alternatives considered

- **继续由调用方生成完整偏好后调用 `save`**：可以直接复用现有事务，改动最少；但脚本仍需要知道全部字段，补丁拼写校验也会散落到调用方，不能提供同一把锁中的局部更新入口。
- **在读取全文件时拒绝未知字段**：所有拼写错误都能被发现，校验实现也简单；但较老客户端会拒绝较新客户端写下的正常配置，破坏既有向前兼容。严格性限定在本次补丁，未涉及的旧未知值原样保留。
- **把实现和测试继续追加到主文件**：与原 PR 相同，访问内部辅助函数方便；但偏好主文件已经很大。子模块同样能访问父模块的私有保存能力，独立文件能保持本切片集中。

## Consequences

局部更新遵守已有 CAS、锁和保存约束，不改变出厂默认值、存储格式或现有完整保存接口。补丁校验失败时不写文件，已有未知字段保持原值。代价是保存内部增加一个只用于未来数组元素删除的强制写回条件，且 Merge Patch 不能对数组按索引编辑。回归覆盖嵌套合并、数组替换、删除与非法值、未知键和未来元素保留、空补丁、冲突及并发竞争；本地门禁和设备结果记录在 PR 验证段，完成后再合并。

历史检索没有找到持有 `apply_patch` 或 JSON Merge Patch 契约的既有笔记；设置界面归属和各偏好类型拆分笔记讨论宿主与类型边界，本切片不改变其决定。
