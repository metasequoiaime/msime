# Agent Note: 搜狗细胞词库的词不能发布到社区

Status: implemented

## Problem

[导入搜狗细胞词库](2026-10-13-scel-import.md)让用户把自己下载的 `.scel` 转成本机词库。读格式本身站得住：最高法指导案例 48 号（(2006)沪高民三(知)终字第110号）认定，研发软件读取他人设定的特定文件格式不构成侵害计算机软件著作权；指导案例 263 号认定，经用户授权、为用户在合理范围内转移数据的，不构成不正当竞争。

风险在「向公众提供」。指导案例 262 号和大众点评诉百度案（(2016)沪73民终242号）都把未经许可获取他人的数据集合、再向公众提供并构成实质性替代的行为认定为不正当竞争；搜狗输入法用户服务协议第 7.1 条把「词库」写进搜狗的知识产权，第 7.3 条禁止未经授权「利用本服务……向第三方提供产品」；2025 年 12 月，一篇介绍深蓝词库转换的文章就因「包括词库在内的汇编作品」收到律师函（imewlconverter issue #364）。水杉里能把词「向公众提供」的出口只有一个：社区词库。共享设置页和 iOS 的发布编辑器逐条收词条，此前不看词从哪来，用户把导入的细胞词库照抄进社区词库，就是由水杉替第三方词库做了公开传播。

## Decision

社区词库发布前核对词条来源，来自细胞词库的词拦下并说明原因；导入细胞词库时就告诉用户这些词只供本机使用。

- client-services 的命名词库多一个只读动作 `third_party_matches`（`DictionaryCollectionsStore::third_party_matches`），收最多 128 个候选词（一份社区词库的上限），回答其中出现在来源为 `import{format:"scel"}` 的集合里的下标。比较的身份是：种类（五笔 86 与 98 不分）、去掉 `'`、`-` 和空白并转小写的编码、原样的词。用户换个拼音写法重敲一遍也认得出；自己整理的同字不同音的词不受影响。动作走现有的 `dictionary_collections` 请求，鸿蒙桥的操作白名单同步加上。
- 共享 UI 的 `CommunityLocalDictionaryClient.thirdPartyMatches` 在宿主有命名词库时由 `createCommunityLocalDictionary` 接上；设置入口只负责传入两种宿主客户端（社区的 `quick` 换成集合的 `quickPhrase`）。发布编辑器在「添加词条」和真正发布前各核对一次，后者覆盖更新旧作品时带进来的词条和添加之后才导入的细胞词库。发布前那次放在 `runAsyncAction` 里面，防重和忙碌状态不变。拦下时错误写明「“X”来自你导入的搜狗细胞词库，不能发布到社区：第三方词库的整理成果属于原作者，公开分享可能侵犯他们的权利。」核对本身失败时不拦：命名词库读不出来，不该让用户连自己整理的词都发不了。
- 词库发布编辑器（共享 UI 和 iOS）一直显示一句规则：只发布自己整理的词条，第三方词库导入的词不能发布。
- 导入成功后的提示末尾加上 `SCEL_PERSONAL_USE_NOTICE`（「搜狗细胞词库的整理成果属于原作者，导入的词只供你在本机使用，不能发布到社区。」）：共享 UI 的桌面分批导入和鸿蒙手机命名词库、Android 词库页、iOS 导入页的细胞词库说明。命名词库列表里细胞词库的副标题加「搜狗细胞词库 · 仅本机」。

### 各平台能做到哪一步

| 宿主 | 来源可查 | 发布时 |
|---|---|---|
| 鸿蒙（共享 UI + 命名词库） | 是 | 硬拦并说明原因 |
| macOS、Linux、Windows 共享面板 | 否：细胞词库经 `scelText` 转成标准文本直接写进个人词库，不留来源 | 只有规则提示 |
| iOS | 否：同样写进个人词库队列，不留来源 | 只有规则提示 |
| Android | 是 | 社区只读，不能发布 |

## Alternatives considered

- **只放一句提示，不做核对**：改动最小，四个平台一致。但提示拦不住照抄，而律师函盯的正是「传播」；在来源可查的宿主上，一个只读查询就能硬拦，代价很小。
- **按词本身（不看编码）核对**：用户换个编码就绕不过去，更严。但通用细胞词库什么词都有，导入一个大词库后，用户连自己整理的「你好」都发不出去；只按词比较误伤太大。
- **给桌面和 iOS 也记下细胞词库导入的词**：能让所有宿主都硬拦。但细胞词库一个文件能转出上百万个词，要么在本机另存一份同样大小的身份表，要么改 `scel_text` 这个纯函数 C ABI 让它带上副作用。规模和契约的代价都大于收益，等这些宿主有了命名词库再接同一个动作。
- **服务端拦**：服务端只收到词条，不知道它们从哪来，拦不了；按内容去比对搜狗词库就要服务端持有搜狗词库，正是要避免的事。

## Consequences

- **收益**：社区这个唯一的公开出口，在来源可查的宿主上不再接收细胞词库的词；所有平台在导入时就说明原因，用户不会到发布时才第一次知道。
- **代价与已知上限**：桌面、Windows 共享面板和 iOS 只有提示，用户照抄仍能发布，最终靠举报和下架。编码完全换掉的同一个词认不出来。核对失败时放行，这是有意的取舍。每次核对要在锁内读一遍全部集合文件，词库很大时「添加词条」会慢一点。
- **不变的边界**：导入只读用户自己选的文件，不从搜狗服务器抓取，不预装，不收进官方词库，测试数据全部是合成的词。

## Verification

- client-services：`third_party_matches_find_words_from_scel_collections_only` 覆盖换写法的编码、大小写、同音不同字、用户自己的文本词库、种类不同、只读不改文件和 128 个的上限；`third_party_matches_without_collections_is_empty`。
- 界面：`apps/desktop/tests/community/community-resource-editor.test.tsx` 覆盖添加时拦下并说明原因、更新旧作品时发布前拦下、核对失败照常发布；`dictionary-collections.test.ts` 覆盖副标题；`dictionary-import-feedback.test.tsx` 和 `harmony-phone-dictionary.test.tsx` 覆盖导入后的提示。
