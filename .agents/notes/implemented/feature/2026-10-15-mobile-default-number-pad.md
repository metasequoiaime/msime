# Agent Note: 移动端数字入口默认使用九宫格

Status: implemented

## Problem

#7834 要求从中文键盘点击数字入口后进入九宫格，同一面板可连续输入数字和四则运算符。Android、iOS 与 HarmonyOS 的拼音九键已有数字网格，常规 26 键和 14 键却仍进入横排 1–0 的符号层；三端数字侧栏也没有统一提供四则运算符。仅验证已有拼音九键不能证明常规数字入口符合要求。

## Decision

三端常规中文数字入口默认复用数字九宫格，沿用电话顺序、0、小数点、删除、空格和回车。原拼音九键继续显示同一数字面板；日文、韩文、越南文、藏文、大千注音、英文和本地工具保留各自符号契约。Android 注音九键也复用数字页。数字面板不改变原来的中文输入布局、语言或 Engine 网格状态，手动返回后恢复原键面。连续数字与运算符按字面上屏，始终留在当前面板，组字中的数字先按既有原样结束组合路径提交。

四则运算 `+ - * /` 在数字侧栏直接可点，不经过中文标点转换；显式 `character_width` 全角设置仍然生效。数字页的 `#+=` 打开原扩展符号页，`123` 返回数字九宫格，原符号面板和 Android 中文标点开关仍然可达。该需求不新增或移除自动计算。键位统计区分原拼音九键 `Nine*` 与从其他中文键面进入的普通数字 `Digit*`，不能因为复用显示控件而把 26 键输入统计成拼音九键。

这是默认行为的变更，不恢复此前撤掉的两项设置或其旧偏好消费者。iPad 全尺寸也显示数字网格，iOS 和 Android 借用网格时暂停分离显示，返回字母后仍按原设置分离。HarmonyOS 只改变触屏数字入口，2in1 的常规数字页保留。手写和笔画只换数字页，返回后恢复原面板。

Android 启动阶段的视图可能尚未提供 `local_mode`，数字显示判定使用既有 `InputViewValuePolicy.textOr(..., "none")` 的缺失值规则；空视图不能被当作本地工具模式，否则 API 35 上首次点 123 仍会误入横排。数字侧栏默认一屏四项，原自定义表、滚动和最小行高保护保留。

## Alternatives considered

- 重新提供“26 键按 123”选项：能同时满足两种偏好，但维护者已因含义不清与分支负担撤掉该选项；新 issue 明确要求数字入口直接进入九宫格，因此调整默认行为。
- 只保证原拼音九键提供运算符：复用范围最小，但常规 26 键的数字入口仍是横排，不能满足验收。
- 新建一套独立拨号盘：布局与按键含义容易控制，但会复制三端已有的数字网格、按键反馈和底行；先核对并复用现有表面，仅在不能满足输入契约时拆出专用组件。

## Consequences

收益是中文入口直接提供连续数字和四则运算，沿用已有网格、反馈和底行，避免再维护第二套拨号盘。代价是原来习惯横排数字的用户会看到固定的新默认，数字侧栏比字母侧栏密，扩展符号多一次入口切换；原有中文标点开关仍在扩展页。
