# Agent Note: macOS 繁简切换复用输入状态 HUD

Status: implemented

## Problem

繁简切换已经改变候选和上屏文字，却没有中英文切换那样的即时反馈。用户只能继续输入有繁简差异的汉字才能确认状态，在 cmux 一类可能提前处理 Control 组合键的编辑器里，尤其难以分辨快捷键未送达和切换成功。

## Decision

繁简切换复用 `MSIMEInputModeHUDPanel`：简体显示「简」，繁体显示「繁」，无障碍播报使用完整的「简体输出／繁体输出」。面板四种单字状态取最大宽度，继续使用中英文提示的 18pt 字号、32pt 高度、光标位置规则、主题及 0.6 秒停留时间。

`InputController` 的繁简动作统一经过 `setTraditionalOutput:`，快捷键、菜单和悬浮工具栏只有实际改变状态且存在活动客户端时才显示提示。长按重复、英文模式下被保留但不执行的快捷键、重复选择当前状态、后台偏好载入都不新增提示。`input_mode_hud` 同时控制中英文和繁简反馈，不引入偏好字段或改变出厂默认值。

[不迁入旧版位置与聚焦播报](2026-10-21-caret-indicator-position.md) 的范围判断继续成立；本次用户明确要求恢复繁简反馈，只扩展单格 HUD 的状态文本，不恢复旧版整套徽标。

## Alternatives considered

- 独立创建繁简 HUD：可以让两类提示各自定制，但会复制位置、材质、淡出计时和设置开关，也无法保证与用户要求的中英文提示一致，因此复用现有面板。
- 在 `appearanceChanged:` 中自动播报繁简状态：能覆盖偏好变化的所有来源，但主题调整、轮询载入和多个控制器通知都可能产生无关提示，因此只在用户操作入口触发。

## Consequences

繁简切换获得即时、可见且可读屏的确认，沿用用户现有的 HUD 开关。中英文与繁简连续切换更新同一个提示并重置停留时间，不叠加窗口。

本改动不能让输入法收到被宿主提前处理的按键。cmux 的 Control 快捷键兼容仍依赖宿主将对应组合键交给输入上下文；本机已单独配置 `keybind = ctrl+shift+f=ignore`，不把用户本机配置提交到仓库。

回归覆盖真实控制器的 Ctrl+Shift+F 入口、两个方向、重复按键、英文模式、关闭提示、同值选择、菜单、工具栏以及无活动客户端。
