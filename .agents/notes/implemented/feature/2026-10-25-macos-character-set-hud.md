# Agent Note: macOS 输入状态切换共用 HUD

Status: implemented

## Problem

繁简切换已经改变候选和上屏文字，却没有中英文切换那样的即时反馈。用户只能继续输入有繁简差异的汉字才能确认状态，在 cmux 一类可能提前处理 Control 组合键的编辑器里，尤其难以分辨快捷键未送达和切换成功。

## Decision

繁简切换复用 `MSIMEInputModeHUDPanel`：简体显示「简」，繁体显示「繁」，无障碍播报使用完整的「简体输出／繁体输出」。面板单字状态取最大宽度，多字提示按文本扩展宽度，继续使用中英文提示的 18pt 字号、32pt 高度、光标位置规则、主题及 0.6 秒停留时间。

`InputController` 的繁简动作统一经过 `setTraditionalOutput:`，快捷键、菜单和悬浮工具栏只有实际改变状态且存在活动客户端时才显示提示。长按重复、英文模式下被保留但不执行的快捷键、重复选择当前状态、后台偏好载入都不新增提示。`input_mode_hud` 统一控制输入状态反馈，不引入偏好字段或改变出厂默认值。

[不迁入旧版位置与聚焦播报](2026-10-21-caret-indicator-position.md) 的范围判断继续成立；本次用户明确要求恢复繁简反馈，扩展现有 HUD 的状态文本，不恢复旧版整套徽标。

### 输入状态反馈范围

用户进一步要求补齐其余缺失的 HUD。全半角显示「全角／半角」，标点显示「中文标点／英文标点」，英文候选模式显示「英文候选」并在退出时显示当前输入模式，方案切换显示菜单中的完整方案名称，译文开关显示「译文开／译文关」。快捷键、输入法菜单和工具栏共用同一个动作入口。标点被锁定、组字收尾失败、长按重复或同值选择不弹提示。

中日英循环等一次操作同时改变模式与方案时，只提示最终状态；日语、韩语、越南语、藏语分别使用「日／韩／越／藏」，不把它们误报为中文。系统输入模式回报沿用已有去重规则，后台偏好载入、应用聚焦不新增播报。方案 HUD 从现有菜单取得实际可用方案和双拼／五笔配置名称，不另建名称表。

清理输入缓存快捷键仅在核心返回成功后提示「缓存已清理」，失败和重复键不提示。重启与退出本身结束当前进程，不增加即将消失的提示。Caps Lock 继续使用系统指示。语音、手写、表情等操作有自己的面板或录音状态，工具栏显隐会直接改变可见界面，不叠加瞬时 HUD。设置页内的一般偏好修改保持现有反馈方式。

## Alternatives considered

- 独立创建繁简 HUD：可以让两类提示各自定制，但会复制位置、材质、淡出计时和设置开关，也无法保证与用户要求的中英文提示一致，因此复用现有面板。
- 在 `appearanceChanged:` 中自动播报繁简状态：能覆盖偏好变化的所有来源，但主题调整、轮询载入和多个控制器通知都可能产生无关提示，因此只在用户操作入口触发。

## Consequences

繁简切换获得即时、可见且可读屏的确认，沿用用户现有的 HUD 开关。中英文与繁简连续切换更新同一个提示并重置停留时间，不叠加窗口。

本改动不能让输入法收到被宿主提前处理的按键。cmux 的 Control 快捷键兼容仍依赖宿主将对应组合键交给输入上下文；本机已单独配置 `keybind = ctrl+shift+f=ignore`，不把用户本机配置提交到仓库。

回归覆盖真实控制器的繁简、全半角、标点和英文候选快捷键、两个方向、重复按键、标点锁定、组字收尾失败、关闭提示、同值选择、菜单、工具栏及无活动客户端；真实引擎会话覆盖三语循环最终状态和失败时静默，面板测试检查长方案名不被裁切并恢复单字尺寸。
