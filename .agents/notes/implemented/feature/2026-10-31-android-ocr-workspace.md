# Agent Note: Android 独立拍照识字窗口与图片选区

Status: implemented

## Problem

#10377 撤回 #10233／PR #10357 的键盘内大预览方案：键盘高度仍限制相机，长按选字也不便操作。要求应用内独立拍照、图片裁剪／涂抹、逐字点选结果，再返回原输入框。不能把失焦后失效的输入连接凭包名重新绑定。

## Decision

`OcrCaptureActivity` 在输入法 `:ime` 进程独立承载相机、图片处理与结果三个页面，不调用外部相机。相机占主要空间，快门放在底部；图片页提供左上返回键盘、右上裁剪、左下涂抹、右下下一步和图内右下重拍图标；结果页提供左上返回、右上重拍、左下复制、右下插入，以及独立全选图标。裁剪支持四边与四角，涂抹只识别画过的区域，空选区不推进。识别全文默认选中，单击字素切换选择，不依赖长按。

Activity 不含文本编辑器，以 `FLAG_ALT_FOCUSABLE_IM` 遮盖键盘而不建立新输入连接，相机与图片页不受键盘高度限制。入口经独立 `ResultReceiver` 交接，窗口只持有结果通道，不持有 `InputConnection` 或原编辑内容。注册、插入、取消与应答各有固定消息码；会话代次保护旧回传，成功或拒绝前先消费本次请求。插入前核对原连接、修订与前／选中／后文；切编辑器、停止会话、新请求和销毁取消旧请求。插入失败保留结果，不能自动复制或向未知目标投递。

照片只在内存中受限解码、按 EXIF 转正；`OcrPhotoSelectionView` 将裁剪四边与四角、笔刷轨迹记录为原图坐标，显示缩放与旋转后的布局不改变已选范围。裁剪和涂抹是互斥模式，再点同一按钮恢复全图；切换模式清空旧选区。裁剪实际缩小推理图片，笔刷在白底上只保留画过的部分，不把屏幕上灰暗的原文字继续送入 OCR。空涂抹不能前进。不自动保存照片或结果，复制仅由用户按钮触发；窗口沿用截屏保护设置。相机只在前台拍照页运行，离开页面或应用及时释放；异步解码／识别按页面代次过滤。

## 既有笔记审计

- [离线 OCR](../../implemented/feature/2026-10-24-android-offline-ocr.md)：部分取代，仅替换键盘内相机与长按选字的交互；固定模块摘要、隔离加载、模型、许可、离线和资源安装规则保持。
- [语音自动插入](../../implemented/bug-fix/2026-10-21-android-voice-auto-insert.md)：部分重叠，沿用原连接与上下文守卫，不改语音持久化或异步交接。

## Alternatives considered

- **继续在键盘内扩展相机**：无需跨窗口交接，既有系统输入连接稳定，PR #10357 已通过设备专项。但高度仍由用户的键盘设置限制，报告者在 #10377 明确取消该方案。
- **普通可编辑 Activity 返回后按包名／fieldId 找回目标**：可复用普通应用窗口焦点规则。但同一 WebView／Compose 内多个编辑器可共享标识，不能证明还是原输入目标，不采用猜测重绑定。

## Testing

- API 28／35 独立焦点探针：专用测试输入法从第三方合成编辑器打开带 `FLAG_ALT_FOCUSABLE_IM` 的 Activity，核对原连接身份、可读性与实际 `commitText`；窗口打开到插入之间没有新增 `onStartInput`／`onFinishInput`，原编辑器收到固定合成文字。探针不是产品验收替代品；临时 APK 已卸载，原输入法已恢复。
- 产品专项从真实输入法“更多工具”进入，实际相机 JPEG → EXIF 解码 → 独立图片页 → 可选模块推理 → 单字点击／全选 → 复制／插入原 `EditText`。另检查裁剪四边的实际像素、笔刷白色遮罩、空笔刷、背景释放相机、返回不插入和旧结果在新输入会话中失效。字素覆盖组合附加符、ZWJ emoji 和旗帜序列。
- 复用固定提交 `abab458037f6f35f6bd32c0d49878a167470f3d4` 的 Rust 动态库和与其临时测试锁配对的合成模块；已核对其 Rust 源码与本分支基点相同。JNI 按本分支源码重新编译、Java 按本分支完整构建与签名。合成锁和模块不提交，不把验收 APK 当正式产品发布。
- `check-host.sh` 通过 Java／JNI、316 项 JVM 冒烟与设备套件编译；Gradle `assembleFullRelease lintFullRelease` 通过，`verify-local.sh --quick` 和笔记校验通过。API 28／35 最终产品专项均通过，同时覆盖前文保留、照片旋转后推理和重拍；两版系统撤回相机权限专项通过。
- API 28／35 在同一个真实 `:ime` 进程中完成离线手写 → 相机 OCR → 离线手写，覆盖真实笔迹、候选、空格／回车上屏、撤销和符号层返回。API 28 曾在进入手写前失败：专用 AVD 只启用了全拼，方案面板没有手写卡片。手写专项经原生设置页临时添加手写，结束后移除，仅在本次添加时还原；原书写模式和原输入方案同样恢复。前置失败截图与识别阶段失败截图分开，避免恢复操作覆盖原始现场。

## Consequences

独立窗口不再占用“更多工具”面板的生命周期，关闭面板或隐藏键盘只处理键盘呈现；新的输入会话、停止、销毁和新 OCR 请求仍使旧插入授权失效。不按包名或 `fieldId` 重新绑定，结果仍可在旧窗口内复制。系统回收 Activity 时丢弃照片与文字，不落盘恢复；屏幕旋转由当前实例处理，相机页重开驱动，图片选区保持原图坐标。

窗口可聚焦以支持返回键和无障碍，但不建立新编辑器连接。此做法遵循 [Android 窗口与软键盘的焦点标志说明](https://developer.android.com/develop/ui/views/touch-and-input/keyboard-input/visibility)；连接能否继续使用仍由系统与原应用决定，插入必须通过运行时守卫。模拟器的原生合成编辑器不能替代真机、WebView、Compose 或第三方应用验收，未知编辑器拒绝读取／写入时保留结果供手动复制。

涂抹可能截断字形，识别结果需要用户核对。逐字点击基于系统 ICU 字素边界，空白和换行也参与全选；没有可编辑文字控件，不重新引入另一个输入框。相机、照片和结果中的按钮区域保持紧凑，API 35 的系统栏边距单独处理，避免操作键落到导航栏下面。模块摘要、隔离加载、离线和许可规则仍由旧笔记持有，不改模块格式、模型和默认值。
