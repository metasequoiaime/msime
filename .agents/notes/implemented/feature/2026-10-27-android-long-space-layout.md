# Agent Note: Android 可选长空格布局

Status: implemented

## Problem

#9881 反馈 Android 的 26 键底行空格较短、右侧键多而容易误触，希望保留逗号并用下滑输入句号，同时让数字层遵循同一习惯。原有底行是已经确定的跨平台默认布局，不能因为新增选择而翻转现有用户的默认值。

## Decision

新增仅在 Android 本机保存、默认关闭的「长空格布局」。26 键字母层从 `123 | 符 | 空格 | ， | 中 | 回车` 变成 `123 | ， | 空格 | 中 | 回车`；原符号键的宽度交给空格。英文键面原先多出的独立句点也由逗号滑动接替。26 键的普通数字入口使用带空格的 123 层，不借用没有空格的九宫格；真正的数字字段和密码字段仍沿用原键盘。数字与更多符号层把底行原表情／符号入口换成逗号，保持返回字母、标点模式与回车可达；两层的逗号同样滑动输入句号。符号面板入口放在顶栏，长空格模式开启时显示；用户主动隐藏工具栏时仅保留顶栏符号入口。长按数字键打开符号面板的原有动作保留。14 键、九键、手写等独立键面不改。

逗号上滑和下滑都输入句号。#9881 要的是下滑，但字母键滑动输入符号的方向默认是上滑（`platform.android.swipe_symbols_direction`），只认下滑时，照字母键习惯上滑的用户什么也打不出来；逗号键没有别的纵向手势，两个方向都接，也不必再跟随那个方向设置。为了不和点按、长按冲突：滑动门槛与字母键相同，是 14 dp（严格大于），不用约 8 dp 的 touch slop，否则点逗号时手指往上带一下就会出句号；按满系统长按时限还没滑出去的触摸归长按，之后挪动手指不再起滑动，免得长按出句号后松手又补一个。

逗号手势的缓存同时记录按钮实例与启用状态。同一输入法服务会重建输入视图，不能只因开关仍为开启就跳过新按钮的绑定；替换时解除旧按钮监听，再给新按钮绑定。

## Alternatives considered

- 把原布局直接改成较长空格，可以减少一个设置项，但会改变所有现有用户的触控习惯；保留原默认布局。
- 逗号只跟随「滑动输入符号」的方向设置：与字母键一致，但默认上滑时 #9881 要的下滑就不再生效，改方向的用户也要重新学一次逗号；两个方向都接更简单。
- 数字层继续用原底行，可以少改一张键表，但用户从字母切到数字时逗号手势会消失；让两层都有同一逗号键。

## Verification

`bash platforms/android/check-host.sh` 验证 281 项 JVM 冒烟、245 份设备测试源码编译和 Java/API、资源契约；键位测试核对默认布局、长空格宽度、英文无独立句点、数字和更多符号层的逗号，以及其他布局不变。在专用 API 35 模拟器上，用真实按钮触摸派发和合成编辑器验证同一服务两次创建输入视图：修复前第二次下滑不能提交句号，修复后两次均能提交。原生 Java 宿主在外盘增量构建，复用已核对来源及 JNI 接口的词库与原生库，未声称本次重编 Rust 全栈。`scripts/verify-local.sh --quick` 已完整执行；公共 Windows Depot runner 契约等待 #9986。共享构建目录曾混入其他分支的 Rust 元数据，串行强制重算后，workspace 全目标检查与 Android 目标检查均通过。

## Consequences

原有底行和默认值不变。长空格模式的 26 键中文数字入口从九宫格换为带空格的数字符号层；独立数字字段仍使用九宫格。顶部符号入口占 44 dp，隐藏工具栏时仍保留品牌、符号、收起三个按钮。设备回归覆盖触摸手势系统派发和输入视图重建；面板往返和设置重启生效仍待扩展验收。
