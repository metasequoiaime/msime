# Agent Note: 香港街道与地方名称进入粤拼和普通话词库

Status: implemented

## Problem

[msime#10911](https://github.com/metasequoiaime/msime/issues/10911) 要求把香港街道和地方名称录入词库。维护者在本次任务中确认同时补粤拼和普通话拼音。现有粤拼词表缺少砵典乍街、彌敦道、窩打老道等整词；普通话主表虽有弥敦道，却没有覆盖同一批名称。

## Decision

名称使用香港特别行政区政府地政总署通过 CSDI 提供的 Road Centreline 和 Place Name 数据。2026-11-05 取得的快照分别有 4,575 条中英文街名组合和 2,826 条地方名称记录；中文名排除空值后合计去重为 6,997 个。这里的数目是原始记录覆盖，不是可输入词条数，不能把它写成验收通过的数量。

- 原始名称、来源和摘要固定在 msime-dictionary 的 `sources/hong-kong/`，生成表为 `landsd-readings.tsv`，四列是繁体、简体、粤拼、普通话全拼；生成器与发布构建接入留在 msime 的 `crates/dict-builder`。不复制邻仓未提交内容。
- 粤拼保留香港繁体字形，普通话按既有拼音库的简体字形输入契约生成。英文街道名称只作核对依据，不直接当作粤拼。
- 读音使用已有的固定字词表和明确的香港地名读音审校表。多音字未消歧、未知字、非汉字和不符合当前纯汉字词条格式的记录必须输出待审清单；不能默认取字表第一音后声称已核对。
- 补充表不覆盖既有同键同词的权重。新增地名最多 10 分，且低于导入前同键最轻的已有行（最低 0），避免替换日常同音词的首选。普通话阶段在 `custom-words` 之后、读音纠错与否决之前，不改变人工词条提权的归属；粤拼在原有来源构建后增加，仍遵守否决表，不改变既有字词权重。
- CSDI 名称仍遵循其原有使用条款，不能把整个派生库继续声明成只有 CC BY 4.0。随库的现有许可证附件补入政府、地政总署与 CSDI 的署名、来源、改动说明和条款；不新增客户端需要下载的附件。

## 粤拼完整词查询

实际输入 `zaadingaai` 时，首选切分是 `zaa ding aai`，词库中的「渣甸街」却在 `zaa din gaai` 下。普通粤拼除首选路径外，还查询分段器原有最多 16 条路径中的完整词条，放在首选整段候选后、短词前。备选路径不补全、不展开短词、不参与组句；显式分隔符和双拼确定的音节仍是硬边界。任何覆盖输入全长的词条都会阻止首选路径生成错误整句。重复查询缓存分段路径，但不缓存词条，用户词更新仍立即生效。

## Alternatives considered

- **复用 Rime 的 `jyut6ping3.maps.dict.yaml`**：现成的 4,000 多条街名表，来源提交与项目正在用的粤拼表一致。但该表从 OpenStreetMap 提取于 2020 年，没有读音、采用独立的 ODbL 许可，而且不能替代官方地方名称集。选择官方当前快照，仍明确处理其署名和许可义务。
- **只追加 issue 中列举的街名到 custom**：能沿用现有导入和验证流程，很快补齐举例。但不能实现要求的香港街道与地名覆盖，也不适合今后重复更新。

- **提高地名权重来修复漏词**：实现简单，但未被查询的切分无论权重多高都不会出现，还会改变同音词排序，所以修复查询范围。

## Verification

- 原始去重名称共 6,997 个；6,931 个进入双方案表，待审读音 0 个。另有 65 个锦绣花园分段街名含拉丁字母，1 个名称含官方源中的私用区字，这 66 个保留在 `audit.json` 的不支持清单，不删字强行拼出另一个名称。首尾空白、路段横线、方向括号与全角巷号的规范化都有原名映射。
- 与固定词库基线 `c239ba1` 同构建器比较，普通话新增 6,342 行、粤拼新增 6,675 行；953,156 条既有拼音行和 139,340 条既有粤拼行均未修改或删除。
- `scripts/test-hong-kong-places.py` 验证多音字未消歧时拒绝生成、专名和通用词优先级、标点规范化不吞字母与私用字、快照摘要损坏、补字音必须有出处。构建器单测验证两种方案不改已有权重、同键封顶、重复导入幂等、否决仍有效、旧 checkout 兼容以及目录不完整或表摘要损坏时失败。
- 引擎单元测试 3,042 项和 golden 31 项通过；粤拼专项 89 项通过（另 1 项需要外部发布库而忽略）。备选完整词回归覆盖连续输入、显式分隔符、无效尾键、不同音节数的歧义路径与选词消费范围，原有双拼和重复查询分配门禁保持通过。
- `crates/dict-builder/tests/hong_kong.rs` 用实际构建的数据库测试 issue 的 13 条街名及 7 个代表地名在两种方案中输入、选词与上屏。命令：`MSIME_HONG_KONG_TEST_DATA=<含 pinyin/ 与 languages/ 的目录> cargo test -p msime-dict-builder --test hong_kong -- --ignored`。本地 20 个名称 × 2 种方案的 40 次输入、选词和提交通过；默认忽略是因为 CI 没有本次生成的数据库，不能把普通 `cargo test` 说成执行了这一项。
- 生成表须在干净且已提交的 msime 工作区生成；`sources.json` 记录生成器提交和表、覆盖报告摘要。词库仓 `scripts/check_hong_kong.py` 加入已有 quality workflow；修改输入后另用生成器 `--check` 比较表内容。政府下载快照没有 Git 上游，不给 `upstream.lock.json` 捏造提交。

## Consequences

官方数据没有粤拼或普通话读音；通过字表校验只能证明音节是该字的合法读音，不能代替地名的读音核对。选择规则和专名消歧集中在 `curation/hong-kong-readings.tsv`，不散在引擎里。`䃟` 的普通话补音附汉典字音出处；`乾秀里` 在专名字形表保留「乾」，不被单字简化成「干」；「暢行、行善、順行、高行」与「銀行、琴行」分开，「茜發」不套「茜草」的粤音。没有声称经过粤语母语者逐词验收，也没有真机或原生编辑器验收。

代价是增加约 1.3 MiB 的来源快照以及审校表、覆盖报告和派生表。带字母街名要等明确的混合词读音规则，私用字要先找到官方 Unicode 对照，不能猜。现有客户端和引擎格式不变；旧词库 checkout 没有整目录时保持兼容，目录存在但缺表时构建失败。

跨仓提交顺序为先合 msime 构建器，再把词库仓 `builder.lock.json` 指向包含本功能的已合入提交，最后合词库数据。合词库数据会触发仓库已有的自动发布，本任务不手动发布。两边 PR 互链；词库数据 PR 在构建器尚未合入、构建器锁未更新时保持 draft，不能靠旧构建器构建成功来证明新表生效。应用随包锁的更新遵循后续词库版本流程，本任务不把未发布分支伪装成 Release。
