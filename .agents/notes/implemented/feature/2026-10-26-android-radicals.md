# Agent Note: Android 符号面板偏旁分类

Status: implemented

## Problem

Android 符号面板没有按笔画查找偏旁的入口。用户只能在中文符号和 Engine 目录中逐项寻找部件，无法按 issue #9786 附件提供的部首表快速定位。

## Decision

在 Android 符号面板加入稳定身份为 `radicals` 的「偏旁」分类。分类使用 issue 附件整理的 301 个部件，按 1 至 14 画和 17 画分成 15 组。进入该分类时，面板主体显示左侧可纵向滚动的笔画栏，右侧显示所选组的五列网格；切换笔画会清空并重建右侧网格，同时把滚动位置复位。分类栏和笔画栏都更新选中状态及无障碍描述，保留现有符号上屏、长按和「常用」记录规则。

偏旁数据放在 Android 宿主的不可变模型中，不加入 Engine 目录分页协议，也不改变其他平台的分类顺序。分类顺序设置继续使用稳定 ID，缺少或重复的旧设置由现有策略补全。

点击笔画后重建右侧网格的交互已由[连续笔画导航](../bug-fix/2026-10-26-android-radical-panel-scrolling.md)取代；本篇保留数据与分类身份的决定，界面行为和设备验证以该篇为准。

## Alternatives considered

- **复用 Engine 的 `symbol_catalog`**：可以减少 Java 内置数据，但目录只按语义父类分页，不能保证部首表的笔画分组和离线可用性，因此保留独立的静态模型。
- **把 301 项全部放进一个五列分类**：实现简单，但用户仍需长距离滚动，无法满足按笔画筛选的交互目标，因此增加左侧笔画栏。
- **为每个笔画创建底部分类**：能复用现有底栏，但会挤压已有分类并增加横向查找成本；竖直笔画栏能在同一主体区域内保留已有分类入口。

## Consequences

偏旁功能完全离线可用，分类和笔画选择可通过无障碍树识别，已有符号面板的上屏和最近记录行为不变。代价是 Android 面板增加一列固定宽度的笔画栏，窄屏上右侧网格可用宽度减少；超长数据不走 Engine 分页，因此后续修改部件表必须同步更新模型冒烟测试中的数量和边界断言。

## Verification

- `platforms/android/check-host.sh` 通过，包含 Android Java/C++ 宿主检查和 JVM 冒烟测试。
- `SymbolCategoryOrderPolicySmoke` 校验 15 个笔画组、301 个条目及首尾数据；`SymbolPanelModelSmoke` 校验新增分类仍保持既有分类 ID、顺序和目录索引契约。
- 设备模拟器上的 UI 验收仍需在 API 28 或 API 35 上确认笔画栏滚动、分类切换和窄屏点击区域。
