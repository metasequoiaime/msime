# Agent Note: 图片工具栏共享契约与资源兼容

Status: implemented

## Problem

固定参考 `metasequoiaime/msime-windows` 的默认分支 `develop` 提交 `3aa15daf73a029243bbf6ec143c2089c2ccfe544`。上游图片工具栏允许按钮在背景外、按状态切图和自动排列，对齐前本仓库只读取工具栏颜色。这会使同一皮肤在其他平台退化，且安装、同步的资源收集未包含工具栏图片。

## Decision

共享 `client-services::skin::catalog` 在独立 `toolbarImage` 字段传递图片模式，不扩展严格的旧 `host_candidate_catalog` 条目。共享模块负责字段校验、默认值继承、状态图选择和按钮排列；原生宿主可通过无磁盘 I/O 的 `msime_client_skin_toolbar_image_layout` 使用扫描缓存，切换状态不重新读图。宿主负责当前显示按钮、当前状态、图像绘制和命中。浏览器预览有同规则的 TypeScript 布局副本，以同一份合成契约样例同时校对 Rust 的解析和布局，避免依赖桌面壳才能预览草稿。只排列宿主本来显示的按钮，`visible = false` 进一步隐藏，皮肤不能重新开启用户关闭的功能。

按上游先校验字段，再忽略 `bar` 模式的图片设置；未知按钮忽略，未知状态仍先校验图片路径。图片仅包内 PNG/APNG/GIF/WebP。固定坐标不推进 flow，缺坐标且无 flow 的按钮不显示。按钮自身优先于 defaults，宽高出厂值 26 DIP；状态图优先于通用图，再回退宿主图标。窗口包含背景和所有按钮的矩形并集，透明背景不截获输入，按钮矩形仍可点击。图片模式不绘制条形工具栏的边框、把手、阴影和分隔线。

资源引用统一供扫描预算、整包导出、安装与同步使用，避免解析成功但跨设备丢图。本地安装、草稿校验和整包导出支持最多 64 张（原有 37 加工具栏 27），保留原有字节、像素和帧预算。社区传输保留 37 张上限；图片工具栏上传先要求同源响应明确声明 `X-MSIME-Candidate-Toolbar: image-v1`，仅有 `canvas-v1` 不足以证明支持工具栏资源。现有服务器未部署此能力时保持本地可用、上传拒绝，不静默漏存图片；本切片没有改动服务器或假定线上已升级。

本切片落实共享清单、资源安装、MCP 说明、无 I/O 布局桥和共享设置预览。macOS、Windows 与 HarmonyOS 2in1 的原生悬浮窗绘制仍未接入，本切片不把预览能力当作原生绘制能力。Android、iOS 与 HarmonyOS 触屏保留键盘内工具入口，不引入桌面窗口。Linux 保持框架菜单所有权，不为皮肤伪造无上下文的悬浮窗。报告分别说明共享资源兼容、原生绘制、系统输入验收，不能互相替代。

## Alternatives considered

把图片字段加进现有 `SkinToolbar` 可以减少一处顶层字段，但旧宿主目录严格拒绝未知字段，颜色和图片的兼容生命周期不同，因此用可选独立字段。各平台独立解析 TOML 可以直接复用宿主绘制条件，但会复制安全校验、继承和布局规则，因此由共享层规范化。

## Testing

共享测试覆盖 bar 忽略、未知按钮与状态兼容、非法数值与路径、状态优先级、固定与 flow 混排、隐藏与用户开关、越背景按钮边界。64 张合成资源经过安装、重扫和重新打包保持一致；损坏后续状态图或超出数量上限不会覆盖已安装包。社区测试覆盖旧能力、未知能力拒绝，以及明确能力后的上传顺序。宿主桥校验缓存数据的数值、路径和请求数量，不能让非法 JSON 变成巨大窗口或越包资源路径。

共享皮肤专项 336 项、宿主桥专项、MCP 94 项单测与 12 项 stdio 集成测试通过；相关三个 crate 的 clippy（含测试目标，警告视为错误）与 Rust fmt 通过。前端最终类型检查及图片工具栏、既有工具栏和外部皮肤共 73 项测试通过，生产构建通过。全仓 quick 通过，包含 macOS 宿主编译、Linux 设置外壳编译及 94 项 Linux 原生测试；Windows 交叉编译与 HarmonyOS HAP 在该远端未配置，quick 明确跳过。笔记门禁通过。Android API28/35 两个专用模拟器的四个共享 crate 设备测试已通过：client-base 36 项、client-core 429 项、client-providers 230 项、client-services 1219 项，均无失败。该设备测试不等于 APK 输入法的真实编辑器验收，此处也不宣称原生悬浮工具栏验收通过。

## Consequences

同一份有效图片清单进入扫描预算、资源导出、MCP 安装和整包链，避免只在源目录预览成功。旧条形皮肤没有新增 JSON 字段，旧严格宿主目录保持原样。新布局桥有一次有界 JSON 转换开销，但没有状态切换时的磁盘扫描和图片解码。

社区 37 张上限与线上部署仍是独立约束，64 张本地包不能据此宣称可上传。预览、共享契约和原生绘制分开报告，完整 Windows 皮肤兼容目标保持未完成。原生接入需要继续处理透明区域命中、动画帧并集与窗口范围，不能只复用按钮坐标就宣布完成。
