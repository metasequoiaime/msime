# Agent Note: 命名词库的分组管理与批量操作

Status: implemented

## Problem

#10996 要求导入词库按来源管理、默认使用文件名并可改名、导入已有分组、自动去重和多选批量操作。共享集合存储已经覆盖单集合动作，但 Android 只导入新集合，iOS 和桌面还没有命名集合入口。逐项从界面发请求会在中间失败时留下难以判断的部分结果，也反复解析全部集合。

## Decision

沿用 `DictionaryCollections/` 的本地磁盘格式与集合语义，一个命名词库就是一个分组。新增共享的 `set_enabled_many` 与 `delete_many`：一次最多选择现有的 32 个集合，先验证全部 id 和存在性，再在同一集合锁和内存状态上操作并一次提交。重复 id 只操作一次；空选择、内置词库和任意不存在的集合在写入前拒绝。沿用原有待发队列、已有词回执、跨集合所有权保护和启停默认值，不承诺跨多个磁盘文件的崩溃原子性。

原生界面按自建、文件导入、社区来源呈现集合，支持多选启用、停用和带确认的删除。文件导入默认以文件名命名，用户可改名或选择相同类型的已有集合。导入已有集合继续使用共享去重与容量限制，不复制解析器。

分组元数据继续只在本机保存，账号和 WebDAV 的词条同步边界不变。新界面放在原生宿主，不扩展冻结的 AppKit 设置回退或 `packages/ui`。macOS/Linux 经输入菜单打开独立窗口，Windows 现代设置和 Win7 共用原生分组对话框；Linux 需要 GTK 4.8+，legacy 构建没有分组窗口。HarmonyOS 保留原设置 Web 组件，原生面板显示时隐藏它，返回不重新创建页面；首次授权和启动遮罩完成前不显示入口。

桌面窗口的 `synchronize_settings` 在有队列或 outbox 时才经 `QuiescedHosts` 协调输入会话，空队列只返回状态。移动端继续用不打断其他宿主的 `synchronize`，iOS 键盘仅在确有集合待发项时释放自身会话，并保留 Swift 队列中的 `alreadyPresent` 回执，防止停用分组误删用户原有词条。Swift 兼容 Rust 已有的 `snapshotDate: "updated"` 标记，将它视为无可用列表时间并触发刷新；仍拒绝其他无效日期，不能因集合同步写过列表就拒绝整份个人队列。快捷短语集合沿用个人词库的 `quickPhrase` 类型名，不使用导入解析器内部的 `quick_phrase`。

iOS 清除学习记录后，已启用分组由共享层重排并在键盘空闲时写回；旧测试假设「iOS 没有命名分组，所有导入都删除」已不成立，文案断言改为区分分组词与未分组词，并补默认设置下的分组重排行为用例。

## Alternatives considered

- 界面循环调用单集合动作：无需新增协议；但一次多选会产生多个独立提交，任意无效 id 只能在前几项已写入后报告，且重复读写集合。共享动作能在落盘前统一校验。
- 新建分组表并把集合归入组：可让一个分组容纳多个独立词库；但现有命名集合已经是可启停的分组，增加层级会带来两层名称与开关的冲突，当前需求不需要。
- 同时同步分组元数据：换设备后管理更一致；但现有账号同步传递的是词库快照，集合身份、社区版本和停用词条需要新的冲突与加密协议，超出本地管理所需范围。

## Testing

共享行为测试覆盖多选的重叠词归属、用户原有词保护、重复选择、无效项不落盘和启停/删除后的重新加载；导入已有集合对重复行计数准确。当前共享集合 41 项测试和 Host API 空队列/预算检查通过，两包严格 Clippy 通过；macOS Objective-C++ 与 Windows MinGW 新窗口的语法检查通过。Android API 28/35 的分组导入设备测试通过，iOS Release 模拟器构建、个人词库 12 项、清除学习 3 项单测（运行 `20261114-174752`）及分组 UI 测试（运行 `20261114-175500`）通过。最终 quick 门禁在 `20261114-182725` 通过；该次随后执行的 HAP 打包因同步镜像缺生成 HAR 失败，按既有暂存脚本重建。最终 HarmonyOS 未签名完整 HAP 在运行 `20261114-185002` 通过。Linux 的首轮 Debian/Fedora CI 暴露 GLib 回调宏把 lambda 内 JSON 初始化列表的逗号当作宏参数，以及新 GTK 对兼容接口的弃用警告；回调表达式增加括号，并与已有离线翻译窗口一致声明 GTK 4.8 API 范围，不关闭其他编译警告。macOS 首轮 CI 的菜单行为测试漏列新增的分组入口，现将 `showDictionaryGroups:` 加入顺序、action 与 target 校验，不改变原有快捷键测试前置条件。Android API 28/35 的完整客户端 core 与词库维护租约测试均通过。最终代码的 quick 门禁通过，独立菜单回归曾通过；随后完整构建后的 shortcut 在 `WaitForGloss` 等待释义时失败，正在定位。API 28 整套装包冒烟已发现剪贴板详情顶部点击和数字编辑器状态断言失败，剩余套件及 API 35 继续执行，不将整套冒烟记为通过；桌面实际窗口及 HarmonyOS 设备验证仍需补齐，具体结果写入 PR，未执行项不计为通过。

## Consequences

旧版宿主不认识新增动作，但已有单项动作和磁盘格式不变。批量集合仍在一次调用内读取全部集合，最大内存与原实现一致。导入到自建分组时需确保第三方来源不会因合并而丢失；发现来源无法保留时应拒绝这种合并并明确提示。
