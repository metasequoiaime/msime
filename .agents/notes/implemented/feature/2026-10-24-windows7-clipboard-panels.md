# Agent Note: Windows 7 独立剪贴板面板复用共享存储与来源校验

Status: implemented

## Problem

Windows 7 设置里的剪贴板页可以管理历史，但托盘面板仍依赖 Tauri，缺少不依赖 WebView 的独立入口与返回原编辑器的能力。只复用加载过的列表会在用户关闭历史、切换中继或改变设备批准状态后继续复制旧内容。

## Decision

`panels/win7` 增加 `clipboard` 与 `cloud-clipboard` 两个原生路由，并由 Win7 产品启动器和安装包集成；现代 Windows 入口和默认值不变。本地面板复用真实历史接口与每页 20 条的公共分页，提供刷新、固定、删除、复制和输入原编辑器；初次只读历史，显式刷新才采集系统剪贴板。文本不裁剪，保留首尾空白、CRLF 与 emoji。

本地窗口不激活，捕获打开时的原编辑器，只在它仍在前台时上屏。云面板需要编辑搜索与上传，因此允许激活；`NativeTextInputTarget::InsertFromPanel` 仅在前台仍是本面板时恢复原编辑器，再经已有 `Insert` 检查并发送。前台切到第三个窗口后拒绝，不能抢回焦点。关闭或无效目标拒绝，不把发送失败计为成功。

本地复制和输入前重新加载同一共享历史，要求开关仍开启且原文本仍在列表。云面板直接复用 `CloudClipboardForm`、`CloudClipboardWorker`，保持账号／中继绑定、令牌脱敏、密钥与设备批准规则；复制和输入前用相同 binding 再读列表和设备，只有重新验证的 ready 状态仍含完全相同 id／text 才执行。来源变化、坏设备响应、待批准或中继错误立即禁用旧条目，不回退账号来源。来源配置只保存，手动刷新才联网。

面板的读写在串行 worker，关闭时收尾已受理任务，完成消息不携带堆指针。输入成功后经共享统计接口记 `unknown` 来源聚合，带既有面板输入标记防止 TSF 重复；复制和失败输入不计数。系统复制与输入边界可注入测试接收器，正式构造仍调用系统 API。

## Verification

Windows 11 服务会话的 x64／x86 MSVC `/W4 /WX` 构建与三个面板 CTest 通过。本地面板测试操作真实 HWND、共享历史与统计，覆盖分页、固定重排、删除、原文复制与输入、失败输入不计数、外部关闭拒绝和损坏文件保留。云面板使用真实偏好 CAS、合成网络传输，覆盖复制／输入、失败输入、搜索、置顶、上传、删除确认、来源变更前拒绝联网、中继失败不回退、请求期间配置变化后丢弃结果、坏设备状态和待批准拒绝；另验证滚动顶部／底部、整页与结束消息。

测试不读真实剪贴板、不联系真实账号。Win7 SP1 x64 桌面已运行 x64 与 x86 的独立进程编辑器验收：第三个窗口在前台时拒绝发送且不抢焦点，恢复原编辑器后本地和云面板均通过真实 `SendInput` 输入合成 Unicode 文本，统计各计一次。编辑器放在子进程，系统消息负责有界文本读取；把编辑器和面板放在同一输入队列会被 `BM_CLICK` 内部的 `SetFocus` 干扰，不能当作外部编辑器证据。原生面板两架构回归也在此 Win7 桌面通过。完整安装、升级与实际 TSF 输入已通过；真实云传输未使用账号执行。早期 quick 的 Linux 时限失败之后已有完整 quick 通过，最终门禁见[产品构建](2026-10-24-windows7-product-build.md)。

## Alternatives considered

- **缓存当前列表后直接输入。** 点击更快且不必等待网络，但跨进程关闭历史或更换加密来源后仍能使用旧文本，因此在传输前重新验证同一选择。
- **云面板也不激活。** 与本地面板使用同一焦点模型更简单，但搜索、上传及中继设置无法正常键盘编辑，因此允许激活并限制恢复原编辑器的条件。

## Consequences

Windows 7 有了可独立构建的本地与云剪贴板面板，业务逻辑继续由共享服务持有。代价是传输前多一次读取，云端延迟期间禁用编辑；完整产品已集成其余原生面板、启动器与安装包，Win7 实机结果按总笔记分层记录。
