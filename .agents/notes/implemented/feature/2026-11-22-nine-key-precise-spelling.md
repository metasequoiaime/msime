# Agent Note: 全拼九键精确拼写模式

Status: implemented

## Problem

[#11781](https://github.com/metasequoiaime/msime/issues/11781) 希望输入 `2` 时先看到这一键的字母，点 `436` 左列中的 `G` 后锁住第一键，并在 `4363` 上把精确词和混合简拼排在尾音节补全之前。目前左列会显示预测音节，点字母只筛首字母，候选也会在相同覆盖内按原有权重混排。

## Decision

Android 和 iOS 原生键盘设置提供可选的「九键精确拼写」。`touch_nine_key_precise` 缺字段按关闭读取，只有全拼九键会话使用。左列保留已输完的多字母音节，单字母用现有的大写标识；点一个字母锁住一键，重用音节锁定的撤销、换选和部分上屏。查词按段核对已锁定的字母和其余音节，读音行显示实际覆盖的字母，词库全拼保留给选词与学习。

尾段第一键可以作为混合简拼。短词的尾段已经是完整音节时不沿这一段继续补全；四音节及以上可继续补全。长读法已有词库精确命中时，另从同一张词表最多取 12 个尾段补全。相同数字覆盖内精确读法与混合简拼优先，然后才是尾段补全。在有全覆盖精确候选时，逐键模型也只比较这组完整读法。手动固定仍有自己的席位。

## Alternatives considered

- **直接替换出厂排序和左列。** 所有用户立即获得短左列，但上一轮[整表严格分档实验](../../rejected/bug-fix/2026-10-29-nine-key-completion-order-in-typing-flow.md)量到简拼召回下降。[左列现有决策](../bug-fix/2026-10-10-nine-key-spelling-column-order.md)保留预测音节的用法，因此把新的手感作为可选项。
- **只过滤左列的预测项。** 实现会更短，也能马上清理列表，但选字母仍不能推进边界，`ge'me` 的尾段补全也仍可越过精确读法。

## Consequences

- 设置保存在本机的共享偏好文档里，Android 和 iOS 使用同一字段与引擎规则。出厂九键、双拼和 14/18 键沿用原来的查询规则。
- 用合成词库逐键验证 `2`、`63`、`4363` 的左列，`436` 点 `G` 后读作 `g'en` 并选中合成候选，还有长句的精确行与尾段补全共存。另经宿主接口验证建会话和偏好更新。
