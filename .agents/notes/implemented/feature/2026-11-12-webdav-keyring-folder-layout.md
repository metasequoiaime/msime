# Agent Note: WebDAV 词库密钥串使用扁平目录并兼容旧布局

Status: implemented

## Problem

词库 WebDAV 同步复用了云剪贴板的事件日志协议。旧传输层只给每个协议请求加上 `msime-dictionary/keyring/` 前缀，协议自身仍带着 `msime-clipboard/` 根目录，因此同一个词库目录里出现了 `msime-dictionary/keyring/msime-clipboard/`。这让词库同步和云剪贴板的远端目录混在一起，也使用户难以判断每个顶层目录的归属。

## Decision

新版本把云剪贴板协议根 `msime-clipboard/` 映射为空间前缀，词库密钥串的新布局直接使用 `msime-dictionary/keyring/v1/`。协议的格式名、事件格式、加密域和设备身份不变；这里只改变 WebDAV 路径映射，因此词库密钥串仍是独立于云剪贴板的另一份实例。

传输层首次收到扁平路径的 `404` 或 `409` 时探测旧的嵌套路径。旧路径存在则本次进程锁定旧布局继续读写，不把旧日志当成新日志重建，也不删除旧目录；两种路径都不存在时保留扁平布局，让新安装只创建扁平目录。测试连接同样通过扁平映射运行，旧布局只在同步请求的回退探测中兼容。

文档把扁平路径写成 WebDAV 契约，并明确记录旧布局的兼容边界。云剪贴板自身仍使用根目录下的 `msime-clipboard/`，不受这次映射影响。

## Alternatives considered

- **继续保留嵌套布局，只修改文档名称**：改动最小，也不会增加探测请求；但用户仍会看到两个层级不同的 `msime-clipboard`，没有解决 issue 的目录混淆，因此不采用。
- **启动时把旧目录整体 MOVE 到扁平目录**：可以一次性清理旧目录，但 WebDAV 服务端对目录 MOVE 的支持和原子性不一致，移动期间还可能与其他设备并发读写，失败时容易留下半迁移状态；因此采用按请求回退，不做破坏性迁移。
- **删除旧布局并从扁平目录重新生成密钥串**：实现简单，但会丢失已有设备批准和密钥，已同步的词库日志也无法解密；不接受这种数据损失。

审查发现，探测响应曾把鉴权、限流和服务端错误也当成「目录存在」。例如首次扁平请求返回 `503` 会锁定扁平布局，重试返回 `404` 时便不再探测已有的旧密钥串。现在仅成功响应（以及 `MKCOL` 的已存在 `405`）确认布局；其他错误原样返回，供上层重试，且保留未知状态。回归覆盖扁平和旧布局探测各自先返回 `401`、`403`、`429`、`500`、`503` 后重新探测旧目录，修复前稳定得到错误的 `404`，修复后应读取原有 `207` 响应。

## Consequences

新设备和新网盘目录的结构清晰，词库目录下不再出现云剪贴板目录名；云剪贴板协议仍可复用，未增加第二份日志实现。已有安装会保留旧目录并继续使用它，因而不会自动清理用户网盘上的历史目录；只有在旧布局不存在时才会创建扁平布局。首次识别旧布局可能多发一次探测请求，仍计入词库 WebDAV 的请求预算。

验证覆盖扁平路径的创建与 MOVE 目标，以及旧嵌套路径在扁平路径缺失时的回退；未把真实网盘上的旧目录迁移列为自动操作。
