# Agent Note: Android 横向候选条连续浏览完整候选

Status: implemented

## Problem

#9468 希望不展开面板就能左右滑动全部候选。目前横向候选条只装引擎当前页，滚到页尾之后没有后续项。

## Decision

仅在触屏横向引擎候选条使用 `currentCandidateSnapshot()` 读取完整列表，按会话和代次缓存。该接口补齐引擎候选时同步当前视图，避免沿用取数前的旧身份。按钮先建 48 项，接近内容尾部再追加；同代重画保留已建数量和偏移，新代回到开头。候选选择使用完整候选的全局身份；长按管理和译文插入仍拒绝旧代回调。实体键盘、纵排与特殊候选行沿用当前分页。

检索旧笔记后，[展开网格分批建格子](../../implemented/bug-fix/2026-10-09-android-candidate-grid-batches.md) 部分重叠，复用其批量规则；[候选触摸释放](../../implemented/bug-fix/2026-10-18-android-candidate-strip-rebuild-drops-tap.md) 部分重叠，保留其按压期间延后重画的约束。其余候选几何、九键侧栏及桌面展开笔记不涉及横向完整列表，不改其决定。

## Alternatives considered

- 到边界直接翻引擎页：可复用现有数字选择与按钮，但整页替换会丢失滚动连续性，无法顺着同一条内容反向返回。
- 一次创建全部按钮：实现直接，但单声母可有数千候选，已有网格实测说明测量与绘制会阻塞主线程。沿用分批创建。
- 滑到页尾才读取完整候选：减少首帧取数，但接口可能生成新代候选，拖动中同步与重建会取消当前手势。先取数同步身份，再建立按钮，缩小手势中的状态变化。

## Consequences

触屏可以不展开面板就左右浏览完整候选；同代释义或皮肤刷新保留已建数量和滚动偏移。实体键盘分页和展开按钮仍可使用。当前视图对象改变时重新读取完整快照，包含同代更新的译文；仅皮肤刷新复用快照。

每代首次绘制需要补齐原先延后生成的尾部。缓存减少同代重复取数，分批创建限制首帧 View 数量，但完整数据仍一次取回，持续滑到底部的 View 不回收。设备验证另记录真实滚动、选词和大列表结果；不把只重编 Java 的验证包当作当前 Rust 的设备验收。

设备专项使用独立原生会话取得合成组字的完整候选作为对照，实际键盘必须滑到末项、反向返回首项，再选词上屏；单声母另检查第 70 项，覆盖首次 48 项之外的追加。拖动显式注入 DOWN、十次 MOVE 与 UP，不依赖 shell 滑动提供中间事件。早期 API 28 shell 手势曾在返回时出现误选，截图不能证明 MOVE 的送达情况，因此不以这轮判定产品触摸回归。进展取自实际 `TYPE_VIEW_SCROLLED` 事件，每轮只刷新目标节点，避免旧系统逐个刷新整条候选造成大量 Binder 调用；窗口重新注册后重取节点。

## Verification

API 28、35 的显式手势专项均通过：120 项列表滑到末项、反向回首项、再次到末项并上屏；单声母另到第 70 项，验证首批 48 项之外的追加与往返。API 28 固定旧包在同一夹具的首个末项断言失败，只建出当前页 6 项，不能到达第 120 项。两台设备的完整候选、小鹤部分选词、九键面板、九键逐字选择、旧代回调和首道双拼展开六组回归均通过。

API 28 九键面板首轮在重输阶段未观察到预期 UI 状态；旧包对照及核对安装包 SHA-256 后的修复包复跑均通过，首轮原因未定位。对照脚本改为独立文件并关闭 `adb` 标准输入，避免 heredoc 后续恢复命令被读取而漏执行；未核对包身份的中间复跑不作为修复证据。

原生宿主 `assembleFullRelease`、三轮 quick、258 项 JVM 冒烟及设备源码编译、笔记和 shell 门禁通过。设备包仅重编本分支 Java 与资源，JNI、词库等 150 项原生库与资源摘要与固定 `3d0040bad1f593cf758f62118d9335dd64522313` 旧包一致，不代表本分支 Rust 已重新在设备构建验收。在线请求使用 Engine 自身的查询代次，补齐候选不会使它过期；这条源码核对未引入额外生产改动。PR CI 不跑设备套件。
