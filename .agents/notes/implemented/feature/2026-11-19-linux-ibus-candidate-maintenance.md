# Agent Note: iBus 候选维护快捷键与右键自绘菜单

Status: implemented

## Problem

五笔/拼音自造词会往个人词库写低权重新词（沉底），要维护这些词就需要删除、置顶、固定排位。Windows 早已有逐候选右键菜单（`CandidateMenuLayout.h`）和对应快捷键；Linux iBus 面板没有逐候选菜单接口，候选维护能力不齐。本仓的 iBus 实现此前只有 Ctrl+Shift+Alt+1..8 删除高亮候选（计划文档里误记为缺失）。

## Decision

**后续决定（2026-11-23）**：本篇「宿主自绘 X11 浮层 + 扩展导出候选框矩形避让」的方案已被 [GNOME 扩展渲染候选右键菜单](2026-11-23-gnome-shell-candidate-menu.md) 取代——GNOME 会话改由扩展用 `PopupMenu` 画菜单，点击经 IBus `property_activate` 回传；非 GNOME 会话仍沿用本篇的自绘浮层。本篇的快捷键、动作校验与定位迭代史继续有效。第三轮审查（2026-11-25）之后的现状：锚点枚举是 `{Pointer, Cursor}`（`CandidateRect` 与 `GetCandidateRect` 已删），菜单弹不出来时的快捷键提示常量是 `CandidateActionPolicy.h` 的 `candidate_maintenance_shortcut_hint`（下文的 `CandidateMenuHint.h` 没有落地）。

**后续决定（2026-11-25，固定排位改键）**：固定到第 1..5 位由 `Ctrl+1..5` 改为 `Ctrl+Shift+1..5`；置顶、取消固定、删除三键不变。报告者确认 `Ctrl+1..5` 全部已被别的功能占用，这组维护键必须让开。改键只动 Linux iBus 的解析、iBus 菜单文案与设置页速查，Fcitx5 的菜单文案仍不带快捷键。美式布局的 Shift+1..5 在 IBus 事件里是 `! @ # $ %`，其它布局也可能把数字行换成别的符号，所以解析除认数字与小键盘 keysym 外，还认 evdev 键码 2..6；没有键码的合成事件才退回上述符号表。

从五笔造词 feature 分支拆出独立的 Linux 配套 PR（本分支），基于 develop 只带三个代码提交：

- **快捷键（子线 C，固定排位已按 2026-11-25 的决定改键）**：Ctrl+Delete 删除高亮候选、Ctrl+↑ 置顶、Ctrl+Shift+1..5 固定到第 1..5 位、Ctrl+0 取消固定（主键盘与小键盘等价）。解析抽成 `CandidateMaintenanceShortcut.h` 纯函数：删除/置顶/取消固定恰为 Control、固定恰为 Control+Shift，不抢 Ctrl+BackSpace / Ctrl+左右的分段编辑；动作按 `rendered_candidates` 里 `highlighted` 行的 identity 落库，围栏与面板属性菜单同一组（会话、渲染代次、`candidate_dictionary_actions_available`，删除另有可删除判定）；高亮行不在本页时按键照常往下走。设置页速查只在运行中的宿主报告 `"host": "ibus"` 时列出这四键（`HostCapabilities::apply_linux_ibus_host`），Fcitx5 没有实现，不列。
- **围栏不通过时照常往下走（审查补丁）**：高亮行不可维护、视图代次过期或行 id 不归本会话时，快捷键分支原先直接 `return FALSE`，组字还开着就把 Ctrl+↑、Ctrl+Delete、Ctrl+Shift+1 原样交给应用（例如单字候选上按 Ctrl+Delete 会删掉文档里光标后的词，预编辑却还留着）。改成落到后面的组字路径，和没有这组快捷键时一样：带 Ctrl 的键先取消或结束组字。
- **右键菜单（子线 D）**：IBus 面板没有逐候选菜单接口，自绘 X11 弹层（`OverlayX11Window` + `XGrabPointer`，点外收起、hover 重画、事件泵；Xwayland 会话同样可用）。条目文案与顺序照 Windows `CandidateMenuLayout.h`（置顶 / 固定 1..5 / 分隔线 / 取消固定 / 删除），布局、命中、绘制与悬浮工具栏菜单共用同一套模板化函数（条目类型同构，属纯重构）。动作按被点渲染行的 identity 在 show 时绑定，回调核对会话与渲染代次；连不上 X 时退回候选窗提示条。收起时机统一：render 开头、clear（focus_out 与会话出口）、reset、Esc（只收菜单不取消组字）。
  - **定位按会话分流（本轮修正）**：原实现右键一律用 `XQueryPointer` 取根窗口指针位置定位；实机发现 Wayland 会话下菜单稳定出现在桌面右上角。根因是 Xwayland 根窗口根本不跟踪被 Wayland 合成器（GNOME Shell）管理的指针——`XQueryPointer` 连续采样恒返回陈旧值 `(1901,66)`、`child=0x0`，菜单据此展开后被夹到工作区右上角。现在纯 X11 会话仍用指针模式（坐标可信，`show()` 内 `XQueryPointer` 兜底）；Wayland 会话改用 IBus 上报的 `engine->cursor_area` 作光标锚点。锚点守卫在 `CandidateMenuPlacement.h` 纯函数里：四分量全 0（客户端尚未报光标）或矩形不完整落在工作区内（Wayland 原生客户端报的是表面局部坐标，不是根坐标）都判不可用，回退到工作区水平居中、下沿离底边四分之一处，绝不落回右上角。**可用时菜单水平中心对齐光标中心、整体放在光标上方**（`centered_x = anchor.x + anchor.width/2 - menu_width/2`，`above_y = anchor.y - gap - menu_height`），全程夹在工作区。锚点有效时不做左右翻转，垂直区间与光标下方的候选框分离；锚点贴屏幕顶边时菜单夹到工作区顶部，可能部分越过光标，是已知边界。宿主拿不到 GNOME Shell 画的候选窗矩形，只能按光标矩形 + 字号估计，无法精确到「所选行」。`ClientEngine.cpp:6937` 既有判断（Wayland 下 IBus 分不出客户端显示类型、光标坐标未必是根坐标）由「完全不用」细化为「用 + 守卫 + 回退」，不无条件信任。
  - **鼠标右上方定位（曾作为方案，已被下一版取代）**：报告者进一步要求「以鼠标为基准、放鼠标右上方」，而不是以光标为基准。IBus 的 `CandidateClicked` 事件不带坐标，Xwayland 根窗口的 `XQueryPointer` 又是陈旧的，Wayland 下宿主拿不到真实鼠标位置，只能向 GNOME Shell 要。新增随包安装的 GNOME Shell 扩展 `msime-pointer@msime`（GNOME 45–51 的 ESM 扩展），在 SessionBus 上导出 `org.msime.Pointer.GetPointer()`，返回 `global.get_pointer()` 的 stage 绝对坐标；UUID 与 D-Bus 名按版本生成，full 无后缀、其它版本带版本后缀（六个版本能同时安装，固定名字会让它们的包争同一组文件）。宿主 `GnomePointer.cpp` 用 `G_DBUS_PROXY_FLAGS_DO_NOT_AUTO_START`、40ms 超时同步查询，扩展没启用／总线不可用／超时都返回空并回退到上一版的「光标上方居中」。新锚点 `Kind::ShellPointer` 的菜单左上角：`x = mouse.x + gap`，右边放不下翻到 `mouse.x - gap - menu_width`；`y = mouse.y - gap - menu_height`，全程夹在工作区。扩展给 `(0,0)` 或工作区外的坐标判不可用，回退到工作区中下部。纯 X11 会话不变，仍用 `XQueryPointer` 指针模式。**此版被否**：GNOME Shell 把候选框画成 compositor actor（`IbusCandidatePopup` 继承 `BoxPointer`，加在 stage 的 input panel group 上），画在所有 X11 客户端窗口之上；`xwininfo` 看不到它，`org.gnome.Shell.Eval` 被禁用，侧移鼠标 12/50/60px 实测仍被盖住。鼠标坐标本身给不出候选框的宽度，无法可靠避开这个 actor。
  - **候选框矩形右侧避让（最终方案，取代以上两版）**：根因确定后改为「向 GNOME Shell 扩展要候选框的真实矩形，菜单摆在候选框旁边」。扩展从 `resource:///org/gnome/shell/misc/ibusManager.js` 的 `getIBusManager()._candidatePopup`（BoxPointer actor）取 `get_transformed_position()` + `get_size()`，popup 不可见时返回 `(0,0,0,0)`；D-Bus 方法由 `GetPointer()` 改为 `GetCandidateRect()`（四个 int 出参），总线名与 UUID 保持 `org.msime.Pointer` / `msime-pointer@msime` 不变（已是随包契约，改名会让已启用扩展失效）。宿主 `shell_candidate_rect()` 拿到宽高非正（含全 0）即返回空。锚点枚举收敛为 `{Pointer, CandidateRect}`：删掉 `ShellPointer`（鼠标方案作废）与 `Caret`（不再回退到光标）。`CandidateMenuAnchor::Kind::CandidateRect` 依次尝试候选框的右、左、下、上：取第一个能让菜单完整避开候选框、又夹进工作区的位置，横向摆放时与候选框垂直居中、纵向摆放时水平居中；宽高非正或矩形不完整落在工作区里判不可用。右键入口 `ClientEngine.cpp` 用现成的 `candidate_panel_is_gnome_shell()`（含 `org.gnome.Shell` 总线名确认，能排除 KDE Wayland 与 GNOME Flashback）分流：**仅 GNOME Shell 会话**查候选框矩形，拿到就按矩形摆菜单，拿不到（扩展未启用／D-Bus 超时／候选框不可见）就**不弹菜单**，在辅助区域显示快捷键提示「候选维护：Ctrl+Delete 删除 · Ctrl+↑ 置顶 · Ctrl+1-5 固定 · Ctrl+0 取消固定」（`CandidateMenuHint.h`）；**非 GNOME 会话**（纯 X11 及其它）保持指针模式（`show()` 内 `XQueryPointer` 兜底），不受影响。范围经确认：fcitx5（含 GNOME 下）不引用、不链接这些符号，是独立模块 `msime-fcitx5`，候选由 fcitx5 自身 UI 绘制、右键走 `CandidateAction` 或 X11 原生画布原地替换，不存在 compositor actor 遮挡前提，零行为变化。

原先这些内容写在五笔造词的决策笔记 `2026-11-15-wubi-run-phrase-learning.md` 里。本 PR 独立成篇：造词 PR 不含 Linux 代码，iBus 段落随代码一起归属本 PR；造词笔记恢复为不含 iBus 段落的版本。

## Consequences

- 新增两个纯函数单测：`linux-candidate-maintenance-shortcut`（四键解析、小键盘、修饰组合排除、不抢既有组合键）与 `linux-candidate-menu-items`（文案顺序、勾选、可用性），由 Linux ctest 覆盖。
- 新增 `CandidateMenuPlacement.h` 纯函数与 `linux-floating-panels-model` 中的定位单测：光标居中上方、贴右边缘仍居中并夹在工作区内、贴顶边夹到工作区顶部（已知边界）、全 0/工作区外回退到中下部（断言不落右上角）、指针模式保持原「下方放不下翻上方」。定位从 `CandidateMenuSurface::show()` 的 Xlib 分支抽到纯函数，Xlib 层只负责取工作区与缩放。**最终方案**把锚点收敛为 `{Pointer, CandidateRect}`（删掉 `Caret`/`ShellPointer`），定位单测改为：候选框右侧（垂直居中）、贴右边缘翻左、横向占满时中部退下方/贴底边退上方（均完整避开候选框、夹进工作区）、无效矩形回退工作区中下部、指针模式保持原样。
- 自绘弹层依赖 X11；纯 Wayland 会话下退回候选窗提示条，属已知边界，layer-shell 原生菜单留作后续增强。
- 新增 `GnomePointer.h/.cpp`（文件名沿用，语义已改为候选框矩形）：SessionBus 同步查询助手，40ms 超时、不自动激活服务；`ClientEngine.cpp` 的 GNOME Shell 右键分支查候选框矩形，有效按矩形摆菜单，否则不弹菜单、改在辅助区域显示快捷键提示。`candidate_panel_is_gnome_shell()` 区分 GNOME 与否（比只看 `WAYLAND_DISPLAY` 准，能排除 KDE Wayland）；非 GNOME 会话保持指针模式。
- 新增 GNOME Shell 扩展 `platforms/linux/gnome-shell-extension/msime-pointer@msime/`（`metadata.json.in`、`extension.js.in`），CMake 按版本生成 UUID 与 D-Bus 名后装到 `${MSIME_SYSTEM_DATADIR}/gnome-shell/extensions/<uuid>`，不写用户启用状态、不新增 WebView 或设置页入口。全版本配置各生成一份，full 是 `msime-pointer@msime`／`org.msime.Pointer`，wubi 是 `msime-pointer-wubi@msime`／`org.msime.Pointer.wubi`，互不争文件。扩展在 SessionBus 暴露的 `GetCandidateRect()` 只有 int 出参，返回候选框屏幕矩形。总线名与 UUID 保持 `org.msime.Pointer` / `msime-pointer@msime` 不随方法改名而改，避免已启用用户失效。
- 新增 `linux-gnome-pointer-dbus` 契约测试（目标名沿用）：有 session bus 时起假服务验证矩形读取、候选框不可见（返回全 0）判空、名字释放后返回空；无 bus 时 skip（77）。测试用工作线程调同步助手、主线程泵 D-Bus 事件，否则假服务无法应答。
- 新增 `CandidateMenuHint.h`：`kCandidateMaintenanceShortcutHint` 常量锁定辅助区域提示文案，`linux-floating-panels-model` 断言四个快捷键都在文案里。
- 与造词 PR 无代码依赖：本 PR 的平台代码只碰 `platforms/linux/`，另只改共享能力位与设置页速查声明，独立验证、独立 PR。
- **快捷键提示只写在 iBus 菜单上**：`CandidateActionPolicy.h` 里无后缀的 `candidate_*_label` 恢复成不带快捷键的文案，继续供 Fcitx5 候选菜单与状态区操作使用；新增的 `*_with_shortcut` 只供 iBus「候选操作」属性菜单和右键菜单。最初把共享常量直接改成「置顶 (Ctrl+↑)」等带提示文案，CI 的 `fcitx5-native-context` 随即失败；根因不是测试过期——Fcitx5 没有实现 `CandidateMaintenanceShortcut.h` 这组按键，照搬提示等于在菜单上写出用户按不出的键，和本篇「fcitx5 零行为变化」的范围约定冲突。修的是文案归属，不改旧断言。

## Verification

- 本机 Linux 工具链可用（CMake 4.3.4、GCC 15.3.0、ibus-1.0 1.5.34、nlohmann_json 3.11.3）。手工打出 `msime-linux_0.17.0_amd64.deb`：源码取本分支，编译产物（host-api、MCP、桌面壳、词库/模型）复用主 worktree 已验证的那套（本 PR 不碰 `crates/`，host-api ABI 不变）。`-Wall -Wextra -Werror` 编译 `msime-ibus-host`（含改动的 `ClientEngine.cpp` 与新增的 `CandidateMenuSurface.cpp`）及全部原生测试通过。
- 全量 `ctest`：124 项中 122 项通过。两项 `linux-candidate-native-canvas`（`/...-chrome`）失败是本机字体渲染环境的既有问题——在不含本 PR 改动的基线上以相同断言、相同行号失败（`auxiliary_ink > 10`、`colors(...)[0x808080] > 10`），与本 PR 无关；打包时排除这两项后 122/122 通过，deb 后处理去掉了 Fcitx5 库依赖（`ibus | fcitx5` 保留）。
- `ctest -R 'linux-candidate-(maintenance-shortcut|menu-items)$'`：2/2 通过。前者覆盖四键解析、小键盘、修饰组合排除、不抢既有组合键；后者覆盖文案顺序、勾选与可用性。2026-11-25 改键后同两项与 `linux-candidate-action-policy` 重新通过：解析测试先出红灯（新用例要求第三个键码参数，旧函数编译失败；临时去掉该用例后，旧函数仍让 `Ctrl+1` 固定的断言以 `SIGABRT` 失败），实现后覆盖 `Ctrl+1..5` 不固定、`Ctrl+Shift+1..5` 与小键盘固定、美式 Shift 符号与键码 2..6 映射；另外两项旧文案断言在改文案前失败，改后通过。设置页速查的 Vitest 同法先红后绿，断言 `Ctrl+Shift+1–5` 出现且 `Ctrl+1–5` 消失。改键后另跑了完整 Linux 原生门禁：`cargo build -p msime-host-api --locked`、`cmake -S platforms/linux -B target/linux-gate -DMSIME_ENABLE_FCITX5=ON`、`cmake --build target/linux-gate -j4`、`ctest --test-dir target/linux-gate --output-on-failure`，125 项中 123 项通过；`linux-candidate-native-canvas` 与 `linux-candidate-native-canvas-chrome` 的像素断言在本机确定性失败（辅助区字号颜色计数不足），两份测试源码都不包含本次改动的头文件，与本轮改键无关。`scripts/verify-local.sh --quick` 的其余阶段（contract、Rust workspace、Linux desktop shell）实际跑过且无 `FAIL:`；其 `crash-symbols.py` 打印的失败来自本机 binutils 2.47 的 `readelf -h -n` 不再输出 `Machine:` 行，也与本轮无关。

## Alternatives considered

- 给 IBus 面板加逐候选属性菜单入口——IBus 属性菜单是全局菜单，动态逐候选绑定要维护额外的属性树且与桌面面板渲染耦合；自绘弹层照搬已有的工具栏菜单栈更省。
- Wayland layer-shell 原生菜单——X11 弹层在 Xwayland 下就够用，layer-shell 留作后续增强，不影响本次验收。
- 定位方案（本轮收敛）：光标锚定 + 守卫 + 菜单放在光标上方居中。否掉的四条——(1) Wayland 下把菜单固定放在工作区中上部：最稳、绝不会跑到角落，但完全不跟随输入光标，用户明确要靠近候选行；仅在锚点守卫判不可用时作为回退形态使用。(2) 光标侧方摆放（右方 12px、整体右移 50px/60px）：实机读到 `(620,392)`→`(680,392)`，报告者确认仍被 GNOME Shell 候选框盖住；候选框横向较宽，X11 窗口压不过合成器 actor，侧移无法解决。(3) GNOME Shell 扩展取光标 stage 坐标（参考 WindInput 的 `org.windinput.Caret`）：能拿到精确坐标，但当时判断属新增 GNOME 专属组件、只覆盖 GNOME 不覆盖其它 Wayland 合成器，超出本 PR 范围而未采纳；报告者随后明确要求以真实鼠标为基准并同意把扩展并入本 PR，故改为新增扩展取鼠标坐标、未启用时回退光标，仍不覆盖非 GNOME 的 Wayland 合成器（那里退回光标方案）。(4) IBus 原生 `candidate_actions()` + `property_list` 由面板画：代码已有此能力，但 `publish_mode()` 在 GNOME 下刻意不注册；GNOME 把 IBus properties 画在输入法状态菜单而非候选框旁，历史上还引发 Shell actor/GC 抖动到桌面冻结。选「光标上方居中」是因为候选框在光标下方，垂直区间分离后 X11 菜单不必与合成器 actor 争层级，交互和快捷键都不变；代价是 `engine->cursor_area` 在 Wayland 下可能是表面局部坐标，靠「必须完整落在工作区内」的守卫拦截，拦不住的边界情况仍可能摆偏，故保留工作区中下部回退；光标贴屏幕顶边时菜单夹到工作区顶部、可能部分越过光标，属已接受的边界。最终收敛为「鼠标右上方（GNOME 扩展）＋ 光标上方居中回退」：真实鼠标比光标更贴合用户右键位置，右侧展开、上方避开候选框；代价是扩展需用户手动启用、只覆盖 GNOME，故保留光标方案作回退。否掉「扩展取光标坐标」而非「扩展取鼠标坐标」的理由：用户点的就是鼠标位置，鼠标与光标在长文本里可能相距很远，取光标仍不贴合。原「光标上方居中」的取舍（垂直区间分离、工作区守卫与中下部回退、贴顶边界）在回退路径上继续成立。
- 定位方案（最终收敛）：候选框真实矩形 + 右侧→左→下→上避让，拿不到矩形就不弹菜单、改在辅助区显示快捷键提示。否掉上一版「鼠标右上方（ShellPointer）＋ 光标上方居中（Caret）回退」的理由：报告者实测鼠标右上方仍被 GNOME Shell 画的候选框盖住——候选框是合成器 actor（非 X11 窗口），`xwininfo` 看不到、`Eval` 被禁用，侧移 12/50/60px 均失败；鼠标坐标给不出候选框宽度，无法可靠避开它。光标矩形同样只是估计、拿不到候选框实际边界，且 Wayland 下可能是表面局部坐标。改用扩展读 `_candidatePopup` 的真实矩形后，菜单能确定地摆在候选框外；拿不到矩形（扩展未启用／超时／不可见）时，与其猜一个位置弹出来被盖住或挡住正文，不如不弹菜单、在辅助区给出四个维护快捷键让用户自己操作——这些键是宿主固定处理、必存在的。「拿不到就不弹」否掉了「拿不到时回退到光标或工作区中下部弹菜单」：后者在 GNOME 下正是被遮挡或被报告为「位置不对」的来源。范围只锁 GNOME Shell 会话（用 `candidate_panel_is_gnome_shell()` 判定，含总线名确认），KDE 等桌面与纯 X11 保持指针模式不变；fcitx5（含 GNOME 下）走独立模块、候选由自身 UI 绘制，无合成器遮挡前提，无需改动。
- 固定排位继续用 `Ctrl+1..5`：不采纳。用户确认这五个组合都已被别的功能占用，继续用会在维护候选时抢掉原有功能；改成 `Ctrl+Shift+1..5` 只让固定这一项让开，置顶、取消固定、删除不变。没有改其它宿主对 `Ctrl+1..5` 的处理，也没有把新键扩散到 Fcitx5——它从来没有这组维护键，菜单照旧不标快捷键。
