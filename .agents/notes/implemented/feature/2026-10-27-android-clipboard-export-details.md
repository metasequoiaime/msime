# Agent Note: Android 剪贴板导出记录详情

Status: implemented

## Problem

#9964 要求 Android 导出的记录文本带官网、项目链接与每条记录的完整时间，并在能取得时标明复制来源应用和包名。原有导出由共享 client-core 返回正文和置顶标记，历史条目虽保存时间戳，文本快照却没有它。

## Decision

Android 导出继续先检查实时隐私开关，并在文件公开前再检查一次；目录授权、文件名和写入流程沿用[原导出决定](2026-10-16-android-clipboard-export.md)。此平台读取共享存储返回的有序条目快照，再在 Android 宿主生成供人阅读的 TXT：文件头带官网和项目链接，逐条写置顶标记、本地时区的完整记录时间、来源字段和未经修改的正文。时间缺失时写“时间未知”。共享 `export_text` 仍供其他宿主使用，不改它的格式。 全量导出与面板多选导出都从同一份结构化条目快照筛选后进入 `ClipboardExportFormat`：`selectedTexts` 为 `null` 时保留全部，空选择导出为空，其余按共享历史顺序匹配原文；不使用缺少时间戳的预格式化 `Export(text, count)`，避免多选接线覆盖记录详情。

Android 的公开 `ClipboardManager` 和 `ClipDescription` 不能给出可靠的复制来源包名。导出里的来源 App 和包名写“系统未提供”，绝不把粘贴目标的包名或剪贴板标签当作复制来源。待有可信来源并写入共享条目后，格式可以原位填充这两个字段。

历史页的全量导出按钮与搜索框同放在固定导航中，搜索框占用剩余宽度，导出按钮保留独立触摸区域。`DetailPage` 在页面提供固定导航时会隐藏原有标题栏，因此不能再把导出按钮放进 `headerActions()`；这里只调整历史页，不改变其他详情页的标题与导航约定。

设备验收把 SAF 文档创建和写入结束分开等待。`createDocument` 返回后，空文档已经能被列出和读取，文件数增加不能充当全文已写完的信号。合成提供方用 `ParcelFileDescriptor.OnCloseListener` 报告写入流关闭；测试随后一次性核对条数、详情、置顶顺序和完整 Unicode 正文。键盘导出场景先用跨进程门闩暂停写入，确认新文档确实为空，再放行并等待关闭，使旧等待方式的竞态成为确定性回归。探针只在测试 APK 中，不进入产品，也不改真实存储提供方的行为。API 29 起的默认 Download 路径继续等待 `IS_PENDING` 清除。

API 34 起，控件查找在缓存树中找不到目标时清空无障碍缓存，再观察当前窗口；不重新点击、不延长等待，也不重试整套用例。动态短提示会在缓存未更新时被遗漏。首次 SAF 授权之前不访问合成提供方探针；脚本清空了提供方数据，API 28 首份文本从已知为 0 的关闭计数开始，在授权后等待首个正常关闭事件。

## Alternatives considered

- **直接修改共享 `export_text`**：实现行数少，但所有平台的既有导出格式都会改变；需求只指向 Android，平台内格式化更符合范围。
- **从现有 TXT 解析元信息再补充**：已有快照没有时间戳，解析分隔行还会把包含同样文本的原文误识别为记录边界，因此直接格式化结构化条目。
- **使用当前编辑器包名补来源**：复制与粘贴可能来自不同应用，会制造错误记录，因此不用。
- **让 `DetailPage` 同时显示固定导航和原有标题栏**：可保留原来的按钮接线，但会改变所有固定导航详情页的标题布局；历史页在自己的导航中放置按钮即可恢复入口，影响范围更小。
- **反复重试全文断言，直到文件看起来完整**：可以容忍提供方慢写，但会把正文校验当成时序同步，难以区分迟到与内容损坏；改为等待真实关闭事件，内容断言仍只执行一次。

## Consequences

Android 导出文件可直接用于回看记录时间和项目来源，正文与历史顺序不变；其他宿主的格式仍保持原样。宿主多一份阅读格式实现，并需要在读取结构化快照时取得分类目录，分类存储损坏时导出同样报读取失败。来源应用和包名仍未真正取得，#9964 只能部分完成。

## Verification

#10215 的原运行只报告合并后的全文断言失败，没有记录当时的文件长度，不能据此反推出是哪一项内容不同。本机 API 35 在当前源码完整重编的 APK 上，用写入门闩稳定重放同一窗口：旧的文件数等待在 `real keyboard panel export control` 阶段以 `snapshot count; bytes=0` 失败；选择目录和第一次导出已经通过。这确认了验收确实能把尚未写入的文件误判为快照损坏。

当前源码完整构建 Rust/JNI、锁定词库与原生 APK，完整 API 35 `clipboard-export.sh` 的 select、verify 两阶段退出码均为 0。选择阶段记录 2 次、验证阶段记录 7 次缓存查找失败后刷新即可找到控件的观察；此前未刷新时重复停在无系统认证的短提示断言。中途主动结束的两轮不计通过；首次引入探针时 API 28 在授权前访问提供方导致的 `SecurityException` 也不计通过。本地 quick、NDK/JNI、JVM 宿主检查与笔记门禁通过；API 28 的完整复验单独记录。

`ClipboardExportFormatSmoke` 用合成 Unicode、换行、固定项和缺时间记录检查格式与顺序，并覆盖全量、空选择、逆序选择、重复与失效选择以及筛选后元信息保持。`platforms/android/check-host.sh` 通过 287 项 JVM 冒烟、246 份设备测试源码编译及 Java/API、清单和资源检查；`pnpm run verify-notes` 通过。

API 35 专用模拟器上的完整 `clipboard-export.sh` 通过 select 和 verify 两阶段，覆盖默认 Download 与 SAF 目录、重启后导出、真实键盘和历史页导出、认证中断重入、目录取消、撤权、删除、故障以及新增详情和正文断言。修复前的真实设备用例停在历史页导出认证中断场景，找不到隐藏标题栏中的导出按钮；移入固定导航后完整复跑通过。最终 APK 的增量 Gradle 构建通过，原生库和 host-assets 复用 `734b` 世界时钟任务已构建的缓存，并非本分支 Rust 全量编译；API 28 未补跑。本机 quick 因系统盘空间不足在契约阶段中止，未完成，不计通过。
