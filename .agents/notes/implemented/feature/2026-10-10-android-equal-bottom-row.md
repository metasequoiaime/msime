# Agent Note: Android 键盘底行默认与字母行同高，并分摊键盘高度调整

Status: implemented

## Problem

Android 键盘的底行（123、中/英、空格、换行那一行，以及 123 / #+= 层自带的那一行）比上面的键矮一截。键行来自 `KeyboardGeometry.KEY_ROW_HEIGHT_DP`（56 dp，另加一份行距），底行来自 `STANDARD_ROW_HEIGHT_DP`（46 dp，不加行距）；键帽在行里上下各让出半份行距（默认 3.5 dp），所以默认时字母键帽 56 dp、底行键帽 39 dp。#6354 说九宫格第四行点起来「像减速带」，#6472 说底栏的中/英键面积太小。

56 dp 来自 #3782 的改版：按设计的 46 dp 排，九宫格的键像横条，于是所有布局的键行一起加到 56 dp，底栏留在设计键高 46 dp。仓库里没有任何地方写明底行应该比键行矮，iOS 和 HarmonyOS 都是四行同高：iOS 的 `KeyboardViewController` 让数字行、字母行、符号行都等于 `actionRow` 的高度，九键块是它的三倍加 14；HarmonyOS 的 `KeyboardMetrics.totalHeightVp` 是 `ROW_HEIGHT_VP × KEY_ROWS`（4 行）加调整量。

底行也不跟着键盘高度走。`ImeStyler.applyKeyboardHeight` 给底行角色固定高度，整份调整量都给了上面的键行，于是调得越高差距越大：160% 时底行键帽 39 dp，字母键帽 92–93 dp。这条「底栏不分摊调整，调矮时换行键不被压扁」的约定出自 [2026-10-08-android-keyboard-height-range](2026-10-08-android-keyboard-height-range.md)，可当时的压扁其实是 123 层底栏挂了 `rowCount` 为 1 的高度角色、在三行之外又拿了一遍整份调整：75% 的 −46 dp 把 46 dp 的底栏压成 0。四行均分时它在 75% 分到 −12 dp，和字母行一样还剩 40 dp。

[2026-10-09-android-tall-bottom-row](2026-10-09-android-tall-bottom-row.md)（#6488）加了一个默认关的本地开关「加高底行」：打开后底行 56 dp 加一份行距，键盘整体高出约 17 dp，仍不分摊调整，所以只有 100% 时底行和键行同高。维护者看过之后决定改成默认同高、总高不变、取消开关，本篇取代那一篇。

## Decision

- 键区四行一样高：`KEY_ROW_HEIGHT_DP` 从 56 改为 52，字母行、数字层前三行、九键 / 笔画 / 手写 / 大千四行这类三行高的键块的每一行，以及底行，都是 52 dp 加一份行距。`STANDARD_ROW_HEIGHT_DP` 和 `bottomRowHeightDp` / `bottomRowSpacings` 删去，底行的高度角色 `KeyboardHeightRole.bottomRow()` 是 52 dp、一份行距。
- 默认行距（7 dp）下键区 4 × 59 = 236 dp，原来是 3 × 63 + 46 = 235 dp。字母键帽 56 → 52 dp，底行键帽 39 → 52 dp。
- 键盘高度调整由四行均分（`KEYBOARD_ROW_COUNT = 4`）：底行分到 `KeyboardGeometry.bottomRowAdjustment` = `floorDiv(调整量, 4)`，即把底行当作四行里的最后一行时 `adjustedRowHeight` 给它的那一份；底行以上的键行和三行高的键块分其余部分 `keyRowsAdjustment` = 调整量 − 底行那份，在三行之间照旧把余数给前面的行。两份相加恰好是整份调整量，所以总高、`HEIGHT_PERCENT_BASE_DP`（184，1% = 1.84 dp）、−46…110 的存储范围和 `windowHeightAdjustment` 的窗口封顶都不变，存着的设置值意义不变。
- 日语九键、注音九键没有单独的底行，四行都在一块里（`KeyboardHeightRole.threeRowsWithBottomRow()`）：块是 4 × 52 dp、四份行距，拿整份调整，和三行加底行的布局总高相同。
- 数字行（#6022）沿用第一行字母的份额，键盘照旧整体高出一行。底部留白（#6392）和键盘底栏是键区下面的固定内边距，不参与这套分摊。
- 「加高底行」（`platform.android.tall_bottom_row`）整个移除：设置项、设置页开关、搜索关键词、服务里的字段和 styler 参数。它没有进过任何发布，不做迁移。`AndroidLocalSettings.decode` / `accepted` 丢掉不认识的键，读取不会失败，下一次写入时这个键随之从文件里消失；本地备份恢复（`LocalBackup.restoreSettings`）按 `specs()` 逐键收，不认识的键跳过，导出只导 `explicit()` 里认识的键。

各高度调整下的行高（dp，不含行距）：

| 高度 | 调整量 | 三行键 | 底行 | 四行合计 |
| --- | --- | --- | --- | --- |
| 75% | −46 | 41 / 41 / 40 | 40 | 162 |
| 100% | 0 | 52 / 52 / 52 | 52 | 208 |
| 130% | 55 | 66 / 66 / 66 | 65 | 263 |
| 160% | 110 | 80 / 80 / 79 | 79 | 318 |

## Alternatives considered

- **保留默认关的「加高底行」开关**（#6488 的做法）：对现有用户零变化，喜欢矮底行的人照旧，想要同高的人自己打开，风险最小，以后还能只改默认值。不用它，是因为它只在 100% 时对：开关打开后底行固定 56 dp 不分摊调整，75% 时底行键帽（56 dp）比字母键帽（40–41 dp）还高，130% 时又比字母键帽（74–75 dp）矮一截，用户换个高度就又不齐。默认关还意味着报告问题的人和绝大多数用户都碰不到它，设置页多一个需要解释「键盘会高出 17 dp」的开关。iOS 和 HarmonyOS 没有这个开关，三端的键盘应该长成一个样子。
- **底行加到 56 dp，键盘整体高出约 17 dp**：保住 #3782 刚加到 56 dp 的字母键和九宫格键，每一行的触控面积都比现在大，也不用动其他行。不用它，是因为每个用户的键盘默认都高出 17 dp，竖屏手机上候选区和输入框被往上挤；横屏手机窗口只有 360–410 dp，键盘高度封顶的 14% 是按现在的总高调出来的。想要更大的键可以把键盘高度调高，四行一起变大，比默认就加高更可控。字母键从 56 dp 降到 52 dp，仍比 #3782 嫌扁的 46 dp 高出 6 dp。
- **底行同高但继续不分摊调整**：保留 [2026-10-08-android-keyboard-height-range](2026-10-08-android-keyboard-height-range.md) 的「调矮时换行键不被压扁」，75% 时底行仍有 52 dp。不用它，是因为这又只在 100% 时同高，和开关的毛病一样；那条约定要防的压扁来自 123 层底栏拿了整份调整（压成 0 dp），四行均分时底行在 75% 还有 40 dp，与同一高度下的字母行相同，而字母键在 75% 一直就是这个高度。
- **只加高九宫格的底行**：#6354 只提了九宫格。但 26 键和九宫格用的是同一条功能行，切换布局时一条高一条矮，键盘高度会跳。
- **百分比基准改成 4 × 52 = 208 dp**：让「100%」对应的 dp 数和画出来的键高对上。不改，是因为存着的是 dp 调整量，换基准会让每个用户已存的百分比显示成另一个数，窗口封顶的 130%（55 dp）也要跟着重算；184 dp 只是换算常数，1% = 1.84 dp 的拖动手感保持不变更重要。

## Consequences

- **收益**：所有布局默认四行同高，底行键帽从 39 dp 到 52 dp，中/英、空格、换行更好按；调任何高度时底行都和字母行一样高（最多差 1 dp 的取整），与 iOS、HarmonyOS 一致。键盘总高不变，用户不需要重新调高度。设置页少一个开关，高度规则只有 `KeyboardGeometry` 里的两个纯函数。
- **代价**：字母键和九宫格键默认矮 4 dp，调高或调低时上面三行分到的调整也少了四分之一（75% 时字母行 41 / 41 / 40 dp 不变，160% 时从 93 / 93 / 92 降到 80 / 80 / 79）。打开过「加高底行」的用户（只有 develop 上的测试构建）键盘会矮回 17 dp。如果有人反馈默认字母键太矮，先看是不是要把整体默认高度（而不是哪一行）调高，那要改 `KEY_ROW_HEIGHT_DP` 并重看窗口封顶。

## Verification

- `KeyboardGeometrySmoke` 钉住 52 dp、四行、默认 236 dp，以及 75% / 100% / 130% / 160% 每一行的高度；对 −46…110 的每个调整量核对四行合计、三行高的键块加底行、连底行的四行块都等于 4 × 52 + 调整量，行与行最多差 1 dp。`AndroidLocalSettingsSmoke` 核对 `platform.android.tall_bottom_row` 不再是设置项，读取时和不认识的键一样被丢掉。都由 `platforms/android/check-host.sh` 运行。
- 设备上 `KeyboardHeightDeviceSmoke`（`smoke.sh emulator-5580`）在默认、75%、130% 三档核对空格键和「n」同高（差不超过 1 dp 加 2 px），并在默认高度核对从「q」上沿到空格下沿是 229 dp（四行 52 dp 加三份行距）。
