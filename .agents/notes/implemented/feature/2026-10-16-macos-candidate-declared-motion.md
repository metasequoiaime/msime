# Agent Note: macOS 候选窗只播放皮肤清单写出的动效

Status: implemented

本篇的候选界面动效决定由[所有平台的候选立即呈现](../simplification/2026-10-30-candidate-immediate-presentation.md)取代，macOS 也忽略显式预设。共享清单声明标记、同步状态和装饰图自身的播放规则继续成立。

## Problem

#7760（外部用户）报告：从 0.53.0 起，候选窗每次出现都要淡入，打字快的人来不及看清，而 macOS 自带输入法和搜狗都没有这种动画。[即时显隐决定](../bug-fix/2026-10-14-macos-candidate-instant-display.md)因此让 macOS 完全不执行皮肤动画，但这样一来，明确要求动效的皮肤在 macOS 上也什么都不播。共享的[动效契约](../architecture/2026-10-13-candidate-skin-v2-motion-contract.md)在 Windows 和 Web 上仍然有效。

#7760 有两个根因：

- **默认组合**：v2 包省略 `[animation]` 时，共享解析器补上活泼默认组合（进场 `fade_scale`、退场 `fade`、选中 `spring`、180ms、错峰 14ms）。所以用户没要求过的动画在每个词出现时都播一遍。
- **异步显隐**：旧实现靠 `NSWindow` 的 `alphaValue` 动画淡出，退场期间 `isVisible` 一直是 YES。数字、空格、方向键和指针都被路由到即将消失的旧候选上。

## Decision

macOS 只播放皮肤清单 `[animation]` 表里显式写出的预设。显示、隐藏和选中状态的变化都是同步的，动画只是加在 Core Animation 图层上的装饰。

### 声明标记

- `crates/client-services` 的 `SkinAnimation` 带一个 `declared` 字段，序列化为 `{"enter","exit","selection"}` 三个布尔值。
  - 只有清单表里实际写了的键才为 true。
  - 补上的默认值，包括 `lively()` 整组默认，一律为 false。
- 已解析的预设值和其他宿主的行为不变。Windows、Web、鸿蒙和设置页都忽略这个附加字段。
- macOS 的 `AnimationFromJSON`（`SkinManifestBridge.mm`）把未声明的预设读成 `none`。没有 `declared` 字段的旧库也按 `none` 处理。
- `duration_ms` 和 `stagger_ms` 是参数，不是动画。某个预设写了而时长没写时，沿用解析器给的 180ms 和 14ms，只写一个 `enter` 也能播放。
- 内置主题、不画包的明暗、省略 `[animation]` 的 v2 包，以及把三个预设都写成 `none` 的包，都是即时显隐。

### 同步状态与图层动画

两条渲染路径共用 `MSIMECandidateMotion`（`platforms/macos/src/candidate/CandidateMotion.mm`）：IMK 产品用的 `InputController` 和只在测试里编译的 `MetasequoiaCandidatePanel`。所有显示都经过 `showPanel:`，没有调用点能绕过它直接 `orderFrontRegardless`。

- **显示与隐藏**
  - `orderFrontRegardless` 和 `orderOut:` 立即执行。
  - 窗口的 `alphaValue` 始终为 1，`animationBehavior` 始终为 None。
  - 因此候选窗的 `isVisible` 永远是唯一真相，键盘路由、指针处理、翻转记忆和 VoiceOver 都不需要知道有动画。
- **动画加在哪里**：进场和退场加在内容视图（卡片）的图层上，错峰加在候选行的图层上。模型值始终是最终状态，所以撤掉动画永远回到完整显示。
- **进场时的窗口阴影**：窗口服务器不会跟着图层透明度重算阴影，所以进场期间关掉窗口阴影，进场结束时恢复。
- **进场途中重建**：打字时每个键都重排整页，重排出来的卡片和候选行接着同一条时间线播完，既不重播，也不跳到不透明。`InputController` 每次换一个新内容视图，卡片和各行都重新加；`CandidatePanel` 在同一张卡片里重建候选行，只给还没在浮现的新行补上错峰。新的一页行数更多时，进场的结束时间顺延到最后一行播完，仍然不超过 `duration_ms` 加 80ms。
- **候选行的图层是惰性建的**：卡片是图层宿主，但 AppKit 要到这轮事件结束时的绘制才给它的子视图建图层、挂到卡片图层下面。`InputController` 每次排版都换新内容视图，显示和选中装饰又在同一轮事件里发生，这时候选行还没有图层，错峰和选中装饰都会落空。所以要加错峰或选中装饰、而行还没挂上图层时，先对已经上屏的面板做一次 `displayIfNeeded`。这次绘制本来就要在这轮事件结束时发生，提前做不多花时间；不播这两种动效的皮肤（包括所有默认皮肤）从不走这一步。

### 退场

退场只用于普通收起，也就是 `empty`（上屏或取消后没有候选）和 `english_mode`。失焦、会话替换、被别的控制器接管、光标无效、找不到屏幕和模式切换都立即收起。这些隐私相关的原因还会立即撤掉正在播放的退场，屏幕上不留旧候选文字。

退场的过程如下：

1. 候选窗本身立即 `orderOut`，换上一个空内容视图。
2. 旧内容视图移进一个独立的退场窗淡出。退场窗不接收鼠标，不能成为 key window，也没有窗口阴影。
3. 退场完成回调带代次令牌。令牌对不上就什么都不做，所以迟到的回调永远收不起后来又显示的候选窗。

退场期间的其他情况：

- **再次显示**：先把候选窗摆上屏幕，再撤掉退场窗。候选窗以完整不透明度出现，不播进场。
- **重复收起**：已经收起时再收一次，比如上屏后又按了一个没有候选的键，不会重新开始退场。

### 连续输入

候选窗收起后 400ms 内再次出现，算同一段连续输入，不播进场。

这个阈值的依据是：Dhakal 等人在 CHI 2018 分析了 1.36 亿次击键，平均击键间隔约 240ms。上屏键到下一个声母之间还会多停一点，超过 400ms 才算用户停下来看。仓库里没有可复用的实测击键间隔，打字特效的 3000ms 连击窗口是另一回事。

### 选中

- **高亮立即移动**：高亮和选中状态在同一帧里同步画好。
- **触发条件**：高亮在同一个输入串的同一页里换了格位才装饰，也就是方向键、Tab 和网格里的移动。按格位比较而不按候选身份比较，所以打字换出新候选不会重播；打字或翻页时 Engine 把高亮放回第一格，那不是用户的选中，也不装饰。`CandidatePanel` 只在 `selectCandidateWithIdentifier:` 时装饰，两条路径一致。
- **装饰方式**：在新高亮行的图层下面插一个底色图层，动画期间由它接管行的高亮底色，行只画文字和选中条。文字从不变淡，也从不缩放，对应 Windows 只动高亮底色的做法。
- **结束**：动画结束、高亮再移动、页面重排或收起时，都撤掉这个图层，行重新自己画底色。

### 减弱动态效果

- 读取 `NSWorkspace.accessibilityDisplayShouldReduceMotion`，并监听 `NSWorkspaceAccessibilityDisplayOptionsDidChangeNotification`。
- 打开时什么都不播。正在播放的进场、选中装饰和退场窗会立即结束。
- 测试直接设置 `reduceMotion`，不依赖测试机器的系统设置。

### 不加新的用户设置

不新增用户设置。是否有动画由用户选的皮肤决定。

## 预设映射

时长限制在 40–600ms。进场一律用 ease-out，退场一律用 ease-in。

进场原先照搬 Web 候选栏的 `cubic-bezier(.16, 1, .3, 1)`，装到真机上用户报告「完全没有动画」。诊断日志（`candidate motion show=enter … skin=… enter=slide_up duration_ms=200`）证明皮肤数据到了、进场也决定播放，问题在曲线：200ms 里第一帧就走完 44%，第三帧 83%，上浮和淡入在三帧内结束，看起来就是瞬间出现。换成 ease-out 后第二帧约 26%、第五帧约 59%、170ms 到 96%。当初以为曲线可以照搬，是因为测试只断言图层上挂了动画，不看每一帧画到哪里；`candidate motion` 这行诊断日志随这次修复留下，以后动效「看不见」时先读它。

| 预设 | 进场（卡片） | 退场（卡片） | 选中（高亮底色） |
|---|---|---|---|
| `fade` | 不透明度 0→1，ease-out | 不透明度 →0 | 底色不透明度 0.45→1 |
| `fade_scale` | 不透明度 0→1，以中心从 0.96 放大到 1，各行错峰 | 不透明度 →0，缩到 0.96 | 同 `fade` |
| `slide_up` | 不透明度 0→1，从下方 8 点升起，各行错峰 | 不透明度 →0，向下沉 8 点（Web 的倒放） | 同 `fade` |
| `spring` | 不透明度 0→1，缩放 0.96→1.004→1 | 同 `fade_scale` | 底色缩放 0.94→1.025→1 |
| `glow` | 不透明度 0.82→1（同 Windows） | 不透明度暗到 0.82 后整张收起 | 底色不变，强调色描边不透明度 0.65→0 |

错峰只用于 `fade_scale` 和 `slide_up`，与 Web 相同。每行不透明度 0→1，并从下方 3 点升到原位。第 i 行延迟 `min(i × stagger_ms, 80ms)`，所以再长的一页，进场也最多比 `duration_ms` 多 80ms。

位移的方向看父图层：图层变换里的平移落在父图层的坐标系里。候选行是翻转视图（`NSButton`），它自己的图层 `contentsAreFlipped`，而卡片图层不翻转；按行自己的图层取方向会让行从上方掉下来。

各预设偏离 Web 或 Windows 的地方，都来自 AppKit 的限制：

- **卡片会被窗口边缘裁掉**：窗口正好和卡片一样大，卡片越过窗口边缘的部分会被裁掉。
  - 所以 `spring` 进场的回弹只到 1.004，接近 Windows 的千分之几，没有用 Web 的 1.025。
  - `fade_scale` 不像 Web 那样加 5 点位移。
  - `slide_up` 起止几帧被裁掉的部分不透明度很低。
- **没有提亮滤镜**：图层上没有 Web 的 `brightness` 滤镜，所以 `glow` 进场按 Windows 的 0.82→1 不透明度处理。

## Alternatives considered

- **macOS 保持完全静态**（2026-10-14 的决定）
  - 最强理由：实现最简单，不可能重现 #7760，而且 macOS 自带输入法和搜狗都没有候选窗动画。
  - 不采用的原因：#7760 的两个根因（隐式默认组合、异步显隐）都可以单独解决。完全静态会让明确写了 `[animation]` 的皮肤在 macOS 上失去契约里的一整类能力，而 MCP 的 `make_skin` prompt 正是让作者写这张表。
- **只保留选中动效**
  - 最强理由：选中只发生在已经可见的候选窗里，从不推迟候选窗出现，风险最小。
  - 不采用的原因：契约里的进场、退场、选中是三个独立字段，写了进场的作者在 macOS 上会悄悄什么都得不到。有了连续输入规则和同步显隐，进场已经不会拖慢输入。
- **照搬共享的隐式活泼默认**
  - 最强理由：与 Windows 和 Web 完全一致，一条规则走遍所有宿主。
  - 不采用的原因：这正是 #7760。没要求过动画的皮肤在每个词出现时都播一遍，而 macOS 用户拿来比较的是系统输入法。
- **加一个用户开关**
  - 最强理由：让用户自己决定要不要动画。
  - 不采用的原因：设置项正在精简。选择皮肤本身就是开关，无障碍需求由系统的减弱动态效果覆盖。
- **退场时候选窗留在屏幕上，改用逻辑可见标志**
  - 最强理由：与 Windows 相同。Windows 在同一个窗口里画退场快照，逻辑上已经隐藏。
  - 不采用的原因：控制器里约 40 处用 `_panel.isVisible` 做路由（数字选词、空格、方向键、指针、翻转记忆、VoiceOver），每一处都要换成同一个标志；`ShortcutTest` 的替身面板还直接设置 `visible`。漏掉一处，就是 #7760 那种吞键。把内容移进独立的退场窗，`isVisible` 仍然是唯一真相。
- **重新用 `NSWindow.alphaValue` 动画**
  - 最强理由：窗口阴影能跟着一起淡出。
  - 不采用的原因：这是 0.53.0 的实现。动画由 AppKit 在主线程驱动；隐藏又显示时，淡出会继续把新显示的窗口带到透明（按代码推断，旧 `CandidatePanel` 会停在 alpha 0）；显隐也会依赖动画完成回调。

- **维持单个大排版测试，只延长等待或提高进程活动优先级**
  - 最强理由：不改测试入口，慢速 CI 能得到更多完成回调的时间。
  - 不采用的原因：活动优先级的连续通过未能在后续重复中保持；扩大等待也不能防止几何矩阵持续增长后超过 CI 的 20 秒单项时限。按矩阵拆分进程保留原断言与时限，失败还能直接定位到对应的绘制字段。

## Consequences

收益：

- 写了动效的皮肤在 macOS 上重新有进场、退场、错峰和选中动效，语义与 Windows、Web 一致。
- 默认皮肤、内置主题和省略 `[animation]` 的 v2 包保持即时显隐。
- 快速输入时，候选窗在退场中或刚收起后重新出现，直接以完整状态显示。
- 任何时刻按键和点击都作用于屏幕上真实的候选窗，从不作用于正在消失的旧页。

代价：

- **作者需要显式写出预设**：同一个 v2 包，省略 `[animation]` 在 Windows 和 Web 上会动，在 macOS 上不动。作者想在 macOS 上要动效，必须显式写出预设。用 MCP 做皮肤的 agent 也是作者：`list_candidate_skins` 的 `animation` 报的是补好默认之后的预设，所以同时带上 `declared`，标出哪几个是清单写出来的，否则 agent 会把省略后的默认组合当成皮肤在 macOS 上的动效；`create_candidate_skin` 的说明和 `make_skin` prompt 也要求三个预设都显式写出。
- **选中的触发比 Windows 和 Web 窄**：那两边只比较高亮格位，打字让高亮回到第一格时也播选中；macOS 只在用户移动高亮时播。
- **阴影突然出现**：进场结束时窗口阴影是突然出现的。
- **退场窗口的副作用**：
  - 退场窗没有阴影。
  - 打字特效的上屏闪光如果正好插在卡片里，会跟着进入退场窗。
- **新增预设或改映射**：要同时改 `CandidateMotion.mm`、`shared/candidate/CandidateMotionRules.h`（Linux 原生画布按它逐帧采样，时长与幅度常量两边共用）、本笔记的映射表和 `candidate-panel` 测试。

测试：

- **`candidate-panel`** 用一个写了 `[animation]` 的皮肤包和一个没写的 v2 包，验证以下几点：
  - 显式写出的进场、错峰、选中和退场在图层上播放。
  - 隐藏后面板立即不可见，退场窗不接收鼠标。
  - 进场途中在同一张卡片里重建的候选行接着错峰。
  - 退场中重新显示时立即撤掉退场，迟到的完成回调收不起面板。
  - 400ms 内再次出现不播进场。
  - 减弱动态效果会立即结束并禁止全部动画。
  - 高亮同步移动，选中装饰不碰行里的文字。
  - 隐式默认和默认主题都是即时显隐。
- **`candidate-row-layout`** 守住控制器在没有皮肤包时的即时路径：alpha 为 1，没有缩放、进场或选中动画。**`candidate-declared-motion`** 用一个写了 `[animation]` 的皮肤包和真正上屏的产品面板走一遍 `InputController` 的动画路径：每次排版换新内容视图之后，各行立即有错峰，错峰总延迟不超过 80ms，行和 `slide_up` 卡片都从下方升起；整页重建换高亮时新高亮行立即被装饰；打字让高亮回到第一格时不装饰；进场途中换成行数更多的一页时，后来的行不被提前撤掉；减弱动态效果时什么都不播。
- **异步完成与连续输入分开验证**：`candidate-panel` 等待退场窗真正撤销，`candidate-declared-motion` 等待选中装饰和行底色归位，不把一次固定时长的 run loop 当成完成信号。连续输入专项在退场结束后通过 KVC 提供刚隐藏的内部时间夹具，再走实际显示路径并断言 `show=burst`，排除因其他条件禁用进场而误通过；不把 CI 调度退场回调的时间算进这个 400ms 前提。仍断言动画和窗口状态，不重试、不跳过。
- **验证记录**：CI `39243613593` 的 153 项中，候选窗连续输入与选中装饰结束断言失败，其余 151 项通过；原两项在本地独立运行通过，源码显示固定 run loop 等待同时承担了异步完成与上限计时，改为状态等待和独立时间夹具后，本地完整原生套件 153 项全部通过，`scripts/verify-local.sh --quick` 通过。
- **未覆盖的部分**：动画的实际观感，包括阴影出现的时机和 `slide_up` 的边缘裁切，没有在真机上验证。

系统候选卡片的[液态玻璃底板](2026-10-19-macos-candidate-liquid-glass.md)作为背景子视图跟随这套卡片图层动画，不增加独立的显隐时间线。


组合排版新增大量皮肤矩阵后，动效结束断言间歇超时；高精度活动曾连续 10 次通过，后续仍失败，不能把它当作充分修复。探针显示运行循环与后台 400ms 定时回调可执行，主队列的定时回调却没有在两秒内到达；更长的单轮循环与共同模式定时器也未稳定通过，未把这些未证实方案留在产品里。布局专项改为各自释放自动释放对象；动效和装饰两组计时验收通过 `candidate-declared-motion` CTest 以同一个测试程序的 `--declared-motion` 入口单独启动进程，避免在大型几何矩阵的旧窗口、视图和图层回调之后才开始计时。所有实际控制器、进场、选中、退场、装饰与无障碍断言照常运行，原来的两秒门限保持不变，移除测试专用高精度活动。独立运行的证据不能替代新皮肤组合的几何验收，两组都必须执行。
