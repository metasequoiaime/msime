# Agent Note: Android 原生设置开放候选与编码字号

Status: implemented

## Problem

#11002 反馈 Android 把拼音放在候选栏时字号太小。键盘已经消费共享偏好 `candidate_font_size` 和 `candidate_preedit_font_size`，但 Android 原生「键盘 → 工具栏 → 键盘工具栏」只有整体「候选栏大小」，用户不能分别调候选字和拼音/编码。

## Decision

在 Android 原生键盘设置的「键盘工具栏」组里增加「候选字号」和「编码字号」两个滑块。两项都复用共享偏好，范围为 12–32、步长为 1，分别写入 `candidate_font_size` 与 `candidate_preedit_font_size`；设置页读取同一字段，缺失或越界时回到共享默认值。Android 键盘现有的字号解析和候选栏整体缩放继续负责实际绘制，设置入口不复制绘制规则。

两个控件的说明放在标题旁的「?」里，搜索索引登记标题。默认值、字段名和其它平台行为不变；调整字号仍由既有偏好热更新路径生效。

本项与[Android 候选栏整体大小](2026-10-26-android-candidate-bar-size.md)及[三端触屏候选栏大小](2026-10-29-touch-candidate-bar-size.md)互补：前两篇负责字号参与布局和整体缩放，本篇只补 Android 原生的独立入口。

## Alternatives considered

- **只把当前字号写死成更大**：可以立即改变截图，但会静默改变已有用户的输入手感，也无法满足用户按个人偏好调整，因此不采用。
- **增加一个 Android 专用字号字段**：能避开共享设置，但会产生第二套存储和同步语义；键盘已经消费共享字段，复用它能保持设置页与实际绘制一致，因此不采用。
- **改成候选栏上方的浮动拼音布局**：能解决视觉层级问题，但会改变候选栏几何和窗口高度，超出本 issue 的字号诉求；布局改动另行评估。

## Consequences

用户可以分别放大候选字或拼音/编码，设置值会沿现有共享偏好和热更新路径进入键盘；没有改过设置的用户看到的默认字号和布局不变。两个字号仍受共享 12–32 校验，叠加「候选栏大小」后实际显示尺寸可继续按既有整体缩放规则变化。

代价是 Android 键盘设置多出两行控件，字号变大时候选栏和工具栏可能随既有测量规则变高；这属于当前 `candidate_font_size` 与 `candidate_preedit_font_size` 的既定行为。真实 Android 设置页和键盘仍需在 API 28/35 设备上验收，不能用 JVM 编译代替设备验证。
