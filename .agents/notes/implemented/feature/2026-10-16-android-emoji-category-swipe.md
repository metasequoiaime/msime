# Agent Note: Android 表情分类扩宽与横向滑动

Status: implemented

## Problem

#8180：表情页底栏的 ABC 按钮与顶部工具栏返回键盘的入口重复，占用分类空间。分类只能点小图标切换，用户希望在表情内容上左右滑动切换分类。

## Decision

移除底栏 ABC，保留删除键，其余宽度交给原有等分分类栏；顶部表情按钮和返回键盘入口继续关闭面板。只在表情网格的 ScrollView 内识别单指横向手势：超过触摸阈值且横向距离明显大于纵向才接管，并给原触摸目标发取消事件，避免滑动误上屏表情；松手且滑动足够远才切换一个相邻分类。纵向滚动与分页继续交给 ScrollView。最近项存在时参与首项切换，两端不循环；多指或取消不切换。设备验收从实际分类栏读取末项，并以共同的网格描述前缀定位手势区域，兼容普通 Emoji 与组合表情两种排版。

## Historical audit

- [常用表情默认页](2026-10-21-android-common-emoji-default.md)部分取代分类顺序：常用始终参与横划并位于最左，水杉娘可用时排第二；本篇的取消、分页及不回绕规则保持。

- [符号目录与表情候选](2026-10-08-android-symbol-catalog-and-emoji-candidates.md)部分重叠：保留目录分页和字体过滤，不改变符号面板或候选算法。
- [Android 设备门禁](../testing/2026-10-08-android-device-gates.md)部分重叠：复用专用模拟器与现有表情设备验收，手势通过真实触摸注入验证。

## Alternatives considered

- 用横向分页容器承载全部分类，可以获得连续拖动动画和现成的手势分发；但当前目录按分类异步分页，预建九张网格会增加加载、内存及代次维护，单次切换的需求不需要重做目录所有权。
- 给每个表情按钮附加横划监听，改动可局限于按钮绑定；但空白内容区不能划动，监听器还要与网格纵向滚动及按钮点击逐个协调，父容器统一取消原触摸目标更直接。

## Consequences

分类获得 ABC 原占用的宽度，横划不要求命中分类图标。手势只负责相邻分类切换，不提供连续分页动画；仍可点分类图标精确跳转。取消事件与多指不会触发切换；多指路径只按源码和宿主编译验证，未做设备多指注入验收。

## Verification

- 本轮修正后的 API 35 表情手势套件、组合表情排版套件（165 条、240/320/411dp）及真实输入套件均通过，覆盖末项不循环、分类切换不上屏、分页尾项、最近项重启恢复和普通 Emoji 回切。Java 宿主从本分支重编，原生库与词库暂存复用已合入 `develop` 的提交 `508c8d9cce9a98f60e400d36c52849de36145f20` 的构建产物；不将本轮表述为 Rust 原生库重建。
- 追查 Windows 游戏兼容合入后的 Native Platform CI（run `38852114941`）时，在 API 35 复现表情套件的末项边界失败。补充诊断确认面板仍打开，旗帜左滑后选中组合表情：组合分类追加后，原测试把旗帜写死为末项的假设已失效。修正测试读取实际末项，保留边界不循环断言，并增加旗帜滑向组合表情且不上屏的验收。手势定位同时接受组合网格描述，避免修正末项后卡在原八列网格选择器上。

- 新增设备断言在旧安装包上失败，原因为仍包含重复 ABC 返回键。
- `check-host.sh` 与原生 Android 宿主 Gradle `assembleFullRelease` 通过。Java 宿主重新编译，设备包复用 #8094 已验收的原生库与 staged 资源，不将这轮表述为 Rust 原生库重建。
- API 35 专用模拟器的完整表情验收通过：底栏无 ABC 且分类获得原有宽度，网格左右滑动不输入表情，纵向滚动与分页、上屏、删除、最近使用及重启恢复均通过。
- 补充的真实触摸验收通过：最近项参与分类顺序，首尾两端不循环，横向手势收到取消事件后不切换分类也不输入表情；顶部表情按钮可关闭面板。
- 最终 `bash scripts/verify-local.sh --quick`、`pnpm run verify-notes` 和差异检查通过。
