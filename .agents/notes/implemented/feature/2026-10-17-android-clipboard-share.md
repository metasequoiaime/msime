# Agent Note: Android 剪贴板条目分享

Status: implemented

## Problem

#8517 的 Android 剪贴板历史长按操作只能插入、编辑、删除或同步，用户无法把选中的一条记录交给其他应用。截图中的入口是条目操作行，不是整个历史的导出。

## Decision

Android 在长按条目的操作行中增加「分享」，位置紧跟「分词」，位于常用语和云剪贴板操作之前。点击后只把当前条目的原文作为 `Intent.EXTRA_TEXT` 交给 `Intent.ACTION_SEND` 的系统选择器，并以 `FLAG_ACTIVITY_NEW_TASK` 从输入法服务启动；成功后收起剪贴板面板和键盘。没有可用文本或系统没有分享应用时提示用户，不修改剪贴板历史，也不把历史列表、时间戳或内部标识放进 Intent。

## Alternatives considered

- **分享整个历史或复用全文导出** — 可以一次携带更多内容，但截图和操作上下文指向长按的单条记录，也会把用户未明确选择的内容交给外部应用；保留为单条分享。
- **在剪贴板顶栏增加分享按钮** — 顶栏没有当前条目的明确选择，点击后必须再弹出选择列表，增加一次交互并可能分享错误内容；入口放在条目操作行。
- **复制到系统剪贴板后让用户自行分享** — 会覆盖用户当前剪贴板，还需要用户离开键盘再执行一步；直接使用系统分享 Intent。

## Consequences

单条文本可以直接进入 Android 的分享面板，分享应用由系统解析，键盘不需要依赖具体目标应用。分享动作会收起输入法，用户返回原编辑器后可继续输入；系统没有目标应用时只显示错误提示。系统选择器会看到用户主动选择的原文，这是该功能的预期外发边界。

## Verification

`ClipboardSharePolicySmoke` 覆盖入口文案、普通 Unicode 多行文本、首尾空格保留、空值和空白文本拒绝；`check-host.sh` 与完整 Android Java 编译检查 `ACTION_SEND`、文本 MIME、chooser、输入法新任务标志和按钮入口。设备验收应在 API 28/35 模拟器上长按条目并确认系统分享选择器出现，当前提交前先完成主机门禁和 Gradle 编译。
