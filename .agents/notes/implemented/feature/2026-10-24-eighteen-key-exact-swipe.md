# Agent Note: 十八键双拼横滑限定单个组码字母

Status: implemented

## Problem

#8930 的十八键点按由 #9530 实现，但双字母键只送整组，左右滑动尚无入口。现有长按选项会先结束组字再上屏字母，不能用于限定当前双拼拼写。把滑动字母交给普通 `character` 也不成立：网格组字期间该接口不收字母；没有组字时它又会开启另一套实体键盘组字。

## Decision

Android 十八键双拼的双字母键左滑选择左字母，右滑选择右字母，松手一次输入当前双拼网格；点按仍送多义整组。固定横向位移超过 24 dp 且大于纵向位移的 1.5 倍才接手；轻微抖动、纵向移动和未触发手势的长按保留原行为。激活后回到起点、系统取消或多指触摸不输入；反向拖动可重选。只在双拼十八键绑定，十四键、十八键全拼与普通字母键不使用该手势。

现有 `grid_key` 接口的小写字母继续表示整组；仅十八键双拼增加大写 ASCII 字母表示同一键上的精确小写字母。它是网格输入标记，不是 Shift 或英文字母上屏。沿用 C ABI 和 JNI 的单字节参数，实体键盘的 `character` 行为不变。共享引擎从已经校验的双拼方案派生精确与整组的混合编码，不在 Java 放音节表；微软分号仍通过 L 整组和原有消歧使用，横滑仅作用于两字母键。

精确标记保留在已有组码串里，因此中间插入、删除、锁定前后切换、部分选词及运行时退格恢复继续使用同一串码和既有生命周期。派生表为每个合法两键编码登记整组／精确的组合，精确码只收原方案确实接受的对应字母；拼写列表去重，避免多个编码别名重复显示同一个音节。原有九键和十四键的表不增加精确码。

无候选时的 `CommitRaw`、越界 `finish` 和逐段结束后的无候选余码，在十八键双拼中先原地转为 ASCII 小写再上屏，防止内部精确标记变成用户可见的大写。普通九键仍移动原缓冲，保留其零分配预算。

## Alternatives considered

- 复用长按的直接上屏：接口最少、能快速输入英文，但会结束正在输入的中文，不能限定同一次双拼组字，故不用。
- 在宿主切换到二十六键再输入：可复用已有确定字母入口，但会清空网格和候选，不能与点按交替，故不用。
- 给每个组码另存一份精确字母位置数组：类型表达更直接，但必须同步所有插入、删除、锁定、部分消费和撤销结构；选择在现有组码串中保留标记，使这些生命周期天然一致。

## Testing

- 合成词库测试检查整组有多义候选，横滑指定字母后只保留相容双拼读法；覆盖首键、韵母键及与普通点按混用。
- 覆盖内置及合法自定义表、微软别名、无效码、光标编辑、锁定撤销、部分选词与退格恢复；普通网格和实体键盘不接受这套标记。
- Android 宿主测试覆盖方向、阈值、纵向偏移、回到起点、反向选择、多指和取消；设备用真实触摸验证组字、松手单次提交和后续点按。
- 完整 quick、相关 Rust 回归与严格 Clippy 通过；宿主编译不替代设备通过。

## Consequences

`editing_text` 中可出现精确输入的大写标记，所有网格恢复路径必须保留大小写，不能按普通 Shift 字符重放。别名增加可能重复拼写，必须用真实候选和拼写唯一性断言检查。宿主负载仍高，设备执行不得以源码检查替代，也不放宽超时或断言。

新增纯 Java 触摸状态回归先因缺少 `Gesture` 编译失败，补入实现后通过。设备专项在现有十八键双拼验收中注入真实 `MotionEvent`，包含左右选择、反向重选、取消、回中心、松手单次输入和后续普通点按；多指和长按优先级另由纯状态测试覆盖。标准双拼专项的路由依赖独立 PR #9583；本基点的 `runEighteen` 没有调用方，本次不复制其入口改动。目前尚未运行修复后的 API 28／35 设备验收，本 issue 与 PR 保留此缺口，不因已有点按布局验收而关闭。

收尾自查新增两条合成词库回归，先分别确认无候选 `I` 错误上屏为大写、`NiI` 逐段结束错误上屏为「你I」。修复覆盖直接原文上屏、无候选结束组字及中文后的余码。#9583 已合入 develop，设备验收应覆盖包含该路由修复的集成结果。
