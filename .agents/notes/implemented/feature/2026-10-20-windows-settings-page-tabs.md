# Agent Note: Windows 设置的页内标签框架与键盘手写、剪贴板两页

Status: implemented

## Problem

macOS 设置（共享设置 UI 的桌面分支）在「语音」「键盘与手写」「剪贴板」「AI」几页顶上用 `useSettingsTabs` 画一排页内标签：铺满内容宽度，每段等宽，至少 36px 高、14px 字，选中的那段浮起（`settings-style.ts` 的 `candidateTabs`）。选中哪个标签由 `useSettingsIntroTabs` 记在窗口里，跨页面保留、不写偏好，页首引导随标签换说明。Windows 原生设置窗口只有 AI 页有标签，用的是靠左的紧凑分段控件（26 高、13 DIP 字），状态是一个专用的 `ai_mcp_view_`，搜索落到「连接 AI 助手」时靠比较行名切过去。「键盘与手写」把键盘四组和手写一组排成一列；「剪贴板」把开关、历史和云剪贴板排成一列，「清空历史」挂在开关行下面，历史关着时整组不画，历史一次画完（上限可到 1000 条），每条只露出「重新复制」、其余三项收在菜单里。「恢复默认」是普通前景色，macOS 是危险色。用户要求以 macOS 为准迁移，后续几页（语音、快捷键、标点与翻译、词库、关于）也要分标签，需要一套共用的写法。

## Decision

### 标签框架

- `segmented_control` 加 `full_width` 参数，即页内顶部标签的样式：外框横向铺满，每段是 Grid 的一个 `*` 列，段高 36、14 DIP 正文色的字（选中与否都是正文色，与 `candidateTabs` 相同），外框圆角 6、段圆角 5，底色照 `candidateTabs` 在 macOS 上的 `--p-seg-bg` 与 `--p-seg-border`：浅色 rgba(0,0,0,.055)、深色 rgba(255,255,255,.08)，没有描边（紧凑样式仍是 `seg_well` 加描边）；选中浮起沿用紧凑分段控件的白底（深色 #5A5A5E）加描边。这种样式不按 `maximum_segments` 退成下拉框。行内的小分段、打字统计和社区图库的标签仍是紧凑样式。
- `page_tab_bar(page, 名称, 标签, 自动化前缀)` 画标签条并返回这一页现在的标签 id；`in_tab(tab, id)` 决定一块内容画不画。选中的标签按页面 id 记在窗口成员 `page_tabs_`，跨页面保留、不写偏好；没选过或记下的标签这一页没有时落到第一个。点标签时写 `page_tabs_` 并整页重画。标签条与页首引导、下面的第一组各相隔 24 DIP。标签按钮的自动化 ID 是 `<前缀>-<标签 id>`，选中的 ItemStatus 是「已选择」。
- 页首引导：`make_page_header` 把 `page_tabs_` 里这一页的标签交给 `show_page_intro_tab`，标签切换整页重画时引导跟着换成 `SettingsMascotIntro.h` 里那个标签的说明和插画。
- 搜索：建索引时 `page_tab_bar` 不画、返回空，`in_tab` 对每块都返回真并把 `tab_index_` 设成这一块的标签，`record` 把它记进 `SearchEntry::tab`；`open_search_result` 先把结果所在的标签写进 `page_tabs_` 再画页面。这取代了 AI 页按行名判断标签的做法；折叠区仍由 `fold_holds_focus` 展开，两者各管一层。
- 路由：构造窗口时 `mcp` 写成 AI 页的「连接助手」，`handwriting` 在提供手写的版本里写成「键盘与手写」的「手写」（共享 UI 的 `handwriting` 路由只进合并页，这里多走一步落到手写标签，是缺口清单要求的）。
- AI 页改用这套框架，`ai_mcp_view_` 删掉，连接结果回来时是否重画改看 `page_tab("ai")`。

### 键盘与手写

- 提供手写的版本顶上是「键盘手写分类」：「键盘」放屏幕键盘、尺寸、工具栏、外观四组（`build_osk_keyboard`），「手写」只放「手写识别板」一组（`build_hand_page`）。不提供手写的版本没有标签。
- 「手写识别板」组在打开面板的一行下面加一张预览卡片（`make_inner_card`，与屏幕键盘预览相同，上下各留 10，排在组末不贴外层边框），照共享页非 macOS 桌面分支的 `SettingsPreviewBlock` 与 `panel-surface-style.ts` 的 `mock`：「预览」小字，最宽 560 的示意，至少 230 高、12 圆角、虚线描边的画布中间一个 110 DIP、倾 -7° 的楷体「水」，下面相隔 10 一排四个等宽候选「水 永 木 未」。颜色取设置窗口的明暗。
- 「尺寸」组的「恢复默认」按钮前景用 `danger_color()`，与共享页的 `danger-text` 和统计页的「清空统计」一致。

### 剪贴板

- 顶上是「剪贴管理分类」：「设置」放「剪贴板」组（历史开关、上限）和「云剪贴板」组；「历史记录」一直进得去。历史关着时只写「请先在「剪贴板」中开启剪贴板历史」，开着但没有记录时写「暂无历史记录」。
- 有记录时列表上面一行，左边「清空历史」（两步确认不变），超过一页时右边是翻页器：「上一页」、「第 N / M 页 · 共 X 条」（读屏礼貌播报）、「下一页」。翻页整页重画，`show_clip_page` 记下点的那个按钮，重画后焦点交回同一个新按钮（翻到头不能再点时落到另一个），状态文字进了可视树后发 LiveRegionChanged；只在翻页后的那次重画里这样做。每页 20 条。分页算法放在不依赖 Windows 的 `HistoryPagination.h`：`lastOffset` 是最后一页的起点，记下的起点超过它就退到最后一页。翻页只改 `clip_offset_` 再重画，不重读历史；删除后渲染时把起点收进有效范围并记回去；历史关掉时回到 0；离开再回到本页保留页码，与共享页组件保持挂载的效果相同。
- 每条记录右边照共享页直接排出「重新复制」「发到云剪贴板」「固定 / 取消固定」「删除」，可用条件同共享页（发送要云剪贴板就绪且不在发送中，固定和删除在写入期间不可用）。行窄到正文不足 180 DIP 时后三个收起，换成原来的「更多操作」菜单（同样的名字和自动化 ID），只留「重新复制」。切换在行的 SizeChanged 里做：三个按钮排开时量一次它们连同「重新复制」的期望宽度，收起后沿用这个宽度判断什么时候排回来。

## Alternatives considered

- **每页各自拼一个整宽分段控件、各用一个布尔成员记标签**：AI 页原来就是这样，改动最少。否决：后面还有五六页要分标签，每页一份状态、一段搜索特判，搜索落到标签里的行要各写一遍按行名切换；而且引导随标签换说明需要一个统一的「这一页现在是哪个标签」。
- **标签切换只切换各块的 Visibility，不重画整页**：切换更快，滚动位置和输入框状态都不动，接近共享页「面板保持挂载」。否决：建页时就要把所有标签的控件都画出来，剪贴板历史和屏幕键盘预览的回调、成员引用要按可见性分辨；现有页面一律靠整页重画保持一致，重画一次的代价在这几页可以忽略。
- **剪贴板记录按窗口宽度固定一个阈值切换按钮布局**：不用量控件。否决：按钮宽度随字体和「固定 / 取消固定」变化，固定阈值要么在宽窗口里仍然收进菜单，要么在窄窗口里挤掉正文。
- **分页交给宿主接口**：读得更少。否决：共享页也没有这样做，历史接口返回完整快照，改它要动所有宿主的客户端契约。

## Consequences

- 后续要分标签的页面只需 `page_tab_bar` 加几处 `in_tab`，搜索、路由和页首引导自动跟上；用法写在 `platforms/windows/settings/README.md` 的「页面与导航」。
- 标签条宽度不够时不会像 `candidateTabs` 那样横向滚动，各段会挤窄、字被裁掉；现有页面最多四个短标签，最窄窗口下放得下，标签多的页面接入时要再看。
- 选中的段只有白底和描边，没有 macOS 的阴影；紧凑分段控件也是这样。
- 切标签是整页重画，滚动位置保留在原来的偏移上（新标签内容短时由滚动视图自己收回）。
- 每条剪贴板记录多了三个按钮和一个按尺寸切换的处理器，一页最多 20 条，渲染量反而比原来一次画完全部记录少。
