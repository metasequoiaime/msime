# Agent Note: Android 符号面板整行返回提示

Status: implemented

## Problem

#10307 的符号面板顶部实际整行可返回，但左侧「返回」与右侧普通贴纸看起来仍是两个独立区域，用户常跨到左上角点击。

## Decision

保留 44 dp 高度和整行返回动作，文字居中为「返回上一界面」，两侧各显示一张水杉娘朝内指引的插图。按钮铺满整行，装饰叠在两端，不接收点击和无障碍焦点；图片缺失不影响文字、点击范围或布局。继续使用既有「关闭符号面板」无障碍描述，返回打开符号面板前的键面，不固定切到字母层。

通过 EveryAPI 的图像 API 生成两个独立朝向的位图；沿用现有角色的绿色长发、红色发梢、琥珀眼、杉叶头饰与浅色中式衣服，放大手指便于小尺寸辨认。用户已明确授权 CLI/API。imagegen CLI 默认模型 `gpt-image-2` 在 EveryAPI 没有可用渠道；用户明确指定 EveryAPI 后，使用该账户可用的 `doubao-seedream-5.0-pro` 原生兼容接口，使用文字描述生成；保留最终提示词、资源来源与哈希。离线随 Android assets 打包，沿用 ImeStickers 工作线程解码，不下载、不新增偏好。返回栏素材独立于贴纸清单，`build-apk.sh` 打包并断言两张资源存在，`ImeStickers` 沿用工作线程读 assets；不让键盘核心类依赖构建时的 `R`，宿主 Java 快速编译仍可独立运行。

- [手机水杉娘贴纸](../../implemented/feature/2026-10-20-mobile-mascot-stickers.md)：角色参考有重叠，贴纸清单、发送和缓存契约不变；新图不进入贴纸列表。

## Alternatives considered

- 仅居中文字、复用原贴纸并左右镜像：不增加生成素材且角色一致，但原贴纸双手托脸，不能表现朝内指引，不符合 issue 要求。
- 两侧各做独立按钮：可沿用标准图片按钮，但会重复无障碍动作，且中间空白的整行返回语义变弱，采用一个铺满整行的文字按钮与两张不接收事件的装饰。

## Verification

原草稿 `4f51dcfda6` 用同一张既有缩略图，API 28／35 两项符号专项与 PR CI 通过，但插图交付尚缺。原 quick 曾因共用 Apple bridge 缓存指向其他 worktree 失败，在原产物目录重新配置后通过；构建签名的脚本上下文和同步删除输出问题也已纠正。未挂接窗口的布局夹具无法立即读取排队的点击回调，实际关闭保留在系统输入专项中明确等待「符号面板」消失，并验证原键盘与空编辑器；不以底层键盘节点存在代替关闭。

两张独立生成图已目视核对：左侧向右、右侧向左，手指放大；透明裁切和 WebP 重编码后在深色底复查，人物服装与轮廓保留。两图合计 38,796 字节，来源、SHA-256 与完整提示词见 [素材记录](../../../../docs/assets/android-symbol-return.md)。Android 宿主检查通过（316 项 JVM 冒烟、258 份设备源码、JNI 与资源契约）。同源原生瘦包构建、arm64 ELF 依赖和 16 KB 对齐通过，包内两张插图已核对，包体 128,378,550 字节，低于既有告警线与上限。API 28／35 的 `SymbolPanelLayoutDeviceSmoke` 通过，覆盖 320／720／1000 px、双图／缺图、取消触摸、装饰不拦截触摸和无障碍、单次关闭动作；`LongSymbolCellDeviceSmoke` 通过，新增系统注入点击左／中／右返回后原键盘可见且编辑器为空，保留分类滚动、连续输入、删除、偏旁和长后缀回归。两版实际产品截图均已目视核对：文案居中、双图朝内、布局正常。完整 quick 通过（Rust workspace、Android、Linux 设置壳、Windows x64 原生链接及 GNU Rust、Apple bridge）；其余无关平台阶段按范围跳过，macOS 上无暂存 app 的 Rust 设置壳由 Linux／Windows 配置检查补充。最后保留明确等待面板消失的断言后，再跑宿主 316／258 编译和两版上述设备专项，全部通过。未在物理手机或实际深色皮肤验收。

## Consequences

文字和朝内手势共同强调整行可返回，按钮占满原有高度；两侧插图增加约 38 KiB APK 素材与两张小位图。单图或两图缺失时返回入口仍完整。物理手机体验尚未验收。
