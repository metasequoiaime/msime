# Agent Note: Windows 候选窗预编辑区开关

Status: implemented

## Problem

Windows 候选窗已有 `candidate_preedit_style`，只能决定首行是否画拼音文字；它与首行版式和候选列表的几何绑在一起，用户无法单独保留文字样式选择、同时收起候选窗的预编辑区。旧设置页和新设置页也没有独立入口。

## Decision

新增共享布尔偏好 `show_candidate_preedit_area`，缺字段按开启，以保持旧版本的候选窗高度和位置。Windows 候选宿主把它与 `candidate_preedit_style` 分开消费：样式决定预编辑文字是否绘制，区域开关额外控制首行及其版式是否允许出现；区域关闭时同时收起 logo、页码、翻页按钮和候选编辑提示，使候选窗直接从候选列表开始。新旧 Windows 设置页都提供该开关，设置预览与原生候选窗使用同一语义。

这个偏好属于共享文档，因此旧版本和其他宿主会保留未知字段；本 issue 的行为与入口只在 Windows 落地，不改变 macOS、Linux 的既有候选窗默认值或设置布局。

## Alternatives considered

- 继续复用 `candidate_preedit_style=empty`：实现最小，但无法表达“暂时收起区域、恢复时保留原文字样式”，也不能解决样式与区域含义混在一起的问题。
- 只在 Windows Server 内保存本地状态：能避开共享偏好改动，但无法随设置文档同步，且新旧设置页无法使用同一字段。
- 把区域开关加入共享设置页的所有桌面宿主：能力覆盖更广，但本 issue 只有 Windows 报告和入口，提前改动 macOS/Linux 的原生设置和候选几何会扩大范围并改变未授权的界面行为。

## Consequences

旧配置缺少新字段时行为不变；选择“候选窗预编辑：不显示”只隐藏文字，首行是否占位仍由 logo、页码或候选编辑提示决定，不能由默认开启的区域开关凭空撑出一行。区域关闭时进一步收起整行；重新开启恢复原先样式下的布局。关闭区域后候选窗尺寸和无障碍树不再包含预编辑首行，候选列表仍按原规则绘制。窗口行为回归直接构造生产 `CandidateWindow`，在横排和竖排下测量实际窗口：只有候选列表时区域开启与关闭同高，有文字、logo、页码或候选编辑提示时关闭区域才变矮；同时验证恢复原布局和候选行点击。pve9 Windows 交互桌面上的修复前探针在全隐藏配置下测得 131/102 像素，确认并修正了空首行回归。
