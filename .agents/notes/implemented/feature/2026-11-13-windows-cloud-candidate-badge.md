# Agent Note: Windows 云候选来源角标开关

Status: implemented

## Problem

Windows 候选窗把云候选的 `☁️` 来源角标写死。候选内容本身可以正常显示和选择，但使用自定义皮肤或希望保持简洁的用户无法隐藏这个标识。#11377 要求在设置中提供显示选择。

## Decision

共享偏好增加 `candidate_cloud_badge`，默认开启以保持现有用户的候选外观。Windows 原生「输入 → 候选与联想」页提供「显示云候选来源角标」开关，说明收进标题旁的「?」。候选窗通过偏好监视器实时读取该值：关闭时只省略 `☁️`，仍保留云候选的来源、候选序号、选词身份和网络请求行为。旧文档缺少该字段时按开启读取；设置值保存在共享偏好中，但本次只接入 Windows 候选窗，其他平台继续保持原有显示。

候选投影的默认参数仍为开启，测试和不带偏好监视器的工具不会改变既有画面。运行中的 Windows Server 使用共享原子状态接收偏好发布，避免在候选窗口绘制线程读取文档或引入锁等待。

本条与[整句候选来源徽章提案](../../proposed/feature/2026-10-21-sentence-source-badge.md)独立：该提案明确排除了云候选，本条只处理云候选来源角标。

## Alternatives considered

- **继续写死角标。** 最强理由是无需增加设置和偏好字段；但无法满足报告者对自定义皮肤和简洁候选栏的控制需求。
- **把角标选项放进云候选服务配置。** 最强理由是用户会在同一页看到云候选设置；但角标是显示偏好，不应随本机服务地址、请求头和凭据配置混在一起，且服务配置草稿保存失败时不应阻塞外观选择。
- **在候选投影时每次读取偏好文件。** 最强理由是实现路径短；但候选窗绘制和输入回调会被磁盘锁与 JSON 读取拖慢，且违反偏好监视器的发布边界。
- **同时改动 Android、iOS、HarmonyOS 和 Linux。** 最强理由是共享字段在各端语义一致；但本 issue 只有 Windows 的报告和验收条件，其他平台已有各自的候选展示实现，扩大范围会把未验收的跨平台视觉变化塞进一个 PR。本次只接入 Windows，其他平台仍按现状显示。

## Consequences

用户可以在 Windows 设置页关闭云候选角标，设置变更会在当前 Server 会话的候选投影中生效；候选排序、编号、点击和网络行为不变。共享偏好多一个兼容字段，旧文件无需迁移。Android、iOS、HarmonyOS 和 Linux 尚未读取该字段，因此跨平台同步来的关闭值不会改变这些平台的画面；若后续要做全平台对齐，应另开 issue 并补齐各自宿主、设置页和设备截图。
