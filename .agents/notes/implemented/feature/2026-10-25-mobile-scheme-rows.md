# Agent Note: 三端手机设置按输入方案分行

Status: implemented

## Problem

Android、iOS 和 HarmonyOS 的手机输入设置都把全拼、双拼、五笔、注音、粤拼等方案折在「普通话」或「粤语」语言行里。用户需要先打开语言面板才能辨认方案，三端的行名和可用方案也不一致。

## Decision

三端手机的「语言与方案」卡片统一按可选方案族分行：全拼、双拼、五笔、注音、笔画、手写和粤拼各有独立行；日语、韩语、越南语和藏语继续按语言分行。每行的弹窗直接列该行的布局或子方案，最多两层：点行是第一层，弹窗里的方案是第二层。双拼弹窗直接列小鹤、自然码、微软、首道和九键双拼，五笔弹窗直接列 86 和 98；最初两者各自再开一层子菜单，「双拼」行、方案弹窗、双拼弹窗成了三层，Android 的双拼排法还在第四层。不在弹窗里的设置各归其页：双拼的 26／14／18 键排法在键盘页「中文键盘」（鸿蒙、iOS 原本就在那里，Android 由输入页移过去），九键双拼的表在「九键双拼方案与自定义」页（Android 原先只有子菜单里的「编辑自定义表…」能进，现在与 iOS 一样在卡片下单列一行）。移除操作关闭该行的全部方案；没有启用的行从「添加方案」进入，添加只启用首个方案而不切换当前输入方案。底层偏好字段、资源包下载、当前方案回退和键盘布局逻辑保持不变。

这项决定取代[输入语言与中文方案分层选择](./2026-10-19-input-language-scheme-hierarchy.md)中“触屏语言卡片不改动”的范围判断，但保留该笔记关于共享偏好和宿主能力过滤的约束。

## Alternatives considered

**继续保留普通话语言行，只在面板中增加更多方案**：改动最小，但用户仍需要进入普通话面板才能找到方案，三端仍无法用相同的行名表达方案。

**把所有方案都改成独立开关**：可见性最直接，但会破坏当前方案选择与启用列表分离的语义，也会让双拼 profile、五笔版本和词库下载各自复制一套保存逻辑。最终保留现有“行 + 方案弹窗 + 添加/移除”的交互，只改变分组。

## Verification

共享设置页通过 Harmony 和桌面类型检查；Swift 源文件通过语法解析；Harmony 语言卡片测试覆盖方案族分行、双拼和五笔弹窗直接列出方案（换回子菜单版本时这两项失败）、14 键与九键双拼、添加和移除回退。Android 主机检查因本机未配置 `ANDROID_SDK_ROOT` 未能运行，iOS/Android 真机 UI 验收待设备环境可用后补充。

## Consequences

三端手机用户可以在同一张卡片中直接找到全拼、双拼、五笔、注音和粤拼。中文方案也可以像其它语言一样单独移除和添加，因此默认只有全拼时会出现更多方案在「添加方案」中；键盘始终至少保留一个可运行方案。旧的共享偏好无需迁移，旧版无障碍标识在 iOS 全拼行上继续保留。
