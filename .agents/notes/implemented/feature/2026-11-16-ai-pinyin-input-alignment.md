# Agent Note: AI 候选保留原始全拼并校验备选切分

Status: implemented

## Problem

#11508 的中文 AI 请求只发本地 `segmented_pinyin`，`input` 为空。默认提示把本地切分当成唯一解释；`woxiwangaikeyi` 被切成 `wo/xi/wan/gai/ke/yi` 后，模型无法给出可验证的 `wo/xi/wang/ai/ke/yi`。宿主又在取候选文字时丢掉模型返回的切分，普通解析器只检查文本长度，不能排除语义改写、漏字或越过手动边界。

## Decision

全拼候选请求使用查询身份里保留大小写和单引号的原始输入，同时保留原本的本地切分。`explicit_boundaries` 用去掉单引号后的字母偏移表示用户边界，模型可调整推断边界，不能移动手动边界。双拼继续只提供转换后的本地拼音，不把双拼键串冒充全拼；英文补全纠错的独立模式保持原来的宽松拼写规则。

`client-providers::ai::alignment` 校验每个候选：`segmentation` 必须完整覆盖原始字母，保留手动边界；每个中文字符消耗一个读音匹配的音节，每段连续英文按原样字母消耗一个或多个输入区间，忽略大小写。中英之间允许空格，数字和其他字符仍需要原始输入的证据。读音使用已有 `pinyin` 依赖的多音字数据，兼容输入法已有的 `v/ü` 与 `lue/lve` 等键入形式。中文音节通过字符读音证明合法性；英文区间可以不是汉语音节，但不能改变对应字母。模型的 `confidence` 不参与排序。

macOS 的原始全拼请求带 `sentence_punctuation` 和标点指令（#11771），允许模型在 `text` 的词句接缝补必要的全角标点。允许列表只包含逗号、句号、问号、叹号、分号、冒号和顿号，标点不参与 `segmentation`，也不消耗字母。开头、连续标点和两段 ASCII 字母之间的分隔仍拒绝。把能力随请求交给校验器，保留原提示词、双拼和英文的边界，也避免让普通候选或提交时机随模型变化。

旧的纯文字回复只有按本地切分对齐成功才接受；非法或不完整的切分元信息不能退回宽松解析。过滤发生在限额之前，保留有效候选的原顺序并去重。翻译、聊天和高情商回复继续使用原来的通用解析器，不能套用拼音约束。

全拼 AI 查询不再要求本地每段都是完整拼音，允许至多 256 个原始字母和单引号的输入，让 `GitHub` 这类英文区间进入候选协议；双拼的完整音节条件不变。字面输入、辅助码、焦点、隐私授权和现有在线入口约束仍先于这项资格。查询生成和回包核对使用同一个资格判断，并继续逐项核对原始身份、本地分段、缓存键、会话和代次；模型给的分段不能替换查询身份。

六端候选路径通过 `msime_client_ai_candidate_protocol` 的内存协议接入共享解析。解析只返回文字数组，宿主仍用原查询调用会话应用接口；经过校验的文字不能绕过过期查询拒绝。macOS 的 AI 批次带上候选查询，只有这类批次使用严格解析，翻译批次不受影响。Android 和 HarmonyOS 不再自行从候选正文里只取 `text`。iOS 与 Windows 在原异步回调里解析；Linux 经 ctypes 复用共享库，库或协议不可用时不发请求，不退回未校验候选。

Linux 的缓存增加原始查询身份摘要，手动边界不同但本地分段相同的请求不能互用旧结果。原有上下文、提示词、模型和凭据指纹分区仍保留。容器测试先构建共享库再执行 Python 用例，因为拼音校验已经不由 Python 副本负责；legacy 用已安装包的库运行相同用例，不跳过旧断言或修改出厂默认值。

上屏后的词库学习仍使用当前本地切分。AI 候选必须在词库里逐字找到当前读音的正面证据才能学习；缺字不能作为读音匹配的证据，否则合法备选切分的文字会被写到错误的本地切分下。没有证据时仍正常上屏，只跳过这次词条学习。云词的罕见字兼容行为保持不变，旧云词学习回归继续运行。备选切分元信息用于回包校验，现阶段不改个人词库的学习协议。

Android 的 JNI 与导出符号清单包含新协议。移除要求 Java 服务自行提取 `content/text` 的源码守卫，已有 JVM 行为测试继续验证严格字符串、空值、顺序和限额。HarmonyOS 删除不再被宿主使用的旧候选 JSON 解析器，逐条无效结构不影响邻居、控制字符、字节限额和去重等断言由实际共享解析器覆盖，ArkTS 适配器测试仍核对完整回包与原查询的透传。Linux 配置发现测试的合成回包使用与 `ni/hao` 对齐的「你好」，保留配置晚创建、权限拒绝、移除、损坏及修复的全部前置条件与断言。

## Alternatives considered

- **只修改默认提示词。** 最强理由是不用改宿主接口，模型也能尝试重新切分。但无法证明回包对应输入，宿主丢掉切分后仍会接收增字、漏字和违反手动边界的结果，因此不用。
- **让模型直接覆盖本地切分并抢前几个候选。** 最强理由是可以立刻采用更合理的全句解释。但异步响应会改变用户已经看到的座位，也会让旧查询的身份字段漂移。本项只增加经过验证的候选，不修改本地切分或排序。
- **在各宿主复制读音、音节和对齐规则。** 最强理由是保持传输解析各自独立。但六份实现、字典和兼容规则难以一致，Python 与 ArkTS 也没有现成相同读音数据，因此统一放在已有共享 provider 层。

## Consequences

模型可以在本地切分之外提出有字母、边界和读音依据的结果；不可靠的语义改写被过滤，本地输入和网络失败的回退保持原样。完整拼音以外的全拼输入也可能在原停顿计时后发起 AI 请求，仍受用户已经开启的 AI 服务、取消和代次控制；不会进入同步按键路径。

严格对齐会过滤自由改写、超出请求允许范围的标点及读音库不认识的汉字。带标点的候选仍走 AI 座位，只有选中才上屏。现阶段提供模型提出的切分路径，不额外计算本地备选切分，也不把模型置信度当作概率。专项测试覆盖合成的备选切分、中英混排、标点、手动边界、增漏改字、元信息错误、实际会话完整上屏及迟到回答拒绝；不以设备验收作为提交前提。
