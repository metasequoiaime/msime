# Agent Note: 语法模型保留本地快照

Status: implemented

## Problem

#9839 发现语法模型的下载描述、安装状态和离线使用绑在同一份应用内嵌锁文件上。上游替换同名 LTS 资产后，已安装且完整的旧模型会因摘要不再匹配当前锁文件而被当成不可用，输入功能随应用更新静默降级。

## Decision

语法模型的 `msime-model.json` 作为安装时快照保存。读取语法模型时，当前锁文件仍用于新下载和更新提示；如果本地快照的资源包 ID、文件名集合、长度、SHA-256 和实际文件字节自洽，就继续离线使用，即使它与当前锁文件不同。原生宿主调用的 `verify_installed` 与 `installed_file` 共用这条快照规则，并额外核对 `.gram` 格式。资源包列表仍显示 `Outdated`，让用户知道有可选更新。设置宿主在用户点击检查时读取项目维护的 HTTPS 模型目录，严格限制模型 ID、通道、文件名、大小、SHA-256、URL 和 `.gram` 格式。下载地址必须是程序里按模型 ID 固定的上游 Release 前缀（万象 `github.com/amzxyz/rime-wanxiang-data/releases/download/`，八股文与精简版 `github.com/lotem/rime-octagram-data/releases/download/`）后接一个普通的 tag 段和该模型的文件名，任一条目不符则整份目录作废：目录取自自动合并的 `develop` 分支，地址和摘要出自同一份文件，摘要只能证明下载到的是目录说的那份字节，证明不了目录说的来源可信，所以来源必须在编译期钉死；目录结果只用于提示和用户随后发起的下载，其他资源包继续严格匹配当前锁文件，避免扩大未审计文件的信任范围。

## Alternatives considered

- 发现锁文件变化就删除或禁用旧模型：会让应用更新强制联网，直接破坏报告者要求的离线使用。
- 只相信 `msime-model.json` 而不重新校验文件：本地清单可被损坏或替换，不能作为模型完整性证明。
- 对所有资源包放宽摘要匹配：词库和运行库也可能被替换，扩大信任边界；本次只放宽语法模型。
- 新建动态模型解析服务：能把版本选择放在服务端并随时调整，但每次检查要把客户端通道和版本发给服务端；当前静态目录由客户端筛选，公开文件就能独立维护。
- 把每个模型的 SHA-256 编译进程序，目录只能指向这些摘要：来源最可信，但万象 LTS 会在同一 Release 地址原地重传，固定摘要等于取消在线更新，这正是目录要解决的问题；本次只固定来源仓库，不固定字节。
- 目录改从 `main` 读取或对目录签名：前者让每次模型更新都要走一次发版，且 `main` 同样允许管理员绕过保护规则；后者要新增密钥管理和签名流程。两者都可以在固定来源之外再叠加，本次先做不改变发布流程的那一层。
- 只用上游 HEAD 的长度和时间判断更新：请求轻量，但不能提供下载前可审查的 SHA-256；本次继续让官方目录明确固定可接受的字节。

## Consequences

已安装的旧语法模型在当前锁文件变化后继续可用，列表可以同时表达“当前可离线使用”和“有新版本可更新”。读取时会重新校验快照记录的文件字节，因此首次使用旧模型可能增加一次哈希开销。在线目录只在用户主动检查和下载时读取；目录不可用或下载校验失败时保留旧模型。Windows 原生设置页与共享设置页都提供主动检查入口。

## Verification

- 新增合成快照测试，验证锁文件变化后旧语法模型仍能由 `installed_file` 找到，同时列表状态为 `Outdated`。
- 同一测试验证原生宿主校验入口接受完整的旧快照，拒绝被篡改的文件及摘要虽自洽但格式无效的 `.gram`。
- `cargo test -p msime-client-providers --lib resource_packs::tests::` 通过，34 个资源包测试全部通过；目录测试覆盖通道回退、非法 URL、路径和重复条目，以及指向其他主机、同主机其他仓库、借 `..` 折叠跳出仓库路径、带查询串和换文件名的地址都会让整份目录作废，换一个普通 tag 仍然接受。
- 共享设置页测试验证点击“检查更新”不会启动下载，用户再点“下载更新”才调用安装。
