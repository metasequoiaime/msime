# Agent Note: Windows 7 设置范围收缩

Status: implemented

## Problem

Win7 原生设置把现代 Windows 的在线服务页、本机设置和输入工具混在一棵导航树中。账号、AI、社区、云剪贴板和 AI 助手页面依赖登录、网络或现代桌面宿主，兼容版即使能画出控件也不能保证在旧系统上稳定完成操作，结果是页面数量看起来完整，使用时却出现长时间加载、空白区域和跨宿主跳转。

## Decision

Win7 导航只保留能在本机独立完成的核心能力：快捷键、输入、标点与翻译、候选窗口、悬浮工具栏、本地主题与皮肤、剪贴板、词库、背单词、本地插件、语音、屏幕键盘与手写、打字统计、维护与诊断、关于与帮助，以及键盘皮肤制作。账号与同步、AI 输入辅助、云剪贴板、社区皮肤／插件／词库、连接 AI 助手从 Win7 导航中移除；它们的 `settings:<类别>` 路由返回失败，不再把请求落到默认页或另一个页面。现代 Windows 设置页面、共享 Rust 业务和默认值保持不变。

本地插件和键盘皮肤制作继续保留，因为它们的包扫描、编辑和保存可以在本机完成；语音设置保留为兼容运行库和系统音频设备的本机配置入口，在线服务请求仍由用户明确发起。固定页面索引不重排，避免破坏已有深链接和内部控件契约；导航树只插入可用页面，隐藏的旧页面不再对用户可达。本地插件页同时移除通往社区插件的按钮，账号页移除通往社区资源的按钮，避免保留死入口。

## Alternatives considered

- **继续让 Win7 追齐现代 Windows 的全部页面。** 页面可以逐项编译通过，但旧系统缺少现代宿主和稳定的在线服务承载，用户会看到无法完成的加载和跨页跳转；这不符合兼容版先保证本机输入与维护的定位。
- **只隐藏导航，继续接受旧路由。** 深链接仍会打开不可用页面，托盘或旧版本残留入口会重新暴露半成品，因此路由必须和导航同时收缩。
- **删除现代 Windows 的对应页面。** 会扩大兼容版改动范围并改变现代用户能力，本次只改变 Win7 的产品边界。

## Verification

- 路由测试断言账号、AI、社区、云端和 MCP 页面不可用，保留的输入、词库、插件、语音、屏幕键盘和键盘皮肤路由继续可用。
- Win7 设置 CMake 测试集合移除独立社区与 MCP 页面测试；主设置测试仍覆盖本机页面、隐藏旧索引不影响存储回归。
- `git diff --check`、`pnpm run verify-notes` 通过；远端 Windows 11 MSVC 用同一份源码构建 Win7 设置目标并运行 10 项 CTest，全部通过。该远端会话使用同源 debug host-api 导入库，证明编译、链接和测试契约，不替代 Win7 SP1 实机验收。

## Consequences

Win7 设置窗口更短、更容易解释，用户不会在兼容系统里看到需要账号或现代桌面宿主的半成品入口；深链接失败也能让启动器明确知道该功能不可用。代价是 Win7 用户不能从设置窗口访问账号、社区、云剪贴板、AI 或 MCP，这些能力仍在现代 Windows 产品中保留，输入工具面板和本机核心设置不受影响。
