# Agent Note: 触屏 AI 对话改为二级页面并恢复稳定底部入口

Status: implemented

「四个入口统一为设置 / 全部设置 / 统计 / 我的」与「全部设置复用既有设置列表」已被 [触屏宿主底部第二格恢复为社区](2026-10-16-mobile-community-bottom-tab.md) 取代：「全部设置」与设置标签页是同一份列表，第二格改为社区。本篇的 AI 对话二级页等决定仍成立。

「共享壳对话页保留底部导航」已被 [触屏 AI 对话二级页不带底部标签栏](2026-10-17-mobile-chat-hides-tabs.md) 取代：二级对话页三端都不带标签栏，返回走顶部。

「设置根标识直接作用于导航栈」已被 [iOS 设置栈不再靠换栈回到根页面](../bug-fix/2026-10-30-ios-settings-stack-no-identity-swap.md) 取代：手机重选设置标签改为按状态弹回根页面，不再换栈。

## Problem

用户在小米 Android 14、full 0.4.2 上仍看不到聊天时的底部导航，要求把 AI 对话改成二级页并同步 iOS 与鸿蒙。共享触屏壳确实在输入框聚焦时主动隐藏导航；Android 已有的 inset 修复没有解决用户设备上的反馈，不能把模拟器结果当作该小米设备已修复的证据。

## Decision

Android、iOS 和 HarmonyOS 的四个入口统一为「设置 / 全部设置 / 统计 / 我的」。AI 对话从「AI 辅助」或「AI 润色与回复」进入二级页，顶部提供返回入口；「试用键盘」复用该页并请求输入焦点。共享壳不再因输入框聚焦隐藏底部导航，已打开的对话继续保留草稿与请求状态。Android 通过 `PageId.CHAT` 和 `SettingsNavigator` 复用现有去重、返回栈及来源 Tab 契约。原生宿主的全部设置复用既有设置列表，省去首页状态卡。iOS 的全部设置实例不消费外部深链，避免两个导航栈在设置标签激活时同时推入同一个目的地。部分系统不把 Tab 重选写回 SwiftUI Binding，原生观察器放在设置标签内部，按视图挂载与布局生命周期绑定祖先标签控制器；它处理设置标签的重选，其余可选回调转发给 SwiftUI 原委托。设置根标识直接作用于导航栈，避免只替换标签内容时系统缓存旧栈；原委托拒绝重复选择也不阻止当前设置栈回根。共享壳在 WebView 历史记录中保存来源 `tab`，子页面留在打开它的标签中；旧记录没有该字段时继续按页面默认归属恢复。

### 告警与兼容边界

鸿蒙 UTF-8 编解码、组件快照、宿主上下文及字体枚举改用当前 SDK 接口。输入法选择器由组件持有 `InputMethodListDialog`，通过回调供桥接使用，关闭后刷新启用状态。目录选择先检查 `FolderSelection` 系统能力；普通文件选择在不支持该能力的手机上保留默认模式。

Android 的窗口 Insets 控制和无障碍节点边界改用兼容接口，候选管理的操作结果显示在已有的 live region，兼顾可见提示与读屏。`Drawable.getOpacity` 的抽象实现和浮动输入对话框的 `ADJUST_RESIZE` 是最低系统兼容所必需，弃用豁免仅限这两个方法，不对整个模块关闭诊断。Rust 只在消费方平台编译桌面辅助函数，Android 语音桥用具名错误代替单元错误，并移除无效的引用克隆；快照校验索引归为一个状态对象，仍由同一份快照共享唯一性与交叉校验。

系统调用的错误在操作边界记录固定上下文后继续交给既有失败回复路径，日志不新增输入、路径或凭据。只读文件与音频回调的清理失败单独记录，后续释放继续执行，避免清理错误覆盖原始失败。写事务仍传播写入、关闭与重命名错误。iOS 迁移到 trait 注册与新版 `onChange`，共享社区界面的兼容适配仍支持 macOS 13；不可变的模糊音规则表可从非隔离上下文读取。

iOS Rust 构建只用逐符号 `-U` 延后解析四个 Swift 桥接导出，替代已弃用的全局 `-undefined dynamic_lookup`，其余缺失符号仍需链接失败。鸿蒙 `resource://` 页面必须是单文件，所以构建显式关闭代码拆分并使用 2 MiB 的单文件预算；单文件校验继续保留。笔记脚本目录单独声明 ESM，避免 Node 再解析告警；不改变根包模块模式，以保留鸿蒙测试等生成的 CommonJS 脚本运行环境。源码守卫允许提示文案换行，并沿 `NativeCleanup.close` 检查描述符释放与下载请求销毁。文本规范化守卫按文件检查共享策略复用，不绑定固定调用总数，兼容候选翻译从双目标收窄为单目标。 Windows 纯策略测试在当前主机运行，编译时不继承 macOS 产品的 `MACOSX_DEPLOYMENT_TARGET`，避免产品的 13.0 目标误报主机浮点 `to_chars`（macOS 13.3）的可用性；macOS 原生产品继续按最低版本构建。

## Alternatives considered

- **继续修补一级聊天 Tab 的 inset。** 能保留最短的聊天入口；但此前同类修复后用户仍反馈底栏不可见，且不能解决共享壳主动隐藏导航的问题。按用户要求使用有顶部返回入口的二级页。
- **输入时隐藏导航，失焦后恢复。** 能给聊天保留更多空间；但用户恰恰需要输入时也能退出或切换，故移除这条行为。
- **把第二格恢复为社区。** 能直接浏览内容；但社区已经按作品类型并入各功能页，恢复完整聚合页会扩大本次改动，全部设置可直接复用现有页面。

## Consequences

聊天入口多一层，但返回不再依赖底栏。全部设置与首页共享部分列表，减少重复实现；iOS 标签页各自保留栈，Android 切换标签继续沿用清栈规则。没有调整版本号或触发发布。

## Verification

共享 UI 的导航回归测试覆盖二级标题、返回、标签归属、草稿保留和聚焦时仍显示底栏。Android 新增原生 `ChatNavigationDeviceSmoke`，随核心设备验收检查全部设置异步刷新、AI 设置进入聊天、输入焦点和顶部返回，不以 Tauri 开发壳替代原生宿主。原生验证分别运行 Android 宿主检查与设备验收、iOS 实际 App 构建及界面测试、HarmonyOS 逻辑测试与真实 HAP 编译；各命令的最终结果在 PR 中按层级列出。小米实机没有连接到本次环境，不能宣称已在该机型验证。
