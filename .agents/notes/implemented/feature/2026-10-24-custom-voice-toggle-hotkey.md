# Agent Note: 语音输入支持录入自定义切换快捷键

Status: implemented

## Problem

#8990 希望录入语音输入快捷键，并提出自定义识别、润色服务和预设服务测试失败。现有语音快捷键只有固定组合；共享服务目录已有自定义服务入口，但原报告没有平台、请求或响应，不能据此认定两个预设服务已修复。

## Decision

增加默认空串的 `keybindings.toggle_voice_input`，空串表示不额外绑定，保留所有既有语音快捷键的默认值。语义是按一次开始、再按一次结束，复用宿主已有语音切换动作；按住录音仍由原来的选项控制。

复用 `KeyChord`、`ToggleHotkeySlot`、共享录键控件与保存时冲突检查，语音键与其他切换键、启用的固定语音键及维护键互斥。沿既有 C ABI 返回规范主键与修饰键，宿主只映射本机事件，不再实现一套字符串解析器。macOS、Windows、IBus 与 Fcitx5 分别接线；设置入口只在宿主确实支持并有校验桥时出现。

录键取消、清空绑定和保存失败均不得改写既有绑定；重复按下不重复切换，禁用语音、失焦及敏感字段沿用现有门控。不得为了实现该功能关闭默认键、调整提供商默认值或记录真实录音及凭据。

## Alternatives considered

**直接让 `Ctrl+F9` 字段接受字符串**：设置结构更短，但会改变现有布尔字段的存储类型，旧客户端无法读取，且取消原来的快捷键需要额外迁移。采用新增空绑定字段，避免改变老用户行为。

**各平台自行解析组合键**：能快速在单个平台支持录入，但会重复别名归一化和冲突规则，难以保证共享偏好在各宿主一致。复用共享解析器，原生端仅将规范主键映射成本机键值。

## Consequences

默认不增加任何绑定，老用户的固定语音键保持原样。新增字段是额外切换动作，移动端不显示入口。Windows 与 Linux 通过公共 C++ 适配消费 Rust 解码结果，原生设置预检复用新增 `msime_client_check_toggle_hotkey`，不复制语法与占用表。

Linux 真实事件按 evdev 位置匹配 DOM code；Fcitx5 的 X 键码先减八。没有硬件键码的合成事件才回退到规范化 keysym，Shift 和布局变换不改变真实物理键绑定。按键消费保持到松开，改绑或修饰键提前松开不能重复切换。

系统或应用可能先占用用户录入的组合键，静态表不能证明全局可达。Windows 原生录键断言与截图已通过，修正退出码后的 CI 状态、全局钩子现场、完整 IBus smoke 的聚焦失败和完整 quick 仍是合并前缺口。原报告的豆包与 DeepSeek 测试问题没有可验证的请求／响应，现有自定义服务入口也尚未逐平台现场验收，本 PR 使用 `Refs #8990`，不自动关闭整项诉求。
