# Agent Note: 鸿蒙底行长按 123 打开符号面板，回车让出几 vp 给中/英

Status: implemented

## Problem

#6409 把手机底行改成 `123 | ， | 空格 | 。 | 中 | 回车` 之后，鸿蒙底行还有两处不顺手：

- 26 键下打开完整的符号面板要按三下：123、#+=、符号。华为小艺把「符号」键直接放在底行。
- 中/英紧挨着回车。两键误按的代价不对等：误按中/英，再按一下就回来了；误按回车，聊天里消息直接发出去，搜索框里直接提交。原来两键的触摸区在键帽之间那条缝的中线相接，拿不准的点击一半会落到回车上。

## Decision

只改鸿蒙，Android 和 iOS 不在这次范围内。

- **长按 123 打开符号面板。**
  - 26 键底行（`designActionRow`）和九键底行（`nineKeyActionRow`）的 123 都加了 `LongPressGesture`，写法和逗号键的长按一样：外面包一层 Column 挂手势。
  - 长按记一次 `SOFT_SYMBOL`，与点「符」键相同。
  - 单击仍然切数字层。在符号层里这个键是「返回」，长按不做事。
- **回车把触摸区让出 `KeyboardGeometry.RETURN_YIELD_VP`（6vp）给中/英。**
  - 回车的触摸区整体右移 6vp（`KeyboardGeometry.shiftedHitOffsets`），右边多出的部分落在键盘边缘的留白里。
  - 紧挨回车的中/英键，右侧伸过整个键距再加 6vp（`languageKeyHitRegion`）。两者的分界在回车键帽里 6vp 处，中间没有缝。
  - 只用在中/英紧挨回车的两种底行。123 符号层里回车左边是空格，不变（`designReturnKey` 的 `besideLanguage`）。
  - `KeyOptions` 新增可选的 `hitRegion`，`fixedKey` 有就用它，没有仍是 `keyHitRegion`。
- **键面不再参与命中测试。**
  - 原因：模拟器上逐点扫描时，回车键帽左边那 6vp 先成了谁都不接的死区。键面那层 Column 按自己的键帽大小被命中，挡住了伸进来的中/英键；可外层的回车又不在自己的触摸区里，所以那一下落空。
  - 做法：`keyFace` 加 `hitTestBehavior(HitTestMode.None)`。键的外层触摸区本来就覆盖整个键帽，普通键的行为不变。

## Alternatives considered

- **底行加一个「符号」键，像华为那样。** 最强的理由是不用长按，新用户一眼能看到。不用它，是因为底行已经有六个键，再加一个会把空格挤窄。长按 123 不改布局。
- **只让中/英伸进缝里（各占缝的一半改成全给中/英），不动回车键帽。** 改动最小。不用它，是因为键帽之间的缝只有 6vp，手指落点的误差比这大，误触主要发生在回车键帽的边缘上。
- **把中/英从回车旁边挪走。** 这是 #6409 刚做的决定，搜狗手机版也是中/英挨着回车，没有理由推翻它；这次只降低它的误触代价。

## Consequences

- **收益**：
  - 符号面板一下长按就到。
  - 中/英和回车之间拿不准的点击，算给代价小的那个键。
- **代价**：
  - 回车键帽最左边 6vp 按下去是中/英。回车约 64vp 宽，正常按它不受影响，但按在最左边缘的人会切换语言而不是回车。
  - 长按 123 对读屏用户不可见，他们仍然从 #+= 层的「符号」进入。
  - 这次只改了鸿蒙。
- **验证**：
  - `KeyboardGeometry` 的触摸区由 node 测试逐点断言：从中/英到回车中部，每一点只归一个键，分界在回车键帽里 6vp 处。
  - 模拟器（HarmonyOS 6.0.2）上逐点扫过 26 键和九键的边界：
    - 26 键：回车键帽内约 18px 处仍切换中英文，30px 处归回车，整段没有死区；
    - 九键：回车键帽内约 11px 处切换中英文，31px 处归回车。
  - 长按 123 在两种底行都打开符号面板，松手后不会顺带切到数字层。
  - 回归了打字母出候选、按回车、长按逗号弹出常用标点。
  - 没有在真机上验证。
