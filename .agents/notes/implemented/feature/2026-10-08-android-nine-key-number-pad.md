# Agent Note: Android 九键左侧符号栏、数字键面、算式结果与滑动出数字

Status: implemented

## Problem

Android 拼音九键左侧的符号栏原来是 ，。？ 三个键铺满三行键高，每个键约 54 dp 高，间距大到还能再放两个，也没法换成自己常用的符号（#5574）。笔画键盘用的是同一个外框，问题相同。

拼音九键按 123 切到的数字键面只是把网格键面换成 1–9：没有 0，没有小数点，左栏仍是 ，。？，右列最下面仍是 ！（#5590）。打版本号、价格、算式都要换别的输入法。报告人还希望在数字键盘上打 `12*12` 这样的算式后，结果直接显示在工具栏左侧（#5688），列购物清单时不用切到计算器。

临时打一个数字（「买 5 个苹果」）原来只能长按九键弹出选项再点一下（#5580）；报告人希望上滑直接出数字，下滑弹出字母，26 键英文的数字角标也上滑输入。

## Decision

### 左侧符号栏

- 拼音九键和笔画键盘的左栏是 `NineKeySymbolRail`（`platforms/android/java/app/msime/android/keyboard/NineKeySymbolRail.java`）：一个不显示滚动条、带上下渐隐边的 `ScrollView`，一屏显示 `NineKeySidebarPolicy.VISIBLE_ROWS`（5）个符号，多出来的上下滑动。每个符号键的高度在 `onMeasure` 里按栏高均分（`NineKeySidebarPolicy.rowHeight`），并扣掉键自己的上下外边距，所以键盘高度和行距偏好变了不用重建；符号不足五个时按实际个数均分整栏，不留空白；键盘高度调到最矮、五个会让每个低于 `MIN_ROW_HEIGHT_DP`（28 dp）时一屏少放几个。
- 符号表来自本地设置 `platform.android.nine_key_symbols`（`AndroidLocalSettings` 新增的 `TEXT` 类设置）：用空格分开的符号，存储前经 `NineKeySidebarPolicy.normalize` 规范成单空格连接、去重；空串、单个符号超过 4 个码位、含控制字符、超过 30 个符号或文本超过 200 个 UTF-16 单元一律不合规，写入时拒收，读到时整张表回到默认值。默认表是 `， 。 ？ 、 ： ； …… ～ @`：前三个和原来一样，！ 仍在右列最下面，不在左栏重复。
- 设置页「键盘 › 布局 › 九键左侧符号」用 `InputDialog` 编辑这张表，留空恢复默认（删掉这一项）。键盘每次出现时重读本地设置，`ImeLayoutRows.sidebarStale` 发现屏上的符号表和设置不同时，`render` 重建键行。
- 这个设置只在本机，不随账号同步：同步表在 `crates/client-core/src/account/settings_sync.rs` 的 `ANDROID_LOCAL_SETTINGS`，那里只有布尔、选项和整数三种类型。

### 拼音九键的数字键面

- 左栏是另一张符号表 `platform.android.nine_key_digit_symbols`，默认 `+ - * / = % ( ) : @ ， 。 ？ ！`：先给半角的四则运算和算式符号，！ 挪到第一屏之后（报告人原话「叹号移动到左侧红框区域，手指向上滑动时才能显示」）。设置页另有一行「九键数字键盘左侧符号」，规则与字母键面那张相同。
- 0 和小数点由 develop 上的 #5780 提供：数字键面的右列是删除、小数点、0（与 iOS、HarmonyOS 的九键右列一致），两者都经 `commitNineKeyLiteral` 字面上屏，小数点不随中文标点模式变成「。」；底行不变。本分支原先把小数点放在右列最下面（换掉 ！）、把 0 放进底行空格的左半边（`KeyboardActionRow.DesignSlot.ZERO`），与 #5780 同时存在会出现两个 0 键，rebase 时删掉了这一部分，只保留左栏的数字符号表。

### 算式结果

- `ArithmeticResultPolicy`（`platforms/android/java/app/msime/android/policy/`，无 Android 依赖）从光标前文字的末尾取最长的一段算式：加减乘除、括号、小数点、一元负号，`×` `÷` 和全角数字、运算符先换成半角。要以数字或右括号结尾、至少一次二元运算；不从一个数的中间开始。BigDecimal 求值，除法的中间结果按 `MathContext.DECIMAL128`（34 位有效数字）保留，只在最后格式化时舍到至多 10 位小数；最初用 `DECIMAL64`（16 位）时 `50/3*600000` 显示成 `10000000.000000002`，除法的舍入误差被后面的乘法放大到了第 9 位小数。除以零或结果的绝对值达到 10^15 时没有结果。
- 最长的完整算式像日期或号码时整体不给结果（`looksLikeNumberSequence`）：两个以上同一个 `-` 或 `/` 连着的纯数字段（`2026-10-08`、`2026/10/08`、`138-1234-5678`），或者有以 0 开头的多位整数（`0571-88886666`、`10-08`）。不退到更短的后缀，否则 `138-1234-5678` 会改算 `1234-5678`。
- `ImeCalculator`（`core/`）在选区变化（`onUpdateSelection`）和切换键面时，只要键盘在数字 / 符号层（`Layer.SYMBOLS`，九键和 26 键都算）、不是密码框、没有组字，就向编辑器要光标前 64 个字符重算；结果是工具栏品牌键右边的一个 `PILL` 胶囊「= 144」，没有结果时隐藏，不占宽度；胶囊最宽 96 dp，长结果截断显示（点按仍上屏完整结果），否则七个各至少 40 dp 的工具栏键加上它会超出 393 dp 宽的屏幕，把最右边的「收起」挤到滚动区外。点按经 `commitNineKeyLiteral` 上屏 `=144`，算式后面已经打了 `=` 时只上屏 `144`。离开数字层时 `render` 里的 `syncVisibility` 不做 IPC 就收起它，离开输入框时清掉。
- 读到的上文只在内存里算一次，不记日志、不保存。

### 九键滑动出数字

- 拼音九键字母键面的九个网格键都挂 `ImeLayoutRows.bindNineKeySwipe`，判定在 `NineKeySwipePolicy`。开关和方向是单独的本地设置「键盘 › 手势 › 九键滑动输入数字」（`platform.android.nine_key_swipe`，取值 `off` / `up` / `down`，默认 `off`，不随账号同步），只在拼音九键可用的版本里列出。选了方向后沿它滑过 14 dp，键面换成数字，松手上屏键上印的数字（1 键是 1）；往反方向滑过 14 dp，弹出和长按相同的数字与字母选项（1 键没有字母，不弹）。
- 按下时不拦截，没滑过阈值前点按和长按仍由按钮自己处理；滑过阈值的那一刻给按钮补一个 `ACTION_CANCEL`，它不会再点按或长按；长按弹窗已经出来时不再判定滑动。
- 26 键英文键盘的「上滑出数字」已经存在：设置「键盘 › 手势 › 滑动方向」选「上滑」即可，这次不改它。九键不跟它的开关和方向走。
- 最初的实现让九键共用 26 键的「滑动输入符号」开关和方向。那个开关默认开、方向默认下滑，于是升级后所有九键用户开箱就有了滑动：手指落下后稍往下拖就打出数字（还会先提交正在组的拼音），稍往上拖就弹出选项、丢掉这次点按；而报告人要的上滑出数字、下滑出字母恰好相反。改成单独一项、默认关闭，老用户的点按不变，报告人选「上滑」就是他要的手势。

## Alternatives considered

- **只把三个键改小、固定显示五个，不滚动** — 改动最小；但用户要求能上下滑动和自定义，固定五个装不下自定义表，最后还是要滚动。
- **符号表放进共享偏好（`crates/client-core` 的 `Preferences`），走 Tauri 设置页** — 能随设置同步，其他平台日后也能读；但只有 Android 的九键有这条可滚动的符号栏，共享偏好要改 Rust 结构、默认值、同步和 Tauri 页面，其他平台却没有任何消费者。先按 `platform.android.glide_typing` 的先例只存本机，等别的平台也做同样的符号栏时再挪进共享偏好。
- **把 0 放进网格，做成 4×3 的数字键盘** — 和手机拨号盘一样，0 在 8 下面；但九键块固定三行键高，塞进第四行要么整块变高（切换键面时键盘高度跳动），要么每行变矮。报告人的截图也明确把 0 画在空格的左半边。
- **数字键面的右列保留 ！，小数点放进左栏** — 改动更少；但小数点在数字里和 0 一样常用，藏进可滚动的左栏要多一次寻找，而报告人点名要它在右下角。
- **0 放在底行空格的左半边、右列只换出小数点** — 本分支最初的做法，报告人的截图也这样画；但 #5780 先合入 develop，按 iOS、HarmonyOS 的九键把 0 和小数点都放进右列（拆分在数字键面上本来就不起作用），两个位置同时存在只会多一个 0 键。跟随已合入、与其他平台一致的那一种，空格也保持原宽。
- **算式求值放进 `crates/engine`，所有平台共用** — 架构上「输入算法归引擎」；但这里算的是已经上屏的文字，不是组词，也不碰候选和会话状态，放进引擎要新增 C ABI、JNI 和原生重编，换来的只是一个四则运算。先做成 Android 的纯 Java 策略类，别的平台要做时再一起挪进引擎。
- **自己记录数字键面上点过的键，不读编辑器** — 不需要 `getTextBeforeCursor`；但删除、移动光标、粘贴、26 键符号层打的运算符都会让记录和文档对不上，结果就错了。读光标前的文字是唯一的事实来源。
- **用第三方表达式库（如 exp4j）** — 现成、经过测试；但只要四则运算和括号，一个约 200 行（含注释）的递归下降就够，新增依赖要走依赖审批，还要处理它对 `×` `÷`、全角字符和 BigDecimal 精度的不同约定。
- **九键共用 26 键「滑动输入符号」的开关和方向** — 一个设置管两种键盘，报告人把方向改成「上滑」两边一起变；但那个开关默认开、方向默认下滑，九键老用户升级后点按就变了，而且默认手势和报告人要的相反。这是第一版的做法，审查后改掉。
- **九键单独一项、默认上滑出数字** — 报告人开箱即得；但同样改变了所有九键老用户的点按，上拖一点就打出数字而不是拼音。
- **把 26 键的默认方向改成上滑** — 新用户开箱就是报告人要的手势；但这是已经随账号同步的设置，改默认值会让所有没动过它的 26 键用户的下滑突然失效。
- **每个符号固定 dp 高度** — 不需要自定义 `onMeasure`；但九键块的高度随键盘高度偏好在 75%–130% 之间变，固定高度时一屏可见个数跟着变，有时露出半个键。

## Consequences

- **收益**：同样的高度放五个符号，默认多出 、：；……～@；用户可以把常用符号换进来，顺序即显示顺序。数字键面能打出 0、小数点和四则运算符号，不用离开九键；打完算式点一下工具栏就能补上结果。九键上一划就能打出单个数字，不用长按再选。
- **代价与已知上限**：五个符号时每个约 32 dp 高，比原来窄，误触面积变小；左栏滚动时手指从符号键上纵向滑开会被 `ScrollView` 截走，这一下不上屏。设置不随账号同步，换设备要重设。数字键面右列没有「重输」和 ！，！ 在左栏第一屏之后。为了不把日期和电话号码当算式，不带空格的同号连减、连除（`20-10-5`、`100/5/2`）也不给结果，带空格或混用别的运算符照常算；长结果在胶囊里截断显示；在数字层每次选区变化多一次 `getTextBeforeCursor` IPC。九键滑动默认关闭，报告人要在「九键滑动输入数字」里选「上滑」一次；打开后纵向滑动超过 14 dp 的点按（手指落下后拖动）会变成数字或弹窗，而不是原来的字母键。

## Verification

`platforms/android/tests/keyboard/NineKeySidebarPolicySmoke.java` 锁住两张默认表、一屏五行的行高、解析与校验，以及本地设置按 `TEXT` 收值、不进同步；`NineKeySwipePolicySmoke` 锁住两个方向、阈值、默认关闭且只在本机、1 键的特例；`ArithmeticResultPolicySmoke` 锁住取算式、优先级、小数精度（含先除后乘）、全角输入、日期和电话号码等没有结果的情况和上屏文字；由 `bash platforms/android/check-host.sh` 运行。设置页的编译由 Gradle 的 `compileFullDebugJavaWithJavac` 覆盖，check-host 不编译 `home/`。
