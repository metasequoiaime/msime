# Agent Note: Android 九宫格将宽度和加高空间留给常用键区

Status: implemented

## Problem

#8784 希望九宫格的左右栏各占 15%、中央占 70%，并将提高键盘高度所得的空间分给上面三行。现有宽度为 0.9:3:0.9，中央只有 62.5%；高度调整由四行均分，底行分走四分之一的增量。#8779 已将高度上限放宽至 170%，本次复用这个范围。

## Decision

- `NineKeyLayout` 的两侧和中央份额改为 3:14:3，热力图继续共用这些常量。
- 实际由 `rebuildNineKeyRows` 构建的网格在正调整量时，底行固定 52 dp，增量全部分给上方网格。拼音、九键双拼和其他中文布局借用的数字页使用同一规则，切换字母与数字层不改变键区总高。
- 默认高度和负调整量继续四行均分。26 键等其他键面保留原规则；独立四行的日语、注音键面不属于这个三行外框。
- 使用实际已建出的网格状态选择分摊，不能只凭用户选择的布局判断，否则 26 键借用数字页和九键进入扩展符号页会套错规则。键区和其兄弟底行始终使用同一状态与窗口封顶后的调整量。
- 九宫格主体挂独立的高度角色，上方「数字行」借用到数字页的补充符号行仍按原字母行分摊，避免切层时多拿增量而改变总高。
- 不增加设置或改变存储格式，总高、75%–170% 范围、窗口封顶、底部留白和底栏规则均复用现状。

### 旧笔记审计

- [四行同高](2026-10-10-android-equal-bottom-row.md)：部分取代九宫格正调整量的均分决定，其他布局与缩小量继续成立，两篇互链。
- [高度范围](2026-10-08-android-keyboard-height-range.md)：范围和封顶继续成立，不再扩大上限。
- [数字页](2026-10-16-android-nine-key-numeric-bottom-row.md)：部分重叠，保留键位和空间归属；本次只改变同一外框的比例及增量分配。
- [热力图](../bug-fix/2026-10-16-mobile-key-heatmap-follows-keyboard.md)：继续成立，宽度由共用常量自动跟随。
- 其余关键词命中为其他平台、笔画、14 键或候选窗，和本次外框无关；没有需要删除的提案。

## Alternatives considered

- **继续四行均分**：底行与网格键始终同高，切层简单，符合之前的统一布局决定。但 #8784 明确希望新增高度集中给使用最频繁的三行，此方案不能实现。
- **所有布局都将调整量交给上方三行**：只需改一个默认公式。但会改变未提出此需求的 26 键等键面；负调整量也全部交给三行会使上方键帽更小，因此仅九宫格的正增量改变分配。

## Consequences

- 收益：上三行占更大的水平和垂直空间；底行在默认和缩小时仍保持原有点击面积。热力图随共用常量同步，切到数字页的总高不变。
- 代价：加高后的底行与网格不再同高；侧栏更窄，长标点和重输文字继续沿用既有字体策略。九键双拼虽然外框相同，内部有四行，增量由其四行均分。
- 高度范围和窗口封顶不变，本次没有增加 170% 以上的档位；如果需要更高，应另行检查横屏窗口的可用空间。

## Verification

- 固定比例回归在旧实现失败、新实现通过；`KeyboardGeometrySmoke` 检查 −46…129 完整范围的增量守恒和非九宫格布局的分配。
- `NumberRowDeviceSmoke` 在 130% 高度下检查字母数字行、借用数字页补充符号行和扩展符号页的行高与位置一致。
- `NineKeyNumericLayoutDeviceSmoke` 在默认、75%、130%、170% 的真实字母及数字键面上测量两侧和中央比例、上方键区与底行高度、切层总高，并保留数字、空格、小数点和符号面板投递验收。
- 253 项 JVM 冒烟、200 个设备套件源文件编译通过。原生产品与 API 28、35 的最终验收结果随同 PR 记录；没有真机单手握持舒适度验收。
