# Agent Note: Android 长按候选打开释义卡片

Status: implemented

## Problem

Android 键盘长按候选弹出系统 `PopupMenu`：可上屏的释义义项、词库操作（优先显示、固定到首位、取消固定、删除词条…）、朗读和加入生词本挤在一个菜单里，看不到完整译文，也看不出译文从哪里来，想把译文复制出去没有入口。#10915 由维护者在 2026-11-05 定下三端一致的设计：长按打开一张「释义」卡片，盖住按键区，列出译文和来源，底部是「上屏译文」「复制译文」，原菜单的操作全部并进卡片。

## Decision

- **入口和位置**：候选条（固定槽位和横向完整候选条）与展开候选面板里的长按都走 `ImeCandidates.openGlossCard`，打开 `ImeGlossCard`。卡片和一层挡板最后加进 `keyboardSurface`，盖在所有面板之上，包括展开的候选面板；卡片顶边跟着 `alignOverlaysBelowTopRow` 对齐顶部一行的底边，候选栏和读音行留在上面。挡板盖住顶部一行，读屏描述「关闭释义」，点上去只关卡片、不选词。长按的门槛与原菜单相同（`candidateGlossInsertionEnabled` 或 `candidateManagementEnabled`），候选的读屏描述末尾从「；长按管理」改成「；长按查看释义」。
- **关闭**：点挡板（候选栏）、点卡片右上的「收起」、返回键（`onKeyDown` 的 `KEYCODE_BACK`）、收起键盘（`closeToolbarPanels`，`finishInputViewPresentation` 经它）都关；每次 `render` 由 `ImeGlossCard.sync` 检查会话（换输入框就换）、组字是否还在、组字文字是否变了，变了就关，实体键盘接着打字不会留下属于旧组字的卡片。候选只换了一代而组字没变时卡片留着：停顿后的整句重排（`PauseRerankController`）正好在用户停下手、伸手长按的时候到达，设备验收里卡片打开 130 ms 就被它换代关掉过；云候选、AI 候选到达同理。卡片内容属于候选文字，换代不影响；词库操作执行时先看长按时的身份是否还是当前的，换了代就在当前候选里按原文找同一个词，找不到提示「候选已更新，请重新长按」。上屏、词库操作之后卡片也关。
- **内容**（`CandidateGlossCardModel`，纯 Java，JVM 冒烟覆盖）：标题「释义」，候选原文 26 sp，每个目标语言一段，段首「目标语言名 · 来源名」，来源是离线释义、水杉账号、腾讯翻译、小牛翻译、自定义服务、AI 辅助之一；义项按 `CandidateTranslationPolicy.insertionGlosses` 切开逐条列出，点哪条上屏哪条。某语言离线释义有就用离线，没有才用在线，与候选栏的 `mergeGlosses` 相同；一段都没有而离线英文释义有时补一段英语，因为目标语言不是英语又没装那种语言的词典时候选栏上画的就是英文释义。没有译文时显示「暂无译文」；只有没配置可用的在线翻译服务（路由是 `NONE`）时下面才说明「可以在设置里开启翻译服务」，正在请求时说「正在请求译文…」，请求过仍没有、或这个候选按规则不送翻译服务时就不再多说。
- **按钮**：「上屏译文」上屏第一目标语言那一段的第一个义项并结束组字（命令 3），不是整段（整段会把「my; mine」连分号一起上屏）；第一目标语言没有译文时两个按钮都不可用，读屏补一句「暂无某语言译文」，不拿英文补段或别的语言顶上，要那些义项就点义项本身。走 Ctrl+Enter 义项页同一条 `commitTranslationSense`；卡片开着就说明组字没变，不再核对候选身份。原菜单专用的 `insertExpandedCandidateGloss`、`insertStripCandidateGloss` 和 `expandedCandidateIsCurrent` 随菜单一起删掉。「复制译文」把同一项写进系统剪贴板，诊断行提示「已复制译文」，卡片不关。两个按钮都作用于同一项。这四条（第一条义项、不拿别的语言顶上、设置提示的条件、「仅当前高亮」时长按非高亮候选也问一次）与 HarmonyOS 的卡片（#10924）一致。
- **原菜单的操作**：在底部按钮上方一行可横向滚动的次要操作里，顺序与原菜单相同：优先显示、固定到首位、取消固定、删除词条…、朗读、加入生词本。「删除词条…」点了就地换成「确认删除此词条」，不开子菜单也不开对话框（取代[原来的子菜单确认](../bug-fix/2026-10-14-android-candidate-removal-submenu.md)，理由相同：输入法里不开可获得焦点的窗口）；词库操作执行前复核候选身份。朗读和加入生词本用卡片上的译文（卡片没有译文时用候选栏上显示的那份）。
- **译文从哪里来**：只走现有通路。离线释义在卡片自己的单线程上为这一个候选查（与整页的 `scheduleCandidateGlosses` 同一个 `NativeClient.candidateGlosses`，同样受「候选英文释义」开关和方案门槛约束）；整页释义的 worker 只排一个任务、新的挤掉旧的，卡片的查询放在那里会被下一次刷新无声挤掉。在线译文先读整页共用的缓存：用户服务的直接读，账号的先在工作线程取绑定、回主线程再取一次，一致且 `CandidateTranslationStore.boundTo` 说缓存正属于这个账号才读，不替整页改绑定。离线和缓存都没有的目标语言经新加的 `CandidateTranslationStore.request` 单独请求一次：不防抖、不取消排着的整页请求，回答照整页规则清洗后进同一份缓存，缓存清空（换服务、换凭据、换账号）后才到的回答丢掉。在线请求的门槛与整页的账号路径、用户服务路径相同（没有本地模式、不是日文方案、方案显示释义、来源可以送翻译服务、`candidate_translations` 开着且选了服务）。
- **目标语言**：只有主目标语言。#8218 定下手机键盘只显示一种候选翻译、不读 `translation_secondary_language`（`check-host.sh` 守着），iOS 的 `CandidateTranslationPreference.secondary` 固定为 nil，HarmonyOS 手机 `keepPrimaryOnly`；卡片的模型按目标语言列表分段，有几种列几种，触屏键盘上就是一段。
- **隐私**：单独请求让发出去的词超出了 PRIVACY.md 原来写的「当前一页」：范围是「仅当前高亮」时长按的可以不是高亮的候选，展开面板里长按的可以不在当前一页。PRIVACY.md 的 Android 用户服务一段和水杉账号一段各加了一句，交维护者审阅。
- **无障碍**：卡片开着时被盖住的按键行、功能行和展开面板设成 `IMPORTANT_FOR_ACCESSIBILITY_NO_HIDE_DESCENDANTS`，读屏摸不到看不见的键；卡片是一个 accessibility pane（标题「释义」），标题标成 heading，候选原文读「候选：你好」，每个义项读「英语 · 离线释义：hello；点按上屏」，按钮的读屏文字就是按钮上的字，「收起」读「收起释义」。

## Alternatives considered

- **保留 `PopupMenu`，只在菜单顶上加一行译文和「复制」**：改动最小，系统菜单自带无障碍。但菜单项只能是一行短文字，长译文和来源放不下；菜单是可获得焦点的弹出窗口，WebView 浏览器里一弹键盘就被收起（#5653），这正是剪贴板、常用语面板都改成画在键盘里的原因；而且与 iOS、HarmonyOS 已定的卡片设计不一致。
- **卡片打开时重新跑一遍整页的离线释义和在线翻译调度**：不用写单独查询，回答直接画到候选栏上。但整页调度按代次去重（`candidateGlossRequestedGeneration`、`signature`），同一代不会再查，强行重查要绕过这些去重；在线的整页刷新还会取消已经排着的请求、按「仅当前高亮」只问高亮的那个，长按的若不是高亮候选照样问不到。为一个候选单独查，规则可控，也不扰动整页。
- **账号路径直接调 `verifyCandidateTranslationBinding` 再读缓存**：与整页完全同一条核对。但它用一个共享的代次，下一次整页 render 发起核对就把卡片这次的回调作废，有一条分支（换号且缓存非空）根本不回调，卡片会一直停在「正在请求译文…」。改成只读的 `boundTo` 核对，绑定的建立和改写仍归整页。
- **按 #10915 的字面读第二目标语言，卡片列两段**：维护者的设计写了「有第二目标语言时两段都列出」，卡片也没有候选栏那样的高度顾虑。但手机上不读第二目标语言是 #8218 定的、有源码守卫，iOS 和 HarmonyOS 手机同样不读，只在 Android 卡片上读会让三端不一致，也是在没有单独授权的情况下改变一个已定的读取规则；PR 里把这一点列出来，要翻转由维护者决定。

## Consequences

- **收益**：长按能看到完整译文和来源，能上屏、复制译文；原菜单的所有操作都还在，删除确认一次长按完成；全程不开任何弹出窗口，WebView 编辑器里键盘不再被长按收起；在线服务开着时长按任何候选都能拿到译文，回答进缓存，之后候选栏和下一次长按都不再请求。
- **代价**：原菜单的操作多了一层位置变化（从菜单列表变成卡片底部的一行），词库操作要横向滚动才看得全；卡片盖住键区期间不能打字，要先关掉。单独请求让发出去的词比 PRIVACY.md 原来写的范围多了长按的那一个；水杉账号没有负缓存，没有译文的词每次打开卡片都会再问一次。
- **测试**：`tests/candidate/CandidateGlossCardModelSmoke.java` 覆盖分段、来源名、按钮对象、英文补段、暂无译文的说明和要单独请求的语言；`tests/candidate/CandidateTranslationStoreSmoke.java` 覆盖单独请求不取消整页请求、进共享缓存、缓存清空后丢弃、已缓存或非中文不请求、`boundTo` 只读。设备上 `CandidateGlossDeviceSmoke` 走打开卡片、内容、删除的就地确认、返回键、点候选栏、「收起」三种关闭、复制译文（读系统剪贴板）、上屏译文、优先显示、义项上屏，以及展开面板里长按后返回键只关卡片、面板还在。`StaleCandidateDeviceSmoke` 原来直接调随菜单删掉的 `insertStripCandidateGloss`，改成打开卡片后把视图换成旧组字、确认 `sync` 关掉卡片且会话不受影响。`check-host.sh` 去掉了钉住 `PopupMenu` 子菜单和朗读菜单项的源码守卫：删除确认由设备冒烟覆盖；朗读入口按设备实际安装的 TTS 服务断言存在且可用或不存在，模拟器缺引擎也覆盖隐藏分支，不再用源码字符串守卫替代行为。该断言只验证入口可用性，不代表真实声音播放已验收。
