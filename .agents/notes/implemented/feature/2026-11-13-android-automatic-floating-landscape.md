# Agent Note: Android 横屏自动浮动键盘

Status: implemented

## Problem

#11346 希望 Android 键盘在横屏时自动缩成可移动的浮动面板，竖屏时恢复占底停靠。现有浮动键盘只由本机手动开关控制，旋转后不会按方向切换。

## Decision

Android 新增本机布尔设置 `platform.android.floating_keyboard_auto_landscape`，默认关闭且不随账号同步。打开后，横屏强制使用现有浮动键盘窗口布局，竖屏强制停靠；关闭后完全沿用 `platform.android.floating_keyboard` 手动开关。外接键盘候选条模式仍优先停靠，避免候选条与浮动面板争用同一输入法窗口。

设置页把自动模式放在手动浮动开关下面；自动模式打开时手动开关置灰，但其值保留，关闭自动模式后恢复。浮动几何、位置和拖动逻辑不另复制，方向变化经现有 `onConfigurationChanged`/`render` 路径重新套用窗口和表面布局。

自动模式下竖屏仍停靠，因此底部高度设置保持可用，不因保留的手动浮动值而置灰。自动开关保存后重新读取页面状态，手动开关与底部高度均以落盘值更新，避免连续切换使用旧快照。

## Alternatives considered

- **默认让所有用户横屏自动浮动**：直接满足报告者预期，但会改变已有用户的键盘出厂行为；仓库规则要求这类默认值变化有单独授权，因此采用默认关闭的显式开关。
- **把现有布尔开关改成三态值**：存储更集中，但会改变旧版布尔值的解析和同步兼容边界；新增独立本机键能保留旧值并在关闭自动模式后恢复手动选择。
- **横屏时另建一套键盘窗口**：可以隔离方向状态，但会重复已验证的浮动窗口、insets 和拖动实现；复用 `FloatingKeyboardPolicy` 的生效判断，减少窗口生命周期分叉。

## Consequences

- 自动模式打开后，旋转横屏会让应用不再为键盘让出高度，竖屏会恢复原来的停靠布局；手动浮动位置仍按现有千分比保存并在尺寸变化后钳回窗口。
- 设置新增一个本机字段和一个 Android 设置行，旧安装升级后默认行为不变；自动模式不会在 iOS、HarmonyOS 或共享设置页出现。
- 需要 Android API 28/35 设备验证旋转、浮动面板触摸区域和返回竖屏后的停靠窗口；JVM 策略与本机设置回归覆盖默认值、生效条件和不同步属性。
