# Agent Note: Android 世界时钟按国家名称搜索

Status: implemented

## Problem

添加世界时钟城市时，用户必须先选择洲，再在较长的国家列表中滚动查找目标国家。国家目录已经随包离线提供，但页面没有按国家名称定位的入口。

## Decision

从键盘选择洲后，在非导出的 `WorldClockCityActivity` 内选择国家和城市。国家名称输入框和「搜索」按钮属于普通 Activity 窗口，输入法可以正常为它提供输入连接；搜索只过滤当前洲的离线国家列表，保留现有排序，空查询恢复完整列表，无匹配时显示明确提示。搜索不联网、不申请权限，也不改变城市持久化格式。

城市添加仍在工作线程调用共享 Rust 的 `worldClock` 接口。选择页单独成任务、不进入最近任务；保存或取消后返回原编辑器。`ResultReceiver` 只通知完成，输入法等原包名、输入框、可见窗口和偏好数据目录都恢复后重新加载时钟，搜索框通过 `privateImeOptions` 明确排除，输入法销毁后旧回调失效。旋转时保留国家、查询和城市页状态。窗口显示早于异步运行时初始化时保留恢复请求，在引擎或无会话外观加载完成的真实回调中继续；不以固定延迟猜测目录何时就绪，也不因过渡编辑器提前消费恢复。

## Existing note audit

- [离线世界时钟](../feature/2026-10-23-offline-world-clock.md)：复用现有离线国家目录、城市选择和保存协议。
- [剪贴板搜索](2026-10-09-android-clipboard-search.md)与[剪贴板编辑](2026-10-09-android-clipboard-edit.md)：沿用在普通 Activity 中承载可编辑文本的边界。

## Alternatives considered

- 每次输入都访问地理编码服务：不用，世界时钟的目录和功能应保持离线，联网会引入隐私和可用性问题。
- 将所有城市直接放进一个搜索列表：不用，会破坏现有按洲、国家再选城市的层级和城市排序。
- 在输入法面板里放 `EditText`：不用切换任务，控件也更少，但它与软键盘共用输入法窗口；点击后国家面板会被常规键区替换，文字无法稳定写入搜索框。原设备用例用 `ACTION_SET_TEXT` 绕过了这一限制，因此改为真实软键盘输入来验收。

## Consequences

用户可以用当前软键盘输入国家中文名称，缩小当前洲的列表，再选城市。代价是从键盘到 Activity 的任务切换；已保存城市和当前编辑器正文保持原状，完成后重新加载时钟。选择页只接收应用内部传来的固定目录和离线目录，不接受外部启动。

## Verification

- API 35 上先将旧用例的 `ACTION_SET_TEXT` 换成点击软键盘输入 `meiguo` 并提交，旧实现无法把「美国」写入国家搜索框，复现失败。
- API 35 复跑发现原编辑器已显示、偏好目录仍被输入会话重启清空的竞态，时钟停在「时钟尚未就绪」。恢复改为等待窗口和数据目录同时就绪后才消费请求。
- 专用 API 35 模拟器上完整 `WorldClockDeviceSmoke` 通过：软键盘输入 `meiguo` 并提交「美国」、筛选国家后添加纽约、原编辑器保持空白、时钟持续刷新、东京 ISO 时间和系统星期上屏、城市重启持久化、长按删除与再次重启、返回键区。搜索结果点击限定为按钮，避免误点显示同名国家的搜索框；空编辑器按 `isShowingHintText` 判定，符合已有设备用例。
- `bash scripts/verify-local.sh --quick` 通过，覆盖仓库契约、笔记、Rust workspace、Android Rust 目标和原生 Java 宿主；未提交的用户图片不属于任务范围，验证时临时从作用域扫描排除，文件保持原状。
- 原生 Android 宿主 Gradle 构建通过；`check-host.sh` 的 281 项 JVM smoke 和 245 份设备套件源码编译通过。
- Java 改动复用 `b0a6a8005` 的原生宿主 APK 中的资源和 arm64 JNI：该提交与本分支的 Android JNI、`NativeClient` 及参与 Android 构建的共享 Rust 源码一致；排除 AGP 生成的 `assets/dexopt` 后，使用 JDK 21 与原生宿主的 Gradle 工程重新打包。构建树与专用 API 35 AVD 位于有足够空间的外盘，不在不足 50 GiB 的系统盘新建构建树。
