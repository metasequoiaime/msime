# Agent Note: 德语读音取方括号的实际读音，韩语读音改成文化观光部式罗马字

Status: implemented

## Problem

[法日西俄德韩释义行的读音](2026-11-01-target-language-gloss-readings.md)第一版里，德语只取维基词典斜线的音位层（`haben` 的 `/ˈhaːbən/`、`Mutter` 的 `/ˈmʊtər/`），比学习者在词典里看到的实际读音（`[ˈhaː.bən]`、`[ˈmʊtɐ]`）多写了 `ər`、`ən`；韩语给的是 dump 的窄式 IPA（`소지하다` 的 `[ˈsʰo̞(ː)d͡ʑiɦa̠da̠]`，13,729 行里约 3,400 行带 `(ː)`、`ɦ` 这类记号），而韩语学习者用的是罗马字，和日语给赫本式罗马字是同一个道理。维护者认可了两项调整：德语有方括号的语音标音时优先给它，没有时退回斜线；韩语改给文化观光部式罗马字（Revised Romanization of Korean）。其他四种语言不变。

## Decision

**德语**（`scripts/build_target_pronunciations.py` 的 `BRACKETS_FIRST`）：地区仍先比（不带标签的、标准音地区的、其他地区的），同一档里方括号的语音标音排在斜线的音位标音前面。只标了一部分的方括号（`haben` 的 `[-bn̩]`、`sprechen` 的 `[ˈʃpʁɛ-]`）照旧不用，所以没有完整方括号的词仍给斜线（`Katze` 的 `/ˈkatsə/`、`sprechen` 的 `/ˈʃprɛçən/`）。方括号优先以后，标 `colloquial` 的口语缩读（`er` 的 `/ɐ/`、`mal` 的 `/ma/`）、标 `plural` 的复数读音（`Knie` 的 `[ˈkniːə]`，单数是 `/kniː/`）和标 `especially` 的地区偏好读法（`Bon` 的 `[bɔŋ]`，不带标签的是 `[bɔ̃ː]`）在德语里丢掉，免得排到标准读音前面；评审逐个查过这次换了读音的词，只有这两个是被带标签的方括号顶掉的。只写在 `sounds[].other` 里的方括号不取（见下文）。17,903 个词里 2,184 个换了读音，给方括号的从 2,721 个变成 4,905 个，词数不变。

**韩语**：罗马字由生成器按《国语的罗马字表记法》（文化观光部告示第 2000-8 号）从谚文生成，规则写在 `revised_romanization` 那一节的说明里：

- 发音用维基词典写的发音谚文（`sounds[].other`，`읽다` 的 `[익따]`、`환율` 的 `[화뉼]`），连音、鼻音化、流音化、送气、腭化和 ㄴ 添加都已经在里面，ㄴ 添加这类靠拼写推不出来。维基词典没写发音谚文的词条（约七千个，多是 `개`、`책`、`세계` 这类元音有 ㅐ/ㅔ 两读、只给了 IPA 的），按标准发音法从拼写推出发音，规则只到不需要知道词的构成为止；收音 ㅅ、ㅊ、ㅌ 在 ㅎ 前先读代表音 ㄷ 再送气成 ㅌ（`꽃향기` 是 `kkotyanggi`），只有 ㅈ 送气成 ㅊ（`맞히다` 是 `machida`），现在的表里没有词走到前一种情况。
- 按规范：紧音化不写（`학교` 是 `hakgyo`，`없이` 的 `[업씨]` 是 `eopsi`）；元音按拼写（`희망` 是 `huimang`）；ㅎ 在 ㄴ、ㄹ、ㅁ、ㅇ 和元音后照读，维基词典写出的弱化读法（`전화` 的 `[저놔]`）不算；体词里 ㄱ、ㄷ、ㅂ 后的 ㅎ 照写（`묵호` 是 `Mukho`），谓词照常送气（`좋다` 是 `jota`，`시작하다` 是 `sijakada`）；音节界线会读错的地方加连字符（`goyang-i`、`jung-ang`、`chin-gu`）；专名首字母大写（`Silla`）；词与词之间的同化不写（`누워서 떡 먹기` 是 `nuwoseo tteok meokgi`）。
- 词头不是谚文的词条（`1월`、`K-pop`、`-까지` 这类，原来 41 个有 IPA）不收：发音谚文和拼写对不上，紧音化无从判断。韩语表从 13,729 词变成 13,688 词，483,328 字节变成 327,680 字节。
- 规范的正文例词（`Baengma`、`Wangsimni`、`Jiphyeonjeon`、`Apgujeong`、`Hae-undae`……共 42 个，另有只用发音谚文能写对的 `Hangnyeoul`、`allyak`）全部写进 `scripts/test-target-pronunciations.py`，从拼写推出的那条路径必须逐个写对。

**数据**：从锁里同一份过滤后的输入（`target-pronunciations-input-2026.10.25.jsonl.gz`）重建，`filter` 没改，所以输入不用重新发布。法、日、西、俄四张表与 `-r2` 逐字节相同。新的数据库和 NOTICE 发布在 `metasequoiaime/chinese-ime-lm` 的 `target-pronunciations-2026.10.25-r4`，锁的 `built` 指向它。`-r3` 是这个变更第一次发布的结果，德语那时还没丢掉 `plural`、`especially`，`Knie` 给成了复数读音；`-r4` 只换了德语表（`Knie`、`Bon` 两个词），其余五张表和 NOTICE 与 `-r3` 逐字节相同，`-r3` 没有被任何已合并的提交引用过。NOTICE 的「Changes」写明德语取方括号、韩语是按规范生成的罗马字。六个数据库合计 3,596,288 字节，连同 NOTICE 3,597,923 字节。重建在维护者的 MacBook 上用 Homebrew 的 Python（SQLite 3.54.1，与锁里的 `sqlite_version` 相同）做：先用旧生成器重建 `-r2`，七个文件与锁逐字节相同，再用新生成器连跑两遍，结果相同；`-r4` 同样在这台机器上构建，先用 `-r3` 的生成器重建出与 `-r3` 逐字节相同的七个文件，再用修正后的生成器连跑两遍，结果相同，上传后再下载回来与本地逐字节比对。Mac Studio 上的 Python 是 SQLite 3.53.4，同一份输入重建 `-r2` 得到不同的字节，所以没在那里构建；输入 13 MB、输出不到 4 MB，不占什么磁盘。

**宿主**：韩文行的读音现在是罗马字。Android、iOS、鸿蒙校验共享层回答的形状时，韩语和日语一样只要求非空（`CandidatePronunciationModel.wellFormed`、`CandidateGlossModel.wellFormed`、`CandidatePronunciationPolicy.wellFormed`），读屏按开头不是 `/` 或 `[` 念「读音」而不是「音标」，不用改。macOS、Windows、Linux 原样画共享层的回答，只改了注释。设置页「显示读音」的说明在六个平台都改成「日文和韩文给罗马音，法、西、俄、德语给国际音标」；macOS 和 Windows 那一句另写明韩文罗马音来自随包的离线词表、日文罗马音由系统生成。

**核对**（只用于检查，不是输入）：kaikki.org 现在的韩语 dump（2026-10-30，ETag `"6ae52434-1493abd"`）在 `forms[]` 里带着维基词典自己的罗马字。拿它对照新的韩语表：13,640 个查得到的词里 13,410 个完全相同（不分大小写，维基词典的撇号算连字符），45 个只差音节界线符号的位置，185 个不同。不同的里面 143 个是 `-하다`、`-히` 这类谓词的送气（维基词典写 `saenggakhada`，这里按规范写 `saenggakada`），其余主要是 ㄴ 添加（维基词典的发音谚文有、它的罗马字没写，规范的例词 `알약` 是 `allyak`）和 `져`、`쳐` 的元音（维基词典写 `jeo`，这里按拼写写 `jyeo`）。

## Alternatives considered

**韩语直接用维基词典自己的罗马字**（`forms[]` 里标 `romanization` 的那一条，日语就是这样取的）。这是最省事、最不容易出错的做法：维基词典的模块按同一套规范生成，2026-10-30 的 dump 里 59,008 个韩语词条带着它，不用在仓库里维护转写规则。没有这样做，因为锁住的过滤后输入只给日语留了 `forms`，韩语词条里没有这个字段；锁住的那一周的原始 dump 已被 kaikki.org 覆盖，要拿到它只能用新的一周的韩语 dump 重新过滤，韩语就和另外五种语言不是同一次抽取，锁里要另记一份输入，「从锁里的输入逐字节重建」也要跟着拆成两份。生成的结果和维基词典的罗马字 98% 相同，不同的地方大多是维基词典自己偏离了规范的正文（谓词送气、ㄴ 添加）。下次离线释义和读音一起从新的一周重建时，可以让 `filter` 也给韩语留 `forms`，再比较一次。

**韩语只从拼写推出发音，不用维基词典的发音谚文**：只有一条规则路径，行为更好预测，和维基词典罗马字的一致率也差不多（97.9% 对 97.6%）。没有这样做：一致率接近是因为维基词典的罗马字同样不写 ㄴ 添加，而规范要写；ㄴ 添加、合成词里的连音（`겉옷` 的 `[거돋]`）和例外词（`다신론` 的 `[다신논]`）只有发音谚文里有。两条路径都由同一个转写函数收尾，发音谚文缺失时才退回规则。

**连字符改用维基词典的撇号**（`goyang'i`），和数据来源一致。规范第 3 章第 2 项写的是连字符，罗马字表记在路牌、教材里看到的也是连字符；撇号是马科恩–赖肖尔式的习惯。

**德语也取 `sounds[].other` 里的方括号**，这样 `Wasser` 能给出 `[ˈva.sɐ]`。德语 dump 里 `other` 带方括号的只有 36 处，大多是用法说明里的片段：`der` 有 `[dɛɐ̯]`、`[ˈɪnɐ]`（`in der`）、`[ˈaʊ̯fɐ]`（`auf der`）好几条，`du` 有 `[ˈhast‿u]`，和词条本身的读音分不开。只为 `Wasser`、`Croissant` 两三个词加一条判别规则不值，`Wasser` 仍给 `/ˈvasər/`。

**德语只给方括号，没有的就不标**，所有德语读音都是同一层。17,903 个词里只有 4,905 个有完整的方括号标音，这样会去掉七成的德语读音。

## Consequences

- **收益**：德语常用词给的是实际读音（`[ˈhaː.bən]`、`[ˈmʊtɐ]`、`[ʔeːɐ̯]`）；韩语给学习者认得的罗马字，读屏念「读音」；韩语表小了约三分之一。
- **代价**：德语表里方括号和斜线混着出现，同样的音在两层里写法不同（`[ˈɡeː.ən]` 对 `/ˈʃprɛçən/`）。韩语的罗马字是仓库自己的转写代码生成的，维基词典没写发音谚文又需要 ㄴ 添加的词（`색연필`、`금융`）会少写一个 `n`；谓词送气和维基词典的写法不同。41 个词头不是纯谚文的韩语词不再有读音。专名只在选中的那个词条词性是 `name` 时大写，而词性先比名词，所以和普通名词同形的地名是小写（`서울` 是 `seoul`、`부산` 是 `busan`，`일본`、`중국` 只有专名词条，是 `Ilbon`、`Jungguk`）；改成「同一词头有 `name` 词条就大写」不行，`김`、`이`、`박` 这些普通名词都有姓氏的 `name` 词条，会写成 `Gim`、`I`、`Bak`。
- `-r2` 还没有随任何平台发布过（`#10507` 合并后没有发版），下载过它的只有开发机，资源包按锁的清单判定为需要更新、重新下载即可。
- 测试：`scripts/test-target-pronunciations.py`（德语的取舍、韩语的罗马字和规范例词、确定性），`scripts/test-language-data-notices.py`（NOTICE 在锁里和随包渠道里），共享层 `msime_client_pronunciation_request` 的单测（德语方括号、韩语罗马字原样回答），Android、iOS、鸿蒙对韩语罗马字的形状校验和读屏文案。
- 需要真机核对：Android、iOS、鸿蒙在韩语目标下的读音行和读屏；macOS、Windows、Linux 的韩语和德语读音行。
