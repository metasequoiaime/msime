# Agent Note: Android 工具栏语音共用水杉娘聆听绘制

Status: implemented

## Problem

#10313 希望工具栏语音使用自家人物与耳边红线，并在静音时去掉线条。键盘已有麦克风光圈，外部 MacroDroid 听写入口已有水杉娘与放大耳部；复制另一份绘制会让两边人物和音量表现漂移。长按空格的界面调整属于另一项需求，不能一起改变。

## Decision

工具栏与功能菜单开始的键区语音会话启用人物指示，复用已打包的 `stickers/shuishan/01.webp`，不新增素材、依赖或默认偏好。`VoiceMascotDrawing` 持有原外部入口的绘制路径，两处共同调用；外部入口的视口与耳部比例保留。

人物只占既有指示区域，标题、中间文字、提示、说完了和取消按钮继续使用[移动聆听面板](2026-10-28-mobile-voice-listening-panel.md)的布局与行为。红线按现有平滑音量显示，静音没有红线；进入识别或润色阶段立即隐藏信号，迟到音量不能使它恢复。系统关闭动画时按静音绘制。长按空格经 `hold` 明确关闭工具栏耳部信号，继续使用 develop 已合入的 #10327 缩略图、音量短线与锁定／发送／编辑布局。工具栏与长按使用独立的位图字段，素材稍后加载不改变入口选择，也不覆盖长按角色。

内置贴纸只在工作线程解码，在主线程更新之前同时核对会话代次和原视图实例；取消、换面板与新会话不能消费旧回调。进程内缓存已成功加载的位图，不发起下载，不记录采样或识别内容。素材异常时仍保留文字和结束／取消控件。

## Alternatives considered

- 直接在键盘内复制外部绘制：改动点集中，不碰外部入口。但耳部和红线随后需要改两处，提取原路径能以像素对照守住外部表现。
- 工具栏与长按都换人物：代码条件更少。但 #10313 明确针对工具栏，长按有独立 #10327 需求，保留现有长按界面。
- 主线程同步解码：回调更少。但第一次打开语音会阻塞键盘，采用后台解码与实例／代次校验。

## Verification

设备专项复用既有 instrumentation 的 `voice-mascot` 场景，不增加清单入口；用真实产品类、内置位图和 Canvas 验证静音／满音量、停止后的迟到音量、关闭人物与外部入口逐像素一致。专项不打开麦克风，不替代实际录音体验。

远端 quick 通过（`20261031-000406` 的 quick 阶段）；同轮后续临时打包脚本因缺少自身 `repo_root` 变量中止，没有把整轮算成通过。随后将 Gradle 构建、开发签名、安装与专项串联，`20261031-000933` 退出 0；API 28／35 两份原始结果均为 -1，涵盖上述绘制断言。JNI 按本分支重编并通过 ABI 校验；Rust、共享代码与资源相对固定 `587b0f9304` 没有差异，复用已有产物，不新建 Rust 或完整原生构建树。

API 35 实际运行的产品 View 在 Canvas 上生成静音与满音量合成图，已目视确认人物和放大耳部一致、静音没有红线、有声出现三道弧线。它们是产品 View 的设备渲染，不是工具栏真实入口或麦克风识别质量验收。最终源码含合成图输出与配色的 quick、打包和两版专项在 `20261031-001112` 完整退出 0。尚待 PR CI；未声称物理手机、真实录音或 MacroDroid 互通重新验收通过。

同步 #10327 时保留长按面板的全部布局和触摸状态机，工具栏绘制只在非长按模式生效。合并后同源 Rust／JNI、原生 APK、ABI 与 16 KB 校验通过；API 35 角色专项实际通过，包含迟到工具栏位图不能改变长按角色或绘制模式。该像素断言首次被逐帧回落的音量影响，夹具明确冻结静音后复验通过，没有为通过测试改变产品音量逻辑。系统长按语音专项也通过：触区、取消、锁定、编辑、符号返回、明确发送与迟到结果保护均通过，合成服务完成清理，脚本恢复原输入法与权限。本轮未重跑 API 28。

新工作区首轮 quick 的 HarmonyOS 设置页因包内依赖链接未准备而找不到 `tsc`；补齐相同锁版本的依赖后，该构建通过。首轮已中止，不记作完整通过；补齐依赖后的合并结果完整 quick 退出 0（`target/voice-mascot-merge-quick.log`）：Windows x64 链接与 GNU 设置、Linux 原生 112 项注册／111 项通过／1 项环境跳过、Android 宿主、HarmonyOS 共享设置、macOS 原生与共享 Apple bridge、x64／i686 pipe-only 均通过。新工作区当时没有 x64 compile database，开头的 Windows i686 宿主语法检查跳过；HarmonyOS 原生 HAP 缺 staged 环境而跳过，均不算已验收。

## Consequences

两处使用相同的人物、耳部和红线绘制，原素材无需复制。首次加载增加一个后台任务和一张进程内位图；极矮面板仍按原布局缩小指示区，不改变文字与按钮的取舍规则。其他平台不变。
