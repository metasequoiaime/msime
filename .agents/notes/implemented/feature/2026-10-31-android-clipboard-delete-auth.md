# Agent Note: Android 剪贴板删除数据验证

Status: implemented

## Problem

#10408 要求单条和多选删除剪贴板记录前可由用户开启系统认证门禁；访客剪贴板即使主模式开关关闭也不能绕过门禁。开关本身的切换也必须认证，取消或失败不得改写开关；删除后的撤销按用户确认不增加认证。

## Decision

新增本机设置 `platform.android.clipboard_delete_authentication`，默认关闭，设置入口放在「首页 → 键盘 → 工具栏 → 剪贴板」。切换开关先通过现有 `ClipboardAuthenticationActivity` 和 `SystemAuthenticators.allowed()`，成功后才写入设置；认证取消、失败或认证器不可用时恢复原值并保留原设置。

输入法服务重读这个共享本机设置。主模式按开关决定是否认证，访客模式无条件认证；多选删除先复制当前选择并整批只启动一次认证，成功后原子删除，撤销沿用现有倒计时而不认证。认证桥区分“设备没有可用认证器”和普通取消，让设置页能提示用户先设置指纹、图案或密码。

设备没有任何锁屏凭据时，认证桥返回 `RESULT_UNAVAILABLE`（2002），服务单独处理，不再落到「未通过系统认证」。删除门禁按来源分两种：用户没打开开关、门禁只来自访客模式时，照旧直接删除（`ClipboardDeleteAuthenticationPolicy.allowsWithoutAuthenticator`）；用户自己打开过开关时拒绝删除，提示「这台设备没有可用的系统认证，请先在系统设置开启指纹、图案或密码」。理由是没有锁屏的设备谁都能解锁和操作，访客门禁在这里保护不了任何数据，拦下只会让访客剪贴板的单条、左滑和多选删除全部失效，比改动之前更糟；而打开开关是用户明确要求的保护，宁可拒绝也不悄悄放行。搜索、导出和清空沿用 [Android 剪贴板敏感操作认证](2026-10-25-android-clipboard-operations-auth.md) 的决定，没有凭据时仍拒绝，只是提示改成同一句可操作的说明。

多选删除只在认证通过、真正发起删除之后才退出多选（`removeClipboardItems` 的 `removed` 回调）；认证取消或失败时选择原样保留，用户不用重新勾选。认证 Activity 若被系统或任务移除直接结束、没走到 `finishWith`，`onDestroy` 在 `isFinishing()` 时补发一次取消：输入法服务的 `clipboardAuthenticationBusy` 和设置页开关的等待标记都只在收到结果时复位，收不到就再也发不起认证；配置变更重建不算结束，不补发。

本决定沿用[Android 剪贴板敏感操作认证](2026-10-25-android-clipboard-operations-auth.md)的认证方式和跨进程桥，不改变剪贴板存储格式、访客数据目录或撤销快照。

## Alternatives considered

- 每次删除都认证：语义直接，但会让主模式的默认体验和用户开关失去意义，也不符合 Issue 约定的“可开启门禁”。
- 仅在设置应用内认证开关、键盘删除直接执行：实现较少，但无法保护输入法进程里的单条、滑动和多选删除入口，访客模式也会漏过门禁。
- 没有锁屏凭据时访客模式也一律拒绝删除：门禁语义最整齐，访客模式「始终认证」没有例外。但这台设备上的认证本来就无法满足，任何人都能解锁，拒绝换不来保护，只换来访客剪贴板删不掉的回归，因此只对用户自己打开的开关保持拒绝。
- 没有锁屏凭据时一律放行，包括用户打开过开关的情形：开关打开后再移除锁屏凭据的用户不会被卡住删除。但打开开关是明确的保护请求，静默放行会让设置页显示「已开启」而实际不设防；拒绝并说明原因，用户可以先在系统设置补上凭据。
- 撤销也要求认证：可进一步保护恢复动作，但用户明确要求撤销不认证；撤销只把刚才的本地快照写回，不扩大删除暴露面。

## Consequences

用户可在一个本机开关控制主模式删除门禁；认证成功后才会发生删除，访客模式始终有门禁，单条、左滑和多选入口共用同一条认证路径。代价是认证不可用的设备不能开启门禁；开关打开后用户又移除了锁屏凭据时，主模式删除和关闭开关都会因为没有可用认证而被拒绝，直到用户在系统设置补上凭据。

`platforms/android/check-host.sh` 钉住接线：两个删除入口都经 `authenticateClipboardDelete`，真正删除的两个方法各只有一处调用，2002 单独处理，多选在删除发生后才退出选择，认证 Activity 的 `onDestroy` 补发取消。

验证：本机 `platforms/android/check-host.sh`（`ANDROID_SDK_ROOT` 指向本机 SDK，只用 javac）通过，含 `ClipboardDeleteAuthenticationPolicySmoke`。本机磁盘不足，没有起 Gradle 构建，也没有在 API 28/35 模拟器或真机上验收认证、取消和撤销路径，交由 PR CI 和合并后的设备检查。认证 Activity 盖在键盘上时，撤销倒数是否照走、回来时撤销按钮是否还在，需要真机确认。
