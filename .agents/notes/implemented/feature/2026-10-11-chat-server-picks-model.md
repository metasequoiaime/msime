# Agent Note: 对话不让用户选模型，断网写「连接失败」，打字时让开标签栏，启动屏图标带底板

Status: implemented

## Problem

- 对话页（共享设置界面，鸿蒙手机的「对话」标签和桌面）顶部有一个模型下拉框，桌面还有「刷新模型」。产品决定不让用户选模型：服务端决定用哪个，默认模型失败时由服务端换备用模型重试（msime-cloud 的 `chat.fallback_model`）。
- 对话请求在传输层就失败（断网、连接被重置）时，鸿蒙抛出的是 `BusinessError` 而不是 `Error`，账号桥把它归成 `account_unavailable`，页面写「聊天服务暂不可用，请稍后重试」，让人以为是服务坏了。
- 在「对话」里打字时，键盘把底部标签栏顶到输入框和键盘之间，键盘上方挤着一排标签。
- 鸿蒙的启动屏图标用的是透明底的 `app_icon`：屏幕中间一块带绿色毛边的黑色 logo，没有桌面图标那样的底板。

## Decision

- `ChatPage` 去掉模型下拉框和「刷新模型」，仍然加载模型目录（用来判断是否已登录、拿到默认模型），发送时固定用目录的 `defaultModel`。目录加载失败（不是因为没登录）时，错误后面的「重试」重新加载目录，代替「刷新模型」。 目录、发送和重试由公共 `useChatConversation` 持有，页面只消费会话状态与动作，见[对话会话边界](../simplification/2026-10-16-chat-conversation.md)。
- 鸿蒙账号桥：`chat` 操作抛出的传输层异常返回 `account_network`。对话页不认识这个码，按默认文案写「连接失败，请检查网络后重试」。其他操作的错误码不变。
- `ChatPage` 的触屏输入框报告焦点（`onComposerFocusChange`），外壳在对话页输入框有焦点时不画底部标签栏，失焦后画回来。
- 启动屏图标换成 `start_window_icon.png`：把分层图标的前景叠在 #252525 背景上、裁成圆角方形，256×256，和桌面图标同一个样子。

## Alternatives considered

- **请求里不带模型（像 Android 那样）。** 最干净，服务端完全做主。不用它，是因为鸿蒙账号桥和 client-core 现在都要求请求带模型，桌面也走同一个 `ChatClient` 契约；改契约要同时动几处宿主。发送目录给的默认模型效果相同，msime-cloud 的备用模型对显式默认模型同样生效。
- **启动屏用 `app_icon_layered`。** 分层图标只给桌面用，`startWindowIcon` 要一张普通图片。

## Consequences

- **收益**：用户不再面对模型名；断网时提示说的是实话；打字时键盘上方只有输入栏；启动屏和桌面图标一致。
- **代价**：模型目录仍要加载一次才能发送；服务端换了默认模型、而页面还拿着旧目录时，发送可能被拒（`unsupported_model`），回到标签或重试会重新加载目录。
