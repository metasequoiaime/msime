# Agent Note: Android 社区皮肤 Tab 直接承载完整列表

Status: implemented

## Problem

皮肤页已经提供固定的「社区」Tab，却仍只展示六款缓存预览，再用「浏览更多皮肤」打开完整列表。分类内部多了一层相同内容的导航，搜索和筛选也藏在第二层。

## Decision

`SkinsPage` 的社区分类直接承载 `CommunityFragment` 子 Fragment，复用已有搜索、分类、分页、详情、获取和使用逻辑。嵌入模式隐藏子页的标题和返回按钮，保留皮肤页标题与三项 Tab。社区列表单独占满 Tab 下方空间，不嵌在外层滚动区中；子 Fragment 使用固定容器 id，以便旋转与恢复视图后重新关联。

切换到内置或我的时隐藏社区容器并收起其搜索键盘；返回社区时保留已有搜索和列表，不重新创建子 Fragment。皮肤页继续检查键盘目录缓存是否过期，社区列表继续沿用原有缓存刷新。删除皮肤页中的六款截断和重复社区卡片获取路径。

检索审计：[固定顶部 Tab](../../implemented/feature/2026-10-13-android-skins-top-tabs.md)保留分类导航和本地皮肤模型的决定，社区展示部分由本篇取代；[社区内容并进功能页](../../implemented/feature/2026-10-11-android-community-into-feature-pages.md)的皮肤预览加更多入口部分由本篇取代，词库、短语、回复入口和缓存契约继续成立；请求代次与皮肤库代次笔记的边界继续由现有 `CommunityFragment` 实现守住。其他平台、皮肤明暗和文件安全笔记无关。

## Alternatives considered

- **只删除更多入口，展开全部缓存卡片**：改动小、离线也能直接显示目录。但缓存有条数上限，且会失去搜索、分类、详情和举报入口，无法完整替代原列表。
- **在皮肤页复制完整列表实现**：可以完全定制布局。但请求代次、分页、获取、详情和账号检查会分成两份；复用子 Fragment 只增加展示模式，不复制这些规则。

## Consequences

- 社区 Tab 直接显示搜索、分类和列表，不出现更多入口、第二个标题或返回按钮。
- 分类筛选和列表请求正常；切回本地分类后仍可选择本地皮肤，搜索键盘收起。
- 旋转后保持社区 Tab；子列表重建正常，返回按钮回到皮肤页之前的页面。
- 社区卡片不再混入本地皮肤模型，完整列表和本地分类各自维护数据。

## Verification

- 原生签名 APK 构建、`scripts/verify-local.sh --quick`、`pnpm run verify-notes` 和 `git diff --check` 通过。
- API 35 专用模拟器中直接显示搜索、分类和两列完整列表，没有更多入口、重复标题或返回按钮；自然筛选仅显示自然分类。
- 搜索合成词返回无匹配结果并收起键盘；切到内置隐藏社区列表并收起搜索键盘，切回保留查询框和筛选。
- 横屏与竖屏恢复社区分类、筛选和已提交查询；返回直接离开皮肤页，不经过额外社区页面。没有获取、上传或举报作品。
