# Agent Note: iOS 九键双拼接入共享网格与自定义表

Status: implemented

## Problem

#6572 的共享引擎和 Android 已实现九键双拼；iOS 的 `ChineseInputScheme`、方案映射和九键键面仍只有全拼，不能选择或输入九键双拼。只增加方案名称会把数字送给全拼 T9，所得读音不符合每音节两码的要求。

## Decision

共享 React 设置页的稳定方案列表与 Rust `TouchKeyboardScheme::ALL` 一致，九键双拼追加在末尾并默认关闭；普通话语言卡片单独决定展示顺序，可把它放在全拼九键旁边。选择后写 `scheme = quanpin` 与 `touch_keyboard_layout = nine_key_shuangpin`，旧文档缺失方案列表时沿用原有默认方案。

在 iOS 追加默认不启用的 `nineKeyShuangpin` 入口，对应共享标识与布局 `nine_key_shuangpin`，引擎方案保持 `quanpin`。桥接网格编号 3，重建会话时恢复该网格；设置文档持有选表和自定义表，App Group 仅保存方案选择镜像。

设置页与键面都通过已有 C ABI `msime_client_nine_key_shuangpin_layout` 获取内置表、有效方案、键面和带位置的校验问题。提供米旮旯 3、米旮旯 2、辜氏 2 低重码和自定义表；自定义表支持逐项编辑及 JSON 导入导出，保存前由共享引擎校验。非法表在编辑器中保留并显示问题，禁止保存，不能把引擎用于运行时回退的有效表误作用户编辑中的表。

中文九键双拼沿用九键拼音列、读音、候选筛选及面板；1 到 9 直接组码，0 在字母层可用，分词仍保留独立入口。键面不使用电话键盘字母，不提供会插入电话字母的长按操作；数字层直接上屏数字，离开数字层恢复当前方案映射。普通全拼九键与专用英文输入保持各自行为。

## Alternatives considered

- **把数字换成电话键盘字母后复用全拼九键**：无需新增网格桥接；但每音节两码和声韵母分组不等于全拼 T9，会得到错误读音。
- **Swift 保存内置映射并自行校验**：键面与编辑器更容易实现；但会形成与共享引擎独立的规则，换表后可能显示与输入不一致，因此继续调用唯一的共享接口。
- **自定义表只支持导入文件**：代码和设置项较少；但 issue 明确要求配置声母、韵母映射，仍需可编辑的表和保存反馈。

## Consequences

- iOS 提供九键双拼方案、内置表和自定义映射的编辑/导入/导出，沿用共享引擎解码与验证。新增入口默认关闭，旧方案顺序保持不变，账号只同步布局，不同步本机方案表。
- 键盘需要分别处理全拼 1 键标点与双拼 1 键组码；双拼字母层保留底行 0，读屏给出完整声韵母，数字页仍直接输入数字。长按电话字母在双拼中禁用。
- 导入最多读取 16 KB 加一个探测字节，超限拒绝；结构经共享接口检查，单位错误保留在草稿中可修正。缺失单位仍有输入行，多余单位可删除；错误草稿不能保存。
- 新增 FFI 声明、工程源清单、方案标识、统计归属和云端布局映射一起维护。HarmonyOS 同步方案入口、NAPI 键面读取、1/0 组码与数字层路由，现有逻辑测试覆盖这些分支；本机未完成 HAP 打包或设备验收。缺乏完整来源的辜氏 2 普通版仍不内置，#6572 继续开放。
