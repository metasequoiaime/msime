# Agent Note: 候选窗口设置恢复顶部功能标签

Status: implemented

## Problem

[主题页与候选窗口页精简](../simplification/2026-10-16-macos-appearance-settings-prune.md)把候选窗口设置放进一列和一个「更多选项」。用户明确要求重新按功能拆成多个顶部标签，避免在混合的折叠区里寻找字体、窗口几何和预编辑设置。

## Decision

共享桌面候选窗口页使用现有 `candidateTabs` 模型的四个标签：布局、字体与大小、窗口样式、预编辑。标签位于页面顶部、共用预览之前；预览一直挂载，各分区也保持挂载，只隐藏非当前分区。选择属于窗口状态，不写偏好；切换标签回到内容顶部，方向键、Home 和 End 沿用公共标签组件。

布局包含排列、每页数量、展开、页码、logo 和跟随光标；字体与大小包含字体预设、自定义主字体、英文字体、候选字号和整体大小；窗口样式包含不透明度、圆角和内边距；预编辑包含预编辑字号与原有预编辑选项。仍按宿主能力过滤控件，颜色与皮肤继续属于主题页。手机包括 HarmonyOS 手机保留原有直列布局。

## 历史审计

- [候选窗口标签模型](../simplification/2026-10-16-candidate-tabs.md)部分重叠：复用其标识、顺序与标题，更新共享页重新使用该模型的事实。
- [正常候选设置入口](../bug-fix/2026-10-13-macos-primary-settings-tabs.md)部分重叠：沿用正常入口与预览生命周期边界；本次顶部标签放在预览之前。
- [AppKit 原生候选标签](../feature/2026-10-13-macos-candidate-settings-tabs.md)不属于本次改动，原生备用窗口继续冻结。
- 本篇仅取代上述精简笔记的共享桌面候选页排版决定，不改变宿主能力、主题解析、手机和 Windows 原生设置的决定。

## Alternatives considered

- **保留一列与「更多选项」**：常用四行直接可见，控件数量少时浏览很快。但把字体、几何与预编辑混在一起，不符合用户这次明确要求的功能分类。
- **只挂载当前标签**：减少隐藏 DOM，但切换会重建字体目录状态和局部编辑状态。复用公共标签组件的隐藏面板能够保留草稿和预览连续性。

## Consequences

桌面只显示当前分区；预览和各分区一直挂载，切换和离页返回保留草稿、自定义字体选择与字体目录状态。手机仍保留直列和「更多选项」，桌面控件测试需要先进入所属标签。

## Verification

`candidate-settings-layout.test.tsx` 检查四分区可见性、滚动复位、键盘导航、跨标签保存、预览实例和自定义字体状态；字体目录、窗口样式、手机与设置页既有回归同步覆盖分区入口。前端类型检查、构建、笔记和本地 quick 门禁，以及本机完整 macOS 安装包里的标签验收负责其余验证。
