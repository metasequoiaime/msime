# Agent Note: 可写的个人生词本

Status: implemented

## Problem

背单词只认整本的词书：内置的八本考试词表、插件词书，以及用户导入的 CSV/TXT。打字时候选旁边显示的英文释义和背单词之间没有任何连接，看到一个想记的词，只能自己抄下来、拼成文件再导入一本新书。后续的候选窗动作（桌面各候选窗、移动三端键盘）需要一个能逐词写入的去处，而现有的 `WordbookLibrary` 只会整本导入、整本删除。

## Decision

生词本是 `WordbookLibrary` 里 id 固定为 `personal` 的一本书（`library::PERSONAL_ID`），名字是「生词本」，存在同一个 `vocabulary-wordbooks/` 目录、同一把 `wordbooks.lock` 下。它和其他书走同一条读路径：`list` 把它列出来（`WordbookSummary.personal` 为 true），`load` 读它，背单词的会话、排程和复习进度不需要知道它特殊，`ReviewAction::Remove` 删掉它就是清空。

写入只有四个入口，都在锁内完成「读整本、改、写回」：

- `add_personal(entry)`：加一个词。词头已经在了就把中文释义并进原有释义（以「；」分隔、已有的不重复、超过 256 字就不并），原来没有读音时补上，不另起一行。卡片按词头记进度，同一个词两行就是一张卡两份释义，`Wordbook::is_valid` 也拒绝重复词头。
- `remove_personal_entry(word)`：移走一个词，这个词的复习进度留着，以后加回来接着原来的排程。移走最后一个词时生词本连文件带索引行一起删掉，因为词书至少要有一个词。
- `export_personal()`：导出成 `词,读音,释义` 三列的 CSV，含逗号、引号、首尾空白或以 `#` 开头的字段加引号。这正是导入解析器读的格式，导出的文件既能导回生词本，也能当普通词书导入。
- `import_personal(text)`：用普通词书的解析器读文本，逐行并进生词本，整份只写一次，返回新增、合并、未变、超限和格式错误各几行，不回显内容。

候选释义到卡片的映射是 `personal_entry_from_gloss(候选, 释义, 读音)`：词头取释义第一行的第一个义项（按 `;`、`；` 切），和单义项时 Ctrl+Enter 上屏的那个一致；释义是中文候选本身；读音不合格时丢掉读音，不连累词。其余义项是同一个中文词的别的译法，不是这个外文词的意思，不收。规则放在共享层，六个宿主只把高亮候选的原文、释义和读音交进来。

上限：生词本最多 5000 词（`MAX_PERSONAL_ENTRIES`）。每加一个词都在打字时重写整本，5000 条按释义上限算不到 2 MB。生词本不占导入书的 32 本名额，索引因此最多 33 行；`library.import` 拒绝用 `personal` 这个 id，生词本不会被整本替换成普通书。

隐私：生词本只在本机，不进账号同步、云词库，也不属于 #10043 的输入习惯同步。`PRIVACY.md` 的「留在本地的东西」加了一条。

### 既有笔记审计

- [词书目录句柄](../../implemented/bug-fix/2026-10-09-vocabulary-library-directory-handle.md)、[词书锁目录](../../implemented/bug-fix/2026-10-09-vocabulary-wordbook-lock-directory.md)：部分重叠。生词本的写入沿用同一把锁和锁定目录的句柄，不新增文件操作原语。
- [导入后只切换选择](../../implemented/bug-fix/2026-10-30-vocabulary-import-settings.md)：无关，生词本写入不改进度里的选择和限额。
- [输入习惯端到端同步](../../proposed/feature/2026-10-27-learning-sync-e2e.md)：同步范围不变，生词本不在其中；以后要把它纳入，应当在那篇里另做决定。

## Alternatives considered

- **生词本单独一个文件、单独一把锁，不进词书目录**：最强的理由是逐词写入的热路径和几 MB 的导入书互不干扰，锁也不会被导入长时间占着。不用：背单词的列表、读书、删书、复习进度都已经围着 `WordbookLibrary` 写好，单独存放就要在会话层再接一种书，六个宿主的书目也要再认一种来源。导入一本书持锁的时间只是写一个文件，候选窗的一次添加等它不会被察觉。
- **每个中文候选的全部义项都做成卡片，或者把整行释义当词头**：多收一些信息。不用：整行「my; mine」当词头在卡片上很别扭，也会和同一个外文词的其他来源对不上；几个义项各做一张卡，等于用户点一次加进来好几个词。
- **生词本也受 `MAX_ENTRIES`（两万）约束**：和导入书一致。不用：导入书一次写入，生词本每加一个词都要重写整本，而且发生在打字的时候；想背更多的人可以把导出的文件当普通词书导入。
- **移走一个词时同时删它的复习进度**：存储更干净。不用：误删后加回来要从头背，而一个词几行进度数据可以忽略；整本删掉时进度照旧随 `ReviewAction::Remove` 一起清。

## Consequences

- 背单词的书目里会多出「生词本」这一行（有词时），排在导入的书前面。宿主据 `personal` 字段显示「移出生词本」和导出；没认这个字段的旧宿主照常把它当一本导入书列出、复习和删除。
- 生词本不受内置书和插件书的约束，也不会被 `ReviewAction::Import` 产生或替换。
- 这一步只有共享层；桌面候选窗的入口和背单词页的导出、移出见[桌面候选窗的「加入生词本」](2026-11-01-desktop-candidate-personal-wordbook.md)，移动三端在后续 PR 里接入。
