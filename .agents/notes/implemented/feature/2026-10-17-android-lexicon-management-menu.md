# Agent Note: Android 词库管理操作收进标题菜单

Status: implemented

## Problem

Android 词库页把「新建词库」「导入词库」「导出词库」「刷新词库」作为独立的四行操作卡片放在已安装词库列表下面。四个动作属于低频管理操作，却占据与词库列表同等的纵向空间，窄屏上需要滚动才能看到更多词库。

## Decision

已安装词库组在标题右侧提供「管理」按钮，点击后打开 `PopupMenu`，菜单按「新建词库」「导入词库」「刷新词库」「导出词库」列出原有四个动作。动作仍调用原来的对话框、文件选择器、刷新和导出流程；只移除占高度的四行操作卡片。首次读取失败且没有模型时继续保留单独的「刷新词库」恢复入口，避免页面在管理菜单尚未渲染时无法重试。

## Alternatives considered

- 保留四行操作卡片并缩短每行：可以继续让所有动作一眼可见，但低频动作仍挤占已安装列表的首屏空间，无法解决用户反馈的布局问题。
- 将四个动作放进已安装卡片底部：比独立卡片紧凑，但仍把管理动作与词库列表混在一起，列表变长后仍要滚动经过它们；标题右侧菜单能在不改变列表行的情况下提供入口。
- 只保留标题右侧的图标按钮：占用更少空间，但没有文字提示，容易隐藏动作含义；使用带文字的「管理」按钮保持可发现性和无障碍描述。

## Verification

通过 Android 主机检查（248 项 JVM 冒烟、151 项设备套件源码编译）、设置搜索索引、`git diff --check` 和决策笔记校验。构建并签名 `0.5.0` arm64 APK 后安装到 Android 设备 `8AFY0K0SC`，从原生 `HomeActivity` 打开 `LEXICON` 页面：截图和无障碍树确认已安装标题旁显示「管理」、四行操作卡片消失，菜单提供「新建词库」「导入词库」「刷新词库」「导出词库」四项。

## Consequences

正常词库页纵向空间留给已安装列表和社区词库，管理动作多一次点击且一次只显示菜单项。菜单复用既有动作实现，不新增存储或文件格式契约。读取词库失败时仍显示直接刷新行，保证恢复路径独立于正常页面菜单。
