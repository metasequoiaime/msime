# Agent Note: Android 常用语分类与纵向展开

Status: implemented

## Problem

#8642 要求最多六个自定义常用语分类，分类和常用语在设置中管理；键盘按纵向列表展开，不使用横向分类条，并允许指定首次展开的分类或全部收起。

## Decision

分类归入 client-services 的 `CommonPhrases` 文档，复用原文件锁和原子发布。分类名称去除首尾空白后限制为 1–20 个 UTF-16 单元，不含控制字符，不重复，也不占用「全部」「未分类」「不展开」等界面名称；分类最多六个。常用语通过稳定的分类 UUID 归属一个分类，未分类仍可从「全部」找到。删除分类只清空归属，不删除正文或备注；被删分类若是默认展开项，则回到「全部」。

Android 设置页提供分类增删改、每条常用语的归属选择和默认展开选择。键盘在条数及设置入口下显示「全部」和自定义分类的纵向折叠标题，同时只展开一组；重开面板采用保存的默认值。点正文或备注只插入正文，增删改仍在设置页完成。

分类只在本机使用，不改变云端正文协议。本地备份仍保留正文数组及备注映射，新增按分类名称及正文关联的可选分类数据。恢复时由 Rust 原子合并分类：同名复用，已有正文的本机分类不覆盖，只有本次新恢复的正文接收备份归属；分类上限等失败不写分类，沿现有恢复事务撤销新加正文。没有本机分类时恢复备份默认展开项，否则保留本机选择。

备份中的 `phrases.json` 上限为 3 MiB：200 条各 1000 UTF-16 单元的正文和备注，加上备注键及分类成员中的正文，按最多四份 UTF-8 内容计入，避免导出的合法满容量备份在恢复时超过读取上限。

备份中的分类携带原 UUID，展开项也引用该 UUID；恢复时将其映射到按名称复用或新建的本机 UUID。名称为 `all` 的用户分类也能准确恢复，不把用户名称当作「全部」的机器标记。

## Alternatives considered

- Android 单独存一份分类映射：不扩展共享文件，但删常用语、更新社区短语包和不同进程写入时需要协调第二份文件；放入原文档可由同一次锁维护引用。
- 横向分类条：实现简单且节省纵向空间，但长分类名会被挤压，且违背 issue 明确要求的纵向展开方式。
- 同时扩展云端分类协议：可以跨设备同步，但现有云端只支持正文，会扩大本次 Android 需求范围；本地备份承接换机保留，不把分类编码进正文。

## Verification

- 27 项常用语 Rust 测试和 client-services all-targets Clippy 通过；覆盖旧文件默认值、六分类上限、名称和重复拒绝、归属持久化、删除分类保留内容、默认展开修复、非法文件保护及备份合并原子性。
- Android API 28/35 四个客户端核心库的完整设备测试通过；API 28 原生分类和原有备注专项通过。补充的 200 条满长度正文及备注、分类的真实 ZIP 在 API 28 上通过导出与恢复前完整校验；完整 quick 通过。最终 API 35 UI 及两版通用 smoke 仍在验收中，交付前以实际结果更新。
- 旧 APK 的负对照在分类创建处失败，确认专项能识别缺失的功能。

## Consequences

带分类字段的文件不能由拒绝未知字段的旧客户端编辑；旧版本会保留文件并报格式不支持。分类只在 Android 提供界面，其他新版本宿主读取后写回仍保留字段。社区短语包重新安装会替换其条目及本机备注/归属，沿用原有替换语义。
