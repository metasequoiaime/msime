# Agent Note: iOS 无组字时横滑键盘移动光标

Status: implemented

## Problem

#9081 希望在没有正在输入的拼音时，从键盘上的普通按键起滑移动文档光标。现有 `spaceCursorPan` 和关闭语音后的空格长按只覆盖空格，不能从其他字母或数字键开始。直接截获所有触摸会影响轻点、多指快打、角标符号和假名 flick。

## Decision

- 按维护者确认，增加独立的「横滑键盘移动光标」开关，默认关闭。与滑行输入一致存储在本机 App Group，不同步；App 的键盘手势页提供控件，恢复全部设置时删除该键。
- 单个单指 pan 挂在键区根视图上，只接受键区内非功能按键的起始触摸。空格、退格、回车、模式切换、候选栏、面板和假名 flick 保留各自入口；九键字母层的 `1 符号` 打开标点，也不作为起点，切到数字层后才允许。字母、数字和多字母键可以起滑。
- 无组字、未进行空格移动且滑行输入未接管当前字母键盘时，横向速度大于纵向速度才开始。识别前不延迟按下或抬起；识别后由 UIKit 取消原键触摸，避免松手输入起始字母。
- 文档位移复用 `SpaceCursorMovement` 的步长、文档身份校验和结束取消规则，不添加第二套位移算法。手势进行中新的触摸不命中按键，结束、取消、失焦和停用时恢复；文档身份缺失、切换或位移校验导致步进器自行取消时，也结束识别序列并恢复命中。滑行输入与横滑各自记录活动状态，再合并维护键区触摸抑制，避免一个手势的取消回调清掉另一个手势的抑制。
- 在逐触摸起点过滤之前，使用 `UIEvent.allTouches` 计入所有未结束、未取消的触摸；包含被起点规则排除的空格和退格。出现多指时清理光标活动状态并重置 pan，同时锁住本次序列；只有下一次单独的 `.began` 才解除锁定，第二指先抬起不能让旧首指重新识别。这里不依赖 UIKit 对 `.possible` 状态禁用再启用的未明确行为。
- 文档身份的既有读取缺陷由独立 PR #9375（#8906）修复，已以 `5ab79e0373` 合入 `develop`；本分支同步该提交后包含修复，不再临时替换源码。文档相关回归直接断言公开代理身份可用，读取回退时失败而非跳过。

## 历史检索

[iOS 滑行输入宿主](../../implemented/feature/2026-10-07-ios-glide-typing-host.md) 持有触摸取消与多指保护的既有取舍；[空格光标与快捷符号](../../implemented/feature/2026-10-18-ios-space-cursor-and-quick-symbols.md) 持有文档步进和输入框切换取消。本篇增加空闲键盘的起滑入口，不替代两者。检索 proposed、implemented、rejected 没有其他 iOS 整块键盘横滑实现；Android 空格左右滑动属于其他宿主。

## Alternatives considered

- 给每个普通按键挂独立 pan：起点自然限于按键，但需要在各布局构造时逐个注册、共同协调多指与文档步进。选择根视图上的一个手势，并通过命中的按键及祖先判断范围。
- 复用滑行输入识别器并按开关分支：可以共享跨键触摸采样，但滑行输入会收集完整轨迹并在抬手时调用引擎，光标移动需要实时消费位移且不解码拼音。保留独立手势，复用既有位移逻辑；同时开启时滑行输入优先。
- 默认开启：用户无需设置就能发现功能，但会改变现有连续点按和滑动手感。维护者明确选择默认关闭。

## Consequences

收益是提供从字符键开始的光标定位，同时默认关闭以保留现有用户的连续点按习惯；位移精度与空格手势共用一套实现。代价是增加一个本机偏好、一个根手势和手势间的活动状态裁决。

初始横向阈值与多指快打的真实手感仍需真机验收。最终集成版本已通过 26 项控制器和文档身份回归、1 项原生设置 UI 回归及 1 项独立编辑器内真实系统扩展 UI 回归，覆盖普通连续点按、触摸取消、抬手不输入起始字母和开关控制实际文档位移。控制器里的多指锁定断言不能替代真实多指触摸；模拟器的系统扩展验收也不等于真机手感验收。
