# Agent Note: Android 语音工具栏和长按空格入口可并用

Status: implemented

## Problem

#10309 要求将语音页的「长按空格」「工具栏按钮」合成「工具栏/长按空格」，工具栏是否放按钮仍可在键盘工具栏设置中单独开关，「更多工具」中的语音输入始终保留。现有语音页和工具栏页都主动关闭另一入口，无法稳定并用。

## Decision

语音页保留「工具栏/长按空格」与「无」两项。状态由已有的本地 `platform.android.space_voice` 和共享 `touch_voice_shortcut` 派生：任一开启显示组合项，两者关闭显示「无」。只读页面不迁移、不改写旧设置。

明确选择组合项时开启长按空格，保留工具栏开关；说明文字指向「键盘 → 工具栏 → 语音」。重复选择组合项也执行这一显式操作，使旧的仅工具栏状态可直接开启长按空格。选择「无」关闭两种快捷入口，但识别配置和「更多工具」磁贴保留。工具栏开关只改 `touch_voice_shortcut`，不关闭长按空格。工具栏隐藏时继续显示提示，按钮开关不改变整体隐藏设置。

此决定翻转 #10142 修复时的互斥决定，按新 issue 明确要求支持并用，不自动开启旧用户未开启的入口。

## Alternatives considered

- 保留旧的两个独立启动选项，再加组合项。能够直接表达四种底层状态，但不满足 issue 合并选项的要求，且工具栏控制仍重复。
- 选择组合项时同时开启工具栏。操作最直接，但工具栏显隐由用户在键盘工具栏中独立决定，切换语音方式不应顺带翻转该选择。

## Verification

- 两入口可同时开启；工具栏开关切换不改长按空格。
- 四种旧开关状态只读后保持原样；组合项和「无」的显式选择落盘正确。
- 任意工具栏开关与隐藏状态下，「更多工具」都保留语音输入。
- 不改偏好默认值、共享结构或其他平台。
- 原生设置专项覆盖四种旧值只读、组合项与「无」的真实存储回调、工具栏双向切换；工具栏专项覆盖显隐与开关四种组合时磁贴保留。API 35 上经安装的原生产品运行这两个专项均通过；四种旧值只读断言、组合项与「无」保存回调及工具栏双向开关都读回真实共享／本地存储。原生 release APK 的 Gradle 构建、JNI 导出与 ELF／16KB 对齐、测试 APK 编译通过。远端 `bash scripts/verify-local.sh --quick` 通过，覆盖 Android Java、工作区／Android／wasm 编译、macOS 宿主和 Apple 桥；环境缺失的阶段按脚本跳过，`pnpm run verify-notes` 与 `git diff --check` 通过。

## Build provenance

本项只改 Java 与设备测试。Rust、共享代码及资源锁与 `587b0f9304` 的差异为空，复用该固定提交已验证的 `libmsime_host_api.so` 和固定资源暂存；JNI 由本分支原生源码重新编译，Gradle 重编本分支 Java，再按现有脚本的开发证书签名并验证。没有复制其他 worktree 的未提交源码，也没有从零重编未改的 Rust 发布库。

## Consequences

旧的仅工具栏状态也显示组合项，必须用说明写明工具栏与长按开关的关系；不能只改文案而保留互斥写入。新增设置专项使用隔离模拟器与合成数据，不启动联网识别。
