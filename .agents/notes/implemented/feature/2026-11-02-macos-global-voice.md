# Agent Note: macOS 跨输入法语音快捷键

Status: implemented

## Problem

现有语音快捷键要求水杉已有获得焦点的 IMK 控制器。用户在其他输入法里按相同的键不能开始说话；另设一组全局键又增加记忆负担。

## Decision

其中「等 IMK 激活后才开始录音」的时序由[先录音、后交付](../architecture/2026-11-03-global-voice-capture-before-imk-delivery.md)部分取代；[录音与目的地许可分开](../architecture/2026-11-03-global-voice-optional-destination.md)进一步允许没有初始输入框时录音。本篇保留原决定的理由、手势、权限及目标安全边界；新的录音与交付实现以该篇为准。

macOS 使用 `voice_input.hotkey_global` 增加「快捷键生效范围」：默认「仅水杉输入法」，可选「任意输入法」。继续使用现有按住说话、空格锁定、`Control+F9` 与自定义切换组合键，不新增手势或修改其他平台默认值。

全局事件入口属于原生输入法宿主的单一协调器，不在设置 WebView 中监听。后台启动只通过用户同意的 `SMAppService`；引导程序经 Launch Services 打开同一输入法应用，不另建录音服务和未鉴权的跨进程录音命令。

跨输入法会话保存原输入源及前台目标，选择已启用的水杉输入源，等 IMK 激活且目标仍有效后复用原录音路径。按住键在等待期间松开就取消，不产生迟到的录音。结果提交或完整取消之后才恢复原输入源；用户自行切换后不抢回。普通修饰键组合仍交给原应用；全局捕获失败、权限和系统冲突有可见提示。

提交绑定原 IMK 客户端、前台进程与辅助功能焦点元素，不把旧结果插入后来获得焦点的应用。目标失效时保留已经识别的文本供显式复制。原有录音波形、提供商、提示音与取消按钮继续复用。

## 旧笔记检索

检索 `全局语音`、`全局.*快捷键`、`跨输入法` 与 `语音.*恢复`：[自定义切换语音快捷键](2026-10-24-custom-voice-toggle-hotkey.md)部分重叠，保留其组合键契约；输入源唤醒恢复与后台更新的笔记只涉及系统恢复、安装等待，与本功能无关。此功能不吸收或翻转它们。旧 PR `#10637` 是启动偏好与工具栏所有权修复，不把其整组改动带入此分支。

## Alternatives considered

- 独立全局听写服务无需切换输入源，也能兼容多种编辑器；但会重复录音生命周期和提供商适配，并扩大剪贴板、辅助功能提交的职责，本次复用 IMK 路径。
- 常驻辅助进程通过套接字控制输入法可隔离监听器；但会新增认证、重连及两个进程的会话状态。当前宿主本来就常驻，优先让监听与会话协调在同一进程完成。
- 全局另设快捷键最容易避免冲突，但用户已选择相同按键和相同手势；冲突应提示并可调整现有绑定。
- 切源后固定休眠最容易规避通常的回调延迟，但机器负载与编辑器初始化没有统一耗时；按真实输入源与客户就绪等待，并用上限取消，避免延时到期后仍启动在错误目标上。

## 验证边界

- 旧偏好缺少范围字段时仍只在水杉中生效；范围字段只由 macOS 宿主读取。React 设置页按[原生迁移约束](../../proposed/architecture/2026-11-03-all-native-ui.md)不新增范围入口，编辑已有快捷键时保留已经保存的范围值。
- 从其他已启用输入法开始，最终提交后恢复精确的原输入源；手动切换不被覆盖。
- 等待激活、快速松开、连续触发、取消、权限拒绝与目标丢失都不遗留录音。
- 全局和 IMK 事件不重复启动；普通修饰键组合不被吞掉。
- 运行聚焦的偏好、状态机、原生适配和设置测试，保留原生编辑器验收证据及限制。不运行用户已跳过的全平台本地门禁。

## Consequences

全局键盘权限、后台项批准及输入源可用性由 macOS 决定，必须通过实际系统状态呈现，不能把保存偏好等同于功能可用。输入法启动和 IMK 激活存在竞态；需要有界等待及会话代次。当前磁盘低于 50 GiB，复用既有缓存，不创建新构建树。

原生 arm64 Release 目标在复用的 `target/macos-release` 缓存中编译，Rust Host API 为本分支增量构建；没有创建新构建树。聚焦的七个原生套件、七项 Rust 偏好回归、十一项设置测试通过，设置宿主 `cargo check -p msime-desktop --lib --locked` 通过。原生边界测试明确隔离系统注册、全局监听和麦克风，使用合成事件、客户端和转写，不声称完成真实录音、后台项批准或登录后的验收。

界面改前、改后的组件预览使用当前 React 控件、macOS 平台 token、既有发布 CSS 和 WKWebView 截图，留在本机 `local-evidence/macos-global-voice`；这是组件效果图，不是真实原生设置窗口的截图。真实登录启动、权限撤销与重新授权、全局录音的输入源恢复和 Chrome/TextEdit 等编辑器仍待用户启用范围及授权后验收。最初实现阶段未安装，后续按用户要求完整安装并启动；没有发布或开 PR。用户要求跳过全平台本地检查，验证只运行这些相关路径。

只读 TIS 探测在本机找到一个已启用且可选择的水杉输入源，未切换输入源或访问麦克风。已生成 bundle 的后台项标识、可执行文件与参数检查通过；这不等同于系统批准或登录验收。

完整 universal 打包补充验证：Intel ABI 的 Objective-C `BOOL` 是有符号字节，直接放进 C++ `bool` 聚合初始化会触发窄化错误；按住键选项先用 `!= NO` 转为真正的 C++ 布尔值，保留原有语义。Apple silicon 和 Intel 的原生目标均编译通过，聚焦原生套件复跑。打包明确使用仓库钉住的 Rustup `1.97.1`，不能让 PATH 中 Homebrew 的同名编译器拿自己的 sysroot 去找 Rustup 安装的 Intel 标准库。

安装补充验收：完整 universal 构建、签名与包结构检查通过，设置应用、输入法及 MCP 均为 `0.57.0`。真实设置窗口可见范围控件，录键按钮取得实际键盘焦点，Esc 取消成功，范围保持「仅水杉输入法」。输入法后台引导入口成功启动宿主，已登记并可选择；没有开始音频录制，也没有以直接引导成功代替登录验收。主工作区的 `local-evidence/macos-global-voice/install-20261103T040000Z/` 保存范围行截图、日志、版本与二进制哈希，以及原有两个 bundle 的签名备份。资源锁未改，续跑复用已通过的资源包检查，并对缓存的核心资源再次逐字节验证；后续编译、签名与完整包校验均保留原脚本步骤。

安装后的权限恢复采用真实宿主状态验证：设置中保存 `hotkey_global=true` 不代表原生进程已经取得辅助功能权限；系统设置显示开关开启时，宿主仍可能返回未获准。日志只记录范围、权限布尔值、后台项状态与错误码、监听创建结果，不包含按键、输入、路径或音频。首次后台项状态为 `NotFound` 时也调用注册并检查实际返回值，不能因为只处理 `NotRegistered` 而直接跳过；`RequiresApproval` 保留用户决定，不反复注册。使用非提示的辅助功能检查轮询授权变化；已授权但监听创建失败时每五秒重试，已存在的监听不重建，也不重复弹授权框。原生回归覆盖首次缺失服务、等待批准、关闭注销、同修订授权变化、监听失败的退避与权限撤销；七个聚焦套件通过。真实全局录音仍需要操作系统对当前已安装宿主给出有效授权，不能用模拟用例代替。

重新添加当前安装路径的辅助功能条目后，真实宿主报告权限从未获准变为已获准，事件 tap 自动创建，后台项注册状态为 `Enabled`；这证明开关显示与当前二进制的有效授权必须分开验证。用户随后触发了输入位置不可用提示。焦点查询保留系统级入口，并在它失败或没有元素时读取前台应用的 `AXFocusedUIElement`；元素 PID 与查询前后的前台 PID 都必须一致，安全文本框继续拒绝，不退化为仅绑定窗口或进程。聚焦回归用合成 AX 返回值覆盖系统查询失败、应用查询成功、异进程、安全框及双重查询失败。真实 Codex 编辑器上的生产 helper 能取得当前焦点元素并核对前台进程；不读取文本内容，此项检查也不代表完成录音或上屏验收。

跨输入法激活不把 `TISSelectInputSource` 接受请求当作切换已经完成。合成宿主回归复现了旧行为：原输入源仍被系统报告时，协调器立即取消，而系统随后仍能切到水杉。协调器在三秒上限内等待源实际到达，第一次到达之前看到原源不算手动切换；第三个源或到达后离开才按手动处理。请求目标在调用系统前保存，取消未完成的选择时重发原源，避免松手后迟到的水杉切换。真正换应用或焦点元素仍立即停止；同一应用中 AX 查询无响应不再截断采集；提交时仍独立核对原客户、会话和元素，无法验证就保留结果供复制，不放宽插入授权。

全局录音的波形与开始提示音在第一份有效 PCM 到达后出现，不能在引擎尚未送来音频时宣称正在录音。引擎启动后两秒没有任何帧则取消并显示输入设备错误；超时绑定服务实例、语音代次和捕获轮次，旧回调不会取消后续录音，识别阶段也不要求继续收音。局部按键路径保留原有启动时机，socket 提供商仍由其就绪阶段驱动显示。日志只记录是否送帧和阶段，不记录音频、输入或设备身份。十二个相关原生套件通过，覆盖延迟切源、手动改源、AX 恢复、无帧与迟到帧、跨轮次超时，以及原有 PCM、HTTP、流式和上屏行为。以上不代替用户环境中的实际麦克风与上屏验收。

输入源到达后，协调器仍不把调用 `startGlobalVoiceHolding` 等同于已经启动。IMK 的光标查询和会话准备会重入客户激活，原来的 `void` 入口可以静默返回；合成回归复现了第一次未就绪后整轮被提前完成的问题。入口显式返回重试、已接受或失败，只有已接受才进入活动阶段；重试继续保留切源等待与原目标，明确失败恢复原源且不重复弹授权或提供商请求。每次尝试绑定独立内存令牌，准备与核心启动返回后再次核对令牌、客户和会话，重入取消不能补开麦克风。回归覆盖一次未就绪后成功、明确失败不重试、等待重试期间松手取消。用户后续尝试中还发现设置实际选择了「右 Control+右 Option」；通过真实设置页恢复用户要求的「右 Option」并保留任意输入法范围。无法据此判断此前选择由何处修改，不把这个发现当作自动覆盖设置的证据。

真实安装与激活期间观察到用户选择再次从「右 Option」变回旧的「右 Control+右 Option」，修订号随之增加；合成回归也复现了首次输入偏好只读取输入字段、语音默认值仍旧，随后模式/外观保存将旧语音字段写回的问题。首次使用同步载入共享语音值；全局协调器在范围启用或关闭过渡中也同步已读文档。普通外观保存和方案同步不再拥有 `voice_input`，明确的原生语音设置通知才发布语音字段。排队的原生语音编辑在请求时冻结成不可变快照，不能被晚到的偏好载入覆盖。回归实际读写临时文档，验证首次读取、无关外观写入、明确原生编辑以及排队编辑遇到晚到缓存变化。十五个相关原生套件通过，包含工具栏可见性、原生按住键默认与偏好生命周期；未运行全平台门禁。此补丁只修复当前功能暴露的语音字段启动与写入归属，不吸收旧 `#10637` 的工具栏所有权整组改动。


实际编辑器补充排查：合成宿主和真实 macOS 编辑器检查不能互相替代。用户环境中的无波形尝试已经收到按住键并请求切源，但部分尝试没有有效 IMK 客户端；另一次在等待激活时 AX 暂时报出不同元素，被原实现直接取消。等待阶段现在保留原元素，在既有三秒上限内等它恢复，恢复前不启动、不授予插入权限，也不把后来元素当成原目标；超时、松手、换应用仍取消。活动阶段换元素仍立即停止。新增回归在改前失败，改后覆盖原元素恢复、持续改变后的超时和开始录音后换字段的严格停止。

同机安装排查还发现同一输入法标识符同时指向旧安装镜像、设置包内副本和用户输入法目录。仅看进程路径、签名、版本和菜单选中不足以证明 IMK 连接可用。按既有安装脚本移除竞争的 Launch Services 登记（不删除 bundle），强制刷新已安装路径并重新登记后，实际空白测试编辑器的两次录音都收到有效 PCM 并到达波形就绪，随后用 Esc 取消，没有检查转写或音频内容。安装后的检查须等原生副本与嵌入副本的修订、二进制哈希一致，再完成登记和实际 IMK 验证；本次使用的本地完整安装辅助脚本补上此步骤，不能只登记外层设置应用。

诊断启动必须经 Launch Services。把原生可执行文件作为工具子进程直接运行，会让 TCC 把系统语音权限请求归到工具宿主；一次测试因此被系统以宿主缺少用途声明终止。输入法自己的两项用途声明本来齐全，这不是删除或补写用途声明的理由。该次探测无效，不能用来归因用户原来的失败；后续改用正常启动的输入法和独立空白编辑器，由已有授权的工具进程只驱动合成按键。诊断期间的限 PID 禁止启动开关只用于本地探测，已从最终源码移除。没有采用重放修饰键的方案：热身后的对照均可启动，证据不足以证明额外按键有必要，不向用户编辑器注入未经证明的唤醒事件。

本轮最终复用既有 universal 原生产物目录，十五个相关 macOS 套件和 `verify-notes` 均通过。没有运行全平台本地门禁；后续校验发现测试污染真实语音偏好，详见下段更正。恢复登记后空白编辑器的实际捕获就绪已经验证；用户在 Codex 中说话时的波形响应和最终上屏仍需复验，不能把空白编辑器的捕获就绪写成该场景已完成验收。


测试隔离补充修复：最后实装检查发现按住键再次从「右 Option」变回「右 Control+右 Option」，这次文件修改时间明确落在 `live-voice-controller` 套件内。合成控制器虽使用临时会话和 volatile defaults，`handleEvent:` 启动偏好轮询时仍继承基类 `runtimeOptions`，读到了已安装应用的定位器；测试里的外观编辑随后把合成语音选择写入真实偏好目录。此前把这种反复变化全部归为产品启动覆盖并不完整，测试自身也是写入者。

三种语音控制器夹具现在显式拒绝系统定位器，保留各自的合成会话与内存设置。回归将基类定位器临时换成虚构目录，只调用没有客户端的轮询准备，检查夹具没有采用该目录；回归在改前失败，恢复基类方法之后再断言，不触碰真实用户配置。HTTP、流式和系统识别夹具都运行这个隔离检查。十五个聚焦套件重新通过，运行前后真实偏好文件 SHA-256 完全一致；使用真实设置窗口恢复用户要求的右 Option 绑定。提供商也曾被夹具写成系统识别。用户确认仍使用原来的本地模型后，已通过真实设置窗口恢复 `asr_provider=local`，保留原模型目录；按住键、全局范围及 `Control+F9` 等原选择再次核对。测试隔离单独落地时原生产品代码为 `e020b0cdc6`，该次补充仅修改测试与笔记，当时无需为了测试隔离再次替换应用。

实际画面留档补充：安装的原生代码修订为 `e020b0cdc6`，已保留只含语音浮层的真实窗口截图。合成修饰键在切源期间可能被系统恢复的物理键状态提前释放，因此这类探测的短录音或未出现波形不能直接等同于实体按住键失败。最终用户使用 ABC 与 Codex 的实体按住、说话后波形响应仍单独验收，未把孤立编辑器的 PCM 和窗口证据当作整条路径通过。


硬件配置变化的启动恢复：用户实体按住后的框架日志确认，一轮录音的 `AVAudioEngine` 已启动，却在首帧前因 I/O 配置变化被系统停止，随后首帧超时报告无音频；另有几轮仍停在 IMK 客户端等待，二者不能归为同一个原因。当时补查的默认内置麦克风未静音、独占所有者为 `-1`，当前没有其他输入客户端；这是当前快照，不能据此断言历史上从无其他程序使用麦克风。[Apple 的通知契约](https://developer.apple.com/documentation/avfaudio/avaudioengineconfigurationchangenotification)明确说明硬件声道数或采样率变化会停掉并反初始化引擎，应用负责恢复格式和连接。

原生采集服务现在订阅当前引擎的配置通知，退出 AVFoundation 内部通知队列后在主线程处理。仅在本轮尚未收到音频、引擎确已停止时恢复一次；重装 tap 时重新读取设备格式，冻结旧 tap 的计时，保留 PCM 流与识别请求，不能调用会结束识别的完整停止入口。正常运行中的通知不重启；取消、松手后的停止移除观察并推进代次，旧引擎或旧一轮排队的通知不得补开麦克风。恢复再次失败仍交给既有全局首帧超时显示错误，不无限循环，不把捕获成功当作识别成功。已有录音后的设备变动不作为本次「首帧启动」重试，本次也不把自动恢复扩大到离开目标或结束录音之后。

合成引擎回归在改前复现首帧前停止不恢复，改后覆盖运行中通知、硬件采样率变化、重复通知、旧 tap 迟到、取消后开始下一轮、停止后通知、恢复失败不循环以及已收到音频时不重试。测试不打开真实音频设备。IMK 客户端未到达的另外几轮仍需单独排查，不以这项采集恢复声称全局按住键的完整验收已经通过。

启动恢复补充验证：复用同一 universal 缓存编译原生宿主及相关测试目标，十五个 macOS 聚焦套件通过，整轮测试前后真实偏好文件逐字节一致，笔记校验通过。实装与用户实体按住验收另行记录，不用合成引擎代替真实设备结论；全平台本地检查仍按用户要求跳过。


## 独立审查后的入口与后台约束

全局入口遇到当前 IMK 控制器已由菜单或工具栏开启的录音时，把切换动作交回局部入口，不接管原字段、识别请求或提交目标。第一次切换结束录音，处理中的再次切换沿用既有取消行为。空格锁定同时传给外层协调器和内部修饰键手势；普通组合键仍交给编辑器，实际松开修饰键后解除交付等待。

后台登记由原生宿主负责。登记身份包含源码修订、构建号、可执行文件和 LaunchAgent plist 的修改时间；已批准的旧构建等待异步注销完成后再登记，等待期间的功能关闭优先。`RequiresApproval` 保留用户的拒绝或待批准状态，不通过循环重新登记覆盖。未批准、登记失败和迁移期间不创建全局键盘入口；即使偏好修订未变或暂时读取失败，也观察系统批准变化并关闭已有入口。失败后的尝试有间隔，局部 IMK 输入不受此全局门禁替代。

设置进程只有同时满足正式 `.app` 资源布局、默认 HostOptions 定位、未覆盖状态目录和原生应用数据目录时，才管理正式安装的后台项。隔离开发配置照常编辑自己的偏好，但不会注册、撤销或启动正式宿主。后台 helper 成功之后才缓存已应用值；失败按 2、4、8、16、32、60 秒的有上限间隔重试，用户改变选择时立即重新评估，避免首次安装竞争永久吞掉配置。

回归只使用合成控制器、提供商、时钟和后台服务替身，覆盖连续代次、迟到回调、长录音／慢响应、重复错误清理、菜单与全局入口混用、锁定组合键松手、后台更新与撤销、隔离配置及失败重试。启动边界夹具经过输入阶段与宿主阶段两个真实初始化入口；测试偏好套件使用 `MSIMERemoveTestPreferenceSuite` 清除域和文件。这里的聚焦测试不等于实机批准迁移、真实 socket 服务或实际说话验收；本轮不重新安装，不运行用户明确跳过的全平台本地检查。
