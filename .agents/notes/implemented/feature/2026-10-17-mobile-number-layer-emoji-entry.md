# Agent Note: 移动端数字页按工具栏入口选择表情或符号键

Status: implemented

## Problem

#7836 指出顶部工具栏已有表情入口，数字页底行却仍固定放表情键。扩展符号页已有直达符号面板的键，数字页反而需要先经过扩展页。直接删除表情键还会丢失隐藏工具栏时的备用入口。

## Decision

Android、iOS、HarmonyOS 的数字页在工具栏提供表情入口时，把底行同一位置用于「符号」，复用现有符号面板动作和宽度；工具栏关闭表情或整条隐藏时保留表情键。扩展符号页保持符号键。只改宿主展示，不增加共享偏好。

Android 与 iOS 依据已有表情开关和工具栏隐藏设置；HarmonyOS 工具栏固定提供表情，依据当前工具条是否显示。设置恢复或键盘重新出现时同步更新键面。候选、面板等临时覆盖不改变 Android 与 iOS 的已配置入口语义。

## Alternatives considered

- 删除底行入口并扩大空格：能去重并扩大空格，但没有把释放位置用于符号输入，也要另找隐藏工具栏时的表情入口。复用现成符号键保留全部宽度规则。
- 一律替换成符号键：行为最简单，但 Android 与 iOS 允许关闭顶部表情，必须保留备用入口。

## Consequences

数字页直接进入符号面板，两种入口复用相同权重，不留空位。Android、iOS 的工具栏开关继续生效，HarmonyOS 根据固定工具栏的当前显示状态选择入口。

Android 底行的旧表情动作只显示面板，没有像工具栏入口一样刷新返回键状态。底行的表情和符号动作现在在打开后刷新展示；隐藏工具栏时面板暂时显示工具栏，供用户返回，关闭面板后恢复隐藏。该变更由同一项回归覆盖。

三端工具栏实现不同，不增加共享偏好。iOS 两个按钮由栈显隐互换，继续使用现有可隐藏宽度约束。键盘层的临时覆盖与已配置入口语义保持前述平台边界。
