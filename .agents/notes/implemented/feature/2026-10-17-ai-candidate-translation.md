# Agent Note: 候选翻译复用 AI 配置并放宽整句长度

Status: implemented

## Problem

#7078 的用户服务翻译已经接入 Android，但候选翻译仍不能使用现有的 OpenAI 兼容 AI 配置，且共享层把所有候选原文限制为 40 个字符，较长的中文整句没有翻译机会。翻译服务和 AI 候选原先各有请求描述器、响应边界和宿主接入点，继续在各平台复制一套大模型 HTTP 逻辑会造成配置、隐私和错误处理分叉。

## Decision

候选翻译复用当前会话已经解析出的 `ai_assistant` 服务商、接口地址、模型和密钥，不新增第二份 AI 凭据或独立的翻译服务配置。共享层提供候选翻译 AI 请求描述器和严格响应解析器，宿主只负责传输、把成功译文按已有 `CandidateTranslationStore` 的生成代次应用，并沿用现有的服务级退避与取消边界。

AI 翻译请求使用固定的机器可读提示词，要求返回目标语言译文数组，不接受解释、Markdown 或多余字段；空回答、结构错误、重复原文和超过单项长度的结果都按无译文处理。请求只在用户开启候选翻译、AI 配置有效、候选是中文且没有离线译文时发出，目标语言沿用候选翻译的主次语言。

共享层把候选翻译原文上限从 40 个 Unicode 字符提高到 256 个；单词候选、账号服务和已有自定义服务同时使用这个上限，字节上限和各服务的请求超时保持不变。六个平台的宿主统一调用共享 ABI，不再各自定义长度、提示词或响应校验。

## Alternatives considered

- **新增独立的 AI 翻译接口、模型和密钥配置**：能让翻译与 AI 候选分别计费和调参，但会在六个平台再增加一套设置、密钥存储和隐私说明，也会让同一个用户的 AI 配置出现两个容易不一致的来源，因此不采用。
- **继续使用 40 字上限，只在 Android 放宽**：实现较小，但长句翻译的行为会随平台不同，且共享账号和用户服务仍会拒绝同一原文；不符合 issue 要求的跨平台语义，因此不采用。
- **由每个平台直接拼接 Chat Completions 请求**：可以绕开共享 ABI，但会复制鉴权、地址策略、响应校验和提示词，任一平台修复都可能遗漏其他平台；不采用。

## Consequences

候选翻译现在可以复用用户已有的 AI 配置，并在中文整句长度为 41 至 256 个字符时生成翻译计划；超过 256 个字符、空文本、非中文或受保护候选仍被拒绝。请求凭据只在构造描述器时使用，不进入宿主日志或持久化翻译配置；AI 服务失败不会回退到水杉账号或其他用户服务。AI 请求可能比普通翻译服务更慢并消耗更多额度，现有请求级超时、每会话去重、服务级退避和候选数量限制继续控制影响范围。

共享 Rust 单测、host API 单测、各平台 quick 门禁和 Android API 28/API 35 的 `client-base`、`client-core`、`client-providers`、`client-services` 设备测试均通过。Android 通用 UI smoke 仍有既有的笔画键盘合成状态失败，重置 API 28/35 应用状态后仍复现，与本次候选翻译代码无关。
