# Agent Note: 移动端补齐多种双拼方案

Status: implemented

## Problem

#11343 要求 Android、iOS 和 HarmonyOS 的移动端输入方式增加搜狗、加加、紫光、智能 ABC、国标双拼。原有共享 Engine 只有智能 ABC 的部分支持，移动端入口只暴露小鹤、自然码、微软和首道；各宿主自行补表会造成键位、同步和统计不一致。

## Decision

把五套方案作为共享 Rust 的 `ShuangpinProfileKind` 追加值，并由共享 Engine 保存唯一的声母、韵母和零声母映射。智能 ABC 复用已有共享表；搜狗、加加、紫光、国标按公开方案说明独立转录为静态表，不把第三方配置文件复制进仓库。ABI 序号只追加，既有 0–5 保持不变。

Android、iOS 的原生设置追加对应触屏入口；三端键盘与共享偏好保留标题、短名、键位提示和统计来源。HarmonyOS 在设置顶部提供原生「双拼方案」入口，以独立 ArkUI 面板显示共享 Rust 的方案目录；共享页仅回显已经保存的新增 profile，并保留原生端已启用的触屏方案，不增加 React 控件。原生面板每次选择前重读偏好，用 `client-core::touch_shuangpin_settings` 同时更新 Engine 方案、上次中文方案、双拼 profile、触屏布局、启用集合与选中项，再按原修订号 CAS 保存。本地方案入口不要求网络授权；启动时回读已有授权标志，不依赖再次弹窗初始化原生入口状态。只把用户选中的新方案加入现有启用集合；不替换其他输入方式。冲突和失败后回读，不自动覆盖重试。返回共享页面时强制刷新其快照，避免宿主已记住新修订号、网页却继续保存旧值。搜狗、紫光与微软一样显示 `;` 韵母键；其余新增方案沿各自映射显示普通 26 键。新入口加入 Android、iOS 原生可选列表，不加入新装或旧文档的默认启用集合，用户显式打开后才显示。账号同步只在下载方向认识四个新增双拼 profile；上传方向五种新增方案（含智能 ABC）都暂不写 `input.shuangpin_schema`，iOS 也不写这五种方案的 `input.schema`：已经发布的 iOS 读到不认识的双拼方案会拒绝整份账号设置。新版 iOS 读到不认识的双拼方案只跳过方案这一项。等能容忍未知取值的 iOS 版本发布后再打开上传。云词库候选面板只提供 `valid_candidate_query` 接受的 profile，搜狗、加加、紫光和国标等云端确认能编码后再加入。

## Sources

搜狗、加加、紫光、智能 ABC 的键位参考公开 Rime schema；加加的零声母按其首字母作声母键（aa、as、af、er、eq），紫光的单韵母 ü 留在 V 上，只有 üe、ue、ui 在 N 上。国标双拼参考公开键位表后独立转录。仓库只保存声韵母到键的结果和测试断言，不把第三方 schema 文件当作运行时输入或信任根。

## Alternatives considered

- **只在 Android、iOS 或 HarmonyOS 宿主内写映射**：会让同一份偏好在不同平台产生不同编码，也无法让桌面或账号同步识别新 profile，因此不采用。
- **只增加可编辑的自定义表入口**：不能满足用户直接选择常见方案的需求，且键位提示和统计无法稳定命名，因此不采用。
- **把新增方案加入默认启用列表**：会改变现有用户的快捷方案顺序和新装键盘数量；本 issue 只要求能力可达，故保留默认值并让用户显式启用。

## Consequences

共享偏好、Android/iOS 原生入口、账号下载、键位提示和统计来源都认识五套新方案；HarmonyOS 原生选择入口已补齐，旧 profile 的序号和默认行为不变。新方案默认关闭，启用后三端使用同一套 Engine 映射。搜狗和紫光的分号键需要宿主显示与路由，其他方案不增加专用键。

## Verification

- `cargo test -p msime-engine shuangpin::profile --lib` 通过，覆盖五套表的选择、关键映射和分号键规则。
- `cargo check -p msime-client-core -p msime-client-services -p msime-host-api` 通过。
- 共享设置页只保留已有方案的可选顺序，并覆盖原生已存 profile 的禁用回显、保存保留和已启用触屏方案的展示；触屏方案回退与统计中文聚合测试保留；统计聚合包含四个新增云端方案，默认启用列表仍保持旧值。
- 鸿蒙原生目录与选择事务补充共享 Rust 行为测试，宿主模型覆盖最新修订号、无关偏好保留、冲突只回读、存储/目录失败禁止写入。设备验证缺口在各 PR 的验证段单独注明，不据此阻塞后续 issue 实现。
