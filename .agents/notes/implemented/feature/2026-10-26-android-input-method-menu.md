# Agent Note: Android 功能菜单提供输入方式入口

Status: implemented

## Problem

#9731 的用户关闭工具栏「输入方式」后，品牌菜单没有对应入口，无法在键盘内方便地切换布局。

旧笔记检索：品牌菜单与工具栏入口去重由 [Android 工具栏排序](../../implemented/feature/2026-10-15-android-toolbar-order.md)描述，部分重叠，保留原有排序与开关存储；[手机方案选择器](../../implemented/feature/2026-10-09-mobile-picker-single-shuangpin.md)持有方案列表过滤，部分重叠，复用该面板，不修改列表规则。其他平台和桌面菜单整理记录与本入口无关。

## Decision

功能菜单第一页在「手写」前增加「输入方式」，使用现有键盘图标，先关闭功能菜单，再打开现有输入方案选择器。可用条件与工具栏一致：会话与偏好就绪。选择器自身继续处理保存中的防重入。

沿用菜单对表情、剪贴板等入口的去重规则：工具栏显示输入方式时，菜单不重复；工具栏该按钮关闭或整行隐藏时，菜单保留入口。不改变默认开关、品牌 Logo、输入方案和持久化方式。

## Alternatives considered

始终同时显示菜单与工具栏入口，位置容易记忆；但现有菜单会过滤工具栏已有入口，因此本次沿用去重约定，解决关闭工具栏图标后无法到达的问题。

## Verification

- `FunctionPanelModelSmoke` 覆盖新增入口的顺序、三页上限与全部工具栏去重组合，现有默认工具栏配置下的菜单顺序保持。
- Android 35 专用模拟器的 `MoreToolsDeviceSmoke` 通过：通过原生设置页关闭图标，从菜单第一页打开选择器，切换英文并核对已选中状态、恢复原方案并核对已选中状态、返回键盘，重新启用图标后菜单去重；原菜单排列、开关与子页回归也通过。
- 当前分支重新构建 Rust、JNI 与原生 full APK，Android 真机使用正式证书覆盖安装 0.6.0（`versionCode=6000`），保留现有数据。

## Consequences

关闭工具栏图标后仍能在键盘内切换布局，且复用已有的方案过滤与保存逻辑。新增条目在工具栏隐藏时会推动后续条目位置，菜单仍使用现有分页网格。
