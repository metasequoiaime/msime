# Agent Note: Android 十八键全拼入口

Status: implemented

## Problem

#8892 希望 Android 全拼提供比二十六键更宽的按键，并能选择布局。现有十四键已提供完整组码与消歧入口，共享引擎也已支持十八键全拼，但 Android 原生键盘尚无十八键全拼的偏好、方案卡片与键面接线。

## Decision

在全拼既有二十六键、十四键、九键选择中追加十八键，并提供独立、默认不启用的 `eighteen_key` 触屏入口。复用 `KeyGrid::EighteenKey` 和编号 4 的 C ABI，字母组固定为 `Q WE RT Y U IO P / A SD FG H JK L / Z XC V BN M`。点按发送多义组码，实体键盘仍发送确定字母，组词、读音锁定和候选归共享引擎。

原生键面复用十四键的符号与拼音侧栏、三栏候选、分词、长按、底行和数字层。三排采用七份宽度，第二排居中，第三排加上分词和删除后同宽；窄屏文字保持单行。布局可在设置中切换和恢复，英文、密码和本地模式沿用确定字母的回退路径。

十八键全拼只在已经画出键面的 Android 和 iOS 自动启用（iOS 见 [iOS 十八键](2026-10-25-ios-eighteen-key.md)）。其他宿主原样保留新增偏好，暂不画出未接线的键面。保留现有出厂默认值与启用列表，不增加十七键或任意可编程布局；这些需要额外的明确分组与行为契约。

## Behavior coverage

原生设置可在二十六、十八、十四、九键之间选择；重启后保留选择。十八个键覆盖全部字母，触屏多义组码与实体确定字母分路；可以选择读音、撤销锁定并提交候选。英文、密码和 URL 回落可用，数字层返回十八键。API 28／35 的真实键面和窄屏、横屏、浮动、单手几何均已通过专项验收；默认列表不增加入口。

## Historical audit

- [共享十八键全拼](../../implemented/feature/2026-10-24-eighteen-key-quanpin-engine.md)：部分重叠，直接复用已合并的算法与编号；Windows 的原生接线仍由 #8936 单独跟踪。
- [十四键全拼](../../implemented/feature/2026-10-10-fourteen-key.md)：部分重叠，沿用组码、确定字母和候选身份边界，不翻转已有布局决定。
- [Android 拼音侧栏](../../implemented/bug-fix/2026-10-13-android-fourteen-key-left-spellings.md)：部分重叠，复用已有纵向拼音选择，不重新引入增加键盘高度的独立拼音行。
- #9124 的 PR #9530 实现十八键双拼；#8930 另请求双拼与精确滑动字母。它们不属于本 issue，本分支不复制双拼算法、不自动关闭其他 issue。

## Alternatives considered

**只把两个字母印在键上并发送首字母**：可直接复用普通字母按键，但另一个字母无法参与候选，所以使用共享组码入口。

**在 Android 保存音节表和组词状态**：可以独立调整触屏行为，但会复制引擎算法、学习与候选身份，跨越架构边界；Android 只负责键面和输入来源。

## Consequences

新增入口由用户选择，出厂布局与启用列表不变。复用十四键的组码展示和共享引擎消歧，避免宿主保存另一份拼音状态；代价是统计来源和键位白名单跨端追加，同时维护旧来源的顺序与读取兼容。十八键双拼的并行 PR 会改到相同的网格展示代码，整合时需要保留两个 issue 各自的方案入口与验收记录。

## Risks

加权键行在两级设备按实际边距和宽度检查，保留 2 像素误差上限，单看权重不足以证明第二排与其他行同宽。统计白名单在四端独立声明，由离线键表契约防止新增键被丢弃。十八键双拼与全拼共用分组，但设置和路由分别归各自 issue。

## Verification

先记录缺少原生入口和偏好识别的失败，再实现设置、宿主与布局。验证包含共享偏好与平台门控、Java 键表和入口、API 28/35 实际设置与组字、消歧、提交、布局切换及几何。复用已完成任务的标准远端构建缓存，不新建本地 Rust 或原生构建树；完整门禁与设备结果按实际执行范围更新。

已记录入口、共享偏好、宿主门控、统计来源与键面标签的初始失败；新增 Rust 专项及账号布局往返通过，离线键表／四端统计契约通过。Android 266 项 JVM 冒烟、234 份设备源码编译及 Java/JNI、清单、资源检查通过。client-core 534 项、host-api 945 项通过（另 5 项忽略），相关前端 35 项、类型检查和 HarmonyOS 键盘逻辑检查通过；远端 quick 门禁通过，Apple 原生和真实 ArkTS 构建因环境未就位而跳过。

API 28 在原 APK 的真实设置中确认缺少十八键选项。新 APK 已通过设置保存、组码提交、读音锁定与撤销、分词、展开候选、英文／数字／实体字母和密码／URL 回退；初次几何验收在左手模式发现中排宽 95 像素、首排宽 92 像素。中排只有六个字母键，普通半权重占位未计入第七个键的横向边距；在每次应用几何时由两端占位各保留半个键的边距预算，保证键距就地变化时也更新。修正后 API 28／35 的完整十八键专项均通过；竖屏、720×1280 窄屏、左手、右手、浮动和横屏六种几何全部满足原来的 2 像素误差上限，两级共十二张键面截图已逐一检查。
