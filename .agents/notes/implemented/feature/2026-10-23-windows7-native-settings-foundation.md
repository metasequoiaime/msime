# Agent Note: Windows 7 原生设置窗口的持久化、输入、标点、快捷键、工具栏与维护

Status: implemented

## Problem

现有 Windows 设置使用 WinUI 3，无法作为 Win7 设置入口。兼容窗口必须使用相同配置、默认值和版本能力过滤，并且不能在保存少数字段时抹掉其他页面、令牌或另一窗口的修改。完整页面适配期间也不能把普通 Windows 的设置入口切到未完成的窗口。

## Decision

设置外壳使用左侧分类导航与右侧页面标题、说明和子页标签。分类树沿用系统控件的键盘导航和读屏语义，深链接与树节点共用原页面索引；原组合框仅保留为内部路由适配，不再显示。输入方案页把标签与选项放在同一行，组合框、普通按钮和单行编辑框按用途限制宽度，说明文字不再继承系统灰底。窗口按工作区居中并限制初始尺寸，正文、导航与底栏分别布局。读取成功的底栏显示「设置已就绪」，不将语音等需要显式保存的表单误写成全部自动保存。视觉调整不修改出厂值、保存时机、页面草稿或 Rust 业务归属；实际截图与最低窗口尺寸检查是外观验收的一部分，不能只以控件存在和 CTest 通过认定可交付。

`settings/win7` 使用 Win32 标准控件、系统字体和兼容 DPI 接口，复用不依赖 WinRT 的页面模型与同一个 Rust Host API。独立目标 `msime-client-settings-win7` 目前提供快捷键的按键设置与按键速查，以及悬浮工具栏的显示、按钮与尺寸控件；维护与诊断页提供服务与 TSF 日志开关、服务重启、目录打开和设置文件导入导出。只有同时含中文与日语方案的版本显示日语切换控件，不提供手写的版本不画手写按钮开关；不添加未实现页面的占位入口。工具栏提供图形预览和主题页跳转。普通构建、启动器、安装包及出厂默认值保持现状。

`PreferencesStore` 保留完整快照，按明确存在的路径及契约登记的可省略叶字段与类型替换值，带原修订号调用 Rust 的比较并交换保存。默认值、配置格式、字段校验和磁盘提交均由 Rust 负责。切换中英文的三个互斥布尔值在一次保存中修改；不改动无关字段。工具栏尺寸复用 `FloatingToolbarSizeModel.h`，一次保存缩放与字体尺寸；已有自定义值照实显示，进入页面不归一化存储。当前 C ABI 没有冲突错误码，适配器识别其实际描述 `preferences changed; reload before saving`，并以集成测试约束这一边界。

输入页接通「选词与翻页」：以词定字、退格回退与六组可配置导航键。以词定字的组合框只列当前未用于翻页的键组；把它正在使用的键组改为翻页时，同一次 Rust 保存关闭以词定字，避免中间态冲突。选择关闭保留记住的键组。Tab 与 PageUp/PageDown 在 Windows 固定生效，界面说明这一行为，不修改文档里对应的共享偏好。`navigation.mouse_wheel` 为假、`backspace_reverts_selection` 为真时共享格式省略该字段，界面按契约展示，首次修改只允许补入这两个明确的布尔叶字段；未知键、类型不对与缺少中间对象仍被拒绝。页面切换和刷新只读当前值，不把现代窗口的展示回退值写成默认值。输入页还提供「输出设置」标签：简体与繁体、同次上屏中英文之间加空格，以及会话初始全半角。繁简只改现有布尔键，不触碰其他宿主的繁体变体；说明复用 `InputSettingsModel.h`，随实际方案与选择更新。快捷键与输入各自记住已选标签，换页、换标签均只读，不改修订号。输入页的「候选与联想」提供云候选、混输总开关、英文与首页数量、emoji、符号、颜文字、版本允许时的临时日文、学习、只出单字和本地整句联想；混输关闭时禁用子项但保留值，不修改 Windows 固定使用的最短触发长度。「中英模式」接通默认中英文、按应用记忆与全局统一、光标旁切换提示，以及应用例外的新增、切换模式和移除。应用名复用 `AppInputModeRuleList.h` 规范化与即时提示，最终仍由 Rust 校验；粘贴路径取文件名、ASCII 转小写，中文名称走严格 UTF-16/UTF-8。修改一条规则保留整表中的其他平台标识，空表按共享格式省略。列表刷新保留仍存在的选中应用；无选择时禁用修改与移除。

输入页的「输入方案」按 edition 过滤语言与中文方案，切换非中文语言时在同次保存记住原中文方案，切回中文时优先恢复它，再按 edition 默认和第一个可用中文方案回退。双拼提供五种内置方案、键位图提示和原始按键／拼音预编辑；已有自定义表只展示当前值，选内置方案不抹自定义表。五笔提供 86／98、拼音混输、余码提示、四码唯一自动上屏和二三候选快捷键。两个选词键先留在表单中，成对提交，允许交换；本地模型校验字符形状，翻页／以词定字冲突由 Rust 最终拒绝，失败保留草稿，无关配置刷新不抹草稿。越南语提供 Telex／VNI 和新旧声调位置。仅绘制当前方案的选项，隐藏组不占滚动高度，切换仅展示时不改其他方案的值。

五笔查码使用有大小上限的宿主选项读取和既有 `msime_client_settings_dictionary` 的 `wubi_codes` 操作，工作线程执行，展示整词、逐字的 86／98 编码和截断提示，查码不写偏好。可输入多行文字，长度与现代窗口相同为 1000 个 UTF-16 码元。窗口按系统控件类别处理焦点滚动，按钮统一开启焦点通知；组合框滚动按收起后的高度计算，新增的辅助码、方案和查码控件无需维护另一份焦点 ID 清单。

输入页的「高级选项」复用 `InputSettingsModel.h` 的快捷模式、模糊音规则与依赖关系。Shift 总开关仅禁用通过 Shift+字母进入的模式，`/` 与 `@` 独立，地名依赖 `@` 模式；禁用不清除选择。模糊音首次启用在一次保存中启用全部规则并写 `seeded`；后续开关保留规则，确认重置时关闭并清空规则而保留 `seeded`，取消不写入。调频提供五种模式，学习关闭时禁用整组，关闭调频时禁用触发频次，只有线性模式启用步长，原值均保留；Rust 接受的 7–10 作为现有值展示，界面不擅自压到标准档位 1–6。

辅助码只在提供全拼或双拼的版本显示，两族各自控制启用、方案和候选中显示。自定义码表经 `msime_client_helpcode_schemas` 读取，插件经 `msime_client_plugins` 的 catalog 读取，均在工作线程执行，进入输入页或重新读取时刷新。采用现代窗口相同的宿主选项来源；读取有大小上限。资源或插件缺失时保留当前选项，页面刷新不改变修订。选择插件仅改整份 `plugins` 中对应的族，保留其他插件配置与原方案；选择普通方案同次清除对应插件。`plugins` 在全默认时会被 Rust 整体省略，因此存储只额外允许补入这一个明确的对象；不允许补造任意中间路径。辅助码触发方式等隐藏字段原样保留。

「标点与翻译」页分「标点设置」「候选释义」和「翻译服务」标签。标点模式、锁定和智能标点复用现代窗口的 `PunctuationSettings.h`：选「始终」只改本机锁定，保留起始标点；选普通中英文标点在一次保存里解除锁定并写起始标点。智能标点总开关同次修改总开关、数字后直出和字母后直出三个键，其他子项保留。关闭总开关时子项禁用并保留原值；两种直出都关闭时展示共享模型的惰性提示。引号和方头括号样式、空格开关属于默认时省略的字段，存储适配器仅允许按契约类型补入这些叶字段，不允许补造未知配置树。

候选释义接通离线英文释义、候选词翻译、读音、目标语言和第二种语言。翻译与英文释义任意一个开启时，语言与读音控件可用；两者都关时禁用并保留已选值。第二种语言的「不显示」通过 Rust 写空值并恢复省略，只额外放行这个明确可省略的语言叶字段；目标语言仍只修改原字段。标点与翻译记住自己已选标签，切换标签与页面不落盘。

翻译服务复用 `TranslationServiceSettings.h` 的服务优先级、腾讯云本次选择状态、凭据校验与测试门槛。未配置腾讯云密钥的默认配置显示「不使用在线服务」，用户明确选择腾讯云后，即使偏好未改变也保留当前选择。选择服务一次修改三个服务启用位和账号选择，凭据不随服务切换清除。每组凭据单独留草稿并显式保存，实际凭据未改变时，服务启用位和其他偏好刷新不抹掉草稿；保存后仍由 Rust CAS 校验与持久化。密钥默认遮住并提供显示／隐藏按钮。自定义端点的 WHATWG 地址校验使用同一个 `msime_client_translation_endpoint_issue`，不在 C++ 复制 URL 解析规则。

「测试配置」在串行工作线程调用 `msime_client_test_api_credential`，不修改偏好；界面明确说明会发送合成请求。测试结果绑定测试时的配置，编辑字段立即隐藏旧结果，只展示当前所选服务的控件。选「不使用在线服务」不关闭离线释义。界面、错误提示和测试日志都不打印凭据内容。

云候选配置独立保留表单草稿，来源、方法、响应格式及文本编辑都不立即落盘。保存按钮将来源、地址、请求头、请求体、响应路径、超时与缓存作为一个对象交给原 Rust 校验和 CAS 持久化；无效配置不改变修订号，保留草稿并提示。无关偏好保存后仅当实际云候选对象改变才重填表单，避免把未保存编辑抹掉；并发保存冲突时重新读取实际服务配置，旧草稿不自动重试覆盖。请求头仅在本机保存，保存表单不发网络请求。文本通过严格 UTF-16/UTF-8 转换，业务校验不复制到 C++。

所有配置和运行时选项文件读写在串行工作线程执行；界面等待时禁用编辑控件，不累积整份旧快照。保存失败后重新读取实际状态并提示，既处理并发冲突，也处理可能已经落盘后清理失败的情况，不自动重试覆盖。关闭时完成已受理的保存并等待线程退出；完成消息不传堆指针，不把结果发给已销毁窗口。状态目录优先级与现代窗口一致，读取运行时选项有大小上限。

设置文件通过现有 Rust 导出与导入接口处理，复用 `SettingsDocumentFile.h` 的大小、UTF-8 和文件写入约束。导入带当前修订号，不覆盖并发修改；服务配置与密钥、诊断日志、使用统计和剪贴板历史开关按共享规则保留。文件选择在窗口的 STA 使用从 Vista 起支持的 `IFileDialog`，文件内容的读写与导入仍在串行工作线程执行。服务重启复用当前 edition 的 Aux 管道，仅提示是否已发送请求；目录打开优先实际日志子目录，不存在则打开数据目录。

独立 CMake 目标使用同架构、同源核心导入库；开发时可指定既有原生依赖前缀，CI 使用此目录的最小 vcpkg 清单，仅安装现有锁定版本的 JSON 依赖。`windows-settings` 在构建同源普通核心后构建和运行此目标，现代 WinUI 页面验收继续保留。CI 覆盖控件和存储，专用 Win7 核心、运行库与实机兼容性继续单独验证。

每个配置的程序目录生成同源 `edition.json`，使 Rust 的包身份与 C++ 的编译期 edition 一致；不能让独立编译的五笔等版本因缺少声明而在 C ABI 一侧被当作 full。

偏好默认值仍按安装准备阶段写入状态目录的 `edition` 记录读取，与包内声明分别验证。原生测试为非 full 版本建立同样的合成记录，断言首次偏好中的方案与本版本一致；不把未准备的空目录冒充已安装产品。full、五笔和日文的 x64 控件与配置测试通过，日文手写的原生窗口和 C ABI 均拒绝未提供的功能。

候选窗口外观页接通横竖排列、每页数量、logo、跟随光标、主字体与英文字体、字体预设、两种字号、整体缩放、不透明度、圆角覆盖和两种预编辑。展示档位沿用现代窗口，Rust 已接受但不在这些档位内的原值以「当前值」展示，不因刷新或改其他字段而归一。圆角的「跟随皮肤」保存空值并恢复省略；字体与游戏配置只登记各自明确可省略的叶字段或对象，未知路径仍不能补造。

字体预设和主字体补丁复用 `CandidateFontPresets.h`，主字体与回退链在一次 CAS 保存中更新。文本先留草稿，显式保存两种字体；无关修改、目录刷新和 CAS 冲突不抹掉草稿。系统字体目录由工作线程调用 `msime_client_list_font_families` 获取，两个可编辑组合框共用同一份结果，目录重载保留现有输入；失败可以重试或直接输入名称。显示中文字段走严格文本转换，不向共享配置写替换字符。

游戏组复用 `GameProcessList.h` 的程序名规范化、跨表去重和总数量校验，开关关闭保留两张程序表。原生候选登记名称复用普通设置使用的 `GameCompatProfile.h`：按钮明确说明管理员授权，工作线程启动同一可执行文件的现有提权命令，入口在建立窗口之前识别该命令；运行结果与登记状态均由工作线程读取，UI 不伪造成功。工作线程建立并平衡 STA，避免 ShellExecute 所需 COM 环境依赖调用方。测试不运行提权、不修改真实输入法注册；这条系统操作仍需完整产品安装后的验收。外观页已提供原生固定样例预览，完整屏幕键盘皮肤由专用原生面板绘制。

主题页使用独立 `ThemeForm`，从 `msime_client_theme_catalog` 获取主题 ID、名称与明暗，从 `msime_client_skin_catalog` 获取本地皮肤；不保存一份主题列表或调色板。颜色模式、候选明暗、全局主题、皮肤选用与停用、五项候选颜色的设置和清除均通过原有 CAS 持久化。皮肤的双明暗槽位、底色与取色器切换规则复用 `ThemeSkinModel.h`，复合操作只提交一次修订，保留其他自定义项。颜色先留草稿再显式保存，目录刷新与无关设置修改保留未保存文本。选择预览明暗只更新窗口状态，不写偏好。

皮肤文件夹通过同一 STA 的 `IFileOpenDialog` 选择，确认文本明确列出所选目录及同名整包替换行为；取消选择或拒绝确认不调用导入。实际导入、目录扫描、主题解析和图片读取解码在串行工作线程完成。预览由共享解析接口给出颜色，原生回退和选中文字推导复用候选宿主的 `CandidatePalette.h`，皮肤图片经经过包内路径校验的 `msime_client_skin_resource` 和静态图像解码接口读取，复制为预乘 BGRA 后由 GDI 绘制；不在绘制中读盘、解析或解码。图片失效显示说明并保留基础配色，预览失败不把已保存设置误报为存储失败。当前预览展示固定候选样例、圆角、不透明度、背景适配和装饰首帧；皮肤制作与完整主题卡片由后续共享模型和原生控件接通，见[皮肤制作](2026-10-24-windows7-keyboard-skin-editor.md)。

社区皮肤使用独立 `CommunitySkinForm`，复用 `CommunityPageModel.h` 的分类、评分、许可、发布字段和错误文案，经 `msime_client_community` 接通搜索、分类、我的皮肤库、分页、详情、预览、安装、评分、举报、可见性、作品分类、下架与显式同步。本地包可补 PNG/JPEG 预览、补素材许可、只检查不上传，再填写名称、说明、可见性与分类发布。网络、文件、base64 与图片解码均在同一串行 worker 执行，绘制只使用已复制的预乘 BGRA。预览限定 PNG/JPEG data URL、256 KiB 和正式解码接口；不在页面上访问任意图片地址。

同名安装先以 `replace:false` 调用共享安装器，收到 `candidate_skin_exists` 后才提供确认替换；取消不请求。同步会上传内容、下架会改变账号皮肤库，操作前显示具体确认；公开发布还需要确认素材权利。发布 UUID 在本地皮肤选择后生成，同一次发布重试沿用；刷新本地目录不抹掉同一皮肤的发布草稿。社区安装不擅自修改主题偏好，成功后重扫本地目录，由用户选用。授权和预览写盘继续经过共享服务的包校验，不在宿主重写清单规则。服务失败只在社区页提示，不把网络失败误报为设置保存失败。

原生窗口允许注入社区传输，合成服务通过真实 HWND 和 worker 验证请求及确认边界；正常构造仍直接调用 C ABI。测试中的补许可、补预览和打包检查复用真实共享接口，在线发布、评分、举报、同步和下架只使用合成响应，不操作真实账号。这组验证不能代替在线服务、交互桌面或 Win7 SP1 的验收。

打字统计由独立 `StatisticsForm` 与 `StatisticsData` 适配共享聚合存储，复用现有 `TypingStatisticsModel.h` 的日期、概览、速度、范围、分类、候选位次与按键热力图规则。日历显示 53 周聚合，速度图显示最近 30 天；活跃不足一分钟的日期不推测速度。开关、自动清理和清空经 `msime_client_typing_statistics` 写同一状态根，保留初次关闭的默认值；不把统计保存进偏好。进入、重新激活与页面打开时的 5 秒计时器在空闲 worker 上刷新，离开页面不轮询。图表与日期选择只改 UI，逐日明细保留已选日期；只绘制已读取的计数，不在绘制中读盘。缩短保留期与清空先确认，取消恢复实际控件值；延长保留期直接保存。读取损坏统计失败只提示，不自动重置；随后返回的上传状态不得覆盖本地统计读取错误。

上传操作经现有账号 C ABI，携带同一个统计根和本地日期，平台仍为 `windows`。共享服务负责上传开关、十分钟节流与关闭时删除云端数据。上传开关变化先说明具体行为并确认；网络失败可能发生在本机开关已经写好之后，worker 必须重新读取上传状态，UI 用实际状态和本次错误分别展示，不能把旧开关重新画回去。原生测试在上传传输边界注入合成响应，统计加载、计数、保留期清理与清空走真实共享服务，不对真实账号进行上传或删除。

悬浮工具栏预览复用正式宿主的 `floating_toolbar_settings`、`floating_toolbar_slots`、`toolbar_metrics`、`toolbar_icon` 与 `toolbar_palette`。按钮顺序、尺寸、logo 握把和版本能力来自当前配置，不另写默认值。工具栏配色按顶层颜色模式解析，不能继承仅影响候选的明暗覆盖；共享主题解析在 worker 上执行，绘制只读结果。Win7 不保证存在 Fluent 字体，图标使用正式宿主定义的文字回退；有限窗口宽度下等比缩小并保留自然 DIP 尺寸说明。「颜色与明暗」跳转到同一窗口的主题页，不写设置或启动面板。

账号资料与设置同步继续使用同一账号 C ABI。昵称规范化复用 `msime_client_account_name`，账号资料显示 ID、邮箱、注册时间和登录方式；验证码保留 60 秒重发间隔，按有效期和六位数字控制提交，目标或渠道改变后清除旧 challenge 与可见验证码，首尾空白变化不作新目标。状态、资料、同步结构异常只提示，不能把已有登录态当作退出。状态 → 资料 → 同步的后续任务在 UI 完成函数末尾受理，整条链路保持 busy，避免中途允许另一个请求覆盖单槽队列。

Google 登录等待浏览器时保留取消按钮；取消不进入正阻塞等待的串行 worker。仅在 Google 请求期间建立可回收的取消线程，使用完全相同目录和 `client_agent` 调用共享内存取消接口；用户取消或窗口关闭时触发，持续到请求结束，涵盖取消先于 Rust 建立等待标志的竞态。正常完成不调用取消接口，不取消已经完成的登录；所有路径先结束取消线程再收回请求局部状态。关闭前已受理的偏好保存仍照常收尾。系统浏览器、回环授权和真实网络登录仍需交互桌面与 Win7 验收。

头像通过账号接口取得受限 data URL，由 worker 调用同一正式图片解码器转换为预乘 BGRA，绘制不访问远程 URL。`DataUrlImage.h` 共用社区与头像的 PNG/JPEG 校验、解码和 GDI 绘制，社区上限仍为 256 KiB，头像上限为 1 MiB；账号切换、退出、头像变化和失败刷新清理旧图片。上传复用带图片过滤器的 `IFileDialog`，取消不请求，文件内容与大小仍由共享账号服务校验；移除上传头像先确认。网络与上传传输使用合成响应，未变更真实账号头像。

设置上传、应用、退出所有设备、清除失效本机会话和注销均先确认。上传与应用携带同一个偏好目录；应用成功或失败都重读实际快照，并重新解析候选与工具栏预览，避免写后清理错误或并发变化留下旧修订。`account_recent_login_required` 只提示重新登录，不清空当前会话。账号请求携带当前 edition、编译版本与设备生成的 `client_agent`，会话迁移沿用共享接口已有的 `legacy_directory` 字段；该字段是已有跨宿主契约，不作为 Windows 7 产品命名。

`AccountManagementForm` 接通 QQ 群助手绑定、登录设备与云端数据管理，仍嵌在同一账号页面。QQ 列表、8 位绑定码兑换和解除绑定走原有账号操作；设备按服务端会话 ID 撤销，撤销当前设备后重读状态并清除账号界面。刷新失败禁用旧列表的撤销按钮，不能因旧行仍可见就提交旧就绪状态。云端数据概览展示服务端分区与匿名语音数量未知的说明，ZIP 导出使用明确的保存对话框；清空只发送用户勾选的分区，并在确认中逐项列出。请求与网络均在 worker 执行，数据清空后使旧同步快照失效并重新读取。

清空或注销成功但匿名语音清理失败是部分成功：清空结果和账号退出照常生效，保留独立提示和 `voice_delete` 重试入口，不能自动重做已完成的分区删除。匿名语音重试在未登录时仍可用，退出或换号也不抹掉未完成清理的提示。分区、会话 ID、绑定码和导出文件的最终校验与落盘均归共享 Rust 服务，原生表单只维护选择和呈现。

本地剪贴板由 `ClipboardForm` 接同一 `clipboard_history.json`、偏好锁与历史锁，启用、限额、读取、固定、删除、清空和复制后捕获继续走共享 C ABI。启用保存成功后才采集一次系统剪贴板；关闭先确认，只有 CAS 保存成功才能清空，冲突或保存失败不执行历史动作。分页复用现有桌面每页 20 条的模型，翻页与选中只改 UI，不写偏好或历史；固定重排后继续选中同一内容。重新复制先检查系统写入成功，再用共享捕获接口记录；共享偏好在此期间被关闭时不再捕获。

历史动作前后均重读实际偏好，外部关闭后立即移除窗口旧内容；历史读取失败保留原文件并禁用旧列表操作，不能自动重置损坏数据。数据读取、捕获和存储在 worker，UI 只画已读内容；复制使用 Win7 原有剪贴板接口。激活时的刷新用窗口消息延后到当前点击结束，不能在按钮按下与通知之间设置 busy 并禁用控件，否则第一次点击会被吃掉。`ClipboardServices` 只为原生验收注入捕获与系统复制边界，测试的其余读写仍走真实 Rust 存储，不触碰测试机真实剪贴板。云端历史、设备批准和中继设置由同篇后续表单与[独立面板](2026-10-24-windows7-clipboard-panels.md)覆盖。

## Alternatives considered

- **用 UI Automation 贯通系统文件对话框。** 可以覆盖实际选择行为，但保存与打开的控件模型、自动补全及交互桌面状态都会影响驱动，服务会话中的不确定性还会掩盖应用的文件读写断言。集成测试在文件选择边界注入路径，系统对话框单独做桌面验收，不因驱动失败就跳过实际配置验证。

- **冻结旧 WebView2 并复用共享 React 设置。** 可减少界面适配量，但依赖停止维护的旧引擎，前端能力和当前插件也没有完整兼容保证。原生兼容窗口可以直接复用共享 Rust 业务接口与既有纯页面模型。
- **在 UI 线程直接调用配置 API。** 实现更少，但目录、文件与锁等待会阻塞窗口；串行工作线程维护一份实际读取的快照，明确保存与关闭的顺序。
- **冲突后自动合并并重试。** 可以减少用户重做，但多字段操作存在业务关系，重试可能覆盖另一窗口刚做出的选择。这里刷新并提示，由用户决定下一次修改。
