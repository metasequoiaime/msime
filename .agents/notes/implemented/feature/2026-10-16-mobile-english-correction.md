# Agent Note: 移动端英文保留原文并提供唯一纠错

Status: implemented

## Problem

#8119 要求手机英文输入保留原始按键，并提供连写分词、少键、多键、邻键纠错、固有大小写与撇号恢复。已有英文前缀补全不能纠错，也不能让空格默认提交纠错。

## Decision

纠错算法放在 Engine，宿主沿用普通英文直出和从编辑器读取当前词的路径。共享英文查询请求增加可选的 `correction: true`；缺省仍是原有补全，手机明确请求纠错才得到原文第一行和可选的唯一建议。实际用户文字不写日志、不学习、不落盘；缓存只持有固定词库的条目及其两字母索引前缀，不保存完整按键串。宿主在选词或空格、标点边界重新读取当前词并校验，再替换这一词，不维护跨输入框的影子原文。

算法使用现有英文词库的索引查询。完整单词精确匹配优先；否则对最多 32 字节做动态规划，每词最多一次编辑、全串最多两次、最多六词。词频的对数、词数和编辑代价共同评分，避免把 `langiage` 拆成 `lang I age`。每页最多 128 条，每个查询线程只保留最近一个固定资源目录、128 页轻量词条；不预载整份词库。词库缺失、输入超过纠错界限或无法解码时，仍返回原文。网络缩写、常见撇号形式与 `I`、`Chinese`、`English` 的固有写法有确定规则。第一字母显式大写时建议也保留大写；不对句首额外大写。首字母之后还有显式大写时，整词只保留原文；这个检查先于固定词形恢复，以免 `IM`、`I'M`、`ENGLISH` 或 `eNglish` 被空格边界自动改成 `I'm`、`English`。

宿主接线的契约是：手机在空格边界使用纠错建议并追加 ASCII 空格；标点紧随词，随后补空格。点原文候选是本次明确拒绝纠错，下一次边界不再改写它。沿用现有英文候选开关，密码、网址、邮箱及禁止建议的输入框不自动纠错。九键数字组码仍按九键英文消歧处理。

拒绝纠错在当前词或外部编辑上下文变化时失效。iOS 额外比较可选文档标识，但系统不提供标识时仍允许本次拒绝生效，不能以标识必须存在为前提。Android 的数字页标点和字母页共用英文提交入口；HarmonyOS 在手机纠错模式下同步写入字母，让紧随其后的边界查询能读到最后一键。

Android 的 #9178 录屏显示普通英文输入和删除时工具栏反复闪动。每次新前缀先清空建议，空列表使界面短暂回到空闲工具栏，异步查询返回后又切回候选。现在查询排队前立即用当前原文作为唯一临时候选，收到共享引擎的结果后再替换；不把上一词的建议留给新前缀。代次、编辑器当前词与结果前缀校验仍负责丢弃过期答案。词边界、无建议输入框、模式切换与会话结束继续清空建议，原文行本身不推断纠错。

## Alternatives considered

- 整份英文词库预载到 Trie：查询快且召回完整，但每个键盘进程长期保留数万词条与节点，iOS 扩展的内存预算不适合再增加无界常驻索引。先复用有界 SQLite 检索，真实词库检查召回和延迟。
- 将三个宿主的普通英文全部切换为专用英文组字：原文、候选和提交可以直接由会话控制，但要改变已有的光标、删除、输入框切换和 iOS 临时英文行为。现有补全已经从编辑器读取当前词，并对异步结果做代次与原文校验，复用它更容易守住边界。算法仍只有共享 Rust 一份，平台只负责读取、校验和替换。
- 固定词形规则优先于显式大小写：能让全大写输入也恢复撇号和语言名称的常用写法，但手机在空格边界自动采用唯一建议，会改写用户刻意输入的缩写或混合大小写；显式大小写保护应覆盖所有建议来源。只有首字母大写的 `Im`、`Youre` 仍可恢复为 `I'm`、`You're`。
- Android 查询期间保留上一前缀的建议：能稳定候选栏且无需提前产生一行，但它展示的是已经过期的词，必须另加禁用状态防止误选。当前原文已能从编辑器得到，直接显示它既符合共享查询的第一行契约，也避免旧词残留。

## Verification

针对 #9178，`EnglishSuggestionPendingChecks` 复用既有英文纠错设备入口，在安装后的原生服务中阻住真实查询线程，覆盖首次输入、继续输入、删除回原前缀、同词旧代次答案拒绝与词清空后恢复工具栏。API 28 的旧宿主在第一处等待结果断言确定性失败，报告 `Pending English query flashed the shortcut toolbar`。修复后同一套件在 API 28、35 通过，包含真实编辑器中的既有纠错、点原文拒绝、标点、无建议／网址／邮箱／密码输入框门控。Java/JNI、254 项 JVM 冒烟、203 个设备源文件编译、原生 full APK 的资源锁与 ELF／签名检查、quick 门禁通过。未在报告人的 vivo 真机上验收。

合成词库覆盖 issue 示例、正确词只有原文、大小写、缩写、手动撇号、长度边界与缺失词库；C ABI 回归核对原文顺序、两行上限、不改变输入会话、旧请求保持补全。固定词库的六个分词/纠错示例全部通过，本机调试构建单次查询约 0.4–29 毫秒。手机延迟尚未测量。

显式大小写回归覆盖 `IM`、`I'M`、`I'VE`、`ENGLISH`、`CHINESE` 及混合大小写只返回原文，同时保留 `Im`、`Youre` 的撇号恢复和 `English` 原样返回。算法与 C ABI 回归在旧检查顺序下均先失败；修复后完整 Engine 单测 2185 项通过、33 项按既有条件忽略，31 项 golden 通过；host-api 单测 639 项通过、2 项忽略，两 crate 的 `--all-targets` Clippy 与 Rustfmt 通过。独立审查复跑聚焦算法和 ABI 回归通过。本次本地 quick 门禁通过，含工作区、Android、WASM、Android Java、macOS 原生宿主和共享 Apple 桥接编译；Linux 容器、MinGW 和 HarmonyOS 真打包因本机环境缺失跳过。该次大小写修复只调整纯算法的检查顺序，没有新增文件访问或宿主代码改动，因此当时未重新运行手机设备套件。

原功能接线验收时，Engine 全套 2156 项、31 项 golden 和新增 C ABI 专项通过，相关 crate 的 clippy 通过。Android 235 项 JVM 冒烟及 129 个设备套件源文件编译通过；功能接线时重编的原生 APK 在 API 28、35 的专用模拟器通过纠错示例、正确词与缩写、明确点原文、数字页标点和禁止建议／网址／邮箱／密码输入框验收。

iOS 的 16 项词边界与组字测试通过；系统加载的键盘扩展在模拟器真实编辑器中通过原文、唯一纠错、正确词不补全、空格、拒绝纠错、句号追加空格和手动首字母大写验收。没有安装到真机。

HarmonyOS 纯逻辑套件、OpenHarmony 原生交叉构建、`ohpm install` 后的 `hvigorw assembleHap --no-daemon` 通过。真打包顺带修复了原有九键双拼响应的内联对象类型，以及只读数组直接赋给视图状态的 ArkTS 类型错误。没有已连接的 HarmonyOS 设备，尚未验证其系统输入法入口和编辑器替换时序。

原功能接线的本地 `CARGO_PROFILE_DEV_DEBUG=0 MSIME_BUILD_JOBS=2 ANDROID_SDK_ROOT=… bash scripts/verify-local.sh --quick` 通过，覆盖 Windows 原生链接、macOS 和 Apple 共享桥接；Linux 因本机没有 Docker 跳过。`cargo fmt --all --check`、`git diff --check` 和 `pnpm run verify-notes` 通过。

## Consequences

有界高频前缀页会漏掉低频词，分词不具备完整语境语义。明确保留原文入口；当前词及编辑器必须在替换时重新核对，不能拿旧建议删除其他位置的文字。查询结果缓存只对固定的分代资源有效，切换资源目录时要替换整个缓存。

Android 普通英文当前词的一键清除复用本篇的词边界和编辑器重读规则，见[英文当前词的一键清除](2026-10-22-android-english-word-clear.md)；清除不会采用纠错建议，且会作废旧建议代次。

Android 的普通英文候选还追加词典前缀补全，见[Android 英文前缀补全](../bug-fix/2026-10-23-android-english-prefix-completions.md)。该展示拓展保留本篇的独立边界纠错查询，只有手动点选才采用补全。
