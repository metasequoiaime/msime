# Agent Note: 移动端英文保留原文并提供唯一纠错

Status: implemented

## Problem

#8119 要求手机英文输入保留原始按键，并提供连写分词、少键、多键、邻键纠错、固有大小写与撇号恢复。已有英文前缀补全不能纠错，也不能让空格默认提交纠错。

## Decision

纠错算法放在 Engine，宿主沿用普通英文直出和从编辑器读取当前词的路径。共享英文查询请求增加可选的 `correction: true`；缺省仍是原有补全，手机明确请求纠错才得到原文第一行和可选的唯一建议。实际用户文字不写日志、不学习、不落盘；缓存只持有固定词库的条目、两字母索引前缀和未命中片段的带随机种子的哈希，不保存按键原文。宿主在选词或空格、标点边界重新读取当前词并校验，再替换这一词，不维护跨输入框的影子原文。

算法使用现有英文词库的索引查询。完整单词精确匹配优先；否则对最多 32 字节做动态规划，全串最多两次编辑、最多六词。每个词的代价是 30 减去词频对数（对数封顶 22），30 约等于词库总频次的对数，使分词近似一元语言模型：多切出一个词必须换来足够常见的词。邻键替换、相邻对调和少按一键各计 8，多按一键计 12，以免 `haveaniceday` 把 `a` 当成 `nice` 的多余键。至少五个字母的目标词允许元音互换（`seperate`、`pleese`），至少七个字母的目标词允许两次编辑（`tommorow`），其余目标词只允许一次。

多词分词的每个片段必须是固定词形，或者是词频不低于一千万的小写词或至少四个字母、只有首字母大写的专名；不超过三个字母的片段门槛为两千五百万。全大写缩写（TNT、ESE）、首字母大写的短缩写（Sep）与 res、er、ate 这类碎片因此不会出现在分词里，单个字母只剩 `a` 与 `I`。整串只纠成一个词时不受这些门槛限制，`languge` 这类低频长词照常可达。编辑纠错的目标词至少三个字母，三字母目标必须是词频不低于一亿的小写词（the、you、and），首字母之后含大写的词条从不作为编辑目标。

候选词按两字母索引前缀分页，每页最多 128 条。每个起点固定查原样前两键、第二键漏按或与第三键对调、前两键对调和第二键的各个邻键这几页；这些页都没有可用匹配时，再查首键按到邻键或多按首键的前缀页；首键或第二键漏按各要 26 页，只在整串开头查，放到连写中间的每个起点会让一次查询读上百页，而词中间的漏键在连写里也难与前一个词的末尾区分。每个查询线程只保留最近一个固定资源目录、128 页轻量词条，以及合计最多 4096 条的整词查询结果（含未命中），满了整体清空；逐键输入时，前一键查过的子串不再访问 SQLite。不预载整份词库。词库缺失、输入超过纠错界限或无法解码时，仍返回原文。

网络缩写与固定词形有确定规则。受保护的缩写（omg、thx、pls、cya、ty、np、u、ur、asap、tmrw、idc 等）整词原样保留。固定词形只收去掉撇号后本身不是常用词的缩约形式，如 that's、there's、who's、haven't、won't、it'll、you'd、they'll、mustn't、would've；well、shell、hell、ill、id、its、lets、were 是常用词，不在其中。`wont` 虽在词库中，仍恢复为 `won't`。`I`、`Chinese`、`English` 的固有写法同样是固定规则。第一字母显式大写时建议也保留大写；不对句首额外大写。首字母之后还有显式大写时，整词只保留原文；这个检查先于固定词形恢复，以免 `IM`、`I'M`、`ENGLISH` 或 `eNglish` 被空格边界自动改成 `I'm`、`English`。

宿主接线的契约是：手机在空格边界使用纠错建议并追加 ASCII 空格；标点紧随词，随后补空格。点原文候选是本次明确拒绝纠错，下一次边界不再改写它。沿用现有英文候选开关，密码、网址、邮箱及禁止建议的输入框不自动纠错。九键数字组码仍按九键英文消歧处理。

拒绝纠错在当前词或外部编辑上下文变化时失效。iOS 额外比较可选文档标识，但系统不提供标识时仍允许本次拒绝生效，不能以标识必须存在为前提。Android 的数字页标点和字母页共用英文提交入口；HarmonyOS 在手机纠错模式下同步写入字母，让紧随其后的边界查询能读到最后一键。

Android 的 #9178 录屏显示普通英文输入和删除时工具栏反复闪动。每次新前缀先清空建议，空列表使界面短暂回到空闲工具栏，异步查询返回后又切回候选。现在查询排队前立即用当前原文作为唯一临时候选，收到共享引擎的结果后再替换；不把上一词的建议留给新前缀。代次、编辑器当前词与结果前缀校验仍负责丢弃过期答案。词边界、无建议输入框、模式切换与会话结束继续清空建议，原文行本身不推断纠错。

## 合并展示

共享查询另有可选的 `completions: true`，只能与 `correction: true` 同用，单独使用报请求错误。它给手机候选栏一份完整的展示列表，至多 `limit` 行：

- 有纠错时，列表只有原文与纠错两行，不附加补全。
- 没有纠错且原文本身已是完整的正确词时（词库精确命中、与固定词形大小写不论相同，或是受保护的缩写），列表只有原文。
- 其余情况原文后接至多 `limit - 1` 个前缀补全，按大小写不敏感去重。原文首字母大写时补全的首字母随之大写，其余照词库拼写；原文含撇号时只保留延续该拼法的补全。

响应比另外两种请求多一个 `corrected`，当且仅当第二行是纠错时为真；`limit` 为 1 时没有第二行，`corrected` 为假。不带 `completions` 的补全和纠错请求响应形状不变，宿主严格解析，不能在其中加字段。缺词库时与纠错请求相同：固定词形照常恢复，其余只有原文。三个手机宿主尚未改用这一模式。

## Alternatives considered

- 整份英文词库预载到 Trie：查询快且召回完整，但每个键盘进程长期保留数万词条与节点，iOS 扩展的内存预算不适合再增加无界常驻索引。先复用有界 SQLite 检索，真实词库检查召回和延迟。
- 将三个宿主的普通英文全部切换为专用英文组字：原文、候选和提交可以直接由会话控制，但要改变已有的光标、删除、输入框切换和 iOS 临时英文行为。现有补全已经从编辑器读取当前词，并对异步结果做代次与原文校验，复用它更容易守住边界。算法仍只有共享 Rust 一份，平台只负责读取、校验和替换。
- 固定词形规则优先于显式大小写：能让全大写输入也恢复撇号和语言名称的常用写法，但手机在空格边界自动采用唯一建议，会改写用户刻意输入的缩写或混合大小写；显式大小写保护应覆盖所有建议来源。只有首字母大写的 `Im`、`Youre` 仍可恢复为 `I'm`、`You're`。
- 只设一道分词片段的词频门槛、不提高每词代价：规则简单，但真实词频分不开 tomorrow（约 2100 万）与 res（约 1980 万），`a dress`、`hell I`、`go id` 这类全由正当词组成的切分也拦不住。现在门槛只排除碎片和缩写，正当词之间的取舍交给每词代价与编辑代价；`haveaniceday` 与 `helli` 两侧的约束只差不到一个对数单位，多按一键单独计价才同时成立。
- 整词缓存直接以字符串保存未命中：实现最直接，但未命中多是按键子串，第一次查询就包括整个当前词，会违背只缓存词库条目的约定。未命中改存带进程随机种子的 64 位哈希，误判为未命中的概率可以忽略。
- Android 查询期间保留上一前缀的建议：能稳定候选栏且无需提前产生一行，但它展示的是已经过期的词，必须另加禁用状态防止误选。当前原文已能从编辑器得到，直接显示它既符合共享查询的第一行契约，也避免旧词残留。

## Consequences

有界高频前缀页会漏掉低频词，分词只按一元词频，不具备语境语义：`have an ice day` 与 `have a nice day` 这类取舍只靠词库里没有 `an` 和固定的 `a` 词频成立。分词片段的词频门槛也会拦下 dad、sit、leg 这类真实短词，`ilovemydad` 之类连写不会切分，宁可保留原文。首个词之后的词若漏按首键或第二键，不再纠正。三字母目标只认词频不低于一亿的小写词，生僻缩写若不在保护列表里，仍可能被纠成常用三字母词。明确保留原文入口；当前词及编辑器必须在替换时重新核对，不能拿旧建议删除其他位置的文字。查询结果缓存只对固定的分代资源有效，切换资源目录时要替换整个缓存。

Android 普通英文当前词的一键清除复用本篇的词边界和编辑器重读规则，见[英文当前词的一键清除](2026-10-22-android-english-word-clear.md)；清除不会采用纠错建议，且会作废旧建议代次。

Android 的普通英文候选还追加词典前缀补全，见[Android 英文前缀补全](../bug-fix/2026-10-23-android-english-prefix-completions.md)。该展示拓展保留本篇的独立边界纠错查询，只有手动点选才采用补全。
