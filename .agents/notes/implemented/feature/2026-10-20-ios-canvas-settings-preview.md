# Agent Note: iOS 外部候选皮肤选择器绘制真实画布预览

Status: implemented

## Problem

iOS 的键盘候选条已支持 canvas，外部皮肤选择器下的明暗预览却只画安全回退配色，无法判断选中的九宫格、挂件和动画是否生效。主线程上的设置更新不应为此解码图片；旧模式的异步结果也不能覆盖新选择。

## Decision

选择器的三词预览复用 `CandidateCanvasHostView` 和后台资源解码，不复制九宫格或动画实现。每次偏好、明暗或页面资源重载以不可变请求启动后台加载；先解析安全配色，再按共享解析结果加载当前包，只有面板成功时才请求贴图配色。主线程仅接收当前代次，替换旧画布与样本文字。SwiftUI 释放预览视图时使在途结果失效，现有画布视图负责窗口、后台与减少动态效果生命周期。

页面重载提供独立资源代次，同名包被替换或删除后不能只靠皮肤 id 复用旧图。这里不改变键盘的皮肤开关、选择与保存规则。

## Historical audit

- [iOS 候选画布](../../implemented/feature/2026-10-19-ios-candidate-canvas.md)：部分重叠，复用现有渲染与预算，仅补选择器预览。
- [跨平台渲染边界](../../implemented/architecture/2026-10-13-cross-platform-candidate-rendering-boundaries.md)：保留；预览只在原生设置 App 中，不新增候选窗口。

## Alternatives considered

- **用 SwiftUI 单独画九宫格和动画**：能保留原预览的结构，但需再次维护切片、挂件层级与动画生命周期，因此复用 UIKit 产品组件。
- **在每次 SwiftUI 更新时同步加载**：代码量最少，也自动看到同名资源更新；图片解码和文件校验会阻塞设置页，因此采用资源代次和后台队列。

## Verification

iOS 27 专用模拟器执行 `CandidateSkinPreviewTests`、`CandidateCanvasTests` 与 `CandidatePaletteTests`，共 34 项、0 失败；仅既有的本机上游资源专项因未暂存而跳过。新增三项实际执行，覆盖九宫格像素、成功后贴图文字色、同名资源刷新与损坏回退、异步旧结果丢弃、动画预览离开窗口停播与销毁清层。三张明暗和替换后附件已导出，完成目测。首轮截图发现序号标签在栈中横向拉伸，现固定它的横向拥抱优先级；动态字号同时调整预览高度。最终工程只保留新增源文件的生成条目，避免带入生成器补出的无关构建预设，基于最终工程与序号布局再次复验，仍为 34 项、1 跳过、0 失败；修正后截图完成目测。原生 `MSIMEApp` Release 模拟器构建与 `verify-local.sh --quick` 均通过，quick 包含仓库契约、Rust workspace 和共享 Apple 桥接，其余平台按 iOS 改动范围跳过。最终笔记和差异检查通过。验证层级为模拟器里的生产预览组件及原生 App 编译，不等同于真机或完整设置页面导航验收。

## Consequences

选择器能显示真实 canvas，资源失败回到可读颜色。代价是设置页可同时保留两种模式的有界资源快照。通用六词候选预览卡仍是独立组件，本篇不宣称所有设置预览或全平台目标已完成。

## Risks

设置页同时显示两种模式时占用两份受预算限制的快照；加载失败、页面消失或快速换肤必须先撤旧图，避免显示与保存值不符。
