# Agent Note: Android 设备信息与一键复制

Status: implemented

## Problem

#5662：用户反馈问题时常常漏填机型、系统版本这些排错必需的信息，而且一个问题可能只在某个版本的 Android System WebView 上出现。应用里没有地方列出这些信息，更没法一键复制；「帮助与反馈」的「附带诊断信息」只随站内反馈提交，贴到 GitHub Issues 或 QQ 群时用不上。

## Decision

- 「关于」页新增「设备信息」组：应用版本（版本名、版本号、产品版本 id）、品牌、型号、系统版本（Android 版本与 API 级别）、系统构建（`Build.DISPLAY`）、处理器架构（`Build.SUPPORTED_ABIS`，首选在前）、屏幕分辨率（窗口最大尺寸的真实像素与 dpi）、存储空间（数据分区可用/总量）、运行内存、Android System WebView（`WebView.getCurrentWebViewPackage()` 的版本与提供方包名）、键盘是否已启用和是否为默认。组末「复制设备信息」把整段文本放进剪贴板；「帮助与反馈」的「其他渠道」里也有同一个复制按钮。
- 格式化与复制文本在纯 Java 的 `DeviceInfoReport`（JVM 冒烟覆盖），系统读取由 `core/DeviceInfoCollector` 统一提供：设置页先在主线程从 Activity 窗口量屏幕，键盘则从已附着视图的 Display 量真实像素，不向应用 Context 请求窗口服务；其余字段在各自宿主的后台工作线程读取。存储与内存用十进制单位，与系统设置的显示一致；读不到的项写「未知」。
- 只在用户点「复制」时进剪贴板，什么都不上传；不读账号、输入内容、已安装的其他应用或任何能标识设备的 id。站内反馈的诊断字段白名单（`FeedbackApi.DIAGNOSTIC_KEYS`）不变。

键盘功能菜单第二页提供「复制设备信息」（#8041），不跳设置页、不关闭菜单、不提交或清除组字。它复用同一份十一项白名单和文本格式，不依赖引擎就绪；使用既有偏好工作线程，完成后回主线程写剪贴板并显示键盘提示。重复点击只采纳最后一次结果，服务销毁后的回调不再写剪贴板。菜单仍为四列三行、两页。

## Alternatives considered

- **把这些字段并进站内反馈的「附带诊断信息」** — 一处收集、自动附带；但白名单是服务端定的，加字段要改服务端，而且贴到 GitHub Issues、群里的场景照样拿不到。
- **从键盘跳到反馈页复用按钮** — 不需要抽取采集器；但仍迫使用户离开正在反馈的编辑器，无法满足 #8041 的直接复制要求。
- **单独做一个「设备信息」详情页** — 和截图里的视频压缩应用一样有独立页面；但「关于」本来就显示版本，信息只有十来行，再加一层页面只是多点一次。

## Consequences

功能菜单沿用空闲态入口，组字时顶部改显示候选栏；本功能不增加组字中打开菜单的入口。设备回归验证已输入内容保持、菜单不跳转和复制后继续组字上屏，不把它称为组字中打开菜单的验证。

- **收益**：反馈时一次复制就带齐排错信息，WebView 版本问题有了对照。
- **代价**：「关于」页变长；厂商系统版本（如 OriginOS）没有统一的 API，只能靠「系统构建」间接看出。

## Verification

`DeviceInfoReportSmoke`、菜单分页及全部十六种工具栏去重组合由 `check-host.sh` 的 231 项 JVM 冒烟覆盖，设备测试源码也参与编译。原生完整 APK 构建通过。`CopyDeviceInfoDeviceSmoke` 在独立 API 28 与 API 35 模拟器中点击真实菜单、读取系统剪贴板，验证十一项白名单、应用版本与屏幕尺寸有效、不含合成输入内容、编辑器已有文字保留，并在返回键盘后继续拼音组字上屏。两个级别都按条目的无障碍描述「设备信息」找到磁贴，用网格的前后翻页动作翻到它所在的页再点，仍以实际剪贴板内容判定成功，不用调用采集器代替菜单验收。早先认为 API 28 的 UiAutomation 读不到菜单磁贴，改成按工具栏边界和网格位置盲点第二页某行某列；菜单每增减、重排一项这个位置就可能错，套件跟着红。2026-10-25 在 API 28 模拟器上逐节点刷新读出的树里有「更多工具」面板和全部磁贴（第二页的磁贴不可见、坐标在屏幕外），按描述查找加翻页在 API 28 和 35 上都通过，位置点击随之删除。API 35 的 `MoreToolsDeviceSmoke` 通过，回归入口、分页、开关、子页及返回；它先定位第一页，不假设前一个套件没有保留第二页页码。

新增复制用例纳入 `smoke.sh --core`，最低 API 也必须执行；独立 API 28 的安装、词库准备、核心输入、复制及剪贴板保存生命周期整套通过。合入最新 `develop` 后重建原生 APK，API 35 整套核心验收通过，API 28 重新绑定输入法后再次通过复制回归；报告既不含合成拼音，也不含编辑器已输入文字和原剪贴板占位文本。合并后的 quick 门禁与笔记校验通过；本次没有 Android 真机验收。

默认工具栏下，无结果的语音条目隐藏后，「设备信息」位于第二页第三行第一列；API 28 的触摸验收按这个位置点击。干净的 `develop` 提交 `ed50628aed` 安装包在旧坐标下同样失败，仅修正测试坐标后通过；该差异属于设备测试定位，复制白名单与实际剪贴板断言保持原样。翻页后额外等待 UiAutomation 界面空闲，避免主机负载高时动画延迟调度，固定 400 毫秒延时结束仍点中移动中的磁贴。

稀疏横拖可能丢失首次接手位移，独立缺陷及真实分发回归见[分页网格手势修复](../bug-fix/2026-10-19-android-paged-grid-intercept-delta.md)。复制白名单、原文保留和继续组字的验收断言保持原样。
