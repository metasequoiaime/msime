# Agent Note: 快捷短语混输默认落在首页末位

Status: implemented

## Problem

普通组字混入快捷短语时（宿主请求 `quick_phrase_candidates`，用户打开「快捷短语混输」），没有学习记录的整组短语追加在全部普通候选之后。#9702 实测：小鹤双拼 `zj`（zan）有 83 个普通候选，快捷短语「」排在第 84 位，每页 6 个时在第 14 页，等于看不见。选中一次之后调频把整组拉到首页第 5 格，此后每用一次再往前。默认位置远比学过一次的位置差，用户第一次根本找不到它，也就不会有第二次。

[macOS 普通候选接入快捷短语](2026-10-17-macos-quick-phrase-candidates.md) 把「追加项可能排在首屏之后」记成保持普通候选排序的取舍，[快捷短语混输与调频两个共享偏好](2026-10-22-quick-phrase-preferences.md) 加调频时沿用了「没有记录追加在末尾」。这两处取舍对编码少的短语无害，对 `zj` 这类高频单音节码就是功能失效。

## Decision

没有学习记录时（包括「快捷短语参与调频」关着、或词频调整整体关着），整组短语的默认槽位由宿主的每页候选数 `first_page_rows` 决定，落在首页尾部；有学习记录时照旧按 `quick_phrase_slots` 里学下来的槽位摆放，前移、后退和「最多退到首页末位」的规则都不变。

落位规则在 `default_quick_phrase_slot`（`crates/engine/src/ime/queries.rs`），口径和学习槽位相同，都是「组前面有几个计位候选」（`counts_toward_quick_phrase_slot`）：

- 记 `P = max(first_page_rows, 1)`，`N` 为普通候选里计位候选的个数，`Q` 为去重后的短语条数。
- `N < P`（普通候选不满一页）：整组照旧接在普通候选之后，不把任何普通候选挤到下一页。
- 否则首页让给短语的格子数 `k = max(min(Q, ⌊P/2⌋), 1)`，槽位为 `max(P - k, 1)`。首页至少留下 ⌈P/2⌉ 个普通候选，首选永远是普通候选；整组连在一起、组内顺序不变，放不下的几条接在下一页开头。
- 例：每页 5、6、9 个、只有一条短语时分别落在第 5、6、9 格；每页 6 个、三条短语时占第 4–6 格；每页 9 个、五条短语时占第 6–9 格，第五条在第二页第一格；每页 1 个时首页不让格子，整组紧跟首选（第二页第一格）。

页大小来自 host-api：`EngineOptions.first_page_rows = host_page_size(page_size_override 或 candidate_page_size)`，偏好变更重建选项时跟着变，和全拼补全词、英文首页席位用的是同一个值。K 模式（`Shift+K`）只列快捷短语，不经过这条路径。

目前请求 `quick_phrase_candidates` 的只有 macOS（`InputController.mm`）和 Linux 的两个宿主（`ClientEngine.cpp`、`FcitxEngine.cpp`）；Windows、iOS、Android、HarmonyOS 不声明这项能力，行为不变。

## Alternatives considered

- **对齐 Windows 旧行为，组固定在首位**：快捷短语最显眼，但每个与短语同码的普通输入都要多按一次才能上屏首选，打扰最大；Windows 出厂关掉混输正是因为这一点。首页末位让短语在第一屏可见，又不动首选。
- **只在首页末位放一条，其余短语接在全部普通候选之后**：首页只让一格，普通候选挤得最少；但同一组被拆成两段，学习槽位的「整组连在一起」语义就不成立了，选中第二条时组的位置也说不清。
- **在最终混排列表上按显示位置落位**：英文、云候选占位、联系人、固定位置这些行都在快捷短语插入之后才进列表，按最终位置算能保证短语一定在首页；但这些行各有自己的位置规则（固定位置、联系人置顶、单字过滤会删掉含汉字的短语），在最后再挪短语要和每一条规则重新协调，还会让默认落位和学习槽位用两套口径。默认落位和学习槽位共用「计位候选」口径，这些行把短语往后推的量与学过的槽位一样。
- **按候选总数比例或固定第 2 格落位**：与页大小无关的固定位置在每页 1–3 个的窄窗口里会挤掉首页大半，在每页 9 个时又离首选太近；按页大小算才是「首页最后」的本义。

## Consequences

- 收益：没学过的快捷短语第一次输入就在首页可见，默认位置与学过之后的位置一致（都在首页内），学过之后的规则一个字没改。
- 代价：普通候选满一页时，首页最后 `k` 个普通候选被挤到下一页开头；`N < P` 时不挤。
- 英文、emoji、云候选占位（`☁`，开着云候选时在第 2 格）、联系人和固定位置的行不计位，它们排在短语前面时短语会被推后同样的格数，最坏落到第二页开头；学习槽位一直有同样的近似。
- 旧版本在 Halve 或 Linear 调频下从末尾学出来的槽位可能在首页之外，这些记录照旧生效，不做迁移；默认的 Promote 从末尾学出来的槽位是 4，在首页内。
- 验证：`crates/engine/src/session/tests.rs` 用合成的小鹤 `zj` 词库（83 个普通候选）覆盖每页 5、6、9 个的默认落位、学习前移与后退封顶、多条短语、不满一页和 K 模式，前四类在改动前失败。

快捷短语的 `${cursor}` 展开与上屏后缀契约见[光标定位笔记](../../implemented/feature/2026-10-31-quick-phrase-cursor.md)；不改变本文原有决定。
