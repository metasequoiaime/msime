# Agent Note: Windows 界面采用 macOS 的分组与选中样式

Status: implemented

## Problem

Windows 设置窗口把每一项设置画成独立的高卡片，侧栏和页边距挤占正文；候选窗使用蓝色文字与竖线标记选中。macOS 使用紧凑的分组卡片和实心绿色选中底。两边功能接近，视觉层级却不同，用户要求 Windows 参考 macOS 改版。本篇接管[Windows 候选窗口补齐 macOS](2026-10-10-windows-candidate-window-mac-parity.md)中的默认外观，候选内容及交互约定继续沿用。设置窗口的初始尺寸和侧栏选中样式后来由[外壳配色与侧栏对齐 macOS](2026-10-20-windows-settings-mac-shell.md)接管：窗口改为 1000 × 780，侧栏选中改为中性底色。分组与行的具体尺寸、正文边距、页面标题和标题栏返回按钮后来由[行与组密度对齐 macOS](2026-10-20-windows-settings-mac-density.md)接管。

## Decision

Windows 保留 WinUI 3 设置宿主与 Direct2D 输入浮层，以 macOS 的 `SettingsLayout.h`、`AppearancePreferences.mm`、`NativeCandidateTokens` 为布局、信息结构和默认颜色依据。窗口采用独立的侧栏搜索与内容工具栏，取消重复搜索入口；18 页均有说明。窗口初始为 1000 × 760 DIP，最小为 800 × 560 DIP，随初始系统 DPI 换算；使用工程已固定的 Windows App SDK 1.7 的 `OverlappedPresenter.PreferredMinimumWidth`／`PreferredMinimumHeight`，避免窗口缩到侧栏与正文无法操作。宽度边界参照 macOS 的 `contentMinSize`，高度包含 Windows 标题栏空间。

账号页参照 macOS 的紧凑身份卡与登录分组：52 DIP 头像与说明并排，登录方式使用标准设置行，验证码表单沿用标签与控件分列，去掉大幅居中欢迎区、固定 300 DIP 表单和嵌套卡片。已登录资料卡、设置同步也不再套第二层卡片；同步操作纵排，避免窄窗挤出正文。

公共下拉、分段控件与滑块数值区采用紧凑字号和宽度；复选框复用自适应网格，标签可换行，行高由内容决定。导航的 28 DIP 行高同时调整模板实际读取的 `NavigationViewItemOnLeftMinHeight` 为 24 DIP，余下 4 DIP 留给模板上下边距，避免内层默认 36 DIP 裁掉标签。滑块工厂明确返回 `Grid`，屏幕键盘拖动预览所持有的滑块从这个容器取得；容器布局改变必须同步直接读取子项的调用方，不能仍向旧 `StackPanel` 强转。

输入设置拆为「输入方案」「输入习惯」「按键」：输入方式逐项单选，专属选项与辅助码仅显示当前方案；选词与翻页归按键，混输、输出、快捷模式与调频归输入习惯。输入习惯优先展示标点，按键优先展示模式切换，再列选词与翻页。路由 id 和持久化字段保持稳定，搜索索引由所属页面重新登记，方案专属项只索引当前可见选项，切换后的偏好修订使索引重建（后来由[打字三页照 macOS 分标签](2026-10-20-windows-settings-typing-mac-parity.md)取代：这些内容归回「输入」页的六个页内标签，选词与翻页在「选词与翻页」标签，快捷键和标点与翻译两页各自分标签）。

皮肤网格中的缩略图用真实候选调色板绘制选中底和前景色，网格随正文宽度重排列并等分填满，不重建按钮以保留焦点。卡片下方分行展示名称、明暗类型或使用状态，避免窄卡片文字重叠。主题选择在前，完整实时预览在后，首屏即可选择主题。实时候选预览仅在皮肤和候选窗口页提供，有独立舞台及滚动视口，横向长候选不会撑出页面。

候选窗口按 macOS 分为「布局」「字体大小」「窗口样式」「预编辑」四个标签，字体与自定义候选配色从皮肤页移入相应标签；这部分取代[原生候选字体设置](2026-10-11-windows-settings-candidate-fonts.md)为了保持旧页面组织而暂留主题页的安排，其字体目录、校验与回退契约继续沿用。搜索索引遍历全部标签并保存条目归属，打开结果时先切换标签；标签选择只保存在窗口内，不写偏好。切换标签时释放旧字体控件引用，字体列表异步回调不会更新离开的控件。候选预览按原生 `CandidateFontSettings.h` 的英文字体、已保存回退列表顺序逐字回退，并使用保存的拼音字号，字号／字体／配色变更即时更新。参照 macOS 的公共预览控件，预览提供示例文字和独立明暗选择；示例按空白分词，短列表循环填满当前页，空白输入恢复内置示例。示例最多 256 个 UTF-16 单元，只存在本次窗口内，切换标签与页面保留；两项预览操作均不写偏好。

状态栏页有独立效果预览，复用原生 `ToolbarLayout.h` 的真实几何和 `ToolbarIcons.h` 的按钮图标，按勾选项目、缩放和图标大小绘制并显示 DIP 尺寸；调色板经过真实工具栏使用的 `toolbar_palette`，圆角和随缩放变化的边框宽度取这个结果，避免误用候选窗的几何。边框叠在固定尺寸的画布上，保持原生内部描边的占位关系，外框不会在标注尺寸之外额外增加两侧边宽；图标坐标不因边框而平移。语言按钮根据已保存方案与默认输入状态调用原生图标策略，双拼、五笔及其他语言不再统一画成「中」；文案明确这是默认状态预览，不读取或假定当前输入会话的 Caps Lock 与临时切换状态。长工具栏只在预览舞台内横向滚动。组件复选框与预览共用顺序表，去掉与实际可关闭状态冲突的「始终显示」伪选项。

词库结果按 macOS 的编码、词条、权重分列，与操作列共用表头和列宽，长文本可换行。剪贴板历史保留正文与复制按钮，发送、固定和删除收进「更多操作」菜单，参照 macOS 将次要操作收进菜单的密度，避免四个按钮挤掉记录（后来由[页内标签框架与键盘手写、剪贴板两页](2026-10-20-windows-settings-page-tabs.md)取代：宽行照 macOS 直接排出四个按钮，窄行才收进菜单）；历史和统计去掉嵌套卡片。统计概览沿用自适应网格，最多三列，窄窗口排成两列。统计的六个内容分类保留可直接点选的页内标签，不因通用分段控件的选项数阈值退化成下拉框。

设置以功能组为卡片，标签与控件分列，窄行把控件移到标签下方；搜索保留设置项检索。候选窗、工具栏和托盘共用绿色强调色与浅深色表面，用户主题及皮肤覆盖继续优先。WinUI 复选框、单选项、滑块和链接覆盖各自模板实际查找的资源键，含悬停和按下状态；高对比度时保留系统控件资源。仅覆盖全局 `SystemAccentColor` 和 `AccentFillColorDefaultBrush` 无法重算模板已经解析的静态别名，旧运行截图中的复选框与滑块因此仍为系统蓝色。资源键依据 [WinUI 1.7 固定源码](https://github.com/microsoft/microsoft-ui-xaml/tree/a37e4e2c44582980aad0f9d91b11230a119cffac/src/controls/dev/CommonStyles)，不复制控件模板。

自定义主题改变选中底但没有指定选中文字时，在白色与深灰色中选实际对比度较高的前景；编号沿用同一前景并保持既定透明度。固定亮度阈值 `0.45` 会在 `#FF8000`、`#999999` 等中等亮度底色上误选白字，因此不再使用。显式选中前景、未改变的原生默认值和半透明底色沿用普通行前景的规则保持优先。

## Alternatives considered

- 保留 HWND 捕获为硬前提：能够在移动前判断传统 Win32 控件是否收到了按下；但 WinUI island 使用自身指针捕获状态，前提会在真正移动前挡住测试。改为核对系统按钮状态、排队注入结果，以及实际的按住／松开数值，不用固定睡眠猜测控件处理时间。
- 数值回调直接强持有标签：改动更小并能保留创建时的投影对象；本次选择从事件源查询当前兄弟控件，使引用只活到回调结束，并沿用已有容器结构契约，避免额外的 UI 持有关系。

- **让 Windows 承载共享 React 设置页** — 能直接共享页面实现，但替换原生宿主会影响已有账号、社区及文件对话框路径，超出视觉改版需要；保留原生宿主并调整构件。
- **只修改颜色** — 风险小，但独立大卡片、宽侧栏和密度仍旧不一致，不能满足布局改版。

## Consequences

字体预览使用 [WinUI `FontFamily` 支持的回退列表](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.media.fontfamily?view=windows-app-sdk-1.7)，避免示例中的拉丁字符绕过已设定的英文字体。统一基础构件会覆盖全部设置页，也要求检查特殊表单、搜索定位和窄窗口。字体与标题栏仍采用 Windows 原生能力。最小尺寸使用 [Windows App SDK 的窗口尺寸接口](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.windowing.overlappedpresenter.preferredminimumwidth?view=windows-app-sdk-1.7)，不另设 Win32 子类窗口过程。MinGW 不编译 WinUI 3，必须独立核实设置工程的编译与运行证据。
