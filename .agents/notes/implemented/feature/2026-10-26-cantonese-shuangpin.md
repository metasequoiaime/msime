# Agent Note: 粤语双拼独立键位规则

Status: implemented

## Problem

issue #9799 提议为现有粤拼方案增加粤语双拼。报告附带的参考仓库没有许可证声明，不能直接复制其中的 schema、映射表或词表；现有引擎已经有受许可的 `msime-cantonese.db` 和粤拼音节库存，可以作为候选边界。

## Decision

依据公开的粤拼声母和韵母分类，独立实现从无声调粤拼音节到两键码的规则：普通声母同键，`gw`、`kw`、`ng`、`j` 分别映射到 `i`、`u`、`v`、`y`，零声母使用 `o`；韵母按固定的 26 个字母和 `;` 键分组（包括 `ek` 与 `it` 共用 `t`）。反向解析只在已加载的粤拼音节库存中枚举，按字节序稳定排序，不携带任何上游词表或 schema 文件。

规则模型已接入 `CantoneseScheme`：当用户输入的前两个字符形成库存中不存在的双拼码时，会话进入双拼解释；后续每两个字符按双拼码展开。反向展开最多保留 64 个组合，只使用已加载库存并按字节序稳定排序。候选查询对每个展开读音复用原有粤拼查找，再把候选覆盖范围映射回两键码；退格、候选选择和原始粤拼输入继续走原有路径。

双拼输入的预编辑显示为两键一组（例如 `nz hb`），普通粤拼仍优先于同形双拼码；这避免把现有合法粤拼音节静默改成另一种解释。双拼模式接受 `;` 作为韵母键，并保留现有粤拼的撇号边界规则。

## Alternatives considered

- **直接复制 issue 附件仓库**：实现最快，但仓库没有许可证，无法证明可再分发。
- **把双拼码当作普通粤拼缩写交给现有分段器**：不需要新状态，但双拼码与粤拼音节边界不一一对应，无法在候选查询时恢复实际音节。
- **复制完整粤拼词表并生成新数据库**：候选质量可控，但重复已有受许可数据库并扩大资源包和维护面，因此先复用现有库存。

## Consequences

规则模型不包含参考仓库文件或其逐字数据，候选仍来自已有受许可粤拼数据库。一个双拼码可能对应多个粤拼音节，组合展开会增加查询成本；64 个组合上限保证单次查询有界。自动识别依赖首码不是合法单个粤拼音节，同形码会继续按普通粤拼处理。

## Verification

- `cargo test -p msime-engine cantonese:: --lib`：38 项通过，覆盖规则编码、库存边界、双拼候选展开、撇号边界、宿主重建和既有粤拼回归；另有会话层测试验证双拼候选与 `;` 韵母键路由。
- 尚未接入各平台的独立方案选择项，也未完成 Android、iOS、macOS、Windows、Linux、HarmonyOS 的真实键盘验收；这些是后续接入工作的缺口。
