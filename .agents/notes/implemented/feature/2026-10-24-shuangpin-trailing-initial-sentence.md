# Agent Note: 双拼末尾声母参与整句补全

Status: implemented

## Problem

双拼的完整前缀可以组词，但末尾只输入声母时，共享整句合并入口拒绝所有不完整音节。因此合成输入 `nihckejigsj` 只能退回 `你好科技工`，不会把末尾的 `j` 与前面的 `gong` 一起查成 `工具` 再参与整句评分。

## Decision

仅对双拼中「前面音节完整、最后一个音节为声母」开放补全。跨度查询把末尾声母展开为有限的合法完整音节，复用已有精确批量查询，每个跨度仍受现有行数上限约束。词边携带词典中的完整读音；候选消耗实际输入的双拼按键，包括末尾的单键，不消耗未输入的韵母。

复用词网格解码、搭配打分和候选合并，不改变全拼等其他方案的完整音节门槛，不把中间声母或错码解释成任意读音。没有补全路径时保留原有完整前缀回退。句中辅助码约束使用同样的跨度查询，在束搜索前过滤；真正命中的末尾辅助码保持优先。

末尾声母与词典音节的声母严格相同，单字母 `z/c/s` 不匹配 `zh/ch/sh`。完整音节仍精确匹配，`ji` 不扩展成 `jing`。批量 SQL 的全局 `LIMIT` 维持原跨度行数预算，溢出词表也只匹配同音节数的完整键。补全整句不经过拼音纠错，不把末音节预测标成错字修正。

## Alternatives considered

- **逐个枚举末音节后分别解整句**：不需要扩展跨度查询，但同一前缀会重复建图和解码多次。只把枚举用于精确跨度查询，让所有韵母在同一词格中竞争。
- **直接把最后声母当成完整读音**：容易复用现有入口，但会污染候选标准读音和学习记录，因此词边必须使用精确词典行的完整键。
- **让所有方案默认接受任意简拼整句**：覆盖面更广，但会改变全拼和中间简拼语义，超出本次末尾单音节补全的范围。

## Verification

合成用例在修复前明确失败：`nihckejigsj` 的首选是 `你好科技工`，修复后是 `你好科技工具`，同时保留完整前缀作为备选。冷、热缓存及手动分隔符均覆盖。

四种双拼方案均覆盖：选中末尾预测后，按完整读音学习并消耗全部实际输入按键。跨度单测覆盖行数限制、完整音节不扩展、声母平翘舌、ü 别名、中间简拼拒绝和溢出桶音节数。

实际发布词库上的隔离会话逐键探测：完整输入与少最后一个韵母键的输入均产生相同的 8 字首选，整段逐键输入分别耗时 35 ms 与 29 ms；不使用个人词库、不记录反馈原文。这是共享引擎会话证据，不等于系统编辑器验收。

300 个合成脚本中只有 3 个因新增预测候选改变快照：`ri_microsoft_semicolon_editing`、`sp_xiaohe_delimited_no_helpcode`、`sp_xiaohe_trailing_helpcode`。仅更新这 3 份预期；辅助码命中行仍领先，光标编辑、前缀和非双拼行为不改。

- `cargo test --locked -p msime-engine`：2547 项单测与 31 项 golden 通过，56 项忽略。
- `cargo clippy --locked -p msime-engine --all-targets -- -D warnings`、`cargo fmt --all`、`pnpm run verify-notes`、`git diff --check`：通过。
- `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer bash scripts/verify-local.sh --quick`：仍失败于上一次已复现的 `client-core` 测试编译错误和 Android 文档注释 `-Werror`；完整 Xcode 环境下 Swift 阶段通过。不修改这些无关代码。

## Consequences

末尾声母不再导致整句预测停在前一个音节，前缀回退仍可选。未完成声母有多个韵母，词格按正常词频和搭配竞争；不保证任意句子都符合用户本意，不为反馈词组硬编码。

代价是冷查询的末尾跨度需要生成有限的完整键集合并执行批量精确查找；一次查询只解一张图，原有候选缓存和每跨度行数预算不变。真实辅助码开关和出厂默认值不变。
