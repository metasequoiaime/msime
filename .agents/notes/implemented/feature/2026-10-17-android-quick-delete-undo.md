# Agent Note: Android 快速删除后下滑撤回

Status: implemented

## Problem

#8325：快速清除文本之后不能恢复。用户要求长按删除键后向下滑动才触发撤回，未选中时提示为灰色，选中后才显示强调色背景。[原快速删除设计](2026-10-08-android-backspace-quick-delete.md) 刻意不保存内容，这一处取舍由本篇取代；其连删速度、上滑阈值及短按即删仍成立。

## Decision

#9324 的[同次按压左右滑动](2026-10-23-android-backspace-scrub.md)补充逐步删除与恢复；水平激活和原有上下滑阶段互斥，原有快速删除及其跨按压撤回规则保留。

- `QuickDeleteUndo.Capture` 收集快速清除明确接受删除的片段，按原顺序恢复，包含快速清除当时的选区。容量为 65,536 个 UTF-16 单元（至多 128 KiB 文本负载），给[共享的 Binder 事务缓冲](https://developer.android.com/reference/android/os/TransactionTooLargeException)留出余量；超限放弃整份备份，不提供残缺撤回。
- 备份只存在当前 `InputConnection` 的内存，最多 60 秒。密码、禁止学习和无痕输入框不保存。结束输入、切换输入框、普通文字输入或删除、上下文不符时释放；不写剪贴板、日志、统计或磁盘。
- 删除完成后记录绝对折叠光标、光标两侧各 64 单元及连接身份。撤回前重新读取核对。位置取 `getExtractedText` 的 `startOffset + selectionStart`，读取失败、选区未折叠、实际删除位移不符均不提供撤回。清除本身仍兼容不支持读取位置的编辑器。分段删除的中间选区回报可能晚于最终备份到达；收到不同位置的回报时重新读取真实编辑器核对，避免旧回声误删备份，同时仍拒绝用户实际移动后的位置。
- 有可用备份时，删除键短按改为松手时删除，长按 420 ms 后显示「下滑撤回」：未待命时固定浅灰背景、灰色细边和深灰文字（#9013），让提示在各种键盘皮肤上都有独立轮廓。这次按压不先删字、不连删；下滑到键下沿外 16 dp 待命并显示强调色背景，滑回取消待命。待命松手恢复一次，`ACTION_CANCEL` 不恢复。备份不存在时保持原上滑清除和加速连删。
- 撤回直接写回原文，不经过候选选择、学习、全角转换或输入统计；写入采用批量开始、提交、批量结束、回读的顺序；跨进程返回成功可能只表示请求已投递，位置和上下文完全未变时仍保留备份允许重试，发生写入后消费备份。编辑器自行改写或过滤写入结果时以编辑器为准，不再次盲目插入。
- 普通删除按下即删的既有行为保留；上滑快速清除之前已经通过短按或连删删掉的字符不属于该次快速清除备份。

## Alternatives considered

- **使用系统撤销或剪贴板保存**：编辑器可以维护完整撤销栈，剪贴板也已有管理界面；但并非所有 Android 编辑器提供撤销，剪贴板会延长内容寿命并可能跨设备同步，与本次只恢复快速清除的范围不符。
- **按下时就照常删除，再下滑恢复备份**：短按响应时机完全不变；但第二次按下可能删掉光标后的原选区或继续改变恢复位置，长按阶段也会破坏待恢复上下文。有备份时延迟短按到松手，避免撤回手势产生新删除。
- **保存不限量完整编辑器文本**：恢复状态最简单；但自定义编辑器可能只提供短读，大文本带来不受控内存和隐私负担。保留有界快速删除片段，其他文本仅留短上下文。
- **使用渐变背景和边框突出撤回提示**：在纯色皮肤上辨识度高；但多色键盘仍可能与渐变混在一起，也不容易区分灰色未待命与强调色待命。固定灰底、灰边与深灰文字让未待命提示有稳定对比，待命继续使用皮肤强调色。

## Consequences

- 快速删除有一次局部撤回，并通过长按、方向阈值和取消路径降低误触。原有无备份删除不增加持久状态。
- 有备份的短按延迟到松手；上下文读取不可靠或大文本超限时不提供撤回。底排删除键下方空间较少，提示框夹在键区内，手势阈值仍以实际键下沿计算。
- 64 单元上下文和绝对光标可以排除常见位置变化，但无法识别应用在相同位置完成一次内容完全相同的替换；Android 没有通用文档修订接口。
