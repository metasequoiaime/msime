# Agent Note: Android 数字层中英文标点切换

Status: implemented

## Problem

Android 123 / #+= 层的标点会跟随「中文标点」状态显示中文或 ASCII，但切换入口藏在「更多」面板。用户从数字层打数字和符号时，必须先退回字母层或打开工具面板，才能切换中英文标点。原先的数字行决定曾因数字行减少切层需要而不改 123 层；数字行只解决字母层打数字，不能解决已经打开数字层时的标点切换。

## Decision

123 和 #+= 层的底行在表情 / 符号入口旁增加一个独立的标点切换键：当前为中文标点时显示「中标」，按下切换到英文标点；当前为英文标点时显示「英标」，按下切换到中文标点。键的无障碍描述明确说出目标状态，数字层和扩展符号层都提供同一个入口。表情和符号入口占用同一位置，新增标点键从空格键宽度中让出空间，整行总宽度不变。数字页在顶部提供表情时改用符号键，关闭顶部入口时恢复表情，见[数字页入口去重](2026-10-17-mobile-number-layer-emoji-entry.md)。

切换复用现有 `toggleChinesePunctuation()`，因此会同时更新 Engine 会话、123 / #+= 的标点键面以及字母角标；状态仍是当前输入会话的状态，下一次会话的默认值继续由共享「中文标点」设置提供。

## Alternatives considered

- 继续只放在「更多 → 中文标点」：实现不改，但用户在数字层打符号时仍要离开当前键面，不能满足入口就地可用的需求。
- 用表情键或符号键替换新入口：可以不压缩空格，但会把已有的表情或符号入口藏起来，用户需要再绕到工具栏或面板。
- 把中英文标点合并进底行的「中/英」语言键：语言切换和标点切换是两个状态，合并后按键动作不可预测，也无法在专用英文或其他语言方案下保持原有语言轮换语义。
- 只在 123 层提供、#+= 层不提供：切换后用户经常继续留在扩展符号层，状态入口会再次消失；两层共用同一个位置和动作更容易理解。

## Consequences

数字和扩展符号键面都能直接切换中英文标点，表情或符号入口按工具栏状态显示，键盘总宽度不变。空格键比原来窄约 1.05 个键宽份额，但仍保持明显宽于功能键。该入口只改变当前会话，和工具面板里的「中文标点」状态保持同步；字母层、底行逗号句号和字母角标也会一起刷新。九键、注音九键、笔画和手写等不使用这套数字设计层的键面不新增这个键。

设备验收覆盖 14 键借用的 123 层：中文标点下显示「中标」和「。」；切换后显示「英标」和「.」；再切回中文后恢复。
