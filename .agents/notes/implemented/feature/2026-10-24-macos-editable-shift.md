# Agent Note: macOS 单按 Shift 的可编辑焦点限制

Status: implemented

## Problem

#9532 希望焦点在空文本框时也能切换中英文，而选中只读文本或用 Shift 多选时不改变输入模式。IMK 控制器活着或持有客户端不代表当前焦点可编辑；`selectedRange` 在不支持 TSMDocumentAccess 的正常客户端里也会返回 `NSNotFound`。

## Decision

共享偏好新增 `keybindings.switch_language_shift_requires_editable`，默认关闭，仅 macOS 消费。共享 React 设置页说明需给水杉输入法辅助功能权限，未授权或无法确认焦点时不切换，不在按键处理期间弹权限请求。

启用后，只在单按 Shift 的按下和松开边沿通过只读、有超时的 AX 查询确认前台应用与 IMK 客户端一致、焦点元素属于文本控件且值可写；两次须是同一元素和进程。不读取文本、选区内容或记录应用信息。其他键、修饰键、鼠标操作和生命周期切换取消本轮，事件照常交给应用。其他模式切换快捷键不受限制。

## Existing notes audit

[Shift+Space 打断与漏释放](../../implemented/bug-fix/2026-10-23-macos-shift-space-after-chord.md)、[热键身份](../../implemented/bug-fix/2026-10-23-toggle-hotkey-layout-identity.md)、[Caps Lock](../../implemented/feature/2026-10-11-caps-lock-language-switch.md) 部分重叠：本项只增加单按 Shift 的门禁，不翻转这些规则。[状态项](../../implemented/feature/2026-10-12-macos-input-mode-status-item.md) 部分重叠：同样不能把 IMK 激活当作文本焦点。没有完全吸收或过时提案。

## Alternatives considered

仅用 IMK 状态无需新权限，改动也小；但 IMK 公共接口没有可靠的可编辑属性，范围查询失败也不代表只读，无法满足空框和只读文本两端的要求。

仅按 AX 文本角色放行能覆盖更多应用，包括不实现可写值的终端；但只读文本也可能使用同一角色，因此遇到未知实现时拒绝切换。用户已接受这个兼容边界。

## Consequences

缺字段默认关闭；macOS 设置页说明辅助功能权限，其他平台不显示。同一生产头文件的跨进程探针已验证空文本框允许、只读文本和按钮拒绝；这不是产品输入法验收。独立门禁测试覆盖捕获失败、焦点/进程改变、鼠标取消后另一侧 Shift、不带限制的旧行为和 Control。真实控制器专项接入 CTest，使用系统边界替身，不需要 CI 辅助功能授权。共享偏好通过独立集成测试验证缺省值、JSON 往返和实际存储重载；已有库内单测的初始化/所有权编译错误由 #9531 处理，不修改或豁免它们。UI 31 项及前端构建通过，基点缺少新开关的两个测试失败。

AX 有跨进程开销，每条消息使用 20 毫秒超时，只在 Shift 两个边沿查询；不支持可写值的应用会被保守拒绝，权限撤回也拒绝。两次查询校验焦点身份，鼠标操作和其他按键取消；鼠标全局计数还校验监视回调迟到的事件，临时监视器最多保留半秒；期间发生又恢复的纯程序焦点变化没有持续 AX 观察器覆盖。输入法切换、客户端接管和会话重建会清理门禁及临时鼠标监视器。

本机磁盘不足 50 GiB，只编译小型独立测试并检查控制器语法，不新增完整宿主构建树。Windows 验证机的完整 quick 退出 1，18 个失败阶段及 30 个可移植失败文件与上一轮相同；macOS 构建在该机器跳过。原生宿主链接/控制器 CTest 与真实输入法验收分别记录；探针和共享界面单测不能替代真实输入法验收。
