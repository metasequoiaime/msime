# Agent Note: Android 九键符号栏改为可视化编辑

Status: implemented

## Problem

「键盘 › 布局 › 九键左侧符号」和「九键数字键盘左侧符号」点击后直接打开一个输入框，要求用户用空格拼出整张符号表。这个界面把顺序、删除和添加混成一串配置文本，用户无法直观看到每个符号在键盘上的位置。

## Decision

两项设置都打开 `NineKeySidebarSheet` 可视化编辑面板。面板逐项显示当前符号，使用上移、下移和删除操作调整草稿；「恢复默认符号」恢复对应键面的默认表；「添加自定义符号」一次添加一个经过同一解析规则校验的符号；「保存」才把规范化后的整张表写入原有本地设置。面板关闭或取消不会写入草稿。原来的空值回退、最多 30 项、单项最多 4 个码位和本机存储契约保持不变。

旧的整串 `InputDialog` 方案记录在[九键左侧符号栏、数字键面与滑动出数字](../../implemented/feature/2026-10-08-android-nine-key-number-pad.md)，本篇取代它的编辑交互，不改变键盘运行时的符号表协议。

## Alternatives considered

- 继续保留整串输入框：实现最小，也能表达任意符号和顺序；但用户需要记住空格分隔格式，无法直接理解当前键位排列，正是这次反馈的问题。
- 只提供固定符号的多选开关：比输入框直观，但会丢掉已有的自定义短串能力（例如 `……` 或 `:-)`），也无法表达任意顺序；因此保留单个符号添加入口，把自由输入降到明确的次级动作。
- 每次调整立即写入本地设置：交互更短，但上下移动多次时容易留下半成品，取消也无法撤销；采用草稿到保存的边界。

## Verification

Gradle `compileFullDebugJavaWithJavac`、Android 主机门禁（248 项 JVM 冒烟、151 项设备套件源码编译）和 `git diff --check` 通过；随后构建签名 APK，安装到 Android 设备并打开键盘设置页，确认两项符号栏入口打开的是逐项编辑面板，不再直接显示整串文本输入框。

## Consequences

用户可以直接看到和调整符号顺序，删除和恢复默认不需要编辑格式字符串；添加完全自定义的短串仍需进入一次单项输入对话框。面板新增一层草稿状态和保存动作，设置写入仍复用原有 `KeyboardSheets.saveLocal`，键盘端不需要改动。
