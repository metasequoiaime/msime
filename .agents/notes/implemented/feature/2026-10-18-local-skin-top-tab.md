# Agent Note: 本地皮肤独立为主题页顶部标签

Status: implemented

## Problem

桌面主题页将内置主题和本地皮肤包放在同一条轮播里，导入目录也混在主题配置后面。用户要求本地皮肤成为顶部标签，与候选窗口的功能分类保持一致。

## Decision

桌面主题页提供「主题」「本地皮肤」「社区皮肤」三个顶部标签，缺少社区客户端时只显示前两个。主题标签保留明暗、内置主题和自定义配色；本地皮肤标签承载皮肤包、当前明暗槽位、导入目录、刷新和发布结果；社区标签继续使用原有图库。本地包与内置主题各自轮播，切换保留挂载和草稿，选择只属于窗口状态。手机继续使用原有布局与分类。

内置主题与本地包分成两个入口的决定由[本地皮肤统一选择](../simplification/2026-10-18-local-skins-unified.md)取代；共享标签的键盘导航、面板保留和社区安装后的跳转继续使用。

## 历史审计

- [主题页精简](../../implemented/simplification/2026-10-16-macos-appearance-settings-prune.md)部分重叠：保留能力过滤和配色折叠，只拆分桌面本地皮肤。
- [社区视图状态](../../implemented/simplification/2026-10-17-settings-community-views.md)部分重叠：扩展桌面分类，并保持手机分类和插件覆盖契约。
- [手机皮肤顶部标签](../../implemented/feature/2026-10-16-mobile-skin-page-top-tabs.md)无改动：手机的内置、我的、社区布局维持原样。

## Alternatives considered

- **只把「我的皮肤」改名为「本地皮肤」**：改动最小，但内置主题和本地包仍混在同一轮播，不能形成独立入口。
- **在皮肤页内再套一组标签**：无需改变外壳，却会与现有社区标签形成两层导航；统一为同一层三个分类更直接。

## Consequences

桌面内置主题与本地皮肤各有入口，标签切换不保存偏好，保持草稿与卡片预览；社区安装后的「去启用」直接打开本地皮肤。本地目录为空时只显示现有目录说明，不渲染空轮播。没有已选包时用 `-1` 表示未选中，避免目录新增包改变默认第一张的标识、打断正在看的卡片。

代价是查看内置主题与本地包需要切换标签。手机继续沿用原布局；皮肤包的明暗槽位、导入与刷新接口不变。桌面设置外壳的皮肤状态与插件状态各自保留类型边界。

## Verification

相关回归覆盖键盘与 ARIA 导航、滚动复位、预览状态保留、启用后的双槽位保存、社区安装后的跳转、目录重扫保留卡片以及手机原布局。类型检查、构建、格式、lint、笔记与本地 quick 门禁在提交前执行；完整 macOS 安装包在本机验收。
