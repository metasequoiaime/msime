# Agent Note: 十八键全拼共用字母归组引擎

Status: implemented

## Problem

#8936 请求 Windows 的十八键全拼以扩大字母触摸区域。现有共享屏幕键盘只注入确定虚拟键，不能把双字母键直接当成首字母输入。Windows 的 TSF 与 Server 各持有同源会话，面板不能另建组词状态代替二者。

## Decision

十八键全拼按三排 `Q WE RT Y U IO P`、`A SD FG H JK L`、`Z XC V BN M` 归组。复用引擎现有的多义全拼网格、读音选择、学习和候选；组码入口必须显式区别于实体键盘的确定字母。实体键盘、现有默认布局、默认方案及快捷键保持原样。

增加 `KeyGrid::EighteenKey` 与独立 `eighteen_key` 视图名，C ABI 布局编号为 4。[Android 十八键双拼](2026-10-24-android-eighteen-key-shuangpin.md)共用字母分组，追加编号 `5`，不改变全拼编号 `4` 的含义；两种方案错误选用对方编号时，会话保持原状。十八键组码不能原样上屏；回车与既有十四键一样确认高亮候选。宿主切换网格必须等组字结束，不能丢弃现有组合。

Windows 的组字与上屏仍归 TSF 与 Server 会话所有。本切片只实现共享引擎与宿主 C ABI，不展示尚无原生接线的十八键面板入口，也不宣称 #8936 已解决。面板原生接线验收必须覆盖明确的组码来源、延迟按键回放及新旧组件版本协商。

- [十四键](../../implemented/feature/2026-10-10-fourteen-key.md)：部分重叠，沿用多义全拼与独立组码入口；十八键的字母分组和 Windows 宿主链路是新增决定。
- [Windows 屏幕键盘设置](../../implemented/feature/2026-10-11-windows-settings-screen-keyboard.md)：部分重叠，面板仍由共享组件承载，原生设置归属不变。
- [九键双拼](../../implemented/feature/2026-10-10-nine-key-shuangpin.md)：独立能力；十八键全拼不改成固定两键一个音节的双拼。
- #8930 另请求十八键双拼及左右滑动精确取字母，属于另一项 issue，本分支不将它自动关闭。

## Alternatives considered

**只改键面并注入每组首字母**：可以直接复用现有 SendInput，但另一字母永远无法参与拼音解码，界面与实际能力不一致，因此不用。

**在 Tauri 面板另建会话，选完词后注入文本**：可避开 TSF 协议改动，但实体键盘组字与面板组字会成为两个独立状态，容易留下旧组字和错位选词。复用原生宿主已有会话。

## Testing

- Windows 上新增引擎会话用例通过：合成词库的「你好」和「波好」来自不同拼音，但同属 `bihai`；两者都参与候选，锁定 `ni` 后排除 `bo`，退格与回车确认有效。实体键盘仍输入精确 `nihao`，不会把字母变成归组键。
- 两项直接调用 C ABI 的集成用例通过，覆盖编号 4、独立视图名、组字中拒绝换网格、拼写锁定、提交、双拼方案拒绝开启和拒绝后视图不变。
- 十八键加入原有键表覆盖检查，核对二十六个字母恰好覆盖一次；引擎与 runtime 的全部目标严格 Clippy 通过，格式与笔记门禁通过。
- Windows 的 31 项 golden 回归全部通过；恢复功能源码后强制更新修改文件时间并重新编译，再次通过新增会话用例和两项 C ABI 测试，避免解包时的旧时间戳误用基线产物。
- 完整引擎库：功能分支 2495 通过、19 失败、55 忽略；固定基点 `4fcc62e34a1cf6441df8c0975c9d2916a616a35c` 同机 2495 通过、18 失败、55 忽略。十八项失败名称相同；功能分支额外的 `a_new_journal_releases_an_unused_store` 单独重跑通过，但整套结果仍不能记为通过，也没有将它加入失败豁免。
- runtime 库在功能分支与该基点均为 333 通过、3 失败，三个失败名称相同。Host API 严格 Clippy 被未修改的 `host-windows::read_clipboard_text` 返回 `Result<_, ()>` 告警挡住，没有放宽检查。
- 完整 Windows quick 已执行，退出 1：`client-core` 偏好测试的三项基线编译错误（独立 #9531 尚未合并）、三个既有 pipe-only MSVC 告警及发布／参考／平台夹具检查失败；缺失工具链的平台阶段按脚本跳过，没有把这次门禁记为通过。原生输入入口尚无通过记录。

## Consequences

十八键复用现有全拼网格的切分、候选、拼写锁定、学习和筛选，没有第二份输入算法，也不新增落盘偏好或改变现有默认值。多义键始终经 `grid_key` 进入，实体字母仍经 `character` 进入；组码不是可提交的拼音文字，回车确认候选。

进程首次使用十八键时多建一份音节拼写索引，并常驻到进程退出；与十四键相比，重码结构不同，准确率和延迟尚无真实词库评测，不能声称性能或输入体验已经改善。

Windows 屏幕键盘、TSF 与 Server 的接线见[焦点租约面板](2026-10-24-windows-eighteen-key-panel.md)，两篇部分重叠：本篇持有共享算法与 C ABI，面板篇持有 Windows 来源、焦点与恢复边界。真实编辑器验收仍缺；本切片使用 `Refs #8936`，不以共享引擎测试代表 Windows 完整功能。本地磁盘不足，没有新建本地构建树，构建和真实 C ABI 用例在有余量的远端 Windows 工作区执行。
