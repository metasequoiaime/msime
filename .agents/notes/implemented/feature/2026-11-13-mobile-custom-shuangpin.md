# Agent Note: 移动端普通 26 键自定义双拼

Status: implemented

## Problem

共享偏好和 Engine 已经支持 `shuangpin_custom_profile` 及逐项校验，但移动端只有九键双拼的自定义页面。Android、iOS 和 HarmonyOS 无法在「语言与方案」里编辑、导入、导出或切换普通 26 键自定义表；键盘收到 `custom` 时也无法从共享层取键位提示。

## Decision

共享 `host-api` 提供无状态的 `msime_client_shuangpin_custom_layout` 接口，输入方案名和可选表，返回实际生效方案、规范表、带位置的校验问题以及字母键提示。自定义表不合法时按小鹤运行，和会话创建时的既有回退一致；接口不落盘，编辑器每次修改都可以调用。

Android 原生设置页和 iOS 原生设置页都直接使用这份接口完成编辑、导入、导出与保存。删除操作只移除自定义表，正在使用自定义时把实际码表回退到小鹤，不改变其他键盘选择、内置方案或词库；原生确认框明确说明后果。HarmonyOS 键盘复用同一计算接口读取键位提示；原生 ArkUI 管理页提供模板、逐项编辑、导入导出、保存使用、删除确认与提示开关，不向共享 Web 设置页增加入口。所有平台仍通过 `PreferencesStore` 保存 `shuangpin_profile` 和 `shuangpin_custom_profile`，不改变内置方案或默认值。

保存「使用」是一笔方案事务：Android 用 `ShuangpinCustomSelection` 同时更新引擎方案、布局和触屏选择；iOS 先调用 `InputSchemePreference.write`，再写实际的 `shuangpin_profile` 和表。已有内置方案用对应入口，自定义和智能 ABC 使用普通双拼入口。不能先写码表名再写入口映射，否则入口映射会把它覆盖成小鹤；也不能只改码表名，让仍指向全拼或其他双拼的触屏选择在下一次会话覆盖它。

Android 自定义提示直接使用已解析的共享键位表，不把它再次编码成裸 JSON 交给期望响应信封的解析器；这种转换会丢掉整张提示表。三端空格键短名也按实际的自定义或智能 ABC 码表显示，避免入口名字仍显示小鹤。

三端从其他键盘返回普通双拼入口时保留 `custom` 和 `smart_abc`，明确在设置里选小鹤时仍切换到小鹤；共享入口不代表码表名。iOS 在键盘出现时的 `applyInputScheme` 也读取这份实际方案，不能再硬编码小鹤，否则保存成功后第一次打开键盘就会覆盖表名。

自定义表中的分号从共享接口给出的键位提示决定可达性：26 键在中文、非工具模式时显示分号键，Android 在组字时把它作为韵母送进引擎；空闲或英文模式仍沿既有标点路径。不通过复制韵母规则猜测表的合法性，也不依赖用户是否打开键位提示来决定分号能否输入。

删除专项先切到原生「自定义」分页，再展示删除入口，取消时表保持原样，确认后仅当前自定义方案回退小鹤；不能在重开页面默认的「方案」分页中等待未挂入的控件。

设备回归使用合成码表交换 `j` / `k` 的韵母组，验证原生页面从全拼保存并使用后，键盘的 `j` 提示和实际 `bj → 冰` 相符；再换成微软表检查自定义 `b; → 冰`。文件导入在应用 UID 下检查合法表、未知分组和 16 KB 上限；测试结束恢复原偏好并删除合成文件。iOS 事务用例遍历各方案，核对保存后的方案名、启用列表和触屏选择。

HarmonyOS 的偏好选择和删除事务放在 `client-core::custom_shuangpin_settings`，导入的 16 KB UTF-8 上限、JSON 分组与 Engine 码表校验经无状态 `msime_client_custom_shuangpin_settings` 提供。ArkUI 编辑模型独立持有草稿，非法编辑不能用 Engine 的小鹤回退表覆盖；非法导入不替换旧草稿。每次保存重读最新修订号并 CAS，冲突只回读，不重试覆盖，前台刷新保留未保存草稿。导出前再校验，文件选择器只读用户所选 URI，读取有容量边界，短写循环到完整写入。

## Alternatives considered

直接在 Android、iOS 或 ArkTS/React 中复制 Engine 的缺失韵母、重复按键和零声母规则，能少改 C ABI，但会产生三套会漂移的校验和回退行为，和现有九键双拼编辑器的宿主契约冲突，因此不采用。

## Consequences

设置页和键盘提示共享同一个表及问题格式，导出的 JSON 使用三端共享的表格式，管理入口落在 Android、iOS 与 HarmonyOS 的原生界面。新增了跨平台 C ABI 和原生文件编辑入口；HarmonyOS 真机、iOS 真机和 Android 设备上的完整输入验收需要设备条件，Android API 28 与 35 已通过文件边界、真实原生页面保存、独立键盘进程提示和 `bj` / `b;` 实际输入专项；iOS 模拟器的七个共享 C ABI、事务、删除隔离和真实键盘控制器用例通过。真机和系统键盘扩展跨进程验收仍分开记录，PR 验证段必须保留未完成项。
