# Agent Note: 手机 26 键的「123」可以换成九宫格数字层

Status: implemented

## Problem

用户希望手机 26 键切到数字时，能选九键那样的数字排列。26 键的「123」原来只有一种：1 到 0 排成一行，下面是符号行。打电话号码、验证码、金额这类连续数字时，十个窄键排一行比 3×3 的大键难按，而九键用户早就有 3×3 的数字层。

[数字键盘顺序](2026-10-08-number-keypad-order.md) 当时把「26 键的 123 页也做成 3×3 小键盘」列为备选并放弃，理由是那是另一种布局、用户没提。这次用户提的正是它，所以它作为一个独立选项落地，不改那篇的决定。

## Decision

- 新增共享偏好 `touch_twenty_six_key_number_layout`，取值 `row`（默认，一行 1 到 0）或 `nine_key`（九宫格数字层），定义在 client-core 的 `TwentySixKeyNumberLayout`。缺省、旧文档和不认识的值都按 `row`。桌面宿主原样保留、不使用（`preference_coverage.py` 记为不适用）。
- 选了 `nine_key` 时，手机 26 键按「123」不画一行数字的符号页，改画三端各自现成的拼音九键数字层：同一个外框、同一组键，排列跟 `touch_number_keypad_order` 走。唯一的差别是回到字母的那个键回到 26 键字母，而不是九键字母。不另画一套新键面，三端的九键数字层已经各自对齐过设计稿，复用它就不会出现第二种 3×3。
- 哪些键面会换：字母层是 26 个字母键的那些方案——全拼、双拼、五笔、英文，以及同样画字母行的韩文、越南语、藏文等。拼音九键本来就是这一层；笔画、手写、注音、假名九宫格各有自己的数字层或符号行，不受这个偏好影响。
- 各平台判断放在一个不依赖界面的函数里，测试直接锁住它：Android `NineKeyLayout.twentySixKeyDigits`，iOS `KeyboardViewController.opensNineKeyDigitPad`，HarmonyOS `TwentySixKeyNumberLayout.opensNineKeyDigits`。
- 形态差异：
  - **iOS**：只在手机形态换（含 iPad 的浮动键盘和窄窗口）。iPad 全尺寸键盘本来就有数字行，3×3 拉满整个宽度也不顺手，所以保留一行的 123 页，分离式键盘因此也不受影响。
  - **Android**：横屏分离式键盘照旧用 123 层。分离是为了两半各贴一侧给拇指，三列网格铺满整个宽度，两只手都够不着中间。
  - **HarmonyOS**：只区分 2in1 和触屏两种形态，平板与手机用同一套触屏键面，九键在平板上本来就画这一层，所以平板也换；2in1 屏幕键盘不换。
- 数字的输出走 26 键原来 123 页数字的同一条路，不走九键的那条。韩文先上屏音节、越南语 VNI 的声调数字、藏文、组字中的网址，对数字的处理都和一行时一样。
- 打字统计：三端都按输入的数字记键位（`Digit*`），与一行的 123 页记到同一个键上，统计页不会给只用 26 键的人多出一块九宫格热力图。拼音九键自己的数字层仍记 `Nine*`。
- 按「123」时正在组的字和原来一样保留。长按「123」打开符号面板照旧可用。
- 设置入口：
  - 共享设置页「屏幕键盘 › 布局」在移动宿主上「数字键盘顺序」之前加一行「26 键数字键盘：一行 / 九宫格」。HarmonyOS 用的就是这一页。
  - Android 键盘设置页和 iOS 键盘布局设置页各加同名一行。「数字键盘顺序」的说明改成「九宫格数字键盘的排列」，因为它现在同时管两处。
  - Android 上「九键数字键盘左侧符号」在本版本没有拼音九键、但 26 键选了九宫格时也列出来，两处用的是同一张符号表。
- 账号同步：Android 和 iOS 走 client-core 的 `platform.android.twenty_six_key_number_layout`，HarmonyOS 走 `platform.harmony.twenty_six_key_number_layout`，取值都是 `row` / `nine_key`。和数字键盘顺序一样，服务端字段表登记之前，上传时会被过滤掉。

## Alternatives considered

- **为 26 键单独画一个 4×3 电话拨号盘（0 在 8 下面）**：最强的理由是和手机拨号盘手感一致，0 的位置不用重新找。不用它，是因为三端的九键数字层已经存在、已经对齐过设计稿，而且用户说的就是「9 键的数字排列」。再画一套会多出第二种 3×3，两处的符号栏、小数点、0 的位置都要各自维护。
- **复用 26 键的「123」页，只把第一行 1–0 改成 3×3 嵌在符号行上方**：可以保留 #+= 和整页符号。不用它，是因为 3×3 至少要三行键高，整块键盘要么变高（切层时高度跳动），要么符号行被挤掉，最后剩下的仍是一个九宫格数字层。
- **存成宿主本机设置**：不必改 client-core。不用它，理由与[数字键盘顺序](2026-10-08-number-keypad-order.md)相同：HarmonyOS 的设置页就是共享页，读不到宿主本机设置；而且这项和数字键盘顺序是一对，应该存在同一个地方。
- **数字格记九宫格键位（`Nine*`）**：和九键数字层完全一致，Android 和 HarmonyOS 的第一版就是这样。不用它，是因为只用 26 键的人在统计页上会多出一块从没选过的九宫格热力图，而一行 123 页的数字本来就记在 `Digit*` 上。

## Consequences

- **收益**：
  - 26 键用户打连续数字时可以用 3×3 的大键，排列也可以选计算器顺序。
  - 三端各自只多一个判断加一个开关，键面本身没有新增代码路径。
- **代价**：
  - 选了九宫格后，26 键到不了 #+= 层。这和九键数字层一样，更多符号要从左侧符号栏或长按「123」打开的符号面板里找。
  - iOS 上藏文用户选九宫格后，123 页上的 `'` 和 `+` 就没有了。
  - 三端形态规则不同：iOS 的 iPad 全尺寸键盘、Android 的分离式键盘不换，HarmonyOS 平板换。
  - 服务端字段表登记新键之前，这一项只存在本机。
- **验证**：
  - `cargo test -p msime-client-core`：旧文档缺省为 `row`，`nine_key` 能存能读，同步导出和导入都覆盖到。
  - `apps/desktop` 的 `touch-keyboard-geometry-section.test.tsx` 覆盖设置行。
  - HarmonyOS：`platforms/harmony/tests/run.sh` 覆盖判断和账号同步；`hvigorw assembleHap` 做过 ArkTS 编译。没有上模拟器。
  - iOS：`NineKeyKeyboardTests` 与 `KeyboardGeometrySettingsTests` 在 Studio 的 iPhone 18 Pro / iOS 27 模拟器上跑过，97 个通过、1 个原本就跳过。测试渲染的键面截图人工看过。App 编译通过。iOS 27 模拟器切不到第三方键盘，没在真实编辑器里看过。
  - Android：
    - `check-host.sh` 的 JVM 冒烟锁住偏好取值和判断函数（含分离式键盘），Gradle `compileFullDebugJavaWithJavac` 通过。
    - 在一次性 API 35 模拟器上装包实测：设置行能保存；选九宫格后点 123 出数字键面，底栏是 ABC、空格、中、回车；点 1 . 0 + 上屏 `1.0+`；ABC 回到 26 键字母；组字中点 123 保留组字；在数字键面上点中/英重建成英文字母层；改回一行恢复原来的 123 层；长按 123 打开符号面板。
    - 没在设备上测：键盘显示时改偏好立即重建、韩文、平板和分离式键盘、浮动键盘、云同步。
    - 记键位改成 `Digit*` 是在设备验收之后做的，只经过编译和 JVM 冒烟。
