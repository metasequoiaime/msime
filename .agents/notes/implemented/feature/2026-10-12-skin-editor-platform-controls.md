# Agent Note: 皮肤编辑器改用设置页的平台控件，键盘预览移到控件上方

Status: implemented

## Problem

「设计我的皮肤」（`TouchKeyboardSkinEditor`）是在设置页换成平台控件（`GroupList`、`Row`、`SwitchRow`、`SliderRow`、`SelectRow`，颜色和形状取自 `--p-*` 令牌）之前写的，一直没有跟着迁移。它自己画了一套灰色卡片（`bg-subtle`）、浏览器默认的复选框和方框取色器、带边框的五格标签栏，以及两颗同样粗重的实心大按钮「AI 皮肤抽卡」「保存设计」。在鸿蒙手机的季节主题下，灰卡片叠在米色页面上，蓝色复选框和矩形色块跟页面的强调色、圆角都对不上，整页看起来像另一个应用。用户看了截图的评价是「太丑了」。

键盘预览排在所有控件的最下面。在手机上改颜色时要一直滚到底才能看到效果，改完再滚回去，而「改了马上看到」恰恰是这个页面最需要的。

## Decision

- 控件全部换成设置页的平台控件，按「预设 / 颜色 / 照片壁纸 / 纹理」「颜色 / 造型」「文字」「模板」「我的皮肤」分组。 整数 RGB 颜色行已独立为公共 `RgbColorRow`，保留数值颜色契约；透明度和文本草稿仍由 `HexColorRow` 负责。开关用 `SwitchRow`，滑块用 `SliderRow wide`，末端显示当前值，选择用 `SelectRow`（鸿蒙手机上自动变成点开选择面板的整行）。颜色是新的 `ColorRow`：末端是色值文字和一个圆形色块，色块仍是原生 `<input type="color">`，只换了画法。这样每个平台的分组、行高、分隔线、开关样式都和同一宿主的其他设置页一致，季节主题也自动跟上。
- 键盘预览移到标题下方，和撤销、重做（图标按钮）、保存设计（淡强调色胶囊）、使用皮肤（实心）放在同一张卡片里。全屏（鸿蒙手机）时这张卡片吸顶（`sticky`，顶部让出 `safe-area-inset-top`），预览限宽 300 让出下面的控件空间；内嵌（桌面）时不吸顶，预览限宽 560。全屏时预览用 `phone` 外观，与皮肤网格里的缩略图一致。
- 「AI 皮肤抽卡」从标题下的大按钮改成预览下方的一张淡强调色入口卡片（标题、一句说明、箭头），可访问名称仍是「AI 皮肤抽卡」。
- 分类标签保持 `tablist` / `tab` 语义，画法改成分段控件，颜色取自各平台分段控件的令牌（`--p-seg-*`）。
- 背景预设改成色块在上、名字在下，当前设计正好等于某个预设时，那一块带强调色外圈和对勾（`aria-pressed`）。预设、模板、图库网格按宽度自动排列列数：手机上三列或两列，桌面上一行排得下全部九个预设。
- 所有控件和按钮的可访问名称保持不变（「撤销设计」「重做」「保存设计」「使用皮肤」「背景预设 …」「皮肤模板 …」「应用已保存皮肤 …」以及各滑块的 `aria-label`），现有测试不需要改。

## Alternatives considered

- 保留现有结构，只把灰卡片、复选框和取色器的颜色改成令牌。理由最强的一条：改动最小，测试和布局都不动。没采用：难看的根源不只是颜色——复选框和矩形取色器本身就不是设置页的控件，标签栏和大按钮的比例也和其他页面不同；只换颜色之后它仍是一个与周围页面不同的孤岛，以后设置页的平台控件再改，它还要再追一次。
- 预览放在底部，加一个悬浮的「看预览」按钮。理由：控件区域更长，不占顶部空间。没采用：要多一次点击和一次来回滚动才能看到效果，等于没解决「改了看不到」的问题。
- 预览整宽吸顶。理由：预览更大更清楚。没采用：手机上整宽的键盘连同按钮栏有四百多像素高，吸顶后控件只剩不到半屏；限宽到 300 后吸顶部分约占三分之一屏，下面还能放五六行控件。

## Consequences

- 皮肤编辑器跟随平台控件和令牌的后续改动，不再需要单独维护一套 `controlBlock` / `formGrid` / `colorInput` 样式，这些导出已删除。
- 全屏编辑时预览一直在屏幕上方，[HarmonyOS 手机的皮肤编辑器全屏视图](../bug-fix/2026-10-11-harmony-skin-editor-full-screen.md) 里「编辑器底部自带键盘预览」的说法相应改为顶部。
- 吸顶区域约占手机屏幕三分之一。如果以后在小屏手机上觉得太挤，可以再缩小 `previewFrame` 的限宽，或在向下滚动时把预览折叠成一条。
- 发布表单里的「同意发布」复选框（`AiSkinGeneration`）不在这次范围内，仍是 `ControlledCheckbox`。

## Verification

- `apps/desktop`：`pnpm exec vitest run` 全部 565 个文件、2964 个用例通过，其中皮肤相关的 8 个文件 395 个用例覆盖编辑器的标签、撤销重做、模板、图库、保存和 AI 入口；`tsc --noEmit`（desktop、harmony）通过；`pnpm run lint` 对改动文件没有告警；`vp fmt --check` 通过；`bash scripts/run-checks.sh` 全部通过或跳过。
- 视觉检查：用一个不提交的临时页面把编辑器挂在 `data-platform="harmony"`（带秋季主题令牌和鸿蒙表单上下文）和 `data-platform="mac"` 下，在 390 × 844 和 900 宽的无头 Chromium 里截图比对改动前后，并检查了向下滚动后预览吸顶的效果。没有在 HarmonyOS 模拟器或真机上装包验证。
