# Agent Note: Android 命名词库取消条数硬上限

Status: implemented

## Problem

命名词库此前把每个集合限制为 50,000 条。Android 词库页导入大于该数量的文件时，后续词条被截断并显示词库已满。已有的 16 MiB 文本导入上限、48 MiB 单集合文件上限和 96 MiB 待发送队列上限已经限制了输入规模，条数边界造成了重复约束。

这次决定覆盖并翻转[词库集合容纳三万行导入](../../implemented/bug-fix/2026-10-19-dictionary-collection-capacity.md)中保留 50,000 条边界的决定。旧笔记记录的测试、性能和字节边界仍然成立，新的行为只取消条数裁决。

## Decision

命名词库不再按条数拒绝、截断或判定落盘文件损坏。集合数量仍限制为 32 个，文本导入仍限制为 16 MiB，搜狗细胞词库仍使用其二进制大小限制，单集合 JSON 仍限制为 48 MiB，索引和待发送队列的字节限制不变。集合导入和增删继续在集合锁内完成，超出字节边界时保持原子失败。

解析器使用自然增长的词条和身份集合，不为已经取消的条数上限预分配容量。`truncated` 字段保留在返回结构中以兼容已有宿主，取消条数上限后正常导入返回 `false`。

## Alternatives considered

- **把上限提高到 100,000 或更大**：改动小，但仍会在下一个规模上再次截断用户词库，也无法兑现取消硬上限的需求。
- **按文件大小保留现有保护并取消条数边界**：最强的理由是复用已有原子写入和字节预算。采用它，避免无界文件和请求进入落盘，同时允许同一字节预算容纳更多短词条。
- **自动拆成多个集合**：能保留旧的单集合边界，但会改变用户的启用、停用、删除和失败回滚语义，也会制造多个集合名称。

## Consequences

- Android 和共享设置页可以导入超过 50,000 条的单个命名词库，只要请求和落盘文件没有超过既有字节限制。
- 旧版客户端仍可能拒绝新版本创建的超大集合，降级前需要导出并拆分，属于版本兼容代价。
- 集合读取、校验、排序和待发送队列可能占用更多内存和时间，已有 16/48/96 MiB 边界继续限制最坏的持久化规模。
- 错误提示中的 `collections_limit` 现在只描述集合数量上限。

## Verification

- 新增共享服务回归，导入并追加超过 50,000 条合成词条后重新加载，计数和尾条保持完整，后续导入不再截断。
- 更新 Host API 细胞词库回归，50,000 条导入报告 `truncated=false`。
- Android 和共享设置页的集合数量错误提示同步更新。
- Android 真机验收需在 PR 设备门禁完成，当前改动涉及词库写入和资源目录，按仓库 Android 设备流程执行。
