# Agent Note: Android 无释义候选行与小工具栏

Status: implemented

## Problem

#11424 报告关闭读音／释义后，候选与拼音的间隔仍然很大；工具栏最小只能选 90%，图标仍显得过大。候选行无条件预留 42 dp，原本为了容下候选字与一行释义，关闭释义后仍空出这一行。独立工具栏又必须与候选区统一总高，避免 #11108 的切换抖动，单独放宽范围不能消掉这部分留白。

## Decision

无释义的候选行以 32 dp 为设计高度，有释义时仍以 42 dp 加后续每行 14 dp 为基准。按候选缩放计算后，用当前候选字体、字号与键盘字体缩放的实际文本布局作下限（包含汉字、假名和韩文的回退字体），大字号不为紧凑而裁切。展开与关闭按钮不高于候选行。`CandidateStripSizing` 缓存排版结果，只在字体、字号或释义行数改变时重测；释义标签复用产品的 `candidateLabel`，避免字号比例重复定义。API 35 设备断言曾检出 50%／32 号候选的回退字形高于主字体 `FontMetrics`，因此不能只按主字体的 ascent／descent 定行高。

已有 Android 本机工具栏尺寸扩展到 50%–150%，仍每步 10%；行高至少 44 dp，图标可继续缩小，按钮点击宽度不缩。默认 100%、缺字段跟随候选栏、旧设置取值和共享候选缩放 50%–200% 均保留。两种状态的总高继续取较高值并补预留，最近复制与内联填充继续同高。

对应旧决定：[独立工具栏尺寸](2026-10-26-android-toolbar-size.md)、[独立尺寸切换抖动](../bug-fix/2026-11-08-android-toolbar-size-jitter.md)、[三端候选缩放](2026-10-29-touch-candidate-bar-size.md)。本次只改变 Android 的无释义布局和已有控件范围，不改变上述设置默认值。

## Alternatives considered

- 只扩展工具栏范围，改动最少，也能缩小图标；但稳定总高仍被空出的释义行撑住，不能解决报告中的候选间隔。
- 取消工具栏／候选区统一总高，用户选择的独立行高能直接体现；但会把 #11108 的输入时窗口跳高重新带回来，因此保留统一总高。
- 固定缩小所有候选行，视觉统一；但一行或多行释义和较大的实际字体会被裁掉，因此按启用行数与字形保留空间。

## Consequences

- 无释义行更紧凑，有释义行与大字体不裁切；展开、关闭和候选点击有效。
- 50%、70%、90%、100%、150% 的工具栏均可选择并持久化；缺字段跟随行为保留。
- 空闲、组字、上屏联想、最近复制间切换，输入法窗口持续存在且 bounds 不跳。
- 设备专项覆盖 API 28／35，保留默认设置的旧稳定高度回归，并保存改前／改后截图。实际结果随 PR 验证段记录。

## 字体与验证边界

实际字体与第三方皮肤的留白不同，需要设备上的字形边界与大字体验收。只缩小图标不缩小点击区会让低比例下的控件看起来更疏，这是保留易用性的代价。

## 既有笔记归属

独立尺寸、切换稳定总高与三端候选缩放三篇笔记与本次部分重叠，均保留并互链。本次取代 Android 无释义时固定 42 dp 的行高和独立工具栏 90% 的下限；共享候选缩放、缺字段语义及两种状态统一总高的决定继续有效。其他候选皮肤、桌面候选与 iOS 点击反馈笔记只在检索中命中，不改变其决定。
