# Agent Note: Windows 7 屏幕键盘皮肤编辑与共用绘制

Status: implemented

## Problem

Win7 屏幕键盘已有真实按键、间距和高度设置，但只使用解析主题的基础颜色。共享自定义设计的形状、材质、图片、透明度与命名库没有完整可达入口，不能据此宣称键盘能力对齐。

## Decision

新增独立 Win32 皮肤页面，复用 `msime_client_custom_skin_library` 的新建、重命名、更新和删除。显式新建传空设计对象，由 Rust 补默认值；原生承载只编辑共享字段，不另存一种皮肤格式。应用同时按修订号保存 `global_theme=custom` 与 `custom_theme.keyboard`，保留候选主题等其他字段，并发冲突不自动重放。

设置预览和实际键盘共用 GDI+ 绘制器，读取当前的 `custom_theme.keyboard`。支持七种颜色、圆角、边框、阴影、三种图案、等宽字体、四种形状、四种材质、键透明度、渐变、边框颜色与照片遮罩和位置。图片字节经共享有界解码；读取、库操作和图片解码在串行工作线程完成。

编辑器提供 30 步撤销／重做；历史仅存在当前窗口，不写用户配置。15 个模板和 9 个背景预设提取为 `resources/keyboard-skin-presets.json`，共享 React 与 Rust 使用同一份数值，默认设计保持原样。重置、背景变换和对比度优化由 `client-core::keyboard_skin` 通过 `msime_client_keyboard_skin_design` 提供，Win32 不复制配色规则。变换只更新草稿，保存库与应用仍须显式触发。

AI 生成直接调用现有 `msime_client_ai_skin_generate`，在工作线程显示进度，主线程可通过共享取消接口终止。窗口关闭先取消再等待工作线程；生成方案只进入临时列表，选择后载入预览，不自动保存或应用。请求 id 不含用户输入，错误提示不输出提示词、凭据或服务端原始响应。

- 按键盘皮肤、命名库与 Win7 检索活跃记录，其他平台的现有皮肤设计与共享格式保持原状。

## Alternatives considered

- **只提供 JSON 文本编辑框。** 字段覆盖容易，但用户必须理解内部格式，且无法直接调整和预览，因此提供标准控件。
- **复用旧版 WebView。** 可以直接承载共享编辑器，但引入已停更的运行库与另外一条部署链，因此使用系统 GDI+，共享业务仍归 Rust。

## Testing

x64 与 x86 在 Windows 11 上编译并通过真实控件、共享命名库、CAS、照片解码和形状／材质／渐变像素测试。Win7 SP1 x64 的交互桌面运行两架构测试，皮肤、路由、键盘面板和键盘设置共八项全部通过；包括第 22 页的直接路由。WOW64 测试不能替代 32 位 Win7 系统验收。

## Consequences

预览与实际键盘使用同一绘制器，显式应用前不修改全局主题或默认值；实际键盘通过刷新操作读取新皮肤。GDI+ 的抗锯齿与共享网页栅格化不完全相同，验收检查字段能生效和绘制结果，不要求跨平台逐像素相等。图片过大、坏编码和库错误明确提示，不能静默清空已存设计。

新增操作已随最终同源产品完成 x64／x86 重建，并在 Win7 SP1 交互桌面通过真实控件、共享目录、照片像素和取消回归。AI 测试注入合成服务，检查工作线程、进度、载入和取消，不花费真实账号额度。
