# Agent Note: Android 拼写编辑可关闭并释放入口空行

Status: implemented

## Problem

#11161 同时要求快速输入不误开拼写编辑，以及允许关闭这个功能、移除它独占的空间。旧评论把图标认成手写入口，报告者移除手写后仍能复现；视频实际显示的是拼写编辑面板。当前没有关闭该面板的设置。误打开的根因仍在通过真实输入与选区事件定位，本开关不能代替该修复。

## Decision

共享 Rust 偏好新增 `touch_spelling_editor`，缺字段和出厂值都为开启，保留所有现有用户的行为。Android 原生键盘页提供「拼写编辑」开关，解释收进标题旁的问号。其他宿主保留该字段，不改变其行为。

关闭后，读音标题不再响应打开编辑条，笔图标和无障碍编辑动作消失，输入框的选择变化也不再打开编辑条；已经打开的面板随偏好刷新收起。空闲和正常行内组字都不再为笔图标保留一整行，候选分页本身不强制撑开这行。候选栏拼写和网格布局仍从空闲时预留读音行，非拼写方案保持原布局；必要的拼写、准备或失败状态、退出模式动作仍可显示，不能为了紧凑而隐藏内容。

本篇补充[放大拼写编辑](2026-10-21-android-composition-magnifier.md)的可达性控制；原来的编辑、拖动与开启状态下的行为契约仍归原笔记。[压成一行](2026-10-25-android-compact-spelling-editor.md)只约束打开后的面板形态，不被本开关取代。检索到的 iOS、HarmonyOS 拼写入口笔记属于其他宿主，本次不改。

## Alternatives considered

- 默认关掉编辑：可以直接避免大多数误打开，但会改变所有旧用户习惯，也会掩盖开启状态下的 bug，因此保留默认开启并继续定位。
- 只隐藏笔图标：改动少，但输入框选区仍可打开编辑条，空行也仍存在，不满足关闭功能与释放空间的要求。
- 无条件隐藏整条读音行：最省高度，但会丢掉候选栏拼写、非拼写方案读音及必要状态，所以只移除编辑入口独占的空行。

## Consequences

用户能按自己的选择关闭编辑条且减少空白。共享偏好支持持久化与旧文档兼容，产品默认值不变。关闭时页码随空读音行隐藏，候选翻页和展开操作保持；实际拼写或状态需要显示时仍占用必要高度。

Rust 回归覆盖旧文档、默认值、显式关闭保存与类型拒绝；纯 Java 行布局回归覆盖空闲/组字、网格、必要内容与非拼写方案。真实设置操作、键盘窗口尺寸、快速双键输入以及 API 28/35 截图仍待设备验收；在原 issue 两项要求都被证明之前保持 draft，不把本开关作为误打开已修复的证据。


验证入口为 `smoke.sh --spelling-editor`：仍跑主输入、Rust 设备单测及崩溃检查，设备专项覆盖原生开关、保存重开、立即关闭旧面板、释放空行、输入时窗口稳定。完整 nightly 的组字套件也运行这项；不加入短 PR 或发布冒烟。Java 文件读取沿用 API 28 支持的 `readAllBytes`。共享字段在原生入口清单注明，不向 React 添加新设置。移除旧侧边数字面板守卫中仅约束 `touchGeometryKey` 拼接换行的文本匹配，原有行为用例和其余守卫保持。首轮 quick 在字段可达清单与该换行匹配上失败，补齐后重跑，不能记作通过。


#11161 的另一项诉求是两个字母几乎同时按下。增加默认开启状态的真实双指设备回归：间隔 1/20ms 按下 N、A，分别按正序与逆序抬起，要求输入 na/an 且没有拼写编辑面板。使用触屏多指事件，不以无障碍点击代替重叠触摸；此回归尚未完成设备运行，不能据此认定 Android 17 报告已修复。

首次双 API 专项 `42803034891` 的 API 28 在动态关闭后的“入口、面板消失且行高减少”联合断言失败。补上这三个条件各自的结果与失败截图，原断言保持，尚未据此确认是哪一项没有生效。新增双指用例的远端 quick 已通过 Android Java 编译，但最后两项 Windows 交叉链接遇到编译盘耗尽；已在确认本任务远端副本无进程使用后清掉其 macOS 构建缓存，后续门禁改用本地已有产物目录。
