# Agent Note: macOS 候选窗首行显示输入状态、云候选预览和装饰

Status: implemented

## Problem

macOS 候选窗首行只有水杉 logo、拼音加光标，以及右侧的页码和翻页箭头。打字时看不出当前是哪个方案、中英文和简繁状态，要去菜单栏或悬浮工具栏找；云候选和 AI 候选只是候选行里带角标的一格，整句结果被压在一格宽度里，翻到后面一页就看不到了。首行大部分宽度是空的。

## Decision

首行在显示拼音时（`show_candidate_preedit` 打开）多画三样东西，并在首行和候选行之间加一条细线：

- 拼音后面用一条竖线隔开，画一段输入状态：方案名、「中」或「英」、简繁、全角，用「 · 」连接（`MSIMECandidateStatusText`）。方案名和悬浮工具栏共用 `schemeTitleForScheme:`；「英」取 `view.dedicated_english` 或临时英文模式；简繁只在 `view.script_conversion` 为真时写；全角取运行时的全角开关。整段用次要色。
- 右侧、翻页控件之前，预览这一页的云候选（来源 2），没有云候选时预览 AI 候选（来源 3），AI 占位行不算（`MSIMECandidateOnlinePreview`）。预览带云或星形符号，用强调色，最宽 220pt，超出截断。点它和点候选行里那一格一样，走 `selectCandidate:`，用的是同一个候选身份。候选行里的那一格照常保留，选词键不变。
- 最右端画一枝三片叶的小装饰，用强调色。

这三样只占卡片已有的宽度，不计入卡片的最小宽度：云候选是异步到的，算进去的话回答一到卡片就会突然变宽，中英切换也会让卡片跟着伸缩。卡片宽度仍由候选行、拼音和翻页控件决定，放不下时先去掉装饰，再去掉状态，预览按剩下的宽度截断，太窄就不画，拼音总能拿到余下的宽度。关掉候选窗拼音时，这三样都不画。细线在用 canvas 绘制的皮肤上不画，因为那类皮肤的整张卡片都是贴图。设置里的皮肤预览也画同样的竖线、状态和细线。

全部在 macOS 宿主里完成，不改共享偏好、皮肤清单和 Engine 视图字段。

## Alternatives considered

把云候选从候选行里移走、只在首行显示。这样首行和候选行不会出现同一个词，界面更干净；但云候选就没有数字选词键了，得另配快捷键，用户已有的选词习惯会变。维护者选择两处都显示。

为状态、预览和装饰各加一个偏好开关，或者把装饰做成皮肤清单里的新槽位，这样可以单独开关、由皮肤作者定制。没这么做，是因为开关和清单字段都是跨平台契约，要同时改 client-core、共享设置页和其他宿主；现在跟随已有的「候选窗拼音」开关就够了，需要单独开关时再加。

把状态、预览和装饰算进卡片的最小宽度，它们就总能显示出来，竖排的窄卡片也不例外。第一版就是这样做的，结果候选很短时短页和长页一样宽，卡片还会在云候选到达时变宽，所以改成只占已有宽度。

## Consequences

`ShortcutTest` 覆盖状态文本的各种组合、预览的取舍（云优先于 AI、跳过占位行）、首行各元素从左到右不重叠、细线位于首行和候选行之间、配色取自主题、中英切换不改变卡片宽度、卡片窄时让出状态和装饰，以及没有在线候选和关闭拼音时不画。

竖排或候选很少时卡片窄，状态和预览常常放不下而不显示。展开的候选网格首行没有改，仍只显示拼音和行号。
