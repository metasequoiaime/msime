# Agent Note: 商业云候选与上屏后云预测分开接入

Status: implemented

## Problem

现有 Google/自定义云候选只处理未上屏拼写；上屏后联想只有 Android 的词库续词和个人相邻词。将汉字上下文直接塞进拼音查询会误发到转换服务；把预测当普通候选又会让原生空格和数字快捷选择提前提交用户未输入的文字。

## Decision

云候选增加已验证 HTTPS 回包的百度来源，保留原有默认值、超时、来源隔离缓存及原始 JSON 回传机制。当前搜狗 APK 的加密 Protobuf 与 WebSocket 链路只提供结构参考，未打通的私有云不作为可用来源展示。样本哈希、具体类与网络检查见[逆向记录](../../../../docs/commercial-prediction.md)。

上屏后查询以 `OnlineInputMode::Prediction` 与拼音/英文隔离，身份由引擎的独立会话/代次、当前方案和最多 64 字的本次上屏序列决定。即使本地没有建议，也可等待云回复。仅在 `next_word_prediction`、云候选及本机 `prediction_enabled` 同时开启时，对自定义服务发送 `mode: prediction` 和上下文；不回退到只支持拼音的内置服务。配置整组已经排除导出和账号同步，新授权沿用这一边界。

解析器最多接收八条有界、去重的文本候选；普通拼音仍只取首条。预测引擎只接受汉字后缀，本地首选保留在前，最多三条新增云行随后插入，总共最多八行；本地页单独保存，撤销云行可以完整恢复本地结果。点选只上屏后缀并触发下一次预测。新输入、取消、失焦、布局/隐私变化或来源切换作废旧请求。

macOS 现在与 Android 一样可选择上屏后联想。macOS 原生快捷选择在空闲联想状态先清除建议，不用空格或数字提交；点选和回包还必须匹配上屏时的选区锚点。普通输入清除建议保留已上屏词序；外部光标变更重新建立焦点边界，不能把旧上下文带到新位置。

## Historical audit

[自定义云候选](2026-10-19-custom-cloud-candidate-url.md)继续持有 HTTP 描述符、来源切换与本机配置边界，本篇部分替代其“不内置百度”的选择，采用实际可用的 HTTPS 证据而不假定服务承诺稳定。[上屏后联想](2026-10-24-post-commit-prediction.md)继续持有空闲建议不属于组字的规则，本篇增加独立云查询与 macOS 原生入口。已有整句模型和负载降级笔记只持有排序/调度，没有被本篇替代的活跃提案。

## Alternatives considered

- **直接复用搜狗旧 Web URL**：接入代码少，旧公开客户端有参考；本次真实请求已失效，不能作为可工作的来源。
- **直接把上屏文本发往所有拼音服务**：可复用完整传输链路；这些服务没有后续词契约，且会悄悄扩大现有联网授权，因此为预测增加独立模式和本机授权。
- **将云预测放在普通组字候选中**：数字、空格和高亮都能复用；会让未输入的词被提交，继续保留独立空闲状态与显式点选。

## Consequences

`PRIVACY.md` 同步列出百度与自定义云候选目的地、请求字段，以及独立云预测的授权条件、最多 64 个汉字、撤回和本机配置边界。

用户得到可选择的商业拼音云候选，以及支持本地回退的后续词服务入口。代价是维护第三方无稳定承诺的百度协议、最多八行的预测缓存及两种查询语义；仅有自定义服务实现后续词协议时才获得云预测。本次没有恢复或分发搜狗专有模型，没有证据声称其预测准确率已经达到商业产品。原生验证与 Docker 共享层验证分别记录，不能互相替代。

## Verification

新增回归覆盖百度状态/响应形状、预测的独立授权与缓存身份、GET/POST 模式、空本地页、后缀点选、旧代次、隐私撤销和来源配置；Docker 执行结果保存于本轮事务记录。macOS 控制器与 ShortcutTest 的严格语法检查、iOS Swift 解析单独执行；桌面系统输入源和 Android 设备安装仍需单独验收。

Docker 普通用户复核：引擎 2601 通过、56 忽略，运行时 382 通过、1 忽略，client-core 545 通过，31 个 golden 与 3 个 adaptive 事务测试通过；C ABI 云候选与预测 3 项通过，四个受影响 crate 严格 Clippy 通过。实际百度合成请求由生产描述符构造并经生产解析器得到「你好」；预测探针得到 seed=「吃」、本地=「饭」、cloud_applied=true、suffix_commit=「米饭」。前端完整 848 个文件、5409 项测试通过，类型检查与生产构建通过，笔记门禁通过。macOS 控制器和 ShortcutTest 严格语法检查与 iOS Swift 解析通过。

完整引擎首次以 root 执行时四项权限回归失败，改用 nobody 运行同一测试二进制全部通过，未改变生产权限规则或断言。Linux 容器原生门禁 111 项通过。主机 quick 受缺失 JDK、CMake、XCTest 模块与 Cargo 的 libllhttp 动态依赖阻塞，缺失 SDK 的设备阶段跳过；不得把 Docker 共享层结果描述成 Android 设备或已安装 macOS 输入源验收。

新增一键 Docker 脚本在启用真实网络探针后执行成功：百度/自定义云协议 15 项、引擎预测 14 项、运行时预测 7 项通过；C ABI 项目使用最终单独复核，生产探针仍返回「你好」。
