# Agent Note: macOS 横向候选按宽度自适应与跨列展开

Status: implemented

候选展开与收起过渡的决定由[全平台即时候选呈现](../simplification/2026-10-30-candidate-immediate-presentation.md)部分取代；自适应分页、尺寸和滚动规则继续成立。

## Problem

固定数量的横向候选随词长伸缩；历史最大宽度又会留下无用空白。需要按宽度选择一行可见候选，同时让展开后的长词占多列。

## Decision

macOS 横向增加 `candidate_count_mode`（`fixed` / `adaptive`）、`candidate_max_width`（默认 420pt，160–1200）和 `candidate_columns`（默认 6，1–10）。默认保持固定数量，不改纵向、其他平台和已有每页数量。固定数量取消横向最小宽度填充；自适应不足一行时收紧，溢出时以最大宽度封顶。滚动条占位保留。

自适应使用带代次的全候选快照做展示分页；导航同步引擎高亮，选择走已有全候选选择接口，不修改引擎排序、候选身份或固定分页；宿主另外把显示的一行报给 runtime（见下文「显示页」）。展开按等宽列向上取整跨度，键盘与滚动使用真实行边界。

未展开的单行按需分页：逐行贪心装填只取决于前面的候选，所以只测量到高亮所在那一行排完、再多一项确认后面还有，首批 16 项，不够时按已量项数成倍追加后重排。单项宽度不含序号栏，前缀量出的行与全量逐行一致。因此只知道「到下一页为止」的页数：翻页箭头与「下一页」按这个已知页数判断，首行不显示「1 / N」总页数，只留 ‹ ›。备选的「先显示 1 / …、空闲时补全总数」和「开页码时才全量测」被放弃：前者要额外的空闲调度且数字会跳变，后者让开关决定性能。

展开网格同样按需排版，不做全量排版。单字母输入（例如只打一个 j）有三千多个候选、六百多行，全量排版打开网格约 140ms，而且旧实现每移一次光标都整份重排，每步同样约 140ms。现在展开时从首行起立刻排 20 行（皮肤的视口加 8 行预读更多时以那个为准），并包含光标所在行；测量按 64 项一批接在已测部分后面，不重测前缀（单项宽度与一起测量的是谁无关，序号栏按行内编号，网格一行最多十项，首批已够），已排的行不会再变。下移、翻屏前先补到这一步要到的行；鼠标或触控板滚到已排末尾附近时视口回调追加行，已建按钮与滚动位置按新增高度一起平移，看到的内容不动。网格不显示「第几行 / 共几行」：总行数要排完全部候选才知道，按需排版时给不出准确数字。滚动条照常显示，按已排部分画：追加行后滑块变短、位置随之调整，这种跳动经用户确认可以接受；曾短暂隐藏滚动条，用户要求恢复。移动光标与按行滚动的重画沿用已排的逐行几何，只重建可见行的按钮；候选数组、字体、缩放、明暗、皮肤、可用宽度、列数与最大宽度任一变化或外观通知到达时整份重排。固定数量的网格仍全量排版（共用列宽要看全部行），移动光标同样沿用缓存。实测三千六百个候选（离屏宿主、合成候选）：自动适应打开网格约 24ms、每步约 14ms，与候选数无关；固定数量打开约 155ms、每步约 20ms。

PR #9772 审查补充：

- **显示页**：自动适应的一行可能跨过引擎的固定页。二三候选键（`;` `'`）和五笔自定义选词键由 runtime 按「高亮 ÷ 每页数」算页起点，翻到第二行后会选到固定页里的另一个候选；翻译查询也只列固定页，显示行里固定页之外的候选拿不到释义。共享层新增只增不改的 `msime_client_set_display_page`：宿主每画出一行就报这一代显示的候选序号，runtime 只对那一代采用，快捷键改走全候选选择、翻译查询列显示行；同一代换回固定分页时清掉，组字推进后自动失效。宿主侧给释义、目标语言词典和自定义翻译看的服务视图也换成显示行。放弃的备选：宿主自己把快捷键映射到显示行，需要在宿主复制 runtime 的方案、拼写符号、微软双拼韵母位等排除规则，容易与共享层分叉。
- **数字键 `0`**：自动适应时按「显示行项数」与「引擎每页数」中较大的判断第十格，这一行没有第十格时由候选身份检查吞掉，不落进引擎选它固定页里看不见的第十个。
- **翻页接管**：只在候选窗可见且不在联想状态时接管。收起后（上屏、取消）的翻页键交给引擎；联想翻页在 runtime 里会清掉联想，沿用原来的单次命令。
- **首行控件**：卡片被最大宽度封顶时（160pt、200% 下三个键就要 168pt），先让出 logo，仍放不下再把首行的 ‹ › 与展开键等分收窄，都留在卡片里、互不重叠；固定数量的卡片按首行定宽，不受影响。
- **全候选快照失败仍隐藏候选窗**：`allCandidatesWithError:` 只在会话已关闭、不在主线程、宿主调用重入或 runtime 内部 panic 时失败，`all_candidates()` 本身不返回错误、放出延后候选失败也只回已有部分，没有可恢复的短暂失败。回退到固定分页会多出「显示按固定页、按键按自动适应」的不一致状态，而同一个坏掉的会话也选不了词，因此不做回退。

自适应测量把候选内容宽度与序号栏分开，序号栏只按当前行的本地编号计算；换行重新从 1 开始，同一行达到两位数时同步扩展已有候选的序号栏。不能把全候选快照中的最大序号宽度塞进每格，否则显示时本地编号较短，差额就变成文字右侧的额外留白。皮肤最小项宽、用户内边距与滚动条占位仍参与测量。

滚动条占位只用于展开网格。未展开的单行没有滚动条，分页与实际排版只扣除窗口内边距和实际显示的翻页、展开按钮；不能提前扣掉展开网格的滚动条宽度，否则有空位也会少显示一项。短列表收窄时同样不追加这笔不存在的留白。

横向序号栏使用当前字体十个数字中的最宽字形乘以本地编号位数，测量与绘制共用该栏宽；保留原字体，不强制等宽数字。系统字体的数字 3 和 4 宽度不同，只按当前可见序号取最大值，会在候选数量从三项变成四项时移动所有候选的文字起点。同位数的栏宽不随候选数量变化，只有本地编号真正跨位数时才加宽；纵向继续沿用已有测量。

展开、收起用一条 `NSViewAnimation` 直接改变原候选窗的真实 `frame`（200ms），候选按钮按完整身份（会话、代次、索引）从旧位置移到新位置，不按文字匹配；`MSIMECandidateChromeView` 在尺寸变化时调整内容原点，保持顶部对齐。只有横向展开状态改变才播放；普通输入、选行、滚动和纵向同步更新，重排、隐藏或释放控制器时停止上一条动画。「减弱动态效果」沿用 `MSIMECandidateMotion.reduceMotion`，开着时直接到位。逻辑状态、命中和选择不等待动画。

快速连按展开/收起时，重画必须先记下候选当前看到的位置，再停止上一条动画。停止会清掉顶部对齐，窗口还在半途时旧内容整体按底部对齐，先停再记会让记下的位置差出「上一版布局高度 − 当前窗口高度」，左上角本应不动的第一项随之上下跳。

参考仓库 `SlimeNull/macOS-Style-PinyinInputMethod` 的默认分支 `master`，固定提交 `5b5e27a438d94ac6ffedfd423177285f38a12167`。仅参考 `CandidateWorldPanel.ColumnCount` 的布局行为与移动动效，不复制源码；该提交没有许可证。

## Alternatives considered

- 动态修改共享 runtime 的每页数量：可复用数字选词与翻页，但该接口只允许空闲时修改，且最大十项；按像素排布属于宿主，不应改变其他宿主的分页协议。
- 保留历史最大宽度：能减少抖动，但短词无法收窄，正是本次要去除的视觉缺陷。
- 同步缩窗再给内容挂图层裁剪与位移：窗口几何和命中立即就位，但旧网格已被真实窗口裁掉，收起过渡看不见。
- 截图覆盖窗：逻辑窗口可以立即切换并保留旧画面，但原窗与替代画面交接时真机仍闪烁，用户明确排除。

## Testing

设置顺序、横向可见性、配置保存与校验均有测试；真实原生控制器覆盖 160/400/600pt、50%/100%/200% 缩放与 3/6/10 列的矩阵，短列表收窄、跨列、翻页选择、纵向不变、滚动条留白与动画挂载。选择和导航的会话采用合成替身，纯布局测试验证一行可以超过十项，不把数字快捷键上限当显示上限。

右侧留白回归以 3、30、300 个合成候选检查首格宽度不受快照总数影响，并逐格验证文字之后只有既定内边距。纯布局测试覆盖本地序号从 9 到 10 时重测整行、放不下时换行重置序号，以及皮肤最小项宽。

单行装填阈值回归从真实按钮尺寸推算四个四字合成候选及展开按钮所需的精确宽度，验证恰好足够时显示四项、少 1pt 时只显示三项，并检查最后一项不覆盖展开按钮；展开网格的滚动条占位断言保持不变。

比例数字回归使用系统字体，在 18/32pt 与 50%/100%/200% 缩放下逐一改变一位数候选数量，检查序号到内容的起点保持一致；测试数据均为合成候选，不使用实际输入记录。

动画测试直接推进原窗口的动画进度（25%、75%、终点），验证动画目标就是同一个窗口、高度连续变化、内容顶部对齐，候选按钮起点对应展开前或收起前的位置；夹具含文字相同但身份不同的两项。完成回调由测试直接调用，不等真实时间：锁屏或熄屏时 `NSAnimation` 不前进。收起到 40% 再展开的回归检查第一项在新动画 0% 与 50% 时仍停在打断时的位置；先停再记的旧顺序在这里失败。

按需网格的回归用三千个合成候选：打开网格测量少于 400 项，连按 60 次下键和 5 次翻屏后累计仍少于全部，每步高亮都跟着光标；展开后正好排出 20 行；首行与网格里都没有行号；滚动视图照常显示滚动条；滚到已排末尾时文档变高、看到的首行不变、按钮不错位。缓存回归在两种模式下各按两次下键、一次右键、一次上键：固定数量一项都不再测量，自动适应只有下移可能追加一批；改最大宽度和列数后下一次移动照常重排。纯排版测试覆盖 `minimumRows` 与等宽列网格的按需前缀和全量逐行一致。

## Consequences

- 收益：横向数量与宽度独立于共享 runtime 的固定分页，不丢候选，也不改变纵向、其他平台或已有每页数量。长词跨列，短词可容纳更多；展开后的导航使用真实行边界而非下标除以固定数量。
- 代价：自适应每次排版仍取全候选快照（引擎会放出延后的候选并推进代次），但只测量到高亮所在行为止；翻到越后的页、网格往下走得越远量得越多，但每一步只量新增部分；固定数量的展开网格打开时仍测量全部候选；异步候选按新代次重测。自适应不显示总页数。固定数量不再遵循皮肤的横向最小宽度和多余的均分留白，预编辑在窄窗内截取；必要翻页控件仍占实际宽度。
- 动效只在展开状态切换时直接改变原窗口的 frame；普通输入更新、展开后的选行、滚动和重排不播放布局动画。目标布局与输入状态同步完成，真实窗口在 200ms 内抵达目标，内容始终顶部对齐。减弱动态效果关闭过渡。保留展开网格的滚动条占位，不把最大宽度再乘整体缩放。
- 验证边界：离屏原生宿主与合成会话不是安装后在真实编辑器中的验收；不替换用户的已安装输入法。
