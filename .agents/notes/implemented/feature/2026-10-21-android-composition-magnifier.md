# Agent Note: Android 拼写放大编辑与偏移光标手柄

Status: implemented

## Problem

#9016 要求点击输入框里的拼音后二次编辑，并用与光标拉开距离的右侧手柄拖动。触屏拼写移入输入框后，候选读音行的点击入口通常不可见；`onUpdateSelection` 把组字内部的选择变化也当作离开组字，取消引擎，无法继续修改。

## Decision

保留输入框中的拼写与固定候选位置。对仍有完整组字标记、可对齐的 ASCII 按键方案，将组字内的单点选择换成引擎光标命令，并打开放大编辑条。候选标题提供「编辑拼写」入口，覆盖输入框不回报同位置点击或不支持选择更新的情况。放大条只在编辑时显示，原字母键和退格继续作用于引擎光标；选词、取消、换输入框或结束会话后关闭。

放大条显示完整拼写的可滚动视口和闪动光标，下面的拖动手柄在光标右侧偏移，靠边时夹在可触摸区域；相对拖动而非绝对触点控制拼写位置，手指不会盖住当前字母。长拼写自动跟随光标，边缘持续拖动可到两端。复用现有 `CompositionCaretPolicy` 的拼音与九键数字映射，不复制引擎编辑状态。写回编辑器仍把系统选区置于组字末尾，避免破坏既有批量编辑读回与长度过滤器处理。

## Historical audit

- [组字光标点按](../../implemented/feature/2026-10-08-composition-caret-tap.md)：部分重叠，保留引擎命令和对齐规则；本篇接手当时延期的放大交互，双方互链。
- [触屏拼写入框](../../implemented/feature/2026-10-15-touch-composition-in-field.md)：部分重叠，默认展示决定不变；本篇只新增临时编辑入口，双方互链。
- 硬件光标候选、九键字号、输入长度过滤器等其他命中分别管理硬件布局、字体和编辑器拒写，不改变其决定。

## Alternatives considered

- 永久恢复候选读音行：任何输入框都能点，但重复拼写并改变已经确定的默认展示；临时编辑条只在需要二次编辑时出现。
- 让 Android 系统选区一直停在拼写中间：系统光标最直接，但既有编辑器桥按组字末尾读回完整拼写，部分编辑器的批量回报也会重置选区。编辑光标继续归引擎，放大条明确显示它。

## Verification

- 全拼和九键都能通过输入框组字内部点击及「编辑拼写」进入放大编辑，插入、退格不丢后缀。
- 偏移手柄可拖到长拼写的开头和末尾，靠边仍可触摸；直接点放大拼写可定位。
- 自己的选择回声不触发编辑；选区跨出组字、丢失标记、方案不支持时仍沿用原规则。
- `CompositionCaretPolicySmoke` 覆盖组字边界、前缀、分隔符、范围选择、丢失标记和截短；JVM 冒烟、远端 quick、原生 full APK 与 ABI 检查通过。
- Android API 28：`CompositionRestartDeviceSmoke -e magnifier true` 与默认套件、`CompositionBatchDeviceSmoke`、基础 `DeviceSmoke` 通过；实际放大条和右侧手柄已截图检查。旧 APK 在 Android API 35 的同一放大编辑专项失败。
- Android API 35：新版放大编辑专项通过；默认组字重启（含放大编辑）、批量编辑与基础输入回归也全部通过。运行 instrumentation 前按现有设备脚本先启动产品主进程，使用 `--no-restart`；逐项检查通过标记，不以 instrumentation 进程退出码代替断言。

## Consequences

临时编辑条增加 144dp 高度，只在编辑时占用屏幕；日常输入不重复显示拼写。输入框可能不回报同一点的点击，因此提供键盘内入口。组字内的真实文字修改不能误认成单纯选择，必须核对组字文本与范围。九键读音里分隔符不是按键，必须走现有对齐规则。
