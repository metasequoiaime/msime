# Agent Note: Android 拼写放大编辑与偏移光标手柄

Status: implemented

## Problem

#9016 要求点击输入框里的拼音后二次编辑，并用与光标拉开距离的右侧手柄拖动。触屏拼写移入输入框后，候选读音行的点击入口通常不可见；`onUpdateSelection` 把组字内部的选择变化也当作离开组字，取消引擎，无法继续修改。

## Decision

保留输入框中的拼写与固定候选位置。对仍有完整组字标记、可对齐的 ASCII 按键方案，将组字内的单点选择换成引擎光标命令，并打开放大编辑条。候选标题提供「编辑拼写」入口，覆盖输入框不回报同位置点击或不支持选择更新的情况。放大条只在编辑时显示，原字母键和退格继续作用于引擎光标；选词、取消、换输入框或结束会话后关闭。

放大条显示完整拼写的可滚动视口和闪动光标，下面的拖动手柄在光标右侧偏移，靠边时夹在可触摸区域；相对拖动而非绝对触点控制拼写位置，手指不会盖住当前字母。长拼写自动跟随光标，边缘持续拖动可到两端。复用现有 `CompositionCaretPolicy` 的拼音与九键数字映射，不复制引擎编辑状态。写回编辑器仍把系统选区置于组字末尾，避免破坏既有批量编辑读回与长度过滤器处理。

长拼写的设备夹具保持触摸按下，直到真实无障碍光标到达目标边缘再松手。两次边缘拖动各沿用原来固定拖住 5 秒加松手后断言 15 秒的总预算；按住期间与松手后的检查共用同一个截止时间，失败也必须在 `finally` 里松手。该检查不规定自动滚动必须在 5 秒内完成，仍严格要求完整拼写的两端都可达。每次边缘拖动前清理可用的无障碍缓存并刷新手柄节点，再读取触摸坐标；手柄随光标平移，前一段短拼写中的节点快照不能代表当前落点。Android 的 [`AccessibilityNodeInfo.refresh()`](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo#refresh()) 契约明确区分节点快照和 View 的最新状态。

候选读音节点的可见文字继续显示引擎读音，无障碍描述用于「编辑拼写」动作。十四键设备回归同时限定动作描述与可见文字，不能把动作描述当读音，也不能只按文字误匹配侧栏选项。

输入框里的全拼预编辑按宿主快照显示音节分隔符，放大条仍显示原始按键。中间插入 `h` 后，输入框精确期待 `nhi'hao`，退格后为 `ni'hao`；长拼写每组累加 `ni'hao` 并保留组间分隔符。设备夹具分别断言两种展示，不能把放大条的原始拼写用作输入框预期，也不通过删除分隔符或宽松匹配绕过展示契约。

## 斜指针补齐（#8633）

#8633 要求 45° 斜指针，并在后续评论中允许以大拼写、粗光标和远离文字的手柄代替独立放大镜。沿用本篇的编辑入口与相对拖动，只补齐手柄的视觉指向、触摸大小和留白。圆形手柄的触摸区为 56dp，中心向光标右下方各偏移 64dp，用原生 Canvas 绘制连接到光标下缘的斜杆与箭头；文字下缘和触摸区之间留 32dp。横向滚动提前为整只手柄留空间，右端不依赖夹紧手柄改变指针角度。手柄使用带按钮无障碍语义的自绘 View；皮肤遍历会给 Button 重新加矩形底，不能只在构造时清空背景。

新增设备断言要求手柄足够大、与拼写留出间距，并继续执行全拼、九键和长拼写双端拖动。长拼写夹具使用真实字母键分组输入，每组确认编辑器完整收到再继续，不以 shell 批量注入返回就认定四十个字母已经到达。明确安装含旧编辑器的基线 APK 后，API 28 在手柄尺寸断言失败；最终自绘圆手柄版本的同一专项通过，实际截图也确认无矩形底、斜杆准确连接光标下缘。宿主契约、258 项 JVM 冒烟及 222 份设备源码编译通过；API 35 的最终版本在逐组构造完整长拼写后通过整套专项，实际画面确认斜指针和圆手柄；API 28 也已以同一最终夹具通过；首次启动遇到的 System UI ANR 经选择等待后恢复，专项结果未跳过任何断言。完整 `scripts/verify-local.sh --quick` 已通过；首轮仅共享 Apple bridge 的缓存源码路径不匹配，改用本树标准 `target/apple-bridge` 配置并构建后，完整重跑通过。此前 #9016 的设备记录只说明旧版本，不能代替本次改动的验收。

## 端点验收的等待条件

在 #9124 的完整回归中，API 35 的四十字符拖动在固定五秒后松手，光标停在第 37 个字符而失败；同包在 API 28 通过。保持同一触摸并逐秒采样时，约 3.6 秒到 33、5.2 秒到 39、6.2 秒到 40，说明逐字移动经过真实引擎和界面刷新，固定手势时长把机器负载写进了断言。短串与长串都在保持触摸时等待无障碍选区到达目标端点；短串使用原十五秒等待预算，长串保留原五秒触摸加十五秒等待的二十秒总预算；无论通过或失败都在 `finally` 松手，松手后的端点断言保留。加长固定等待最容易改，但仍依赖机器速度，因此不采用。

端点等待修正后，同一产品 APK 在本任务独占的 API 28（`emulator-5602`）与 API 35（`emulator-5594`）通过完整放大编辑专项，覆盖全拼、九键、中间插删、短串与长串两端拖动。诊断采样只使用合成字符的位置和长度，临时采样代码不进入提交；完整平台冒烟仍单独核对终态。

组字宿主显示改用[引擎分节](../bug-fix/2026-10-23-quanpin-host-preedit-segmentation.md)后，设备断言分别核对输入框的 `nhi'hao`／`ni'hao` 与放大条的原始 `nhihao`／`nihao` 及光标位置。长串按已知合成音节检查完整分节显示，再逐字核对放大条四十字符和尾端选区；不删除分隔符后模糊比较，避免漏掉真实后缀丢失。

- 硬件光标候选、九键字号、输入长度过滤器等其他命中分别管理硬件布局、字体和编辑器拒写，不改变其决定。

## Alternatives considered

- 永久恢复候选读音行：任何输入框都能点，但重复拼写并改变已经确定的默认展示；临时编辑条只在需要二次编辑时出现。
- 让 Android 系统选区一直停在拼写中间：系统光标最直接，但既有编辑器桥按组字末尾读回完整拼写，部分编辑器的批量回报也会重置选区。编辑光标继续归引擎，放大条明确显示它。

- 旋转整个系统按钮：无需自绘，能直接得到倾斜外形；但按钮的触摸边界与视觉矩形不一致，按钮也不能准确连到当前光标，故保留轴向触摸区并单独绘制斜指针。
- 额外叠加系统放大镜：能复用系统文字放大体验；但这里本来就是放大的自绘拼写，叠层仍可能遮挡输入，且 #8633 已明确接受拉开距离而不加放大镜，故使用现有编辑条。

- 用 `input text` 一次注入长拼写：夹具准备最快，但 API 35 的一次验收实际只收到 28 个字母，shell 命令返回不足以证明 40 字母夹具成立。改为逐组触屏输入并确认编辑器内容，代价是更多界面交互，收益是失败能定位到输入准备或拖动本身。
- 固定拖住 5 秒后松手，再等光标到达：操作简单，但 API 28 的实际诊断在松手后只到第 32/40 位；松手已经停止边缘滚动，后面的等待无法补齐手势。改为在同一总预算内等待真实位置，额外成本是拖动期间查询无障碍状态。

## Verification

- 输入框分词断言的修正已在 API 28 的同一固定原生开发包上做修改前后对照：旧夹具在中间插入后的编辑器文本断言失败；修正后的完整放大镜专项通过，包含全拼中间插删、长拼写两端和九键。原生包前后摘要相同，测试结束恢复原夹具包；该对照不代表重建了最新原生宿主，也不替代默认完整 smoke。
- 全拼和九键都能通过输入框组字内部点击及「编辑拼写」进入放大编辑，插入、退格不丢后缀。
- 偏移手柄可拖到长拼写的开头和末尾，靠边仍可触摸；直接点放大拼写可定位。
- 自己的选择回声不触发编辑；选区跨出组字、丢失标记、方案不支持时仍沿用原规则。
- `CompositionCaretPolicySmoke` 覆盖组字边界、前缀、分隔符、范围选择、丢失标记和截短；JVM 冒烟、远端 quick、原生 full APK 与 ABI 检查通过。
- Android API 28：`CompositionRestartDeviceSmoke -e magnifier true` 与默认套件、`CompositionBatchDeviceSmoke`、基础 `DeviceSmoke` 通过；实际放大条和右侧手柄已截图检查。旧 APK 在 Android API 35 的同一放大编辑专项失败。
- Android API 35：新版放大编辑专项通过；默认组字重启（含放大编辑）、批量编辑与基础输入回归也全部通过。运行 instrumentation 前按现有设备脚本先启动产品主进程，使用 `--no-restart`；逐项检查通过标记，不以 instrumentation 进程退出码代替断言。

- 十四键旧选择器在固定基线与修复包上同样失败；按动作描述和可见文字分别定位后，API 28、35 的完整十四键套件通过，包含窄屏与实际选词提交。
- #9473 的 API 28 完整 smoke 在长拼写拖动失败，仓库外阶段诊断确认右边缘松手时为第 32/40 位。保持按下并等待目标的初版夹具完整 quick 已通过，但 API 35 的完整专项仍在右端失败。只运行逐键长拼写、并在左拖前清理节点缓存的定向诊断在 API 35 到达两端；该结果不能代替完整专项。补齐每次拖动前刷新手柄坐标后，API 35 完整组字放大专项通过，覆盖短拼写、中间插删、长拼写两端与九键；产品 `bbb30d848d066a14b22056e0b7d1621d5ecb9bbc6ca166ad1bc0bae294f1a242` 和夹具 `6fd71c9f05386260cad00c113c8284ab507957fcdce0a12adf45ba456d4ba0c7` 的安装前后哈希一致，原始 instrumentation 为 `-1`，结束后恢复原包并核对。API 28 和本轮完整 smoke 仍待复验。API 28 的后续复验遇到设备被其它会话换包，安装哈希守卫中止的运行不计通过或产品回归。

## Consequences

临时编辑条在通常字体比例下增加约 182dp 高度（大字体时继续自适应），只在编辑时占用屏幕；日常输入不重复显示拼写。输入框可能不回报同一点的点击，因此提供键盘内入口。组字内的真实文字修改不能误认成单纯选择，必须核对组字文本与范围。九键读音里分隔符不是按键，必须走现有对齐规则。
