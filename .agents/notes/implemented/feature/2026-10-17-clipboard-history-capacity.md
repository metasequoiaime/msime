# Agent Note: 剪贴板历史容量可选档位

Status: implemented

## Problem

本机剪贴板历史的容量分散在各平台实现：Windows 默认 50 条，移动端固定 200 条，用户不能按自己的存储和隐私需求选择。移动端还共享同一份历史文件，平台各自复制上限会导致同一份文件在不同宿主显示不一致。

这项决定取代[移动端剪贴板历史扩展到 200 条](2026-10-15-mobile-clipboard-history-limit.md)；原笔记中记录的共享文件边界和固定优先规则仍然有效。

## Decision

在共享偏好中增加本机字段 `clipboard_history_limit`，档位固定为 50、100、200、500、1000，缺省为 50。共享 Rust 存储按调用方传入的有效档位裁剪、去重和淘汰，固定条目继续优先保留；平台设置页只负责选择档位和显示当前值。容量字段与剪贴板开关一样只属于本机，不导出到跨设备设置文件。

## Alternatives considered

- **只修改 Windows 的 50 条常量** — 改动最小，但 Android、iOS 和 HarmonyOS 共享同一移动历史文件，平台之间仍会出现不同容量规则。
- **把容量继续写死为 200 条** — 能缓解当前限制，但不能满足用户按存储和隐私需求调整的要求，也无法覆盖 50、500 和 1000 条的使用场景。
- **让每个平台自己保存容量和裁剪历史** — 可以避免扩大 Rust 接口，但会重新复制去重、固定和淘汰规则，容量变化时容易产生跨平台漂移。

## Verification

- 偏好缺少或写入非法容量时使用 50；合法档位可被各宿主保存并读取。
- 共享存储读写、固定、删除、编辑和清空均遵守当前档位；降低档位后只返回按固定优先规则保留的记录。
- 共享设置页、Windows 原生设置、Android 原生设置和 iOS 原生设置提供相同档位；移动端键盘显示的容量与共享偏好一致。

## Consequences

容量提高会增加一次读取和返回的 JSON 大小；共享存储继续使用绝对文件和文本边界，平台解析上限覆盖 1000 条结构化结果。

## Risks

历史容量提高会增加一次读取和返回的 JSON 大小；共享存储继续使用绝对文件和文本边界，平台解析上限必须至少覆盖 1000 条的结构化结果。
