# Agent Note: 鸿蒙手机冷启动恢复简短开屏动画

Status: implemented

## Problem

用户在真机指出启动时没有动画。现有实现明确把动画限制在首次欢迎流程，设备写入已播放标记后只显示静态原生盖板。旧的完整开屏停留 2.8 秒，也不适合每次打开设置。

## Decision

鸿蒙手机每次新建设置文档时播放同一套品牌开屏，时长 1.4 秒，可点击跳过。底色继续跟随系统深浅色，标志和圆盘沿用系统启动窗的第一帧，季节配色通过现有主题解析。开屏由文档会话内的组件状态管理，与磁盘上的首次播放标记无关；后台恢复、页面切换和重放新手引导均不重播。首次引导在开屏之后直接进入第一步，二合一维持现有桌面入口。

本篇部分取代[启动画面跟随系统外观且只首次播放](2026-10-11-harmony-launch-follows-appearance.md)的播放时机；其深浅色、完整标志和无白闪盖板继续适用。[每次启动播放](2026-10-11-harmony-launch-splash-every-start.md)与[启动画面连续性](2026-10-11-harmony-launch-one-picture.md)的视觉衔接继续复用，不恢复深色硬编码或 2.8 秒等待。

## Alternatives considered

- 直接恢复 2.8 秒完整动画：能复用欢迎流程，但此前已因每次打开等待过久被否，改用缩短节奏的同一动画。
- 只重置首次播放标记：最多再次播放一次，且会把启动动画继续绑在欢迎流程上，无法满足后续冷启动。

## Verification

- 两个源码基线上的开屏与引导测试均通过 33 项，覆盖新文档重新播放、1.4 秒自动结束、点击跳过、同次挂载内页面变化与前台恢复不重播、二合一直接进入页面和深浅色系统栏。
- 桌面与鸿蒙两套 TypeScript 类型检查、Lint、`verify-notes`、启动画面连续性契约、`git diff --check` 和本地 quick 门禁通过。
- 安装基线保留真机原有原生库与桥接接口，应用本补丁后重新构建设置页和 HAP；包内 HTML 与该基线构建产物逐字节一致。HAP 与代码签名校验通过，覆盖安装成功，原有社区入口清理仍在包内。
- 真机解锁后连续两次强制停止并重新启动，逐帧看到原生标志过渡到季节圆盘、文字与进度条动画，随后进入设置。返回前台没有重播开屏。截图仅用于本地查看，验收后删除。

## Consequences

普通冷启动增加最多 1.4 秒可跳过的动画展示；减少动态效果的系统设置仍由现有样式遵守。
