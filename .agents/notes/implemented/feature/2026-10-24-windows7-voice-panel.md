# Agent Note: Windows 7 原生语音录音与结果审阅面板

Status: implemented

## Problem

Windows 7 没有共享 WebView 面板承载。原生 Server 已持有麦克风、识别、润色与焦点租约，已有控制协议专门把审阅结果交给面板；另写一套录音与识别管线会使设备选择、静音、提示音和取消规则分叉。

## Decision

经 Host API 暴露现有 `host-windows::voice_controller` 的阻塞识别和独立停止／取消信号，Win32 面板只负责状态、音量、用户开始／结束／取消、结果编辑、复制与最终输入。Server 始终拥有录音与原始焦点租约，审阅模式不执行自动上屏；面板是唯一最终提交方。

创建时返回不复用的会话句柄，容量有限；识别仅消费一次，停止／取消可在任意线程发生。关闭移除句柄并置取消，正在执行的工作仍持有自己的原子信号，不能取消新会话。回调在调用线程执行，内容只在回调期间有效；所有网络、管道、配置读写均在工作线程，不记录或落盘音频、识别文本与凭据。

窗口录音时不激活，结束后允许编辑结果。向原编辑器提交沿用原生面板的前台核对，失败不重放；复制不计统计，成功输入才记录语音来源统计。关闭先取消再等待工作线程退出，未完成与过时的结果不能再操作。

## Alternatives considered

- **让面板自行通过 WASAPI 录音。** 可以独立于 Server 运行，但会复制现有设备选择、静音、提示音、流式识别和焦点租约，无法保证与原生热键录音一致，因此复用专用语音控制协议。
- **直接在 Win32 中另写管道客户端。** 可以避免增加 C ABI，但共享 Rust 已有同用户／会话认证、有界 I/O、取消与协议校验，重写会扩大认证与生命周期维护面，因此只增加同一实现的宿主接口。

## Consequences

共享层的五项测试在 x86／x64 Win7 Rust 目标通过：容量、单次消费、关闭后旧信号存活、语言边界、预先取消和连接回调重入关闭；均不访问真实麦克风。两架构 clippy 通过。原生面板各八套窗口回归通过，新增测试覆盖读取已应用语言、音量与阶段、录音期间只读、不激活窗口、结果编辑、复制与输入的统计差异、取消后故意返回成功、工作线程完成但消息仍在队列中的取消，以及关闭时取消并等待线程。工作线程与 C ABI 不抛出跨边界异常，进度只保留最新一帧。

取消立即在 UI 标记结果失效，不依赖控制句柄仍存在；否则识别已经结束但完成消息未分发时，取消会被已关闭句柄拒绝并把迟到结果显示出来。按键的双击消息也走不抢焦点的按下／释放路径，屏幕键盘同步使用同一规则，并有实际 HWND 测试覆盖。完整 x64／x86 面板的已知阻断导入检查分别覆盖 284／279 项；这些检查不代表系统全部导出已在 Win7 验证。

Windows 7 SP1 x64 桌面已运行两个架构的原生窗口回归并通过，包含语音面板的合成协议及取消回归；产品入口和完整安装包已集成。同源本地识别库对固定 SAPI 合成语音产生非空转录，真实合成 TLS／WebSocket 传输通过。VM100 加入 HDA 虚拟声卡后，双架构核心和同源 Server 的录音、播放渲染及提示音专项通过；窗口测试自身仍使用合成协议，不代表物理麦克风、扬声器或付费识别服务验收。早期 Linux 时限失败之后的完整 quick 已通过，最终门禁见[产品构建](2026-10-24-windows7-product-build.md)。
