# Agent Note: 十四与十八键的网格辅助码

Status: implemented

## Problem

十四／十八键的一个字母键代表两个字母，组码本身就有歧义，同音字词多时只能翻页找。26 键的辅助码靠在原始按键串末尾接大写字母或触发键，网格组字的组码串里没有这样的位置：组码是每组的代表字母，十八键双拼的大写已经是精确字母标记（[十八键双拼横滑](2026-10-24-eighteen-key-exact-swipe.md)），再塞辅助码会和组码、选词推进、退格恢复缠在一起，也会漏进组字区和上屏文字。

## Decision

辅助码作为组码之后的独立条件，由组码会话持有，不写进组码、预编辑、上屏文字或句子种子。

### 状态与入口

- `NineKeySession` 只多一个字段 `helpcode: Option<GridHelpcode>`：`None` 是没有分隔符，`Some` 且零槽是只有分隔符，最多两槽。每槽是键面上的整组字母，可以确定成组内一个字母。码表和一码严格偏好在放下分隔符时取定，组字中途改设置从下一次组字起生效。
- `Session::grid_helpcode(GridHelpcodeOp)` 有四种操作：`Begin` 放下分隔符，`Group` 追加按下的键上的整组字母，`Exact` 追加确定字母（给十八键双拼横滑这类已有的精确字母手势用），`Clear` 清掉。放下分隔符后组码不再变，`grid_key` 一律未处理，宿主把字母键改送 `Group`；两槽已满时再来的 `Group`、`Exact` 已处理、不变化。`Group`、`Exact` 只收小写：26 键双拼一码的大写是「尾字优先」，网格辅助码的大写留给与它一致的含义。分隔符之前 `grid_key` 照旧，十八键双拼的大写仍是主码的确定字母。长按字母弹层照旧结束组字再上屏字母，不进辅助码槽。
- 开关是 `SessionOptions::grid_helpcode`，默认关；还要求当前方案的辅助码开着、码表非空。九键、九键双拼和五笔十四键不接受，所有操作都返回未处理，候选修订号也不变。
- 有分隔符时快照的拼音选择区（`nine_key_spellings`）换成整串解释，按键面顺序展开，第一槽在外层；选中一项（`choose_nine_key_spelling`）一次锁定各槽，不上屏，宿主沿用拼音选择的代次校验。只有分隔符或各槽都已确定时没有解释。拼音选项仍留在会话里，去掉分隔符后照旧显示。
- 退格先删槽、再去掉分隔符，这两次都不删组码；点分词键先清辅助码再照旧切分；选词、部分选词、取消、换方案或网格、移光标、向后删除、启用笔画筛选都清掉辅助码。放下分隔符时清笔画筛选，单字筛选保留。
- 快照多三个字段：`grid_helpcode_display`（`|Q[ER]` 这样的显示，全拼都大写，双拼首码小写、次码大写，只是显示）、`grid_helpcode_available`（这次组字能不能用）和 `grid_helpcode_constrained`（至少一槽、候选是筛过的，下游不能再跨行重排）。

### 匹配与候选

- 复用 `match_single_helpcode`、`matches_double_helpcodes` 取码，不另写取码规则。槽里多个字母按并集匹配。两码按码序严格匹配。一码不严格时首码（或首尾都）命中、只有尾码命中、都不中依次排；严格时都不中的筛掉，全拼只筛不排，双拼仍让首码命中的在前，与 26 键的一码规则相同。
- 至少一槽时，刷新在查询和基础排序（含键盘模型整句重排）之后另走一段收尾：在整张已查到的列表上筛排，按覆盖再按等级稳定排序后截到 `CANDIDATE_LIMIT`，再照[粗俗词政策](../bug-fix/2026-11-04-vulgar-first-page-and-english-second-slot.md)挪出首屏。普通路径的截断位置不变。固定位置、[首页补全折算](../bug-fix/2026-10-27-nine-key-completion-discount-on-first-page.md)、[裁决标记](2026-10-29-nine-key-model-contests.md)、句子种子和英文、表情、日期混入都不做：它们为没有条件的列表而设，作用在筛过的列表上会跨过匹配等级。
- 筛后列表里选词不调词频、不记[最近选择的位置](2026-10-17-nine-key-recent-candidate-priority.md)，那里的下标和普通列表的不是一回事；造词和个人上下文照常记。筛选时不能置顶、删除或固定位置。
- 有条件而筛空时分两类。用户结束一个词的键（首选上屏、标点、网格组字中的其它字符键如空格和数字）都已处理、不上屏，组字留着，免得边界键先上屏、组字留在后面。宿主在插入别的内容（符号面板、剪贴板、表情、工具栏、焦点变化等）之前结束组字用的原样上屏和 `finish` 丢掉这次组字、什么也不上屏：十四／十八键的组码是每组的首字母，不是用户想写的字母，当原文上屏只会多出一串乱码，而留着组字又会让插入的内容排到这次组字前面。有候选时数字照旧按当前页选词，与码数无关；原样上屏照旧按首选结束。

### 偏好、runtime 与宿主接口

- 偏好是 `quanpin_helpcode.grid`、`shuangpin_helpcode.grid`（`HelpcodePreferences::grid`），默认关、关着时不写进文档，按会话实际跑的方案取一份，经 `EngineOptions::grid_helpcode` 进 `SessionOptions`；改偏好与其他辅助码设置一样在空闲时重建会话。
- runtime 的 `Action::GridHelpcode` 转交引擎；视图多 `grid_helpcode_available`、`grid_helpcode_display` 两项，为假或为空时不出现。`grid_helpcode_constrained` 只留在快照里：为真时 `order_presentation`（逐键重排、句首语气词、读法降位、在线座位）、落定重排和脚本插件的重排、隐藏都不运行，免得跨过匹配等级。网格组字本来就不发在线请求，不另加限制。
- C 接口新增 `msime_client_grid_helpcode(session, op, letter)`（ABI 3 只增），`op` 0、1、2、3 对应 `Begin`、`Exact`、`Clear`、`Group`，其他值报错。

### Android

- 规则集中在 `GridHelpcodePolicy`（JVM 冒烟 `GridHelpcodePolicySmoke`），JNI 是 `NativeClient.gridHelpcode`。
- 十四／十八键的分词键改为能画角标的键：这次组字能用（`grid_helpcode_available`）时右上角画「辅」、读屏说明上滑；上滑过 24 dp（与十八键横滑相同）放下分隔符，没滑过时点按照旧（`ImeGridHelpcodeEntry`）。
- 视图的 `grid_helpcode_display` 非空就是放下了分隔符：字母键改送 `Group`，十八键双拼横滑的大写改送小写的 `Exact`；读音行在读音后面接上这段显示，不写进输入框；拼音选择区的读屏改说「选择辅助码」。
- 系统返回键在放下分隔符、键盘显示、没有符号面板或展开候选盖着时，第一次只 `Clear`，组字和键盘留着。
- 结束组字的入口按上面两类走引擎，宿主不另做判断：空格（软键盘和实体键都是命令 1）、标点、数字由引擎留着组字；长按字母、快捷符号、符号面板、剪贴板、表情、工具栏、文字编辑面板、中英切换、OCR、手写笔和焦点变化照旧先发命令 2 或 9，筛空时由引擎丢掉组字再插入。只有回车（软键盘和实体键都经 `enter`）在筛空时不发命令 2、直接留着组字，与空格、标点一致（`GridHelpcodePolicy.holdsEnter`）。
- 设置页开关尚未接入。

## Alternatives considered

- **在组码串里接辅助码，像 26 键那样解析**：能复用 26 键的触发与解析。但网格组码是代表字母，十八键双拼的大写已是精确标记，一槽里有多个允许字母也没法写进单个字符；辅助码还会随组码进组字区和上屏文字。所以只复用取码与匹配。
- **宿主持有槽并自己筛候选**：手势接线最短。但分页、选词推进、旧动作和主码编辑会有两份状态，其他宿主也不能复用，所以状态归引擎。
- **在已截断的 128 行里筛**：对现有流水线改动最小。但本轮已查到、却排在第 128 行之后的目标永远进不了列表，所以有条件时先筛后截。
- **有分隔符时 `grid_key` 按状态分流，小写进辅助码槽、大写当确定字母，不要 `Group`、`Exact`**：宿主的字母键不用分辨状态，接口也少两种操作。但同一个 `grid_key` 的意思要看调用方看不见的分隔符；网格里大写就成了「确定字母」，26 键双拼一码的大写却是「尾字优先」，同一种输入在两类键盘上意思不同，以后网格也没有大写可用来表达尾字优先；十四键和十八键全拼的 `grid_key` 还得只在有分隔符时收大写；以后九键的数字从 `character` 进，还要再在那里分流一次。只有调了 `Begin` 的宿主才会进辅助码，它本来就知道状态，按状态换操作不多花什么，放下分隔符后还送 `grid_key` 的宿主会马上看到未处理，而不是悄悄填了槽。所以 `grid_key` 只管主码，辅助码只从只收小写的 `Group`、`Exact` 进，大写留着。
- **另起一个选择动作和快照列表放整串解释**：语义独立。但要新增一套选择接口、代次校验和界面，宿主已有的拼音选择区正好在同一位置，所以复用它。

## Consequences

- **收益**：状态只有一处；网格接线只是组码会话里几处转交，普通组字路径和截断位置不变；宿主只需画分隔符、接进入手势和精确字母，选择区、代次校验沿用现有的。
- **代价与已知上限**：有条件时要对整张已查到的列表求等级、排序，查询预算不变，预算之外的词仍然出不来。组字中途改码表不立即生效。九键的数字到辅助码字母、九键双拼的键面都没有设计，要接入需另行决定。显示繁体时仍按原字取码。

## Verification

`crates/engine/src/session/tests/grid_helpcode.rs` 用合成词库覆盖四种键盘的进入、整组与确定字母、有分隔符时拒收网格键和大写字母、整串选择、满槽、退格、分词、选词、筛空吞键、筛空时宿主结束组字丢掉组字而有候选时原样上屏按首选结束、有候选时数字交还、严格与不严格一码、两码、笔画与单字筛选、粗俗词挪位、学习与候选管理、码表取定、128 行之外的已查到目标，以及九键和功能关闭时一律拒绝、开关打开或只有分隔符时与普通组字相同。普通九键、十四／十八键与 26 键的既有回归和参考回放（`golden`）照旧通过。`crates/input-runtime/src/tests/grid_helpcode.rs` 用真实引擎走动作、视图字段和整串解释的代次校验，并以对照证明落定模型在普通列表里会挪行、在筛过的列表里不动；`candidate_transform.rs` 的跳过用例覆盖脚本插件。`crates/host-api/tests/grid_helpcode.rs` 经 C 接口验证偏好接线、默认关闭和非法操作。
