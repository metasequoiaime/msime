# Agent Note: 本地词库查询兼容中文词条

Status: implemented

## Problem

#8301 的本地词库管理只接受编码前缀，记得中文词条时无法定位内置行。界面把未执行查询与查询无结果都显示成「点击查询」，使搜索是否完成也不明确。

## Decision

沿用现有 `query` 字段：ASCII 查询保留编码前缀、大小写和拼音分隔符规则；含非 ASCII 字符的查询按词条字面包含匹配，不把 `%`、`_` 当通配符。引擎在只读 SQLite 查询中完成筛选、排序和分页，拼音词条搜索覆盖所有首字母与音节表，包括溢出表；个人词条查询保持同样的匹配语义。无需修改数据库或新增索引。

共享设置页将输入框改为「词条或编码」，对旧宿主未筛选响应保留种类与查询核对，但词条搜索不再误用编码前缀规则。空列表采用查询状态：未查、查询中、无匹配和失败各自明确。

## Related decisions

- [词典空页缓冲](../../implemented/testing/2026-10-10-bundled-dictionary-lazy-buffer.md)：部分重叠，保留只读查询、结果首次命中才分配整页和现有排序契约。
- 其余按「编码前缀」「本地词库管理」检索到的笔记涉及辅助码、候选和导入，不改变本次查询契约。

## Alternatives considered

- 显式增加查询模式能同时支持英文文本与英文编码，但需要每个调用方新增控件或协议字段；当前需求是中文词条，沿用字符类别判断兼容现有调用方。
- 在设置页拉取整库再筛选最易实现界面，但会漏掉未加载分页并复制业务规则，改由 Rust 在分页前筛选。
- 给每张词库表建立词条索引可加速精确查找，但包含查询不能直接使用普通 B 树，还会改变资源格式与只读查询约束，当前不采用。

## Consequences

中文查询覆盖内置与个人词条，并在分页前完成匹配；编码查询保留原有规则，查询不创建或修改词库与 journal。未查询、查询中、无匹配与失败各有明确提示。ASCII 词条仍按编码解释，需要英文文本搜索时再扩展显式查询模式。

词条包含查询需要扫描所选种类的表，成本高于编码索引。仅在用户主动查询时执行，保留长度和分页上限，避免整库传输；本次不修改数据库格式，也不扩展原生平台设置界面。
