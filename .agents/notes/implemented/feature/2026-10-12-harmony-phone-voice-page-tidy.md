# Agent Note: 鸿蒙手机的语音页只留常用设置，服务的细节收进「服务配置」子视图

Status: implemented

## Problem

鸿蒙手机的「语音输入」页从上到下摊着六组：识别、识别服务、录音行为、识别结果、文本润色、录音设备。「识别服务」一组就有：

- 接入说明按钮、空的识别模型输入框；
- 豆包鉴权方式，流式接口和它的四行解释，`wss://` 接口地址；
- API Key、资源 ID、更多选项、测试配置；
- 一段讲 16 kHz 采样和 CoreSpeechKit 的页脚。

「录音设备」里有录音后端、读取录音设备、一段讲设备类型与地址的长说明。仓库负责人看到后要求「优化整理」。这些开关鸿蒙键盘都实现了（提示音、开始/结束提示音、静音、流式预编辑、录音设备、润色），所以只改排版，不删功能。

## Decision

- 主页面只有三组：
  - **识别**：识别语言、自动添加标点、边说边显示（原「流式预编辑」，从「识别结果」组挪来）。
  - **识别服务**：语音输入开关、识别服务、「服务配置 ›」。右侧显示状态：网络服务看 `asr_token` 有没有填（已填写 / 未填写），豆包按键盘同一套判断显示「未填写，暂用系统识别」「未填写完整」或「已填写」（见[豆包凭据没填全时不再悄悄改用系统识别](../bug-fix/2026-10-12-harmony-doubao-missing-credential.md)），本地识别看 `asr_model_path`（已选模型 / 未选模型）。系统识别不用配置，不画这一行。
  - **录音**：提示音、录音时静音其他声音。
- 「识别服务」组的页脚改成一句普通话，按服务说用的是什么、要不要配置、去哪配置（`harmonyPhoneVoiceFooter`）。2in1 和桌面的说明不变。
- 「服务配置」是语音页上的子视图，做法同「浏览更多」图库：全屏覆盖，标题前带返回，压一条带 `voiceService` 的历史记录，系统返回先关它，离开语音页时随之关上。里面依次是：
  - 识别服务的全部配置（接入说明、模型、鉴权方式、流式接口、接口地址、密钥、资源 ID、更多选项、本地模型、测试配置）；
  - 文本润色；
  - 提示音（开始、结束，总开关关着时变灰）；
  - 录音设备。
- `LinkRow` 新增可选的 `value`，画在 › 前面，并挂在 `aria-describedby` 上。
- 桌面语音页照同一分法收进「服务配置」子视图，子视图在页面里换上来而不是全屏覆盖，见[精简语音输入设置页](../simplification/2026-10-16-macos-voice-settings-prune.md)。
- 「服务配置」里的「提示音」组（开始、结束）后来随 `voice_cue_switches` 收起：键盘只看总开关；「录音设备」改成一个「麦克风」下拉。原因见[精简语音输入设置页](../simplification/2026-10-16-macos-voice-settings-prune.md)的「各平台跟进」。

## Alternatives considered

- **把这些项直接删掉。** 都有实现，有人在用（填密钥是用豆包的前提），删掉就配不了服务。
- **用「更多选项」折叠区原地展开。** 展开后页面一样长，而且密钥、接口和录音设备混在一个折叠区里没有分组。
- **为每样东西各开一个子页面。** 层级太多；会去配置服务的人一次就会把这些都看一遍。

## Consequences

- **收益**：主页面一屏放下，普通用户只看到语言、标点、开关、选服务和两个录音开关；服务没配好时，「服务配置」行直接写着「未填写」。
- **代价**：配置服务要多点一下。提示音细分和录音设备藏在「服务配置」里，名字上不太对得上；它们很少要改，换来主页面干净。

## Verification

- `apps/desktop/tests/settings/voice-handwriting-harmony.test.tsx`：
  - 主页面只有「识别」「识别服务」「录音」三组，看不到密钥、流式接口、录音设备、提示音细分、文本润色；
  - 「服务配置」显示「未填写」，点进去能看到这些，返回回到语音页；
  - 系统识别没有「服务配置」行；
  - 原来测流式接口、密钥行、录音设备、润色方案的用例改为先打开「服务配置」。
- `apps/desktop/tests/settings/mobile-app-chrome.test.tsx`：手机不列语音快捷键（#7210 改了行为，这个测试当时没改，develop 上一直是红的，见下）。
- `apps/desktop/tests/input/host-capabilities.test.tsx`：两个测能力的用例改用 2in1，它们测的是能力不是手机排版。
- HarmonyOS 6.0.2 phone 模拟器：语音页一屏放下，「服务配置」显示「未填写」，点进去是全部配置；系统返回键先关子视图，回到语音页。

CI 不跑前端的 vitest，只有本地 `verify-local.sh` 跑，推送前钩子的 `--quick` 也没拦下 #7210 让 `mobile-app-chrome` 失败的那次，这个缺口还没补。
