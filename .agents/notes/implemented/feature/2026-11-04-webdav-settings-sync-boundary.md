# Agent Note: WebDAV 设置同步核心边界与密文契约

Status: implemented

## Problem

#10787 要求用用户自己的 WebDAV 同步设置和主题。完整偏好不能直接上传：其中包含窗口位置、宿主能力、模型路径、账号会话和网盘凭据；主题还可能引用只存在于本机的皮肤包。此前只有设置文件导出会排除本机段，没有独立的 WebDAV 设置域契约。

## Decision

本篇记录已落地的核心契约；[完整设计](../../proposed/feature/2026-11-04-webdav-settings-theme-sync.md) 仍是后续实现范围，不因核心切片落地而视为完成。

第一阶段在 `client-core::settings_sync` 建立无网络的文档投影和三方合并契约。输入必须是已经通过 `Preferences::validate` 的类型化偏好，输出固定为 `app.msime.settings-sync`、版本 1 的 JSON 文档，分成 `shared` 和 `theme` 两个对象；读取外部文档时严格检查格式、版本和域边界。

`settings_sync/fields.rs` 逐项列出可共享字段，只有显式白名单和主题字段进入网盘，未知字段一律留在本机。账号凭据、网络代理、语音/AI、云剪贴板和词库 WebDAV、宿主快捷键、窗口位置、设备布局尺寸、本机插件和皮肤库引用均不上传；此边界比用户主动导出的设置文件更严格，不改变现有导出格式。主题字段单独放进 `theme`；自定义主题保留可移植定义，删除 `candidate_skin` 和 `candidate_skin_dark` 这类本机皮肤库引用。文档上限为 1 MiB，超过上限直接失败，不截断、不静默丢弃。

三方合并按字段比较基线：一端未改时采用另一端的修改，两端同时改同一字段时保留本地值并返回冲突清单。删除使用显式墓碑，所有因序列化省略的默认字段也写为墓碑；外部旧文档未提供的字段沿用基线。应用到本机时墓碑恢复该字段已有的出厂默认值，自定义主题则只保留本机皮肤引用，避免恢复默认后又被旧主题覆盖。同步文档应用回本机时复用设置文件导入的未知字段、版本收窄和一次性迁移规则，本机字段始终保留。

事件信封固定为 `app.msime.settings-sync-event`、版本 1，带设备摘要、单调序号、父事件 SHA-256 和文档正文。核心验证大小、字段格式、偏好类型与取值和哈希链。`settings_sync/crypto.rs` 从独立的设置密钥串用 `msime-settings-v1-key` 派生密钥，用 XChaCha20-Poly1305 加密事件；nonce 由生产入口从系统生成。格式、版本、密钥编号、序号、设备和父哈希全部绑定到 AAD，密文解析前后都受大小限制；待批准的设备没有可用密钥。自动触发和原生设置页接入继续作为后续切片；本阶段不新增 `packages/ui` 设置入口，也不改变任何默认值。

服务层 `client-services::settings_webdav` 复用现有 WebDAV 请求和 MOVE 独占创建；密钥串另起 `msime-settings/keyring/`，文档日志放在 `msime-settings/v1/`。每轮先核对批准、拉取并验证链头，再独占追加密文、按偏好修订号应用并私有落盘基线；冲突整轮暂停，双方都保留。每轮刷新密钥缓存但保留链头和防回退记录，避免配对后立即批准仍被短缓存误判为设备不存在。先追加再写回本机，防止抢号失败后把已下载的远端值误当成本机修改，覆盖竞争设备的新选择；合成双设备回归在旧顺序下失败，修正后验证重试仍保留竞争设备恢复的默认值。

`settings_webdav/transaction.rs` 在任何远端追加或偏好写回之前先私有落盘 `settings-sync-pending`，依次记录准备发布、已发布、明确未写回三种阶段，再推进基线并清理。日志仅保存有界的可移植投影、偏好修订和事件，绑定网盘、账号空间与设备身份。MOVE 响应丢失通过重读计划事件确认；已应用下载通过目标投影确认；明确未写回时用已发布前的本机投影推进基线。这样进程重启不把已下载设置误当作本机编辑，也不重复发布已有事件。

偏好与基线无法跨文件原子提交；中断后的新编辑可能无法证明下载是否已生效。此时返回 `settings_sync_recovery_conflict`，保留三方内容等待显式选择，不以“修订变大了”猜测写回完成，更不重放整份旧偏好。已经提交基线但清理失败的日志只清理；所有恢复都保留已确认事件的防回退约束。离线状态增加 `pending_write`，不为查询状态联网或建目录。

`host-api::settings_webdav` 和 C 入口 `msime_client_settings_sync` 提供状态、同步、设备列表、批准和拒绝，目录固定取偏好目录下的 `settings-sync`；默认只用已有身份。尚未有任何原生设置入口自动调用它，细节和限制见 [协议文档](../../../../docs/settings-webdav-sync.md)。

`settings_webdav::run_scheduled` 承接保存、打开页面、定时和手动四种信号。共享投影的摘要改变后等一分钟安静期，一直编辑时最多延后十分钟；本机凭据等被排除的字段不重置防抖。打开页面至少间隔一分钟拉取，定时拉取间隔三十分钟。调度与事务共用进程间锁，返回下一次调用间隔，宿主不在输入线程等待；原生宿主的定时线程和设置入口仍待接线。

`settings-sync-schedule` 私有保存摘要、待发送时间、退避和滚动额度，不保存设置正文或应用密码。每三十分钟自动请求最多 40 次，总请求最多 60 次，为手动重试留出余量；同步事件、密钥批准查询、目录创建和底层重试都经过同一计数器。每次实际传输前先原子写入预扣记录，失败响应和进程退出不会退回额度；切换网盘或身份也不重领额度。时钟回拨保留已消费记录，网络错误按一分钟到一小时退避，凭据、协议和冲突错误等待显式处理，手动重试仍受总额度约束。旧的一次 `run` 和设备管理入口保持兼容，新原生自动接入使用 `scheduled`，不把它们说成已经改为后台同步。

初次保存后若尚无成功拉取，定时轮询仍尊重首个编辑的一分钟防抖；不会因为“还没拉取”把截止时间改成立刻联网。打开页面与手动同步仍保留显式触发语义，行为回归包含旧策略失败的负对照。

同步完成后只把已确认事务基线与此刻本机投影一致的改动标为已发送；在途的新编辑仍保留待发送状态。C/JSON 入口新增 `scheduled` 与离线的 `schedule_status`，不改变已有请求形状和默认身份策略。

原生宿主的连接配置落在独立的 `settings_sync_webdav` 本机段，默认全空且省略，不改变旧文档的行为。密码进入凭据清单，账号和密码在诊断中脱敏，地址去除用户信息与查询；整个连接段不进入设置导出、导入覆盖、账号同步或 WebDAV 投影。恢复默认与现有网盘一致保留连接，用户明确停止才清空。新类型的 Debug 也只显示是否配置，不输出账号和密码。

C/JSON 的 `configuration` 与 `configure` 提供离线摘要和带修订号的 CAS 保存，不返回应用密码、不生成同步身份；保留密码必须显式指定，且地址、账号都与旧配置相同。同步操作省略 `config` 时由共享层读取已存连接，未配置则离线拒绝；旧宿主显式传连接仍兼容。这只是原生页面所需的业务入口，尚未等同于原生页面交付。应用私有偏好沿用其他网盘连接的存储边界，不能声称系统钥匙串加密。

`settings_webdav/background.rs` 提供可停机的后台线程与 C 启停入口。宿主调用启动时只解析有界路径并创建线程；偏好读取、每五秒的修订检查及网络都在线程中执行。修订变化报告 `local_change`，其他轮次按服务的 `next_check_ms` 调 `periodic`，不另算防抖、额度与退避。只用已有身份，空配置或尚未配对不创建同步目录、不联网；原生宿主的实际启停接线仍待逐端完成。停止超时保留句柄，让插件卸载前能够再次等待；同一目录重复启动无动作，切换目录时旧轮次仍在则返回忙，不允许两个后台线程同时跨目录工作。

## Alternatives considered

- **直接复用完整设置文件**：能最快得到换机效果，但会把本机凭据、代理地址、模型路径和平台字段带到 WebDAV，拒绝。
- **把 WebDAV 字段混进账号设置同步**：可少一套接口，但会破坏用户自托管存储和端到端密钥域的隔离，拒绝。
- **偏好保存成功后才记录同步意图**：正常路径少一次私有写入，但退出后无法区分下载与本机编辑，可能覆盖其他设备恢复的默认值，拒绝；意图必须在发布和应用之前持久化。
- **先同步皮肤包引用**：能覆盖更多现有主题，但另一台设备可能没有同名包，结果是悬空引用；本阶段只传可移植主题定义，拒绝静默复制引用。
- **一轮结束后再把请求数写盘**：正常路径减少私有文件写入，但进程退出或响应丢失会重复获得额度；采用每次传输前预扣，代价是同步工作线程多一次小型原子写入。

## Consequences

- 共享 Rust 现在有可供 WebDAV 驱动和宿主调用的稳定文档边界与字段级合并结果，测试明确证明合成凭据与代理不会出网，格式错误和本机皮肤引用会被拒绝。
- 主题选择和自定义键盘设计可以进入后续加密事件；本机候选皮肤包仍需单独设计可移植清单，因此 #10787 仍未完成自动同步。
- 服务层和 C 入口具备一次端到端同步、本机连接管理及后台线程，但六端原生设置页和线程启停尚未接入；现有用户行为不变。1024 条日志与单次 8 MiB 拉取是当前硬限制，检查点、分批续传、换钥和原生冲突选择仍需完成；自动恢复覆盖可证明的中断状态，无法判定的编辑仍需显式选择，PR 保持 Draft。
