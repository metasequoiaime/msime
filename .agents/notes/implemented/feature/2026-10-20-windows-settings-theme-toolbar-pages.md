# Agent Note: Windows 设置的主题页改成整宽卡片轮播，悬浮工具栏页对齐 macOS

Status: implemented

## Problem

macOS 设置（共享设置 UI 的桌面分支）的「主题」页是一次一张整宽卡片的轮播（`settings/theme-carousel.tsx` 的 `ThemeCarousel`）：内置主题和外部皮肤包同在一个轮播里，下面一行是「‹」、最多 9 个圆点、「n / N」和「›」，轨道高度跟随当前卡片。每张卡片照 `skin-card-header.tsx`：卡头左边是「名称（浅色 / 深色）」「使用中」和说明，右边一列是开关、「预览浅色 / 预览深色」和皮肤包的「发布到社区」；卡头下面是整宽的预览面，横排、竖排两个完整候选窗口加一条悬浮工具栏，套用用户在「候选窗口」页设的圆角和不透明度。内置卡片的说明来自 `globalThemeDescription`。页面顺序是两段页首说明、「明暗」组、轮播、槽位说明、「本地皮肤」组、「自定义主题」组，来源标签叫「本地皮肤」。

Windows 原生设置窗口的「主题」页是 174 DIP 宽的小卡片网格，每张只画两行假候选「1 水杉输入法 / 2 水杉」，点整张卡片即选用，说明是自己的一套（使用中 / 自定义候选配色 / 深色主题…）；皮肤包另起一列 6 圆角的卡片，左边 260 DIP 的预览；所有卡片都不画工具栏。颜色模式和候选窗口主题在一个叫「外观」的组里，排在卡片之后；目录一行在「更多皮肤」组；来源标签叫「我的皮肤」。

「悬浮工具栏」页 macOS 是三组：页首无标题组里的预览块（12px 灰字「预览」）、「显示」、「按钮」（纵向一列复选框）、「尺寸」（工具栏大小，末尾是整行可点的「颜色与明暗」）。Windows 是两组：「显示与组件」里放开关、带「前往」按钮的「颜色与明暗」和 174 DIP 宽网格的「工具栏按钮」，「尺寸」里只有工具栏大小；预览不在组卡片里，标题是「效果预览」，下面多一行「W × H DIP · 按默认输入状态预览…」。

用户要求以 macOS 为准迁移这两页（缺口清单 G1.1、G1.2、G1.3、G1.5、G1.6、G1.10、G1.11）。G1.6 指出主题页在轮播之后还画了一份 Windows 自己的完整实时预览、页头也有「界面预览」开关，而共享页 `skin-page.tsx` 没有 `AppearanceCandidatePreview`，卡片本身就是预览。用户决定保留的 Windows 专有预览工具只限「候选窗口」页（示例文字框、预览明暗下拉、页头「界面预览」开关、「编辑主题」按钮），不包括主题页。

## Decision

### 主题页

- 顺序照共享页：「本地皮肤」来源标签，两段 12 DIP 次要色的页首说明（`PageIntro`「选择皮肤与配色；候选窗口的布局、字体和显示方式在「候选窗口」中设置。」和 `SkinPlatformNotice`「选择候选窗口和悬浮工具栏使用的主题；明暗预览仅影响当前卡片，不修改设置。」），「明暗」组（颜色模式、候选窗口主题），轮播，槽位说明和发布结果，「本地皮肤」组（外部皮肤目录一行），「自定义主题」组。主题页不再画完整实时预览，`has_preview` 只对「候选窗口」页为真，所以主题页的页头也没有「界面预览」开关。
- 轮播是 WinUI 的 `FlipView` 加 `PipsPager`：卡片作为 FlipView 的项，一次一张、整宽；触控板横滑、FlipView 获得焦点时的左右方向键和它自带的悬停箭头都能切换。下面一行是自绘的 28 DIP 圆形「‹」「›」（到头时 40% 不透明且不可用）、`PipsPager`（`MaxVisiblePips` 9，选中的圆点经模板资源 `PipsPagerSelectionIndicatorForegroundSelected` 用强调色）和 12 DIP 的「n / N」。FlipView 的高度不跟随当前项，所以在选中项变化和宽度变化时，用当前卡片在这个宽度、无限高度下 `Measure` 出的高度设 FlipView 的高度；第一次布局前按正文宽度估一次。
- 停在哪张卡片由 `ThemeSkinModel.h` 的 `carousel_index` 决定，照 `theme-carousel.tsx` 按卡片 key（`theme:<id>`、`package:<id>`）跟踪：选中的卡片换了时跟过去，否则留在上次显示的那张，那张没了时停在原序号、越界退到最后一张。窗口成员记着显示中的 key 和序号、上次画页面时选中的 key，所以切换卡片上的预览明暗、重扫皮肤目录、窗口获得焦点后的重画都不会把用户正在看的卡片换掉。搜索落到某款主题或皮肤时停在那张。
- 指针停在卡片上时，竖向滚轮由卡片处理掉并转给页面的 ScrollViewer，横向滚轮照常交给 FlipView。
- 内置卡片与皮肤包卡片共用一个外框（`make_skin_card_frame`）：10 DIP 圆角，选中时 2 DIP 强调色描边；卡头左右 24、上下 20，15 DIP 半粗体标题、强调色「使用中」、13 DIP 说明；右边一列是 `ToggleSwitch`，以及 24 高、6 圆角、11 DIP 字的「预览浅色 / 预览深色」「发布到社区」小按钮；预览面底色是共享页的 `--skin-preview-stage-bg`（浅色 rgba(0,0,0,.03)，深色 rgba(18,18,18,.13)），每块左右 24、上下 9。
- 内置卡片改成开关语义：打开开关选用主题，选中的卡片再点不改设置、开关回到打开；「自定义」卡片槽位里还有目录里没有的包时照样清掉两个槽位，与原来点卡片的规则相同。卡片画的明暗照 `builtinCards`：固定明暗的主题用它自己的，「自定义」看它的底，跟随系统和以跟随系统为底的「自定义」用候选窗口当前明暗，并有「预览浅色 / 预览深色」（按主题 id 记在窗口里，不写偏好）。配色是这个主题在卡片明暗下经 `msime_client_resolve_theme` 解析的那一份（「自定义」不带皮肤包），不再用主题目录的预览色。说明取 `ThemeSkinModel.h` 的 `theme_description`，即 `globalThemeDescription` 的桌面分支。
- 两种卡片的候选窗口都用 `make_skin_sample` 画（内置卡片传一个空的包），并套用 `CandidateWindowStyle.h` 的规则：用户设的圆角压过包和主题的圆角，表面、描边和包的背景图随不透明度淡化，与共享页的 `candidateWindowStyle` 相同。
- 每张卡片在候选窗口下面画一条悬浮工具栏。「悬浮工具栏」页原来的绘制抽成 `make_toolbar_sample(colors, current_settings)`，按钮状态都按默认输入状态。「悬浮工具栏」页传 `true`，按当前设置的按钮、大小和 logo 画（共享页传 `preferences={floatingToolbar}`）；卡片传 `false`，画全部按钮、100% 缩放、默认图标尺寸、不画 logo（共享页卡片里的 `<SkinToolbarPreview />` 不带设置），隐藏了按钮或把工具栏调到 150% 都不影响卡片。卡片传入卡片候选配色经 `toolbar_palette` 的那一份，与 Server 给工具栏的配色同源。皮肤包清单里的工具栏颜色和圆角（Server 的 `apply_toolbar_skin`）和只有 macOS 读的 `toolbar_stylesheet` 不画。
- 去掉完整实时预览后，「自定义配色」取色器拖动时的即时反馈改由「自定义」卡片承担：共享页每次 `onCandidateColorChange` 都按草稿重画卡片，Windows 的取色器开着时不能整页重画（会拿掉取色器所在的页面），所以窗口记着「自定义」卡片的预览面和轮播（弱引用，每次画页面重设），每次写颜色后按不带皮肤包的自定义主题重画这张卡片的横竖候选窗口和工具栏；写完后在用的是「自定义」卡片本身（`sk::shown_package` 为空）时轮播跟到这张卡片，与关上取色器后整页重画停的位置一致。卡头的「使用中」、开关和「（浅色 / 深色）」等关上取色器整页重画时再更新。
- 皮肤目录扫描的结果变了时把搜索索引标成作废，新装的皮肤下次搜索就搜得到；原来索引建好后皮肤名不再更新，轮播里的皮肤卡片又只能经搜索或翻页找到，这一项必须跟上。

### 悬浮工具栏页

- 页首是无标题组里的预览块：12 DIP 次要色的「预览」小字，下面一块与卡片预览面同底色的舞台，工具栏靠左，太宽时横向滚动。尺寸和状态那一行去掉；画出来的 DIP 尺寸写进「预览」小字的读屏帮助文本（自动化 ID `toolbar-preview-label`，读屏名「悬浮工具栏预览」，与共享页的 aria-label 相同），界面验收靠它确认勾选按钮后预览跟着变。
- 分「显示」「按钮」「尺寸」三组。「按钮」一行的标题是「按钮」、说明「勾选要显示在悬浮工具栏上的按钮」，复选框按工具栏顺序排成纵向一列、14 DIP 字（`checks_panel` 多了列数上限和字号两个带默认值的参数）。「颜色与明暗」改成「尺寸」组末尾的跳转行（`link_row`，行尾「›」），仍落到「主题」页的「颜色模式」。

## Alternatives considered

- **自己拼轮播：只画当前那张卡片，下面一行自绘圆点**：高度天然跟随当前卡片，圆点能照 `theme-carousel.tsx` 逐个命名「查看 X」、两端缩小，也没有滚轮被 FlipView 吃掉的顾虑。否决：触控板横滑和切换动画都要自己做；FlipView 加 PipsPager 是 WinUI 自带的同类控件，横滑、方向键、动画和圆点窗口都现成，只需补高度和滚轮两处。
- **保留小卡片网格，只在每张里多画竖排候选和工具栏**：改动小，一屏能看到所有主题。否决：网格格子 174 DIP 宽，放不下横竖两个候选窗口加工具栏和右侧一列操作，与 macOS 的版式差得最远。
- **卡片里的工具栏用包的工具栏颜色（`apply_toolbar_skin`）**：与 Server 真画出来的更接近。否决：设置窗口读到的皮肤包没有清单里的工具栏段，要扩 `msime_client_skin_catalog` 的回答或另读清单；「悬浮工具栏」页的预览原来也不套用它，两处保持一致，差异写进 README。
- **主题页保留 Windows 的完整实时预览和页头「界面预览」开关**：调颜色模式、自定义配色时能在同一页看到整份候选窗口。否决：共享页的主题页没有这份预览，卡片已经画了当前配色下的横竖候选窗口和工具栏；用户决定保留的预览工具只在「候选窗口」页，那里照旧。
- **卡片的工具栏也按当前设置画**：与「悬浮工具栏」页的预览一致，少一个参数。否决：共享页卡片里的工具栏不带设置，隐藏按钮或调大工具栏后卡片会和 macOS 画得不一样；卡片比较的是配色，不是用户的工具栏布局。

## Consequences

- FlipView 会虚拟化不显示的项，读屏和界面验收只看得到当前那张卡片里的元素；`tests/tools/settings_ui.ps1` 的 canvas 皮肤检查因此先经搜索打开那张卡片，再找它的图片。
- 只有选中项变化和宽度变化时重算高度。卡片内容在不重画页面的情况下变高（目前没有这种路径，图片解码完成会整页重画）时高度不会跟上。
- 竖向滚轮转给页面时按滚轮增量直接滚动，没有 ScrollViewer 自己处理滚轮时的步长曲线。
- FlipView 自带的悬停箭头和下面一行的「‹」「›」同时存在，这是 WinUI 控件的默认模板，不改模板就去不掉。
- 每次重画主题页都为每张内置卡片调一次 `msime_client_resolve_theme`，与原来小卡片网格的次数相同。
- 取色器拖动时只重画「自定义」卡片的样例，卡头要等取色器关上；第一次写颜色把原来的主题留作底时，卡头写的明暗和「预览浅色 / 预览深色」在这之前还是旧的，样例已经按新底的明暗画。
- 皮肤包卡片的工具栏不反映包清单里的工具栏颜色和圆角，选用后真工具栏可能与卡片上的不同。
