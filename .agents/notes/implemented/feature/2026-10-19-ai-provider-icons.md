# Agent Note: AI 服务商选择菜单显示图标

Status: implemented

## Problem

AI 辅助的服务商选择只有文字。原生 `<option>` 无法承载品牌 SVG，只在控件旁加图标不能满足展开后每项都有图标的要求。

## Decision

为 AI 服务商建立独立的带图标选择控件，保留目录的 `id/title` 数据和原有预设更新入口。图标静态打包，不在用户打开菜单时请求外站。菜单使用带名称的 combobox/listbox，支持方向键、首尾键、文字查找、确认、取消、Tab 与外部点击关闭。菜单通过 portal 放到最近的设置窗口根节点，继承平台颜色，按视口可用空间选择展开方向和最大高度。液态玻璃分组的 `backdrop-filter` 会让内部 fixed 元素以分组为基准，必须越过分组渲染，不能仅在普通浏览器主题下验收定位。活动选项只调整菜单自身的 `scrollTop`，避免 `scrollIntoView` 滚动页面后触发菜单的外部滚动关闭；外部滚动仍取消菜单。鸿蒙手机沿用既有选择面板，避免改变整行入口与面板操作契约。

## Existing notes audit

按服务商、`provider-preset`、combobox 和下拉菜单检索活跃笔记。[服务商预设模型](../../implemented/simplification/2026-10-16-provider-preset-model.md)拥有纯数据类型，不扩充 React 图标字段；[字体输入法导航](../../implemented/bug-fix/2026-10-14-font-family-ime-navigation.md)属于可编辑输入框，本控件复用合成输入事件判断但不修改字体输入逻辑。其余模型选择、凭据归属及外观精简笔记不拥有此菜单。

## Alternatives considered

- 原生 select 加一个外侧图标：保留系统交互最省维护，但展开后仍是纯文字，不能满足需求。
- 把全部 Select 替换成自定义控件：可统一加图标，但让模型、语言等无关控件承担键盘与无障碍实现成本，故只替换 AI 服务商这一处。
- 安装整套品牌图标依赖或使用远程图片：方便后续扩展，但这里只需要少量图标，选择固定版本的本地 SVG 并记录许可与来源。

## Consequences

菜单需要自行维护定位和键盘交互。服务商选择继续进入原有偏好更新逻辑，密钥与端点契约不变。

## Testing

服务商菜单、预设、AI 偏好归属与目录测试共 25 项通过；浏览器以合成配置验证 12 个选项均带图标，方向键、取消、文字查找、确认和外部关闭有效。1000×780 浅色与 800×600 深色下没有横向溢出，小窗口菜单按剩余高度滚动。前端类型检查与生产构建通过。

macOS 本机安装与严格签名校验通过，实际设置窗口展开后 12 项图标均可见。真实液态玻璃窗口曾暴露 fixed 菜单被分组偏移的问题，改为根节点 portal 后再次装机，菜单边界位于窗口内并与触发控件右侧对齐。浏览器另开启液态玻璃标志复验该定位路径。

`verify-notes`、定向 lint、格式检查与本地 quick 门禁通过。quick 包含 macOS 原生构建、Linux 设置壳与原生宿主构建（90 项测试）、Android Java 冒烟和 Windows 管道交叉构建；不代表其他平台已做设备验收。

[AI 服务配置顺序](../bug-fix/2026-10-19-ai-service-setup-order.md)的矮窗口验收补充菜单自动滚动回归：选中末项、展开提示词并滚动页面后，菜单仍可展开与选择。
