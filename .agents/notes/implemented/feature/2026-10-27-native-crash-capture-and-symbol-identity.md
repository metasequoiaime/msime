# Agent Note: 自有宿主的独立崩溃采集和符号身份

Status: implemented

## Problem

匿名遥测的共享队列不等于所有进程都有采集入口。Android 原生致命信号、桌面设置与面板、iOS App 信号、鸿蒙设置应用的系统诊断存在缺口；Windows x86 的异常只有直接故障帧。旧报告也没有足以区分同版本多次构建的身份，Linux、Android、HarmonyOS 和 Win7 缺少对应的发布符号归档。

## Decision

沿用共享遥测的同意开关、匿名安装身份、队列和上传协议。`capture_only` 为独立应用准备记录路径与构建头，不建立输入会话；输入法宿主仍持有自己的 `session_id`。崩溃摘要只留类型、信号和错误码，不上传异常消息或原始系统日志。构建身份的格式、原件确认删除与会话归属由[会话归属笔记](../../implemented/bug-fix/2026-10-24-telemetry-session-ownership.md)持有。

### 采集边界

- `platforms/common/CrashRecorder` 独立于 Host API，在正常路径预备路径、构建头和模块映射。信号回调使用有界静态缓冲区，只尝试一次配置锁，先保存摘要和故障帧，再尽力展开，不联网。保留第一份记录，并交还原有处理程序；关闭时先解除采集。
- Windows x86 通过 `ReadProcessMemory` 读取有界 EBP 链，x64 与 ARM64 使用系统展开表。Win7 构建保留帧指针。Server、现代原生设置、Win7 设置与面板以及桌面公共面板分别准备采集；独立界面不增加输入会话分母。
- Android 的 App 和 IME 分别准备独立捕获和输入会话，JNI 接入原生记录器。API 30 以上的系统退出报告只认领自身留下的同意标记，保留旧版本，ANR 和系统处置独立归属。Java 只写异常类型与栈，不写异常消息。
- Apple 信号入口先保存系统上下文的故障指令：macOS 共同记录器和 iOS C 记录器均在正常配置路径预备模块加载基址、可执行区间与 UUID，信号路径按故障地址输出文件名、模块相对偏移和 UUID，不查询动态加载器或写出设备目录；先写直接故障帧，再尽力展开处理器栈。arm64 使用系统的线程状态访问宏，x86_64 使用 RIP；不能让采集器或展开器占据业务首帧。
- macOS 输入法使用共同记录器，异常、退出与会话仍由原生宿主管理。Tauri 设置与公共面板独立捕获，在偏好变化时重读同意并解除采集。
- 桌面 `msime-mcp` 单独链接同一原生记录器，在解析出实际命令后、创建异步运行时和候选查询之前准备 `mcp` 组件的独立捕获。帮助与版本查询不启动采集。长驻服务器每 500 ms 重新读取运行时选项及实时偏好；配置不可读时停用，显式关闭时清空本版本待发记录。MCP 不调用遥测网络传输，主入口未处理的 Rust panic 只写固定类型、源码文件名与行列后继续原有展开退出；panic hook 仅在本线程的固定缓冲区保留源码位置，不读 payload、不写文件，工具内捕获和 Tokio 接管的 panic 不认作进程崩溃。同意观察线程若意外 panic，先解除采集，避免留下不再响应关闭操作的记录器。与原生宿主共用按版本划分的遥测目录，不跟随可搬迁的词库目录；测试子进程的 HOME、LOCALAPPDATA、XDG_STATE_HOME 均使用合成根目录。
- MCP 的目标平台链接由现有 Linux 设置应用和 Windows 原生设置 CI 门禁补验，两者运行该包的 Clippy、原生故障子进程和协议测试；不能只在 macOS 上编译便声称另外两个平台可用。
- iOS App 与键盘共享 C 信号记录器，预计算构建头与路径成对发布，MetricKit 保留系统给出的原始版本；卡死独立归属。App Group 保存本轮持续同意的起点，关闭时删除；MetricKit 只给批次时间范围，跨越该起点的整批跳过，不能用当前同意追认历史诊断。C 文件放在 `SharedUI/core`，由 XcodeGen 的共享源组加入每个使用方，避免跨源组路径合并。
- HarmonyOS 的应用与键盘均监听 `APP_CRASH` 和 `APP_FREEZE`。只读取标准异常类型、原生帧、原始版本、进程号和时间；卡死不增加 `session_crash`，不读取 hilog、页面历史或外部日志。系统诊断的稳定文件身份同时作为共享层的 `diagnostic_id`，重送不产生随机新事件。每次回调重新读取共享同意；持久化连续同意的起点，关闭时删除，缺标记或发生时间早于本轮同意的历史诊断不补录。

### 符号归属

ELF 帧保存模块名、相对偏移和 GNU build id；Mach-O 帧保存模块偏移和 UUID。Android、Linux 和 HarmonyOS 构建保留原始调试行与 build id，打包时另行裁剪安装副本。`crash-symbols.py` 归档本产品模块，记录版本、提交、构建运行、重跑编号、架构、模块 build id 与 SHA-256；还原前核对哈希和 build id，拒绝同名异构建模块。主程序快照没有名字时会写成 `<executable>`，还原工具只按 build id 唯一认领清单里的模块；同一身份出现多个候选时仍拒绝。Linux 源码包携带固定提交，离线构建仍有来源身份。

Win7 的归档脚本分别收集 x86、x64 的配套 PE 和 PDB，任一必需文件缺失或为空就失败。发布 workflow 同时保留九十天 artifact；只有维护者手动选择发布时才推到平台滚动符号 release。本次不触发发布。现代 Windows、macOS 的已有滚动符号和 iOS 的 dSYM 保留机制继续使用。

macOS 发布构建显式为 Rust、C++/Objective-C++ 和 Swift 保留源码行，归档四个自有可执行文件及 `MSIMEBackend.dylib`。Rust 和 Swift 单步编译链接会在临时对象消失前产生原始 dSYM；universal 构建按分片归并这些原件，不能对合并后的已失去对象的程序再次运行 `dsymutil`。CMake 保留的原生对象仍可用于生成输入法和语音辅助程序的 dSYM。`crash_symbols.py` 对每个架构核对 UUID 和非空源码行表，缺架构、错误构建或空行表都中止打包；清单保留原始版本、源码提交、构建运行及 DWARF 哈希。符号归档不随版本安装包分发。

## Alternatives considered

- **统一引入第三方崩溃 SDK**：成熟的转储、符号化和设备采集最全面，但会新增第三方传输与隐私边界，也不能直接替换自有后台。本次复用系统诊断和本地捕获，继续使用现有传输。
- **独立进程也调用普通 begin/end**：最省接入代码，但会把打开设置计作一次输入会话，改变无崩溃率分母。独立捕获只产生 `crash`。
- **在 MCP 的全局 panic hook 中记崩溃**：能取得最初抛出点，但 Rust 的可恢复 panic 和工具任务失败也会经过 hook，不能证明进程死亡。钩子只暂存源码位置，主入口边界仅为实际越界的 panic 写记录；原生致命信号仍由共同记录器处理。代价是该类 Rust 记录的展开栈位于主入口边界；摘要中的源码行来自最初的 panic hook，不能将边界栈冒充抛出点栈。
- **在故障时动态查模块和格式化完整异常**：信息丰富，但可能再次进入已损坏的堆、加载器锁，异常消息也可能含用户内容。模块映射和身份提前固定，故障时只做有限写入和尽力展开。
- **对所有最终 Mach-O 统一重新运行 `dsymutil`**：调用最简单，也能生成同名目录；但 Clang/Swift 的临时对象可能已清理，命令仍返回零并覆盖掉可用的原始 dSYM。按编译器的产物生命周期保留原件，以 UUID 和实际源码行拒绝空包。
- **只归档工作流 artifact**：不需要滚动 release，但九十天后正式版仍在线而符号消失。发布构建额外留滚动符号，文件名含运行及重跑编号，安装包不携带调试符号。

## Verification

- 共享层遥测 50 项、Host API 遥测 4 项及相关 Rust 库 Clippy 均通过，覆盖损坏构建头、原子写入、超过单批额度的保留和入队失败后的原件保留。
- MCP 在 macOS 构建机运行 124 项单元测试与 18 项协议测试，全部通过；记录器子进程入口由父用例显式启动，不把该入口的 ignored 状态计作通过。七种子进程情况验证未处理 panic、原生终止、可恢复 panic、启动关闭、运行中关闭再开启、配置不可读；记录不含合成私密参数，按新版本补报时仍保留故障原版本，不产生输入会话事件。该包全部 target 的 Clippy 通过。帮助与版本命令的实际二进制用例确认不初始化遥测目录。Linux 与 Windows 新增的 MCP 门禁尚待本轮 PR CI 执行。

## Consequences

新增入口让独立进程和原生故障进入既有队列，构建身份能指导选择精确符号。队列容量不再允许普通统计挤掉崩溃；全为崩溃时保留后续原文件。共享层异常写入完整落盘后原子发布，损坏的新格式身份不回退为当前版本。

限制：信号处理时的运行库展开是尽力而为，不能保证栈耗尽和堆破坏时仍有完整栈；备用栈目前只覆盖安装线程。运行中后加载的模块要重新准备后才在快照里。iOS C 模块帧与符号还原已有宿主合成用例，但真实 iOS App/键盘故障到设备 dSYM 的链路仍需验收。直接原生写入和并发采集仍有半份记录的竞争窗口。系统延迟诊断缺少精确源码提交时标为未知，不猜测当前构建；旧无头独立记录无法恢复原版本。TSF 位于外部宿主进程，尚未加入仅认领本产品模块的捕获；看门狗、准备程序、语音辅助进程也尚未逐项覆盖。以上设备、收件和覆盖缺口继续由全平台提案跟踪，不能据本篇声称百分之百采集或全平台闭环已完成。
