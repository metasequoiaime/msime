# Agent Note: Windows 7 原生表情、颜文字与符号面板

Status: implemented

## Problem

Windows 7 缺少共享 WebView 面板承载，但表情、颜文字、符号目录和插件符号集仍是已有可用能力。只跳到系统表情面板既不覆盖 Win7，也会丢失本产品的目录。

## Decision

原生窗口经 `msime_client_emoji_catalog_request` 加载实际资源目录，使用游标直到完成，保留符号父分类和插件组。搜索与分类只过滤当前目录快照，不另造表情目录。内置目录失败单独显示，插件组继续独立读取；复制与输入绑定当前选择，输入沿用面板焦点保护和统计标记。最近使用属于界面元数据，在当前用户状态目录内限量保存，读坏不自动覆盖。剪贴板操作继续打开已有的原生历史面板。

Win7 的实际候选里，`nihao` 后的第二项是 U+1F44B 挥手表情，文本保持正确，但系统字体缺字。`common/Windows7EmojiFont.h` 为候选测量、绘制和原生表情列表提供相同的 DirectWrite 私有字体集合；只覆盖主字体缺字且随包字体实际有字的完整表情簇，不拆开 UTF-16 代理对、ZWJ 家庭、肤色、键帽、旗帜和变体选择符，也不更换中文主字体。候选测量与绘制必须同时应用，避免补字后行宽与点击区域仍使用缺字尺寸。原生表情列表保留系统列表的字符串、选择与无障碍行为，采用相同排版绘制；独立预览显示选中的完整表情，旁边保留可选取的说明文字。

字体使用固定 Google Fonts 提交的原始 `NotoEmoji[wght].ttf`，以 `NotoEmoji.ttf` 随 Win7 程序分发，来源、SHA-256 与 OFL-1.1 许可证均放在 `assets/fonts` 并一起安装；构建先验摘要。字体只从程序旁的只读目录加载，不写系统字体注册表、不修改用户偏好。Win7 使用默认字重的单色轮廓；现代系统继续使用已有回退和彩色表情。

Win7 的 DirectWrite 即使显式启用 `ccmp`，仍把 ZWJ 家庭、肤色和键帽分成独立字形。私有字体因此使用基线锁定的 HarfBuzz Core 整形，再由 `IDWriteInlineObject` 把字形、字宽和基线交给 DirectWrite；只处理需要回退的完整组合表情簇，原始 UTF-16 文本与候选索引不变。单个表情仍走现有私有字体排版，现代 Windows 保持系统排版。内联绘制的原点与效果继承遵循 [IDWriteInlineObject::Draw](https://learn.microsoft.com/en-us/windows/win32/api/dwrite/nf-dwrite-idwriteinlineobject-draw)，排版保留原始范围，绘制原点加字体基线。显式文本选择符 VS15 不会单独触发表情字体回退。测试渲染器必须实际调用内联对象的绘制，不能因回调被跳过而假通过。

集成主线的多桌面候选调度后，各桌面的 UI 线程共用私有字体。遵循 [HarfBuzz 对象生命周期约定](https://harfbuzz.github.io/object-model-lifecycle.html)，字体在设定整形函数和比例后标记不可变；每次排版独立创建缓冲区。回归同时在四条线程反复绘制家庭、肤色和键帽，并核对字形与 UTF-16 命中范围，覆盖跨桌面的共享对象边界。

Win7 设置／面板最小清单与完整原生产品的 `compat/vcpkg.json` 统一固定到 `04a9d8e5212d01ee1dd9478eadd9caade4f8b0d4`，使用同一 HarfBuzz 14.4.0 Core。旧最小清单的 `ef7dbf94b9198bc58f45951adcf1f041fcbc5ea0` 对应 HarfBuzz 10.2.0，其包配置无条件查找 FreeType，即使关闭全部默认特性也会在干净 CI 配置失败；完整产品原已使用修正条件依赖的基线。统一 Win7 清单可以让最小 CI 和已验收产品使用同一依赖契约，不引入 FreeType 或更换现代 Windows 依赖。

## Alternatives considered

- **仅指定私有字体并启用 OpenType `ccmp`。** 不增加整形依赖，但在 Win7 实测仍输出分离的家庭、肤色和键帽字形，不能覆盖组合表情。
- **给旧最小清单额外添加 FreeType。** 可满足旧包配置无条件查找，但 HarfBuzz Core 未使用该后端，新增依赖不能消除最小 CI 与完整产品基线不一致。统一到完整产品已验收的固定基线，不另外维护覆盖端口。
- **预生成表情到字形的映射表。** 可减少运行时依赖，但会把字体规则和表情目录冻结成第二份数据，自定义插件与新增组合容易漏掉；运行时复用字体本身的 OpenType 规则。

- **调用 Win+.。** 可以直接使用现代 Windows 的系统表情面板，但 Win7 没有该入口，而且不能展示已有插件符号集，因此提供本产品的原生目录承载。
- **要求用户安装新版微软表情字体。** 可以获得熟悉的字形，但需要额外系统改动，且不能假设用户拥有相应字体的再分发权。使用许可证清晰、随包可核验的私有字体集合，安装后即可显示。
- **隐藏画不出来的候选。** 可避免缺字框，但会静默丢掉已有表情能力；这里补齐显示，不改变候选文本与排序。

## Testing

- x64／x86 的 7 项真实共享目录测试通过，覆盖游标、父子分类与 32 位偏移边界；原生面板双架构通过 MSVC `/W4 /WX` 构建及全部 6 套 CTest。
- HWND 用例验证空页推进、跨页 257 项、重复、大小写搜索、父分类、真实插件接口、成功／失败传输、统计、最近使用限制、坏文件保留和锁冲突，偏好修订保持不变。
- 两架构最终程序分别通过 263／258 项已知阻断导入检查；此检查不等于完整 Win7 系统兼容证明。
- x64 clippy 通过；x86 的 Win7 标准库 TLS 展开对已有 `const { ... }` 初始化误报 `missing_const_for_thread_local`，仅在该命令级豁免这一 lint，其他警告仍按错误处理；再次运行通过。没有修改这些业务源码。
- Win7 SP1 x64 交互桌面的 x64／x86 原生目录与窗口回归通过。早期 Linux 时限失败后的完整 quick 已通过，最终门禁见[产品构建](2026-10-24-windows7-product-build.md)。

- 双架构私有字体排版测试验证挥手、新表情、UTF-16 范围和中文主字体保留；四条线程各 64 轮的家庭、肤色与键帽真实布局和绘制已在 Win7 SP1 双架构运行通过。家庭、肤色与键帽必须整簇选字并产生完整字形，同时核对整簇宽度与 UTF-16 命中范围。Win7 SP1 交互桌面的双架构完整运行回归通过，覆盖新字体与实际内联绘制、系统对话框、外部编辑器传输和 MCP。

## Consequences

目录与插件复用共享服务，面板不联网，不保存真实输入内容到诊断日志。最近使用增加一个受锁保护的限量界面元数据文件，坏文件不覆盖。Win7 随包补充表情单色轮廓，彩色显示继续取决于目标系统；系统 TSF 提交由最终安装包的记事本验收单独覆盖。
