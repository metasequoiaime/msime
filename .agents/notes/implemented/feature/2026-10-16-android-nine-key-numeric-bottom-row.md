# Agent Note: Android 九键数字层把 0 移到底行中间

Status: implemented

## Problem

#8058 输入手机号和价格时，0 在 9 右边不符合数字键盘习惯。报告人要求把 0 与带麦克风的空格键换位，并让底行保留符号入口、原有功能不丢失。

## Decision

0 与空格的排法由[26 键「符」与「123」互换和数字键盘空格位置](2026-10-29-touch-symbol-first-and-number-pad-space.md)部分取代：下面的排法是 Android 的默认（`touch_number_pad_space` 的 `platform_default` / `right_column`），三端现在都能在三种排法之间选，「没有新增偏好」「本次只改变 Android」不再成立。

数字层前两键的顺序由[数字九宫格的返回键和符号入口留在字母层那一格](../bug-fix/2026-10-29-mobile-number-pad-entry-position.md)部分取代：拼音九键一族与字母层一样先符号、后层切换，借用页跟着来源键面，下面保留原排列的记录；0、空格及控件归属决定仍成立。

Android 拼音九键和九键双拼的数字层使用 `九键 | 符 |（地球）| 0 | 中/英 | 回车`。0 接替底行空格的宽度份额；右列变成删除、小数点和原空格键。字母层仍是 `符 | 123 |（地球）| 空格 | 中/英 | 回车`。语言与数字键交换继续交换这两个动作，不移动 0 或符号入口。

右列移动同一个 `spaceButton`，保留点击空格、长按语音、拖动光标、按键统计和反馈；仅省略狭窄键帽上的方案短名。这一格的键面见[数字页空格键主标画 ␣](../bug-fix/2026-10-29-android-number-pad-space-glyph.md)：主标是 ␣，麦克风只在开着长按空格语音时作右上角提示。0 使用 `Nine0` 标识，经 `commitNineKeyLiteral` 字面上屏，小数点和左栏运算符语义不变。

`ImeBottomRow` 的排布签名包含是否在九键数字层，确保往返两个键面时收回空格。数字网格重新挂载空格后清空底行签名，下一次渲染重新确认按键归属；不在每次按键时重建整个网格。

### 既有笔记审计

[Android 九键数字页](2026-10-08-android-nine-key-number-pad.md)与[九键符号入口](2026-10-15-nine-key-symbol-key-and-quick-marks.md)部分被本篇取代：只翻转 Android 数字层的 0 和空格位置，其余符号表、手势、三端的字母层决定保持。[语言与数字交换](2026-10-14-android-language-number-key-swap.md)部分重叠，沿用动作交换及宽度随动作走的规则。[移除数字排列设置](../../implemented/simplification/2026-10-11-remove-number-keypad-settings.md)不被取代，1–9 仍按电话顺序排列，没有新增偏好。

## Alternatives considered

- 保留右列 0：与旧的三端数字层一致，底行不必区分键面；但没有解决报告人指出的高频数字位置问题。
- 把空格改成独立的点击语音键：麦克风图标对应点击动作更直接；但会丢失原有空格和光标手势，与原功能不变的要求冲突。
- 新增第四行数字网格：0 能严格与 8 等宽对齐；但要改变键区高度或压缩所有数字键。本次复用现有底行，保持切换时键盘高度稳定。

## Consequences

0 回到底部中间，数字层仍能直接打开符号面板。原空格键在右列变窄，水平拖动光标可用的起始范围缩小，方案短名只在字母层显示。本次只改变 Android；iOS、HarmonyOS 仍遵守各自现有布局，不冒称三端统一。

## Verification

九键几何和[右侧大回车](2026-10-27-touch-key-layout-styles.md)的设备夹具在编辑器取得焦点后，先等语言键可用并明确选择中文；方案偏好与当前焦点的中英文模式分别建立前提。首组几何先真正切入英文，再选回中文，保证连续套件留下英文时仍覆盖实际九键。原来的尺寸、比例、输入与切层断言保持，不用跳过或增加超时掩盖模式差异（#10364）。 修正后的 quick 及 API 28／35 完整九键专项均通过（远端运行 `20261030-235222`，退出 0），两份仪器化原始结果均为 -1；去掉选回中文调用、保留先切英文的失败对照在 API 35 确定性复现第一组几何等待英文键面的失败。产品复用 #10361 的已提交开发包，随机入口默认关闭；几何尺寸策略、Rust、共享代码、原生桥与资源没有差异，但 `ImeLayoutRows.java` 含随机数字状态与绑定差异，因此这轮不等于整个产品同源验收，也不证明 #10048 旧 CI 的 175/136px 失败已经修复。

`KeyboardActionRowSmoke` 覆盖数字层的唯一 0、原空格不重复、符号入口、地球键、语言数字交换和其他布局保持。`check-host.sh` 的 235 项 JVM 冒烟和 128 个设备源文件编译通过。

独立的 `NineKeyNumericLayoutDeviceSmoke` 在 API 28 和 35 专用模拟器上均通过两轮往返：0 在 8 下方、空格在 9 右侧，`10 .` 经真实输入连接上屏，符号面板返回和字母页空格位置恢复正确。API 28 的无障碍缓存会在换页后保留字母节点，失败瞬间的合成画面已确认数字网格实际绘制正确；旧系统缓存处理只在本套件遍历时刷新节点；公共基类另提供显式调用的中文模式前提，不改变其他套件的启动行为或生产逻辑。运行前核对两台设备安装 APK 的 SHA-256 与本分支产物一致。

当前分支完整原生库、同锁词库和签名 APK 构建及原生依赖校验通过；API 35 的完整 `smoke.sh --core` 和既有九键英文用例通过。API 28 完整 core 在受限输入框组字步骤失败，既有英文用例也未能进入布局断言；本次不把这两项报成通过。专项用例通过不替代所有键盘套件、物理手机或真实录音识别验收。
