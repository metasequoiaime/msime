# Agent Note: Android 九键数字层把 0 移到底行中间

Status: implemented

## Problem

#8058 输入手机号和价格时，0 在 9 右边不符合数字键盘习惯。报告人要求把 0 与带麦克风的空格键换位，并让底行保留符号入口、原有功能不丢失。

## Decision

数字层前两键的顺序由[固定符号与返回入口的位置](../bug-fix/2026-10-21-android-number-entry-position.md)部分取代：现在与字母层一样先符号、后层切换，下面保留原排列的记录；0、空格及控件归属决定仍成立。

Android 拼音九键和九键双拼的数字层使用 `九键 | 符 |（地球）| 0 | 中/英 | 回车`。0 接替底行空格的宽度份额；右列变成删除、小数点和原空格键。字母层仍是 `符 | 123 |（地球）| 空格 | 中/英 | 回车`。语言与数字键交换继续交换这两个动作，不移动 0 或符号入口。

右列移动同一个 `spaceButton`，保留点击空格、长按语音、拖动光标、按键统计和反馈；仅省略狭窄键帽上的方案短名，麦克风由现有语音可用规则显示。0 使用 `Nine0` 标识，经 `commitNineKeyLiteral` 字面上屏，小数点和左栏运算符语义不变。

`ImeBottomRow` 的排布签名包含是否在九键数字层，确保往返两个键面时收回空格。数字网格重新挂载空格后清空底行签名，下一次渲染重新确认按键归属；不在每次按键时重建整个网格。

### 既有笔记审计

[Android 九键数字页](2026-10-08-android-nine-key-number-pad.md)与[九键符号入口](2026-10-15-nine-key-symbol-key-and-quick-marks.md)部分被本篇取代：只翻转 Android 数字层的 0 和空格位置，其余符号表、手势、三端的字母层决定保持。[语言与数字交换](2026-10-14-android-language-number-key-swap.md)部分重叠，沿用动作交换及宽度随动作走的规则。[移除数字排列设置](../../implemented/simplification/2026-10-11-remove-number-keypad-settings.md)不被取代，1–9 仍按电话顺序排列，没有新增偏好。

## Alternatives considered

- 保留右列 0：与旧的三端数字层一致，底行不必区分键面；但没有解决报告人指出的高频数字位置问题。
- 把空格改成独立的点击语音键：麦克风图标对应点击动作更直接；但会丢失原有空格和光标手势，与原功能不变的要求冲突。
- 新增第四行数字网格：0 能严格与 8 等宽对齐；但要改变键区高度或压缩所有数字键。本次复用现有底行，保持切换时键盘高度稳定。

## Consequences

0 回到底部中间，数字层仍能直接打开符号面板。原空格键在右列变窄，水平拖动光标可用的起始范围缩小，方案短名只在字母层显示。本次只改变 Android；iOS、HarmonyOS 仍遵守各自现有布局，不冒称三端统一。

## Verification

`KeyboardActionRowSmoke` 覆盖数字层的唯一 0、原空格不重复、符号入口、地球键、语言数字交换和其他布局保持。`check-host.sh` 的 235 项 JVM 冒烟和 128 个设备源文件编译通过。

独立的 `NineKeyNumericLayoutDeviceSmoke` 在 API 28 和 35 专用模拟器上均通过两轮往返：0 在 8 下方、空格在 9 右侧，`10 .` 经真实输入连接上屏，符号面板返回和字母页空格位置恢复正确。API 28 的无障碍缓存会在换页后保留字母节点，失败瞬间的合成画面已确认数字网格实际绘制正确；专项用例只在旧系统遍历时刷新节点，不修改公共测试基类或产品逻辑。运行前核对两台设备安装 APK 的 SHA-256 与本分支产物一致。

当前分支完整原生库、同锁词库和签名 APK 构建及原生依赖校验通过；API 35 的完整 `smoke.sh --core` 和既有九键英文用例通过。API 28 完整 core 在受限输入框组字步骤失败，既有英文用例也未能进入布局断言；本次不把这两项报成通过。专项用例通过不替代所有键盘套件、物理手机或真实录音识别验收。
