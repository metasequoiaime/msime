# Agent Note: ONNX 后端混合时词网格分只占三成

Status: implemented

## Problem

逐键重排在词网格整句之间比较时，把词网格逐字分与模型逐字分混合后取最高（[静态证据](../bug-fix/2026-10-14-rerank-static-evidence.md)）。混合是等权的，那个比例是在随包 `model-v1`（4.25M）上定的，那篇笔记自己也写了「等权不能据此推广到所有设置或未来模型」。ONNX Runtime 后端的 8x448 / 6x256（[ONNX 后端](../architecture/2026-11-01-onnx-rerank-backend.md)）在 ctx-v1 池上比 `model-v1` 准十几个点，等权让词网格分的错误偏好拖着它。

## Decision

`CandidateScorer::static_evidence_weight` 给出词网格逐字分在混合里的权重，模型逐字分占其余；默认 0.5（等权，随包 `model-v1` 和桌面停顿模型照旧），`OnnxScorer` 报 0.3。host-api 各会话共用的 `SharedOnnxScorer` 照样转发。比较集合、可信词典首选的豁免和九宫格的窄裁决点都不变。

权重只按打分器给，不改随包模型：这次只在 ONNX 后端上量过，`model-v1` 没有重量。

## 评测

dev 上定权重（ctx-v1 全拼按来源单位 `unit` 的 SHA-1 首位 0–4 切出的 dev：分句 741、选词 737；typing-chat-v1 dev 110 段），在 0.2、0.3、0.4、0.5 里选。0.3 在两个模型、三份集合上都是最好或并列最好（分句 6x256 487 → 497、8x448 491 → 500，选词 607 → 615、610 → 620，typing-chat 71 → 72、70 → 72）；0.2 与它相近，部分集合略差。定下 0.3 以后才跑 test。

## Alternatives considered

- **0.2。** dev 上与 0.3 相近，6x256 的分句一样（497），选词还略高（617 对 615），但 8x448 的分句低了 2 条；按事先定的「两个模型都最好或并列最好」选了 0.3。
- **所有打分器都改成 0.3。** 一处常量、更简单；但 `model-v1` 弱得多，词网格分对它更有用，这次没有为它重量，不能推过去。
- **不改。** 等权有它的依据，但那份依据就是在 `model-v1` 上量的，而 ONNX 后端在三份 dev 集上一致地更好。

## Consequences

- 挂 ONNX 后端的设备（「增强」）首选更准：ctx-v1 分句 test +0.6 到 +1.0 个点，选词 +0.8 到 +0.9 个点，sentences-v2 +2.2 到 +2.9 个点。
- 打分器接口多一个方法，以后换模型时要连同这个权重一起在 dev 上重量。
- 随包 `model-v1`、桌面停顿模型、不挂打分器时的排序都不变。
