# Agent Note: Windows 7 原生云词库与完整快照面板

Status: implemented

## Problem

Win7 不能承载现有 WebView 面板，但仍须管理账号云词条、完整目录、候选排序与固定位置，并能备份、恢复和应用整份快照。仅把设置字段搬到原生窗口不能替代这些操作。

## Decision

原生表单复用 `msime_client_cloud_dictionary`，业务校验、账号请求、快照校验与激活继续归共享 Rust。串行 worker 在操作前核对列表所属账号，失败清除旧结果的操作权限；完整文件经 `_file` 接口流式处理，不把 512 MiB 快照放进窗口内存。同一 edition 的每个登录会话以命名互斥量限制为一个云词库窗口，使用会话专属中转目录；不同会话互不清理彼此的预览，下一次启动仍清理该目录里的遗留文件，系统文件选择在 STA，取消不请求。恢复与替换本机先展示快照元数据并确认；预览绑定账号、内容摘要及云端修订，不自动重试冲突。

面板上下文把缺失、损坏或非对象的运行配置统一表示为 JSON 空值；云词库的账号远程操作仍可构造有效请求，本地激活入口继续由共享层核对必需配置。不能把 JSON 解析器内部的 `discarded` 状态直接序列化。窗口回归显式隔离 `MSIME_CLIENT_HOST_OPTIONS`，避免构建机已有配置掩盖首次启动问题。

## Alternatives considered

- **让云词库继续打开 Tauri**：可以复用现成页面，但 WebView2 的系统要求正是 Win7 承载的障碍，因此用原生窗口配合同一业务接口。

## Verification

Windows 11 服务会话的 x64／x86 MSVC `/W4 /WX` 构建与五套面板 CTest 均通过。新增测试使用真实 HWND、串行 worker、临时词表、实际共享偏好和合成账号／云传输，验证 100 条分页、新增与带修订编辑、删除确认取消、目录覆盖、五种排序模式选择、双拼候选使用 canonical_pinyin、服务器上下文与修订用于固定排位、导入读取和文件取消、文件式导出参数、快照预览／替换／恢复确认、修订冲突禁用旧预览、请求前与传输期间换号拒绝及损坏响应清除旧结果。系统文件对话框和确认框里发送轮询消息，验证不会先提交状态任务再吞掉已确认操作。

Win7 x64 Rust 目标实际运行共享 `cloud_dictionary::` 29 项测试并通过，覆盖完整文件备份／恢复、摘要变化拒绝、失败时保留旧文件、中转清理、未登录拒绝和队列节流；窗口测试注入的是网络服务边界，不宣称真实云端备份与恢复已经通过。程序已知 PE 导入审计 x64 252／x86 247 项；这不等于完整 Win7 系统导出与运行库审计。最终全部源码 quick 另行记录。Win7 SP1 x64 桌面的初次运行揭示了缺失配置触发无效请求的问题；修复后构建机 x64／x86 各八套面板回归通过；Win7 SP1 x64 的两个架构各 21 项原生窗口回归全部通过，其中云词库覆盖缺失、损坏、非对象及有效配置。此结果仍使用合成云传输，不代表真实云账号备份成功。

## Consequences

`panels/win7 --route=cloud-dictionary` 提供原生独立云词库，覆盖个人词条、完整目录、候选调频、固定排位、单类文件导入导出、整份备份／恢复和快照应用。候选固定排位使用服务端返回的上下文，修改双拼候选时使用 canonical_pinyin，不把用户后来改过的查询文字当作已显示候选的身份。整份文件经共享流式接口处理，宿主只保留元数据和路径。轮询仅在账号已绑定且没有业务请求、文件选择或确认框时受理。

代价是增加原生界面维护和每次操作前后账号核对；账号变化或错误后禁用旧控件，需重新查询，不自动覆盖或重试。关闭窗口会收尾后台任务，待应用队列下次打开后继续。Win7 产品启动器与安装包已集成，双架构原生窗口回归在 Win7 SP1 桌面通过，安装与实际输入证据见[产品构建](2026-10-24-windows7-product-build.md)；真实云账号备份与恢复未执行。
