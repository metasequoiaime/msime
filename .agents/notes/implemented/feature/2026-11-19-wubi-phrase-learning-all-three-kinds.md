# Agent Note: 五笔造词写入改为三版全对称

Status: implemented

## Problem

[五笔按输入习惯自动造词](2026-11-15-wubi-run-phrase-learning.md)沿用了[引擎与宿主接入新世纪五笔](2026-11-02-wubixsj-engine-host.md)定下的写入边界：造词时 86/98 方案只写 `wubi86`、`wubi98`，只有当前方案是新世纪才写 `wubixsj`。理由是降级兼容——2026-11 宽松读取之前发布的引擎遇到日志里的 `wubixsj` 行会把整次回放回滚、拒绝准备词库，所以只让主动选了新世纪的用户产生这种行（[词库数据格式 §6.2](../../../../docs/data-formats.md)）。

维护者 2026-11-19 明确要求翻转：项目已经能对新世纪单字表正确推导任意新词的四码（`wubi::code::phrase_code` 的回调查询哪张表就取哪张表的码，新世纪表「甲 qrst + 乙 uvwx → qruv」有测试钉住），新造的词理应同时写进三版字库；86/98 用户以后切到新世纪，以前造的词要直接可用，不必重打一遍。原先「等宽松读取版本覆盖足够多用户再放开」的门槛由维护者这次授权跨过。

## Decision

造词写表与当前方案解耦，`learned_kinds()` 改成无参函数，恒定返回 `Wubi`、`Wubi98`、`WubiXsj` 三版：

- `learn` 和 `delete_other_learned_kinds` 的 `profile` 参数保留在签名里（调用方与 C/宿主边界不变），改名 `_profile`，不再决定写哪版或删哪版；文档注释写明这一点，并链接本篇笔记。
- 原有的 `sqlite_master` 表存在检查保留：旧词库没有 `wubixsj` 表时跳过这一版，不产生日志行，86/98 照常写。
- 对称删除跟着改成三版：`delete_other_learned_kinds` 对除 `keep` 外的两版按各自码表独立推导四码，删行并写墓碑；86 用户删词也会清掉 `wubixsj` 里的残行，不再留单侧残行。
- 编码推导不变：三版都走同一条 `phrase_code`，只是回调查询的表不同；新世纪行按新世纪单字全码取码，不拿 86 的码充数。

### 影响面与降级兼容

翻转的代价全部落在这一个点上：所有 86/98 方案下造词的用户，日志里从此都会出现 `dictionary='wubixsj'` 的 upsert 行和对应的删除墓碑。产生面从「少量主动选新世纪的用户」扩大到「所有造词的 86/98 用户」。降级到 2026-11 宽松读取之前的引擎时，这些日志会被整份判为失败、拒绝准备词库；宽松读取版本修复的是「不认识的种类只跳过那一行」，救不了没有这层保护的旧版本（[宽松读取的边界与已知上限](../architecture/2026-11-02-wubi-kind-forward-compatible-reads.md)）。这是维护者知情后接受的代价，本篇不把它记成无风险。

写日志与回放是词库跨代次持久化的唯一途径，所以不能为了规避降级风险只写 `wubixsj` 表、不写日志行：那样词库一换代次，新词就没了。

## Alternatives considered

- **维持「只有当前方案是新世纪才写」**——最强理由：保住原来的降级兼容边界，86/98 用户的日志里永远不出现新种类，风险只限愿意选新世纪的人。不用：维护者 2026-11-19 明确要求翻转，理由是新世纪编码推导能力已经具备、切换方案应当保留造词；原文记录在[五笔自动造词](2026-11-15-wubi-run-phrase-learning.md)和[引擎与宿主接入新世纪五笔](2026-11-02-wubixsj-engine-host.md)里，本篇接管这个取舍。
- **只写 `wubixsj` 表、不写日志行**——最强理由：日志里没有新种类，降级兼容问题整个消失，同时用户当下能看到新世纪的码。不用：日志是回放和跨代次持久化的唯一来源，不写日志的词在词库换代次后就丢了，等于造词只有本次会话有效。
- **做成设置项，让用户自选是否写新世纪表**——最强理由：在意降级的用户可以关掉，兼顾两边。不用：与 11-19 撤回造词时机选项时的简化方向相反，多一个设置项增加维护和选择成本；本次由维护者直接拍板全写，不需要用户再决策。

## Consequences

收益：三版字库对新词保持一致，86/98 用户切到新世纪后以前造的词直接可用；删除同步清三版，不留单侧残行；编码推导与权重规则完全复用原有路径，没有分叉。

代价与风险：

- 降级到 2026-11 宽松读取之前的引擎不受支持，且影响面扩大到所有造词用户；这一条仍未在真机做降级验收，发布说明需要写明。
- 日志行数按造词量线性增加三倍，回放和本地备份的开销随之增加，未量化。
- 三条既有测试的前置条件随决策变更而更新，不是为了让改动通过而绕过 bug：`derived_wubi_words_keep_native_rank_and_survive_replay` 的回放行数由 2 改 3 并补断言 `wubixsj` 也回放成功；`derived_wubi_words_preserve_existing_rows_and_deletions` 原来假设 86 的两版都已有行或墓碑、`learn` 返回无变化，现在第三版没有前置行和墓碑、照常写入，断言改为「86 已有行和 98 墓碑不动、新世纪写入」；`deleting_a_wubi_candidate_removes_both_learned_versions` 改名为 `...all_learned_versions`，断言删除与墓碑覆盖三版。

验证：`cargo test -p msime-engine` 全套 3242 项通过（59 项按既有标记忽略）、0 失败；`cargo clippy -p msime-engine --all-targets -- -D warnings` 无告警。测试用合成 fixture 词库，没有真实输入、没有真机与真实编辑器验收。
