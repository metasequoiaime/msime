# Agent Note: 词库持续补全与五笔新词学习

Status: implemented

## Problem

公共词条进入拼音输入后，两版五笔仍消费早先生成的补充表，新增词可能缺码。混输组字能保存拼音新词，却没有同步建立五笔编码；只修一个词不能改善后续缺词体验。

## Decision

每次词库构建使用当前固定输入和人工词条重新生成两版五笔补充数据，沿用现有筛选和排序规则，不改锁定输入。个人组词经用户选择并通过现有学习校验后，按各版单字全码生成五笔词条，写入现有工作库与回放日志。已有词条、删除记录和无法确定编码的字不被覆盖。个人学习不向公共服务上传。

公共扩词补齐固定上游的可复现生成工具及更新检查；设置页提供官网已有投稿表单入口，由用户主动填写并经审核进入公共词库。

## Related decisions

检索现有笔记后，[五笔多字词覆盖](../../implemented/feature/2026-10-18-wubi-vocabulary-coverage.md)负责来源筛选，部分重叠并保持权重门槛；[共用编码流程](../../implemented/simplification/2026-10-12-wubi-supplement-common.md)负责编码规则，部分重叠并复用；[五笔反查](../../implemented/feature/2026-10-11-wubi-reverse-lookup.md)继续禁止反查学习，与本次确认组词的边界互补。没有需要删除或归档的过时提案。

## Alternatives considered

- 全量放开低频拼音词：覆盖广，但增加四码重码与语料碎片，先保持现有门槛并输出覆盖、重码报告。
- 继续手动更新五笔补充表：版本容易审计，但每次人工投稿后都可能遗漏重建，构建时派生能消除这一步。
- 自动公开个人新词：能收集长尾词，但不能把个人学习当成公共投稿授权，复用用户主动投稿入口。

## Consequences

人工投稿不必同步重建五笔源快照即可进入两版发布词库。逐字确认的个人组词在两版五笔中生成低权重词条，沿用工作库和用户日志的事务及升级回放；关闭学习、反查、已有词条、删除记录、缺码和码不明确的情况不误写。两版写入在日志失败时共同回滚。

词库仓每周从干净上游检出生成审核候选，记录完整提交、生成器提交、输入摘要、去重集合及许可证。未注音行和引擎不支持的读音单列，不猜读音；无注音的 Tencent 表不导入。历史补充表有万象对齐，候选词频不能直接替换现行数据。上游升级仍需审核并同步跨仓引用、许可证与锁，预览不自动发布。

新增五笔词增加重码，可能使原本唯一四码停止自动上屏；构建报告统计数量。每次重派生增加构建时间。个人学习不上传，设置页只打开无词条参数的官网投稿表单。

## Verification

引擎完整单测覆盖原有反查禁学；新增合成组词覆盖全拼和五笔混输、学习开关、两版编码、低权重、幂等、删除、缺码和事务回滚。构建器集成测试在没有源快照的词库检出上修改人工词条，验证两版派生。

真实固定上游 `da1fbe602e38f26db846fa10120ee64c2b0324c0` 生成 35,706 个中文词音组合、2,448 个英文显示词，排除 143 个不支持的词音组合和 256 个未注音词；相同输入重复运行逐字节相同。这是审核候选，不代表已更新或发布源词库。

本机引擎完整单测 2,297 通过、40 忽略；构建器 182 通过、1 忽略，另有 11 项网页词库集成测试通过。Android API 28 专用模拟器的四组共享层测试通过，新增的 4 项五笔学习测试与 1 项跨会话组词测试也直接在设备上通过。Rust clippy（引擎与构建器全部目标）及共享设置 TypeScript 检查通过。

完整 Android 冒烟发现的复制设备信息失败已用默认分支安装包复现：旧测试的默认菜单坐标过时，修正定位后原安装包通过，未修改复制业务。
