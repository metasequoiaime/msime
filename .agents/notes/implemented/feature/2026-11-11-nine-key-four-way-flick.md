# Agent Note: 三端九键四向 flick 与共享阈值

Status: implemented

## Problem

#11244 要求拼音九键直接用四向 flick 输入字母，避免用户先滑出数字再点二级选项。现有 Android、iOS 和 HarmonyOS 只支持按配置上下滑出数字或弹出字母，阈值也只有 Android 可调，三端行为不一致。

## Decision

三端拼音九键 1–9 键保留轻点组字和长按选项；原来的数字滑动路径不再作为输入入口，数字继续通过长按选项输入。flick 只在有字母的 2–9 键上生效，判定以按下点为基准，取纵横位移较大的轴：上滑取第一个字母，左滑取第二个字母，右滑取第三个字母；下滑、超过现有字母数量的方向和 1 键均无动作。方向判定严格超过阈值，阈值使用共享偏好 `touch_nine_key_flick_threshold`，范围 14–48、步进 2、默认 24，三端原生设置页可修改，并随共享偏好在三端同步；HarmonyOS 在设置应用顶部的「九键四向滑动」打开独立 ArkUI 面板，不新增共享 React 控件；账号文档使用跨平台 `input.nine_key_flick_threshold`，同时保留 iOS、Android 和 HarmonyOS 的平台键以兼容旧客户端。iOS 只有在全拼九键字母层接管 flick，符号层、九键双拼、长按菜单、光标手势和 VoiceOver 不抢触摸。保留旧的 `touch_nine_key_swipe_digits` 字段读取兼容，但宿主不再使用它驱动输入。

HarmonyOS 的 `NineKeyFlickPanel` 只展示和适配控件，`FlickThresholdSettings` 通过既有设置桥读取共享 Rust 快照，每次保存前重读、仅修改 `touch_nine_key_flick_threshold` 并携带最新修订号；保存回复是显示值的权威来源，冲突与磁盘错误后回读，不自动覆盖重试。滑动期间只预览，松手或点按滑块才保存。缺字段仍显示 24，打开面板不主动写默认值；恢复默认时接收共享 Rust 省略默认字段的回复。回前台重新读取同步结果，返回键先退出原生面板。解释收在标题旁的「?」，读失败时滑块禁用而说明与重试保留可用。退出原生面板时强制把当前快照交回已有共享设置页，避免桥接记录过修订号后网页继续持有旧文档。本地阈值入口不要求联网授权，词库分组原有授权条件不变。原生设置使用现有镜像发布和键盘消费路径，不另存本机阈值。

完整偏好 Schema 公开九键 flick 阈值及默认值 24，便于文件事务命令和脚本查询。默认值仍从落盘文档省略；只给 Schema 覆盖 `skip_serializing_if`，不改变实际序列化和用户设置。

超过阈值和存在方向字母分开记录：下滑、1 键和字母不足的方向同样接管本次触摸，但不产生文本，也不回退成点按或在折返后改选另一方向。Android 的触摸适配放在独立的 `NineKeyFlickTouchListener`，保留长按弹窗的同次按压拖选、取消及按下态收尾；普通方向 flick 不再弹出字母菜单。三端保持首次超过阈值的方向锁定。

阈值的读写以共享偏好为唯一来源。默认 24 不落盘，所以「缺键」本身就是 24：Android 键盘和设置页、iOS 的 App Group 镜像都把缺键或不合规当作 24，iOS 只在文档读不到时保持原值；Android 旧的本机「九键滑动距离」不再当退路，否则用户调回 24 时键盘仍用旧距离。旧距离由 `KeyLayoutStyleMigration` 在共享阈值缺键、旧值合规且不是 24 时迁一次后删除，旧备份里的这个键恢复时转成平台键。账号同步时 Android、鸿蒙与 iOS 一样以 `input.nine_key_flick_threshold` 为准，文档里没有它时才退回本平台键，免得本机留在云端的旧平台键把别的平台刚改的值改回去；桌面没有这个设置项，不导出也不应用它，免得桌面上传用默认值盖掉手机上的选择。iOS 的 flick 与长按菜单、Android 和鸿蒙一样输入小写字母。拼音九键字母层的 ！ 与符号页相同固定上滑 14 dp 出 0，不再跟已经没有设置入口的「九键滑动输入数字」走。

旧设备测试的数字滑动及反方向弹窗前置条件由本次产品决定取代：预览改为断言方向字母，弹窗的进入、离开、松手留待点选与系统取消仍走长按入口完整验证；额外从系统输入法入口回放全部 2–9 键方向、下滑无动作、1 键无动作、取消、长按数字，以及共享阈值 14/48 对下一次触摸的影响。原有 `check-host.sh` / `tests/run.sh` 的对应源码 grep 移除，接线由行为测试承担。

## Alternatives considered

- 将四个方向完整映射到 7/9 键的四个字母：看似覆盖更多字母，但与已确认的“上/左/右依次映射、剩余方向无动作”不符，也会让下滑重新承担旧数字滑动的方向语义。
- 继续保留 Android 本机阈值、iOS/HarmonyOS 固定 24：实现成本较低，但用户明确要求共享阈值设置和三端同步，且会让同一账号在不同设备上手感不一致。
- 删除旧共享字段及其所有兼容测试：会让旧版本同步文档中的值无法被新版本平滑保留，增加升级时的字段漂移；本次只撤销宿主消费，字段继续由共享层宽松读取。

## Consequences

九键字母可通过一次方向手势直接输入，数字入口统一为长按；7/9 的第四个字母仍可从长按选项输入。用户可在 Android/iOS/HarmonyOS 原生设置调整同一阈值，三端下一次触摸都使用新值；鸿蒙原生控件补齐后的代码、构建和设备验证结果按各自提交区分。旧方向字段仍占据少量兼容代码和测试，但不会改变新手势行为；真实设备仍需分别验收 Android、iOS 和 HarmonyOS 的视觉反馈、触摸取消及设置同步。
