# Agent Note: 三端九键四向 flick 与共享阈值

Status: implemented

## Problem

#11244 要求拼音九键直接用四向 flick 输入字母，避免用户先滑出数字再点二级选项。现有 Android、iOS 和 HarmonyOS 只支持按配置上下滑出数字或弹出字母，阈值也只有 Android 可调，三端行为不一致。

## Decision

三端拼音九键 1–9 键保留轻点组字和长按选项；原来的数字滑动路径不再作为输入入口，数字继续通过长按选项输入。flick 只在有字母的 2–9 键上生效，判定以按下点为基准，取纵横位移较大的轴：上滑取第一个字母，左滑取第二个字母，右滑取第三个字母；下滑、超过现有字母数量的方向和 1 键均无动作。方向判定严格超过阈值，阈值使用共享偏好 `touch_nine_key_flick_threshold`，范围 14–48、步进 2、默认 24，三端设置页均可修改并随共享偏好同步；账号文档使用跨平台 `input.nine_key_flick_threshold`，同时保留 iOS、Android 和 HarmonyOS 的平台键以兼容旧客户端。iOS 只有在全拼九键字母层接管 flick，符号层、九键双拼、长按菜单、光标手势和 VoiceOver 不抢触摸。保留旧的 `touch_nine_key_swipe_digits` 字段读取兼容，但宿主不再使用它驱动输入。

超过阈值和存在方向字母分开记录：下滑、1 键和字母不足的方向同样接管本次触摸，但不产生文本，也不回退成点按或在折返后改选另一方向。Android 的触摸适配放在独立的 `NineKeyFlickTouchListener`，保留长按弹窗的同次按压拖选、取消及按下态收尾；普通方向 flick 不再弹出字母菜单。三端保持首次超过阈值的方向锁定。

旧设备测试的数字滑动及反方向弹窗前置条件由本次产品决定取代：预览改为断言方向字母，弹窗的进入、离开、松手留待点选与系统取消仍走长按入口完整验证；额外从系统输入法入口回放全部 2–9 键方向、下滑无动作、1 键无动作、取消、长按数字，以及共享阈值 14/48 对下一次触摸的影响。原有 `check-host.sh` / `tests/run.sh` 的对应源码 grep 移除，接线由行为测试承担。

## Alternatives considered

- 将四个方向完整映射到 7/9 键的四个字母：看似覆盖更多字母，但与已确认的“上/左/右依次映射、剩余方向无动作”不符，也会让下滑重新承担旧数字滑动的方向语义。
- 继续保留 Android 本机阈值、iOS/HarmonyOS 固定 24：实现成本较低，但用户明确要求共享阈值设置和三端同步，且会让同一账号在不同设备上手感不一致。
- 删除旧共享字段及其所有兼容测试：会让旧版本同步文档中的值无法被新版本平滑保留，增加升级时的字段漂移；本次只撤销宿主消费，字段继续由共享层宽松读取。

## Verification

Android 当前分支 arm64 原生 APK 构建通过；API 28/35 专用 AVD 的系统输入法四向触摸回放通过，覆盖全部 2–9 键字母、下滑和 1 键无动作、取消、长按数字及共享阈值 14/48。API 35 的预览与长按拖选专项通过；鸿蒙 `tests/run.sh` 全套通过，包含新的触摸所有权行为测试。Swift 的真实状态机代码独立回放通过。iOS 27 专用模拟器的系统键盘与独立编辑器实测通过：v5 回放全部 2–9 键的上/左/右、下滑无动作和长按数字；v7 在重新编译测试宿主后验证阈值 48/14 对下一次系统触摸生效。期间发现首行长按菜单会越出扩展上边界，已用边界约束修复并由同一回放覆盖。Android 设置改前/改后原尺寸截图保留在本机产物目录，图床下载回验为 PNG 且字节一致。

真实 ArkTS 编译补验发现 `KeyboardSession.appearance` 的初始对象缺少新增的 `nineKeyFlickThreshold`，已补上策略默认值；`ohpm install` 后的 `hvigorw assembleHap --no-daemon` 通过（`20261113-182849`）。这次产物只作为 ArkTS 编译与打包证据，没有暂存本分支的 Rust/NAPI 库和核心词库，也没有签名，不能作为可安装产品包。`tests/run.sh`、`pnpm run verify-notes` 与全平台 quick（`20261113-183128`）通过。`hdc list targets -v` 返回空列表；本分支完整 HAP 和签名设备验收仍需补齐；hdc 仍无设备。

## Consequences

九键字母可通过一次方向手势直接输入，数字入口统一为长按；7/9 的第四个字母仍可从长按选项输入。用户可在任一移动端调整同一阈值，三端下一次触摸都使用新值。旧方向字段仍占据少量兼容代码和测试，但不会改变新手势行为；真实设备仍需分别验收 Android、iOS 和 HarmonyOS 的视觉反馈、触摸取消及设置同步。
