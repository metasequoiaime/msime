# Agent Note: 三端九键四向 flick 与共享阈值

Status: implemented

## Problem

#11244 要求拼音九键直接用四向 flick 输入字母，避免用户先滑出数字再点二级选项。现有 Android、iOS 和 HarmonyOS 只支持按配置上下滑出数字或弹出字母，阈值也只有 Android 可调，三端行为不一致。

## Decision

三端拼音九键 1–9 键保留轻点组字和长按选项；原来的数字滑动路径不再作为输入入口，数字继续通过长按选项输入。flick 只在有字母的 2–9 键上生效，判定以按下点为基准，取纵横位移较大的轴：上滑取第一个字母，左滑取第二个字母，右滑取第三个字母；下滑、超过现有字母数量的方向和 1 键均无动作。方向判定严格超过阈值，阈值使用共享偏好 `touch_nine_key_flick_threshold`，范围 14–48、步进 2、默认 24，三端设置页均可修改并随共享偏好同步。保留旧的 `touch_nine_key_swipe_digits` 字段读取兼容，但宿主不再使用它驱动输入。

## Alternatives considered

- 将四个方向完整映射到 7/9 键的四个字母：看似覆盖更多字母，但与已确认的“上/左/右依次映射、剩余方向无动作”不符，也会让下滑重新承担旧数字滑动的方向语义。
- 继续保留 Android 本机阈值、iOS/HarmonyOS 固定 24：实现成本较低，但用户明确要求共享阈值设置和三端同步，且会让同一账号在不同设备上手感不一致。
- 删除旧共享字段及其所有兼容测试：会让旧版本同步文档中的值无法被新版本平滑保留，增加升级时的字段漂移；本次只撤销宿主消费，字段继续由共享层宽松读取。

## Consequences

九键字母可通过一次方向手势直接输入，数字入口统一为长按；7/9 的第四个字母仍可从长按选项输入。用户可在任一移动端调整同一阈值，三端下一次触摸都使用新值。旧方向字段仍占据少量兼容代码和测试，但不会改变新手势行为；真实设备仍需分别验收 Android、iOS 和 HarmonyOS 的视觉反馈、触摸取消及设置同步。
