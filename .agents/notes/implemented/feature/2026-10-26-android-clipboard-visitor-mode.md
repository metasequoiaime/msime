# Agent Note: Android 剪贴板访客模式

Status: implemented

## Problem

临时把手机交给他人操作时，输入法剪贴板历史仍与机主共享；只依赖无痕输入会丢失机主历史的隔离边界，也没有手势入口让机主快速切换。云剪贴板还可能把访客期间的内容带到账号设备。

## Decision

Android 输入法用一个跨进程共享的布尔偏好保存剪贴板模式。主模式继续使用原来的 `filesDir`，访客模式固定使用 `filesDir/clipboard-visitor`，输入法和设置页通过同一个目录选择器读写，因而删除、编辑、分类和导出不会跨模式触碰记录。模式切换不记录剪贴板文字，只保存模式本身。剪贴板补读用的“已处理身份”也按主模式和访客模式分别保存；否则主模式处理过的当前剪贴板会阻止键盘未运行期间的访客模式首次补读。升级时旧版本共用的 `handled_clip` 只迁移到主模式，避免主模式重复补读当前剪贴板，同时不让旧身份挡住访客模式。

回车键保留普通点击和组字长按确认；只有在键盘边界内、向上移动至少一枚键高、横向偏移不超过键宽且没有滑出过远区域的手势才切换模式。切换后短暂显示不同的回车图标，输入法重建键盘或从持久化状态恢复时始终显示回车图标。访客模式仍显示云端分段，但状态固定为“此功能开发中”，不发起网络读取、插入或上传。

## Alternatives considered

- **清空主模式历史后复用同一目录**：实现简单，但会破坏机主数据，无法满足访客结束后恢复原历史的要求。
- **仅把模式放在输入法进程内存中**：进程回收、切换输入法或锁屏后会回到主模式，违反模式必须跨生命周期保持的要求。
- **访客模式完全隐藏云端分段**：不会触网，但用户无法确认当前仍在访客模式；保留分段并显示固定状态能给出明确反馈，同时网络门禁仍在服务层生效。

## Consequences

主、访客历史在磁盘目录层隔离，输入法进程重启和应用切换后模式仍由共享偏好恢复；补读身份也不会跨模式互相阻挡。访客模式会强制开启本地历史以便记录临时内容，但不会改变主模式的剪贴板开关；模式切换后面板从新模式的本机历史开始，丢弃上一模式的云端标签状态。回车上滑的策略测试覆盖有效手势、短按、横向误触和滑出边界；回车图标策略测试覆盖持久化访客模式和切换中的短暂提示；完整 Android 模拟器验收仍需在有 SDK 和设备的环境执行。

## 后续决策

2026-11-09：#11134 报告输入法重建后所有输入框的回车键显示垃圾桶，实际动作仍是换行。原因是键盘初始化直接把持久化的访客模式映射为垃圾桶。决定只在刚切换到访客模式时短暂显示垃圾桶，恢复持久化模式时显示回车，保留切换动作和存储隔离。
