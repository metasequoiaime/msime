# Agent Note: Android 剪贴板访客模式

Status: implemented

## Problem

临时把手机交给他人操作时，输入法剪贴板历史仍与机主共享；只依赖无痕输入会丢失机主历史的隔离边界，也没有手势入口让机主快速切换。云剪贴板还可能把访客期间的内容带到账号设备。

## Decision

Android 输入法用一个跨进程共享的布尔偏好保存剪贴板模式。主模式继续使用原来的 `filesDir`，访客模式固定使用 `filesDir/clipboard-visitor`，输入法和设置页通过同一个目录选择器读写，因而删除、编辑、分类和导出不会跨模式触碰记录。模式切换不记录剪贴板文字，只保存模式本身。

回车键保留普通点击和组字长按确认；只有按下点在键盘边界内、向上移动至少一枚键高、横向偏移不超过键宽且没有滑出过远区域的手势才切换模式。切换后短暂显示不同的回车图标，输入法重建键盘或从持久化状态恢复时始终显示回车图标。访客模式仍显示云端分段，但状态固定为“此功能开发中”，不发起网络读取、插入或上传。

切换时总是回到本机标签，关闭旧面板并立即重绘工具栏；重开面板从新模式的历史读取记录与计数。删除撤销的待恢复条目和倒数回调也随模式切换清除，不能把原模式的记录恢复到新模式。普通收起面板不清除撤销，避免改变同一模式下已有的恢复体验。

## Alternatives considered

- **清空主模式历史后复用同一目录**：实现简单，但会破坏机主数据，无法满足访客结束后恢复原历史的要求。
- **仅把模式放在输入法进程内存中**：进程回收、切换输入法或锁屏后会回到主模式，违反模式必须跨生命周期保持的要求。
- **访客模式完全隐藏云端分段**：不会触网，但用户无法确认当前仍在访客模式；保留分段并显示固定状态能给出明确反馈，同时网络门禁仍在服务层生效。
- **跨模式保留撤销并绑定原存储**：可以在切换后恢复原模式的误删，但访客仍能操作机主记录；模式切换清除临时撤销内容，原模式磁盘数据不因此改变。

## Consequences

主、访客历史在磁盘目录层隔离，输入法进程重启和应用切换后模式仍由共享偏好恢复。访客模式会强制开启本地历史以便记录临时内容，但不会改变主模式的剪贴板开关。回车上滑的策略测试覆盖有效手势、短按、横向误触和滑出边界；回车图标策略测试覆盖持久化访客模式和切换中的短暂提示。API 28/35 的实际产品服务回归覆盖模式切换、重绘、独立历史计数及跨模式撤销；模式切换会丢弃尚未使用的删除撤销。报告者设备的完整手势与复现场景仍需复验。

## 后续决策

2026-11-09：#11134 报告输入法重建后所有输入框的回车键显示垃圾桶，实际动作仍是换行。原因是键盘初始化直接把持久化的访客模式映射为垃圾桶。决定只在刚切换到访客模式时短暂显示垃圾桶，恢复持久化模式时显示回车，保留切换动作和存储隔离。

2026-11-13：#11314 的首轮修复重置云端标签并显式重绘服务，防止触摸序列被手势消费后工具栏继续沿用旧选中状态，仍不读取或上传系统剪贴板。该轮没有设备证据；报告者实际选中本机标签、没有垃圾桶的现象不能仅凭这处重绘归因。访客首次补读的模式身份隔离由 #11318 的独立 PR 负责。

2026-11-13：#11312 在 Android 0.7.4 仍复现上滑回车后没有提示。原因是手势策略要求抬手点仍在键盘窗口内；从底部回车键向上滑时，抬手点常在窗口上沿之外，模式没有切换。现在只校验按下点在键盘内、横向偏移和最大行程，允许抬手点越过上沿但不能滑出三枚键高的范围。

2026-11-14：#11314 的补验覆盖实际服务切换、面板重画、两个历史的独立计数和删除撤销。新增设备回归在改前 API 35 APK 上分别确认工具栏未重画、原模式的撤销记录写进访客历史；模式切换清除撤销内容及计时器。同一模式的删除认证和撤销期限仍按[剪贴板删除认证](2026-10-31-android-clipboard-delete-auth.md)处理。组件图片来自实际产品视图在设备上的绘制，未连接云服务或读取系统剪贴板；它们不替代报告者 vivo 上的完整手势复验。
