# Agent Note: 一码辅助码严格筛选

Status: implemented

## Problem

全拼和双拼的一码辅助码以前只把命中的候选前移，未命中的候选仍留在候选列表中。用户无法选择排除这些候选的严格模式；双码辅助码已有严格筛选，行为需要保持不变。

## Decision

新增独立的 `strict_filter` 偏好，默认关闭，并沿用旧配置的缺省值。宿主把该值传入会话和查询请求；全拼一码在开启时只保留至少一个汉字命中该辅助码的候选，关闭时继续使用原有重排逻辑。双码始终使用已有严格筛选逻辑。设置页和 Android 输入设置页都提供同名开关，并明确说明一码关闭时只重排、开启后排除不匹配项，而两码一直严格筛选。

该字段使用可选序列化并跳过 `false`，因此旧配置无需迁移，默认值也不会改变已有用户的候选排序。

## Alternatives considered

- **把一码行为直接改成严格筛选**：实现简单，但会改变所有现有用户的候选列表和选择顺序，违反保持默认值的要求，因此不采用。
- **复用双码开关或按辅助码长度隐式决定**：无法让用户独立选择一码行为，也无法在设置页准确表达状态，因此不采用。

## Consequences

用户可以分别在全拼和双拼中开启一码严格筛选；关闭时保持兼容，双码行为不变。新增偏好贯穿 client-core、host-api、Engine 和移动端设置界面，增加了一个跨模块配置字段。由于本机磁盘空间低于仓库规定的完整构建门槛，本次只完成格式、差异和静态构造审查，Android 模拟器与完整 Rust 构建留给 CI 或有足够空间的环境复验。
