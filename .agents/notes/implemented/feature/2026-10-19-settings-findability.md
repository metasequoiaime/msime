# Agent Note: 设置搜索定位与桌面内容归位

Status: implemented

## Problem

侧栏搜索只匹配页面名，用户知道「麦克风」「字体」却不知道页面和标签时仍要逐页查找。语音结果提交与录音设备收在服务配置中，也让内容归属难以预测。

## Decision

搜索从已挂载偏好表单的行标题建立本机内存索引，只读取显式标题，不读取输入值、描述、历史记录或诊断输出。页面作用域标记归属；标签沿用 ARIA 关联；服务下钻提供显式展开入口。选择结果先切页面，再切标签、展开折叠并聚焦目标，不直接篡改 React 管理的显隐状态。语音标签沿用页首水杉娘的受控选中状态，搜索和录音设备显隐读取同一个 `selected`，避免两套标签状态互相覆盖。侧栏展示具体结果与页面、标签路径，保留中文组词键盘保护。

桌面语音的结果提交归入「识别与输入」，麦克风与细分提示音归入「录音行为」，服务配置保留接入、模型、凭据和测试。触屏原有结构不变。标签用自然标题，主题与候选窗口增加职责说明。

## Alternatives considered

- 静态逐项登记搜索词可严格控制收录，但需要重复维护每个宿主的能力与条件渲染，新增设置易漏收；采用挂载表单的显式行标题与可展开标记，不扫描任意页面文本。
- 搜索只筛页面最简单，但不能回答设置在哪个标签，也不能直接定位到隐藏内容。

## Verification

新增五项整页搜索测试覆盖麦克风、候选字体、服务高级项、折叠展开、焦点与中文组词保护；相关 175 项回归与整页设置 399 项回归通过。前端类型检查与生产构建、HarmonyOS 构建通过，Windows 可移植原生测试 157 项通过。浏览器验证 macOS 1000×780 浅色、800×600 深色及 Linux 800×600 深色的设置搜索、下钻与焦点跳转，无横向页面溢出或脚本错误。格式、lint、笔记与 quick 门禁通过。Windows 原生 WinUI 无法在此 Mac 上验收。同步 develop 时，保留录音行为标签内的能力正反例，并让云剪贴板回归按「历史记录 → 设置 → 历史记录」走完中继保存流程；提示词测试进入当前「自定义提示词」折叠。

## Consequences

整页回归按实际内容归属查找控件：Windows 麦克风进入「录音行为」，系统识别先在「识别与输入」修改提交策略，再进入服务配置检查润色；旧 MCP 路由归到 `ai`。中继编辑和辅助码导入等待目标控件解除禁用后操作，因为偏好草稿挂载早于加载请求的 `finally` 解除禁用；仅等待表单出现不代表用户已经能操作。不增加固定延时，不放宽凭据保留、插件选中或保存内容的断言。

只有已挂载且宿主支持的设置参与索引；条件控件需先启用其前置选项。索引不读控件值，剪贴板记录不带可索引标记。显隐由页面、标签和下钻各自持有，搜索通过显式展开契约进入；未标记的隐藏条件不由搜索越过。Linux 侧栏补上搜索入口，使共享桌面设置均可使用逐项定位。

结果以页面、标签、分组显示路径；搜索期间替换侧栏导航，清空后恢复扁平导航。Windows 已有原生逐项搜索，沿用实现，同步输入辅助标题、主题职责说明与语音内容顺序。桌面服务下钻不再承担结果提交与录音设备。
