# Agent Note: Android 诊断包导出记住授权目录

Status: implemented

## Problem

#8040 希望用户选一次导出文件夹，以后直接导出。开发者页只生成缓存 ZIP 并打开分享面板，没有持久目录。裸文件路径不能代表 Android 文档提供方的授权，也不能跨重启恢复访问。

## Decision

用系统 `ACTION_OPEN_DOCUMENT_TREE` 选择文件夹，取得可持久化读写授权后才写入本机开发者设置。目录不进同步或备份，重置设置清除默认目录。默认导出直接在授权目录创建独立 ZIP；未选目录时先选择并继续本次导出。更改选择被取消或授权失败时保留原设置。失去授权、目录被删除或不可写时明确提示重新选择，不擅自保存到其他位置。

保留独立的分享入口。两条路径都复用共享 Rust 诊断包和现有隐私过滤。文件名带时间与 UUID，SAF 写入复用空文档检查；失败不删除提供方文档，提示可能的半成品。缓存分享归档一天内保留独立路径，避免旧分享 URI 指向新内容。页面结果沿用 `HostTask` 的视图代次隔离。

## Alternatives considered

- 记住分享选择器或裸路径：改动少，但下次仍需用户选择，且路径不能提供文档访问授权，不能满足直接导出。
- 将导出统一改为目录保存：入口少，但用户仍可能需要直接分享诊断包，因此保留单独分享按钮。
- 写入失败删除新文档：界面干净，但提供方可能返回已有文档，误删代价高；保留文档并提示用户检查。

## Verification

231 项 JVM 冒烟与设备源码编译通过，原生完整 APK 构建通过。API 28 已通过输入主路径与原生诊断包隐私回归，系统选择器授权与首次导出通过。跨进程重启、取消、撤权、异常提供方与 API 35 的完整目录回归仍在验收，尚不声明这些路径通过。

## Consequences

固定目录避免每次导出重复选择，独立分享继续可用。文档提供方可能不支持持久授权或创建文件，这类目录不能保存。跨提供方写入无法保证原子完成，失败可能留下半成品。设备验收只证明专用模拟器上的系统提供方与合成故障，不等于全部厂商文件管理器或真机覆盖。
