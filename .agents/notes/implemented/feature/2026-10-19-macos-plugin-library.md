# Agent Note: macOS 插件页采用分类卡片库

Status: implemented

## Problem

macOS 插件页把内置音效、音乐和数据插件串成全宽长列表。常用设置、插件状态和导入入口之间没有明显层级，查看后面的类型需要经过全部音效。

## Decision

仅 macOS 使用插件库布局：声音与效果和 @ 名单是顶部快捷卡片；已安装插件以两列卡片展示，类型筛选和搜索缩小列表。导入操作放在插件库标题旁，说明使用折叠区。筛选由 `usePluginsSection` 持有，`PluginsSection` 负责视图组合，打开详情再返回仍能恢复原卡片的焦点。其他平台保留现有布局，插件选择与授权规则继续复用原有函数。

## 旧笔记审计

检索活跃笔记中的「我的插件」、`PluginListView`、插件列表与详情。[导航行独立复用](../../implemented/simplification/2026-10-17-plugin-nav-row.md)、[插件操作块](../../implemented/simplification/2026-10-17-plugin-action-block.md)和[社区插件卡片](../../implemented/simplification/2026-10-17-community-plugin-card.md)只约束各自组件，部分重叠但继续有效；脚本授权与指令行笔记负责运行时规则，无关。本篇不取代已有决定。

## Alternatives considered

- 仅缩短原列表的行高：改动最少，也保持所有插件始终可见；但不同类型仍只能依次向下寻找，无法解决长列表的信息层级问题。
- 每个类型单独一页：类型边界清楚，但查找和比较少量插件要反复切页。采用同页筛选和卡片，在原详情导航上减少定位成本。

## Verification

新增四项交互回归覆盖分类与搜索、详情返回焦点、缺失包恢复、空结果、目录问题、导入及删除分类最后一个包。相关六个测试文件共 131 项通过；类型检查与前端构建通过。Chromium 中检查深浅色和 1000、800、600、390 像素宽度，无横向溢出。macOS 原生宿主与设置组件从当前分支构建通过，仓库 `verify-local.sh --quick` 通过（含 Linux 设置壳容器编译）；HarmonyOS ArkTS 阶段因未准备构建依赖跳过。顶部 Tab 恢复共用样式后，相关 7 项测试、类型检查与前端构建再次通过。原生设置窗口预览未完成，未验收系统输入源安装或真实编辑器输入。

## Consequences

卡片宽度受设置窗口影响，使用容器查询在窄内容区降成一列；搜索只影响插件列表，不隐藏目录错误。顶部「我的插件 / 社区插件」沿用共用 Tab 样式，不单独覆盖尺寸。筛选状态不写入偏好。筛选增加一次操作，但同时提供全部视图，声音与效果和 @ 名单在任何筛选下都可打开。macOS 新增单独的展示组件，其他平台继续使用分组列表，数据、选择、授权和异步动作由原来的父级管理。

共享状态与导航的模块边界见[插件设置状态与导航](../simplification/2026-10-23-plugins-section-state.md)，本篇的布局和筛选保留规则继续有效。
