# Agent Note: 云剪贴板双向自动同步

Status: implemented

## Problem

#11154 的自动上传仍要求接收端打开云端面板再复制。维护者在本次会话明确「云剪贴板开启即自动同步」，并在询问是否自动写入接收端系统剪贴板时选择「最佳体验」。该授权覆盖自动上传和接收；不新增默认关闭的第二个开关。

## Decision

Android、iOS 和 HarmonyOS 在输入视图可见且当前编辑框允许云剪贴板时自动接收；Android 现有复制监听继续自动上传；iOS 与 HarmonyOS 同步键盘可见期间观察到的新复制。云端新文本只写入系统剪贴板。账号、中继和 WebDAV 继续复用现有端到端加密与绑定校验。密码框、隐私模式、访客模式、未批准设备和系统敏感剪贴板均禁止自动同步。接收不改编辑器正文；用户仍以正常粘贴决定输入位置。

宿主串行调度请求，接收前重新核对账号、选路、当前输入框和本机复制代次。接收产生的剪贴板回调不得再上传。网络失败不持久化文本、不弹错误、不重试旧复制；轮询采用退避，离开允许的生命周期即停止。剪贴板已经有更新的本机复制、敏感文本或非文本内容时，不被旧云端文本覆盖；历史条目删除后也不回放更老内容。

Android 用系统剪贴板时间戳比较新旧；没有可靠时间戳的非空本机文本、图片和敏感内容均保留。网络请求沿用串行工作线程，开启且设备已批准时每三秒检查，关闭、未登录或失败时等待三十秒，收起键盘即停；排队任务在发请求前还核对可见生命周期。接收标记随系统剪贴板保存，换输入框、换号或服务重启后也不回传。状态只保存在内存，没有新增文件或持久文本队列。

iOS 通过 `UIPasteboard.changeCount`、条目数和文本类型判断本机是否发生复制，不读正文；自动接收只在键盘扩展可见且有完全访问权限时轮询。本机已有内容时，首次有效列表只建立云端水位，随后更晚的远端复制可以替换未再改变的本机文本；本机复制发生后，下一次有效列表重新建立水位。空列表同样建立基线，避免云端开始为空时漏掉第一条新复制；图片等非文本内容不写回。接收成功用本地剪贴板选项写入并记录内存标记。iOS 在云端确认已开启且本机获批准后读取本轮新复制并自动上传；正文读取服从系统粘贴授权，拒绝或失败后不反复读取同一次复制。初始未知时间的本机内容、刚换账号或中继前的内容不自动上传，避免陈旧内容覆盖新设备。系统收起扩展后无法保证继续监听，不能宣称全系统后台常驻。读取与接收都绑定可见生命周期和本轮账号，接收更新的 `changeCount` 直接记为已知，不触发回传。

HarmonyOS 在会话绑定编辑框且获得隐私联网授权时轮询，使用文本快照区分用户复制和上一次接收；已有文本与本机复制后的首次列表只建立水位，之后允许新的远端复制。系统读取失败与非文本返回独立的空值，不把它们误作空剪贴板。写入失败不推进远端代次；会话 detach、stop 或编辑框不允许云剪贴板时停止有效处理，任何异步挂起点之后都核对生命周期代次，写入前同步复核账号或中继绑定。HarmonyOS 在同一串行轮询中自动上传观察到的新本机文本，复用 `CloudClipboardClient.add` 与现有有效文本校验；读列表期间又复制时只发送重读后的当前文本，不补传旧快照。初始内容和换绑定时已有内容不上传，接收回声按同一快照去重；失败不保留待发队列，用户明确发送历史条目的入口继续保留。

本决定取代[Android 自动上传](../../implemented/feature/2026-11-13-android-auto-cloud-clipboard.md)中「云端条目不自动写回」的范围限制，其账号绑定、隐私闸门和失败处理继续成立。

## Alternatives considered

- 只自动上传：无需覆盖系统剪贴板，系统权限和生命周期更简单；接收端仍要进面板操作，不能实现维护者要求的直接复制、粘贴。
- 失败后保存待上传文本：可以最终补传，但会把旧复制延后送出，扩大保留范围，且可能覆盖之后产生的新内容；只在内存中处理当前事件。

## Verification

新 Linux 同步 helper 加入 `MSIME_AUXILIARY_TARGETS` 后，崩溃回归发现它没有采集器，测试也未传入它要求的 runtime options 参数，因而在读取请求前退出。本轮为真实程序补上绑定显式配置的 `CaptureOnly`，测试按真实命令行传入合成配置；保留关闭不记录、真实信号、原版本补报和配置安全的全部断言。

iOS 与鸿蒙的原接收测试只证明本机内容不会被覆盖，未证明已有本机文本时后续远端复制可达。本轮保留初始内容和请求期间本机复制的保护，补上新修订可达、空云端基线、换绑定、停止后迟到请求及非文本／读取失败的行为用例，修复永久拒绝接收的实现缺口。检索到的 Android 自动上传笔记与本篇范围互补，原地更新本篇，不改变默认设置或上传授权。

`CloudClipboardReceivePolicySmoke` 通过，覆盖新旧复制、同内容去重、重复接收通知、本机并发复制、取消代次、敏感或非文本保护、缺失与非法时间戳、删除后的旧条目，以及同一毫秒内的微秒修订。iOS 本分支原生静态库构建及实际模拟器上的 `KeyboardCloudClipboardTests` 26 项通过；HarmonyOS 键盘逻辑、真实 `.ets` 适配器测试及 unsigned HAP 构建通过，尚缺本分支完整 Rust/NAPI 暂存和签名设备验收。共享账号绑定测试及相关 crate 的 Clippy 通过。Linux 父进程同步与配置目标测试 15 项、Wayland 子进程回归 5 项通过。Linux 新 helper 及 X11 读取在既有构建镜像中以 `-Wall -Wextra -Werror -fsyntax-only` 检查通过；真实崩溃采集回归仍待 Linux CI。两台真实设备间经加密后端复制、粘贴尚未验收，不把纯策略测试记作端到端通过。

## Consequences

移动操作系统会限制后台监听或主动读取，系统权限提示和应用未运行时的限制必须如实记录。跨设备系统时钟有偏差，时间戳只能配合复制代次和云端修订使用；无法确定新旧时保留本机内容。

macOS 与 Linux 同样先建立本机内容的云端水位，后续新复制仍可达。macOS 按系统复制代次保护同文本的再次复制，排除密码管理器标记、非文本和读取失败；写回后核对正文才推进水位。Linux 用带时区的日期比较修订，读取失败与非文本不再被当作空串覆盖。原生 X11 读取用独立状态 3 表示没有选区所有者，监视器只把这一状态认作空剪贴板；图片或读取失败仍保留，空剪贴板因此也能接收新的远端复制。自动上传集中到父监视器，Wayland 采集子进程只向管道交付当前事件，本机历史关闭时仍观察云复制；启动和换绑定只建立基线。helper 的列表和上传携带来源快照，中继携带修订号，账号携带预期用户；请求完成后再次比对绑定。显式 provider 优先，需遵守预期用户字段；外部 provider 的独立账号无法由本机账号推断，不宣称已覆盖这一能力。纯 Wayland 无 XWayland 可复读时仅上传 data-control 事件，不自动接收；不调用可能抢焦点的 `wl-paste` 轮询，完整双向接收仍是未完成范围。

Windows 同步线程在全部成员初始化完成后启动，按系统剪贴板代次独立采样，不依赖本机历史开关。源选择、偏好修订号和账号固定在同一轮；中继请求携带 `expected_revision`，账号动作携带可选的 `expected_user_id`，共享层在取得加密驱动凭据时拒绝换号，旧调用未传字段时维持原行为。系统剪贴板在打开并持锁时再次比较代次再清空，读取失败、图片及隐私标记均不作为空白覆盖。UTC 修订先校验并补齐小数秒，再作水位比较；写入失败不消费远端修订，初始内容与本轮新复制只建立基线。

本次落地 Android、iOS、HarmonyOS、macOS、Linux 和 Windows 常驻宿主的自动接收；桌面同步绑定宿主生命周期，沿账号或自建中继当前选路，接收成功才写入系统剪贴板并标记回声，失败不保存待上传队列。Linux 复用登录时启用的剪贴板服务：本机历史关闭时仍可轮询云剪贴板，自动同步 helper 每三秒读取列表并在本机没有更新时写回；Windows Server 以独立 worker 线程每三秒轮询，通过系统复制代次抑制接收回声，不依赖历史采集回调。策略测试、Linux 监视器回归、原生 Swift 编译与 iOS 模拟器测试已通过；完整 Windows 宿主、Linux GTK/X11、HarmonyOS 签名设备和双设备端到端验收尚未完成。#11154 与现有 PR 继续保持开放。各宿主必须遵守系统读取授权和运行限制，桌面接入原生常驻宿主，不能依赖云剪贴板面板存活。
