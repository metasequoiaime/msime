# Agent Note: 云剪贴板双向自动同步

Status: implemented

## Problem

#11154 的自动上传仍要求接收端打开云端面板再复制。维护者在本次会话明确「云剪贴板开启即自动同步」，并在询问是否自动写入接收端系统剪贴板时选择「最佳体验」。该授权覆盖自动上传和接收；不新增默认关闭的第二个开关。

## Decision

Android、iOS 和 HarmonyOS 在输入视图可见且当前编辑框允许云剪贴板时自动接收；Android 现有复制监听继续自动上传；iOS 与 HarmonyOS 同步键盘可见期间观察到的新复制。云端新文本只写入系统剪贴板。账号、中继和 WebDAV 继续复用现有端到端加密与绑定校验。密码框、隐私模式、访客模式、未批准设备和系统敏感剪贴板均禁止自动同步。接收不改编辑器正文；用户仍以正常粘贴决定输入位置。

宿主串行调度请求，接收前重新核对账号、选路、当前输入框和本机复制代次。接收产生的剪贴板回调不得再上传。网络失败不持久化文本、不弹错误、不重试旧复制；轮询采用退避，离开允许的生命周期即停止。剪贴板已经有更新的本机复制、敏感文本或非文本内容时，不被旧云端文本覆盖；历史条目删除后也不回放更老内容。

Android 用系统剪贴板时间戳比较新旧；没有可靠时间戳的非空本机文本、图片和敏感内容均保留。网络请求沿用串行工作线程，开启且设备已批准时每三秒检查，关闭、未登录或失败时等待三十秒，收起键盘即停；排队任务在发请求前还核对可见生命周期。接收标记随系统剪贴板保存，换输入框、换号或服务重启后也不回传。状态只保存在内存，没有新增文件或持久文本队列。

iOS 通过 `UIPasteboard.changeCount`、条目数和文本类型判断本机是否发生复制，不读正文；自动接收只在键盘扩展可见且有完全访问权限时轮询。本机已有内容时，首次有效列表只建立云端水位，随后更晚的远端复制可以替换未再改变的本机文本；本机复制发生后，下一次有效列表重新建立水位。空列表同样建立基线，避免云端开始为空时漏掉第一条新复制；图片等非文本内容不写回。接收成功用本地剪贴板选项写入并记录内存标记。iOS 在云端确认已开启且本机获批准后读取本轮新复制并自动上传；正文读取服从系统粘贴授权，拒绝或失败后不反复读取同一次复制。初始未知时间的本机内容、刚换账号或中继前的内容不自动上传，避免陈旧内容覆盖新设备。系统收起扩展后无法保证继续监听，不能宣称全系统后台常驻。读取与接收都绑定可见生命周期和本轮账号，接收更新的 `changeCount` 直接记为已知，不触发回传。

HarmonyOS 在会话绑定编辑框且获得隐私联网授权时轮询，使用文本快照区分用户复制和上一次接收；已有文本与本机复制后的首次列表只建立水位，之后允许新的远端复制。系统读取失败与非文本返回独立的空值，不把它们误作空剪贴板。写入失败不推进远端代次；会话 detach、stop 或编辑框不允许云剪贴板时停止有效处理，任何异步挂起点之后都核对生命周期代次，写入前同步复核账号或中继绑定。HarmonyOS 在同一串行轮询中自动上传观察到的新本机文本，复用 `CloudClipboardClient.add` 与现有有效文本校验；读列表期间又复制时只发送重读后的当前文本，不补传旧快照。初始内容和换绑定时已有内容不上传，接收回声按同一快照去重；失败不保留待发队列，用户明确发送历史条目的入口继续保留。

本决定取代[Android 自动上传](../../implemented/feature/2026-11-13-android-auto-cloud-clipboard.md)中「云端条目不自动写回」的范围限制，其账号绑定、隐私闸门和失败处理继续成立。

桌面的持久登录绑定复用已有 `SavedAccountSession.session_id`：刷新令牌保留 UUID，重新登录生成新 UUID，旧会话的缺字段迁移沿用共享写锁。只读 `binding` 不联网、不返回访问或刷新令牌。初次列表、上传和 401 刷新重试都核对同一登录，不能用新进程总从零开始的实例内 generation 代替。provider 的独立账号按相同握手契约返回自己的登录编号，并在取得凭据时拒绝过期 `expected_login`。

## Alternatives considered

- 直接把 `wl-paste --type text --watch` 的缓存当作当前选区：复用原有工具最少接线，但 wl-clipboard 2.2.1 在选区没有文本类型时直接跳过回调，父进程会保留旧文本；命令返回也不能证明异步所有权已经写入。采用原生 data-control，完整观察失效事件并取得来源回执。此处扩展常驻监视器的能力，[不抢焦点的既有约束](../../implemented/bug-fix/2026-10-10-linux-wayland-clipboard-no-focus-read.md)继续成立，未为 Tauri 引入新的客户端或设置。

- 直接使用账号 ID 或实例内 generation：无需扩展握手，接线更少；不用，因为同账号重登不会改 ID，而 Linux helper 每次新进程的 generation 不能区分两次登录。
- 由本机账号推断 provider 身份：兼容已有本地状态，少一次 socket 请求；不用，因为外部服务可以独立登录，且旧 provider 无法保证拒绝过期绑定。

- 只自动上传：无需覆盖系统剪贴板，系统权限和生命周期更简单；接收端仍要进面板操作，不能实现维护者要求的直接复制、粘贴。
- 失败后保存待上传文本：可以最终补传，但会把旧复制延后送出，扩大保留范围，且可能覆盖之后产生的新内容；只在内存中处理当前事件。

## Verification

Fedora 45 的首轮 PR CI 在启动独立 Sway 时返回 `EPERM`，11 项断言未执行。固定同一个 Fedora 基础镜像可复现：发行包的 `/usr/bin/sway` 带 `cap_sys_nice=ep`，默认容器能力边界不允许执行；移除这项文件能力后同一二进制的版本检查成功。RPM 测试镜像显式安装 `libcap`，仅对镜像内的测试合成器执行 `setcap -r`；不扩大容器权限，不关闭任何测试，也不改变客户端运行时。修订后的完整 Fedora 门禁等待最终提交 CI，不能用 Debian 结果替代。

本轮原生 Wayland 核心在 Debian 容器编译，独立无窗口 Sway 的真实选区测试通过，包含带所有权回执的云端写回、父监视器上传接收与回声抑制、同文本再次复制、请求期间本机复制、图片失效、敏感标记与明文同时提供、过期代次拒绝及 4000 字完整管道传输。只使用合成内容，未接触登录桌面；初次父监视器用例在选区基线建立前发布远端复制，触发预期的启动保护，改为等待第二轮基线后通过。首次完整门禁发现测试在版本号初始化前注册，预期版本为空；调整 CMake 顺序后，生产辅助程序的 11 项 Wayland 用例全部通过，包含真实崩溃采集开关、原版本补报及私人正文不入报告的回归。`platforms/linux/build-container.sh` 最终退出码 0：129 项 CTest 中 128 项通过，现有 `linux-ibus-demand-activation` 因容器环境跳过；full/wubi 两套构建与安装暂存、测试目标开关隔离和八个 Python 入口的真实崩溃采集均通过。固定协议 XML 的 HPND 全文随包分发，来源见第三方清单。

## Consequences

移动操作系统会限制后台监听或主动读取，系统权限提示和应用未运行时的限制必须如实记录。跨设备系统时钟有偏差，时间戳只能配合复制代次和云端修订使用；无法确定新旧时保留本机内容。

macOS 与 Linux 同样先建立本机内容的云端水位，后续新复制仍可达。macOS 按系统复制代次保护同文本的再次复制，排除密码管理器标记、非文本和读取失败；写回后核对正文才推进水位。Linux 用带时区的日期比较修订，读取失败与非文本不再被当作空串覆盖。原生 X11 读取用独立状态 3 表示没有选区所有者，监视器只把这一状态认作空剪贴板；图片或读取失败仍保留，空剪贴板因此也能接收新的远端复制。自动上传集中到父监视器，Wayland 采集子进程只向管道交付当前事件，本机历史关闭时仍观察云复制；启动和换绑定只建立基线。helper 的列表和上传携带来源快照，中继携带修订号，账号携带持久登录绑定；请求完成后再次比对绑定。显式 provider 优先，自动同步先向所选 socket 请求 `binding`，由 provider 返回它自己的用户与登录编号，不再读取本机水杉账号来推断外部登录。provider 不支持握手或返回无效绑定时暂停自动同步，不回落其他来源；手动面板请求保持原协议。纯 Wayland 由新的原生 data-control 工具负责选区，监听文本、非文本、空选区和敏感 MIME；读取有一秒和 4000 UTF-16 单元上限，读取开始即撤销旧文本快照。写入携带当前选区代次，原生端先完成一次合成器往返再复核，只有未变化且可读的选区才允许写入。原生来源提供唯一 MIME 标记，收到该来源的选区事件才确认写入；后续用户复制即使正文相同也有新的选区代次。延迟回执仍带接收来源，不回传。缺少原生工具时保留旧 `wl-paste --watch` 采集；该回退没有 XWayland 时仍不自动接收。不支持 data-control 时沿用 XWayland 或暂停，不轮询可能抢焦点的 Wayland 读取。

Windows 同步线程在全部成员初始化完成后启动，按系统剪贴板代次独立采样，不依赖本机历史开关。源选择、偏好修订号和账号固定在同一轮；中继请求携带 `expected_revision`，账号动作携带可选的 `expected_login:{user_id,session_id}`，共享层在取得加密驱动凭据前后核对持久登录编号，拒绝换号与同账号重新登录；旧调用只传 `expected_user_id` 或未传字段时维持原行为。系统剪贴板在打开并持锁时再次比较代次再清空，读取失败、图片及隐私标记均不作为空白覆盖。写回使用临时的隐藏消息窗口作为所有者；空窗口句柄配合 `EmptyClipboard` 会使 `SetClipboardData` 失败，不能把只返回策略成功当作写入成功。窗口在关闭剪贴板后销毁，已分配的完整系统数据继续可用。新增真实 Windows 测试覆盖写回后的读取、所有者销毁后数据保留、前台焦点不变、过期代次拒绝覆盖和空内容拒绝；CI 的 x64/Win32 pipe-only 作业显式编译并执行它，本机交叉编译不记为运行通过。本轮将 x64 与 x86 静态测试程序复制到 Windows 11 测试机，在各自新建的隔离窗口站和桌面中运行，退出码均为 0；测试只操作该窗口站独立的剪贴板，不读取或改写登录用户的剪贴板，也不在测试机新建构建树。CI 继续以 MSVC 在 x64/Win32 上执行同一测试。依据见 [Microsoft OpenClipboard 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-openclipboard)。UTC 修订先校验并补齐小数秒，再作水位比较；写入失败不消费远端修订，初始内容与本轮新复制只建立基线。

本次落地 Android、iOS、HarmonyOS、macOS、Linux 和 Windows 常驻宿主的自动接收；桌面同步绑定宿主生命周期，沿账号或自建中继当前选路，接收成功才写入系统剪贴板并标记回声，失败不保存待上传队列。Linux 复用登录时启用的剪贴板服务：本机历史关闭时仍可轮询云剪贴板，自动同步 helper 每三秒读取列表并在本机没有更新时写回；Windows Server 以独立 worker 线程每三秒轮询，通过系统复制代次抑制接收回声，不依赖历史采集回调。策略测试、Linux 监视器回归、原生 Swift 编译与 iOS 模拟器测试已通过；完整 Windows 常驻宿主、真实 Linux 桌面的双设备链路、HarmonyOS 签名设备和双设备端到端验收尚未完成。#11154 与现有 PR 继续保持开放。各宿主必须遵守系统读取授权和运行限制，桌面接入原生常驻宿主，不能依赖云剪贴板面板存活。
