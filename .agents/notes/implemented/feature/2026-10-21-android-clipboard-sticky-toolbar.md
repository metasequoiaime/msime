# Agent Note: Android 剪贴板面板固定顶栏

Status: implemented

## Problem

#9035 反馈剪贴板历史较长时，顶行的本机、云端、搜索、导出、多选、清空和撤销操作会随记录一起滚出视口。用户必须先滚回顶部才能再次使用这些入口，长列表中尤其明显。

## Decision

Android 剪贴板面板把顶行拆成固定区域和内容滚动区域。`clipboardSurface` 作为面板的可见性和覆盖层边界，固定的 `clipboardHeader` 直接放在顶部，原有 `clipboardPanel` 保留在 `clipboardScroll` 中，只滚动历史卡片和面板正文。固定区域与滚动区共享同一面板背景和水平内边距，顶栏高度固定为 32dp；清空确认、多选状态和云端刷新仍在固定顶栏内重绘。所有打开、关闭、工具栏对齐和面板状态判断都以外层 surface 为准，避免滚动容器滚动后留下孤立的返回状态。

## Alternatives considered

- **在公共关闭方法中刷新**：所有关闭入口都能立即同步按钮，但面板切换会连续关闭多个区域再统一渲染，底层关闭方法主动刷新会渲染中间状态。因此插入入口在提交文本、清除最近复制条目并关闭历史面板后统一刷新，顶栏与底栏都读取最终状态（#10036）。

- **只在滚动时把原顶行重新滚回顶部**：实现改动小，但会打断用户浏览历史，且无法保证用户拖动或惯性滚动期间顶栏持续可用，因此不满足“任何时候都能使用”。
- **把顶栏悬浮在现有 `ScrollView` 上方**：可以避免重排历史内容，但需要额外处理悬浮层的遮挡、背景和面板显隐，且现有面板状态仍以滚动容器为边界，容易在工具栏隐藏时留下错位入口。将滚动内容和固定区域放进同一个外层 surface 能让可见性、对齐和背景只有一个边界。

## Consequences

固定顶栏不再参与历史内容的滚动，长列表滚动只作用于 `clipboardScroll`；顶栏会占用固定的 32dp 高度，内容可用高度相应减少。分词页继续在内容区内部使用自己的滚动区，底部操作行的既有固定行为不变。面板的显示、关闭和工具栏退出判断增加了一个 surface 层，后续新增剪贴板子视图应放入对应的固定区或滚动区，不能直接绕过这两个边界。底栏的剪贴板入口也必须以 `clipboardSurface` 作为切换和选中态边界；只读 `clipboardScroll` 会在 surface 隐藏后保留子视图的可见属性，造成剪贴板图标仍高亮（#9259）。

设备回归在隔离缓存目录写入 30 条合成记录，驱动实际剪贴板渲染；在 320dp 和 600dp 下确认记录确实滚动、顶栏位置不变、首行不被遮挡，以及关闭后整个面板和打开状态一起清除。该检查不读取或修改用户历史。

插入入口在隐藏面板后立即调用 `render()`。引擎取消组字时的渲染发生在关闭面板之前，提交文本本身不会刷新；若只隐藏面板，顶栏和底栏都会保留上一次的选中态，直到下一个按键刷新（#10036）。回归用真实 `EditText` 的输入连接调用 `insertClipboardText`，先确认合成文本确实写入、面板确实关闭，再在同一次调用返回时检查两个入口均取消选中；测试不补调 `render()`，也不等待编辑器回报或额外按键。

#10036 的新增断言在未修复版本复现“文本写入、面板关闭但顶栏仍选中”；修复后，独立 API 28 模拟器上的 `ToolbarEdgesDeviceSmoke` 完整通过，包含两入口状态、240/320/600dp 布局、固定顶栏和键盘重建后的手势检查。`ClipboardSegmentActionsDeviceSmoke` 同时确认真实键盘里的分词、分享、常用语、复制、最近复制预览与插入流程通过。

验证使用 Android 宿主检查、APK 构建和 API 28 模拟器剪贴板设备回归，确认固定顶栏改动没有破坏历史、分词和插入流程；#9259 另在 API 35 模拟器确认底栏入口在面板打开时选中、点击后关闭且立即取消选中。

[手动分类与返回顶部](2026-10-23-android-clipboard-categories.md)复用此固定区域边界，顶栏仍为 32dp；返回顶部是正文区域的独立操作。分类、导出、清空收进了顶行的 [「更多」菜单](2026-10-29-android-clipboard-more-menu.md)，菜单画在滚动区里，顶行在常见宽度下不再需要横滑，放不下时仍可横向滚动。
