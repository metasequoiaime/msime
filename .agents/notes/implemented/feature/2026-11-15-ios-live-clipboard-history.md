# Agent Note: iOS 在键盘可见期间采集连续复制

Status: implemented

## Problem

[#11448](https://github.com/metasequoiaime/msime/issues/11448) 已确认全平台处理。iOS 本机历史原先只在点「保存」时读取系统当前文本，连续复制后只能保存最后一条。

## Decision

设置说明收进已有标题旁的「?」，不常驻重复介绍。原生剪贴板设置页接入已有共享 Rust 偏好 `clipboard_history`，以「自动保存复制内容」显式选择；沿用默认关闭和缺字段关闭，不新增默认值。键盘可见、允许完全访问、本次出现已成功异步重读共享偏好、用户已开启且隐私闸门允许时，收到系统变化通知立即读取正文并按序存入既有共享历史 ABI。偏好读取失败不沿用旧的开启状态，也不在主线程等待共享文件锁。保存失败保留有界原文队列重试，隐藏或停用即丢弃内存待保存内容。

## Existing notes audit

[移动端容量](../../implemented/feature/2026-10-15-mobile-clipboard-history-limit.md)及[可选容量](../../implemented/feature/2026-10-17-clipboard-history-capacity.md)继续持有存储规则；[Android 设备门禁](../../implemented/testing/2026-10-08-android-device-gates.md)不持有 iOS 权限生命周期。本项不改变手动保存能力或跨平台默认值。

## Alternatives considered

无条件在后台读剪贴板能减少操作步骤，但会改变未选择自动采集的用户行为，且 iOS 会合并后台通知，无法支持持续后台历史。只提示用户每次点保存不增加能力，不能覆盖本次范围。选择已有关闭默认值下的显式开启与前台采集。

## Verification

新增 `ClipboardHistoryCaptureTests` 覆盖连续变化的原文队列、存储失败重试、关闭与隐私状态不读正文、启动不导入旧值、停止丢弃待保存内容、队列上限，以及真实隔离 `UIPasteboard` 的三次变化通知。iOS 27 专用干净模拟器上的 7 项测试通过，包含真实隔离 `UIPasteboard`；主应用及扩展同源编译，模拟 App Group 权限存在。两个原生 UI 测试通过：设置页截图、开关切换后终止重启仍保留并恢复原值。测试点右侧开关，避免 SwiftUI 组合行中心的「?」。生成工程提交新增文件引用，并保留许可证分组既有名称。完整 quick 与最终页面截图另在 PR 记录；模拟器不替代真机及报告者环境。

## Consequences

系统只保留当前正文，扩展被挂起时已经覆盖的条目无法追回；系统可能要求用户允许来自其他应用的粘贴。说明收进标题旁「?」，不承诺持续后台采集。最多保留 128 条未保存原文，单条最多 100,000 字节，与共享移动端字节上限一致；隐藏、进入隐私状态或停止时清除。共享存储明确拒绝的空、非法或全固定满载内容不定时重试，用户仍可手动处理。
