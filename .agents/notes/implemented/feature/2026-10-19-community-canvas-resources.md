# Agent Note: 社区画布资源按服务端能力上传

Status: implemented

## Problem

上游夜樱包包含四张 PNG/APNG/GIF 资源，共享社区代码仍限制三张 PNG/JPEG，并在本地拒绝 canvas 与 wechat_scroll。[云端 PR #956](https://github.com/metasequoiaime/msime-cloud/pull/956) 扩展图片协议，但不能假定用户配置的服务端已部署它。

## Decision

打包、校验与安装在共享 client-services 支持最多 37 张有界 PNG/JPEG/APNG/GIF/WebP。预览仍限 PNG/JPEG，所有图片完整解码，动画逐帧按画布累计。上传新增方言或扩展资源前从同源列表响应探测 X-MSIME-Candidate-Resources: canvas-v1；没有明确能力头时拒绝扩展上传，保留普通旧包上传。列表、详情、下载与同步声明 resources=canvas-v1，旧部署忽略该查询键时照常返回旧包。滚动升级的拒绝作为正常请求失败处理，不无限重试。云端扩展写入默认关闭，所有副本升级后才由部署方开启，避免旧副本向旧客户端返回新格式。

image-webp 0.2.4 对有损动画先解码内部 VP8 再核对 ANMF 矩形，ALPH 分支还会把下一块直接当成 VP8；外层画布限制因此不足以约束内存与像素缓冲。共享的无像素分配预检核对 RIFF 长度、块边界、每帧矩形、VP8/VP8L 内部尺寸及全部帧的预算。ANMF 只接受解码器支持的单个位流或 ALPH + VP8 顺序，不能跳过未知块后再校验后面的位流。本地扫描与社区完整解码共用预检；几何无效时拒绝，不能沿用旧损坏资源的静态图回退。

## Alternatives considered

直接删除上传拦截改动较少，但会把新包发给尚未升级的服务器。按域名或版本号判断可少一次探测，但用户可配置自托管服务且滚动升级混有多个版本，因此要求明确能力头。

只依赖 ImageReader 的尺寸与分配上限可以少一层格式处理，但内部动画位流仍可在尺寸检查前解码，不能保护现有预算，因此在完整解码之前预检全部帧。

## Testing

合成五资源动画包覆盖打包、原子安装、目录重扫与字节往返；旧部署和未知能力头只收到 GET 探测，不接收扩展上传；普通旧包保持一次 POST/PUT。新增替换接口探测顺序、损坏后续帧不覆盖已安装包、帧数、像素与预览格式边界测试。图库测试将同一批合成清单与图片通过 include_bytes! 带进测试程序，运行时写入临时目录；不再依赖构建机 CARGO_MANIFEST_DIR 在 Android 上存在。本次远端完整服务测试 1210 通过、1 项原有忽略；MCP 单测 69 项与 stdio 11 项通过，两 crate 的 clippy 在 -D warnings 下通过。共享界面构建、类型检查和相关 135 项 vitest 通过。Android API 28、35 各在专用模拟器执行四个共享 crate：base 36、core 419、providers 224、services 1163 项通过（每个平台合计 1842 项），沿用原有忽略项及 runner 的 hard_link 跳过；新增资源与图库测试全部实际执行。WebP 专项回归覆盖有损、无损、透明通道、内部尺寸伪造、后续帧几何不符、块长度、重复位流、帧数与解码预算；目录扫描拒绝危险几何，安装拒绝后已安装包不变。此证据属于设备共享层测试，没有进行 APK 输入法安装、真实编辑器打字或原生动画目测。

固定上游 msime-windows 提交 `dd018f79858314ed542a47c528608752b13bd261` 的夜樱包保留原始四张资源，仅为 MCP 请求补上必需的预览声明。实际 CLI 创建、目录重扫及全部资源逐字节比对通过，APNG 24 帧与 GIF 8 帧保持。远端 quick 门禁通过，包含 Linux 原生 90 项测试、Linux 设置外壳、macOS 原生与共享 Apple 桥构建、Android/wasm 检查和 Windows 可移植测试；Windows 全量原生构建缺 MinGW、HarmonyOS HAP 缺 staged 库与模块时仍明确跳过。

## Consequences

MCP 创建与社区安装共用这些资源规则；工具 schema、生成提示词和共享/Windows 发布说明同步更新。MCP 不持有账号会话，上传由宿主触发并协商。每次设备测试有独立临时图库，代价是测试程序包含少量合成素材，但无需把构建机路径暴露给设备，也无需在 runner 中单独同步图库。逐帧完整校验有 CPU 成本，受尺寸、帧数、内存与总像素约束。云端与客户端需配套部署；通过资源往返不能宣称 Linux 等宿主已完整绘制画布。
