# Agent Note: Windows 设置的打字三页照 macOS 分标签

Status: implemented

## Problem

macOS 设置（共享设置 UI 的桌面分支）的「输入」页顶上有六个页内标签（`input-tabs.ts`）：输入方案、中英模式、选词与翻页、候选与联想、输出设置、高级选项；「快捷键」页分「按键设置」「按键速查」；「标点与翻译」页分「标点设置」「候选释义」「翻译服务」。Windows 原生设置窗口还是[按 macOS 改版](2026-10-15-windows-ui-macos-layout.md)时的归页：「输入」页一列排下中英文、十个方案的单选列表、「当前方案选项」、五笔查码和只画当前那一族的辅助码；混输、输出、快捷模式、纠错与模糊音、调频画在「标点与翻译」页的标点后面；选词与翻页画在「快捷键」页。逐行也有出入：中英两行是分段控件，以词定字是下拉，「繁体输出」是开关，「全角输入」收在折叠区，逐个模式是十二个没有说明的复选框且总开关关掉时不变灰、没有「@ 地名」，模糊音是一片扁平的复选框、没有重置，云候选要点「配置」打开对话框、所有字段一律显示，日语、韩语、粤拼、注音、笔画选中后没有任何说明行，五笔选词键没有即时校验，快捷键页没有页首说明、组说明、按键速查和「Ctrl+Space（由 Windows 管理）」。另有三处 macOS 设置里没有的：「二三候选」「自动纠错」和「恢复默认快捷键」。用户要求以 macOS 为准迁移，并决定这三处从 Windows 设置里去掉，只去界面，不动偏好、引擎行为和 C ABI。

## Decision

### 归页与标签

- 三页都用[页内标签框架](2026-10-20-windows-settings-page-tabs.md)的 `page_tab_bar` 加 `in_tab`，自动化前缀是 `input-tab`、`shortcuts-tab`、`expression-tab`。标签列表和几处要逐字对齐的文案放在新的 `platforms/windows/settings/InputSettingsModel.h`（不依赖 Windows 头文件），由 `tests/ui/input_settings_model.cpp` 核对并加进 CMake 测试。
- 「输入」：「输入方案」是「方案」组和选用五笔时的「五笔查码」；「中英模式」是「中英文」组；「选词与翻页」是原来挂在快捷键页的 `build_selection_keys`；「候选与联想」「输出设置」「高级选项」是原来挂在标点页的 `build_input_habits`，高级选项依次是快捷模式、逐个模式、模糊音、辅助码、拼音方案调频。
- 「快捷键」：「按键设置」是页首说明（与 macOS 的 `ShortcutsIntroSection` 逐字相同）和「输入模式切换」组；「按键速查」是只读键帽行。
- 「标点与翻译」：「标点设置」是「标点」组；「候选释义」是「多语言与释义」「候选词翻译」；「翻译服务」单独成组（共享页的 `serviceInOwnGroup`），下面接所选服务的凭据组。
- 标签多了以后最窄窗口放不下一行字，`segmented_control` 的整宽样式改成段至少 36 高、字可以折成两行、同一排的段一起变高；紧凑样式不变。
- 插件页「前往输入设置」「前往辅助码设置」先把输入页的标签设成「高级选项」再跳过去。

### 逐行

- 方案组：第一行「输入语言」下拉（中文、日文、韩文、越南文、藏文，只列本版本提供的，只剩一项时不画），选「中文」回到 `last_chinese_scheme`，不可用时回到版本默认方案，再不行用第一个中文方案，与共享页 `fallbackChineseScheme` 相同；本版本一个中文方案都没有时不列「中文」，共享页在这里会列一个选了也回不到可用方案的「中文」。当前是中文方案时下面是三列「中文方案」卡片单选：每张卡片是一个 8 圆角、1 DIP 分隔色描边的 Border，里面是整宽的 RadioButton（自动化 ID 仍是 `scheme-<方案>`），选中的描边是强调色、底色是 `accent-soft`（浅色 rgba(44,122,75,.12)、深色 rgba(95,191,132,.22)），悬停铺中性底色。上下内边距取 6 而不是 macOS 的 12，因为系统单选自带 32 DIP 的最小高度，合起来与 macOS 卡片同高。
- 双拼方案的顺序改成小鹤、自然码、首道、微软、智能 ABC。「自定义双拼」和它的编辑页另立项，平时不列；文档里已经是 `custom`（从 macOS 同步来）时照共享页 `shuangpinProfileOptions` 列一项不可选的「自定义双拼」，否则下拉框找不到当前值，显示成空白。
- 日语、韩语、粤拼、注音、笔画各补一行说明，越南语两行的标题、说明和选项照 macOS，五笔那一行叫「五笔四码唯一候选自动上屏」。藏文那一行也照 schemeNote 改叫「藏文方案」、说明逐字取共享页；Esc 在两边都由引擎的 `restore_tibetan_raw` 处理（第一次切回威利原文，第二次取消），「Esc 恢复原始按键」不需要 Windows 的另一种写法。
- 五笔选词键边输入边校验（`valid_wubi_candidate_keys`，即共享页 `validWubiCandidateKeys` 的 ASCII 标点范围）：无效时「自定义选词键」的说明换成「请输入两个不同的单个英文标点。」，保存按钮变灰；与翻页、以词定字的冲突仍交给偏好库在保存时判断。
- 「默认中英文」「中英文状态」改成下拉。
- 以词定字改成「关闭 / [ / ] / - / =」三段的分段控件，被翻页占用的键组那段按不下去；退格回退和鼠标滚轮的文案照 macOS。
- 云候选去掉对话框：开关之后直接是「云候选来源」，选自定义 HTTP 接口时才有接口地址、请求方法、请求头、响应格式，POST 时才有请求体模板，响应格式选 JSON 路径时才有 JSON 路径，然后是超时、缓存和「保存云候选服务」。改动记在窗口成员 `cloud_provider_draft_` 里，三个下拉改了整页重画；保存时把草稿的一份拷贝写进文档（文档存的是对象引用），一次 commit，失败时提示原来的那句、草稿留着。文档里的配置变了（保存成功或别处改了）草稿作废，与共享页随 provider 重置草稿相同。说明改成「仅将当前正在组的拼写发送给 …」。
- 「中文输出」是简体 / 繁体两段，说明随选项和方案变（粤拼、注音、笔画各补一句）；Windows 不认繁体变体，只写 `traditional_chinese_output`。「全角输入」从折叠区拿出来直接放。
- 逐个模式的「更多选项」里每个模式一行带说明的开关（`local_modes`，标题、说明、默认值照共享页），总开关关着时 Shift+字母进入的各行变灰，加「@ 地名」（`mention_places`，@ 模式关着时变灰），没有选在线翻译服务时指令模式的说明补上 fy 不会出结果那句。折叠区用 `fold_index_` 登记，搜索落到其中一行时展开。
- 「模糊音」自成一组，开关叫「启用模糊音」；打开后才有说明、按「平翘舌」「声母」「前后鼻音」「其他韵母」分组的规则和「重置模糊音配置」。重置先用现有的 `confirm` 问「关闭模糊音 / 所有模糊音规则会被清空。 / 关闭并清空」，确认后关掉开关、清空规则，`seeded` 不动。
- 「辅助码」不再按方案隐藏：本版本提供全拼或双拼就画，主流程是当前方案那一族（双拼方案是双拼，其他是全拼）的三行，另一族的三行收在组末「更多选项」里。
- 快捷键页：组首说明、Caps Lock 说明末尾补「大写锁定开着时按一下照常关掉。」，「切换中英文」「Ctrl+Shift+F 切换繁体输出」去掉说明，Ctrl+Shift+J 排到 Ctrl+Shift+F 前面（共享页的顺序），全半角那行改成「关掉后这个组合键交给应用处理；工具栏的全半角开关和 Ctrl+Shift+Space 不受影响。」（后半句保留 Windows 的系统全半角键），组末加只读的「Ctrl+Space（由 Windows 管理）」。按键速查照 `CandidateShortcutReference`：选择候选（Windows 数字键总能选词，写「Space 或 1–9」）、向前 / 向后翻页（按当前生效的列出，Tab 和 PageUp / PageDown 固定算开，多组时键帽排到标题下方）、开着时才列的鼠标滚轮、上下键、左右键、以词定字，再是 Home / End、编辑输入串、提交 / 取消，最后「打开屏幕键盘 Ctrl+Shift+Win+K」（Server 的 `MaintenanceHotkeys.h` 真的处理这个组合键）。键帽至少 120 宽、圆角 5、1 DIP 描边、次要按钮底色、12 DIP 字；多组翻页键照 `settings.shortcutKeys` 按自身宽度靠左、相隔 6 DIP、放不下折行，WinUI 没有按子项宽度折行的面板，用 `responsive_grid` 的 Auto 列（按 140 DIP 一列估算列数）代替。
- 去掉「二三候选」「自动纠错」「恢复默认快捷键」三行。`second_third_candidate`、`quanpin.autocorrect_transposition` 和 `keybindings` 的默认值都不变，TIP 和 Server 照旧按偏好工作。

## Alternatives considered

- **保留三页的 Windows 归页，只修逐行差异**：改动小，不碰搜索索引和测试脚本。否决：用户要的是与 macOS 一致的信息结构，选词与翻页在快捷键页、混输在标点页本身就是用户找不到设置的原因。
- **五笔选词键的校验只交给偏好库**：规则只有一份。否决：保存失败时整页重读，打到一半的键位会丢；共享页也是本地先拦，规则只有一行正则，放进头文件有单测。
- **云候选保留对话框，只按条件显示字段**：草稿天然只活在对话框里。否决：macOS 是组内展开的行，对话框把云候选和其他候选设置分成两个层级；草稿放在窗口成员里与云剪贴板中继的写法相同。
- **重置模糊音用危险色的确认按钮**：与 macOS 的 `danger` 一致。否决：Windows 设置里所有不可撤销的确认（清除学习数据、删词表、恢复屏幕键盘）都用同一个 `confirm`，没有危险样式；给 ContentDialog 换按钮样式要在 C++ 里拼 Style，本机编不了 WinUI 无从验证，留给统一改确认框的时候。
- **「输入语言」照共享页总是列「中文」**：与共享页逐字相同。否决：日文、越南文、藏文版没有中文方案，选了也只能回到一个本版本不提供的方案。

## Consequences

- 三页的结构、标签名和大部分文案与 macOS 一致；搜索结果的第二行带标签名，打开时先切标签，逐个模式和辅助码的折叠区由 `fold_index_` 展开。
- 「二三候选」「自动纠错」「恢复默认快捷键」在 Windows 上只能经同步或直接改偏好文件调整；已经打开二三候选的用户行为不变，但在设置里看不到它。
- 云候选的草稿跨页面保留，离开页面不提示未保存。
- 六个标签在 800 宽的窗口里会有段折成两行。
- 方案卡片的单选圆点仍是系统 RadioButton 的样式，卡片高度靠内边距凑。
- 自定义双拼编辑器、桌面神经联想、Windows 上的 `traditional_chinese_variants` 都不在本篇范围。

## Verification

- 本机没有 WinUI 3 / C++/WinRT 工具链，`main.cpp` 只能由 PR 的 `CI (platforms)`「Windows native settings」以 `/W4 /WX` 编译并运行 `tests/tools/settings_ui.ps1`：三页的每个标签都切一遍并截图（浅深色、800 / 1000 宽），确认「二三候选」「自动纠错」「恢复默认快捷键」不在、标点页没有混输、按键速查有屏幕键盘一行；方案切换、五笔快捷选词仍走 `scheme-<方案>` 和原来的自动化 ID；从「输入方案」标签搜「@ 地名」确认切到「高级选项」并展开折叠区。
- `tests/ui/input_settings_model.cpp` 本机用 clang++ `-Wall -Wextra -Wshadow -Werror` 编译运行通过，并用 `x86_64-w64-mingw32-g++ -std=c++20 -Wall -Wextra -Werror -fsyntax-only` 检查。
- `scripts/test-windows-input-habits-settings.py`、`test-windows-settings-ui-pages.py`、`test-windows-settings-art.py`、`test-windows-editions.py` 通过。
