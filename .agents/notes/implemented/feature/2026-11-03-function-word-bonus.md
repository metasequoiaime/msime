# Agent Note: 单独的轻声助词也拿一份成词加分

Status: implemented

## Problem

真实输入法验收里，「那我买周六早上的高铁票了」打成「…高铁飘了」，「中午只能吃食堂了」打成「…食躺了」，「终于上完线了」打成「…上完闲了」。

整句解码给多字词每个音节一份 `PHRASE_LENGTH_BONUS`（20），单字拿不到。词库从语料里收了很多「某字 + 助词」的条目，例如「飘了」17738、「闲的」486358。这些条目凭成词奖励压过了正确的切分：

- 「高铁 | 飘了」两个条目各拿一份奖励。
- 「高铁票 | 了」里的「了」一份也拿不到。

不计 n-gram 时前者领先 8.7 分。逐键模型拿到的候选里根本没有「高铁票了」，救不回来。

早些时候试过反过来做：给这些条目扣成词奖励。结果「了」作为单字没人撑腰，输给了「乐」「勒」（「台历海勒」「疏勒」），sentences-neutral 掉了 1–5 个点，没有采用。

## Decision

整句解码建边时，单独成边、读音也对得上的轻声助词加 `FUNCTION_WORD_BONUS`（8.0）。范围是：读 `de` 的「的 / 地 / 得」，读 `le` 的「了」，读 `zhe` 的「着」。两种切分在助词那里接近打平，回到按词频、n-gram 和逐键模型比。

「了」读 liao、「着」读 zhao、「的」读 di 时不加；多字条目照旧。

## 评测

2026-11-03，`convert_eval`，锁定词库，资源里去掉随包模型。分两组：只用引擎，和 6x256 配 32 条。聊天集是 typing-chat-v1 按标点切出的句段，上文按消息加换行。

调参集合扫了 0、8、14、20，首选准确率：

| 集合 | 组 | 0 | 8 | 14 | 20 |
|---|---|---|---|---|---|
| typing-chat dev | 引擎 | 52.7 | 56.4 | 58.2 | 58.2 |
| typing-chat dev | 6x256/32 | 68.2 | 69.1 | 70.0 | 72.7 |
| sentences-neutral-v1 | 引擎 | 53.2 | 53.5 | 53.5 | 51.9 |
| sentences-neutral-v1 | 6x256/32 | 84.2 | 84.9 | 84.7 | 84.3 |
| sentences-v2 | 引擎 | 49.7 | 49.4 | 47.8 | 47.4 |
| sentences-v2 | 6x256/32 | 76.6 | 77.2 | 76.9 | 76.6 |

8 是只用引擎的 sentences-v2 只掉 0.3 个点、其余都涨的那一档。更大的值让「贯彻得」这类「得」变成「的」。

没参与调参的集合（0 → 8）：

|---|---|---|

| sentences-particles-v1 | 不变 | 不变 |

括号里是改对 / 改错。六个集合两组合计：改对 39，改错 11。

## Alternatives considered

- **给「某字 + 助词」条目扣成词奖励。** 试过，见上面 Problem 的最后一段。
- **取 20，与成词奖励相同。** 聊天 dev 上最好（+4.5），但 sentences-v2 和只用引擎的 neutral 都变差。助词的单字词频本来就高，再给满额奖励，「得」「地」会被统一成「的」。
- **清理词库里的这类条目。** 词库在另一个仓库，条目数以千计，里面「真的」「好的」「目的」这样的真词要留。改解码一处，所有词库版本都生效。

## Consequences

- **收益**：聊天打字首选高 1.4–2.8 个点，「高铁票了」「食堂了」「第一期的排期」「辛苦大家了」改对。
- **代价**：「得」被「的」吃掉的情形略多。改错的 11 条里，「贯彻得 → 贯彻的」「减得 → 见得」都是这一类。

## Verification

- `crates/engine/src/lattice/decode.rs` 的 `a_lone_function_word_competes_with_entries_that_swallow_it`，用锁定词库的真实权重：「高铁 | 飘了」和「高铁票 | 了」的差距在 1 以内；读音对不上的助词和多字条目不加分。
- `cargo test -p msime-engine --tests`（31 个 golden 测试不变）、`-p msime-input-runtime --lib`、`-p msime-host-api --features onnx-rerank --lib` 全部通过。
