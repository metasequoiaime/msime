# Agent Note: Android 剪贴板记录一步存为常用语

Status: implemented

## Problem

#5909：用户想在键盘剪贴板面板里长按一条记录，一步把它存成无编码常用语，之后在键盘的「常用语」面板里点一下就上屏。现在长按操作行只有「固定 / 删除 / 分词 / 发到云剪贴板 / 收起」，要先插入、再去应用的常用语页手动添加。

## Decision

- 只做 Android（issue 列出的菜单就是 Android 的操作行）。长按操作行在「分词」后面加「添加到常用语」（`CommonPhrasesPanelPolicy.ADD_FROM_CLIPBOARD`），阅读顺序是 固定、删除、分词、添加到常用语、发到云剪贴板、收起。
- 操作行拆成两行（`ImePanels.addClipboardItemActionRow`）：第一行放短按钮（固定、删除、分词），第二行放两个长按钮和「收起」。六七个按钮挤在一行时，360 dp 宽的手机上每个按钮都被截成省略号。
- 写入经 `CommonPhrasesStore.add`：校验（1000 个 UTF-16 单元、不含控制字符）、去重、自己添加的 200 条上限和标记「常用语」有本机改动都在那里，键盘不另写一套。它要等文件锁，放在 `preferencesWorker` 上，结果回到主线程用 `notice` 说出来；`check-host.sh` 守住这两点。
- 提示文案在 `CommonPhrasesPanelPolicy.clipboardAddNotice`：成功是「已添加到常用语」；失败时原样用常用语存储给的原因（「已经有这条常用语了。」、上限说明），没有原因时用常用语的通用失败说法。剪贴板历史不限 1000 字、允许回车和制表符，常用语都不行。存之前先把 `\r\n` 和单独的 `\r` 换成 `\n`（`CommonPhrasesPanelPolicy.clipboardPhraseText`，和 client-core 收社区短语时的 `normalize_line_breaks` 一样），从 Windows 或网页复制来的多行文字照样能存；换完仍存不下的在键盘里先拦下，`clipboardRefusal` 按实际原因说：空白、超过 1000 字、含制表符等控制字符（后者指向「编辑」，去掉后再添加）。最初一律提示「常用语不能为空，最多 1000 字。」，review 发现带制表符或 CRLF 的记录既不空也不长，那句话说错了原因。按钮不置灰：置灰的按钮点了没反应，用户不知道为什么。
- 提示不写「只保存在本机」：剪贴板历史只在本机，而常用语开着同步时会上传。这是用户自己点的，所以接受，但文案不能让人以为它还留在本机。

## Alternatives considered

- **制表符换成空格后存** — 表格里复制的一行也能一步存下；但以后上屏的文字和原来不同，对齐、粘回表格都会变，而且是悄悄改的。不换，说清原因，让用户自己在「编辑」里决定。

- **按钮文字缩成「存为常用语」，仍放一行** — 不用改操作行结构；但产品要求的文字就是「添加到常用语」，五个字也仍然挤，加上 #5971 的「编辑」后一行更放不下。
- **操作行改成横向滚动** — 一行高；但滚到右边才看得到的操作等于不存在，而且横向滚动和剪贴板面板的纵向滚动、#5962 的左滑删除抢手势。
- **iOS 和 HarmonyOS 同时加** — 三端一致；但这次只要求 Android，另两端的键盘写常用语时是否标记同步改动没有核实，留给以后单独做。

## Consequences

- **收益**：剪贴板里常用的一段一步变成常用语，键盘「常用语」面板和应用的常用语页都能看到它，开着同步时也会同步到其他设备。
- **代价**：操作行多占一行（38 dp 加间距）。剪贴板内容一旦存成常用语就离开了「只在本机」的剪贴板历史，开着同步时会上传。

## Verification

`platforms/android/tests/keyboard/CommonPhrasesPanelPolicySmoke.java` 验证按钮文字、成功和各类失败的提示、CRLF 和单独 CR 换成换行后能存（长度按换完的算）、制表符原样保留并说明是它的问题、过长和空白各有自己的说法；`bash platforms/android/check-host.sh` 编译面板代码、运行它并检查写入走工作线程。在 API 35 的专用模拟器上长按一条，操作行分两行显示；点「添加到常用语」后 `CommonPhrases.json` 里多了这一条。提示文字、重复添加和超长记录的提示、常用语面板和常用语页里的显示没有在设备上看过。
