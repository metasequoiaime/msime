# Agent Note: 双拼用 Tab 显式进入辅助码

Status: implemented

## Problem

#9425 希望微软双拼在 Tab 前严格按两键音节解析，按 Tab 后才接收辅助码。现有间接触发只有分号、反引号和大写，末尾直接及逐音节直接辅助码仍可能解释裸字母。

## Decision

双拼 modes 增加缺省关闭的 manual_tab。开启时引擎在消费端暂时停用其它触发方式，保留偏好原值，关闭即可恢复。Tab 经现有 character 接口交给引擎，只在完整双拼基座后写入已有末尾标记，复用一码重排、两码过滤、退格和提交逻辑。macOS 在普通 Tab 翻页之前尝试该字符；Shift+Tab、已展开网格和释义页保持既有归属，空闲和未完成音节的 Tab 不强行进入辅助码。

共享设置页提供开关，其余触发行开启时禁用并保留值。当前需求的平台是 macOS，共享设置页只在该宿主显示开关；Host API 在非 macOS 消费端屏蔽 `manual_tab`，保留落盘偏好并继续使用当地原有触发方式。

暂存词段后，runtime 只保留引擎针对剩余合法拼写公布的 Tab，并让该字符直接进入引擎；其它符号继续遵守禁止在暂存词段后打开新模式的原规则。Host API 在应用偏好更新时同步复制触发方式，确保关闭开关立即恢复旧配置，而不是等重建输入法进程。

手动模式的 Tab 标记和后续辅码不属于原文。回车与无候选原文回退使用 `QueryRequest.raw_input_with_cases` 的去段拼写，避免内部 `|` 或辅助码流入文档；其它模式沿用既有原文提交语义。

## Existing notes

[触发偏好与默认值](2026-10-21-shuangpin-helpcode-trigger-modes.md)和[直接、间接与句中触发实现](2026-10-22-shuangpin-helpcode-trigger-modes.md)部分重叠：它们持有旧触发规则，本篇仅增加显式 Tab 入口与暂时覆盖规则，不重定义辅助码解析。检索未发现同一 Tab 决定的旧篇。

## Alternatives considered

- 直接复用反引号：无需增加偏好，但不能满足 Tab 习惯，且不保证原有直接辅助码停用。
- 开启手动时永久清掉其它触发设置：消费简单，但关闭后无法恢复用户原先选择，因此仅在引擎消费端计算有效配置。
- 新增 C ABI 命令：语义显式，但已有 ASCII character 接口足够表达 Tab，无需扩大协议。

## Verification

自动化回归覆盖 Tab 前不认裸字母辅助码、Tab 后重排、退格、微软双拼报告中的三段输入、禁用与空闲；共享偏好往返和 UI 开关保留原值；macOS 原生按键路径优先于普通候选翻页。提交门禁包含本地 quick、fmt、Clippy、UI 类型检查与构建；记录只代表实际运行的层面。

## Consequences

Tab 同时用于翻页、展开和释义列：已展开网格和释义页保留原归属；从释义页退出的同一枚 Tab 不进入辅助码。普通候选中的 Tab 先交给引擎，Shift+Tab 仍翻页。其它宿主不新增入口，不能宣称所有平台支持外接键盘 Tab。未安装或改动用户当前输入法时不能把单测表述为真实编辑器验收。
