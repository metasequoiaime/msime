# Agent Note: 统计对齐复用共享明细与连续输入计数

Status: implemented

## Problem

#11546 要求统计能力在各平台可达。Android 已展示共享成就，Windows 已有按键热力图和账号入口，不能根据报告者没有找到入口就重复实现。实际缺口包括 Android 没有按日明细、Windows 没有成就展示、逐键计数没有语言维度，以及云端协议不包含逐键与成就。

共享库的连续输入计数原来由 `cfg!(any(target_os = "android", test))` 决定。桌面、iOS 和 HarmonyOS 正常编译的库不记录这项数据，单元测试却始终开启，无法揭示正式宿主与测试的差异。先补界面会把缺失的底层数据误当作用户没有连续输入。

Host API 的候选上屏效率也有同样的 Android/测试限定，非 Android 正式宿主没有整句、联想和少按键的聚合数据，已有单元测试的同步写入同样掩盖了它。

## Decision

各宿主共用 `record_at` 的活跃间隔规则记录 `current_run` 与 `longest_run`，不再由目标平台决定。原有统计开关、10 秒活跃间隔、跨午夜保留开始日、并列保留较早一段、清空与批次规则保持不变。只存已有的字数与日期字段，不保存输入内容。

Host API 在各宿主的候选选择上统一采集效率，继续复用既有统计开关、隐私会话、镜像会话排除、后台串行写入和批次上限。正式库集成测试经候选选择、失焦、销毁后等待后台聚合结果，覆盖实际异步路径，不沿用仅在单元测试里同步写入的假设。

`summary` 增加 `daily_details`，由独立的 `daily_details.rs` 统一派生截至宿主本地今天最近 30 个记录日。按日期倒序，不把最近 30 个记录日改成最近 30 个自然日。分类未覆盖的历史字数计入「其他」，速度只算汉字、拉丁字母与其他文字，未测活跃时间及速度为 JSON `null`，已记录的零值仍是零。

Android 原生统计页增加「明细」分段，表格与解析分别放在 `StatisticsDailyDetailsView.java`、`TypingStatisticsDailyDetails.java`，页面只接入。表格使用主题颜色与可增长的文字单元格，横向滚动显示九列。规则说明收进组标题旁的「?」。旧摘要缺少 `daily_details` 时显示暂不可用，不当作用户没有历史。

Windows 现代设置增加「成就」标签，Win7 在现有图表选择中增加「成就」。两者均在统计工作线程调用既有 `summary`，由共享库持久化新解锁项；同时通过词库 `count` 传入用户拼音词条数。定义、描述、当前进度和目标都来自共享 Rust，不移植第二份徽章阈值。原生模型、WinRT 数据适配、展示和 Win7 适配分别放在独立文件，巨型窗口文件只接入调用。读取失败显示不可用，不能展示成全部成就都没解锁。成就按全部保留数据展示，不随图表所选单日缩小。

本次不改变统计出厂默认值或缺字段读法，也不改变独立的云端上传授权。对齐依照[统计纯模型](../../implemented/architecture/2026-10-15-typing-statistics-model.md)保留历史未知值口径；旧的 TypeScript 与 Windows 明细仍按原调用链工作，新增宿主消费共享 Rust 派生结果。

Windows 原生语音在确认至少一段文字已投递后，同时向共享统计提交实际采集时长。时长由采集回调累计的帧数和采样率换算，流式识别不依赖已被清空或未保存的 PCM 缓冲，也不计识别与润色等待时间；按既有 `record_voice` 契约单次最多 10 分钟。录音失败、取消、过期或没有上屏时不记，审阅录音继续由面板持有结果，不借此算作已上屏。后台提交继续由共享库检查统计开关、保留期和每日上限，不上传音频或识别文字。

Windows 的皮肤成就事件从 Server 实际套用主题的路径提交，因此原生设置、托盘和同步后的主题都能覆盖，不依赖某个设置窗口存活。内置主题记录主题 ID；外部包记录共享解析器为当前明暗实际选中的包 ID，不把另一个槽位或设置预览算成用过。`AppliedSkinStatistics` 只抑制同一皮肤的重绘通知，回到以前用过的皮肤仍交给共享 `record_skin` 去重、检查开关及数量上限。请求沿用已有后台统计写入，不在绘制线程等文件锁。

逐键语言由共享 `key_languages.rs` 聚合。宿主在按下时复用已有 `TypingSource`，同一日内按来源和键位攒批，不为语言切换增加写盘；`record_keys` 的可选 `sources` 中，每个键的来源计数之和必须恰好等于原有 `keys`，缺漏、重复计数、未知键位、零计数或溢出均拒绝整批。保留原有总计字段，旧共享库忽略新增来源时仍能计总数；新共享库接受旧宿主缺省来源，不能由收到批次时的当前方案回填过去。

共享层把拼音、五笔、注音、笔画折叠到中文，其余明确语言使用自己的桶；没有可靠语言的本地模式、手写、AI 等来源归未分类。修饰、导航、编辑和层/语言切换等功能键统一计入 `common`，不混进某种语言的字母热力。可打印数字、符号和拼字键仍按按下时的来源归组。新增的 `dailyKeyLanguages` 与 `dailyKeys` 在同一锁内验证和写入，一起执行保留期和清空。读取旧文件先校验已有分组没有超过总数，再只将缺少来源的功能键补为通用、其他键补为未分类；不使用当前语言猜测旧历史。不增加按键顺序、小时或精确时刻。

Android 的 `KeyPressBatch` 同时持有总数与来源计数，交给工作线程的是双层不可变快照；`countKey` 在主线程取得来源，`KeyPressRequest` 只编码聚合请求。跨午夜、256 次和 30 秒写出、隐私编辑器排除及统计开关继续沿用已有路径。Android 原生按键页通过 `StatisticsKeyLanguagePicker` 提供语言筛选，复用摘要的近 7 天窗口。`TypingKeyLanguages` 只聚合共享层已分类的每日桶，不复制分类规则；只列窗口内有记录的语言，并提供「通用键」「未分类」及完整总计「全部」。旧共享库没有新字段时仅保留「全部」，不能展示为零次输入。筛选只作用于热力图和其他键列表，已有近 7 天全部输入的 KPI 保持原口径。其余宿主采集与原生筛选仍需继续实现，不能把 Android 可达等同于全平台可达。

iOS 的按键批次主体独立于巨型控制器和存储文件，`countKeyPress` 在主线程读取既有 `typingSource` 并立即按来源计数；后台写出只转交快照，不重新读取模式。`TypingKeyPressBatch.swift` 继续沿用日切换、256 次、30 秒及键盘收起封批，语言切换不额外落盘。Swift 嵌套字典按值交给后台队列。旧的无来源构造和计数入口统一使用 `unknown`；直接调用 `recordKeys` 仍可省略来源。键位校验、完全访问、隐私门禁和统计开关维持原有路径，没有增加 FFI 查询或改变云端上传。此切片不包含 iOS 的原生语言筛选。

Windows 物理键在 TSF 入口按下时捕获来源，当前引擎视图从既有响应 JSON 的解析结果提取轻量快照，不新增逐键 FFI 或 JSON 解析。快照不读取上一键的 `commit_context`；没有视图的在线查询保留当前值，销毁与失败清掉快照，下一次有效视图前记未知来源。偏好改变方案或专用英文而尚未重载时，使用配置中的新方案，不沿用旧本地模式；IME 关闭态归英文。

JSON 提取只在实现侧的 `KeyTypingSourceResponse.h`，公开适配器持有的 `KeyTypingSource` 只依赖标准库和原有来源枚举。既有五笔生命周期回归会在没有 JSON include 路径时编译适配器公开头，继续守住这个轻量边界，不给旧测试增加解析器依赖。

同一日内按来源聚合并保留旧总计，日期、256 次阈值、30 秒和失焦封批不变。新 TIP 先发送只有空计数的 `TypingKeySources` 探测，新 Server 允许后每来源分片交共享存储，一片只累计一次总计；旧 Server 不认识新格式时先探测旧 `TypingKeys` 并仅发送原总计。非空发送失败不切格式重发，避免部分分片已经写入后重复累计；旧 TIP 对新 Server 继续按未知来源记录。协议不保存按键、语言切换顺序或输入文字。

Linux 的 IBus 和 Fcitx5 在事件分派前复用已有输入来源；输入法关闭态直接归英文，旧本地模式不覆盖它；会话尚未给出有效视图时归未知，不调用会假设视图已经就绪的来源读取器。同一批同时带总计和来源计数，不因切换语言增加写盘；原有持键与合成重复排除、跨日、跨目录、256 次、30 秒、失焦及退出规则保持。IBus 逐键读取方案时只借用偏好对象，不复制整份配置；两宿主写出共用独立 `TypingKeyPressRequest.h`，后台只编码既定快照。旧计数器调用缺省为未知来源。公共计数器头继续不依赖 JSON，语言分类只由共享 Rust 执行。

macOS 在 `handleEvent:client:` 处理按键前捕获当前来源，再把枚举值交给原有计数位置；键内切换模式不能重标这个键，新客户端尚未接管时归未知。英文关闭态优先于旧本地模式。`KeyPressBatch` 同时保存总计和来源嵌套聚合，`TypingKeyPressRequest.h` 在原统计线程编码快照；原有安全输入、重复键、修饰键边沿、跨日、256 次和 30 秒规则不变，不新增逐键 FFI 或写盘。旧无来源调用继续归未知，公共计数器头不引入 Foundation。

## Alternatives considered

- 在 Java 再移植一份 TypeScript 明细公式，接线最少，且有现成的桌面实现可照搬。但这会继续增加分类、保留窗口和未知值规则的语言副本；新功能由共享 Rust 提供完整明细，Java 只解析与格式化。
- 仅给 Windows 增加成就卡片，可以先补可见入口。但正式库没有记录连续输入，和仅在 `cfg(test)` 下通过的测试不同；先统一聚合计数，并用集成测试调用正常编译的库。
- 用识别完成时间减录音开始时间计算语音时长，只需读两个时钟。但这样会把网络与润色延迟计入语音；读取整份 PCM 长度虽直接，流式路径又不保留这份缓冲，所以从采集阶段已有的帧计数带出时长。
- 在每个原生设置页的皮肤按钮里记一次，实现可以直接拿到点击的 ID。但还需覆盖 Win7、托盘与同步修改，且失败或冲突的保存不能算实际使用；从 Server 套用主题处记已解析的 ID，复用所有入口的最终路径。

- 在批次写出时按当前模式标记语言，接线最少，且不用改变宿主批次。但 30 秒内可以切换多次语言，会把整批归给最后一种；改为按下时分组，并在同一批内聚合，避免暴露切换顺序或增加写盘。

## Verification

`tests/typing_statistics_runs.rs` 通过正常共享库入口验证重开、flush、跨午夜、10 秒边界、超时重新开始及默认关闭/关闭后不再累计。`tests/typing_statistics_daily_details.rs` 覆盖 30 个记录日、未来日过滤、类别折叠、历史未知、已测零与可读字符速度。Java 冒烟核对九列顺序、千分位、时长格式及未知值。

`windows-voice-typing-statistics` 覆盖不同采样率、毫秒取整、10 分钟截断、极端计数不溢出、无效采样率和请求中仅有聚合字段。该测试接入原生 CMake 和既有主机可运行测试发现规则，不依赖设备。

`windows-skin-typing-statistics` 验证首次套用、重复重绘、内置主题切换、当前明暗的外部包、移除外部包、返回以前的皮肤和请求中只带聚合 ID。测试接入同一原生 CMake 与主机测试发现入口。

`typing_statistics_key_languages` 的正常库集成测试覆盖混合来源、共享功能键、旧历史未知、旧宿主兼容、整批拒绝、溢出、保留期、关闭和清空；Host API 集成测试覆盖 JSON 分批与返回字段。Android JVM 行为用例验证跨语言批次不会重标记历史来源，交回的嵌套快照不会被下一批修改。

`test-ios-statistics-key-batch.py` 编译实际批次模块和现有键位表，在 macOS 主机运行混合来源、无来源兼容、无效键、跨午夜、256 次阈值、嵌套快照及 JSON 传输行为。脚本由既有 contracts 自动发现；不需要启动设备或模拟器。原有 iOS XCTest 的跨日、阈值、开关和清空前置条件保持不变。

`windows-typing-key-source` 验证当前视图优先于上一键提交上下文、临时日文、本地模式、IME 关闭态、偏好切换、非视图响应、混合批次快照、逐键加总及新旧 JSON 请求。`windows-aux-typing-key-sources` 验证空探测、新旧协商、未知来源拒绝、长度分片和无重复恢复。两个用例接入原生 CMake 与现有主机测试发现入口。

实际执行结果在 PR 的验证段记录。设备或真实编辑器验证缺口如实列明，不作为继续修代码和提交 PR 的前置条件；不操作设备或发表 issue 调查评论。

`linux-typing-key-sources` 使用实际批次和 JSON 编码器验证混合来源、快照隔离、旧调用未知、日与目录切换、阈值、定时和持键去重，再调用实际 Host API 验证默认关闭、总计、通用键和语言分桶、旧宿主兼容、异常整批拒绝及全部来源可接受。原有 `linux-typing-statistics` 的回归、include 路径和前置条件保持不变。

`typing-key-sources` 链接正式 Host API，验证混合来源快照、请求编码、跨日、256 次、清空、旧调用、默认关闭、通用键和共享语言分类、异常整批拒绝及全部合法来源。`cross-commit-spacing` 保留原断言和前置条件，只让测试替身跟上来源参数，并新增真实事件分派时序回归：按键内切模式仍用按下前来源、英文关闭态优先以及新客户端未知来源。

## Consequences

非 Android 宿主在用户已开启统计时也记录连续输入，旧统计文件无需迁移；历史未记录的连续输入无法追溯补齐。摘要增加最多 30 行派生结果，不增加落盘的逐次输入历史。

本篇当前落地共享计数、Android 按日明细、Windows 成就入口、原生语音时长、实际皮肤使用记录、共享逐键语言聚合、Android 来源采集与筛选、iOS 来源采集、Windows 来源采集、Linux 双宿主来源采集及 macOS 来源采集。审阅语音等成就源事件的记录覆盖、其余宿主按语言逐键采集及原生筛选、云端协议与跨设备展示仍需在 #11546 的同一分支/PR 继续核对和实现，不把新增本地字段说成已经完成跨设备同步。各平台已有账号与热力图入口继续复用。

云端调查固定在实际默认分支 `main` 的提交 [`c9a65255ebb17a98efa86b30e866b6ad481e5df1`](https://github.com/metasequoiaime/msime-cloud/blob/c9a65255ebb17a98efa86b30e866b6ad481e5df1/internal/account/typing_statistics.go)。`TypingDay` 仅含每日字数、活跃秒数、小时、类别和来源，上传一次最多 31 天；服务端保留 62 天、最多 8 台设备。该文件的上传处理只区分写入与删除，并非客户端全量历史同步协议。没有读取相邻仓库的未提交内容，也没有改服务端或向生产环境发请求。
