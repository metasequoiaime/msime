# Agent Note: macOS 原生候选设置页用顶部四标签切换

Status: implemented

## Problem

原生 AppKit 候选窗口页把布局、字号、窗口几何与预编辑堆在同一张长卡片中，用户要滚动找设置。用户要求四个顶部标签，并要求装到本机；安装与验收对象是 `platforms/macos` 的输入法宿主。

## Decision

用原生 `NSSegmentedControl` 提供布局、字体大小、窗口样式、预编辑四个标签。原来的控件实例保留，只隐藏不选中的分区；公共候选预览、示例文字、预览明暗和展示状态不重建。标签状态只属于本次窗口，不写用户偏好，不发外观变更通知。

布局承载排列、候选个数、跟随光标、模式提示、logo、页码与展开候选；字体大小承载字体预设、主字体、英文字体、候选字号、拼音字号与整体缩放；窗口样式承载不透明度、圆角、边距和原有完整配色；预编辑承载候选窗预编辑。双拼方案的预编辑选项继续属于输入方案页。

每个分区恢复入口只恢复所属设置。搜索保留未选中标签的条目，打开结果先选择其标签，再滚动并高亮对应行；方案本身不支持的隐藏选项继续过滤。

## 正常入口的后续修复

[正常候选设置入口显示顶部四标签](../bug-fix/2026-10-13-macos-primary-settings-tabs.md) 取代本篇对共享页面的入口判断：`showAppearance:` 正常打开共享设置页，AppKit 是启动失败时的备用窗口。本篇的原生标签、搜索与生命周期决定仍适用于备用窗口；实际正常页面的四标签由后续修复实现。

## 历史审计

[展开候选](../../implemented/feature/2026-10-12-macos-expanded-candidate-grid.md) 与布局开关部分重叠，只改变它的展示位置，不改行为。[宿主预览 token](../../implemented/bug-fix/2026-10-11-macos-candidate-preview-native-tokens.md) 讨论共享预览绘制，与原生标签无关。此前本分支的共享 React 标签改动完全撤回，由本篇记录原生实现的边界。

## Alternatives considered

- 重建当前标签的控件：只需要布局一组内容；但会丢失临时预览状态，并使控件引用、搜索索引和恢复入口需要重建。保留控件、隐藏分区更符合现有原生设置窗口的生命周期。
- 改共享 React 页面：能复用跨平台组件；但本次用户要求的是本机原生窗口，Tauri 设置壳不是 macOS 输入法产品，改它不能完成请求。

## Verification

原生构建与 `skin-preview`、`bundle-contents`、`backend-library-load` 测试通过；测试覆盖四标签、隐藏分区、预览状态保留、无偏好写入及搜索跨标签跳转。通过安装脚本装入系统输入法目录后，在原生窗口逐个切换四个标签，确认只有对应卡片显示。`verify-local.sh --quick` 通过。

共享 UI 全量测试使用 4 个 worker 运行，568 个文件、3018 项全部通过。双拼键位提示测试先完成方案保存，再断言下一次保存沿用返回的 revision，避免自动保存拆成两次时依赖执行快慢。

## Consequences

搜索必须区分标签隐藏与不支持的设置隐藏；标签切换要重新布局并回到页顶，避免停留在旧标签的滚动位置。
