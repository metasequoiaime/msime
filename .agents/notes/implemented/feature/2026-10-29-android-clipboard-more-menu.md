# Agent Note: Android 剪贴板顶行的「更多」菜单

Status: implemented

## Problem

#10037：Android 键盘剪贴板面板的顶行依次是「本机 ▾、云端、计数、分类、搜索、导出、多选、清空」，删除后还有「撤销」。这些按钮挤在一行里，常见手机宽度下右边几个落在屏外，要横滑才找得到，看上去也杂乱。报告者的草图是：顶行只留本机、云端、计数、搜索、多选，右上角加一个带向下箭头的「更多」，分类、导出、清空这些用得少的收进去，点了向下展开。报告者特别提醒，弹出来的菜单在系统深色模式下文字不能和底色融成一片。

iOS 和鸿蒙的剪贴板顶行没有分类、导出、多选、撤销这些入口（iOS 只有搜索、清空和来源分段，鸿蒙只有保存当前和清空），不存在拥挤问题，这次只改 Android。

## Decision

- `ImePanels.renderClipboardHistory` 的本机常态顶行（不在确认清空、不在多选）是：本机分类 ▾、云端（可用时）、计数（`weight=1`）、搜索（有记录时）、多选、「更多 ▾」。删除后的「撤销」不在顶行，浮在面板右下角（[浮动撤销与撤销时长](2026-10-29-android-clipboard-undo-floating.md)，#10073）。「更多」是最右边的文字按钮，读屏说明是「更多剪贴板操作」，展开时选中、字样换成「更多 ▴」，API 30 起另报「已展开 / 已收起」（API 28、29 上读屏只能读到「已选择」）。剪贴板历史没开时顶行只有本机、计数和「更多」，菜单里只有「分类」，和原来顶行一直有「分类」一致。
- 菜单由 `renderClipboardMoreMenu` 画在 `clipboardPanel` 最上面、贴右对齐，正好落在「更多」下方，下面的卡片随之下移。菜单容器本身不设无障碍说明，免得 TalkBack 在一个不能操作的节点上多停一下。展开时列表滚回顶部，菜单才看得见。菜单项与原来顶行上的出现条件相同：「分类」一直有（读屏「管理剪贴板分类」），「导出」要有记录（「导出全部剪贴板历史」），「清空」要历史开着（「清空剪贴板历史」）。点「清空」收起菜单，顶行换成 #10027、#10030 的确认行，确认和认证流程不变。
- 菜单 never 是 `PopupWindow`、`PopupMenu` 或对话框，理由同 [剪贴板面板原地操作](../bug-fix/2026-10-08-android-clipboard-panel-in-place.md)：输入法没有 Activity 的窗口令牌，弹窗会让键盘进程崩掉或抢走编辑器焦点（#5605、#5653）。`check-host.sh` 的无对话框守卫把 `renderClipboardMoreMenu` 也纳入检查（守卫的正则同时匹配 `void` 和 `LinearLayout` 返回类型，否则返回菜单视图的这个方法匹配不上）。守卫用 `awk` 扫到方法结尾的 `    }` 为止，不再用 `rg -A 30` 截固定行数：菜单方法最后几行正是把菜单挂到面板上的地方，按行数截会漏掉在那里新加的弹窗；同时把 `PopupWindow` 也列进禁用名单。
- 菜单项是普通键帽 `KeyboardKeyRole.KEY`，由换肤遍历按当前皮肤上色，字色和底色就是字母键的 `keyForeground` / `keyBackground` 那一对。跟随系统的皮肤在系统深色模式下由 `ImeStyler.themed` 换成深色那一套，所以菜单文字的反差和键盘上的字母一样，换肤、深浅色切换都跟着走。菜单外框不归换肤遍历管（遍历只给按钮和文字上色，不碰容器），由 `ImeStyler.applySkin` 在遍历之后调 `ImePanels.styleClipboardMoreMenu` 补画：底色是皮肤背景色，描边是按键前景色 25% 透明度，深浅底上都看得出边界。外框必须挂在 `applySkin` 上，不能只在 `renderClipboardHistory` 末尾画一次：系统深浅色切换时 `onConfigurationChanged` 换了皮肤、走 `render()` 和 `applySkin()`，但不重画剪贴板面板，只在渲染时画的外框会留着旧皮肤的浅色底。
- 菜单与分类选择器互斥：点「更多」先关掉分类选择器，点「本机 ▾」先收起菜单，渲染时选择器优先。换分段、重开面板、进入多选、点撤销、长按一条、点 ⓘ 看详情，以及点了菜单里的任何一项，都会收起菜单（`clipboardMoreOpen = false`）。点 ⓘ 时记下的滚动位置按菜单收起后的布局算（`clipboardScrollYWithoutMoreMenu` 减掉菜单高度和上下边距）：从详情返回时菜单已收起、列表上移了约 140 dp，直接记 `getScrollY()` 会让刚看的那条错开甚至滚出顶部。「搜索」不单独收：通过认证后面板关掉，重开时菜单已经收起；认证被取消时菜单留着展开。
- 「更多」不在横向滚动里：常态顶行是一个横排，左边是带权重的 `HorizontalScrollView`（本机 ▾ 到多选），右边钉着「更多」。横排先量不带权重的「更多」，滚动区只分到剩下的宽度。收走三个按钮后，360dp 宽、系统默认字号下滚动区一行放得下，不需要横滑；有云端分段、分类名很长、字号很大或键盘很窄时，只有左边那些按钮要横滑，「更多」始终整个在键盘宽度以内。原来「更多」是滚动区里的最后一个按钮，超宽时它最先被挤出屏外，正好重现报告抱怨的「要横滑才找得到」。

## Alternatives considered

- **照草图做成浮在卡片上方的下拉层**：最接近草图，展开时列表位置不动。但菜单要挂在固定顶栏 `clipboardHeader` 里、盖住正在滚动的卡片，菜单外的区域要么透传触摸（点卡片会直接上屏、长按会打开操作行，菜单还开着），要么自己铺一层拦截触摸的遮罩并管无障碍焦点；固定顶栏的设备验收也要改成区分展开和收起两种高度。面板内展开和分类选择器是同一种做法，状态只有一个布尔值，代价是展开时列表回到顶部、卡片下移一截。
- **用 `PopupWindow`（`INPUT_METHOD_NOT_NEEDED`）**：剪贴板全文预览就是这样做的，能真正浮在面板上。但它是另一个窗口，要自己处理键盘收起、旋转、面板重画时的关闭，且无对话框守卫针对的正是从面板弹出窗口这一类问题；三项菜单不值得引入第二个窗口。
- **去掉 `HorizontalScrollView`，顶行按键盘宽度 `EXACTLY` 量**：确认行（#10030）就是这样做的，按钮永远在屏内。但常态顶行的「本机 ▾」显示的是当前分类名，长度不可控，按钮总宽超出时横向 `LinearLayout` 会把右边的按钮裁掉；左边保留横滑兜底、「更多」钉在滚动外，两头都顾到。
- **「更多」留在横向滚动的末尾**：第一版就是这样，结构最简单。但只在 360dp、无撤销时量过不需横滑；删除后出现「撤销」、有云端分段或系统字号调大时整行超宽，「更多」作为最后一个按钮最先被推出屏外，又要横滑才找得到。
- **图标工具栏（报告附的语燕输入法动图）**：图标比文字省地方，但面板里其余按钮都是文字，「分类」「导出」这类操作没有通行的图标，读起来反而要猜。

## Consequences

- **收益**：常见宽度下顶行一屏放得下，搜索和多选不再藏在屏外；分类、导出、清空集中在一处；菜单配色复用键帽的前景、底色配对，深浅色和换肤下的可读性与键盘本身一致，不另维护一套颜色。
- **代价**：分类、导出、清空多点一次；展开菜单时列表回到顶部、卡片下移一截，滚到中间时用户会丢掉原来的位置。窄键盘、很长的分类名或大字号时，左边的搜索、多选仍可能要横滑才看得到，「更多」不受影响。如果用户反馈展开时跳回顶部很烦，再考虑浮层方案。
- 设备验收里依赖顶行按钮的地方（`ClipboardCategoriesDeviceSmoke` 的分类管理、`ClipboardExportDeviceSmoke` 的键盘导出、`ClipboardSegmentDragDeviceSmoke` 的清空确认）都先点「更多剪贴板操作」。

## Verification

`ToolbarEdgesDeviceSmoke.checkClipboardMoreMenu` 用 30 条合成历史驱动真实渲染：菜单收起时面板里没有分类、导出、清空；360dp、600dp 下顶行内容不比横向滚动视口宽，「更多」在键盘宽度以内；`checkClipboardMorePinned` 从 240dp 起每次收窄 20dp，直到滚动区确实超宽（到 120dp 还不超宽就失败，不然这条测不到要测的情形），再断言「更多」不在 `HorizontalScrollView` 里、整个落在键盘宽度以内；`performClick`「更多」后菜单画在「更多」下方、不出右边界、容器没有无障碍说明，三项都有宽高、都是 `KeyboardKeyRole.KEY`、字色等于当前皮肤的 `keyForeground`；清掉菜单外框后单独调一次 `ImeStyler.applySkin`，外框重新画上、底色等于当前皮肤背景色；点「清空」后菜单收起、`clipboardClearPending` 为真；`checkClipboardMoreDetailReturn` 在菜单开着时滚到第 6 条、点它的 ⓘ 再返回，断言这一条回到离开时的位置。`bash platforms/android/check-host.sh` 编译面板和设备套件并跑 JVM 冒烟。

这些设备断言都没有在模拟器或真机上跑过；深色模式、深色皮肤下的实际观感，菜单开着时切换系统深浅色的外框换色，360dp 加系统最大字号时顶行的实际样子，展开菜单时编辑器焦点是否保留，都没有截图或真机确认。
