# Agent Note: 从已发布拼音输入补足五笔多字词

Status: implemented

## Problem

五笔补充表只从 rime-ice 主表取权重至少 5000 的二字词；三字及以上词、拼音补充表和人工词条均未覆盖。机器学习、环境变量、持续集成、短视频与五笔输入法等现有拼音词因此没有五笔编码。

## Decision

86 与 98 生成器读取 rime-ice 主表、补充表、区划补充表和 custom/words.txt。rime-ice 收录两字及以上、权重至少 100 的汉字词；100 覆盖上游以该权重整理的现代词语，同时过滤更低权重语料碎片。人工词条与区划名称不受门槛限制。已有另一版五笔词组仍完整参与候选。

同词多音或多来源取最大权重、只生成一行，按本版单字全码生成编码，不跨版本借码；原始表任何编码已有的词一律跳过。来源集合、摘要、收录条件及生成器提交写进补充表头，依然在原路径整份生成。

[共用编码流程](../simplification/2026-10-12-wubi-supplement-common.md) 继续负责全码、一致前缀、同码排序与权重封顶；本改动只扩展候选来源及长度范围。

## Alternatives considered

- 只解除二字限制并保持 5000 门槛：规模较小，但短视频、五笔输入法等权重 100 的现代整理词依然缺失。
- 收入全部拼音行而不设门槛：覆盖最广，但把低权重语料碎片和罕用长串一并引入四码候选，增加重码负担。
- 手工加五笔编码：少量补词直接，但不能系统解决数十万现有拼音词缺码的问题，也违背补充表必须由生成器重建的约定。

## Consequences

五笔词组显著增加，补充词最高权重仍为 9，原始表同码候选优先。新增重码会让一些原有唯一四码失去自动上屏条件，生成器报告统计其数量；低权重补充词较多时依赖生成行序维持词频顺序。没有一致全码的词继续跳过，两版均在生成时排除构建器不会收录的扩展区汉字（包括长词不参与编码的中间位置）。专业 packs 与未获再分发授权的输入不参与生成。

更新词库仓的两份审计快照时必须用干净的生成器提交并同步 NOTICE；运行完整数据构建、重复生成的字节比较、编码及候选顺序检查后才准备发布。生成器单测覆盖门槛边界、长词、补充表、低权重人工词条与多音去重。

构建时重新派生与个人学习共用取码规则的后续决定见[词库持续补全](../../implemented/feature/2026-10-18-dictionary-completion.md)；本篇的来源筛选及权重约束继续适用。
