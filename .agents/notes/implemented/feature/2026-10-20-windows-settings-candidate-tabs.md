# Agent Note: Windows 设置候选窗口页改回 macOS 的四个标签

Status: implemented

## Problem

macOS 桌面设置的「候选窗口」页在 [候选窗口顶部功能标签](2026-10-18-candidate-window-top-tabs.md) 之后分四个页内标签：布局、字体与大小、窗口样式、预编辑，标签条下面是一张无标题卡片里的预览，样例是拼音 ni'mf 和「你们、你、尼…」，带水杉 logo 和辅助码。Windows 原生设置窗口还停在 [主题页与候选窗口页精简](../simplification/2026-10-16-macos-appearance-settings-prune.md) 时的一列：预览、「布局与字体」组，其余九行收进一个「更多选项」，「游戏」组放在折叠区后面。行控件也和 macOS 不一样：每页数量是 1–9 的滑块带「每页显示的候选项（1–9）」说明，字号和预编辑字号是滑块，「候选窗口跟随光标」名字不同，整体大小和不透明度的说明是固定的，圆角旁的按钮叫「默认」且没有按下态，「候选字体」六个选项超过 `segmented_control` 默认的三段，退成了下拉框。预览自己画一个「中」字、拼音 hou’xuan’xiang 和「候选项、后选项…」，打开翻译时还带英文释义，不画 logo 和辅助码。用户要求 Windows 以 macOS 为准迁移这一页。

## Decision

### 页面结构

- 页首引导下面是 `page_tab_bar` 画的四个标签，名称「候选窗口设置」，标签 id 与共享 UI 的 `candidateTabs` 相同（`layout`、`font`、`style`、`preedit`），自动化前缀 `candidate-tab`。每个标签里一组，组名与标签同名。
- 「布局」：候选项排列方式、每页候选项数量、显示水杉 logo、跟随光标。「字体与大小」：候选字体、按需出现的主字体、字号、英文字体、整体大小。「窗口样式」：不透明度、圆角大小。「预编辑」：预编辑字号、候选窗口预编辑、行内预编辑。展开候选、页码和内边距在 Windows 上没有能力位，不画。
- 预览在标签条和标签内容之间，放进一张 `add_group(page, L"")` 的无标题卡片，内边距照共享页 `groupPreview`（左右 24、上 20、下 30 DIP）。
- 「游戏」组是 Windows 独有的功能开关，不属于哪个标签，画在标签内容下面、一直显示。建索引时画它之前清空 `tab_index_`，搜索结果的位置只写「候选窗口 › 游戏」，打开时不切标签。
- 原来的「更多选项」折叠区和它的 `candidate_more_open_` 删掉；搜索落到某一行时由标签框架切到所在标签，不再靠 `fold_holds_focus("candidate-more")`。

### 行控件

- 每页候选项数量照 `CandidatePageSizeSection`：3 到 9（Windows 的 `max_candidate_page_size`）的滑块，每档一个刻度（`TickFrequency` 1、`TickPlacement::Inline`），数值在右边，没有说明；存着的值不在这个范围里时把范围放宽到它，不改写（`offeredCandidatePageSizes` 的规则）。
- 「字号」「预编辑字号」用 `number_select_row` 画成 12–32 的下拉框，没有说明。
- 「跟随光标」改用共享页的名字。
- 整体大小和不透明度的说明随数值写成「N%，字号与窗口尺寸一起缩放」「N%，文字和焦点高亮保持不透明」，拖动时经 `row_subtitle` 就地改写，不重画整页。滑块旁的数值文字收起：共享页这两行只传 `valueText`、不传 `displayValue`，`valueText` 只渲染成读屏用的 `aria-valuetext`（`platform-controls.tsx`），可见数值只有传了 `displayValue` 的 `SliderRow` 才画。
- 圆角大小旁边的按钮叫「跟随皮肤」，是一个 `ToggleButton`：没有覆盖值时选中（按下），再点不起作用；有覆盖值时点它清掉 `candidate_corner_radius` 并重画。说明在跟随时是「跟随皮肤；设置后覆盖皮肤自带的圆角」，覆盖时是「Npt，覆盖皮肤自带的圆角」；滑块旁的数值文字和整体大小、不透明度一样收起，否则跟随时会在同名按钮旁再画一个「跟随皮肤」；拖动滑块时就地改写说明、抬起按钮。点按时读文档里现在的值，而不是画出来时的状态，因为拖动不重画页面。
- 「候选字体」调用 `segmented_control` 时把 `maximum_segments` 设成选项数，六段都画成分段控件，圆体那一段照旧按不下去。

### 预览

- 顶上一行是共享页 `AppearanceCandidatePreview` 的说明「预览：固定样例随当前设置草稿变化，不代表实际输入候选。」，12 DIP 次要色，与预览面相隔 18 DIP。
- 默认样例与共享页的 `previewSamples` 相同：首行是水杉 logo（随 `show_app_logo`，16 DIP 见方、隔 6，即候选窗的 `logo_side`、`logo_gap`）、拼音 ni'mf（强调色半粗）和 1.5 DIP 宽、1.2 倍字高的光标；拼音隐藏时只剩 logo，logo 也关掉时首行不画。候选是你们、你、尼、妮、泥、逆、拟、腻、拧。
- 方案是全拼或双拼、这一族的辅助码打开且「在候选窗口中显示」时，候选后面同字号同色带上辅助码（「你们(rR)」）；缺值取 client-core 的出厂值，与「输入」页的 `helpcode_rows` 相同。用户输入的示例文字不带辅助码。
- 不再画英文释义：共享页的样例没有释义。
- 示例文字框、「跟随设置 / 预览浅色 / 预览深色」下拉、页头的「界面预览」开关和「编辑主题」按钮是 Windows 自己的比较工具，按用户的决定保留。
- 「主题」页的完整预览和这一页是同一个 `make_preview` / `update_preview`，所以上面的说明行、ni'mf 样例、logo 和辅助码同样出现在「主题」页，那里的预览也不再画英文释义（`candidate_translations` / `candidate_english_gloss` 不再进任何一处预览）。
- 当前皮肤包照共享页 `ExternalAppearancePreview` 画进预览：选着自定义主题时取预览明暗那个槽位的包（`candidate_skin_for`），包得在扫描到的目录里、能在这种明暗下画（`skin_draws_in`）并支持当前排列方式和明暗（`card_compatible`），画布皮肤除外。画它时用包的圆角（用户设了圆角时用用户的，`candidate_card_radius`）、最小宽度、背景图（`ImageBrush` 按 fit 拉伸、按卡片内圈圆角裁切，透明度乘窗口不透明度）和装饰图（照候选窗的 `candidate_decoration_rect`：卡片上方留出 `decorationTopDip × 整体大小` 的装饰带，图宽是装饰宽度、按比例，底边压进卡片顶边一个内边距，太高时等比缩小，按 `decorationAlign` 离卡片左右边一个内边距或居中）。预览卡片外面因此套了一层 `preview_frame_` Grid，装饰图和卡片同在一格。图片沿用主题页那套扫描和解码（`scan_skins`、`skin_images_`）：进入「候选窗口」页、以及停在这页时窗口重新获得焦点，若自定义主题设了皮肤包就把目录标成待扫；`redraw_themes` 在这一页只调 `update_preview`，扫描落地、图片解码完成或失败时重画预览而不拆掉页面上的控件。

## Alternatives considered

- **「游戏」做成第五个标签**：页面全部由标签分区，搜索和截图的写法更整齐。否决：「游戏」管的是候选窗在游戏里出不出现，不是外观，和四个外观标签不是一类；macOS 没有这一组，加一个 macOS 没有的标签会让两边的标签条对不上。放在标签内容下面一直显示，不论在哪个标签都找得到。
- **按缺口清单去掉示例文字框、预览明暗下拉、「界面预览」开关和「编辑主题」按钮**：与 macOS 完全一致。否决：用户决定保留这几个 Windows 自己的比较工具，它们只改预览、不写偏好，不影响和 macOS 一致的那部分。
- **预览只画包解析出来的配色，背景图和装饰图留到以后**：不用在候选窗口页触发皮肤扫描、也不用改 `redraw_themes`。否决：用着带图皮肤包时预览和真实候选窗看起来不同，正是 macOS `ExternalAppearancePreview` 要避免的；扫描和解码已经有一套，在这一页标待扫、让 `redraw_themes` 在这一页只重画预览就能接上，改动不大。
- **直接复用 `make_skin_sample` 画当前皮肤包**：现成的带图样例。否决：那是包卡片上按 0.7 缩放、固定三个候选的示意，不跟随字号、每页数量、辅助码、logo 和用户的圆角、不透明度；预览要的是跟着设置草稿变化的那一份，所以把背景图和装饰图加进 `update_preview` 本身。
- **整体大小、不透明度和圆角的说明在拖动时整页重画来更新**：不用找说明那一行。否决：重画会拆掉正在拖动的滑块，拖动中断。

## Consequences

- **收益**：Windows 与 macOS 的候选窗口页分区、行名、控件类型和预览样例一致，CI 截图可以逐标签对照；搜索落到任何一行都切到所在标签，不再有折叠区状态。
- **收益**：圆角的「跟随皮肤」有按下态，说明随数值变化，用户看得出现在是不是覆盖了皮肤的圆角。
- **代价**：标签之间切换是整页重画，滚动位置停在原偏移上；字体框的读取状态跟着「字体与大小」标签走，切到别的标签再回来会重建字体框（字体目录本身只读一次）。
- **代价**：「候选窗口」页用着皮肤包时，进入页面和窗口重新获得焦点会在后台重扫一次皮肤目录；扫到的与上次相同时不重画。皮肤包不兼容当前明暗或排列方式、或图片读不到时，预览只画配色，不像共享页那样写一行状态说明。
- **代价**：`candidate_percent_row` 和 `corner_radius_row` 依赖 `row_subtitle` 找到 `add_row` 画出的说明那一行，两者还依赖 `formatted_slider_control` 把数值文字放在第二个子元素来收起它，这两个元素树变了要一起改。

## Verification

- 本机没有 WinUI 3 / C++/WinRT 工具链，`main.cpp` 只能由 PR 的 `CI (platforms)`「Windows native settings」编译并运行 `tests/tools/settings_ui.ps1`：打开「候选窗口」页确认「布局」标签里有预览说明、每页候选项数量、跟随光标和「游戏」组、没有字号、行内预编辑和「更多选项」；逐个切到「字体与大小」「窗口样式」「预编辑」截图，每个标签下「游戏」组都在，「窗口样式」里「跟随皮肤」是按下的、圆角说明是「跟随皮肤；设置后覆盖皮肤自带的圆角」、圆角滑块后面紧跟的不是数值文字、没有写着「100%」的不透明度数值；搜索「主字体」切到「字体与大小」并画出主字体框，搜索「行内预编辑」切到「预编辑」；候选窗口页去掉「更多选项」后，折叠区的搜索覆盖改由「主题」页承担：搜索「候选悬停色」展开默认收起的「自定义配色」并画出这一行；示例文字清空后第一个候选回到「你们」。
- `scripts/test-windows-settings-ui-pages.py`、`scripts/test-windows-settings-art.py` 通过。
- 预览画皮肤包背景图和装饰图的那部分没有自动化覆盖：`settings_ui.ps1` 的合成状态里只有画布皮肤 `verify-canvas`，而画布皮肤按设计只画配色；要在 Windows 上手工选一款带背景图和装饰图的皮肤包，在「候选窗口」页切浅深色、横竖排和整体大小核对。
