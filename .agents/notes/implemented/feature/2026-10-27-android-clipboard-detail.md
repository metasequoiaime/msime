# Agent Note: Android 剪贴板记录详情

Status: implemented

## Problem

#9963 希望在键盘里的本机剪贴板面板直接打开单条记录的详情，查看记录时间、来源应用和包名，并从详情插入原文或返回上一个界面。现有卡片只显示相对时间，长按打开的是全文预览和管理操作。报告者圈出的位置是长按弹出的全文预览（「插入」「修改」「关闭」那一行）里「插入」的左边，返回要回到这个预览；第一版只在列表卡片左侧加了入口，预览里仍没有。

## Decision

详情有两个入口：本机历史卡片左侧的独立详情键，和长按全文预览操作行最左侧、「插入」左边的「详情」。两个入口打开的是同一个详情页，详情仍画在原剪贴板面板内，不弹出可取焦点的窗口；插入沿用原记录的插入动作。详情记着自己从哪一级打开（`ClipboardDetailPolicy.Origin`）：从卡片进入的返回时重新读取同一分类的列表并恢复滚动位置；从预览进入的保留长按展开的操作行，返回时同样重绘列表，再用重新读取到的那条记录重开全文预览，读屏把顶栏和底部操作行的两个返回键都读作「返回剪贴板全文预览」。记录在详情打开期间被删掉或移出当前分类时，返回只回到列表，不对已不存在的记录重新提供插入和修改（`ClipboardDetailPolicy.reopensPreview`）。详情只持有打开时的记录快照，面板关闭或重新打开即清理。记录时间由共享存储已经保存的毫秒时间戳按设备本地时区显示，缺失时明确写“时间未知”。

Android 公开的 `ClipboardManager` 和 `ClipDescription` 没有提供复制来源应用包名的可靠字段。详情对这两项显示“系统未提供”，不把当前编辑器的包名误当复制来源，也不从剪贴板标签猜测。这两个字段只有未来取得可信来源并写入共享记录后才能填充。

## Alternatives considered

- **沿用长按全文浮层加元信息**：能复用窗口，但它是覆盖键盘上方的阅读入口，返回到列表与插入操作的状态不如面板内详情明确，而且仍不能得到来源。
- **预览里的「详情」返回到列表**：和卡片入口共用一条返回路径，不用记来源；但报告者明确要回到带「详情」的那个预览，从预览进入却回到列表，用户得重新长按才能接着读全文或修改。
- **用当前输入框的应用包名代替来源**：容易得到字符串，但复制和粘贴可能发生在不同应用，记录会产生错误归属，因此不用。

## Consequences

用户可以在键盘内查看完整记录时间和正文，并直接插入或回到进入详情前的列表或全文预览；多选、左滑删除和长按管理保持原有入口。每条记录左侧的详情键占用一些卡片宽度，双列布局下正文可见行更短；预览操作行多了一个按钮，四个按钮平分宽度，每个比原来窄。来源应用和包名仍显示“系统未提供”，只有未来取得可信来源并写入共享记录后才能填充，这仍是 #9963 的未完成部分，不能把本改动标为完整关闭该 issue；云端记录的只读预览不带详情入口，「剪贴板中搜索→历史」页面不变。

## Verification

`ClipboardDetailPolicySmoke` 用合成时间验证本地日期与未知值，并覆盖详情返回到哪一级及返回键的读屏说明。`platforms/android/check-host.sh` 经 `rbuild` 在构建机上运行，跑 JVM 冒烟、编译设备测试源码并检查宿主契约，其中钉住预览里「详情」排在「插入」之前、本机记录的预览以 `Origin.PREVIEW` 打开详情、返回经 `reopensPreview` 决定是否重开预览。`ClipboardSegmentDragDeviceSmoke` 的 `preview-actions-only` 阶段增加从预览打开详情、核对记录时间和“系统未提供”、返回后预览重新出现并从重开的预览插入原文，这一轮只编译、未在设备或模拟器上运行；PopupWindow 回调、返回后重读记录并重开预览这条接线目前没有运行时证据，合并前仍需设备验收两个入口、返回、插入及双列布局。
