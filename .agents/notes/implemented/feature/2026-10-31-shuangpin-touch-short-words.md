# Agent Note: 双拼触点短词纠错

Status: implemented

## Problem

#10018 的触点协议、三端接线与按两键码学习已合入，但纠错词图至少要求三个音节，1–2 音节输入没有对应候选。单纯降低整句解码门槛无法覆盖单字，也会改变不带触点的桌面输入。

## Decision

仅对完整的两键或四键触屏请求查询短词纠错，使用现有的方案解码、触点变体计价、纠错类型开关及学习折扣。每次只改一个音节，邻键或两键对调保持各自的开关。无触点、物理键、手动分隔、辅助码与部分编辑继续原路径。

直接查变体的完整词条，按 `ln(max(weight, 1)) - penalty` 排序；只有落点支持、相对字面完整词频未超过现有 `show_margin` 的候选可显示。查询沿用 96 键预算、每键四行的缓存，最多增加四条。保留现有首选，按罚分后的词频插入其余完整词与前缀之间，不把短词查询接到尚未过门槛的首选提升规则上。读音、原按键与纠错标记交给已有选择和学习链路。

非法两键也可尝试合法邻键读音；不能以原码无法解码为理由跳过变体，接受时仍按本次实际生成的变体记键码对。整串没有字面候选时不会单独生成纠错首选，此项受既有首选质量门槛约束，需明确报告召回影响。

## Alternatives considered

- 降低整句的三个音节门槛：能复用词图和语言模型，但不能处理单字、依赖字面路径存在，且会作用于没有触点的旧路径，因此不用。
- 把所有邻键词条直接追加：实现简单、覆盖广，但落在键中心时也会制造大量无关候选，且追加在单字长列表末尾不可见，因此按触点罚分和词频筛选、排序。

## Verification

合成引擎用例覆盖单字、两字邻键、非法两键、类型开关、辅助码隔离、微软分号、缓存和学习；会话用例验证三种短词纠错选中后完整消耗原码，并写入实际的两键码对。另加两个纠错候选同时命中时的排名用例，断言两条纠错行按罚分后的排名出现；这个顺序由纠错行按排名降序排序后逐个插入保证。引擎全套 2899 项、golden 31 项和两组各 3 项集成测试通过；随后补入的对调门槛用例与其余短词用例共 7 项复验通过。运行时 420 项、Host API 串行 1074 项及三 crate 严格 clippy 通过。Host API 并行首跑的翻译测试失败，单独及串行全套通过；同名并行失败在[既有验证记录](../bug-fix/2026-10-28-preferences-forward-compat-runtime.md)中已记录，不能把并行首跑写成通过。

固定 `dict-v2.0.41` 资源、小模型、五个方案与既有种子，125 组词级评测完成。σ=0.25、偏置 0 时，noisy 前九位召回由约 4%–5% 升至 52%–56%。clean 共 109920 例，首选变化 0，金标准降位 3 例；最差单组 1/2748。两份 dump 共 288540 条记录逐行比较，首选对象全部相同，13740 条无触点记录逐字节相同。另 14 组 G0 的报告与完整候选明细也逐字节相同。输入锁、二进制和 dump 哈希、逐组计数及复现命令见[测量记录](../../../../resources/eval/measurements/shuangpin-short-words-2026-10-31.md)。

Android API 35 arm64 模拟器实际运行这 7 项引擎回归，通过；同源原生 APK 与设备测试通过安装产品的触点专项，包括 `aivv` 无触点不出「癌症」、带冻结落点后出现完整纠错词、首选保持、选词后四键全部消费，以及原有长句、键距和微软分号断言。首轮界面测试把小模型评测首选「爱追」写死，设备实际是「哎追」；改为比较同设备两臂的首选描述后完成验收，不据此修改产品排序。

iOS 同源模拟器静态库重建后，在临时 iOS 27 模拟器用 ad-hoc 签名运行 `TouchPointTests`，20 项通过；未新增 iOS 短词专项。HarmonyOS 同源 Rust/NAPI 编译、暂存资源、`ohpm install`、HAP 打包与逻辑测试通过，核对包内核心词库、设置页、许可证及原生库 `.text` 与本次产物相同；没有鸿蒙短词设备验收。最初一轮 iOS 命令错误关闭签名，已中止且不计入通过记录。

最终完整 quick 已通过，包含 Windows i686 的 478 份源码语法检查、跨宿主 203 项测试、完整 x64 原生链接、Linux 设置壳和原生宿主、HarmonyOS HAP、Android Java、Rust／Wasm、macOS 与 Apple bridge；Linux 注册 113 项，112 项通过、1 项因缺少 IBus／D-Bus 守护进程而跳过。历史句集在其他构建结束后完成两方案各五轮与 A/A 共 20 次复验，全部退出 0：小鹤触点 p95 中位数 5.17 ms、两臂差 +0.07 ms、A/A -0.01 ms；微软 5.10 ms、+0.05 ms、A/A +0.05 ms，历史句集的 16 ms 预算与 0.5 ms 增量门槛通过。短词专集的 20 次延迟运行均在 16 ms 预算内，但小鹤两臂 p95 之差中位数 +0.62 ms（A/A +0.01 ms），超过历史 0.5 ms 门槛的数值；不能宣称没有可测开销。历史门槛使用句集加助词，首次与编译并发时两臂都超 16 ms，保留失败结果，编译结束后复验通过，不放宽预算。

首轮 quick 通过，但缺交叉构建参数与 Docker，分别跳过 Windows x86、Linux，HarmonyOS 暂存也未完成。补齐环境后的运行发现既有 `desktop_candidates.cpp` 枚举 lambda 使用默认调用约定，不能在 x86 上转换为 `WNDENUMPROC`；复用固定已提交的 `bb96458f5cc3768139491804d2db69fcdca5c531` 修为 `BOOL CALLBACK`，不复制其他检出的未提交内容。按真实 x64 编译数据库提取参数，修改后的该文件 i686 语法检查通过，修复后完整 quick 复验通过；没有把环境跳过记成覆盖，也没有关闭失败检查。

## Consequences

短词可以在第一页提供完整纠错词，同时保留原有首选、默认值、文件与 FFI 格式。当前只改一个音节；整串没有任何字面候选、缺一键触点、带分隔或辅助码时仍不纠。同文前缀恰好是首选时也不替换，否则会破坏首选对象不变的约束；真实词库的 `gq → 给` 可以触及此限制，合成会话回归只证明首位是其他词时的完整消费。未经学习的对调罚分通常高于默认展示阈值，只有既有学习折扣或明确调参使其达标时才展示，本次不放宽阈值。

词频不同于上下文概率，短词缺少句子消歧。固定词级评测集主要覆盖两音节，单字目前只有合成回归；模拟误触不能替代三端真机盲打。首选提升仍受原有失败质量门槛约束，`lead_margin` 保持无穷大，本次只完成 #10018 的短词部分，不宣称整个 issue 已完成。
