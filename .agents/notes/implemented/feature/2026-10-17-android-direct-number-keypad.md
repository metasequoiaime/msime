# Agent Note: Android 数字输入框直接使用九键数字面板

Status: implemented

## Problem

#8477 要求 Android 数字键盘不要把 `1–0` 挤在同一行。现有中文输入框点击 `123` 时已经复用数字九宫格，但数字、电话和数字密码输入框不会启动 Engine，首次进入时仍按字母层建键，无法得到同一套易盲输的数字面板。

#9474 补充文字密码框的手动入口：密码不能使用中文会话，但需要通过 `123` 切到同一套九宫格，方便输入含数字的密码。

## Decision

Android 把 `TYPE_CLASS_NUMBER` 和 `TYPE_CLASS_PHONE` 识别为直接数字输入。输入会话开始时把键层设为数字层，键行复用现有数字九宫格、左侧符号栏、删除/小数点/空格侧列以及底行 `0`，不创建 Engine 会话。数字密码沿用同一布局，但仍由既有隐私策略排除统计和云功能。用户可以用现有层切换键回到字母键盘，满足应用需要时的回退路径。

数字密码与文字密码一样进框临时切英文（`EditorPolicy.prefersLatin` 包含 `EditorPolicy.password` 认的数字密码，离开时恢复原来的中英），所以它的字母层是英文 26 键。没有引擎会话时字母层按记住的中文键面（`touchLayoutHint`）画，不切英文的话九键、注音、笔画用户在密码框里回到的是一块没有引擎、打不出字母的中文键面（#10481，夜间 API 28 上前一个套件停在大千注音时就是这样）。鸿蒙把 `PATTERN_PASSWORD_NUMBER` 归入密码，同样走英文。普通数字框和电话框不切，仍按用户的中英进框。

数字输入的判定放在 `EditorPolicy`，键区只通过 `MSIMEInputService#directNumberPad` 读取；这样数字键盘的入口不会复制到渲染代码，也不会改变中文输入框点击 `123` 的既有方案判定。数字页的 `#+=`、符号、删除、空格手势和 `0` 仍沿用现有组件。每次重建数字输入框的键行时同时清除 `ImeLetterRows#moreSymbols`，避免同一个输入法服务从普通文本框切换过来后把旧的 `#+=` 页带进数字框。

文字密码的普通、可见和网页三种类型保持字母首页；只在用户切到数字符号层时，由 `ImeLetterRows#numberPadDrawn` 复用 `EditorPolicy.password` 选择九宫格。此条件不加入 `directNumberPad`，避免文字密码首次进框被强制换成数字。输入仍不创建 Engine 会话，密码的统计、学习和在线建议排除规则继续生效。沿用本篇的布局决定，不新增另一套密码键盘；自动数字行笔记只控制额外一行，与此手动数字页无冲突。

## Alternatives considered

- 只调整 `KeyboardLayout.numberLayer` 的横排数字：能改变英文或独立语言的符号页，但数字输入框根本不会进入这条设计层，无法修复报告的首次键盘。
- 让数字输入框启动 Engine 再走中文 `123`：可以复用现有会话状态，但数字和电话字段不应组词、学习或读取候选，且密码字段会扩大敏感数据边界。
- 为数字输入另建一套拨号盘：能完全控制键位，但会复制九键的统计、反馈、删除和符号侧栏，后续修复会产生两套行为漂移。
- 只改设备测试，数字密码返回后不再断言 `q`：夜间能转绿，但九键、注音、笔画用户在数字密码框里回到一块没有引擎的中文键面这个产品缺口原样留着。
- 把文字密码也归入直接数字输入：能复用首次进框的切层逻辑，但会把含字母密码的默认键盘改成数字；仅扩大数字页的显示条件即可满足手动切换。

## Consequences

数字和电话输入框首次弹出键盘即可看到三行 `1–9`，`0` 与空格保持在底行/侧列的既有易用位置，密码框不增加 Engine 或云端暴露。代价是数字字段的层键仍可切到普通字母面，应用若拒绝字母输入会由编辑器过滤；这是保留输入法现有回退入口的结果。独立语言和中文输入框的数字页规则不变。

## Verification

#10481：`EditorSmoke` 钉住数字密码 `prefersLatin`、普通数字与电话不切；`NumberPadDeviceSmoke -e password-number-pad true` 先以九键用户在中文框里显示一次九键，再跑四种密码框，数字密码返回字母层必须是英文 `q`，不再取决于前一个套件停在哪种键面。

`EditorSmoke` 覆盖普通数字、数字密码、电话输入和文本输入的分类边界；设备测试编辑器增加合成数字输入框，`NumberPadDeviceSmoke` 在 API 28 专用模拟器上先让普通文本框停在 `#+=` 页，再切换数字框，检查三列九宫格并输入 `1203`。`platforms/android/check-host.sh` 的 242 项 Android JVM 冒烟和 Gradle Java/Lint 构建通过；API 28 上单独运行 `NumberPadDeviceSmoke` 通过。完整 `smoke.sh emulator-5566 --core` 在无关的剪贴板导出取消选择阶段失败。

#9474 专项 `NumberPadDeviceSmoke -e password-number-pad true` 在 API 28、35 均通过，覆盖普通、可见、网页文字密码及数字密码的默认键面、真实三列几何、数字输入和删除、返回字母、符号页往返。仅检查合成密码的长度，不依赖密码明文是否可通过无障碍读取。同一份最终测试夹具对固定旧包均在文字密码 `type 129` 的九宫格断言失败，修复包则跑完四种类型；两台设备实际安装的 APK SHA-256 均与待测产物一致。

API 28 首轮在网页密码页采集几何超时：逐数字刷新整棵无障碍树导致未在期限内取得两帧坐标。测试改为一次遍历收集九个数字，保留连续两帧一致与三行三列断言；切层后先等待数字页的 `#+=`，避免误认字母页自动数字行。API 35 最终复跑前曾遇模拟器退出与 System UI ANR，中断日志另存，不计入通过结果。

完整中文数字布局回归需要笔画、注音的语言词库。初轮新旧 APK 都在 `stroke letter face` 失败，因为所复用的核心包没有附带按需词库；复跑前经原生「输入」设置下载语言词库，遵循[设备门禁的词库前置约定](../testing/2026-10-08-android-device-gates.md)。缺少测试输入时先补输入，不跳过依赖这些方案的断言。 补齐后同一修复 APK 和最终夹具的 API 35 完整 `NumberPadDeviceSmoke` 通过，覆盖全拼、小鹤、十四键、九键、笔画、注音九键及全角数字，并检查连续算式、符号往返、原键面恢复与键位统计。

本次 258 项 JVM 冒烟、225 份设备源码编译、包含最终测试夹具的完整 `scripts/verify-local.sh --quick` 和原生 Gradle `assembleFullRelease` 均通过。设备包重编本分支 Java 与资源，复用固定提交 `3d0040bad1f593cf758f62118d9335dd64522313` 的 JNI 和词库：逐项核对的 150 项原生库及固定资源一致，Java 构建生成的两份 dexopt baseline profile 单独排除并保留比较记录。此结果不代表当前 Rust 核心已重新在设备构建验收；本次不改 Rust、JNI 契约或词库，未在报告人的 vivo 真机或 KeePassDX 验收。
