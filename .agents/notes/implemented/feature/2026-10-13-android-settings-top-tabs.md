# Agent Note: Android 设置分组统一为顶部分类

Status: implemented

## Problem

Android 功能页把多个设置分组串成长列表，用户需要反复滚动寻找。皮肤页已有固定的顶部分类，其他页面的导航方式与它不一致。

## Decision

除手写外，所有含多个分组的 Android 详情页复用顶部通栏圆角分段导航，统一采用统计页的等宽段、容器内边距和 40dp 高度。分类多时仍保持等宽，按标题分组，不缩小字体。`DetailPage` 维护分类选择及各分类内容列；页面显式指定每组的归属。`HomeActivity` 在所有主界面页面首次创建、底部 Tab 切换和详情页导航期间显示统一的圆形 loading 覆盖层，页面视图创建后以最短时长淡出；根 Tab 与详情页都绑定关闭回调。切换只改变内容列可见性，保存与异步刷新保留分类，视图恢复保存分类名。空的条件性分类不展示；必要的公共错误提示仍可在页面内容区显示。

## Alternatives considered

- 沿用长列表，只增加跳转到分组的按钮：实现简单且所有设置一直可见，但点击后导航与内容仍不一致，不能满足一次只看一类设置的要求。
- 在公共卡片工厂按标题自动分类：页面改动少，但动态标题、未命名卡片和异步添加内容会产生隐式契约，且不能准确判断确认操作的归属，所以采用页面显式绑定内容列。

## Verification

键盘页在 Android 12 真机安装后显示「布局 / 反馈 / 手势 / 工具栏 / 剪贴板」顶部分类，AI 润色作为设置首页独立入口；点选「反馈」后只显示按键反馈内容。所有主界面页面和 Tab 切换共用统一 loading 覆盖层，顶部分类与统计页采用相同的通栏等宽样式；AI 润色和常用语不再嵌套在键盘、表达页内，而是设置首页的独立入口，真机安装启动后 loading 正常消失且可操作，无崩溃。`build-apk.sh`、`scripts/verify-local.sh --quick` 与 `git diff --check` 通过。

## Risks

多分类使用等宽段；AI 页面和常用语页面从设置首页独立进入。页面内从「我的」打开皮肤、词库等详情时保留来源 Tab，返回不会跳到「设置」。输入表单切换时须收起输入法，避免焦点仍留在不可见分类。原有依赖和异步任务继续使用原页面的生命周期。

## Consequences

顶部分类让长设置页一次只显示一个主题，切换时不再滚动寻找分组。多分类页面需要横向滑动；分类内容列保留在内存中，因此页面会多占少量视图内存。手写页继续使用原来的分组布局。
