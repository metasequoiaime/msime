# Agent Note: Android 设置分组统一为顶部分类

Status: implemented

## Problem

Android 功能页把多个设置分组串成长列表，用户需要反复滚动寻找。皮肤页已有固定的顶部分类，其他页面的导航方式与它不一致。

## Decision

除手写外，所有含多个分组的 Android 详情页复用顶部通栏圆角分段导航，统一采用统计页的等宽段、容器内边距和 40dp 高度。分类多时仍保持等宽，按标题分组，不缩小字体。每页最多四个分类：等宽分段在第五个时每段明显变窄，和其他页面对不齐，所以内容多的页面合并相近的分组，而不是加第五个分类。键盘页因此是「布局 / 反馈 / 手势 / 工具栏」，剪贴板面板从工具栏打开，它的设置作为「剪贴板」一组放在工具栏分类里；语音页是「识别 / 服务 / 润色 / 隐私」，本地模型本身就是一种识别服务，「本地识别准备」和「本地模型」两组跟在识别服务下面。条件性分类也算在四个之内，`check-host.sh` 检查每个详情页声明的分类数。`DetailPage` 维护分类选择及各分类内容列；页面显式指定每组的归属。`HomeActivity` 在所有主界面页面首次创建、底部 Tab 切换和详情页导航期间显示统一的圆形 loading 覆盖层，页面视图创建后以最短时长淡出；根 Tab 与详情页都绑定关闭回调。切换只改变内容列可见性，保存与异步刷新保留分类，视图恢复保存分类名。空的条件性分类不展示；实际内容不足两类时隐藏整条分类导航并收回高度，异步加载或选服务后出现第二类内容时重新显示。联系人与云剪贴板的首张卡片不再重复显示「电话本」「云剪贴板同步方式」小标题，具体操作仍由卡片内的行标题说明（#9010）。必要的公共错误提示仍可在页面内容区显示。

慢公告导致设置内容延后显示的线程调度缺陷见[公告请求不阻塞设置内容](../bug-fix/2026-10-22-android-notices-settings-queue.md)；本篇的分类导航与布局决定继续成立。

## Alternatives considered

- 沿用长列表，只增加跳转到分组的按钮：实现简单且所有设置一直可见，但点击后导航与内容仍不一致，不能满足一次只看一类设置的要求。
- 在公共卡片工厂按标题自动分类：页面改动少，但动态标题、未命名卡片和异步添加内容会产生隐式契约，且不能准确判断确认操作的归属，所以采用页面显式绑定内容列。

## Verification

#9010 的原生 APK 在 API 28 模拟器验证：联系人、未启用在线翻译的翻译服务、未登录的云剪贴板均不再显示单项分类条，联系人与云剪贴板的重复卡片标题移除，内容上移且不留分类条占位。翻译服务选自定义后「服务 / 配置」重新出现、两类可以切换，改回「不使用」后分类条收起；键盘页仍可从「布局」切换到「反馈」。`check-host.sh` 通过 250 项 JVM 冒烟与 196 个设备测试源文件编译。

键盘页在 Android 12 真机安装后显示顶部分类（当时是「布局 / 反馈 / 手势 / 工具栏 / 剪贴板」五个，后来按四个的上限合并），AI 润色作为设置首页独立入口；点选「反馈」后只显示按键反馈内容。所有主界面页面和 Tab 切换共用统一 loading 覆盖层，顶部分类与统计页采用相同的通栏等宽样式；AI 润色和常用语不再嵌套在键盘、表达页内，而是设置首页的独立入口，真机安装启动后 loading 正常消失且可操作，无崩溃。`build-apk.sh`、`scripts/verify-local.sh --quick` 与 `git diff --check` 通过。

## Risks

多分类使用等宽段；AI 页面和常用语页面从设置首页独立进入。页面内从「我的」打开皮肤、词库等详情时保留来源 Tab，返回不会跳到「设置」。输入表单切换时须收起输入法，避免焦点仍留在不可见分类。原有依赖和异步任务继续使用原页面的生命周期。

## Consequences

顶部分类让长设置页一次只显示一个主题，切换时不再滚动寻找分组。多分类页面需要横向滑动；分类内容列保留在内存中，因此页面会多占少量视图内存。手写页继续使用原来的分组布局。
