# Agent Note: Android 日语九键按下即显示收在键内的五向提示

Status: implemented

## Problem

#6716（Android 0.3.1，小米 Android 16）：日语九键的假名提示要按住大约半秒才出来，出来的又是一个盖住周围一大片键的十字，用户要「一按下就显示」「滑动在一个键内完成」「去掉大十字」。

半秒的延迟是我们自己加的。fb6a5d06fa（PR #3868，和连点切换 あ→い→う 同一批）把 `ImeLayoutRows.bindJapaneseFlick` 从按下即显示改成 `postDelayed(..., ViewConfiguration.getLongPressTimeout())`，理由是连点打字时每一下都闪出一个 3×3 键大的十字太吵。十字本身来自 `MSIMEInputService.JapaneseFlickPreview`：五格每格一个键大，按 ±1 格摆开，盖住被按键四周的 3×3 个键，看上去像要滑很远，其实方向早就由 12 dp 阈值（`JapaneseNineKeyLayout.direction`）决定了。

## Decision

- 按下就显示提示，`bindJapaneseFlick` 不再等长按时长；移动时只在方向变化时重画。`check-host.sh` 禁止 `ImeLayoutRows` 再出现 `getLongPressTimeout`。
- 提示浮层收起时是 `INVISIBLE` 不是 `GONE`：现在每个假名键按下、松开都显隐一次，`GONE` 和 `VISIBLE` 之间切换会让整个键区重新布局，而这个 issue 本身就是在抱怨慢。浮层铺满键区，大小不随显隐变化，`INVISIBLE` 只重画。
- 提示是一个共用的浮层，记着此刻画的是哪个键。松开或取消某个键时，提示属于它才收起：两只拇指交替快打时（按住 か 期间松开先按的 あ），后按、还按着的键的提示不会被先按的键收掉。后按的键先松开、提示被收掉时，还按着的那个键下一次移动就把自己的提示画回来。键盘收起和换布局仍然不分属于谁一律收起。
- 提示只画在被按的键上：方框是键四边各外扩 4 dp，3×3 排出中间和左、上、右、下五格，每格至少 18 dp，键太小时方框按这个放大；方框平移进覆盖层，边上的键不被裁掉。几何在无 Android 依赖的 `JapaneseFlickGuideGeometry`，`JapaneseFlickGuideGeometrySmoke` 覆盖包含、四边夹取、方向格的方位和小键下的不重叠。
- 当前方向那格用强调色填满、字用 on-accent 加粗；中间格字号接近键面，方向格小一号，都不超过格高。空标签（や键的空位、数字层）不画。浮层仍然不拦截触摸、读屏不念。
- 中间格写此刻轻点会打出的假名：同一个键的连点还在时间窗里时是循环里的下一个，否则是键面上的那个。判断放在无 Android 依赖的 `JapaneseNineKeyLayout.tapDirection` / `toggleRemainingMillis`，时间窗和轻点的切换判断共用 `withinToggleWindow`，`JapaneseNineKeyLayoutSmoke` 覆盖时间窗内外和边界、数字符号层、换了键、や/わ 循环跳过直接上屏的方向。每次画提示都重新算，另一只拇指在按住期间打了字、连点断了时，下一次重画就跟着变。按住期间连点时间窗到期（松手会从键面假名重新开始），按 `toggleRemainingMillis` 排的回调把中间格换回来；提示那时画的是别的键就不抢回来。
- 方框的位置在 `onDraw` 里才算，坐标相对浮层自己取，不再相对键盘外框：模拟器上第一版在 `show` 里读位置，当时浮层隐藏时是 `GONE`、没有布局，第一次按下读到 0，提示画到键盘左上角；改成 `INVISIBLE` 后仍在 `onDraw` 里按这一帧的布局算，换布局、拖动浮动键盘之后不会用到旧位置；浮层铺满键区，浮动键盘时键区在外框里有偏移，相对外框算会整体错位。
- 12 dp 方向阈值、轻点和连点切换的输入行为不变；iOS 和 HarmonyOS 不在这次范围内（HarmonyOS 本来就是键内提示，iOS 仍是大十字）。

这推翻了 fb6a5d06fa「轻点不显示」的决定。当时的理由是大十字盖住相邻的键；现在提示只比被按的键大一圈，连点时只是这一个键上的字在变，不再遮挡别的键，于是按下即显示的代价消失了，和 Gboard 的做法以及用户的要求一致。

## Alternatives considered

- **保留大十字，只去掉延迟** — 改动最小，直接解决「慢半拍」；但每一下轻点都会闪出盖住 3×3 个键的浮层，正是 fb6a5d06fa 当初要躲开的问题，用户同一个 issue 里也明确要去掉它。
- **像 HarmonyOS 那样只在键里显示选中方向的一个假名胶囊** — 最省地方，不会有小字；但按下时看不到四个方向分别是什么，用户要的是「按下就看到提示」，只剩一个字等于没有提示。
- **提示中间格固定写键面假名** — 简单；但连点切换时会出现提示写 あ、松手打出 い 的矛盾，挑战意见专门指出了这一点。
- **记下所有按着的键，松开一个就把提示交给另一个** — 交替快打时提示一直不断；但要多维护一份跨按键的状态，换布局时还得清理指向已摘下的键的条目。现在的做法只记一个所有者，被收掉的那个键下一次移动就画回来，手指按着时总会有细小的移动。
- **只在中间格不显示（连点时只画四个方向）** — 也能避免矛盾；但连点时用户最想确认的就是这一下会打出什么，写出来比留空有用。

## Consequences

- **收益**：提示零延迟出现；不再遮挡相邻的键和候选栏；边上的键（あ、さ、わ 所在列）不被裁掉；几何有 JVM 冒烟，延迟回归有 `check-host.sh` 守着。
- **代价**：方向格的字比原来小（约 15 sp，受格高限制），窄键上更小；快速连点时被按的那个键每一下都会闪一下提示。按住超过连点时间窗时多一个延迟回调。
- 方框比键四边各大 4 dp（模拟器上的手机键约 51 dp 高，没碰到每格 18 dp 的下限），第一排的提示上沿会压到候选栏下缘约 4 dp；不会盖到相邻键的字。
- **已验证**：API 35 模拟器上按下即出现提示、提示落在被按的键上（な、ら）、左滑选中 に、あ 连点第二下按下时中间格显示 い 且松手打出 い；浮层改成 `INVISIBLE` 后重测，第一次按下提示仍落在被按的键上，あ 连点第二下按住超过一秒时中间格换回 あ、松手打出 あ；装包后 `smoke.sh` 全部通过。**未验证**：真机手感、API 28、浮动和单手键盘下的位置、两只拇指交替按时提示的归属（`adb shell input motionevent` 只能模拟单指）。
- 连点时中间格依赖宿主现有的连点状态（`toggleKey`、`toggleAt`），与 `tapJapaneseKey` 共用同一个时间窗判断（`withinToggleWindow`），二者不会分叉。
- [日语九键连点切换开关](2026-10-23-android-japanese-toggle-input.md) 增加可关闭连点的本机选项，默认仍开启；关闭时中间格显示键面假名，与重复轻点的实际输出一致，四向滑动提示保持可用。
