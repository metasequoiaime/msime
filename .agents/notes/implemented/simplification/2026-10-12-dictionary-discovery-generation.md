# Agent Note: 发现词库复用异步请求代次

Status: implemented

## Problem

HarmonyOS 词库页的“发现词库”列表使用局部 `let current = true` 和 effect cleanup 保护异步结果。详情分页和其他设置组件已经使用共享的 `useAsyncGeneration`，继续保留局部模式会让客户端更换时的请求隔离出现两套实现。

内置拼音词库详情仍有自己的数字 `useRef`，只在真正发起查询时递增。客户端更换或搜索进入防抖等待后，旧回包仍可能抢在新请求前更新列表；退出详情后，失败回包还能在词库列表上弹出提示。

词库列表外层也复制了挂载 ref、忙碌状态与刷新计数。挂载 cleanup 在 StrictMode 重放后不会恢复；客户端更换没有隔离修改回包；图库打开没有作废旧列表刷新和内置词条计数。

## Decision

`packages/ui/src/dictionary/dictionary-discovery.tsx` 提供独立的 `DiscoverDictionaries`，接收社区客户端、集合视图、忙碌状态、安装与浏览更多回调，不读取设置表单上下文；安装读取最新详情、修改归属与图库导航仍由页面持有。发现列表继续使用 `useAsyncGeneration(community)`，成功和失败回调只有在当前请求代次仍有效时才更新状态。列表上限、错误提示、添加动作和显示行为保持不变。

`packages/ui/src/dictionary/dictionary-details.tsx` 提供可独立挂载的 `CollectionDetail` 与 `BuiltinDictionaryDetail`，不读取设置表单上下文。命名词库的开关、添加与删除通过回调交还页面；内置详情组合独立的搜索分页状态，持有添加对话框和编辑接线。两个详情共用私有标题与已有编辑对话框，列表和详情共用 `dictionary-detail-parts.tsx` 的字标与加号。页面继续持有详情历史和导出文件操作；内置详情只接收可选 `onExport`，原有能力条件、返回提示和取消空串保持。

`dictionary/use-builtin-dictionary-entries.ts` 的 `useBuiltinDictionaryEntries` 持有内置拼音词条的查询、列表、加载状态、后续页与刷新，接收仅要求 `list` 的词库客户端及可选提示回调，不依赖详情 UI、设置表单或 toast 上下文。它使用 `useAsyncGeneration(dictionary, query)`，客户端、搜索词变化及卸载立即作废旧请求；每次加载仍递增代次，维持分页和添加词条后刷新的顺序。250 毫秒防抖、每页 100 条、拼音规范化与词语过滤均属于此领域 hook，不进入通用守卫。读取失败使用最新提示回调，更新回调本身不触发重新读取。

后续页偏移按宿主返回的原始条数推进，不能按词语过滤后的可见条数推进；没有匹配词条的一页也消耗宿主偏移。只有当前代次的成功页更新偏移，失败和过期页不推进；刷新从零替换列表，客户端或查询变化时归零。详情的“加载更多”只调用领域操作，不再根据展示列表推导宿主分页位置。

`dictionary/use-dictionary-collections-state.ts` 提供独立的 `useDictionaryCollectionsState`，接收集合客户端、可选计数能力、社区归属对象、图库可见状态与提示回调，不读取设置表单或 toast 上下文。它拥有集合视图、刷新错误、内置计数、修改忙碌与有效结果返回；页面只接具体动作与导航。`captureOwner()` 在文件准备开始时捕获修改代次，返回读取完成或失败后可调用的守卫，不把底层 runner 的 ref 暴露给页面。

外层修改在状态 hook 内使用 `useAsyncActionRunner`，owner 为 `collections`、`dictionary` 和 `communityResources`，共享忙碌、挂载与客户端代次守卫。图库打开不取消修改。列表刷新和内置计数使用独立的 `useAsyncGeneration(collections, dictionary, galleryOpen)`，图库打开立即作废旧刷新；每次刷新仍递增代次，公共 runner 接受修改后也递增刷新代次，保持修改结果优先于先前刷新。

社区安装从读取详情起就进入公共 runner，详情回包后检查 owner 再调用安装接口，避免准备阶段更换客户端后进入旧闭包；详情失败也走当前操作的错误通道。准备期间全页修改保持忙碌，防止另一项修改抢占它。成功提示仍使用最新详情中的名称。

领域包装继续返回有效的 `DictionaryCollectionsView`，让新建、添加和删除的调用方决定关闭对话框或打开详情；公共 runner 收尾后再次检查修改代次，过期结果返回 `undefined`。错误适配器忽略 runner 开始时清除错误的空字符串，以免生成空 toast；当前修改失败仍提示并重新加载列表。导入准备阶段捕获修改 owner 代次，读取完成或失败后检查它，防止客户端更换后调用旧客户端或弹出旧读取提示。

## Alternatives considered

- 只抽刷新函数：接入更短，但视图、计数、修改抢占和过期结果返回仍依赖页面里的 ref 与 setter，无法独立组合完整状态生命周期。
- 只把内置词条读取函数迁出、继续由详情持有搜索与偏移：函数参数更少，但请求代次、防抖、失败恢复和分页位置仍与 UI 混在一起；用领域 hook 一起持有这些状态。保留按可见条数翻页可减少一个偏移字段，却会在中文过滤后重复读取，整页没有匹配时还会反复读取同一页，因此显式跟踪宿主已读位置。
- 把中文词语筛选改为宿主查询：可减少读取量，但会同时改变既有详情的查询行为和平台调用参数；这次保留原有拼音前缀与已读词语过滤策略，修正偏移并让状态独立组合。
- 向页面返回底层 runner：可以逐行照搬原代码，但页面仍需知道挂载与代次 ref 的组合；返回调用时捕获的 `captureOwner()`，保留文件准备阶段既有时序而隐藏实现细节。

- 将发现列表与安装、图库导航合并成一个设置页 Hook：调用方接线更少，但会把可独立展示的列表绑定设置上下文；组件只拥有读取第一页、当前添加项和展示反馈，页面保留跨功能编排。

- 把详情连同设置上下文、历史和文件导出一起迁移：调用方接线更少，但组件仍绑定整页宿主能力；详情只收数据、词库客户端和动作回调，使列表编排与详情展示各有归属。

- 保留局部布尔值：能够处理卸载，但重复实现请求代次管理。
- 只使用挂载 ref：不能在社区客户端变化后阻止旧客户端结果覆盖新列表。
- 保留内置详情的本地计数并补 cleanup：可以分别修补防抖与卸载窗口，但会继续复制公共代次的 owner 生命周期；复用已有 hook 后只保留查询顺序的递增。
- 外层刷新和修改合用一个代次：字段更少，但图库打开应作废刷新且不能取消已经提交的修改，合用会让两种生命周期互相干扰。
- 把文件读取整个放进公共 runner：可以直接使用操作守卫，但会把准备文件阶段也计入修改忙碌，改变现有交互；保留读取流程并检查 owner 即可隔离过期准备结果。

## Consequences

集合状态可以脱离设置表单与提示容器组合，页面不再直接持有刷新、修改的 ref；代价是多一个状态 hook 和准备阶段守卫函数。社区对象只作为修改 owner，不参与刷新 owner；图库可见状态只作废刷新，不取消已经提交的修改。已发出的宿主操作仍不会取消。文件读取、保存和协议都保留在原调用方。

独立详情可以由其他共享界面直接组合，新增模块内部导出，不增加包入口符号。它仍依赖共享控件、toast 和请求代次 Hook，不接管平台文件能力。

内置词条状态可以独立于详情界面挂载，UI 不再持有读取与防抖生命周期。代价是领域 hook 维护一个不可由展示条数替代的宿主偏移；它仍保留按已读页过滤词语的策略，不把后端完整查询扩展混入这次抽取。

`dictionary-details.test.tsx` 在没有设置表单上下文的环境覆盖回调更新保留草稿、添加返回空值时继续编辑、忙碌与删除确认、可选导出及取消提示、分页与客户端变化后的旧响应隔离。迁移前相关五文件 61 项通过，迁移后加上独立详情共六文件 65 项通过；桌面生产构建、HarmonyOS 类型检查、lint、格式和笔记检查通过。六个组件声明及页面导出函数在排除模块导出、回调适配和格式差异后与基点一致；独立审查未发现阻断问题。

发现词库列表与同页详情加载共用请求代次机制，移除局部 cleanup 样板。现有词库页测试和新增源码契约测试覆盖该抽取。
