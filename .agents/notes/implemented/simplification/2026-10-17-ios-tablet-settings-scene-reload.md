# Agent Note: 平板设置页复用前台重新加载修饰符

Status: implemented

## Problem

iOS 平板设置页仍在组件内直接声明 `scenePhase`，并手写出现和回到前台时的处理；其他设置页已经通过 `reloadOnAppearAndActive` 统一这段生命周期。平板页首次出现还要先读取输入方案，再处理可能存在的深链页面，不能照搬会重复读取方案的旧迁移。

## Decision

`TabletSettingsView` 使用 `reloadOnAppearAndActive`，把读取 `InputSchemePreference.scheme` 和 `show(router.settingsPage)` 放在同一个重新加载闭包中。修饰符在首次出现时按该顺序执行；回到前台时再次读取方案，`show` 遇到已经清空的路由直接返回。组件删除自己的 `scenePhase` 环境值和两个生命周期钩子，深链变化监听保持不变。

契约脚本要求平板页使用共享修饰符，并禁止重新声明 `scenePhase` 或手写前台钩子；它同时核对首次出现时读取方案先于深链处理的源码顺序。

## Alternatives considered

- **继续保留平板页的内联钩子。** 行为改动最小，但设置页会继续维护第二份生命周期逻辑，后续修复容易只改到部分页面。
- **直接使用带 `onAppear` 前置动作的重载。** 可以复用修饰符，但修饰符会先执行前置动作再执行重新加载；为了保留“读取方案后处理深链”要么重复读取方案，要么引入额外状态。
- **扩展修饰符增加重新加载后的出现回调。** 能精确表达两个动作的顺序，但会扩大公共 API 和测试范围；将深链处理放进现有重新加载闭包已经能保持顺序且无需新增状态。

## Consequences

- 平板页与其他 iOS 设置页共用同一个 `scenePhase` 生命周期实现，组件不再复制环境值和钩子。
- 首次出现仍只读取一次方案，并在读取后处理启动深链；回到前台只刷新方案。
- 回到前台时闭包会检查一次已清空的深链路由，空值路径无副作用。
- 契约测试覆盖共享修饰符归属和源码顺序；未在本机启动 iPad 宿主，原生编译与 UI 验收交给 iOS CI。
