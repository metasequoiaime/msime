# Agent Note: 双拼自定义编辑器复用异步生命周期守卫

Status: implemented

## Problem

自定义双拼编辑器在键位校验和导入、导出、填入内置方案时分别手写请求代次、挂载状态和忙碌状态。校验结果需要丢弃旧草稿的回答，文件操作需要在组件卸载后停止更新；这些边界与共享 UI 的异步生命周期规则相同，继续维护局部 `useRef` 容易产生另一套守卫。

输入页替换宿主能力时编辑器可能仍挂载，只有挂载检查会把旧内置方案或导入结果写进当前草稿，并发布旧导出结果和错误。旧请求还会继续占用操作互斥，确认框迟到后也可能调用旧宿主或关闭当前编辑器。

## Decision

键位校验使用 `useAsyncGeneration(client, draft)`，按客户端和草稿变化隔离延迟校验及其异步回答。导入、导出和内置方案操作使用 `useAsyncActionRunner(setError, setNotice, client, saveExport)`，由共享 runner 提供 `busy`、挂载状态和宿主能力代次；操作在确认、文件读取及宿主请求之后检查 `isCurrent()`，只为当前客户端写回草稿、结果和具体错误。返回确认使用同一个操作代次检查，旧确认不能关闭新的客户端视图。共享挂载守卫在 StrictMode 的 effect 重放后重新生效，避免校验和操作结果永远无法更新界面。runner 同步阻止重复操作，并为原先未捕获的异常提供兜底提示。校验触发时机、文件格式和保存条件保持不变。

## Alternatives considered

- 保留编辑器自己的 `generation`、`mounted` 和 `busy`：可以保持当前行为，但会继续复制共享异步生命周期实现，后续修复容易只覆盖部分调用方。
- 只替换 `generation` 和 `mounted`，保留局部 `busy`/`run`：能减少部分重复，但异步操作仍会复制共享 runner 的启动、清理和防并发逻辑。
- 让操作 runner 也以 `draft` 为 owner：能统一所有代次，但修改草稿会让正在进行的文件操作失效，改变现有操作完成后的提示语义，因此不采用。
- 只在结果返回后比较客户端身份：检查局部且直观，但不能自动释放旧互斥，也无法识别客户端切走又切回；已有 runner 的递增代次同时守住操作结果和收尾。

## Consequences

编辑器与其他设置页共用异步请求和操作生命周期守卫，旧校验回答以及卸载后的操作收尾不会更新界面。文件操作随客户端或导出能力变化失效，不因编辑键位变化中断正在进行的导入或导出；校验仍单独按草稿代次隔离。已经发出的宿主请求仍可能完成，但不会更新当前视图；新客户端不再被旧操作阻塞。行为测试覆盖 StrictMode 下校验、填入方案和解除忙碌，以及旧草稿校验成功、失败迟到；StrictMode 用例在旧实现上因保存按钮始终禁用而失败，共享守卫版本通过。

## Verification

客户端替换相关的 11 项回归在修复前全部失败，分别复现旧模板和导入覆盖草稿、三类操作的迟到成功或错误、旧确认触发请求或返回、迟到文件读取继续校验、替换导出能力后仍提示旧结果，以及旧操作占用新互斥。修复后编辑器 25 项、配置恢复 3 项及共享 runner 5 项测试通过；另覆盖同一客户端导出期间编辑草稿仍能显示导出结果。桌面类型检查与生产构建、改动文件 lint 和格式、笔记与差异检查、本地 quick 门禁通过；quick 的 HarmonyOS 原生编译因缺少 staged 依赖跳过。本改动只调整共享 UI 的异步结果归属，不修改文件读取实现、导入格式或原生宿主，不作为原生设备验收。
