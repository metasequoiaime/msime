# Agent Note: 设置侧栏按功能分组折叠

Status: implemented

## Problem

桌面设置侧栏把多个功能连续平铺，输入、外观、工具、账号和支持入口混在一列里，页面数量增加后难以扫描。原来的分组投影已经存在，但桌面只消费页面数组，组标题和组边界没有呈现出来；统计页也与工具入口混在同组。

## 后续决定

[连续平铺侧栏](../../implemented/simplification/2026-10-19-settings-flat-sidebar.md)按用户要求取代共享侧栏的分类标题与折叠状态。内部页面归属、顺序、Windows 原生窗口和移动投影继续保留。

## Decision

桌面侧栏使用注册表中的六个功能组：打字、输入方式、外观、工具、数据和支持。统计与账号归入“数据”，AI 助手继续作为工具组中的独立页面，不与智能辅助合并。共享桌面侧栏和 Windows 原生设置窗口同步这套组顺序。每个有标题的共享桌面组显示可访问的折叠按钮和组内页面容器；首页这种无标题组继续直接显示。折叠状态只存在设置外壳本次挂载期间，当前页面所在组和搜索结果组始终自动展开。触屏侧栏继续平铺页面，移动分组标题仍由 `mobileGroupTitle` 转换。

`packages/ui/src/settings/settings-sidebar.tsx` 的 `SettingsSidebar` 独立绘制侧栏。它接收现有平台投影中的五个展示标志、页面分组、当前页面、搜索框、窗口拖动处理器、导航与展开回调，以及预览标志；不读取整个设置模型，也不保存折叠或搜索状态。`useSettingsShellNavigation` 继续持有展开、搜索和导航规则，`SettingsShell` 只负责组装输入；公共入口转导出组件与属性类型。

这次决定部分取代[桌面设置精简时保持连续平铺的决定](./2026-10-16-toolbar-keyboard-handwriting-settings-prune.md)：页面归属、顺序和路由仍由同一个 `settingsNavGroups` 提供，改变的是桌面侧栏的呈现方式。

## Alternatives considered

- **继续平铺页面，只缩短标题**：改动最小，但不能解决入口密集和功能边界不清的问题。
- **删除或合并 AI 助手与智能辅助**：可以减少一个入口，但 MCP 是独立能力页，用户需要分别管理辅助偏好和 MCP 连接，因此不采用。
- **让移动端也使用折叠组**：能统一代码路径，但触屏设置列表依赖当前平铺和底部标签页的扫描方式，桌面问题不应改变触屏交互。

- **继续在外壳内联侧栏**：输入与渲染同处一段代码，改动最少。但品牌、搜索和分组已有完整 UI 边界，独立组件能复用这些展示与可访问性接线，同时保留现有 hook 的状态所有权。
- **侧栏自己调用导航与平台 hook**：调用处可以更短。但侧栏会重复拥有搜索或折叠状态，并可能与标题栏共用的搜索框和主内容的路由分离，因此继续通过属性接收现有结果。

## Consequences

桌面侧栏首屏仍保留所有组标题和页面，用户可以按组收起无关页面；导航搜索不会因为折叠状态隐藏命中项，当前路由也不会落在收起的组里。分组名称改变会同时影响桌面和触屏投影测试，新增页面必须在注册表中选择一个明确的功能组。折叠状态不持久化，重新打开设置后恢复展开，避免引入新的偏好字段和跨宿主同步契约。

验证覆盖注册表与桌面、触屏投影、Windows 原生组映射，侧栏折叠及搜索和当前页自动展开行为；设置导航相关测试、异步状态测试、TypeScript 类型检查和共享 UI 构建通过。

共享侧栏由[独立设置页组件](2026-10-19-settings-page-component-module.md)调用 `SettingsSidebar`，导航 hook 与平台展示规则保留各自边界。品牌、窗口拖动区域、搜索位置、iPad 隐藏标志和空结果提示随同一段侧栏渲染复用；抽取前后 JSX 及行为回归用于验证输入接线。

组件抽取验证：侧栏 JSX 完整一致，仅预览条件由外壳计算后传入；10 个属性接线和外壳其余函数一致，组件及 19 个传递模块没有到入口的运行时依赖。相关侧栏、窗口、移动外观和导航回归共 6 文件、87 项通过；桌面构建（含类型检查）、lint、格式与笔记检查通过，lint 只有既有 4 条未使用声明警告。quick 门禁通过，覆盖 Rust 工作区、Android 目标、Linux 桌面外壳、共享 Apple 桥和 HarmonyOS 设置包检查；缺少完整工程的 HarmonyOS ArkTS 编译按脚本跳过。独立审查没有阻塞项。
