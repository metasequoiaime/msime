# Agent Note: 模型选择器状态与纯模型复用

Status: implemented

## Problem

`ModelPickerRows` 同时服务 AI、语音识别和文本润色设置，但已知模型去重、列表身份、自定义输入展开和选择编辑动作都嵌在 JSX 组件中。其他调用方要复用模型选择规则，必须依赖整块 UI；列表更新后清除手动展开意图的边界也没有独立契约。

## Decision

用 `modelPickerModel` 纯函数承接已知模型去重、列表键和当前值是否需要自定义输入的判断，用 `useModelPickerRows` 承接受控选择、编辑转发以及列表变化时重置展开意图。`ModelPickerRows` 只负责绑定 `SelectRow`、`TextInputRow` 和文案；AI、语音识别、文本润色继续共用同一个公共控件。

输入语义保持不变：空字符串是「自定义…」选项值，不写回；选择已知模型才调用 `onChange`；自定义输入即使变成已知名称也保持展开；模型列表身份改变后按当前值重新判断。空列表仍只显示文本框。

## Existing notes audit

- 已检索设置页的模型选择、服务商预置模型和自定义接口状态，没有发现持有同一模型选择规则的 proposed 或 implemented 笔记。
- [豆包自定义接口状态](2026-10-17-voice-credential-editor.md)记录的是凭据接口地址的身份状态，和模型列表状态不同；本片不改变其 hook。
- [AI 皮肤抽卡状态](2026-10-17-ai-skin-generation-state.md)及社区模型笔记不涉及设置模型选择器，本片不吸收其异步生命周期决定。

## Alternatives considered

- **继续把规则留在 `ModelPickerRows`**：改动最小，但无界面调用方无法复用去重和自定义判定，三个领域只能继续依赖 JSX。
- **只抽纯函数、不抽 hook**：可以复用列表判断，但选择动作和列表身份状态仍留在组件里，调用方还要复制「输入已变成预设也保持展开」规则；因此同时抽出受控 hook。
- **把模型选择器改成通用下拉组件**：会把文本框、平台 `SelectRow` 的 Fragment 约束和领域文案混在更大组件里；当前只抽领域状态，保留现有 UI 边界。

## Verification

新增纯模型与 hook 测试先在旧实现失败；实现后模型 hook、现有模型选择器和凭据回归共 13 项通过，desktop 类型检查和变更文件格式检查通过。构建、lint、笔记门禁和 PR CI 随本片验收。

## Consequences

- AI、语音识别和文本润色共享同一份模型选择状态规则，后续无界面调用方可以直接使用纯模型或 hook。
- 公共 API 增加两个导出，调用方仍负责受控 `model` 值和持久化；hook 不读取服务、不发请求。
- 模型列表身份由去重后的顺序拼接值决定；列表内容或顺序变化会清掉手动展开意图，现有用户看到的当前值仍按列表成员关系决定是否显示输入框。
