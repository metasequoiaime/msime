# Agent Note: 全局语音按当前输入客户端交付

Status: implemented

## Problem

全局按住键与采集已经在用户环境中出现波形和识别结果，但 Codex 同一输入框持续聚焦时仍进入「无法确认原输入位置」的 Copy 恢复。用户明确要求保留全局语音，移除目的地验证与 Copy 流程，采用普通输入法的当前客户端行为。

## Decision

不跨录音追踪原应用或 AX 输入框，不根据原焦点身份决定是否插入。录音与识别继续独立运行；松手及最终结果后取得当前活动的 IMK 客户端，按现有提交方式交付。输入源恢复以交付前用户实际选中的源为基线；交付过程中新的手动切源仍优先。

移除 Copy 窗口、恢复文本槽与它对后续录音的拦截。没有 IMK 客户端时仍有界等待，最终失败使用既有错误浮层并释放本轮；不增加历史、最近结果或剪贴板后备。保留权限、后台批准、手势及录音代次、socket 租约、取消、显式模拟输入策略和统计。当前客户端调用仍核对会话令牌及控制器是否仍活动，不追认原字段许可。

## 旧笔记审计

[录音与交付许可分开](../../implemented/architecture/2026-11-03-global-voice-optional-destination.md)和[先录音后 IMK 交付](../../implemented/architecture/2026-11-03-global-voice-capture-before-imk-delivery.md)部分重叠：保留不等 IMK 开始录音与提供商生命周期，翻转原应用／AX 绑定和显式复制的决定。[全局语音快捷键](../../implemented/feature/2026-11-02-macos-global-voice.md)的键位、系统许可与来源恢复继续适用。其他普通输入法组字或会话恢复笔记不属于本次删除范围。

## Alternatives considered

- 继续修复 AX 字段识别与 Copy 流程：能避免迟到结果进入后来选择的字段，并保留失败结果。但它为普通输入法增加跨录音的输入框身份与恢复状态，已在真实稳定焦点环境中误拒；用户明确选择撤除此流程。
- 只隐藏 Copy 窗口：改动最少，但目的地拒绝与待处理结果拦截仍存在，会让无波形和不上屏继续发生，不能完成用户要求。

## 验证契约

没有 AX 输入框身份、录音中换字段或选择另一应用，仍按交付时的当前 IMK 客户端处理。既有组字按普通提交完成；陈旧会话令牌不提交。结果失败后下一轮可开始，无恢复面板或待复制结果槽。输入源恢复尊重交付前与交付中的用户选择。聚焦测试、独立审查及完整本地更新分别记录，不运行全平台本地门禁。

## 验证记录

移除前，缺少原 AX 身份但当前编辑器存在的回归在 `probe.posted` 断言失败；移除后通过。复用既有 universal 原生缓存构建宿主、HTTP／流式／系统识别控制器，18 项聚焦套件全部通过，包含当前客户端交接、迟到令牌拒绝、当前组字与真实 `NSTextView` 的追加顺序、交付前后手动切源、交付失败后的下一轮、全局与局部入口、socket 租约及 PCM 路径。测试前后真实偏好文件哈希相同；测试使用合成文本，不打开实际麦克风。

独立审查后的两项回归先在原实现中失败：最终同步客户端查询重入后开始的新组字会被语音替换，临时切源后的睡眠／会话失活／锁屏取消不会恢复来源。现在同步查询后若出现新组字则重试，下一轮按普通组字路径结束再追加；系统挂起只取消会话，不伪造手动切源。真实 `NSTextView` 的重入回归及三种挂起通知与手动切源的组合均通过。

## Consequences

当前焦点与输入法客户端由系统拥有；用户在说话或交付时改变焦点会改变文字的接收位置，与普通键盘一样由用户控制。没有可用客户端且等待失败的结果不再保留供复制。真实编辑器与实体麦克风需单独复验。
