# Agent Note: 设置功能页组合独立复用

Status: implemented

## Problem

设置外壳已把偏好表单、账号与社区区域拆成独立组件，但仍同时维护窗口布局和首页、试用键盘、聊天、社区、统计、词汇复习的挂载与动作接线。定制共享设置宿主仍需复用整个窗口外壳，页面内容与窗口控件的边界不清楚。

## Decision

公开 `SettingsFeaturePages` 与属性类型，集中组合这组不属于偏好表单的功能页。组件消费现有模型字段投影和外壳的聊天挂载、焦点状态，以及既有导航、本地词库与皮肤统计回调；不创建第二份模型或外壳状态。原分支顺序、条件、图库 key、动作与 DOM 保持，皮肤和插件区域、偏好表单、状态提示、窗口与导航布局仍由外壳组合。

## Historical audit

- [设置页组件](../../implemented/simplification/2026-10-19-settings-page-component-module.md)部分重叠，继续持有窗口和内容布局，本篇持有非表单功能页的组合。
- [账号接线](../../implemented/simplification/2026-10-19-settings-account-page.md)和[社区根页接线](../../implemented/simplification/2026-10-19-settings-community-page.md)部分重叠，继续持有各自页面接线，原挂载条件移到本组件。
- [外壳临时状态](../../implemented/simplification/2026-10-17-settings-shell-state-hook.md)部分重叠，聊天首次进入后的挂载标记与焦点请求继续归外壳，组件只消费。
- [移动子视图](../../implemented/simplification/2026-10-17-mobile-settings-subview.md)持有图库历史，模型、社区视图、皮肤和插件区域、平台展示与侧栏笔记各自持有其他边界，不改变规则。
- 按组件名、功能页组合、聊天挂载和图库子视图检索活跃笔记，没有同名实现、完全吸收的决定或失效提案。

## Alternatives considered

- 把聊天挂载状态与社区导航一起迁入组件：调用属性更少，但状态会跟随功能区域卸载，且表单仍消费同一模型和社区导航，因此保留已有唯一 owner。
- 给每个页面再加一层设置包装：每个接口较小，但账号和社区已有包装，额外包装仍让外壳逐项维护完整的功能分支；集中一个功能页组合边界可让外壳继续只负责排列区域。

## Consequences

共享宿主可以独立组合非表单功能页，窗口外壳只排列功能区域。代价是新增公开属性契约，模型投影继承账号和社区组件所需字段，聊天状态由调用方传入；此组件本身不创建模型或 hook。

功能页组合增加一层 React 组件，必须保持模块顶层定义与稳定位置；不能按当前页给整个组件设 key，否则触屏聊天会丢状态。皮肤和插件区域仍与表单共享原视图对象，状态提示、恢复、窗口与导航布局仍归外壳。若功能页将来独立持有导航，需要重新审视模型和聊天的生命周期，不能从本次搬迁推导出迁移状态的授权。

不改变宿主接口、文件读写、权限和原生资源；前端自动化验证不代表原生宿主装机验收。
