# Agent Note: 翻译凭据偏好使用公共模型

Status: implemented

## Problem

翻译设置绑定、自定义翻译设置和凭据测试配置分别从 `Preferences` 声明腾讯云、小牛和自定义翻译偏好；凭据测试还各自维护一份最小字段投影。相同的偏好字段归属分散后，服务设置与凭据测试的输入契约可能漂移。

## Decision

在无 React 依赖的 `translation-credential-preferences.ts` 定义三种完整翻译服务偏好模型，并从这些模型派生三种凭据测试所需的最小投影。设置绑定、设置组件和凭据测试配置直接引用公共模型，保留所有函数输入、输出和运行逻辑不变。

## Existing notes audit

检索活跃笔记中的翻译凭据、翻译服务和偏好模型，没有发现拥有这组 TypeScript 输入契约的记录；Windows 原生翻译设置笔记描述跨语言服务行为与协议，不涉及本次共享 UI 类型归属。

## Alternatives considered

- 保留各文件里的 `NonNullable` 和 `Pick`：改动最少，但完整偏好与凭据测试投影继续分散维护。
- 只抽取凭据测试的三个 `Pick`：能减少配置文件内的重复声明，但设置绑定和自定义设置仍各自声明完整模型，后续字段变化仍需多处同步。
- 让凭据配置函数直接接收完整偏好：调用更宽松，但会把 `enabled` 等与凭据测试无关的字段带入契约，不能表达最小输入边界。

## Consequences

- 翻译服务设置与凭据测试共用无 React 的完整偏好模型及最小投影；旧函数路径和服务请求字段保持不变。
- 新公共模型只依赖 `Preferences`，不引入运行时模块或平台耦合；凭据测试仍只接受实际需要的字段。
- 类型兼容测试覆盖三种完整模型和三种凭据投影；翻译设置测试、类型检查、构建、lint、笔记检查和 quick 门禁验证迁移。
