# Agent Note: macOS 零窗口内边距不再受边框宽度限制

Status: implemented

## Problem

共享配置允许窗口内边距为零，但原生 `CandidateInset`、`CandidateVerticalInset` 和共享预览都取内边距与边框宽度的最大值。默认边框为 1pt，导致用户设置 0 与 1 的布局相同，无法继续收紧窗口。

候选项布局贴边后，静态选中、悬停和动画高亮还固定向内缩 1pt，露出窗口底色。仅检查候选项矩形与窗口高度不能证明底色已经贴边。

## Decision

窗口内边距仅以零为下限，不再以边框宽度兜底。两轴覆盖与旧统一内边距遵守相同规则；负值仍钳制到零，长度仍随整体大小缩放。共享预览同步取消边框下限，边框本身继续绘制，不修改其宽度。

候选项背景直接使用整个候选项矩形；四角路径、统一圆角和动画高亮遵守相同边界，不再叠加固定 1pt 内缩。窗口内边距小于半个边框宽度时，即使候选项圆角跟随皮肤，也启用既有卡片内轮廓遮罩，避免铺满的底色覆盖描边。图片皮肤画布的内容区约束和字体自身留白不属于这次移除的隐式内缩，仍然保留。

本篇部分取代[旧内边距保护](../bug-fix/2026-10-15-macos-candidate-padding-below-2pt.md)的边框下限，默认 4pt 和既有圆角推导不变。[独立几何配置](../feature/2026-10-21-candidate-item-geometry.md)的字段、范围和恢复语义不变。

## Alternatives considered

- 保留边框下限可以让候选区域远离描边，但会继续让合法的 0 与 1 产生相同布局，不符合用户明确要求，因此移除。
- 保留候选项背景的 1pt 内缩可以维持旧高亮大小，但会让用户设置的窗口留白与可见留白继续相差 1pt，因此由统一的卡片裁剪保护边框，而不是靠背景额外内缩。

## Consequences

0 与 1 在实际候选行位置、窗口高度和预览中分别生效。代价是零内边距不再额外保留描边保护带；显式候选项圆角仍由已有卡片内容遮罩裁剪，未显式设置时继续沿用圆角保护。

高亮底色的直边与候选项布局一致；相同配置下，底色比旧实现向四边各扩展 1pt，但不改变文字、命中区域、项间距或窗口尺寸。圆角和抗锯齿仍可能在角部露出底色，不承诺把窗口描边、图片皮肤内容区或文字字形留白一起移除。

## Testing

原生回归覆盖两轴零值、负值、旧统一字段，以及 50/100/150/200% 缩放下横竖排从 0 改到 1 的候选位置和窗口高度差。原生预览与快捷键路径的布局断言同步改为实际零内边距，前端检查两轴 CSS 不再以边框宽度为下限。

`candidate-skin`、`candidate-row-layout`、`skin-preview`、`shortcut` 四项 CTest 和 51 项定向前端测试通过，类型检查与生产构建通过。本机已更新输入法及配置应用，签名、输入源和进程启动检查通过；未修改用户的内边距配置。

背景绘制回归在 1×、2× 位图中覆盖静态选中、悬停以及统一和独立四角，逐条检查四边最外侧像素不再透明；旧实现先在该断言上失败。动画另断言高亮图层或路径与候选项边界一致，并覆盖跟随圆角时的零内边距描边保护。
