# Agent Note: 设置页主题预览状态

Status: implemented

## Problem

`packages/ui/src/index.tsx` 同时计算设置窗口、候选窗口、悬浮工具栏和屏幕键盘的预览明暗，还维护皮肤卡片的临时明暗覆盖、宿主可绘制的自定义主题副本以及自定义键盘选中态。页面模型需要知道主题注册表和预览钩子的全部细节，主题预览规则与页面模型状态边界混在一起。

## Decision

`packages/ui/src/settings/use-settings-theme-previews.ts` 统一返回设置页所需的主题取值、三种表面预览、宿主可绘制的自定义主题、皮肤卡片明暗覆盖及自定义键盘选中态。候选预览明暗变化时仍清空临时覆盖；宿主不支持的自定义颜色只在预览副本中移除，草稿保持原样。`index.tsx` 只传入草稿、宿主能力和颜色能力位，并消费 hook 返回值。

## Alternatives considered

- **继续在设置页模型中保留这些派生值**：代码改动最少，但预览规则仍与页面模型耦合，其他设置外壳若需要同一组主题数据还要重复理解明暗和宿主能力边界。
- **只抽出三个 `useCandidatePreviewTheme` 调用**：可以减少几行代码，但皮肤覆盖、自定义主题副本和选中态仍留在入口，预览状态依然分散；本切片把同一预览契约一次收拢。

## Consequences

设置页模型减少主题预览实现细节，主题预览状态可由其他共享设置页面复用；公共 hook 额外暴露一个包含候选、工具栏和屏幕键盘字段的输入类型，以保持 `Preferences` 的完整主题字段可传入。预览计算仍依赖现有主题偏好和候选预览 hook，未改变草稿持久化或宿主主题行为。
