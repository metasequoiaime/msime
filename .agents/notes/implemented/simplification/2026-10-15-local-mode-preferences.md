# Agent Note: 快捷模式偏好与控件状态共用纯模块

Status: implemented

## Problem

快捷模式类型与默认值在 React 组件中，偏好模型、总偏好、插件页和工具页回调都反向依赖组件。总开关与单项开关的交互、拆字缺省值和地名从属条件也留在组件的表达式中，离开组件不能直接使用这份状态规则。

## Decision

由无 React 依赖的 `settings/local-mode-preferences.ts` 持有原类型、同一个默认对象及单项控件的勾选和禁用状态计算；同目录 `local-mode-options.ts` 持有模式行、iOS 文案、翻译提示及按宿主能力筛选可见行的纯数据与函数。原组件保持类型与默认值重导出，模型、总偏好、插件页、回调及需要模式清单的消费者直接依赖叶子模块。公开入口只暴露筛选并解析好文案的 `localModeRowsFor` 和行类型；内部数据表保持私有，更新回调继续由组件持有。

总开关关闭只让 Shift+字母模式置灰，保留勾选；`command`、`mention` 和 `mention_places` 不受它约束，但地名仍只在名字模式开启时可改。只有显示总开关的宿主读取其禁用效果，其他宿主忽略文档里的 `shift_letter_entry: false`。拆字缺键时按是否显示总开关决定桌面关、触屏开，显式布尔值总是优先。默认对象仍不包含这些后加的可选字段。

## Historical audit

按 `LocalModesSection`、`LocalModePreferences`、`shift_letter_entry` 和拆字缺省值检索活跃笔记。[Shift+字母总开关](../../implemented/feature/2026-10-11-shift-letter-entry-switch.md)持有总开关、保留单项值和宿主能力的行为决定；[内置拆字](../../implemented/feature/2026-10-13-builtin-chaizi-mode.md)持有触屏与桌面不同的缺省值。两篇均部分相关并保持行为归属，本片只统一共享 UI 类型、默认值及状态规则，不取代引擎和原生宿主决定。

## Alternatives considered

- **只抽类型与默认值。** 能最小化消除模型到组件的依赖，但宿主缺省和开关从属关系仍只存在于 JSX，无法由纯模块独立复用和验证。
- **按总开关统一清除单项状态。** 可以直接把关掉的模式显示为未选中，但会丢失已保存的单项选择，违背重新开启总开关即可恢复的既有行为。

## Consequences

模型、总偏好、插件页和工具页回调不再从 React 组件获取快捷模式契约；模式清单、iOS 文案和宿主筛选也不再绑定 React。组件复用共同状态与选项规则，只持有开关渲染和更新回调；代价是增加一个选项叶子模块。旧类型、默认对象和导出路径保持，字段可选性及存储格式不变。状态计算不写回偏好，不按 `ios` 推断宿主形态，也不改变引擎和原生宿主。

新增九项纯状态回归在空实现上八项按预期失败，显式关闭拆字的控制用例通过；本片另以纯选项回归覆盖九项模式顺序、V/`/`/@ 触发模式、临时日语和 @ 地名的宿主筛选，以及 iOS 文案与翻译提示。正式实现后连同既有控件、插件、工具回调和默认偏好相关测试通过；推进本片的全量设置回归暴露云词库页签测试的等待缺口：只等请求发出就点击下一页签，刷新仍处于忙碌状态时点击被串行保护挡住。独立运行通过，源码确认请求与忙碌状态释放存在异步间隔；用例改为等目标页签恢复可用后再点击。此次连同全量设置、插件、快捷模式控件和纯规则回归共五文件 445 项通过；独立审查复跑新增三项和云词库页签一项通过，逐字核对 49 个迁移文案字面量及其顺序。抽取前后三项真实设置页集成通过，覆盖 macOS 全量模式开关、iOS 触屏入口文案及桌面组合键文案。字段门禁保持 34 组共享类型。

桌面构建、Harmony 类型检查及旧导出与回调类型探针通过；探针核对原对象别名的 `Record<string, unknown>` 兼容性、最小偏好、可选字段和单项模式键范围。格式、lint、笔记与字段门禁通过。
