# Agent Note: 十六进制颜色编辑行独立复用

Status: implemented

## Problem

`CandidateSkinEditor` 内嵌了原生 RGB 取色器与十六进制输入框的组合。它维护可暂时无效的文本草稿、规范化后的受控颜色和独立的透明度显示；其他共享界面要使用同一交互时只能复制编辑器内的实现。

## Decision

公开 `HexColorRow` 与 `HexColorRowProps`，把现有实现迁入设置控件目录。调用方继续传入规范化的 `#RRGGBB` 或 `#RRGGBBAA` 与 `onChange`；控件只持有文本草稿，规范化复用 `normalizedColor`。原生取色器只替换 RGB 并保留当前受控值的透明度，文本输入只接受 `#` 开头的有效颜色，支持原有短写；无效输入不通知调用方，失焦恢复当前受控值，外部值变化同步草稿。

候选皮肤编辑器迁移全部配色行，保留明暗模式的实例 key、可访问名称、样式、输入长度和透明度百分比。公开接口不加入当前没有使用的重置、可选颜色或数值格式策略。

## Existing notes audit

已按 `candidate-skin-editor`、`ColorRow`、`skinEditorColor` 与十六进制颜色格式检索 proposed、implemented、rejected，没有相同公共控件决定。

- [候选窗皮肤编辑器](../../implemented/feature/2026-10-19-candidate-skin-editor.md)部分重叠，继续持有草稿、预览和保存；更新颜色行的归属并互链。
- [触屏编辑器平台控件](../../implemented/feature/2026-10-12-skin-editor-platform-controls.md)是相邻能力但契约无关，持有整数 RGB 与只读色值行；该行不接受文本草稿，不迁入本控件。
- Windows schema 与 Android 包配色笔记仅规定皮肤格式、规范化和原生绘制，属于无关宿主行为，不改动。

## Alternatives considered

- 统一所有颜色行并通过参数选择数值格式、透明度和跟随主题：可以让所有颜色入口只引用一个组件，但三种行的受控类型、有效值与重置语义不同，会把领域规则变成组合开关。保留各自契约，只抽现有十六进制编辑能力。
- 只抽文本草稿 hook：能复用输入状态，但每个调用方仍要重新接取色器、透明度和可访问名称。现有组合完整且无宿主依赖，直接作为公共行复用。

桌面生产构建（含类型检查）、鸿蒙类型检查、全仓 lint、变更代码格式与 diff 检查通过；lint 仅保留两条未改动文件的既有警告，构建保留既有大包提示。独立只读审查未发现阻断或重要问题，另行复跑两个文件共 22 项通过。

## Consequences

其他共享页面可直接组合相同的颜色编辑交互，无需依赖候选皮肤编辑器。代价是公共接口要求调用方按现有规则提供规范化颜色，并在通知后回传新值；控件不另持有已接受颜色。

同步草稿的 effect 和明暗模式 key 保持原实现与调用 key。不改文件、持久化、皮肤协议或原生宿主；jsdom 交互验证不代表原生取色面板或真实输入法装机验收。
