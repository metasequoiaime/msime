# Agent Note: 首页规则与宿主契约独立于布局

Status: implemented

## Problem

设置客户端为取得 `HomePageActions` 反向引用首页组件；根设置行把类型、分组和值投影与 JSX 放在一起。触屏搜索状态和键盘打开回退也由页面布局持有，无法在不引入布局的情况下复用。

## Decision

首页宿主契约和可选键盘动作回退由 `home-model.ts` 持有，根页面类型、分组与值投影由 `root-settings-model.ts` 持有；`use-home-search.ts` 持有查询、过滤和组合输入保护。原页面与列表保留兼容导出，内部消费者直接引用模型。页面决定聊天优先和各自的回退页面，桌面方法调用保留接收者，触屏继续使用分离的回调。所有 JSX、样式和文案不变。

## Historical audit

按 `HomePageActions`、`home-page`、首页搜索与试用键盘检索活跃笔记，没有记录持有本次模块归属。

- [搜索组合键保护](../../implemented/bug-fix/2026-10-14-settings-search-ime-keys.md)持有事件契约，本片原地同步其入口位置。
- [触屏试用键盘](../../implemented/feature/2026-10-08-touch-try-keyboard-page.md)与[移动对话二级页](../../implemented/feature/2026-10-16-mobile-chat-secondary-page.md)持有路由和设备验证，本片保留其行为。
- 移动快捷方式裁剪、主题跟随、账号与聊天会话笔记各自保留，均不持有首页规则模块。

## Alternatives considered

- **只迁首页操作类型。** 风险最低，可以解除客户端反向依赖；但分组、搜索和重复的键盘失败处理仍困在布局里，因此同时迁出完整的规则边界。
- **统一桌面和触屏回退页面。** 调用代码更短；但桌面无聊天时打开屏幕键盘，触屏则进入试用子页，统一会改变功能，因此路由选择留在布局调用点。

## Consequences

契约和纯规则可直接复用，搜索依照 [React 自定义 Hook 的模式](https://react.dev/learn/reusing-logic-with-custom-hooks)独立持有每次调用的查询；根行组件只负责渲染。旧导出多一层转发。过滤仍在每次渲染时计算，不引入缓存，宿主页面与偏好更新时立即投影。页面布局差异仍由调用点选择；将来改变试用入口时需同时审查桌面与触屏回退。

## Verification

迁移前现有首页、组合键和键盘引导三个文件 55 项通过；新增桌面缺失、成功、失败与聊天能力组合的六项用例，在原实现上通过，并明确检查方法接收者。独立搜索测试先因模块不存在而失败，覆盖宿主页面与偏好更新、查询保留、空白查询及调用隔离。迁出的分组和值投影、类型与搜索代码逐段比对，页面 JSX 原文保留。验证限共享组件和编译层，不计作原生设备验收。

独立审查指出失败回退须保留零参调用；精确回调参数断言先因收到合成错误而失败，改为 `catch(() => fallback())` 后复验。

修复后五个文件、97 项测试通过；桌面生产构建、HarmonyOS 类型检查、lint、格式、笔记和差异检查通过。本地 quick 通过，源码门禁仍识别 42 个可选回调与 35 组共享偏好类型。quick 的 Rust 工作区、Android 目标与 Apple 桥接编译通过；Linux 容器、Windows 交叉编译与 HarmonyOS 原生打包因工具链条件跳过，其他原生阶段按改动范围跳过。
