# Agent Note: 社区资源发布建议字段共用一套生成规则

Status: implemented

## Problem

候选皮肤与插件的社区打包器各自截取本地名称和简介，再按相同的社区字段规则生成发布表单默认值。两段实现逐字重复；以后调整字符上限或无效名称的回退规则时，容易只改其中一处。

## Decision

`crates/client-core/src/community.rs` 提供 `suggested_publication_fields`，接收本地名称、可选简介和回退 ID。候选皮肤与插件打包器共用它，继续先按字符数截取、再去除首尾空白、再校验；名称无效时取回退 ID 的前 32 个字符，简介无效时使用空字符串。打包产物字段及校验边界保持原样。

## Alternatives considered

- 在两个打包器里分别保留原实现，改动最小，也使每个模块独立可读；但这段规则属于同一份社区发布契约，继续复制会使后续维护产生偏差。
- 把生成规则放进某一个资源模块供另一模块调用，可以少改一个文件；但插件与皮肤没有主从关系，社区模块已经持有两者共用的字段校验规则。

## Consequences

默认字段规则只在一处维护，两个打包器仍控制各自的资源读取和产物。新增一次跨模块调用；建议字段保持原有返回类型与行为。现有候选皮肤和插件打包测试分别核对建议名称，插件测试同时核对简介；相关 Rust 测试和 Clippy 验证改动。
