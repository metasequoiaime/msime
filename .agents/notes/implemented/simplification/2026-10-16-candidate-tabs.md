# Agent Note: 候选窗口标签模型

Status: implemented

## Problem

候选窗口设置页把四个标签及其字符串标识直接写在页面模块中。需要复用候选设置导航的宿主必须依赖页面实现，标签顺序也没有独立的契约测试。

## Decision

`candidate-tabs.ts` 公开 `candidateTabs` 和从数组推导的 `CandidateTab` 类型，包入口公开模型供其他宿主复用。标签顺序、标识和中文标题保持不变。共享的候选窗口页已经不再分标签（见 [macOS 主题页与候选窗口页精简](2026-10-16-macos-appearance-settings-prune.md)），页面不再引用这个数组，模型和包入口的导出仍保留。

## Alternatives considered

- **继续把标签留在页面中**：改动最少，但导航契约无法脱离 React 页面复用和验证。
- **只公开标签类型而保留页面数组**：能复用类型，却仍会让各宿主重新复制顺序和标题，容易产生漂移。

## Consequences

候选窗口标签导航可以独立导入和测试，页面状态和初始标签保持不变。修改标签顺序或文案时需要同步更新模型测试；此片不改变路由、页面内容或选中状态逻辑。

验证包括模型测试、桌面类型检查、格式检查、构建、lint、笔记门禁和仓库 quick 门禁。
