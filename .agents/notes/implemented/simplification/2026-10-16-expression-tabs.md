# Agent Note: 表达页标签模型

Status: implemented

## Problem

表达页把标点、候选与释义、候选翻译和翻译服务四个标签直接写在页面模块中。其他宿主若要复用表达设置导航，必须依赖页面实现，标签顺序和标题也没有独立的契约测试。

## Decision

`expression-tabs.ts` 公开 `expressionTabs` 和从数组推导的 `ExpressionTab` 类型。表达页继续使用同一数组，并通过 `@msime/ui` 公开模型。翻译服务仍由页面按能力过滤，模型只负责固定标签顺序和标题。

## Alternatives considered

- **继续保留页面内数组**：改动最少，但表达页导航契约不能脱离 React 页面复用和验证。
- **把能力过滤也塞进模型**：会让纯标签数据依赖翻译服务运行时状态，混合固定导航和页面能力判断，扩大模型边界。

## Consequences

标签内容后来由[「标点与翻译」页精简](../../implemented/simplification/2026-10-16-expression-page-prune.md)改成标点、候选释义、翻译服务三个，模型模块的做法不变。表达页标签可以独立导入和测试，页面的能力过滤、移动端展示和选中状态保持不变。修改标签顺序或标题时需要同步模型测试；此片不改变翻译服务逻辑或路由。

验证包括模型测试、表达页标签回归、桌面类型检查、构建、格式检查、笔记门禁和仓库 quick 门禁。
