# Agent Note: 抽取屏幕键盘面板状态与动作

Status: implemented

## Problem

`KeyboardPanel` 同时维护布局持久化、修饰键、按键发送队列、长按连发、语音入口和窗口生命周期。它们与皮肤、间距和按钮 JSX 耦合，无法单独复用或验证客户端切换时的队列归属。

## Decision

公共 `useKeyboardPanel` 集中管理屏幕键盘状态和动作，返回布局、键行、修饰键、通知、语音状态和事件回调。`KeyboardPanel` 保留网格、皮肤、间距与布局宽度，单键绘制和点击来源判断由[公共按键按钮](2026-10-19-keyboard-key-button.md)承载。保持 effect 依赖、同步修饰键引用、直接更新键面、队列上限、发送顺序以及 Windows 松开时发送的语义。

键面与发送提示的标签计算复用[公共按键标签方法](2026-10-19-keyboard-key-label.md)，键面与发送的 Shift 判定仍由各自调用方保持。

历史检索：手写与表情状态笔记属于同类模式但管理独立面板；键盘几何、工具栏与设置裁剪笔记只约束显示和偏好，不管理发送生命周期，均保留。没有已有笔记承载本次状态边界决定。

## Alternatives considered

- **只拆按钮或键行组件**：能缩短 JSX，但输入队列和客户端生命周期仍与整个面板绑定，无法单独复用状态，因此不采用。
- **拆成布局、发送、连发多个 hook**：各部分可以独立命名，但长按失败、关闭和客户端切换共享同一队列与定时器边界；本片整体迁移，避免引入跨 hook 协调。

## Verification

新增 hook 测试覆盖存储与 host 布局、串行发送、失败取消、客户端替换和语音互斥；既有视图测试覆盖长按、Windows 松开发送、macOS 键面、布局、拖动和桌面集成。原失焦订阅契约测试跟随实现路径迁移。

## Consequences

状态与动作可通过公共入口复用，面板和按键按钮保留布局样式与点击来源判断。发送队列、修饰键和定时器共享一个生命周期边界，抽取期间保持原函数内容、effect 依赖和回调调用位置，避免改变闭包或异步完成归属。hook 仍通过既有 DOM 选择器同步键面，与现有键盘网格结构保持约定。本片只验证共享前端，不替换原生宿主按键注入，也不声称完成设备验收。
