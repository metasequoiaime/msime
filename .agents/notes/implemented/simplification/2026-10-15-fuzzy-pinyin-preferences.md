# Agent Note: 模糊音偏好转换脱离设置组件

Status: implemented

## Problem

模糊音规则目录、首次启用种子、规则集合更新和清空转换都在 `fuzzy-pinyin-section.tsx`。设置偏好模型为了读取默认值依赖 React 组件，总偏好的类型也来自组件；行式与分组式界面只能借助组件内部闭包复用这些转换。

## Decision

由无 React 依赖的 `settings/fuzzy-pinyin-preferences.ts` 持有原类型、同一个默认对象、规则目录及三个纯转换，组件保留原导出路径并转发交互。模型和总偏好直接依赖叶子模块。确认弹窗及其异步回调仍由组件持有，保留点击时偏好快照的语义。

首次启用仅在 `enabled && !seeded` 时种下全部规则，沿目录顺序写入；已经种过的偏好再次开启保留规则原引用，包括刻意清空的规则。开关关闭不补写 `seeded`。勾选规则沿用 `Set` 去重与默认排序，保留未知规则。重置只返回关闭、空规则及 `seeded ?? false`，不复用普通开关转换。

## Historical audit

按 `FuzzyPinyin`、`模糊音`、`fuzzy_pinyin` 检索活跃笔记。[设置文件互通](../../implemented/feature/2026-10-10-windows-settings-file-and-local-data-parity.md)持有导入后保留种子标记、避免覆盖已挑选或刻意清空规则的决定；[Windows 偏好路径](../../implemented/architecture/2026-10-11-windows-settings-preference-paths.md)持有字符串集合稳定排序的决定，均部分相关并保持原职责。其他命中属于引擎模糊音候选、九键、双拼、设备门禁或设置布局，不持有共享 React 转换。没有已有归属笔记被取代。

## Alternatives considered

- **只移动类型与默认值。** 可以最小化消除模型对组件的依赖，但规则种子与更新仍留在 React 闭包里，无法直接验证或复用偏好转换。
- **重置调用关闭开关转换。** 可以少一个函数，但普通关闭保留规则，重置必须清空；两者的 `seeded` 缺省与返回字段也不同，合并会改变持久化语义。

## Consequences

设置偏好模型不再为了模糊音默认值依赖 React 组件，两个布局共用的纯转换可以独立消费和验证；代价是增加一个叶子模块。原类型、默认对象、规则目录顺序及旧导出保持，存储格式与宿主行为不变。首次种子不统一排序；重开时不按空数组判定首次启用；确认期间仍使用点击时的偏好快照。

新增十一项纯转换回归在空实现上全部按预期失败，正式实现后通过。真实控件新增两种布局的取消确认和行式规则更新回归，抽取前后均通过；连同既有默认偏好测试合计三文件十九项。测试使用冻结的合成偏好，验证规则原引用、未知规则、去重排序、可选种子标记及重置的固定字段。

真实输入页两项模糊音集成测试通过，覆盖首次全选、关闭保留规则、再次打开和显式重置及保存。桌面构建、Harmony 类型检查、原导出与 `Record<string, unknown>` 兼容探针通过；字段门禁仍核对 34 组共享类型。独立审查确认转换与旧表达式一致，并独立验证三文件十九项回归和字段、笔记门禁。
