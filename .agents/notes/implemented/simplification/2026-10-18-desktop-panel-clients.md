# Agent Note: 桌面面板客户端装配脱离启动入口

Status: implemented

## Problem

`main.tsx` 内联六类面板的客户端。语音、云剪贴板和表情重复关闭、目标应用记录、发送与复制动作；剪贴板启用还隐式依赖入口中的设置客户端。启动入口因此同时持有界面选择与 Tauri 命令装配，订阅失败清理和偏好保存也无法单独验证。

## Decision

`apps/desktop/src/input/desktop-panel-clients.ts` 提供 `createDesktopPanelClients`，显式接收偏好读写、已有云词库客户端和完整的剪贴板历史客户端。入口仍在模块级创建一次，独立窗口、设置页内面板和手写资源包装配继续共用原客户端对象。

`apps/desktop/src/input/desktop-clipboard-client.ts` 的 `createDesktopClipboardClient` 统一历史读取、同步、复制、删除、清空与固定六个命令。入口创建一个实例供设置页和面板工厂共用；桌面契约要求六个方法齐全，使用 `Required<ClipboardHistoryClient>` 表达。设置页取得完整记录，表情面板只投影文字，保留记录顺序与重复项，不修改原记录。工厂不启动原生命令；调用失败原样交还消费者。

语音、云剪贴板和表情复用私有的文本面板动作工厂。键盘与手写保留各自动作；语音继续复用 `createVoiceRecognitionClient` 的请求标识与过滤，事件桥只取 `payload`；云词库保持传入对象的身份。剪贴板数据、启用时的修订号与偏好合并、两条顺序订阅和第二条失败时释放第一条的顺序不变。

## Alternatives considered

- **按六类面板分别建模块**：各面板独立演进最直接。但这些实现主要是少量命令适配，三个文本面板仍需共用基础动作；先保留一处集中装配，已有语音请求模块继续独立。
- **只搬移原对象**：入口最短且差异最少。但重复文本动作仍需多处修改，因此统一这四个确实相同的动作，保留其他专属能力。
- **让表情面板直接使用设置客户端的可选 `clipboard`**：少传一个参数。但共享设置契约允许缺少读取、同步等方法，桌面两处实现却始终完整；显式传入完整客户端让缺方法成为编译错误，也避免面板工厂隐式依赖整个设置客户端。

## Verification

直接测试命令与窗口标签、语音事件有效期、剪贴板映射与偏好保存、正常订阅释放和注册失败清理。剪贴板命令单独覆盖完整记录与空列表、命令参数和失败透传；另用注入客户端验证表情面板确实复用它。另执行真实入口路由与面板相关回归、类型检查、构建、lint、笔记、quick 和 CI，实际结果记录在 PR。

## Consequences

启动入口减少命令装配实现，三个文本面板只维护一份共用动作。工厂如果在渲染中调用，会改变客户端身份并重启面板任务；入口继续在模块级调用。订阅顺序和清理顺序若变化会留下监听，保存偏好若只写一个字段会丢失其他设置，均保留原逻辑并直接测试。新增一个桌面装配模块是维护成本；本项不代表原生宿主装机验收。
