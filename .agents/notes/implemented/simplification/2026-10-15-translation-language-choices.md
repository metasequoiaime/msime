# Agent Note: 翻译语言类型与可见选项共用叶子模块

Status: implemented

## Problem

翻译语言的七值联合在语言目录、候选控件、设置 hook 和总偏好中重复声明。第二语言的空字符串选项也重复声明。移动端为当前主语言和第二语言分别补回已保存俄语的逻辑留在设置 hook，语言目录模块只提供数组，类型和呈现规则可能各自漂移。

## Decision

由现有 `settings/translation-language-helpers.ts` 持有语言、第二语言及只读选项元组类型，并提供主语言与第二语言的可见目录计算。总偏好和绑定直接依赖叶子类型，组件与 hook 保留旧导出路径。hook 消费计算结果，服务选择和系统翻译下载提示继续由它持有。

桌面直接返回原目录引用；移动端每次创建两个目录数组，原始元组继续共享。普通移动端目录不含俄语，仅当前对应字段已保存 `ru` 时在对应目录末尾加入「俄语（已保存）」，不能把主语言的选择泄漏给第二语言或后续页面。第二语言的首项及目录顺序保持，偏好字段仍不接受界面的空字符串，关闭第二语言继续存 `null`。

## Historical audit

按 `translation-language`、`TranslationLanguage`、翻译语言、俄语和第二种语言检索活跃笔记。[系统语言刷新顺序](../../implemented/bug-fix/2026-10-12-macos-on-device-language-refresh-order.md)及[腾讯占位值与语言下载提示](../../implemented/bug-fix/2026-10-15-macos-translation-placeholder-download-notice.md)持有读取代次与下载提示条件，部分相关且保持职责。[Windows 候选分栏](../../implemented/feature/2026-10-10-windows-candidate-window-mac-parity.md)持有多语言展示和偏好绑定，独立保留。其余 Android 释义插入、账号服务和键盘布局命中不涉及共享语言目录。没有已有叶子类型或可见目录决定被取代。

## Alternatives considered

- **只替换重复联合类型。** 改动最少，但移动端的目录呈现仍挂在设置 hook，与已有语言目录分离，无法直接复用或验证两种语言的独立保留规则。
- **统一复制桌面与移动端目录。** 可以统一引用规则，但桌面当前直接共享静态数组，复制会改变现有引用语义，且对只需添加旧值的移动端没有收益。

## Consequences

语言取值与可见目录规则由现有叶子模块统一持有，组件、绑定、总偏好和设置 hook 直接引用共同类型；代价是在该模块增加一个目录计算函数。旧导出路径、只读选项元组与可修改目录数组的原类型继续保留。偏好第二语言仍为语言代码或 `null`，界面的空字符串没有进入持久化契约。系统下载提示、服务优先级及原生能力不变。

新增七项目录回归在未实现移动端逻辑时六项按预期失败，桌面引用控制用例通过；完整实现后，连同既有控件与绑定回归为五文件十五项通过。抽取前后移动端真实页面两项集成通过，覆盖离线英文释义开启后的语言可编辑性和旧俄语不泄漏到新页面。字段门禁保持 34 组共享类型。

另有翻译服务与系统下载提示两文件 64 项回归通过，确认语言模块抽取未改变服务、凭据和下载提示行为。桌面构建、Harmony 类型检查及独立 TypeScript 探针通过；探针核对包根、组件和 hook 的旧类型导出、可修改目录数组、只读元组，以及持久化字段拒绝空字符串和未知语言。
