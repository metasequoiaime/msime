# Agent Note: 手写与表情面板共用复制输入按钮组

Status: implemented

## Problem

`panels.tsx` 的手写识别区与表情操作区分别渲染复制、输入两个模式按钮，重复维护按钮类型、选中语义、禁用与模式回调。两处的宿主能力判断、提示、外观和偏好存储并不相同。

## Decision

`PanelActivationButtons` 是受控的公共按钮组，只渲染按钮片段，由调用方传入当前模式、切换回调、禁用状态、输入按钮是否存在、输入标签和按钮样式。按钮组不新增 DOM 包装，保留原有分组与描述；`@msime/ui` 公开导出组件、属性和模式类型。

手写继续按原有能力回退模式、写入 `msime.handwriting.activation` 并在关闭或提交中禁用；复制能力缺失时只禁用复制按钮。表情继续在两种能力同时存在且页面允许时显示分组，保留提示和临时模式。

## Alternatives considered

- 直接逐个改用 `ActionButton`：可以复用基础按钮，但两个模式的顺序、选中状态与输入能力分支仍重复，且基础按钮的默认样式不适用于无样式的手写按钮。
- 共享完整模式 Hook：可以连状态一起收口，但手写持久化且包含关闭守卫，表情只在本次挂载保留模式；合并会扩大生命周期与能力回退的契约。

## Verification

新增的面板行为用例与既有桌面手写、表情提示用例共 17 项，在抽取前后通过，覆盖手写偏好保存、能力缺失和提交中禁用，以及表情模式切换与实际复制、输入。抽取后连同手写笔画、表情最近记录与符号目录，共 6 文件 43 项通过。桌面类型检查与生产构建、HarmonyOS 类型检查通过；lint 无错误，保留三个未改文件的既有未使用导入警告。

## Consequences

两处共用按钮顺序、`type="button"`、`aria-pressed` 和禁用语义，表情的选中与未选中样式也只写一次。代价是两面板开始依赖同一按钮契约。组件原样转发可选 class，不自行填入基础按钮样式，手写按钮仍直接作为原有容器的子节点；能力回退、关闭守卫、持久化和异步宿主动作由原面板持有。验证范围是共享 UI 行为与构建，没有启动原生输入法宿主。

## Existing notes audit

以 `PanelActivation`、激活模式、点击候选和 `ActionButton` 检索活跃笔记，没有同机制归属。[宿主操作按钮 runner](2026-10-14-host-action-runner.md) 负责异步操作锁，与本次同步模式切换无关；[元素尺寸订阅](2026-10-15-element-resize-subscription.md) 负责手写候选测量，不受本次按钮抽取影响。两者保留原有决定。
