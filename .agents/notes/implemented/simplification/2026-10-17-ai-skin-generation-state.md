# Agent Note: AI 皮肤抽卡状态独立复用

Status: implemented

## Problem

`AiSkinGeneration` 已是公共组件，但生成、插画准备、保存、发布和表单状态仍嵌在 JSX 模块，其他入口无法单独使用流程。请求结果仅按请求 ID 与挂载检查，服务身份变更没有同步放弃旧结果；保存记录按提案名称索引，重抽同名设计复用旧设计的记录。

## Decision

公开 `useAiSkinGeneration`、选项与状态类型，同时公开原控件和 props。流程组合现有 `useAsyncActionRunner`、`useAsyncGeneration` 和 `trackAsyncSubscription`；生成服务、图库与社区服务共同界定抽卡会话，更换任一服务时取消在途生成、清空会话状态并隔离旧异步续点。展示保留全屏滚动、返回和使用设计回调。

保存记录按当前提案对象关联，防止同名的新设计被当作已保存。保存后打开发布表单的续点同样检查会话归属；发布表单的字段与验证仍由领域 hook 持有，原文案与发布协议不变。

## Existing notes audit

- [抽卡模块](../../implemented/simplification/2026-10-14-ai-skin-generation-module.md)持有组件与编辑器解耦以及全屏样式归属，部分重叠，更新其当前状态归属并互链。
- [进度监听](../../implemented/simplification/2026-10-14-ai-skin-progress-subscription.md)持有公共订阅清理和注册失败处理，部分重叠，保留并更新调用位置。
- [取消请求](../../implemented/bug-fix/2026-10-11-ai-skin-cancel-request-generation.md)持有取消先使本地请求失效的决定，保留并互链。
- iOS 可见页面代次和 Android 抽卡视图生命周期属于原生实现，不迁移到 React hook，既有约束仍然成立。

已检索 proposed、implemented 和 rejected，未发现同范围提案或需要完全吸收的旧笔记。

## Alternatives considered

- 只移动生成与取消：最强理由是迁移更小、进度测试可直接复用；但保存和发布仍不能独立使用，异步所有者规则仍分散在 JSX，无法让抽卡控件成为纯展示。
- 直接使用社区图库的发布 hook：最强理由是复用现有发布表单状态，但该 hook 会主动载入整个图库并持有图库选择与登录导航；抽卡按已经保存的提案发布，直接套用会增加读取和改变发布标识语义。保留领域流程并复用公共 runner。

## Verification

原组件的四项回归稳定失败：更换生成服务仍沿用忙碌状态、同名新设计被当作已保存、更换图库后旧加载继续写入、旧保存结果打开发布表单；原有八项组件测试通过。新 hook 的十项测试先因公共入口缺失失败。抽取后组件、hook、生命周期契约、公共 runner 和订阅清理合计七文件三十项通过；设置整页的四项抽卡集成通过。

验证范围是共享 UI 状态、类型与构建。本片不改原生图片处理、文件读写、权限或平台资源，不声明原生设备验收。

## Consequences

公共入口既可使用原控件，也可独立使用生成、取消、保存与发布状态，代价是新增领域 hook 及提案对象关联的保存映射。生成、保存和发布各自复用 runner 的同步互斥，调用方可等待实际操作完成；保存重复调用会复用当前提案记录，不把同名的新设计标成已保存。打开发布表单时重新确认授权与分类，发布过程中不替换当前草稿。

三个服务的对象身份界定会话，展示回调变化不影响它。保存已发出的写入不能回滚，但离页或切换服务后旧结果不能写回新 UI 或继续下一步发布；加载结束时也先检查归属再发起写入。进度订阅在 StrictMode 与请求更替时仍释放迟到注册。
