# Agent Note: 抽取账号页移动端我的分组组件

Status: implemented

## Problem

`packages/ui/src/account/account-page.tsx` 同时定义移动端「我的」分组、跳转行和无标题支持分组，并在桌面与触屏分支反复组合跳转行。页面文件因此同时承担布局契约和账号状态接线，移动端的行结构不能独立复用或验证。

## Decision

账号模块提供公共 `AccountMeSection`、`AccountMeGroup`、`AccountMeRow` 与 `AccountMeSupportGroup` 组件。`AccountMeSection` 只持有标题的 `useId` 和分组外壳，允许账号页与下载页保留各自的内容容器；`AccountMeGroup` 在这个外壳内加上 `NavGroup`，其他组件只持有链接行 DOM、禁用属性和回调。页面继续决定哪些入口存在、分组顺序和账号业务状态。账号页和「其他平台下载」页改用这些组件，保留现有 class、文本、箭头和条件渲染，不改变宿主接口或导航行为。

## Verification

新增组件契约测试先在公共导出缺失时按预期失败，完成实现后 4 项通过；账号页、资料页和账号操作回归共 3 个文件 89 项通过。测试覆盖标题分组与无标题分组、可复用的分组外壳、整行按钮的回调和禁用状态，以及没有入口时支持分组不渲染。

桌面 TypeScript 类型检查、改动文件格式检查和仓库 lint 通过；lint 仅报告两个未改动文件的既有未使用导入警告。未修改原生宿主、文件读写或网络契约，因此不需要 Android 设备验收。

## Alternatives considered

- **只把组件移到账号页文件底部。** 改动最小，但仍不能由独立测试或其他账号子页复用，页面继续拥有展示组件实现，因此不采用。
- **把分组数据和账号状态一起放进组件。** 可以减少调用方 JSX，但会把登录、客户端忙碌和平台入口条件混入展示层，扩大公共组件契约并改变接线边界，因此不采用。

## Consequences

账号页不再持有移动端「我的」行组件实现，账号页与下载页共用分组外壳，公共组件可以脱离页面状态独立验证和复用；代价是账号模块增加一个导出符号，调用方需要显式传入每个入口的回调。`NavGroup` 包裹层级、按钮 class、`useId` 标题关联和业务条件仍由原实现保持。
