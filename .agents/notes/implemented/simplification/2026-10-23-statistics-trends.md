# Agent Note: 统计趋势视图独立于页面

Status: implemented

## Problem

统计页同时编排日期范围、选中日期和宿主读取，还持有每日柱图、长周期折线、速度与小时对比的绘制。仅搬走已有命名函数会留下桌面柱图和日均计算，趋势职责仍分散在页面与模块两处。

## Decision

把每日趋势说明、日均与峰值计算、桌面柱图和手机折线一起归入 `statistics-trends.tsx` 的 `StatisticsDailyTrend`；速度与小时视图分别导出 `SpeedTrend`、`StatisticsHourlyBars`。列中心、断线路径、参考线、折线、轴与柱样式留作模块内部细节。页面继续持有日期范围和选择切换，组件只报告被点中的日期，不持有状态。不增加包入口导出。

保留原有 JSX、配色、缩放、空态、超过 120 天才启用的尾随七日均线、原始面积和选中值、速度断线和长范围孤立圆点规则。`typing-chart.ts` 现有环形图几何不包含相同计算，不把趋势私有几何加入它的公共符号集。

## 旧笔记审计

按 `typing-statistics`、趋势图、七日均线和 `typing-chart` 搜索活跃笔记。[统计模型归属](../../implemented/architecture/2026-10-15-typing-statistics-model.md)部分重叠，随实现更新趋势归属并互链；[统计分布](../../implemented/simplification/2026-10-23-statistics-distributions.md)、[热力图](../../implemented/simplification/2026-10-23-statistics-heatmaps.md)与[读取状态](../../implemented/simplification/2026-10-23-typing-statistics-state.md)各持独立边界。日历跨度、午夜刷新、云上传、最佳成绩行和 Windows 原生统计属于数据规则或其他实现，不接管；无同范围过时提案。

## Alternatives considered

- 仅搬移三个已有函数，代码改动最小，也最容易逐字验证。但桌面柱图、峰值和非零日均仍散落页面，独立组件无法覆盖每日趋势的两种形态；将其作为一个受控视图一起抽取。
- 另建纯几何模型，可以直接测试路径数值。但几何没有其他消费者，拆分会增加内部契约，图表的可见行为仍需要 DOM 回归；保持私有计算，以视图与页面回归覆盖。

## Verification

迁移前两份页面回归共 38 项通过；新独立测试先因模块不存在而失败，迁移后同一基线与独立视图共三文件 44 项通过。六项独立测试覆盖非零日均、零值完整列、受控选择、120/121 天均线阈值、原始面积及选中点、速度断线与上下界、长范围孤立点及小时共同量程。几何与原有三个图表视图排除注释、空白和导出修饰后与基点一致。桌面类型检查与构建、Harmony 类型检查、变更文件 lint、格式及差异空白检查通过。独立审查未发现阻断问题，并复核两文件 37 项通过。首次 quick 的既有 Swift 豆包测试与语音语言目录检查在冷构建时触及 120 秒时限；不改超时与跳过规则，豆包复跑 17 项全部通过，目录示例预构建后完整消费者检查通过。随后完整 quick 通过，包含契约、Rust 工作区、Android 目标、Linux 桌面外壳和 Apple 共享桥接编译；ArkTS 缺少本机输入，Windows 缺少工具链，其他平台阶段按范围跳过，macOS 桌面 Rust 包仍因规定资源尚未准备而跳过。

## Consequences

统计页移出 341 行净内嵌实现，趋势视图不再依赖页面或宿主客户端。增加一个内部模块，三个导出按显示职责划分，几何细节不扩张到包入口。日期和速度数据仍由页面提供，选择切换仍由页面解释；长周期折线仍使用原有固定渐变标识，本片不改变该行为。装机不在本片验证覆盖内。
