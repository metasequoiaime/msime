# Agent Note: 抽取手写笔迹编辑视图

Status: implemented

## Problem

手写面板已把识别与笔画生命周期交给 `useHandwritingPanel`，但 SVG 画布、辅助线、笔迹绘制和四项编辑操作仍内联在大型 `keyboard/panels.tsx`。其他手写宿主无法单独复用这块编辑视图，画布事件转发和编辑按钮语义也只能通过完整面板验证。

## Decision

把整个笔迹编辑区抽成公共 `HandwritingInkEditor`，通过 `@msime/ui` 导出组件与 props。组件接收只读笔迹、书写与关闭状态、操作可用标志及回调，不接收客户端、不创建识别队列或笔画状态。面板继续从 hook 的当前状态计算操作可用条件，再传入组件。保留 section、SVG、辅助线、单点圆、多点折线、空提示、按钮样式、快捷键声明与指针取消接线。

## Alternatives considered

- **只抽 SVG 画布**：props 更少，也能复用笔迹绘制；但编辑动作仍和面板布局耦合，复用一个完整书写区需要再复制工具栏，因此不采用。
- **把整个状态 hook 作为一个 prop**：调用处最短，但使公共视图依赖下载状态、候选、提交及窗口生命周期，其他消费者必须构造与画布无关的状态，因此不采用。

## Verification

- 新增 5 项组件测试覆盖空画布、单点与多点笔迹、全部指针事件、动作回调、禁用状态和可选识别入口；公共组件缺失时失败，迁移后通过。
- 连同原面板的指针、候选、激活按钮、窗口订阅和模型资源回归，6 个文件、67 项测试通过。
- 设置整页中的手写相关用例定向运行，12 项通过，其他无关用例跳过。
- 公共导出随桌面生产构建检查；HarmonyOS 类型检查、lint 和修改文件格式检查通过。

## Consequences

公共组件可独立承载笔迹编辑，面板只负责状态和动作接线；代价是调用方要明确提供各动作的可用条件。SVG 的 `lostpointercapture` 或操作可用条件遗漏会改变中断笔画的处理，因此保持现有指针回调原样转发，并用原面板行为测试验证接线。
