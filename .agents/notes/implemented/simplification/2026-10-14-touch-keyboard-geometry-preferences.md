# Agent Note: 复用触屏键盘几何偏好读取

Status: implemented

## Problem

设置页主体和拖动预览各自读取 `touch_keyboard_height_adjustment`、`touch_key_spacing_tenths` 和 `touch_row_spacing_tenths`，两处都写同样的空值回落。重复实现容易让默认值或零值语义在后续修改中分叉。

## Decision

共享 `touchKeyboardGeometryPreferences` 统一解析三项几何偏好。读取使用 `??`，因此缺失值回落到 `defaultTouchKeyboardGeometry`，显式的零仍然有效；函数不做范围裁剪，拖动起始值仍在 `pointerdown` 时捕获，拖动中的范围约束继续由现有 hook 负责。Windows 原生设置窗口的同步和取值规则仍由[原生屏幕键盘设置笔记](../feature/2026-10-11-windows-settings-screen-keyboard.md)负责，本次只收拢共享 UI 的读取。

检索现有几何和间距笔记后，Windows 原生设置笔记与本次默认值、拖动时序部分重叠，保留其原生同步决定并链接；双拼键位提示笔记持有布局开关，键盘高度回弹和 Android 首帧配色笔记持有原生持久化、快照来源，均不涉及本次共享 UI 解析器，不改写这些决定。

## Alternatives considered

- **继续保留两处内联读取** — 改动最小，但默认值契约仍有两个维护点，后续容易只改一处。
- **让读取函数顺便裁剪范围** — 可减少调用处代码，但读取偏好和编辑中的约束是不同职责，会改变现有对异常存储值的处理边界。

## Consequences

- 共享设置页和拖动 hook 使用同一个几何偏好解析器，显式零和既有默认值保持不变。
- 读取函数新增一个共享 UI 内部模块及单元测试，通过直接导入供两个消费者使用；范围校验、拖动捕获时序和原生宿主同步保持原位置。

## Verification

- 读取函数、几何控件及拖动 hook 的三个测试文件共 15 项通过，覆盖缺失与部分字段、零、负高度、异常值不裁剪及冻结源。
- 拖动 hook 新用例在抽取前后均通过：缺省起点、下一次按下采用最新草稿、拖动中草稿更新保留按下起点与其他字段、键距和行距分别计算。
- 设置整页的几何预览、滑块、拖动与保存用例通过。
- UI 类型检查与构建、改动文件格式检查、笔记门禁及 quick 验证通过。quick 在本机缺少 Docker 和 MinGW 时按脚本跳过对应阶段，不代表原生产品装机验收。
- CI 暴露账号头像取消测试的等待竞态：等待宿主调用次数不代表取消请求的异步收尾结束，第二次点击可能遇到禁用按钮。该用例在点击之间等待按钮恢复可用，产品操作逻辑不变；账号测试文件 69 项通过。
