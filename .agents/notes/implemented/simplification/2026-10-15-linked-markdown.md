# Agent Note: 公告与试用页复用 Markdown 渲染和链接委托

Status: implemented

## Problem

公告和试用键盘回复都使用相同的 Markdown 配置，并各自维护点击及辅助点击的链接委托。两份实现都必须关闭原始 HTML 和图片、阻止 WebView 默认导航，但允许打开的协议并不相同；继续复制容易让一次维护只覆盖一个入口。

## Decision

`core/linked-markdown.ts` 统一可带链接的 Markdown 渲染，以及从事件目标查找最近链接、取消默认导航、按调用处协议规则交给宿主的处理。公告保留仅 HTTPS，试用页保留 HTTP、HTTPS 与 mailto。宿主回调缺失时仍取消链接默认导航，普通非链接点击不受影响。保留 `noticeBodyHtml` 导出供现有消费者使用，不扩大包的公共导出面。

历史检索中，[试用键盘页面](../feature/2026-10-08-touch-try-keyboard-page.md)持有回复格式与协议策略，部分重叠，保留并互链；[试用入口切换到对话标签](../feature/2026-10-11-touch-try-keyboard-is-the-chat-tab.md)说明正式对话页故意禁用链接，其决定继续有效，不将 `ChatPage` 迁入本模块。发布 PR 正文中的 Markdown 字数预算与 UI 渲染无关。

## Alternatives considered

- **只抽取链接点击处理。** 可以让委托逻辑只维护一份，但相同的 Markdown 配置仍有两份，HTML 和图片规则仍可能分叉，因此把渲染和委托放在同一叶子模块。
- **给所有对话与公告提供可配置的统一渲染器。** 能覆盖三个使用 `MarkdownIt` 的页面，但正式对话页故意禁用链接，当前没有复用相同规则的需求；为单个不同消费者增加模式开关扩大了本片契约，保留其独立渲染器。

## Consequences

- 公告与试用页复用一个渲染器和一个事件委托实现，协议规则与宿主回调仍由调用处持有；`noticeBodyHtml` 通过别名保留，包的公共导出面没有增加。
- 共享解析器只配置一次、不暴露可变实例。两处后续改变渲染规则时必须一起验证；若其中一处需要不同语法，再评估单独的渲染模式。
- 原生宿主的 URL 校验和浏览器打开行为继续由宿主负责。本片不改变被拒绝链接的显示方式，也不吞掉宿主回调的错误。
