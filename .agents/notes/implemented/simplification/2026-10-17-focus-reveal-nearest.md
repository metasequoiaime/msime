# Agent Note: 复用键盘候选的聚焦与滚动定位逻辑

Status: implemented

## Problem

表情导航和手写候选导航都需要先以 `preventScroll` 聚焦按钮，再用 `scrollIntoView({ block: "nearest", inline: "nearest" })` 让目标保持可见；表情搜索框也重复了同样的两步。调用顺序和滚动参数属于键盘操作契约，分散复制会让后续修改只覆盖其中一处。

## Decision

新增 `focusAndRevealNearest`，统一执行“禁止聚焦触发页面滚动，再按最近位置显示目标”两步操作。表情导航和手写候选导航继续自行决定目标、按键和边界，只复用这段 DOM 操作；函数从 `@msime/ui` 导出，供其他键盘列表复用。

## Alternatives considered

- **继续在每个导航处理器内联两步调用。** 现有代码短小，但三个入口的调用顺序和参数会继续复制，修改滚动策略时容易出现行为分叉。
- **只抽取 `scrollIntoView` 调用。** 这样仍可能让调用方忘记 `preventScroll`，导致浏览器先把页面滚到目标再调整最近位置，破坏原有键盘体验。

## Consequences

- 表情搜索、表情项目和手写候选保持原来的聚焦顺序、滚动参数和键盘边界行为。
- 公共函数对空目标安全返回，并有独立测试覆盖正常和空目标分支。
- 新增了一个 UI 核心导出；其他导航仍需自行决定何时调用，不会自动改变其事件处理逻辑。
