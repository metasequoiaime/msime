# Agent Note: 移动键盘反馈契约独立于反馈组件

Status: implemented

## Problem

`MobileKeyboardFeedback`、`MobileKeyboardFeedbackClient`、手写颜色和滑动符号方向类型定义在反馈 JSX 组件里。宿主客户端、保存 hook、外观动作、手写预览与几何设置都因此从展示组件导入公共契约。设备缺省能力、振动强度行可见性和原生英文建议的缺省值也散在 JSX 中。

精确检索类型与组件名命中[振动档位](../../implemented/bug-fix/2026-10-08-keyboard-haptic-levels.md)和[预览操作归属](../../implemented/bug-fix/2026-10-15-mobile-feedback-preview-owner.md)：前者持有四档映射，后者持有异步生命周期，本片沿用它们，不改变原生实现或时序。按「按键反馈」扩展检索命中的宿主存储、账号同步、备份、安卓导航与检索、滑行输入和跨平台设计笔记各自持有平台行为，没有持有本片契约从 JSX 拆出的决定。

## Decision

纯模块 `mobile-keyboard-feedback.ts` 持有原有四个类型和 `mobileKeyboardFeedbackControlState`。使用方直接依赖纯模块；组件保留旧类型重导出。状态投影只计算振动开关、强度行是否显示，以及原生英文建议是否勾选：缺省设备能力按可用，只有能力明确为 false 才隐藏，振动关闭只隐藏强度行；英文建议只有明确为 false 才关闭。

## Alternatives considered

- **只移动类型**：改动少，所有非展示使用方都能摆脱 JSX 依赖。但可见性和缺省规则仍散在组件中，纯投影集中已有行为，方便独立验证设备能力与已存设置的区别，因此一起抽出。
- **设备不支持时清除已存振动偏好**：投影结果和偏好一致，后续消费者不必再考虑能力。但 iPad 隐藏的是本设备用不了的控件，已存选择还要留给其他设备；只计算显示状态，不改写它。

## Consequences

- 宿主契约、保存 hook、外观动作、手写和几何设置直接依赖纯模块，反馈组件继续重导出原四个类型；包入口的 API 集合保持不变。
- 类型成员、可选性和客户端方法签名保持。存储与异步流程不变；投影只计算控件状态，不把设备能力或缺省值写回设置。
- 能力缺省或为真时显示振动开关，明确为假时隐藏振动与强度；关闭振动保留强度选择，只隐藏强度行。英文建议缺省开，显式 false 关闭。
- 多一个小型公共模块；未来新增反馈字段在这里定义，展示组件不再持有客户端协议。新增纯函数只处理现有反馈显示规则，不改变手写、滑动符号或按键弹出预览。

## Verification

纯投影用例覆盖旧宿主缺省、设备不支持与显式关闭，冻结输入对象确认只读。原组件、加载保存、预览归属与真实设置页回归验证文案、开关和 iPad 能力降级；手写与几何回归验证类型使用方。独立 TypeScript 探针对照旧组件、包入口与纯模块的类型形状、可选方法和枚举；另跑桌面构建、Harmony 类型检查、字段契约、笔记及 quick 门禁。
