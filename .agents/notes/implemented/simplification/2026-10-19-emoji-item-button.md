# Agent Note: 表情与符号共用受控条目按钮

Status: implemented

## Problem

`EmojiPanel` 的最近符号、符号目录和通用目录三次维护同一个文本按钮，重复显示文本、根据关键词取提示和向选择动作传递原始文本与关键词。三处的几何、键盘导航标记和忙状态并不相同，继续复制容易在整理时误把这些差异统一。

## Decision

公开受控 `EmojiItemButton` 与 props，接收原目录条目、选择回调和原有的流式、紧凑、导航、禁用及附加样式输入。按钮直接呈现原文，使用已有 `emojiDisplayName` 提示，并原样传回条目。原 `panelTile` 字面量迁入已有内部 `emoji-panel-style` 模块，保留流式优先于紧凑的规则。

面板三处共用同一个选择适配器，将条目的文本和关键词交给现有 `copy(text, false, keywords)`。最近符号继续紧凑且没有导航标记和忙状态禁用；符号目录继续紧凑且参与导航，但没有忙状态禁用；通用目录继续按组决定流式布局、参与导航并在剪贴板修改期间禁用。列表 key、容器、分组、状态与宿主请求归属不变。

- [激活按钮组](../../implemented/simplification/2026-10-17-shared-panel-activation-buttons.md)管理复制与输入模式选择，与目录条目视图无关。

## Alternatives considered

- **只抽 `panelTile` 样式**：迁移最小且三处外观保持一致，但仍分别维护 tooltip、文本和选择参数，不能消除条目按钮的重复契约。
- **按钮自己读取面板状态或执行宿主请求**：调用处更短，但会重复拥有最近使用和操作代次，无法在其他目录中作为受控视图复用。按钮只通过回调交还条目。
- **把三处导航和禁用规则统一**：属性更少，后续维护简单，但会让最近符号加入原本不参与的键盘网格，或改变修改期间的按钮可用性；此片保留差异。

## Consequences

目录按钮的文本、提示、几何与选择转发在一处维护，代价是新增公共 props 与内部样式依赖。目录选择仍由 hook 判断当前模式，面板适配器固定传 `false` 并保留完整关键词。导航依赖同一面板根节点中的 DOM 标记，组件不增加包装层，也不给最近符号补标记。共享前端验证不代表原生宿主装机。
