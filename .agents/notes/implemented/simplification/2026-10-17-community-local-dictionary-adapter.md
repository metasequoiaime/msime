# Agent Note: 社区本机词库适配器

Status: implemented

## Problem

共享设置入口 `packages/ui/src/index.tsx` 内联组装社区图库需要的本机词库客户端：命名词库安装、第三方词库来源核对，以及 `quick` 到 `quickPhrase` 的类型映射都和页面拼装混在一起。社区资源操作已经是独立模块，但设置入口仍保留一份宿主适配逻辑，后续社区入口容易重复实现这条边界。

## Decision

`community-resource-actions.ts` 提供 `createCommunityLocalDictionary`，接收普通本机词库客户端和命名词库客户端，返回社区图库使用的适配器。没有命名词库能力时原客户端按原对象返回；有命名词库能力时，社区安装统一调用 `installCommunity`，第三方词库核对统一把 `quick` 映射为 `quickPhrase`，并把宿主返回的 `third_party_matches` 投影为索引数组。设置入口只传入客户端并继续把适配器交给所有社区图库入口。

## Alternatives considered

- **继续内联在设置入口**：不改变当前行为且改动最少，但社区资源适配规则继续依赖大型设置页面，新的入口会再次复制映射和安装分支。
- **让每个社区页面自己适配宿主客户端**：页面看起来独立，但会在社区主页、图库子视图和功能页保留多套命名词库和第三方来源契约；统一操作模块更能保持边界。
- **把适配器放入 `SettingsClient` 类型**：能让设置客户端直接暴露社区形状，但会让宿主契约同时知道社区页面的 `quick` 类型映射，扩大跨层依赖；适配属于共享 UI 操作层，因此留在社区模块。

## Consequences

社区资源操作和宿主客户端的转换有独立单测与公共导出，设置入口减少页面级业务逻辑。普通本机导入能力、命名词库优先级、接收者绑定和第三方核对失败语义保持不变；适配器仍不负责 toast、刷新或请求生命周期，这些职责继续由调用方持有。
