# Agent Note: 设置导航按功能语义命名

Status: implemented

## Problem

桌面导航为了统一四字名称，把「快捷键」改成「按键设置」、「剪贴板」改成「剪贴管理」，还省略了「标点与翻译」中的连接词。相似的后缀和不自然的缩写降低了入口的辨识度，用户要求取消长度限制。

## Decision

删除共享设置的四字桌面标题映射与注入回调，直接复用注册表中自然的功能名称。合并后的屏幕键盘页叫「键盘与手写」，不恢复独立侧栏入口。AI 两类配置的桌面入口由[AI 功能共用导航入口](2026-10-19-ai-settings-top-tabs.md)继续精简为「AI」，顶部标签区分辅助功能与助手连接。Windows 原生设置的导航标题同步；移动标题投影保留既有叫法。

布局的图标尺寸、文字起点、行高和间距保持一致，不依赖字数排齐。窗口标题与返回按钮从同一投影读取名称；搜索继续匹配显示名称和注册名称，合并页可按「屏幕键盘」搜索。页面 id、排序、能力过滤与偏好不变。

## Historical audit

- [工具栏、键盘和手写页精简](../../implemented/simplification/2026-10-16-toolbar-keyboard-handwriting-settings-prune.md)：部分取代其中的桌面四字菜单命名规则；保留合并页面、能力边界、排序和页内标签。
- [连续平铺侧栏](../../implemented/simplification/2026-10-19-settings-flat-sidebar.md)：保留平铺呈现，仅同步当前标题事实。
- [键盘与手写顶部标签](../../implemented/feature/2026-10-19-keyboard-handwriting-top-tabs.md)：保留标签与旧路由，更新合并页标题。
- [MCP 独立页](../../implemented/architecture/2026-10-18-mcp-independent-settings-page.md)：沿用「AI 辅助」与「AI 助手」的功能区分。

## Alternatives considered

**继续保持四字，依靠不同图标和颜色区分**：视觉轮廓统一、改动最少；但用户依旧需要解读相似后缀和缩写，因此用自然标题承担识别，布局承担整齐。

**把全部页面压缩到两个字**：侧栏占用更少，但「候选」「维护」等会丢掉范围信息，「快捷键」「剪贴板」也没有必要缩短，因此不另设长度限制。

## Verification

相关设置、导航、平台能力和皮肤回归共 12 个文件、662 项通过：11 个文件首轮通过；平台能力文件中的三个旧用例先在改名前的分支复现失败，补齐等待表单和进入服务配置的步骤后，该文件 41 项全部通过。原有功能断言保留。桌面与 HarmonyOS 设置构建、格式和 lint 通过。合成浏览器核对 macOS 1000×780 浅色、800×600 深色，以及 Linux 800×600 深色：13 个导航标题准确、点击后的页面标题一致、按「屏幕键盘」仍能找到合并页、无文本截断与横向溢出。macOS 360×540 的内容标题与布局正常。

本地 `scripts/verify-local.sh --quick` 通过，Windows 设置页结构检查通过。quick 中 HarmonyOS ArkTS 与 Windows 原生编译因本机工具链未就绪跳过；HarmonyOS 共享设置前端已单独构建通过，Windows 窗口仍需在 Windows 上验收。

## Consequences

导航标题长度不等，统一布局继续承担对齐，名称按功能范围决定。删除额外标题表后，共享设置不再维护两套桌面叫法；移动命名继续由独立投影负责。Windows 原生标题同步修改，macOS 上不宣称完成 Windows 窗口交互验收。本机已安装保留水杉娘改动的合成版本，并通过系统辅助功能树核对自然标题；后续点击时窗口不可访问，因此点击交互由合成浏览器补充验证。
