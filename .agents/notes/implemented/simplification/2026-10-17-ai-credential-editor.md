# Agent Note: AI 凭据编辑复用公共展示模型与宿主契约

Status: implemented

## Problem

`AiCredentialSection` 内嵌已存接口和模型的比较、损坏状态说明、输入与操作禁用条件；组件还自行声明 `AiCredentialStored`。已有保存和配置测试函数虽然独立，包入口尚未公开它们，独立调用方仍需依赖内部路径或重新组装。

## Decision

在无 React 依赖的 `ai-credential-model.ts` 定义公共 `aiCredentialEditorModel`，统一展示推导和按钮条件，组件只绑定字段。已存元数据从 `ProviderCredentialStatus` 投影，保存参数从 `ProviderCredentialClient.saveAi` 派生，已有保存函数使用该宿主参数契约。

包入口公开模型、相关类型以及已有保存和配置测试函数；旧组件类型出口和已有函数路径保持兼容。偏好投影直接依赖独立的 `ai-assistant-preferences.ts`，避免公共纯类型绕包入口。

绑定比较继续使用原始接口和模型精确匹配；保存条件只用 `trim` 判断模型和输入是否为空。忙碌时保存、清除禁用，密钥输入仍只受接口来源是否有效影响。保存函数保留非空密钥原文，空白密钥省略。

## Existing notes audit

- [腾讯云凭据公共纯模型](2026-10-17-tencent-credential-editor.md) 与[语音凭据编辑状态](2026-10-17-voice-credential-editor.md) 提供既有分层模式；AI 表单没有本地生命周期状态，采用纯函数。
- Windows AI 宿主接口笔记拥有原生网络与凭据来源，本片不改变它们。

## Alternatives considered

- **只抽取展示文案**：改动少，但按钮和输入条件仍留在组件，调用方还需重复维护。
- **统一成所有服务的通用凭据编辑器**：能共享更多表单代码，但 AI 的精确绑定、语音的豆包展开状态、腾讯云的双密钥与地域契约各不相同；保留领域模型，复用已有基础控件。

## Verification

公共模型与出口测试先在旧实现出现 6 项预期断言失败；实现后 8 个相关测试文件共 32 项通过，覆盖绑定精确匹配、损坏说明优先级、新旧凭据保存条件、密钥输入可编辑性、保存原文和空白省略。类型兼容测试覆盖包入口、旧组件路径、宿主保存参数及偏好投影。独立只读审查通过，审查方另跑 4 个核心文件共 15 项通过；desktop 类型检查与构建、HarmonyOS 类型检查、格式、lint、笔记和本地 quick 门禁通过，lint 保留未涉及文件的已有警告。

## Consequences

- 组件专注字段绑定，独立调用方可直接复用展示模型及既有保存、配置测试函数；旧路径继续兼容。
- 已存元数据与保存参数依赖宿主契约，偏好投影直接依赖独立设置模型，减少跨层类型漂移。
- 公共出口增加维护面；调用方仍负责受控输入、接口来源解析和异步操作，模型不持有已存密钥或替代共享 Rust 的持久化校验。
- 本片验证范围是共享 React 层，不代表原生宿主装机或真实 AI 服务验收。
