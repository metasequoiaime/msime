# Agent Note: AI 凭据编辑复用公共展示模型与宿主契约

Status: implemented

## Problem

AI 凭据编辑需要已存接口和模型的比较、损坏状态说明、输入与操作禁用条件，也需要按宿主选择 Linux provider、配置说明或直接 Token 输入。将这些绑定留在 `AiSettingsContent` 中，其他入口即使复用展示模型，仍须重新组装宿主分支和保存、清除回调。

## Decision

在无 React 依赖的 `ai-credential-model.ts` 定义公共 `aiCredentialEditorModel`，统一展示推导和按钮条件，组件只绑定字段。已存元数据从 `ProviderCredentialStatus` 投影，保存参数从 `ProviderCredentialClient.saveAi` 派生，已有保存函数使用该宿主参数契约。

包入口公开模型、相关类型以及已有保存和配置测试函数；旧组件类型出口和已有函数路径保持兼容。偏好投影直接依赖独立的 `ai-assistant-preferences.ts`，避免公共纯类型绕包入口。

`ai-credential-control.tsx` 的 `AiCredentialControl` 选择完整的凭据编辑界面，并连接 `useProviderCredentials` 的受控草稿、忙碌状态、反馈和操作函数。不鉴权的服务返回空内容；Linux 有凭据能力时复用 `AiCredentialSection`、现有保存配置函数和 provider 操作，没有能力时保留服务配置说明；其他宿主复用 `AiApiTokenSection`。控制组件只依赖三字段 `AiCredentialPreferences`，不依赖完整设置客户端或设置页，也不引入本地状态。包入口保持现有 API，控制组件由共享设置内部模块显式导出。

输入回调只接受字符串，兼容既有设置组合器；不能因状态来源是 React setter 而扩大为要求函数式更新的契约。草稿清理仍属于凭据 hook。

绑定比较继续使用原始接口和模型精确匹配；保存条件只用 `trim` 判断模型和输入是否为空。忙碌时保存、清除禁用，密钥输入仍只受接口来源是否有效影响。保存函数保留非空密钥原文，空白密钥省略。

## Alternatives considered

- **只抽取展示文案**：改动少，但按钮和输入条件仍留在组件，调用方还需重复维护。
- **统一成所有服务的通用凭据编辑器**：能共享更多表单代码，但 AI 的精确绑定、语音的豆包展开状态、腾讯云的双密钥与地域契约各不相同；保留领域模型，复用已有基础控件。
- **只抽出 Linux 保存与清除回调**：能缩小设置页内联操作，但独立入口仍需重复选择不鉴权服务、Linux 能力回退和其他宿主的 Token 输入；控制组件承接整个凭据插槽，异步状态仍复用现有 hook。

控制组件迁移前相关 6 个测试文件 43 项通过；新增独立组件测试先因模块缺失失败，实现后 8 项通过。用例覆盖不鉴权服务的宿主与能力矩阵、Linux 无能力回退、其他宿主的独立 Token 回调，以及用真实凭据 hook 保存原文、忙碌期间继续编辑、保留新草稿、留空重绑模型和清除当前服务。

相关回归 9 个文件共 73 项通过；独立审查另跑控制组件和设置页文案两个文件 17 项通过，确认宿主分支、闭包与插槽 DOM 不变。桌面构建、HarmonyOS 类型检查、全仓 lint、变更文件格式和笔记校验通过。lint 仅有未改动文件的两条既有警告；构建保留既有大包提示。类型检查发现并修正过输入回调契约过宽的问题，修正后重新构建通过。

修正后的提交前 `scripts/verify-local.sh --quick` 通过，包含 Rust 工作区、Android 目标、Linux 桌面外壳和共享 Apple 桥编译；按改动范围或缺少工具链跳过的阶段由门禁明确列出，不作为设备验收。

## Consequences

- 组件专注字段绑定，独立调用方可直接复用展示模型及既有保存、配置测试函数；旧路径继续兼容。
- 设置页组合器只向凭据插槽传入控制组件与必要状态；独立入口可以复用完整宿主选择和操作绑定。控制组件不读取凭据文件，不替代共享 Rust 的校验或持久化。
- 已存元数据与保存参数依赖宿主契约，偏好投影直接依赖独立设置模型，减少跨层类型漂移。
- 公共出口增加维护面；调用方仍负责受控输入、接口来源解析和异步操作，模型不持有已存密钥或替代共享 Rust 的持久化校验。
- 本片验证范围是共享 React 层，不代表原生宿主装机或真实 AI 服务验收。
