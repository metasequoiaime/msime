# Agent Note: 抽取屏幕键盘按键按钮

Status: implemented

## Problem

屏幕键盘的标签、提示、材质、修饰键按下状态与点击来源判断仍内联在 `KeyboardPanel` 的键行循环中。调用方难以独立复用一个真实按键，也无法直接验证指针事件目标与同步更新后的键面文本。

## Decision

公共 `KeyboardKeyButton` 接收已有按键定义、只读修饰键集合、材质、宽度比例、禁用状态和事件回调。组件复用公共标签方法，保留单字符 Shift 键面规则；保留原按钮、标签与提示 DOM，转发指针事件，只有修饰键、Num Lock 或 detail 为零的点击调用激活回调。激活回调接收原按键与事件发生时的按钮文本。宽度计算、键行、同步 DOM 更新、布局与发送生命周期继续由原调用方持有。

## Alternatives considered

- **只抽一个接受任意 children 的样式按钮**：接口更通用，调用方控制全部行为；但标签、修饰键状态和重复发送守卫仍会复制，因此采用有明确按键语义的组件。
- **抽整个键盘网格并传入完整 hook 返回值**：接线更少，能一次收走全部循环；但组件会依赖布局、队列和语音等无关状态，单键也无法独立复用，因此保留逐键接口。

## Verification

- 公共入口测试先确认组件缺失而失败，迁移后新增 11 项组件测试通过。
- 组件、标签、连发、布局、桌面接线、macOS 键面、状态 hook、窗口订阅、皮肤和间距回归共 10 个文件、98 项通过。
- 设置整页的屏幕键盘相关用例另有 14 项通过，381 项无关用例跳过。
- 桌面生产构建、HarmonyOS 类型检查与 lint 通过；lint 的 4 条警告均在未修改文件。
- quick、修改文件格式、笔记门禁和 diff 检查通过；独立审查无阻塞问题，另跑 11 项组件测试通过。

## Consequences

真实按键可以独立复用，代价是调用方需明确提供布局宽度和事件动作。组件不缓存 props，保留现有同步 DOM 键面更新与重新渲染。按钮文本包含提示时也按原样转发；不把键定义的 label 当成事件时的显示值。指针 currentTarget 仍是按钮，不新增包装元素。此片只验证公共前端，不代替原生宿主设备验收。
