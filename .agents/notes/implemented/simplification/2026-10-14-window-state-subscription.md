# Agent Note: 窗口状态监听复用公共异步订阅清理

Status: implemented

## Problem

`useWindowState` 手写异步注册完成后的取消函数保存、过期注册立即释放和 effect 退出时释放。公共 `trackAsyncSubscription` 已被语音模型、资源包和键盘面板使用，维护相同的清理规则。

## Decision

窗口监听使用公共工具接管取消函数。挂载及宿主代次仍由窗口 hook 判断，保留注册前的微任务守卫、宿主更换时重置最大化状态，以及当前宿主失败时的固定提示。公共工具接受 `Promise<(() => void) | void>`，以接收在微任务开始前已失效而未注册的分支；没有取消函数时清理为空操作。既有返回取消函数的消费者保持兼容。

## Alternatives considered

- 保留窗口 hook 的局部清理：所有流程集中在一个 effect 中，可独立理解，也已有整页测试。代价是重复维护公共工具已提供的晚到注册释放规则。
- 给失效分支返回空取消函数：不用调整工具的类型，但会为了满足接口制造未发生订阅的取消句柄。允许空结果直接表达没有注册，既有消费者的调用方式保持兼容。

## Verification

窗口 hook 的 8 项行为测试在抽取前后通过，覆盖 StrictMode、当前监听更新、更换宿主及卸载后的晚到注册、同步与异步注册失败，以及过期事件和错误不会影响新宿主。与公共订阅工具和宿主窗口状态测试合计 18 项通过；设置整页的 5 项窗口相关用例也在抽取前后通过。测试只替换宿主接口，不替换共享 hook 或订阅工具。

## Consequences

窗口 hook 减少一份取消函数保存与释放实现，晚到注册和正常卸载共用工具的清理规则。公共工具的输入类型多了空结果分支；挂载、宿主代次、注册时机和界面提示仍由调用方维护。注册前保留代次判断，固定错误提示在交给工具之前处理，行为测试检查资源释放次数及错误归属。本项验证共享前端监听生命周期，不代表原生产品的装机验收。

## Existing notes audit

按 `useWindowState`、`use-window-state`、`trackAsyncSubscription`、异步订阅、订阅清理和窗口状态检索活跃笔记，没有同机制归属。桌面分区标签的窗口状态记录讨论标签选择的持久化范围，与宿主最大化监听无关。本篇只记录共享监听清理及注册前失效边界。
