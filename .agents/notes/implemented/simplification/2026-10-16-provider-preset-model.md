# Agent Note: 服务商预设的公共模型契约

Status: implemented

## Problem

AI 目录、语音默认表和预设说明组件分别声明同一组字段。AI 页的选项类型又归组件所有，更新逻辑也独立声明目录的子集，纯数据消费者难以找到统一契约。

## Decision

在 `core/provider-preset.ts` 定义展示元数据 `ProviderPreset` 和含端点、模型默认值的 `ProviderDefaults`。AI 目录组合选项和默认值契约，并让更新逻辑直接投影该目录类型。旧路径继续转导出类型，包入口公开模型；表数据、默认值与运行行为保持不变。

## Existing notes audit

按 `ai-provider`、`provider-preset`、服务商预设和模型关键词检索活跃笔记。Windows 原生 AI 页笔记描述跨语言数据和行为对齐，属于相关但独立的决定，本次不修改预设值或原生表；其余端点策略、凭据与语音引擎笔记不拥有展示类型契约。

## Alternatives considered

- 保留各处结构类型：每处都很短，使用方无需导入。但相同字段继续分别维护，模型列表和文档的可选性可能漂移。
- 把所有类型放在 React 组件：原路径不变，但目录和语音纯逻辑要反向依赖展示层，因此改为纯模型模块并保留转导出。

## Consequences

- AI、语音默认表和预设组件共用无 React 依赖的模型；旧组件和语音路径继续转导出原类型，包入口直接导出纯模型。
- AI 目录、页选项和更新预设使用组合与投影表达字段关系；展示选项仍只要求 `id/title`，文档和已知模型仍可选。
- `ProviderDefaults` 用 `Pick` 投影元数据再组合字段，保留原对象类型对 `Record<string, unknown>` 的结构兼容性；直接组合接口会丢失这一隐式索引兼容性，类型检查已复现并用类型断言覆盖。
- 不修改任何服务商数据、选择和回退规则，也不修改只读层级；新增公共类型是维护成本，后续相同字段应复用这里，避免继续独立声明。
- 用现有 AI 预设、语音默认值和预设说明组件测试验证行为，类型检查验证现有消费者兼容，构建和 quick 门禁验证集成。
