# Agent Note: 剪贴板历史与云端发送状态独立复用

Status: implemented

## Problem

`ClipboardHistorySection` 同时定义宿主模型、本地读取与写入生命周期、自动同步、清空确认和云端可用状态及发送。共享设置以外的使用者无法独立复用状态，core 类型消费者也依赖 JSX 模块。云端发送只靠 React 状态阻止重复点击；本地替换客户端后，在新读取完成前仍会保留旧条目和清空确认，复制失败也没有错误处理。

## Decision

把历史类型移入纯模型，保留旧模块的类型转导出。公开 `useClipboardHistory` 和 `useClipboardHistoryCloud` 及选项、状态和现有控件 props；组件只持有展示与事件绑定。

本地读取继续按页面、客户端、开关和 revision 隔离。写入的所有者不含页面：删除和保存开关后的同步可以跨页完成。操作互斥与错误守卫复用 `useAsyncActionRunner`，保留读取序号防止旧列表覆盖操作结果。更换本地所有者时清除旧条目与清空确认。复制保持独立于列表写入，失败经当前客户端的错误回调报告。

云端可用状态与发送按请求函数、历史可见性和路由独立管理；只在挂载或所有者变化时查一次，不轮询。发送复用 runner 的同步互斥，不截断超过 UTF-16 上限的条目，沿用账号、中继与设备批准的错误映射。

- iOS 页面代次、Android 历史保留和目录句柄分别属于原生页面与存储约束，本片不改变它们。

已检索 proposed、implemented 和 rejected，未发现同范围提案或需要完全吸收的旧笔记。

## Alternatives considered

- 只导出已有控件：最少迁移，但类型继续依赖 JSX，读取、操作与云端状态无法独立使用。
- 把本地和云端放入一个 hook：调用处更短，但它们的所有者和忙碌状态不同；本地操作要跨页完成，云端发送必须随路由和页面能力失效。保留两个领域 hook，展示处组合。
- 将页面纳入写入代次：规则表面上更统一，但已有整页回归要求离页后返回仍接收本次删除和同步结果；页面只能控制读取，不应取消同客户端的已发出写入。

## Verification

公共 hook 可独立操作本地历史及云端发送；控件不持有异步业务。先失败回归覆盖同批云端重复发送、替换客户端后的旧条目与确认，以及复制失败。保留原有跨页写入、自动同步、旧列表隔离、可用状态及路由更换回归。类型、构建、笔记与 quick 门禁覆盖共享包对桌面和 HarmonyOS 设置的接口。

## Consequences

收益是状态可以脱离控件复用，模型消费者不再依赖 JSX，三种错误与并发缺口有独立回归。代价是增加两个公共 hook 的兼容维护责任，并明确要求调用方提供稳定的客户端与请求函数身份。展示回调变化不能重置客户端状态或触发再次同步。已有写入可能在服务更换后实际完成，但迟到 UI 更新与错误必须被隔离。所有回归使用合成文字，不读取系统剪贴板；本片不改原生文件读写、权限或平台资源。
