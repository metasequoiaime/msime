# Agent Note: 翻页与以词定字共用偏好转换

Status: implemented

## Problem

输入页与快捷键页分别按对象引用判断是否写入 `word_character`。翻页复选框和 HarmonyOS 的恢复默认分别判断是否要让出以词定字按键。两个偏好类型、默认值及互斥转换分散在组件中，总偏好又内联声明一次以词定字字段。翻页复选框、以词定字按键选择和候选操作速查的选项与状态又各自位于 JSX，按键标签重复，无法独立复用同一组偏好的展示规则。

## Decision

以无 React 依赖的 `settings/candidate-paging-preferences.ts` 持有两份类型、默认值、翻页变更、恢复默认、以词定字开关及翻页存储补丁。控件与两个页面消费这份规则，原模块继续重导出类型和默认对象。总偏好直接使用叶子类型。

`settings/candidate-paging-options.ts` 持有桌面与 Harmony 手机的翻页选项、只读状态投影、已开启的翻页速查组合、以词定字按键标签与占用状态，以及 Linux 滚轮说明。三个组件直接消费，公共入口导出三项状态函数。桌面仍显示八项，Harmony 手机仍按原顺序显示七项并隐藏滚轮（第八项是后来加的左右键，见[左右键在输入串两端移动候选](../../implemented/feature/2026-10-16-left-right-candidate-navigation.md)）；隐藏不改写已保存的值。选项缺少可选滚轮键时只显示关闭，不补写。速查中的 `Page Up / Page Down` 与桌面控件的 `PageUp / PageDown`、手机的 `PgUp / PgDn` 分别保留；以词定字的两个按键标签共用一份字典。iOS 不显示按键选择的门控仍在组件里。

只在本次打开的翻页键恰好占用以词定字按键时关闭它；修改无关项不修复预先存在的冲突。无冲突时保留原以词定字对象引用，补丁只在引用变化时写入 `word_character`，不把未设置的默认对象写进文档。恢复默认使用同一个默认翻页对象；以词定字关闭时保留翻页对象，开启时关闭所占用的翻页键。可选的滚轮字段保持缺省；左右键字段缺失时按开启的共享默认读取，显式关闭仍可保存。

## Historical audit

按类型名、`defaultNavigation`、`onPagingChange` 和以词定字互斥检索活跃笔记，没有已有共享转换归属决定。[macOS 候选控件](../../implemented/feature/2026-10-12-macos-candidate-page-controls-toggle.md)持有滚轮默认关闭及宿主行为，独立保留；[日文混输](../../implemented/feature/2026-10-12-mixed-japanese-candidates.md)仅把滚轮的缺省字段当作兼容先例，与本片转换无关。原生按键路由、候选展开、上屏生命周期和 iOS 的硬件限制不由此模块负责。

## Alternatives considered

- **只抽取两个页面的补丁表达式。** 可以最少改动去掉完全重复的代码，但互斥规则仍由控件与恢复默认分别维护，默认值也继续依附 UI。共同模型把同一组偏好的转换留在一处。
- **每次变更都按整份翻页偏好消除冲突。** 模型更短且总能得到互斥状态，但会在修改无关键或关闭翻页时顺带关闭旧文档中的以词定字，改变现有行为。
- **按值比较以词定字对象以减少写入。** 可以跳过值相同的克隆，但当前页面以引用是否变化作为写入依据；保持引用语义，避免扩大持久化行为改动。
- **把所有翻页标签合成同一份表。** 按键身份只有一套，新增键时容易同步，但桌面、手机和速查的标签与排序各有现行语义，强行统一会改变页面。保留三份不同用途的表，只共享同义的以词定字标签与纯状态生成。
- **只移动常量，状态映射留在 JSX。** 改动更少、渲染就近可读；但禁用和过滤规则仍依附 React，其他调用方无法直接获得可用按键与速查。叶子模块同时持有对应的纯投影，不吸收控件布局与交互。

## Consequences

原导出、默认对象引用、类型可选性、补丁字段和控件行为保持。收益是两页补丁和控件与恢复默认的冲突规则只有一份；代价是新增一个纯偏好转换模块。变更对象沿用对象类型，保持旧回调接收对象与 `Record<string, unknown>` 的兼容性。

选项模型另增加一个运行时叶子模块；翻页和以词定字每次渲染仍生成新数组，速查只过滤自己的五种组合键，滚轮和箭头继续由独立行显示。组件不再持有这些表和状态映射；控件布局、iOS 门控及写回链路不变。新增三项模型回归先因未导出 API 失败，落实后连同翻页转换、三个控件、Harmony 手机与快捷键页面组合共八文件 39 项通过；冻结输入验证可选滚轮不补写、隐藏值保留、占用状态跟随偏好与速查过滤。共享 UI 构建、Harmony 类型检查、修改文件格式与 lint 通过。

新增十项回归在空转换实现上有八项按预期失败，落实后十项通过；连同既有两种页面、控件、默认值来源和输入偏好测试为六文件、33 项通过。测试使用冻结的合成输入，核对两种冲突键、无关变更保留旧冲突、对象引用、可选滚轮字段、恢复默认和按引用生成补丁。真实输入页面另有九项集成测试通过，覆盖互斥、保存、滚轮及快捷键展示。桌面构建与 Harmony 类型检查通过。

字段门禁从 35 组变成 34 组：移除的唯一配对是 `WordCharacterPreferences` 与 `Preferences.word_character (inline)`，它与同名类型配对合并；对照改动前的入口，受检 Rust 类型集合及字段可达性相同，不修改检查脚本或豁免。控件顺序、平台提示、可见条件、存储格式及原生按键处理不变。
