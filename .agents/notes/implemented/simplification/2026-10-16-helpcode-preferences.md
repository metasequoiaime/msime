# Agent Note: 辅助码公共偏好与方案目录

Status: implemented

## Problem

候选预览读取辅助码默认值、设置动作接收辅助码补丁、目录 hook 返回自定义表元数据，都依赖 `pages/helpcode-page.tsx`。这些契约实际由多个消费者共享，却跟页面渲染放在一起；七个内置方案的名称和顺序也只存在于页面中。

## Decision

`helpcode-preferences.ts` 统一持有辅助码类型、默认值和 `helpcodeSchemaOptions`，仅以类型导入依赖插件偏好。候选预览、设置动作、目录 hook 和包入口直接引用模型，页面保留旧类型和默认值的兼容导出。默认对象不复制，内置方案顺序和名称保持原样。

动态自定义表标签、缺失选中项回退、插件选项及互斥写回继续由页面处理。标签一致性检查从新模型读取内置目录，仍与原生宿主和固定参考来源比较。

## Alternatives considered

- **只导出页面内的方案数组**：修改最少，但预览仍通过页面加载默认值，类型消费者也继续依赖 UI 层，不能解决已有依赖方向。
- **同时抽取动态选项与写回逻辑**：能进一步减少页面代码，但会引入新的函数契约和更多迁移点；这些逻辑没有其他消费者，本次只迁移已经共用的数据契约。

## Consequences

模型没有 React 运行时依赖，多个现有消费者共用一个默认值来源。页面公开接口、偏好格式和对象缺失时的默认行为不变。后续修改方案列表必须同步标签检查和模型测试，修改默认值须验证候选预览与设置页。

历史笔记检索中，[辅助码目录 hook](2026-10-14-helpcode-catalog-hooks.md) 负责异步加载，和本次的类型归属部分重叠但决定不变；[五笔 86 辅助码](../feature/2026-10-09-wubi86-helpcode.md) 负责跨平台方案与来源，不被本次迁移替代。
