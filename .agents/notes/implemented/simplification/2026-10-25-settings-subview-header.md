# Agent Note: 抽取设置子视图标题栏

Status: implemented

## Problem

词库详情、插件详情和自定义双拼编辑器都直接绘制 `settings.subViewHeader` 与 `settings.subViewTitle`，其中插件和双拼还重复绘制返回按钮。标题层级、返回按钮的禁用与焦点标记分散在不同页面，其他共享设置子页无法复用同一套标题栏契约。

## Decision

公共 `SettingsSubViewHeader` 统一渲染设置子视图的 `h2` 标题和可选返回按钮。返回配置显式传入标签、无障碍名称、回调、禁用状态、按钮引用和可选数据标记；调用方继续决定历史返回、确认逻辑和焦点恢复。词库详情、插件视图和自定义双拼编辑器都消费该组件，保留原 class、文案、`data-plugin-back` 和返回按钮事件。

## Verification

独立标题栏测试先在公共导出缺失时失败，完成实现后 2 项通过；设置、插件、词库和双拼相关测试均通过。测试覆盖无返回标题、返回按钮的禁用状态、无障碍名称、动态数据标记、`ref` 转发和点击行为。

桌面 TypeScript 类型检查、改动文件格式检查和仓库 lint 通过；lint 仅报告两个未改动文件的既有未使用导入警告。未修改原生宿主、文件读写或网络契约，因此不需要 Android 设备验收。

## Alternatives considered

- **只抽标题容器，保留各页返回按钮。** 接口更小，但插件和双拼仍复制同一返回按钮语义，焦点和禁用属性容易漂移，因此不采用。
- **把返回历史与确认逻辑放进组件。** 能进一步缩短页面接线，但会让标题栏依赖插件历史、编辑器脏状态和页面路由，越过设置外壳的状态边界，因此不采用。

## Consequences

设置子页不再重复维护标题栏 DOM，公共组件可以脱离页面状态独立验证和复用；代价是调用方需要显式传入返回按钮配置。组件只负责静态标题栏和属性转发，返回数据标记与引用仍由调用方声明，编辑器的异步确认、插件历史和词库详情历史保持原有归属。
