# Agent Note: 抽取设置社区导航分流

Status: implemented

## Problem

`packages/ui/src/index.tsx` 同时负责根据社区客户端能力生成分类标签、判断触屏社区页是否存在，以及把「浏览更多」入口分流到社区标签或功能页图库。入口还要处理没有皮肤服务时的词库回退。导航状态和设置外壳的页面模型混在一起，后续修改社区入口容易只更新其中一条路径。

## Decision

`packages/ui/src/settings/use-community-gallery-navigation.ts` 集中持有社区分类的能力投影和图库入口分流。它复用既有的 `useSettingsTabs` 与 `CommunityGalleryView` 契约：无范围的皮肤或词库浏览在触屏且存在社区页时切换到对应社区标签；「我的」范围、回复模板、桌面宿主或没有社区页时继续打开功能页上的完整图库；缺少皮肤服务时保留原有的词库回退。设置外壳只传入平台、服务能力、页面选择器和完整图库打开器，并继续消费同一个 `communityTabs` 结果。

## Alternatives considered

- **继续把逻辑留在 `useSettingsPageModel`**：改动最小，但社区能力投影、标签状态和入口分流仍会和整个设置页模型耦合，下一次社区入口变更还要在大文件中维护多段条件。
- **把标签分类和分流拆成两个纯函数**：能减少条件重复，但 `useSettingsTabs` 的选择状态仍留在外壳，调用方还要自己组合状态和动作，不能形成社区导航的单一边界。

## Consequences

社区导航规则有了独立可测试的 hook，设置外壳保留页面渲染和宿主能力组装；现有页面、历史记录和返回行为不变。hook 继续依赖设置标签状态，因此它不是无 React 的纯模型；分类标签的 `useId` 和选择状态仍按原生命周期保留。新增测试覆盖两类社区标签、范围图库、回复模板、缺少皮肤服务、桌面和缺少社区页的回退路径。
