# Agent Note: PR 的截图上传到 catbox 并嵌进正文

Status: implemented
Archived: 2026-11-02

## Problem

改了界面、图标或配色的 PR，审阅的人看不到改前改后长什么样。截图只留在作者本机（`~/msime-screenshots/<任务>/`），PR 正文里写的是本机路径或一句「已截图」，别人打不开。二进制图标的 diff 在 GitHub 上只显示裸文件：iOS 应用图标是不透明正方形、Android 自适应图标的前景层只有白色笔画，直接看都不像最终效果，审阅时容易误判。

把图嵌进 PR 需要一个能直接引用文件的外链。匿名文件站里有不少靠广告变现的（tmpfiles.org、file.io 一类），落地页上有伪装成下载按钮的恶意广告；随手挑一个贴进 PR，等于引导每个审阅的人去点它。

## Decision

PR 里的截图和效果图一律上传到 catbox，用它返回的 `https://files.catbox.moe/<id>.<扩展名>` 直链，以 Markdown 图片的形式嵌进 PR 正文。

- 改了界面、图标、配色或任何看得见的东西的 PR，正文「截图」一节必须附改前和改后的图，按真实尺寸、真实底色截或画；会被系统再裁剪的图标按裁剪后的样子给。不改视觉的 PR 在这一节写「无」。
- 上传命令：`curl -F reqtype=fileupload -F fileToUpload=@<图片> https://catbox.moe/user/api.php`。贴进正文之前把链接下载回来，确认返回的是图片、与本地文件逐字节一致。
- 只用 files.catbox.moe 的文件直链，不用 catbox 以外的匿名文件站，也不贴任何落地页链接。
- catbox 的匿名上传是公开的、删不掉：图里不能出现真实输入、账号、个人资料、本机路径或凭据。
- 本机截图照常保留，上传的是另一份。

规则写在 `AGENTS.md` 的「改动范围」，PR 模板 `.github/pull_request_template.md` 加了「截图」一节提示。

## Alternatives considered

- **只在本机留图，PR 正文写路径。** 最省事，也不往外发任何东西。但审阅的人看不到，作者以外的人无从判断视觉改动对不对，等于没附图。
- **用 GitHub 自己的附件（在网页上把图拖进评论框，得到 `user-attachments` 链接）。** 链接在 GitHub 域内、不经第三方，是最稳妥的托管方式。但它只能在浏览器里拖拽上传，`gh` 命令行没有对应的上传接口，在终端里开 PR 的作者和编码代理都做不到；要求先开浏览器会让这一步被跳过。统一用一个命令行就能上传的图床，所有 PR 的做法才一致。

## Consequences

- 收益：视觉改动的 PR 都能在正文里直接看到改前改后，二进制图标 diff 的误判可以靠效果图纠正；图床固定为一个已知可用、直接返回文件的服务，不再每次临时挑。
- 代价：图公开且删不掉，一旦误传含隐私的截图无法撤回，所以上传前的内容自查是硬要求；catbox 若停服或删文件，旧 PR 里的图会失效，本机留存的原图是唯一备份。
- 没有脚本检查 PR 正文是否附图，靠 `AGENTS.md` 和 PR 模板提示执行。
