## Problem

## Proposal

为 #8782 另建一条独立 Draft PR 作为交付跟踪入口，补齐最小复现、版本与环境证据，再按确认的责任路径加入代码、回归和目标平台验收。

## Alternatives considered

- **直接复制相邻平台修复**：可能快速覆盖相似症状，但没有该 issue 的独立复现和验证，容易把无关改动带入目标平台，因此当时不采用。
- **只在 issue 下追加调查评论**：无需创建分支，但不能形成可审查的代码交付边界，因此当时不采用。

## Acceptance criteria

- PR 正文关联 `#8782`，并记录该 issue 的平台、复现和验证边界。
- 责任路径确认后，在同一 issue 的实现切片中加入代码、回归和平台验收。

## Risks
