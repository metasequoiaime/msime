# Agent Note: 个人模型计数表复用已有数值散列

Status: rejected — 局部收益不足以证明解决真机卡顿，不承担可预测桶索引的代价

## Problem

真机九键每键词网格解码均值约4 ms。个人模型的六张计数表都以已经由完整词串算出的64位FNV键查找，标准哈希表又对该数值运行SipHash。模型上下文和每条有效转移会重复走这些计数表，输入内容并不需要在表中再次散列。

## Proposal

仅为私有 `CountTable` 改用保留数值键的 hasher，沿用现有二元备忘使用已散列键的做法。词串生成FNV键、完整u64键相等比较、计数饱和/删除、上下文、概率和浮点运算完全保留。没有模型格式或外部API变化。先做真机对照，无稳定收益则撤回。

## Historical audit

检索 `CountTable`、个人模型与SipHash，未找到同一计数表改动。[二元备忘entry](../../implemented/testing/2026-10-17-lattice-bigram-memo-entry.md)管理的是另一张数值评分表，部分相关但不替代。已否决的[静态参考概率复用](../../rejected/bug-fix/2026-10-19-lattice-personal-reference-rows.md)改变临时计算行，保留其收益不足和内存代价结论。本提案不增加模型计数或引用行。

## Alternatives considered

- 保留标准随机哈希：防范攻击者刻意制造哈希桶聚集更强，但会对已经混合词串的内部数值键重复散列；本提案仍以完整u64相等核对，不改变FNV自身碰撞语义。
- 缓存完整个人转移分数：能复用概率及对数，但需要绑定上下文、模型版本和参数，新缓存与失效协议更大。

## Acceptance criteria

计数表和原HashMap对照覆盖边界键、相同低位键、重复计数、饱和、删除、克隆和清空；既有个人模型及持久化测试通过；真机比较保留所有学习和候选设置，结果无益则撤回。

## Risks

可预测桶索引使刻意构造聚集的模型比随机哈希差。个人模型仍受既有转移上限和衰减约束；需要测量真实查询收益，不把局部散列省略外推为不卡顿。

## Experiment result

旧数值散列的相邻真机对照中，词网格解码均值3.93/4.08 ms、P95 10.61/10.56 ms；复用数值键的两轮为3.79/3.89 ms、P95 9.94/10.20 ms。整键P95仍为40.08/40.40 ms，旧组为40.99/40.86 ms。每轮279键，配置不变，后一次混入词块布局试验，因此不能将全部端到端差异归因于散列。个人模型5项既有测试和新增计数对照共6项通过，计数边界、低位聚集、饱和、删除和克隆结果一致。收益不足以承担可预测桶索引的代价，本提案及新增局部测试一并撤回，不声称不卡顿。
