# Agent Note: Android 空语音结果提示移到键盘浮层

Status: rejected — 键盘顶部不符合 issue 要求的手机屏幕顶部，且覆盖了要求保留的工具栏图标。

## Problem

Android 键盘内的语音识别没有录到声音、没有识别出文字或结果只剩标点时，提示会复用诊断行。诊断行属于候选区的纵向布局，显示和消失会改变工具栏高度；#11113 的截图显示工具栏会短暂变矮并抖动。系统识别的超时、无匹配、网络和配置失败还需要保留各自的错误说明。

## Proposal

空结果提示使用独立的 `VoiceEmptyNoticeOverlay`，挂在 `keyboardSurface` 顶边并水平居中。它使用黑色药丸和白字，隐藏时为 `GONE`，不参与候选区、工具栏或按键区的测量，也不拦截触摸。开始新识别、输入窗口收起、输入框结束和服务销毁时清除它；显示后沿用输入法提示的自动消失时间。

`ImeVoiceEntry` 给识别交付增加空结果标记：HTTP、本地模型和豆包的 `Failure.EMPTY`，系统识别的空回包，以及标点处理后为空的结果都标记为浮层提示；系统识别的 `ERROR_SPEECH_TIMEOUT` 与 `ERROR_NO_MATCH` 也走浮层。权限、麦克风占用、网络、超时、服务和配置错误继续走 `notice`，避免把需要用户处理的长错误挤进键盘顶部。

## Alternatives considered

- **继续使用诊断行**：改动最少，但诊断行参与键盘测量，无法满足提示出现时工具栏高度保持不变，因此不采用。
- **所有语音错误统一移到浮层**：位置稳定，但会把网络、权限和配置错误与空结果混在一起，且改变既有错误提示的阅读路径，因此不采用。
- **使用独立 `PopupWindow` 或输入法子窗口**：可以脱离键盘布局，但需要额外处理输入法令牌、浮动键盘、旋转和销毁时机；键盘表面已有覆盖层，直接复用它的生命周期更稳定，因此不采用。

## Consequences

空语音结果出现和消失不会再推动工具栏或按键移动，提示仍有无障碍实时区域和原有自动消失行为。识别结果交付增加了一个只在空结果路径使用的布尔契约，设备测试的反射调用必须随签名同步；提示本身只在键盘窗口可见时使用浮层，窗口不可见时仍回退到 `Toast`。
