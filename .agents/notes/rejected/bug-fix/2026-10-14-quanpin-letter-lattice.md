# Agent Note: 自动全拼以字母位置表达词网格边界

Status: rejected — 三轮字母位置图试验没有首选净收益，最终首选正确数 857→854，不采用生产改动。

## Problem

#7583 的合法读法跨过主切分音节边界时，词网格没有对应的边。既有跨度试验用主音节列承载其他读法，不能正确表达不同音节数，也覆盖不到落在主音节内部的词边界；最终没有首选净收益。

## Proposal

自动完整全拼且存在歧义时，使用原始字母位置作为网格列，原读音的词边保留，完整音节图提供可达的其他词边。每条词边用自己的音节数计分，并扣除音节奖励与均匀完整音节先验，最终加回原读音的统一常数，让不同音节数能够比较；明确撇号、双拼及改字保持现有音节网格。纠错边通过原音节到字母位置的映射进入同一图，不把纠错权限混入合法边界选择。

继续使用既有束宽、终点候选数与每词查询上限；新增边查询必须有明确预算。先完成合成边界与上屏回归，再用同资源的完整句子、词和延迟配对评测检验能否采用。没有质量收益时撤回，不以单例改善作为完成。

## Trial evidence

仅去掉音节奖励的第一轮在同一 1,477 句上首选 .580→.555、top-5 .869→.829、found .927→.879，13 条改对、51 条改错。全部改对的字数与主读音相同，改错中多数新增一个字。每词代价不能代替音节切分先验，因此第二轮用完整音节集合大小的自然对数作为每音节先验；原最少音节切分的硬选择变为可比较的有限代价，固定音节路径仍只差同一常数，不按评测 ID 特判。

均匀完整音节先验的第二轮仍没有首选净收益：12 条改对、13 条改错，top-5 .869→.861、found .927→.918。下一轮在原终点预算内保留原音节图的路径，只允许联合图最佳不同句子竞争原末位；低于原末位的新增句子不挤掉原路径。它检验的是字母图的新边界覆盖是否能在保留原候选覆盖后有收益，不扩大终点数。

五个合成图测试覆盖主音节内部词边界、不同音节数、原路径分数、重复边和纠错位置映射，在前两轮通过；第一轮经 SQLite 词库查询的合成回归也通过。完整引擎/runtime、golden、三种键面词级对照和延迟没有继续运行：句子质量已经否决，不以窄测试通过作为采用理由。

撤回四份生产文件和新增测试；本试验只保留否决记录及与旧跨度试验的关联，不发布、不替换系统输入法，不把新的候选覆盖宣称为 #7583 修复。

后续候选方向应同时表达切分先验与候选静态证据，并检验运行时独立模型对它们的取舍。`chinese-ime-lm` 的固定提交 `7e024873` 明确用逐字均值比较回答整个按键串的候选，并允许不同字数；不能只因本试验长候选抢先，就把合法读法按字数排除，或擅自把该接口改为总分。源库提供 `log_probabilities` 供与引擎证据混合，混合需要明确的元数据和接口契约，不在本次失败试验中偷加。

后续[独立排序的静态证据](../../implemented/bug-fix/2026-10-14-rerank-static-evidence.md)保留本篇否决结论：现有固定音节图的混合收益优于复装字母图。本篇的失败源码不随新方案进入生产。

## Alternatives considered

- 再次只在主音节跨度内查询替代词条：查询复用简单，但词边仍不能落在主音节内部，已否决的覆盖与剪枝问题不能靠换一个缓存解决。
- 枚举整句切分并独立解码：复用既有解码器最容易，但重复图查询和路径乘积使延迟难以约束，优先用一个位置图合并共享前缀。
- 更改最少音节的同分规则：代价低，但把一种合法读法系统性置后，不使用词条和上下文，不能作为全局修复。
- 把独立模型均值直接改为总分或排除不同字数候选：可压低新增长读法，但与固定上游的混长完整按键契约相反，还会把合法读法按长度排除；本次不通过改弱比较集来消除回退。

## Acceptance criteria

合成测试覆盖主音节内部词边界、不同音节数、规范读音、明确撇号、纠错位置与选择上屏。完整 engine/runtime、golden、同一锁定资源的质量与延迟对照支持改动后再提交生产代码。

## Risks

更多词边会争夺束搜索位置；新图的分数与字母列预算可能影响已有正确读法。需要报告逐条改对和改错，不仅看四舍五入的比例。新图还可能增加冷查询和常驻缓存，必须测量。
