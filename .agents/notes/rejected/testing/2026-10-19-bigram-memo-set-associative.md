# Agent Note: 二元备忘同容量组相联的命中率

Status: rejected — 完整轨迹中位耗时比2.4322，未通过预设0.95预算，撤回测试原型并保留生产HashMap

## Problem

[低位直接映射诊断](2026-10-19-bigram-memo-direct-map.md)在32768槽比现有HashMap多12806244次未命中，碰撞淘汰可能抵消一次下标的收益。全清策略又让HashMap每臂清空502次；每组保留多个完整键可能减轻冲突且不需要全清，但没有轨迹证据。

## Proposal

仍只做诊断，在固定81例的每个备忘对象旁独立模拟32768个键槽的2路、4路、8路组相联，每组按低位取组、逐一核对完整u64键；命中不刷新，未命中优先填空，组满按轮转位置覆盖。再单独模拟同容量4路LRU，命中移到组首、满组淘汰最久未访问键。所有模拟只按表地址失效，不随HashMap全清；原HashMap继续返回全部评分。

预先要求候选未命中数不高于现有HashMap，且至少一个候选减少10%，才考虑生产替换。均未通过就记录否决，不扩大容量寻找结果；诊断源码撤回。若通过，性能预算、独立参考、红绿测试和缓存语义变更另行形成实施决定。

## Historical audit

已检索直接映射、组相联、LRU、BigramMemo及容量淘汰，没有相同候选。[entry决定](../../implemented/testing/2026-10-17-lattice-bigram-memo-entry.md)仍持有生产实现；[低位直接映射](2026-10-19-bigram-memo-direct-map.md)保留其负结果，本片只调查冲突时每组多保留几个完整键，没有翻转该结果。其它评分行和键构造决定继续保持。

## Alternatives considered

- 每组轮转：只在未命中写游标，命中没有年龄维护；可能淘汰热键，因此并列观察4路LRU。
- 每组LRU：能保护刚用过的键，但每次命中更新年龄；即使命中率通过，也须在完整生产计时中承担维护成本。
- 更大的直接映射表：实现最短，但以额外内存补冲突；本轮保持32768键槽比较淘汰策略，不扩大预算。

## Acceptance criteria

每臂调用、HashMap命中/未命中及清空计数必须与前次诊断相同，记录四种候选全部数据，不挑选流段。候选至少减少10%的未命中才进一步设计；数据只证明命中率，不能代替计时。采集后恢复decode.rs并验证笔记及quick，原16ms预算保持。

## Risks

额外模拟扰动时间，LRU模拟移动完整键也不代表生产实现成本。固定合成集合不保证其他输入分布，未来实现必须覆盖高冲突及全未命中负载、表切换和内存上界。

## Diagnostic evidence

与直接映射相同的基线、资源和完整访问流，两臂均110796740次调用，现有HashMap命中94315035、未命中16481705、清空502次，逐项与前次相同。2/4/8路轮转未命中20059145/15499315/13484280次，4路LRU为13635388次。8路轮转和4路LRU分别减少18.19%/17.27%，达到进一步设计门槛；2路和4路轮转未达10%。所有模拟只是计数，不支持性能结论。

## Prototype budget

先单独验证8路轮转，命中不写年龄；4路LRU每次命中需要移动条目，保留为备选，不凭命中率直接接入。捕获同一固定81例第一臂的全部110796740个u64键，临时轨迹只来自公开合成集合，记录哈希后不入库。冻结当前HashMap完整访问和容量全清，8路原型逐键比较原始评分位模式，然后同进程6对、交替先后回放整条轨迹（各臂独立冷缓存），中位新旧比必须小于0.95；另对全命中、小热集、连续未命中及冲突集各21对、最快臂至少20ms，中位比均小于1.05。原型若失败就撤回，不把查表次数减少等同于访问变快。全部通过后再设计生产替换及冻结测试迁移，不提前改现有BigramMemo类型。

原型只从键构造完成之后开始计量，两臂都省略相同的FNV字节循环；保留Arc地址失效、缓存读取、精确表查找、写入和淘汰，不把这种局部计量当作完整BigramMemo或端到端成绩。8路原型每组保存8个连续完整键、8个评分、已用长度和轮转位置，共4096组；空槽按轮转次序填充，表地址变化重置。调试红测试在原HashMap委托实现上真实失败（32770对32769次查表），接入原型后两项功能测试通过。

## Measured outcome

完整轨迹每次逐键结果位模式与冻结HashMap相同，共110796740次；原底表查询16481705次、候选13484280次，与诊断一致。正式第四轮完整运行27.12秒、退出101：四个控制均通过1.05门槛，但完整轨迹六对排序后的第4个新旧比为2.4322105966，远超0.95。六对比值为2.329281、2.332169、2.386126、2.432211、2.441311、2.467159；不重测寻找通过结果。

控制full-hit/small-hot/miss-stream/conflict中位比分别为0.815159、0.545388、0.971807、0.308309。控制先填充再计时，不含初始化和析构，不能用其加速覆盖完整轨迹退化。完整轨迹包括冷缓存初始化、查表、替换及析构，但两臂省略相同FNV键构造。使用现有测试CountingAllocator委托System，计数开关关闭，没有把它冒充普通发布分配器；局部否决不外推端到端回退幅度。

前三轮均因观察到外部构建而作废，包含第三轮已经输出完整结果、最后一条监测才发现2个clang的情况，不能采用2.1913那轮成绩。第四轮26次每秒监测均未观察到cargo/rustc/clang，一分钟负载11.46–14.66；不代表独占机器，也不能排除采样间短进程。全部84对控制、6对轨迹、诊断计数及四轮监测见[原始数据](../../../../docs/measurements/2026-10-19-bigram-memo-cache-rejected.json)，[原型快照](../../../../docs/measurements/2026-10-19-bigram-memo-associative-prototype.rs.txt)仅为可审计文档，不接入编译。
