# Agent Note: 简拼编码只物化最终页

Status: rejected — 正常分配器的有效输入存在 局部墙钟耗时回退，只保留独立预算预检

## Problem

固定 `3cef2fd243` 的实际九键按键采样包含 `initials_codes` 的 `flat_map` 和字符串分配。现有实现逐层创建所有前缀页；例如 `999999` 超出 1024 个编码时，前五层已经分配完成后才拒绝。每次刷新仍需保持原有编码数量、顺序和拒绝边界。

## Proposal

先按各键合法首字母数量预检完整乘积；无效键或超出原预算时直接拒绝。有效输入预留最终页，构造第一条编码，随后从前一条编码的末位向前进位并重建后缀，只为最终字符串分配。末位的后继字母预先写入 26 字节栈表，其余进位保留原字母顺序，避免每一条结果都重新扫描末位字母表。空输入继续返回单个空串，包括限额为零的情况。原安全字符串操作足够，不引入递归、固定长度限制或 unsafe。最终页容量改为精确编码数；字符串容量保持输入字节数，SQL 接收的文本和顺序保持。

## Existing decisions

按 `initials_codes`、简拼编码、声母组合检索活跃笔记。没有同一决定；[组码前缀](../../implemented/testing/2026-10-16-nine-key-code-prefix.md)负责候选读法检查，[缓存排名](../../implemented/testing/2026-10-16-nine-key-cached-rank.md)负责排名求键，二者部分相关但不改变其契约。没有完全吸收或过时提案。

使用同仓库 `letter_prefixes` 作为编码展开参考，使用 [Rust String](https://doc.rust-lang.org/std/string/struct.String.html) 的 `pop`、`push`、`with_capacity` 和 [Vec](https://doc.rust-lang.org/std/vec/struct.Vec.html) 的容量契约。标准库开源实现可核对最终字符串克隆与容量。

## Alternatives considered

- 逐层接管父编码：能省一部分分配且容易保留原循环，但仍有中间页和被拒绝时已分配的前缀。
- 递归深度优先输出：直接表达笛卡尔积，但私有 helper 原先可以处理很长的单选择输入；递归会新增栈深限制，使用迭代进位。
- 保留原实现：改动风险最小，但超预算路径仍先创建上千个无用字符串；仅在局部完整入口配对计时没有收益时保留现状。

## Verification

真实红测试中，旧生产入口在 `999999` 被拒绝前仍申请 1391 次，零分配断言失败。新入口四项测试通过：枚举九键、十四键和三个内置双拼表的全部一至三键组合，限额取 0、1、结果数前后边界、1024 与 `usize::MAX`；比较全部有序文本与字符串容量，逐次分配不增加。另覆盖 1024 条边界、末尾非 ASCII、非法键及 4096 位单选择串。有效非空输入严格只分配最终页及每条字符串。

| 输入 | 旧/新申请次数 | 旧/新逻辑请求峰值字节 | 旧/新保留字节 |
| --- | --- | --- | --- |
| `2356` | 136 / 82 | 4272 / 2268 | 3396 / 2268 |
| `99999` | 1391 / 1025 | 37120 / 29696 | 29696 / 29696 |
| `999999` | 1391 / 0 | 38400 / 0 | 0 / 0 |
| `99999!` | 1391 / 0 | 38400 / 0 | 0 / 0 |

逻辑请求量来自线程局部分配器，不含分配器内部暂存，不能当作 RSS。完整引擎 2193、golden 31、runtime 294 通过，34 项忽略（含新增手动计时）；两 crate 全 targets Clippy `-D warnings`、fmt、差异与笔记校验通过。真实模型使用 `MSIME_NEURAL_MODEL_DIR` 指向固定资源，不用评测专用目录冒充完整 `MSIME_EVAL_RESOURCES`。

独立只读审查机械核对旧函数正文与 `4007628d74` 一致，确认 ASCII 唯一字母约束、进位和容量行为，无阻塞或重要问题。配对计时包含构造和析构，预设每形状新/旧中位比不超过1.05。第一版完整 quick 和固定质量评测通过，但不能抵消下面的正常分配器 局部墙钟耗时失败；第二版在 局部墙钟耗时失败后不再继续门禁。

## Intermediate entry

第一版未缓存末位后继。测试分配器的完整局部矩阵通过且未观察到并行编译，但正常分配器的完整正文提取程序在两个有效双拼四键形状超过 1.05 门槛：米旮旯2 `6666` 为 1.056651、辜氏2 `2222` 为 1.064071。该轮37次环境采样里4次有并行编译，最多2个，且分布很宽；不能直接归因于环境后接受。

保持全部形状和门槛，将单臂校准时长从10ms延长到50ms后重新比较整表，米旮旯2 `6666` 仍为1.076236，p10/p90为1.053758/1.098654，确认正常分配器局部墙钟计时仍存在回退，尚无对应线程CPU测量。其余形状和完整失败结果保留，最终数据在下节汇总。原型每行都重新查询并扫描末位字母表，这是当时怀疑的额外成本，未单独测量证明；第二版入口预计算末位后继后重新验证，不放宽门槛。

上节完整测试、quick及质量数据来自第一版；第二版末位缓存未通过局部墙钟门槛即放弃，未将第一版验证当作第二版结论。

## Consequences

进位顺序、空输入零预算、长单选择后缀和字符边界需要显式回归；预检额外扫描在短输入上可能增加成本。局部节省不能证明九键端到端提速或 16 ms 达标。

## Rejection

第二版预计算末位后继仍未通过同一37形状、31对、单臂至少50ms的正常分配器矩阵：九键 `9999` 为1.127729、`99999` 为1.060460；米旮旯2 `6666` 为1.297959（p10/p90 1.036963/2.087872），米旮旯3 `2222` 为1.350234（1.187501/1.469936），辜氏2 `2222` 为1.280515（1.126564/1.404482）。125次环境采样中30次有编译，最多4个；环境噪声存在，但没有足够证据接受该实现。两版都不进入生产。上文分配收益和门禁属于失败实验，不能作为最终改动验证。

改为[完整预算预检](../../implemented/testing/2026-10-16-nine-key-initials-preflight.md)，保留原有成功展开逻辑，不以分配计数下降代替 CPU 验证。
