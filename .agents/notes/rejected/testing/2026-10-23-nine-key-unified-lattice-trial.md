# Agent Note: 九键无约束数字图原型的质量与延迟试验

Status: rejected — 当前原型有首选收益，但丢失已有句子候选且引入首字母选择分配回归，不接入生产；完整数字图提案保留。

## Problem

[统一数字词网格提案](../../proposed/feature/2026-10-09-nine-key-digit-lattice.md)希望消除九键逐切分解句的重复成本与切分上限。本轮只验证无锁定、无手动切分、无首字母、无模糊音、无筛选、无搭配模型的普通九键；不能覆盖全部数字的输入、14 键和九键双拼沿用旧路径。不能把这一子集的收益视为完整提案落地。

## Proposal

数字位置作为列，完整音节作为段；单字精确查询，长词按前两个完整音节查询再核对剩余数字，每个精确读法最多 32 行、最多 7 音节。复用现有 n 元模型和束搜索，在搜索前按每条边的音节数消去奖励，输出再恢复现有权重格式。逐切分查询只取词库行，统一图负责整句。原型另建不含整句的候选缓存，与原整句缓存分别保存。

首版终点输出 12 条；发现 found 下降后改为整句备选开启时输出默认束宽 32 条，否则仍取 `MAX_RERANK_PATHS`。没有改评测集、词级基线、束宽或测试阈值。

## Alternatives considered

- **接入当前 32 条版本**：首选和单轮延迟都有收益，词级没有首选回退；但已有句子候选丢失、缓存切换分配回归尚在，缺少完整质量和交互验证，不采用。
- **只对长数字串启用**：可保留短词缓存行为，也符合已有长串处理界限；但它改变新旧路径切换位置，仍需重测，且不能补回长句丢失的候选。本轮不以新增阈值绕过失败测试。
- **继续支持首字母约束或共享缓存**：可以消除当前模式切换问题，是重访时的可行方向；涉及约束图和缓存契约，单独验证，不能由本轮无约束测量推断正确。
- **保留逐切分生产实现**：重复解码成本仍在，但不引入当前原型的候选与交互回归，作为本轮结果采用。

## Acceptance criteria

重新采用数字图时必须同时验证锁定、切分、首字母、模糊音、筛选、模型和词典版本失效；解释并覆盖候选替换，保持原有分配预算；跑完整引擎与 golden、九键各句子集、词级分档及无构建干扰的交替延迟对照。不得只用总体 found 抵消局部丢失，不得把单轮 p95 下降写成 16 ms 达标。

## Risks

共享束中的不同读法争夺同一预算，不再等价于每条切分分别保留备选；增加终点数只恢复总体 found，不能证明原候选仍被保留。原型没有给出覆盖、缓存成本和束宽之间的可靠取舍，因此本轮停止扩大试验，保留完整提案与可复现证据供后续设计使用。
