# Agent Note: 词网格二元评分行复用前词散列

Status: rejected — 两轮配对计时均未获得所有形状通过回退预算的证据，候选暂不进入生产路径

## Problem

固定 `59f20f26b5de69723afbdd3a89b157b2dfeb07ad`、资源代次 `7356c4a452d8ba15475c0e57f134fccf7b7cbe267440461541c74d09b11b6ffe` 和模型 pin `0f19789abbad5aa887e3b27088bf168acf6e9098` 的三十秒九键采样中，`decode_graph` 与模型 `Matrix::dot_row` 分别有 3998、3662 个栈顶样本。解码器最热指令覆盖二元行填充、散列备忘查询与行索引。每条评分行内前词相同，现有 `bigram_key` 却为每条出边重新散列完整前词；热备忘也没有省去这段串行字节循环。采样运行的延迟受观察干扰，不作为无采样门禁成绩。

## Proposal

二元评分行创建时以原 FNV 初值混入前词与原分隔符一次，再按原出边顺序混入后词。使用模块内有类型的前缀，限制新接口作用域；原单项 `bigram` / `bigram_key` 仅供测试旧参考，正文不变；`lattice` 是 crate 私有模块，不影响 crate 对外接口。保持散列算法、落盘格式、查表、备忘容量与失效顺序。没有表时不创建前缀。个人模型仍取得相同原始二元分，评分算术与假设展开保持。

## Historical audit

按 `BigramMemo`、FNV、前词散列与二元行检索活跃笔记，没有同一前缀复用决定。[二元评分缓冲](../../implemented/testing/2026-10-11-lattice-bigram-lazy-reserve.md)负责行生命周期，[桶内键切片](../../implemented/testing/2026-10-15-ngram-bucket-key-slice.md)负责查表，两者部分重叠但不管理键构造。现有 `fnv1a_mix`、`fnv1a_separate` 与 `fnv1a_words` 是同仓库实现参考，保持算法与字节契约。

## Alternatives considered

- 每个前词/后词都保留跨查询散列缓存：可进一步避免重复读词面，但要新增缓存所有权、容量和失效规则，当前行内复用无需额外堆状态。
- 先改九键候选缓存排序键：可减少同一候选的反复解析，标准库提供稳定的 `sort_by_cached_key`；最新采样中排名键占比显著小于解码和点积，先处理已定位的二元行重复工作，排序另行评估。
- 修改模型点积内核：覆盖另一个大热点，但模型参考归上游维护，且数值累加顺序影响质量；本项的行前缀复用保留每个最终键与分数。

## Acceptance criteria

先以 debug 测试专用计数器观察旧实现的字节预算失败；计数器完全不进入 release 测试与产品计时。覆盖有无备忘、空表、空后词、表切换与容量清空，最终散列键、分值位模式及备忘状态必须一致。既有完整路径矩阵继续通过。release 同进程旧新配对每形状四十对、交替先后，最快批次校准至少五十毫秒，中位新旧比必须小于 1.05。固定资源质量 JSON 保持。两 crate 完整测试、Clippy、fmt、notes、quick 与 pre-push 门禁通过再交付。

## Risks

每行只保存一个机器字散列，不增加堆容器；只有一条后词的行无重复前缀可省，全空后词行可能多算一次前词，须纳入回退计时。已有公开键构造继续保留，增加一个模块内分批构造入口和测试维护成本。该局部减少不代表九键 16 ms 已达标；模型点积和其余展开仍需独立处理。

## Experiment outcome

候选最强的理由是：同一评分行逐后词重算前词是可确定消除的重复工作；debug 红绿验证在宽度 1/4/32/65、有无备忘及冷热两轮中精确减少 `(width - 1) * previous.len()` 字节，键、分数位模式、备忘状态与分配请求均相同。首轮若干有表密集图也测到约 2%–8% 局部改善。

但预设门禁要求每形状中位新旧比严格小于 1.05。两轮分别耗时 269.96、384.81 秒，均正常完成全部 36 形状并以断言失败退出（101）。首轮无表 4/4 为 1.109578，p10/p90 为 0.797462/2.076336；第二轮同形状为 0.994056，却有四项超限：无表 12/32 为 1.072977（0.216130/2.838996），有表无备忘 1/1 为 1.081639（0.417946/2.168475），热备忘 1/1 为 1.061155（0.717500/3.261226），热备忘 12/8 为 1.158689（0.726572/2.777720）。

主机有 10 个逻辑核，观察到的 load average 约 19–62，第二轮期间约 57；任务自身没有并行构建、质量评测或其他采样。负载与大幅分位波动削弱了计时可信度，不能据此断言候选必然更慢，也不能认定所有失败均来自环境。不能跨两轮挑选每个形状的较快值拼成通过。本轮不继续重试计时。

产品 `decode_graph`、`BigramMemo::score`、`bigram` 与 `bigram_key` 恢复固定基线；候选完整解码和 `score_key` 冻结在 `decode_prefix_experiment_tests.rs`，只由 `cfg(test)` 模块接线。`BigramPrefix` 与构造入口也只编译到测试。固定旧参考在 `decode_prefix_legacy_tests.rs` 独立保留，debug 字节计数不进入 release 测试或产品。两轮计时是在候选仍接入生产入口时取得；隔离后测试函数入口不同，保留的 ignored benchmark 供将来另行评估，不能把它当成已经跑过的相同入口。

隔离后的路径/分配矩阵还覆盖个人模型、三元模型和附加图。生产路径恢复基线，因此不重复运行优化候选的端到端质量及四轮延迟，也不作这两项通过的结论。九键 16 ms 目标仍未通过；后续继续评估解码与模型点积热点。
