# Agent Note: 二元评分行只核对一次表身份

Status: rejected — 未取得有效配对耗时证据，候选不进入生产；本记录不证明方案更慢

## Problem

九键 16 ms 目标仍未达成。最新固定基线 `1330287680040ab5a0ddbc36029c3f09dfc47138` 的普通 release 诊断仍将模型矩阵、二元备忘和查表列为主要入口。`BigramMemo::score` 对同一评分行的每条出边重新核对同一表地址，存在可确定减少的重复校验。

本轮资源提交为 `128a332cabc5fa42b1cf5f827033ad5697ff528b`，代次 `7356c4a452d8ba15475c0e57f134fccf7b7cbe267440461541c74d09b11b6ffe`，资源锁内全部 12 个文件尺寸及 SHA-256 相同。合成评测仍为 81 例、每臂 1791 键、5 例预热和原 16 ms 预算。

## Proposal

私有行填充入口先按旧顺序输出没有有效键的正零；遇到首个有效键才核对表身份并执行原失效，然后用原 entry 算法处理余项。全空行不改变备忘身份；满容量命中不清空，未命中才清空。键仍逐词完整 FNV 构造，不采用前缀散列复用，不增加缓存、字段或原始评分的复用寿命。原单项方法仅供测试保留，正文与基线相比只多 debug 计数接线。

## Alternatives considered

- **解码开始就绑定表**：分支最少，但空图、空词和空表原本不改变备忘身份，提前清空会破坏状态契约，候选选择首个有效键才核对。
- **行绑定标志逐边惰性检查**：保持延迟失效容易表达，但仍在热循环检查状态，候选改为先消费首个有效键再处理余项。
- **直接重启完整数字图**：有减少逐切分解码的潜力，也有单轮首选收益；当前原型会丢失已有句子候选并增加首字母切换分配，仍需独立设计。
- **按确定性计数减少直接接入**：可以确认少做身份校验，但首键拆分、余项迭代和函数布局也有成本；未取得完整解码耗时证据时保留现状。

## Evidence

启动后前 20 秒的自有进程采样共有 14461 个主线程样本，其中 972 在 `type_case` 外。逐键路径按最深已知入口归类为词库 3499、分配 2881、模型矩阵 2259、二元备忘 1296、解码 1191、九键 800、n 元查表 728、复制/比较 587、模型其余 200、runtime 40、未分类 8；归类总和与原始栈一致。分配桶按调用栈符号归类，不代表已识别为不必要分配。

采样混合两臂、包含预热，并非覆盖完整 81 例的独占采样。107 次观察中 38 次见编译，load1 为 16.36–18.33。该轮带模型 p95 为 26.42 ms、423 键超过 16 ms，程序按原预算退出 1；这些受采样与外部构建影响的墙钟不能作为正式基线或新旧收益。

有效 debug 红测在第二列扇出 2 时核对表身份 3 次，目标为两条评分行各一次。候选通过四项定向测试；扇出 1/2/8/32/128 时身份校验均为 2 次。空词、空表、表切换、负零/NaN/无穷分值、满容量命中及缺失清空的值与状态保持。完整冻结解码的 640 配置各跑冷/热两轮，共 1280 次对照，路径字段、分数位模式、回调顺序及备忘键值、身份、容量相同。

普通 System 分配器 release 程序还停用了 KeyHasher 的测试 TLS 计数器，三项完整对照通过；构建后两处临时源码均逐字恢复。首次 probe 构建的测试闭包生命周期错误已修正，保留的错误日志不当作有效红测。最终 release 测试探针的冻结完整解码和旧单项备忘与固定基线机械核对一致。

预先约定 4/12 列 × 1/4/16 行 × 无表/冷备忘/热备忘，共 18 形状，各 21 对、交替先后、每臂校准至少 10 ms；每格中位比须 <1.05，宽行目标几何均值须 <0.98。正式运行前需连续 30 秒无编译且 load1≤10。180.5 秒等待终态未满足条件，172 次观察中 66 次见编译，load1 为 12.46–34.43，`timed=false`。没有配对样本、几何均值或性能预算失败，没有改门槛或重试找绿。

## Consequences

生产继续使用原单项评分入口，候选及新测试仅随精确补丁保存，不增加产品内存或代码路径。后续重访需先取得上述完整解码的有效配对成绩；现有确定性计数只证明减少了身份校验，不能证明净提速。默认九键 16 ms 目标继续未达成。最终文档门禁和 quick 结果以证据 README 及本轮 PR 为准。
