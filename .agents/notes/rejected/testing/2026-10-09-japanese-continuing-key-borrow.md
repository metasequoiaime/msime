# Agent Note: 日文待定补全借用两段查询键

Status: rejected — 合成 release 查询计时出现回退，采用保留原完整键比较的单缓冲方案

## Problem

`prefix_lemmas_continuing_with` 为每个非空后缀创建完整 `prefix + kana` 字符串，然后只用于二分与范围扫描。单后缀未命中仍分配一次；三个后缀命中的原测试为五次，其中三次是查询键。词库和调用方已经拥有两段文本，这些拼接字符串不会成为输出。

## Proposal

二分下界共用原循环，普通查询继续直接比较完整读音，continuing 非空后缀通过两段借用文本比较。先比较候选与前缀的等长公共字节段，有差异直接返回；相等且候选短于前缀时为小于，否则比较剩余候选字节与后缀。只切字节切片，不按任意字节切 `str`，保留原 UTF-8 字节字典序。

扫描范围通过 `strip_prefix(prefix)` 后检查剩余文本的 `starts_with(kana)`，与完整键前缀等价。空后缀仍走原分支，排除恰好等于 prefix 的读音；后缀顺序、重复和重叠后缀重复 ID、负成本、平局、限额、排名容量及最终排序保持。没有新增缓存、公开接口或文件操作。

## 既有笔记审计

[词条借用](../../implemented/testing/2026-10-09-japanese-lemma-borrow.md) 与[空排名存储](../../implemented/testing/2026-10-09-japanese-empty-ranking.md) 部分重叠，分别继续约束词库生命周期与按首次命中分配排名堆，本篇只消除 continuing 查询键；后续落地方案互链并同步仍成立的后果。它们的历史验证数字保持。[末行文本转移](../../implemented/testing/2026-10-09-japanese-final-text-move.md) 和其他日文转换笔记处理不同存储层，无关且保留。活跃笔记检索 continuing、suffix、lower_bound、后缀和拼接读音没有另一套查询键决定；注音后缀去重、拼音修正后缀路径与滑行文本拼接命中均属其他算法，保留。

## Alternatives considered

- 单个可复用拼接缓冲：实现直观，多个后缀只需一次容量分配；仍要创建完整键并反复复制公共前缀，两段借用可消除全部键存储。
- 字节迭代器 chain 比较：自然表达拼接顺序且无需存储；每字节迭代增加长公共前缀的处理成本，等长切片比较复用标准库批量比较。
- 保留原拼接：最容易阅读，但每个后缀独立分配没有输出用途。

## Acceptance criteria

旧实现预算失败是性能回归测试的起点；非空后缀未命中零分配，多后缀命中只保留排名堆与结果向量两次分配。固定旧拼接查询对照完整字段、重复 ID 与顺序；两段比较和二分下界在 ASCII、假名、汉字、emoji、短候选、空段和各字符边界处等价。完整引擎、golden、Clippy、笔记和 quick 的结果在完成验证后记录。

## Risks

候选短于前缀时不能直接以整段前缀比较结果继续比较后缀，否则会把短候选误判；只按字节比较避免不同宽度 Unicode 的切片 panic。重叠后缀本来会重复排名 ID，本篇不去重。两段比较增加分支，需测量相同合成词库的查询耗时，不把分配收益当作实际打字延迟承诺。

非空后缀不再创建临时键，未命中不需要存储，命中仅保留排名堆与结果向量。代价是一个私有两段比较函数与参数化下界循环，空后缀分支和所有权边界保持；普通 exact/prefix 查询仍用原单段比较。

## Rejection evidence

release 十批交替顺序、每批 1000 次的首轮中位耗时：16 条词库命中 2.399→2.713 ms、未命中 0.361→0.399 ms；1024 条命中 254.507→239.094 ms、未命中 0.831→0.920 ms。比较器长度检查前置并内联后，小词库命中 2.362→2.564 ms、未命中 0.365→0.417 ms，大词库命中 218.447→337.188 ms、未命中 0.860→0.900 ms。两段扫描和比较增加热点路径开销，零分配不足以支持采用。改用[查询内单缓冲](../../implemented/testing/2026-10-09-japanese-continuing-query-buffer.md)，保留原字节比较。
