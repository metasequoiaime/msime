# Agent Note: 回溯时计算词网格路径的错字边数

Status: rejected — 原生产入口的无表单边短图超出事前 5% 回退预算，产品保留累计字段

## Problem

`Hyp.typo_edges` 在每条展开边上读取、累加和写入，并占用一个机器字；比较器、剪枝、二元/个人评分均不读取它。其唯一消费者是最终 `SentencePath.typo_edges`，而回溯本来就访问每条图边，边本身已保存 `typo` 标记。

## Proposal

移除假设中的派生计数，在已有回溯循环中累计边标记，输出时保存到路径。保持所有边都计数，包括合成边的空词面，不用词数代替边数。前驱、图边、搜索展开、评分、束宽和平局排序保持。本机假设由 40 缩到 32 字节。

## Historical audit

按 `typo_edges`、错字边计数、假设布局检索活跃树。[起点标记复用](../../implemented/testing/2026-10-15-lattice-hyp-layout.md)去除重复判别状态，本项去除派生计数，两者部分重叠并互链；[列容量](../../implemented/testing/2026-10-15-lattice-column-capacity.md)减少预留条数，其旧参考补齐当时的假设和比较器，固定四十字节布局。[双拼纠错整句](../../implemented/feature/2026-10-09-shuangpin-typo-sentence.md)持有纠错准入与排序契约，本项保持输出路径的错字边数和全部纠错规则；[编码缓冲](../../implemented/testing/2026-10-15-shuangpin-typo-code-buffer.md)与[边收集缓冲](../../implemented/testing/2026-10-10-typo-edge-lazy-buffers.md)管理输入边的准备，与本假设布局无关。[二元评分缓冲](../../implemented/testing/2026-10-11-lattice-bigram-lazy-reserve.md)管理评分行，不使用路径计数。

## Alternatives considered

- 将计数缩为 `u8` 或 `u16`：仍可常数时间读取累计数，但引入输入长度边界与溢出约束，且字段对齐可能吃掉收益；计数本来不参与搜索，无须保留。
- 保留累计字段：输出计数是常数时间读取，回溯无须增加工作，现有实现也最直接；但每条展开假设都携带只为末列输出准备的数据，在已确认的搜索热点中增加存储和读写。接受回溯时的少量整数加法，并用配对计时约束回退。

## Acceptance criteria

旧布局和逻辑堆预算先失败。固定旧假设、容量和完整解码，覆盖冷/热备忘的 51200 组选项，比较完整路径字段、顺序、评分位模式和错字边数；额外检查混合标记与空词面边。18 种 release 形状各 40 对，中位新旧比小于 1.05。固定资源质量、九键延迟、完整相关测试、Clippy、fmt、笔记与 quick 通过后交付 PR。

## Risks

未来若将错字边数用于搜索评分或剪枝，应重新评估保存状态的必要性。回溯多做一次布尔转整数及加法，但次数仅属于末列保留路径；是否抵消布局收益由配对计时验证。纯 Rust 逻辑堆测量不代表 RSS 或宿主绘制延迟。

## Rejection evidence

固定 `febc38877bce3b302de4927d1f38cb224aae2eb5`，Rust 1.97.1、macOS arm64。原布局预算在旧版真实失败（40 字节，预算 32）；旧逻辑堆预算同样真实失败。实验版 `Hyp` 为 32 字节，三种图的分配次数与返回存储均相同，逻辑请求峰值下降：

|---|---|---|---|---|

## Diagnostics

汇编显示旧参考的容量预扫描被内联，实验入口仍调用 `column_capacities`。只加普通 `#[inline]` 提示后，生成代码仍保留调用，完整 18 组复测的无表单边中位比为 1.070732（p10/p90 1.045097/1.095546），热备忘单边为 1.057456。该提示没有实现预期的内联，不能由此断言强制内联也无效；提示已撤回，不继续叠加未经证实的代码调整。

单元测试的全局分配器即使不在测量范围内，也经过线程局部计数器；两侧生成代码对这段测试逻辑的优化不同。临时改成 `System` 分配器、只测三种单边配置，诊断中位比分别为 1.052426、1.044419、1.027142；第一项 p10/p90 为 0.592294/1.734008，噪声较大。它不能证明生产短图确有精确的 5.24% 回退，也不足以证明已经符合预算。分配器和完整计时矩阵均恢复，没有用这次诊断替代失败门禁。回溯计数的寄存器存活、分配大小类与代码布局的各自贡献尚未分离，不宣称已找到机器指令级根因。

## Retained experiment

产品恢复固定基线的累计字段、展开和回溯正文，四十字节假设预算保持。仅在 `cfg(test)` 下保留实验、独立旧参考、语义和逻辑请求对照，以及默认忽略的计时；没有把实验或替代分配器接入产品。旧参考和实验各自拥有假设、比较器及容量函数，避免后续产品布局变动污染历史对照。测试 helper 只扩大到相邻测试模块可见。

复现逻辑与请求对照：`cargo test --release --locked -p msime-engine -p msime-input-runtime lattice::decode::traceback_tests -- --nocapture`。复现完整计时：`cargo test --release --locked -p msime-engine -p msime-input-runtime traceback_typo_count_rejected_release_comparison -- --ignored --nocapture`。后者仍保留中位比小于 1.05 的门槛，不满足时退出失败；它不是普通 CI 门禁，也没有放宽通过条件。

## Consequences

保留累计字段继续付出每个假设一个机器字的成本，接受现有短图路径的性能。否决方案和原门槛可复现，避免未来仅凭布局及逻辑堆缩小再次采用。重访本方案必须先隔离短图成本，并在完整形状及固定资源质量上重新证明符合预算；已记录的局部内存收益不是采用依据。没有生产文件读写、权限、目录遍历或 Android 资源改动，不包含设备验收结论。

## Verification

完整本地 quick 退出 0 并报告 `quick check passed`：Windows 本机 149 项、Linux 原生 87 项测试通过；Rust workspace、Android target 与 Java、WASM、Linux 设置外壳、macOS 原生宿主和 Apple bridge 构建通过。Windows MinGW/x86、pipe-only 及缺少暂存输入的原生 ArkTS 阶段按脚本跳过，没有设备验收结论。差异手工审查没有阻断项，没有创建子代理。
