# Agent Note: 日文矩阵行内保存固定八个节点槽

Status: rejected — 固定数组减少分配但 release 查询未显示稳定收益，生产保留 Vec 行

## Problem

日文矩阵每行严格最多保留八个节点，却为每行另分配八项 Vec 缓冲。单假名有两行，未知双假名有三行，这些固定节点缓冲不需要独立堆分配。当前 Row 外层向量与每个节点文本的拥有关系不要求行内部再使用动态向量。

## Proposal

Row 使用八个已初始化 Node 槽与实际使用长度，空槽包含空 String，不分配。活跃节点切片保持原插入顺序；第九项即使败选仍稳定排序，严格改善才原地旋转并替换最差节点，后到同分放在既有同分项之后。末行 EOS 加成本和稳定排序只处理活跃槽，拥有数组迭代取实际长度，输出继续接收节点拥有文本。

前驱行与后续目标行用 `split_at_mut` 分开借用，避免每个起点反复初始化和移动整行；末行只转移一次。不增加 unsafe、依赖、公开接口或常驻缓存。行仍放在按输入长度分配的外层 Vec，不给输入长度设置新上限，也不把整张矩阵放到栈上。Row 在局部移动时更大，必须测量初始化与移动成本及短、长、稀疏、密集查询的 release 耗时。

## 既有笔记审计

[节点提前筛选](../../implemented/testing/2026-10-09-japanese-pruned-node-text.md) 部分重叠，继续守住首次第九项和稳定平局规则，互链；[末行文本转移](../../implemented/testing/2026-10-09-japanese-final-text-move.md) 保留输出所有权，互链。[待定读音键](../../implemented/testing/2026-10-09-japanese-pending-reading-buffer.md) 部分重叠，继续查询键预算与原流程，互链。生产与旧 pending 测试均保持 Vec Row 和原查询正文；本实验另冻结当前基线，仅比较固定八槽存储和前驱借用的试验变化。[注音路径栈缓冲](../../implemented/testing/2026-10-09-zhuyin-stack-conversion-paths.md) 为定长存储参考，算法不同，不吸收。其他临时日文候选行、转换缓冲、词库排名堆属于别的层，保留；注音、粤拼、拼音路径命中无关且保留。活跃笔记按 MAX_NODES_PER_ROW、Row::new、行存储、节点数组和节点缓冲检索，没有固定八槽行决定。

## Alternatives considered

- 保留八项 Vec：Row 很小、移动成本低；每行单独分配固定容量，短查询分配成本明显。
- 引入 SmallVec/ArrayVec：容器可封装初始化和切片操作；这里上限固定且只需要活跃切片与原地旋转，不为少量操作增加依赖。
- 只延迟空行分配：局部改动较少；未知假名回退保证所有行可达，不能消除实际查询的每行分配。

## Acceptance criteria

先运行旧实现分配预算红测试。冻结当前 Vec Row 与完整查询正文对照，保留旧 batch oracle，检查全字段、排序、平局、重复词面、负成本、连接成本、待定尾部、空与零限额和长 Unicode 查询。直接行构造/转移不应分配，败选文本仍零分配。量化 Row 布局、整体矩阵存储及 release 多种查询耗时；只有常规查询有收益且长/密集路径没有不可接受回退才采用。完整引擎、golden、Clippy、格式、笔记、quick 和独立审查后提交合并清理。

## Risks

只能对活跃槽排名与输出，不能把空槽当作零成本节点。替换需要准确丢弃最差节点并保留稳定同分优先级。默认行长度必须为零，初始行需要明确启用一个零成本空文本节点。较大 Row 在 mem::take/恢复过程中增加复制与初始化成本，不能凭分配减少推断延迟更快。

## 实测后的调整

最初保留每起点 `mem::take` 和恢复整行的数组版本，在隔离 release 中单假名 0.916→0.966 ms/2000 次，双假名 1.752→2.000 ms/2000 次，出现回退；分配减少不能据此直接采用。将前驱和后续目标行分开借用，消除新增整行移动成本后再验证。旧 Vec 查询对照继续保留原 `mem::take` 正文。

## Rejection evidence

旧生产实现收紧分配预算时，未知双假名为 8 次而预算 5、简单单假名为 11 而预算 9、密集单假名为 25 而预算 23，红测试三项失败。数组实验消除每行独立缓冲，非空读音且非零限额严格少 `字符数 + 1` 次分配。三项新增行为测试包括默认空行和零分配构造/转移、全部插入位置与同分、两种合成词库的空/待定/别名/负成本/连接成本/长 UTF-8/未知回退完整输出对照；固定 Vec 行及完整查询正文与 `33a5a3f464232a382b0b94ca49df9f24196f377f` 独立核对一致。

布局实测 Node 40 字节、旧 Row 本体 32 字节加 320 字节节点缓冲、新 Row 336 字节；整体每行存储减少 16 字节，但局部移动大小增大。外层仍按真实字符数分配，无新输入上限。数组初版逐起点转移整行出现短路径回退，改为 `split_at_mut` 直接借用前驱与目标后短批次约持平，长路径计时仍有波动。因此十批交替顺序的每批次数扩大十倍，不并发运行本任务其他构建或测试。

较长批次的本机 release 中位耗时（旧 Vec → 固定数组＋直接借用）：简单单假名 8.791→9.185 ms/20000 次，双假名 17.644→17.400 ms/20000 次；密集单假名 47.188→46.975 ms/10000 次，密集双假名 82.324→85.279 ms/10000 次；32 字符稀疏 49.296→52.721 ms/1000 次、密集 270.954→278.576 ms/1000 次；128 字符未知 Unicode 184.449→244.680 ms/1000 次；待定 `kak` 32.430→21.959 ms/10000 次。只有待定字母的 `k` 与空/零限额控制路径未创建矩阵，部分控制路径也有波动，不能把这些合成计时当作真实按键延迟或确定的同比速度。

上述轮次没有显示常规查询的稳定收益，并有多条短长路径回退，未达到采用标准。生产恢复原 Vec 行、逐起点转移及既有分配预算。仅在 `cfg(test)` 的 `inline_row_experiment`、冻结 Vec 行和 `inline_row_tests` 中保留实验与可复现的 ignored release 对照；之后生产变化不应同步改写固定旧对照。实验没有成为公开 API、依赖或产品查询路径，现有 pending benchmark 仍只沿生产实现，不包含本否决实验。

运行计时：`cargo test --release -p msime-engine --lib benchmark_inline_matrix_rows -- --ignored --nocapture --test-threads=1`。计时无 CI 阈值。长 Unicode 案例直接构造非空 hiragana，避免罗马字转换器把 emoji 留在 pending 而误测空读音路径。

抽出为最终测试模块后再次独立跑同一 release 命令，三项行为测试和计时对照通过；长稀疏 142.152→154.551 ms/1000 次、未知 Unicode 141.707→188.964 ms/1000 次、密集单假名 156.669→188.419 ms/10000 次仍出现回退，其他路径有改善。未创建矩阵的只有待定 `k` 控制路径也从 18.359→31.687 ms/20000 次，说明环境或代码布局波动很大；这些数据不足以精确归因或承诺速度差。保留否决决定的依据是没有可靠的整体查询收益，避免仅凭分配减少引入未经证实的优化。
