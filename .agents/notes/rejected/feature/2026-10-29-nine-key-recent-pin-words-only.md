# Agent Note: 九键最近选择只给两字以上的词固定第 1 位

Status: rejected — 评测 8 格里 7 格不降，一词一块打字 +0.8 到 +1.0pp；14 键聊天主配置一格少 4 个字，在噪声以内，但按事先写下的门不改。真正挡住它的是 #8492、#9066 的单字契约，要不要翻转由产品决定

## Problem

九键打字流评测（`typing_sim`，未合并的 `test/typing-sim-eval` 分支）在一词一块、不简拼的打法下，缺口最大的一类是「最近选择」：[最近选中的候选优先](../../implemented/feature/2026-10-17-nine-key-recent-candidate-priority.md) 把非首位的选择写进 `nine-key:<digits>:<locked>` 的第 1 槽，后一次选择替换前一次。同一串键对应不止一个常用单字时（他/她/它、的/地/得、那/吗、要/烟），第 1 位跟着上一次选择来回翻：Tatoeba dev 上首位是置顶行的步里只有 53% 被用户点了。缺口分析的 oracle「pinwords」（单字不再记最近选择，多字词照旧）在宽口径下一词一块 +0.9 / +0.7pp。

## Proposal

在 `NineKeySession::select` 记最近选择的条件里加一条：选中的词至少两个字（`count_utf8_chars >= 2`）。单字的选择照旧走调频（手机默认 `promote`，挪进前五位），不再写第 1 槽。

### 和已有决定的关系

- 它不是笔记里否决过的任何一种做法。#8492 否掉的是「靠全局调频强制置顶」「让单字进个人模型」「另建一张表」，[锁定读法后的最近选择](../../implemented/bug-fix/2026-10-21-nine-key-locked-selection-recent.md) 否掉的是「去掉上下文里的锁定部分」。
- 但它收回了这两篇的核心承诺。#8492 的需求就是单字：「像能这样的字仍可能需要展开候选栏」，Consequences 写明「单字和多字词都适用」，单元测试 `recently_selected_candidate_leads_the_same_nine_key_context` 用的就是 能。#9066 修的 #9041 录屏也是单字：`64` 锁 mi / ni 再确认 米 / 你，`spelling_*` 一组单元测试、Android `NineKeyPanelDeviceSmoke -e recent-learning true` 设备验收和 Android README 都按单字写。所以要做就是翻转决定，要另立一篇 implemented 笔记、改这几处测试和文档，并由产品确认。

### 事先写下的门

规则在跑之前写下（研究产物 `RULE.md`）：typing_sim test 严口径 CFA，主配置和一词一块不简拼，Tatoeba 与聊天，九键与 14 键，共 8 格，任何一格低于现状都不改；`convert_eval` 学习关，必须逐位不变。全键盘不走 `NineKeySession`，不受影响，没有跑。

## Alternatives considered

- **P2：只在不锁读法时停掉单字置顶，锁定读法之后确认的单字照旧置顶。** 它最强的理由是保住 #9066 已发布、有设备验收的行为，只收窄 #8492。看到 P 推翻 #9066 之后加的这一臂，跑之前把取舍规则补进了 `RULE.md`。结果很差（见下）：锁读法时写进未锁定上下文的单字，之后再也不会被不锁读法的单字选择替换，第 1 位卡在一个旧字上。
- **完全去掉最近选择（nopin）。** 缺口分析里宽口径一词一块 Tatoeba 0.805，但聊天 0.821 比现状低，而且整个撤掉 #8492，没有再跑。
- **单字选择清掉第 1 槽里的自动记录、而不写自己。** 能消掉 P 的不对称（多字词的置顶不会再被单字的选择替换，见下面 让 的例子），但固定位置表分不清手动和自动的第 1 槽，#9066 也提到过这一点；要先改存储，没有做。

P 在 8 格里 7 格不降，一词一块明显变好；14 键聊天主配置少 4 个字（1690 字里 0.24pp，远在区间之内，dev 上是 2 赢 4 输：吧、有、别、完），按事先写下的门不改。8 格合计多 173 字、少 4 字，评测本身没有否掉 P；按门不改只是照规则执行，挡住它的是上面写的单字契约。P2 在三格上大幅变差，否掉。

`RULE.md` 要求把 P 和改动一选中的臂（A4）叠加再跑一次，这一臂没有跑：A4 在验证上已经不过，不会发。

dev 上逐块看（九键一词一块 Tatoeba，P 对 A0：赢 50 字、输 27 字）：

- 赢：要（烟 → 要）、到（道 → 到）、吗（那 → 吗）、想（像 → 想）、的（地 → 的）、他（它 → 他）、这（写 → 这）、带（呆 → 带）。都是上一次选了同键的另一个单字、第 1 位被它占着。
- 输：让（5 字，首位成了 萨米：萨米 置顶之后，选 让 不再替换它），买、家、丢的首位成了 那个、基本、地图，另有 钱、新、刀、见。一类是多字词的置顶不再被单字选择顶掉；另一类是单字靠调频挪进前五位以后没有回到首位。

耗时与负载见 [补全排序那一篇](../bug-fix/2026-10-29-nine-key-completion-order-in-typing-flow.md)，两组臂一起跑。

### 以后再碰这里

- 收益真实存在（九键一词一块 +1.0 / +0.8pp，14 键 +0.9 / +0.2pp），代价是推翻两篇已实现决定的单字契约。如果产品决定要它，按翻转决定的流程走：新的 implemented 笔记，改 能、米 / 你 的单元测试、Android 设备验收和 README，再在真机上确认 能 这类字不展开候选栏也能找到。
- 不要做 P2 这种只关一半的版本：第 1 槽靠「后选替换」才不会卡住，任何让一部分选择写、另一部分不写的规则都要先量卡住的代价。
- `NineKeySession::select` 记最近选择的逻辑由所有网格共用，包括十八键、九键双拼、14 键双拼和十八键双拼。typing_sim 只量了九键和 14 键，要做时这四种网格也要量。
