# Agent Note: 横向候选验收在滑过目标后回找

Status: proposed

## Problem

#10356 跟踪 develop `0e2824c8a2` 的 API 28 设备失败。共享单测全部通过，唯一设备失败是连续候选专项寻找第 70 项时已滚到偏移 181289、创建 1873 项，随后在列表尾部停止。夹具始终按调用者给出的方向滑动，不核对已建目标是否落在身后，因此一次越过目标就再也不能回找。

## Proposal

目标存在时按其真实屏幕边界决定下一次手势的方向和距离；目标尚未建立时才沿原方向推动追加。保留真实 DOWN/MOVE/UP、候选顺序、首末往返、真实点击上屏和停滞失败断言。单声母增加确定性的越过目标再回找，使用旧固定方向实现做失败对照。

## Related notes audit

- [连续候选条](../../implemented/feature/2026-10-23-android-continuous-candidate-strip.md)部分重叠，继续持有分批加载与候选身份；本篇只修设备夹具的寻路策略，两篇互链。
- [低端机热路径](../../implemented/bug-fix/2026-10-27-android-keyboard-low-end-power.md)持有批量与复用，不修改产品实现或通过扩大等待掩盖失败。
- 候选即时呈现与各平台几何笔记无关，不改决定。

## Alternatives considered

- 增加滑动次数或延长超时：有助于慢设备，但已到末尾时继续向前不会到达身后的第 70 项。
- 使用无障碍滚动到目标或直接修改偏移：定位简单，但会绕过真实触摸与追加链路，不能代替候选条验收。

## Acceptance criteria

确定性越过目标时旧夹具失败、修后通过；API 28/35 的完整连续条专项通过，保持末项、首项、追加边界及上屏断言。构建测试 APK、quick 与 notes 通过。不得把 arm64 模拟器通过扩大为 GitHub x86_64 原失败环境已绿。

## Risks

无障碍节点可能被替换，仍需刷新并核对目标身份；屏幕边界与触摸距离要使用同一坐标系。新 head 的 CI 必须单独核对。
