# Agent Note: 鸿蒙设置应用与键盘扩展改用共享沙箱交换数据

Status: proposed

## Problem

鸿蒙宿主是按「设置应用（UIAbility）和键盘（InputMethodExtensionAbility）两个进程共用 `files/state`」设计的：偏好、登录会话、按键反馈、自定义皮肤、打字统计、遥测队列都放在那里，各自加锁读写。

从 API 12（OpenHarmony 5.0.0.38）起，输入法扩展进程改用独立沙箱。OpenHarmony 的变更说明把这标为不兼容变更：「输入法 Extension 进程使用独立沙箱……新增输入法 Extension 与应用的主入口的共享沙箱」。2026-10-09 在 HarmonyOS 6.0.2(22) 模拟器上实测，两个进程的 `files/state` 内容完全不同，设置应用写的文件键盘一个也看不到。

可见的后果：
- 设置页改的输入方案、按键反馈、自定义皮肤传不到键盘；
- 键盘看不到登录会话，账号相关功能按未登录处理；
- 打字统计永远是 0：统计默认关闭，设置页开启的只是它自己那份文件。

## Proposal

用华为提供的「共享沙箱」：

1. 在 AppGallery Connect「开放能力管理」申请「输入法应用内数据共享」，拿到 `data-group-id`。这需要包名能在 AGC 建应用，所以先把 bundleName 改成 `app.msime.hmos`，原来的 `app.msime.harmony` 含保留字被拒。
2. 重新生成带这个 ID 的调试和发布 profile（手动签名，自动签名不支持这项能力），键盘扩展在 `module.json5` 的 `dataGroupIds` 里声明同一个 ID。
3. 两个进程都用 `context.getGroupDir(id)` 得到共享目录，原先放在 `files/state` 里、需要两边都看到的东西改放到那里：偏好、登录会话、按键反馈、自定义皮肤库、打字统计、遥测队列、社区回复库，以及插件目录 `plugins/`（含 `@` 名单 `mentions.json`）：设置应用导入的音效包、指令表、短语表、辅助码表、特效包和符号集只有放在这里，键盘才读得到。只属于键盘自己的数据（常用语、个人词库、表情记录、剪贴板历史）留在键盘自己的沙箱。
4. 基础访问模式下键盘对共享沙箱只读，完整体验模式下可读写。用 `inputMethodEngine` 的 `getSecurityMode()` 判断当前模式、监听 `securityModeChange`；只读时，键盘需要写的数据（统计计数、遥测）不写，统计页如实提示需要完整体验模式。
5. `getGroupDir` 返回空（没有 ID 的开发包、签名不带 ID）时退回各自的 `files/state`，行为与现在相同，并在设置页说明键盘无法同步设置。

## Alternatives considered

- **设置应用通过进程间通信把数据推给键盘。** 最强的理由是不需要 AGC 申请，不签名的开发包也能用。不用它，是因为文档明确说基础访问模式下键盘的公共事件、进程间通信、共享内存都被限制；而且输入法框架没有给自家设置页传数据的接口，`privateCommand` 只对键盘当前绑定的编辑器有效。
- **用带 `dataGroupId` 的 `@ohos.data.preferences` 或关系型数据库。** 文档说它们支持「同一应用的不同进程间共享，只支持三方应用中输入法和输入法的扩展场景使用」，并提供 `multiProcessChange` 通知。不作为主方案，是因为偏好文档、统计、皮肤库现在都是 client-core 管理的文件，带着锁和原子替换，换成 preferences 等于把这些存储在 ArkTS 里重写一遍；共享目录可以让 client-core 原样读写。偏好变更的通知可以单独考虑用它。
- **什么都不改，只在文档里说明。** 不行：设置页对键盘基本不起作用，打字统计永远为零，这是功能失效。

## Acceptance criteria

- 用带 ID 的 profile 签名后，在真机上：设置页改输入方案，键盘下次弹出时生效；设置页登录后，键盘里的云剪贴板可用；开启统计后打字，统计页计数增加。
- 基础访问模式下键盘不写共享目录，统计页给出明确提示，没有异常日志。
- `getGroupDir` 不可用时，行为与现在一致，并有一条说明日志。

## Risks

- AGC 审核结果和时间不确定（文档说 1–3 个工作日），审核要求应用能出现在「设置 → 系统 → 输入法」里。
- 文档没有说明模拟器是否认带 ID 的 profile，验证可能只能在真机上做。
- 已经在键盘自己沙箱里积累的数据（常用语、个人词库）不受影响；设置应用那边的数据要迁到共享目录，需要一次性迁移，迁移要能中断后重来。
