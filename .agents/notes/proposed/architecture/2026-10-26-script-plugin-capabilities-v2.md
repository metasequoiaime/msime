# Agent Note: 脚本插件第二批能力：设置项、随包数据、加候选、指令时间与扩展参数、持久存储

Status: proposed

## Problem

维护者 2026-10-26 定下的目标是让用户按自己的需要做插件、把插件生态做起来。脚本插件现在只能写出一类插件：无状态地读当前这一次的上屏或候选，然后改写、重排、隐藏、注释，或者在自己的 `/` 指令里出几行。审计时列出的缺口逐条对应一类做不出来的插件：

- 没有设置项：「隐藏生僻字」不能让用户自己定阈值，任何「按用户偏好」的插件都只能把选择写死在模块里。
- 只能把数据编进模块：模块上限 256 KiB，进程内存总账按模块字节的 128 倍记，几百 KiB 的词表一个插件就吃掉大半个 64 MiB（理由见 [脚本插件的只读数据文件](../../rejected/architecture/2026-10-13-script-plugin-data-files.md)，那篇因为没有使用者被搁置，问题本身仍然成立）。
- 不能往普通候选里加词：只能动前 20 行已有的候选，新文字只能出现在 `/` 指令行里。表情联想、自定义缩写展开这类插件做不了。
- 看不到时间：日期、时间、倒计时类的 `/` 指令做不了；指令表的 `{date}` 模板只覆盖固定格式。
- `/` 指令参数只有小写字母：计算、进制换算、单位换算、编号生成都要数字。
- 没有任何存储，每次聚焦全部实例丢弃：任何「越用越懂你」的插件（按自己的使用频率重排、记住常用的表情）都做不了。

最后一条和现有设计直接冲突。插件的隐私承诺里有一条不变量（原设计里编号 I2，作者文档「隐私规则」写作「插件的状态只活在一个输入框里，不能把一个应用里的内容带到另一个应用」），上面那篇被否的笔记明确写了「设计明确不加存储和时钟」。2026-10-26 维护者在知道这一点、也知道下面「持久存储」一节的残余风险之后，选择给存储，单独授权并写明风险。这篇笔记就是这次翻转的记录，旧笔记里对存储的否决理由（持久化通道）在这里被接受为残余风险，而不是被反驳。

## Proposal

全部按 ABI v1 只追加：新的 import、新的能力名、新的事件字段编号，已有编号和语义一个都不改。旧模块不导入新函数，行为逐字节不变；旧客户端遇到申请了新能力的清单在能力名处拒绝（失败方向安全）。新能力让 `CapabilitySet` 超过 8 位，改成 `u16`；授权文件里存的是能力名，不受影响。

### 1. 设置项（不需要能力）

- 清单 `[[script.settings]]`，最多 16 项，每项 `key`（1 到 32 个小写字母、数字、`_`，清单内不重复）、`title`（1 到 24 个字符）、可选 `description`（不超过 120 个字符）、`type` 和默认值：
  - `type = "bool"`，`default = true|false`；
  - `type = "choice"`，`options = [{value, title}]` 2 到 16 项，`default` 是其中一个 `value`；
  - `type = "number"`，整数，`min`、`max`（`i32` 范围内，`min <= default <= max`）；
  - `type = "text"`，`max_length` 1 到 256 个 UTF-16 码元，`default` 可以为空，值不能含控制字符和格式字符（与注释同一条规则）。
- 用户在授权页插件详情里设置；值存在插件目录旁的 `script-settings.json`（按 id，带 `revision`，写法同 `script-grants.json`：原子替换、持锁、读取上限），不进内容哈希，所以改设置不需要重新授权。值变了，宿主像授权变了一样重读计划并在下一次聚焦重建实例。清单里删掉或改了类型的项，旧值丢弃、用新默认值。
- import：`setting_value(index, dst, cap) -> i32` 按清单顺序取第 `index` 项的当前值（布尔是 `0`/`1`，数字是十进制文本，选项是 `value`，文本原样），`setting_count() -> i32`。不需要能力：值是用户为这个插件写的，读它不暴露任何输入。授权对话框和详情页列出设置项，说明「插件能读到你在这里填的值」。
- 所有钩子里可读，快照钩子（`before_commit`、`command`）里读到的是快照时的值。

### 2. 随包只读数据文件（不需要能力）

沿用被搁置那篇的骨架，但不定义宿主格式，只给原始字节，让作者自己决定编码（排序表、前缀树、压缩块）：

- 清单 `[script] data = ["words.bin", ...]`，最多 4 个文件，文件名规则同模块，单个不超过 4 MiB、合计不超过 8 MiB，按数据文件的规则检查（存在、非空、算进 16 个文件）。
- 内容哈希在现有的 `sha256("msime-script\0" ‖ len ‖ plugin.toml ‖ len ‖ 模块)` 之后按清单顺序追加 `len ‖ data_i`。没有数据文件的包哈希逐字节不变，已有授权（包括官方 uuid）继续有效。
- 后台编译线程随模块一起读入、核对哈希，按哈希放进进程级缓存，多个会话共享一份；内存总账按 1 倍记（不走模块的 128 倍）。
- import：`data_len(file) -> i64`、`data_read(file, offset, dst, cap) -> i32`（复制 `min(cap, len - offset)` 字节，`offset` 越界 `INVALID`，`file` 越界 `INVALID`），按复制字节数计 fuel（每 4 字节 1，加每次调用 100）。授权页「只能知道发生了什么事件」改为「…以及读自己包里的数据」，详情写「自带数据 N KB」。

### 3. 往候选里加词（能力 `insert_candidates`，依赖 `read_candidates`）

- 只在 `candidates` 钩子里、本地模式 `none` 时有效，别处返回 `DENIED`。`candidates_insert(position, text, tlen, note, nlen) -> i32` 暂存一行，插在插件变换之后呈现顺序的 `position`（0 到当前行数）处；每次调用最多 3 行，每个插件每次 `candidates` 最多 3 行，所有插件合计最多 6 行。
- 文本规则同 `command_row`：非空、首尾不是空白、不超过 64 个 UTF-16 码元、不含控制、格式和不可见字符，不含 `://`、`www.`、`mailto:`；注释不超过 32 个码元。
- 插入的行是来源 `Plugin` 的候选：选中时原样上屏，不进词库、不调词频、不计打字统计、不作为上文发给 AI 候选，也不查释义或翻译（和插件指令行同一套排除）。旁路调用（在线候选回来、停顿后的重排）不运行脚本，按呈现位置和相邻候选的身份重放最近一次的插入，相邻身份对不上时丢弃插入，不猜位置。
- 合成顺序：重排、隐藏、注释照旧按执行顺序合成之后，再按执行顺序插入；后面的插件看不到前面插件插入的行（它们读到的仍是插件变换之前的列表，与现在一致）。

### 4. `/` 指令里的本地时间（不需要能力）

- 只在 `command` 钩子里，`event_scalar` 新增字段：`LOCAL_DATE`（`yyyymmdd`）、`LOCAL_MINUTE`（当天第几分钟，0 到 1439）、`WEEKDAY`（1 到 7，周一为 1）、`UTC_OFFSET_MINUTES`。别的钩子里是 `ABSENT`。
- 只给到分钟、只在用户刚打完自己触发词的那一次给，所以量不出打字节奏和停顿；`command` 跑在快照上，时间也留不下来。原设计不给时钟的理由是计时侧信道，这个粒度和投递时机下不成立。

### 5. `/` 指令的扩展参数

- `[[script.commands]]` 新增可选键 `arguments = "letters"`（默认，与现在相同）或 `"extended"`。`extended` 的指令在完整打出触发词之后，额外接受数字和 `. + - * / % ( ) = ,` 作为参数，参数上限仍是 64 字节；`command_text(ARGUMENT)` 读到的就是这串。
- 冲突处理：参数里一旦有了数字，这一份输入里数字键不再选候选，改为空格选高亮行、方向键移动、点选；宿主照计算模式那样处理候选序号的显示（实现时以引擎里计算模式的现有做法为准，各宿主逐一核对）。参数里没有数字时行为与现在相同，所以 `/uuid` 这类只用字母的指令不受影响。
- 授权页「提供 / 指令」的说明相应加上「以及数字和运算符号」。

### 6. 持久存储（能力 `persist_data`，单独授权）

- 每个插件一块私有存储，上限 64 KiB，按插件 id 存放在用户插件目录下的 `script-data/<id>.bin`（0600 权限，原子替换，持文件锁写入）。插件更新（内容哈希变了）时数据保留，授权照旧要重新给；卸载插件、撤销 `persist_data`、或用户在详情页点「清除数据」时删除。
- import：`storage_len() -> i32`、`storage_read(offset, dst, cap) -> i32`、`storage_write(src, len) -> i32`（整块替换，`len` 不超过 64 KiB，超出 `LIMIT`）。读写都按字节计 fuel。写入先落在进程内的缓冲里，在失焦、会话结束和后台线程的定时刷新时写盘，不在按键路径上做文件 IO；同一插件在同一进程里共用一份缓冲，跨进程（IBus 和 Fcitx5 同时在跑）以最后写盘者为准。
- 只在持久实例上的钩子里可用（观察类钩子和 `candidates`），在快照钩子 `before_commit`、`command` 里返回 `DENIED`：快照钩子的输出只取决于这一次的输入，这条不随存储改变。
- `persist_data` 和 `rewrite_commit` 不能同时申请（与 `rewrite_commit`、`read_composition` 互斥同一个理由）：否则插件能把以前在别的应用里打过的字夹带进这一次上屏。它可以和 `insert_candidates`、`annotate_candidates` 同时申请：存下的内容可能出现在候选和注释里，这正是授权页要写明的风险。
- 授权对话框里这一项单独一组、默认不勾、红字说明：「插件能把读到的文字长期记在这台电脑上，包括你在不同应用里打过的字。这份数据存在你的用户目录里，没有加密，同一用户下的其他程序能读到它。卸载插件或撤销这一项时删除。只给你信得过的插件。」详情页显示已用大小和「清除数据」按钮。
- 不变量的新表述：没有授予 `persist_data` 的插件，状态仍只活在一个输入框里；授予了的，只有它自己那 64 KiB 跨输入框，其余状态照旧每次聚焦丢弃。作者文档「隐私规则」按这个表述改写。

### 交付顺序

1. 运行时和清单：`CapabilitySet` 扩宽，五组 import、能力、字段、清单键，`msime-pack validate`/`run` 跟上（`run` 的夹具能给设置值、数据文件、时间和存储的初值），SDK 的 Rust 绑定和 C 头文件跟上，`crates/pack-tool/tests/sdk.rs` 的核对跟上。
2. 宿主侧：设置文件与数据文件的读取和缓存、存储缓冲与刷盘、加候选的合成与重放、`/` 扩展参数（引擎）、时间字段。
3. 设置界面：共享页和 Windows 原生页的授权对话框、详情页设置表单、数据大小与清除按钮。
4. 文档与示例插件：每项能力一个最小示例，放进 `plugins/script/`。

## 运行时和清单里定下的细节

第一个 PR（运行时、清单、作者工具）落地时，按「拿不准就取更窄的」定下了设计没写死的几处，宿主侧照这些接：

- 设置项和随包数据在 `msime_init` 里也能读：它们不随事件变化、和输入无关，初始化时算好的东西进了快照也带不进任何输入，作者可以在初始化里建好查找表。存储在 `msime_init` 里是 `DENIED`：初始化之后取的快照要是含有存储的内容，快照钩子就能把以前存下的字带进这一次的输出。
- 存储写入和别的修改类动作一样先暂存，钩子正常返回才写进缓冲；trap、fuel 用完、返回负数、被本轮配额截断时作废。同一个钩子里写完再读，读到的是暂存的那一份。内容没变的写入不算改动，不触发写盘。宿主没交缓冲时存储类 import 返回 `ABSENT`，不悄悄丢掉写入；快照实例上连缓冲都不带。
- 运行时不做任何文件 IO：宿主经 `Resources` 交进设置值（已经按 ABI 写成文本）、随包数据（按内容哈希共享的 `Arc<[u8]>`）和 `Storage` 缓冲（每个插件每个进程一份，`take_dirty` 取走待写盘的内容，写盘失败用 `mark_dirty` 放回，清除数据用 `clear`）。`Storage` 和 `Resources` 的 `Debug` 只打长度。盘上读回的初值超过 64 KiB 时整块不要、当作空的，不截断。
- 设置项、数据和存储都不受本地模式屏蔽：它们不暴露这一次的输入；文本类 import 照旧屏蔽。`data_read`、`storage_read` 复制 `min(cap, len - offset)`，读到末尾返回 0、不返回 `LIMIT`，作者按块读大文件；`offset` 越界是 `INVALID`。
- `candidates_insert` 的位置按窗口行数校验（0 到 `candidate_count`），宿主合成时把它解释成插件变换之后呈现顺序里的位置。本地模式只认 `none`（0）：临时英文、emoji 这些能读文本的模式也不行，插进去的行会混进那个模式自己的候选。
- 时间字段：宿主交来的时间不合规（日期、分钟、星期越界，偏移超出 ±18 小时，或者落在和返回码撞车的 -1 到 -4）时四个字段一起 `ABSENT`。偏移可以为负，SDK 另给 `event::signed` 读它。
- 数据文件扩展名只认 `.bin`：设计只说文件名规则同模块，没说扩展名；收成一种，免得数据文件和说明文件（`.txt`、`.md`）、模块混在一起看不出是什么。数据文件不能和模块、清单同名，没在清单里点名的 `.bin` 照旧报「没有用到」。
- 设置项：`choice` 的选项 `value` 和 `key` 一样是 1 到 32 个小写字母、数字和 `_`（它是插件读到的机器值，不是显示文本）；标题和说明不含插件文本禁用的字符，标题首尾不是空白；`number` 只收 TOML 整数。值的取舍（不合规回到默认值、清单里删掉的键不交）在 `script_pack::setting_values`，宿主和 `msime-pack run` 共用；`msime-pack run --settings` 写错是命令行错误，不回到默认值。
- 内存总账：数据文件按 1 倍记，申请了 `persist_data` 的再加一整块 64 KiB 存储（`limits::resident_bytes`）。授权写入时的准入检查已经按它算，输入法进程里的准入在宿主接入时跟上。
- 指令扩展参数的字符集只有 `abi::EXTENDED_ARGUMENT_SYMBOLS` 这一份（`abi::valid_command_argument`），引擎接入时照它；`msime-pack run` 按清单里每条指令的 `arguments` 核对夹具。
- `CapabilitySet` 扩到 `u16`，编译期断言守着第 17 项。`persist_data` 和 `insert_candidates` 都不算读文本的能力（`reads_text` 为假）：前者的存储跨输入框保留，实例里的其余状态照旧每次聚焦丢弃。

## Alternatives considered

- **不给存储，保留 I2（推荐过的方案）。** 最强的理由是「状态只活在一个输入框里」是一条用户能理解、能被验证的承诺，而存储加上读文本能力，等于在用户目录里留一份没加密的输入记录，同一用户下的任何程序不需要系统授权就能读走，也没有钥匙串可用来加密（维护者 2026-10-12 否决过钥匙串）。维护者知道这些之后选择给存储，代价按上面「单独授权、红字说明、默认不勾、可清除、和 `rewrite_commit` 互斥、快照钩子里不可用」收窄。
- **存储只给不读文本的插件。** 最强的理由是这样不破坏 I2。不用：不读文本的插件几乎没有需要记住的东西，生态要的「越用越懂你」类插件全部需要读文本。
- **数据文件用宿主定义的 MSTB 有序表和 `data_seek`。** 最强的理由是宿主侧查找省 fuel、作者不用自己写二分。不用：一种宿主格式要在导入、加载、作者工具三处保持一致，只服务一种查找方式；原始字节加按偏移读，二分查找每步一次调用（约 100 fuel），8 MiB 的表 23 步以内，作者想用前缀树、压缩块都行。
- **时钟做成任何钩子都能读的 `clock_now()`。** 最强的理由是通用。不用：任意钩子里的毫秒时钟能量出按键间隔和停顿，这正是现在不投递按键事件要防的东西；日期时间类插件只需要在 `/` 指令里、到分钟的时间。
- **加候选复用 `command_row`，让插件在普通输入里也走「行」的路径。** 不用：`/` 指令的行由引擎按预编辑串缓存、只在 `/` 模式出现；普通候选的插入要和重排、隐藏、注释一起合成，要在旁路调用里按身份重放，走 `candidates` 钩子才和现有的三种修改一致。

## Acceptance criteria

- 没有新清单键、不导入新函数的模块：清单解析、内容哈希、运行行为逐字节不变；官方 uuid 的哈希不变。
- 每个新 import：没授权 `DENIED`、错钩子 `DENIED`、字段越界 `INVALID`、放不下 `LIMIT`、按字节计 fuel；`persist_data` 与 `rewrite_commit` 同时申请被拒；快照钩子里存储不可用；隐私规则下的本地模式屏蔽照旧。
- 存储：64 KiB 上限、写盘不在按键路径、卸载与撤销与「清除数据」删除文件、进程重启后读回、跨两个进程以最后写盘者为准。
- 加候选：三种排除（词库、统计、AI 上文）、旁路调用重放与身份对不上时丢弃、文本过滤与 `command_row` 一致。
- `/` 扩展参数：有数字时数字键不选候选、空格和点选可用，`letters` 指令行为不变。
- 设置项：改值不作废授权、触发重建、删除的项丢弃旧值。
- 共享页和 Windows 原生页的授权对话框都有 `persist_data` 的单独一组和红字说明，详情页有设置表单、数据大小、清除按钮。

## Risks

- 持久存储是一条被有意接受的残余风险：恶意插件能在本机攒下用户打过的字，同一用户下的程序能读走。缓解只能是授权页的说明、默认不勾、社区先审后发和「清除数据」。
- 加候选让插件的文字直接进入普通输入流，用户可能把插件给的行当成词库候选误选；靠来源角标区分，各宿主都要画出插件来源。
- `/` 扩展参数改变了数字键在这一种输入里的含义，用户可能误以为数字在选候选；靠候选序号的显示变化提示。
- 新能力扩宽了授权页，授权对话框会更长；按「读文字」「改文字」「记住数据」分组。
