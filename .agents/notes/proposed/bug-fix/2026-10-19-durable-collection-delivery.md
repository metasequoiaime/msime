# Agent Note: 集合用稳定待发身份直接交付有界引擎批次

Status: proposed

## Problem

#8643 的目标是约三万词以每秒万行完整写入。当前 33555 词的合成宿主测量中，引擎直接处理 263 个 128 项批次的最终测量为 3288 毫秒，经过个人请求队列为 7180 毫秒；完整集合导入的一轮为 21266 毫秒。主机其他负载没有隔离，这些不是固定比例，但个人队列本身已超过 33555 词对应的 3355.5 毫秒总预算。

集合已有持久化的待发记录，却先将每批词再保存为个人请求，应用后又保存个人请求结果，最后重写集合的剩余待发正文。只减少集合文件序列化不足以覆盖目标；直接绕过这些文件又会丢掉崩溃恢复、请求幂等身份、已存在词的所有权回执和逐项失败管理。

## Proposal

实现一条以集合待发记录作为持久化意图的交付路径，由 Host API 取得原有引擎维护租约并调用引擎批量写入。服务层仍只持有内容和存储，不依赖引擎。用户手工编辑与旧个人请求继续使用原有 128 项队列和逐项结果。

### 稳定身份与迁移

- 为每个集合待发操作保存稳定请求 id，且始终带 `collections-` 前缀。词条身份相同但载荷发生变化时使用新的 id；仅重新排版、分块或重载不得改变 id。
- 新格式使用版本 2。先原子保存索引的版本门槛，再写新待发格式；旧程序通过索引版本拒读，不能忽略发送进度并重放新队列。
- 新程序允许索引版本 2 配旧待发格式的中断迁移状态，重新完成迁移后才能交付新操作。版本 1 索引配新格式属于损坏。
- 迁移时先检查旧个人队列，将载荷相同的集合请求身份延续到对应待发项，防止升级发生在旧队列提交成功、集合检查点尚未保存的窗口时，把集合自己写入的词误记为用户原有词。

### 待发页与检查点

- 用不可变正文页保存操作，每页至多 4096 项；清单保存页代次、条数、内容摘要和已确认位图。所有文件通过原有 `PrivateDirectory` 锚定目录读写，继续执行原子替换、文件同步和目录同步。
- 每批只更新清单与必要的所有权回执，不重写其他待发词的正文。整页确认后，先原子提交不再引用该页的清单，再删除正文页。
- 集合发生增删、抵消或改权重时才重建待发页。先完整写入新页，清单切换为唯一发布点；读者不得从半成品页推断待发状态。
- 必须有持久的暂存代次记录，覆盖新页写到一半失败以及清单切换成功后清理失败的情况。恢复只清理清单不再引用的已知代次文件，不按路径扫描并删除未知文件。
- 每次有界调用仍完整验证所有被引用的待发页及集合，不引入跨调用缓存。损坏检查必须发生在第一个引擎写入前。已确认整页不再被引用，避免长期重读已发送正文。

### 有界提交与失败回退

- 保留现有普通编辑接口的 128 项上限，另设仅用于集合追加的导入接口。当前实测上限为单次至多 4096 项，并在处理前缀时检查短 CPU 预算；只在外层事务提交成功后返回已提交前缀的回执。最终上限与预算仍需结合维护租约时长和目标平台测量后确定。
- 专用接口保留已有词的实际内容、排序与所有权，只添加缺失词；同一个请求的重试读取已提交回执，不能凭“当前已存在”重算所有权。
- 当前引擎回执只保存载荷，`AlreadyPresent` 分支不保存回执，而命中旧回执的重试一律返回 `Written`。新交付必须在同一事务中保存载荷及 `Written` / `AlreadyPresent` 结果；旧回执升级时默认为 `Written`。不能只沿用原回执表的存在性就声称所有权已经具备幂等保证。
- 快路径任何一项失败时撤销本次外层事务，回退到既有个人队列处理，以保留逐项失败、重试和忽略入口。回退必须沿用同一批稳定请求 id，包含此前提交成功但集合尚未确认的项。
- 回退前先收取此前已提交的所有回执，尤其要先持久化 `AlreadyPresent` 的所有权并确认对应待发项，不能把这类已完成项再次塞进旧个人队列；剩余未提交项才进入原有失败管理。
- Host API 在快路径前处理旧个人请求与已有回执，排除正在等待或失败的同身份请求；删除操作继续走原有路径。每批释放维护租约，继续遵守 2000/100 毫秒调用软预算及 Android 的代次、空闲边界。
- 每批按集合锁、引擎维护租约、个人队列锁的固定顺序取得保护；在维护租约已经取得后，非阻塞取得个人队列守卫，并在引擎提交前保持它，防止“检查没有等待项”之后手工请求插入同一身份。取不到守卫就释放租约并保留待发状态，不能反转为持个人队列锁等待维护租约。引擎回调仍由 Host API 执行，服务层只提供守卫与状态。
- 所有权回执先落盘，随后才能确认待发项。引擎提交成功而检查点失败时，下一次以同一 id 重试；检查点失败不能报告本批已全部生效。

## Alternatives considered

- 只给整份不可变 outbox 加位图：实现较小、检查点紧凑；但每次仍需读取已确认正文，接近排空时尤其浪费，也没有减少个人队列重复持久化，不能单独覆盖目标。
- 在整个两秒作用域结束时统一确认：写盘次数最少；但崩溃窗口会跨越多个引擎提交，缺少稳定操作身份时会重发并误判所有权，不能以放宽持久化换吞吐。
- 扩大普通个人队列和普通编辑事务上限：能摊薄固定成本；但会改变手工编辑、失败请求容量和键盘维护租约的共同边界。专用导入接口与错误回退把这项变化限制在集合交付。
- SQLite 保存待发操作与进度：少量行更新和事务使恢复更直接；但服务层目前没有这套存储依赖，开库及边车访问还需要维持现有目录锚定边界。本提案先复用已经在各平台落地的私有原子文件 API，若分块恢复代码更复杂，应重新比较此方案，不把“不新增依赖”当作性能正确性的替代。

## Acceptance criteria

- 旧格式迁移、旧版拒读、迁移中断、任意页损坏、位图越界、重复请求身份、正文摘要不符均有明确回归；损坏时引擎与个人队列不发生写入。
- 注入引擎提交成功后、所有权保存前、检查点保存前后的失败，重建存储后继续交付，词条计数、所有权、删除与重试结果一致。
- 已存在词的跳过结果必须有持久回执；在首次跳过后改变当前词条再重试，同一请求仍得到原结果，载荷不同时仍拒绝复用 id。旧回执迁移不能改变过去真正写入项的所有权。
- 快路径严格事务失败后回退，失败项仍可在原有个人词库入口重试或忽略；不得靠吞掉错误、截断或改变原始顺序通过。
- 并发手工排队与快路径具有明确先后顺序；个人队列忙碌时快路径不推进，锁顺序不得与原有个人同步形成等待环。
- 先用同一 release 二进制交替测量完整旧/新路径，再在 API 28、35 原生产品路径验证 33555 词完整落库、重载、排序、繁忙重试及维护租约持有时间。全量路径未达到目标时继续保留 #8643，不以分层测量代替。
- 运行相关回归、严格 Clippy、quick 和笔记门禁；文件读写改动须完成两套 Android 设备四包测试及原生 smoke。

## Risks

此提案改变落盘格式和交付边界，不能只靠吞吐数字验收。正文暂存、代次清理、旧个人队列与新意图之间的身份衔接，以及快路径失败后的回退是主要恢复风险。较大导入事务也可能延长新输入会话等待；软预算不能代替实际维护租约时长测量。
