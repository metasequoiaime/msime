# Agent Note: 跟踪 macOS 输入源变灰复测

Status: proposed

## Problem

`#11464` 报告 macOS 26.7.1、水杉 0.59.4、双拼方案下输入法经常变灰，无法切换到水杉，删掉输入源再重新加入也不能恢复。`#11231` 的进程退出收尾修复（正常退出、`SIGTERM` 和崩溃路径最后用 `SIGKILL` 收尾，避免 `imklaunchagent` 累计死亡次数后置灰输入模式，决策见 [macOS 输入法进程以 SIGKILL 收尾](../../implemented/bug-fix/2026-11-10-macos-im-exit-by-sigkill.md)）已经进入 develop 和 macOS 0.59.4，也就是报告者所用的版本，因此它不能被视为本 issue 的修复。

维护者在 2026-11-15 的 issue 评论中请报告者在包含 `#11231` 的最新 nightly 或预览版上复测，并补充三项不含个人输入的状态：双拼和五笔是否都变灰、复现前后是否发生输入法进程重启、`check_input_source.swift` 的注册和启用状态或诊断时间点。截至本记录更新（2026-11-22），原报告者在该请求之后没有在 issue 中补充这些信息。

另一位用户 netstu 在 2026-11-18 于本 issue 下评论遇到同样的问题，使用 86 五笔，并指向自己提交的 `#11592`（macOS 27.2.1，“不定时会失效，无法切换”），该 issue 由跟踪 PR `#11683` 记录。netstu 在 `#11592` 中补充：失效时仍能输入英文，所有 App 都受影响，偶尔在不同 App 的输入位置之间切换能恢复，有一次从输入源中删除再添加后恢复，大多数时候需要重启系统；没有提供构建号、输入源状态或诊断日志。这说明症状不限于双拼，也出现在 macOS 27，但与本 issue 报告者“删掉重新加入也不行”的描述不完全一致，是否同一根因尚未确认。

## Proposal

本记录作为 `#11464` 的跟踪记录合入 develop，不包含产品代码改动。继续跟踪包含 `#11231` 的构建上的复测结果，并与 `#11592` / `#11683` 交叉核对证据：双拼和五笔（含 86 五笔）是否同时变灰、复现前后是否发生输入法进程重启、`check_input_source.swift` 的注册和启用状态、删除再添加输入源是否能恢复，以及删去输入内容和私人路径的 `focus_in`、`keyboard_loaded`、输入源切换日志。拿到能定位责任路径的复现证据后，另开修复 PR（正文写 `Fixes #11464`），针对 `imklaunchagent` 异常死亡或输入源注册路径加入最小修复和回归测试；若确认与 `#11592` 同一根因，修复 PR 同时关联两个 issue。

## Alternatives considered

- **重复提交 `#11231` 的退出收尾改动**：最强理由是报告症状与输入法被系统置灰相似，但该修复已经进入报告版本 0.59.4，重复提交无法证明覆盖本 issue，因此不采用。
- **直接重置所有输入源启用状态**：最强理由是可以让图标重新出现，但会改变用户的输入源选择并掩盖进程崩溃根因，因此不采用。
- **把本 issue 直接并入 `#11592` 只跟踪一处**：最强理由是 netstu 认为是同一个 bug，但两边的系统版本、方案和“删除再添加能否恢复”的描述不同，在根因确认前分开跟踪、交叉引用更不容易丢失证据，因此暂不合并。

## Acceptance criteria

- 收集到包含 `#11231` 的构建上的复测结果和输入源状态（来自本 issue 报告者或 `#11592` 的报告者）。
- 若仍复现，明确责任路径，在独立的 `Fixes #11464` 修复 PR 中加入 macOS 宿主回归测试和实际编辑器验收。
- 确认本 issue 与 `#11592` 是否同一根因，并在两边记录结论。

## Risks

本记录只是调查和跟踪，不宣称输入源变灰已修复。未经现场证据的注册表改动可能影响用户输入源配置。若把 `#11592` 的症状当作本 issue 的证据而根因不同，可能导致修复只覆盖其中一种情况。
