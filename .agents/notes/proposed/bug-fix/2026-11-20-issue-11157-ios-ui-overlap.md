# Agent Note: 调查 iOS 键盘界面重叠

Status: proposed

## Problem

`#11157`（2026-11-09 提交）报告水杉输入法 0.54.0（构建 216338496）在 iOS 27.2、iPhone17,1（双拼 · 小鹤，皮肤跟随系统）上有概率与另一层输入法界面重叠，报告者推测叠在微信输入法上面，附一张截图。仅凭这张截图无法区分是键盘扩展高度没有收回、宿主没有结束上一段 `inputView`，还是聊天应用自身的消息预览叠加。

维护者于 2026-11-09 在 issue 中请报告者在最新 nightly 复现并补充：具体 App 名称和版本、进入输入框前后是否切换过其他输入法或打开过系统键盘的表情/剪贴板面板、收起再唤起键盘是否恢复、nightly 构建号和不含真实聊天内容的截图。2026-11-22 整理本记录时查看 issue，评论区只有自动欢迎语和这条维护者请求，没有报告者的回复，因此本记录的判断只基于原始截图和环境信息；当时引用 `#11157` 的只有本跟踪 PR `#11703`，按“重叠”“覆盖 输入法”“微信输入法”等关键词检索也没有找到描述同一 iOS 现象的其他 issue。后续是否已补充信息，以 issue 本身为准。

## Proposal

本记录作为 `#11157` 的跟踪记录合入 develop，修复不在本记录对应的 PR 中进行。拿到报告者在最新 nightly 上的最小复现（上面列出的宿主、切换路径、收起再唤起结果、构建号和脱敏截图）并据此确认责任路径后，另开一个写明 `Fixes #11157` 的 PR，加入键盘扩展生命周期修复和 iOS 模拟器或真机回归。

## Alternatives considered

- **直接调整键盘扩展高度或强制结束 `inputView`**：最强理由是可能消除截图中的重叠，但没有宿主和生命周期证据，容易破坏其他编辑器的键盘切换，因此不采用。
- **依据截图认定是水杉界面绘制错误**：最强理由是截图能看到重叠，但无法排除宿主应用或另一输入法的叠加层，因此不采用。
- **保持草稿 PR 不合入**：最强理由是调查尚无结论，但跟踪记录留在草稿分支上容易被遗忘，维护者决定把它作为跟踪记录合入 develop，因此不采用。

## Acceptance criteria

- 获得最新 nightly 的最小复现和具体宿主信息。
- 确认重叠来自键盘扩展生命周期后，在单独的 `Fixes #11157` PR 中加入对应代码、回归测试和真实设备验收。

## Risks

本记录只是调查跟踪，不宣称已修复报告者的 iOS 环境。未经定位的窗口尺寸改动可能影响所有 iOS 编辑器。如果报告者一直不补充信息，这条记录需要在后续整理时确认是否转为 rejected。
