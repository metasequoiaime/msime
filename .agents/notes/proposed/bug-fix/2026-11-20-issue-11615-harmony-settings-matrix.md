# Agent Note: 跟踪 HarmonyOS 设置与键盘状态对齐

Status: proposed

## Problem

`#11615` 报告在 HarmonyOS 输入法 0.5.0（`harmony-v0.5.0`）上，设置中启用的语言与方案（全拼、双拼、日语，并禁用其余方案）没有反映到键盘，键盘仍显示默认方案；键盘设置中的双拼键位提示、工具栏隐藏“表情”“常用语”“皮肤”、按键振动、逗号句号和顶部数字行同样没有生效。报告者已提供设备与系统信息（HUAWEI Mate 80 Pro Max，SGT-AL10，HarmonyOS 7.0.0，软件版本 7.0.0.111，API 26.0.0）、稳定复现的步骤和三张截图，不需要再向报告者索取复现信息。

代码调查表明这不是单一状态字段故障。与设置到达键盘直接相关的路径是 `#11637`（设置修改要到下次聚焦才生效），已由 `#11649` 于 2026-11-19 合入 `develop`：键盘显示期间轮询共享偏好指纹，发现新偏好后复用镜像导入和会话重建。`#11649` 合入晚于 `harmony-v0.5.0`，截至 2026-11-22 没有包含它的 HarmonyOS 发布版本；它的 PR 也列明未完成 HAP 构建和签名设备验收，因此还没有证据表明报告者的现象已经消失，也没有证据表明它覆盖了报告中的全部字段。

`#11640`、`#11635`、`#11633`、`#11632`、`#11634`、`#11636` 和 `#11638` 引用的是汇总 issue `#11639`，分别处理候选窗观察外观快照、电脑候选窗下的键盘背景、翻页后的候选选择、多行文本框组字、切换窗口后的悬浮工具栏、皮肤文件夹导入和候选皮肤 canvas 图片更新。它们与本 issue 的候选、外观和工具栏现象相邻，但都不直接针对方案列表、键盘布局、振动或标点字段，截至 2026-11-22 均未合入。issue 中 2026-11-18 的维护者评论曾把方案列表和键盘布局的实时刷新归到 `#11640`、`#11635`、`#11633`、`#11632`，但这四个 PR 的正文和改动范围分别只涉及外观快照、候选窗底层背景、翻页候选身份和多行文本框类型，本记录以 PR 正文为准。2026-11-22 检索 HarmonyOS issue 未发现与 `#11615` 重复的报告。

## Proposal

本记录作为 `#11615` 的跟踪入口合入 `develop`，修复本身不在本 PR 中。继续保持一个行为一个代码 PR，不把多个状态链路合并成一次改动。

先以包含 `#11649` 的签名 HAP 在 HarmonyOS 设备上复现报告的两组设置：若方案列表和键盘设置在保存后生效，再请报告者在下一个包含该改动的发布版本上复测；若仍有字段不生效，按字段逐一定位设置写入、跨进程同步、镜像导入和键盘读取中断开的环节，为未覆盖的字段另开独立修复 PR，最终完成修复的 PR 写 `Fixes #11615`。`#11639` 下的关联 PR 按各自 issue 推进，不作为本 issue 的完成证据。

## Alternatives considered

- **把所有设置字段集中改进一个 HarmonyOS PR**：最强理由是能一次覆盖报告中的多个现象，但会违反一个 issue 一个 PR 的边界，也无法按字段隔离设备回归，因此不采用。
- **依据 `#11649` 合入或模拟器与 ArkTS 测试关闭 issue**：最强理由是偏好同步路径已有合成回归，但没有包含该改动的发布版本，签名 HAP 和报告设备也尚未验收，不能把合成证据当作现场结论，因此不采用。

## Acceptance criteria

- 包含 `#11649` 的签名 HAP 在 HarmonyOS 设备上验证：启用全拼、双拼、日语并禁用其余方案后，键盘方案切换只出现这三种。
- 同一构建上验证双拼键位提示、工具栏按钮隐藏、按键振动、标点和顶部数字行设置在保存后生效。
- 报告者在 Mate 80 Pro Max（HarmonyOS 7.0.0.111）上用包含修复的发布版本确认上述设置生效。
- 验证中发现仍不生效的字段时，为该字段建立独立 PR，并在 issue 中链接。

## Risks

本记录只提供跟踪，不宣称已经修复任何设置字段。若把 `#11639` 下的相邻修复误当作本 issue 的修复，可能在报告者现象仍存在时关闭 issue。把不同状态链路合并会让缺陷定位和回滚边界不清楚。
