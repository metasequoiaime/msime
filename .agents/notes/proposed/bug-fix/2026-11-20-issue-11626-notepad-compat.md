# Agent Note: 调查 Notepad-- 兼容性

Status: proposed

## Problem

`#11626` 的原始报告是：在 Windows 11 26H2 上使用水杉 v0.5.0 时，打开 Notepad-- v3.9.2 plugin/Qt6 安装包会卡死。维护者在 issue 中请求补充完整架构、是否只在切换到水杉时发生、切回系统输入法能否恢复以及事件查看器摘要后，报告者在 2026-11-19 的评论中补充了 Windows x86 环境，以及事件查看器记录的 `Notepad--.exe` 在 `KERNELBASE.dll` 抛出 `c06d007e`（延迟加载找不到模块），并说明切换到水杉后持续崩溃、切换系统输入法不能恢复。

报告使用的 v0.5.0 早于两项相关修复，两者都首次随 Windows v0.6.0 发布，v0.6.1 也包含：`#11557` 于 2026-11-17 合入 develop，让 TSF 在 `ActivateEx` 中预先解析宿主导入，把缺模块、缺导出的 `0xC06D007E` / `0xC06D007F` 转为 HRESULT，不再让加载输入法的应用退出，x64 与 x86 都有回归（见 [宿主延迟加载记录](../../implemented/bug-fix/2026-11-04-windows-immersive-host-delay-load.md)）；`#11601` 于 2026-11-18 合入 develop，为 x86/x64 TSF 单独提供静态 CRT 宿主（见 [静态 CRT 隔离记录](../../implemented/bug-fix/2026-11-18-windows-qq-crt-isolation.md)）。`#11626` 报告的 `c06d007e` 正是 `#11557` 处理的异常码。本记录 2026-11-22 更新时，issue 中最新的证据仍来自 v0.5.0，还没有在 v0.6.0 或更新构建上对 Notepad-- 的复测结果；跟进时以 issue 中的最新评论为准。

已关闭的 `#11542` 是相邻报告：原报告是 QQ 崩溃，另一位用户补充 Notepad-- 也崩溃。`#11557` 的 PR 说明记录该 issue 的附件给出 `0xC06D007E`，与 `#11626` 相同；同一用户后来在 x86_64 系统上用本机绕过脚本恢复，其附带分析指向 CRT 区域的 `c0000005`。该 issue 以 `#11557` 和 `#11601` 的修复结论关闭。`#11626` 的报告者是另一位用户，环境为 x86，且没有任何 v0.6.0 或更新构建上的结果，因此不按重复处理，两项修复是否覆盖它仍需直接复测确认。当前证据还不能区分第三方插件、Qt 运行库和 TSF 宿主初始化路径。

## Proposal

以本记录作为 `#11626` 的跟踪记录，等待报告者在包含 `#11557` 与 `#11601` 的 Windows x86 构建（v0.6.0 或更新）上复测同一 Notepad-- 安装包。复测使用合成文本，记录切换水杉后的启动结果；若仍崩溃，补充新的脱敏模块名、异常码和调用栈摘要。只有在水杉路径仍能稳定触发时，才另开 PR 加入最小宿主兼容修复和回归测试，并以 `Fixes #11626` 关联。

## Alternatives considered

- **直接以 `#11557` 与 `#11601` 宣称解决**：最强理由是 `#11557` 已把同一异常码 `c06d007e` 转为 HRESULT，`#11601` 已处理同类运行库复用风险，`#11542` 中的 Notepad-- 崩溃也随之结案，但 `#11626` 来自另一位用户的 x86 环境，又没有 v0.6.0 或更新构建上的 Notepad-- 直接复测证据，因此不采用。
- **在 TSF 宿主中加入通用异常吞掉或延迟初始化**：最强理由是可能绕开单一第三方进程的启动崩溃，但会隐藏真实宿主错误并影响所有编辑器；`#11557` 只在激活入口处理延迟加载的缺模块、缺导出两类异常，已覆盖这条报告的异常码，因此不再扩大范围。
- **把 `#11626` 并入已关闭的 `#11542`**：最强理由是两者都涉及 Notepad-- 和 `c06d007e`，修复也相同，但 `#11542` 的结案依据是另一位用户在 x86_64 上的恢复反馈，合并会丢失 x86 环境这条独立证据，也没有人在 x86 上确认过，因此不采用。

## Acceptance criteria

- 在包含 `#11557` 与 `#11601` 的 Windows x86 构建中完成 Notepad-- 最小复测，并把结果记录到 `#11626`。
- 若不再复现，以复测结果为依据结案，不提交代码改动。
- 若问题仍归因于水杉，在独立 PR 中加入对应代码、回归测试和 Windows 验收记录。

## Risks

本记录只有调查结论，不宣称已修复第三方编辑器。未经复现的 TSF 生命周期改动可能影响其他宿主。报告者若无法复测，跟踪会停留在现有证据上，需要维护者另行判断是否以证据不足结案。
