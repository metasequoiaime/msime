# Agent Note: 剪贴板添加常用语的独立提示

Status: proposed

## Problem

#9351：剪贴板中「添加到常用语」的结果复用候选区诊断行，提示出现和消失都会改变候选区高度，并触发整页重画。用户把这种变化感受为等待和卡顿，希望把提示放到手机屏幕顶部，原位置保持正常列表。

目前保存已经在 `preferencesWorker` 执行，先验证提示带来的布局变化，不把后台文件保存误判为主线程阻塞。

## Proposal

仅为剪贴板添加常用语的校验、成功和失败结果提供独立的临时提示；不改设备信息、引擎错误等其他诊断反馈。使用输入法现有窗口令牌下的 `TYPE_INPUT_METHOD_DIALOG` 独立窗口验证屏幕顶部定位，不申请悬浮窗权限。`PopupWindow` 原型在 API 35 上能画到顶部，API 28 上出现黑色长条；不继续依赖越过 IME 父窗口的应用子窗口。

如果窗口方案可行，提示可点按关闭、不可取焦点；不触发 `render()`，不改变候选区、键盘和剪贴板卡片的位置；重复提示替换前一条，定时消失，输入结束、收起键盘、重建输入视图和服务销毁时取消窗口及回调。异步保存结果需要绑定本次提示代次，收起键盘后的迟到结果不能再弹窗。

## Existing notes

检索 `diagnosticView`、诊断行、输入提示和 `PopupWindow`：与[设备信息复制反馈](../../implemented/feature/2026-10-17-device-info-copy.md)部分重叠；其诊断行保底用途不变，本片只处理添加常用语。候选借用、插件失败提示和候选删除菜单笔记属于其他消息来源，不改变它们的行为。现有 `ImeLayoutRows` 注释指出 API 28 的选项子窗口受 IME 父窗口裁剪，这是需要设备验证的边界。本片没有完全吸收或作废的旧笔记。

## 原型证据

`PopupWindow` 关闭裁剪后，API 28 的窗口报告坐标虽然在顶部，实际截图却出现从提示下沿延伸到 IME 顶沿的黑色长条，不能只以 `dumpsys` 的坐标认定成功。API 28 的 `AccessibilityController` 明确过滤 `FLAG_NOT_TOUCHABLE` 窗口，故最终提示允许点按关闭，以保留无障碍可见性；`FLAG_NOT_FOCUSABLE` 保持编辑器焦点，`FLAG_NOT_TOUCH_MODAL` 允许窗口之外继续操作。

## Alternatives considered

- 系统文字 Toast：系统管理窗口与生命周期，实现最少；但 Android R 起面向 R 及以上的文字 Toast 忽略 `setGravity`，不能满足屏幕顶部位置，见[官方 API 说明](https://developer.android.com/reference/android/widget/Toast#setGravity(int,%20int,%20int))。
- `PopupWindow` 应用子窗口：复用现有键盘选项菜单方案，生命周期和父窗口关联最直接；但 API 28 的实际像素与窗口坐标不一致，不能作为跨版本的屏幕顶部提示。
- 申请全局悬浮窗权限：可以独立控制跨应用提示的位置；为一句常用语操作结果增加独立授权和跨应用窗口的管理成本，收益不足。
- 继续使用诊断行：能复用当前已有的提示、超时与无障碍机制；但会改变列表可用高度，并把局部操作结果交给全局键盘重画，保留了本 issue 报告的干扰。

## Acceptance criteria

- 旧 APK 在 API 28/35 均不能通过顶部提示检查；新方案能在 API 28/35 的屏幕顶部看到提示。
- 提示出现和消失时，剪贴板滚动位置、卡片坐标和操作位置不变，键盘和目标输入框继续响应。
- 成功确实保存正文，重复、无效正文和写入失败仍有明确结果；不记录真实剪贴板内容。
- 收起键盘、切换输入框、重复提示和销毁时清理窗口，不出现迟到提示或焦点丢失。
- 若 API 28/35 上不能在现有令牌和公开 API 下可靠定位屏幕顶部，停止该窗口实现，记录实际限制并重新评估替代位置；不以额外授权规避验证失败。

## Risks

`PopupWindow` 的屏幕裁剪和原点在 API 28 与新系统之间存在差异，位置不能只用 JVM 数值测试证明。顶部还需要避开状态栏和挖孔；无障碍提示与不可触摸窗口的可观测性需要在设备上确认。独立窗口方案正在设备上验证，尚未确认通过。
