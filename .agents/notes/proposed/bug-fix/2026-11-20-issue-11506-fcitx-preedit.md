# Agent Note: 跟踪 Fcitx5 下 0.16.1 预编辑消失

Status: proposed

## Problem

`#11506` 报告 KDE Plasma Wayland、Fcitx5 5.1.22、Ubuntu 26.10 下，msime-linux 0.16.1 在 Qt 文本编辑器里输入 `nihao` 时候选窗正常，但看不到 `ni'hao` 预编辑；回退 0.16.0 立即恢复，再装回 0.16.1 再次消失，配置为候选窗口预编辑「不显示」（`empty`）、行内预编辑「拼音分词」（`pinyin`）。报告来自官网反馈表单，附有 0.16.1 与 0.16.0 两张对照截图，在两个 Qt 应用中复现；没有提供 Qt、Fcitx5-Qt 版本，`QT_IM_MODULE`、`QT_QPA_PLATFORM` 或 `fcitx5-diagnose` 输出。

对照截图给出的证据与报告文字不完全一致：两张截图里编辑器文本行都是空的，0.16.0 截图中带下划线的 `ni'hao` 画在候选面板顶部，0.16.1 截图中候选面板没有这一行。这正是输入上下文的能力标志里没有 `CapabilityFlag::Preedit` 时，水杉把预编辑交给 Fcitx5 面板代画的表现。该标志缺失有两种来源：客户端本身没有声明，或者 Fcitx5 的「在程序中显示预编辑文本」被关闭，此时 Fcitx5 的 `InputContext::capabilityFlags()` 会去掉这一标志。`#11201`（已合并并随 0.16.1 发布，见 `linux-v0.16.0..linux-v0.16.1` 中 `platforms/linux/fcitx5/FcitxEngine.cpp` 的 `FcitxState::render()`）把这条回退改为只在候选窗口预编辑不是 `empty` 或方案为 `AlwaysInlinePreedit` 时才执行，因此报告配置下面板里的拼音按设计被移除。声明了客户端预编辑能力的上下文仍走 `setClientPreedit`，不受该改动影响。

维护者在 issue 中的评论曾把 Fcitx5 5.1.23 的一项上游修复列为可能原因：该版本在 `zwp_input_method_v2` 收到 `done()` 时强制刷新预编辑（fcitx/fcitx5#1690）。这项修复针对的是已经走客户端预编辑的链路；截图显示 0.16.0 下预编辑同样不在输入框内，它解释不了版本切换带来的差异，权重随之下降，只在确认客户端声明了预编辑能力后才需要复测。

## Proposal

用本记录跟踪 `#11506`，先把问题定性为「客户端未声明预编辑能力时，候选窗口预编辑关闭是否也应关闭面板回退」的设置语义问题，而不是客户端预编辑链路丢字：

1. 向报告者确认：0.16.0 下看到的 `ni'hao` 是否就是候选面板顶部那一行；并请求 Qt 与 Fcitx5-Qt 版本、`QT_IM_MODULE`、`QT_QPA_PLATFORM` 和脱敏的 `fcitx5-diagnose` 输出，并确认 Fcitx5 的「在程序中显示预编辑文本」是否开启，判断该应用的输入上下文是否带有 `CapabilityFlag::Preedit`。
2. 若上下文未声明客户端预编辑：由维护者决定设置语义，在保留 `#11201` 契约（候选窗口预编辑「不显示」时面板不出现编码）与「客户端无法行内显示时，行内预编辑样式回退到面板」之间二选一，或在设置界面说明这一组合下拼音不可见。
3. 若上下文已声明客户端预编辑而输入框仍无文本：请报告者在同一环境升级到 Fcitx5/Fcitx5-Qt 5.1.23 或更新版本复测，仍复现时在水杉侧做最小改动并补 Qt/Fcitx5 回归。

修复本身另开 PR，并在其中写 `Fixes #11506`。

## Alternatives considered

- **直接回退 `#11201`**：最强理由是能让报告配置下重新看到面板里的拼音，与 0.16.0 一致；但会让 JetBrains 等不声明客户端预编辑的编辑器在候选窗口预编辑关闭时重新出现编码行，违背 `#11201` 已落地的设置契约，因此在维护者确定语义前不采用。
- **把预编辑文本强制绘制到候选窗口，不看设置**：最强理由是总能让用户看到拼音，但同样推翻候选窗口预编辑开关，也不能把文字放进目标应用输入框，因此不采用。
- **只等待上游 Fcitx5 5.1.23 复测**：最强理由是上游修复的发布时间和 Wayland 预编辑现象吻合；但截图显示 0.16.0 下预编辑同样不在输入框，单靠上游升级无法解释版本切换带来的差异，因此只作为第 3 步的分支。

## Acceptance criteria

- 记录报告环境中目标 Qt 应用的输入上下文是否声明 `CapabilityFlag::Preedit`，以及对应的 Qt、Fcitx5-Qt、`QT_IM_MODULE`、`QT_QPA_PLATFORM`。
- 维护者对「客户端无预编辑能力 + 候选窗口预编辑不显示 + 行内预编辑拼音分词」组合的期望行为有明确结论，并写进修复 PR 或对应的实施记录。
- 修复 PR 带 `Fixes #11506`，原生 Fcitx5 回归测试覆盖选定语义下面板回退的显示与隐藏。

## Risks

本记录不宣称水杉已经修复 `#11506`。按截图得出的定性依赖报告者对两张截图的说明，若报告者实际看到的是输入框内的行内预编辑，需要回到客户端预编辑链路排查。改变面板回退语义会影响所有不声明客户端预编辑的 Linux 编辑器，回退宿主客户端预编辑能力则会影响所有正常支持行内预编辑的用户。
