# Agent Note: 调查 macOS 快速双拼输入异常

Status: proposed

## Problem

`#11391` 报告 macOS 26.6、水杉 0.59.4、微软双拼下快速输入时字母被错误分词、进入英文候选或候选窗口不显示。报告正文只有这三种现象和版本信息，没有最小按键串、异常时预编辑文本、编辑器和输入源切换上下文，无法区分会话方案读取、输入源上下文重置和候选窗口重绘问题。

维护者在 2026-11-13 的 issue 评论中说明 `develop` 已合入首个会话读取最新双拼方案（#11333）和输入源切换时保留/重置会话上下文（#11336、#11341）的修复，同时指出仅凭“打快了”还不能判断问题属于这两类，还是候选窗口重绘拿不到光标，并请报告者补充按键串、预编辑文本、输入源切换情况、受影响编辑器、当前 develop/nightly 是否复现和脱敏诊断片段。这三个 PR 都在 2026-11-13 合入 develop；按 git 标签核对，它们不在报告者使用的 `macos-v0.59.4` 中，首次随 `macos-v0.60.0` 发布，因此报告中的现象可能部分来自这些已修复的问题，需要在 0.60.0 及以后的版本上重新确认。报告者补充的复现信息和其他引用本 issue 的 PR 以 issue 时间线为准。同为 macOS、水杉 0.59.4 的 #11315（双拼首次输入为全拼模式）已由 #11333 修复关闭；若本 issue 的“字母全部分词”来自首个会话仍按全拼切分双拼按键，即属于这一类，但现有报告不足以确认。按关键词检索未找到 macOS 上的重复 issue；标题相近的 #10887（双拼概率丢字）是 Windows 上选词后残留按键的报告，维护者已将其作为 #10867（Windows 小鹤双拼选词后残留按键）的重复关闭，现象和平台都与本问题不同。

## Proposal

本记录作为 `#11391` 的跟踪记录合入 develop，修复不在本记录所在 PR 中进行。继续收集合成复现证据：具体按键串、异常预编辑文本、编辑器类型、是否刚从其他输入源切回、是否使用 Caps Lock/Fn/Shift，以及 `macos-v0.60.0` 及以后的正式版、当前 develop 或 nightly（均已包含 #11333、#11336、#11341）是否仍复现。必要时启用诊断日志，仅保留按键延迟、候选窗口状态和输入源状态行。拿到可复现的按键串并确认根因后，另开 PR 加入最小修复和 macOS 回归测试，正文写 `Fixes #11391`；若报告者确认上述较新版本已不再复现，则以上述三个已合并 PR 关闭 issue，并把本记录改为相应状态。

## Alternatives considered

- **直接扩大双拼按键超时或修改分词规则**：最强理由是可能缓解快速输入，但会改变所有用户的组字边界，且没有复现按键串支撑，因此不采用。
- **回退现有输入源上下文修复**：最强理由是 issue 可能与切换输入源后的会话状态有关，但回退会重新引入已修复的跨输入源问题，因此不采用。

## Acceptance criteria

- 获得最小合成按键串和受影响编辑器信息。
- 在包含 #11333、#11336、#11341 的版本（`macos-v0.60.0` 及以后、develop 或 nightly）上确认是否仍复现。
- 根因明确后，修复 PR 加入 macOS 宿主回归和真实编辑器验收记录。

## Risks

本记录只是调查与跟踪记录，不宣称快速输入问题已修复。未经复现的超时或分词改动会影响所有双拼用户。报告者长期不补充信息时，问题可能无法定位，需要维护者自行用常见微软双拼按键串在真实编辑器中尝试复现。
