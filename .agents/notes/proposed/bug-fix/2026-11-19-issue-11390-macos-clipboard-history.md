# Agent Note: #11390 macOS 系统剪贴板历史调查

Status: proposed

## Problem

#11390 报告在 macOS 26.6、水杉 0.59.4 下，按 `⌘Space` 再按 `⌘4` 打开的 Spotlight 系统剪贴板历史为空。报告者已给出系统版本、水杉版本和复现入口；维护者 2026-11-15 请求的合成文本对照（切换水杉输入源前后各打开一次历史）、其他应用的复制项是否也消失、水杉本地剪贴板历史开关状态，截至 2026-11-22 本笔记更新时 issue 中尚无报告者回复；之后的进展以 issue 评论为准。

代码核查结论：

- 本地剪贴板历史采集（`platforms/macos/src/backend/clipboard/BackendClipboardCapture.swift` 的 `MacClipboardCapture`，以及 Tauri 侧 `crates/host-macos/native/clipboard.mm`）只读取 `NSPasteboard` 的 `changeCount`、类型和字符串，不调用 `clearContents` 或写入 API，也不在输入源切换时触发写入。同一文件里的 `MacPasteboardSource.setText` 会先 `clearContents` 再写入，但只由下面的云剪贴板自动同步调用，采样路径不使用它。
- 0.59.4 中会写系统剪贴板的路径都由用户主动触发：剪贴板面板复制条目、手写面板复制、表情面板复制（`MacEmojiClipboard`）、支持窗口复制 QQ 群号，均为先 `clearContents` 再 `setString` 的普通复制；语音输入的提交方式设为 `ctrl_v` 时（`platforms/macos/src/voice/VoiceTextCommit.h`，默认是 `tsf`），会先 `clearContents` 再写入带 `org.nspasteboard.ConcealedType` 与 `org.nspasteboard.AutoGeneratedType` 标记的识别文本并模拟粘贴，这些标记的用意是让剪贴板历史工具跳过该条目。
- 云剪贴板自动同步（`BackendCloudClipboardAutoSync.swift`，#11392）在登录且开启云剪贴板时于后台写入接收到的文本，这是唯一不经用户操作的写入路径。#11392 首次发布于 macos-v0.60.1，报告者的 0.59.4 不含这条路径。
- 上述写入都是替换当前内容的单次写入，按设计应在历史中新增条目或被历史跳过，而不是清空已有历史。现有证据不足以把系统历史为空归因于输入法。

## Proposal

以这份笔记作为 #11390 的跟踪记录落地，修复另开 PR。下一步用合成文本复现：在同一应用执行一次普通 `⌘C`，再分别在切换水杉输入源前后打开 Spotlight 剪贴板历史，记录历史是只缺部分条目还是整体为空、其他应用的条目是否同时消失、水杉本地剪贴板历史与云剪贴板开关状态、语音输入提交方式及水杉版本。只有确认存在由输入法造成的写入或清空路径时，才在新 PR 中加入修复和回归测试，并写 `Fixes #11390`；若复现显示与输入法无关，则在 issue 中给出对照结果。

## Alternatives considered

- 修改公共剪贴板监听或给输入源切换加清空保护：当前没有写入证据，可能破坏系统剪贴板和 Spotlight 历史。
- 保持 Draft PR 不合入：调查记录只留在分支上，后续修复 PR 无法引用 develop 上的跟踪结论，因此改为落地为提议笔记。

## Acceptance criteria

- 复现结果明确 Spotlight 历史是只缺部分条目还是整体为空，以及是否与切换水杉输入源相关。
- 确认输入法是否在用户未操作时调用系统剪贴板写入或清空 API（含云剪贴板自动同步开启与关闭两种情况，以及语音输入 `ctrl_v` 提交方式）。
- 有产品责任证据后，修复在单独 PR 中以 `Fixes #11390` 提交并附回归测试；否则不改动剪贴板监听。

## Risks

未确认写入者时修改监听可能影响所有 macOS 应用的剪贴板历史。云剪贴板自动同步从 0.60.1 起会在后台写系统剪贴板，较新版本的复现需要分别记录其开关状态，避免把两类现象混在一起。
