# Agent Note: #11464 输入源变灰的复测跟踪

Status: proposed

## Problem

`#11464` 报告 macOS 26.7.1、水杉 0.59.4、双拼方案下输入源经常变灰，无法切换到水杉，删除后重新加入也不能恢复。`#11231` 的输入法进程退出收尾修复已经进入 0.59.4，因此不能把它当作这条报告的修复依据。此前的调查记录见已关闭的 PR `#11704`，其中没有产品代码改动。

`#11592` 的报告者后来补充了另一组 macOS 27.2.1 证据：输入法进程持续运行，失败时所有应用都被切回 ABC，输入源图标变灰，系统安全输入状态可能由其他进程持有。这个现象与 `#11464` 的输入源变灰相似，但两个报告的系统版本、方案和恢复表现不同，目前不能证明是同一责任路径。

## Proposal

本次只把新的复测边界和两条报告之间的证据关系记录进仓库，不改输入源注册、进程重启或自动恢复逻辑。当前代码和已有测试没有显示水杉会主动把双拼、五笔统一禁用，也没有报告者环境的状态输出来确认是未注册、无可选模式、进程退出，还是系统安全输入导致的全局置灰。

继续推进 `#11464` 前，需要报告者在包含 `#11231` 的最新 nightly 或预览版上补充以下合成、脱敏证据：

- 双拼和五笔是否同时变灰，输入源菜单显示什么图标，以及能否切换到系统 ABC。
- 复现前后输入法进程是否重启，`check_input_source.swift` 输出的注册、启用和可选状态。
- 失败时的 `focus_in`、`keyboard_loaded`、`input_source switched_away` 诊断日志时间点，不包含输入文本、令牌和私人路径。
- 删除并重新加入输入源后是否恢复，以及恢复时是否有安全输入占用者或系统窗口状态变化。

若这些证据指向水杉的输入源注册或进程生命周期，再另开独立修复 PR，并用 `Fixes #11464` 关联本 issue；若指向另一个进程持有系统安全输入，则在 issue 中记录责任边界，不增加会改写用户输入源配置的自动重注册行为。

## Alternatives considered

- **重复提交 `#11231` 的进程退出收尾改动**：它已经随报告者使用的 0.59.4 发布，无法解释当前报告，重复修改也没有新增证据。
- **无条件重注册输入源或重启输入法**：可能暂时恢复图标，却会覆盖用户选择并掩盖系统安全输入、输入源注册或进程崩溃的真实原因。
- **把 `#11464` 与 `#11592` 直接合并**：两条报告的系统版本、输入方案和恢复现象不完全相同，在责任路径确认前合并会丢失独立复现信息。

## Acceptance criteria

- 获得 `#11464` 报告环境在最新包含 `#11231` 构建上的复测结果和输入源状态。
- 判断问题属于输入源注册、输入法进程生命周期、系统安全输入，还是其他宿主路径。
- 若属于水杉代码，另开带 macOS 回归测试和真实编辑器验收的 `Fixes #11464` 修复 PR；若不是，保留调查结论并在 issue 中说明不可修复边界。

## Risks

这份记录不宣称输入源变灰已经修复。未经复现就修改注册表或自动恢复流程，可能破坏用户的输入源选择、正在进行的组字和其他应用的 IMK 会话。
