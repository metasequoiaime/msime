# Agent Note: 在同一组字中按用户选择的语言连续转换

Status: proposed

## Problem

#8921 希望用户选择可用语言后，连续输入中英日的编码即可得到混合文字，不必在每段之间手动切换方案。现有英文和日文混输都只对整个输入串查一次；把它们同时打开仍没有跨语言的切分路径。给整段输入再增加一种语言候选，不能完成这个请求。

现有中文词频、英文权重和日文连接成本不在一个尺度上。日文混输已经记录过直接比较它们及仅按罗马字合法性识别的误判，不能把这些被否定的方案重新包装成统一识别。

## Proposal

在共享 Rust 引擎中增加按原始输入位置连接词条的网格。每条边携带消耗的输入范围、转换文字和语言；只有完整覆盖输入的路径才能成为混合候选。先支持已有可提供词典证据的中文、英文和日文提供者，用户选择的语言集合显式传入解码器。其他输入方案仍需建立可用于识别的语言证据，不能把接入三个提供者说成已覆盖全部语言。

解码器保留每个结束位置、已用语言集合和末尾语言的路径，跨语言回溯完整组字；不能在当前位置贪心地选最长词。先比较是否完整覆盖，再比较词条数、语言切换数与提供者返回的同读音候选名次。原始词频和日文成本只参与各自提供者内部排序，不直接比较。完整单语言路径的词条更少时，不强行把普通词拆成混合碎片；词条数相同则保留混合备选。结构排序和范围预算的独立内核契约见[路径内核](../../implemented/architecture/2026-10-24-multilingual-path-kernel.md)，词库识别准确率尚未得到证明。

统一输入使用独立且默认关闭的偏好，旧英文／日文混输语义保持。用户已明确选择中文优先、混合结果作为备选：有完整中文解释时，混合路径即使词条更少也不得抢占中文首选；内核返回完整中文路径的存在性，宿主编排消费这个事实，不能再自行识别语言。语言未选择、模型缺失、没有完整路径或预算用尽时保留既有候选和原始编码，不丢输入、不自动下载模型。

混合结果保留每段的语言与输入范围。上屏、简繁转换、选词学习、候选来源和宿主绘制必须消费这些信息：只转换中文片段，不把日文汉字整体转成中文繁体，不把跨语言整句写入拼音词库。共享设置页及 Windows、Android、iOS 原生设置都要提供同一份语言选择契约。

## Alternatives considered

- 复用现有英文和日文整段混输，能省掉新配置、来源与宿主适配，且已有误判校准；没有采用，因为它没有跨语言切分，无法完成 issue 的连续输入例子。
- 每个位置贪心选择最长词，计算量小，也容易增量更新；没有采用，因为一个较长前缀可能让剩余输入无法转换，必须保留不同语言的完整路径。
- 把所有提供者的原始权重直接相加，能立即复用各自排序；没有采用，因为词频和连接成本的数值尺度及方向不同，结果没有可解释的跨语言意义。
- 用在线 AI 直接重写输入，能处理未知词和复杂混句；没有采用，因为按键转换不能依赖网络、账号额度或把用户输入上传到服务。

## Acceptance criteria

- 用合成词库证明两次以上语言切换、全串覆盖、歧义备选、关闭及语言子集约束、模型缺失、拼写中途状态和非贪心回溯。
- 在真实公开词库上核对 issue 的中英日连续例子及中文、英文、日文对照，记录误判和每键预算，不能仅以合成测试通过宣布完成。
- 共享偏好、资源门控、候选来源、逐段简繁、上屏与学习边界完成真实 Host API 回归；选中混合结果后能正常开始下一段。
- 共享页面和三套原生设置可读写相同配置；相关平台原生构建、设备专项、完整 quick、独立复审及 CI 通过。缺少的真实系统入口验收须继续列明，PR 保持 `Refs #8921`。

## Risks

锁定公开词库的首轮 22 条探索中，19 条单语言对照有 14 条被错误强制混合，包括 `women`→我men、`hello`→hell哦。与完整单语言路径比较后，这 19 条不再新增混合候选，3 条混合输入仍有完整路径。这不是规模准确率评测：issue 示例的中文片段仍误选为「在日问世」，中文片段的词面排序需要复用现有引擎，不能把结构排序当成语言模型。探索夹具的日文最低长度曾按假名数而非拍数计算，接入提供者时必须使用生产拍数契约。

跨语言网格若逐键重复查询全部子串会影响输入延迟，需要按实际调用次数和耗时决定增量缓存。候选来源与逐段简繁会经过多个宿主，遗漏一个消费点就可能错误上屏或学习；在这些契约补齐前不能开启产品入口。

## Dictionary adapter slice

词库适配封装为共享引擎的 `DictionaryComposer`，已落地的查询、增量失效和整体预算契约见[词库适配笔记](../../implemented/architecture/2026-10-24-multilingual-dictionary-adapter.md)。锁定公开资源的 24 个样例通过整串与逐字追加一致性检查，原例输出为 `hello在中文是你好在日文是おはよう`；19 个单语言对照没有新增混合行，两项歧义保留完整中文证据。这是有限校准，不能代表整体识别准确率。日文后台加载的就绪领取与同串失效契约已补入适配器笔记；公开资源有限校准不能代替设备与原生入口验收。

## Session candidate slice

会话候选和学习边界已落地的契约见[会话候选笔记](../../implemented/architecture/2026-10-24-multilingual-session-candidates.md)。共享偏好默认关闭；Host API 只在显式开启且资源及版本门槛通过时注入所选语言集合。只有普通全拼 26 键组字、混输总开关打开且没有专用英文、本地模式、光标前缀、辅助码或单字限制时查询适配器。当前提供者的中文边是全拼，不把双拼原始编码误当全拼。新增来源追加为 18，不复用既有 ABI 数值；混合候选整段消费，不调频、不写跨语言整句或个人上下文。完整中文存在时将混合行放在完整中文之后；固定排位等已有用户选择不因新增行而被重新解释。

会话使用已解析的日文模型路径，空路径才回退到资源目录，并在准备阶段沿现有提供者预热。当前最佳混合结果最多一行，语言分段作为单个可选转换随快照传递，按来源、编码及完整词面匹配，避免为每个重排路径再增加一组平行向量。逐段简繁和共享偏好已沿 Host API 接通，产品入口仍默认关闭。

## Host and runtime output slice

Host 原始输入身份、语言分段和共享逐段展示及上屏契约见[运行时逐段输出](../../implemented/architecture/2026-10-24-multilingual-runtime-output.md)。中文段与暂存中文前缀按已注入的简繁设置转换，日文与英文及上屏尾部保持原样；来源 18 的成功上屏禁止宿主整行再转，元数据失效保留原文。以词定字按明确首末方向追溯所属语言；原始首行提交命令按引擎座位逆映射记录；分段变化触发候选刷新。产品 Host API 构造与空闲重建均注入经过滤的语言集合；四套设置和六宿主消费已接线，Windows 同时包含 WinUI 与 Win7 原生入口。固定 develop 整合后完整 quick 通过，Android API35 真实 IME 专项和 iOS 桥接模拟器测试通过；Windows 定位旧夹具假设并修正后，在交互桌面原生全套 267 项通过，Harmony 仅完成含核心资源的未签名打包，具体边界见运行时笔记。设置选择只写共享契约，资源和版本门槛由 Host API 决定，避免宿主各自计算有效语言。完整设备、原生入口及 CI 验收须继续补齐并逐项记录。
