# Agent Note: 自建存储云剪贴板同步方案

Status: proposed

## Problem

#9989 希望在 Windows、Android、Linux 等设备之间同步常用词库和剪贴板，并提出 WebDAV、S3 或自建服务器。仓库已有自建云剪贴板中继，但它是专用 HTTP 协议；本地剪贴板历史、账号云剪贴板和中继数据的边界不能因为新增后端而悄悄改变。

## Proposal

把“自建剪贴板同步”限定为用户明确发送到「云剪贴板」的条目，不自动上传本机全部剪贴板历史。沿用已有端到端加密信封和设备批准模型，新增存储适配器层：WebDAV 以文件和清单实现，S3 以对象和同一清单实现，自建中继继续走现有协议。

- **对象范围**：文本、图片、创建时间、置顶和保留状态；本机历史、应用来源、复制时的窗口信息和账号会话不上传。每个条目有随机 `item_id`，删除写墓碑，不靠远端直接删文件判断传播。
- **加密**：条目在客户端加密后才上传；服务端只看到版本、大小、随机对象名和密文。设备密钥仍由现有设备批准流程建立，用户凭据只进入平台安全存储。导出、诊断和日志不包含密钥、令牌或剪贴板正文。
- **同步**：拉取清单后按 `item_id` 合并；内容版本按 `(logical_time, device_id, version_id)` 稳定排序，删除与修改同样参与排序。置顶和保留状态作为独立字段合并，清空操作写一个带设备序号的全局墓碑，避免离线设备把已清空内容重新上传。
- **后端边界**：共享层提供无网络的信封、游标、合并和大小限制；WebDAV/S3 只实现列举、读取、条件写和删除。网络请求永远在后台，不阻塞输入线程；写入本机历史或设置状态时沿用已有维护锁和错误码。
- **用户选择**：设置中明确区分“本机历史”“水杉账号”“自建存储”。切换后不自动迁移旧数据，首次启用显示“只同步以后手动发送的条目”，关闭后远端密文保留或删除由单独确认决定。

## Alternatives considered

- **直接把所有本机剪贴板历史同步**：覆盖面大，但会在用户没有明确动作时上传密码、验证码或应用内容，违背现有隐私边界，拒绝。
- **把 WebDAV/S3 伪装成现有中继**：可以少写设置项，但会把文件存储缺少的设备批准、条件写和删除墓碑语义藏在驱动里，两个后端最终产生不同的冲突行为，拒绝。
- **只同步一个可覆盖的 JSON 文件**：实现简单，但并发写会丢条目，离线删除无法传播，也无法进行幂等重放，拒绝。

## Acceptance criteria

- 两台合成设备经自建后端互传文本和图片，断网交错后恢复一致；重复拉取和重复提交不产生重复条目。
- 置顶、保留和清空在并发和离线情况下有稳定结果；删除墓碑不会被旧设备重新拉回。
- 本机未手动发送的合成剪贴板内容不会出现在网络请求；日志、诊断包和设置导出不含正文或凭据。
- WebDAV/S3 响应、清单、单条密文和批次都有上限；认证失败、条件写冲突、远端回滚和离线恢复均有测试。

## Risks

图片密文会增加存储和带宽，清空墓碑需要游标和压缩协议；用户删除远端数据后，离线设备重新上线的行为必须在 UI 中明确。WebDAV 服务的锁和条件请求支持不一致，适配器需要在不满足条件写时拒绝，而不能静默退化成最后写入获胜。
