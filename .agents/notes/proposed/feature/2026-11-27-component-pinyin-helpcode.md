# Agent Note: 拼音后用部件全拼筛选候选

Status: proposed

## Problem

Issue #11804 请求在全拼输入后按反引号进入部件全拼辅助筛选，例如 `cheng` 后输入部件读音筛出目标字。报告环境为 macOS 27.2、水杉 0.60.1，目标是让普通全拼用户不必记传统辅助码。

仓库目前有一条不同的能力：Shift+C 进入共享引擎的 `LocalInputMode::Chaizi`，随后按部件全拼查询编进引擎的 `chaizi-chars.tsv`，可输入多个部件并用撇号分隔。它从空闲状态开始，候选是拆字反查结果，不能接在已经完成的普通拼音组字后，也没有把结果限制为当前拼音候选的筛选操作。`SessionSnapshot::spelling_symbols` 已能把拆字分隔符交给宿主，桌面默认关闭拆字入口。

## Proposal

先把需求作为共享引擎设计记录，不在本 PR 直接改状态机。实现需要同时确定以下契约：

- 触发键只在普通全拼或双拼组字的有效末尾进入辅助筛选，不能与微软双拼的分号韵母、网址模式、标点和现有显式辅助码入口冲突。
- 辅助段使用部件全拼，而前面的输入仍按当前方案解释。双拼前缀需要先规范成全拼读音，再把部件读音限制到当前候选字的部件集合。
- 候选筛选必须由共享 `Session` 产生，不能让 macOS 宿主单独读取 `chaizi-chars.tsv` 或复制候选规则。现有 `Chaizi` 结果的字形转换、繁体去重和注释规则应复用或明确区分。
- 视图需要同时表达普通拼音、触发键和部件辅助段，编辑、退格、光标移动、取消和原样上屏都要保持可逆。`SessionSnapshot`、C ABI、Host API 和六个宿主的输入路由需要一起更新。
- 缺字段时的默认值、桌面设置入口和触发键选择需要单独产品决定。当前不能把现有拆字开关的默认关推导成新功能的出厂值。

验收应覆盖合成词库中的单字、多部件、部件顺序、同音重码、双拼前缀、微软分号冲突、光标编辑、繁简输出和六端宿主对同一快照的显示与上屏。拿到明确的触发键、默认值和候选筛选语义后，再另开实现 PR 并写 `Fixes #11804`。

## Alternatives considered

- 直接复用 Shift+C 拆字模式并改入口键。它不能限制到当前拼音候选，且会改变现有拆字模式的入口语义，因此不满足需求。
- 只在 macOS 候选窗中按部件表过滤。其他平台会得到不同候选，宿主也会复制引擎字形和繁简规则，因此不采用。
- 把部件拼音编码写入现有辅助码表。传统辅助码是固定短码，部件全拼允许多音节和任意部件顺序，混用会破坏校验、编辑和同步语义，因此不采用。

## Acceptance criteria

- 明确触发键、前缀方案、部件匹配顺序、默认值和设置入口。
- 共享 `Session` 能产生带稳定候选身份的筛选结果，C ABI 与 Host API 能表达并编辑该状态。
- 六端按同一快照完成候选显示、选择、取消和原样上屏，并有合成回归覆盖冲突键与旧模式。

## Risks

新状态同时跨普通组字和拆字模式，若没有稳定的编辑和候选身份契约，可能让触发键误结束组字、让不同宿主显示不同候选，或把普通标点误当成部件输入。
