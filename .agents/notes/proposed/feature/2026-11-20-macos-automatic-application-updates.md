# Agent Note: macOS 设置应用自动更新设计

Status: proposed

## Problem

#11681 希望 macOS 用户在设置应用内选择自动更新，应用发现新版后下载、校验并在用户允许的时机安装，避免手动打开发布页替换整套应用。当前仓库已经有 Sparkle 更新输入法本体和设置应用的能力，但两条更新路径的安装单位、用户确认和输入法占用状态不同，直接增加一个开关可能让设置应用和输入法 bundle 版本不一致，或在用户打字时重启。

## Proposal

在 macOS 设置应用的「关于」页增加自动更新开关，沿用现有更新通道和 Sparkle 签名链。开关只控制设置应用自身的后台检查与下载，安装仍由 Sparkle 在用户选择「现在安装」或下次启动时执行。设置应用与嵌入的输入法 bundle 必须作为同一个发布单元安装，安装前确认没有未提交的组字、录音、设置窗口或词库编辑工作，安装失败时保留旧 bundle 和当前状态目录。

输入法本体已有的静默下载与离开输入源时安装策略继续独立运行。新的设置应用开关不能改变输入法后台更新的默认值，也不能把稳定版用户切到测试或 nightly 通道。默认值、首次启用时机、是否允许下次启动自动安装、以及设置应用和输入法版本不一致时的回退规则，需要在实现 PR 前确定。

实现需要先补一条共享更新状态契约，明确检查、下载、待安装和失败状态的落盘位置，再接入原生关于页和 Sparkle 驱动。设置应用和输入法共用状态目录时，锁必须覆盖检查和安装之间的并发窗口。

## Alternatives considered

- 只在现有「检查更新」按钮旁增加自动检查，不增加设置开关。优点是改动小，但不能满足用户选择自动下载安装的需求，也无法表达安装时机。
- 让输入法本体的 Sparkle 直接更新整个 `MSIME.app`。优点是沿用现有输入法更新链，缺点是输入法是 `LSBackgroundOnly` 进程，不能安全承载设置应用的安装确认和整包替换。
- 把更新迁移到 Tauri updater。优点是设置应用已有 Rust 命令和页面，缺点是会引入第二套签名与发布元数据，并破坏现有 Sparkle 版本比较和密钥连续性。

## Acceptance criteria

- 设置应用能读取并持久化自动更新选择，默认值经过单独产品确认。
- 自动检查遵循用户选择的更新通道和现有节流规则，下载包完成后能显示版本、签名和摘要状态。
- 安装在用户选择的安全时机发生，不打断输入、录音、词库编辑或打开的设置窗口。
- 安装覆盖设置应用与嵌入输入法，保留状态目录、词库、学习记录和个性化设置。
- 失败、取消、断网和关闭开关后，旧版本继续可用，重试入口明确。
- macOS 13 以上完成设置应用、输入法和真实编辑器验收，覆盖稳定版、测试版和 nightly 通道边界。

## Risks

- 设置应用与输入法的 bundle 更新时序不一致会造成版本漂移或输入法加载旧资源。
- 自动安装时机判断遗漏录音、词库窗口或未提交组字，可能丢失用户工作。
- 更新开关和现有输入法自动更新策略含义相近，文案和状态若不区分会让用户误以为整套应用已经更新。
