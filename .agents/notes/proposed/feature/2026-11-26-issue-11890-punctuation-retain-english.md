# Agent Note: #11890 中文标点按键保留英文调查

Status: proposed

## Problem

#11890 希望在中文标点模式下，按键级保留部分 ASCII 标点。报告者重点使用反引号和反斜杠，并希望不必频繁切换英文模式。现有契约把反引号映射为 `·`，反斜杠映射为 `、`；反斜杠还与两个顿号开关共享键位。

issue 中已确认两项产品决定：保留反斜杠英文时接受两个顿号开关都关闭后不再从反斜杠输出顿号；macOS、Linux、HarmonyOS 在共享设置页仍是现有可编辑入口，不能只在 Windows、iOS、Android 增加控件。

## Proposal

后续实现采用按键集合 `preserve_english_punctuation`，只允许中文标点契约中已有的 21 个 ASCII 输入键：`simple` 段的 17 个键，加上引号键和书名号键。集合缺省为空，保持现有行为；集合中的键在中文标点模式下交回 ASCII 原键，日文方案不受影响。反斜杠进入集合后不再参与「至少一个顿号键开启」的归一，两个顿号开关可以同时关闭。

实现需要同步更新标点契约、Engine 的 `PunctuationMarks`、`client-core` 偏好校验与保存、Host API/View、Windows 偏好解析，以及 macOS、Linux、Android、iOS、HarmonyOS 的本地补全、跨过、空格转换和符号键面表。共享设置页增加该集合的多选入口，保持旧文档和缺字段默认值不变。

本 PR 只记录方案和依赖边界，不提前修改契约或宿主代码。当前架构要求 `packages/ui` 只修缺陷，macOS 的新设置入口正在迁移到原生界面；在该边界下直接增加共享设置控件会违反仓库约定，也会留下 macOS 无法编辑的半成品字段。待原生设置迁移为该设置提供合规入口后，再以独立实现 PR 关闭 #11890。

## Alternatives considered

- 现在只实现 Engine 和共享偏好：macOS 用户无法编辑该字段，设置能力不可达，不能满足 issue 的使用场景。
- 在 `packages/ui` 直接增加入口：会违反「共享 React 设置页只修缺陷」的迁移约定，并使迁移期间新增设置继续依赖冻结的 WebView 页面。
- 支持任意字符映射：各宿主无法预先识别补全、跨过和空格转换中的配对字符，Windows TIP 还需要扩展 IPC 表，范围超出当前需求。
- 把反斜杠并入顿号开关：无法表达「保留反斜杠英文」与「顿号键选择」两个独立决定，也会改变既有偏好语义。

## Acceptance criteria

- 原生设置迁移为 macOS、Linux、HarmonyOS 提供该字段的可编辑入口，共享 Rust 和 View 使用同一校验规则。
- 21 个允许键有契约测试，未知键、非 ASCII、重复键和日文方案均有拒绝或不变回归。
- 反引号、反斜杠、引号和书名号在六个平台的中文标点、组字、成对补全、跨过和空格转换行为一致。
- 实现 PR 使用 `Fixes #11890`，不改变缺字段默认值，附各平台实际验证结果。

## Risks

在界面迁移前落地字段会造成用户无法配置的半成品设置。只改 Engine 而不更新宿主手抄表会让补全、跨过或空格转换识别不到保留英文键，产生重复或错配字符。放宽顿号归一时若遗漏反斜杠路径，会出现界面显示与实际输出不一致。
