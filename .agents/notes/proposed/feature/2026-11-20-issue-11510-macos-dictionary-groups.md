# Agent Note: 跟踪 macOS 词库分组与批量管理

Status: proposed

## Problem

`#11510` 的报告者在水杉 IME 0.60.0、macOS 27.2.1、全拼方案下，希望云端词库和本地词库能像搜狗细胞词库那样自定义分组（相当于目录），按组管理组内的词，并支持批量删除，附了一张词库列表截图。报告提交于 2026-11-16 06:51 UTC，截至本记录更新时 issue 下没有其他评论，报告者也没有补充日志或复现步骤。

报告提交几小时后，`#11447`（`feat(dictionary): 六端支持词库分组与批量管理`，`Fixes #10996`）于 2026-11-16 14:12 UTC 合入 develop，并随 `macos-v0.60.1`（2026-11-19）发布；报告者使用的 0.60.0 不含这项改动。按 `docs/dictionary-groups.md` 和 `platforms/macos/src/dictionary/DictionaryCollectionsWindow.mm`，macOS 现在从「输入菜单 → 词库分组」打开原生窗口，一个命名词库就是一个分组，按自建、文件导入、社区来源列出，支持新建、改名、导入到新分组或同类型已有分组、多选启用和停用，以及确认后批量删除；停用或删除只撤回该分组独有的词条。

对照报告，已发布版本仍有三处没有覆盖：分组只有一层，不能把多个词库归入一个上级目录（`2026-11-14-dictionary-collection-groups.md` 把「新建分组表」列为未采用的方案）；窗口只列出分组的来源、名称和条数，不能浏览或编辑某个分组里的词；分组名称、来源和开关只保存在本机，账号和 WebDAV 不同步分组元数据，云端词库窗口也没有分组。`#10996`（导入词库支持分组管理并统一逻辑）已由 `#11447` 关闭，`#11510` 与它部分重叠，但多出了云端词库和组内词条管理两项诉求。

## Proposal

把本记录作为 `#11510` 的跟踪入口，不在其中提交实现。下一步先请报告者在 macOS 0.60.1 或更新版本上试用「词库分组」窗口，确认它是否满足需求，以及剩下的三项缺口里哪些仍然需要。确认后按需求分别开实现 PR：组内词条浏览与删除放在共享 `client-services` 集合规则和 macOS 原生窗口；多级目录需要先在共享层设计分组与集合的两层名称和开关如何不冲突；分组元数据跨设备同步需要新的冲突与加密协议，单独设计。界面改动在实现 PR 中补改前改后截图。

## Alternatives considered

- **直接在现有分组窗口里加文件夹层级和词条列表**：最强理由是入口已经存在、改动集中，但会在没有确认报告者实际诉求、也没有定下两层开关语义时锁定数据模型，因此不采用。
- **只在 macOS 本地加上级分组**：最强理由是实现简单，但其他五端共用同一套集合规则，单端加层级会让各平台分组结构分叉，与 `#10996` 要求的统一逻辑相反，因此不采用。
- **认为 `#11447` 已满足需求而直接关闭 `#11510`**：最强理由是分组和批量删除都已发布，但报告还提到云端词库和组内词条管理，这两项都没有实现，未经报告者确认就关闭会丢掉这部分诉求，因此不采用。

## Acceptance criteria

- 报告者或维护者在 macOS 0.60.1 及以上版本确认「词库分组」窗口覆盖了哪些诉求，并明确剩余需求。
- 对确认需要的缺口，写清分组持久化、同步、导入、删除和回滚契约，共享规则有行为测试，macOS 原生窗口有实现。
- 完成真实 macOS 输入法验收，并在实现 PR 中附界面改前改后截图。

## Risks

本记录只做跟踪，不宣称 macOS 已支持多级分组、组内词条管理或分组同步。报告者使用的是 `#11447` 之前的版本，若不先确认就按原文实现，可能重复已有能力或与现有单层分组模型冲突；未经契约确认的批量操作可能让用户词库的改动不可逆。
