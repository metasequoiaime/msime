# Agent Note: 移动端数字入口默认使用九宫格

Status: proposed

## Problem

#7834 要求从中文键盘点击数字入口后进入九宫格，同一面板可连续输入数字和四则运算符。Android、iOS 与 HarmonyOS 的拼音九键已有数字网格，常规 26 键和 14 键却仍进入横排 1–0 的符号层；三端数字侧栏也没有统一提供四则运算符。仅验证已有拼音九键不能证明常规数字入口符合要求。

## Proposal

将三端常规数字入口的默认显示改为可复用的数字九宫格，沿用电话顺序、0、小数点、删除、空格和回车。原拼音九键继续显示同一数字面板；已有独立数字布局的语言保留其输入契约。数字面板不改变原来的中文输入布局、语言或 Engine 网格状态，手动返回后恢复原键面。连续数字与运算符都按字面上屏，始终留在当前面板，组字中的数字仍先按现有切层规则完成组字。

四则运算 `+ - * /` 在数字面板就地提供，避免借中文标点转换产生全角运算字符。该需求不增加自动计算。键位统计区分原拼音九键与从字母键面进入的数字键，不能因为复用显示控件而把 26 键输入统计成拼音九键。

这是默认行为的变更，不恢复此前撤掉的两项设置或其旧偏好消费者。平板全尺寸、横屏分离式、手写、笔画、注音和日文的入口、底行、返回动作需要逐项核对，不能只改手机全拼截图后宣称三端完成。

## Historical audit

- [撤掉数字布局选项](../../implemented/simplification/2026-10-11-remove-number-keypad-settings.md)：部分取代。该决定去掉设置和计算器排列的理由继续成立；本次新要求改变的是固定横排这一默认行为，需要实现时互链，不能覆盖旧决定的理由。
- [Android 九键数字键面](../../implemented/feature/2026-10-08-android-nine-key-number-pad.md)：部分重叠，复用数字字面上屏、自定义侧栏、0 和小数点，不顺带修改已有算式求值。
- [数字层标点切换](../../implemented/feature/2026-10-14-android-number-layer-punctuation-toggle.md)：部分重叠，核对新数字面板与扩展符号层的功能入口和状态，避免丢失刚加入的标点切换。
- 数字行、语言数字键交换、底行对齐、符号键与快捷标点、九键双拼和键帽提示笔记涉及邻接显示与统计约束，继续保留；它们不持有常规数字入口默认横排的决定，不合并或归档。

## Alternatives considered

- 重新提供“26 键按 123”选项：能同时满足两种偏好，但维护者已因含义不清与分支负担撤掉该选项；新 issue 明确要求数字入口直接进入九宫格，因此调整默认行为。
- 只保证原拼音九键提供运算符：复用范围最小，但常规 26 键的数字入口仍是横排，不能满足验收。
- 新建一套独立拨号盘：布局与按键含义容易控制，但会复制三端已有的数字网格、按键反馈和底行；先核对并复用现有表面，仅在不能满足输入契约时拆出专用组件。

## Acceptance criteria

三端从全拼 26 键、双拼与 14 键等现有中文入口进入数字九宫格，验证 0–9、长串数字、小数点与四则运算都连续正确输出；手动返回恢复原布局。已有九键、独立语言数字面、中文标点开关、底行语言键、删除与回车继续可用，统计键位不混淆。Android 在 API 28 与 35 原生宿主验收，iOS 在原生键盘扩展验收，HarmonyOS 完成 ArkTS 真打包及可用设备上的系统入口验收；缺失设备证据时保留明确缺口。提交前跑各平台相关单测、quick、notes 和 diff 门禁。

## Risks

复用九键外框容易误触发 Engine 的九键组码、读音侧栏和手势；数字面板必须有独立于实际输入布局的显示判定。固定默认会改变习惯横排数字的用户体验，需要保留清楚的返回与符号入口。三端 UI 框架和大屏形态不同，源码表一致不能替代原生运行证据。
