# Agent Note: Android 文本编辑触控板与光标文字放大镜

Status: proposed

## Problem

#9260 要求在远程终端、脚本和普通编辑器中，通过键盘上的触控板上下左右移动光标，并把现有编辑操作放在同一面板，拖动时显示光标附近文字的放大镜。报告者提供的设置截图还包含水平和垂直灵敏度、按住工具临时打开、双击选词和三击选行、逐步震动、轨迹及放大镜开关。只给现有方向键添加滑动事件不能覆盖这份需求。

现有 `ImeTextEditPanel` 已拥有方向键、选择模式、首尾跳转、删除，以及右列可滚动的全选、复制、剪切、粘贴、数字键盘、空格和换行七项操作。它通过 `InputConnection` 向真正的编辑器发送 DPAD 和修饰键，不能把本地重画的一份文档当作实际编辑器。

## 历史检索

已检索活跃笔记和 Android 源码中的 `9260`、触控板、放大镜、`trackpad`、`Magnifier`：没有同一功能的实现。既有[文本编辑面板](../../implemented/feature/2026-10-08-android-text-edit-panel.md)持有编辑动作与选区修饰键的规则，本提案在其上增加交互入口，不替换复制、剪切或密码框的限制。GitHub 当前没有对应 #9260 的实现 PR，issue 已分配给 `houko`；独立分支为 `feat/issue-9260-text-trackpad`。

## 方案

- 在现有文本编辑面板增加方向键和触控板的显式切换。触控区域与原有编辑动作共存，保留上述七项右列操作、选择模式、首尾跳转和删除；新装仍从原方向键面板进入，用户主动切换后记住选择。工具栏和功能面板复用现有文本编辑入口，按住临时打开的行为由独立开关控制，松手恢复之前的面板状态。
- 单指拖动按相对距离移动，横向按字符、纵向按编辑器排版的行；小于一步的余量在同一手势内累计，反向先抵消余量，结束后清零。默认水平 12 dp、垂直 28 dp，可分别设置为 4–48 dp 和 8–96 dp。继续复用现有 DPAD、Shift 的按下和松开路径，避免在宿主侧猜测换行位置或破坏远程终端的按键协议。
- 选择模式与面板共用一个状态。长按后拖动临时延伸选区，松手只解除临时模式、保留编辑器选区；双击选词、三击选行由独立开关控制。文字边界使用平台分词能力，并核对输入连接、返回片段的偏移和最新选区；编辑器不提供足够上下文时给出明确反馈，不把一个局部片段误当成全文。
- 震动、轨迹和放大镜分别可关。震动遵守系统与现有键盘反馈设置；轨迹只在活动触摸期间保留。双击选择、震动、轨迹和放大镜的功能开关默认开启，但只有用户打开触控板后才参与交互。水平、垂直灵敏度的默认值和合法范围由共享 Rust `client-core` 定义，原生 Java 页面只负责呈现与持久化桥接；设置不加入账号同步白名单。
- 放大镜使用编辑器经 `InputConnection` 返回的有限光标上下文重画文字、选区和插入点，不截取其他应用的屏幕。优先跟随 `CursorAnchorInfo` 的插入点，经矩阵换成屏幕坐标；没有位置、位置不可见或被键盘遮挡时放在键盘上方。密码输入框直接绘制掩码，不读取明文；长选区不整段跨 Binder 读取。上下文读取放在单一后台队列，连续移动合并请求，并用输入连接身份和代次丢弃迟到结果。
- 宿主已有物理键盘候选栏的光标位置订阅。触控板放大镜复用 `synchronizeCursorUpdates` 的统一订阅入口，将两个消费者的需求合并；某一方结束不能发出取消订阅而破坏另一方。`onUpdateCursorAnchorInfo` 先分发给当前有效消费者，再执行其各自判断，不让物理键盘专属条件挡住软件键盘放大镜。
- 切换输入框、输入连接重建、隐藏键盘、关闭面板、失去窗口和多指状态转换均取消旧手势、停止重复动作并清除预览。轨迹和上下文不写日志、偏好或测试快照，测试只使用合成文档。

## Alternatives considered

- 单独新增一个没有编辑按钮的大面积触控板：移动区域更大，也容易复用上游的默认布局；但报告者明确要求把七项编辑操作一起保留，因此选择在现有面板中切换主要移动区，保留操作列。
- 只发送四方向按键，暂不提供放大镜和选区：可以最早覆盖远程终端的基础移动，也不需要读取上下文；但它遗漏显式需求，不能作为本 issue 的完整交付。
- 直接使用 Android `Magnifier` 放大宿主输入框：能复现原字体和真实像素；但该 API 需要调用进程持有附着窗口的源 `View`，输入法没有其他应用编辑器的 `View`，因此使用编辑器返回的文本绘制独立预览，不新增截图或无障碍服务权限。
- 为所有移动直接计算 `setSelection`：横向位置容易测试，也不依赖编辑器处理 DPAD；但视觉行由编辑器排版决定，且远程终端可能只接收按键。继续使用既有按键通道，只有明确需要的选词或选行操作在片段与绝对偏移均可靠时设置选区。

## 验收标准

本篇仅完成需求、源码和公开 API 调查，尚未实现生产代码、运行新增测试或创建 PR。后续交付需要以下证据，不能用纯算术测试代替设备验收：

1. JVM 回归先红后绿：二维余量和反向、取消后不泄漏余量、选区手势状态、双击和三击窗口、边界和代理对失败返回的处理，以及短片段、长选区、代理对、密码掩码和过期结果丢弃。
2. Rust 偏好回归：缺字段默认值、范围校验、往返、账号同步排除和恢复设置；确认默认值只有共享层一份。
3. API 28 和 API 35 的原生输入法设备测试：在独立 EditText 和 WebView 中真实拖动、上下跨行、反向、延伸选区、七项编辑操作、返回原键区和输入框切换取消；读取真实文本及选区验证，不只比对事件队列。
4. 放大镜设备检查：位置报告可用和拒绝报告、长选区、密码框、快速关闭或切换输入框，以及与物理键盘候选栏订阅共存。截图只含合成文本。
5. 原生设置页逐项开关、灵敏度边界、进程重启持久化和按住临时打开；普通方向键面板回归不变。远程终端还需真实客户端或可独立确认的按键接收宿主验收，不能以 EditText 通过替代。
6. 完整本地 quick、笔记门禁和差异检查通过后，仅为 #9260 创建一条 PR。新增本机构建树前再次检查系统盘至少 50 GiB，按仓库规定复用产物目录。

## Consequences

完整方案保留输入法现有编辑通道，让不支持文本回读的编辑器仍可接受方向移动；放大镜和基于文本的选择能力则明确受编辑器公开接口约束。代价是增加面板模式、触摸状态、原生设置以及一个有界异步上下文读取生命周期，需要同时验收软件键盘与物理键盘候选栏。

本方案不引入第三方依赖，不复制上游源码；若后续确需引入依赖或代码，另按许可证、来源固定提交和仓库依赖规则处理。

## 风险

当前尚未验证跨应用浮层的实际放置和不同编辑器的选词边界，不能把这份设计记为已实现。`InputConnection` 的回读可能阻塞或返回过期片段，异步队列、连接身份及代次核对是实施前提；光标订阅需要与现有候选栏共用所有权，不能独立取消别人的订阅。
