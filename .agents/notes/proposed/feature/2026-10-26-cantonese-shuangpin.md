# Agent Note: 粤语双拼独立键位规则

Status: proposed

## Problem

issue #9799 提议为现有粤拼方案增加粤语双拼。报告附带的参考仓库没有许可证声明，不能直接复制其中的 schema、映射表或词表；现有引擎已经有受许可的 `msime-cantonese.db` 和粤拼音节库存，可以作为候选边界。

## Proposal

依据公开的粤拼声母和韵母分类，独立实现从无声调粤拼音节到两键码的规则：普通声母同键，`gw`、`kw`、`ng`、`j` 分别映射到 `i`、`u`、`v`、`y`，零声母使用 `o`；韵母按固定的 26 个字母和 `;` 键分组。反向解析只在已加载的粤拼音节库存中枚举，按字节序稳定排序，不携带任何上游词表或 schema 文件。

当前先落地规则模型和反向查找的单元测试；接入 `CantoneseScheme`、会话偏好和各平台方案选择前，必须确认候选覆盖、编辑边界、分号键路由和移动端键盘布局的完整契约。

## Alternatives considered

- **直接复制 issue 附件仓库**：实现最快，但仓库没有许可证，无法证明可再分发。
- **把双拼码当作普通粤拼缩写交给现有分段器**：不需要新状态，但双拼码与粤拼音节边界不一一对应，无法在候选查询时恢复实际音节。
- **复制完整粤拼词表并生成新数据库**：候选质量可控，但重复已有受许可数据库并扩大资源包和维护面，因此先复用现有库存。

## Acceptance criteria

- 规则模型不包含参考仓库文件或其逐字数据，编码样例覆盖声母、零声母、复合声母和长短韵母。
- 反向查找只返回当前 `msime-cantonese.db` 音节库存中的结果，结果顺序稳定。
- 接入会话后，双拼码能查询现有粤拼候选，退格、候选选择、分隔符、光标编辑和繁体输出行为与粤拼方案保持一致。
- Android、iOS、macOS、Windows、Linux、HarmonyOS 的方案选择与键盘输入路径都有对应验证。

## Risks

规则分组存在同码多音节，候选数量和排序会改变；` ; ` 在部分宿主是候选翻页或选词键，需要先扩展 `spelling_symbols` 契约。没有真实粤语双拼用户验收时，键位布局和零声母约定仍可能需要调整。
