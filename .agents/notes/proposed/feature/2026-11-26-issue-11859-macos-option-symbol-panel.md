# Agent Note: #11859 macOS Option 长按符号面板调查

Status: proposed

## Problem

#11859 希望在 macOS 上长按 Option 打开符号面板。报告环境为 macOS 27.2.1，后续回复明确希望使用左 Option，并提到游戏场景下切换输入模式仍不能解决快捷键问题。issue 尚未说明长按期间系统输入法菜单、应用快捷键和按键重复是否应继续生效。

macOS 当前已有独立的符号面板路由、输入菜单、悬浮工具栏和中英文切换快捷键，但 `InputController` 没有全局 Option 长按符号面板手势。现有按住手势目录主要服务语音输入，不能直接复用为符号面板入口。

## Proposal

把 #11859 作为左 Option 长按手势的设计与约束记录。实现前需要明确左 Option 的按下、保持和释放语义：是否在超过阈值时吞掉 Option，是否在没有触发面板时将原始 Option 交回应用，是否允许右 Option 保持原有语义，面板打开时是否先结束组字，以及面板关闭后是否恢复原始修饰键状态。

若产品决定只对左 Option 生效，手势应在 macOS 宿主的统一事件路由中实现，复用现有符号面板 surface route。长按未达到阈值时必须保留 macOS Option 的正常修饰键行为，触发后只在确认面板已打开时吞掉对应事件，并为取消、失焦、系统安全输入和面板启动失败保留回退路径。

当前 PR 只记录调查边界，不新增全局修饰键拦截。缺少上述手势约束时直接实现会改变所有 macOS 应用的 Option 输入和快捷键行为，也无法为 Wine 游戏场景区分输入法责任与封装层接收问题。

## Alternatives considered

- 任意 Option 长按都打开面板：会覆盖右 Option 的字符层和用户已有应用快捷键，超出报告者明确的左 Option 需求。
- 立即吞掉左 Option：短按 Option 的字符输入和应用快捷键会丢失，不能接受。
- 复用语音按住手势配置：语音目录的按住与释放语义、权限和冲突处理不同，复用会把符号面板绑定到错误的设置和生命周期。
- 只在输入菜单增加入口：不能满足长按 Option 的需求，也不能解决游戏场景中的快速切换诉求。

## Acceptance criteria

- issue 明确左 Option 的触发阈值、未触发时的透传、触发后的吞键范围、失焦和取消行为。
- 有回归测试覆盖短按左 Option、长按打开面板、长按取消、右 Option、带其他修饰键、应用快捷键和安全输入状态。
- macOS 原生构建和真实编辑器验收确认短按 Option 与普通应用快捷键不回归。
- 实现 PR 使用 `Fixes #11859`，并在 PR 正文说明 Wine/游戏场景只作为复现环境，不增加未经证实的应用规则。

## Risks

全局修饰键拦截会影响所有 macOS 应用的输入和快捷键。阈值、事件重放或面板启动失败处理不当，会造成 Option 字符丢失或应用收到重复快捷键。未确认安全输入状态时强行弹出面板，可能违反系统对密码和安全输入窗口的限制。
