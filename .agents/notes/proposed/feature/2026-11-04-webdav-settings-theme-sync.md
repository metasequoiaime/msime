# Agent Note: WebDAV 设置与主题自动同步设计

Status: proposed

## Problem

#10787 要求用用户自己的 WebDAV 同步设置和主题，并在修改后自动同步。现有账号设置同步只覆盖服务端字段表，云剪贴板和「我的词条」WebDAV 各自有独立的端到端加密与设备批准状态；如果直接把整份偏好或主题目录复制到网盘，会把窗口位置、设备路径、宿主能力、下载模型和凭据带到不兼容的设备，也会在两台设备同时修改时静默覆盖。

## Proposal

### 同步边界

同步文档只包含经过共享 Rust 白名单筛选的用户选择：输入方案、输入与候选行为、可跨平台的显示偏好，以及主题选择和用户主题的可移植定义。每个字段由 `client-core` 标记为 `shared`、`theme` 或 `local`；只有前两类进入 WebDAV 文档。

下列内容永远是本机数据：窗口位置和尺寸、快捷键中绑定具体宿主的动作、`platform.*` 宿主能力或编辑器字段、词库和输入习惯、下载目录与模型文件、账号会话、WebDAV 地址/账号/应用密码、设备身份和密钥串。主题中的绝对路径、图片外链、字体文件名和本机文件引用也不上传；可移植主题只允许已验证的有限颜色、尺寸、字体族名和内联图片，超出上限的包留在本机并报告不可同步。

### 存储与加密

在 WebDAV 基地址下使用独立的 `msime-settings/v1/` 命名空间，不复用 `msime-clipboard/` 或 `msime-dictionary/`。文档采用云剪贴板相同的设备身份、核对码、批准和密钥轮换协议，网盘只看到加密事件和大小元数据；设置与主题使用独立的密钥串，不能因为移除剪贴板设备而读取设置数据。网盘凭据只进本机安全存储和凭据清单，不进入导出文件、账号设置同步或诊断快照。

事件正文是有界的加密 JSON，包含文档修订、字段变更和主题包内容；设备先以临时文件 `PUT`，再用 `MOVE` 独占创建序号。客户端保留最近检查点和事件链，发现回退、格式不认识或超出大小上限时停止自动同步并要求重新开始，不能把网盘内容当作信任根。

### 冲突与自动同步

每个可同步字段保存基线摘要和本机修改时间。无冲突的字段按三方合并写回；同一字段两端都改时，较新的设备逻辑时钟获胜，并在设置页显示最近一次合并来源。主题选择与主题定义作为两个字段集合合并：选择冲突沿用用户最后一次本机选择，定义冲突保留双方命名版本并要求用户选一个，避免自动覆盖正在使用的主题。删除主题是带版本的墓碑，不能因另一台设备的旧快照重新出现。

修改偏好或主题后先本地落盘，再以一分钟防抖触发自动同步；应用回到前台、打开同步页和手动「立即同步」可以立即运行，但都受共享退避和 WebDAV 请求额度限制。自动同步不在输入线程运行；设置页正在编辑时只读状态，保存成功后再记一条本机修改。账号设置同步与 WebDAV 同时配置时各自使用独立命名空间，WebDAV 的结果只写入它白名单中的字段，不覆盖账号同步未涉及的字段。

### 分层与迁移

先在 `client-core` 定义字段白名单、三方合并、事件格式和大小上限，在 `client-services` 复用现有 WebDAV 传输与加密设备协议，在 `host-api` 提供 `settings_webdav` 的无网络 JSON 请求入口。宿主只提供本机偏好目录、主题目录和触发信号；网络、退避、锁和冲突状态由 Rust 持有。桌面、Android、iOS、HarmonyOS 的设置界面按各自原生迁移顺序接入，不能在共享 React 设置页新增入口。

首个实现阶段只交付核心契约、WebDAV 驱动和桌面原生宿主；移动端沿用同一 C/JNI/Swift 契约逐平台接入。现有账号设置同步和「我的词条」同步保持不变，直到该设计的字段表和真机迁移验收完成。

## Alternatives considered

- **直接同步整份设置文件和主题目录**：实现最快，也能覆盖用户期待的“换设备一样”。否掉：会泄露或覆盖设备路径、窗口位置、模型和宿主专属设置，主题里的外链和本机文件也无法在另一设备解析。
- **复用账号设置同步的明文服务端文档**：不用增加 WebDAV 协议。否掉：需求明确是用户自己的网盘，且设置和主题包含应由端到端加密保护的内容，不能把 WebDAV 凭据或主题数据混进账号字段表。
- **每台设备整份最后写入者胜出**：冲突规则简单。否掉：两台设备各改一个设置时会丢掉其中一处，主题定义和选择也会互相覆盖；按字段三方合并能保留独立修改。
- **先做主题二进制文件同步，再补设置**：用户可先获得完整皮肤迁移。否掉：二进制包的大小、路径和字体依赖尚未有跨平台契约，先同步会固化不可移植格式；先约束可移植定义和大小上限更可逆。

## Acceptance criteria

- `client-core` 的白名单逐字段列出 `shared`、`theme`、`local`，测试确认设备路径、模型、窗口位置、账号凭据和平台字段永不出网。
- 模拟 WebDAV 服务测试首次配对、设备批准、加密读写、断点续传、回退检测、大小上限、退避和凭据脱敏。
- 三方合并测试覆盖两端改不同字段、同字段冲突、主题定义与选择冲突、删除墓碑和重复事件，结果与到达顺序无关。
- 宿主契约测试确认自动同步在工作线程运行，输入会话不被阻塞，账号设置同步和 WebDAV 不互相覆盖。
- 每个平台接入 PR 在真实设置页和真实编辑器中验证保存、自动同步、冲突提示和恢复默认；未完成的平台不声称“全平台已支持”。

## Risks

- 可移植主题的白名单和图片上限若过窄，用户会看到主题未同步；必须在界面上显示不可同步字段和原因，不静默丢弃。
- 用户同时在多台设备编辑同一个主题时，逻辑时钟只能决定顺序，无法判断审美意图；定义冲突应保留版本并要求选择。
- WebDAV 只提供存储，不提供可信服务端时间或原子事务；事件链、独占创建和回退检测必须在客户端严格执行，网盘目录和清单不能成为信任根。
- 先接入的原生平台可能改变共享设置页与账号同步的边界；每个平台 PR 必须引用本设计并列出未接入字段，不能顺手改变默认值。
