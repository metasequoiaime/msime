# msime-dict-builder

`msime-dict-build` builds the dictionary release msime ships (the artifacts `resources/desktop-dictionary.lock.json` pins): `msime-pinyin.db`, `msime-wubi.db`, `msime-english.db`, `msime-others.db`, `msime-japanese.dat`, `msime-bigram.bin`, `msime-trigram.bin`, `msime-mozc_dictionary_oss_README.txt`, `msime-mozc_LICENSE.txt`, `msime-scowl_Copyright.txt`, then `msime-dictionary-manifest.json` and `msime-SHA256SUMS.txt`. It replaces the Python pipeline in MSIME-Engine `dictionary/` (`build_all.py`, `build_profile.py`, `makecikudb/`) and reproduces its desktop output row for row.

```sh
cargo build --release -p msime-dict-builder
target/release/msime-dict-build --cache <sources-cache> --out <output>                # every stage, about a minute
target/release/msime-dict-build --cache <sources-cache> --out <output> --skip ngram   # without the zhwiki pass
target/release/msime-dict-build --cache <sources-cache> --out <output> --dictionary <msime-dictionary checkout>
target/release/msime-dict-build languages --cache <sources-cache> --out <output> [--dictionary <msime-dictionary checkout>]
target/release/msime-dict-build --list
target/release/msime-dict-build places --cache <sources-cache>                        # the @ place table the engine embeds
target/release/msime-dict-build places-supplement --cache <sources-cache> --out <msime-dictionary>/sources/pinyin/places.txt
target/release/msime-dict-build english-supplement --cache <sources-cache> --out <msime-dictionary>/sources/english/scowl-words.txt
target/release/msime-dict-build hanja --cache <sources-cache>                         # the Korean Hanja table the engine embeds
target/release/msime-dict-build hkcancor-counts --cache <sources-cache> --out <msime-dictionary>/sources/cantonese/hkcancor-word-counts.txt
```

## Inputs

- `resources/dictionary-sources.lock.json` pins every third-party or large input by URL, size and SHA-256: the lexicons and custom dictionary files at a fixed msime-dictionary Git commit, ECDICT, Mozc's OSS Japanese dictionary sources and the zhwiki dump part the n-gram tables count. They are downloaded into `--cache` on first use (about 500 MB) and reused while they still match; `--offline` refuses to download.
- The base lexicons (under `sources/`) and the custom words, translations and English words (`custom/words.txt`, `custom/translations.txt`, `custom/english.txt`) live in the dictionary source repository [metasequoiaime/msime-dictionary](https://github.com/metasequoiaime/msime-dictionary), which msime and MSIME-Windows both consume from the fixed commit recorded in the lock. `sources/pinyin/rime-ice-supplement.txt` is the GPL-3.0 rime-ice delta merged into the licensed Quanpin build, while `sources/wubi/wubi98-fcitx.txt` is the GPL-3.0-or-later Fcitx5 98 Wubi supplement merged into the Wubi 98 table. The Cantonese and Zhuyin sources under `sources/cantonese/` and `sources/zhuyin/` (rime-cantonese and libchewing-data files that msime-dictionary keeps byte for byte) are read only by `msime-dict-build languages`; their upstream commits are the `rime-cantonese` and `libchewing-data` references, which `languages` records in each database as `source_commit` and `scripts/test-language-data-notices.py` checks against the licence files.
- The Stroke scheme's `msime-stroke.db` is built by `languages` from rime-stroke's `stroke.dict.yaml` (LGPL-3.0, `resources/licenses/rime-stroke-LGPL-3.0.txt`), ranked by the per-character sum of the pinned `sources/pinyin/single-chars.txt` weights. The source file is read from the fixed msime-dictionary commit and checked against its pinned size and SHA-256; with `--dictionary` it is read from the checkout and still has to match that size and SHA-256.
- `--dictionary <path>` (the main build and `languages`) reads msime-dictionary's files from a checkout instead: every file the lock pins from `raw.githubusercontent.com/metasequoiaime/msime-dictionary/<commit>/<path>` is read from `<path>/<lock path>`, without the lock's size and SHA-256 check, and a path under `sources/` or `custom/` the builder asks for but the lock does not pin also resolves from the checkout, so a new dictionary file needs no lock entry. The exception is upstream data whose commit msime records outside the file: `sources/pinyin/rime-ice.txt`, `sources/pinyin/rime-ice-supplement.txt`, `sources/english/rime-ice-en-supplement.txt`, `sources/wubi/wubi98.txt`, `sources/wubi/wubi98-fcitx.txt`, `sources/zhuyin/tsi.csv`, `word.csv`, `mcbopomofo-supplement.txt` and `phrase.occ`, and everything under `sources/cantonese/`, `sources/stroke/`, `sources/japanese/` and `sources/korean/`, together with the tables msime's generators write from such an upstream: `sources/cantonese/hkcancor-word-counts.txt` (`hkcancor-counts`, HKCanCor) and `sources/english/scowl-words.txt` (`english-supplement`, SCOWL). The manifest's references and `mozc_revision`, the `source_commit` the language databases record and the licence texts under `resources/licenses` all name those commits, so these files are still read from the checkout but must match the lock's size and SHA-256 and must be pinned in it; a checkout that replaced one with a newer upstream version fails the build until the lock reference (or the Mozc revision), the lock entry and the licence texts in msime are updated. Inputs pinned from other repositories (ECDICT, the zhwiki dump, the `places/` tables) still come from `--cache`. The checkout's Git commit pins the content: the manifest records `git -C <path> rev-parse HEAD` as `custom_dictionary_commit` and as the `msime-dictionary` reference, and `source.dirty` is true when either the msime checkout's builder inputs or the checkout's `sources/` and `custom/` have uncommitted changes. Without the flag nothing changes: every file comes from the lock, and an unpinned path is an error.
- `languages` weighs the Cantonese words rime-cantonese's essay does not list by `sources/cantonese/hkcancor-word-counts.txt`, which `hkcancor-counts` generates from the HKCanCor transcriptions pinned under `hkcancor/` (CC BY 4.0, attributed in `resources/licenses/rime-cantonese-CC-BY-4.0.txt`), and the Zhuyin phrases libchewing-data does not count by McBopomofo's `phrase.occ`, kept verbatim as `sources/zhuyin/phrase.occ` (MIT, reproduced in `resources/licenses/libchewing-data-LGPL-2.1.txt`). Both are scaled to the main frequency list by the median ratio over the words the two share, and neither lifts a weak word over a stronger source on the same key: a Cantonese word HKCanCor counts fewer than three times stays below every essay word of its key, and a filled Zhuyin phrase stays below the key's chewing-counted entry; see `src/cantonese.rs` and `src/zhuyin.rs`.
- `resources/dictionary-sources/` holds the other hand-maintained inputs: quick phrases, the emoji, kaomoji and symbol tables, the single-character whitelist additions, `pinyin-overrides.txt` and `pinyin-reading-corrections.txt`.

Inputs without a redistribution grant (`src/licensing.rs`) are left out unless `--include-unlicensed` is given; such a build is for local evaluation and must not be released.

## Changing the data

- Edit the files under `resources/dictionary-sources/` and rebuild.
- Base lexicons, custom words, translations and English words are changed in msime-dictionary. To take its new state, set the `msime-dictionary` reference in the lock to the new commit, update each repository file URL, size and SHA-256, rebuild, and compare. Do not follow a moving branch or publish source files as dictionary Release assets.
- A word the pinned quanpin inputs read wrongly (重采样 as zhong'cai'yang, 调优 as diao'you) is listed in `pinyin-reading-corrections.txt` as `word<TAB>wrong pinyin<TAB>correct pinyin`. The `reading-corrections` stage runs after `custom-words`, deletes every row with that word and wrong pinyin, and fails when an entry deletes nothing (the input changed, so drop the entry) or when the word is left without a row at the correct pinyin (append the correct reading to msime-dictionary's `custom/words.txt`). Only readings that are wrong for the word's meaning belong there; a word with two valid readings keeps both.
- Emoji, kaomoji and symbol keywords get their pinyin from the `pinyin` crate one character at a time. When a new polyphone keyword needs its phrase reading, add `keyword<TAB>item<TAB>item...` to `pinyin-overrides.txt`.
- To move a pinned input, change its URL, size and SHA-256 in the lock in the same commit, rebuild, and compare the result with the previous release before publishing.

## The `@` place table

`@` mode can offer Chinese administrative divisions after the user's own mention list. Unlike the dictionary artifacts, that table is small enough to ship inside the engine: `msime-dict-build places --cache <sources-cache>` reads `places/provinces.csv`, `places/cities.csv` and `places/areas.csv` from [modood/Administrative-divisions-of-China](https://github.com/modood/Administrative-divisions-of-China) (WTFPL, see `resources/licenses/Administrative-divisions-of-China-WTFPL.txt`) at the commit the lock pins, and rewrites `crates/engine/src/local/places.tsv`, which is committed. Place names whose per-character pinyin is wrong (重庆, 六安, 蚌埠, ...) are listed in `READINGS` in `src/places.rs`; the command fails when an entry there no longer matches any name. To take newer data, move the three `places/` entries in the lock to the new commit, rerun the command, and review the diff of `places.tsv`.

The same divisions also feed the pinyin dictionary. `msime-dict-build places-supplement --cache <sources-cache> --out <file>` writes msime-dictionary's `sources/pinyin/places.txt`: full and short names (金华市 and 金华) whose reading the pinned `sources/pinyin/rime-ice.txt` and `sources/pinyin/rime-ice-supplement.txt` confirm, that those files lack or hold only at an unranked weight (10 or below), written at a floor the generator measures per level from the same data; a name those files already rank keeps its weight, and a floor is capped one below any other word of the same full pinyin weighted above the common line (the 90th percentile of `rime-ice.txt` weights), so a place name never takes the first candidate from a common word (盐城 stays under 严惩); a word at a placeholder weight does not count as common, a placeholder being any single weight value held by more than 1% of the `rime-ice.txt` rows above the common line (9999 in the pinned data, a fill-in value rather than a frequency: 紧皱 no longer holds 锦州 down), and the highest real-weight word of the key decides instead. The rules (suffixes, exclusions, reading confirmation, floors, the cap) are documented in `src/places_supplement.rs` and in the file's header, and the command prints what it left out. The `places-supplement` stage merges the pinned file into the quanpin tables before `custom-words`, raising weights only. When the `places/` entries, `READINGS` or the compared pinyin files change, rerun the command into msime-dictionary, commit the file there, and pin its new size and SHA-256 here.

## The SCOWL English words

`msime-english.db`'s `english_words` table holds the rime-ice word lists (`sources/english/rime-ice-en.txt`, `sources/english/rime-ice-en-supplement.txt`), `sources/english/scowl-words.txt` and `custom/english.txt`, ranked by `sources/english/google-word-counts.txt`; a word without a count is stored at 0, after every counted one. Every casing a list gives a word is its own row (china and China, PostgreSQL and postgresql). One casing leads with the word's count and the others are stored one below it: the casing SCOWL's spelling dictionary lists when it lists the word only capitalised (Wikipedia, Ukraine, Skype), otherwise the all-lowercase one (china, may, go), otherwise the first one listed (DOS before DoS). A word with several casings and no count gets 1 for its leading casing, so the zero tie does not fall to the Engine's display byte order. The English stage reads the pinned SCOWL archive for this.

`msime-dict-build english-supplement --cache <sources-cache> --out <file>` writes msime-dictionary's `sources/english/scowl-words.txt` from the Aspell English dictionary en-wl/wordlist publishes with a release (pinned as `scowl/aspell6-en-*.tar.bz2`, its commit as the `SCOWL` reference): SCOWL up to size 60, American plus British -ise spellings, letters only and at least three of them, without the words the rime-ice lists or `custom/english.txt` already have in any casing or that rime-ice commented out (`# huang huang`), without the slurs in `OFFENSIVE`, without capitalised-only names whose lowercase form is the full pinyin of a word in the pinyin lists (Guangzhou, Wang: mixed input would put them in the second slot whenever that pinyin is typed), and without words Google has no count for. The `english-glosses` stage gives these words English-to-Chinese glosses but keeps them out of the Chinese-to-English index, which therefore stays as the rime-ice and custom lists make it. SCOWL's licence (`resources/licenses/scowl-aspell6-en-Copyright.txt`) asks for its notice in every copy, so the file's header repeats it, the English stage stores the licence text in the database's `source_notices` table and writes it beside the database as `msime-scowl_Copyright.txt` (a shipping artifact the product check requires byte for byte, for msime-dictionary's `dict-v` release to attach), and the command stops when the package's `Copyright` no longer matches the committed text. The rules are documented in `src/english_supplement.rs`. When the archive, the compared files or the rules change, rerun the command into msime-dictionary, commit the file there, and pin its new size and SHA-256 here.

## The Korean Hanja table

Korean mode converts the composing syllable to Hanja from a table that also ships inside the engine: `msime-dict-build hanja --cache <sources-cache>` reads `sources/korean/hanja.txt` from [libhangul](https://github.com/libhangul/libhangul) (`data/hanja/hanja.txt`, BSD-3-Clause, see `resources/licenses/libhangul-hanja-BSD-3-Clause.txt`) at the commit the lock pins, and rewrites `crates/engine/src/korean/hanja.tsv`, which is committed. Only single-syllable readings are kept: one precomposed Hangul syllable mapped to one Hanja in CJK Unified Ideographs, Extension A, or one of the twelve unified ideographs of the CJK Compatibility Ideographs block (U+FA0E, U+FA11 and so on, which NFC leaves alone). True compatibility ideographs, characters outside the BMP and multi-character values are dropped, each syllable keeps the source's order, and the source's 훈음 comment becomes the third column. `scripts/test-korean-hanja-table.py` checks the committed table against these rules, and against the generator's output when the pinned source is in `target/dictionary-sources`. To take newer data, move the `sources/korean/` entry in the lock to the new commit, rerun the command, and review the diff of `hanja.tsv`.

Releases are cut by msime-dictionary's `.github/workflows/release-built-dictionaries.yml` whenever a push to its `main` changes `sources/` or `custom/`: it builds every artifact without `--include-unlicensed`, passing the checkout of that pushed commit as `--dictionary` so the release is built from exactly that commit, checks `msime-SHA256SUMS.txt` and `msime-language-dictionaries-SHA256SUMS`, and publishes a `dict-vX.Y.Z` release on metasequoiaime/msime-dictionary with the artifacts, `msime-dictionary-manifest.json` and the checksum files as the builder wrote them. After a release is published, bump `resources/desktop-dictionary.lock.json` and `resources/language-dictionaries.lock.json` to the new files under `metasequoiaime/msime-dictionary`.

## Checking contributed words

msime-dictionary's CI gates changes to `custom/words.txt`, `custom/translations.txt` and `custom/english.txt` with `check-words`. Pass a base/head pair for each file to check (at least one); the words pair keeps its original `--base`/`--head` names:

```sh
msime-dict-build check-words \
  [--base <old words.txt> --head <new words.txt>] \
  [--translations-base <old translations.txt> --translations-head <new translations.txt>] \
  [--english-base <old english.txt> --english-head <new english.txt>] \
  [--msime-db <shipped msime-pinyin.db>] [--english-db <shipped msime-english.db>] \
  [--json report.json] [--markdown summary.md]
```

For every file a change may only append lines, and each appended entry goes through the parser the build uses and must not repeat another appended line or an entry already in that file. Per file:

- `words.txt`: word, `'`-separated quanpin that maps to a table, integer weight. The weight must lie within the range the existing entries use; with `--msime-db`, a row with the same word and pinyin in the shipped quanpin tables is rejected.
- `translations.txt`: `source<TAB>gloss`. A new gloss for an existing source is accepted (the build's last line wins), but the same source and gloss again is a duplicate.
- `english.txt`: lowercase ASCII word, non-empty display, integer weight of at least 1. An entry is its word and display; the weight must lie within the range the existing entries use; with `--english-db`, a word and display already in the shipped `english_words` is rejected.

Appended blank and `#` lines are skipped. The JSON report lists `added` and `rejected` lines, each with its `file` (for example `custom/english.txt`) and 1-based line number; added lines carry the parsed fields, rejected ones the text and reason. It also has `accepted`, a `files` array with each checked file's line counts and `weight_range`, and, at the top level as before, `words.txt`'s line counts and `weight_range` (null when `words.txt` was not checked). The Markdown summary is the same in table form, with an Added table per file, and is also printed to stderr. The exit status is 0 when nothing is rejected, 1 when anything is (the reports are still written), and 2 when the check cannot run: an unreadable file, a base file the build itself would reject, or a database without the expected table.
