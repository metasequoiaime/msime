# msime-dict-builder

`msime-dict-build` builds the dictionary release msime ships (the artifacts `resources/desktop-dictionary.lock.json` pins): `msime-pinyin.db`, `msime-wubi.db`, `msime-english.db`, `msime-others.db`, `msime-japanese.dat`, `msime-bigram.bin`, `msime-trigram.bin`, `msime-mozc_dictionary_oss_README.txt`, `msime-mozc_LICENSE.txt`, `msime-scowl_Copyright.txt`, then `msime-dictionary-manifest.json` and `msime-SHA256SUMS.txt`. It replaces the Python pipeline in MSIME-Engine `dictionary/` (`build_all.py`, `build_profile.py`, `makecikudb/`) and reproduces its desktop output row for row.

```sh
cargo build --release -p msime-dict-builder
target/release/msime-dict-build --dictionary <msime-dictionary checkout> --cache <sources-cache> --out <output>                # every stage, about a minute
target/release/msime-dict-build --dictionary <msime-dictionary checkout> --cache <sources-cache> --out <output> --skip ngram   # without the zhwiki pass
target/release/msime-dict-build languages --dictionary <msime-dictionary checkout> --cache <sources-cache> --out <output>
target/release/msime-dict-build --list
target/release/msime-dict-build places --cache <sources-cache>                        # the @ place table the engine embeds
target/release/msime-dict-build places-supplement --dictionary <msime-dictionary checkout> --cache <sources-cache> --out <msime-dictionary>/sources/pinyin/places.txt
target/release/msime-dict-build english-supplement --dictionary <msime-dictionary checkout> --cache <sources-cache> --out <msime-dictionary>/sources/english/scowl-words.txt
target/release/msime-dict-build wubi86-supplement --dictionary <msime-dictionary checkout> --cache <sources-cache> --out <msime-dictionary>/sources/wubi/wubi86-supplement.txt
target/release/msime-dict-build wubi98-supplement --dictionary <msime-dictionary checkout> --cache <sources-cache> --out <msime-dictionary>/sources/wubi/wubi98-supplement.txt
target/release/msime-dict-build wubixsj-supplement --dictionary <msime-dictionary checkout> --cache <sources-cache> --out <msime-dictionary>/sources/wubi/wubixsj-supplement.txt
target/release/msime-dict-build wubi86-helpcode --dictionary <msime-dictionary checkout> --out resources/helpcodes/wubi86_helpcode.txt   # the 五笔 86 helpcode table
target/release/msime-dict-build hanja --dictionary <msime-dictionary checkout> --cache <sources-cache>                         # the Korean Hanja table the engine embeds
target/release/msime-dict-build hkcancor-counts --cache <sources-cache> --out <msime-dictionary>/sources/cantonese/hkcancor-word-counts.txt
target/release/msime-dict-build cleanse-report --dictionary <msime-dictionary checkout> --out <dir> [--upstream <rime-ice checkout>] [--reference <file>...]   # candidate lists for curation/
```

每个产物的格式（建表语句、二进制布局、`msime-pinyin.db`、`msime-wubi.db`、`msime-others.db` 的文件内版本 `metadata.format_version`）和数据许可证见 [docs/data-formats.md](../../docs/data-formats.md)。

## Inputs

- `resources/dictionary-sources.lock.json` pins only the third-party inputs downloaded by URL, each by size and SHA-256: ECDICT, the zhwiki dump part the n-gram tables count, the `places/` tables, the SCOWL archive under `scowl/` and the HKCanCor transcriptions under `hkcancor/`. They are downloaded into `--cache` on first use (about 500 MB) and reused while they still match; `--offline` refuses to download. The lock also records the upstream references (repository and commit) and the Mozc revision that the manifest, the language databases and the licence texts name.
- The base lexicons (under `sources/`) and the custom words, translations, English words and reviewed Cantonese words (`custom/words.txt`, `custom/translations.txt`, `custom/english.txt`, `custom/cantonese.txt`) live in the dictionary source repository [metasequoiaime/msime-dictionary](https://github.com/metasequoiaime/msime-dictionary). The lock pins none of them: every path under `sources/`, `custom/` or `curation/` (the maintainer-reviewed tables described under「Curation tables」below) is read only from the `--dictionary` checkout, so without that flag the stages that read them fail and no manifest is written (a build that writes no manifest removes any `msime-dictionary-manifest.json` and `msime-SHA256SUMS.txt` already in `--out`, since the databases it rebuilt no longer match them). `sources/pinyin/rime-ice-supplement.txt` is the GPL-3.0 rime-ice delta merged into the licensed Quanpin build, while `sources/wubi/wubi98-fcitx.txt` is the GPL-3.0-or-later Fcitx5 98 Wubi supplement merged into the Wubi 98 table. The Cantonese and Zhuyin sources under `sources/cantonese/` and `sources/zhuyin/` (rime-cantonese and libchewing-data files that msime-dictionary keeps byte for byte) are read only by `msime-dict-build languages`; their upstream commits are the `rime-cantonese` and `libchewing-data` references, which `languages` records in each database as `source_commit` and `scripts/test-language-data-notices.py` checks against the licence files.
- The Stroke scheme's `msime-stroke.db` is built by `languages` from rime-stroke's `stroke.dict.yaml` (LGPL-3.0, `resources/licenses/rime-stroke-LGPL-3.0.txt`), ranked by the per-character sum of the weights in msime-dictionary's `sources/pinyin/single-chars.txt` (no record pins this file; the checkout's commit fixes its content); a traditional character weighs at least a quarter of its simplified form's frequency (`stroke::traditional_weights`, pairing the forms by OpenCC's `STCharacters.txt`, `TWVariants.txt` and `HKVariants.txt`), and characters outside the Basic block and Extension A are kept only from weight 100 (`stroke::EXTENSION_MIN_WEIGHT`) or when a word of the Cantonese words file uses them (`stroke::cantonese_characters`). `languages` requires `--dictionary`, so the source file is always read from the checkout and checked against its `upstream.lock.json`. `stroke.rs`'s `SOURCE_SIZE` and `SOURCE_SHA256` only guard the `--cache` fallback in `stroke::source`, which is no longer reachable from the command line.
- `--dictionary <path>` names the msime-dictionary checkout the build reads (the main build, `languages`, `places-supplement`, `english-supplement`, `wubi86-supplement`, `wubi98-supplement`, `wubixsj-supplement`, `wubi86-helpcode` and `hanja`; it is optional for the main build, so `--only emoji`, `symbols` or `ngram` still run without it). Its Git commit pins the content. The files msime treats as upstream data (`UPSTREAM_FILES` in `src/sources.rs`: `sources/pinyin/rime-ice.txt`, `sources/pinyin/rime-ice-supplement.txt`, `sources/english/rime-ice-en-supplement.txt`, `sources/wubi/wubi98.txt`, `sources/wubi/wubi98-fcitx.txt`, `sources/wubi/wubixsj-byujiang.txt`, `sources/wubi/wubi86-jidian.txt` and `sources/wubi/wubi86-rime-wubi.txt` (the 86 table split into the jidian rows and the rows merged in from rime-wubi; a checkout without `wubi86-rime-wubi.txt` predates the split and its merged `wubi86-jidian.txt` is read without a record, see `src/wubi86_table.rs`), the 17 rime-wanxiang dictionaries under `sources/pinyin/wanxiang/`, `sources/zhuyin/tsi.csv`, `word.csv`, `mcbopomofo-supplement.txt` and `phrase.occ`, everything under `sources/cantonese/`, `sources/stroke/`, `sources/japanese/` and `sources/korean/`, and the tables msime's generators write from such an upstream, `sources/cantonese/hkcancor-word-counts.txt` and `sources/english/scowl-words.txt`) must be listed under the same upstream name in the checkout's `upstream.lock.json` and match its size and SHA-256, and every commit that record names must equal the lock's reference of that name (`lock.mozc` for `mozc`); otherwise the build fails. The manifest's references and `mozc_revision`, the `source_commit` the language databases record and the licence texts under `resources/licenses` all name those commits, so a checkout that replaced one with a newer upstream version fails until the reference and the licence texts in msime are updated first. The manifest records `git -C <path> rev-parse HEAD` as `custom_dictionary_commit` and as the `msime-dictionary` reference, and `source.dirty` is true when either the msime checkout's builder inputs or the checkout's `sources/`, `custom/`, `curation/` and `upstream.lock.json` have uncommitted changes. This builder cannot rebuild a msime-dictionary commit from before `upstream.lock.json` was added; build those with the msime commit their manifest names.
- `languages` weighs the Cantonese words rime-cantonese's essay does not list by `sources/cantonese/hkcancor-word-counts.txt`, which `hkcancor-counts` generates from the HKCanCor transcriptions pinned under `hkcancor/` (CC BY 4.0, attributed in `resources/licenses/rime-cantonese-CC-BY-4.0.txt`), and the Zhuyin phrases libchewing-data does not count by McBopomofo's `phrase.occ`, kept verbatim as `sources/zhuyin/phrase.occ` (MIT, reproduced in `resources/licenses/libchewing-data-LGPL-2.1.txt`). Both are scaled to the main frequency list by the median ratio over the words the two share, and neither lifts a weak word over a stronger source on the same key: a Cantonese word HKCanCor counts fewer than three times stays below every essay word of its key, and a filled Zhuyin phrase stays below the key's chewing-counted entry; see `src/cantonese.rs` and `src/zhuyin.rs`.
- `languages` also adds the hand-reviewed Cantonese words of msime-dictionary's `custom/cantonese.txt` (`word<TAB>toned Jyutping`, one syllable per character, the msime project's own data under CC BY 4.0, attributed in `resources/licenses/rime-cantonese-CC-BY-4.0.txt`). A word weighs its essay count, or `ESSAY_WORD_MIN_COUNT` when the essay does not list it, and only adds an entry or raises one. Every character's toneless syllable must be one of that character's readings in `jyut6ping3.chars.dict.yaml`, and a malformed or repeated row fails the build; the check stops typos and readings a character never has, not a wrong pick among a polyphonic character's readings, which is left to review. A checkout without the file (msime-dictionary before it was added) builds as before and the summary says so.
- `languages` writes the Cantonese texts in Hong Kong forms where HKCanCor shows them. The candidate variant pairs come from OpenCC's `sources/opencc/TWVariants.txt` and `sources/opencc/HKVariants.txt` (verbatim from the pinned OpenCC commit and checked against the checkout's `upstream.lock.json`; neither table's content is written into the database). A pair is applied only when the corpus never uses the rime-cantonese (OpenCC) form and does use the other, and the characters listed in msime-dictionary's maintainer-reviewed `custom/cantonese-variant-vetoes.txt` (one OpenCC character per line, each a key of one of the two tables) are never replaced; 搵 is one. Both tables and the veto list must be in the checkout, so a msime-dictionary commit from before `HKVariants.txt` was added fails to build instead of silently dropping 溼→濕; see `src/cantonese.rs`.
- The `wubi` stage reads the 86 table through `src/wubi86_table.rs`, and so do the three supplement generators, `wubi86-helpcode` and `word-vetoes`. In a split checkout the jidian rows keep their same-code ranks (10, 20, 30, …) and the rows merged in from rime-wubi, whose weights are frequencies from another corpus, are written at 10, after the jidian rows of their code and before the supplement, unless the pinyin tables say they are far more common: both sides are compared on the highest weight any reading of the word has in `sources/pinyin/single-chars.txt`, `rime-ice.txt`, `rime-ice-supplement.txt` and `places.txt` (`FREQUENCY_TABLES`), read the way the Wubi supplement generators read them for ordering (`PinyinCuration::wubi_rows`: vetoed readings do not count and the `wubi`-scoped frequency corrections of `curation/pinyin-weight-overrides.txt` replace the corrupted weights, so 斯基, restored to 2, no longer passes 苦苦 on `adad`), and a rime-wubi row of at least 100 there that is more than 10 times as frequent as each of the last jidian rows of its code goes before those rows, at the first one's weight plus one (的话 before 魅族 on `rqyt`, 南平 before 塏 on `fmgu`; 老师 stays before 考量 on `ftjg`, only 1.24 times apart). Rows with no Han character (kana, zhuyin, Greek, symbols, Latin words) then drop to the weight of the next row of their code, or to 10 when they are last, which keeps every code's own order but stops the jidian ranks of the 90-row kana codes from filling the one- and two-letter prefix completions (`c` used to complete to ァ ア ィ). A checkout that predates the split is read as it is. The supplement headers list the four pinyin tables among their inputs (the curation tables were already listed); `wubi86-helpcode` reads only the two 86 files, since only the codes decide it.
- The `wubi` stage appends msime-dictionary's hand-maintained `custom/wubi86.txt` (`value<TAB>code<TAB>weight`, append-only, the project's own data) to `wubi86` after the jidian table and the generated supplement, so a custom row sorts after the upstream rows of its code at the same weight; the first rows put ①…⑩ on the 86 codes of 一…十 (`g`, `fg`, …, `fgh`). A checkout without the file builds the table without it and says so in the stage summary.
- The `reweight` stage (after `quanpin`, before `places-supplement`, `src/reweight.rs`) recomputes the quanpin weights shared with rime-wanxiang from the 17 `.dict.yaml` files msime-dictionary keeps byte for byte under `sources/pinyin/wanxiang/` (upstream `rime-wanxiang`, commit `7ab73ee`, CC BY 4.0, attributed in `resources/licenses/msime-engine-dictionary-NOTICE.md`). Its first step always runs and repeats msime-dictionary#84's one-off rewrite: a row whose word and toneless reading one of 15 dictionaries lists with a non-negative weight (the 16 that `wanxiang.dict.yaml` imports other than `cuoyin`, as #84 chose) gets `round(highest such weight × file coefficient)`, half up in integers, with 9.42 for `single-chars.txt`, 9.2 for `rime-ice.txt` and 9.28 for `rime-ice-supplement.txt`. The three files already carry exactly those weights (all 597343 shared rows match), so the step leaves every artifact unchanged; it keeps the alignment when a supplement is regenerated at its path or the upstream commit moves. The second step is off unless msime-dictionary has `curation/pinyin-reweight.txt` (see「Curation tables」). A checkout whose `upstream.lock.json` does not record `rime-wanxiang` (msime-dictionary up to `dict-v2.0.56`) skips the stage and builds exactly as before; one that records it must hold all 17 files at their recorded bytes, including `cuoyin` and `mixed`, which give no weights and are read only to tell whether rime-wanxiang lists a word under any reading.
- `resources/dictionary-sources/` holds the other hand-maintained inputs: quick phrases, the emoji, kaomoji and symbol tables, the single-character whitelist additions, `pinyin-overrides.txt` and `pinyin-reading-corrections.txt`.

Inputs without a redistribution grant (`src/licensing.rs`) are left out unless `--include-unlicensed` is given; such a build is for local evaluation and must not be released.

## Changing the data

- Edit the files under `resources/dictionary-sources/` and rebuild.
- Base lexicons, custom words, translations and English words are changed in msime-dictionary. To try its new state, build with `--dictionary` pointing at a checkout of the target commit and compare. To reproduce a release, check out msime-dictionary at its manifest's `custom_dictionary_commit` and msime at its `source.commit`. Do not follow a moving branch or publish source files as dictionary Release assets.
- A word the pinned quanpin inputs read wrongly (重采样 as zhong'cai'yang, 调优 as diao'you) is listed in `pinyin-reading-corrections.txt` as `word<TAB>wrong pinyin<TAB>correct pinyin`. The `reading-corrections` stage runs after `custom-words`, deletes every row with that word and wrong pinyin, and fails when an entry deletes nothing (the input changed, so drop the entry) or when the word is left without a row at the correct pinyin (append the correct reading to msime-dictionary's `custom/words.txt`). Only readings that are wrong for the word's meaning belong there; a word with two valid readings keeps both.
- The `custom-words` stage merges msime-dictionary's `custom/words.txt` raising weights only, and caps a word it newly inserts (no input before it has that word and pinyin) one below the highest common word (weight 1000 or more) of the same full pinyin, or, when that full pinyin has none, of the same nine-key code and syllable count (both limits hold, and the full-pinyin one is always the lower); competitors are counted as the later `reading-corrections`, `word-vetoes` and `weight-overrides` stages leave them, and the build log lists every capped word (`src/custom_ceiling.rs`). A row that custom raises from an earlier input keeps the raise-only rule and is not capped (the weight overrides cannot lower it either, see「Curation tables」).
- A word or reading to delete, a weight to correct, the offensive word list and English words to keep out go in msime-dictionary's `curation/` tables, not into the byte-locked upstream files or the append-only `custom/` files; see「Curation tables」below.
- Emoji, kaomoji and symbol keywords get their pinyin from the `pinyin` crate one character at a time. When a new polyphone keyword needs its phrase reading, add `keyword<TAB>item<TAB>item...` to `pinyin-overrides.txt`.
- A keyword deleted from `emoji/emoji.txt`, `emoji/emoji_en.txt` or `kaomoji/kaomoji.txt` (a vulgar keyword, or a keyword paired with the wrong emoji) is also listed in `keyword-vetoes.txt` as `keyword` (any item) or `keyword<TAB>item` (that pair only), so a later re-import from upstream cannot bring it back: the `emoji` and `kaomoji` stages fail and name every keyword-file line a veto matches, and a pair whose item is in none of the three files fails as stale. Keywords compare ASCII-case-insensitively, items ignoring U+FE0F; see `check_keyword_vetoes` in `src/others.rs`.
- To move a pinned input, change its URL, size and SHA-256 in the lock in the same commit, rebuild, and compare the result with the previous release before publishing.
- A pull request that changes the builder or the inputs it reads from this repository gets an artifact diff from `.github/workflows/dict-builder-artifact-diff.yml`: the same msime-dictionary commit (main by default) is built with the pull request's builder and with the base builder, and `scripts/dict_artifact_diff.py` reports, file by file and table by table, the rows added, removed, reweighted and moved (the engine breaks weight ties by row order, so a moved row can change the candidates). The report is informational; label the pull request `expect-no-artifact-change` (and rerun the job) when the change must leave every artifact as it was, and any difference then fails the check. When the builder starts using another `msime_engine` file, `scripts/test-dict-artifact-diff.py` fails until that file is added to the workflow's paths.

## Curation tables

msime-dictionary 的顶层目录 `curation/` 放维护者审定的表（不接受投稿；`custom/` 由 msime-web、msime-cloud 直接读写，不放这里）。上游文件逐字节锁定、`custom/` 只追加，删词和改权重只能写成这些独立的表，由构建器在读入之后施加（`src/curation.rs`）。下表前七张是逐条的表，共同规则如下：前五张由主构建读，接着两张粤拼表只由 `languages` 读（`src/cantonese_curation.rs`）；最后两行是 `reweight` 阶段第二步的开关、参数和豁免表（`src/reweight.rs`），它们的校验写在各自那一行：

- **文件不在就是空表。** `curation/` 不在时，这套表的机制本身不改产物，所以构建器可以先于数据合入。例外是构建器内置的英文蔑称（见下表 `english-vetoes.txt` 一行）：它不靠 `curation/` 也总是生效，换上这个构建器后的第一次发布就会少掉 rime-ice 英文词表里的 nigger、tranny、beyatch 和它们的释义（按 `dict-v2.0.41` 的内容是 `english_words` 3 行、`en_zh_glosses` 2 行，`zh_en_glosses` 里 深棕色 不再译成 nigger）。这只说 `curation/` 这套表：构建器自己的规则对任何 checkout（包括没有 `curation/` 的旧提交）都生效，和这套表一起引入的那些也一样，所以换构建器重建旧提交，产物照样会变。例如五笔码表过滤引擎显示不了的兼容汉字、修正极点名次的最低权重（`msime-wubi.db`，见 `src/msime.rs`、`src/wubi86_table.rs`），释义按义项位置选（`msime-english.db`，见下文「释义怎么选」），粤拼 essay 补词要有佐证、注音用 `phrase.occ` 打破并列、笔画的繁体继承简体字频（`languages` 的三个库），表情和颜文字的关键词否决（`msime-others.db`，见上文 `keyword-vetoes.txt`）。升级 `builder.lock.json` 前要用 `scripts/dict_artifact_diff.py` 比较全部产物，不能只看 `curation/` 管的那几张表。
- **每一条都必须匹配到东西。** 一条在本次输入里什么也没匹配到，构建失败、表不动，照 `pinyin-reading-corrections.txt` 的做法：输入变了，条目就该删掉，不让表悄悄过期。
- 一行一条，`#` 开头的行和空行不算，字段用 TAB 分隔；重复的条目、写错的全拼都让构建失败，报错带文件名和行号。

| 文件 | 每行 | 阶段与效果 |
| --- | --- | --- |
| `curation/pinyin-vetoes.txt` | `词`（整词否决，至少两个字）或 `词<TAB>全拼`（只否决这个读音） | `word-vetoes` 阶段（在 `reading-corrections` 之后、`wubi` 之前）从全拼表删掉这个词的所有读音或这一个读音。整词否决还让三张五笔表（`wubi86`、`wubi98`、`wubixsj`，原表的行和生成的补充行都算）不写入这个词；五笔补充词组生成器和 rime-wubi 的行与极点行比拼音库词频时，被否决的读音都不算。一条否决在全拼表里一行都没删到、整词否决在五笔原表里也没有时构建失败。同一个词既整词否决又按读音否决算错。 |
| `curation/pinyin-weight-overrides.txt` | `词<TAB>全拼<TAB>权重`（不小于 0 的整数），可以再加第四列 `wubi` | `weight-overrides` 阶段（紧接 `word-vetoes`）把这个读音的权重设成这个值，可降可升。第四列 `wubi` 标出与全拼键无关的频率修正（本地损坏恢复上游值、占位权重），五笔补充词组的同码排序、rime-wubi 的行与极点行比拼音库词频时也用这个值；不写的是相对同一全拼键的降权（碎片、非标准读音、人工词条越位），只改拼音。全拼表没有这一行，或者这一行是 `custom/words.txt` 从已有的行提了权的（custom-words 之前并入的输入，即单字表、词组输入和 `places.txt`，已经有这个词和读音，而且权重低于 custom 写的）时构建失败：人工词条的提权只升不降，覆盖表不把它改回去。custom 新插入的词（之前的输入都没有这一行）可以覆盖，越位的投稿词条（例如压过同音常用词的品牌名）就靠这里降权；custom 列了但没有提权的行也可以。一个读音不能既被否决又被覆盖。 |
| `curation/offensive-words.txt` | 一个词，或 `!` 开头的豁免写法，格式与引擎内嵌的 `crates/engine/src/lattice/offensive_words.txt` 相同 | `sentence-excluded` 阶段（紧接 `weight-overrides`）用引擎的同一个解析器（`msime_engine::parse_offensive_words`）读它，写进 `msime-pinyin.db` 的 `sentence_excluded(value, exempt)`（[docs/data-formats.md](../../docs/data-formats.md) §4.5）。每个词必须是全拼表里某一行的词，每条豁免写法必须出现在全拼表某一行的词里并含一个表里的词。文件不在时不建这张表（`--out` 里上一次留下的会被删掉），引擎用内嵌表。`wubi`、`wubi98`、`wubixsj` 阶段还按它把五笔表里含粗俗词的行（豁免写法盖住的不算）挪到同码其余行之后：粗俗词本身保留、不当首选，引擎的首选排位不管五笔；同码只有它一行的不动。文件不在时五笔表不动。 |

### 释义怎么选

`english-glosses` 阶段从 ECDICT 推两张释义表（`src/english.rs` 的 `derive_glosses`），两个方向都以义项位置为主：

- 拆义项：每行去掉行首的领域标签、词性和词性后面的标签（`[计] vt.`、`n. [俚]`），带标签的行算领域义项；只有计算机标签的行还能进中译英，`[网络]` 行不进。同一个词在不同的行里各算一次。行首写着「X的…」（`be的现在式第三人称`）的记下原形 X。
- 英译中：一行之内按义项顺序；行与行之间按各行首项在拼音表里的权重排，第一条通用行占 10 倍优势（ECDICT 常把名词行放在最前，give 的第一行是「n. 弹性」）；领域行排在通用行后面。冷僻义项（拼音表权重低于 1000，或不到这个词最常用的通用义项的 1/50；「X的」看它和 X 中较高的权重）按行的先后排在所有常用义项后面：post 的「柱」「杆」排在「邮件」「职位」后面，school 的「鱼群」，may 的「五月」。取前两项，第一项是通用义项时不拿领域义项凑数。没有通用义项、只有屈折说明的词（is、are、was）用原形的义项。
- 中译英：每个（中文义项，英文词）的分数是英文词的常用度，在行内每靠后一位乘 7/10，不在这个英文词主行（英译中选中的那一行）上再乘 7/10；取最高分，第二个英文词要有它的 60%。最高分的义项位置超过 3 步（行内第五项以后）时这个中文词不给译文。屈折形式的领域义项不记到原形名下。显示时大小写只从 ECDICT 词头和 SCOWL 拼写词典来，不借 `english_words` 的写法：词头是小写就显示小写（putty 在 `english_words` 里只有 PuTTY，「淡灰色」仍显示 putty）；词头有大写时，SCOWL 只收小写的显示小写（ECDICT 把 core、fax、maxim 写成 CORE、FAX、Maxim），只收词头写法的显示词头（Africa、Monday），两种都收时只有首个义项和以它开头的义项用大写（China 的「中国」「中国的」，china 的「瓷器」）；SCOWL 两种都不收时（缩写、品牌）看 `english_words` 有没有小写写法。
- `custom-translations` 阶段按文件顺序写人工译文，译文是单独一个 `-` 的行删掉这个源词的释义（ECDICT 生成的和更早的人工行都删）。词库仓的 `check-words` 固定的构建器、`builder.lock.json` 和 msime-windows 的 `english_db.py` 都支持它之前，词库里不能加这种行，否则旧构建器会把 `-` 当成译文。
- 抽样之外，2026-11-04 还把拼音权重前 1000 个中文词的中译英和英文词频前 1000 个词的英译中与 dict-v2.0.56 逐条对比过；打分改不动、ECDICT 本身列错的高频配对写进了 `curation/gloss-vetoes.txt`。

英文的生成器 `english-supplement` 不读 `curation/english-vetoes.txt`：那张表的否决在 `english` 阶段施加，生成的 `scowl-words.txt` 里照常有这些词，否决才总能匹配到。

### 清洗候选报告

```sh
msime-dict-build cleanse-report --dictionary <msime-dictionary checkout> --out <dir> \
  [--upstream <rime-ice checkout>] [--ratio 5] \
  [--reference <参照频率表>...] [--reference-min 100] [--reference-scale <系数>] \
  [--nonstandard-min 1000]
```

只写候选清单，不改任何库和源文件；维护者逐条审定后再抄进上面的表。被检查的是进发布的四份拼音输入（`rime-ice.txt`、`rime-ice-supplement.txt`、`places.txt`、`custom/words.txt`），已经被 `curation/` 否决或覆盖过的行不再列出。每类一个 TSV，表头写 msime 提交、msime-dictionary 提交和每个对照文件的 SHA-256，最后一列是可以直接抄进表的行（列里的 `\t` 换成 TAB）：

- `weight-disagreement.tsv`（给了 `--upstream`）：`rime-ice.txt`、`rime-ice-supplement.txt` 里与上游检出 `cn_dicts/base.dict.yaml`、`cn_dicts/ext.dict.yaml` 同词同音、权重相差 `--ratio` 倍以上的行，建议恢复上游权重。先按四份发布来源取同词同音的最高权重，区划或人工词条已提权覆盖的旧上游行不列出。给了 `--reference-scale` 时，权重恰好等于参照权重乘这个系数（四舍五入）的行算作有意按参照表改写，不列出（万象对齐用 9.2）。
- `placeholder-weights.tsv`：多字词的权重不小于 1000 且每位数字相同，或是梗数字 19260817、12345678；给了参照表时参照表收了的词不列出。
- `fragment-over-common.tsv`（给了 `--reference`）：参照表任何读音都不收的多字词，在同一个全拼键上压过参照权重不低于 `--reference-min` 的词，建议降到被压过的词最低的权重之下；`custom/words.txt` 的行不列。
- `nonstandard-readings.tsv`（给了 `--reference`）：参照表收了这个多字词、却不收这个读音的行，在自己的全拼键上压过一个读音是参照表收了的、本地权重不低于 `--nonstandard-min` 的词，建议降到被压过的词最低的权重之下；`custom/words.txt` 的行不列。参照表只收一种读音不等于另一种读错了（剥皮 bao'pi、调到 diao'dao、顺利地 shun'li'de 都对），这一类按 2026-11-04 的逐条审查九成是误伤，只能逐条挑。
- `vulgar-fragments.tsv`：含粗俗词、本身不是表里的词、也没有被豁免写法盖住的词（引擎拼整句时拦的同一种），建议整词否决。粗俗词表用 `curation/offensive-words.txt`，没有时用引擎内嵌的表。
- `wubi-vulgar-fragments.tsv`：同样的词在五笔原表（86 极点表、两张 98 表）里的，带编码和所在的表，并标出拼音行里是否也有（有的话上一份已经列过）。整词否决让三张五笔表都不写入这个词。
- `custom-outranking.tsv`：`custom/words.txt` 的行在自己的全拼键上权重最高，压过同键一个本地权重不低于 1000 的词（人工词条越位），建议降到同键权重最高的另一个词之下。custom 从已有的行提了权的只标出 custom 之前的权重、不给建议行（覆盖表不能改它）。只看全拼键，不看九键码。
- `unknown-provenance.tsv`（给了 `--upstream`）：`rime-ice.txt` 里来源对不上上游的行，只供审阅、不给建议行，按上面各类处理，不整块删除。两种标记：上游检出 `cn_dicts/` 的六张表都没有这个词；上游 `base`、`ext` 没有这个词而且参照表也不收这个词和读音（上游删了、万象对齐也没碰到的孤儿行）。

参照表和上游表可以是 Rime 的 `.dict.yaml`（读音带声调、空格分隔也行，统一成 `ni'hao` 再比），也可以是没有文件头的 `词<TAB>读音[<TAB>权重]`；`--reference` 可以给多份，同词同音取最大权重。

## The `@` place table

`@` mode can offer Chinese administrative divisions after the user's own mention list. Unlike the dictionary artifacts, that table is small enough to ship inside the engine: `msime-dict-build places --cache <sources-cache>` reads `places/provinces.csv`, `places/cities.csv` and `places/areas.csv` from [modood/Administrative-divisions-of-China](https://github.com/modood/Administrative-divisions-of-China) (WTFPL, see `resources/licenses/Administrative-divisions-of-China-WTFPL.txt`) at the commit the lock pins, and rewrites `crates/engine/src/local/places.tsv`, which is committed. Place names whose per-character pinyin is wrong (重庆, 六安, 蚌埠, ...) are listed in `READINGS` in `src/places.rs`; the command fails when an entry there no longer matches any name. To take newer data, move the three `places/` entries in the lock to the new commit, rerun the command, and review the diff of `places.tsv`.

The same divisions also feed the pinyin dictionary. `msime-dict-build places-supplement --dictionary <msime-dictionary checkout> --cache <sources-cache> --out <file>` writes msime-dictionary's `sources/pinyin/places.txt`: full and short names (金华市 and 金华) whose reading the pinned `sources/pinyin/rime-ice.txt` and `sources/pinyin/rime-ice-supplement.txt` confirm, that those files lack or hold only at an unranked weight (92 or below, Wanxiang's floor weight 10 times the factor 9.2 msime-dictionary #84 aligned the shared rows with), written at a floor the generator measures per level from the same data; a name those files already rank keeps its weight, and a floor is capped one below any other word of the same full pinyin weighted above the common line (the 90th percentile of `rime-ice.txt` weights), so a place name never takes the first candidate from a common word (盐城 stays under 严惩); a word at a placeholder weight does not count as common, a placeholder being any single weight value held by more than 1% of the `rime-ice.txt` rows above the common line (9999 in the pinned data, a fill-in value rather than a frequency: 紧皱 no longer holds 锦州 down), and the highest real-weight word of the key decides instead. When the checkout records rime-wanxiang, a name the 15 weight-giving Wanxiang dictionaries under `sources/pinyin/wanxiang/` list with the same reading (the set the `reweight` stage's first step reads) also gets `round(Wanxiang weight × 9.2)` as a floor, raise only: it is written when it is above both the weight the tiers and the cap give and the weight those files already have. Being on the same scale as the aligned rows it competes with, it is not capped and it raises ranked names too, so a city rime-ice lacks but Wanxiang counts above its homophone goes back ahead of it (湖州 1228 against 胡诌 662), while one Wanxiang counts below a common word stays behind (固原 436 against 雇员 2672). The rules (suffixes, exclusions, reading confirmation, floors, the cap, the Wanxiang floor) are documented in `src/places_supplement.rs` and in the file's header, and the command prints what it left out. The `places-supplement` stage merges that file, read from the `--dictionary` checkout, into the quanpin tables before `custom-words`, raising weights only. When the `places/` entries, `READINGS`, the compared pinyin files, the `curation/` pinyin tables or the Wanxiang files change, rerun the command into msime-dictionary and commit the file there (update `upstream.lock.json` too when the file is in it).

## The SCOWL English words

`msime-english.db`'s `english_words` table holds the rime-ice word lists (`sources/english/rime-ice-en.txt`, `sources/english/rime-ice-en-supplement.txt`), `sources/english/scowl-words.txt` and `custom/english.txt`, ranked by `sources/english/google-word-counts.txt`; a word without a count is stored at 0, after every counted one. Every casing a list gives a word is its own row (china and China, PostgreSQL and postgresql). One casing leads with the word's count and the others are stored one below it: the casing SCOWL's spelling dictionary lists when it lists the word only capitalised (Wikipedia, Ukraine, Skype), otherwise the all-lowercase one (china, may, go), otherwise the first one listed (DOS before DoS). A word with several casings and no count gets 1 for its leading casing, so the zero tie does not fall to the Engine's display byte order. The English stage reads the pinned SCOWL archive for this.

`msime-dict-build english-supplement --dictionary <msime-dictionary checkout> --cache <sources-cache> --out <file>` writes msime-dictionary's `sources/english/scowl-words.txt` from the Aspell English dictionary en-wl/wordlist publishes with a release (pinned as `scowl/aspell6-en-*.tar.bz2`, its commit as the `SCOWL` reference): SCOWL up to size 60, American plus British -ise spellings, letters only and at least three of them, without the words the rime-ice lists or `custom/english.txt` already have in any casing or that rime-ice commented out (`# huang huang`), without the slurs in `OFFENSIVE`, without capitalised-only names whose lowercase form is the full pinyin of a word in the pinyin lists (Guangzhou, Wang: mixed input would put them in the second slot whenever that pinyin is typed), and without words Google has no count for. The `english-glosses` stage gives these words English-to-Chinese glosses but keeps them out of the Chinese-to-English index, which therefore stays as the rime-ice and custom lists make it. SCOWL's licence (`resources/licenses/scowl-aspell6-en-Copyright.txt`) asks for its notice in every copy, so the file's header repeats it, the English stage stores the licence text in the database's `source_notices` table and writes it beside the database as `msime-scowl_Copyright.txt` (a shipping artifact the product check requires byte for byte, for msime-dictionary's `dict-v` release to attach), and the command stops when the package's `Copyright` no longer matches the committed text. The rules are documented in `src/english_supplement.rs`. When the archive, the compared files or the rules change, rerun the command into msime-dictionary and commit the file there (update `upstream.lock.json` too when the file is in it).

## 五笔词组补全

`Wubi`、`Wubi98` 阶段每次从本次 `--dictionary` 的原表、拼音表、区划表与 `custom/words.txt` 重新生成补充数据，再导入 `msime-wubi.db`。生成的中间文件位于 `--out`，不会改写词库仓。词库仓的 `sources/wubi/*-supplement.txt` 继续作为可复现的审计快照；发布构建不依赖快照是否已跟上人工投稿。

两版分别从自己的单字全码推导词组码：两字取 2+2，三字取 1+1+2，四字及以上取前三字与末字的首码。多个全码的所需前缀不一致时跳过。收录另一版原表中缺失的多字词、rime-ice 主表与补充表中权重不低于 100 的多字词，以及不限权重的人工词条和区划词。原表任意编码已有的词不再补入。补充词权重低于原表同码词，且至多为 9；新增重码可能使原本唯一的四码停止自动上屏，生成报告统计这类编码。CJK 扩展字与未授权词库不参与补全。

### 新世纪五笔

`WubiXsj` 阶段（`--only wubixsj`）构建 `msime-wubi.db` 的第三张表 `wubixsj`，结构和索引与 `wubi86`、`wubi98` 相同。上游码表 `sources/wubi/wubixsj-byujiang.txt`（byujiang/wubi06_rime 的 `dicts/wubi06.dict.yaml` 原样副本，来源存疑，见 `resources/licenses/msime-engine-dictionary-NOTICE.md`）只取单字：CJK 统一汉字基本区（U+4E00–U+9FFF）以外的字、部首、私用区字符、标点和编码不是 1 到 4 个 a–y 字母的行都不收，上游的 61702 个词组也不收。上游权重是个人手调的数值，不进表；文件里同一编码下几个单字的先后没有意义（`g` 下「王」在「一」之前），所以只用上游权重定同码单字的名次，再按名次给 10 的倍数，和 98 表的做法一样。

这个阶段只在 `--dictionary` 收了新世纪词组快照 `sources/wubi/wubixsj-supplement.txt` 时运行。构建器不读这份快照的内容（词组每次重新派生，见下一段），只拿它在不在当发布开关：没有它时阶段跳过，`msime-wubi.db` 里没有 `wubixsj`，产品检查也要求这张表不在；有它时产品检查要求这张表至少 50000 行。所以第一个带 `wubixsj` 的 `dict-v` 由收快照的那个 msime-dictionary PR 发出，它同时补上 NOTICE 和发布说明，专利和商标要在合入它之前查完；只收了上游码表、还没收快照的 msime-dictionary 提交照常发布，`msime-wubi.db` 不变。在那之前的提交，包括 `upstream.lock.json` 还没记录 `sources/wubi/wubixsj-byujiang.txt` 的旧提交（例如 `dict-v2.0.41`），用这个构建器也能照常重建。

新世纪表的词组全部由 `wubixsj-supplement` 生成（`src/wubixsj_supplement.rs`），候选与 86、98 补全相同（86 极点表和两张 98 表里的多字词、rime-ice 权重不低于 100 的多字词、人工词条与区划词），编码按同一套词组规则由新世纪单字全码推出；这套规则在上游自己的 61702 个四码词组上全部还原。权重分两层：86 原表里有的词沿用它在 86 表里的权重（拆分之后 rime-wubi 的行按上面 `wubi` 阶段说的换算，只来自 rime-wubi 的词不带它在 86 表里越过同码极点行得到的权重，在新世纪编码上按同一条规则只和同码单字比一次，越不过时取不比词频的权重，一般是 10，排在同权重的单字之后），所以常用词组可以像在 86 里那样排在同码生僻单字之前；其余的词与 86、98 补充表一样至多为 9，所以低于所有单字（最低是 10）；对同码的第一层，它们至多是第一层最低权重减 1、最低为 0，第一层最低权重为 0 时两者同为 0。构建把生成表并在单字之后，同一编码内第一层在第二层前面，引擎同权重按 rowid 排，所以第二层在候选里永远排在同码单字和第一层之后。

`wubi86-supplement`、`wubi98-supplement`、`wubixsj-supplement` 子命令仍可单独重建快照。编码规则共用引擎的 `wubi_phrase_code`；个人确认组词也使用该规则，写入本地回放日志以保留到词库升级后，受原有学习开关与反查限制，不上传公共词库。

## rime-ice 更新审核候选

```sh
msime-dict-build rime-ice-supplement --upstream <干净的 rime-ice 检出> --dictionary <msime-dictionary 检出> --out <候选目录>
```

此命令写出中英文补充表、上游许可证、`upstream-update.json`、不支持读音的 `unsupported-readings.txt` 与未注音行的 `unannotated-words.txt`。表头记录完整上游提交、生成器提交、全部输入摘要与去重集合。中文读取 `base`、`ext`、`8105`、`others` 四份带读音表，按同词同音排除主拼音表、单字表、区划与人工词条；重复词音取最大权重。引擎暂不支持或不符合逐字校验的读音单列供审核，不猜读音。未注音的 `tencent.dict.yaml` 不导入。英文读取 `en`、`en_ext`，排除基础英文、SCOWL 与人工英文已含的小写词形（用 `english` 阶段的同一套解析器取，多词短语不算成它的第一个词；基础英文表里被 rime-ice 注释掉的 `# 词 编码` 条目也算，不把 rime-ice 有意去掉的词加回来），保留纯 ASCII 字母显示词和上游的大小写。上游只给大写写法、而小写词形本身是普通英文词的（PuTTY 和 putty 油灰），SCOWL 补充表按小写词形对照不会再收，所以 `english` 阶段给补充表里只有非小写写法、SCOWL 拼写词典收了小写词形的词补上小写写法（`english::add_attested_lowercase`），小写写法领头。表头第 1 行写生成器所在的 msime 提交，有未提交改动时带 `-dirty`，词库仓的 `check_upstream.py` 拒绝这种表头。

词库仓每周生成审核 artifact，仍需按跨仓流程审核词频、读音和许可，并同步上游引用、许可证、源数据与锁文件后试跑完整发布构建。此命令不修改锁或自动发布；历史补充表的权重曾另经万象对齐，本次候选的权重变化也必须审核。

## The 五笔 86 helpcode table

`resources/helpcodes/wubi86_helpcode.txt` is the table of the `wubi86` helpcode scheme: one `character=code` line per character, the code being the first two letters of the character's full code in msime-dictionary's 86 table, `sources/wubi/wubi86-jidian.txt` together with `sources/wubi/wubi86-rime-wubi.txt` once the checkout has split them (the two layouts give the same table). `msime-dict-build wubi86-helpcode --dictionary <msime-dictionary checkout> --out resources/helpcodes/wubi86_helpcode.txt` writes it; it reads nothing else (not even the pinyin tables the build compares the rime-wubi rows on, because the weights do not matter here) and downloads nothing, so it takes no `--cache`. The full code is the one the 86 supplement uses, the character's longest code in the table; a character whose several longest codes disagree on their first two letters, or whose longest code is shorter than two letters, is left out, and so are the characters of CJK Extension A and beyond the Basic Multilingual Plane, which `msime-wubi.db`'s `wubi86` table drops too. The header records the SHA-256 of each file it read (one file before the split, two after it) and no commit, so the same input gives the same bytes. The rules are documented in `src/wubi86_helpcode.rs`; where the table comes from and what licence it is under is in `resources/helpcodes/NOTICE-wubi86.md`, which also records the SHA-256 of the committed table. When the jidian file changes, rerun the command, commit the table and update that notice.

## The Korean Hanja table

Korean mode converts the composing syllable to Hanja from a table that also ships inside the engine: `msime-dict-build hanja --dictionary <msime-dictionary checkout> --cache <sources-cache>` reads `sources/korean/hanja.txt` from [libhangul](https://github.com/libhangul/libhangul) (`data/hanja/hanja.txt`, BSD-3-Clause, see `resources/licenses/libhangul-hanja-BSD-3-Clause.txt`) at the commit the lock's `libhangul` reference records, kept verbatim by msime-dictionary, and rewrites `crates/engine/src/korean/hanja.tsv`, which is committed. Only single-syllable readings are kept: one precomposed Hangul syllable mapped to one Hanja in CJK Unified Ideographs, Extension A, or one of the twelve unified ideographs of the CJK Compatibility Ideographs block (U+FA0E, U+FA11 and so on, which NFC leaves alone). True compatibility ideographs, characters outside the BMP and multi-character values are dropped, each syllable lists the readings that have a 훈음 comment before those that have none or only a pointer to another Hanja (噋 `啍과 同字`), and among the latter puts the characters that OpenCC's `STCharacters.txt` (read from the same checkout) lists only as simplified forms (双, 兴) last, each group in the source's order (the unglossed rows hold most of the simplified and rare characters: 庄 led 팽 ahead of 彭), and the source's 훈음 comment becomes the third column. `scripts/test-korean-hanja-table.py` checks the committed table against these rules, and against the generator's output when `MSIME_DICTIONARY` names a msime-dictionary checkout. To take newer data, first change the `libhangul` reference, `COMMIT` in `crates/engine/src/korean/hanja.rs` and the script's constants in msime, then replace the file in msime-dictionary and update its `upstream.lock.json`, rerun the command, and review the diff of `hanja.tsv`.

Releases are cut by msime-dictionary's `.github/workflows/release-built-dictionaries.yml` whenever a push to its `main` changes `sources/` or `custom/`: it builds every artifact without `--include-unlicensed`, passing the checkout of that pushed commit as `--dictionary` so the release is built from exactly that commit, checks `msime-SHA256SUMS.txt` and `msime-language-dictionaries-SHA256SUMS`, and publishes a `dict-vX.Y.Z` release on metasequoiaime/msime-dictionary with the artifacts, `msime-dictionary-manifest.json` and the checksum files as the builder wrote them. After a release is published, bump `resources/desktop-dictionary.lock.json` and `resources/language-dictionaries.lock.json` to the new files under `metasequoiaime/msime-dictionary`. To move an upstream to a new commit, or to regenerate `hkcancor-word-counts.txt` or `scowl-words.txt`, merge the msime change first (the reference, the Mozc revision for mozc and the licence texts, so `scripts/test-language-data-notices.py` passes), then the msime-dictionary change that replaces the files and updates `upstream.lock.json` (`scripts/check_upstream.py --update <path>`); try that branch first with the release workflow's `workflow_dispatch` at `msime_ref=<the msime branch>` and `publish=false`. A push to msime-dictionary between the two merges fails the release in `Dictionary::open` rather than publishing mismatched data; rerun the workflow after both are in.

## 网页词库

网页内置输入法（`crates/engine-wasm`）不带完整的桌面词库，而是带从词库 release 的 `msime-pinyin.db`（全拼表与 `quick_parases`）和 `msime-wubi.db`（`wubi86`、`wubi98`，较新的发布还有 `wubixsj`）裁出来的两个库，由 `web` 子命令生成。两个输入先在临时副本里合成拆分前单个主库的布局（五笔表按 rowid 顺序复制），再按下面的规则裁剪：

```sh
cargo run --locked --release -p msime-dict-builder --bin msime-dict-build -- web --pinyin <msime-pinyin.db> --wubi <msime-wubi.db> --out-dir target/web-dict [--keep-multi 200000]
```

- `msime-pinyin.db`：全拼和双拼共用。保留全部单字表 `tbl_1_*`；多字表 `tbl_{2..7,others}_*` 合在一起按 `weight DESC, key, value, 表名, rowid` 排序，只保留前 `--keep-multi` 行（默认 200000，即评测里的 d200000）；`wubi86`、`wubi98`、`wubixsj` 和 `quick_parases` 清空。
- `msime-wubi86.db`：只保留 `wubi86`，全拼表、`wubi98`、`wubixsj` 和 `quick_parases` 清空。`wubixsj` 只在带新世纪表的发布里有，没有时两个输出里也没有这张表。

两个库都保留两个输入库合起来的全部表结构和索引，被清空的表查询时返回空结果而不是报错；随后 `ANALYZE`（只留 `sqlite_stat1`），再用 `VACUUM INTO` 写出不带空闲页的回滚日志模式数据库。输入只读打开，不会被修改。输出逐字节可复现：同样的输入跑两次得到相同的 sha256，`tests/web.rs` 会检查这一点。输入库里出现不认识的表、`msime-wubi.db` 里有五笔以外的表或拼音库里已有五笔表（两个输入给反了，或不是拆分后的 release）时命令直接失败。

## Checking contributed words

msime-dictionary's CI gates changes to `custom/words.txt`, `custom/translations.txt`, `custom/english.txt` and `custom/cantonese.txt` with `check-words`. Pass a base/head pair for each file to check (at least one); the words pair keeps its original `--base`/`--head` names:

```sh
msime-dict-build check-words \
  [--base <old words.txt> --head <new words.txt>] \
  [--translations-base <old translations.txt> --translations-head <new translations.txt>] \
  [--english-base <old english.txt> --english-head <new english.txt>] \
  [--cantonese-base <old cantonese.txt> --cantonese-head <new cantonese.txt> --cantonese-characters <jyut6ping3.chars.dict.yaml>] \
  [--msime-db <shipped msime-pinyin.db>] [--english-db <shipped msime-english.db>] [--cantonese-db <shipped msime-cantonese.db>] \
  [--pinyin-vetoes <curation/pinyin-vetoes.txt>] [--english-vetoes <curation/english-vetoes.txt>] \
  [--json report.json] [--markdown summary.md]
```

For every file a change may only append lines, and each appended entry goes through the parser the build uses and must not repeat another appended line or an entry already in that file. Per file:

- `words.txt`: word, `'`-separated quanpin that maps to a table, integer weight. The weight must lie within the range the existing entries use; with `--msime-db`, a row with the same word and pinyin in the shipped quanpin tables is rejected; with `--pinyin-vetoes <curation/pinyin-vetoes.txt>`, a word that table vetoes as a whole word, or under this reading, is rejected, since the build would delete it. A vetoes file given but missing (msime-dictionary before it added the table) counts as empty, as in the build.
- `translations.txt`: `source<TAB>gloss`. A new gloss for an existing source is accepted (the build's last line wins), but the same source and gloss again is a duplicate. A gloss of a single `-` deletes the source's gloss in the build (the ECDICT one and any earlier custom line).
- `english.txt`: lowercase ASCII word, non-empty display, integer weight of at least 1. An entry is its word and display; the weight must lie within the range the existing entries use; with `--english-db`, a word and display already in the shipped `english_words` is rejected. A word the English stage vetoes is rejected: the builder's built-in slurs always, and with `--english-vetoes <curation/english-vetoes.txt>` the words of that table too.
- `cantonese.txt`: word of at least two characters, toned Jyutping with one syllable per character, each character read as `--cantonese-characters` (the checkout's `sources/cantonese/jyut6ping3.chars.dict.yaml`, required with this pair) reads it, the same checks the build runs. An entry is its word and toneless Jyutping, so a row that differs from another only in tone is a duplicate; with `--cantonese-db`, a word already in the shipped `entries` under the same toneless Jyutping is rejected.

Appended blank and `#` lines are skipped. The JSON report lists `added` and `rejected` lines, each with its `file` (for example `custom/english.txt`) and 1-based line number; added lines carry the parsed fields, rejected ones the text and reason. It also has `accepted`, a `files` array with each checked file's line counts and `weight_range`, and, at the top level as before, `words.txt`'s line counts and `weight_range` (null when `words.txt` was not checked). The Markdown summary is the same in table form, with an Added table per file, and is also printed to stderr. The exit status is 0 when nothing is rejected, 1 when anything is (the reports are still written), and 2 when the check cannot run: an unreadable file, a base file the build itself would reject, or a database without the expected table.
