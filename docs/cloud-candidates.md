# 云候选服务

拼音与日文云候选只发送当前未上屏的拼写，不发送已上屏文本、个人词库、输入历史或 AI 前文。英文补全另需本机显式授权，并携带最近提交的前文，见下方「英文模式」。新装默认关闭；已有的 Google 选择继续保留。关闭或请求失败时继续使用本地候选，不阻塞按键。

macOS、Linux 和 HarmonyOS 在「设置 → 输入」配置；Windows 在「输入」页「候选与联想」标签的云候选各行配置（「云候选来源」起，按「保存云候选服务」保存）；iOS 在「候选栏 → 云候选服务」配置并需允许键盘完全访问；Android 在「输入 → 中文 → 云候选服务」配置。macOS、Linux、HarmonyOS、Windows 和 iOS 编辑完成后保存整组配置；Android 的字段逐项确认保存，配置好方法和接口后再选择自定义来源。

## 来源与请求

- Google input-tools：保留原有拼音、日文请求和首条候选行为。
- 百度输入法：通过 `https://olimenew.baidu.com/py` 转换当前拼音，校验 `status: "T"`、`errno: "0"` 后采用首条候选；不发送账号、设备标识、已上屏文本或个人词库，不接管日文与英文请求。
- 自定义 HTTP 接口：填写自己的服务地址，支持 GET 和 POST。公网地址必须用 HTTPS，本机 `localhost`、`127.0.0.1`、`::1` 可用 HTTP。不会跟随重定向，也不会附带系统 Cookie。
- GET：在地址的路径或查询参数中使用 `{query}`，例如 `https://cloud.example.invalid/candidates?q={query}`；共享层按 URL 参数规则编码当前拼写。不能在主机名中使用占位符。
- POST：地址可固定，请求体模板必须是 JSON 对象；字符串值里的 `{query}` 会被替换并按 JSON 转义。例如 `{"query":"{query}"}`。请求头默认包含 `Accept: application/json` 和 POST 的 `Content-Type: application/json`。
- 请求头填 JSON 字符串映射，例如 `{"Authorization":"Bearer synthetic-token"}`。`Host`、`Cookie`、`Content-Length`、连接控制和代理凭据头由传输层管理，不能自定义。

请求头和模板各最多 4096 字节；最终请求体最多 8192 字节，URL 最多 2048 字节。模板不能读取其他偏好、词库或历史。接口地址、请求头和模板只保存在本机，不随设置文件导出或账号设置同步；诊断快照不包含这组配置。不要在公开问题报告里粘贴自己的请求头或地址查询串。

## 响应

默认选择「标准 candidates 数组」，返回 UTF-8 JSON：

```json
{"candidates":[{"text":"合成候选"},{"text":"另一候选"}]}
```

当前只采用第一条候选，保留一个云候选席位；缺少数组、文本不是字符串、文本为空、含控制字符或超过 512 字节时按失败处理。也可以选择 Google input-tools 响应格式。

「JSON 路径」支持点分对象键和数组下标，例如 `data.0` 对应 `{"data":["合成候选"]}`，`data.0.text` 对应 `{"data":[{"text":"合成候选"}]}`。路径必须最终指向字符串，不执行脚本，也不展开通配符。模型接口可自行填写固定模型和提示词的 JSON 模板，再以 `choices.0.message.content` 等路径取候选；它独立于 AI 联想，不会自动带入 AI 前文或凭据。

回包上限为 256 KiB，只接受成功状态；解析失败静默保留本地候选。百度预设的 HTTPS 请求与真实 JSON 回包已通过合成拼音验证；它没有提供接口稳定性承诺。搜狗样本的当前云联想使用加密传输与 Protobuf，旧 Web 接口已不可用，因此本版本没有提供能直连搜狗私有云的预设。逆向证据与实际接入范围见[商业云候选与后续词预测](commercial-prediction.md)。

## 超时与缓存

默认总时限两秒，可设置为 100–10000 毫秒；连接时限最多两秒，且不长于总时限。各宿主在原有输入空闲防抖后异步发送。macOS 的 NSURLSession 没有独立连接时限，以总时限限制整次请求。

打开缓存时，成功回答在本进程内存保留十分钟，空或无效回答保留六十秒，最多保存 4096 项，不落盘。缓存键包含来源、接口、请求头、模板、解析配置、语言和拼写的摘要；修改任一配置不会复用旧来源的回答。关闭缓存后不读写这份 HTTP 结果缓存；当前组字已收到的候选仍正常显示。

切换来源或修改配置会立即移除旧云候选，使旧查询失效。迟到回包不能进入新配置；Google 不可达或自定义服务失败时也不会自动切到另一个服务。

## 英文模式

macOS 的「AI 辅助」页提供默认关闭的 `english_online_candidates`。开启后，普通英文、专用英文和临时英文的字母串与最近提交的前文可以发送给已启用的服务；关闭授权立即撤回英文在线行并拒绝旧回答。这项本机授权不随设置文件或账号同步。其他宿主尚未接通普通英文输入路径，不显示此开关。

内置 Google input-tools 只接收原有的拼音或日文查询，不接收英文补全请求。英文云候选只用用户配置的自定义服务，继续使用原有 `{query}` 模板传字母串，并显式补上模式与前文：POST 的 JSON 根对象增加 `mode: "english"` 和 `context`；GET 增加同名查询参数，覆盖模板里的旧值。前文与模式参与缓存身份；展开后超出已有地址或请求体上限时跳过该次云请求，不回退到内置服务。响应格式与原有云候选协议相同。

AI 请求的用户消息携带 `mode: "english"`、`input`（原始字母串）、空的 `segmented_pinyin`、`context` 和 `candidate_limit`。空提示词槽使用英文补全与纠错提示；已有的自定义提示词槽仍完整替换默认提示。原拼音请求缺省模式不变，缓存与英文分开。


## 上屏后联想

Android 的「表达 → 智能」和 macOS 的「输入 → 候选与联想」提供默认关闭的「上屏后联想」。选词上屏后可继续点选后续字词，只上屏所选后缀；空格、回车、数字和导航键仍由编辑器处理。新输入、失焦、外部光标移动或隐私会话清除建议。

本地建议来自词库续词和已启用学习时的个人词序。自定义 HTTP 服务可在云候选配置中另行开启「允许上屏后云预测」：仅在云候选与上屏后联想都已开启时发送刚上屏序列的最多 64 个汉字，不包含整篇文档、光标后文本或输入历史。此授权只在本机保存，不随账号同步；关闭后立即拒绝在途回复。

服务收到的 `{query}` 是这段汉字，另携带 `mode: "prediction"` 和相同的 `context`。GET 用查询参数传递，POST 用 JSON 根字段传递；服务必须返回**尚未上屏的后续词**：

```json
{"candidates":[{"text":"饭"},{"text":"东西"}]}
```

响应最多接收八条有界、去重的纯汉字后缀；本地首选保留在前，至多三条新云建议随后插入，总计不超过八条。JSON 路径格式也可指向字符串数组或带 `text` 的对象数组。云端失败、空回复或超时保留本地建议；Google 与百度的拼音预设没有后续词协议，汉字预测不会回退到这些服务。只有显式点选才提交云建议，迟到结果不能跨组字、选词、焦点或配置生效。
