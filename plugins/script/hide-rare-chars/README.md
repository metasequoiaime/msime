# hide-rare-chars：隐藏生僻字

把候选窗口里含生僻字的候选隐藏起来。打 `kao` 时「丂」、打 `jiong` 时「囧」这类不在常用字表里的字不再出现在列表里，常用字往前补位。

| 项 | 值 |
| --- | --- |
| 钩子 | `candidates` |
| 能力 | `read_candidates`（读候选窗口前 20 行的文字和来源）、`filter_candidates`（把其中一些行隐藏） |
| 许可证 | 代码 MIT；内嵌的常用字集来自 Unihan（Unicode-3.0）和 OpenCC（Apache-2.0），见包里的 NOTICE.txt |
| 模块 | 约 6.9 KiB，内存 2 页 |

插件不读你打的编码，不改上屏的文字，也不改候选的顺序；它能做的只有「把某几行藏起来」。

## 什么算生僻

一行候选里只要有一个字同时满足下面两条，这一行就算生僻：

- 落在汉字区段：扩展 A（U+3400..U+4DBF）、基本区（U+4E00..U+9FFF）、兼容汉字（U+F900..U+FAFF）、第二和第三平面（U+20000..U+3FFFF，扩展 B 及以后）；
- 不在常用字集里。常用字集是《通用规范汉字表》的 8105 字，再加上这些字的繁体形，共 11 049 字，详见下面的「数据来源」。

所以「龘」「㐀」「𠮷」、兼容区的「豈」（U+F900）算生僻；「們」「這」「發」「爲」「為」「峯」这些繁体形不算，注音、粤语这类输出繁体的方案不会被误伤。字母、数字、标点、假名、emoji 永远不算生僻，「T恤」「A股」照常显示，「A𠀀」会被隐藏。

判断只看码位，不看字体能不能显示。

## 哪些行不动

- **窗口第 0 行**，即使它是生僻字。首位出现生僻字，几乎都是你打了它的完整编码或者学过这个字；失焦上屏、14 键原样上屏等「取首选」的路径取的也总是它。另外宿主保证引擎给出的第一个候选永远不被隐藏：两者通常是同一行，偶尔内置排序把它挪到别处，这时宿主会忽略对它的隐藏请求，插件看不出来，也不用处理。
- **不是引擎词库给的行**：用户词库、快捷短语、emoji、颜文字、生成的文本（计算器、日期等）。只隐藏来源为词库（0）、英文（4）、兜底（9）和键盘整句模型（11）的行；以后新增的来源默认也不动。
- **云候选、AI 候选和 AI 占位行**：宿主锁定它们，插件也不点名。固定了位置的词和五笔四码唯一的首选同样被宿主锁定，插件点了名也不会生效。
- **日文候选窗口**：本地模式是临时日文，或者窗口里有含假名的行（emoji、颜文字行里的「ツ」「ノ」不算），整个窗口不动。常用字集不收日文新字体（気、込、広），不跳过的话日文汉字会被当成生僻字藏掉。
- **第 21 行及以后**：插件只看得到窗口前 20 行，翻页之后可能还会看到生僻字。

## 例子

| 候选窗口 | 结果 |
| --- | --- |
| 中、忠、㐀、钟、丂、终 | 隐藏第 2、4 行（㐀、丂） |
| 龘、中、囧、钟 | 隐藏第 2 行（囧）；第 0 行的「龘」留着 |
| 中、槑（用户词）、囧 | 只隐藏「囧」 |
| 中、囧（AI）、槑（云）、猋 | 只隐藏「猋」 |
| 気、きょう、込 | 日文窗口，不动 |
| 們、這個、發、乾、爲 | 都是常用字的繁体形，不动 |
| T恤、A𠀀、Q囧、hello | 隐藏「A𠀀」「Q囧」 |

## 代价

被隐藏的行降到列表末尾，不显示，也选不到，所以开着这个插件时打不出这些字。需要时在设置的「插件 → 脚本插件（实验）」里临时关掉它，或者换用 [rare-chars-last](../rare-chars-last/)（生僻字靠后，不隐藏）。两个插件一起开没有意义：被隐藏的行不会再出现在重排结果里，二选一即可。

## 限制

- 每次最多读 640 字节的候选文字，第 1 行起最多细看 100 个 U+3000 以上的字（辅助平面的汉字按 3 个算）。哪个先用完就停在那一行，那一行和后面的行不判定、不隐藏，日志里写 `stop <行号>`。正常的候选窗口（20 行、每行几个字）远到不了这两个数。
- 单行超过 256 字节（约 85 个汉字）的候选不判定。
- 插件没有设置项，生僻与否的标准不能调。

## fuel

实测（rustc 1.97.1、wasmi 2.0），`candidates` 单次上限 125 000：

| 窗口 | fuel |
| --- | --- |
| 6 行单字，2 行生僻 | 约 3 700 |
| 20 行单字，没有生僻 | 约 9 400 |
| 19 行「中国人民」×8，常用字用满 100 个后停下 | 约 25 400 |
| 19 行各 8 个辅助平面常用字 | 约 20 300 |
| 第 0 行 12 个字母加 20 个句号，其余 19 行各 12 个字母加「中国人民囧」，全部隐藏 | 约 38 000 |
| 20 行随机混排：汉字、繁体字、辅助平面字、注音、泰文、各种标点和 emoji，多种来源（细看满 100 个字后停下，夹具最后一条，实测最坏） | 约 38 600 |
| 20 行各 255 个 ASCII 字母，读满 640 字节后停下 | 约 15 700 |

最坏情况约 38 600，约为上限的 31%，同一个按键里宿主多调用几次也够用。夹具最后一条来自随机生成的窗口：在 3 000 个这样的窗口里它最贵。

插件没有用共用的 `common_chars::classify` 逐字分类，而是在 `src/scan.rs` 里先按 UTF-8 首字节跳过不可能是汉字或假名的字节，只在汉字上调用 `common_chars` 的查表函数：wasmi 在函数入口按函数体里全部指令扣 fuel，`classify` 每个常用汉字约 290 fuel、每个 ASCII 字节约 36 fuel，这里分别约 250 和 17。

## 数据来源和许可证

常用字集是 `plugins/script/data/common-chars.bin`（约 4 KiB），由 `plugins/script/tools/gen_common_chars.py` 确定性地生成，编译时嵌进模块：

- Unicode Han Database（Unihan）17.0.0 的 `kTGH`（《通用规范汉字表》2013 年版，8105 字）和 `kTraditionalVariant`，许可证 Unicode-3.0，包里带 `Unicode-License-V3.txt`；
- OpenCC 提交 26753884f1984add422f3b0249ccee8613deaff6 的 `STCharacters.txt`，补充 151 个繁体形，许可证 Apache-2.0，包里带 `OpenCC-LICENSE.txt`。

插件代码按 MIT 发布（`LICENSE.txt`）。包的 `license` 写 `MIT AND Unicode-3.0 AND Apache-2.0`，`NOTICE.txt` 写明数据的来源、版本、摘要和生成方式。
