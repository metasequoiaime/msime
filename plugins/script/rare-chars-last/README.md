# rare-chars-last：生僻字靠后

把含生僻字的候选移到候选窗口的末尾，其余候选保持原来的先后顺序。打 `yi` 时「乚、伇」这类字不再夹在「一、以、已」中间，但仍然在窗口里，需要时照样能选。

| 项 | 值 |
| --- | --- |
| 钩子 | `candidates` |
| 能力 | `read_candidates`（读候选窗口前 20 行的文字和来源）、`rerank_candidates`（调整这些行的先后） |
| 许可证 | 代码 MIT；嵌入的常用字集来自 Unihan（Unicode-3.0）和 OpenCC（Apache-2.0），包里带全文和来源说明 |
| 模块 | 约 12.4 KiB，内存 2 页 |

插件读不到编码、注释、预编辑串和上屏文本，也不改写任何文字；它只决定窗口里各行的先后。

## 例子

| 窗口（行号从 0 起） | 结果 | 日志 |
| --- | --- | --- |
| 中、㐀、钟、𠀀、忠 | 中、钟、忠、㐀、𠀀 | `order 0,2,4 rare 1,3` |
| 㐀、中、丂、钟 | 㐀、中、钟、丂（第 0 行不动） | `order 0,1,3 rare 0,2` |
| 中国、叁𠀀、钟表、T恤 | 中国、钟表、T恤、叁𠀀 | `order 0,2,3 rare 1` |
| 中、钟、㐀、丂 | 不变（生僻行已经在末尾，不调用重排） | `keep rare 2,3` |
| 們、這個、發、乾、爲、裡、峯 | 不变（繁体形都在常用字集里） | `keep` |

## 规则

- **什么算生僻字**：码位在汉字区段（扩展 A、基本区、兼容汉字 U+F900..U+FAFF、第二和第三平面）里，并且不在常用字集里的字。常用字集是《通用规范汉字表》的 8105 字，加上这些字的繁体形，共 11 049 字，所以注音、粤语等输出繁体的方案不受影响。一行里只要有一个生僻字，这一行就算生僻。字母、数字、标点、假名、韩文、emoji 都不算。
- **只看码位，不看字形**：扩展区的字即使字体显示不出来也算生僻；「囧」「槑」这类网络用字不在《通用规范汉字表》里，也算生僻。兼容汉字区的字（例如 U+F900「豈」）都不在常用字集里，一律算生僻。
- **不判定的行**：来源是用户词库、英文、快捷短语、emoji、颜文字、生成的文本（计算器、日期等）的行，一律当作不生僻。用户自己加的词和短语，插件不替用户判断。
- **不点名的行**：云候选、AI 候选和 AI 占位行由输入法锁定在原位，插件不点名，它们也不会被移动。固定了位置的词、五笔四码唯一时的首位，输入法同样锁定，插件看不出来，点名了也不动。
- **窗口第 0 行永远不动**，即使它是生僻字。首位出现生僻字，多半是你打了它的完整编码，或者以前选过它。窗口第 0 行通常也就是引擎的首位，输入法失焦上屏、原样上屏时取的是它，留在原位，屏幕上的首选和实际上屏的字才一致。例外是输入法自己的逐键排序把别的候选提到了第 0 行：这时引擎的首位在后面某一行，插件看不到引擎的次序，它含生僻字时也会和别的生僻行一样移到末尾（输入法只保证引擎的首位不被隐藏，不限制重排）。
- **移到窗口末尾，不是列表末尾**：插件只看得到前 20 行。生僻行排到这 20 行里所有不生僻的行后面，但仍在第 21 行及以后的候选前面，翻页时还会先看到它们。
- **能不动就不动**：生僻行已经全在末尾（包括全是生僻字、只有第 0 行生僻）时不调用重排，这样不会盖掉别的插件的排序。

## 什么时候整窗不动

- 窗口少于 2 行。
- 本地模式是临时日文，或者窗口里任意一行含平假名、片假名：日文的新字体（気、込、広）不在常用字集里，不能按中文的标准判断。U+30FB「・」不算假名。
- 本地模式不在可读文本的范围内（网址、命令、快捷短语等），插件读不到候选。
- 没有授权，或者宿主拒绝重排：窗口保持原样，不算失败。

## 限制

- 失焦上屏、原样上屏取的是引擎的首位，不受任何重排影响。
- 为了不超出 fuel，一次最多读 768 字节文本、最多扫描 80 段（见下面的 fuel 一节），单行超过 256 字节也不读。没读或没读完的行按不生僻处理，日志里列在 `unread` 后面。常见的窗口（20 行、每行几个字）远用不完。
- 和别的重排插件一起用时，几个插件的重排是排在后面的优先。这个插件点名了窗口里全部不生僻的行，排在后面会盖掉前面插件的排序，所以请在「脚本插件（实验）」里把它放在最前面。
- 和 hide-rare-chars（隐藏生僻字）做的是同一类事：两个都开时，被隐藏的行不会再显示，靠后这一步就白做了。二选一即可。

## fuel

插件每行先读来源（约 110），需要判定的行再读文字（100 加每 4 字节 1），然后扫描。扫描在 `src/rare.rs`：判定和 `plugins/script/shared/common_chars.rs` 的 `classify` 逐字相同，但 `classify` 每个汉字约 200、每个辅助平面字约 500 fuel，20 行长候选会耗尽 fuel，所以这里在编译时把常用字集展开成按码位直接查的位图（基本多文种平面 U+3000..U+9FFF 每码位 2 位共 7 KiB，辅助平面按 256 个码位一组约 2.5 KiB），按字符种类分段扫描。实测（rustc 1.97.1、wasmi 2.0）：

| 输入 | fuel |
| --- | --- |
| 5 行单字，两行生僻（夹具第 1 条） | 约 4 900 |
| 20 行，每行 30 个汉字（读满 768 字节后其余行不读） | 约 27 500 |
| 20 行，每行 16 个汉字（正好读满 768 字节） | 约 28 500 |
| 20 行，辅助平面字和字母交替（用满 80 段） | 约 36 600 |
| 20 行随机混排：辅助平面字、繁体字、注音、泰文、各种标点和 emoji，多种来源（读满 768 字节，夹具最后一条，实测最坏） | 约 38 700 |
| 临时日文模式 | 约 500 |

`candidates` 单次上限 125 000，同一个按键里的几次调用共用每轮 125 000；最坏情况约 38 700，不到单次上限的三分之一。夹具最后一条来自随机生成的窗口：在 5 000 个这样的窗口里它最贵。

## 数据来源和许可证

常用字集是 `plugins/script/data/common-chars.bin`，由 `plugins/script/tools/gen_common_chars.py` 从 Unihan 17.0.0（`kTGH`、`kTraditionalVariant`）和 OpenCC `STCharacters.txt`（提交 26753884）生成，和 hide-rare-chars 共用。包里带：

- `LICENSE.txt`：插件代码的 MIT 许可证。
- `Unicode-License-V3.txt`：Unihan 的许可证全文。
- `OpenCC-LICENSE.txt`：OpenCC 的 Apache-2.0 全文。
- `NOTICE.txt`：数据的来源、版本、摘要和变换说明。

## 夹具

`fixture.jsonl` 覆盖上面每一条规则：打 `yi` 的窗口、生僻行在中间、第 0 行生僻、没有或全是生僻行、生僻行已在末尾、各种不判定和锁定的来源、第 0 行是锁定的云候选、词里含生僻字、假名窗口、临时日文、繁体窗口、拉丁字母和 emoji 混排、兼容汉字和中点、扩展 A 和辅助平面里的常用字、韩文、超级简拼、空窗口、单行窗口、网址模式、超长的行、同一轮里的第二次调用，以及读满字节预算、用满段落预算的最坏情况。插件每个事件写一行日志：`order <点名的行>`（调用了重排）或 `keep`，后面跟 `rare <生僻行>`、`unread <没读的行>`；整窗不动时是 `skip: <原因>`（`denied`、`absent`、`japanese`、`kana`）。`expected.jsonl` 是去掉 fuel 之后的期望输出，由 `scripts/test-script-plugins.sh rare-chars-last` 核对。
