# emoji-memory：常用表情

记住你在某个编码下选过的 emoji，下次打同样的编码时把它插到候选第二位。例如在 emoji 模式里打 `xiao` 选了 😄，以后用拼音打 `xiao` 时 😄 直接出现在「小」后面，不用再进 emoji 模式去找。它是持久存储（`persist_data`）和往候选里加行（`insert_candidates`）的参考样板。

| 项 | 值 |
| --- | --- |
| 钩子 | `candidates`、`candidate_selected` |
| 能力 | `read_candidates`（读候选窗口前 20 行的文字、编码和来源）、`read_commit`（读你选中的那一行）、`insert_candidates`（往候选里加行）、`persist_data`（长期保存数据） |
| 许可证 | MIT |
| 模块 | 约 7.6 KiB，内存 2 页 |

## 它会在你的电脑上存什么

**这个插件会把数据长期存在这台电脑上，授权前请读完这一节。**

- 存的是一张表，每条三项：**编码**（你打 emoji 时候选窗口第一行的编码，例如 `xiao`、`kaixin`）、**emoji**（例如 😄）、**次数**。最多 32 条，约 2 KiB。
- 只在你选中一个 emoji 时记一条：选中的必须是候选窗口里来源为 emoji 的那一行，或者这个插件自己插进去的那一行。你选的汉字、词、英文都不记，你打出的句子不记，选中的时间不记，在哪个应用里打的也不记。但「编码」本身就是你打过的拼音，所以这张表能看出你在什么词下面用过哪些 emoji。
- 文件在 `<数据目录>/plugins/script-data/emoji-memory.bin`，权限 0600，**没有加密**，同一用户下的其他程序能读到它。它是纯文本，用任何编辑器打开都能看懂（格式见下面）。
- 授权对话框把 `persist_data` 单独放在「记住数据」一组、默认不勾，并用红字说明：插件能把读到的文字长期记在这台电脑上，包括你在不同应用里打过的字；数据没有加密，同一用户下的其他程序能读到；卸载插件或撤销这一项时删除。不勾它，这个插件就什么都不记、也什么都不插。
- 清除：插件详情的「数据」一组显示「已存数据 N KB」，点「清除数据」删掉整个文件；撤销 `persist_data` 或卸载插件时也会删除。插件更新（内容哈希变了）时数据保留，授权照旧要重新给。

## 用法

1. 构建并导入（见[合集的 README](../README.md)），在「插件 → 脚本插件（实验）」里打开「常用表情」，勾选它申请的四项能力，包括「记住数据」组里的 `persist_data`。
2. 在 emoji 模式里打编码选 emoji（或者在开着「候选混输」的普通候选里选 emoji 行），插件记下「编码 → emoji」，次数加 1。
3. 以后在普通的拼音、双拼、五笔输入里打出同样的编码时，这个编码下次数最多的两个 emoji 插在第 1 行（第 0 行候选之后），注释「常用」。选中它们同样会让次数加 1。

| 你做过的事 | 之后打 `xiao` 时的候选 |
| --- | --- |
| 在 emoji 模式里打 `xiao` 选过一次 😄 | 小、😄、笑、校…… |
| 又选过一次 😂 | 小、😄、😂、笑……（😄 次数多，排在前） |
| 候选里本来就有 😄（候选混输） | 小、😂、笑、😄……（😄 已经在窗口里，不再插一次） |

## 规则

- **编码**：取窗口第 0 行候选的编码，去掉 `'` 和空格、大写转小写，只收 1 到 24 个字母；含数字或别的字符（九宫格的数字编码）、更长的都不记也不查。emoji 模式里每一行的编码就是你打的关键词，所以那里记下的编码和普通拼音输入里的对得上。
- **什么时候记**：`candidate_selected` 里，本地模式是 `none` 或 emoji、选中之后直接上屏（暂存进词组的不算）、选中的文字是上一窗里来源为 emoji 的行或插件插的行。含零宽连接符的组合 emoji（👨‍👩‍👧‍👦）和用标签字符拼的旗帜不记：插件插入的行不能含格式字符，输入法会拒绝，记了也插不进去。emoji 后面的 VS16 可以有。
- **什么时候插**：`candidates` 里、本地模式是 `none` 时（输入法只在这时接受插入，临时英文、emoji 模式里都不插）。在这个编码的记录里取次数最多的两个（次数一样时先记下的在前），已经在窗口前 20 行里的跳过，插在第 1 行。每次最多插 2 行（输入法的上限是每个插件 3 行）。
- **满了**：32 条满了以后，新的一对替换次数最少的那一条（最少的有几条时替换最早记下的）。次数到 99 999 不再加。
- **插入的行**：来源是插件，带「常用」注释；选中时原样上屏、组字结束，不进词库、不调词频、不计打字统计、不作为上文发给 AI 候选。这些是输入法对所有插件行的规则。
- **存储什么时候可用**：只在持久实例上的钩子里（这两个钩子都是）。`before_commit`、`command` 和 `msime_init` 里读写存储都是 `DENIED`，所以插件在第一次 `candidates` 时才把存储读进来。`persist_data` 不能和 `rewrite_commit` 一起申请，这个插件也不改写上屏。

## 存储的格式

定长的文本，`msime-pack run` 打出的 `storage` 字段就是它：

```text
emoji-memory 1
00002 xiao                     😄
00001 xiao                     😂
```

第一行是格式和版本。之后每条 64 字节一行（上面省掉了行尾补齐的空格）：5 位次数、空格、编码（24 字节，空格补齐）、空格、emoji（32 字节，空格补齐）、换行，按第一次记下的先后排列。

- 读进来时只看第一行、总长度是不是整条、每条末尾是不是换行。不对（被别的程序改过）就整块当作空的，日志写 `reset: unreadable storage`，下一次记录时覆盖。格式对但内容乱的记录不会出错，只是查不到，或者在插入前被拒。
- 为什么是定长：逐字节解析或比较 32 条变长记录，一次 `candidates` 就要几万 fuel。定长以后读进来只看每条最后一个字节；查找先拿编码、emoji 的前 8 字节当一个 64 位整数比（一条 `i64.load`），对上了才比整个字段、才读次数；次数原地改写，写回就是把整块交给 `storage_write`。
- 为什么不按次数排序：排序要在记录之间挪动，最坏一次挪 2 KiB；找次数最多的两条在查找时顺手比较就够了。窗口里的 emoji 另记一个 64 位的位图，记录的 emoji 不在位图里就不用逐个比。

## 夹具与核对

- `fixture.jsonl`：在 emoji 模式里学、换输入框（`focus_out`、`focus_in`，存储跨输入框保留）后在拼音里插、选中插入的行、选普通候选不记、按次数排两个、窗口里已有的跳过、编码的规范化（`Xi'ao` 当作 `xiao`）、没有记录的编码、暂存进词组的选择、临时英文、网址模式读不到候选、太长和带数字的编码、选中的不是上一窗的 emoji 行、组合 emoji 不记、带肤色的 emoji 能记、空窗口。
- `cases/corrupt/`：`storage.bin` 是一份被手改坏的文件（记录错位），整块当作空的，之后照常记录。
- `cases/full/`：`storage.bin` 是满的 32 条，全是同一个 24 个字母的编码、次数递增，用来卡最坏情况：每一条都要比、窗口里有 19 个 emoji 都要跳过、选中最后一条、满了以后替换次数最少的那一条。
- 不授予任何能力时，每个事件都不能有动作、插入或存储改动（`check_run.py` 核对）。

## 最坏情况的 fuel

实测（rustc 1.97.1、wasmi 2.0）：

| 钩子（单次上限） | 情况 | fuel |
| --- | --- | --- |
| `candidates`（125 000） | 普通的窗口、几条记录 | 约 5 000–8 000 |
| `candidates` | 32 条同一编码、窗口里 19 个 emoji、第一次读入存储（`cases/full` 第 1 条，最坏） | 约 36 800 |
| `candidate_selected`（25 000） | 普通的一次记录 | 约 5 500 |
| `candidate_selected` | 满了以后替换次数最少的一条并写回 2 KiB（`cases/full` 第 6 条，最坏） | 约 10 900 |

都在各自上限的一半以内（62 500、12 500）。`candidate_selected` 的最坏情况离一半只剩一成多：记录上限定在 32 条就是为了它，64 条时找次数最少的那条会超过一半。
