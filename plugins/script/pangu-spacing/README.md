# pangu-spacing：中英文之间加空格

上屏前在中日韩文字和英文字母、数字直接相邻的地方加一个空格：「用Rust写插件」上屏为「用 Rust 写插件」，「今天是2026年。」上屏为「今天是 2026 年。」。

| 项 | 值 |
| --- | --- |
| 钩子 | `before_commit` |
| 能力 | `read_commit`（读上屏文本）、`rewrite_commit`（改写它） |
| 许可证 | MIT，包里不含第三方数据 |
| 模块 | 约 3.7 KiB，内存 2 页 |

## 规则

- 「中日韩文字」的范围和 pangu.js 相同：CJK 部首和康熙部首、平假名、片假名（不含 U+30FB「・」）、注音、带圈字、扩展 A、基本区、兼容汉字，另加第二、第三平面的汉字（扩展 B 及以后）。「英文」只指 ASCII 字母和数字。
- 只在这两类直接相邻的地方插入一个空格。已经有空格的地方、全角标点（「」，。！等）两侧都不插，所以插件是幂等的：改写过的文本再过一次不会再变。
- 数字和单位按 pangu 的惯例也加空格：「2026年」→「2026 年」，「5G网络」→「5G 网络」，「T恤」→「T 恤」，「A股」→「A 股」。这是有意的。
- 像网址、邮箱或路径的文本整段不改：出现 `://`、`www.`（不分大小写），`@` 两边都是 ASCII 字母数字，或者出现 ASCII 的 `/`、`\`、`?`、`=`。最后这条是为了不带协议头的网址、路径和查询串（`example.com/a`、`C:\Users`、`?q=`），它们没有可靠的边界。宁可错过一次加空格，也不在网址或路径里插空格。普通的域名照常处理：「打开example.com看看」→「打开 example.com 看看」。
- 带重音的拉丁字母（é）、希腊字母、全角字母不算英文，旁边不加空格。
- 只改上屏文本里可改写的一段（body）。标点和顶字的尾巴只读，body 和尾巴的交界处、两次上屏之间都不补空格。

## 什么时候不改

- 宿主说这次上屏不可改写：本地模式不是 `none`（网址、命令、快捷短语等）、方案自己的文本、失焦上屏、以词定字、非普通输入框等，见 docs/plugins.md 的能力一节。
- 没有授权（`commit_text` 返回 `DENIED`）、body 为空，或者结果和原文相同。
- body 超过 1024 字节（约 340 个汉字），或者字节种类的切换超过 64 处。字节分三类：其他 ASCII、`:` `.` `@` `/` `\` `?` `=`、多字节字符；相邻两个字节类别不同就算一处切换，所以 ASCII 和汉字之间每次算一处，单独出现的 `:`、`.`、`@` 各算两处（进、出），连在一起的几个（`...`）合算两处。正常的一次上屏远到不了这两个数；超过时整段按原文上屏，不截断，不耗尽 fuel。
- 宿主拒绝改写时按原文上屏，不算失败。

## 和内置开关的关系

设置的「输出」组里有内置的「中英文之间加空格」（默认关），规则相近。两者的区别：

- 内置开关只看汉字；这个插件按 pangu.js 的范围，假名、注音、部首旁边也加。
- 内置开关还处理快捷短语和超级简拼的上屏；插件只能改写宿主允许改写的上屏（本地模式 `none`），快捷短语它碰不到。
- 插件跳过像网址、邮箱、路径的文本；内置开关不做这个判断。

两个都打开也不会多出空格：内置开关在 `before_commit` 之前执行，插件看到的是已经加过空格的文本，而它不在已有空格旁边再插。一般开一个就够。

## fuel

插件按字节扫描 body，只在 ASCII 和多字节字符的切换处细看，插空格时整段复制；body 用 SDK 的 `commit::bytes` 读，不做 UTF-8 校验。实测（rustc 1.97.1、wasmi 2.0）：

| 输入 | fuel |
| --- | --- |
| 「用Rust写插件」 | 约 1 700 |
| 1024 字节，前 897 字节是汉字，后面汉字和字母交替，插 63 个空格 | 约 37 200 |
| 1022 字节，前 894 字节是汉字，后面片假名和字母交替，插 63 个空格（最坏的成功情况：假名、注音所在的块里有不算中日韩文字的码位，每处切换都要完整解码；换成注音也一样） | 约 43 800 |
| 「中a」重复到 1024 字节（超过 64 处切换，放弃） | 约 22 300 |
| 1025 字节（超长，不读） | 约 500 |

`before_commit` 单次上限 100 000，这里的最坏情况约 43 800，不到一半。模板 docs/script-plugin-template 的同名例子逐字处理并先校验 UTF-8，body 超过约 100 个汉字就会耗尽 fuel，这个插件就是为此重写的。

## 夹具

`fixture.jsonl` 覆盖上面每一条规则，以及最坏情况和超长输入。插件每个事件写一行日志：改写时是改写后的文本，否则是 `keep` 或 `skip: <原因>`（`not rewritable`、`denied`、`address`、`too long`、`too many changes`）。`expected.jsonl` 是去掉 fuel 之后的期望输出，由 `scripts/test-script-plugins.sh pangu-spacing` 核对。
