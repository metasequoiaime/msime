# calc：指令扩展参数的参考样板

在 `/` 指令里打 `/calc` 加一个算式，例如 `/calc12*(3+4)`，给出结果和「算式=结果」。它是 `[[script.commands]]` 的 `arguments = "extended"`（触发词后面除了字母还收数字和运算符号）的最小样板。输入法本来就有计算模式（`V` 模式），这个插件不是为了取代它，而是给想做进制换算、单位换算、编号生成这类「指令后面跟数字」的作者一个能照抄的起点。

| 项 | 值 |
| --- | --- |
| 钩子 | `command` |
| 能力 | `provide_commands`（读你在它的触发词后面打的字母、数字和运算符号，给出候选行） |
| 指令 | `/calc`（标题「计算」，`arguments = "extended"`） |
| 许可证 | MIT |
| 模块 | 约 10.3 KiB，内存 2 页 |

插件读不到你平时打的字、上屏文本和候选窗口，也不改写任何文字。

## 用法

1. 构建并导入（见[合集的 README](../README.md)），在「插件 → 脚本插件（实验）」里打开「计算」，授予「提供 / 指令」。授权页上这一项的说明写的是「之后打的字母以及数字和运算符号」。
2. 打开「输入 › 快捷模式」里的 / 指令（默认关），并使用中文标点。
3. 没有输入时按 `/`，打 `calc`，再打算式。打完触发词之后数字就是参数，不再选候选：用空格、方向键或点选选中一行。

| 输入 | 候选（注释） |
| --- | --- |
| `/calc12*(3+4)` | `84`（结果）、`12*(3+4)=84`（算式） |
| `/calc0.1+0.2` | `0.3`（结果）、`0.1+0.2=0.3`（算式） |
| `/calc1/3` | `0.3333333333`（约等于）、`1/3≈0.3333333333`（算式） |
| `/calc-7%3` | `-1`（结果）、`-7%3=-1`（算式） |
| `/calc1,000,000*3` | `3000000`（结果）、`1,000,000*3=3000000`（算式）、`3,000,000`（千分位） |
| `/calc1,234.5` | `1234.5`（结果），只有一个数时没有「算式」行 |
| `/calc1+2=` | 末尾的 `=` 去掉不算：`3`、`1+2=3` |
| `/calc`、`/calc1+`、`/calc(1+2`、`/calc1/0` | 不给行，只有原样的那一行 |

## 规则

- **字符**：参数里能出现的只有小写字母、数字和 `. + - * / % ( ) = ,`（`abi::EXTENDED_ARGUMENT_SYMBOLS`，输入法和 `msime-pack run` 都按它核对），最多 64 字节。字母在算式里算写错。
- **运算**：`+ - * / %`，先乘除取余、后加减，同级从左到右；`%` 是截断取余，结果的符号跟被除数（`-7%3` 是 `-1`，`7%-3` 是 `1`），和输入法的计算模式相同；括号可以嵌套；数前面可以有正负号（`-3`、`2*-3`、`-(2+3)`）。没有乘方。
- **数**：整数或小数（`12`、`0.5`、`.5`、`5.`），整数部分可以用 `,` 按三位分组（`1,000,000`），分组不对（`1,00`、`1,0000`）算写错。
- **精确计算**：按分数算，分子分母都是 64 位整数，每一步约分。所以 `0.1+0.2` 是 `0.3`、`1/3*3` 是 `1`，不会出现二进制浮点的尾巴。小数部分不超过 10 位时原样写出（`10/4` 是 `2.5`），否则（除不尽，或者位数更多）四舍五入保留 10 位小数、去掉末尾的 0，注释写「约等于」，算式行用 `≈`。很小的数可能约成 `0`（`0.00000000004`）。
- **不给行**：参数为空、算式没写完或写错、除以 0 或对 0 取余、任何一步的分子或分母超出 64 位整数（`9999999999*9999999999`）时不给任何行，输入法只显示原样的那一行。插件给不出「错误提示」行：候选行选中就会上屏，不能拿来显示说明。原因写在日志里：`skip: empty`、`skip: syntax`、`skip: divide by zero`、`skip: overflow`。
- **行**：结果总是第一行；有二元运算符时第二行是「算式=结果」，超过 64 个 UTF-16 码元（一行的上限）时不给这一行，日志末尾注明 `equation too long`；整数部分有 5 位以上时最后一行是千分位写法。
- **在快照上运行**：`command` 每次都在 `msime_init` 之后的快照上运行，插件拿不到上一次的状态，输出只取决于这一次的参数。

## 写法：为了 fuel

参数最多 64 字节，最坏情况是 31 个运算符、每一步都是分数。wasmi 在函数入口按函数体词法上的全部指令扣 fuel、每轮循环按循环体扣，所以：

- 求值用调度场算法，不递归（递归最深 256 层，64 个左括号就可能撞上），两个栈放在静态变量里，不在栈上清零 1 KiB。
- 逐字节的循环只分派到两个小函数（该是数的位置、该是运算符的位置）；读数、规约、每种运算各是一个不内联的函数，常见路径不为没走到的分支付钱。整数的加减乘除取余走不通分、不约分的快路径，分数路径单独成函数。
- 带溢出检查的 64 位乘法在 wasm 里要走 128 位乘法，读数时改成先和 `(i64::MAX - 位) / 10` 比较；两个乘数都在 32 位以内时直接乘。长除法写小数位时一般用 64 位，只有分母极大时才走 128 位除法。

## 夹具与核对

`fixture.jsonl` 有 52 个事件：上面每条规则，写错的各种形状，除以 0，64 位整数的边界（`9223372036854775807` 能算，大 1 就溢出），以及几个塞满 64 字节的最坏情况（13 个质数分母的分数相加、30 层括号、63 个负号、31 个混合运算符、16 个 `1.1` 连乘）。`scripts/test-script-plugins.sh` 除了按 `expected.jsonl` 逐行核对，还跑 `check_output.py`：它用 Python 的 `fractions` 和 `ast` 换一种做法把每个算式重新算一遍，核对每一行的文字和注释；插件报溢出时，它要求确实出现了超过 10^9 的中间值。

## 最坏情况的 fuel

实测（rustc 1.97.1、wasmi 2.0），`command` 单次上限 100 000，测试断言不超过一半：

| 参数 | fuel |
| --- | --- |
| `1+2*3` | 约 5 300 |
| `1/3` | 约 6 100 |
| 30 层括号里的 `1+2` | 约 16 200 |
| 63 个负号加 `1` | 约 26 000 |
| 16 个 `1.1` 连乘 | 约 33 800 |
| 13 个质数分母的分数相加 | 约 41 000 |
| `1+2-3*4/5%6+7-…`（31 个混合运算符，夹具里最贵） | 约 45 900 |

最坏情况约为上限的 46%，离一半只剩一成。改这个插件时先跑 `scripts/test-script-plugins.sh calc`，它会在超过一半时失败。
