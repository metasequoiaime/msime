# macOS 最小上手

目标：在本机编译、安装原生输入法及配套设置应用。不包含 pkg 安装包的打包。以下命令均在仓库根目录执行；最低运行系统为 macOS 13。

## 1. 配置环境

需要完整 Xcode、Rust（`cargo`）、Python 3.10+、Homebrew、CMake 和 Sparkle 2.9.6。本机安装需要可用的代码签名证书及私钥，**不等于必须购买 Apple Developer Program**：没有 Developer ID 时，先按第 4 节通过免费 Apple Account 准备开发签名；没有证书仍可构建和运行原生测试。

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
export CMAKE_PREFIX_PATH="$(brew --prefix)"
export CARGO_TARGET_DIR="$PWD/target/macos-cargo"
export CFLAGS="-mmacosx-version-min=13.0"
export CXXFLAGS="-mmacosx-version-min=13.0"
export CMAKE_OSX_DEPLOYMENT_TARGET=13.0

df -h ~
xcodebuild -version
cargo --version
python3 --version
cmake --version
security find-identity -v -p codesigning
```

磁盘剩余不足 50 GB 时，不要开始新的构建。不要设置全局 `MACOSX_DEPLOYMENT_TARGET`，它可能破坏 Rust 过程宏构建。

缺依赖时先确认再安装，例如 Homebrew 工具：`brew install cmake python sqlite`。Xcode 和 Rust 需分别安装；首次启动 Xcode 完成组件准备。

Sparkle 已有时直接设置 `MSIME_SPARKLE_ROOT`；否则下载并校验：

```bash
export MSIME_SPARKLE_ROOT="$HOME/Developer/Dependencies/Sparkle-2.9.6"
mkdir -p "$MSIME_SPARKLE_ROOT"
(
  set -e
  cd "$MSIME_SPARKLE_ROOT"
  curl -fL -o Sparkle-2.9.6.tar.xz \
    https://github.com/sparkle-project/Sparkle/releases/download/2.9.6/Sparkle-2.9.6.tar.xz
  echo "52bf9e88cdd972fc0c81501377a880e90d47031bd8ca5462488f843e2609e192  Sparkle-2.9.6.tar.xz" | shasum -a 256 -c -
  tar -xf Sparkle-2.9.6.tar.xz
)
```

该目录下应直接包含 `Sparkle.framework`。首次构建还可能下载 Cargo 依赖、OpenCC 数据和固定语音运行库；后续准备词库也需要网络。

## 2. 构建与检查

```bash
cargo build -p msime-host-api --locked &&
cmake -S platforms/macos -B target/macos-isolated \
  -DMSIME_HOST_LIBRARY="$CARGO_TARGET_DIR/debug/libmsime_host_api.a" \
  -DMSIME_SPARKLE_ROOT="$MSIME_SPARKLE_ROOT" \
  -DMSIME_EDITION=full &&
cmake --build target/macos-isolated --parallel 4

ctest --test-dir target/macos-isolated --output-on-failure \
  -R '^(bundle-contents|session-smoke|text-client|desktop-input-session|input-source-registration|backend-library-load)$'
```

产物：`target/macos-isolated/水杉输入法.app`。以上仅运行 6 项关键测试；运行全部原生测试时去掉 `-R` 及其表达式。

**本机 SQLite 兼容问题**：若测试报 `Symbol not found: _sqlite3_set_errmsg`，说明 SDK 与系统 SQLite 不匹配。确认已有 Homebrew SQLite 后，重新配置、编译并重跑测试：

```bash
cmake -S platforms/macos -B target/macos-isolated \
  -DSQLite3_INCLUDE_DIR="$(brew --prefix sqlite)/include" \
  -DSQLite3_LIBRARY="$(brew --prefix sqlite)/lib/libsqlite3.a" \
  -DCMAKE_EXE_LINKER_FLAGS= &&
cmake --build target/macos-isolated --parallel 4
```

这里必须使用 `.a` 静态库，不要使用 `.dylib`：外部 Homebrew 动态库没有与开发证书相同的 Team ID，签名安装后会被 hardened runtime 拒绝加载，表现为输入法启动即崩溃。清空 `CMAKE_EXE_LINKER_FLAGS` 是为了移除旧配置的动态库搜索路径。安装前用 `otool -L 'target/macos-isolated/水杉输入法.app/Contents/MacOS/水杉输入法'` 确认不再依赖 Homebrew SQLite；安装后的实际输入仍需单独验收。

## 3. 准备词库

只安装 `.app` 不会准备词库，缺少运行配置时无法输入中文。把词库放在持久目录，不要让运行配置指向可能被清理的 `target/`：

```bash
STATE="$HOME/Library/Application Support/app.msime.macos"
RES=$(cargo run --quiet -p msime-client-core --example install_resources --locked -- target/resources) &&
bash platforms/macos/stage-resources.sh "$RES" &&
mkdir -p "$STATE" &&
ditto target/macos/EngineResources "$STATE/EngineResources" &&
cargo run --quiet -p msime-host-api --example prepare_host --locked -- \
  "$STATE/EngineResources" "$STATE"
```

这会写入当前用户的词库和 `runtime-options.json`；已有安装时请先备份同名数据。

`install_resources` 是下载、校验后退出的一次性程序，不是服务。首次下载约 190 MB；`--quiet` 和 `RES=$(...)` 不显示下载百分比，网络慢时会长时间停在 `Verifying ...`。每个下载请求超时为 300 秒；失败后不要继续安装，也不要同时重复运行以免等待安装锁。

## 4. 安装与使用

### 没有 Developer ID：先准备免费开发签名

脚本默认只自动查找 **Developer ID Application**，所以报 `no Developer ID Application identity found` 不代表本机测试必须付费。脚本也接受通过 `MSIME_SIGNING_IDENTITY` 显式指定的其他代码签名身份。

1. 打开 Xcode → Settings → Accounts（部分版本称 Apple Accounts），登录普通 Apple Account，接受开发者协议；无需购买会员。
2. 选择自己的 **Personal Team** → Manage Certificates → `＋` → **Apple Development**，创建开发证书。若没有个人团队，先完成免费开发者注册；若 Xcode 创建失败，保留具体错误排查，不要直接跳过签名。
3. 在终端确认有效身份：

   ```bash
   security find-identity -v -p codesigning
   ```

   应列出有效的 `Apple Development: ...` 身份。若显示 `0 valid identities found`，先不要安装，执行 `security find-identity -p codesigning`：若能列出身份但加 `-v` 后没有，检查证书有效期、信任链及登录钥匙串是否已解锁；若两者都没有，检查证书是否创建成功、是否带有本机可访问的私钥（只有 `.cer` 文件不够）。

   本机曾遇到缺少 **Apple WWDR G3 中间证书**、仅有已于 2023 年过期的旧版 WWDR 的情况。若在「钥匙串访问」中确认开发证书的颁发者是 Apple Worldwide Developer Relations Certification Authority，组织单位为 **G3**，从 Apple 官方下载 [AppleWWDRCAG3.cer](https://www.apple.com/certificateauthority/AppleWWDRCAG3.cer)，双击导入「登录」钥匙串；保持「使用系统默认设置」，不要改成“始终信任”，也不必删除旧版证书。这是公共中间证书，不是你的开发证书或私钥。

   导入后重跑上述 `security find-identity -v -p codesigning`，确认身份有效再继续；无需重新编译。其他颁发者不要盲目套用 G3，仍为 0 时继续排查证书链和私钥，不要跳过签名。

4. 找到 `Apple Development: ...` 对应的 40 位 SHA-1，替换下面占位值。在执行安装命令的同一终端设置：

   ```bash
   export MSIME_SIGNING_IDENTITY="替换为上面列出的40位SHA-1"
   ```

这是免费开发签名的配置路径，不是 Developer ID 分发或公证。本向导尚未实测 Personal Team 签名后的系统输入验收；签名成功不等于系统输入源可用。Apple 官方说明：[Personal Team](https://developer.apple.com/help/account/basics/about-your-developer-account)、[创建签名证书](https://help.apple.com/xcode/mac/current/en.lproj/dev154b28f09.html)。

### 执行安装

已有 Developer ID Application 时，安装脚本可以自动选择证书，但这不会设置当前终端的 `MSIME_SIGNING_IDENTITY`。为让第 5 节的设置应用使用同一身份签名，两种证书路径都应先从 `security find-identity -v -p codesigning` 的输出中选择有效身份的 40 位 SHA-1，并在同一终端执行：

```bash
export MSIME_SIGNING_IDENTITY="替换为上面列出的40位SHA-1"
```

安装会替换当前用户已有的水杉输入法，并停止其运行实例，**脚本目前先停进程、后检查签名身份**，因此先确认身份有效，再切换到系统自带输入法执行：

```bash
find target/macos-isolated -maxdepth 1 -name '*.app' \
  -exec bash platforms/macos/scripts/install.sh {} \;
```

安装签名时可能多次弹出访问「登录」钥匙串的授权窗口。确认请求方是 `codesign`、访问的是刚创建的开发证书后，输入 **Mac 当前用户的登录密码**（不是 Apple Account 密码），选择「始终允许」即可，后续相同私钥访问不再逐次询问；这会持久授权 `codesign` 使用该私钥。若不希望持久授权，可逐次选择「允许」。登录密码不被接受时，可能是钥匙串仍使用修改前的旧密码，不要直接重置或删除钥匙串。

脚本签名后安装到 `~/Library/Input Methods/水杉输入法.app` 并注册输入源。不要用 `MSIME_SIGNING_IDENTITY=-` 绕过身份检查：ad-hoc 签名不等同于开发证书，此安装路径没有验证它可用；也不需要关闭 SIP 或 Gatekeeper。

**覆盖 Release 后如何确认**：输入法名称和安装路径不变，不能只看菜单图标。先退出从 Release 安装的 `MSIME.app` 设置应用，再安装本地构建；开发测试期间不要重新打开它，其启动安装/刷新逻辑可能用内嵌的 Release 输入法覆盖本地版本。安装后执行：

```bash
BUILT="target/macos-isolated/水杉输入法.app/Contents/MacOS/水杉输入法"
INSTALLED="$HOME/Library/Input Methods/水杉输入法.app"
xcrun dwarfdump --uuid "$BUILT"
xcrun dwarfdump --uuid "$INSTALLED/Contents/MacOS/水杉输入法"
codesign -dv --verbose=2 "$INSTALLED" 2>&1
ps -axo pid,comm | grep -F '/水杉输入法.app/Contents/MacOS/水杉输入法'
```

两份可执行文件在**相同架构**下的 UUID 应一致，安装副本的 `Authority` 应为你选择的开发证书；重新签名会改变文件哈希，不要直接用 SHA-256 判断是否同一构建。切换输入法并在编辑器输入后，进程路径应指向上述用户安装目录，而不是构建目录或备份目录；路径相同本身仍不能区分新旧版本。若 UUID 不一致，本地构建未正确就位或已被替换，应检查安装输出和 Release 设置应用是否重新启动。

1. 打开「系统设置 → 键盘 → 文字输入 → 编辑 → ＋」，添加水杉输入法。
2. 若首次安装提示需要重新登录，注销并重新登录后再添加。
3. 从菜单栏切换到水杉输入法，在文本编辑器输入 `nihao`，用空格或数字键选词。

刚安装后注册表可能短暂查不到输入源，稍等再检查，不必反复重装。选中后仍只输出英文，优先检查第 3 步的词库与运行配置。

若安装后启动失败，尤其第 2 节使用了 Homebrew SQLite 时，先检查是否有 `Library Validation`、`different Team IDs` 或 `mapped file has no Team ID` 错误；外部 Homebrew 动态库不一定满足脚本启用的 hardened runtime 签名要求。此时不是重新登录能解决的问题，不要通过关闭系统安全机制掩盖它。

完整安装、签名、设置应用与打包说明见 [macOS README](../../platforms/macos/README.md)。

## 5. 构建并安装配套设置应用

第 4 节核心可用后，再构建与它配套的共享设置组件。不要继续使用官方 Release 设置应用：它可能把已安装核心换回官方版。以下复用第 1 节的环境变量和第 4 节的 `MSIME_SIGNING_IDENTITY`，产出本机架构的开发包，不是发行包。

需要 Node.js 和仓库指定的 pnpm（版本见根目录 `package.json`）。确认允许下载依赖后，首次执行 `pnpm install --frozen-lockfile`；Cargo 首次构建设置应用也可能下载锁定依赖。不要直接运行 `pnpm tauri dev/build`。

先完成第 3 节，确保 `target/macos/EngineResources` 存在；若已装官方版且希望省去重复下载，可先校验其公共资源，再复制，校验失败不能继续：

```bash
cargo run --locked -p msime-client-core --example verify_resources -- \
  --omit-on-demand /Applications/MSIME.app/Contents/Resources/EngineResources &&
mkdir -p target/macos &&
ditto /Applications/MSIME.app/Contents/Resources/EngineResources \
  target/macos/EngineResources
```

暂存第 4 节已安装、签名并验收的本地核心，再编译页面和原生设置程序：

```bash
ditto "$HOME/Library/Input Methods/水杉输入法.app" target/macos/水杉输入法.app &&
(
  cd apps/desktop &&
  node_modules/.bin/tsc --noEmit &&
  node_modules/.bin/vite build
) &&
TAURI_CONFIG="{\"version\":\"$(cat platforms/macos/version.txt)\"}" \
  cargo build --locked -p msime-desktop --bin msime-desktop \
  --features tauri/custom-protocol &&
(
  cd apps/desktop &&
  node_modules/.bin/tauri bundle --debug --bundles app --no-sign \
    --config "{\"version\":\"$(cat ../../platforms/macos/version.txt)\"}"
)
```

不要设置 `MACOSX_DEPLOYMENT_TARGET`，避免损坏过程宏缓存。这里遵循 macOS 打包流程：先用 Cargo 编译，再只用 Tauri 打包，不把共享组件当成独立输入法。

Tauri 复制资源会展开 Sparkle 符号链接，必须把内嵌核心整体换回保留链接的副本，再签外层应用：

```bash
APP="$CARGO_TARGET_DIR/debug/bundle/macos/MSIME.app"
rm -r "$APP/Contents/Resources/水杉输入法.app" &&
ditto target/macos/水杉输入法.app "$APP/Contents/Resources/水杉输入法.app" &&
codesign --force --options runtime --timestamp=none \
  --sign "$MSIME_SIGNING_IDENTITY" "$APP" &&
codesign --verify --deep --strict "$APP"
```

退出所有正在运行的 MSIME 设置应用（不能只关窗口），再替换 `/Applications/MSIME.app`。以下会删除旧设置应用包，不删除用户词库和配置；需要备份时先自行保存旧包。只使用一个同标识的设置应用，避免原生核心打开错误副本。

```bash
rm -r /Applications/MSIME.app &&
ditto "$APP" /Applications/MSIME.app &&
codesign --verify --deep --strict /Applications/MSIME.app &&
open /Applications/MSIME.app --args --route=settings
```

关于页版本应与 `platforms/macos/version.txt` 一致。核对下列两份核心在相同架构下的 UUID 一致，且设置页能显示、输入仍正常：

```bash
xcrun dwarfdump --uuid \
  /Applications/MSIME.app/Contents/Resources/水杉输入法.app/Contents/MacOS/水杉输入法
xcrun dwarfdump --uuid \
  "$HOME/Library/Input Methods/水杉输入法.app/Contents/MacOS/水杉输入法"
```

若不一致，先退出设置应用，再按第 4 节重装已验证的本地核心；不要直接向运行中的已签名包覆盖文件。菜单或 Ctrl+Space 仍缺输入源时，保存工作后注销并重新登录，再检查 `Metasequoia · WB` 等模式名称。开发包不包含发布流程另行加入的 `msime-mcp` 命令行工具。
